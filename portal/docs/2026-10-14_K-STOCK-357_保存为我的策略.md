# K-STOCK-357 · 保存为我的策略（NL 建策略沉淀进卡墙）

日期：2026-10-14 ｜ 提交：`80fa149` ｜ 作者：主控会话（老田「下一步」驱动，352 起两次提及的挂账收官）

## 功能闭环

NL 一句话建策略 → 解析核对 → **💾 保存为我的策略** → 卡墙出现「🧩 我的策略」组 → 点卡出参数面板 → **⚡ 重跑回测**（同参数再验证）/ **🗑 删除**。

## 实现

**后端**（api_backtest.py + portal_api.py）：
- `_api_my_strategies`：list/save/delete 三动作；单文件存储 `portal/data/my_strategies.json`（原子写：tmp+os.replace）。
- **参数键白名单**（与 bt2_run 同语义 12 键）+ fail-closed：缺 strategy/窗口直接拒（400 语义、200+ok:false）。
- POST 走 `_MUTATION_POSTS` 守卫（token+每 IP 每分钟 ≤12 限频）；GET 列表只读。
- 299 纪律执行：新函数已同步 portal_api.py 导入名单。

**前端**（paper.html，v0.8）：
- nlParse 结果区加「💾 保存为我的策略」按钮 → prompt 起名 → POST。
- 卡墙新增「🧩 我的策略（N）」组（已接入通道之后），渲染名称+窗口+闸门+评分摘要；data-s=后端原始 id（my_ 前缀）。
- 点卡 → exec-mystrat 专用面板：参数 chips 全展示 + 重跑（参数塞回 _nlParams→nlRun 复用整套轮询渲染，结果出在 NL 区）+删除。
- showExecPanel 加 mystrat 分支（my_ 前缀识别）。

## E2E 排障判例（本轮最大收获）

首轮 UI E2E「toast 显示已保存但文件为空」疑案，三层排查定位根因：
1. **直连 8091 API CRUD 全通** → 后端无辜；
2. **浏览器 fetch 决定性实验全通** → nginx 反代/守卫无辜；
3. **带事件捕获的探针**抓到 toast 真文：「❌ 参数集缺 strategy 字段」——**根因=NL 解析结果只含窗口/样本域/买点/槽数，strategy/gate_mode/min_score/slot_pct 是 nlRun 时才由 NL_DEFAULTS 合并的**；nlSave 直接发原始 _nlParams 被服务端白名单 fail-closed 正确拒绝。
- 🔴 判例：**同一份参数在前端有两条消费路径（执行/保存）时，默认值合并必须在共同入口做**——nlSave 改为与 nlRun 同口径 `Object.assign({},NL_DEFAULTS,_nlParams)`。
- 顺修：data-s 双前缀（my_my_）统一为后端原始 id。

## 验证

- API CRUD：save×2/坏参数拒绝/list/delete×2 清零全过。
- UI E2E 全绿：解析→保存→卡墙「🧩 我的策略（1）」组→点卡 mystrat 面板（chips 全展示）→删除清理；console 零错误；无测试残留。
- 静态语法+DOM 断言全过。

## 已知边界（非缺陷）

- 规则引擎版 NL 解析对「高位闸门/评分 80」等复杂口径不产出 gate_mode/min_score 键，保存的是「解析结果+默认值」——面板 chips 里看得见，用户核对后可再跑 bt2_nl 的 LLM 兜底或手动改参数（后续可做「保存前编辑参数」增强）。
