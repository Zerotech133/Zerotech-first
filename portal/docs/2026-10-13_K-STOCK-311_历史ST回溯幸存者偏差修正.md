# K-STOCK-311：历史 ST 回溯（幸存者偏差修正）

日期：2026-10-13 ｜ 状态：已上线切默认（E2E 实锤） ｜ 前序：307（诚实口径矩阵）/ 309（lc+runup5 切默认）

## 一、问题

`market_scan.py` 现名剔 ST（code2name 按 2026-10 现名）存在**幸存者偏差**：
历史上被 ST、后来摘帽的股票（现名不带 ST）一直留在回测宇宙里。宇宙口径与
实盘行为不一致——实盘现名过滤挡掉现行 ST，当年这些票处于 ST 状态时同样不会买。

## 二、数据源

远端自建 API 表 `ts_namechange`（股票曾用名）：**4044 行 / 3026 只 / 2020-01-06 起**。
字段 `ts_code, name, start_date, end_date, ann_date, change_reason`，
区间 [start_date, end_date] 与回测窗口有交集且 name 含 ST 即命中（end_date 空=现行）。

- 产物：`data/tdx/ts_namechange.parquet`（+`ts_stock_basic.parquet` 现名对照）
- 拉取器：`_pull_namechange_311.py`（幂等可重跑）
- 🔴 **教训**：该 API 忽略 `page/page_size`，分页必须用 `offset/limit`
  （首跑 page 参数得到 4000 行完全重复的假象，去重后仅 100 行）。

## 三、覆盖边界（诚实声明）

表仅覆盖 2020-01 以后的曾用名区间。若某票 2020-01-06 之前已戴帽且窗口内仍未
摘帽，其 ST 区间整段缺失——此类票现名大概率仍为 ST（现名过滤已覆盖），漏网
风险极小，但非零。

## 四、偏差量级

| 窗口 | 窗口内 ST 区间股票 | 其中历史增量（现名非 ST 但曾 ST） |
|---|---|---|
| 三年窗 20231010→20261012 | 474 只 | 199 只 |
| 一年窗 20251013→20261012 | 377 只 | 102 只 |

## 五、实现（零重扫·引擎侧事件过滤）

- `market_scan.hist_st_set(d0, d1)`：窗口交集判定 → ST 股票集合。
- `backtest_engine_v2.calc_chanlun_signals_market(..., hist_st=False)`：
  事件加载后整体剔除（买卖信号同剔），等价宇宙剔除；`n_codes/n_events_drop`
  落 meta 作生效证据（305 教训）。
- 透传链：`run_job`（DEFAULTS **hist_st=True**）→ bool 解析 → meta；
  CLI `--hist-st`（默认 true）；portal `_bt2_start` 白名单（默认 true）；
  `bt2_view.html` 清仓规则组新增「历史ST回溯」select。

### 结论

1. **四臂全部同向改善**——历史 ST 票是系统性拖累（三买信号在 ST 票上质量差），
   原基线是被 ST 票拉低的；修正后口径更接近实盘。
2. **🔴 311 新锚定基线（取代 309 数字）**：一年窗 **-21.90%/768 笔/PF0.91**、
   三年窗 **-32.44%/1973 笔/PF1.04**。
3. **终选组合（high+min80+top10+lc+runup5+hist_st）三年窗 -4.96%/PF1.20/回撤
   -12.11%**——距打平仅一步，vs 同口径基线 +27.5pp；结构性结论（高位限定+
   评分门槛为最强组合）在诚实口径下不变。
4. E2E：portal 重启（走 ZeroPortalAPI 计划任务）后默认 true 生效，一年窗
   -21.9%/768 笔与 CLI 完全一致。
