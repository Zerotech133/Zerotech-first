# 推送管理中心

日期：2026-10-14 ｜ 服务：`portal/push_admin_server.py`（127.0.0.1:8097，零第三方依赖）

## 需求与定位

用户需求：把"每日新闻分析 + 盘中盯盘异动"的推送统一管理——推送给谁、推到哪里、怎么推、什么时间点，并要统计。

**定位**：推送内容的执行者仍是既有管道（`subscribe.py` 订阅引擎、4 个日报计划任务），本平台做**配置 + 触发 + 统计**，不重复造发送层。

## 管辖范围

| 域 | 内容 | 操作 |
|---|---|---|
| 日报任务 | 金融新闻日报 08:30 / 统一日报 03:00 / 预警晨 07:10 / 预警晚 16:05 | **改时间点**（Set-ScheduledTask 即时生效）、立即执行、状态/上次结果；只读展示 TodaysPicks、自选股行情快照、预警监听、持仓异动监控 |
| 订阅推送 | 每日选股批次 / 预警信号 / 自选股异动 / 闽东电力报告·买点 | 启停（写 subscriptions.json）、改接收人、**试推**（`subscribe.py --test` force，真实发送，前端二次确认） |
| 接收人 | receivers.json（订阅按名字解析，**缺名字会被引擎静默丢弃**——平台严格校验拒绝而非静默） | 增删（引用中的名字禁止删）、「从推送目标一键同步」把 news push_targets（含量化群）并入 |
| 统计 | 今日推送合计 = 订阅今日次数（subscribe_state）+ KM 卡片（km_stats）+ 日报任务今日运行数 | 页面 KPI |

## 已知边界

- `LastRunTime` 显示为美式日期格式（PowerShell culture），仅外观
- 订阅"今日次数"来自 subscribe_state（引擎只留当日）；日报类无逐日流水（历史在各自 C:\Temp 日志），近 7 天趋势未做——需要时给日报脚本加统一流水表
- 试推/立即执行都是**真实动作**（真实发送/真实跑任务），按钮已带二次确认
- 会话内派生实例会被 Job 连坐收割（同 8095/8096 判例），真实宿主是计划任务
