# K-STOCK-351 · 策略管理中心（接待后置选策略）

> 老田 10-14 指令：「值班经理没有一开始就选什么策略一说，策略 Agent 是在后面去选的。增加一个策略的市场——基金管理人的策略、操盘手的策略、研究员的策略，放在一个策略管理中心，看放在什么地方更合适。」

## 一、设计落点

**策略管理中心 = paper 新页签（第二页签·紧随接待大厅）**。页签序：接待大厅 → **策略中心** → 交易员市场 → 持仓 → 历史（212 动线的「服务选择」站升级为独立页签，客户进门先听接待，选策略是下一步的事）。

三类策略按角色归位（页签头部一句话导览）：
| 角色 | 策略含义 | 位置 |
|---|---|---|
| 📡 研究员 | 选什么股 = 信号来源 | 策略中心·四张策略卡（AI 值班/量子双刀/青萍/手动）+ 执行台 |
| 🧑‍💼 经理 | 怎么按市况配策略 | → 交易员市场·经理阵营（链接直达） |
| 🧑‍✈️ 操盘手 | 怎么买卖 = 执行纪律档案 | → 交易员市场·操盘手（链接直达） |

上新策略 → /market-strategy 策略市场选购，订了即出现在策略中心并在此执行。

## 二、改动（纯 paper.html 单文件·后端零改动）

1. **desk 两栏整块搬家**（信号源卡+执行台）从接待大厅 → 新 `#tab-strategy` 页签；列标题改角色语言「📡 研究员的策略 · 信号来源」「⚡ 执行台」。
2. **接待大厅净化**：只剩接待主卡 + 今天的事 + 投研机制折叠——进门零策略卡零执行面板。
3. 接待卡**动线指引更新**：② 选服务 → ②「策略中心选策略」（点击跳页签）。
4. renderSvcMenu 服务清单三处链接改页签跳转（gotoTab：策略中心/经理卡区/交易员战绩）——跨 tab 锚点本就无效，顺手修正。
5. Tab 切换走既有通用机制（`.tab[data-tab]`→`#tab-X`），零 JS 新增。

## 三、🔴 修复判例

搬移脚本在 JS 单引号字符串里写入 `gotoTab('strategy')`——裸单引号切断 JS 字符串（`Unexpected identifier 'strategy'`）。修复：JS 字符串内的引号必须 `\'` 转义（renderSvcMenu 三处）。判例：**Python 脚本向 JS 字符串注入 HTML 属性时，属性内的单引号在 JS 串里必须转义；注入后必须跑 new Function 语法校验**。
