## 一、这是什么

**一个自建的、不依赖外部客户端的分析台。** 数据自己同步、结构自己算、回测自己跑、信号自己推、页面前端自己发。

它和"用同花顺看盘"的根本区别：同花顺给你图，这只给你**判据 + 时点 + 可回放的证据链**。任何一档名单点进去，能看到是哪条规矩成立的、中枢上下沿是多少、守位在哪、成立当时的价格是什么。

四件事同时在做，共用一个数据底座：

| 线 | 回答什么问题 | 主入口 |
|---|---|---|
| 结构（缠论池） | 今天哪些票在什么结构位置 | `pool_state.py` → 个股页 / PC 工作台 |
| 板块 | 这些位置分布在哪些行业概念里 | `sector_state.py` → 板块平台 |
| 选股 | 除了结构，还有哪些强势/共振标的 | `premarket.py` / `nine_dim.py` / `rps_resonance.py` |
| 组合 | 真拿钱做会怎样 | `portfolio.py` / `portfolio_sim.py` / `execution_engine.py` |

### 5. 每天的进出状况 —— 硬

`positions.json` 三个数组就是完整的进出流水：

```
pending  16 条  待买信号（sig_date 已出，entry 未成交）
open     64 条  持仓中（entry_date / entry_px / last_px / days / marks[] 逐日浮盈）
closed   72 条  已平（exit_date / exit_px / pnl / marks[] 逐日轨迹）
```

`reports/positions.html`（72 KB「纸面持仓跟踪」）是它的可视化，含近 5 日收盘浮盈轨迹。

### 6. 日历 —— 缺（数据有，界面没有）

底层两个模块都很硬：

- `cn_trading_days.py`：双源（tushare `trade_cal` 快照 1991-2027 为主 + 内置 2026 表兜底），2026 全年逐日交叉验证 **0 差异**（242 开市日全对）。
- `calendar_provider.py`：生产级契约，带 sha256 身份、session bounds、segments，明确拒绝"按工作日推断节假日"。

**但 28 个 html 里没有一个日历视图。** 日历目前只用于三处内部门控：判断今天是否开市、判断是否在交易时段、判断"最后一根日线是不是今天"。你在页面上看不到"这个月哪天开市""财报/解禁/交割日排布"。

### 7. 可调校 —— 半（有引擎，无界面）

- `opt_defaults.py`：全池网格寻优，按平均夏普 + Top3 命中选参，产出 `reports/opt.html`「全池参数寻优榜单」。
- **W1-2 纪律门**是这套最值钱的部分：`--apply` 写 config 前必须过 walk-forward（train 252d / test 63d 滚动、≥4 折），OOS 夏普 ≥ 0.6×IS 才放行；否则写回默认参数。开关 `config.opt_discipline_gate`。
- `bt2_tune_batch.py` / `bt2_tune_compare.py`：批量调参与对比。

**缺口**：调校只能在命令行、按季度跑，页面上没有"改个参数看结果"的交互。`opt.html` 只是**结果榜单**，不是调参台。

## 五、平台结构（2026-11-09 15:50 整合完成）

**问题**：28 个页面里 26 个是孤立的，只有缠论三页互跳；17 个页面引 `/static/nav.js`、
`/bt/strategy/*`、`/bt-signals`、`/bt-report/img/*` 这些**门户服务（127.0.0.1:8091）的路由**，
静态托管下全是死链；数据时点不写在页面上——`opt.html` 生成于 10-03 而数据是 09-26 的。

**做法**：`platform_pages.py` 做单向整理，`h5_pack.py` 做编排与自检。

```
platform_pages.py
  CATALOG      24 个页面的单一事实源（域名 / 标题 / 数据日来源 / 发布名）
  staleness()  用交易日历算「数据距今几个交易日」>3 橙、>15 红
  patch()      剥 nav.js 死链 + 注入统一导航条 + 服务端路由标灰（保留文字不假装能点）
  build_home() 生成门面 → reports/platform_home.html + h5_daily/index.html

h5_pack.py （平台构建唯一入口）
  核心四柱缺失 → 停；非核心页缺失 → warn 跳过（不能让一个历史页被清理打断 18:30 流水线）
  自检三项：引用闭环 / 无残留可点门户链接 / 门面每张卡片目标存在
```

**发布目录 25 个文件**（门面 + 24 个分析页，3.1 MB）：

| 域 | 页面 |
|---|---|
| 结构 | 结构日报（手机）· 结构工作台（PC）· 结构池全景 |
| 板块 | 板块操作平台 |
| 选股 | 盘前分析 · 选股中心 · A股/美股/港股/加密 · 全池信号 · RPS |
| 回测 | 每日 Top5 回测 · 四策略纵切 · 参数寻优 · 背驰分层 |
| 模拟 | 纸面持仓跟踪 |
| 数据 | 盘后复盘 · 数据源列对账 |
| 归档 | 双池监控台 · 事故复盘 |

**门面是根入口**：`index.html` 现在是平台门面，结构日报挪到 `pool_report_h5.html`。
旧深链不断——门面检测到 `?stage=` / `?code=` / `?sector=` 会原样转发到对应页；
同时把 `sharecode` 补到每张卡片上（线上逐请求校验，丢一次就是 403）。

**三个数据日的坑**（都实测踩过）：
1. `pool_state_*.json` 用 `data_asof`，`sector_state_*.json` 用 `asof` —— 字段名不一致，
   读错就退回文件 mtime，把 11-06 的结构误标成「今天最新」。
2. 文件名里的日期是**数据日**，不是生成日；盘后重算会把旧数据日的文件写到今天。
3. `run_at` 是生成时刻，不能当数据日（`pool_state_20261106.json` 的 run_at 是 11-09 13:41）。

**验收**：`platform_check.py` 逐页打开 25 个页面，验 HTTP 200 / 无 console 错误 /
有导航条 / 正文非白壳 → **25/25 PASS**；`h5_deeplink_check.py` 验门面→日报→板块→个股
整条链（含 sharecode 场景）→ **PASS**。

## 七、口径清单（踩过的坑，写死在这里）

1. **两个时点必须分开写**：结构（笔/中枢/档位）只能用收盘确认；价格是当下的。盘中这页是两截拼的。
2. **一页四个时点**：九态（结构日收盘）· 五层（盘中 judge）· 市场统计（pool_live 快照）· 每只票价（当场补取）。少写一个就是口径事故。
3. **`pct`（小数）vs `lpct`（百分数）**：`pool_state_*.json` 用 `pct`（−0.0296），`pool_judge_*.json` 用 `lpct`（−2.96），`_fetch_px` 返回百分数。混用会显示 "+28.00%"。
4. **线上逐请求校验 sharecode**：站内跳转不带就 403（不是 404），本地 `file://` 完全复现不出来。
5. **日等权 ≠ 行均值**：20241008 只有 1 个买点板块（−6.8%），与 370 样本的日子同权会把符号弄反。每日 ≥10 样本才计入。
6. **分层比较必须逐日配对**：行均值相减 = 辛普森悖论。曾据此得出"强者恒强"，配对后单调性全消。
7. **末刻首现要剔除**：最后一刻首次出现的信号 ret 恒 0，会稀释胜率。
8. **Python 一律用 3.11**：`"/c/Program Files/Python311/python"`，裸 `python` 指向 3.13 无 pandas。
