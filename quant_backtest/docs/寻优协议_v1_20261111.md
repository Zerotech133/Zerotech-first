# 选股数据集寻优协议 v1 · 2026-11-11（任务 #105）

> 目的：把「回测能不能拿到最优数据集」从感觉变成可复算的流程。
> 两个产物：`reports/trial_ledger.json`（试验台账）+ `reports/dsr_rank_20261111.json`（DSR 校正排名）。

## 一、协议正文（三条，生效即约束）

1. **先登记，后出数**：任何寻优实验（网格/变体/因子尝试）开跑前先在
   `trial_ledger.json` 追加条目（src/job/假设），跑完回填读数。N 必须可数。
2. **排名用校正后显著性**：任何「最优」表述必须标注 N 与校正口径。
   Bonferroni 存活线 = 单侧 p < 0.05/N（当前 N=1501 → **t≥3.99**）。
3. **三标签才算候选**：`[DSR]` 校正后显著 × `[COST]` 122bp 口径为正 ×
   `[OOS]` 样本外未失效（使用≤3 次）。三缺一只能叫「最优候选」。

## 三、DSR 首版结论（最重要的一个数字）

> **N=1501 下 Bonferroni 存活线 t≥3.99；历史候选最高笔均 t≈0.9（v3）。**
> **无一过线——当前不存在统计意义上「证显著」的最优数据集。**

这不是坏消息，是诚实基线：此前所有「最优」（含 11-09 拍板的 v3）在
多重检验校正下全部降级为「最优候选」。与 11-11 当天的组件证伪
（bei30 三源无前瞻信息）互相咬合——搜索空间里真正有信息的维度
（pos+vol）本来就窄。

bt2 侧可排名条目 988 个（有收益读数），122bp 口径 top10 已入
dsr_rank 产物；但 bt2 产物缺笔均超额 t（align 口径），988 条暂只能
按收益排序不能按显著性排名——**bt2 align 化**列为下一步（见 §五）。

## 四、与既有机制的关系

- **不推翻固化 v1**：v3 仍是运行默认，但其身份从「已验证最优」改为
  「最优候选 + 影子外证中」，与影子台账 G-A 门（F1 转正验收）衔接。
- **不否定四窗口协议**：DSR 是其上游——先过 N 校正，再谈 IN/OOS。
- **评分瘦身的 N 红利**：bei30 三源证伪后，寻优维度收缩 → 后续网格
  的 N 更小 → 同样数据下存活线更低、结论更硬。瘦身重扫后的主网格
  按 §五 第 3 条执行。
