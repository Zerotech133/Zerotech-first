## 疑案 3：19:20 追平轮「probe busy, skip」

### 证据链

1. **字符串不在仓内**：全仓（含 tools/、xq_classify.py）grep `probe busy` 源码 0 命中，仅 docs 引用。**它不是脚本输出，是 automation agent 手工 echo 的固定口径**：
   ```
   Command: echo "probe busy, skip" >> C:/aios/automation_runs/xq_classify/xq_classify_status.log && tail -c 200 …
   ```
   （追平轮 automation `4c4ba572-ae2b-403e-ae60-1e716d4dfaad` 的 runs_json 原文；行首无时间戳正因如此——对比脚本 `log()` 输出都带 `YYYY-MM-DD HH:MM:SS | ` 前缀。）

2. **probe 探测什么**（`automations` 表 4c4ba572 的 prompt + `C:/aios/automation_runs/xq_classify/probe.py`/`probe_now.py` 实物）：向本机 Ollama `http://127.0.0.1:11434/api/chat` POST 一次最小请求（`qwen3.5:9b`、`num_predict=8`、`num_ctx=1024`、**timeout=10s**、3 次重试），**必须先清干净代理变量**（prompt 红线：WorkBuddy 宿主注入 `HTTP_PROXY=http://127.0.0.1:53679`，该代理对 11434 返回假 502）。
   - **busy 判定条件**（prompt 原文）：「探测失败时先自查代理变量是否清干净（`echo $HTTP_PROXY` 应为空），清干净后仍失败才判真 busy」。
   - **它探的不是进程锁/文件锁**——是 Ollama HTTP 可用性。与 A1 死进程残留锁**无关**。

3. **19:23 轮（audit 记 19:20 案发轮）实测**：追平轮 run 19:23:17-19:24:51（automation.log `11:23:17.567Z run start`→`11:24:51.301Z success`），其探测输出原文：
   ```
   PROBE_FAIL TimeoutError timed out
   ```
   （禁代理前缀 `HTTP_PROXY= HTTPS_PROXY= … NO_PROXY=127.0.0.1,localhost` 已带上，代理确实清干净）→ 按预案让路，echo 追加 "probe busy, skip"（即现日志 2773 行；20:25 第十轮又追加一行 = 2774 行，报告时点日志尾部共两行）。

4. **「为什么 19:23 会 busy」——追平轮 agent 自己的归因有偏差**：其结案报告称「占用者实例疑似空转卡死」，但当时**根本没有存活的分类进程**：classified 自 18:32:50 起冻结在 2455（19:23 轮只读查库确认），19:50 进程表无对应进程。probe 10s 超时反映的是 **Ollama 服务端自身劣化**：15:42 有人重启过 Ollama（追平轮第七轮 netstat 取证）、18:32 后默认实例（ctx=2048）接管 11434、18:36 预热成功、19:23 起连环超时——形态指向默认实例**卡死/过载**，而非「有别的分类在跑」。
   - probe 的设计缺陷：**无法区分「忙（有消费者）」和「服务卡死（零消费者）」**，两者都是 10s TimeoutError，导致让路策略被误导（连续 10 轮让路、pending 卡 2.1 万）。

5. **历史口径一致性**：日志共 9 处 `probe busy, skip`（行 443/444/2164/2355/2427/2459/2697/2773/2774），历轮形态一致；行 2697 = 18:21 第八轮写入（紧跟 17:25:19 round end 之后），非 18:30 日轮所写。

### 定谳

「probe busy, skip」= 追平轮 automation（4c4ba572）的 **prompt 固定让路口径**，由 agent 用 `echo` 追加（故无时间戳）；probe 探测对象是 **Ollama 127.0.0.1:11434 的 HTTP 可用性**（禁代理、10s 超时），busy 判定 = 代理清干净后仍 TimeoutError。19:23 的 busy **与 A1 死进程残留锁无关**（探测的根本不是锁），真实成因是 Ollama 默认实例接管后疑似卡死——probe 语义缺陷使其被误报为「忙」。

### 明晨处置建议

8. probe 失败时先取证再让路：补一条只读 `GET /api/ps`（看模型在驻与 context_length）+ `netstat -ano | findstr 11434`（看 ESTABLISHED 连接数）——零消费者仍超时即改判「Ollama 卡死」，触发重启而非让路。
9. 让路行改带时间戳：`printf '%s probe busy, skip\n' "$(date "+%F %T")" >> …`，一行改动，排障成本立降。
