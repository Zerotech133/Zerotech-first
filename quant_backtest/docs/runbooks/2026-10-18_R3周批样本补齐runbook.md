## 2. 全量补齐命令（一条完整命令）

**解释器必须用生产 Python311**（workbuddy env 无 neo4j 驱动，KgClient 起不来）。
执行位置 `C:\aios\zerobound-kg`（与调度链同路径，即 `C:\项目\zerobound-kg`
同一目录）：

```powershell
cd C:\aios\zerobound-kg

# KG_* 凭据注入（同 riskguard_r3_weekly.ps1 口径，已设置的不覆盖）
Get-Content 'C:\aios\quant_backtest\.env.local' -Encoding UTF8 | ForEach-Object {
    if ($_ -match '^(KG_[A-Za-z0-9_]+)=(.*)$') {
        if (-not [Environment]::GetEnvironmentVariable($Matches[1])) {
            [Environment]::SetEnvironmentVariable($Matches[1], $Matches[2], 'Process')
        }
    }
}
$env:PYTHONUTF8 = '1'
$errlog = 'riskguard_ledger\r3_weekly_err_' + (Get-Date -Format 'yyyy-MM-dd') + '.log'

& 'C:\Program Files\Python311\python.exe' -X utf8 kg_riskguard.py eval-batch `
    docs\planning\z4-fourstate-snapshot-20261017.csv `
    --with-r3 --only-r3 --skip-done-sec --date 2026-10-17 `
    1>> riskguard_ledger\r3_weekly_snapshot.log `
    2>> $errlog
```

要点：
- `--date 2026-10-17` **必带**：不带则 skip 判重按今天（10-18）取已入账集合，
  812 个旧标的判重不到 → 重复入账污染 OOS；且新行 ts 会落 10-18，
  idem-weekly --date 2026-10-17 覆盖率永远凑不齐。
- `--skip-done-sec` 自动跳过已入账 862（812 旧 + 试点 50），只补剩余 ~1851。
- `--limit N`（可选）分档控量：如 `--limit 500` 每次最多补 500 个，
  多次执行自动顺延（已入标的由判重跳过）。

## 4. 中断与回滚

- **账本 append-only，不可回滚**。若补错（错快照/错参数），无法撤销已写入
  行，只能靠幂等判重不再重跑——执行前核对命令中的快照文件名与 `--date`。
- **中途中断无害**：直接重跑同一命令，已入账标的全部被 `--skip-done-sec`
  跳过，从断点续补（append_ledger 自带瞬态锁重试 + 降级，单点锁不再杀整批）。
- 全量跑完**不要手动再跑第二遍**：第二遍会因覆盖率已达标而行为不同，
  纯浪费；调度侧下个周六 06:40 由 idem-weekly exit 0 自动 skip。
