## ① 方法论与选型说明

- **两版逻辑均为源码摘录，不 import xq_classify**。RE_HK v1.6 两行（xq_classify.py:164-165）
  逐字符摘录进对拍脚本；extract 主流程镜像 :240-264（语境共现一次判定、紧贴名黑名单、
  8 码上限、RE_A/RE_FUND 通道全保留）。选型理由：稳妥优先、零依赖；辅助审计确认
  import 亦安全（模块级仅常量/函数定义，`ensure_table`/`log` 只在函数体内调用，
  `main` 有 `__name__` 守卫），两条路都可行，摘录法使对拍完全确定性。
- **对拍三个版本**（任务指令字面式与保留原集合的并集式各测一版，原因见②）：
  | 版本 | bare/ct 通道后缀 lookahead |

  | v1.6 现行为 | `(?!\s*[元块万亿手点关附])` |
  | 乙字面式 | `(?!\s*(?:整数)?[关附])`（按实施指令原文整体替换） |
  | 乙并集式 | `(?!\s*(?:[元块万亿手点]\|(?:整数)?[关附]))`（原集合保留，仅关/附位允许「整数」插入） |

## ② 核心发现（先读这里）

1. **「整数关口」修复目标达成**：`(?!\s*(?:整数)?[关附])` 两种写法都能让
   「31000整数关口」「30500整数附近」出局，且对「站上 20000 关口」（空格隔断）无影响。
2. **⚠️ 乙字面式有回归面**：若把 :164-165 的整个 lookahead 换成字面式
   `(?!\s*(?:整数)?[关附])`，**元/块/万/手/点 五个排除位随之丢失**——
   对拍样本 ⑧3（144250900 缩样「底部恒指10676点，涨到现在23200点」）实测
   乙字面式回收 `['10676','23200']`，将击穿悬置测试里的
   `test_hk_index_points_and_range_rejected`（该用例 30 用例中现态是过的）。
   **小数前瞻堵得住 NNNNN.dd 点，堵不住整数「NNNNN点」**。
3. **乙并集式零回归**：24 个样本上与 v1.6 行为完全一致，仅多了「整数关口/整数附近」
   的排除能力；6 条红线回归形（`.HK` 后缀/前缀/cashtag/紧贴名/紧贴名+共现）全数保留。
4. **⚠️ 生产库两条 20000 残留，方案乙清不掉**（--reticker 预期核对表的关键修正，
   见⑤）：两行都是「紧贴名通道 + 排除集外后缀」形，且无港股语境——
   - 260113733（2023-09-02，可转债高频）：「单日最高申报笔数**在20000笔**以上」
     ——「笔」不在排除集，「在」不在 _ADJ_NOISE（:171）→ 紧贴名放行；
   - 139380484（2020-01-15，九毛九广告贴）：「**入金20000港币**以上再送300港币」
     ——「币/港币」不在排除集，「金」紧贴放行。
   两行在 v1.6 与方案乙各写法下均实收 `['20000']`（对拍 ⑥/⑥x 实证），
   --reticker 重算后**仍会是 ["20000"]**。
5. **任务描述一处口径澄清**：「腾讯420港元上方应正常收」——420 为 3 位，
   现行三通道（前缀/.HK 后缀/cashtag/紧贴 5 位）**本就不提取 3 位价位**，
   v1.6 与方案乙均返回 `[]`（⑤4 实证），属既有行为非回归；补全形
   「腾讯00700 420港元上方」正常收 `['00700']`（⑤5）。
6. 分支边界干净：「沪指站上3300关口」（4 位）两版皆 `[]`，A 股语境不受 HK 分支影响；
   「沪指站上33000关口」（5 位+关）两版皆 `[]`——关后缀排除先于紧贴名判定，行为合理。

## ④ 结论：方案乙安全性判定

- **判定：可以实施，但必须用「乙并集式」写法，不能用指令字面式整体替换。**
  - 乙并集式：24 样本与 v1.6 全对齐，仅新增「整数关口/整数附近」排除能力；
    悬置测试 30 用例所需语义全覆盖（`test_guankou_suffix_rejected` 断言 2 将转绿）。
  - 乙字面式：核心目标同样达成，但**引入新副作用形态**——「NNNNN点/元/块/万/手」
    排除位整体丢失（⑧3 实证回归），30 用例中 `test_hk_index_points_and_range_rejected`
    会由绿转红，属实施事故。
- 未发现乙并集式的其他新副作用形态；无港股语境的 A 股文本在两版下行为一致。
