# 数据平台规划总案（2026-10-18）

> 触发：老田「认真研究现在的数据源、工作方式依赖、定时拔取任务，全部在一个平台展示，把整个平台规划好」。
> 配套实现：portal/api_dataops.py v2（/api/dataops/overview）+ dataops.html 指挥台。
> 本文是平台的**设计总案**：数据源全景、依赖关系、任务清点、演进路线。

---

## 1. 定位与设计原则

**一句话**：数据池不是一堆文件的集合，而是一条「采集→入池→加工→账本→消费」的流水线；平台（指挥台）是这条流水线的总控视图，Hermes 等调度系统读 `/api/dataops/overview` 一个接口即得全貌。

五条设计原则（v1 落地时验证有效，v2 延续）：

1. **登记表驱动**：COLLECTORS / TASK_GROUPS / POOLS 全部是常量登记表——新数据源/新任务加一行即接入，页面与 API 零改动。自进化的第一形态。
2. **一源一档**：每个数据源登记「载体 / 节奏 / 产出落点 / 健康状态 / 最近动态」五要素。
3. **只读红线**：平台只读（SQLite ro 连接、状态文件读、计划任务 XML 直读），任何治理动作必须走显式工单，不破只读。
4. **fail-visible**：单源探测失败进 errors 数组不静默吞；报告未生成是观测态（200）不是错误；非法参数 400。
5. **口径分离**：`fetched_at`（入库）≠ `created_at`（发帖）——增量统计永远用入库口径，存量看业务口径。

## 4. 依赖关系（数据流 + 关键单点）

```
[外部源]                [L1 原始池]           [L2 加工池]          [L4 消费端]
xtcloud ──TdxSync──▶ tdx parquet 群 ──┐
tushare ─TushareSync─▶ tushare_staging ┤─▶ catalog(233) ──▶ 量化研究(因子/回测 bt2)
雪球 ──XueqiuCrawl──▶ xq_status ───────┼─▶ xq_classified ──▶ 日报→门户/Hermes
股吧 ──GubaCrawl───▶ guba jsonl ───────┘         │
资讯 ──NoticeBackfill─▶ stock_notice ────▶ R3 舆情校准（未来）
                                     ┌─▶ RiskGuard 账本 ──▶ 影子评估
行情+信号 ─BtScan/ChanlunScan─▶ sig_events ─▶ 晨报→推送
agent_platform ─门3 巡检─▶ 账本四件 ─▶ 中枢驾驶舱（并行会话五舱）
```

**关键单点依赖（风险清单）**：
1. **Ollama 11434**（qwen3.5:9b）——分类管道唯一 LLM 依赖；单队列多消费者，熔断让路语义已实证。gpt-oss:120b 到位后成第二模型。
2. **雪球 token**——主+备匿名双池，10-16 曾翻车一次。
3. **xtcloud/tushare 出口**——全部 219 张 part 表的源头。
4. **PG5442**——血缘三表 + pg 布局表；挂了血缘视图降级但采集不挡。
5. **portal 8091**——全部消费端页面与 API 的汇聚点（K-RESTART 三连运维）。

## 5. 平台演进路线

### v1 ✅ 已上线（2026-10-18 上午）
雪球线 11 源采集动线 + 三库数据池 + 三管道状态 + 门户页。

### v2 ✅ 本轮上线（2026-10-18 下午）
- **定时任务总表**：104 任务 × 10 职能组全量入册，Enabled+时刻直读 XML
- **行情仓 catalog 聚合**：233 表 × source 分布（xtcloud 164 / tushare 55 / …）
- `?view=summary` 轻量视图（Hermes 快路径）

### v3（本周，回填追平后开工）
1. **逐表新鲜度**：catalog store mtime → 233 表「最近写入/日均增速」列（数据治理舱核心指标）
2. **依赖图可视化**：§4 数据流图为交互页（读 task_groups+catalog 自动布局）
3. **Hermes 正式接入**：SOUL.md 快路径 + MCP 工具 dataops_overview（18→19 个）
4. **automation 运行史入册**：automation_runs 各 status.log 结构化解析（轮次/产量/熔断史）

### v4（下周，自进化闭环）
1. **治理动作白名单**：pending 重算、断点重置、熔断复位——显式工单+人审，不破只读红线
2. **血缘覆盖度**：catalog 表 × 血缘三表 JOIN，报告血缘覆盖率（并行会话治理指标⑥）
3. **容量治理**：data/ 日增速（GB/日）+ archive 策略（tushare_staging 1GB 批次轮转）
4. **自进化观测**：打标模型 A/B（qwen3.5 vs gpt-oss:120b）、因子探针定期重跑、影子策略漏斗
