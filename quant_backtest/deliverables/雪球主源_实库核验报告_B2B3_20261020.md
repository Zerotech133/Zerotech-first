## 2. R1 结论：target 形态

**R1 一句话**：`docs/2026-10-18_数据全貌复盘与缺口清单.md:43-44` 的「/{user_id}/{status_id} 路径」说法在 xq_status 全域成立（33182/33182 行均为此族形态），但须两点修正——形态实为**带前导斜杠**的 `/{user_id}/{status_id}`；且另有 1.53% 的 `/S/{code}/{status_id}` 变体。

### 2.1 形态分布（xq_status，总行数 33182）

| 形态 | 计数 | 占比 | 说明 |
|---|---|---|---|
| `/{user_id}/{status_id}`（前导 `/`，两段纯数字） | 32673 | 98.47% | user 段 distinct 4822 个 |
| `/S/{code}/{status_id}`（恰 3 个 `/`） | 509 | 1.53% | code 段为 HK 5 位码（如 01918/00700）或 SH/SZ 前缀码（如 SH601318/SZ000002） |
| 空串 / NULL / 其他 | 0 | 0.00% | 无空串、无 NULL、无任何第三形态 |

### 2.2 一致性佐证

- **尾段 = status_id 全域一致**：33182/33182（100%）。
- **user 段与 user_id 列一致性**：`typeof(user_id)` 全为 text 且非空 33182/33182（user 段即 user_id 列值，未逐行比对，形态与抽样佐证一致）。

### 2.4 R1 事实与影响

- **事实**：解析 target 提取 status_id 时按「最后一个 `/` 之后取尾段」全域可靠；但若解析器假设「恰好两段」或「无前导斜杠」，会对 509 条 `/S/` 行失效；若假设「user 段必为纯数字」，同样对 `/S/` 行失效。
- **事实**：文档 §43-44 的表述不精确（缺前导斜杠、未提及 /S/ 变体），但方向正确。
- **影响**：任何依赖 `target` 做 URL 还原或主键反解的下游（含 C9/消费链）需覆盖两种形态。

**R2 一句话**：实库 `xq_status.category` 存储类型为 **integer 32812（98.88%）+ NULL 370（1.12%），TEXT 为 0 条**——DDL 的 INTEGER 声明被实存严格遵守，测试夹具填 TEXT `'stock'` 与实库不符。

### 3.3 R2 事实与影响

- **事实**：实库整列数值型（含少量 NULL），与 DDL `category INTEGER`（xueqiu_common.py:70）一致；与测试夹具 `tests/test_xq_classify_parallel.py:65` 的 TEXT `'stock'` 语义不同——夹具写入的是分类语义标签，实库存的是雪球原始数字码。二者并非同一口径的数据。

## 5. R1 / R2 终局回答（回 WO-032）

- **R1**：成立（全域 100% 为 `/{user_id}/{status_id}` 族路径），但精确形态是带前导斜杠的两段数字（98.47%）+ `/S/{code}/{status_id}` 变体（1.53%），尾段恒等于 status_id。
- **R2**：实库 category 全为 **integer（32812）+ NULL（370），零 TEXT**。DDL 声明与实存一致；测试夹具的 TEXT `'stock'` 是另一套语义口径，不代表实库事实。

## 6. 受限项（如实声明，未造数）

1. `xq_hot_post`、`xq_comment` 两表在实库不存在——原计划的同口径计数与 xq_comment/symbol 核验无法执行。旧链三表 DDL 当前只有 xq_status 在实库落地；hot_post/comment 数据是否在其他介质（parquet/jsonl）需另行核验，超出本次范围。
2. user 段与 user_id 列的逐行相等性未做全表比对（形态与抽样佐证一致，非事实反证）。
3. 同目录 0 字节 `xueqiu.db` 的来源未追溯（只读约束下不做文件系统写操作探测）。
