## 10. 已知局限

1. **运行时拼接的字符串拿不到**。`f"{a}...{b}"` 只能看到字面片段，变量里装的词（例如从 json / db 读出的模板、i18n 词表）不在 AST 里。典型漏网：模板文件、`data/*.json` 里的文案、`picks` 记录里的 `action` 字段值。
2. **跨函数数据流不做追踪**。`def _txt(): return "…"` 被 `push(_txt())` 调用时，只能靠函数名启发式（`_alert_text` 之类）判定，命名不规范就会落到 `sink_unresolved`。
3. **字符串拼接的语义丢失**。`"清仓" + "复盘"` 与 `"清仓复盘"` 都命中，但前者只看到两个片段，报告里截断显示，读起来会像噪音。
4. **docstring 被整体抑制**。它不影响用户，但确实是措辞源头；本报告的建议对所有层一视同仁，实际改动时建议 docstring 与正文同步改，避免二次回流。
5. **交付面（surface）是按文件名 + 出口推断的启发式**，不是真实调用图。`other` 类（31 条）无法自动判断，需人工确认；这也是它们没被排除的原因。
6. **词表是闭集**。同义新词（「轻仓试错」「右侧介入」等）只要不在表内就不会报。第 3 节的全量抑制计数可用于反向抽查。
7. **行号是字符串常量的起始行**，不是词所在行。多行 HTML/模板会偏；所以每条额外给了「词在 N」的命中行（`hit_line`），以它为准。
8. **仓库正在被并发改写**。两次相隔数分钟的扫描，文件数已从 1177 变 1181、字符串数从 201 062 变 202 107。本报告是单次快照，重跑请以新数字为准，结论（核心 54 条、优先 3 条）不受影响。
