## 1. W1 标注快照器 `chanlun_annotate.py`

**做了什么**：给定 code + 日期区间，对区间内**每根 bar** 输出一行结构标注，JSONL 稳定 schema `ann-v1`。

```
{"schema_version","code","date","visible_at","lag_days",
 "fractals":[{type,dt,price,visible_at,lag_days}],
 "bi":[{i0_dt,i1_dt,dir,high,low,confirm_dt,lag_days}],
 "pivots":[{zg,zd,start_dt,end_dt,n_bi,...}],
 "points":[{type,dt,price,detect_date,lag}]}
```

**无前视的实现方式**：主循环 `for m in range(3, i_last+2): st = analyze(bars[:m])`——每行只吃前缀，`first{}` 记录结构首次可见索引并跨行复用（仍是因果量）。`window` 只裁剪"报什么"（`lo = d0 - window` 是因果下界），不影响可见日。

**实跑（600519，2025-01-01~2025-12-31）**

| 项 | 值 |
|---|---|
| 输出行数 | 243（区间内每根 bar 一行） |
| 耗时 | 3.17s（冷跑 5.56s） |
| 每根 bar 平均条数 | 分型 172.50 / 笔 40.83 / 中枢 3.26 / 买卖点 3.53 |
| lag_days(n=53,733) | min=1 中位=1 p90=2 max=66 |
| 买卖点分布 | 1买191 / 1卖7 / 2买132 / 3买284 / 3卖243 |
| 产物体积 | 5.2 MB（`--window 500` 默认；批量建议 `--window 120`） |

**批量自检** `--limit 50 --workers 8`：成功 48 / 失败 2（001237.SZ 有效 bar 113、301699.SZ 36，均 < MIN_BARS=120，与 `chanlun_scan` 同口径，非数据损坏），10,964 行 / 20.3s / 平均 2.68s 每票。

**独立复核（我本人重跑，不采信交付方自述）**：取 2025-03-14 / 06-06 / 11-20 三天，用 `bars[:i+1]` 单独重算，与全量运行同日行比对 `fractals/bi/pivots/points` 四组**逐字段完全一致**。

> 复核过程中先出现 2/3 不一致：原因是我用 `window=0` 对比了默认 `window=500` 的产出，属裁剪口径差异而非泄漏；窗口对齐后 3/3 一致。记录在此，避免后人误判为前视。

**单测** `test_chanlun_annotate.py` 7 条全绿：截断（改乱并删除 `bars[CUT:]` 后结果不变）、幂等（两跑字节相同）、lag≥1、可见日语义、schema 必填与类型、每 bar 一行、过短 bars 抛错。

## 2. W2 标注稳定性 `chanlun_annotation_stability.py`

标注工具的质量指标不是收益显著性，而是**可复现性**：画出来的东西过 1/5/20 天还在不在。

**主口径 all_d0**（每交易日每条标注各记一次观测，11,573,639 条观测 / 43,345 根 K 线 / 50 只 / 11.3s）

| 结构 | @1 | @5 | @20 | 判定 |
|---|---|---|---|---|
| 笔（全部） | 0.998 | 0.992 | 0.989 | PASS |
| 　└ 非末笔 | **1.000** | **1.000** | **1.000** | 硬上界 |
| 　└ 末笔 | 0.934 | 0.714 | 0.608 | 诊断 |
| 中枢 | 0.999 | 0.997 | 0.996 | PASS |
| 信号（B 口径） | 1.000 | 0.999 | 0.999 | PASS |
| 信号（A 口径，对照） | 0.998 | 0.990 | 0.985 | 诊断 |

**首见队列**（每个结构只计一次，"画出来之后还在不在"）：笔 @5 0.782 / @20 0.580；中枢 @20 0.778；B 信号 @20 0.963（PASS）；A 信号 @20 0.525。

**结构性结论**：不稳定**100% 集中在末笔**。已定型的笔存活率恰好 1.000（134.9 万条观测零例外），因为 `chanlun_bi.py:44-46` 只改 `bis[-1]` 的 `e_dt/e_price`，从不回溯改写历史笔；中枢 zg/zd 成形即固定（0.996）。所以"笔的稳定性"实为"存活到被下一笔锁定"的概率——**未锁定的结构不该被当作已定型的标注画出**。我独立 grep `chanlun_bi.py` 确认该实现（`bis[-1]` 两处 + `bis.append` 一处），与实测吻合。

**与 v6「44% 消失」的对账——这是对前序结论的一处更正**

| | 本轮实测 | v6 已发布 | 差 |
|---|---|---|---|
| Jaccard A | 0.527 | 0.560 | −0.033 |
| Jaccard B | 0.969 | 0.987 | −0.018 |
| lag0（dt 当天可见） | A 0 / B 0 | 0/229、0/299 | 一致 |
| 确认滞后中位 | A 1.0 日 / B 16.0 日 | A 2 日 / B 16.5 日 | 抽样差异 |

**44% 不等于"44% 的信号在重放中丢失"**。Jaccard 是对称的，差额全部来自**反向幽灵信号**：在线出现过、定型后不存在——A 口径 472/997（**47.3%**）、B 口径 25/804（3.1%）。机制指向上游：A 的三类锚取 `bis[idx[pv["e_dt"]]-1]`，而 `pv["e_dt"]` 随中枢延伸平移（`find_pivots` 的 end_j 推进），锚点一移，信号身份就变；B 的判定边界是固定的 (zg, zd)，所以几乎无幽灵。

即：**v6 的 0.560 应读作"A 口径有近半数是会自我否定的幽灵标注"，而非"信号被重放抹掉 44%"**。残差 −0.033/−0.018 来自抽样标的与在线侧定义（v6 用 20 只另一批，本轮 50 只 seed=42）。

## 4. W4 遗留三项收口

**① GoldShadow 禁用后验 —— 通过**

`C:\Temp\gold_shadow_task.log` 全文尾部为 `starting/exit=0 2026-11-04T18:30:31`，至 **18:58 仍无 2026-11-05T18:30 行**。任务已停用，昨日为最后一条。v7 留的检查点成立。

**② `cross_poll.py` 的 `detect_date or dt` 回退 —— 不改断言，改可观测**

原待办想"断言化"，本轮否决：断言会在数据缺列时让整个轮询崩掉，而回退方向只是把结果推向"更可能判 stale"（保守侧），代价与收益不对等。改为抽 `_dd_of(r)` 纯函数 + 一次性告警（`logging.getLogger("cross_poll").warning`，仅首条打印并累计 `_DD_FALLBACK["n"]`），两处调用点（:246 池最新检出日、:627 chanlun 锚点）统一。

验证：`_dd_of({'detect_date':'2026-11-05','dt':'2026-10-01'})` → `2026-11-05`（优先取确认日）；连续两条缺 `detect_date` 的行 → `fallback_n=2` 但**只打 1 条 warning**。AST 通过，旧写法残留 0 处。

**③ `gold_signal_shadow.py` 前视 —— 加失败快守卫，不改口径**

原决策是"任务停用、样本 0，改逻辑无法被数据验证，只写注释"。本轮补一道不涉及口径的防线：结算循环前若 `dt != detect_date` 直接 `raise RuntimeError`，错误信息写明正确改法。

理由：任务一旦重启，第一笔真实信号就会因 `detect_date=today` 与 `dt` 不等而**立即崩**，而不是继续产出一份虚增 0.80pp 的漂亮面板。宁可崩，不可静默虚增。journal 文件至今不存在（不是 0 条，是文件不存在），故当前零触发。
