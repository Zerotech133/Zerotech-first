## 1. L-01 裁判层入锁

**问题复述**：`portfolio_sim.py` 是 `total_return` / `max_drawdown` 的唯一实现，却不在 8 个 `engine_files` 里。改引擎 = 换了待判对象，会被 `verify_baseline.py` 抓住；改裁判 = 换了尺子，却一路 PASS。

**做法**
1. `baseline_lock.json` 的 `frozen_manifest.engine_files` 增 `portfolio_sim.py`，字段含 `role=judge` + `note`；其余 8 条补 `role`（`qpzm_backtest.py`=engine，其余=anchor）。新增顶层 `judge_note` 与 `n_files_role`。
2. `verify_baseline.py`：检查顺序改为 judge→engine→anchor；每条 check 带 `role`；文本输出加 `[JUDGE]/[ENGINE]/[ANCHOR]` 前缀；裁决定语区分"裁判变了"与"普通文件变了"。

**实跑**
```
[OK  ] JUDGE  portfolio_sim.py
[OK  ] ENGINE qpzm_backtest.py
[OK  ] ANCHOR ../k_stock/paper/qpzm_adapter.py
...
裁决：PASS
```

**守卫测试**（两条，任一失效即红）
- `test_judge_file_is_frozen_in_lock`：锁里必须有 judge，且 md5 == 当前文件 → **改了不重冻就红**。
- `test_verify_flags_judge_change`：把锁里 judge 的 md5 改成 `0`×32，`check_fingerprint` 必须 FAIL 且首个报警项 role=judge、note 含"裁判"。这条同时验证了"报警没有静默吞掉"。

**残留**：锁里固化的 md5 是 2026-11-07 的状态。下次正规重冻时，judge 项要跟 engine 一起复核，不能只跑引擎。

## 2. L-02 账本版本化 + 并列回放

**问题复述**：`execution_ledger.jsonl` 3843 行跨两套 SL/TP 规则（v1.0.3 用含当日分钟高点的 `hi_eff`，v1.0.4 只用截至昨日收盘的 `hi_prior`），行内无版本标记，跨版本算胜率/均值就是把两把尺子混算。

**做法**
1. 回填：3843 行（execution）+ 242 行（guardian）全部补 `rule_version=v1.0.3`。逐行比对除该字段外完全一致，**行数守恒、坏行 0**；回填事实写进 `paper/ledger_rules_manifest.json`（含时间、md5 前后、备份路径），避免以后误认为该标记是运行时写的。
2. v1.0.4 代码：`RULE_VERSION` 常量，execution 行与 guardian 行都自写版本。
3. 并列回放：`replay_ledger_v104.py` 用 v1.0.4 规则重跑 126 个交易日 → `execution_ledger_v104.jsonl`，**不动原账**。

**回放结果**

| 指标 | v1.0.3 | v1.0.4 |
|---|---|---|
| 行数 | 3843 | 3843 |
| 触发（SL+TP） | 2213 | 2211 |
| SL | 1775 | 1775 |
| TP | **438** | **436** |
| hold | 1630 | 1632 |
| 触发笔均值 | −3.1959% | −3.1963% |

差异 2 笔，全部是 **TP → hold**：`20260817 002546.SZ`（entry 20260812）、`20260923 300833.SZ`（entry 20260923）。两笔都是旧版用"当日已站上成本×1.02"这个含当日高点的条件放行止盈，v1.0.4 去掉该日内前视后不再触发。

**这个数字值得单独说**：3843 笔里只有 2 笔受影响，说明两套口径在实盘中极少分叉——但"极少"不等于"没有"，而且分叉时报告说"已止盈"、账本记"持有"，这种矛盾一旦出现在对账现场就没法解释。修复的意义在一致性，不在这 2 笔的收益差。

## 3. L-03 行业上限：代价算出来了，结论是"不要加"

**做法**：`_dividend_defense.py` 加 `--industry-cap N`（默认 0=不限）。实现上三档策略都先出完整排序序列，再按上限贪心取；**候选不足额时放宽补足**（硬卡上限等于变相减仓，会让口径悄悄变）。每期持仓日志增 `n_industry` / `top_industry` / `top_industry_n`，可事后查集中度。

**三组对照**（同一策略、同调仓日、同成本，只改上限；20230801~20261106）

| 约束 | 年化 | 最大回撤 | Sharpe | 月胜率 | 换手 | 最大行业(均) | 行业数(均) |
|---|---|---|---|---|---|---|---|
| **不限（默认）** | **+18.09%** | **−13.43%** | **1.17** | **61.5%** | 36.0% | 9.9 只 | 9.4 |
| 单行业 ≤3 只 | +13.43% | −17.70% | 0.90 | 59.0% | 42.8% | 3.0 只 | 14.6 |
| 单行业 ≤2 只 | +13.04% | −18.05% | 0.87 | 56.4% | 44.0% | 2.0 只 | 15.9 |

**结论与预期相反**：上限确实把集中度压下去了（最大行业 9.9 → 3.0 只，行业数 9.4 → 14.6），但代价是**年化 −4.66pp、回撤反而恶化 4.27pp、换手 +6.8pp**。

原因不难理解：这档的"防御性"本来就来自银行/公用事业这类低波行业的集中。把它们摊薄，换进来的是波动更高的红利品种——**去掉压舱石不等于更安全**。分年度也印证：2024 年 40.59% → 33.27%（银行大涨那年被削），2025 年 7.75% → 2.54%。

顺带一个反常现象：A 档（纯高股息）和 C 档（综合打分）加上限反而变好（A −0.73→+0.95，C 6.46→9.92）。因为这两档本身选股质量差，分散恰好掩盖了一部分个股风险。**同一约束对 B 有害、对 A/C 有益，说明它不是"风控开关"，而是一个会改变策略本质的自由参数**——所以默认关闭。

页面已加「行业上限」面板（表 + 结论条），风险要素里"行业集中 50%"那条的应对从"需人工设行业上限"改成实测结果。

## 5. P2-a `gold_signal_shadow` 结算前视

**原状**：`i0 = idx[j["dt"]]`（结构端点日）→ `entry = opens[i0+1]`，等于提前 1~3 日知道端点；v7 报告实测 d20 虚增 0.80pp、d5 胜率 97.0%→75.8%。旧"防线"是发现 `dt != detect_date` 就 `raise` —— 只能防不修，还会崩掉整日任务。

**改法**：新增纯函数 `settle_anchor(dts, j)`：
- 有 `detect_date`：`anchor` = 第一个 ≥ detect_date 的交易日；若 detect_date 本身不是交易日（周末/停牌），`anchor` 取它之前最后一根 bar，**入场仍是其后第一根**（样本不丢）。
- 无 `detect_date`（旧 journal 行）：退回 `dt`，标 `settle_basis=legacy_dt`，审计时一眼可辨。
- 面板记 `settle_basis` / `confirm_lag_bars`，顶部加 `settle_rule` 声明"legacy 行不可与新行混算"。

**测试**（`test_gold_settle.py`，6 例）：同日入场、滞后 1 根 bar 时入场后移、非交易日不丢样本、旧行回退并标注、detect 早于首根返回 None（挂 pending 不瞎结算）、以及**合成行情下新口径收益必然低于旧口径**（前视量的存在性证明）。

## 7. P2-c 统一原子写

**新增 `atomic_io.py`**：`replacing(path)` 上下文管理器，`mkstemp` 唯一临时名 + `os.replace` + 6 次退避重试 + 异常清理；`write_text` / `write_bytes` 便捷封装。模块头写清了三个版本的压测数据（固定名 454/480 失败、带 pid 218/480 失败、mkstemp 0 失败），避免以后有人"优化"回去。

**迁移**：写了一个只做机械替换的迁移器（只处理"写 tmp → `os.replace`"同构写法，其余**主动跳过**并列出原因），应用到 10 个文件、**19 处**：`chanlun_ext_backfill`(4)、`chanlun_annotate`(1，另 2 处跳过)、`chanlun_hold_sensitivity`、`chanlun_healthcheck`、`chanlun_gate`、`chanlun_exit_policy`、`chanlun_cost_model`、`chanlun_beta_tv`、`p_g_robot`、`council_sim`。全部 `py_compile` 通过。

**`_json_safe.write` 接入统一实现**：页面 JSON 有 4 个生产者，任一被并行重跑都可能互踩；现在内容合法（NaN→null、`allow_nan=False`）与写入原子性在同一处保证。

**计数**：仓内固定 `.tmp` **172 → 153 处**（同口径排除 venv/archive/test/maintenance），候风链路 **0 处**，并有测试拦新增。
