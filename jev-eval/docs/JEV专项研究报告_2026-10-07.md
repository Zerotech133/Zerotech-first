## 四、设计亮点（值得沉淀为团队规范的部分）

1. **零侵入原则**：只读 `v2_alert`/`v2_candidate_pool` 等表，不改 zhice 一行代码，psycopg2 直连失败自动降级 `docker exec psql`（`jev_common.py:182` `%s → :'pN'` 变量绑定转换，防注入）。
2. **降级链条完整**：Jev 不可用 → CRITICAL 直推不过模型；DB 不可用 → 本轮放弃不标 seen；推送失败 → 死信审计 + 有界重试 5 轮放弃（`jev_gate.py:236-271`）。
3. **幂等与自愈**：`jev_gate_seen` DB 表主键去重，重启/换机不重推；`gate_seen.json` 一次性迁移入库后改名留档；NOTIFY 触发器 DB 重建后启动自愈。
4. **防未来函数回放**（`replay_review.py:12-15`）：公告窗口、持仓、regime、收益全部 as-of pool_date 取数，回放结论可信。
5. **影子期纪律**：所有判定只标注不拦截，明确「必须用自己的 (快照,判定,收益) 三元组重新验证后才进阶段 2」——这是正确的 AI 引入姿势。

## 五、问题清单（按严重程度）

### P1-1 校准闭环欠回填（影响影子期毕业判断）

`triples_outcome.jsonl` 仅 61 条 / 874 条判定 = **7% 覆盖率**。5 日收益窗口的候选早就到期了，回填任务没有跟上节奏。后果：**影子期无法毕业**——没有足够的 (快照,判定,收益) 三元组，就永远算不出「Jev 否决组 vs 放行组收益差」，阶段 2 半自动没有决策依据。
**建议**：把 `signal_review_gate.py --backfill` 挂成每日计划任务（收盘后），并加覆盖率告警（回填率 <50% 推提醒）。

### P1-2 网关日志断链（排障能力受损）

`jev_gate.log` 停在 09-24 且是乱码（PowerShell 以 UTF-16 重定向 + 缺 key 报错）。当前 9101 端口在听说明网关活着，但**它的 stdout 去向不明**——若按你环境的老坑（pythonw+DETACHED 静默秒死、PS 重定向编码坑），下次网关异常将无日志可查。
**建议**：确认当前网关的拉起方式与 stdout 重定向路径；日志统一走 Python 侧 `log()` JSON 单行（`jev_common.py` 已具备），PS 层只负责拉起，不再重定向中文输出。

### P1-3 评测基线 16 天未回归

`results/` 只有一份 09-21 的结果。模型端（`jev-latest`）若静默升级，题型准确率可能漂移，而三个生产组件的阈值（`URGENT_THRESHOLD=0.8`、`REVIEW_KEEP_THRESHOLD=0.35`）都锚定在这份基线上。
**建议**：每月跑一次 `jev_eval.py --repeats 3`（成本 3.6 万 token，可忽略），结果異常（准确率 <90% 或 noul/choice <95%）触发告警。

### P2-1 少量 SQL 拼接（当前低风险，原则性瑕疵）

`signal_review_gate.py:95` 用 `%d` 拼接 `LOOKBACK_POOLS`、`replay_review.py:60,64,74` 用 f-string 拼接 `pool_id`/market。来源均为内部常量/内部表主键，实际注入风险低，但与 P1-7「外部输入必须参数化」的自定纪律不一致。
**建议**：顺手统一为参数化，避免未来复制粘贴成隐患。

### P2-2 阈值散落硬编码

`REVIEW_KEEP_THRESHOLD=0.35`、`crowd_p>=0.7`（`jev_qd_bridge.py:59,393`）硬编码且注释自认「影子期仅标注」。网关侧已做环境变量覆盖（P2-3），桥侧未对齐。
**建议**：影子期毕业后统一收敛到 env / 配置文件。

今日 `n1_report_2026-10-07.txt`：**备份完成但 failed=4**（`[FAIL] backup DONE but failed<>0`），N1 巡检已捕获并推送 `N1_CHECK_FAIL_20261007` 告警。说明备份→告警链路本身工作正常，但**4 个失败文件的原因待查**（建议看 `backup_daily.ps1` 对应轮次的日志）。
