## 2. 你要做的（二选一）

### A1 · 给当前账号提积分/开 anns_d 接口（推荐）

Tushare `anns_d` 需 2000+ 积分（见 <https://tushare.pro/document/1?doc_id=108>）。
充值/做任务提积分后，**不用改代码、不用改配置**，只跑一条命令确认：

```powershell
& "C:\Program Files\Python311\python.exe" C:\aios\tools\tushare_probe.py
```

期望输出（关键两行）：

```
*trade_cal   0  OK
*anns_d      0  OK          <- 权限到位
结论：OK
```

`anns_d` 变成 OK 后再重启一次消费方（让进程重新探测公告源）：

```powershell
Start-ScheduledTask -TaskName 'JevRestart'
```

下一轮 review 日志应出现 `公告源=tushare`（10 分钟内）。

### A2 · 若你手上有「原本就有 anns_d 权限」的那个 JEV 账号令牌

直接灌进来，工具会先验证再落盘（验证不过不写）：

```powershell

    --key TUSHARE_TOKEN --stdin --probe
# 粘贴令牌后回车（不回显）
# 期望：probe code=0 / anns_d OK / OK 已写入并回读校验通过
Start-ScheduledTask -TaskName 'JevRestart'
```

## 4. 从今天起不会再静默

新增 `jev-eval/jev_source_guard.py`，接在每日 07:40 的 `JevCoverageDaily` 任务里
（不新增计划任务，同一个任务第二段）：

| 情形 | 判定 | 退出码 |
|---|---|---|
| `公告源=tushare` | OK | 0 |
| `40203/40204` 无接口权限 | ⚠ WARN + 「提积分/换源」处置建议 | 1 |
| `40101/40102` 令牌失效 | 🔴 CRITICAL + 换令牌命令 | 2 |
| `公告源=none` 但无错误码 | ⚠ WARN（令牌没注入） | 1 |
| 最后一轮超 6 小时 | 🔴 CRITICAL（review 门停摆） | 2 |
| 日志里没有公告源记录 | ⚠ WARN（门没跑 / 日志被清） | 1 |

推送与其它守卫同渠道（`backup_alert.py`）。**同因 3 天内只推一次**（避免每天重复喊同一句），
原因变化立即推；状态存 `review_data/source_guard_state.json`。
输出：`logs/source_daily.jsonl` 一行 JSON，`logs/jev_coverage_task.log` 记 `source exit=...`。
