# JEV DB 通道说明（2026-11-05 / 任务单 JEV-DSN-20261105）

> 一页纸：通道优先级、开关、排障三步、历史四类故障归因。
> 代码权威：`jev-eval/jev_common.py`（DB 直连段）、`jev-eval/tests/test_jev_db_channel.py`。

## 1. 通道优先级（降级已改为 opt-in）

| 顺序 | 通道 | 触发条件 | 结果类型 |
|---|---|---|---|
| 1 | **direct**：psycopg2 直连 `ZHICE_PG_HOST:ZHICE_PG_PORT`（默认 127.0.0.1:5446） | 正常路径 | 原生类型（int/datetime…） |
| 2 | **docker**：`docker exec zhice-db psql`（`%s`→`:'pN'`） | 仅当 `JEV_DB_DOCKER_FALLBACK=1` | **全部字符串** |
| 3 | **denied**：抛 `DBChannelDeniedError` | 直连失败且降级未开（**默认**） | 异常，含 DSN + 排障提示，无口令 |

- 5432 是 infinity 容器占位，**不是 zhice PG**：命中即抛 `DBChannelConfigError`（import 期就炸，不进降级链）。
- 历史故障里 51 条 `Invalid command: syntax error, unexpected IDENTIFIER` 就是误连 5432 的产物，看着像 SQL 错，实为连错库。

## 2. 开关（env）

| 变量 | 默认 | 含义 |
|---|---|---|
| `JEV_DB_DOCKER_FALLBACK` | `0` | docker psql 降级总闸。`0/false/no/off/空` = 关；其它非空串 = 开 |
| `JEV_DB_WARN_THROTTLE_SEC` | `60` | 同类直连失败 WARN 的最小间隔（每进程每 `exc_type` 一条，压掉的数进 `suppressed`） |
| `ZHICE_PG_HOST` / `ZHICE_PG_PORT` / `ZHICE_PG_USER` / `ZHICE_PG_DB` | 127.0.0.1 / **5446** / zhice / zhice_os_v2 | DSN 覆盖 |
| `ZHICE_PG_PASSWORD` | 空 | 口令；空则回落 `C:\项目\zhice-os-v2-windows-20260920\code\.env.local` 的 `V2_DB_PASSWORD`（source=file），再回落旧默认（source=default，仅兜底） |
| `ZHICE_PG_CONTAINER` | `zhice-db` | 降级通道 `docker exec` 的容器名 |

## 3. 可观测

启动自检（gate / review 的 `main()` 第一行 `jc.log_db_channel()`）：一条 info 日志 `msg="DB 通道自检"`，带
`channel / host / port / dbname / user / container / pw_source / driver / fallback_enabled / healthy / probe_error`，**无口令**。
自检内部做一次 `SELECT 1` 判定实况，失败只记 WARN + `probe_error`，**不会让进程起不来**；
只想读状态不连库时用 `log_db_channel(probe=False)`。

`/metrics`（`start_metrics` 端口）：

```
jev_db_queries_total{mod,ok,channel="direct|docker"}   # 按通道分别计数，直连/降级不再混算
jev_db_degraded_total{mod,reason="docker:<Exc>|denied:<Exc>"}
jev_db_channel{mode="direct|docker"}                   # 1=当前生效，两者同 0 表示 denied/未用
```

健康面（健康卡 / `--probe` 复用，不发起连接、不抛异常）：

```python
import jev_common as jc
jc.db_channel_report()
# {'mode': 'direct|docker|denied|unknown', 'fallback_enabled': False,
#  'degraded_total': 0, 'denied_total': 0,
#  'last_failure': {'at','op','exc_type','errno','host','port','dbname','user','pw_source','error'} | None,
#  'port_error': None, 'provenance': {...脱敏...}, 'healthy': True}
jc.log_db_channel()        # 启动自检：探一次 SELECT 1，打一条 info 日志并返回同款 dict
jc.probe_connectivity()    # 追加 "channel"（同上）与 "effective_overall"
```

> `probe_connectivity()` 的 `overall` 表示「通道潜能」（直连不通但 docker 在 → `degraded`）；
> `effective_overall` 才是本进程真实结局（降级未开 → `down`）。两者不一致时说明「能降级但没放行」。

## 4. 排障三步（直连失败时按此顺序看）

1. **口令来源漂移**：看 `pw_source`（env / file / default）。10-30 口令轮换后 env 与
   `.env.local` 未同步即报 `password authentication failed`（历史 100 条）。
   → 同步 `V2_DB_PASSWORD` 或显式 `ZHICE_PG_PASSWORD`。
2. **容器/端口**：`docker ps --filter name=zhice-db` 看是否在跑、`docker port zhice-db` 看宿主映射
   是否为 **5446**；`Connection refused`（历史 13 条）即容器未起或映射变了。
3. **端口写错**：确认 `ZHICE_PG_PORT` 不是 `5432`（infinity 容器）。命中会直接
   `DBChannelConfigError`，提示改 5446。

Docker Desktop 重启窗口（`Software caused connection abort 0x2714` / `server closed the connection`，
历史 9 条）属基础设施瞬断：直连会在下一轮自动重连，不需要人工干预；若不希望窗口期报错，
可临时 `JEV_DB_DOCKER_FALLBACK=1` 放行降级。

## 5. 历史故障归因（`jev-eval/logs/*.log`，2026-10-30 ~ 2026-11-04，共 173 条「DB 直连失败」）

| 归因 | 条数 | 主因 | 定性 | 现状 |
|---|---|---|---|---|
| `password authentication failed` | 100 | 口令轮换后 env/文件未同步 | **配置** | 已由 `.env.local` 文件回落链修掉 |
| `Invalid command: syntax error, unexpected IDENTIFIER` | 51 | 误连 5432（infinity 容器） | **配置** | 由 `ZHICE_PG_PORT=5446` + 本次 fail-fast 根治 |
| `Connection refused` | 13 | 容器未起 / 端口映射变化 | 基础设施 | 由通道自检 + 告警可发现 |
| `Software caused connection abort` / `server closed` | 9 | Docker Desktop 停/重启 | 基础设施 | 瞬断，下一轮自愈 |

结论：**~87% 是真配错（口令/端口），不是容器挂**——所以静默降级一直在掩盖配置漂移；
剩下的 13% 是容器/宿主机瞬断，直连本身会自动恢复。

## 6. 生产切换与回滚

1. 合并 worktree 分支 → 部署 `jev-eval/jev_common.py`。
2. env 变更（`jev-gate.env.ps1` / 任务计划环境）：
   - **不需要**新增任何变量即为新默认（降级关）。
   - 建议显式写 `JEV_DB_DOCKER_FALLBACK=0` 留痕；维护窗口可临时改 1。
   - 确认 `ZHICE_PG_PORT` 未设或 = 5446（若设了 5432，进程会**启动即失败**，这是设计）。
3. 需重启 gate / review 常驻进程才生效（模块常量 `DB_DSN` 在 import 期定型）。
4. 验证：启动日志出现 `"msg": "DB 通道自检"` 且 `channel=direct`；`/metrics` 里
   `jev_db_channel{mode="direct"} 1`；`jev_db_degraded_total` 不再增长。
5. 回滚：还原 `jev_common.py` 即可（无数据/无迁移）；若只想恢复旧行为而不回滚代码，
   设 `JEV_DB_DOCKER_FALLBACK=1` 并重启进程。
