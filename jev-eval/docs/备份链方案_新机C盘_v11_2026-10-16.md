## 1. 背景与目标

换机事实：新机单 C 盘（无 D:/E:），用户 `t`（旧机 Administrator），无 git，无旧机注册表键（HKLM:\SOFTWARE\AIStation\BackupDeploy 不存在）。旧备份链（backup_daily.ps1 v10）的落点、清单、巡检路径全部指向不存在的盘符与容器，处于静默失效状态。

目标：在单 C 盘约束下重建「每日备份 → 镜像 → 云异地」三级链路，保持既有质量门与响亮告警设计不变，巡检（N1）与转发（AlertPush）全链路可用。

## 2. 三级落点设计

| 层级 | 路径 | 留存 | 设计理由 |
|---|---|---|---|
| T1 原件 | `C:\aios\backups` | 4 集 | 项目树内。单盘机与源同卷是物理上限，靠 T2/T3 补偿 |
| T2 镜像 | `C:\backups_mirror` | 4 集 | **盘根目录，刻意隔离项目树**——整树误删/勒索加密时不连坐 |
| T3 异地 | `C:\Users\t\OneDrive\backups_mirror` | 2 集 | 唯一真异地（OneDrive 云端）。集小留少控同步压力 |

单集实测 680MB / 6 文件（旧机 2GB / 10 文件，v11 裁剪后 -66%）。

## 4. 质量门与告警链（全部保留）

- 15KB dump 质量门：zhice_os_v2 空库/异常期间**照常 FAIL 响亮提醒**（用户决策；实测当前库含 17KB schema，暂未触发）
- gzip 完整性全量校验、明文残留守卫

## 6. 凭据与密钥管理

- AES 密钥：新机重新生成（旧 .enc 异机本就不可解，无孤儿密文风险），32 字节随机，`C:\Users\t\.backup_aes_key`，ACL 限 t 用户，**纸质副本为唯一退路**（丢失即全部历史 .enc 不可恢复，脚本会 ABORT+flag 防止覆盖真相）

演练中修复的 4 个坑（均已固化进脚本/MEMORY）：

1. N1 用 `-match 'OffsiteSync'` 咬不住 `offsite_sync.ps1`（下划线断词）→ 双形态 `'OffsiteSync|offsite_sync'`
2. Neo4j Community 无 STOP/START DATABASE（Enterprise-only）→ 停容器 + sidecar dump 方案
3. sidecar 的 /data 挂 `:ro` 被镜像 entrypoint 的 chown 中止 → 去 `:ro`
4. n1_check.ps1 中文任务名参数在 PS 5.1 无 BOM 下解析乱码 → 转 UTF-8 BOM

## 9. 恢复操作速查

```powershell
# 解密 zhice_db dump（需 .backup_aes_key）
#   Unprotect-File 逻辑见 backup_daily.ps1 §Protect/Unprotect（AES-256-CBC+HMAC-SHA256）

# 恢复 neo4j（停容器后反向 sidecar load）
docker stop neo4j-kg
docker run --rm -v neo4j_kg_data:/data -v C:\aios\backups\neo4j:/dumps neo4j:5 `
  neo4j-admin database load neo4j --from-path=/dumps --overwrite-destination
docker start neo4j-kg
```
