```text
            自洽配对 = OpenAPI 直连（apps[0] 凭证 + push_targets「个人」）

15:45:49    JevStack 自动重拉（含 15:32 版，但不含本次 13 处修复）
15:55-15:57 13 处修复落盘 → 旧进程仍跑旧代码
16:01       UAC taskkill 换血：gate 22884 / review 42444 / qd 35276
16:02:03    JevStack 重拉全修复版（born > mtime，验证成立）
16:07       e2e 推送 OK，链路闭环
```

### 核心教训（已回写 MEMORY 判例）

1. **修复写盘 ≠ 生效**：进程出生时间必须 > 文件 mtime；`start_jev_stack.ps1` 只「缺则拉」，无 mtime 重启逻辑，修码后必须杀旧换血
2. **杀 S4U Session0 进程需 UAC**：`Start-Process cmd -Verb RunAs taskkill /F /PID ...`（降权 token 杀不动）
3. **端口判活法**：9101-9104 四端口判活可靠；CIM/Win32_Process 对 S4U Session0 进程枚举不可靠（两次实证：四件套全漏、CommandLine 全 null）
4. **except pass 豁免边界（C2批2）**：只豁免可预期无害分支；ALTER TABLE 的 OperationalError 仅 duplicate column 属预期
5. **e2e 验证法**：`import jev_gate; jev_gate.push_feishu(alert, verdict)`——main() 在 `__main__` 守卫内，import 安全
