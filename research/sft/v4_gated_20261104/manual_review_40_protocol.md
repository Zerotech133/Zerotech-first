# 206 holdout 人工抽检 40 条 · 审阅协议 v1

- 状态：预注册，待 RAG 206 完成后执行
- 审阅对象：`manual_review_40.csv` 的 40 条 holdout
- 输入文件（自动生成）：`manual_review_40_auto_filled.csv`
- 自动列：base/prod_rag 预测、char_f1、检索来源
- 人工列：`base_correct(0/1)`、`rag_correct(0/1)`、`winner(base/rag/tie)`、`citation_ok(0/1)`、`time_sensitive(0/1)`、`reviewer`、`notes`
- 约束：人工列不得由脚本、模型或本协议代填；本协议只规定口径。

## 一、审阅顺序

1. 先读 `question` 和 `reference`，不先看自动 char_f1。
2. 分别读 base 与 RAG 回答，判断是否真正回答了问题。
3. 再核对 RAG 的 `prod_rag_sources` 是否支持回答中的事实/数字；找不到依据即为不可追溯。
4. 最后填人工列，并在 notes 写简短理由；有分歧时保留原判断并记录。
5. 全部 40 条完成后才能汇总；不得只看自动分或只看“看起来更好”的样本。

## 二、字段口径

### base_correct(0/1)
- 1：回答了问题，核心事实/数字无明显错误，未出现答非所问；允许 minor omission，但须在 notes 说明。
- 0：答非所问、核心事实错误、关键数字错误、把资料外内容伪装成资料内事实，或严重时间敏感误导。
- 不确定：先记 0 并在 notes 写“需复核”，不得留空。

### rag_correct(0/1)
- 同 base_correct 的标准；不因“引用了来源”自动给 1。
- 若资料不足而明确说“资料无法回答”，且 reference 也支持“资料不足”，可判 1；若 reference 有答案而 RAG 拒绝，判 0。

### winner(base/rag/tie)
- 只比较事实正确性与问题完成度，不比较文风、长度、格式。
- 两者都对且质量相当：tie；两者都错：tie；一好一坏：好者胜。
- 不得用 char_f1 代替判断。

### citation_ok(0/1)
- 仅评 RAG；base 行留空。
- 1：回答中的关键事实/数字能在给出的来源中找到直接依据，来源与结论一致。
- 0：来源不支持、来源与结论矛盾、编造来源、把检索片段之外的内容说成来源内容。
- 若 RAG 回答没有引用任何来源：0（除非回答只是“资料不足”且无需引用）。

### time_sensitive(0/1)
- 1：回答依赖“今日/昨日/本周/当前点位/最新政策”等会快速失效的信息，或 reference 本身是时间敏感材料。
- 0：概念、方法、定义类内容，不依赖当前日期。

## 三、汇总与判定

先汇总，不直接改生产：

1. 正确数：`sum(base_correct)` vs `sum(rag_correct)`。
2. 胜负：`winner` 的 base/rag/tie 计数。
3. 引用：RAG 中需要事实依据的样本，`citation_ok=1` 的比例；单独列出 0 的样本。
4. 严重错误：列出 base 对/RAG 错、RAG 答非所问、RAG 编造来源的 id。
5. 时间敏感：列出 `time_sensitive=1` 且 RAG 新增误导的 id。

建议给人类的结论只能是以下之一：
- **建议不切 canonical**：RAG 正确数不高于 base，或出现新的严重错误/不可追溯引用；
- **建议进入切换评审**：RAG 不差于 base，引用可追溯，无新增严重错误；仍需人类明确批准；
- **证据不足**：40 条中大量不确定/无法核对，先补样本或补资料。

## 四、与自动指标的关系

- 206 paired char_f1/bigram/number 只作辅助；不能替代事实正确性。
- 若自动指标上升但人工抽检出现“更流畅但错误/编造引用”，结论应为不切换。
- 若自动指标持平但人工抽检显示 RAG 引用更可追溯、答非所问更少，可提交人类讨论；不得自动切换。

## 五、禁止

- 不自动填人工列；
- 不自动切 canonical；
- 不自动重启生产 RAG 服务；
- 不因平均分上升上线；
- 不把本协议当人类批准。
