# CnOpenData 数据源档案 · 字段契约 v1

> 用途：把 CnOpenData（运营主体：河南汉数信息技术有限公司）上与**股票、金融**相关的数据集与 API 登记为可查档案，作为「是否采购 / 是否接入 / 接到哪个板块」的决策底账。
>
> **边界（硬约束）**：本档案只登记**公开目录页上的元信息**（数据集名称、简介、时间覆盖、量级、更新频率、获取方式、字段要点、链接）。**不下载任何数据内容，不登录、不调用付费接口、不使用他人账号或 Cookie。** 直售数据必须走采购授权后才可能进入接入阶段。

## 一、记录结构（registry.json）

```json
{
  "meta": {
    "source": "CnOpenData",
    "source_operator": "河南汉数信息技术有限公司",
    "generated_at": "ISO8601 +08:00",
    "scope": "股票/金融相关数据集与 API",
    "boundary": "仅公开元数据，不含数据内容"
  },
  "datasets": [ { ...record... } ]
}
```

## 二、单条记录字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | str | 是 | `cnod-<slug>`，slug 取 URL 末段，去 `.html`，小写，非字母数字转 `-` |
| `layer` | enum | 是 | `core`=直接股票/金融；`factor`=可做因子补充；`context`=宏观/产业背景 |
| `category_group` | str | 是 | 一级分类，如「SSRD上市公司与资本市场」 |
| `category` | str | 是 | 二级分类，如「A股上市公司另类数据」 |
| `name` | str | 是 | 数据集名，原文 |
| `url` | str | 是 | 详情页绝对链接 |
| `desc` | str | 是 | 简介，压到 120 字内，保留关键口径 |
| `coverage` | str | 是 | 时间覆盖，如 `1992-至今`；页面未写填 `未标注` |
| `volume` | str | 是 | 量级，如 `发帖7.78亿/回帖15.20亿`；未写填 `未标注` |
| `frequency` | enum | 是 | `实时`/`日`/`月`/`季度`/`年度`/`不定期`/`不支持更新`/`未标注` |
| `access_mode` | enum | 是 | `open`(Open标识可免费下载)/`trial`(高校试用)/`direct_sale`(需采购)/`api`(API Key)/`unknown` |
| `api_available` | bool | 是 | 是否有对应 API 接口 |
| `tags` | str[] | 是 | 3–6 个主题标签 |
| `maps_to` | str[] | 是 | 映射到我们板块：`量化/选票`、`量化/因子`、`量化/投研`、`情报/舆情`、`情报/公告`、`风控/事件`、`宏观/环境` |
| `priority` | enum | 是 | `P0`=直接补当前缺口；`P1`=核心但非急需；`P2`=因子候选；`P3`=背景资料 |
| `auth_status` | str | 是 | 当前一律 `未授权-需采购`，除非页面明确标 Open |
| `notes` | str | 否 | 局限、时效风险、口径陷阱（如"2025 年起才有"） |
| `alias_of` | str | 否 | **仅在重复挂载时出现**：指向同数据集正本的 `id`。有值表示本条是另一类目下的副本，两条 URL 都有效、内容同一份。由 `build_registry.mark_aliases()` 自动打，**不删除记录** |
| `alias_reason` | str | 否 | 别名产生原因，当前固定为「同名数据集在另一类目下重复挂载」 |
| `status` | str | 否 | `new_untriaged` = 刷新脚本自动收录、未经人工分诊。缺省表示已分诊 |
| `coverage_page` | str | 否 | **新鲜度证据层**：审计时抓到的页面「时间区间」原文。与 `coverage`（采集席抄录）并存，二者矛盾时以谁为准需人判 |
| `freshness_flag` | enum | 否 | `ok` 页面确实写到至今/实时，或止期在 6 个月内；`lag` 止期距今 7~18 个月；`stale` 止期距今 >18 个月，**实质高估新鲜度**；`page_unlabeled` 页面未写时间区间；`conflict` 其它矛盾。**字段缺失 = 未审计**（不编造 ok） |
| `freshness_lag_months` | int | 否 | 页面止期距审计时点的月数。**任一已审计记录都可能有**（`ok` 也可能带一个 ≤6 的值），仅 `page_unlabeled` 没有 |
| `coverage_checked_at` | str | 否 | 该条新鲜度证据的抓取时间 |
| `freq_page` | str | 否 | **频率证据层**：页面「更新频率」原文。只在页面说法与档案不同时挂，相同的不重复记录 |
| `freq_conflict` | enum | 否 | `频率低频但区间标实时`（页面自相矛盾，需人定口径）/ `档案与页面频率不一致` / `档案未填可补齐` / `抽取可疑需重抓`。缺字段 = 未审计 |
| `freq_note` | str | 否 | 矛盾的原文证据，如「页面时间区间写「截至2025（实时更新）」，与更新频率「年度」自相矛盾」 |
| `freq_checked_at` | str | 否 | 该条频率证据的抓取时间 |

> **证据层铁律**：`apply_freshness_overlay()` 只增字段，**绝不改写 `coverage`**。
> 原记载是采集席抄录的事实来源，改掉就等于换了一份"看起来更对"的数据但丢了溯源。
>
> **闸门怎么验这条**（口径很容易验错）：直接改 `registry.json` 再跑 `verify_all.py` **测不出来**——
> 该脚本会先跑两遍 `build_registry.py` 从分片重建，篡改在被检查前就被覆盖了。
> 要真验，必须**改源头分片**（`_fragments/frag_*.json`）或**单独调用 `check_invariants()`**。
> 已按此法变异验证：改分片 → 报「原 coverage 被改写」。
>
> **证据文件有哈希锁**：`_coverage_audit.json` 旁边有 `_coverage_audit.lock.json`（条数 + sha256）。
> 证据被删或改写都会打红——否则"没有记录就没有违规"，检查会真空全绿。
> 手工改过证据文件必须重跑 `coverage_audit.py`（或 `--lock-only` 重新加锁），再跑 `build_registry.py`。
>
> 统计口径：`meta.freshness_checked` = 已审计条数；`meta.by_freshness` 是**条目**口径，
> `meta.by_freshness_canonical` 是**唯一数据集**口径（`stale` 12 条记录里只有 7 个数据集，其余 5 条是别名副本）。
>
> **频率证据层同规矩**：只增 `freq_*` 字段，**`frequency` 一字不动**（原样抄录，矛盾留给读的人判断）。
> `meta.freq_checked` / `meta.by_freq_conflict` 为计数。`_freq_audit.json` 同样带哈希锁。
>
> **锁的能力边界（别高估）——实测结论，不是推测**：
> 防得住：证据被删（留锁）、证据被改却不重锁（sha 不符）、报告与 JSON 数字不一致（逐档对账）、报告文件缺失（有 else 分支报错）。
> 防不住：① 改完 JSON 再 `--lock-only` 重锁（锁与被锁物由同一脚本产生，不是独立锚点）；② JSON 与锁一起删（标记静默归零，全绿）；③ JSON 与 md 同步改再重锁；④ 改真源分片（重建后继承）。
> 一句话：**这把锁防"改完不同步"，防不了"同步改"。** 要跨过这条线，得把 lock 的 sha256 落到本目录之外的独立锚点（工单/CI 记录/上游提交）。
>
> **因此这层证据的定位**：可作**交付前自检闸门**（证明"文件没背离自己的快照、档案没被证据层改写"），
> 不可作**防篡改审计**（不能证明"快照本身对、没人整体换过快照"）。329 条"一致"记录不留页面原文，要复核只能重爬。

> **统计口径**：`meta.total_records`（条目数）≠ `meta.unique_datasets`（唯一数据集数）。
> 前者含别名副本，做覆盖统计请用后者；需要更细时看 `meta.by_priority`（含别名）与 `meta.by_priority_canonical`（仅正本）。

## 三、优先级判定规则

- **P0**：直接服务雪球/舆情追新与单股历史（含股吧、雪球、财经新闻实时），或直接补当前已证缺口（时间证据、单股覆盖）。
- **P1**：A 股/港股/美股基础、三表、交易行情、股东、研报。
- **P2**：专利、招聘、招投标、司法、ESG、土地房产、海关等因子候选。
- **P3**：宏观、区域、年鉴等背景数据。

## 四、分片约定

- 采集代理各自写 `_fragments/frag_<席名>.json`，**禁止改 `registry.json`**，避免并发覆盖。
- 分片格式：`{"shard":"<席名>","records":[...]}`。
- 主控席合并、去重（按 `id`）、统计后生成 `registry.json` 与 `INDEX.md`。
- 合并顺序：按 `id` 去重 → 按 `url` 兜底去重 → `mark_aliases()` 标同名副本 → 排序落盘。
  正本选择规则：已分诊 > 优先级高 > 有 `notes` > `id` 字典序。**刻意不比描述长度**——描述随再抓取变化会让正本翻转，外部按 `id` 引用就漂了。
- 构建幂等：同一批分片连跑两次，除 `meta.generated_at` 外输出完全一致。
