## 三、研发项目（R-01 ~ R-06）

### R-01 · 全库 id 稳定性治理 + 静态回归护栏【P0】

**目标**：消除非确定性 id 生成路径，并用静态检查永久防回归。

**设计**
1. 修 `obs_bridge.py:43`：裸 `hash()` → `sha256("%s|%s" % (source_id, now))[:16]`，与 sse 同算法族，保持前缀 `bridge-<date>-` 便于人读。
2. 新增静态检查 `tools/id_stability_lint.py`：
   - 规则：源码中裸 `hash(` 调用（排除 `hashlib`、排除注释/文档字符串、支持 `# noqa: unstable-hash` 显式豁免）；
   - 接入 `.git/hooks/pre-commit`（已存在，追加一步），也可独立跑。
3. 输出 `docs/id_stability_audit.md`：全库 id 生成方式普查表（源 / 算法 / 确定性 / 碰撞风险 / 结论）。

**验收判据**
- [ ] `grep` 裸 `hash(` 在 `news_collector/ portal/ tools/` 零命中（注释除外）
- [ ] `id_stability_lint.py` 对故意注入的 `hash(x)` 报错退出非 0
- [ ] `obs_bridge` 同一 `(source_id, now)` 跨进程两次运行 → `snapshot_id` 完全一致（实测）
- [ ] 普查表覆盖 7 个采集器 + 3 个 portal 快照脚本

**工作量**：2 小时　**依赖**：无

### R-02 · 注册表—桥文件一致性守卫【P0】

**目标**：让 `selection_universe.json`（权威）与各 `target_queue_*.json`（受桥脚本重生成）的开关不再静默漂移。

**设计**
1. `tools/registry_guard.py`：
   - 读 registry 每个源的 `xq_include`，映射到对应桥文件的字段（`houfeng_candidates164 → target_queue_houfeng.json:xq_include_candidates`，`cohorts → target_queue_cohorts.json:xq_include_cohorts`）；
   - 不一致 → 打印 `ALERT 漂移: <源> registry=true / 桥文件=false（权威取 registry）` + 建议修复命令；
   - **不自动改文件**（避免与桥脚本每日重生成打架），只报警 + 给命令。
2. 接入点：①`run_xq_daily.py` 启动前自检（漂移只告警不阻断采集）；②可选并入日更自检。

**验收判据**
- [ ] 手工把 `target_queue_houfeng.json` 的 flag 置 `false` → guard 报 ALERT 并指出权威值
- [ ] 正常态（两处一致）→ guard 静默退出 0
- [ ] 不修改任何文件（只读），`git status` 前后无变化

**工作量**：半天　**依赖**：无

### R-03 · 采集新鲜度 SLA 视图【P1，与 T-188 合并】

**目标**：一屏回答「哪个源最后成功是什么时候、连续失败几次、覆盖缺口多大」，替代人肉 `ls -lt`。

**设计**
1. 输入三路：①各源落盘目录 mtime + 文件数；②`logs/*.log` 尾部成功/失败标记；③registry 的期望覆盖（标的数）。
2. 输出 `news_collector/data/collect_sla.json` + 门户一页（复用 T-188 心跳页骨架）：
   - 字段：`source / last_ok_ts / stale_hours / consecutive_fail / expected_codes / covered_codes / sla_state(GREEN|AMBER|RED)`
   - 判据示例：`stale_hours > 26`（交易日）→ AMBER；`> 48` 或 `consecutive_fail >= 3` → RED
3. 阈值**先按经验值上线并标 `DEFAULT`**，实际调参归 11-15 微调日（不由本席单方定死）。

**验收判据**
- [ ] cohorts（停 20261110）在视图中呈 RED 或 AMBER，且能指出 stale 天数
- [ ] 正常源（k_stock 今日刷新）呈 GREEN
- [ ] 重跑幂等，输出 JSON 结构稳定

**工作量**：半天　**依赖**：T-188 心跳页骨架（已排期）

### R-04 · 治理动作可复现化（ACPO 落地）【P1】

**目标**：台账每条治理动作带「复现命令 + 预期输出」，换人接手可自证，不依赖 prose 叙述。

**设计**
1. 台账新增 `<details>` 折叠块或独立 `docs/ledger_repro/` 目录，每条含：
   ```
   [R22-sse-id] 复现：
     $ python news_collector/normalize_sse_ids.py --dry
     预期：files=184 changed=0 （幂等态）
   ```
2. `tools/ledger_lint.py`：校验新条目是否含 `复现` 与 `预期` 两字段；缺字段报 WARN（不阻断）。
3. 历史条目：**能回填的回填，无法回填的标 `legacy`**（不伪造当时输出——这违反 E4 反证纪律）。

**验收判据**
- [ ] 随机抽 3 条已回填条目，按命令重跑 → 输出与预期一致
- [ ] lint 对新条目缺字段报 WARN
- [ ] 历史条目中 `legacy` 占比明确列出，不隐瞒

**工作量**：半天~1 天　**依赖**：需上级同意台账增补 schema（append-only 原则下新增段落，不改历史）

### R-05 · 维度覆盖矩阵（E3+E6 落地）【P2】

**目标**：把「我们哪些关系维度还是盲区」变成机器可生成的矩阵。

**设计**
1. 维度枚举取自书内可视化十法，归并为 6 类：`主体(人/机构) / 事件 / 时间 / 空间(标的/板块) / 资金 / 关系网络`。
2. 各源声明覆盖（新增 `news_collector/coverage_decl.json`），逐源标注 `covered: [维度]`、`evidence: 字段名`。
3. 生成 `coverage_matrix.json` + `docs/coverage_matrix.md`（源×维度 网格 + 盲区清单）。

**验收判据**
- [ ] 矩阵覆盖 7 源 × 6 维度，每格有 `Y/N/partial` 与字段证据
- [ ] 盲区清单可被策略线直接引用（格式：`<源> 未覆盖 <维度>`）
- [ ] 重跑幂等

**工作量**：1 天　**依赖**：哪些维度算"应覆盖"需上级确认（本席只呈现现状，不裁标准）

### R-06 · WAF 自适应节流（R24 深化）【P2，需裁定】

**目标**：固定参数（300s/3 次/20%）→ 按实际拦截曲线自适应。

**设计**
1. 每轮记录 WAF 命中序号序列（第几只触发、间隔多少只）→ `data/xq_timeline/_waf_curve.jsonl`。
2. 自适应规则草案：命中率上升时**先降速**（拉长批次间隔）而非直接停；曲线平稳后恢复常速。
3. 历史回放：用 11-11 日志（130/489 停轮）验证新策略能否跑完全程。

**验收判据**
- [ ] 回放 11-11 场景：新策略下能跑完全部队列（或优雅 defer 而非整轮停）
- [ ] 不引入"硬闯"行为（保持"防拉黑"底线）

**工作量**：1 天　**依赖**：🔴 **风控姿态变更须上级裁定**（比固定参数更激进），未批不做
