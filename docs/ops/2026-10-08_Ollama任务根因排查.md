## 一、结论（一句话根因）

**rc=0xFFFFFFFF 不是 Ollama 服务崩溃——Ollama 此刻是活的（11434 监听中）；真实根因是：该任务 10-07 07:00:32 被登录触发器拉起后仅运行 52 秒，其进程树于 07:01:24 被强制终止（非正常退出），计划程序记录强杀结果码 0xFFFFFFFF；2 秒后（07:01:26）另一实例以 `cmd /c ollama.exe serve` 方式接管服务并存活至今。任务自身配置存在矛盾（SYSTEM 账户 + InteractiveToken、仅登录触发、wrapper 日志无落盘），导致它既不可靠也不可观测。**

## 五、附：rc=0xFFFFFFFF 的含义解释

| 场景 | LastTaskResult 表现 |
|---|---|
| 正常成功 | 0 |
| 正在运行 | 267009 (0x41301) |
| 从未运行 | 267011 (0x41303) |
| 被计划程序终止 | 267014 (0x41306) |
| **进程被强杀/异常终止** | **4294967295 (0xFFFFFFFF = -1)** |

- 0xFFFFFFFF 即有符号数 **-1**。在任务计划程序语境中，它通常意味着：**任务进程树被外部强制终止**（AllowHardTerminate 生效、用户手动"结束任务"、或进程以 -1 退出码异常消亡），少数情况是任务启动器本身异常。
- **它不是"从未运行"**（那是 0x41303）；本例 DynamicInfo（E2）证明任务确实运行了 52 秒，因此定性为「**运行中被强制终止**」。
- 它也**不代表服务当前状态**——LastTaskResult 是"上次运行如何结束"的历史快照。本例中 rc=-1 与"Ollama 此刻健康"两者同时为真，原因即 E3 所述：服务已由另一个实例接管。
