# 回测框架 v2 设计定档：参数化配置 + 逐日日历复盘（K-STOCK-283）

> 2026-10-13 07:38 老田指令：先理框架——选策略（缠论/量子双刀）+ 定时间点 → 看当天满足条件多少只入池 → 评分制取前 10 → **当天买入** → 逐日日历看过程（为什么没卖）→ 清了 50% 是否触发**再选股补位**（按评分+仓位设定）→ 现有回测参数太单一（只有开始时间+策略，没有仓位/加仓选择）→ 没有日历表复盘真实交易日 = 所有回测不准确 → 数据窗口三年内可支持、更早不行 → 结合学院缠论/量子双刀买卖点策略。

## 一、指令拆解（七点，逐条对应设计）

| # | 老田诉求 | 框架落点 |
|---|---|---|
| 1 | 选缠论或量子双刀 | `strategy` 可插拔（两套引擎都已存在） |
| 2 | 定期到那个时间点，看当天满足条件的股票多少入池 | `asof` PIT 锚点 + 逐日 `pool_scan` 事件（入池/出池留痕） |
| 3 | 评分制取前十名 | `scoring` 打分器可插拔 + `top_n=10` |
| 4 | **当天买入** | `buy_when: signal_day_close`（当日收盘成交，见 §五 如实声明） |
| 5 | 日历表看第二天起的过程，**为什么没卖** | 逐日 `hold_note`：不卖也要写原因（未达止损/无卖点/持有期未到） |
| 6 | 清了 50% → 是否再选股补位（按评分+仓位设定） | `refill_on_sell: true` 闭环：卖出/减仓释放仓位 → 重跑选股评分 → 池内未持有补 Top → 按仓位设定买入 |
| 7 | 参数太单一：没有仓位选择、是否会加仓 | `BacktestConfig` 完整参数空间（§三） |

## 二、学院策略对照（买卖点规则化现状）

### 缠论（实现已有：`quant_backtest/chanlun_signal.py`）
- 三类买卖点规则化（笔/线段/中枢 + 力度对比）+ MACD 背驰影子标注（仅 1买/1卖，不拦截）
- 铁律：hfq 后复权 + seen-ever 去重（K-STOCK-263a）
- 学院⑥「买点=中枢区间+成交量触发」：已实测限价回踩有逆向选择（269），**当天收盘买入**是新语义，进框架对照检验

### 量子双刀（实现已有：`agent_platform/engine/quant_double_knife.py` + `_entry.py`，自测 23/23）
- 日线规则：连续两日十字星 + MACD 多头 + 价格/成交额过滤 + 均线多头 + 乖离限制 + **trend_down regime 一票否决**
- 学院④评分仓位层：信号 1-5 分、热度档位→总仓位映射、周期仓位 5:3:2（原文标注"历史主观经验，需数据推演"——框架正是做这个推演的工具）
- 分钟确认（突破/量比/VWAP/开盘强度四过二）：回测无分钟数据 → 用 `next_open` 次日开盘近似
- 学院⑤「开仓时同时确定逻辑、持有周期、止盈止损预期」→ 直接映射为框架参数

### 学院⑦方法论约束（本框架的天职）
「扩大回测时间范围、区分样本内外、完成策略归因、模拟验证后再真实资金」——框架化的意义：**让每一组参数假设都可检验、可归因、可对照**。269 得出的「单票干预负贡献」与老田要的「评分 Top10+止盈止损+补位」不再是对立观点，而是同一框架下的两组配置，跑出来用数据说话。

## 三、BacktestConfig 参数空间（回测表单的目标形态）

```python
cfg = {
  "strategy":      "chanlun" | "quant_blade",   # 选股引擎（可插拔注册）
  "asof":          "20251013",                  # PIT 锚点：只喂 ≤D 数据（241 定档）
  "window":        "1m"|"3m"|"6m"|"1y"|"3y",
  "scoring":       "score_v1" | "mom20_liq" | ...,   # 打分器可插拔（245 雏形）
  "top_n":         10,                          # 评分取前 N
  "buy_when":      "signal_day_close" | "next_open",  # 当天买入=D收盘（老田语义）
  "total_cap":     0.80,                        # 总仓位帽（259 拍板）
  "position_mode": "equal" | "score_weighted",
  "stop_loss":     -0.08,                       # 学院⑤开仓即定（可关）
  "take_profit":   null | 0.15,                 # 可选止盈
  "max_hold_days": null | 20,                   # 学院⑤持有周期（可关）
  "refill_on_sell": true,                       # 卖出/减仓 → 触发再选股补位
  "add_on_signal": "off" | "score_up",          # 加仓规则
  "regime_switch": "on" | "off",                # 组合级市场择时（269 结论的开关）
}
```
269 终案 = 本框架的一组配置（top_n=全池76、无止损、refill=off、regime=on）；老田方案 = 另一组配置。**同框架同数据对照跑，归因干净。**

## 四、逐日日历表 schema（复盘核心，277 骨架扩展）

每天事件流（bt_view 日历已有点击下钻，扩展事件类型）：

| 事件 | 字段 | 复盘问题 |
|---|---|---|
| `pool_scan` | 满足条件数 / 新入池 / 出池名单 | 「当天满足的股票有多少」 |
| `buy` | 标的、评分、当时排名、金额、占比 | 为什么买它（评分第几名） |
| `hold_note` | 每只持仓的不卖原因 | **「为什么没卖」**（未达止损-8% / 无卖点信号 / 持有期未到 / regime 未降档） |
| `sell` | 原因（stop_loss / take_profit / max_hold / sell_signal / regime_down） | 为什么卖 |
| `trim` | 减仓比例（清 50%）、原因 | 为什么减 |
| `refill` | 触发原因（trim/sell 释放仓位）→ 重跑选股+评分 → 新买入标的与排名 | **「清了 50% 是否再选股」的闭环** |

补位循环：`sell/trim → 现金释放 → pool_scan(当日 PIT) → scoring 排序 → 池内未持有取 Top → 按 position_mode/total_cap 买入`。**同日最多一轮补位（防连环触发），T+1 合规（D 确认 D+1 可卖，买入不受限）。**

## 五、如实声明（三条，不粉饰）

1. **「当天买入」与缠论确认滞后的冲突**：263 实锤简化缠论确认滞后中位 53 天——D 收盘时信号往往还不可见。「当天买入」语义下缠论臂的诚实近似是 `buy_when=next_open`（D+1 开盘）；量子双刀是「日线候选+次日分钟确认」设计，天然匹配 `next_open`。两臂统一用 `next_open` 对照最公平，`signal_day_close` 保留给强假设实验。
2. **数据窗口三年是诚实上限**（273 体检）：日线主库 2023-04 起、复权因子连续覆盖 2023-07-31 起 → **三年窗（2023-10→2026-10）全量可信**；更早缺本地日线，与老田判断一致。
3. **269 结论的适用范围**：「单票干预负贡献」是在缠论池+无评分+满池等权上得出的；评分 Top10+止盈止损+补位是不同配置，框架跑完之前不预设谁对——这正是框架存在的意义。
