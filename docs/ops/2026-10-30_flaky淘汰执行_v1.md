## 二、portal flaky 根因与修复

- 根因：该用例**设计上要求独立进程**（顶部断言 `api_backtest` / `portal_api` 不在 `sys.modules`，注释明写 "Run this module alone"）；
  全量套件里其他测试（契约/分钟单测）先 import `api_backtest` → 断言必失败 → 被误登记为 flaky。
- 修复（确定性，非调参）：全量环境下检测到已导入时，**自动在干净子进程重跑本文件**（`python -m pytest <file>`，env 透传 PORTAL_NO_WARMUP=1），
  子进程 rc≠0 才失败。单文件直接运行路径不变（仍原生执行）。
- 证据：单文件 1 passed（3.9s）；全量 **388 passed / 0 failed**（含本用例经子进程通过）；探针 1 轮无失败。
- 基线：`portal/tests.flaky` 移除该条（`_flaky_note` 记录证据）；`test_minute_router_process_restart` 今日 3/3 通过，**保留观察**（未满 7 轮）。

## 三、agent 套件阻塞（并行线回归，已定位，未修）

- 现象：`pytest agent_platform/tests` → **16 errors during collection**，均为 `from tools.safe_urlopen import ...`：
  `ModuleNotFoundError: No module named 'tools.safe_urlopen'; 'tools' is not a package`；
- 最小复现：**单文件跑 `test_a0_agent_p1.py` 必失败；与其他文件同跑则通过** → `sys.path` 顺序/`tools` 包解析被测试自身插入路径影响；
- 试验：新增 `tools/__init__.py`（使 tools 成为常规包）**未根治**（仍 16 errors），已撤回（避免无关变更）；
- 影响：agent 10 条 flaky 本轮**无法用探针验证**（不能按 7 轮规则淘汰）；**不是** agent 业务代码失败，是测试基础设施问题；
- 建议 owner（agent 线）：统一 conftest 在收集前把**仓库根目录置于 sys.path 最前**（或给 `tools` 加包标记并统一 import 方式），
  修好后跑 `python tools/flaky_probe.py --suite agent --runs 7` 完成 10 条 flaky 的淘汰/保留判定。
