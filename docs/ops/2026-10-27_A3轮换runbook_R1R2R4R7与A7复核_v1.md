## 1. R1 Tushare token（最高优先）

**前置**：老田在 tushare 控制台 → 用户中心 → 接口 TOKEN **重置/生成新 token**（旧值立即作废）。

**步骤 1（主仓、先干跑）**：
```powershell
Set-Location C:\项目\老田的AI助手
C:\项目\py312\python.exe -X utf8 tools\secrets\rotate_tushare_token.py --dry-run
```
期望：`vault_dir = C:\项目\_vault\secrets (exists=True)`、`age binary = ...\bin\age.exe (exists=True)`、`OK: 前置齐备`。

**步骤 2（正式轮换）**：
```powershell
C:\项目\py312\python.exe -X utf8 tools\secrets\rotate_tushare_token.py
```
- 出现 `new Tushare MCP token (不回显):` 时粘贴新 token（粘贴不回显、不进命令历史）；再输一次确认。
- 脚本自动：写私密区 → `vault.py encrypt --recursive` → `verify --json` → `render_mcp.py` → `render_mcp.py --check`；
- 期望末行：`[done] R1 本地链路完成`，且输出只有 `len=/sha8=` 指纹（**不会打印 token**）。

**步骤 3（验收）**：
1. 用新 token 跑一次只读 MCP 行情查询（任一次 tushare 取数即可）；失败→按脚本提示回滚旧值；
2. 通过后才重启 MCP 客户端/相关服务（落盘≠生效）；
3. 在 `_vault/secrets/ROTATION_FILLBACK_TEMPLATE.md` 回填「完成时间 + len/sha8」。

> 注：`_vault/secrets/mcp/tushare_mcp_token` 明文当前不在盘（已加密为 `secrets.enc/mcp/tushare_mcp_token.age`）；脚本会按现有 Phase 2 设计**重新写入私密区明文**再加密。若你希望跳过明文落盘直接加密，可后续做 resolver Phase 2（另单）。

## 3. R5 DB 口令（五要素 + 窗口）

- **命令全文**（dry-run 先看；执行需窗口 + 备份 + 离线旧值）：
  ```powershell
  powershell -NoProfile -ExecutionPolicy Bypass -File C:\项目\_vault\patches\exec_20261025\rotate_db_passwords_dryrun.ps1 -Target <zhice_v2|quant_pg|cainiao_mysql|neo4j|...>
  # 窗口内、备份与旧值离线保存后，显式：
  # 先在同一私有 shell 设好 NEW_* 环境变量（不回显），再：
  # powershell ... -Execute -ConfirmPhrase "I-HAVE-WINDOW-AND-BACKUP"
  ```
- **影响面**：对应 PG/MySQL/Neo4j 账户；消费服务需重启（zhice API/scheduler、quant 读取链、cainiao OAuth、KG 查询）。
- **不可逆点**：`ALTER` 后旧口令失效；旧值必须离线保留 24h。
- **替代方案**：先只轮换「已暴露窗口内被读到的」账户（zhice_v2 / quant_pg / cainiao），其余延后。
- **回滚**：`ALTER ... PASSWORD '<旧值>'` + env 回滚 + 重启；回滚前验证旧值可取。
- **验收**：旧口令连接失败；新口令读写成功；服务健康/页面 200；记录指纹。
- **建议窗口**：收盘后/夜间 ≥15 分钟；一次只做一个 `-Target`，不可并发。
