# 长任务可观测性模板 v1（A3 · 2026-10-31 · 关羽）

> 由来：R1 失败根因链（无超时/无 connect_timeout/逐条 DB 往返/死锁不回收/失败无日志）已修复并验证。
> 本模板把该次修复固化为**可复用检查清单**，新建或翻修任何"跑 >30s 的脚本/计划任务"时逐项对照。
> 归口：各任务 owner；关羽验收时按本清单抽查。

## 一、必备项（缺一不验收）

| # | 项 | 要求 | 反例（R1 事故） |
|---|---|---|---|
| 1 | **超时** | 每步外部调用显式超时（DB/HTTP/子进程），默认 ≤ 环境可接受值；总任务有上限 | psycopg2 无 `connect_timeout` → 等 600s |
| 2 | **日志** | 长跑输出落文件/JSON 行，含开始/步骤/耗时/结束；异常写 traceback；不得仅 silence | 18:30 任务失败但无任何日志 |
| 3 | **结构化错误** | 失败返回 `{ok:false, error:<code>, detail}`；计划任务据此 exit 非 0 | 超时无返回、任务只显示 600s |
| 4 | **锁** | 需要互斥时用 `tools/file_lock.py`；死 PID 可立即回收；超时明确 | 死进程锁要等 30min stale |
| 5 | **批量/批处理** | 禁止逐条远程往返；合并查询或批量提交 | 3,416 次 DB 往返 → 600s+ |
| 6 | **健康探针** | 服务类必须有真探针（校验业务特征），不能只看端口/200 | `/health` 被 SPA fallback 假 200 |
| 7 | **fail-visible** | 失败必须让人看见（计划任务结果/日报/事件层），不得静默跳过 | 失败无告警 |
| 8 | **可重跑/幂等** | 重复执行不产生重复数据；有 `--dry-run`/`--check` | 补跑产生重复行 |

## 二、计划任务额外项

- **StartWhenAvailable=True**（错过补跑）；
- `MultipleInstances=IgnoreNew`（防并发）；
- `ExecutionTimeLimit` 显式（默认 1h 过长，按任务设 15–30min）；
- 输出重定向到 `C:\Temp\<task>.log`（或任务历史 JSON），保留最近 N 天；
- 任务 `LastTaskResult` 不等于 0 时，月报/日巡要能列出。

## 三、验收记录模板（复制到回执）

```markdown
| 项 | 结果 |
|---|---|
| 超时 | DB connect_timeout=5s；HTTP 10s；总任务 600s 上限 |
| 日志 | <path>，包含 steps/耗时/结束 |
| 结构化错误 | {ok:false,error:...}；异常 exit≠0 |
| 锁 | file_lock + 死PID回收（或无需锁，说明理由） |
| 批量 | 已批量化，往返 N→M |
| 健康探针 | /probe 校验 <特征> |
| fail-visible | 任务结果/事件 <kind> 可见 |
| 幂等 | 重复运行验证 0 重复 |
| 实测耗时 | 修复前 X s → 修复后 Y s |
```

## 五、与门禁的关系

- 本模板是**验收清单**，不做自动门（避免误伤）；但新建计划任务时 L2 批准单必须引用本清单；
- 若同类事故再发（如又一个"无日志超时"），升级为**自动门**（任务 LastResult + 日志存在性巡检）。
