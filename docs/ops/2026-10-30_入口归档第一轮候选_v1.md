## 一、方法与口径（工具：`tools/entry_archive_scan.py`）

- 引用源 = **代码/配置**文件（.py/.ps1/.bat/.cmd/.js/.ts/.json/.yaml/.yml/.toml/.ini/.sh）；
- **排除**：文档 .md/.txt（历史计划提到 ≠ 在运行）、测试/测试目录、数据根（`quant_backtest/data`、`agent_platform/data`）、清单/索引类 JSON（bundle/catalog/registry，内容含全量路径会伪造引用）；
- 引用判定：①代码/配置文本出现「相对路径」②`.py` 入口的模块名出现在任何非测试 `.py` 的 import 语句（AST）③计划任务 XML 含路径/模块名；
- 0 引用且非测试入口 → 归档候选。

## 三、复核清单（归档前必须逐项确认，任一命中即保留）

1. **计划任务/开机自启**：`schtasks /query /xml` 已纳入扫描，但仍需人工看非本机调度（外部 cron/远程）；
2. **动态 import**：`importlib` / `__import__` / `sys.path` 拼接的引用（静态扫描看不到）；
3. **人工/IDE 运行**：IDE run config、快捷方式、开发者书签；
4. **MCP/工具注册**：是否被 `agent_platform/tools`、`portal` 的 MCP 工具表注册调用；
5. **文档引用**：被 docs 作为"现行入口"引用（若文档已过期则一并更新）。

## 四、处置流程（第二轮执行，需批准）

1. owner 复核（按顶层目录分派）→ 在清单标 `保留/归档`；
2. 归档 = 移入 `archive/` 或原地加 README 标注（L2 先例：原地冻结优先，成本最低）；
3. 每次 L2 审批 + 快照 + 回收站（禁 rm/del），判例留档；
4. 同步更新 `docs/ops/entrypoints_v1.tsv` 与 `legacy_registry_v1.md`（L2 归档登记）。
