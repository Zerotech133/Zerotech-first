## K-ORG-039 关键发现

1. **🔴 038a 产物带潜伏 bug 出生**：qa1_review.py 的 `review_one()` 把字符串传 `chat_auto`（只收 dict）——四通道全炸。而 038a 的冒烟只断言「sha 出现在输出」（标题行即满足）= **假 PASS，弱断言冒烟挡不住带病交付**。GPT-6 链的行为冒烟当场抓住。判例：**冒烟必须验行为（退出码/结论/事件落账），不得验「字样出现」**。
2. **强质检会翻旧账**：GPT-6 当 QA1 对 3a2c59f（带 str bug）判**退回**——正确行为；对 0d93649 也比 flash 档 QA1 更严（指出 dry-run 前置写 probe 污染工作区等设计取舍）。**质检结论随模型档位分层**：flash 档 QA1 宽松、GPT-6 档严格，重要工单复核应指定强档。
3. **配额纪律（官方条款）**：Coding Plan 积分制——Lite 2,000 积分/5h + 10,000/周，非高峰 5 折；单工单约 3K in + 1K out ≈ 4~5 积分，Lite 5h 窗口可跑约 400 单，充足。⚠️ 条款限「AI 编程工具与 OpenClaw 类型 Agent」使用，本产线为编码 Agent 形态属预期内用法，但**勿把套餐 Key 用于通用 API 场景**。
4. **Trae CN 定位**：官方仅限 IDE 内使用、无对外 API，社区破解（trae-local-api 等）违反 ToS 有封号风险——**不采用**。价值定位：老田手中的人工辅助 IDE 工位（人在环），或反向把我们的 gpt6/智谱端点配进 Trae 的 Custom Model。
5. **WorkBuddy 会员定位**：主控会话本身即强模型通道（架构/评审/协调），属指挥层不进 agent_coder 程序化路由。

## 判据要点

1. **模型分层实锤**：同为免费档，4.5-flash 与 flash 编码能力天壤之别——`CODER_CLOUD_MODEL` 一档定生死；充值 glm-4.6 后 claude_glm 通道为升档路线。
2. **闸门栈价值**：glm-4-flash 的四类缺陷全部被「行为冒烟」抓住（语法门/完整性检查均放行）——**行为断言不可省**。
3. **QA1 复核**：cloud 通道 2/2 工单复核通过（review_verdict 入事件账），复核成本 ~27s/单。
