> 风险背景：全部数据在 Docker Desktop WSL2 虚拟盘（ext4.vhdx）命名卷里，宿主备份脚本盲区。

## 二、Neo4j 挂账（两案待选，需停库窗口或迁移）

community 版 `neo4j-admin database dump` 要求目标库停止。两个选项：

- **方案甲（简单）**：找一个停机窗口（如周六早 07:05 跑批前），临时 `docker stop neo4j-kg` → dump → `docker start`，全流程 <5 分钟；脚本加 `--neo4j-window` 参数时启用此路径
- **方案乙（根治）**：把数据从命名卷迁到宿主 bind mount（`E:\...\neo4j-data`），此后直接复制数据目录（仍建议停库保证一致性）；迁移命令：停库 → `docker run --rm -v neo4j-kg-data:/src -v <宿主目录>:/dst alpine cp -a /src/. /dst/` → 改 compose 挂载

另注意图谱数据有下游：`kg_portal.py`（/kg 页）与情报线读 Neo4j 7687，停库窗口避开跑批时段。

## 三、备份链全景（现状）

```

每日 03:00  backup_daily（注册表 AIStation\BackupDeploy 三源）→ 备份体系收走（保留 14 天）
每日 02:10  git auto 快照（:10 每两小时）→ 代码层
```

## 四、商业化部署衔接（K-STOCK-050 结论）

- 部署目标 = Linux + Docker Engine（免费）+ compose；dump 文件即迁移种子（`gunzip < x.sql.gz | psql/mysql` 直接灌）
- Neo4j 迁移用 dump 文件或数据目录拷贝（版本须一致：neo4j:5-community）
- 镜像构建走 buildx 多架构（ARM64 一体机交付线）
