# ACAD1（司马徽）→ D1（鲁肃）池对接 v1

> 状态：**现行**（2026-11-16 WO-ACAD1-D1-BRIDGE）
> 脚本：`tools/acad1_pool_bridge.py` · 测试：`tools/test_acad1_pool_bridge.py`（7 例）
> 计划任务：`D1Acad1Bridge`（每日 10:00）

## 一、为什么需要

ACAD1 每天在 PG 产**官方推荐池**（`/api/acad1/pool`，`review_status=pool_reviewed`），
而 D1 侧的会审输入 `todays_picks.json` 数据日停在 11-13 —— 中间缺一条
「ACAD1 池 → D1 裁决 → 交棒」的桥。

2026-11-16 实测：

| 环节 | 状态 |
|---|---|
| ACAD1 PG 池 | `pool_date=2026-11-16`，**29 只**（CN 12 / HK 10 / US 6 / CRYPTO 1），`source_mode=pg_official_aggregated` |
| `todays_picks.json` | `scan_run_date=2026-11-13`（897 只，11-15 18:20 生成） |
| D1 `pool_v2_sessions` | 最后一场 11-13 |

PG 端口已监听（5432/5433），所以池走官方路径，**不是投影**。

## 二、边界（谁负责什么）

- **ACAD1 只选池/复核**：池条目里 `recommendation` / `confidence` / `tier` 全为 `null`；
- **D1 才裁决**：本桥按显式规则把池内标的落成五档，**不重算选股、不改池**；
- 默认只处理 **CN**（HK/US/CRYPTO 暂无行情源，交棒会跳过）；
- paper-only、不建单、不接实盘；幂等键绑定「池日 + 代码 + 来源」。

## 三、裁决规则（依据 ACAD1 既有证据，可追溯）

实测 29 只全部 `risk_flags=[]`、`selection_reason` 均以「基础信号：买点」开头、`status=selected`。

| 优先级 | 条件 | 结论 |
|---|---|---|
| 1 | `risk_flags` 非空 | **HOLD**（ACAD1 已标风险，D1 不硬顶） |
| 2 | `signal` 含「卖」/`SELL` | **SELL** |
| 3 | `selection_reason` 含「买点」或 `signal` 含「买」 | **BUY** |
| 4 | 其余 | **HOLD**（无可采信买点依据） |

**confidence 不另造数字**，由 ACAD1 `score` 归一：

```
confidence = clamp(0.45 + 0.25 × score/100, 0.45, 0.70)
带 risk_flags 再 −0.10；无买点依据 −0.05
```

## 四、交棒

BUY 且有收盘价才建（无价不造数）：

- `buy_zone = [close×0.98, close×1.01]`，`stop_loss = close×0.95`
- 两条 `watch_plans`：`wp-acad1-<池日>-<代码>-stop` / `-take`，7 天到期
- `target=WA1`（盯盘席），`paper_only/not_a_trade=true`

## 八、数据源与 DSN 配置（2026-11-16 12:0x 落实）

**故障链**：池退化到 `shadow`（11-15、`market=None`）不是"PG 没装"，而是两个配置问题叠加：

| 环节 | 事实 |
|---|---|
| PG 在哪 | **Docker 容器 `zhice-db`**（postgres:15），宿主机端口 **5446**（不是 5432），库 `zhice_os_v2`，user `zhice` |
| 为什么连不上 | ① 端口搞错（默认 DSN 找 5432/5433，容器映射在 **5446**）；② 8091 进程启动时**没有** `ZHICE_V2_DSN`；③ `war_room._pg_guard()` 探测失败后置的 `ACAD1_POOL_PG_DISABLE=1` 在进程内常驻 |
| 数据在不在 | 在。`v2_acad1_pool` 最新 `pool_date=2026-11-16`（see below） |

**修复动作**：

```powershell
# 1) 持久化 DSN（User 级，新进程自动继承）
[Environment]::SetEnvironmentVariable("ZHICE_V2_DSN",
  "postgresql://zhice:zhice_pass@127.0.0.1:5446/zhice_os_v2", "User")

# 2) 带新 env 重启 8091（随后 keepalive 接管）
# 3) 生成只读投影（回退路径）
python -X utf8 tools/datawarehouse/acad1_pool_projection.py \
  --out agent_platform/data/projections/acad1_pool_projection.json
```

**验证**：

| 项 | 结果 |
|---|---|
| 池 API | `pool_date=2026-11-16 count=29 source_mode=pg_official_aggregated degraded=None` |
| 池内市场分布 | `CN 12 / HK 10 / US 6 / CRYPTO 1` |
| 投影文件 | `acad1_pool_projection.json`（7731 B，`--check` rc=0，count=11 single-view） |
| 对账 | `expect_base=12` **自动从池 API 取到**（不再需要 `--expect`），7 项全 OK |
| keepalive 重启后 | kill 8091 → keepalive 0.81s 拉起 → 池仍 `pg_official_aggregated` → **DSN 跨重启存活** |

**代码层的两处防复发**（已提交 `c69af659a`）：

1. `api_acad1_pool._pg_env_says_disabled()`：不信残留 env，实测 5432；

### 8.1 回退路径的真实边界（2026-11-16 13:2x 实测）

强制 `load_pool_snapshot(view="full", allow_pg=False)`：

```
source_mode  : projection
pool_date    : 2026-11-16
count        : 11
degraded     : full_view_requires_pg_aggregation; pg_disabled_by_caller
markets      : {'CRYPTO': 1, 'HK': 10}     ← 没有 CN
```

**结论：projection 是「单日视图」，当天的 CN 标的只在 PG 的聚合视图里。**
所以回退路径对 HK/CRYPTO 可用，对 CN 桥**不可用**——这属于数据口径限制，不是代码问题。

因此桥加了一条守卫：`source_mode=projection` 且该市场为 0 条时，报

```
REFUSED 回退视图 projection 内没有 CN 标的（单日视图通常只含 HK/CRYPTO；CN 需 PG 聚合视图）
→ 修 PG 后重跑，勿按'无事可做'处理   rc=2
```

而不是静默 `NO_POOL`。两条守卫都有单测（`test_projection_without_market_refused` / `test_shadow_source_refused`）。

### 8.2 容器与配置的持久性

| 项 | 值 | 说明 |
|---|---|---|
| `zhice-db` 重启策略 | **`unless-stopped`** | 宿主机重启或 docker 重启后自动拉起，无需人工 |
| `ZHICE_V2_DSN` 作用域 | **User（注册表 `HKCU\Environment`）** | 新进程（含 keepalive 拉起的 8091）自动继承；实测 `kill → 0.81s 拉起 → 仍 pg_official` |
| 投影自检 | `acad1_pool_projection.py --check <path>` | rc=0，`count=11` |

## 九、边界与已知限制
- **HK/US/CRYPTO 未接**：无行情源（腾讯接口仅 A 股），这些市场暂只裁决不交棒；需要港股/美股行情源后再扩；
- **tier 规则是我方映射**，不是 ACAD1 的结论——rationale 里写明「ACAD1 官方池复核产物 → D1 按规则裁 X」，可追溯也可被推翻；
- 池日为 `data_date`（11-13 数据日）与 `pool_date`（11-16 发布日）不同，去重键用 `pool_date`。
