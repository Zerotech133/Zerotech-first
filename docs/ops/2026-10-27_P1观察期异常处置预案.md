## 2. BM25 阈值（`--check`）

| 告警 | 严重度 | 判据 |
|---|---|---|
| `rag_not_enabled` | high | `rag_enabled_rate<90%` 且样本≥5（疑似 env 未注入 8091） |
| `empty_retrieval_high` | high | 空检索率 >30% |
| `latency_p95_high` | medium | P95 >800ms |
| `source_count_low` | medium | 平均来源数 <1（样本≥5） |
| `index_missing` / `index_stale` | medium | 索引不存在/超 7 天未重建 |
| `no_traffic` | info | 尚无流量，不判定 |

## 3. 处置动作（按严重度）

### high（建议当班处置）
1. `rag_not_enabled`：确认 `portal/start_portal_api.ps1` 的 `$env:ZHUGE_RAG='1'` 存在 → 用 sentinel + `Start-ScheduledTask AI工作站门户API` 重启 → 复跑 `--check`；
2. `empty_retrieval_high`：
   - 先 `python tools/zhuge_rag.py --build` 重建索引；
   - 仍高 → **回退关键词**：删除/注释 launcher 中 `ZHUGE_RAG` 行（或设 0）→ 重启 8091；
   - 记录回退原因/样本到 STATUS（不删数据）；
3. 服务不可用：`/health` 检查，必要时按既有冷启动守卫重启（`C:\Temp\PORTAL_API_RESTART.flag`）。

### medium（观察/当班修）
- 延迟高：看索引是否已缓存、机器负载；必要时重建索引/回退；
- 来源数低：抽查 `grounding_usage.jsonl` 的 source_paths，补文档/同义词（F04 同类）。

### C3 / 决策闭环异常
- C3 有新采纳但 `unmatched_count` 高：检查相关决策是否声明 `adoption_domains`；**不自动猜关联**；
- 质询卡已 closed 但决策仍 proposed：跑 `zhuge_c1_decisions --sync`；仍失败则查 card_id/source_card；
- 决策账本 `validate` 不通过：不删历史，追加修正/新记录。

### memory 异常
- 默认关闭；若启用后出现污染/隐私问题：设 `ZHUGE_MEMORY=0` → 重启；保留文件，人工复核后清理（tombstone）。

## 4. 回退手册（秒级）

1. 编辑 `portal/start_portal_api.ps1`：删除/注释 `$env:ZHUGE_RAG = '1'`（或改 `'0'`）；
2. 写 `C:\Temp\PORTAL_API_RESTART.flag` 并 `Start-ScheduledTask AI工作站门户API`；
3. 等 pid 变化 + `/health` 200；复跑 `p1_rag_observe --check`；
4. STATUS 记录：时间/现象/回退点/后续。
