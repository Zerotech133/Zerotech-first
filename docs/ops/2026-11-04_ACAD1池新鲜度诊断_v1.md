## 二、根因链（证据闭环）

```text
[配置变更 2026-10-30 20:11]
  .env.local DB_MAIN_URL = postgresql+psycopg2://…（SQLAlchemy 形态）
        │
        ▼
[8105 调度器 APScheduler 进程存活（heartbeat 正常）]
  但 run_fetch_daily / run_fetch_snapshot 等作业在取 universe 时
  直接 psycopg2.connect(get_settings().db_main_url) → invalid dsn → 抛异常
  自 2026-10-31 起每日 1.5万~2万次 job 失败（累计 76,499 条，日志 617.8MB 无轮转）
        │
        ▼
[v2_bar_daily] HK/US/CRYPTO 最后写入停在 10-30/10-31（CN 由独立 ashare 写入路径维持 11-03）
        │  adapt_platform_global.py: maxd = max(trade_date) FROM v2_bar_daily WHERE market=:m
        ▼
[v2_selection_report] report_date 逐市场冻结 HK 10-30 / US 10-29 / CRYPTO 10-31（CN 11-03）
        │  pool_date = max(report_date)（同脚本 L195-217）
        ▼
[v2_selection_pool] 逐市场 pool_date 冻结（写入动作 11-03 19:18 正常运行，但日期=输入）
        │  build_rule_base_signals 等同样从 bar_daily 派生 → v2_base_signal 冻结
        ▼
[sync_candidate_to_acad1.py（每日 03:15，rc=0）]
  按设计 market_latest_aggregated：CN 11-03 + HK 10-30 + US 10-29 + CRYPTO 10-31 → full 30
        │
        ▼
[/api/acad1/pool] stale=true, freshness_days=5（US 5/HK 4/CRYPTO 3/CN 0）  ← **stale 5d 根因**
```

**30 pending 的独立根因**：
- `v2_acad1_review` 只有 7 条**池级**记录（topic/verdict），没有逐票 action 记录；
- `sync_candidate_to_acad1.py` 每次只写 1 条池级 review（`review_date=max(各市场 pool_date)=11-03`，topic 固定），11-04 运行会覆盖 11-03 同 topic 行 → 不会产生 11-04/逐票记录；
- `acad1_rationale.py` 只写 `selection_reason` 文本，不写 review 表；
- API full 视图 `_new_items(rows, review={}, review_status)` 在无逐票 review 记录时把 30 票全部置 `pending_analysis`；`_summary` 的 reviewed 只统计已决记录 → **reviewed 0 / pending 30**；
- 同时 `review_status=pool_reviewed`（来自池级 verdict）与 `reviewed=0` 语义并存 → 指标易误读。
