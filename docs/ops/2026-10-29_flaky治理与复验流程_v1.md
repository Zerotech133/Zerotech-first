# flaky 治理与复验流程 v1（2026-10-29 · 关羽）

> 背景：agent 套件有 9 条历史 flaky 登记；本轮全量复验发现：**所有 9 条 3 轮未复现**，反而新发现 1 条（`test_closeout_round::test_if_changed_skips_duplicate`，run2 失败、隔离 3/3 绿）。
> 目标：把"已知 flaky"从**静态白名单**变成**可复验、可淘汰**的机制。

## 一、现状（2026-10-29 复验）

| 项 | 数据 |
|---|---|
| agent 全量轮次 | gate 1 + 复验 2 = 3 轮 |
| 历史 9 条 flaky | **3 轮 0 复现**（保留观察，11-05 评估移出） |
| 新 flaky | `test_closeout_round.py::test_if_changed_skips_duplicate`（1/3 复现；隔离 3/3 通过 → 顺序/环境敏感） |
| portal flaky | `test_minute_router_recovers_after_real_process_restart`（真实进程重启类，隔离 2/2 通过） |

## 二、工具：`tools/flaky_probe.py`

```powershell
python tools/flaky_probe.py --suite agent --runs 2      # 全量跑 2 轮（约 10 分钟）
python tools/flaky_probe.py --suite portal --runs 3     # portal 快（约 3 分钟）
```
- 输出：每轮 FAILED 明细、基线 flaky 命中、未登记失败（即新回归/新 flaky）；
- 落盘：`agent_platform/data/flaky_probe/probe_<suite>_<ts>.json`；
- 退出码：0=无未登记失败；1=有（需登记或修复）。

## 三、SOP

1. **每周**（或大改动后）跑 `flaky_probe --suite agent --runs 2`；
2. 未登记失败 → 先隔离跑 3 次：
   - 隔离通过 → 判 flaky：登记基线（附复现轮次+隔离证据）+ 追查共享状态（全局变量/端口/真实文件写入）；
   - 隔离失败 → 真回归：按 P0 修复，不得登记白名单；
3. **淘汰**：连续 7 轮或 2 周 0 复现 → 从 `flaky` 移出（回单注明日期与轮次证据）；
4. 每次变更基线 → 回单写明证据；禁止"直接加白"无证据。

## 四、已知根因与处置建议

| 类别 | 例子 | 根因 | 处置 |
|---|---|---|---|
| 真实进程/端口 | `test_minute_router_recovery` | 进程重启时序 | 保持 flaky；后续改 mock 重启 |
| 共享真实目录 | `test_monday_drill::test_read_only_no_side_effects` | 快照 `agent_platform/data` 全树，并行会话写入即变 | 收窄快照窗口/排除易变子目录（后续单） |
| 子进程重负载 | `test_repair_lane::test_create_and_run_batch` | 全量并发时 pytest 子进程启动慢 | timeout 已 300s；观察 |
| 未明顺序 | `closeout::test_if_changed_skips_duplicate` | 疑似模块级缓存/状态文件 | 本轮登记；下轮若再复现则查 `.closeout_state` 共享 |

## 五、与门禁关系

- `test_gate` 的 flaky 命中**不判负**，但**打印清单**（可审计）；
- 本 SOP 保证 flaky 清单**有证据、会淘汰**，避免"永久白名单化"；
- 目标（11-30 前）：agent flaky ≤5 条（全部附根因），env=0，known=2（k_stock 既存）。
