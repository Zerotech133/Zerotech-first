  --repo-root C:\aios `
  --base-8091 http://127.0.0.1:8091 --base-8734 http://127.0.0.1:8734 `
  --base-8787 http://127.0.0.1:8787 `
  --tdx-db C:\aios\quant_backtest\data\tdx\tdx_info.db `
  --tasks-fixture C:\Temp\tasks_fixture.json

**退出码**：`0`=全部 ready（可进入逐项确认）；`2`=存在 blocked/unknown（按分项处置；**2 本身不是“禁止窗口”**，而是“这些前置还没有机器可判定的 ready”）。
**状态**：`ready` = 该前置已满足/可机器判定通过；`blocked` = 明确未满足（窗口动作或前置修复对象）；`unknown` = 无法判定（网络跳过、S4U 进程创建时间不可读、schtasks 异常等）→ 需人工。

## 四、与 05:30 流程的衔接

1. 05:30 先跑本器（默认含网络），把 `--md --out C:\Temp\l2_precheck_<date>.md` 与 `--json` 落盘；
2. 按表逐项核对：`ready` 项复核即过；`blocked` 项确认“是否正是窗口计划动作/是否需提前修”；`unknown` 项人工补判（如 8091 为 S4U 取不到进程创建时间、schtasks 权限异常）；
3. 逐项向 A0 复核五要素后执行窗口；执行后再跑一次本器做行为层复核（A1/A2 应转 ready，A4/A6/A5 视执行结果）；
4. 本器**不代替**五要素审批与逐项确认，只提供机器可复跑的前置证据。

## 五、边界与已知限制

- **只读**：HTTP GET / `schtasks /Query` / sqlite `mode=ro` / 文本读取；唯一写面是 `--out` 指定的报告文件（原子写）。不改 nginx/任务/服务/配置。
- **不打印凭据**：HTTP 只记录状态码/长度/sha；配置只记录指令/行号/布尔结果，不回显文件内容；JSON/MD 无 token/secret 字段。
- **A1 新鲜度依赖 CIM `CreationDate`**：S4U/Session0 进程可能取不到（如 `Get-Process` StartTime 空）；此时本器降级为「端口判活」并给 note，不假报 ready 也不假报 blocked。
- **A2 以仓库文件为 webroot 事实源**：`docker inspect ai-portal` 显示 `C:\项目\老田的AI助手\portal` bind mount 到容器 `/usr/share/nginx/html`（只读）；若未来挂载源变化，A2 的 served-vs-repo 比对会以 blocked 暴露漂移。
- **A4 stale 用自然日**（含周末）；窗口在 11-05 05:30 跑时，阈值默认 1 天会要求 11-04 数据在库。
- **A5 在合并前预检会 blocked**（注册脚本/工具/申请单尚未进 master）：这是预期，21:40 合并后应转 ready；`--tasks-fixture` 仅测试/异地用。
- **A7 的 A7 窗口项已关闭**（11-03 09:06 执行、09:44 PASS；见组织单），本器只做链尾存在性回归，不重跑 KgDaily。
