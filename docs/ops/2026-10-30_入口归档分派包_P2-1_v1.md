## 二、复核方法（每项 5 分钟，owner 自评即可）

按顺序确认，任一命中 → 填「保留」：

1. **计划任务/自启**：`schtasks /query /xml` 搜文件名（工具已自动查，但请人工看远程/外部调度）；
2. **动态调用**：`importlib` / `__import__` / `sys.path` 拼接 / `subprocess` 拼路径；
3. **IDE/人工运行**：run config、快捷方式、个人书签、notebook；
4. **MCP/工具注册**：`agent_platform/tools`、`portal` 工具表；
5. **文档现行引用**：docs 里若仍作"现役入口"引用 → 保留或先更新文档。

**结论只填三选一**：`保留` / `归档` / `待定`（待定需写原因，进下一轮）。

## 三、回签与执行流程

1. owner 填完 CSV（`decision`/`reason`/`reviewer`/`review_date`）→ 回给关羽（或 commit 到 docs/ops）；
2. 关羽汇总 → 对 `归档` 项出 **L2 五要素批准单**（清单+影响面+回滚；原地冻结优先，其次移 `archive/`）；
3. 批准后执行：快照 → 回收站/移动 → 更新 `entrypoints_v1.tsv` + `legacy_registry_v1.md`（L2 登记）；
4. 每项留判例；**禁止**批量删除、禁止未回签先动。

## 四、纪律与风险

- 引用链口径**只是候选**：动态调用/外部调度不可见 → 误判成本高于收益，一律"先保留再论证"；
- `k_stock` 4 项为**重点风险组**（包内间接引用多），未确认前保持原状；
- `quant_backtest` 93 项可按系列批量给结论（同系列同处置），减少 owner 工作量；
- 归档动作不涉及数据根，但会改仓库结构 → 走 L2 + 回收站 + 单 commit 可 revert。
