## 一、判定对象与两轴输出

- 对象：**同一 Goal 下、四个工作面各 ≥1 件 Outcome 的事件账本**（不是页面/截图/演示视频）。
- 总判拆成两轴，分栏书写，禁止合成一个"通过"：

| 轴 | 取值 | 定义 |
|---|---|---|
| **轴一：B 阶段四件成果** | `通过` / `未通过` | B-1…B-6 全过 → 通过；任一关键项不过 → 未通过，只能报"已建 N/4 面 + 缺口" |
| **轴二：真实受控执行** | `已接通` / `仅隔离` / `受阻` | 真实消费者的正式工单、风控裁决、本人强签准是否已接通并核验。B 阶段默认 `仅隔离`（四件成果在隔离/研究边界内完成） |

**标准结论句（只允许这四句）**
1. `轴一通过 + 轴二仅隔离` → **「B 阶段隔离首版通过；生产执行、真实交易与客户级产品未通过」**
2. `轴一通过 + 轴二已接通`（需另批五要素核验） → 「B 阶段四件成果通过，真实受控执行已接通」
3. `轴一通过 + 轴二受阻` → 「B 阶段四件成果通过；真实受控执行受阻（列阻断项）」
4. `轴一未通过` → 「B 阶段未通过：已建 N/4 面，停在 X」

> 旧版 `PASS / ISOLATED_ONLY` 两个词不再单独使用；判据器可保留退出码（0/3/1/2）作为机器信号，
> 但**对外结论必须按两轴写**。

## 二、四类成果判据（O 系列）

| 判据 | 口径 | 判定 | 依据 |
|---|---|---|---|
| **O-software** | 需求 v1 冻结；隔离产物 a1 + 指纹 + 测试回执；本人 verdict；a2（或"接受不改"回执） | 通过/未通过 | 单事项 G0–G7；负例 N01/N07/N17/N19 |
| **O-business_plan** | BP v1 + 假设台账（hypothesis/validated/falsified）+ citations ≥1；**v2 必须等 X1 的真实审核反馈出现后才验**；假设状态 ≥1 条更新；未对外发送 | 通过/未通过 | G8；推断升事实/同源升级即 FAIL |
| **O-content** | 选题依据；草稿 v1；审核记录；草稿 v2；发布计划存在但**发布=BLOCKED**（无授权不得外发） | 通过/未通过 | G8；越权外发=FAIL |
| **O-research** | 数据 manifest（来源/指纹/as_of）；回测/模拟结果；风险分层结论；v2 + 修订理由；**无真实交易指令** | 通过/未通过 | G8；真实交易提示=FAIL |

每件必须回答六问：服务哪个目标 / 依据什么证据 / 谁授权 / 做到什么 / 谁验收 / 第几版。缺一问 → 该件未通过。

## 三、跨面引用判据（X 系列，v3.1 修订）

| 判据 | 合法来源 | 严格禁止 | 判定 |
|---|---|---|---|
| **X1 内容→BP（hypothesis 链）** | **老田对内容草稿的真实审核反馈**（citation：`source_surface=content`、`source_kind=conversation`、`confidence=hypothesis`、`source_ref=草稿版本`、`source_sha256`） | ① 首版未发布就写"读者/客户反馈"；② 用反馈把假设升为 validated；③ 把"表达需调整"说成"市场需求已验证" | 通过/FAIL |
| **X2 研究→产品（fact 链）** | G4 研究结论（`source_kind=data`、`confidence=fact`、带样本窗口/局限）→ **G4X 第二产品事项**的 `why_now` | ① 把研究未产出的结论回填到 G1 首件 `why_now`；② 把"样本内"写成"实盘有效"；③ 时间顺序倒置（引用晚于事项创建） | 通过/FAIL |
| **X3 通用引用规则** | 三值规则（fact/hypothesis/inference） | 推断当事实（`INFERENCE_AS_FACT`）；同源升级（`CITATION_UPGRADE`）；字段缺失（`CITATION_SHAPE`）；BP/内容/研究空引用（`CITATION_REQUIRED`） | 通过/FAIL |

**X1 表述纪律**：审核反馈只能支撑"产品表达或客户理解需要调整"这类主张，
**不能**作为"市场需求已验证"的证据；BP v2 的修订说明必须原样引用该反馈并保留 hypothesis。

**X2 顺序纪律**：G1 的 `why_now` 只能来自老田的真实需求原话；
研究结论出现后，在**同一 Goal 下新建** `G4X` 事项（`why_now` 引用研究 outcome），
由 G1 的软件能力产出该事项的隔离小页；G1 与 G4X 是两个 item，不合并、不倒填。

## 四、目标锚定判据（G-1）

Goal 由本人建立且假设带状态；每件 Outcome 挂在同一 Goal 下；`why_now`/`attempt_no` 可读；
无 Goal → 该件 `未通过（BLOCKED）`；挂错目标 → `未通过（FAIL）`。

## 五、总判条件（B-1…B-6，轴一）

| # | 判据 | 通过条件 |
|---|---|---|
| B-1 | 四件成果齐全 | 四类各 ≥1 件，类型与 `item.outcome_kind` 一致 |
| B-2 | 每件有 v1→v2 | 至少 1 轮本人反馈 + v2（或明确"接受不改"回执）；**BP v2 不得早于 X1 反馈** |
| B-3 | 跨面关联 ≥2 | X1、X2 各 1 条，X3 全过；X1 只许审核反馈，X2 只许 G4X 链 |
| B-4 | 目标锚定 | G-1 全过 |
| B-5 | 边界未破 | 无生产发布/外发/真实交易/真实账本写入；越界尝试被拒并留痕 |
| B-6 | 本人逐件验收 | 老田对每件各一句"接受/返工"（user actor）；**参与时长按真实计时记录** |

## 六、不算数的证据（防冒充，v3.1 增补）

1. 四个页面/模块能点开——不算成果；
2. 单测 PASS 数、页面截图、HTTP 200——只作辅证；
3. 会议线旧测试、PG `15/15`、OSACK `15 passed`——不覆盖本链；
4. 一版到底无 v2——不满足 B-2；
5. AI 代填"用户已确认"、`confirmed:true`——FAIL；
6. 编造读者/客户反馈——FAIL（首版未发布，不存在合法读者反馈）；
7. 用研究未产出的结论回填早期事项动机——FAIL；
8. 只写"约 20 分钟"没有真实开始/结束/动作记录——不算 B-6；
9. 模拟/回测写成"实盘验证"——FAIL。
