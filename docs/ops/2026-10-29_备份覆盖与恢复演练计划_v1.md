# 备份覆盖与恢复演练计划 v1（2026-10-29 · 关羽）

> 背景：B4 复盘发现 `backups/db` 自 2026-10-15 停更（dump 脚本容器名过期），**已修复并实跑验证**。本计划固定覆盖矩阵与季度演练。

## 一、覆盖矩阵（2026-10-29 实跑）

| 资产 | 容器/来源 | 方式 | 产物 | 本次结果 |
|---|---|---|---|---|
| 菜鸟 MySQL | `quant-cainiao-mysql` | `mysqldump --all-databases --routines --triggers` | `cainiao_mysql_alldb.sql.gz` | ✅ 2.42GB / 42s |
| 智策 OS v2 PG | `zhice-db` | `pg_dump --no-owner` | `zhice_os_v2.sql.gz` | ✅ 7.71GB / 161s |
| quant-pg（含 quant_meta） | `quant-pg` | `pg_dumpall`（全库） | `quant_pg_alldb.sql.gz` | ✅ 0.47GB / 12s |
| Neo4j KG | `neo4j-kg` | 在线 dump **不可用**（community 需停库） | 每日 0300 备份 `neo4j_kg.tar.gz` | ✅ tar 415.8MB（10-29） |
| zerobound Neo4j | `zerobound-neo4j-independent` | 同上 | 同 tar 链 | ⚠️ 由 tar 覆盖，dump 报 ERROR 属 known |
| 离线备份链 | 每日 0300 | `backup_bundles.ps1` + tar + zhice dump | `backups/YYYY-MM-DD_0300/` | ✅ 每日在跑 |

- dump 落 `backups/db/<日期>/`，`manifest.json` 记录每项 rc/大小/耗时；
- 轮转：保留 14 天（脚本内置，删除走回收站）。

## 二、已知边界
1. Neo4j community 在线 dump 不支持 → 以每日 tar 为覆盖手段（**不要**为 dump 停库）；
2. 大库（zhice 7.7GB）dump 约 160s，安排在低峰（现为手工/按需；建议纳入 0300 链）；
3. 覆盖脚本的容器名与现网强绑定 → 容器改名必须同步 `ops/db_dump_daily.py`（本次根因）。

## 三、季度恢复演练（首次建议 2026-11-05 10:00）
1. 选表：`quant_meta` 任一表 或 cainiao 小表；
2. 恢复到**临时库**（PG：`createdb drill_tmp` + `psql -f` 子集；MySQL：临时 schema）；
3. 校验：行数 vs catalog/源库计数、抽样字段；
4. 记录：演练回执（时间/库/表/行数/耗时/结论）落 `_reviews_*/`，并写 `kg_sync_task.log`；
5. 清理临时库（回收站/删库前快照）；
6. 失败即升级：备份不可用 → 按 P0 处理并重跑每日链。

## 四、KPI
- 覆盖：核心库 100%（含 quant_meta）；Neo4j 由 tar 覆盖并标注；
- 备份链：每日 0300 成功、db dump 每周至少 1 次成功；
- 演练：每季度 ≥1 次，回执可查；
- 磁盘：`backups/db` ≤ 30GB（当前 14.6GB，C 盘余 1.2TB）。
