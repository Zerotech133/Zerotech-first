# 脚本入口登记表 v1（2026-10-28 · 关羽）

> 背景：全代码审计发现约 **830 个可执行入口**（quant 471 / tools 241 / portal 118 / agent 188），研究脚本与产线代码混放，维护面过大。
> 本表 = 入口清单基线；**新增入口必须登记**，低频入口按季度归档。

## 一、口径

- 范围：自研主线 13 个目录（`agent_platform / portal / quant_backtest / k_stock / news_collector / jev-eval / osint_video / common / analysis / tools / ops / ollama_service / data_sources`）；
- 入口定义：模块级 `def main(` 或 `if __name__ == "__main__"`（取并集，标注 both/main/guard）；
- 生成：`python tools/gen_entrypoints.py`（默认输出 `docs/ops/entrypoints_v1.tsv`）；
- 排除：venv/vendor/archive/交付物/外部子系统（Hermes、AI/111111、zerobound-kg）。

## 二、纪律

1. **新增脚本必须登记**：提交信息注明用途；本季度复查一次；
2. **产线入口 vs 研究脚本**：产线入口（被计划任务/服务调用）需在表内标注 owner；研究脚本迁 `research/` 或归档；
3. **禁止新增未登记入口**（评审时抽查，后续可纳入 test_gate 建议项）；
4. 入口表随代码演进重新生成，生成结果作为 diff 评审依据。

## 三、基线（2026-10-28）

- 生成文件：`docs/ops/entrypoints_v1.tsv`（path / entry_type）；
- 入口总数以生成文件为准（约 800+）；
- 后续目标：**减少低频脚本**（归档 ≤3 个月未运行）、产线入口全部有 owner。
