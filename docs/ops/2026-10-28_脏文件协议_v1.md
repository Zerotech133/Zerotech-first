# 脏文件协议 v1（P0 #2，2026-10-28 · 关羽）

> 背景：并行会话把**跟踪文件**改了不提交，长期占用主区，阻塞他人合并（今天 B4 被卡 17h+、重试 27 次）。根因不是态度，是**协议缺失**。
> 工具：`python tools/check_dirty.py`（看板）/ `--strict --max-age-hours 4`（巡检判负）。

## 一、规则（对"跟踪文件"生效）

| 年龄 | 动作 |
|---|---|
| **> 2h** | 看板标黄；owner（最近提交者）需在工单/公告板说明 |
| **> 4h** | `--strict` 判负；合并前 `check_dirty` 会提示；需在回单注明 |
| **> 8h** | 升级 A0（老田），允许一次性协调清场（stash/commit/交接） |
| **并行 WIP 文件** | 登记在 `tools/check_dirty.py` 的 `KNOWN_WIP`（9 个），只提示不判负；登记需在回执说明理由 |

## 二、为什么管"跟踪文件"而不是全部

- 未跟踪文件（`deliverables/`、`_reviews_*/`、`data/` 等）是产出物，不影响合并，默认不看；
- 只有**跟踪文件**的本地修改会与 `git merge` 冲突、阻塞合并。

## 三、看板用法

```powershell
python tools\check_dirty.py                       # 人看：年龄/类型/owner 提示
python tools\check_dirty.py --json                # 机读（进事件/日报）
python tools\check_dirty.py --strict --max-age-hours 4   # 巡检：超时 exit 1
python tools\check_dirty.py --include-untracked   # 含未跟踪（偶发排查用）
```

## 四、与既有机制的配合

1. **合并不被脏文件卡死**：先跑 `check_dirty`，冲突文件走"窄单"策略（B17 先例：避开脏文件、从当前 master 重建机械修）；
2. **质量闸（P0 #1）**：`merge_gated.py` / `pre-merge-commit` 钩子负责"合并时测试绿"；本协议负责"主区别长期占着"；
3. **数据根互斥**：仍以 `C:\Temp\kg_sync_task.log` 为准（结构性操作前读尾部）。

## 五、升级路径

- 短期：看板 + 人工提醒（每日 10:00/16:00 跑一次）；
- 中期：计划任务每 2h 跑 `--strict --max-age-hours 4`，失败发 `guard_fail` 事件（需 L2 批准）；
- 长期：文件级租约（认领 `tools/ownership.json`，超时回收），需与并行线协商。
