# D1 日终批量裁决与交棒 v1

> 状态：**现行**（2026-11-16 WO-D1-DAILY-BATCH）
> 计划任务：`D1DailyBatch`，每天 **09:05**（开盘前），`tools/d1_daily_batch.py --top 5 --json`

## 一、为什么有它

两件事同时解决：

1. **业务**：D1 每天都该对会审精选出裁决并交棒盯盘，此前靠人手工跑，经常断（`d1_decisions` 从 11-04 停到 11-16）。
2. **可测**：Q2 的 3 个写接口因「业务直写文件、绕开 API」导致 POST 数为 0，SLO 只能判 NOT_MEASURED。
   本任务让 D1 的日常动作**天然走 HTTP**，样本随业务自然积累。

## 二、一轮做什么

```
pool_v2_sessions.jsonl（最后一场会审）
  → 精选池按聚合分降序，跳过「本池日已判过」的代码
  → Top N（默认 5）
      → POST /api/d1/decision   （五档 + confidence + 三席依据，Idempotent-Key = d1dec-<池日>-<代码>-v2）
      → 有收盘价才 POST /api/d1/handoff（交棒 WA1，带止损/止盈两条 watch_plan，Key = d1ho-<池日>-<代码>-v2）
  → 对 Top1 标的开一场 D1 投研会（create → T1/T2/N1/F1 四票 → finalize，走 POST /api/d1/meeting）
  → watch_plan_autoarm --once（把新 plan 上膛成 armed）
  → 追加 logs/d1_daily_batch.log，--json 输出结构化摘要
```

## 三、幂等与限流（都是踩过的坑）

| 机制 | 细节 |
|---|---|
| **去重** | 读 `d1_decisions.jsonl`，若该 `code` 的 `evidence` 里已含当前 `session_id` → 跳过。换池日则允许新裁决 |
| **幂等键** | 绑定「池日 + 代码」，重跑返回原记录、账本不新增（实测同 `decision_id`） |
| **写端点限流** | portal_api 写接口 **每 IP 每分钟 ≤12 次**；本任务每次写间隔 `--interval`（默认 6s），一轮 2×N 次写刚好在窗口内。首版未节流曾整批 429 |
| **无行情** | `last_close()` 取不到 → 只写裁决、跳过交棒并记 `skipped_no_quote`，**不造数** |
| **arm 失败** | `watch_plan_autoarm` 失败只告警（`ARM_WARN`），不影响已经落账的裁决 |

## 五、与 SLO 的关系

| 写接口 | 每轮样本 | 达 20 条需要 |
|---|---|---|
| `d1.decision.create` | N（默认 5） | **4 轮**（约 4 个交易日） |
| `d1.handoff.create` | N（默认 5，需有行情） | 同上 |
| `d1.meeting.create` | 6（create + 4 票 + finalize） | **3 轮**（约 3 个交易日） |

样本进 `C:\Temp\portal_api_access.log`（行尾带 latency），用 `tools/d1_write_slo.py` 汇总。

## 六、边界

- 只写裁决与交棒回执，**不建单、不执行、不接实盘**（`paper_only=true`、`not_a_trade=true`）。
- 只对本场会审的精选池出裁决，不做全市场扫描、不改池。
- 不改阈值、不造行情、不冒充 measured（样本不足时 `d1_write_slo` 仍判 INSUFFICIENT_SAMPLES）。
