## 2. 方案选择

### 2.1 候选对比

### 2.2 主方案理由（写进 L2 结论）

1. 验收口径要求“**401→200 的合法鉴权路径 + 未登录仍 401**” → 只有受保护前缀同时满足；
2. 与 H4（2026-10-30）/H4-B（2026-11-01）方向一致：默认拒绝 + 高敏数据面登录后读，**不再新增匿名读面**；
3. 数据事实：`stats` 暴露主机绝对路径，`list/get` 暴露数据集相对路径与体量，`sample` 暴露真实样本 → 匿名化不可接受；
4. 页面已按“401 降级/登录后全功能”设计（`credentials:"same-origin"`），方案与前端现状天然匹配；
5. 8091 零改动、无重启，回滚仅需恢复 1 个文件 + reload。

### ③ 不可逆点

- **无数据不可逆**：不写库、不改 schema、不改 8091 代码、不迁移任何文件。
- 配置可还原（备份文件 + 回执目录副本）；reload 失败时 nginx 保持旧配置运行（先 `nginx -t` 再 reload，双保险）。
- 会话不受影响（本次不重启 8091；同窗 8091 换血由执行包自身负责，其会话清空属其影响面）。
- 唯一“半不可逆”是**语义变化**：匿名 401 错误体由 `api_not_in_whitelist` 变为 `unauthorized`；回滚即恢复。已确认全仓无按该错误码分支的客户端（`api_not_in_whitelist` 仅出现在守卫测试与 2 份文档）。

### ④ 替代方案

1. **替代 A（旧申请单方案）**：把 `dw` 加进 H4-B 公开白名单 → 匿名 200。改动见 §3.3；风险=匿名可读数据集路径/绝对 inventory 路径/真实样本，与 H4-B 收敛方向相反；若 A0 选择此方案，需在 L2 单注明“接受匿名暴露 + 审计登记”，并把 §5 验收口径改为“匿名 200 + 未登录不再 401”。
2. **替代 B（混合）**：公开 `dw` metadata（stats/list/search），对 `^~ /api/dw/sample`、`^~ /api/dw/get` 加 auth_request。仍匿名泄露路径与绝对 inventory 路径，且多一层嵌套规则，收益不划算。
3. **替代 C（不改动）**：页面永久快照降级，8734 无法取实时数仓（DWH-104 §六/§七的 P1 入口缺口不闭合）；不推荐。
4. **替代 D（BFF 化）**：在 8091 新增 `/api/bff/dw/*` 由门户服务端代取（浏览器只调 BFF）——需新增代码与测试，比 nginx 前缀方案重；若未来要“浏览器完全不接触 8091 直连语义”再走，本轮不需要。
