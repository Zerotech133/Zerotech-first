# 17 席 A0 日报 07:50 失败修复（2026-11-06）

## 结论

11-05 07:50 的 17 席日报没有产出 `deliverables/daily_briefs/2026-11-05/rollup.json`，任务
`AI-Workstation-A0-Daily-Board` 的 `Last Result` 为 `1073807364`（`0x40010004`，进程被终止）。
根因指向任务执行超时，而不是模型全部返回失败：

- 任务 XML 原 `ExecutionTimeLimit=PT20M`；
- `C:\Temp\hq_daily_run.log` 最后写入时间为 `2026-11-05 07:50:14`，只包含当日 data brief，之后无
  `hq/dept_daily_run` 输出；
- 11-06 05:55 对单个席位 `AI1` 做真实 `/api/chat` 调用，延迟 `45,716 ms`、`binding=glm/glm-5.3`；
  17 席在低并发下可能接近或超过 20 分钟上限。

这只证明“20 分钟上限不足 + 没有进度日志”，不把未生成的 rollup 说成成功。

## 修复

### `ops/run_hq_daily.ps1`

- 使用 `-u` 运行 Python，避免重定向日志被缓冲到进程结束；
- 每个席位超时从默认 120s 收紧为 `--timeout 90`，并发从 3 提到 `--concurrency 4`，给 17 席留出
  有界运行时间；
- 写 `START`、`BRIEF`、`END` 三个带时间戳的日志行，并记录 rollup 是否存在；
- 保留“data brief 失败不阻塞日跑”的原行为。

### Windows 任务 `AI-Workstation-A0-Daily-Board`

- `ExecutionTimeLimit` 从 `PT20M` 提高到 `PT1H`；
- `StartWhenAvailable=true`、`MultipleInstances=IgnoreNew` 保持不变；
- 修改前 XML 备份：`C:\Temp\AI-Workstation-A0-Daily-Board_pre_20261106.xml`；
- 查询确认：Next Run `2026/11/6 7:50:00`，Status Ready。
