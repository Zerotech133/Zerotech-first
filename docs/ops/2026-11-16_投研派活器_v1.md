# 投研派活器（Research Dispatch）v1

> 状态：**现行**（2026-11-16 WO-RESEARCH-DISPATCH）
> 脚本：`tools/research_dispatch.py` · 测试：`tools/test_research_dispatch.py`（6 例）

## 一、它补的是哪一环

诊断结论（2026-11-16）：

```
席位在岗 ✅   12 席 09:20 心跳全绿（ST1/T1/T2/N1/F1/D1/WA1/…）
派活通道 ❌   没有任何动作把池内标的交给席位
产出为空 ❌   ACAD1 池 30 只：analyses={} / recommendation=null / node_exec=[]
```

即「有工人、有工位、没有工单」。本工具就是那条工单通道：

```
读池（ACAD1 官方池，CN 12）
  → 每只生成 4 个工单（T1 多 / T2 空 / N1 舆情 / F1 基本面）
  → 调 engine.deepseek（与席内心跳同一通道）
  → 汇总成 recommendation + confidence（规则透明）
  → 落 research/<date>/<code>.json + research_index.jsonl
```

## 二、边界（两条硬约束）

| 约束 | 原因 |
|---|---|
| **不写 PG** | `v2_acad1_pool` 是 ACAD1 只读真源（projection 写明「不写库」）。`action=analyzed` 只能由 ACAD1 侧改；本工具产出落本地 `data/research/`，供下游消费 |
| **不许编造** | 席位 prompt 强制「材料不足写进 `evidence_missing`」；实测四席全部照做 |

## 三、席位 prompt 与产出结构

每个席位一份 system + user：

- **system**：席位身份（从 `agent_platform/prompts/<seat>.md` 读真卡，含立场强制条款摘要）+ 硬规则
- **user**：ACAD1 池条目原始字段（code/name/signal/score/selection_reason/risk_flags/data_date…）
- **输出**：`{"stance":"bull|bear|neutral|unknown","points":[],"risks":[],"evidence_missing":[],"verdict":"","confidence":0.0}`

## 四、汇总规则（透明可复核）

| 条件 | 结论 | conf |
|---|---|---|
| 四席全无产出 | `UNKNOWN` | 0.0 |
| ≥2 席 bear | `AVOID` | 均值 × 0.8 |
| ≥2 席 bull 且 0 席 bear | `BUY` | 均值 |
| 其余（分歧/缺席位） | `HOLD` | 均值 × 0.9 |

conf 区间：0.10 – 0.32
产出：agent_platform/data/research/20261116/*.json（12 份）+ research_index.jsonl（12 行）

## 六、最重要的对比：机械映射 vs 真投研

| 方式 | 12 只的结论 |
|---|---|
| 桥的机械映射（`acad1_pool_bridge`） | **全部 BUY**（按 score 归一 conf 0.49–0.70） |
| 四席位真投研（本工具） | **全部 HOLD**（conf 0.10–0.32） |

差别不在模型，在**证据标准**：席位被要求「结论必须能复核」，于是它们一致拒绝在只有 `signal/score` 的情况下给买入结论。这正是投研应有的样子。

## 七、下一层缺口（本轮实证暴露）

四席一致指出缺同一批输入：

- 量价/结构数据（T1、T2 都要）
- 资金流、筹码（T2）
- 热度/舆情/公告（N1）
- 财务/行业景气（F1）

对应可补的源：`xsec_profile v2`（生成器 `xsec_profile.py` 在，`panel_xsec*.parquet` 在，但 `data/xsec/` 只有 10-31 的 `l4_status.json`）。

**结论：投研链已通，但当前喂进去的材料只有池条目本身，所以产出必然是保守的 HOLD。** 要让席位给出有方向的结论，下一步应先产出 xsec_profile 并接进工单材料。

## 八、用法

```powershell
python -X utf8 tools/research_dispatch.py --limit 1 --dry-run    # 看首个工单 prompt
python -X utf8 tools/research_dispatch.py --only 001228.SZ       # 单只
python -X utf8 tools/research_dispatch.py                        # 池内全部 CN
```

参数：`--model`（默认 deepseek-flash）、`--max-tokens`（默认 3000；<2000 会导致长回复被截断解析失败）、`--pool-date`。

## 九、已知限制

- 单只约 20–35 秒（4 席串行）；12 只约 2–3 分钟。未做并发（避免席位限流）；
- `T2` 输出最长，`--max-tokens` 低于 2000 时实测会截断 → `no_json` 失败（已调到 3000）；
- 索引按 `(code, pool_date)` 去重，重跑覆盖而非追加；
- 不写 PG、不产生交易指令（`paper_only/not_a_trade=true`）。
