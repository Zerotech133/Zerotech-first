# 投研派活器（Research Dispatch）v1

> 状态：**现行**（2026-11-16 WO-RESEARCH-DISPATCH）
> 脚本：`tools/research_dispatch.py` · 测试：`tools/test_research_dispatch.py`（6 例）

## 一、它补的是哪一环

诊断结论（2026-11-16）：

```
席位在岗 ✅   12 席 09:20 心跳全绿（ST1/T1/T2/N1/F1/D1/WA1/…）
派活通道 ❌   没有任何动作把池内标的交给席位
产出为空 ❌   ACAD1 池 30 只：analyses={} / recommendation=null / node_exec=[]
```

即「有工人、有工位、没有工单」。本工具就是那条工单通道：

```
读池（ACAD1 官方池，CN 12）
  → 每只生成 4 个工单（T1 多 / T2 空 / N1 舆情 / F1 基本面）
  → 调 engine.deepseek（与席内心跳同一通道）
  → 汇总成 recommendation + confidence（规则透明）
  → 落 research/<date>/<code>.json + research_index.jsonl
```

## 二、边界（两条硬约束）

| 约束 | 原因 |
|---|---|
| **不写 PG** | `v2_acad1_pool` 是 ACAD1 只读真源（projection 写明「不写库」）。`action=analyzed` 只能由 ACAD1 侧改；本工具产出落本地 `data/research/`，供下游消费 |
| **不许编造** | 席位 prompt 强制「材料不足写进 `evidence_missing`」；实测四席全部照做 |

## 三、席位 prompt 与产出结构

每个席位一份 system + user：

- **system**：席位身份（从 `agent_platform/prompts/<seat>.md` 读真卡，含立场强制条款摘要）+ 硬规则
- **user**：ACAD1 池条目原始字段（code/name/signal/score/selection_reason/risk_flags/data_date…）
- **输出**：`{"stance":"bull|bear|neutral|unknown","points":[],"risks":[],"evidence_missing":[],"verdict":"","confidence":0.0}`

### 6.6 又一处"表面现象骗人"：T1 不是认输，是被截断

我上一轮说「`605058.SH` 是唯一"多头主动认输"的——T1 从 bull 退到 unknown」。**又是错的。**

查证：

```
605058.SH  T1 ok=False  ms=18781  err=no_json
           raw_head = {"stance":"neutral","points      ← 有内容，但 JSON 被截断
           seats_ok = 3/4
```

**T1 根本没缺席，是它写太长（18.8 秒、超 token 上限）被截断，解析失败，于是在汇总里"消失"。**
它想说的其实是 `neutral`，不是 `unknown`；而 `seats_ok=3/4` 让汇总只按 3 席算，conf 被拉低到 0.16。

这暴露一个**系统性问题：席位越认真越容易"消失"**——输出越长 → 截断 → `no_json` → 被判缺席 → 汇总失真。

修法两条一起上：

1. prompt 里加**篇幅硬约束**：`points/risks/evidence_missing ≤ 5 条，每条 ≤ 80 字`；
2. `--max-tokens` 3000 → 4000（保留余量）。

重跑 `605058.SH`：

```

汇总 HOLD conf=0.30
```

**它从来不是"空头单边"，而是完整的「多空对立」。**

# v2：按「菜鸟系统」的 Agent 团队契约补齐三件（2026-11-16 17:0x）

## 十、C：执行三态（对齐 `execution_mode`）

原来只有 `ok/error`，导致 **`no_json`（输出被截断）被当成"席位没说话"**——今天因此误判两次
（`001326` 的"全未知"、`605058` 的"多头认输"）。

现在显式三态：

| mode | 含义 | 判定 |
|---|---|---|
| `normal` | 拿到可用结论 | JSON 解析成功 |
| `debate` | 该席位处于辩论阶段 | phase 标记 |
| **`degraded`** | **有输出但不可用 / 彻底失败** | `no_json`、`empty_reply`、超时 |

`summary` 里新增 `seats_degraded`，并参与风险判定（降级 ≥2 席 → `risk_level=HIGH`）。
以后再看到"某席 silent"，先看 `mode` 是 `degraded` 还是真的 `unknown`。

## 十一、A：结果契约（五档 + 0-100 + 风险 + 周期）

```json
{
  "recommendation_level": "STRONG_BUY|BUY|HOLD|SELL|STRONG_SELL|UNKNOWN",
  "confidence_score": 0-100,
  "risk_level": "LOW|MEDIUM|HIGH",
  "time_horizon": "SHORT|MEDIUM|LONG_TERM",
  "target_price_min": null,
  "target_price_max": null,
  "target_price_note": "缺行情/估值模型输出，按规则留空"
}
```

映射规则：

| 条件 | 档位 |
|---|---|
| 全席降级 | `UNKNOWN` |
| bear ≥ 2 | `STRONG_SELL`（bear≥3 或 avg≥60）否则 `SELL` |
| bull ≥ 2 且 bear = 0 | `STRONG_BUY`（bull≥3 且 avg≥60）否则 `BUY` |
| 其余 | `HOLD`（文案按 多空对立/单边/全中性/全无立场 四档区分） |

- `confidence_score`：席位给 0–1，统一 ×100 后取均值；
- `risk_level`：`bear≥2 或 degraded≥2 → HIGH`；`bear≥1 或 unk≥2 或 degraded=1 → MEDIUM`；否则 `LOW`；
- **`target_price` 一律 null**：没有可靠的行情/估值模型输出，按规则不编造。

## 十二、B：辩论（T1↔T2 互辩 2 轮）

触发条件：`T1` 与 `T2` 的 `stance` 恰好是 `bull` vs `bear`（对齐菜鸟 `is_debate_node`）。

辩论轮 prompt 要求：
- **逐条针对性回应**对方论据（承认成立的、指出不认同的）；
- 允许据实修改立场，但不得和稀泥；
- 落 `debate_log`（每轮双方 stance + verdict）。

实测 `001228.SZ`（2026-11-16 16:54）：

```
轮1  T1 bull：承认高位与事件未核验两项硬伤，但材料内无任何派发或反向信号，
              CHAN_V7评分100且缩量wash与runup同真，维持条件性看多，
              建议分批建仓并把事件核验作为加仓门槛。
     T2 bear：承认CHAN_V7与高位强势，但事件核验缺失、缩量解释二义、增强证据为空，
              维持反对立即买入。
轮2  T1 bull：我接受高位缺缓冲与事件未核验两项硬伤，但T2未给出任何反向信号，
              材料内distribute=false且CHAN_V7=100，维持条件性看多…
     T2 bear：承认CHAN_V7评分100、distribute=false与无反向信号，但事件核验未完成、
              缩量二义、缺止损与结构位，维持反对。
辩论后 T1=bull T2=bear 改变=False → HOLD conf=33.5 risk=MEDIUM
```

**关键**：双方都在**引用对方的具体论据**（`distribute=false`、`CHAN_V7=100`）并回应，

# v3：加决胜席（Final Decision），对齐菜鸟 `final_decision` 节点

## 十四、为什么需要它

v2 跑完全量 12 只后发现一个结构性问题：

```
T1  bull 10 / neutral 1 / unknown 1
T2  bear 12 / 12          ← 空头对每一只都看空
N1  neutral 11 / bear 1
F1  bear 6 / neutral 4 / bull 2
```

规则 `bear≥2 → SELL`、`bull≥2 且 bear=0 → BUY` 在这组数字下的实际效果是：

- **T2 恒 bear** ⇒ 只要 F1 再转空就是 SELL（6 只）；F1 不转空就 HOLD（5 只）
- **`BUY` 永远不可能成立**（因为 `bear=0` 这个条件被 T2 的恒定立场永久破坏）
- **T1 的 10 个 bull 对结果毫无影响**

即：**四席都说话了，但规则只让 F1 一票有决定权。** 补数据是必要的，但不足以让结论多样。

## 十五、决胜席的设计

| 项 | 设计 |
|---|---|
| 触发 | `should_finalize(bull, bear)`：四席里同时存在看多与看空（真对立） |
| 输入 | 四席立场/论据/缺失 + 辩论纪要 + 三份画像（xsec/finance/sentiment） |
| **硬约束** | ① 必须选出五档之一，**不允许 unknown**；② 必须指出**决定性证据**；③ 必须指出**被否定的论据** |
| 输出 | `decision_level` / `confidence` / `decisive_evidence[]` / `rejected_arguments[]` / `rationale` |
| 覆盖方式 | 覆盖规则结论，但**保留 `rule_level` / `rule_confidence`** 以便随时对比 |
| 失效处理 | 决胜席降级或给出非法档位 → 回落规则，并记 `final_seat_status` |
| 成本 | 仅在对立时调用，每只 +1 次 |

`--no-final` 可关闭，退回纯票数规则。

## 十六、实测（`300476.SZ`，2026-11-16 18:01）

**规则结论**：`HOLD` conf 43.9（多 2 / 空 1）

**决胜席结论**：`HOLD` **conf 58.0**，并给出：

决定性证据（3 条）：

1. 「T1 席位终裁自认『无右侧确认与财务斜率走弱成立』，多方自身材料只支持小额试多，不足以构成正式买点」
2. 「pos250=0.0 叠加 vol20_vs_prev20=1.47 仅来自单日收盘，方向未定；T2 指出缺多日 K 线与成交量绝对值，属左侧接刀」
3. 「F1 财报滞后 **139 天**已超 120 天阈值，且 ROE 由 **33.76% 降至 10.48%**、营收增速 79.77% 降至 28.77%」

被否定论据（3 条）——**它同时否决了双方各一条**：

1. 不采纳 T2「五项假设全否即空头压力」：`hypothesis_distribute` 等为 false 属**证据空白**，双向中性，不可单方计空
2. 不采纳 T2 将 −9.5 万元主力净额记作负面：五日均值极小、口径不明，属**噪声级**
3. 不采纳 T1 把 1.47 放量当作多方承接：缺绝对量与多日 K 线，**量能方向对多空对称**

**这才是裁决**：不是站队，而是逐条给出「采纳/否决」的理由，并把置信度从 43.9 提到 58.0。

# v4：空头粒度收口（两种 SELL 口径）

## 十八、问题的由来

抽查 `301081` / `688777` 时发现规则把两种性质完全不同的「空」合并成一票：

| 空头类型 | 含义 | 该出什么 |
|---|---|---|
| `valuation` 估值/业绩 | 不值这个价 | **不该买** |
| `technical` 破位/新低 | 价格已坏 | **该卖** |
| `flow` 资金/筹码 | 没人接 | 不该买 |

规则 `bear≥2 → SELL` 把它们加在一起，于是「两席说估值高」也会判 `STRONG_SELL`，由决胜席再拉回 `HOLD`。

## 十九、做法：不改 prompt，用已有论据归类

`short_types()` 从席位已产的 `verdict/points/risks` 文本判别类型（零额外成本）：

```python
SHORT_KW = {
  "valuation": ("PE","PB","PS","估值","净利率","毛利","利润","ROE","现金流","OCF","营收","增长","业绩","计提","亏损"),
  "technical": ("破位","跌破","新低","放量下跌","顶背离","底背离","价格背离","下穿","失守","均线下方"),
  "flow": ("资金","主力","净流出","净流入","筹码","户数","换手","减持"),
}
```

**两个词表陷阱**（都是回放时才发现的）：

1. **否定语境**：`688777` 写「**无破位**证据」，裸匹配就命中 → 加 `_hit_positive()`，关键词前 4 字含「无/未/缺/没有/未见」则不计；
2. **同词异义**：修完 1 后仍命中，因为 F1 写「**估值与基本面背离**」（基本面背离，不是价格背离）→ 去掉裸「背离」，只留「顶背离/底背离/价格背离」。

## 二十、两种口径与回放对比

`--sell-policy {technical|valuation}`：

| 口径 | 含义 |
|---|---|
| `technical`（默认，保守） | SELL 必须至少一条 `technical` 依据；只有估值/资金偏空 → 降 HOLD |
| `valuation`（激进） | 估值或资金型空头即可 SELL，不要求价格已破位 |

回放 12 只（同一天数据，不重跑）：

| 代码 | valuation 口径 | technical 口径 | 差异 |
|---|---|---|---|
| `001326.SZ` | SELL | HOLD | **≠** |
| `003036.SZ` | SELL | HOLD | **≠** |
| `300314.SZ` | STRONG_SELL | STRONG_SELL | |

## 二十一、必须交代的副作用

`technical` 口径下 `SELL` 会**很少出现**——只在明确破位时才有。今天的 12 只里只有
`300314`（250 日高位放量无承接）与 `301108` 保留卖出侧档位。

- 若交易逻辑是「价格坏了才走」→ 用 `technical`（默认）
- 若交易逻辑是「基本面烂就别拿着」→ 用 `--sell-policy valuation`

两条都可跑，差异就是上表那 5 只。
