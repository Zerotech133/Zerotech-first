## 2. 401 语义（实证 + 源码）

**401 不是 nginx 门户拦截，而是 8105 服务自身的 JWT/角色鉴权**：

| 证据 | 内容 |
|---|---|
| 同 body 对照 | 8734 6 路径 401 body sha256-12 全 = `7b97e04cadc0`；8105 直连同路径同 sha |
| 错误体 | `{"detail":"missing token"}` —— 来源 `zhice_os_v2/api/dependencies.py` L244-256 `resolve_request_identity()`：无 `Authorization: Bearer` → `HTTPException(401, "missing token")` |

## 3. SSO 链路（源码 + 负例实证）

```
浏览器登录 8734 门户（zb_session cookie）
  → 前端/调用方 POST /quant-api/api/v1/auth/portal-sso（nginx rewrite → 8105）
  → 8105 auth.py L266-296：读 zb_session → 请求门户 /api/bff/identity/me
      → 映射 zhice_user_id → 查用户/active → create_token(JWT)
      → 200 {"ok":true,"token":...,"username":...,"role":...,"read_only":false}
  → 之后请求 /quant-api/api/v1/acad1-research/* 带 Authorization: Bearer <JWT>
      → 8105 resolve_request_identity（签名/有效期/用户/会话版本）→ 200
```

无 session 时的 401 code 全集（源码）：`portal_sso.no_session`（实测 ✅）、`portal_sso.portal_unreachable`、
`portal_sso.not_mapped`、`portal_sso.user_inactive`；acad1-research 无 token → `{"detail":"missing token"}`（实测 ✅）。
本轮**未持有任何门户会话/凭据**，故 SSO 正路径与 6 个接口的 200 数据列为「待登录验证」（未伪造 200）。
