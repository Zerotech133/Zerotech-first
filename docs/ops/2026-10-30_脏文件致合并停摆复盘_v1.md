# 脏文件致合并停摆 · 复盘与守卫 v1（2026-10-30 · 关羽）

> 用户反馈：**并行 worktree 脏文件导致合并停摆（B4 已 BLOCKED 17h+）**。本单做根因复盘并落地"快速失败"守卫，避免同类停摆。

## 一、现象与代价

- 2026-10-29 上午 B4（备份覆盖）等单在 `devtask merge` 中反复失败；
- 失败点出现在 **`git merge` 最后一步**（"Your local changes would be overwritten"），此前已白跑静态门/质量闸（数分钟~十几分钟/次）；
- 叠加并行会话持续写入 master 工作区，单次停摆 17h+ 才被人工定位。

## 二、根因链

1. **多个并行会话在 master 工作区留下未提交文件**（非各自 worktree 内提交）：
   - 实测 4 个 tracked 修改：`gzh/drafts/index.json`、`jev-eval/backup_daily.ps1`、
     `quant_backtest/start_xueqiu_crawl.ps1`、`tools/datawarehouse/qualify_probe.py`；
   - owner 提示：DSH-Lead / laotian-agent / Trae·Worker（`tools/check_dirty.py --strict` 可查）；
2. 待合并分支的改动路径与这些脏文件**重叠**时，git 拒绝 checkout/merge；
3. 原 `devtask merge` **没有前置脏文件检查** → 直到最后一步才暴露，失败信息埋在长日志尾部，且不提示"谁的文件/怎么处置"；
4. 并行会话持续产生新脏文件 → 撞车概率随时间上升 → 停摆。

## 三、已落地守卫（P49）

`devtask merge` 新增 `_dirty_overlap_guard`（门禁之前、秒级）：

- 计算 `git diff --name-only master...task/X` ∩ `git status --porcelain`；
- 有重叠 → 列出文件、打印处置建议（等 owner 提交 / 窄单排除 / 禁止覆盖他人 WIP），并**立即拒绝合并**（不进测试门，省去白跑）；
- `git status` 不可得时 fail-open（仅此守卫，不影响其它门）；
- 事件层记 `guard_fail` 留痕；单测 3 条覆盖：无重叠放行 / 重叠拒绝 / 状态不可得 fail-open。

## 四、SOP（遇到停摆怎么 5 分钟内定位）

```powershell
python tools/check_dirty.py --strict --max-age-hours 4   # 谁的文件、多久了
git status --porcelain                                    # 确认路径
# 处置优先级：
# 1) 等 owner 提交/清理（先小窗沟通，不直接动他人文件）
# 2) 窄单策略：从当前 master 另起分支，动态排除脏文件路径
# 3) 仅当确认是废弃 WIP：owner 授权后回收站清理（禁 rm/del）
```

## 五、预防

- 本守卫已内联到 `devtask merge`（快速失败，不再白跑门禁）；
- 脏文件巡检任务 `ZeroBound\CheckDirty2H`（2h）持续输出看板；
- 协议：脏文件 >2h 提醒 owner、>4h 工单注明、>8h 升级 A0（`docs/ops/2026-10-28_脏文件协议_v1.md`）；
- 建议各并行会话遵守"**能进 worktree 就不在 master 直接改**"，收尾即提交或回收站清理。

## 六、验收

- 制造重叠场景 → merge 在秒级失败并列出文件（P49 单测 + 实仓验证）；
- 无重叠时行为不变（并行验证 P46/P47 已证）。
