# 合并质量闸 · 使用说明 v1（2026-10-28 · P0 #1）

> 目的：堵住"带失败测试合入主区"的漏洞。`devtask.py merge` 只跑静态门，本闸在合并前跑真实测试。

## 一、日常用法

```powershell
# 标准：跑 test_gate -Suite fast（portal + k_stock，约 4~5 分钟）→ 全绿才合并
python tools\merge_gated.py <TID>

# 只跑测试不合并（预检）
python tools\merge_gated.py <TID> --dry-run

# 换套件（如改 quant 相关：--suite all 约 25 分钟）
python tools\merge_gated.py <TID> --suite all

# 纯文档/配置单会自动跳过测试（docs/、deliverables/、portal/static/、agent_platform/skills/ 下 .md/.json/.css/.js 等）
# 显式跳过（仅回滚/紧急，需在回单注明"绕过质量闸"）
python tools\merge_gated.py <TID> --skip-tests
```

## 二、行为

1. 计算任务分支相对 master 的改动文件；
2. 纯文档/配置 → 跳过测试（打印原因）；
3. 否则跑 `tools/test_gate.ps1 -Suite fast`：
   - **新增失败 ≠ 0 → 拒绝合并**（日志落 `%TEMP%\merge_gated_<ts>.log`，事件发 `guard_fail`）；
   - 全绿 → 调 `devtask.py merge`；
4. 合并成功 → 事件发 `merge_done`。

## 三、判据

- **新增失败**以 `test_gate` 三分类基线为准（known/env/flaky 不判负）；
- 已存基线变化需走基线评审（`tools/test_baseline.json`），不得为过闸直接加白。

## 四、边界与注意事项

- 本闸不替代评审门（Mixin/导航/端口/凭据仍由 devtask merge 执行）；
- 不覆盖 quant 全量（默认 fast）；quant 相关变更建议 `--suite all` 或夜间 test_loop；
- 脏文件/并行合并冲突仍可能出现（git 层），闸只能保证"合并前测试绿"；
- **原生 `devtask.py merge` 仅限回滚/紧急**，并在回单注明"绕过质量闸"。

## 五、后续

- 与 `tools/test_loop.ps1`（持续巡检）配合：闸门=合并时，循环=平时。

## 七、P41：消除双跑 + 锁 liveness（2026-10-30）

- 双跑问题：内联门跑完 fast 后，git pre-merge-commit 钩子会**再跑一遍**（每单白等 ~5 分钟）→ 内联门通过后置 DEVTOOL_PREFLIGHT_DONE=1，merge_preflight.py 见标志即跳过（不置位时行为不变）；
- 锁饥饿：merge_lock 原按 15 分钟超时判 stale；新增 **pid liveness**（OpenProcess 探测），持锁进程已死 → 立即归档接管；_read 兼容 utf-8-sig。
- 效果：代码单合并 ≈ 内联 fast（一次性）+ 静态门，去掉重复 5 分钟；崩溃残留锁不再饿死后续合并。
