# 按池对齐（Pool Align）v1

> 状态：**现行**（2026-11-16 WO-POOL-ALIGN）
> 脚本：`tools/acad1_pool_align.py` · 测试：`tools/test_acad1_pool_align.py`（5 例）
> 默认 **dry-run**，`--apply` 才写回

## 一、为什么需要它

桥是**增量**的（`already_judged` 去重），账本只增不减。但池会缩容：

```
2026-11-16 当日池：曾到 18 只 → 回落到 12 只
已裁 18 只 / 池内 12 只 / 池外已裁 6 只 → 11 条 armed 计划仍在盯池外标的
```

上游已撤、下游还在守，这是**必须显式对齐**的缺口。桥的职责是「把池里有的裁掉」，
不该顺手删历史记录；收缩对齐是独立动作，所以做成独立工具。

## 二、口径（三条硬约束）

| 约束 | 做法 |
|---|---|
| **不删记录** | 只把 `status: armed → cancelled`，补 `cancelled_at` / `cancelled_reason` |
| **不动裁决/交棒** | `d1_decisions` / `d1_handoffs` 是已发生的事实，一律不改 |
| **看不见池就不动手** | 池退化（shadow）、池日不匹配、CN 为空 → `REFUSED rc=2` |

额外保护：写回前先备份 `watch_plans.jsonl.bak_<时间戳>`。

## 三、只撤 armed，不撤已触发

实测池外 6 只里 `603669` 只有 `take` 一条 armed —— 它的 `stop` 已 `triggered`。
**已触发/已失效的计划不撤**（那是历史事件），只撤还在等条件的那些。

## 五、用法

```powershell
python -X utf8 tools/acad1_pool_align.py --pool-date 2026-11-16            # 只读预览
python -X utf8 tools/acad1_pool_align.py --pool-date 2026-11-16 --apply    # 执行（带备份）
```

退出码：`0` 成功/无需动作，`2` 池不可用被拒。

## 九、边界

- **不判断该不该撤**：只看"池里还有没有"。若 ACAD1 误撤，本工具会照做——争议在池侧解决；
- **不重建**：撤掉的计划若标的又回到池里，桥会因 `already_judged` 跳过，**不会自动恢复盯盘**。
  要恢复需显式处理（目前不支持）；
- 不做定时：池缩容是事件驱动，挂在日批里容易误伤，建议人工确认后跑。
