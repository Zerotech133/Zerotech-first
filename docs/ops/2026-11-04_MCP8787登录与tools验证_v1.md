## 2. 登录方式 / 鉴权链路（实测 + 代码 + 生产日志）

### 2.1 链路

```
浏览器 → 8734 门户(唯一人类入口) → nginx auth_request 校验 portal session
      → 注入内部头 X-Portal-User: laotian → 反代 8787 (Hermes WebUI next)
      → 8787 trusted-header 认证（只信任 loopback peer）→ 200
直连 8787（不带该头）→ 页面 302 / API 401
```

- 8787 为 Hermes WebUI **next** 代：`Hermes/start_hermes_bg.py` L88
  `SERVER = ...hermes-webui-next\server.py`，实测 `/api/mcp/tools` 端点存在（next 独有）。
- 生产日志（`C:\aios\Hermes\start_hermes_bg.log` L3087-3088，当前实例 pid 15920，
  CreationDate 2026-11-03 13:33:51）：
  `[auth] trusted-header=X-Portal-User (settings password overridden by ephemeral random)`
  + `[launched] server.py detached` → 佐证认证配置已生效（证据
  `evidence/2026-11-04_hermes_launch_auth_evidence.txt`）。
- 代码：`Hermes/start_hermes_bg.py` L175-199（trusted-header 注入；L198-199 每次启动
  `secrets.token_urlsafe(48)` 随机密码，不落盘不打印）；L200-207 fail-closed。
- WebUI 侧：`api/auth.py` L905-944 `ensure_trusted_auth_session()`（loopback peer
  + 指定头 + 有值才建会话）；`api/routes.py` L7199-7214 `_raw_peer_is_trusted_proxy()`
  （按**原始 socket 地址**判信任，不能靠头伪造）；`api/auth.py` L52-60 公共路径仅
  `/login`、`/health`、`/api/auth/*` 等，`/api/mcp/*` 不在公共路径。

### 2.2 密码 / token

- **无 Bearer / API token 认证入口**：webui-next 中 `Authorization: Bearer` 仅用于
  出站调用 provider（`api/providers.py`、`api/gateway_chat.py` 等），不用于入站 API。
- 密码：每次启动随机（见 2.1），登录页虽在但无可用的静态密码 → **无第二道密码登录**。
- 结论：本部署的可用"登录方式"只有 **trusted-header（8734 SSO 同源注入）**；
  会话标识是服务端签名会话 cookie（token.signature，非 JWT/API token）。

### 2.3 未登录行为（代码口径）

`api/auth.py` L1112-1165 `check_auth()`：`/api/*` 未授权 → **401 JSON**
`{"error":"Authentication required"}`；页面路径 → 302 `login?next=...`。

### 2.4 session 标识（脱敏）

带 trusted-header 请求 `/api/mcp/tools` 的 200 响应下发：

```
Set-Cookie: hermes_session=<129 chars>; HttpOnly; Max-Age=2592000; Path=/; SameSite=Lax
脱敏指纹：name=hermes_session, value_len=129, sha256_12=895c7c4a884d
```

- 该 cookie 为服务端会话（`api/auth.py` L62 `COOKIE_NAME='hermes_session'`，TTL 30 天）。
- **重要**：trusted 模式下它不能单独当凭据——无 `X-Portal-User` 头时，服务端会
  invalidate 该 trusted 会话并返回 401（`api/auth.py` L917-929；实测 cookie-only → **401**，
  见 `probe_raw.json.probes.mcp_tools_session_cookie_only`）。
  即：每个请求都必须由 nginx 注入身份头（浏览器侧由 8734 同源反代保证）。

## 5. 入口确认：8787 没有 `/mcp` SSE / streamable-http

- 代码实证：webui-next 的 MCP 相关路由只有 **`GET /api/mcp/servers`**、
  **`GET /api/mcp/tools`**、`PATCH/DELETE/PUT /api/mcp/servers/{name}`
  （`api/routes.py` L16517-16523、L20399-20480）；`git grep` 无 `/mcp` HTTP 路由。
- 实测：`/mcp` 未登录 **302→login**、带登录头 **404** → 该路径不存在。
- 正确口径：
  - **"登录后 tools/list"在本部署 = `GET /api/mcp/tools`**（认证后的 WebUI HTTP API）；
  - `Hermes/hermes-webui-next/mcp_server.py` 是 **stdio 传输**的 MCP server
    （`from mcp.server.stdio import stdio_server`），方向相反：把 Hermes 项目/会话工具
    暴露给外部 agent，不是 8787 的 HTTP 端点；
  - d1-research / dw-* / huangzhong / kb-corpus 等是 **stdio MCP server**，由 Hermes Agent
    进程拉起并维护台账，8787 只读展示（`api/mcp_runtime.py` L1-15、`api/routes.py` L33195）。
- 因此：协议级 `tools/list` 不发生在 8787 的 HTTP 层；8787 侧等价入口就是认证后的
  `/api/mcp/tools` 清单端点。
