# 验收清单检查器 v1

> 状态：**现行**（2026-11-16 WO-ACCEPTANCE-CHECK）
> 脚本：`tools/acceptance_check.py` · 测试：`tools/test_acceptance_check.py`（10 例）

## 一、它解决什么

"验收清单"过去只写在对话里，跑一次就散：结论在聊天记录、检查逻辑在临时脚本（`tmp/`）、
下一次换人换天要重写。本工具把它变成**可复跑的 spec**：

```powershell
python -X utf8 tools/acceptance_check.py --spec <spec.json> [--json]
# 退出码 = 失败项数（0 即全过）；--json 输出结构化结果
```

- 每项输出 `[PASS|FAIL] 名称 ← 一行证据`（证据是文件行号 / JSON 值 / 命令尾行 / 任务时间）
- **只读生产**：除 spec 里显式声明的 `cmd`（通常带 `--dry-run`）外不执行写操作；
  `cmd` 还能用 `unchanged` 断言"跑完这个文件 mtime 没变"——用来证明 dry-run 不碰账本

## 二、spec 格式

```json
{
  "title": "本次验收标题",
  "repo": "C:/项目/老田的AI助手",
  "checks": [
    {"id": "out1-1", "section": "产物①", "name": "脚本存在",
     "kind": "file_exists", "path": "tools/d1_t1_check.py"}
  ]
}
```

`path` 支持相对 `repo` 与绝对路径（绝对路径用于仓库外的交付区，如 `C:/项目/deliverables/...`）。

## 三、支持的 8 种检查

| kind | 字段 | 判定 |
|---|---|---|
| `file_exists` | `path` | 存在且非空（证据带字节数） |
| `file_contains` | `path`, `pattern` | 正则命中（证据给首次命中行） |
| `not_contains` | `path`, `pattern` | 正则**不**命中（防回归：禁止出现某类写操作） |
| `json_field` | `path`, `pointer`, `in` | JSON 点路径取值落在允许集合 |
| `regex_count` | `path`, `pattern`, `expect` | 命中行数精确等于 expect |
| `count_equals` | `path`, `pattern_a`, `pattern_b` | 声明的数字与命中行数一致（如"共 38 条"vs 38 行表格） |
| `cmd` | `cmd[]`, `expect_rc`, `unchanged`, `unchanged_dir` | 跑命令；`unchanged`=指定文件 mtime 不变，`unchanged_dir`=目录内文件清单与大小零变化（防"检查动作污染交付目录"） |
| `task_next_run` | `tasks[]` | 计划任务 NextRunTime 均可读（Windows） |

未知 kind 记为 FAIL（不静默跳过）。

## 六、重跑稳定性与一次性任务

- `task_next_run` 默认要求 NextRunTime 是**未来时间**；一次性任务执行后变 `N/A` 属正常终态，
  这类用例声明 `"allow_na": true`（`N/A` 不再是失败，但仍会检查任务是否存在——缺失必 FAIL）。
- 本批实例：`in-2` 查 `D1T1Check`（`allow_na`）；`acc-1` 只查三个常驻任务
  （`PortalKeepalive` / `D1SloWindowSample` / `D1DailyBatch`）的未来时间。
- 稳定性实测：同一条命令连跑 3 次，`(id, ok)` 序列完全一致，每次 `23 checks, FAIL=0`。

## 七、边界

- 不替代单元测试：`cmd` 只跑套件、不替代套件本身
- 不判断语义正确性：只核对"声明的事实是否成立"（值、行数、状态码、mtime、目录快照）
- **瞬时机句柄错误重试**：本机连续调 `subprocess` 偶发 `OSError: [WinError 6] 句柄无效`，
  `cmd` 类对此**只重试一次**并在证据里标 `retried_winerror6=N`；命令不存在/超时等真实错误不重试。
- 跨平台：`task_next_run` 仅 Windows；其余 kind 平台无关
