# GOVAI 判例签字链 · 运行手册（v1 · 2026-10-26）

> 定位：AI 只产 **draft**；**人签** 是唯一生效闸门；Agent 只做「生成 payload / 验签入库」。
> 首次真实跑通记录：2026-10-26，9/9 `verified=True`（7 张判例卡 + 2 条 GOVAI 草稿，Z4 supervision 域）。

## 一、角色与边界

| 角色 | 能做什么 | 不能做什么 |
|---|---|---|
| **老田（本人）** | 生成私钥；用 `sign_govai_batch.ps1` 签名 | 无需把私钥/口令交给 Agent |
| **Agent（赵云/DSH）** | `--emit` 生成待签 payload；`--apply` 验签入库；出审计证据 | 不签名、不持有私钥、不生成私钥 |

- 私钥：`C:\项目\_vault\keys\principal_private.pem`（加密 PKCS8，**仓外私有区**，永不入库）
- 公钥：`C:\项目\_vault\keys\principal_pub.hex`（64 hex，可公开）
- 签名算法/口径：Ed25519，payload = `{scheme,kind,item_id,fingerprint,action,ts,nonce}`（`signature_guard.canonical_payload`）

## 二、完整流程（新 AI 判例）

```powershell
# ① Agent：生成 draft（需要证据包 json）
cd C:\项目\老田的AI助手
python agent_platform\tools\gov_ai.py --action case_draft --bundle <证据包.json> --force

# ② Agent：把 draft 转成待签 payload（Z4 已有 9 条时自动从 010 起）
python tools\gov_ai_case_bridge.py --emit --draft agent_platform\data\governance_ai\advice\<date>\case_draft.json --out C:\项目\_vault\sign_requests\govai_<tag>

# ③ 老田（本人终端）：一条命令签完该目录，输一次口令
powershell -ExecutionPolicy Bypass -File tools\sign_govai_batch.ps1 -Dirs "C:\项目\_vault\sign_requests\govai_<tag>"

# ④ Agent：严格模式验签入库
$env:EVOLVE_PRINCIPAL_PUBKEY_FILE = "C:\项目\_vault\keys\principal_pub.hex"
$env:EVOLVE_SIGNATURE_STRICT = "1"
python tools\gov_ai_case_bridge.py --apply --signature-dir "C:\项目\_vault\sign_requests\govai_<tag>" --json
```

## 三、证据包格式（`governance_case_bundle/v1`）

```json
{
  "schema": "governance_case_bundle/v1",
  "title": "事件一句话",
  "timeline": [
    {"id": "E1", "what": "发生了什么（含真实数字/提交号）", "when": "2026-10-26"},
    {"id": "E2", "what": "处置动作", "when": "2026-10-26"}
  ],
  "lesson_hint": "可选：经验方向提示"
}
```

硬约束：只允许**已发生真实事件**；`evidence` 必须引用 `bundle:E1…`；数字必须能在输入中找到（validator 强制）。

## 四、常见失败与处置

| 现象 | 原因 | 处置 |
|---|---|---|
| `草稿 status='failed'` | 模型输出未过校验（如 evidence 非数组/数字未接地） | 看 `validator.notes`；修正证据包/prompt 后 `--force` 重跑 |
| `草稿 status='failed'` 且 `--if-changed` 跳过 | 同输入已失败过（缓存） | 加 `--force` |
| `entry_id 漂移` | 域内新增条目后 payload id 过期 | 重新 `--emit`（base 自动取当前条数） |
| `缺少签名` | 签名文件未生成/命名不符 | 用 `sign_govai_batch.ps1` 重签（两种命名均兼容） |
| `未配置 principal 公钥` | 忘设 env | 设 `EVOLVE_PRINCIPAL_PUBKEY_FILE` 后重试 |
| `签名校验失败：signature invalid` | payload 被改过 / 用错私钥 | 重新 emit + 重签 |

## 五、安全与运维

- **私钥备份**：生成后立即离线备份（密码管理器/离线介质）；丢失无法恢复签名能力。
- **轮换**：换钥后旧签名仍有效（历史证据保留），但旧钥不再受信。
- **审计留痕**：payload + signature + draft 全部留 `C:\项目\_vault\sign_requests\`，不删。
- **严格模式**：生产 apply 一律 `EVOLVE_SIGNATURE_STRICT=1`；未配公钥时 bridge 会拒写。
- **可验证性**：Z4 每条含「采纳: 老田 签字于 …」「验签: verified（ok）」；重复 apply/篡改均被拒（有测试与实测证据）。
