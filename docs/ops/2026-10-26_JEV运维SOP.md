## 一、系统总览

```
采集（news_collector/*）
  └→ C:\aios\news_collector\news.db   ← 唯一权威源（SQLite，仅 PK 索引）
       └→ 回填判读（jev_backfill.py，8 条/组）
            ├→ news_ai.jev_judge_one —— 云 TypeSafe（需代理，通常不可达）→ 本地 qwen3.5:9b 回落
            ├→ _validate_jev 校验（失败 → conf<0.7 走 k=3 重采样 → 二次 reason 调用）
            └→ UPDATE news SET jev=<JSON> WHERE id=? AND (jev IS NULL OR jev='')
```

**三席（驿传署，运行体部）**

| 席位 | 角色 | 产物 |

`agent_platform/data/jev_roles/{latest,gate,review,qd,<date>}.json` + `outputs/jev_daily_<date>.md`，
并对应 `agent_platform/registry/daily_work.json` 三个事项（JEV_GATE-01 / JEV_REVIEW-01 / JEV_QD-01）。

## 二、服务栈（四组件）

**启动器**：`jev-eval\start_jev_stack.ps1`（2026-10-26 恢复；此前缺失导致 `\JevStack` 长期 Disabled）
**计划任务**：`\JevStack`，每 10 分钟，S4U，ASCII 脚本

| 组件 | 端口 | 脚本 | 启动参数 |
|---|---|---|---|
| jev-gate | 9101 | `jev_gate.py` | 无 |
| review-gate | 9102 | `signal_review_gate.py` | `--loop` |
| qd-bridge | 9103 | `jev_qd_bridge.py` | `--loop` |
| card-handler | 9104 | `lark_card_handler.py` | 无 |

**判活**：只认端口（9101-9104）。S4U/Session0 进程 CIM 枚举会漏列、CommandLine 全 null——不要用 `Get-CimInstance` 找它们。

**启动器语义**
- 缺则拉（不重启已健康实例）；等待窗口 10s
- **外部阻塞 → warn + rc0**（如飞书平台仍占用该 app 的事件长连接：`online_instance_cnt=1`、日志 `another event bus is already connected`）
- **内部启动失败 → rc1**（任务审计可见）
- card-handler 自愈：进程 age>6h 或 `~/.lark-cli/events/**/bus.log` 最后 SDK 状态为断连且 >90s → 杀进程树重启
- 状态快照：`jev-eval/logs/jev-stack-status.json`（ts/started/down/external/internal/ports）
- 日志：`jev-eval/logs/jev-stack.log`（每次运行一行）、`jev-proc.<comp>.{out,err}`（子进程输出）

**常用命令**
```powershell
# 状态（只读）
powershell -NoProfile -ExecutionPolicy Bypass -File C:\aios\jev-eval\start_jev_stack.ps1 -Status

# 手动补拉（幂等）
powershell -NoProfile -ExecutionPolicy Bypass -File C:\aios\jev-eval\start_jev_stack.ps1

# 全量重启（运维窗口用；会杀四组件）
powershell -NoProfile -ExecutionPolicy Bypass -File C:\aios\jev-eval\start_jev_stack.ps1 -Force

# 任务开关（L2，需审批+五要素留痕）
schtasks /query  /tn "\JevStack" /fo LIST /v
schtasks /change /tn "\JevStack" /disable
```

**启动**：`\ZeroBound\JevNight` **21:50 触发**（2026-10-26 提前 10 分钟，先停 M3 再开跑）
```powershell
C:\Program Files\Python311\python.exe -X utf8 -B C:\aios\tools\jev_night.py --start 21:50 --until 07:00
```
- 启动即写暂停旗 `C:\Temp\k266_m3.pause`（M3 见旗不拉起）

- 07:00 干净退出后**删除暂停旗**；M3 由守护拉起

**巡检**（每小时；仅 22:00-07:00 有效）
```powershell
# 1) 实例数（排除 pytest 等含关键词的假实例）
Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
  Where-Object { $_.CommandLine -match 'jev_night' -and $_.CommandLine -notmatch 'pytest' }
# 2) 日志尾部（judged/ROUND 行距现在 >40 分钟 = 卡住）

# 3) 暂停旗 + M3 必须为 0
Test-Path C:\Temp\k266_m3.pause

  Where-Object { $_.CommandLine -match 'k266_m3' }
```

**卡住时重启**（WMI 脱离会话，勿用本会话后台任务——会被杀树）
```powershell
Invoke-CimMethod -ClassName Win32_Process -MethodName Create -Arguments @{
  CommandLine = 'cmd /c ""C:\Program Files\Python311\python.exe" -X utf8 -B C:\aios\tools\jev_night.py --start 21:50 --until 07:00 >> C:\Temp\jev_night.out.log 2>> C:\Temp\jev_night.err.log"'
```

## 五、灰度开关（全部默认关，行为与现状一致）

| 环境变量 | 默认 | 作用 | 回滚 |
|---|---|---|---|
| `JEV_PREFILTER` | 0 | 两段式规则粗筛（保持/跳过） | 不设或 0 |
| `JEV_ITEM_SLEEP_S` | 0.2 | 条间 sleep（夹取 0-5s） | 不设 |
| `JEV_LOCK_YIELD_PAUSED` | 1 | 设 0 = 恢复原租约让位逻辑 | 不设或 1 |
| `JEV_M3_PAUSE_FLAG` | `C:\Temp\k266_m3.pause` | M3 暂停旗路径 | 不设 |
| `OLLAMA_MODEL` | `qwen3.5:9b` | 本地判读模型 | 改回 9b |
| `HERMES_PUSH_BUDGET` | 600 | Hermes 简报推送预算秒 | 改小/不设 |

| `ZB_HC_BACKLOG_DAYTIME_EXEMPT` | 未设=开 | 健康卡 batch_backlog 白天让位豁免：07:00-21:50 积压上涨判黄（夜间 21:50-07:00 仍红）；设 0 关闭豁免 | 设 0 |

> 白天让位语义：07:00-21:50 M3 独占，JEV 小时轮按设计让位，积压上涨属工作模式；健康卡 `ops.batch_backlog` 在该窗口把"较上轮上升"降为黄，夜跑窗口仍严格判红（`K-ORG-20261026-BACKLOGDUTY`）。

> 两段式试点结论（2026-10-26）：规则层 skip 仅 5-15%、漏判率高 → 否决；批量判读调用降 8x 但 bias 一致率 75% → 否决。**`JEV_BATCH` 不启用**，夜间产能靠方案 A（全量回填）。

| 症状 | 先查 | 处置 |

| 积压只增不减 | `jev_backfill_task.log` 是否 `skip: ollama 锁被 M3 持有超 900s` | 正常让位；夜间窗口会清；持续 3 天则查 M3 是否长期独占 |
