## 一、审计发现（4 项）

### F1 🔴 真 BUG 已修——视图切换刷新不记忆
- **现象**：playwright 断言「切到代码视图→刷新→应仍在代码」失败（12 PASS / 1 FAIL 抓到）。
- **根因**：340 给三根 resizer 加了 localStorage 记忆，但 343 重写五区时 `setView()` 只改内存变量没落 localStorage——视图状态持久化在重写中丢失。
- **修复**：`setView` 写 `localStorage["ide-view"]`，初始化时读回。

### F2 🟡 已修——畸形轨迹 T.jsonl 进入展示面（产线轨迹写入器防线缺失）
- **现象**：轨迹侧栏出现 k_id="T"（2 动作）的无意义条目。
- **溯源**：`shadow/coder_traces/2026-10-13/T.jsonl`（17:26:45 add tools/agent_coder.py → 17:26:49 fail git commit）——**产线 K-ORG-048 自改产线文件的「进程内代码代际」窗口期**（048 commit 17:25→048a amend 17:30 之间），某调用方以残缺 `k_id="T"` 调了 commit_work。工单库无 "T" 工单，判为并行会话占位传参。
- **修复（两道防线·证据文件保留）**：
  - 产线端 `trace_log`：k_id 长度<4 打 `[warn]`（不拒写保留证据·下次产线单生效）；
  - 展示端 bundle 生成器：k_id<4 字符不入 digest（打印 `traces skip`）。
- **判例沉淀**：轨迹文件=证据不删，过滤只做在展示面；「防线加在记录端+展示端双层」。

### F3 🟡 已修——bundle events 无上限（防御缺失）
- 极端大 trace（数千行 jsonl）会全量烘入 bundle 撑爆体积（当前最大 32 条无实害）。
- 修复：events 上限 200 条（保留最近 200）。

### F4 ⚪ 已清——atCheck 局部 `const q` 遮蔽全局 q() helper
- 属性安全 JSON 的 `q()` 是 343 判例的关键 helper，atCheck 内同名局部变量当前无实际冲突，但未来有人在同函数内调 `q()` 会炸。改名 `kw`。
