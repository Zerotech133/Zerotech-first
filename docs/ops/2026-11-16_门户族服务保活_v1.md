# 门户族服务保活 v1（8091 / 8098 / 8789）

> 状态：**现行**（2026-11-16 WO-PORTAL-KEEPALIVE）
> 一句话：**端口不监听就拉起，监听就只看一眼**。计划任务每 2 分钟跑一轮。

## 一、为什么需要

2026-11-15 → 11-16 期间，`8091 portal-api` 与 `8098 model-admin` 多次在夜间消失（进程退出、无人拉起），
导致 D1 接口面整段不可用——这正是 Q2 SLO「读接口 availability 违约」的根因之一
（`deliverables/d1_q2/20261116/Q2_评审决议_NO_GO_v1.md` §3.3）。

## 三、运行方式

```text
计划任务  PortalKeepalive
  触发    每 2 分钟（PT2M），持续 3650 天
  执行    pythonw.exe -X utf8 hidden_launch.py <python.exe> tools\portal_keepalive.py --once
  身份    当前用户（Interactive），无最高权限
  日志    logs/portal_keepalive.log（只增）+ logs/<服务>.out.log（子进程 stdout）
```

手动：

```powershell
python -X utf8 tools\portal_keepalive.py --status              # 只看
python -X utf8 tools\portal_keepalive.py --once --dry-run      # 只看会做什么
python -X utf8 tools\portal_keepalive.py --once                # 保活一轮
Start-ScheduledTask -TaskName PortalKeepalive                  # 立即跑一轮
Get-ScheduledTaskInfo -TaskName PortalKeepalive                # LastResult / NextRunTime
```

## 四、行为边界（不会做的事）

- **不杀进程**：只在端口未监听时启动；已监听一律跳过，绝不会起第二个实例；
- **不改系统配置**：不下发信号、不改注册表、不动防火墙；
- **不掩盖故障**：启动后 12s 内端口仍不监听 → 记 `STARTED ... but port still closed`，退出码非 0（critical 服务）；
- **dry-run 诚实**：脚本缺失时 dry-run 也报 `start_failed`，不假装会成功。

## 六、已知边界

- 任务身份是 `Interactive`：**机器重启后需保持用户登录**才会继续保活（与既有 `QuantWatchdog` / `AlertPushWatchdog` 同口径）；若要无人值守，需改为 S4U 或服务化（属 L2 编制/权限变更）。
- 只保"进程在场"，不保"业务正确"：接口 500、数据为空不在本脚本职责内（那是 SLO 探针与业务监控的事）。
