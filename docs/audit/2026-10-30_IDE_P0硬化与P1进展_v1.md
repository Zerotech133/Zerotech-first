### 2. LDE owner 绑定会话身份

- `/rw` 每次下发独立 `ide_session` token；
- 服务端内存会话表绑定 owner；
- 新增 `GET /api/ide/session`；
- 所有 lock/write/exec 的 owner 必须等于会话 owner；
- 自报 owner 返回 403 `owner_mismatch`；
- 前端 `LDE_OWNER` 改为从 `/api/ide/session` 获取。

实测：

```text
session_owner=lde-ctPeUr1c7K
POST lock owner=spoof → 403
POST lock owner=会话 owner → 200
```

### 3. LDE exec 隔离（Job Object）

新增 `agent_platform/legion_ide/exec_sandbox.py`：

```text
- 子进程加入 Windows Job Object
- KILL_ON_JOB_CLOSE
- ActiveProcessLimit=32
- 超时 TerminateJobObject 整树终止
- IDE_EXEC_ISOLATION=off 可回退普通 subprocess
```

实测：

```text
GET/POST exec git status -s
→ ok=True success=True isolation=job
```

边界：**这是进程树/资源隔离，不是文件系统沙箱**。真正的低权限/容器隔离仍建议后续做。

### 7. 8787 直连 LDE

**暂缓，不硬上。**

原因：

- 8787 直连会绕过 8734 nginx 的 auth_request；
- 当前 LDE cookie 是 SameSite=Strict，跨端口同站点虽可带，但仍需 CORS；
- 直接开 CORS 等于在 P0 认证之外再开一个旁路。

建议：

```text
先给 8787 也加统一认证/本地 token
再做 CORS + /api/ide/session
最后验证 8787 直连 LDE 全链路
```
