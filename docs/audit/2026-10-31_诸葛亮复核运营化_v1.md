## 二、Feature flag（默认关，未变）

```text

```

| 状态 | POST /api/zhuge/review | POST /api/zhuge/review/<id>/adoption | GET status / GET <id> |

## 三、限额（rate limit）

- 维度：**门户 session cookie（`zb_session`）的 sha256 哈希前 16 位**；只存哈希，不落明文 cookie。
  无 cookie 时归入 `anonymous` 桶（仅匿名测试口径）。
- 额度：默认 **6 次 / 小时 / session**，滑动窗口。环境变量可调：
  `ZHUGE_REVIEW_RATE_PER_HOUR`（默认 6）、`ZHUGE_REVIEW_RATE_WINDOW_S`（默认 3600）。
- 全局并发：**单 worker**（`GLOBAL_WORKERS=1`，线程池 `max_workers=1`），多 session 也只能串行复核；
  `GET /api/zhuge/review/status` 的 `worker` 字段暴露 `max_workers/pending`。
- 超限：**429**，body 含 `retry_after_s`（距最早一次命中滑出窗口的秒数，≥1）、`limit`、`window_s`、`scope=session`；
  被限流不会登记新任务、不会触发模型调用。
- 缓存命中（同 diff+test_result）**不计限额**（沿用 Phase C 口径，缓存检查在限额之前）。
- 可测试性：时钟走模块级 `CLOCK`（默认 `time.time`），测试可 `monkeypatch z.CLOCK` 注入固定时间；
  `z._rate_check()`/`z.rate_state()` 可在测试中直接注入 session key。
- 进程内计数（重启清零），与既有 `_rate_ok()`（Phase C 匿名兜底 3/60s，保留兼容测试）并存，互不替代。

## 四、采纳/忽略（adoption）

### 4.1 API

```http
POST /api/zhuge/review/<review_id>/adoption     # 需门户 session（flag on）
Content-Type: application/json
{"adopted": ["zf-3f2a1b0c9d8e"], "ignored": ["zf-aa11bb22cc33"], "note": "修复 P1，忽略 P2", "by": "hermes-lde"}
```

- `adopted`/`ignored`：finding 的稳定 id 数组；同一 id 不得既采纳又忽略；id 必须属于该次复核。
- `note` ≤500 字符，`by` ≤120（缺省取 session 的 `sub`，再退化为 `session:<hash8>`/`anonymous`）。
- 成功 200：

```json
{"ok": true, "review_id": "zr-...", "adoption": {
  "schema": "adoption_v1", "ts": "2026-10-31T08:30:00+0800",
  "review_id": "zr-...", "task_id": "WO-...", "verdict": "concerns",
  "adopted": ["zf-..."], "ignored": [], "note": "...", "by": "...",
  "findings_total": 4
}}
```

- 错误码 → HTTP：`review_not_found` 404、`review_not_ready` 409（复核未完成）、
  `bad_finding_id` 400、`conflict_finding_id` 400、`nothing_to_record` 400、`ledger_write_failed` 500。
- `GET /api/zhuge/review/<id>` 的结果里附带 `adoption`（若已记录）；复核 job 过期但账本有记录时，
  GET 返回 `status="adoption_only"`（只含 adoption，不伪造复核结果）。
- 兼容：旧调用 `POST /api/zhuge/review` + `body.action="adopt"` 仍工作（decision 型走旧逻辑；
  带 `adopted`/`ignored` 字段则走新账本逻辑）。线上主路径为 `/<id>/adoption`，前端仅在
  子资源 404（合并前老 portal_api）时自动回退。

### 4.2 账本（append-only）

```text
portal/data/zhuge_review_adoption.jsonl
```

- 一行一条 JSON（`ensure_ascii=False`），只追加，永不改写/删除；
- schema `adoption_v1`：见 4.1 的 `adoption` 对象；坏行读取时跳过，不造假；
- 测试用 `ZHUGE_ADOPTION_PATH` 或 monkeypatch `ADOPTION_PATH` 隔离到 tmp，**禁止写真实 data 文件**；
- 已知边界：账本无去重（同复核多次记录保留多条，读取取最近一条）；无轮转（数据量小，后续可加）。

### 4.3 finding 稳定 id

- 由 `severity|file|line|claim|evidence` 内容哈希生成：`zf-` + sha256 前 12 位；
- 同一复核内容重算幂等（可跨进程重放），同内容重复 finding 自动加 `-2`/`-3` 后缀保唯一；
- id 随 `findings` 一起返回，作为 adoption 的唯一引用键。

## 五、面板自动 diff + 结构化测试（自动流程）

面板（Hermes 扩展左下角「⚔ 诸葛复核」）打开/提交时自动尝试：

1. **LDE 会话**：先 `GET /lde/rw` 种 `ide_session` cookie，再 `GET /lde/api/ide/session` 取服务端绑定 owner；
2. **工单锁**：`GET /lde/api/ide/lock?task=<id>`；
3. **自动 diff**：有锁且 owner 一致时 `POST /lde/api/ide/git {task, owner, action:"diff"}`
   （LDE 侧为 `git diff --cached` 整单 staged diff，≤64KB 截断交后端校验）；
4. **结构化测试**：`POST /lde/api/ide/test {task, owner, command:"python -m pytest -q .", timeout:180}`，
   成功/失败都取结构化结果（`success/exit_code/output_tail/evidence_run_id`）作为 `test_result`；
   面板打开即后台触发一次，提交时复用同一 promise，若上次不可用（无锁/无会话）提交时会再试一次；
5. **提交**：`POST /api/zhuge/review`，body = `{task_id, diff, changed_files, test_result, context}`，
   `context.diff_source ∈ {lde, manual}`、`context.test_available` 标明来源/可用性。

### 5.1 降级矩阵（明确显示，不静默空、不伪造 pass）

| 场景 | 面板表现 | 提交行为 |
|---|---|---|
| LDE 会话不可用（IDE_RW=off / 未从 /lde 进入） | 橙色降级原因：自动 diff/测试降级，可手动粘贴 | 手动 diff 仍可提交；`test_result={source:"lde",available:false,error:"lde_session_unavailable"}` |
| 工单无 LDE 锁 | 「工单当前无 LDE 锁（先在 LDE 施工台获取锁）」 | 同上；`test_result.available=false,error="lock_required"` |
| 锁属于他人 / owner 不一致 | 显示锁 owner 与当前会话 owner | 同上，不越权取 diff |
| LDE 无 staged diff | 「无 staged diff…不静默提交，可手动粘贴」 | 空 diff 拒绝提交（后端 400） |
| `/api/ide/git` 失败 | 显示 LDE 返回 message/error | 可手动粘贴后提交 |
| 测试运行器级失败（无权限/超时/命令拒绝） | 降级 + 原因，明确「不伪造 pass」 | `test_result.available=false` + error/message |
| 测试真实失败（pytest exit≠0） | 显示「结构化测试：失败 · exit=N」 | `test_result.available=true, ok=false`（真实失败，不是降级） |
| 复核降级（模型不可用） | verdict=degraded，无 findings | 后端 `status=degraded`，不伪造 pass（P0 口径不变） |

## 八、风险与回滚

| 风险 | 说明 | 缓解/回滚 |
|---|---|---|
| flag 忘关/误开 | 模型调用成本与 OpenClaw 通道占用 | 仍默认关；改 env + 重启即生效/关闭；kill switch=`ZHUGE_IDE_REVIEW` 未设置 |
| 限额误伤 | 同一浏览器多标签共享 session 额度；换登录/清 cookie 会重置桶 | 6/h 为运营初值，可调 env；429 明确 `retry_after_s`；不涉及封禁 |
| 匿名测试开关误开 | `ZHUGE_IDE_REVIEW_ALLOW_ANONYMOUS=1` 会绕过 session | 仅测试环境使用；生产不设置 |
| adoption 账本写失败 | 磁盘/权限问题 | 显式 500 `ledger_write_failed`，不假绿；不阻塞复核本身 |
| 账本无限追加 | 无轮转 | 数据量小（人工采纳记录）；后续可加按日归档 |
| 自动跑测试耗时/资源 | LDE 侧 pytest 最长 180s，占用单工单锁 | 有锁才跑；超时/拒绝降级为 `available=false`；不伪造 pass |
| diff 过大 | 后端 64KB 上限 | 面板 64000 字符截断；后端超限 400 |
| 前端回退路径 | 合并前老 portal_api 无子资源，自动回退 `action=adopt` | 合并后主路径为子资源；回退仅在 404 时触发 |
| 路由前缀扩大 | `POST /api/zhuge/review/*` 全交给模块 | 模块内未知子路径显式 404；无新增 handler 方法；mixin 完整性零 diff |

回滚：`unset ZHUGE_IDE_REVIEW` + 受控重启 8091 即回到「复核默认关」；本次改动不改表结构、
不写业务数据（仅新增 `portal/data/zhuge_review_adoption.jsonl`，保留无副作用），回滚无需数据迁移。
