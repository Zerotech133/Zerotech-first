## 0. 边界声明（四不红线，先于一切方案）

1. **不接管任务主控**。Legion（`agent_platform/router.py` + `engine/tasks.py`）是唯一任务编排中枢；Paperclip 无论以何种形态引入，只能作为战略控制面适配层。
2. **不产生第二任务真相**。按架构 §281，Paperclip 只允许「创建请求 / 读取状态 / 回写事件」，**不得**自行产生「任务完成」状态，不得维护一套任务副本账本作为真相源。
3. **不直连执行网关**。实际副作用只有执行网关一处；Paperclip 的任何意图（预算调整、目标变更、审批决策）都必须经既有审批链（ApprovalStore）落凭据后由 Legion 侧执行。
4. **不长期双写**。架构 §543：「必须先完成全量双读校验，再关闭旧主控，禁止长期双写」。本提纲 §5 的迁移门制是该句的可执行化。

**时序红线**：M0-M5 未全部稳定前，任何 Paperclip 集成代码不得入仓（M5 规划红线 4）。本文档是 M6 的**前置评估材料**，不是开工许可。

## 1. 候选角色与现状控制面归属

Paperclip 候选定位：**战略目标、预算、审批、审计四域适配层**（§543 原文），对应 M6 验收语境「只接管目标、预算、审批和公司级治理」。

引入前必须确认以下控制面各有且只有一个归属（§531-541 防双主控铁律）：

| 控制面 | 唯一归属 | Paperclip 允许的形态 |
|---|---|---|
| 全局路由 | `agent_platform/router.py` | 无（不触碰） |
| 任务编排 | Legion / `engine/tasks.py` | 只读 + 请求创建 |
| 最高决策 | A0 田丰 + 老田审批席 | 审批意图回写（经适配层） |
| 身份权限 | org + HR registry | 只读 |
| 记忆 | GNS / 统一检索入口 | 只读 |
| 事实 | 证据层（Evidence/EvidenceStore） | 只读 |
| 实际副作用 | 执行网关 | 无（不触碰） |
| **战略目标** | （当前无独立系统） | **候选接管域 ①** |
| **预算** | （当前分散，M5 成长监察线收敛中） | **候选接管域 ②** |
| **审批** | `engine/approvals.py` ApprovalStore | **候选适配域 ③**（账本不换） |
| **审计** | 统一事件账本 + trace_link 四环锚点 | **候选镜像域 ④**（只读订阅） |

> 判读：①②是「Paperclip 提供能力、Legion 落地」的新增域；③④是「Paperclip 挂到既有账本上」的适配域。四域没有一个要求替换现有写入口。

## 3. 四接口适配层草案（只读适配、账本不换、零新写入口）

### 3.1 战略目标接口（候选接管域①）

```text
Paperclip 目标对象
  → 适配层映射为 goal.created 事件（统一事件白名单 v1 内）
  → Legion 侧消费事件 → TaskStore.open(to_dept, title, body, severity, opened_by="paperclip-adapter")
  → 后续 Task 状态流转全部在 Legion，Paperclip 仅回读
```

- 目标状态对齐：Paperclip 侧展示的目标进度 = Legion 任务状态投影（`ls(dept, status)` 聚合），**不是**独立进度账本。
- 关键约束：`opened_by` 必须带 `paperclip-adapter` 标识，审计可区分来源；目标取消/变更同样走事件回写 + 审批，不直接改 Task。

### 3.2 预算接口（候选接管域②）

```text
Paperclip 预算意图（调额/冻结/分配）
  → 适配层生成预算变更请求 → ApprovalStore.record()（target_type="budget", target_id=预算项 ID）
  → 批准凭据落地后 → Legion 侧按凭据执行
```

- 与 M5 成长监察线的 Token 预算分配衔接：Paperclip 只做**意图与决策层**，预算执行台账仍在本地使用账本（M2 四件套之一）。
- 判据：任何预算生效必须能在 ApprovalStore 里找到对应 approval_id（「建议≠凭据」红线沿用）。

### 3.3 审批接口（候选适配域③）

```text
Paperclip 审批动作（批准/驳回）
  → 适配层调用 ApprovalStore.record(Approval(...), source="paperclip")
  → approval_id 回写 Paperclip 侧仅作展示
```

- **审批账本不换**：ApprovalStore（SQLite）仍是唯一审批真相；Paperclip 不建第二审批库。
- 幂等沿用 record() 既有幂等语义；Paperclip 重复回执按同 approval_id 幂等吸收。
- 高风险动作（真实交易、外部发布、删除、付款、权限变更）审批权**不外放**：仍归老田审批席，Paperclip 只能转发请求。

### 3.4 审计接口（候选镜像域④）

```text
统一事件账本 / trace_links.jsonl / perf_ledger.jsonl
  → 只读订阅（ro 连接，mode=ro 不经写型 Store 判例）
  → Paperclip 侧审计视图 = 投影，不作为真源
```

- 订阅通道建议复用门户 8091 只读端点模式（fail-visible、出口脱敏 `_scrub_repo_paths` 同口径）。
- Paperclip 侧不得反向写任何 jsonl/SQLite；其本地日志与真仓断链可接受（镜像性质）。

### 3.5 四接口共同约束

- 适配层唯一入口形态：**一个独立 adapter 模块**（类比 `adapters/credential_trace.py`、`adapters/unified_projection.py` 的挂接模式），禁止在 engine/tasks.py、approvals.py 里内联 Paperclip 分支。
- 适配层必须 fail-open 双轨 + stderr 诊断（M3 判例沿用）。
- 接口上线前过 P1 安全验收：无盘符路径泄漏、响应脱敏同口径。

## 4. 双读校验方案（仅为未来「迁移任务主控」准备，当前不执行）

**前提**：只有当未来决定把任务主控从 Legion 迁往 Paperclip 时才启用本节。四接口适配层阶段（§3）不需要双读——因为写侧始终只有 Legion。

### 4.1 双读定义

- 写侧：Legion 独写（真源）。
- 读侧：Paperclip 通过适配层只读拉取同一账本，本地形成投影。
- 校验：定时比对「真源快照 vs 投影」，diff 落日报，fail-visible。

### 4.2 比对维度（四项全查）

| 维度 | 真源 | 比对内容 |
|---|---|---|
| 任务集合 | `engine/tasks.py` 账本 | task_id 全集、open/move 历史、终态分布 |
| 状态机快照 | 同上 | 每任务当前 status + last_wiring_key 轮次标记 |
| 审批记录 | ApprovalStore | approval_id 全集、record 幂等结果、stats 汇总 |
| 事件序列 | 统一事件账本 | 白名单 v1 事件流逐条 hash 比对 |

### 4.3 通过判据

- 连续 **≥14 天**四维度 100% 一致（零 diff）方可进入 §5 Gate B；
- 任何一天出现 diff：计数清零重算，diff 定位为 P1 工单（不允许「带 diff 切流」）；
- 日报出件至固定路径，缺失当天即视为不通过（fail-visible，不允许静默跳过）。

## 5. 迁移门制（三段式；仅在「决定迁移主控」时启用）

> 与 §543 语义对齐：「双读校验 → 关闭旧主控，禁止长期双写」。**双写**指长期存在两个写入口；本门制中每个阶段写侧始终单源，阶段间切换是一次性动作，不构成双写。

### Gate A：全量比对（≥14 天）

- §4 双读校验连续 14 天零 diff；
- 产出：比对日报归档 + diff 历史清单（应为空）+ 老田书面确认。

### Gate B：灰度切流（按域，一次性写切换）

- 切流单位：**按业务域**（如先研发域、后投研域），不按时间百分比；
- 每域切换窗口：停写（分钟级）→ 真源快照终验 → 写侧主控指向新系统 → 立即回放该域全部在途任务验证 → 开写；
- **同一域同一时刻只有一个写主控**；切换失败回滚 = 写侧指回 Legion + 快照恢复，回滚演练必须在切换前完成；
- 灰度期间旧主控保持只读在线（供回滚与审计），但**不得写**。

### Gate C：关闭旧主控

- 全部域切换完成且稳定 ≥30 天（零 P0/P1）；
- Legion 任务编排功能**归档不删除**（代码保留、停止调度），审批席与执行网关不受影响；
- 回滚预案：归档后 90 天内可按快照重启旧主控；90 天后进入只读化石状态。

### 明确禁止

- ✗ 双写任何账本（任务/审批/事件）超过一次切换窗口；
- ✗ 跳过 Gate A 直接切流；
- ✗ 「以 Paperclip 回答成功」代替业务验收（架构红线沿用）。
