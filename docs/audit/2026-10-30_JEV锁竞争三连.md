# JEV 锁竞争三连观测（17:00 / 18:00 / 19:00）

- 日期：2026-10-30 19:06
- 结论：**连续三轮同一根因——k266_m3 持有 ollama_batch.lock，JEV 只好收工；不是动态 batch 问题。**

## 三次现场

```text
17:00  batch_auto=501  judged=8/500  left=1068  deadline_hit=0  holder=k266_m3
18:00  batch_auto=501  judged=8/501  left=1618  deadline_hit=0  holder=k266_m3
19:00  batch_auto=501  judged=8/501  left=1897  deadline_hit=0  holder=k266_m3
```

共同点：

```text
batch_auto 正确
deadline_hit=0
锁一丢立即收工
metrics judged=8 < 20，不写基准（符合采样门槛）
```

## 判断

- 动态 batch 已生效，不是“批量过大”；
- JEV 小时轮在 M3 持锁时先抢到过锁，随后 `tick` 发现锁被 M3 抢走，只判 8 条；
- 每小时重复“抢锁 → 丢锁 → 8 条”是纯浪费，且积压继续上涨（left 1068→1618→1897）；
- 继续调 batch 公式不会改善。

## 建议（按优先级）

1. **错峰**：M3 活跃时段 JEV 小时轮不抢锁，直接 skip（现在抢到再丢，浪费 30-350s）；
2. **优先级**：明确 M3 优先还是 JEV 优先；不要让两者每轮互相抢；
3. **独立资源**：若都要跑，给 JEV 单独 Ollama 实例/模型槽，而不是共享 `ollama_batch.lock`；
4. 夜跑（21:50）若仍被 M3 打断，应先确认 M3 是否应在夜间运行。

## 验收

```text
连续 2 轮 judged>=100 或明确 skip，而不是 judged=8 + lock lost
夜跑 batch_auto 能完成到 deadline
```
