- **审计对象**：JEV 判读产线（`news_collector/`）+ JEV 评估治理（`jev-eval/`），含 OLlama 批处理错峰链路、雪球分类对照面。

- **数据快照**：2026-10-26 02:20–03:05（夜间独占运行中）。

## 一、结论摘要

1. **设计完整度高**：云→本地降级、schema 强校验、低置信自一致重采样、租约错峰、漂移监控（JS 散度）、告警门+DLQ、回测重放，构成一个完整的"判读—治理—回测"闭环。
2. **"积压 19k"是被误读的指标**：新鲜数据每天 100% 判完（10-24/10-25 待判=0），欠账是**历史沉淀**（news 集中在 10-19~10-23；雪球 7.7k 主要是 2013–2017 归档）。继续按"总 pending"算 ETA（175h）会误导产能决策。
3. **真正的问题是"兑现率"和"可靠性"**：夜间 batch=600 实际只判 135–558（均值兑现率 57%）；先取批后抢锁、tick 最坏阻塞 5450s、心跳粒度粗于 STALE_S、强杀无留痕——都会造成重复判读或空转。
4. **数据契约存在两代并存**：本地判读 prompt 缺 `scope` 字段，新判行 100% `scope=""`；老云端行有 scope。下游 38 处消费口径分裂。

## 三、设计亮点（判例，不建议推翻）

1. **格式强约束**：`format=json` + `_validate_jev`（K-ORG-159）枚举校验，坏值返回 None 不写库。
2. **低置信自校准**：conf<0.7 触发 k=3 自一致重采样（K-ORG-163），多数票 + 一致率映射 conf。
3. **云→本地降级**：451 地理封锁根因定位（K-STOCK-084）；云失败置 `_CLOUD_FAIL_UNTIL=+300s` 熔断。
4. **租约错峰**：`LEASE_S=300 / YIELD_S=20 / TICK_WAIT_S=900`，M3 与 JEV 不互饿。
5. **写库幂等**：组级事务 + rollback 跳过，下轮重判；取 `jev IS NULL` 天然断点续跑。
6. **空判短路**：连续 3 组 0 判 → 收工（防 451 期间每轮空转 25 分钟）。
7. **漂移治理**：7 天窗口 JS 散度（阈值 0.05）+ 确定性 alert_id 幂等 + jev_gate 降噪推送。
8. **回测闭环**：`jev_archive` 每日归档 + `jev_replay` 全窗口重放。

## 五、缺口清单（分组，带证据）

### A. 数据契约
1. **本地 prompt 缺 scope**（news_ai:455-470）→ 新判行 `scope=""` 100%，图表"市场多空"面板与 `_jev_stats` 分市场段对老数据以外失效（news_jev_chart:71）。
2. **两代 schema 混存**：老行有 scope、新行有 event_type/impact/companies/meter → 下游 38 处读取口径分裂（`api_backtest`/`api_intel_bus`/`premarket`/`nine_dim`/`rps_resonance`/`event_graph`/`daily_report`/`jev_drift` 等）。
3. **无溯源字段**：news 表无 model/prompt_version/judged_at，无法回答"哪代模型判的"，也无法重判对齐。

### B. 调度与并发
4. **先取批后抢锁**（jev_backfill:177 取批 → :192 acquire(900s)）：等锁期间批已过期；双实例会重复判同一批并覆盖已判值。实测 01:00、02:00 各空转 900s 让位。
5. **deadline 仅组间检查**（:209）：最坏一组 8×(25+60+45×2)≈1400s；实测 1800s 轮跑到 1944.7s。
6. **tick 最坏阻塞 6×(900+5)+20≈5450s**（ollama_lock:159-174），远超子进程 hard timeout 1800s（night_batch:126）→ 被硬杀即丢组 + 锁遗留。
7. **心跳粒度=一组 8 条**：单组最坏 > STALE_S(1200s) 即被对方判死锁抢占（ollama_lock:39,88）→ 双写者风险。
8. **xq_classify 完全不用 ollama_lock**（全仓仅 JEV/M3/tdx 加锁）→ NUM_PARALLEL=1 下与 JEV 互抢；`backfill_sprint.py:289` 用 `segment=""` 全量，与 night_batch 的 segment B 重叠，仅靠状态日志 mtime 让路。
9. **每小时任务与夜间独占重叠**：00:00 两实例并行（hourly 判 167 条）；hourly 日志把锁持有者误写为"锁被 M3 持有"。

### C. 可靠性
10. **静默丢单**：失败返 None 仅跳过，无 attempt/error 列、无 DLQ；`jev_feed.py:160` `judged += len(items)` 把失败计成功；夜间 `--alert-threshold 0` 关掉唯一告警（jev_night:328）→ Ollama 整夜挂仍 rc=0。
11. **强杀无留痕**：`atexit.register`（jev_backfill:191）在 kill -9 下不执行；2026-10-25 22:14/23:10 两次实例消失无 END 行，靠下一实例日志试探接管。
12. **暂停旗单向耦合**：旗存在 → JEV 永不 yield（jev_backfill:19）；崩溃残留旗会导致 M3 永久饿死（10-25 已发生一次）。
13. **云端 100% 不可达却无告警**：7890 无监听；告警文案仍写"云端 systemone 故障"（jev_backfill:146）。
14. **batch=600 永不兑现**：应改按时间预算循环（batch ≈ 1500×中位耗时），而非固定条数。

### D. 可观测与测试
15. **积压指标未分层**：`ops.batch_backlog` 直接把历史 pending 计入 ETA（175h），掩盖"新鲜链路健康"事实。
16. **JevFeed-Verify 竞态**：00:15 检查 23:45 才开始、需 78 分钟的产线 → 常态 rc=1。
17. **测试缺口**：`news_collector/jev_backfill.py` 零测试；`ollama_lock` 抢锁/tick/回收零测试；`jev_judge_one` 路由/scope 缺失/熔断零测试；`jev_night` 单实例锁零测试；双实例重复判读无测试。
18. **xq 积压口径偏差**：7698 恒大于可判集 7693（5 行永不清零）；A/B 分片 1,414 vs 6,279 极不均。

## 六、建议

### P0（不占 GPU，可当天做）
1. 积压指标分层：`≤3 天 / 3–7 天 / >7 天`，健康卡按"新鲜积压"判红。
2. `JevFeed-Verify` 挪到 02:00（或读"产线运行中"状态不判红）。
3. 暂停旗加超时（>12h 自动失效），防 M3 永久饿死。
4. nightly `--alert-threshold` 从 0 改为合理阈值（如 500），恢复夜间告警。

### P1（需拍板）
5. **历史欠账处置**（见第八节）。
6. night 实例改用注册任务 `\ZeroBound\JevNight`（现在是手动 WMI 启动），并在 22:00–07:00 禁用 `\JevBackfill` 小时轮，消除竞争。
7. 调 night 参数：`--batch 1500`（≈ 时间预算）或把 deadline 提到 2400s，让每轮跑满。

### P2（结构性）
8. news.jev 增 `model/prompt_version/judged_at`（或独立 `jev_meta` 表）。
9. 建 `(jev, ts)` 索引 + pending 查询限定时间窗。
10. reason 生成改批量一次调用（产能有翻倍空间）。
11. 本地 prompt 补 `scope` 字段，修复分市场面板。
12. `xq_classify` 接入 `ollama_lock`，统一错峰。
13. 低置信（9,974 条）入复核队列。
14. 补 4 组缺失测试（jev_backfill 主循环 / ollama_lock / judge 路由 / jev_night 单实例）。
15. 清理废弃任务 `\JevStack`（10-22 被终止后未维护）。
