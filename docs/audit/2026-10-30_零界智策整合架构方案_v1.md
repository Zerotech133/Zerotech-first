# 零界 × 智策整合架构方案 v1

- 日期：2026-10-30
- 结论：**不合并代码、不合并数据库，采用“两个模块化单体 + 边界 BFF + 同源入口 + 可选 OIDC”的联邦架构。**
- 目标：零界保留个人 OS/AI/军团/运维；智策作为量化交易域，先只读接入，再逐步单点登录与事件联动。

## 1. 开源对标结论

| 层 | 候选 | 结论 | 理由 |
|---|---|---|---|
| 后端拆分 | 微服务 / 模块化单体 | **模块化单体** | 单人/小团队规模，微服务只会增加运维；[MonolithFirst](https://martinfowler.com/bliki/MonolithFirst.html) |
| 前端整合 | 微前端 / 独立应用 | **独立应用 + 入口/反代** | 智策是 React/antd，零界是 vanilla；微前端改造成本高于收益 |
| BFF | 门户 BFF / API 网关 | **门户 BFF（只读）** | [Backends for Frontends](https://learn.microsoft.com/en-us/azure/architecture/patterns/backends-for-frontends) |
| 反向代理 | nginx / Caddy / Traefik / Kong | **沿用 nginx** | 已有 8734 入口；Caddy/Traefik/Kong 会新增服务与迁移成本 |
| 身份/SSO | Keycloak / Authentik / Zitadel / Casdoor / Pocket ID | **先不引入；二期 Pocket ID，团队化再 Zitadel** | Keycloak 偏重（JVM）；[Pocket ID](https://github.com/pocket-id/pocket-id) 轻量 OIDC；[Zitadel](https://zitadel.com/docs) 适合多用户/服务账号；[Authentik](https://docs.goauthentik.io/) 适合 forward-auth；[Casdoor 对比](https://casdoor.ai/docs/comparison/feature-comparison/) |
| Forward Auth | nginx auth_request / Authelia | **二期可选** | [Authelia](https://www.authelia.com/) 与 nginx 组合成熟；[Traefik ForwardAuth](https://doc.traefik.io/traefik/middlewares/http/forwardauth/) 作为备选 |
| 事件总线 | Redis Streams / NATS / Kafka | **二期 NATS JetStream** | 轻量、持久化、Go 单二进制；Kafka 过重；[NATS](https://docs.nats.io/) |
| 可观测 | OpenTelemetry + Prometheus/Grafana | **沿用并补 OTel** | 零界已有健康/任务账本；[OpenTelemetry](https://opentelemetry.io/docs/) |
| 迁移方式 | 一次性重写 / 绞杀者 | **绞杀者** | [Strangler Fig](https://martinfowler.com/bliki/StranglerFigApplication.html) |

### 关键取舍

1. **不做微服务/K8s**：两个应用 + 一个反向代理足够；拆分按“域”而不是按“技术层”。
2. **不做微前端**：智策 React 独立运行；零界只提供入口/同源代理。
3. **不复制 autoSession**：其密码明文存 localStorage、自动注册、登录页禁用，不能作为零界身份体系。
4. **不合并 PG**：智策 PG 5446 保持独立；跨域只走 API/事件。
5. **先只读、后写**：交易/权益写操作必须经智策授权与 L2 审批。

## 2. 目标架构

```text
Browser
  │
  ▼
nginx 8734（唯一人类入口）
  ├─ /                     → 零界 portal 8091（个人 OS/AI/军团/运维）
  ├─ /zhice/               → 智策前端 5175（二期，同源反代）
  ├─ /zhice-api/           → 智策 API 8102（二期，仅服务端/受控）
  └─ /api/bff/zhice/*      → 零界 BFF：只读聚合/健康（二期）
        │
        ├─ 零界 PG / 文件 / 任务账本
        └─ 智策 API 8102（Bearer/服务账号）

身份：
  Phase 0-0：两套账户（零界 admin key / 智策 auth）
  Phase 3：Pocket ID/Zitadel OIDC 或 nginx auth_request 统一门

数据：
  零界：OS/AI/军团/任务/健康
  智策：行情/策略/交易/持仓/复盘/权益
  仅 API/事件交换，不共享表
```

## 3. 集成分级（按风险从低到高）

| 级别 | 内容 | 工作量 | 风险 | 审批 |
|---|---|---|---|---|
| L0 | 入口卡/链接到 5175 | 0.5 天 | 低 | 无（本轮已做） |
| L1 | 只读 BFF：health/market/strategies GET | 2-3 天 | 中 | L1，代码+测试 |
| L2 | 8734 同源反代 `/zhice/`、`/zhice-api/` | 1-2 天 | 中 | **L2**（nginx/入口） |
| L3 | 统一身份/SSO（OIDC/forward-auth） | 1-2 周 | 高 | **L2** |
| L4 | 事件联动/写操作/交易审批 | 1 周+ | 高 | **L2 + 交易审批** |

## 4. 分阶段方案

### Phase 0：安全冻结（必须先做）

1. 设置强 `SECRET_KEY`、`ADMIN_PASSWORD`、`INTERNAL_API_KEY`；
2. 关闭 `autoSession`，恢复登录页；禁止密码明文 localStorage；
3. 确认 `MULTI_USER_EXECUTION_MODE` 与通知模式，先 `legacy`/`shadow`，不直接 enforced；
4. 只绑 `127.0.0.1`，不暴露 5175/8102；
5. 备份数据库后再动配置。

**验收**：默认口令/默认密钥消失；`/auth/me` 未登录 401；无 autoSession 自动注册。

### Phase 1：今日入口（已完成）

- `/os-entry` 的“研究与决策”增加「智策量化驾驶舱」卡片 → `http://127.0.0.1:5175`；
- 外部链接新标签打开，不劫持零界当前页；
- 不改变智策、不共享登录。

**验收**：卡片可见、点击打开 5175、零界页面无回归。

### Phase 2：只读 BFF（下一步）

新增零界服务端 `portal/zhice_bridge.py`：

```text
GET /api/bff/zhice/health
GET /api/bff/zhice/market/overview
GET /api/bff/zhice/market/kline?code=...
GET /api/bff/zhice/strategies
```

约束：

- 仅允许 GET + 固定 allowlist；
- 服务账号 token 只放服务端 env/secret store，不下发浏览器；
- 超时/错误 fail-visible；不缓存用户敏感数据；
- 返回结构统一为 `{ok, source, data, as_of}`；
- 写端点一律 405/403。

### Phase 3：同源反代 + SSO（可选）

- nginx：`/zhice/` → 5175，`/zhice-api/` → 8102；
- 登录：Pocket ID（轻量 OIDC）或 Zitadel（多用户/服务账号）；
- 智策改造：关闭 autoSession，接受 OIDC/反代身份；
- Cookie：HttpOnly、Secure、SameSite；不把 token 放 localStorage；
- nginx `auth_request` 或 `forward_auth` 统一门。

### Phase 4：事件与写操作

- 智策发 `TradePlanCreated/OrderFilled/PositionClosed` 等事件；
- 事务 outbox → NATS JetStream；
- 零界只读消费，做 AI 复盘/健康/日报；
- 交易/权益写操作仍回智策授权，不在零界绕过。

## 5. 数据归属矩阵

| 数据 | 归属 | 跨域方式 |
|---|---|---|
| 个人 OS/任务/军团/健康 | 零界 | 本地 |
| 行情/K线/证券/日历 | 智策 | 只读 API |
| 策略/候选/计划/风控/授权/持仓/复盘 | 智策 | API；写操作只走智策 |
| 用户/角色/权益/计费 | 智策（Phase 3 可迁 OIDC） | API/OIDC |
| AI 建议/记忆/采纳 | 零界 | 本地 |
| 交易/资金 | 智策 | 不跨库、不复制 |

## 6. 安全红线

- 5175/8102 不直接公网暴露；仅 127.0.0.1 或反代；
- 不在前端 localStorage 存密码/token（长期目标 HttpOnly cookie）；
- 不把智策 admin 默认口令带入任何环境；
- 不把 `.env.local`、`SECRET_KEY`、支付/IM token 写入仓库/日志；
- 写操作、实盘、支付、通知绑定全部 L2；
- 数据库不合并；备份先行。

## 7. 验收清单

- [x] 入口卡：`/os-entry` → 5175
- [ ] P0：默认密钥/口令清零，autoSession 禁用
- [ ] P2：BFF 只读 allowlist，GET-only，错误可见

## 8. 结论

**最优结构不是把两个系统合成一个，而是：**
- 智策 = 量化交易域（独立模块化单体 + PG）；
- 零界 = 个人 OS/ AI 参谋长（独立模块化单体）；
- 中间 = 入口 + 只读 BFF + 可选 OIDC + 事件总线；
- 先给用户一个可点击的量化驾驶舱，再逐步做只读 API、同源反代和单点登录。

这符合 [MonolithFirst](https://martinfowler.com/bliki/MonolithFirst.html) 与 [Strangler Fig](https://martinfowler.com/bliki/StranglerFigApplication.html)：先用最小边界创造价值，再按需演进。
