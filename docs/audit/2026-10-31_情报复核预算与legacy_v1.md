## 一、拍板口径

| 项 | 值 | 说明 |
|---|---|---|
| 人工复核预算 | **50** | pending 中第 1~50 个（预算档位）为人工优先档 |
| 机器预审预算 | **200** | pending 中第 51~250 个为机器预审档 |
| 总保留预算 | 250 | = 50 + 200 |
| 其余 pending | **unreviewed_legacy** | 归档状态，不删数据、不算已复核、可重开 |
| resolved | 仅 `status='resolved'` | **修正旧口径**：旧 summary 用 `total - pending` 当 resolved，会把 legacy 误算成"已复核" |

`tier_counts` 为**结构性预算档位**（不依赖具体排序实现，前端别自己写死数字）：

```
human        = min(pending, 50)
machine      = min(max(pending-50, 0), 200)
over_budget  = max(pending-250, 0)      # 尚未归档前的超额 pending
pending      = 当前 status='pending'
unreviewed_legacy / resolved / total    # 真实 status 计数
```

- 归档前（现状）：pending=10525 → human=50, machine=200, over_budget=10275。
- 归档后（预期）：pending=250 → human=50, machine=200, over_budget=0, legacy=10275, resolved=0。

## 二、代码改动

### 2.1 `portal/api_jev_review.py`

- 常量：`HUMAN_BUDGET=50`、`MACHINE_BUDGET=200`、`PENDING_BUDGET=250`、`LEGACY_STATUS="unreviewed_legacy"`，并导出 `budgets()` / `tier_counts()`。
- `STATUSES` 新增 `unreviewed_legacy`；`GET /api/jev/review/queue?status=unreviewed_legacy` 可用；未知 status 仍回落 pending（不 500）。
- `summary()` / `query()` 顶层返回 `human_budget`、`machine_budget`、`pending_budget`、`tier_counts`；summary 内同时保留 `unreviewed_legacy` 计数。
- `_summary()`：`resolved` 改为 `WHERE status='resolved'` 真实计数；新增 legacy 计数。**legacy 不计入 resolved**。
- `resolve()`：仍为唯一复核写入口，`WHERE id=? AND status='pending'`——legacy/resolved 一律 `not_pending`（HTTP 409），不会被当 pending 写回。
- 新增 `reopen()` + `POST /api/jev/review/reopen`：仅 `unreviewed_legacy → pending`；
  - pending/resolved 拒绝（`not_legacy`，避免覆盖既有复核结论）；
  - note 记录 `[reopened by 复核人 @ 时间]`，原 id/title/original_jev/裁决字段不删；
  - 重开后可正常 resolve。
- 不触发 JEV 重判/回填；不改任何表结构。

### 2.2 `tools/intel_review_archive.py`（新建）

CLI：

```powershell
python tools/intel_review_archive.py --dry-run                  # 默认行为（只读 mode=ro）
python tools/intel_review_archive.py --db <news.db> --dry-run --json --samples 10
python tools/intel_review_archive.py --apply --backup-dir C:\Temp  # Lead 执行窗口用
# 可选：--human-budget/--machine-budget/--recent-days/--novel-days/--now/--json
```

分层规则（keep 优先序，`intel-review-archive/v1`）：

| 规则 | 权重/实现 |
|---|---|
| 高影响优先 | 解析 `jev_review_queue.original_jev` 的 `impact`（缺失回退 `news.jev`）：high=+40 / medium=+20 / low=+5 / 缺失=0 |
| 低置信优先 | conf<=0.4：+15；conf<=0.6：+8 |
| 近 7 天入队 | `queued_at` 在 recent-days 内：+20 |
| 新来源 | `news.source` 首次出现（`MIN(ts)`）在 novel-days 内：+10 |
| 稳定排序 | score desc → queued_at desc → id asc；取前 human+machine（默认 250）保留 pending，其余 → `unreviewed_legacy` |

安全与可回滚：

- **默认 dry-run**：只读 URI `file:...?mode=ro`，不做任何写；`--apply` 与 `--dry-run` 互斥。
- **--apply 强制备份**：用 sqlite `backup()` API（一致性快照，含 WAL，不是裸 copy）写
  `C:\Temp\news.db.bak-YYYYmmdd-HHMMSS`（`--backup-dir` 可改），备份后自检：
  可打开 + `jev_review_queue` 行数=源 + `PRAGMA integrity_check=ok`。
- **单事务**：`BEGIN IMMEDIATE` → 分批 `UPDATE status='unreviewed_legacy' WHERE status='pending' AND id IN (...)` → 事务内校验 pending/legacy/total 与计划一致 → `commit`；不符 `rollback` 并报错，不留半成品。
- **只改 status 一列**：title/stocks/original_jev/reviewer/decision/note 全部保留；可重开。
- **幂等**：第二次 apply 待归档=0 → 零写库、不多备份。
- **审计**：备份旁写 `<backup>.manifest.json`：规则版本/预算/计数/时间/备份路径/样本 +
  `legacy_ids_count` 与 `legacy_ids_sha256`（id 清单指纹，可核对，不复制 1 万条原文）。
- 非法 `--now`/缺库/参数错 → 退出码 1；备份或写库失败 → 退出码 2（fail-visible）。

## 六、残余风险与边界

- **R1 数据口径**：93% 行无 impact 字段 → 高影响规则实际只对 732 行生效；legacy 主体是"未复核堆积"，不是"复核后判定低价值"。文档/面板文案不要读成"已判低优先"。
- **R2 resolved 口径变更**：旧 summary 的 `resolved=total-pending` 会把 legacy 混入；升级后前端若消费旧字段需回归（本单测试已锁新口径）。旧代码仍是 `total-pending` 的镜像/缓存可能有短暂差异。
- **R3 并发写**：apply 期间 JEV/采集侧可能写入新 pending；工具用"计划快照 + `WHERE status='pending'` 条件更新"，新增行不会被误标，但计划计数可能略旧（事务内校验会拒掉不一致的提交）。建议执行窗口内暂停 JEV 写队列。
- **R4 备份体积/落点**：备份 ≈120MB 落 `C:\Temp`，需空间与保留期约定（含新闻正文，属本地私有数据；不要外发）。
- **R5 预算硬编码**：50/200 是本次拍板常量；调整需改代码（`api_jev_review.HUMAN_BUDGET/MACHINE_BUDGET` 与脚本默认值同一提交）。
- **R6 tier_counts 为结构性档位**，非逐 id 精确分档；"谁进不进去"的精确 keep 集由归档脚本规则决定（本文 §二.2 固化），面板如需 per-item 档位需另单做投影。
- **R7 重开不撤销历史**：reopen 只把状态转 pending 并留 note，不恢复任何"已删除"数据（本单不删行）；resolved 不允许重开，避免覆盖复核结论。
- **未验证**：生产 apply 未执行（Lead 决定执行窗口）；apply 的并发/耗时以生产窗口实测为准（预计 <5s：10275 条分批 UPDATE + 120MB 一致性备份）。
- **不做**：不改 nginx/auth（另一单）、不改 schema、不重启服务、不做 JEV 重判/回填。
