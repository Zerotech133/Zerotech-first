## 5. 修复建议（可执行）

### P0（恢复同步，1-2 天）
1. **DNS 止血**：`rookie.xtcloud-tech.com` 当前解析失败（errno 11001）。向 DATA1 取远端真实 IP → 钉 `C:\Windows\System32\drivers\etc\hosts`（L2/人工审批，本单未执行）；同时在 `start_tdx_sync.ps1` 保留 `_dns_probe` 错误码便于区分"本机解析失败 vs 远端不可达"。
2. **拆任务防 2h 终止**：`\TdxSync` 当前 `--all` 单进程 + 2h 超时限（`Stop If Runs > 02:00`）。建议拆 2-3 批按表集合串行（任务或 wrapper 内循环）：
   ```powershell
   # 分批示例（先高频行情/资金，后低频财务/静态；具体表清单以 tdx_sync.py --status 输出为准）
   python -X utf8 tdx_sync.py --tables ts_daily,ts_daily_basic,ts_index_daily,ts_moneyflow,ts_hk_daily,ts_margin_detail
   python -X utf8 tdx_sync.py --tables ts_income,ts_balancesheet,ts_cashflow,ts_fina_indicator,ts_fina_mainbz
   python -X utf8 tdx_sync.py --tables <其余>
   ```
   或 L2 调高任务超时（不建议，先拆批）。
3. **补采窗口**：DNS 恢复后先 `python tdx_sync.py --status` 核对 182 键；对 33 张 10-13 断点表按批执行 `--tables <批>` 触发增量（本地 max date 落后 20 天，单次即可补齐；若仍零行则判远端源问题，保持 stale 并上报）。
4. **零行软失败可见化**：现状"假完成拦截"只打屏 + 不盖 done，之后无记录。建议 manifest 每表增 `last_attempt_at / last_success_at / zero_streak`（与 task-26 建议的 `today_incr/last_output_at` 同一思路），并把 `zero_streak≥3` 升级为告警。

### P1（防复发，1 周）
5. **任务级监控**：`\TdxSync` Last Result≠0（含 0x41306 终止）必须告警——现有 `alert_fail_wrap.py` 只在 wrapper 正常返回 rc 时触发，**被调度器终止时 wrapper 根本没机会告警**（10-23~10-28 无 attempt 行即此类）；建议 `KgChainWatchdog`/`DataPipelineProbe` 增加：Last Result、`tdx_sync.lock` 残留 >3h、各表 `last_success_at` 滞后。
6. **freq 标签修正清单（catalog 变更，需治理单）**：`ts_income(_vip)`、`ts_balancesheet`、`ts_cashflow`、`ts_fina_indicator(_vip)`、`ts_fina_mainbz(_vip)`、`ts_forecast(_vip)`、`ts_express(_vip)`、`ts_dividend(_vip)`、`ts_disclosure_date`、`ts_stk_rewards`、`ts_stk_holdernumber`、`ts_stk_managers`、`ts_stk_holdertrade`、`ts_pledge_detail/stat`、`ts_index_weekly/monthly`、`ts_stock_basic`、`ts_bse_mapping`、`ts_kpl_concept`、`ts_tdx_index` → `freq` 改 Q/M/W 或单表 lag 阈值；否则资格评估（task-26）永远把这些表判 stale。
7. **锁残留清理**：`C:\Temp\tdx_sync.lock`（11-01 17:30 残留）由脚本 3h stale 逻辑下次运行清理；建议 wrapper 退出时（含被终止场景无法执行）由 watchdog 兜底，或改用 PID+启动时间双校验。

|---|---|---|
| R1 | DNS 修复依赖外部 IP | 钉 hosts 需真实 IP 且远端 IP 变化会再断；属外部依赖，需远端 owner 协同 |
