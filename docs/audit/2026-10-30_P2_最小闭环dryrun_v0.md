## 2. 已证明

- 三个组件可在本机无外部依赖运行；
- 输出可解析、可留痕、可复现；
- 不做写操作，不触发业务变更；
- patrol 能给出部门级静默/超期/督办清单；
- red-team 有周报与 100% 通过基线；
- planner 能生成结构化计划，但仍是模板。

## 3. 未闭环（P2 红色根因）

1. **无周期**：没有“每周一 patrol / 每周 red-team / 按需 planner”的固定运行与责任人；
2. **无 KPI**：静默人数、督办关闭率、red-team 通过率、planner 计划被采纳率没有趋势；
3. **无行动闭环**：patrol 输出 13 条督办，但没有派单/回执/关闭；
4. **无联动**：三个组件各自产出，没有串成
   `patrol 发现 → red-team 验证 → planner 出整改计划 → 回执 → 下周复查`；
5. **测试面窄**：red-team 仅 12 用例，不能代表真实对抗覆盖。

## 4. 建议的最小闭环（v1）

### 周期

```text
每周一 09:00  Patrol（只读）
每周一 09:10  Red-team 周报（只读）
每周一 09:20  Planner 基于前两者生成 1 份整改计划
每周一 09:30  人工确认；只生成待办，不自动执行
下周一复查关闭率
```

### 指标

| 指标 | 基线（本次） | 目标 |
|---|---|---|
| 静默成员 | 40 | ≤30 且连续两周下降 |
| 超期 doing | 0 | 保持 0 |
| 督办关闭率 | 无数据 | ≥80% / 周 |
| red-team 通过率 | 100%（12 用例） | ≥95%，用例扩到 30+ |
| planner 计划采纳率 | 无数据 | ≥50% |

### 行动

- 13 条部门督办 → 生成待办/回执，不直接执行；
- 研发部 9 人静默 → ARCH1 确认是“无任务”还是“未上报”；
- red-team 扩充注入/越狱/幻觉/工具滥用四类；
- planner 用 3 个真实问题试跑，记录人工修订率。
