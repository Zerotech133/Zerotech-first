## 3. 发布单元缺口与修复（W1-2 / W1-3，代码+单测，未上生产）

### 3.1 缺口：`promote` 只切指针、不切 junction（W1 明令禁止的「指针变了、目录没切」）

- 证据（修复前）：`tools/release_legion_ide.py::promote()` 只写 `current.json`，note 原文
  「仅更新指针；Hermes 需重启/切换 env 后才生效（L2 窗口）」；`rollback_to`=promote 别名；无任何 junction 操作。
  生产 09:30 的切换是**人工**：旧 `current` 改名 `current_prev_20261031_092952`，再 `mklink /J current <new>`（现物证即 §2.4）。
- 影响：若只 `--promote`，`current.json`=新、`current` junction=旧，`/api/ide/version`（读指针）报新、生产 served 是旧 → 假绿 + 发布不可回放。

**修复（`tools/release_legion_ide.py`，向后兼容）**

```text
+ switch_current_link(root, version, dry_run=False)
    · 先 verify_dir(target) → artifact 不完整/被篡改一律不动（fail-closed）
    · 只在 release_root 内切换（resolve+relative_to 防逃逸）
    · 旧 current 改名 current_prev_<version>（保留回滚位，不删除）
    · 新 junction 先建临时名 .current_new_<version>_<pid>，再 rename 成 current（缩小半切换窗口）
    · 任一步失败 → 清临时 junction + 恢复旧 current（不留下半状态）
+ promote(..., switch_current=False, dry_run=False)
    · 默认仍「只写指针」（旧调用方零影响）；显式 --switch-current 才切 junction
    · 指针写失败 → 自动回滚 junction（避免反向漂移）
    · 指针写改为 tmp + os.replace 原子替换
+ status() → 新增 pointer_version / junction{target,version,target_exists} / drift
+ rollback_to(..., switch_current=…)：回滚=同一个原子动作（指针+junction）
+ 命令行：--switch-current / --dry-run / --verify-live / --live-url
```

### 3.2 顺手修掉一个 fail-open：空 manifest 也能「校验通过」

- 修复前 `verify_dir()` 用 `(manifest.get("files") or {}).items()` 迭代：`manifest.json={"files":{}}`（甚至 `"{}"`）→ 0 次循环 → 返回通过。
- 这会让 §3.1 的 `switch_current` 把 junction 切到一个空/坏 artifact，直接影响 W1「一条回滚路径」的可信度。
- **修复**：manifest 非 dict、`files` 空/非对象、条目缺 `sha256` → 全部 `RuntimeError`（fail-closed）；并有专门单测覆盖。
