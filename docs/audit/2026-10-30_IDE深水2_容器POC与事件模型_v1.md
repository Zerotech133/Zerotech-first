## 3. exec 容器化威胁模型 / POC

### 威胁模型

| 资产 | 当前 Job Object 风险 |
|---|---|
| 宿主文件系统 | 命令拥有当前用户权限，可读写工作区外 |
| 其他 worktree | 可跨任务读取/修改 |
| 凭据/vault | 可读取用户可访问的密钥 |
| 网络 | 可外连、可访问内部服务 |
| Docker socket | 若挂载可逃逸 |
| 资源 | Job Object 限制进程数/超时，但 CPU/内存不完整 |

### POC 命令

```bash
docker run --rm --network none --read-only \
  --tmpfs /tmp:rw,size=64m \
  --mount type=bind,source=<worktree>,target=/workspace,readonly \
  -w /workspace --user 65534:65534 --entrypoint sh \
  ghcr.io/openhands/agent-server:latest-python \
  -lc 'pwd; id; python -V; ls /workspace | head; test -d /C && echo HOST_C_VISIBLE || echo HOST_C_NOT_VISIBLE'
```

POC 结果：

```text
PWD=/workspace
uid=65534(nobody) gid=65534(nogroup)
Python 3.13.15
AGENTS.md
HOST_C_NOT_VISIBLE
GIT_POINTER_PRESENT
```

结论：

- 容器只看到挂载的 worktree，非 root，无网络，只读根；
- **但 git 不可直接用**：Windows worktree 的 `.git` 文件指向宿主绝对路径，容器内无该路径；
- 真实集成必须二选一：
  1. 挂载主仓 `.git` + 设置 `GIT_DIR/GIT_WORK_TREE`；
  2. 容器内从 bare repo 创建临时 worktree，再把结果同步回宿主。
- POC 证明“文件系统隔离可行”，但**尚未接入 LDE exec**。

### 落地验收

```text
命令只能访问挂载的单个 worktree
无网络、非 root、只读根
超时/退出码/输出与现有 API 契约一致
git 命令可用（修 .git 指针或临时 worktree）
宿主 Job Object 保留为资源兜底
```

## 4. OH + LDE 统一 run/event 模型（设计）

### 目标

一次用户任务 = 一个 `run_id`，把：

```text
LDE: lock/read/write preview/confirm/undo/exec/audit
OH:  start/action/observation/approval/diff/commit/stop
```

写进同一 append-only event store，可回放、可取消、可追责。

### 最小 schema

```json
{
  "run_id": "run_...",
  "event_id": "evt_...",
  "ts": "2026-10-30T20:05:00+08:00",
  "source": "lde|openhands",
  "type": "lock|write_preview|write_confirm|undo|exec|action|observation|approval|commit",
  "task": "K-...",
  "actor": "zero_bound:bff",
  "payload": {},
  "prev_hash": "sha256(prev)"
}
```

### 迁移步骤

1. LDE API 增加可选 `run_id`（不传则服务端生成）；
2. OH session `cid` 映射为同一个 `run_id`；
3. 两边写同一 JSONL/SQLite event store；
4. 增加 `GET /api/ide/runs/<run_id>` 回放；
5. 审计事件先做 hash 链，再考虑外部锚定。
