## 0. 结论摘要（按严重度）

1. **最高危是 portal 认证链，不是一个孤立 Bug**：`/api/os/*` 可伪造本地页头 → 可自签“真实签准” → 受控链产物落 `index.html` 形成存储型 XSS；且 `/api/` 全局未登录可读审批/工单（实测 200）。这三条串联，优先级高于沙箱。

## 2. 高危 Finding（需优先修）

### H1. `/api/os/*` 认证可伪造 + 预览无鉴权 → 存储型 XSS（verified）

- 位置：`portal/api_os_goal.py:93-115`（`X-OS-Page` 106-108、私网 Origin 79-90）、`:510`；`portal/nginx.conf:164` 的 `location /api/` 无 `auth_request`。
- 证据：审计 A 用 `is_local_page_request` 实测：伪造 `X-Portal-Proxy:1 + X-Real-IP:192.168.1.50 + Origin:http://192.168.1.50:8734` 返回 True；加 `X-OS-Page: quick` 仍 True；去头 False。测试 `tests/test_os_quick_auth.py:128-140` 还把该行为写死。
- 影响链：8734 任意客户端匿名 POST `/api/os/*`（register consumer→grant/real→workorder/formal→claim/real→risk/verdict→controlled/artifact 写 `index.html`），再 GET `/api/os/item/<id>/workspace/index.html`（`:118-135` 无鉴权），在 8734 源执行 JS；同时绕过写频控。
- 修法：`_os_goal_post` 改「peer 回环 or `_check_portal_token()` or 有效 `zb_session`」，删 `X-OS-Page`/私网 Origin 分支；预览强制 `text/plain` + `X-Content-Type-Options: nosniff`。

### H2. `sign_real_grant` 任意 nonce 可伪造“真实签准”（verified）

- 位置：`portal/os_controlled.py:216-258`（只校验 `len(nonce)>=8`；signer 硬编码 laotian）；`api_os_goal.py:221-226`。
- 影响：配合 H1，远端匿名即可给任意 item 签 1–24h L1 grant，后续工单/认领/产物全链以其为准，审批形同虚设。
- 修法：服务端签发一次性 nonce（TTL+单次消费），sign 时比对并销毁；signer 取会话 sub；local_password_session 强制二次校验。

### H3. `/api/analysis/submit|review` 绕过 `_MUTATION_POSTS` 闸门（verified）

- 位置：`portal/portal_api.py:1027-1031`（早分支 return）vs `:159-161`、`:1042`；`api_analysis.py:192-226` 自身无鉴权。
- 影响：局域网匿名入队（写 `work/analysis/queue`）；`llm:true` 触发 LLM 计费，`push:true` 触发飞书推送；review 可改复核状态。
- 修法：分支移到闸门之后，或 `api_analysis.handle_post` 首行 `_check_portal_token()`。

### H4. SSO 只护页面不护 `/api/`（verified）

- 位置：`portal/nginx.conf:164` `location /api/` 无 auth_request（对比 `/openhands/`、`/lde/`、`/devops` 有）。
- 实测：22:52 未登录 `GET 8734 /api/platform/approvals`=200（25,277B）、`/api/org/tasks`=200、`8091 /api/platform/approvals`=200。
- 影响：审批/工单/回放读面裸奔；POST 同前缀，写面 token 未逐点验证。
- 修法：`/api/` 默认 auth_request + 公共白名单；SSO 验收补“未登录 API 必 401/302”断言。

### H5. 合并质量门“自证 + 可跳过”（verified）

- 位置：`tools/devtask.py:1836-1840` 跑**待合并分支 worktree** 里的 `test_gate.ps1`；`:1898` 置 `DEVTOOL_PREFLIGHT_DONE=1`；`tools/merge_preflight.py:110-113` 见该 env 直接 return 0。
- 影响：分支可改 gate 脚本 exit 0、改 `test_baseline.json` 把新失败登记 known；`fast gate PASS` 不可作为独立可信证据。
- 修法：gate 脚本/baseline 固定取 master（sha 钉扎，改动即拒）；钩子改认 TID/HEAD 的一次性令牌文件，不认裸 env；baseline 只允许“减少 known”的 ratchet。

### H6. Codex 插件受限 globals 不是安全边界（verified）

- 位置：`agent_platform/adapters/codex_bridge.py::_exec_globals`、`register_from_source`。
- 证据（不执行危险命令）：`exec` 受限 globals 中 `reached=316`，即 `(1).__class__.__mro__[1].__subclasses__()` 可枚举子类；DENY_CALLS 不拦属性链。
- 影响：若插件来源不完全可信，静态校验+白名单 builtins 可被绕过；in-process `exec` 在主进程。
- 修法：**不要把 restricted exec 当安全边界**；插件注册/试跑进 OS 级沙箱（Windows AppContainer/Job Object/Windows Sandbox；Linux Firecracker/E2B）；移除 in-process exec。

## 6. 外部/开源方案对标（可落地优先）

### 6.1 认证/工具策略

- **OWASP Top 10 LLM/GenAI**：Agentic 风险需按“输入/工具/输出/身份”分层。链接：<https://genai.owasp.org/initiative/owasp-top-10-for-llm-and-genai/>
- **OPA Agent Tool Calling**：harness=PEP、OPA=PDP；每次 tool call 送 `input.tool_calls`，deny 即不执行；decision logs 可审计。链接：<https://www.openpolicyagent.org/docs/agent-tool-calling>
- **OpenAI Agents guardrails/approvals**：官方 guardrails + human review 概念；<https://developers.openai.com/api/docs/guides/agents/guardrails-approvals>
- **用法**：`/api/os`/`sign`/`analysis` 这类高危动作先接“会话/一次性 nonce/审批”而不是自报头；运行期策略可先做 JSON policy，再评估 OPA。

### 6.2 沙箱/隔离

- **Windows 原生**：`Experimental_CreateProcessInSandbox`（Windows 11 experimental）支持 AppContainer 内核隔离、FS/网络策略、Job Object；app_container=false 时 FS/网络/capability 不生效。<https://learn.microsoft.com/en-us/windows/win32/secauthz/createprocessinsandbox>
- **Linux/云**：Firecracker microVM（Rust、小攻击面、~125ms 启动、<5MiB overhead），E2B 用于 AI 代码。<https://e2b.dev/resources/firecracker-vs-qemu>、<https://docs.e2b.dev/network/internet-access>
- **结论**：P0 先移除 in-process exec；Windows 单机先 AppContainer/Job Object + 低权限账户；高风险执行再上微 VM，不要把 Python globals 当边界。

### 6.3 发布/供应链

- **SLSA v1.2 Build Provenance**：buildDefinition/resolvedDependencies/runDetails；L1 即要求 provenance。<https://slsa.dev/spec/v1.2/build-provenance>
- **Sigstore/cosign**：sign-blob/attest-blob 签 manifest+artifact，透明日志。<https://docs.sigstore.dev/cosign/signing/other_types/>、<https://docs.sigstore.dev/quickstart/quickstart-cosign/>
- **in-toto / CycloneDX**：attestation 标准 / SBOM。<https://github.com/in-toto/attestation>、<https://cyclonedx.org/specification/overview/>
- **用法**：现有 sha/manifest/guard 升级为“签名+provenance+SBOM”，artifact 只读；bundle 纳入 manifest。

### 6.4 数据时点/质量

- **Feast point-in-time joins**：按 event timestamp 取当时可见值，防未来数据泄漏。<https://docs.feast.dev/getting-started/concepts/point-in-time-joins>
- **Great Expectations**：schema/类型/列/分布断言。<https://docs.greatexpectations.io/docs/reference/learn/data_quality_use_cases/schema/>
- **lakeFS/Delta time travel**：数据版本/回滚/可复现。<https://lakefs.io/blog/power-up-lakehouse-with-git-semantics-and-delta-lake/>
- **用法**：D4 先做 manifest schema+键规则+tie-break 落库+断言，再考虑 Feast；D1 raw/PIT 必须按数据时点，不按采集时刻。

### 6.5 可观测/评测

- **OTel GenAI semconv**：agent/LLM 调用标准属性。<https://opentelemetry.io/docs/specs/semconv/registry/attributes/gen-ai/>
- **Langfuse**：开源 trace/evals/prompt，基于 OTel，可自托管。<https://langfuse.com/docs>
- **用法**：先落 OTel 兼容 JSONL（trace_id/tool/input hash/output hash/cost/latency），再接 Langfuse/Phoenix；覆盖 D1/run_shadow/工具调用。

### 6.6 测试/静态分析
