# T3 产品决策：parse_ok=false 的 Shadow done 语义（2026-10-17 拍板）

> 决策人：老田（授权 AI 组按建议方案落地）｜来源：M2 验收遗留 T3，
> M3 规划「候选口径：保留 done 但标记 degraded=true（零迁移，倾向后者）」——本日按后者拍板。

## 一、决策内容

**口径命名：`done_degraded`（降级完成）**

1. **保留 `status=done`，零迁移**：shadow_ledger.jsonl 存量与新增行不改状态机，
   不引入第三状态值（避免账本 schema 变更与下游消费方破坏）。
2. **`degraded` 字段吸收两类降级**：`run_shadow.py` 写路径自本日起，
   `degraded = 数据源异常 or parse_ok=false`——解析失败视为降级执行，
   新行自然携带；存量行不动（零迁移）。
3. **审计摘牌**：`idempotency_audit.build_report` 不再将
   `parse_fail_done_count` 计入 blockers（原文案
   "product decision required" 已失效）；保留计数 +
   新增 `parse_fail_policy="done_degraded"` 策略标记，供评估观测。

## 二、理由

- 轨迹是客观观测（LLM 曾给出什么建议、解析是否成功），不是承诺；
  parse 失败样本的价值在于**喂评估**（D1 输出稳定性指标），不是阻塞主流程。
- 证据仓 statement 已含 `parse_ok=%s degraded=%s` 双字段（evidence_collect），
  决策后两类信息在证据链上语义自洽：degraded=true ⇒ 评估时降权采样。
- 零迁移：不动 15:30 收编的证据、不动存量账本行，回放验证器无需改。

## 三、消费约定（对下游）

| 消费方 | 约定 |
|---|---|
| 评估（M5 预研） | done 样本分层：degraded=false 全权样本；degraded=true 降权观测，不入主指标 |
| 回放验证器 | 无需变更（status 语义未变） |
| idempotency_audit | parse_fail_done_count 仅计数；duplicate_done 仍阻塞（并发风险与降级无关） |

## 四、落地清单

- `agent_platform/adapters/idempotency_audit.py`：摘牌 + parse_fail_policy 字段。
