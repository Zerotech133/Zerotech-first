## 一、数据模型（幂等迁移）

`news.db.jev_review_queue` 新增列（旧 schema 兼容，现有行默认 `''`）：

```sql
ALTER TABLE jev_review_queue ADD COLUMN review_type TEXT NOT NULL DEFAULT '';
```

| review_type | 含义 | 写入方 |
|---|---|---|
| `human` | 人工复核（默认档；历史 `''` 统计上归 human） | `POST /api/jev/review/resolve` |
| `ai_first_pass` | N1 AI 初筛（机器映射，仅供 A/B/审计） | `tools/intel_ai_first_pass.py --apply`，reviewer=`N1-AI` |
| `''`（旧行） | 迁移前的历史行 | 统计计为 human，不伪造 ai_first_pass |

- 迁移函数：`portal/api_jev_review.ensure_review_type_column(con)`（幂等：已存在返回 False）；
  人工 `resolve()` 首次写库时自动补列；AI 初筛工具 apply 前也调用同 SQL 的幂等迁移。
- **summary 字段**（`GET /api/jev/review/summary`）新增：
  `resolved_human`、`resolved_ai_first_pass`、`review_type_counts{human,ai_first_pass}`、
  `review_type_column`（是否已迁移）；`resolved` 仍是**总** resolved。
  - 人工 50 只看 `resolved_human`；AI 初筛看 `resolved_ai_first_pass`。
  - 旧 schema（无列）时 summary 不崩：`resolved_human=resolved`、`resolved_ai_first_pass=0`。
- `queue` 接口在列存在时每项附带 `review_type`；未知 status 行为不变。

## 二、AI 初筛映射（机器建议 → 复核三态）

| 机器建议（batch/machine JSONL） | AI 初筛 decision |
|---|---|
| `accept` | `correct` |
| `reject` | `wrong` |
| `needs_evidence` | `uncertain` |
| `unavailable`/缺失 | `uncertain`（缺机器 JSONL 时全走本条，明确降级） |

- reviewer 固定 `N1-AI`、review_type 固定 `ai_first_pass`；note 写
  `ai_first_pass:N1-AI;machine=<decision>;batch=<batch_id>` 留痕。
- **不是人工结论**：A/B/面板必须按 `review_type` 过滤；不得把 AI 初筛当人工裁决。

## 三、工具：`tools/intel_ai_first_pass.py`

```powershell
# 默认 dry-run（只读；不写库/不写文件）
python tools/intel_ai_first_pass.py --dry-run
python tools/intel_ai_first_pass.py --json
# 授权窗口执行（先自动备份，再单事务写入）
python tools/intel_ai_first_pass.py --apply --backup-dir C:\Temp `
  --manifest C:\Temp\intel_ai_first_pass_20261031.manifest.json
```

| 参数 | 说明 |
|---|---|
| `--db` | news.db（默认仓内 `news_collector/news.db`） |
| `--batch` | 批次 JSONL（默认 `C:\Temp\intel_review_batch_20261031.jsonl`） |
| `--machine` | 机器预审 JSONL（默认 `C:\Temp\intel_pre_review_20261031.jsonl`；缺失→uncertain 降级） |
| `--backup-dir` | apply 前备份目录（默认 `C:\Temp`；sqlite backup API 一致性快照 + integrity_check） |
| `--manifest` | manifest 路径（默认 `C:\Temp\intel_ai_first_pass_<date>.manifest.json`） |
| `--limit` | 本批最多写入条数（默认/上限 50） |
| `--apply` | 执行写入（与 `--dry-run` 互斥；默认 dry-run） |

安全/事务：
- 只 UPDATE `status='pending'` 的命中行；**非 pending（legacy/resolved）不覆盖**。
- `BEGIN IMMEDIATE` 单事务 + 事务内校验：`written == 可写条数`、
  `pending 减少数 == written`、`resolved_ai_first_pass 增加数 == written`，不符 rollback。
- 输出 manifest：计数/映射/批次与机器文件 meta/备份路径/`applied_ids_sha256`/post_state/
  回滚提示。退出码：0=成功（含 no-op/降级）；1=参数/数据错；2=备份或写库失败。

## 七、残余风险与边界

- **R1 AI 初筛≠人工**：accept/reject/needs_evidence 是规则映射，不保证内容对错；
  `resolved` 总数会包含 AI 档 → A/B/看板必须用 `resolved_human` 或按 `review_type` 过滤，
  不得把 50 条 AI 初筛当人工 50 的完成量。
- **R2 新旧版本并存窗口**：8091 现役进程仍是合并前代码（不读 review_type）。因此：
  - 数据已写入（DB 层可查），但 API `summary` 新字段要 **Lead 合并后重启 8091** 才上线；
  - 窗口内若人工用旧代码 resolve，写入 `review_type=''`（新 summary 统计计 human，不丢），
    但不会显式写 `'human'`——合并重启后建议观察一次分类。
- **R3 备份体积/侧车**：备份 ≈121.6MB 落 `C:\Temp`，含 `-wal/-shm` 侧车；保留期/磁盘空间需约定；
  备份含新闻正文，属本地私有数据，勿外发。
- **R4 并发写**：apply 用 `BEGIN IMMEDIATE` + 校验，执行窗口内其它写入不会覆盖 AI 行；
  但计划快照与最终状态可能有细微时间差（本批 50 全部命中 pending，跳过 0）。
- **R5 列迁移**：`ALTER TABLE ADD COLUMN` 在活动库上执行（本批已完成、耗时极短）；
  旧代码忽略多出的列，不破坏既有 resolve/查询。
- **R6 不自动跑 A/B**：本单只为 A/B 铺数据；A/B 开关/运行仍需授权与单独窗口；
  未改 `INTEL_TO_N1` 默认值、未改生产 prompt/模型。
- **R7 回填来源**：AI 初筛继续用 `C:\Temp` 批次/机器 JSONL 快照；文件被覆盖/删除后
  重跑会得到不同结果（manifest 记录文件 meta，便于核对）。
