# M3 规划：研发与内容生产线（2026-10-17）

> 总纲验收句：**每份交付物都有来源、审查、版本、负责人和可回滚记录。**
> 前置：M0/M1/M2 已收口（39→236→265 tests）；本文档对齐《老田个人AI组一次成型总体架构》M3 定义与《项目复盘与代码审计》缺口清单。

## 一、M3 目标与范围

M3 解决复盘确认的最大结构性缺口——**Artifact 层缺位**：产物散在各域（gzh md / pitch deck / Worker outputs / 报表），证据仓只记指纹不记产物本体索引，交付物无法按总纲要求回答「来源、审查、版本、负责人、可回滚」五问。

三条生产线（软件 / 路演 PPT / 自媒体）**不新建状态机**——七域接线已有受门状态机（gzh draft→reviewed→published、pitch outline→…→delivered、dev doing→done 门），M3 只做两件事：

1. **补 Artifact 统一登记层**（M3-P1/P2）：让每条产线的受门转移自动登记产物；
2. **补发布闸门的产物绑定**（M3-P3）：Approval 绑定 content_hash（总纲幂等规则：审批绑定目标 revision 与 content_hash，目标变更后原审批自动失效）。

红线不变：不提前建 M5 评测门；不建第二状态账本；不新增事实源写入方。

## 二、任务拆解（五刀，每刀可独立收口）

### M3-P1：ArtifactStore 契约与引擎（第一刀，地基）

- `agent_platform/contracts`：Artifact 信封补全（artifact_id / object_type=artifact / content_hash=sha256 / revision / source_system / source_ref / trace_id / produced_by / supersedes）。
- `agent_platform/engine/artifacts.py`：ArtifactStore（SQLite WAL、裸 BEGIN IMMEDIATE、keeper 判例）；append-only + content_hash 去重（同 hash 复用 artifact_id）；`supersede()` 产生新 revision（可回滚=指回旧 revision）。
- 纪律：**登记不设门**（观测≠承诺判例——登记是事实记录，发布/替换才设门）；对齐 M2 证据仓同款测试风格。
- 测试：test_artifacts.py（去重/append-only/supersede 链/崩溃重放）。

### M3-P2：三产线产物挂接（自动登记）

- **gzh**：draft→reviewed 转移时登记 md 为 Artifact（content_hash=md 指纹，与证据仓 artifact_fingerprint 同源）；published 转移时 Approval 绑定 content_hash。
- **pitch**：deck drafted/delivered 同款；decks.json 首个真实 deck 诞生即触发 fact-check 二次实战（全真三域闭环，清掉空集调用尾巴）。
- **dev**：close_done 时登记 closure 产物（验收记录/closure_note 文件）；TaskStore 零改动（接线层挂）。
- 测试：各域 wiring 测试增断言（转移后 artifact 落仓、hash 与真源一致）。

### M3-P3：发布闸门产物绑定（可回滚的关键）

- Approval 增加 `content_hash` 语义（_ensure_columns 容错加列，对齐 trace_id 先例）：gzh published / pitch delivered / skill approved 三类受门转移强制绑定当次 content_hash。
- **变更失效规则**：真源 content 变更后再次走门 → content_hash 不匹配 → 拒绝重放、要求新一轮（防「批 A 发 B」）。
- 回滚路径：deprecated/supersede 凭据化，产物链可回放（回放验证器加 artifact 段）。

### M3-P4：审计与回放扩展

- idempotency_audit 补 academy/pitch 交叉校验（清 T2 挂账）：history 痕迹派凭据→域内 history 对账。
- replay_query 时间线加 artifact.created / publication.sent 事件段。
- 证据收编补 artifact 指纹域（evidence_collect 第八域或并入各域）。

### M3-P5：门户消费与运营视图（清 T4）

- 新页「能力看板」：/api/unified/skills + /api/unified/evidence + /api/unified/usage 三端点的只读 UI（8091 已点亮，缺消费面）。
- nav.js 入口由 export_nav.py 生成器统一挂（禁手写 nav 判例）。
- portal mixin pytest 单测补齐（api_unified/api_approvals 函数级用例收编）。

### 顺手刀（与 P2 同批，不单列收口）

- T1 路径常量 `_resolve(root)` 化（dev/knowledge/personal/pitch/evidence_collect 五处，测试同步去 patch）。
- T5 键格式文档刷新（skill 幂等键 v<ver> → 嵌原文）。

## 三、验收门（七门制，对齐 M0-M2 格式）

| # | 验收门 | 收口条件 |
|---|---|---|
| 1 | ArtifactStore | 契约/引擎/去重/supersede 链测试全绿；真实仓首个 artifact 登记成功 |
| 2 | 三产线挂接 | gzh/pitch/dev 转移自动登记 artifact，hash 与真源一致；零事实源破坏 |
| 3 | 发布闸门绑定 | 三类受门转移 Approval 带 content_hash；批 A 发 B 被拒绝（测试实锤） |
| 4 | 审计回放扩展 | academy/pitch 交叉校验 0 违规；回放含 artifact 段 |
| 5 | 门户消费 | 能力看板页上线（三端点可见）；portal mixin 单测收编 |
| 6 | 零事实源破坏 / 零第二主控 | 八域账本零改动（只加列不加主控）；m0 验收命令全过 |
| 7 | 判例沉淀 | ≥5 条新判例入审计文档 |

**M3 总验收句**：任意抽一份交付物（一篇 gzh 文章 / 一个 deck / 一张验收单），能沿 artifact_id → 审查凭据 → content_hash → 负责人 → supersede 链完整回放。
