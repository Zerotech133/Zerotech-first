# 分支级质量闸改造 v1

- 日期：2026-10-30
- 工单：`WO-LEGION-GATE-BRANCH-20261030`
- 背景：`docs/audit/2026-10-30_质量闸死锁与一次性绕过记录_v1.md`

## 1. 问题

旧 `_quality_gate(tid)` 固定执行：

```python
os.path.join(REPO, "tools", "test_gate.ps1")
```

`REPO` 是 master 工作区。于是：

- master 有既有失败测试；
- 新分支即使把测试修好，也要先通过 master 的旧测试；
- 质量闸拒绝合并 → 无法把修复合进 master → 死锁。

## 2. 改造

新增：

```python
def _gate_script_for(tid):
    wt = os.path.join(WT_DIR, tid)
    if not os.path.isdir(wt):
        return ""
    script = os.path.join(wt, "tools", "test_gate.ps1")
    return script if os.path.isfile(script) else ""
```

`_quality_gate(tid)` 改为：

- 解析任务 worktree；
- 执行 `.worktrees/<tid>/tools/test_gate.ps1 -Suite fast`；
- worktree 缺失/缺脚本 → fail-closed，拒绝在 master 上跑；
- 变更的 tools 测试仍在 worktree 跑；
- 通过后设 `DEVTOOL_PREFLIGHT_DONE=1`，pre-merge hook 跳过重复测试。

`test_gate.ps1` 本身用 `$PSScriptRoot` 推导仓库根，所以脚本路径在 worktree 时，pytest 路径/baseline 全部来自分支。

## 5. 边界

- `pre-merge-commit` 钩子对**直接 `git merge`** 仍会跑 `merge_preflight.py`，其 cwd 是 master；绕过 `devtask merge` 的直连合并仍可能遇到同类问题。
- 建议：所有合并统一走 `python tools/devtask.py merge <TID>`；不要在 master 手工 `git merge`。
- 本改造不改变 `DEVTOOL_MERGE_GATE=0` 的紧急绕过语义。

## 6. 回滚

```text
git revert <merge commit>   # 或恢复 _quality_gate 旧实现
```

回滚后仍建议先跑 `tools/test_gate.ps1 -Suite fast` 确认 master 健康。
