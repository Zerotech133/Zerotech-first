# 数据/运维线交接：备份异地回执时序（2026-10-31）

## 现象
`MetadataDaily` 今日 09:00 运行 rc=1，报告 `agent_platform/data/reports/metadata_daily/2026-10-31.json`：
`backup_ok=false`，`backup_missing=["offsite_remote_receipt"]`，anomalies=3 条（缺 `offsite_remote_receipt.txt`）。

## 根因（实测，已排除"备份真缺失"）

- 备份代 `backups/2026-10-31_0830/` 六件产物齐全（jev_eval / neo4j_kg / quant_code / quant_data / zhice_db / backup.log）；
- **异地回执 `offsite_remote_receipt.txt` 于 10:07:43 由 `aios-offsite-catchup` 生成**：
  `offsite remote: ...\2026-10-31_0830 -> aiosbackup@10.205.0.118:/home/aios-offsite/2026-10-31 | files=6 ok=6 mismatch=0 missing=0 ... at=2026-10-31T10:07:43`
- 而 MetadataDaily 定时 09:00，检查时回执尚未生成 → **时序竞态**，不是备份缺失。
- 当前复核：`python tools/datawarehouse/backup_receipt_check.py` → `missing=[] / receipt_present=True / rc=0`；
  `python tools/metadata_daily.py --json` → `backup_ok=true / anomalies=[]`。

## 建议处置（L2，数据/运维线）

1. **将 MetadataDaily 触发时间从 09:00 移到 10:30（或 11:00）**，晚于 offsite catchup 完成（近日常态 ~10:07）；
2. 或在 `backup_receipt_check.py` 增加「上一代回执回退」逻辑（当日回执缺失但上一代在 & 年龄<36h → WARN 而非 FAIL）；
3. 请确认 `aios-offsite-catchup` 触发时点与最近一次成功耗时（日志 `C:\Temp\offsite_catchup.log`），避免未来再撞；
4. 本项与安全凭据无关；无需改备份内容或重跑备份。
