# M2 规划 · 共享能力层（统一记忆 / Skill / 证据 / 路由 / 成本）

日期：2026-10-17 ｜ 依据：总体架构 §八 M2 + §九 关键决策 5/7/9/10
状态：**规划定稿（待执行）** ｜ 前置：M0 ✅ M1 ✅（2026-10-17 收口）

## 一、M2 目标（总纲原文）

> 交付：统一记忆入口、Skill 目录、证据仓、模型路由、成本统计。
> 验收：一个批准 Skill 可被投研、研发、内容和路演复用；候选知识不能直接进入生产记忆。

M1 之后平台的现状：六域有了受控写路径与审批门，但**能力本身**仍是散的——记忆写各域直落 jsonl、Skill 无目录与评测、Evidence 只有契约没有仓、模型调用无统一路由与成本归集。M2 把"能力"变成平台的一等公民。

## 二、现状资产盘点（2026-10-17）

| 能力 | 现状 | 缺口 |
|---|---|---|
| 记忆 | MemoryStore（RBAC grants + GNS 命名空间 + jsonl）；data/memory/ 已有 agent×namespace 文件；knowledge_pending.jsonl 候选知识 | 候选→生产无评审流程；跨域记忆读取无统一入口（各域直读文件） |
| Skill | 仅 contracts 契约 | 无目录、无版本、无评测集、无跨域复用机制 |
| 证据 | Evidence 契约（fact_hash/来源） | 无证据仓实体；域内指纹（gzh md/pitch artifact）各自为政 |
| 模型路由 | router.py 是任务路由（规则撮合）；模型调用散在 Hermes/qwen 侧 | 平台级模型路由 + 统一调用记录 |
| 成本 | llm_tool_audit.jsonl（工具审计） | 无 Token/成本归集与按域/按 Agent 分账 |

## 三、刀式推进计划（P1→P5，每刀可独立验收）

### P1 · 证据仓（先做：其余刀的依赖）
- 交付：`engine/evidence.py` EvidenceStore（append-only，fact_hash 去重，来源必填）+ `adapters/evidence_scan.py`（扫描六域现有指纹：gzh md sha256 / pitch artifact 指纹 / dev closure_note / paper trace——**收编为 Evidence 记录**，只读适配）
- 验收：六域任一 Artifact 可查得来源链（谁/何时/什么凭据/指纹）；Evidence 与 Artifact 分离纪律不破
- 判例预期：存量收编（WIRING_TS 时刻级切分复用）

### P2 · 统一记忆入口（总纲红线：候选不直接进生产）
- 交付：`engine/memory_gate.py` 候选知识评审流——knowledge_pending →（评测/人工批准 Approval 门）→ 生产记忆（MemoryStore.write 唯一写口）；`adapters/memory_bridge.py` 六域记忆统一读视图（GNS 规范化，禁直读文件）
- 验收：候选知识不经批准无法出现在生产记忆（审计可检出）；一次批准全程可回放
- 红线对齐：§十"不把所有历史聊天直接灌入长期记忆"

### P3 · Skill 目录与复用
- 交付：`agent_platform/skills/registry.json` Skill 目录（输入/输出/适用/禁用/验收器/版本/回滚——总纲 §七 Skill 八要素）+ `engine/skills.py` SkillStore（注册/版本/状态机 draft→evaluated→approved→retired，**approved 需 Approval 门**）+ 首个跨域 Skill 试点（建议"事实核验"——自媒体/路演/投研三域共用，直接回应 M2 验收句）
- 验收：同一 Skill 被至少两个域调用且走同一注册表与版本

### P4 · 模型路由 + 成本统计（合并一刀：调用记录是成本数据的来源）
- 交付：`engine/model_router.py` 模型路由（按任务类型/成本/可用性选模型，规则优先零幻觉，对齐 router.py 原则）+ `engine/usage_ledger.py` 使用账本（每次调用记 agent/域/模型/token/耗时，append-only）+ 报表 `reports/usage_by_domain.json`
- 验收：任一 LLM 调用可按域/Agent 分账；Token 预算分配有数据基础（M5 前置）
- 边界：Hermes 内部调用路由不动（Hermes 是执行适配层，§九决策 3）；本刀只管平台侧直调

### P5 · M2 收口验收
- 交付：`docs/audit/M2验收报告.md`（对齐 M0/M1 格式，七门制）
- 验收主线：跨域 Skill 复用实测 + 候选知识门禁实测 + 证据链抽查 + 成本分账抽查

## 四、明确不做（总纲 §十 延续）

- 不把历史聊天/影子结论直接灌入生产记忆或 Skill
- 不在无评测与批准下升级 Prompt/Skill（那是 M5 成长线的门，M2 只建目录与门禁）
- 不动 Hermes 内部模型配置；不引入第二记忆主控（CowAgent/Khoj 是入口候选，接入评审在 P2 文档另议）
- live 环境保持关闭
