## 一、研究口径与板块地图

### 1.1 边界（这次盘什么、不盘什么）

- **盘**：情报中枢（`/intel` 业务线）与情报工厂（后台全链）：开源情报（爬虫/舆情）、接口情报（TDX）、知识图谱、数据血缘、JEV 判读、证据—标的、复核、门户、飞书出口、情报部军情司、采集即服务平台（在开发）。
- **不盘**：量化交易/行情/回测本体（仅作为情报消费方）、商业 OS、非情报向的知识库（YouTube KB 只做采集链说明）。
- **口径**：产品对外统一“**情报中枢**”，后台治理全链称“**情报工厂**”（依据 `情报工厂子项目规划_20261018.md`）。

### 1.2 目标链路（文档设计 vs 代码实现）

设计（`情报板块研发方案_v1` §二）：

```text
Source Registry → Collectors → Normalizer/Dedup → IntelEvent Store(news.db)
  → JEV Judge → Review Queue → Published Evidence
  → Intelligence Feed / 工作台 → N1/F1/D1 Context
  → Source Health / Review Ledger
```

实测（07:3x）：**采集/JEV/Feed/工作台 已实现；Source Registry（生产）、IntelEvent 契约、Published Evidence 发布层、Review 常态化运营 未实现**。

## 七、结论

1. **情报板块不是“没做”，而是“做完了上半身、中段没接上”**：采集（9 源 × 15 分钟）、JEV 判读（115k/4 服务）、门户（工作台/总线/查询/复核页）、证据接口（3,237）都已真实在役；但复核运营、实体链、证据契约、消费开关、军团编成没有闭环。
2. **最值钱的在开发资产是 `intel_collector`**：它对准了“采集层无底座”这个根因（Source Registry + Adapter SDK + RightsGate + Orchestrator + SLA/PII/PIT/feedback/cron），84 测试齐全、5 源已登记；但它是**原型**（合成数据、零集成、不碰真实数据根），转正需要老田给凭据/写权/立项。
3. **当前最该做的不是加源，而是三件“接线”**：① 复核队列挂任务滚动；② `news.stocks` 实体链补齐（9.4%→目标≥50%）；③ intel 鉴权/路由收敛（`/bt-jev`、`/api/intel-graph` 私有化；`/intel-dossier`、`/jev-stack` 挂载）。
4. **情报板块必须进军团/Q2 账本**：目前 6 军团没有情报，情报部 8 席不在任何 composition；建议按《整体研发方案 v2》WS-C + `intel-recon` 影子组合落编成，否则永远是“部门日报”而非“作战单元”。
