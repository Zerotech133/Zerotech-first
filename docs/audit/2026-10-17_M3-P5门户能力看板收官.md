## 二、能力看板设计

**端点**：`GET /api/capability/board`（只读、无缓存、mode=ro SQL 直连——
不经 Store 构造避免 GET 建库写副作用，沿 replay_query 判例）。

聚合四块：
1. **产物投影**：total / by_source / by_kind / superseded_count +
   最近 30 条 + supersede 链组（仅长度>1 成链，**旧→新**与
   ArtifactStore.chain 同口径）；
2. **凭据投影**：total / content_hash 绑定率 / legacy 空绑定数 /
   by_target_type / by_target_prefix / 最近 30 条；
3. **产线覆盖**：五线清单（gzh/pitch/dev/skill/intel）×（登记产物数，
   凭据数，是否覆盖）——缺位计 0 显式给行，不静默漏行；
4. **口径注释**：绑定率=非空占比，legacy 属历史存量不回填不迁移。

**凭据产线归属双口径**（实测修正）：30 条存量凭据 target_type='workitem'，
仅按 target_type 归线会把 gzh 的 24 条门凭据漏成 0——补 target_id
`'domain:ref'` 前缀兜底后 gzh=24 正确归线。判例：**覆盖统计必须
双口径并集，target_type 精确 ∪ target_id 前缀**。

实测投影（10-17 真仓）：artifacts.total=1（gzh.drafts）、
approvals.total=31（绑定率 0%——全部 M3-P3 改造前生成，legacy 固有）、
覆盖 gzh+skill 两线。

## 四、validate_json.py（tasks.json 事故判例落地）

- **定位**：把「写前必 loads」从纪律变成一行命令——写入方保存
  真源前先跑，loads 失败退出码 1，门禁/巡检可拦截；
- **JSONL 逐行**：devtask 真源主格式 `tasks_YYYYMM.jsonl`，自动按
  扩展名切换逐行校验（空行容忍，报错带行号列号）；
- **精确定位**：JSONDecodeError.pos → ±40 字符上下文窗口
  （`[HERE→]` 标记），未转义引号一眼定位；
- **退出码**：0=全 PASS / 1=有 FAIL / 2=参数缺失；
- **只读**：不修改任何文件，修复属写入方职责。

实测：真实真源 tasks_202610.jsonl 24 行 PASS；构造未转义引号坏行
精确定位「第 2 行 列 10」+上下文；exit=1/0 正确。
