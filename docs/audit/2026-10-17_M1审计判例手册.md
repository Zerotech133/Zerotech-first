# M1 审计判例手册：轮次化幂等键 · 死凭据 · 交叉校验

> 2026-10-17 收口。适用 agent_platform 全部接线域；新增域按本文一票决定机制选型。
> 基线：全仓回归 249 绿；统一投影九域（gzh/academy/invest/dev/pitch/personal/devtask/knowledge/skill）全 PASS。

## 一、轮次化幂等键：两派机制与选型一票决定

**核心判例**：打回（kickback）后的重批是新的一轮审批承诺，必须落新凭据
（键 `base#r{n+1}`），禁止重放第一轮凭据（否则 decided_by/reason 不可追溯，
审计链断裂）。

选型一票决定，只看一个问题：**打回转移是否走凭据化写路径？**

| 派别 | 适用域 | 机制 | 现行采用 |
|------|--------|------|---------|
| 消费标记派 | 打回**凭据化**的域 | 真源条目记 `last_wiring_key`（最新已消费凭据键）。重放判定：最新凭据键 == 标记 → catch-up；否则按 `own` 凭据序数生成 `#r{n+1}` | gzh / invest / devtask |
| 痕迹守卫派 | 打回**免凭据**（自由 move）的域 | 打回不落凭据但 history 留痕。catch-up 判据加守卫：`to_status` 曾落 history = 凭据曾生效，禁 catch-up | academy（history.stage）/ pitch（history.action `approve:%s`） |

**为什么 own[-1] 启发式不能通用**：`own[-1] == 本次转移` 即判 catch-up 的
前提是「同一 from→to 的旧凭据必然已被消费」。打回凭据化的域成立（每轮
转移都有凭据）；打回免凭据的域不成立（打回后 own[-1] 仍是上轮凭据，
会把重批误判为崩溃窗口吞掉）。academy 曾因此误判，加 history 守卫修复。

**新增域 checklist**：
1. 打回走 approve（凭据化）？→ 消费标记派：写路径记 `last_wiring_key`，
   approve_transition 按 own 序数生成轮次键。
2. 打回走自由 move？→ 痕迹守卫派：history 必须留痕（stage 或 action），
   catch-up 前先查痕迹。
3. 两派都做：崩溃窗口 catch-up（最新凭据在而真源未达 → 补执行 + 重放返回）。

## 二、死凭据：凭据先行必须与真源校验同构

**判例**（dev 域实证）：凡「先落凭据、后写真源」的写路径，凭据落库前的
校验集合必须与真源写路径的校验**同构**。dev `close_done` 曾不校验当前态，
blocked/open 任务的背书先落凭据、后引擎 `ts.move` 恒败 → 账本留下永不
生效的**死凭据**（审计正向查「状态无凭据」查不出来）。

规则：把真源 move 的合法性校验（状态机允许转移、当前态检查）提到凭据
record 之前，校验失败 = 零写入。

## 三、崩溃窗口模拟：原子性未达成 = status 与痕迹双缺

测试模拟「凭据已落、真源未写」时，必须同时回拨：
- 真源状态字段（status/stage）；
- 域内痕迹（history 条目）或消费标记。

只回拨状态的模拟不是真崩溃窗口——痕迹守卫派会（正确地）拒绝 catch-up，
导致测试误报。原子写语义 = 状态 + 痕迹（+ 标记）同次落盘。

## 四、交叉校验器（adapters/credential_trace.py）

审计层补强：各域 `audit_report` 除既有的「状态 vs 凭据有无」正向检查外，
接入共享交叉校验 `cross_check()`，查反向与轮次异常：

| violation | 级别 | 语义 |
|-----------|------|------|
| `credential_never_effective` | FAIL | 凭据 to_status 无任何痕迹/现状未达/键未消费，且非最新 → 死凭据 |
| `pending_execution` | WARN | 同上但是最新凭据 → 崩溃窗口候选（等 catch-up，不告急） |
| `round_exceeds_trace` | WARN | 痕迹命中的凭据张数 > 痕迹次数 → 轮次账与痕迹不一致 |
| `marker_without_credential` | FAIL | 消费标记引用的键不在账本 → 账本被清/篡改 |

接线形态：
- **trace 域**（academy/pitch/dev/skill）：全量校验，statuses 从 history
  提取（stage / action 剥前缀 / TaskStore action 即状态）；
- **latest_only 标记域**（gzh/invest/devtask）：只校验每目标最新凭据
  （旧轮次标记被覆盖不可回溯），另查标记引用完整性；
- **跳过未知目标**：凭据的 target 不在真源清单（被删/测试隔离）→ 无法
  判定，保守跳过（目标缺失由各域 credential_*_missing 检查负责）；
- **rejected 凭据**跳过（否决不承诺状态生效）。

verdict 分级：域内既有 gate 违规（无 severity 键）= FAIL；交叉校验 FAIL
即 FAIL；仅 WARN 时 verdict=WARN（门户可见但不告急）。

## 五、既有审计的轮次语义修正

pitch `audit_report` 的 status_mismatch 判定升级：凭据 to_status 与现状
不一致时，若 history 存在 `approve:<to>` 痕迹**且其后有 move 痕迹** →
合法打回，不算违规；仅状态被改而无 move 痕迹 = 绕门，仍报。
（痕迹存在但无后续 move 的状态漂移 = 绕门改状态，痕迹不能洗白。）

## 六、测试纪律（承既有判例强化）

- wiring 测试 approve/audit 必传 tmp 独立 ApprovalStore（不传落真库跨
  用例污染）；
- CLI 用例 patch 模块级 `_AGENT_PLATFORM` / `_db_path`；
- 交叉校验测试注意：真实共享账本 + tmp 真源的组合下，凭据目标不在
  tmp 真源 → cross_check 跳过（保守语义），不会误报 pending。
