## 三、新 P0：双登录

实测流程：

```text
1. 8734 /api/auth/login（portal admin）→ 200
2. 8734 /hermes/ → 200，title = "Hermes — 登录"
3. 8787/api/auth/login（Hermes 密码）→ 200
4. 8734 /hermes/ → 200，title = "邓芝 · 飞书通讯中枢"
```

也就是说：

```text
入口 8734 先登录门户
Hermes 还要再登录一次
```

影响：

```text
同一用户需要两套密码；
会话过期不同步；
对日常开发是持续摩擦；
出错时很难判断是哪一层登录失效。
```

建议：

```text
优先做 SSO：让 Hermes 信任 portal session（反向代理注入可信头/一次性 token）
或 8734 登录后由 nginx 给 Hermes 签发短期 session
短期至少在登录页明确“还需 Hermes 密码”
```

## 四、新 P0：8787 直连 A0 执行断链

C1 已给 8796 写/执行入口加鉴权：

```python
# oh_auth.py
需要有效门户 zb_session 或 X-ZB-Cap(scope=run:execute)
```

实测：

```text
POST 8796 /api/ide/openhands/start 无 cookie → 403
POST 8796 /api/ide/orchestrate 带 portal cookie → 200
```

但 A0 主聊天在 8787 直连时：

```js
base() = http://127.0.0.1:8796
```

Hermes 的密码 session **不是** `zb_session`，所以 8787 直连 A0 执行时会被 C1 403。

结论：

```text
8734 /hermes/ 路径：portal cookie 在 → A0 可执行
8787 直连路径：只有 Hermes cookie → A0 只能规划，不能执行
```

这本来是“本地直连更简单”的路径，现在反而断了。

建议二选一：

```text
1. 8787 直连强制只读，A0 显示“直连模式不可执行”
2. 8787 页面启动时通过 portal SSO 获取 zb_session/cap token
```

## 六、新 P1：密码文件 fail-open

`start_hermes_bg.py`：

```python
try:
    _pw = open(PW_FILE).read().strip()
    if _pw:
        env["HERMES_WEBUI_PASSWORD"] = _pw
except OSError:
    pass
```

含义：

```text
密码文件存在 → 启用认证
密码文件不存在/读失败 → 静默不启用认证
```

对生产而言这是 **fail-open**：vault 文件被误删/权限变化，8787 会裸奔。

建议：

```text
生产必须显式设置 HERMES_AUTH=on；
密码缺失时拒绝启动，或至少高优先级告警；
不要把“文件不存在”解释成“允许匿名”。
```
