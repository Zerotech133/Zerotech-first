## 四、真实债务（按优先级）

### P0：执行隔离不一致

- OH 走 Docker sandbox（8771）；
- LDE `/api/ide/exec` 仍是宿主 `subprocess`，白名单只防命令形状，不防权限；
- 结论：**同一个 IDE 里有两种安全等级**，不能对用户宣称“都隔离”。

### P0：旧 `/ide` 未退役

- `portal/ide.html` 2111 行仍在线，和新原生 panel 功能重叠；
- 用户可能从旧入口进入，看到两套会话/两套操作；
- 必须先列“旧页独有能力清单”，再决定迁移或跳转，不能直接删。

### P1：身份/权限没有绑定到 IDE 动作

- LDE owner 由客户端自报；任何本机客户端可冒用；
- 锁只做并发互斥，不做身份认证；
- 审计事件无 hash 链，事后追责弱。

### P1：LDE 缺少自动化 HTTP 测试

- tree/git/lock 端点目前主要靠 UI/API E2E；
- 没有进 pytest，回归靠人肉；
- 本次修 bundle 测试说明：**契约测试一漂移就会红/漏**。

### P1：8787 直连 LDE 仍不支持

- 人类主入口 8734 正常；
- 8787 验证/直连场景的 LDE cookie/CORS 未闭环；
- 属“可用性缺口”，不属核心闭环。

### P1：Agent prompt 编辑写 worktree

- “在 LDE 编辑 prompt”目前写任务 worktree；
- 没有来源/版本标识，容易误以为改的是组织主档。

### P2：前端仍是单体扩展

- `app.js` 1194 行，状态/视图/请求全在一个文件；
- 没有组件化、没有 AST/符号面板、没有 checkpoint/undo；
- 长期维护成本会继续上升。

### P2：缺 Agent 评测

- 没有“改一个 bug 的成功率/回滚率/工具错误率”；
- 无法判断优化是真提升还是感觉提升。
