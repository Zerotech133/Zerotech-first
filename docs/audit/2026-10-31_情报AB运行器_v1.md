## 1. 结论

1. 新增隔离 A/B 运行器 `agent_platform/intel_ab_harness.py`：
   - 输入 codes + 两臂目录 + flags → 生成 **off/on 两条 `run_shadow.py` 命令**；
   - **默认 `--dry-run` 只打印**计划（零执行、零目录创建）；`--run` 才执行两臂；`--compare` 可只读对比已有 ledger；
   - 两臂强制 `--rehearsal --root <隔离根>`，并**拒绝**生产 data 根 / 生产 `shadow_ledger.jsonl` 路径；
   - 读取两臂 ledger，按 `(date, symbol)` 对齐，对比 `intel_evidence.source`、recommendation/confidence/parse_ok/status 差异、fallback 率、证据来源分布；
   - **0 resolved 诚实性**：B 臂 0 条 reviewed 证据时明确报告「B 臂应全 fallback（price_proxy）」「本次 A/B 不构成改进证据」，`improvement_claims` 恒为空。
2. 运行器自身**离线**：只读写本地文件 + 只读 sqlite（`mode=ro`），无网络请求；`--run` 启动的是隔离 rehearsal 根的 run_shadow（真实链路含行情/模型，需另行授权；本单未执行）。
3. 坏 ledger（坏 JSON/缺字段/缺文件）**fail-visible**：报告 `errors[]`、退出码 2，不抛 traceback。

## 2. 用法

```text
python -m agent_platform.intel_ab_harness --codes 600519,000858 \
    --off-root C:\Temp\intel_ab_demo\off --on-root C:\Temp\intel_ab_demo\on
```

| 参数 | 说明 |
|---|---|
| `--codes` | 逗号/分号分隔 6 位代码（可带 sh/sz/bj 前缀），非法立即报错 |
| `--off-root` / `--on-root` | 两臂隔离数据根（必须绝对路径、互不相同；**拒绝生产 data 根 / 生产 ledger 路径**） |

| `--intel-db` | 只读 news.db（两臂 `INTEL_N1_DB` 与 reviewed 探测共用） |
| `--python` / `--timeout` | 子进程解释器（默认 `sys.executable`）/ 单臂超时（默认 3600s） |
| `--run` / `--compare` | 执行两臂 / 只读对比（互斥；都不给 = dry-run） |
| `--json` / `--report-out` | JSON 输出 / 报告落盘 |

## 3. 隔离与安全边界

| 守卫 | 实现 |
|---|---|
| 不写生产 ledger | 两臂强制 `--root <隔离根>`；拒绝 root == 生产 data 根（`<repo>/agent_platform/data`、`<repo>/data`）或 ledger == 生产 `shadow_ledger.jsonl`；run_shadow 自带 `--rehearsal` 拒绝真仓 data 根（第二道） |
| 不联网 | 运行器自身只读本地文件/只读 sqlite，无网络代码；dry-run/compare 完全不触网 |
| `--run` 边界 | `--run` 启动真实 `run_shadow`（行情/模型链路），仅限隔离 rehearsal 根；**生产 A/B 需另行授权**（本单未执行、未跑生产模型） |
| 长跑落盘 | 每臂 stdout/stderr 落 `<root>/ab_run_<arm>.log`（末 200KB）；报告可 `--report-out` 落盘 |
| 生产 prompt/契约 | 不改 run_shadow/intel_context/计划任务/production prompt |

## 4. 对比口径

- 对齐键：`(date, symbol)`；同键重复取首行（重复情况在 `rows` 统计中可见）。
- 每臂统计：`rows/done/failed/fallback_known/fallback_n/fallback_rate/degraded/evidence_present/evidence_rows/evidence_sources/reviewed_jev_rows/intel_fallback_rate`。
- 差异：`recommendation_changed_n`（附 off/on 值样例）、`confidence_changed_n`（含 delta）、`parse_ok_changed_n`、`status_changed_n`。
- 证据：`evidence_sources` 按 `intel_evidence.source` 计数；`pairs` 给出对齐行的 off/on source。
- reviewed 探测（只读）：`resolved_total`（`status='resolved'` 计数）+ 各 code `reviewed_news_event` 的 source/events/reason。
- **诚实性规则**（`honesty`）：
  - B 臂无 `intel_evidence` → 明确「无法比较（INTEL_TO_D1 未启用）」；
  - B 臂 `reviewed_jev_rows == 0` → `b_arm_all_fallback=true`，notes 说明「当前 reviewed JEV = N 条（0 resolved），B 臂预期全为 price_proxy/fallback；本次 A/B 不构成改进证据」；
  - B 臂有 reviewed 行 → `b_arm_all_fallback=false`，notes 只提示「按指标人工评审，运行器不做质量结论」；
  - `improvement_claims` 恒为 `[]`（运行器不自动宣称改进）。

- 探针 `resolved_total == 0`（只读 `jev_review_queue WHERE status='resolved'`）；
- 或 B 臂 `intel_evidence.source` 全为 `price_proxy` / `reviewed_jev_rows == 0`；
- 或探测不可用（DB 缺失/坏）→ 报告 `reviewed_probe.errors` + 诚实性 notes 提示「不得声称改进」。

## 6. 运行步骤（建议）

1. **先 dry-run**（本单已完成）：确认两条命令、隔离根、flags 正确，无目录/进程产生；
2. **`--run`（需授权）**：两臂隔离 rehearsal 根执行，日志落 `<root>/ab_run_<arm>.log`；生产 17:10 任务保持 flag 未设置（off）；
3. **采集**：两臂 ledger 在 `<root>/shadow/shadow_ledger.jsonl`；
4. **`--compare --json --report-out`**：对比 + 只读 reviewed 探测 + 诚实性报告；
5. **评审**：由 N1/QA1/老田按覆盖率/质量/延迟/坏行指标判定；运行器不自动下结论；
6. **回滚**：删除 `C:\Temp\...` 隔离根即可（生产零写入）；flags 默认 off，无需改码/重启。
