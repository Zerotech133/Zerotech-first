# 统一幂等语义盘点

- 日期：2026-10-17
- 范围：Paper 模拟盘、Paper Bridge、Shadow 影子执行
- 结论：当前不能直接把 `idempotency_key` 当作全局唯一键；必须保留 Paper 旧 `orders.ref` 兼容语义，并新增统一 `IdempotencyRecord`。

## 一、Paper 现状

### 事实写入口

`k_stock/paper/engine.py` 当前真正的防重判据是：

```text
orders.ref
→ ux_orders_ref
→ 全 orders 表唯一（仅 ref 非空）
```

`orders.idempotency_key` 目前只是可选 provenance 字段，没有唯一索引，也没有作为主要查重条件。

旧格式包括：

```text
{run}#{stock}
stop#{stock}#{date}
{run}@{account}#{stock}
stop@{account}#{stock}#{date}
```

必须保持兼容，不能直接把唯一索引改成只按账户唯一，否则会破坏历史订单重放语义。

### Paper Bridge 风险

`tools/paper_bridge.py` 当前流程是：

```text
检查 portal event
→ 创建 Paper order
→ 写 paper.order.planned event
```

订单创建和事件写入之间存在崩溃窗口；反向情况下，如果事件已经写入但订单不存在或状态异常，重试可能被 `_trace_done` 误判为已完成。

因此事件判重不能只检查：

```text
trace_id + kind
```

必须同时核验：

```text
order_id / ref / account_id / status / payload_hash
```

## 二、Shadow 现状

### 影子决策

`quant_backtest/ai_operator/shadow.py`：

- `decision_id` 是内容哈希；
- `idempotency_key` 是调用者重试键；
- 相同事实包和相同决策重放可复用事件；
- 不同决策可复用同一事实包；
- 同一 `idempotency_key` 搭配不同事实/决策，目前缺少明确冲突拒绝测试。

### 日级 Shadow Ledger

`agent_platform/run_shadow.py` 当前按：

```text
date + symbol + status=done
```

判定同日同票是否已完成。

语义为：

- `done`：阻止重复执行；
- `failed`：允许后续重试；
- 每票最多两次尝试；
- 当前没有数据库唯一约束、文件锁或原子 compare-and-append；
- 多进程并发可能同时通过 `already_done()`，造成重复执行；
- `date + symbol` 没有包含策略、版本、run_id，跨算法可能误去重；
- `parse_ok=false` 仍写入 `done`，会阻止后续重试，需明确产品语义。

## 三、统一 IdempotencyRecord 设计

统一记录至少包含：

```text
record_id
workspace_id
scope
account_id
operation
idempotency_key
payload_hash
attempt
status
source_system
source_ref
trace_id
artifact_ref
created_at
updated_at
result_ref
conflict_reason
```

推荐唯一维度：

```text
workspace_id
+ scope/account_id
+ operation
+ idempotency_key
+ payload_hash
```

语义：

| 情况 | 行为 |
|---|---|
| 同键同 payload | 返回首次结果，不重复副作用 |
| 同键不同 payload | 拒绝并生成冲突记录 |
| 首次失败且允许重试 | 新增 attempt，不覆盖旧记录 |
| Paper rejected/cancelled | 原 ref 保留；新重试必须产生新 attempt/ref |
| Shadow failed | 可重试 |
| Shadow done | 不重复执行 |
| 旧 Paper ref | 通过兼容映射保留，不等同统一 key |

## 四、实施顺序

1. 建立只读审计器，扫描 Paper 旧 `ref` 重复、空 ref、跨账户冲突。
2. 建立 `IdempotencyRecord` 独立账本，不修改旧订单表语义。
3. Paper Bridge 写入 record，并在 event 判重时核验订单事实。
4. Shadow 写入 record，明确 `failed → retry → done` 生命周期。
5. 增加并发 claim/文件锁或 SQLite 唯一约束。
6. 通过回放验证后，再接入统一事件查询层。

## 五、必须新增的验收用例

- 同一 Paper ref 重放只产生一个订单；
- 两账户使用相同旧 ref 的兼容行为不被迁移破坏；
- idempotency_key 相同但 payload 不同必须拒绝；
- Paper order 已写、event 未写时重试可恢复；
- event 已写、order 缺失或状态异常时不能误判 done；
- rejected 后重试产生新 attempt/ref；
- Shadow `failed → retry → done`；
- Shadow `done` 不重复；
- 两进程同日同票不会重复执行；
- `parse_ok=false` 的 done 语义经过明确产品决策；
- 跨策略/版本不发生错误去重。

## 六、当前禁止事项

- 不删除或重建旧 `ux_orders_ref`；
- 不把 `orders.idempotency_key` 宣称为全局唯一；
- 不用事件存在代替订单事实核验；
- 不把失败 attempt 覆盖成成功 attempt；
- 不把 Shadow 结论直接升级为 live 订单；
- 不在统一幂等记录完成前启用真实交易。

## 七、并发与重试补充门禁

### 1. Paper 的 check-then-act 不是稳定幂等响应

Paper 当前是：

```text
SELECT ref
→ 若不存在则 INSERT
→ 依靠 ux_orders_ref 处理竞争
```

这是非原子 check-then-act。两个并发调用使用同一 `ref` 时，唯一索引可以保证最终只落一单，但失败方当前可能直接抛 `sqlite3.IntegrityError`，不能算稳定幂等结果。

统一记录实现必须把并发验收定义为：

```text
同一 scope/account/action/key/payload
→ 一个成功创建
→ 其他调用返回既有结果或明确 skipped
→ 不把唯一约束异常暴露成未知失败
```

### 2. rejected/cancelled 的重试语义必须显式化

`settle` 在涨跌停、可卖量为 0 等条件下将订单转为 `rejected`，但历史 `ref` 仍永久占用。不能用原 ref 直接重试，否则会与旧唯一索引冲突。

在 `IdempotencyRecord` 中必须区分：

```text
completed      已有最终结果，不重试
retryable      允许新 attempt
rejected       领域结果；是否 retryable 由策略明确决定
cancelled      领域结果；是否 retryable 由调用方明确决定
```

如果允许重试，必须生成新 `attempt` 和新 `ref`，同时保留 `supersedes/source_ref` 关系，不能覆盖原订单。

### 3. Paper Bridge 双向崩溃恢复

必须分别验证：

```text
订单已写，事件未写 → 通过 ref/order_id 恢复事件
事件已写，订单缺失或状态异常 → 不得直接 skip，进入核验/repair
```

`trace_id + kind` 只能作为候选索引，不能作为完成事实。事件 payload 至少应核验：

```text
order_id / ref / account_id / status / payload_hash
```

### 4. Shadow 并发和范围隔离

Shadow 的 `date + symbol + done` 当前没有策略、版本或 run_id，跨算法可能错误去重；JSONL 检查与追加也不是原子操作。

统一记录必须覆盖：

```text
strategy_id / strategy_version / run_id / date / symbol / attempt
```

并通过唯一约束或文件锁/原子 claim 防止两个进程同时执行同一票。`parse_ok=false` 是否仍算 done 必须先做产品决策，不能默认为成功。

### 双轨纪律

```text
旧链权威不变：
  paper_bridge: events trace 查重 + orders.ref 引擎查重
  run_shadow:   shadow_ledger date+symbol+done 查重
新账本并行观察：
  IDEMPOTENCY_DB 默认 agent_platform/data/idempotency/idempotency.db
  任何账本异常降级 unavailable（fail-open），绝不阻断旧链
  IDEMPOTENCY_DISABLED=1 / smoke 冒烟强制旁路
claim 处置矩阵：
  paper_bridge: completed/conflict 跳过；claimed/in_progress 继续走引擎 ref 查重
               （订单已写/事件未写崩溃窗口由引擎 ref 幂等补齐事件）
  run_shadow:   completed/in_progress/conflict 跳过；claimed 执行；
               failed 下次死信后自动重试
```

### 死信与人工恢复

```text

     → 标 failed（error=dead-letter: stale lease）→ 自动开新 attempt

  python agent_platform/engine/idempotency.py --db <账本> fail --attempt-id <id>
巡检：stats 子命令含 dead_letters 计数；回放验证器列出超时滞留 claimed（>2h）
```
