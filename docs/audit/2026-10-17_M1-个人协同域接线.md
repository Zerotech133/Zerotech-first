## 设计裁决（承 GZH/Academy 判例，凭据不泛滥）

| 动作 | 门 | 说明 |
|---|---|---|
| pause / resume（enabled 翻转） | 无凭据 | 正常工作流，单一写路径 + 域内 history 追加 |
| **delete** | **必须 Approval** | 不可逆；幂等键 `sched:<sid>:delete`；凭据先落再改真源 |
| add | 无（本模块不做 add） | 新增低风险，旧链 8093 已覆盖 |

- **崩溃窗口 catch-up**：凭据已落而条目还在（旧链重加同 id）→ 补执行删除；条目已不在 → 账本凭据确认幂等重放。
- **无源 ID 不伪造**：sid 不存在且无凭据 → 显式报错零写入。
- **原子写**：tmp + replace 防半写（schedules.json 是 scheduler 运行真源）。
- history 字段随条目持久（legion_scheduler.load 只读 cron/enabled/weekdays_only，多余字段无害）。

## 审计局限（诚实声明）

本域**无消失前快照**：portal 旧链 delete 整条移除条目（history 随之消失），绕门删除无法从本域侧直接检出。审计语义：
- delete 凭据 + 条目在 → `pending_execution`（崩溃窗口待 catch-up）
- delete 凭据 + 条目不在 → `executed`
- 绕门痕迹需 portal 审计心跳（LEGION_SCHED heartbeat）侧对比。
