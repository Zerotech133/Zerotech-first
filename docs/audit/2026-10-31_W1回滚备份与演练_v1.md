### 3.3 耗时与窗口（实测）

```text
promote A --switch-current   : 23.9 ms
promote B --switch-current   : 26.5 ms
rollback B --switch-current  : 17.9 ms
20 次切换(min/median/max)     : 2.63 / 21.54 / 25.01 ms
并发读(普通,紧循环)           : ok=2635  fail=458  other=0
并发读(失败后 1ms 重试)       : ok=2596  fail=1    other=0   → 失败 -99.8%
current 缺失窗口(每次切换)    : 有缺口 15/15 次；median 0.749 ms / max 1.055 ms
```

- 耗时主项是 `verify_dir`（每次发布重算 4 文件 sha256，约 110KB）+ `mklink` 子进程，不是切换本身。
- **窗口来源**：`current` 必须「先改名旧、再改名新」，两次 rename 之间约 0.7–1.1ms 没有 `current` 目录；
  已实测 Windows 上无法用 `os.replace` 原子覆盖 junction（`PermissionError WinError 5`）→ 这是 OS 级固有窗口，**不是本次工具缺陷**。
- 生产影响面：Hermes `api/extensions.py::_extension_root()` 在目录缺失时返回 `None`（L231）→ 该瞬间的 `/extensions/*` 请求得到 404（`serve_extension_static` 的既有 fail-closed 行为），不会崩溃；消费方 1ms 重试即可把失败降到近 0。
- 操作建议：**只在 L2 窗口做切换**（低频），切换后立刻 `--status` + `--verify-live` + 抓一次 `/extensions/app.js` 200/bytes 验证；不要在高频 UI 使用/批量自动化期间切。

### 3.4 演练中的工具行为确认

- `--rollback-to <ver> --switch-current` = 指针 + junction 同一动作；旧版留 `current_prev_<新ver>`（同名已存在时自动加 `_2/_3` 后缀，不覆盖）。
- 任何一步失败（artifact 校验/rename/指针写）都不会留下半状态：先建临时 junction，失败则清临时并恢复旧 `current`（演练 §15-16 实证）。
- 生产 `--status` 会同时显示 `pointer_version` / `junction.target` / `drift`（本次演练用于断言生产未动）。
