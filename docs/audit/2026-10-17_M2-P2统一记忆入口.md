## 二、总纲红线代码化

> 「候选知识不能直接进入生产记忆」

```
knowledge_pending.jsonl（候选池，knowledge_distill.py 产出）
  → promote(): Approval 凭据先落（键 knowledge:<hash>:promote）
      → MemoryStore share/knowledge（enforce=False，授权由门承担）
  → reject(): decision=rejected 凭据（append-only 否决历史，不写记忆）
  → audit_report(): 生产记忆无凭据条目 = bypass → FAIL
```

## 三、设计裁决

1. **提升=跨域承诺 → 必须 Approval**（M1"凭据先落再写"同款）；崩溃窗口 catch-up：凭据在而记忆缺 → 重提补写。
2. **门即 RBAC**：MemoryStore 以 enforce=False 写入，授权由 Approval 门承担——双重授权会造成语义混乱；绕过本模块直写 share/knowledge 会被审计判 bypass（测试覆盖）。
3. **候选池 append-only**：提升/否决都不删候选行（池是原始观测）。
4. **kind 白名单**（lesson/decision/academy_research）+ 内容非空校验——池外杂音进不了生产。
5. **candidate_hash = sha256(canonical kind,dept,content)[:16]**：同候选重复提升幂等零副作用。

## 五、判例

1. **门即 RBAC**：受控写路径内部用 enforce=False 时，必须在文档声明"授权由本门承担"，且审计必须覆盖"绕过该门直写"的检测——否则 enforce=False 就是后门。
2. 模块级路径常量的测试注入：函数都收 root 参数但常量（PENDING_FILE 等）不随 root 走 → setUp 逐常量 patch + tearDown 还原；后续新模块建议路径解析统一走 `_resolve(root)` 函数（判例升级：常量即债务）。
