## 三、规则（无模型、无联网，纯字段推断）

### 3.1 打分（`score`）

| 规则 | 加分 |
|---|---|
| impact：high / medium / low | +40 / +20 / +5（缺失 0） |
| conf：<=0.4 / 0.4<conf<0.6 | +15 / +8（>=0.6 不加） |
| 近 7 天入队（recent-days） | +20 |
| 来源已知（news 表有 source） | +5 |
| 新来源（source 首次出现 <7 天） | +10 |

排序稳定：**score desc → queued_at desc → id asc**；同输入同 `--now` 两次输出逐字节一致（测试锁定）。

### 3.2 决策（`machine_decision`，检查按顺序短路）

| # | 条件 | decision | reason_code |
|---|---|---|---|
| 1 | `original_jev` 非合法 JSON 对象 | needs_evidence | `bad_original_jev` |
| 2 | impact=high | needs_evidence | `high_impact_needs_evidence`（高风险不代决） |
| 3 | conf 缺失 | needs_evidence | `conf_missing` |
| 4 | news 表无对应来源（source 缺失） | needs_evidence | `source_unknown` |
| 5 | conf <= 0.4 | reject | `low_conf_reject`（低于置信下限） |
| 6 | impact=low 且 conf>0.4 | accept | `low_impact_accept`（低风险稳定） |
| 7 | impact∈{medium,low} 且 conf>=0.6 | accept | `stable_judgement_accept` |
| 8 | 其余（0.4<conf<0.6 / impact 缺失等） | needs_evidence | `mid_conf_needs_evidence` |

> `reject` 的语义是"**建议人工驳回/改判 JEV 自动判定**"，不是自动驳回；`needs_evidence`
> 是"证据不足，请人工补证后再判"。两者都不会改库。

## 四、用法

```powershell
# 默认 dry-run（只打印摘要，不落盘）
python tools/intel_pre_review.py --dry-run
python tools/intel_pre_review.py --json                      # 完整 JSON（含 items）
# 写独立 JSONL（--write 才落盘；默认 C:\Temp\intel_pre_review_<YYYYMMDD>.jsonl）
python tools/intel_pre_review.py --write
python tools/intel_pre_review.py --write --out C:\Temp\pre_review_today.jsonl
# 上限/样本/回放
python tools/intel_pre_review.py --limit 200 --samples 10 --json
python tools/intel_pre_review.py --now 2026-10-31T12:45:00+08:00
```

- `--limit`：默认 200；**硬上限 200**（请求 >200 自动封顶并在输出标 `limit_capped=true`；<1 报错）。
- `--db`：news.db 路径（默认仓内 `news_collector/news.db`）。
- 默认 `--dry-run`；`--write` 与 `--dry-run` 互斥；`--out` 只指定路径，不隐含写。
- 退出码：0=成功；1=参数/数据错误（缺库、坏 `--now`、非法 limit、坏参数）；2=写 JSONL 失败。
- 安全：若 `--out` 指向 `news.db` 本身 → 直接拒绝（退出码 2）；连接只读 + `query_only=ON`。

## 八、残余风险与边界

- **R1 规则版非语义模型**：只依据 impact/conf/来源/时效字段，无法判断新闻内容真伪或与市场因果；`accept` 只代表"判定稳定、风险低"，**不等于内容正确**。
- **R2 决策语义易误读**：`reject` 是"建议人工驳回/改判"，不是系统驳回；`needs_evidence` 是"建议补证"。文档/面板必须保留"建议"字样。
- **R3 字段缺失即 needs_evidence**：坏 JSON、conf 缺失、来源缺失都 fail-visible 到 needs_evidence，不猜 0/不伪造。
- **R4 200/日调度未接线**：当前为手动/工具调用；如需日跑需另立计划任务单（排程 + 产物落盘 + 失败告警），并确认不抢占人工 50 档。
- **R5 产物隐私**：JSONL 含标题摘录（≤60 字符）与 id，属本地私有数据，落 `C:\Temp`，勿外发/勿进仓。
- **R6 依赖 news.db 现状**：来源/impact 依赖 news 表 join；采集链清洗或 impact 字段变更会改变分布（测试用临时 DB 锁定规则，生产分布变化不视为 bug）。
- **未验证**：日跑调度/后续下游消费未实现；决策质量（人工采纳率）需上线后由人工 50 档反馈统计，本单不含准确率承诺。
