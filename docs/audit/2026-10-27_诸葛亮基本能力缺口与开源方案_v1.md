# 诸葛亮（AI1）基本能力：缺口重收敛 + 开源社区调研 + 最优方案 v1

- 日期：2026-10-27
- 目的：回答「诸葛亮基本能力还缺什么、开源社区有什么、最优怎么加」；**本报告只调研与提方案，不改能力卡、不装新服务**。
- 方法：现状盘点（CAPABILITIES/角色总卡/近期实测）+ 开源社区检索（官方 README/对比评测/文档），所有外部项目均给出链接与许可信息，供选型复核。
- 前置口径：零执行权不变（新增能力**只读优先**，写/执行仍走 approval_gate）；「能力卡说 ready」≠运行态可用（本轮已多次实证）。

---

## 0. 一页结论

**诸葛亮当前是「有嘴、有技能卡、有诚实标签」的军师，但缺「眼、脑、手、尺、记、盾、镜」。**

现役 10 项能力（CAPABILITIES.json，2026-10-27 重生成）里，真正**运行态可验证**的是：L5 咨询（OpenClaw/DeepSeek 中转）、8796 会议厅、规则建议面（brief）、议会厅规则代行、质询离线通道、建议面投影、采纳率路由（源码已接、账本空）、载体自动切换。**缺的是：**

1. **眼（环境感知）**：无联网检索/浏览、无平台数据通用只读工具；
2. **脑（推理深度）**：无规划分解、无自我反思/一致性校验、无结构化决策记录；
3. **手（受控工具面）**：无 MCP/工具调用；所有数据接入都是硬编码；
4. **尺（评估）**：无 golden set、无回归评测、无引用核查；
5. **记（长期记忆）**：席位记忆是静态卡，无跨会话经验检索；
6. **盾（安全）**：无系统化 prompt injection 防护/输出护栏；
7. **镜（可观测）**：模型调用无 tracing、延迟/成本/失败率不透明；
8. **对抗与演练**：有 adversarial-review/pre-mortem 技能卡，但无自动红队与多视角辩论。

**最优方案（一句话）**：不重写军师本体，在其外围加一层「**诸葛亮能力底座 v1**」——MCP 只读工具层 + 轻量 RAG/证据层 + 轻量记忆 + 评估/红队/护栏/观测四件套；**先 P0（2 天）把「能查、能引、能测、能防」做出来，再 P1 做知识/记忆，最后 P2 做规划/多智能体**。不建议一上来装 RAGFlow/GraphRAG/多智能体框架。

- 无 tracing：GPT6/DeepSeek/GLM 调用链路不可观测，延迟/成本/失败率不透明。

## 2. 基本能力目标态（12 项）与缺口矩阵

> 口径：一个「合格军师」= 能感知、能查证、能推理、能对抗、能记忆、能自评、能安全交互；不要求执行权。

| # | 基本能力 | 现状态 | 缺口/优先级 | 验收判据（可测） |
|---|---|---|---|---|
| 1 | 联网检索/浏览 | ❌ 无 | **P0-高** | 给定问题可抓 3 个来源并引用 URL+日期；离线降级显式 |
| 2 | 平台数据只读工具 | 🟡 硬编码 | **P0-高** | 通过统一 tool 接口读 tasks/org/health/brief/docs，不写 |
| 3 | 知识库 RAG + 引用 | ❌ 无 | **P0/P1-高** | 回答附 `source_id`；找不到就说明，不编 |
| 4 | 证据/事实核查 | 🟡 技能卡 | **P0-高** | claim→evidence 台账；冲突/过期证据显式标注 |
| 5 | 长期记忆/经验检索 | ❌ 无 | P1-中 | 跨会话记住决策/教训并可检索；过期/冲突可纠正 |
| 6 | 规划与分解 | ❌ 无 | P1-中 | 复杂问题输出可执行步骤树；每步有验收条件 |
| 7 | 自我反思/一致性 | ❌ 无 | P1-中 | 重要结论二次自检/反例搜索；不确定度标注 |
| 8 | 红队/对抗演练 | 🟡 技能卡 | P1-中 | 定期对 L5/质询做注入/越狱/幻觉测试并出报告 |
| 9 | 输出护栏/安全 | ❌ 无 | **P0-高** | 注入/越权/敏感内容被拦截或降级，留审计 |
| 10 | 评估基准/回归 | ❌ 无 | **P0-高** | 30+ golden 用例，改 prompt/换载体可一键回归 |
| 11 | 可观测/tracing | ❌ 无 | **P0-高** | 每次调用有 trace：模型/载体/延迟/token/结果码 |
| 12 | 结构化决策记录 | 🟡 质询卡 | P1-中 | 建议/反对/采纳/回滚 schema 化，可进健康卡 |
| + | 多智能体辩论 | ❌ 规则代行 | P2-低 | 3 席辩论出结构化分歧，不执行 |
| + | 情景/兵棋推演 | ❌ 纸面 | P2-低 | 给定变量跑 3 情景，输出敏感性与触发条件 |
| + | 量化分析/图表工具 | ❌ 无 | P2-低 | 只读数据→统计/图，结论附数据来源 |

**结论**：P0 应先补 1/2/3/4/9/10/11 七项（感知+工具+引用+护栏+评估+观测）；P1 补 5/6/7/8/12；P2 再考虑多智能体/兵棋/量化工具。

## 4. 最优方案：诸葛亮「能力底座 v1」

### 4.1 设计原则（先立规矩再加能力）
1. **只读优先**：新增工具默认只读；写/执行走既有 approval_gate，能力底座不持有写权限。
2. **证据强制**：任何外部事实/数据必须带 `source_id/URL/时间`；无来源就标「未取得」，不编。
3. **可测先行**：每加一项能力，先加 golden 用例与验收判据，再上线；不做「感觉变强」。
4. **轻量嵌入式**：优先 Python 库/单进程，不引入重型平台；Windows 单机、低运维是硬约束。
5. **零执行权不变**：不做自动派单/自动改任务/自动发布；多智能体只做「建议/质询/辩论」。
6. **能力卡诚实**：能力状态必须附 `verified_at/verified_scope/证据`，静态卡不等于运行态。

### 4.2 目标架构（叠加在现平台外，不动 OpenClaw 本体）

```
        ┌──────────────────────────────┐
        │ 诸葛亮（OpenClaw agent / L5 / 8796）│
        └──────────────┬───────────────┘
                       │ 统一 tool 调用（只读）
        ┌──────────────▼───────────────┐
        │ 能力底座 v1（新，Python 进程）    │
        │ ① MCP 只读工具总线              │
        │    - 平台数据：tasks/org/health/brief/docs
        │    - 外部：fetch/搜索/浏览器（受限）
        │ ② 知识/证据层：LlamaIndex RAG + 引用
        │ ③ 记忆层：Mem0（v1 可先 SQLite/JSONL）
        │ ④ 评估/护栏/观测：promptfoo/NeMo/Langfuse
        │ ⑤ 编排：LangGraph（质询/规划工作流）
        └──────────────┬───────────────┘
                       │ 只读/审计
        ┌──────────────▼───────────────┐
        │ 现有平台：8091/8795/8796/沙盘仓 │
        └──────────────────────────────┘
```
- 与现有 8795 网关的关系：8795 继续做 **LLM 调用门面**；能力底座是 **工具/知识/评估层**，可被 8795 或独立端点调用，不重复造 LLM 网关。
- 与质询通道的关系：C1 质询卡生成改为「快照→工具查证→引用→质询卡」，输出 schema 不变。

### 4.3 分阶段路线（按价值/风险排序）

#### P0（2 天，立即可做；不依赖新 L2 任务）
| 工作包 | 具体 | 验收 |
|---|---|---|
| P0-1 MCP 只读工具 | 用 MCP Python SDK 起一个 `stdio`/本地 HTTP server：expose `tasks.read`、`org.read`、`health.read`、`brief.read`、`docs.search`（全部只读、域名/路径白名单） | `zhuge` 可调用并返回结构化数据；越权调用拒绝 |
| P0-2 联网取证 | 接 `fetch`（MCP 参考服务器/自建）+ `browser-use` 可选；强制返回 `URL+抓取时间` | 给定问题返回 3 条来源，含 URL/日期；离线时显式「未取得」 |
| P0-3 证据与引用 | 在答复 schema 加 `claims:[{text, source_ids, confidence}]`；无来源标注 | 10 条抽查：无编造来源；冲突标注 |
| P0-4 评估基线 | promptfoo：30 条 golden（L5/质询/建议面），含注入/越权/幻觉用例；CI 脚本 | 一键回归出报告；基线分数可对比 |
| P0-5 护栏 | NeMo Guardrails 前置：话题/越权/敏感输出；prompt injection 检测规则 | 注入用例被拦截或降级；误杀率 <5% |
| P0-6 观测 | Langfuse 本地 Docker（或 Phoenix）接 8795/OpenClaw 调用 | 每次调用有 trace：模型/载体/延迟/token/结果码 |

> P0 完成后：诸葛亮从「会回答」升级为「**能查、能引、能测、能防**」；仍无写权限。

#### P1（1–2 周）
- **知识 RAG**：LlamaIndex 索引 `docs/`（600+）、`deliverables/`、`.worktrees/tasks.json`、判例/经验库；检索结果强制带 `source_id`；先本地向量（FAISS/Chroma），不上 RAGFlow。
- **记忆 v1**：Mem0 自托管（或先 SQLite/JSONL 过渡）：记「决策/教训/偏好/承诺」；支持检索与过期；与 SEAT_CARD/MEMORY 单向引用，避免第二本账。
- **结构化决策记录**：建议/反对/采纳/回滚 schema；接 C3 采纳率（账本非空后）与健康卡。
- **评估扩展**：golden 50+；RAG 引用准确率、幻觉率、注入通过率进日报。
- **红队基线**：promptfoo red team / PyRIT 跑一轮 L5+质询，出报告（只读，不自动修复）。

#### P2（3–4 周，按需）
- **规划/反思**：LangGraph 工作流（pre-mortem→证据检索→反例→结论），每步可审计。
- **多智能体辩论**：LangGraph/CrewAI 3 席（军师/执行/风控）结构化辩论；只产建议，不派单。
- **情景/兵棋**：输入变量→3 情景→敏感性→触发条件；接只读数据与图表。
- **成本/延迟优化**：缓存、token 预算、模型路由（8795 已有门面），Langfuse 成本看板。
- **能力卡 v2**：12+ 项，每项 `verified_scope`，不虚报 ready。

### 4.4 选型组合（推荐「最小可行栈」）

```
MCP (只读工具) + LlamaIndex (RAG) + Mem0 (记忆, P1) 
+ promptfoo (评估/红队) + NeMo Guardrails (护栏) 
+ Langfuse (观测) + LangGraph (编排, P2)
```
**不选**：RAGFlow（等文档量/多人协作上来再评估）、GraphRAG（维护模式+索引贵）、CrewAI/AutoGen（P2 之前无必要）、Letta 整体迁移（与 OpenClaw 重复）。

### 4.5 关键接口契约（建议）
- `tool_call`：`{tool, args, read_only:true, caller, trace_id}`；返回 `{ok,data,sources[],error,elapsed_ms}`；
- `answer`：`{text, claims[], sources[], confidence, warnings[]}`；
- 评估：`eval_case{id,input,expected_behavior,checks[]}` → `pass/fail/reason`；
- 护栏：`rail{name, stage(input/output), action(block|rewrite|flag), test_cases[]}`。

## 5. 风险与边界

1. **零执行权**：工具层一律只读；MCP server 不暴露写接口；写/执行仍须老田五要素/approval_gate。
2. **Prompt injection**：联网/文档/RAG 内容均视为不可信数据；护栏必须区分「资料」与「指令」，禁止资料内指令改变系统行为。
3. **隐私与合规**：RAG 索引仅本机；外部检索不发敏感数据；API key 不落盘（沿用 OpenClaw secret store）。
4. **许可**：SearXNG AGPL、Guardrails/NeMo/PyRIT/Garak 等许可需上生产前复核；本报告仅推荐，不代为合规判断。
5. **运维**：每加一个常驻服务（Langfuse/RAGFlow）都增加 L2/资源；P0 尽量单进程/按需，避免再添 5 个常驻。
6. **评估诚实**：能力卡/报告不得把「装了框架」当「能力可用」；必须 golden 用例通过 + 运行态证据。
7. **避免框架堆叠**：一个能力层只选一个主框架；多智能体/辩论是 P2 可选项，不是基本盘。
