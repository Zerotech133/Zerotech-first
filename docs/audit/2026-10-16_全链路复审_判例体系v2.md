## 四、新发现 F1：JevBackfill 停摆 5 小时（已修复 ✅）

### 4.1 现象与定位

- 现象：`C:\jev_backfill_task.log` 15:00 P0 start 后断流；16:00 起每小时 rc=1 且**零日志**；backlog 持续积压（left=2040）至 19:29 才恢复消化
- 排除链（每步留证）：PSParser 0 错 → BOM 在（EF BB BF）→ review_data 可写 → junction 两路径同文件（len=2886）→ python 前台直跑健康（`--batch 2` judged=2/2 RC=0 9s）

### 4.2 根因（两层叠加）

1. **C:\ 根日志拒写**：15:00 起任务写 `C:\jev_backfill_task.log` 报 Access denied——ACL 允许（Authenticated Users Modify）、非 ReadOnly、Defender 无拦截、无锁进程，**根因未完全定位**（疑受控文件夹访问拦截）。拒写 → ps1 整体 rc=1 → 零日志假象
2. **计划任务幽灵 Running 态**：LastTaskResult=0x80070490（ERROR_NOT_FOUND）= 实例状态机损坏，`Start-ScheduledTask` 被幽灵实例挡住**静默不执行**

### 4.3 修复与验证

- 修复①：[jev_backfill_task.ps1](../../jev-eval/jev_backfill_task.ps1) 日志路径迁至项目内 `review_data\`（S4U 已验证可写），旧日志自动搬运保留
- 修复②：`Stop-ScheduledTask` 清幽灵态 → Start 恢复调度
- 验证：**19:29:53 轮 P0/P1/P2 三段全出、`P2 exit=0 judged=275/500 left=2152`（20:06:47）** ✅ F1 闭环（修复前 16:00-19:00 每轮 rc=1 零日志）。注：本轮 deadline_hit=1（2212.5s 撞时限收批）——判定链遇云端 api.typesafe.ai 断连走本地 fallback 拖慢，属外部依赖波动、批次容错机制正常（下一小时轮自动续判剩余 225 条），**不构成回归**

## 五、新发现 F2：8787 Hermes WebUI 死亡 + guard 触发器缺陷（已恢复 ✅）

### 5.1 时间线与死因

```text
19:26:16     HermesWebUI-Guard 末次自动执行 rc=0（此后下一触发=23:59:00）
19:26-19:49  8787 死亡（死因线索见下）
19:49        审计探针发现 DOWN
19:50:12     手动 Start-ScheduledTask 触发 guard：rc=0 但 8787 仍未起
             （guard= start_hermes_bg.py，幂等探测+DETACHED+DEVNULL 配方本身正确）
20:0x        改用 -u unbuffered + stderr 文件重定向前台诊断：
             server 起后即稳定 UP 200，stderr 捕获真实死因线索：
             「source-update completion failed: an update is still running;
               wait for it to exit, then relaunch Hermes」
```

**结论**：server 启动时撞上未完成的 source-update 状态，在 DETACHED+DEVNULL（零 stderr）模式下 relaunch 链断裂 → 静默死。guard 手动触发执行了但拉起后同因死掉。恢复后以 previous dependencies 运行，服务正常。

### 5.2 guard 触发器缺陷（结构性，未修，列遗留）

- 触发器：`start=23:59:00 rep=PT30M dur=P1D` —— **守护窗口从深夜才开始，白天（8:00-23:59）死亡即裸奔至 23:59**
- 本例 19:26 死亡 → 若非审计发现，将裸奔 4.5 小时
- 修复需 `Set-ScheduledTask`（本次同类操作遇 Access denied 需提权），列遗留清单

### 5.3 恢复配方（可复用）

`Start-Process python -u server.py` + stderr 文件重定向（-u 规避缓冲 flush 炸，重定向仅诊断用；**常驻仍用 start_hermes_bg.py 的 DETACHED+DEVNULL 配方**）。已验证 UP 200 且 >2min 稳定；guard 23:59 首轮探测到 8787 在听即 skip，无冲突。
