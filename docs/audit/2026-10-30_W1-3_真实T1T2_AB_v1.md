# W1-3 真实 T1/T2 prompt JSON-first A/B（2026-10-30）

- 工单：`WO-LEGION-W1T1-EVID-20261030`（实验单 `WO-LEGION-W1T1-20261030` 已放弃，不合并）
- 目的：用真实 `run_invest` 管线复验 JSON-first，而不是继续用代表性 prompt
- 结论：**质量改善，但延迟不过门槛；不生产化。**

## 一、实验设计

同一标的 `002712`，真实 `run_invest --live`：

- 基线：run `313b2b3ab7b3`（现有生产 prompt，2026-10-30 18:44）
- 变体：run `19a37bffc93a`（`ZHUGE_MARKET_JSON_FIRST=1`，2026-10-30 19:57）
- 开关默认关，仅 `market_technical` 节点追加“先 JSON、后 ≤200 字说明、总长 ≤350 token”覆盖指令。

## 二、结果

| 指标 | 基线 313b | 变体 19a37 | 判断 |
|---|---:|---:|---|
| 总耗时 | 299,921 ms | 433,740 ms | **+44.6%，变差** |
| T1/T2 状态 | degraded | **normal** | 改善 |
| T1/T2 JSON | `no_json_block_found` | 完整 JSON | 改善 |
| T1/T2 输出长度 | 564 / 577 字符 | 628 / 645 字符 | 更长但结构完整 |
| T1/T2 单节点耗时 | 117.3s / 117.4s | 176.1s / 176.1s | +50% |
| N1 状态 | degraded | normal | 改善 |
| D1 状态 | normal | **degraded** | **退化** |
| execution_modes | normal 2 / degraded 3 | normal 2 / debate 2 / degraded 1 | 有改善也有新问题 |

### 解释

- JSON-first 确实解决了 T1/T2 的 `done_reason=length`/`no_json_block_found`；
- 但 T1/T2 生成长度增加（JSON + 说明），在 CPU 9b 上单节点从 ~117s 涨到 ~176s；
- D1 在新输出上下文下变成 degraded，说明上游结构变化影响了决策节点；
- 单次真实运行，方差存在；但延迟方向已足够触发“不放行”。
