# OIDC 硬化上线记录（2026-10-30）

- 工单：`WO-LEGION-OIDC-HARDEN-20261030`、`WO-LEGION-OIDC-PATH-20261030`
- 状态：**shadow；`/login` 未默认切 OIDC；真实 passkey 仍暂缓**
- 依据：本轮代码审计 P2 项 + 老田指令“先修 state 绑定、MODE 关闸、registry 错误处理”

## 1. state 绑定浏览器

- `/api/auth/oidc/start` 生成随机 binding，写入 HttpOnly cookie：
  - `zb_oidc_state`，Path=`/api/auth/oidc`，SameSite=Lax，Max-Age=600；
- 进程内只存 binding 的 SHA-256；
- callback 必须带同一 cookie，否则 400 `oidc_state_binding_invalid`；
- callback 成功后同时下发 session cookie 并清除 binding cookie。

## 2. MODE 关闸

- 合法值只认 `off / shadow / on`；其他值按 `off` 处理；
- `shadow` 不暴露登录页按钮（`login_entry=shadow_only`）；
- 登录页仅在 `mode === "on"` 时显示 Pocket ID 按钮；
- runtime 文件被删除/移走时：**立即复位 MODE=off、清空 client 凭据**，不再沿用旧配置；
- 非法 mode 写入 runtime 文件也会被归一为 off。

## 3. registry 错误处理

- 登录时 registry 缺失/损坏：返回 503 `identity_registry_unavailable`，不暴露 JSON 解析异常；
- 智策登录失败统一返回 401 `invalid_credentials`；
- OIDC 回调 registry 错误返回 503，不再伪装成 403 `identity_not_mapped`；
- JWT 校验失败只返回稳定枚举 `oidc_id_token_invalid`，不回显异常类名。

## 4. 额外修复

- 登录 username 长度上限 128、password 上限 4096；
- 限流 map 有界（>5000 key 时清理过期 + 丢最旧）；
- OIDC 默认配置路径从失效的 `C:\aios\_vault` 对齐到实际 `C:\项目\_vault`；
- 回调 URI 改为 `http://127.0.0.1:8734/...`，Pocket ID client 同时保留 localhost 与 127 回调，解决 state cookie 跨 host 不发送问题。
