## 二、补判据：`e_code_importable`

### 为什么补

原预检四条判据覆盖「任务注册 / 历史结果 / 进程存活 / 数据根」，对**代码本身被改坏**全盲。而 10-18 当晚 `run_shadow.py` 恰有在途重构（超时包裹收敛到 `engine/strategy_runtime`，`from strategy_runtime import run_strategy`）。若导入链断，17:10 首跑直接 ImportError，**当日无补救窗口**（下次触发要等周二）。这类风险必须在 16:40 暴露，不能等 17:10 撞。

### 判据口径

- 三件 `run_shadow.py` / `monday_checkpoint.py` / `a0_chief.py` 做 `py_compile`；
- 仅 `run_shadow.py` 做**真导入**（已实证其顶层有 `if __name__ == "__main__"` 守卫于 `:451`，导入零副作用、不写账本、不触发 LLM）；
- 语法失败 = FAIL，导入失败 = FAIL，超时 60s = FAIL。**不降级为 WARN**——到 17:10 就是硬失败，没有「到点复查」的余地。

### 阳性对照（校验器必须自证咬合力）

| 注入 | 期望 | 实测 |
|---|---|---|
| `run_shadow.py` 写成 `import (` | FAIL | `[FAIL] e_code_importable —— run_shadow.py 语法编译失败：File "…\run_shadow.py", line 1` ✅ |
| `run_shadow.py` 写 `import nonexistent_module_xyz_2026` | FAIL | `[FAIL] e_code_importable —— run_shadow.py 顶层导入失败（17:10 首跑直接 ImportError）：Traceback…` ✅ |
| 真实仓 `--repo-root agent_platform`（相对） | PASS | `PASS 4 / WARN 1 / FAIL 0` ✅ |

### 补丁自身踩到的坑（已修）

## 三、修测试污染：`test_monday_checkpoint_timing` 的千万级假红

### 症状

批量跑 6 个门3 相关测试文件时：

```
FAILED test_monday_checkpoint_timing.py::test_main_waits_then_stops_at_ceiling
E  AssertionError: 应等满 3 轮后停止，实际 98030663 轮
E  where 98030663 = len([90, 90, 90, 0.05, 0.05, 0.05, ...])
```

`test_main_does_not_sleep_when_batch_landed_with_failure` 同批失败。表面看极像 `monday_checkpoint` 的等待循环死转 —— 若当真，明日 17:25 巡检会挂死。

### 定性：**产品无 bug，是测试间污染**

三道取证否掉了产品缺陷：

1. 干净进程探针（直接 `mc.main()`，patch 记录 sleep）只记录到 3 次 `90`，随后正常 break 并输出结论；
2. 该用例**单独跑 passed**（2.58s）；
3. `test_monday_checkpoint_timing.py` **整文件 18 项全 passed**（3.98s）。

### 根因链

```
test_run_shadow_guard.py::_DeadloopAgent.propose()
    while True: time.sleep(0.05)          ← 故意留的 daemon 僵尸线程，存活到进程退出
                    ↓ 同进程
test_monday_checkpoint_timing.py
    monkeypatch.setattr(mc.time, "sleep", lambda s: sleeps.append(s))
                    ↑ mc.time 就是全局 time 模块 → time.sleep 被全局改掉
                    ↓
僵尸线程的 sleep 变 no-op → 疯狂空转 → 向 sleeps 灌入 98,030,663 次
                    ↓
assert len(sleeps) == 3 假红；空转抢 GIL → 整个 pytest 被拖到 SIGTERM
```

`_DeadloopAgent` 的 docstring 原本论证过「用 sleep 而非纯自旋以释放 GIL」，但该论证的前提是 `time.sleep` 为真 —— 被另一文件的全局 patch 破坏。

### 修法

不动僵尸线程（它是超时语义所需），改**只替换被测模块的 time 引用**：

```python
class _SinkTime:            # 只实现 sleep（mc 内 time 的唯一用法是 :327 time.sleep）
    def __init__(self, sink): self._sink = sink
    def sleep(self, seconds): self._sink.append(seconds)

monkeypatch.setattr(mc, "time", _SinkTime(sleeps))   # 替换模块属性，真 time 不受影响
```

两处 `setattr(mc.time, "sleep", ...)` 全部替换（锚点 count=2 断言后替换，替换后断言新串存在）。

### 修复后

| 组合 | 修复前 | 修复后 |
|---|---|---|
| `guard + timing` | **SIGTERM 被杀** | 30 passed / **8.56s** |
| `test_check_trigger_chain + timing` | 6 failed / 19 passed | **43 passed** / 51.89s |
| 六文件全量（guard/schema/timing/cp_log/eval/long_cycle） | 2 failed / 59 passed / 246.95s | **61 passed / 8.20s** |
