## 一、项目定位

本项目不是单一聊天机器人，也不是单纯的股票分析脚本，而是一套独立的数字军团操作系统：

```text
组织与 HR
  → 能力、Prompt、权限和记忆
  → 数据册、接口册、路由器
  → 课题/工单/排程
  → Agent Worker 执行
  → 产出验收
  → 监督、复盘、知识反哺
```

核心目标是让新增 Agent 能够入职、归属部门、获得岗位职责和权限，并能被调度、执行、观察、复盘和持续升级。

### C. 仍存在的结构性风险

#### P0：Worker 失败状态和人工恢复机制还不完整

当前失败后会进入：

```text
execution_status = failed
status = review
```

但还没有完整的：

```text
失败分类
→ 自动重试策略
→ 人工复核
→ retry / blocked / cancelled
→ 审批后重新执行
```

#### P0：研究院课题状态与 Worker 状态尚未自动绑定

Worker 完成后不会自动推进：

```text
intake → hypothesis → evidence → validation
```

目前需要 ACAD1 或人工调用课题状态接口。

#### P1：自动验收仍是最小规则验收

目前主要检查：

- 文件存在
- 字符长度
- 标题段落
- 关键词

还没有检查：

- 事实来源是否真实存在
- 数据版本是否匹配
- 输出是否引用正确课题
- 是否存在模型幻觉
- 是否满足 Agent 专属业务验收标准

#### P1：三套组织注册仍未完全单一事实源

当前同时存在：

```text
org.json
team_*.json
hr/*
portal/agent_ide_bundle.json
claude_agents.json
```

已通过重建脚本保持大体一致，但仍然存在源数据重复和投影漂移风险。

#### P1：研究院的实际业务执行器不足

当前真正执行的是 ACAD1 intake。以下角色还未真实跑通：

- STRAT1 策略假设

8093 和 8096 本轮已验证可访问；8099 KM 服务当前未形成同等级的可访问证明。需要后续单独做服务矩阵和启动守护审计。

## 六、建议研发路线

### 阶段 0：冻结基线，不继续堆功能

先固定：

- `org.json` 为组织主事实源
- `team_*.json` 为职能岗位源
- `hr/*` 为人员档案源
- bundle 和 claude_agents 只作为构建产物
- 所有 Worker 工单必须有唯一工单号、Agent、课题、阶段、验收标准

### 阶段 1：完成 Worker 可靠性

目标：把单次成功变成可恢复系统。

- claim 原子化
- 失败分类
- retry 次数上限
- blocked 状态
- 人工重试接口
- 产出哈希
- 输出文件版本
- API/模型超时恢复
- 并发 Worker 锁

验收：连续执行 10 个模拟工单，不能重复领单、丢单或覆盖产出。

### 阶段 2：完成 LCS-1 多阶段链路

顺序：

```text
STRAT1 → DATA1 → BACK1 → ACAD1 → D1/R3 → A0
```

验收：每个阶段必须有：

- 输入
- Agent
- 产出
- 验收结果
- 阶段历史
- 下阶段触发条件

### 阶段 3：补自动事实核验

建立证据对象：

```text
事实
→ 来源
→ 时间
→ 数据版本
→ 原始位置
→ 引用关系
→ 核验结果
```

没有来源的模型陈述不得进入“事实”字段。

### 阶段 4：知识反哺闭环

```text
产出
→ 复盘
→ pending_review
→ 人工/部长审批
→ Prompt/能力册/路由更新
→ 对照评测
→ 批准入库
```

禁止模型单次输出直接修改组织规则。

### 阶段 5：大屏升级为指挥台

重点展示：

- 当前在岗 Agent
- 正在执行工单
- 最近 heartbeat
- 阶段耗时
- 阻塞原因
- 验收失败原因
- 部长点评
- A0 田丰升级事项
- 研究院课题进度
- 每个 Agent 的能力成长

### 阶段 6：受控实战到生产

准入顺序：

```text
Mock
→ Shadow
→ Human-in-the-loop
→ Controlled production
→ Limited autonomy
→ Full autonomy（暂不建议直接规划）
```

金融相关分析和交易执行必须始终保留人工审批、风控和审计边界。

## 八、总判断

当前数字军团已经不是概念原型，而是一个具备真实组织、任务和执行能力的受控平台。

但它还不是完整的自治组织。当前最重要的工作不是继续增加 Agent 数量，而是把以下闭环做牢：

```text
任务定义
→ 正确派工
→ 正确执行
→ 产出可验证
→ 状态可恢复
→ 结果可复盘
→ 知识可审批反哺
```

建议下一轮研发重点：

```text
Worker 可靠性
+ LCS-1 多阶段链路
+ 数据冻结和事实核验
```

在这三项完成前，不建议打开无人值守排程，也不建议进入完全自动化的金融决策或交易执行。
