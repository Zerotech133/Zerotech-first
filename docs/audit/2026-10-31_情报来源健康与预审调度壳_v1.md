## 一、来源健康工具（`tools/intel_source_health.py`，只读）

覆盖 12 源 = 登记表 3 源 + news_collector 9 源：

| 类 | source_id | 数据来源 | 口径 |
|---|---|---|---|
| 登记表 | `guba`（股吧，sampling 启用） | `agent_platform/data/intel/sources.json` + sample_path stat | 文件数/0 字节数/最新非空 mtime |
| 登记表 | `osint_video`（视频，sampling 未启用） | 同上 | 只读样本目录；空/缺显式 error |
| 登记表 | `tdx_market`（通达信行情，registered 未启用） | 同上（sqlite 文件仅 stat，不打开库） | 单文件大小/mtime |
| news | sina / eastmoney / wallstreetcn / announcement / survey / report / world / govpolicy / chinanews | `AIOS_ROOT/news_collector/status.json`（默认 `C:\aios`） | 每源 ok/got/new + 整体采集时龄 |

每源统一字段：`enabled / mode / last_ok / age_s / file_count / 0byte_count /
sample_ok / error`（另有 category/kind/status/sample_path/stale_after_s/last_got/last_new）。
news 源无落盘样本口径的 `file_count/0byte_count/sample_ok` 显式 **null**（如实标注，不伪造）。

### 1.1 status / 阈值语义

- `status`：`ok / stale / missing / empty / error / disabled`；
- news 源：status 整体采集时龄 > `--stale-hours`（默认 **2h**）→ 全部标记 stale；
  任一源 `ok=false` → 该源 error；status 缺失/坏 JSON → 全部 error 并给输入级 error；
- 登记表源：`--sample-stale-hours`（默认 **30h**，日更采集口径）判 stale；
  路径不存在→`missing`；无文件→`empty`；全部 0 字节→`empty`+`sample_all_zero_bytes`；
  `enabled=false` 的源状态记 `disabled`，但仍保留真实样本状态与 error（fail-visible）；
- 汇总 `ok` = registry/status 可读 + 无启用源的硬故障/stale；`enabled_bad` 计数启用坏源。

### 1.2 CLI 与退出码

```text
python tools/intel_source_health.py                # 文本摘要
python tools/intel_source_health.py --json         # JSON 契约 intel_source_health/v1
python tools/intel_source_health.py --strict       # 启用源不健康 → exit 1
可选：--registry PATH --status PATH --now ISO8601
      --stale-hours N（news，默认 2）  --sample-stale-hours N（登记源，默认 30）
```

| 退出码 | 含义 |
|---|---|
| 0 | 健康（非 strict 下 stale 只报不拦） |
| 1 | 输入错误（registry/status 缺文件/坏 JSON）或启用源缺样本/空样本/扫描错误（硬故障，**始终** fail-visible）；`--strict` 下 stale/任意启用源不健康也返回 1 |
| 2 | 参数错误（argparse） |

### 1.3 只读边界

不联网、不写库、不写文件；不打开 `news.db`/`tdx_info.db`（仅 stat mtime/大小）；
纯 stdlib + 复用 `tools/intel_sources.py` 的登记表契约/`path_stats`（同一口径）。
测试含静态 AST 断言（无网络/DB/写盘依赖）与运行前后 tmp 文件树零变化断言。

## 三、机器预审调度壳（`ops/run_intel_pre_review.ps1`）

包装既有只读工具 `python tools/intel_pre_review.py`（该工具不写 news.db，只输出独立
决策建议 JSONL），补齐**幂等调度外壳**，但**不安装任何计划任务**。

### 3.1 行为

- **默认 DryRun**：只跑预审预览，不写产物；显式 `-Write` 才落盘；
- 产物：`<OutDir>\intel_pre_review_<yyyyMMdd>.jsonl`，写前先落 staging `.tmp`，
  成功后 `Move-Item` 原子改名；同日重跑覆盖当日产物（幂等）；
- 旧产物保留/翻转：同名旧产物先移入 `<OutDir>\archive\...prev-<HHmmss>`；
  超过 `-KeepDays`（默认 14）的历史产物也移入 archive（**不删除**：仓库红线要求
  Windows 删除走回收站，脚本不删任何文件，人工可按需回收）；
- 日志：`<LogDir>\run_<yyyyMMdd>.log`，工具输出落盘但截断（`... N lines truncated`），
  防大 JSON 把日志撑爆；
- 并发保护：本地 Mutex，已有实例运行时第二次直接日志跳过并 exit 0（幂等）；
- 可选 `-DbPath` 覆盖 news.db（worktree 无运行库时用 `-DbPath C:\aios\news_collector\news.db`）；
  其它参数：`-Limit`（1..200）、`-KeepDays`、`-OutDir`、`-LogDir`、`-Python`；
- 纯 ASCII + CRLF（PS 5.1 无 BOM 场景安全）；退出码 0 成功、2 配置错误、
  3 产物校验失败、其余透传工具码。

### 3.2 实测（worktree，只读 DB + 产物落 C:\Temp）

| 步骤 | 结果 |
|---|---|
| `-Write`（run1） | rc=0；产物 111,179B / **200 行**；日志落盘（截断 3029 行） |
| `-Write`（run2） | rc=0；旧产物归档到 `archive\...prev-132922`，新产物写入 |
| 默认（DryRun） | rc=0；`dry-run complete; no artifact written`，产物未变 |
| `-Limit 0` | rc=2（配置错误，未调用工具） |
| PowerShell 语法解析 | OK（`[scriptblock]::Create` 解析通过） |

### 3.3 调度注册 = L2，本单不做

**本脚本不注册计划任务、不写系统配置/注册表/服务。** 要让它按日自动跑，
必须经老田 **L2 明确批准**（五要素：命令全文/影响面/不可逆点/替代方案/回滚预案），
并由批准人额外提供任务定义；建议（未注册，示例）：

```powershell
# 示例：每日 07:40 预审（仅示例，本单未执行；注册需老田批 L2）
# schtasks /Create /TN "IntelPreReview" /SC DAILY /ST 07:40 ^
#   /TR "powershell -NoProfile -ExecutionPolicy Bypass -File C:\aios\ops\run_intel_pre_review.ps1 -Write"
```

启用前建议先手动 `-Write` 观察 3–7 天产物/日志，再提交 L2 注册申请；
机器预审只是建议，人工 50 档裁决仍走 `POST /api/jev/review/resolve`（唯一写入口），
本壳不改变该边界。
