## 三、新 P0：生产资产与本地资产不一致

### 3.1 实测差异

```text
app.js   本地 68,085 B   → 8787 实际服务 63,426 B
app.css  本地 14,696 B   → 8787 实际服务 14,099 B
a0-mainchat.js 本地/服务端均 11,574 B（控制面板已在线）
```

服务端响应头：

```text
Cache-Control: no-store
Server: HermesWebUI/baseline-with-custom-20261030-dirty-fb282a7e
```

说明不是浏览器缓存，是 **8787 进程加载的扩展快照比工作树旧**。

### 3.2 影响

```text
E2E 测的是本地 a0-mainchat.js（通过）
生产加载的是旧 app.js/app.css（未验证）
→ 本地绿灯 ≠ 生产生效
```

更隐蔽的是：

- 8787 当前进程不会再热读工作树（至少 app.js/css 是启动时快照）；
- **下次重启**会一次性加载当前工作树，包括未提交的 `app.css` 修改；
- 这就是“重启即发布，且发布内容不可 pin”。

### 3.3 与上一轮判断的修正

上一轮赵云审查说“编辑即 deploy”。实测更准确：

```text
当前：生产加载旧快照（已漂移）
重启：工作树当前内容一次性生效（未提交也生效）
本质：没有 release gate，发布边界是“进程重启”
```

结论不变，但风险点从“实时热更”修正为 **不可控的重启发布**。

## 四、新 P0：测试红灯被 fast gate 漏掉

执行：

```text

```

失败：

```text
test_legion_ide_session.py::test_session_survives_restart
AssertionError: ['LOCAL_DEVELOPER'] != []
```

原因：角色门补了本地默认角色 `LOCAL_DEVELOPER`，测试仍断言旧空 roles。

问题不是这一条断言，而是：

```text
fast gate 的 ide suite 只跑 test_legion_ide_http.py（4 条）
orchestrator / session / undo / E2E 都不在门里
```

所以：

```text
主区可以带着 1 条 IDE 测试红灯合并；
E2E 通过也不代表生产资产正确。
```

已有 `WO-BASE-GREEN-20261030`（doing）在修这个漂移，但尚未收口。

```js
window.open("http://127.0.0.1:8103/rw", "_blank");
```

```text
http://127.0.0.1:8103/rw  → 200（直接可开）
```

### P0-3 D1 的 EvidenceBundle 仍是“摘要自证”

`evidence_bundle.py` 的 refs：

```text
uri = make_context://<symbol>/<segment>
hash = sha256(segment text)
```

它证明“有摘要段”，但不证明“原始 K 线/事件/L4 可核验”。  
`is_sufficient()` 只看 `market_technical + fundamental + >=3 refs`。

所以“无 EvidenceBundle 不许调 D1”实现了，但 **D1 的独立核验能力仍未实现**；这和诸葛亮 review 的判断一致。


```text

```
