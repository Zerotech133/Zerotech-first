## 二、接线语义（六条铁律）

1. **状态真源不动**：`gzh/drafts/index.json` 仍是 draft/reviewed/published 唯一真源；接线层不建第二账本。
2. **无 Approval 不转移**：index 的 status 受控转移只有 `approve_transition()` 一条写路径，且先落凭据后改真源。
3. **禁止跳级**：draft→published 直接拒绝（生成/审查/批准/发布分离）；reviewed→draft 打回合法；published 终态冻结。
4. **幂等**：审批键 `gzh:<draft_id>:<from>→<to>` 确定性生成；重复批准返回既有凭据（replayed=True）；崩溃窗口（凭据已落、真源未写）自动 catch-up 补齐。
5. **无源 ID 不伪造**：workitem_id=`gzh:<draft_id>` 从真源派生；md 缺失标 missing、指纹留空，绝不伪造 hash。
6. **越门可审计**：`report` 回放审批账本比对真源状态；绕过审批门手工改 index → violations 显式列出（verdict=FAIL）。

## 四、判例沉淀

1. **裸 BEGIN IMMEDIATE 纪律**：多连接写 SQLite 必须用 M0 idempotency 同款"裸 BEGIN IMMEDIATE + 显式 commit/rollback"；`with conn:` 包 BEGIN 的写法在 Windows 多连接下出 WAL 异常。
2. **WAL shm 重开竞争**：Windows + SQLite 3.49.1，WAL 库全部连接关闭后 -shm 被删，多连接同时重开重建 shm 有竞争 → 假性 `SQLITE_READONLY`。并发场景必须保持至少一个常驻连接（keeper）；单连接串行 CLI 不受影响。
3. **幂等快路径先行**：重放判定要先于合法性检查（否则同状态二次批准被误判"非法转移"）；catch-up 保证"恰好在源上生效一次"。
4. **append-only 排序**：账本回放 ORDER BY created_at,rowid（同秒记录保发生序，勿按随机 UUID 排）。
5. **importlib 加载 dataclass 模块**：须先 `sys.modules[name]=module` 再 exec_module（字符串注解解析需要模块可寻址）。
