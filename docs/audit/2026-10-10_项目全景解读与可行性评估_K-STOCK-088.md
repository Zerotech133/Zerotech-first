## 五、开源情报 → 量化交易全过程解读

完整链条是：

```
七源抓取(15min) → news.db(2.9万条) → JEV 情绪研判(云+本地回落)
   ├→ N1 情报分析师（影子岗，每日 17:10）
   └→ 知识图谱 kg_*.py 20+ 脚本 → Neo4j（股东数/筹码/共振）
TDX 本地日线(3GB) + 特征湖 parquet(5597 只) + 基本面表
   → 六策略扫描(青萍之末/缠论/量子双刀/RPS/九维/共振)
   → build_todays_picks 聚合 → build_pick_verdicts 裁决复盘
   → RiskGuard 四规则风控(影子) → S3 裁决(10-14)
   → 影子五票账本(5 日) → eval_shadow 三判据 → 10-15 解禁/合流
   → 模拟仓 paper(909 行引擎) → (未来)实盘
```

这条链**每一环都有当日活跃证据**，是本项目最值钱的资产：它不是 PPT 架构，是一条正在流数的管道。

## 六、完整评估：可行性与落地性

### 6.1 总评

| 维度 | 评分(10) | 一句话 |
|---|---|---|
| 技术可行性 | **8** | 全链当日活跃实跑，管道是真的 |
| 数据基础 | **7.5** | 3GB TDX+5597 parquet+2.9 万新闻，双轨不同步扣分 |
| 工程质量 | **5.5** | 23,398 行单文件+跨仓耦合+回测未类化，是最大负债 |
| 组织/AI OS 成熟度 | **6** | 骨架好，但 A0 业务流空转、automation 有漏跑前科 |
| 商业化落地性 | **4** | 算法市场刚上架，商品背后无实盘业绩背书、无付费通道、无 SLA |
| 风险控制 | **6** | RiskGuard 四规则真在跑，但拦截/放行定案悬在 10-14 |

**结论：作为"个人 OS + 影子投研"，可行且已大半落地；作为对外商业化产品，当前不可卖——差的不是功能，是业绩背书、稳定性和责任边界。**

### 6.2 缺陷清单与整改（P0→P2）

**P0-1 portal_api.py 23,398 行巨型单文件** ⚠️
- 风险：任何改动都是高风险合并点（今夜 /algo 就是在 2.3 万行文件里动刀），无路由框架、无测试隔离，一次语法错误=全站 111 条路由全挂。
- 整改：P4 拆分施工图已在册（10-17，按域拆 Mixin）——**维持计划不动**，但加一条铁律：拆分完成前，新页面一律独立小模块挂载（/algo 模式），不再往主文件加千行级 handler。

**P0-2 JEV 云路长降级 + 采集无告警** ⚠️
- 风险：情绪研判事实上全靠本地 9b；新闻抓取 5 源同挂静默 0 条，N1 的输入质量无人兜底。
- 整改：① 给 7890 出口加健康探针（每轮采集前 1.5s 探活，连挂 3 轮→飞书 P1 告警，复用 send_feishu.py）；② 采集轮 0 新增时写一行降级标记进日报，别让"静默"进判据。

**P0-3 关键裁决全部悬在 10-13~15 窗，而 automation 有漏跑前科** ⚠️
- 风险：影子 5 日判据、S3 裁决、conf_calibration 桶样本全靠定时任务攒数；09:10 cowbridge 已有漏跑实锤，漏一天=判据窗作废重来。
- 整改：给 17:10 影子/09:10 cowbridge 各加「产物时间戳晨检」——晨检 automation 已有（07:50 N1 核对），把"昨日产物 mtime 断言"加进 morning_check.py 的核对清单，漏跑当日即可补，不等到验收日才发现。

**P1-1 A0 组织层空转**：有架构无业务流（memory 零写入、tasks 空、点评待拍板）。整改：10-16 批 C 前，先给 A0 派 1 个真实每日任务（如"影子日报点评"转正为必做而非试点），让组织层有第一滴血流。

**P1-2 数据双轨不同步 + 路径漂移**：parquet(10-09) vs tdx_info.db(10-10)；qd_scan_cache/rps_latest 实际位置与文档口径不符，硬编码相对路径会静默降级空数据。整改：data_health 页加"各数据源 mtime 仪表"，任一源滞后>26h 标黄；硬编码路径收敛到一处常量。

**P1-3 回测无统一引擎**：BacktestEngine/T0Engine 仅存在于叙事。整改：不急于类化重构，但把"回测口径"（费率/滑点/成交假设）抽成共享常量模块，防止六个脚本各说各话。

**P2-1 顶层整洁度**：agent_portal/ 空目录、AI/111111、根目录散落 manifest/恢复报告。整改：下次快照前归档进 projects-archive。
**P2-2 游资席位画像停在 9-30 快照**：要么接成日更管线，要么在市场页明确标注"静态研究件"，别让它冒充活能力。
**P2-3 商业化层错配**：/algo 六款商品的"已解锁"目前只解锁"实时入口"叙事，后端无计量/无付费/无用户体系。整改：解禁（10-15）前不上对外链接；对内保持卡密模式即可。

### 6.3 判决

- **可行性：成立。** 这套系统的每一层都有实跑证据，且三日 451 销案、V6-5 转正、影子账本攒满等硬里程碑是按判据推进的，不是拍脑袋。
- **落地性：对内已落地，对外差三件事**——①影子解禁+S3 裁决给风控定案（10-14/15）；②连续 20+ 交易日的影子→模拟仓正收益账本给商品背书；③稳定性整改（P0-1~3）把"演示级"抬到"服务级"。
- **最大单点缺陷：工程质量（portal 巨石文件）**。它是唯一一个"越晚修越贵"的项，P4 拆分（10-17）是全项目当前最重要的还债动作。
