# Hermes 自动执行动线联动研究报告

> 2026-10-18 · 撰写：许清楚（产品经理）· 输入：侦察员七断点证据链（已核实）
> 触发：老田原话——「既然有 Hermes，它就应该是自动去执行，我们人为的只是去看它有没有执行，然后去复盘它的执行有没有问题。它的整个动线没有联动起来。」
> 性质：产品研究报告（非开工指令）。分期路线供老田拍板后转施工单。

---

## §1 愿景与差距总览

**一句话愿景**：系统自动执行 → 人只做两件事——①确认执行是否发生（看一眼）②复盘执行是否有问题（判一下）。其余全部由动线自动完成：触发、出件、上报、聚合、开单、推送、归档、回流。

### 成熟度五维评分（侦察员实测）

| 维度 | 现状分 | 断点证据 |
|---|---|---|
| 定时触发 | 85% | ~100 个计划任务稳定在跑；四点影子链/晨检/推送哨兵齐备 |
| 失败自愈 | 35% | watchdog 只拉活进程；提权须人工 UAC（今晨 8787 案例）；自愈失败静默（AgentWatchdog 拉活失败只写日志、Nginx rc=1 挂两天无告警、回测 0x800710E0 无处置） |
| 观察聚合 | 55% | health_latest.json 无调度者停在 10-16；console 看不到「今天 17:10 AgentShadowDaily 跑没跑」 |
| 复盘闭环 | 45% | eval/perf/checkpoint 全是文件，J1/J2/J3 结论止于人看，不回流不开单 |
| 操作闭环 | 30% | console 可操作面窄：影子链四任务/monday_checkpoint/eval 均不可从总控重跑；无统一事件流，每加产线手工接一根转调线（现 5 根） |
| **综合达成度** | **约 40%** | — |

### 定性判断

**不是再造一套系统，而是在既有 ~100 计划任务底盘上补一层「联动层」。** 底盘（触发、执行、守护、门户）已 85 分位成熟，缺的是三样东西：执行情况的**投影**（R1/R2）、失败后的**必响**（R3）、产物与操作面的**回流与扩容**（R4/R5），远期再补**统一事件流**（R6）。联动层全部是只读投影 + 白名单转调，零接管主控，符合 K-ORG-112 三总原则。

## §2 目标动线（T0 时刻后的理想态）

```mermaid
sequenceDiagram
    participant S as 计划任务(Scheduler)
    participant E as 执行面(产线脚本/daemon)
    participant B as 执行健康总线(R1,8091)
    participant H as Hermes总控(8787)
    participant F as 飞书(移动面)
    participant P as 人(老田)

    S->>E: 定时触发(17:10 AgentShadowDaily等)
    E->>E: 执行+出件(账本/eval/checkpoint/日报)
    E->>B: ①LastRun/LastTaskResult/日志心跳 上报(只读投影)
    E->>B: ②非0结果→事件单(自动开单)
    B->>H: console「任务执行」卡全量投影
    B->>F: 非P0不推; P0/开单→飞书卡
    P->>H: 动作①看一眼: 任务执行卡(全绿?)+告警指挥台(空?)
    P->>H: 动作②判一下: 观察季卡复盘简报+Shadow卡结论
    alt 异常需处置
        P->>H: 一键重跑(R4白名单)/ack告警
        H->>E: POST /api/flow/rerun(幂等阀)
    end
    E->>B: ③复盘产物自动归档
    B->>H: 复盘简报回流(R5)+P1问题自动开单
```

**人的两个动作落点（明确到卡片）**：

| 人的动作 | 界面 | 卡片 | 判据 |
|---|---|---|---|
| ① 确认执行是否发生 | 8787 console | 新「任务执行」卡（R1） | 期望任务全绿、无陈旧格 |
| ①（异常兜底） | 飞书 | 告警卡 | 只推 P0/开单事件，不推日常心跳 |
| ② 复盘执行是否有问题 | 8787 console | 观察季卡（R5 简报）+ 断点登记卡 | 简报自动生成，P1 已自动开单 |

## §3 需求清单（P0/P1/P2）

> 每条标注：依托现状 / 新建 / 验收判据 / 量级。

### R1 任务执行投影 · P0
- **依托**：Windows 计划任务自带 LastRunTime/LastTaskResult；8091 已有 observe 端点与 flow 白名单。
- **新建**：8091 侧「执行健康总线」采集器——轮询全部产线任务的 LastRun/LastTaskResult/日志文件 mtime，聚合为**只读端点** `GET /api/execution/health`；8787 console 加一张「任务执行」卡全量展示（绿=按时跑+结果 0，红=非 0 或超期未跑）。
- **验收**：① 故意停掉任一白名单任务，卡片 10 分钟内变红；② 「今天 17:10 AgentShadowDaily 跑没跑」在卡片上一眼可见；③ 端点只读，无任何写路径。
- **量级**：1-2 天。

### R2 陈旧数据治理 · P0
- **依托**：ops/health_latest.json 停在 10-16、无调度者。
- **新建**：判定废弃，console 健康快照卡改读 R1 端点；旧文件打弃用标记防误读。
- **验收**：console 无任何卡引用 health_latest.json；全仓 grep 无活跃消费方。
- **量级**：0.5 天（与 R1 合并交付）。

### R3 失败必响 · P0
- **依托**：8091 告警链 + 飞书卡 + N1Check 推送先例。
- **新建**：计划任务结果非 0 → 自动开单 + 飞书推送，覆盖现存哑火三类：AgentWatchdog 拉活失败（现只写日志）、Nginx rc=1 静默、回测 0x800710E0。**「自愈失败」本身升级为 P0 事件**（watchdog 拉活≠修复，拉不动必须人知道）。
- **验收**：① 手工注入三个哑火场景各一次，均 ≤10 分钟收到飞书+出现 OPEN 单；② fail-visible：告警链自身挂了，N1 晨检能探出并推送。
- **量级**：2-3 天。

### R4 总控操作面扩容 · P1
- **依托**：8091 POST /api/flow/rerun 现有 17 任务白名单 + legion.py 转调配方。
- **新建**：影子链四任务（AgentShadowDaily/MondayCheckpoint/ChiefPush/ShadowEvalWeekly）+ eval 接入 rerun 白名单。**安全阀**：重跑必须过幂等冲突检查（当日已有产出则拒绝并提示）；monday_checkpoint 保持只读（复盘档不可被总控重写），仅 eval/shadow_daily 可放开。
- **验收**：① 白名单外任务 rerun 返回 403；② 对已出件任务重跑被幂等阀拦截并明确报因；③ 全部重跑带 caller=hermes-* 归因入 observe 账本。
- **量级**：1 天。

### R5 复盘回流 · P1
- **依托**：eval/perf/checkpoint 产物 + console 观察季卡（observe 连接器已建）。
- **新建**：eval/checkpoint 跑完后自动生成「复盘简报」（结论 + J1/J2/J3 摘要 + 异常项）写入 console 观察季卡；简报中 P1 级问题自动开单（走 8093 devtask，legion 配方）。
- **验收**：① 影子链跑完 30 分钟内简报出现在卡片；② 简报含 P1 项时对应工单号可见；③ 简报只追加不覆盖，历史可回看。
- **量级**：2 天。

### R6 事件总线（远期） · P2
- **依托**：8097/8091 已具备 hub 雏形；message_hub 现仅存在于 K-ORG-112 计划文档（批四待办）；Hermes crons 子系统能力完备但零使用。
- **新建**：以 8097/8091 为事件 hub，产线任务统一上报事件，取代逐根手工转调线（现 5 根，每加一条产线手工接一根）。**注意边界**：调度本体仍绝不进 Hermes（K-ORG-112 §3 第 3 条），事件总线只做「上报与分发」，不做定时。message_hub 按 K-ORG-112 批四路线另单落地。
- **验收**：新增一条产线接联动层改动 ≤1 处配置（现状：转调线+白名单+卡片三处）；事件白名单校验同 Paperclip v1 口径。
- **量级**：5-8 天（含 message_hub 骨干）。

### R7 提权类自愈 · P2
- **依托**：今晨 8787 提权重启须管理员跑 restart_hermes_8787.ps1 的实例；Guard 三件已是 S4U+LeastPrivilege。
- **新建**：① 盘点全部需 UAC 的操作清单（重启 8787、杀 Services 会话进程等）；② 设计一次性放行方案：以高权限计划任务（SYSTEM/管理员组，S4U）承载提权重启动作，普通进程只「转调」该任务，不自行提权。
- **验收**：① 清单归档到 runbook；② 模拟 8787 挂死，非提权守护能转调高权限任务完成拉活，全程无人工 UAC 弹窗；③ 高权限任务动作范围白名单化，不提供任意命令执行。
- **量级**：2-3 天。

## §4 分期路线

| 期 | 内容 | 时窗 | 解决什么 | 做完后成熟度预期 |
|---|---|---|---|---|
| **第一期** | R1+R2+R3 | **本周可做** | 「跑没跑看不见、坏了不知道」 | 定时触发 85→90 / 观察聚合 55→85 / 失败自愈 35→60 / 综合 40→约 62 |
| **第二期** | R4+R5 | **观察季 2 周内**（影子链首跑 10-19 后两周数据回看时正好用上） | 「看见了但管不着、复盘止于人看」 | 操作闭环 30→70 / 复盘闭环 45→75 / 综合 →约 78 |
| **第三期** | R6+R7 | **M6 之后**（不与观察季抢施工面） | 「加产线要手工接线、提权靠人」 | 失败自愈 60→80 / 综合 →约 88 |

**分期判据**：第一、二期全部只读投影+白名单转调，零主控改动，可立即施工；第三期涉及事件流改造与高权限任务，须观察季稳定（Gate 0 精神：影子链连续 2 周无 P0）后再启动。

## §5 风险与红线

**沿用既有判例**：
1. **不接管任务主控**：Legion 唯一编排中枢，联动层只投影+转调。
2. **写侧单源**：R5 简报只追加投影，不产生第二本账；console 动作与飞书卡同源同落点（K-ORG-112 §3 第 2 条）。
3. **白名单校验**：R4 rerun 扩容沿用 17 任务白名单同口径；R7 高权限任务动作范围白名单化。
4. **fail-visible**：告警链自身失联必须可被 N1 晨检探出（R3 验收②）；连接器断连明确报「底座不可达」（legion 配方 ③）。
5. **演示不落真仓**：影子链/回测相关一律演示隔离安全阀（M5 刀 2 判例）。
6. **撞车纪律**：施工前对照并行会话施工面，R1/R2 涉及 console 卡改动须与 observe 连接器（8787 侧待提权重启）协调合并。

**新增风险**：
| 风险 | 等级 | 处置 |
|---|---|---|
| 联动层自身成为新单点（总线挂了→全盲） | P0 | 总线只读+无状态，console 卡对总线断连显式红条（fail-visible）；总线挂≠执行面挂（K-ORG-112 门面原则反向适用） |
| R3 必响误报刷屏 → 人麻木漏真警 | P1 | 告警分级（P0 推飞书，P1/P2 只进 console OPEN 队列）；ack/ignore 同源落点去重 |
| R4 重跑与幂等冲突（重跑覆盖当日产出） | P0 | 幂等阀前置拦截，拒绝时明确报因（验收①） |
| R7 高权限任务被滥用 | P0 | 动作白名单+caller 归因入账本+每次动作飞书留痕 |

## §6 与既有规划的关系

- **K-ORG-112（Hermes 总控与双表面边界）**：本报告全部需求循其三总原则与 legion.py 转调配方；R6 即批四 message_hub 骨干的执行细化；R2 是对「健康快照卡」数据源的一次收口，不违背双表面同源。
- **M6 外部触发观察线**：R4/R5 恰为影子链观察季提供「执行可见 + 复盘可见」的观测条件，第一、二期是 M6 的前置保障而非抢跑；R6/R7 严格排在 M6 之后（Gate 0 精神）。
- **Paperclip 提纲 Gate 0 / 四不红线**：联动层不触碰四不红线——不接管主控（红线 1）、不产生第二任务真相（红线 2，R5 简报打「投影」水印字段口径与 R5 判例一致）、事件白名单同 v1 口径（R4 判例）、时序上不与 M5 未稳期抢跑（§4 分期判据）。
