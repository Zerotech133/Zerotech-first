## 1. 结论

1. 新增 feature flag **`INTEL_TO_D1`（默认 off）**：off 时 `build_ledger_row` 不新增任何键、不读 news.db、不导入 `intel_context` → **账本行与旧版逐字一致**（黄金 dict + 四态 env 测试锁定，且 off 无额外打印）。
2. on 时 done 行新增独立字段 **`intel_evidence`**：
   - `source` = `reviewed_jev` | `price_proxy`；
   - `event_refs`（event id 列表）/ `review_refs`（review id 列表）/ `bad_rows`（坏行 id+error）；
   - 附 `reason`（fallback 原因）/ `counts` / `errors`（读取异常可见）。
3. **不改模型 `l1_basis` 文本、不把证据塞进裁决字段、不伪造证据**：`dec`（含 `l1_basis`/`rationale`）原样不传改；`intel_evidence` 只是记录层旁路字段；无 reviewed 时显式 `source=price_proxy` + `reason=no_reviewed_jev`。
4. 只读 `news.db`（SQLite `mode=ro`，复用 `intel_context`）；坏行 fail-visible（`bad_rows` + 一行 warn）**不阻塞裁决/落账**；证据读取异常降级为 `price_proxy` + `reason=intel_error` + `errors`，行照常构造。
5. A/B 以「同批标的、同日、off/on 两臂」运行；默认计划任务保持 off；指标达标后再决定是否默认开。

## 2. Flag 语义

| `INTEL_TO_D1` | 行为 |
|---|---|
| 未设置 / `0` / `false` / `off` / `no` | **默认**。`build_ledger_row` 输出与旧版逐字一致（无新键、无 news.db 读取、无打印） |
| `1` / `true` / `yes` / `on` / `y` | A/B 观察臂：done 行增加 `intel_evidence`（只读 news.db；失败降级可见） |

- flag 只影响 **ledger 决策记录**的附加字段；D1 模型输出、`policy_checks`、`evidence_refs`、`l1_basis`、`recommendation/confidence/score`、`degraded` 等字段全部不变。
- 失败行（`status=failed`）构造路径不变、不附加证据（无决策可挂）。

### 3.2 诚实性边界

- `l1_basis`/`rationale` 是**模型输出**，本单不改写、不注入证据；`intel_evidence` 是**记录层**旁路，供复盘/评测/A-B 归因，不参与 D1 prompt 或规则裁决。
- 无 reviewed 证据时字段显式 `source=price_proxy` + `reason`（不写“已核验/reviewed 支撑”），fallback 不伪造 `event_refs`/`review_refs`。
- 坏行：`bad_rows=[{"id","error"}]` 保留在行内，同时打印 `[warn] INTEL_TO_D1 坏行 N 条…`（fail-visible），裁决与落账继续。

### 3.3 兼容性

- ledger schema 为 `m5.v1` 超集：新键仅在 flag on 时出现；旧行无该键（向后兼容），已入账行不重写。
- `already_done`（幂等）只看 date/symbol/status，不受影响；`enrich_row`/strategy 附加字段在原位置之后仍生效（`intel_evidence` 在 `build_ledger_row` 内、`enrich_row` 前设置，不会被覆盖）。
- 下游读行方（a0_chief 日报、decision_outcomes、diff_baseline 等）按已知键读取，未知键忽略；A/B 期建议两臂数据根隔离，避免 diff 基线把新键当变更。

## 4. A/B 设计

### 4.1 假设与分流

- **H1**：给决策记录挂 reviewed 证据可提升「可追溯性/评测质量」（可回答“这条决策当时看到了哪些已复核事件”），不改变模型裁决质量与延迟；
- **H0**：证据读取增加时延/坏数据干扰落账 → 记录链路劣化。
- 分流：同批次（同日、同 codes）两臂；A=off（无 intel_evidence）、B=on；其余环境一致；A/B 期数据根隔离（`--root`/`--rehearsal`）。
- 建议样本：≥5 个交易日、≥100 条 D1 决策（B 臂有 reviewed 数据后）。

### 4.2 指标

| 维度 | 指标 | 采集 | 判据（建议） |
|---|---|---|---|
| 证据覆盖率 | B 臂 `intel_evidence.source=reviewed_jev` 行占比 | 两臂 ledger 逐行统计 | 有 resolved 的标的上 ≥80%；其余显式 price_proxy |
| 诚实性 | price_proxy 行 reason 分布（no_reviewed_jev/only_rejected…）；0 伪造 refs | ledger 行 | 全部带 reason；reviewed 行 event_refs 非空 |
| 决策质量 | recommendation/confidence/score 分布与 A 臂一致性；change_gate | ledger + change_gate | B 臂不劣于 A 臂 |
| 延迟 | `latency_s` P50/P95 | ledger | 增量 <50ms（只读查询）；无显著劣化 |
| 落账安全 | failed/parse_ok 比例、坏行数 | ledger + last_run.log `[warn] INTEL_TO_D1 坏行` | 坏行 fail-visible；0 阻塞/异常中断 |
| 可追溯 | event_refs/review_refs 可回查 `jev_review_queue` | 抽样 | 引用可达 |
