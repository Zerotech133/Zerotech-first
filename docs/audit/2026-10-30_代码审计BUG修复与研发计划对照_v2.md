## 二、本轮审计发现与修复

### P0-1 Pocket ID 密钥/数据落在 repo junction

**发现**：容器最初使用 `C:\aios\_vault\pocket-id`；`C:\aios` 是仓库 junction，
实际等于把 `encryption_key` 和 SQLite 数据放进了 repo 工作区，`git status`
出现 `?? _vault/pocket-id/`。

**修复**：

- 停容器；
- 将数据/密钥迁到 repo 外：`C:\项目\_vault\pocket-id`；
- 按新路径重建容器，discovery 200 / healthy；
- `.gitignore` 增加：
  - `_vault/pocket-id/`
  - `agent_platform/agent_platform/data/`（旧运行态输出）
- 验证：`git ls-files _vault/pocket-id/*` 无输出；密钥不在版本库。

**待办**：检查历史提交是否曾包含该路径；当前 `git ls-files` 为空，历史用
`git log --all -- _vault/pocket-id` 复核（若无则结项）。

### P0-2 8796 旧 Session0 进程 / 双监听

**发现**：8796 长期被 Session0 旧进程占用，`/sessions`、`/stream` 404；
LegionOps 原逻辑“端口通就跳过”，不会换血。

**修复**：

- 管理员清理旧进程；
- `ops/start_legion_ops.ps1` 改为功能探测：
  `/api/ide/openhands/sessions` 不通 → 杀旧监听 → 最新代码重启 → 再探测；
- 实测杀 8796 后 LegionOps 自动恢复（owner 36672），`/stream` 200、`/sessions` 200。

`serve.py` 的 `from tools.safe_urlopen` 被 zhice 常规 `tools` 包遮蔽，WMI 启动即退。
