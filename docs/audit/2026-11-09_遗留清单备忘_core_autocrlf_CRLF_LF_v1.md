# 遗留清单备忘：core.autocrlf 与 9F69/E4F60 换行差异

- 日期：2026-11-09
- 关联清单：`2026-11-07_ACAD1代码审查与遗留清单_v1.md`
- 结论：`9F69` 与 `E4F60` 内容完全相同，仅换行符不同；hash 不同仅因 CRLF/LF 归一化。

## 两版事实

| 版本 | 行数 | 字节 | 换行 | SHA256 | 位置 |
|---|---:|---:|---|---|---|
| 9F69 | 405 | 23,534 | CRLF | `9F693992F6CF9BA0BB10F394D89CB5F317A719BCB31B1506F9CBE19894C3B620` | Git HEAD blob / 主仓库源文件 / 当前 deliverable |
| E4F60 | 405 | 23,129 | LF | `E4F60E5315815B6E38A8A1D38BB43829B4BB1A816CFC1F7989855DE0E46CB687` | worktree 检出文件 / 同步前备份 |

## 差异与原因

- 逐行统一 diff：0 行差异。
- 两版归一化为 LF 后 SHA256 均为 `E4F60E5315815B6E38A8A1D38BB43829B4BB1A816CFC1F7989855DE0E46CB687`。
- 9F69 比 E4F60 多的 405 字节全部是每行 `\r`。
- 本机 `core.autocrlf=true`；Git 提交/工作区检出存在换行归一化，导致同一内容在不同路径呈现不同原始字节 hash。
- `git status` / `git diff` 对该文件为干净，说明 Git 认为两版仅有换行差异。

## 决策

- 保留 **9F69（CRLF）** 作为 deliverable 当前版本，不再覆盖。
- E4F60（LF）仅作为同内容的检出/备份形态保留，不删除。
- 本备忘单独记录，避免修改 9F69 正文或引入 Git 提交。
