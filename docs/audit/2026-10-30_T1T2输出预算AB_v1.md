# T1/T2 输出预算/契约 A/B（2026-10-30）

- 工单：`WO-LEGION-T1AB-20261030`
- 目的：验证 `llm.attempt degraded` 根因，比较“加预算”与“改输出契约”
- 工具：`tools/t1_ab.py`；结果落 `work/p0/ab/`
- 边界：实验不修改生产 prompt/模型；结论供下一单落地

## 一、真实运行的 reason 确认

单票真实流程：

```text
run_id=313b2b3ab7b3 stock=002712
T1 degraded  reason=length
T2 degraded  reason=length
N1 degraded  reason=length
T1/T2 中间 attempt reason=""（旧代码未记录）
```

结论：**T1/T2 的 degraded 就是 `done_reason=length`，不是异常/网络。**

## 二、A/B 设计

同一 prompt、同一模型 `qwen3.5:9b`，每组 3 次：

| 变体 | num_predict | 契约 |
|---|---:|---|
| current-400 | 400 | 先 Markdown 分析，末尾 JSON 块 |
| budget-800 | 800 | 同契约，仅加预算 |
| json-first-400 | 400 | 先 JSON 块，再 ≤200 字说明 |

记录：`done_reason`、是否含完整 JSON 块、字符数、耗时。

## 三、结果

| 变体 | done_reason | JSON 完整 | 字符数 | 耗时 |
|---|---|---|---:|---:|
| current-400 | length 3/3 | 0/3 | 617–656 | 13.1–13.7s |
| budget-800 | length 3/3 | 0/3 | 1333–1371 | 25.4–26.2s |
| json-first-400 | stop 3/3 | **3/3** | 227–248 | **4.75–4.94s** |

## 四、结论

1. **加 num_predict 不是好方案**：800 仍被截断，耗时约翻倍（25–26s），JSON 仍 0/3；
2. **改输出契约有效**：JSON-first + 短正文，3/3 完整 JSON，耗时仅 4.7–4.9s；
3. 根因是“长 Markdown 在前、JSON 在后”的契约与 400 token 预算冲突，不是模型能力/网络；
4. 下一步应在**真实 T1/T2 prompt** 上落 JSON-first 契约，再跑 `run_invest` 与 trace，确认 `degraded_reasons.length` 下降；
5. 落地前仍过 `change_gate` + 延迟对照，不直接改生产。
