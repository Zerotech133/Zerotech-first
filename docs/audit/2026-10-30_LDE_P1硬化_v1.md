# LDE P1 硬化：锁可见性 / exec 规则 / Session 跨进程锁

- 日期：2026-10-30
- 工单：`K-QUANT-20261030-LDE-NATIVE`
- 范围：LDE 施工台安全/一致性；不改业务写路径

## 1. 锁可见性

新增：

```text
GET /api/ide/lock?task=<TID>
→ {ok, task, locked, owner, age_s, stale?}
```

前端：

- 切工单/初始化/取锁/释放后自动刷新锁 chip；
- 显示：`锁 <owner> · N s`；
- 过期锁显示 `锁 已过期`；
- 被他人占用时提示等待/TTL，而不是只报“属于他人”。

实测：

```text
POST lock owner=hermes-test → locked=True owner=hermes-test age=0.1s
DELETE lock → locked=False
```

## 2. exec 白名单一致性

旧规则只允许 `git status -s`，但文档示例含路径，实际传路径会被拒。

现支持：

```text
git status -s -- <worktree 内路径>
```

并校验路径必须位于 worktree 内。

实测：

```text
git status -s -- agent_platform/legion_command/LDE_NATIVE_OK.txt
→ ok=True success=True
```

## 3. Session 跨进程锁

`work/legion_ide_sessions.json` 原只有进程内 `threading.Lock`，多个 8796
实例并发写可能丢行。

已加 Windows 跨进程文件锁：

```text
work/legion_ide_sessions.json.lock
msvcrt.locking(LK_NBLCK) + 5s 超时
```

- save / list / delete 三个写读路径统一加锁；
- 锁文件不随会话内容提交，不影响 API；
- 8796 通过 LegionOps 受控重启后：

```text
/sessions → 200，sessions=2
/health → ok
```
