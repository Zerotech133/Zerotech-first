### 1.4 接入方案（改 `tools/test_gate.ps1`，两小步）

**硬约束（实测）**：不同套件**不能合并到一次 pytest 调用**——本轮混跑时 `agent_platform/tests` 与 `tools/tests` 出现 `ImportError: cannot import name 'make_context' from 'tools' (unknown location)`（`work/_dsh_w5_20261031/b1_pytest.log`），与 test_gate 现有“一套件一次 pytest”的设计一致。因此新增文件必须按套件各起一次 pytest。

Patch 形状（**建议由 W5 owner 在单独工单实施；本审计未改 gate**）：

```powershell
# ① $paths 表新增三个“关键集”套件（文件列表 = 附录 A/B 的清单）
'agent_key' = @(<B1 的 agent_platform/tests 文件 43 个>)
'quant_key' = @(<B1 的 quant_backtest/tests 文件 9 个>)
'tools_key' = @(<B1 的 tools/tests 文件 5 个>)
# ② Suite fast 改为 6 个套件（每套件仍一次 pytest）
'fast' { $suites = @('portal','kstock','ide','agent_key','quant_key','tools_key') }
# B2 时只扩 3 个列表，不再加套件
```

**基线查找要兼容文件列表**（否则新套件的 known/env/flaky 登记不生效；现脚本按 target 字符串精确取 `$known[$t]`）：

```powershell
$suiteKey = ($t -replace '/[^/]+$', '')      # agent_platform/tests/test_x.py → agent_platform/tests
if ($known.ContainsKey($suiteKey))    { $knownList += @($known[$suiteKey]) }
if ($envKnown.ContainsKey($suiteKey)) { $knownList += @($envKnown[$suiteKey]) }
if ($flaky.ContainsKey($suiteKey))    { $knownList += @($flaky[$suiteKey]) }
```

**上线顺序（不一次全接）**：
1. 先在**任务 worktree**跑 B1 三组（`pytest <file...> -q --timeout=120 -p no:cacheprovider`），确认套件级 `sys.path`/数据根无新增失败；
2. 加套件 → `-Suite fast` 全跑 → GATE PASS 且总时长 ≤ 4.5min → 合入；
3. B2 同法，在 11-14 前完成；每批都要记录“新增失败 → 修或正式登记”（不得直接加白，沿用 baseline 纪律）。

**结论：devtask 的“merge 后重建 + 提交”（tools/devtask.py:1606-1634, call :1955）与 post-merge 钩子功能重复**；包体提交是“机制重复 + 易变字段”造成的纯噪声。
