## 一、先纠正一个研究中的假警报

我第一版 task 探针用了仓库内路径：

```text
C:\项目\老田的AI助手\.worktrees\<TID>
```

报出“21/39 工单 worktree 缺失”。

实际 OH 的根是：

```text
C:\legion-worktrees\<TID>      （ide_worktree.WORKTREE_ROOT）
```

修正后：

```text
39 个 doing/review 工单
18 个已有 worktree
21 个当前无 worktree（选中时 ensure_worktree 会从 task/<TID> 或 master 创建）
```

已修：`K-QUANT-20261030-IDETASKS`，`list_tasks` 改用 `ide_worktree.WORKTREE_ROOT`。

## 二、五个可托付断层

### F1：主聊天能启动 OH，但没有控制面

`a0-mainchat.js` 里没有任何：

```text
startStream / interrupt / respond / approval / diff / pending
```

它只做：

```text
消息 → /api/ide/orchestrate → 等最终结果 → 写回 S.messages
```

实际 OH session：

```text
cid 2c4d30bd-23d4-45df-aca3-cda9ff10cd7e
status = paused
```

`AlwaysConfirm` 策略下，命令确认/审批仍在 OH；主聊天没有审批、停止、diff、commit 入口，用户只能切回军团 IDE 面板。

结论：**A0 主聊天是“入口”，不是“完整开发台”。**

### F2：task 选择器会创建空 worktree，review 任务有风险

- 39 个可选工单；
- 18 个已有 worktree；
- 21 个没有；
- `ensure_worktree()` 对缺失 worktree 会：

```text
有 task/<TID> 分支 → git worktree add
无分支 → 从 master 新建 task/<TID>
```

这意味着：用户选一个 review 工单，可能拿到一个**新建/空工作区**，而不是之前开发留下的那个；同时会悄悄建分支/worktree。

当前选择器只显示 task/project/desc，不显示：

```text
worktree 是否存在
将复用哪个分支
将要新建 worktree
```

### F3：历史仍然是三本账

```text
tianfeng profile      → C:\Users\t\.hermes\profiles\tianfeng\state.db
A0 主聊天             → 客户端 S.messages，刷新即丢
orchestrator run 日志 → C:\项目\_vault\legion_ide\runs\<run_id>.jsonl
OH session            → 8796 sessions JSON
```

实测 39 任务、3 个 OH session、1 个 run JSONL。

run_id 只覆盖 orchestrator：

```text
orchestrate_start / hermes_plan / oh_start / run_end
```

没有：

```text
OH action/observation/approval
LDE lock/write/exec
Hermes 主聊天消息 id
```

所以还不能从 run_id 回放一次完整开发。

### F4：上下文和权限都在“信任本地”

- A0 工单上下文（含 desc）被拼进 system prompt，发给 Hermes `/api/chat`；A0 绑定 `glm/glm-5.3`，**工单描述会出网到云端模型**；
- LDE session 有 `roles=["VIEWER"]`，但写/exec 路径没有按 roles 鉴权；
- `/api/ide/tasks` 在 8796 直连时 200，任何本机进程可读工单摘要；
- 经 8734 `/openhands/` 时受 nginx auth 保护（未登录 302）。

结论：当前是“登录后的单机信任”，不是“按角色+按数据分级”。

### F5：回归层没有覆盖新链路

已有：

```text
test_hermes_orchestrator.py → 4 passed
test_legion_ide_http.py    → fast gate 'ide' suite
```

缺口：

```text
A0 mainchat 前端无浏览器测试
/api/ide/tasks 无 HTTP 契约测试
run_id 事件链无契约测试
fast gate 不跑 test_hermes_orchestrator
```

## 四、目标设计

### 1. 主聊天必须带控制面

最小版本：

```text
A0 执行卡片：
  [审批] [拒绝] [停止] [查看 diff] [打开军团 IDE]
```

数据来源：

```text
GET /api/ide/openhands/status?id=<cid>
GET /api/ide/openhands/stream?id=<cid>
POST /api/ide/openhands/respond
```

### 2. task 选择器要显示“worktree 状态”

```text
[复用] K-... · doing
[将新建] K-... · review · 无 worktree
[无 worktree] 只读咨询
```

默认只列“已有 worktree”；“将新建”必须二次确认。

### 3. 历史合流

优先级：

```text
A0 主聊天 → 建 Hermes 会话 / 或在 tianfeng profile 下建 session
run_id → 绑定 Hermes session_id + OH cid
OH/LDE 事件 → 追加到 run JSONL
```

### 4. 权限和上下文分级

```text
LDE 写/exec：roles 至少 EDITOR/ADMIN
工单上下文发送云端：按项目/敏感级脱敏，或仅本地模型
```

### 5. 回归

```text
test_hermes_orchestrator + /api/ide/tasks 契约进 fast gate
A0 mainchat 加一条浏览器 smoke：开关 → 选 task → answer/executed 卡片
```

## 五、下一步（按价值排序）

1. **执行后控制面**：主聊天内审批/停止/diff（当前 paused session 就是证据）；
2. **task worktree 状态可见 + 防盲建**；
3. **run_id 绑定 OH cid / Hermes session**；
4. **roles 鉴权 + 上下文脱敏**；
5. 旧页 MCP/模型/语音/多 Tab 迁移。

## 六、一句话

**A0 主聊天已经能“发起开发”，但还不能“接管开发”。下一步不是再加一个入口，而是把执行后的审批/停止/diff、worktree 状态和 run 回放接到主聊天里。**
