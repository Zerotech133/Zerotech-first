## 四、M1 判例沉淀（14 条）

**接线纪律**
1. 六铁律（各域通用）：状态真源不动 / 无 Approval 不转移 / 禁止跳级（±1 步）/ 幂等键+崩溃窗口 catch-up / 无源 ID 不伪造 / 越门可审计。
2. 凭据不泛滥：仅用户级承诺（批准/发布/结题/关闭/验收/交付/删除）设门；正常工作流走单一写路径+域内 history。
3. 绿地域（无既有真源）可新建账本，须文档声明依据；架构文档流程是状态机设计唯一权威。
4. 最小增量接线：引擎已覆盖的能力（RBAC/状态机）直通不复制，wiring 只加门与审计。

**工程判例**
5. 多连接写 SQLite：裸 BEGIN IMMEDIATE + 显式 commit/rollback（`with conn:` 包 BEGIN 在 Windows 多连接下 WAL 异常）。
6. WAL shm 重开竞争：全部连接关闭后 -shm 被删，多连接并发重开得假性 SQLITE_READONLY → 并发测试须常驻 keeper 连接。
7. 幂等快路径（同态+有凭据→replayed）必须先于合法性检查；打回重批=新轮次键。
8. append-only 回放 ORDER BY created_at,rowid（勿按随机 UUID）。
9. nav.js 唯一生成器=export_nav.py（AST 读 api_common.py 字面量），勿手改。
10. portals 挂载三件套：模块名绑定 import → Handler 多继承链 → do_GET 分支；mixin 单测用未绑定调用。

**审计判例**
11. 存量收编：接线前发生的历史动作按 WIRING_TS 时刻级切分（日期级同日误报），存量不违规、此后绕门 FAIL。
12. done 无凭据=绕门证据：wiring 拒绝背书，不补票（凭据语义不可事后伪造）。
13. 审计局限诚实声明（如 schedules 无消失前快照）写入 report 输出与文档。
14. domains_wired 类断言用包含性（接线进度不断加域，等值断言必碎）。
