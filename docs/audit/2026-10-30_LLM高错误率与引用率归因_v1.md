# LLM 高错误率 + AI1 引用率归因（2026-10-30）

- 工单：`WO-LEGION-TRACECITE-20261030`、`WO-LEGION-TRACECITE-EVID-20261030`
- 范围：`llm.attempt` 高错误率、AI1 prompt 引用基线 0.4
- 结论口径：先证据后判断；不把“有 trace”当健康

## 一、trace 高错误率：根因

### 现象

2026-10-30 18:29 对 Phoenix 最近 100 个 LLM span 汇总：

```text
llm.attempt 72 个
zhaoyun.status: degraded=56, normal=16
T1/T2 占 48 个 attempt
模型：ollama/qwen3.5:9b（64）、glm/glm-5.3（8）
错误率：77.78%
降级率：69.14%
```

T1/T2 的 attempt 延迟 57s–265s；`team_exec` 节点记录显示：

```text
node_key=t1_market
status=degraded
execution_mode=degraded
duration_ms=168249.0
output=“### 002712 技术面多头推演报告 ...”（在 JSON 块之前被截断）
structured={ "error": "no_json_block_found" }
```

### 根因

**T1/T2 的输出被 `num_predict=400` 截断，Markdown 后的 JSON 块没有生成，结构化解析失败，节点被判 degraded。**

- `agent_platform/engine/llm.py` 的 `qwen3.5:9b` profile：`num_predict=400`；
- T1/T2 的辩论/技术分析输出远超 400 token，模型在写 JSON 块前停止；
- `OllamaLLM.chat` 在 `done_reason=="length"` 时返回 `degraded`；
- `Interpreter._emit_attempt` 把非 normal 状态统一映射为 span `ERROR`，所以错误率看起来很高；
- 不是网络/模型不可用：没有抛异常；是输出预算不足。

### 已修观测

- `_emit_attempt` 新增 `zhaoyun.reason` 属性：记录 `done_reason`（如 `length`）或异常类型；
- `trace_ops` 新增 `degraded` / `degraded_rate` / `degraded_reasons`，把“降级”和硬错误分开；
- 当前历史 span 没有 reason（由旧代码写出），下一次 agent 运行后可按 `length` 归因。

### 建议（未擅自改模型预算）

1. T1/T2 辩论节点单独提高 `num_predict`（建议先 800，A/B 看延迟）；
2. 或把输出契约改成“JSON 块优先、正文 ≤300 字”，避免先写长文后截断；
3. 改预算/契约必须过 `change_gate` 评测 + 记录延迟，不裸改；
4. 下一轮 trace 报告应显示 `degraded_reasons.length` 占比。

## 二、AI1 引用基线 0.4：根因

### 现象

`p0_eval_runner --limit 5` 原结果：

```text
F01 FAIL citation_missing
F02 FAIL citation_missing
F03 PASS
F04 PASS
F05 FAIL citation_missing
rate=0.4
```

### 根因

`p0_eval_runner.judge()` 先执行 `citation_required` 检查，后计算 refusal；  
F01/F02/F05 的模型回答是“资料未取得/不确定”的**正确拒绝**，没有 `[S#]` 是应当的，却被判 `citation_missing`。

这是**评测器误判**，不是引用能力 0。

### 真实 grounded 引用率

`p1_citation_eval.py --limit 5`（走 `zhuge_grounding.grounded_chat`）：

```text
F01–F05 全部 grounded=True
cited=True，sources=[S1,S2,S3] ×5
citation_rate=100%
```

### 已修

- `judge()`：显式拒绝/不确定的回答不再要求 `[S#]`；有事实主张但无引用仍判 `citation_missing`；
- 加 `tools/test_p0_eval_runner.py` 三条回归；
- 重跑 P0 raw F01–F05：**5/5 = 100%**；
- `change_gate` 基线从 `0.4` 更新为 `1.0`：
  - metric：`pass_rate`
  - note：`P0 raw F01-F05 5/5 after refusal-citation fix; grounded citation 5/5=100%`

### 边界

- 1.0 是“修正评测语义后的安全/拒绝基线”，不是“所有回答都有引用”；
- 真实引用率看 grounded 路径：当前 5/5=100%，sources=3；
- 扩到 8 条 factual 后应再跑一次，保持 ≥80% 目标。
