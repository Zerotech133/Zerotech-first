# IDE 项目当前位置评估（2026-10-30 15:05）

## 结论

**定位：单人内测版 / 可日常开发，但生产化未完成。**

核心开发闭环已经跑通：

```text
Hermes 原生工作台
→ Agent / Session / Task / Context
→ OpenHands 执行（8796 + 8771）
→ LDE 文件树 / 编辑 / 写预览 / 锁 / git / exec / 审计
→ SSE / diff / commit / PWA
```

但还不是“可放心交给多用户/无人值守”的正式版；主要缺口在认证切换、LDE 边界硬化、跨进程一致性和旧 IDE 收编。

## 五、明确缺口

### P0（生产前必须）

1. 真实 passkey：当前是软件测试 passkey，`amr=phr`；
2. 登录仍 shadow/密码桥，未切 `on`；
3. 11-30 服务账号轮换尚未真实执行。

### P1（IDE 本体）

4. LDE 锁“属于他人”时无 owner/TTL 展示，无等待/释放指引；
5. exec 白名单与文档规则不完全一致（如 `git status -s -- <path>`）；
6. Session 文件存储缺少跨进程锁，多 8796 实例有竞争风险；
7. LDE 面板 8787 直连不支持（当前只保证 8734）；
8. 新 `/api/ide/tree`、`/api/ide/git` 没有进入正式 pytest，只做了 UI/API E2E；
9. Agent prompt 编辑写 worktree，缺来源/版本标识。

### P2（收编/体验）

10. 旧 `/ide` 与 native workbench 并存，功能有两套；
11. 多文件 diff / 冲突处理 / 撤销未做；
12. 工作台未做多用户隔离。

## 六、下一步建议

```text
P0 真实 passkey + shadow 复验 + 11-30 轮换
P1 LDE 锁 UX / exec 白名单 / session 跨进程 / tree+git 自动测试
P1 决定旧 /ide 的退役顺序（先补 chat/MCP 迁移清单）
P2 多文件 diff/commit、prompt 版本化、多用户隔离
```
