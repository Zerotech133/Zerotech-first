# 数字军团方案整合评估

- 日期：2026-10-17
- 依据：资料库《数字军团整合开发实施方案》与现有项目代码审计
- 结论：不重写现有数字军团，采用“现有 Legion 基座 + 资料库编排治理 + 统一契约与事件链”的融合路线

## 一、两套方案的关系

资料库方案提出的是目标型控制平面：

```text
Paperclip 战略层
  → Codex 树体研发编排
  → 情报哨与策略影子
  → 多源汇总器
  → 审批门禁与 RiskGuard
  → 模拟执行与绩效复盘
```

现有项目已经具备可运行的组织与执行基座：

```text
org/HR/team/bundle
  → Legion 大屏与 API
  → Worker
  → 研究院课题
  → agent_coder
  → shadow / paper
  → heartbeat / observe / review
```

两者不是互相替代关系：

- 资料库方案补充战略编排、策略影子、统一契约、审批与绩效闭环；
- 现有项目提供组织注册、HR、可视化、工单、Worker、研究院和运行监控。

## 二、最终统一架构

```text
L0 组织事实源
  org.json + team_*.json + hr/* + prompts/*

L1 构建投影
  agent_ide_bundle.json + claude_agents.json

L2 战略控制平面
  Paperclip（后续引入）
  目标、预算、审批、审计、组织治理

L3 军团编排平面
  Legion API 8096 + org_registry_server 8093
  会议、课题、工单、排程、Worker、监督

L4 研究与情报平面
  情报哨 + STRAT1/BACK1/DATA1/F1/T1/T2/N1/D1
  StrategyAgent 统一接口 + LCS-1

L5 证据与模型平面
  agent_coder + Hermes + CowAgent + Khoj
  事实包、Prompt、记忆、模型路由、证据引用

L6 风控与执行平面
  Gatekeeper + RiskGuard + paper
  只允许审批后的结论进入模拟执行

L7 统一事件与绩效平面
  portal.db events + trace_id
  paper fill + performance ledger + 复盘
```

## 三、保留项

1. `agent_platform/registry/org.json` 作为组织主事实源。
2. `team_*.json`、`agent_platform/hr/`、`agent_platform/prompts/` 作为岗位与人事源。
3. `portal/agent_ide_bundle.json`、`claude_agents.json` 作为构建产物，不再作为主事实源。
4. `portal/api_legion_ops_v2.py`、`portal/legion.html` 作为军团控制台基座。
5. `tools/legion_worker.py` 作为受控 Worker 执行器。
6. `tools/academy_worker_plan.py` 和研究院课题台账作为研究流程基座。
7. `tools/agent_coder.py` 作为岗位身份、模型路由和质量门禁底座。
8. Hermes/Cowbridge 的影子记忆和人审边界。
9. `quant_backtest/strategy_layer/`、`ai_operator/shadow.py`、`k_stock/paper/` 作为策略、影子和模拟执行资产。
10. `portal/portal_db.py` 作为统一事件底座的起点。

## 四、吸收项

### 1. 统一请求与事件协议

统一引入：

```text
trace_id
request_id
correlation_id
idempotency_key
caller
```

贯通：

```text
会议/课题
→ Worker
→ Agent 模型调用
→ 研究报告
→ 结论件
→ paper 订单
→ 成交
→ 绩效
```

吸收 `HermesEvent` 的生命周期事件语义：

```text
task.created
 task.claimed
 task.started
 task.output.created
 task.accepted
 task.failed
 academy.stage.advanced
 shadow.decision.created
 paper.order.planned
 paper.order.filled
 performance.updated
```

### 2. 统一策略接口

资料库方案中的 `StrategyAgent` 作为策略插件协议：

```python
class StrategyAgent(ABC):
    name: str
    model_tier: str = "default"

    @abstractmethod
    def research(self, intel: IntelItem) -> ResearchReport:
        ...
```

策略只负责研究，不负责下单；汇总器负责多源印证；执行组只接受已审批结论件。

### 3. 统一契约对象

建议新增或收敛以下契约：

```text
IntelItem
ResearchReport
Verdict
OrderIntent
Decision
Evidence
GateDecision
```

与现有 LCS-1 结合：

```text
图形推演
→ 事件佐证
→ 资金佐证
→ 多策略研判
→ 汇总结论
→ RiskGuard / Gatekeeper
→ paper
```

### 4. 吸收 Gatekeeper 三值语义

```text
True  放行
False 否决
None  缺证/降权/需人工核验
```

禁止把“数据不足”误判为“安全”或“直接否决”。

### 5. 吸收事实包版本和 hash

研究输出、影子决策、模拟订单都应保留：

```text
fact_hash
schema_version
decision_id
evidence_ids
prompt_version
bundle_version
strategy_version
```

## 五、需要收敛的项

### 1. 组织事实源

```text

构建投影：agent_ide_bundle.json + claude_agents.json
```

### 2. Legion API 版本

```text

api_legion_ops.py    = 兼容读取层
```

### 3. Worker 状态

在现有状态上补齐：

```text
blocked
retry_wait
cancelled
claim_token
claimed_at
lease_until
attempt
failure_code
failure_detail
recovered_by
```

## 六、实施顺序

### M0：契约与身份收敛

- 固化组织主事实源。
- 新增 contracts 目录。
- 定义 IntelItem、ResearchReport、Verdict、OrderIntent、GateDecision。
- 全链路先传递 `trace_id`。
- 保持所有无人值守排程关闭。

### M1：Worker 可靠性

- 增加 claim 租约与并发锁。
- 增加 retry、blocked、cancelled、manual recovery。
- 输出文件生成 hash。
- 失败原因结构化。

### M2：研究院连续链

```text
intake
→ hypothesis
→ evidence
→ validation
→ review
→ joint_review
→ decision
```

Worker 完成并通过阶段验收后，自动推进课题并生成下一阶段工单。

### M3：策略影子与汇总器

- 将 T1/T2/N1/F1/D1 与 STRAT1/BACK1/DATA1 统一为研究角色和策略影子。
- 研判阶段上下文隔离。
- 汇总阶段才允许跨策略比较。
- 结论不足时输出 `neutral` 或 `需人工核验`。

### M4：Paper 与绩效闭环

```text
decision
→ approved
→ risk_checked
→ paper_order
→ fill
→ performance
→ review
```

当前只做模拟盘，不接真实券商，不启用无人值守实盘。

### M5：Paperclip 战略控制平面评估

Paperclip 不作为现有 Legion 的替代，而作为战略层候选：

- 目标和预算；
- 组织级审批；
- 多项目管理；
- Codex 树体研发编排；
- 审计和预算硬停。

只有在 M0-M4 的契约和事件链稳定后才部署，避免把第二套控制面提前引入造成双主控。

## 七、当前明确不做

1. 不直接部署 Paperclip 并让其成为第二个任务主控。
2. 不把 Codex 树体直接替换现有 Legion Worker。
3. 不把任何策略影子直接接入真实交易。
4. 不把模型输出直接写入生产记忆或组织规则。
5. 不启用无人值守真实下单。
6. 不删除现有 Worker、研究院、paper 或 Hermes 资产。

## 八、整合后的判断

资料库方案适合作为数字军团的战略总纲，现有项目适合作为已经运行的组织与执行基座。最终路线是：

```text
现有 Legion 负责组织、工单、研究院、监督和可视化
资料库方案负责统一契约、策略影子、审批门禁、事件与绩效闭环
Hermes/CowAgent/Khoj 负责交互、执行、记忆和知识能力
Gatekeeper/RiskGuard/paper 负责模拟执行安全边界
```

在以下三项完成前，系统仍保持受控实战阶段：

```text
1. Worker 可恢复执行闭环
2. trace_id 从课题贯通到 paper 和绩效
3. 统一审批、风控、审计和人工确认边界
```
