# 司马徽军团功能审查 v1

- 日期：2026-10-30 22:45
- 范围：Hermes / legion-ide 里的「司马徽研究院 · 选股中台」入口
- 性质：只读审查，未改代码

## 一、结论

功能面是活的，数据面也是活的：

```text
5175 研究台 200
8102 /selection-public/summary 200
data_date=2026-10-30
pool_total=176 report_total=12 supervision_total=1 used=2 rejected=0 resonance=1
ZhiceAcad1Pool 最近一次 17:08:59，LastTaskResult=0
```

但 IDE 里的司马徽面板存在 **承载、隔离、集成** 三类问题：

```text
它不是 IDE 原生的司马徽能力，而是一个 iframe 壳。
实际 iframe 指向 5175 Vite 开发服务器，不是同源静态构建。
```

## 二、P0 问题

### P0-1 面板依赖 5175 Vite dev server，可能直接白屏

代码：

```text
const PAGE = "http://127.0.0.1:5175/cn/replay?tab=selection";
frame.src = PAGE;
```

实测：

```text
5175 当前 200
5175 进程无守护任务（ZhiceAcad1Pool 是数据任务，不是 UI）
5175 /health -> 200，但返回的是 Vite index.html（SPA fallback）
5175 /assets/index-B0vyDQT9.js -> 200，但返回 725 字节 HTML（不是 JS）
```

结论：

```text
5175 的 /health 是假健康；
一旦 Vite dev server 退出，司马徽面板就是空白 iframe；
现有 KPI/guard 不会发现。
```

建议：面板改指向同源静态构建，或给 5175 建独立守护 + 真健康探针。

### P0-2 同源静态构建明明存在，却没被面板使用

实测：

```text
/extensions/zhice/index.html                         200
/extensions/zhice/assets/index-B0vyDQT9.js           200（1,821,561B，application/javascript）
/extensions/zhice/assets/index-Dl42rMEp.css          200（16,229B）
```

说明仓库里已有可用的静态构建；面板却绕到 5175 dev server。

后果：

```text
两套 UI 副本（5175 dev / extensions/zhice build）可能漂移；
生产面板依赖开发服务器，不是发布产物；
版本不可 pin。
```

### P0-3 iframe 没有 sandbox / 加载失败态

代码只有：

```text
const frame = el("iframe", "acad1-frame");
frame.src = PAGE;
```

没有：

```text
sandbox 属性
loading / onload / onerror
iframe 内部可用性探针
刷新按钮
```

5175 是独立源、无认证；静态构建则是同源。无论用哪个，都应该明确隔离策略：

```text
跨源 5175：至少 sandbox（按需 allow-scripts/forms/popups）
同源静态：要么信任并加 CSP，要么 sandbox 掉 same-origin
```

## 三、P1 问题

### P1-1 摘要用 `|| 0` 把缺失数据伪装成 0

```js
"日报 " + (x.report_total || 0)
"候选池 " + (x.pool_total || 0)
```

如果 8102 返回缺字段或空对象，面板会显示：

```text
日报 0 · 候选池 0 · 共振 0
```

而不是“数据不可用”。这会误导研究判断。

应区分：

```text
undefined → "—" / "数据不可用"
0         → 真实 0
```

### P1-2 没有 IDE 上下文桥

面板固定打开：

```text
/cn/replay?tab=selection
```

不接收：

```text
当前 task_id
当前 stock
当前候选池/共振项
当前 IDE 的选中文件
```

也不回写：

```text
选股结论 → IDE
研究项 → 任务
```

所以它不是“IDE 里的司马徽军团”，只是“IDE 弹窗里的另一个网站”。

### P1-3 地址全部硬编码 localhost

```text
BASE = http://127.0.0.1:8102/api/v1
PAGE = http://127.0.0.1:5175/cn/replay?tab=selection
```

后果：

```text
局域网/远程访问时，iframe 的 127.0.0.1 指向访问者本机 → 直接失败
端口变更需要改 JS
```

### P1-4 5175 进程无守护、无真健康

- `5175` 有监听，但进程 CommandLine 为空（S4U）；
- 任务计划里没有 5175 UI 守护任务；
- `/health` 被 SPA fallback 伪装成 200；
- 数据任务 `ZhiceAcad1Pool` 正常，不代表 UI 正常。

### P1-5 面板是全局浮窗，无路由/页面语义

`acad1-btn` fixed 在 `right:18px;bottom:80px`，所有 Hermes 页面都出现。

问题：

```text
可能与其他浮层/输入框重叠
在设置页/会话页也会出现
没有“当前页面是否适合司马徽”的判断
```

## 四、P2 问题

```text
· 无 iframe title（可访问性）
· 打开后无刷新按钮；关闭只是 display:none，iframe 状态保留，数据可能过期
· 摘要 CORS 为 *，任何页面可读 selection summary（若数据敏感需评估）
· 静态构建 1.8MB JS 首次加载较重；无 loading 状态
· 面板与已下线的旧研究台入口可能重复（需统一入口）
```

## 五、建议优先级

### P0（先做）

```text
1. 面板改用 /extensions/zhice/index.html#/cn/replay?tab=selection（同源静态构建）
2. iframe 加 title + sandbox/CSP 策略 + 加载失败提示
3. 5175 不再作为生产依赖；保留为开发环境
```

### P1

```text
4. 摘要缺字段显示 "—"，不要 ||0
5. 支持 ?task=/stock= 上下文注入，或 postMessage
6. 地址去硬编码，跟随 location.origin
7. 加刷新按钮/数据日醒目提示
```

### P2

```text
8. 把司马徽入口收进 IDE 导航，不做全局浮窗
9. 静态构建版本 pin / 发布记录
10. UI 健康进 KPI（真探针，不用 /health 假 200）
```

## 六、一句话

**司马徽的数据面是活的，IDE 里的功能面是“借来的 iframe”；当前最大问题不是没有功能，而是生产面板依赖 5175 开发服务器、而真正的同源静态构建就在旁边没被用。**
