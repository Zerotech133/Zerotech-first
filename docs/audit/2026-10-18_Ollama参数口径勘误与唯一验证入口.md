## 三、唯一验证入口

```bash
$PY agent_platform/tools/start_tuned_ollama.py --status
```

三态判读：

| 输出 | 判定 |
|---|---|
| `STATUS port_open=True processes=1` + `STATUS config={... "OLLAMA_CONTEXT_LENGTH": "65536" ...}` | **tuned**（且是脚本起的） |
| `STATUS port_open=True` + `STATUS 无 serve 日志（可能是桌面 App 起的实例，配置未经本脚本校验）` | **未判定**：端口通但无法证明配置，必须补第二证据 |
| `STATUS port_open=False` | 端口层 DOWN（此判定用 raw socket，不受代理影响） |

⚠ 本机实况（17:31 实测）：输出正是第二态。原因是脚本 `SERVE_LOG`（`C:\aios\automation_runs\ollama_guard\serve_tuned.log`）
与真日志 `%LOCALAPPDATA%\Programs\Ollama\tuned.log` **不是同一个文件**（真 serve 由 `ollama_watchdog.py` 拉起，落后者）。
故 `--status` 单独用**不足以定性**，必须补两条：

```bash
grep -a "server config" "%LOCALAPPDATA%\Programs\Ollama\tuned.log" | tail -1
ollama ps          # 看 CONTEXT 列
```

- `server config` 行里应同时出现：`OLLAMA_CONTEXT_LENGTH:65536`、`OLLAMA_NUM_PARALLEL:2`、
  `OLLAMA_KV_CACHE_TYPE:q8_0`、`OLLAMA_FLASH_ATTENTION:true`、`OLLAMA_KEEP_ALIVE:30m0s`（或 2h0m0s）、
  `OLLAMA_IGPU_ENABLE:1`。缺任一项 = 默认配置。
- `ollama ps` 的 **CONTEXT 列阈值：< 8192 即默认配置**。但**单票 2048 是客户端参数**
  （`quant_backtest/xq_classify.py:57 DEFAULT_NUM_CTX=2048` 按请求下发 `options.num_ctx`），
  不代表服务端默认——判定顺序：先看 config 行，再用 ps 交叉验证（任一模型 =65536 即证明服务端已放大）。

## 四、唯一操作口径

**不要用 `setx OLLAMA_NUM_PARALLEL 2` 单独设参**——它只改一个参数，且要重启才生效，
九成会留下"并行度对了、ctx 还是 4096"的半吊子实例。改用脚本（一次注入六个 + 代理清理）：

```bash
$PY agent_platform/tools/start_tuned_ollama.py --status        # 先查，别盲重启
$PY agent_platform/tools/start_tuned_ollama.py                 # 已在跑则不重启，仅在缺跑时拉起
$PY agent_platform/tools/start_tuned_ollama.py --restart       # 仅在班间隙执行（会打断在飞推理）
```

## 五、探针陷阱（HTTP_PROXY 假阴性）

本机会话沙箱给子进程注入 `HTTP_PROXY=http://127.0.0.1:50207`、`NO_PROXY` 为空。
`urllib` **不会自动绕过回环**，实测证据：请求无服务的 `127.0.0.1:11439`
返回 **HTTP 502 Bad Gateway**（代理应答），而不是 `ConnectionRefused` ——证明回环请求确实走了代理。
代理不可用/限流时，"服务其实健康"也会得到 502 → 被误判成"服务挂了"或"配置错"。

禁代理探测（唯一正确写法）：

```python
import urllib.request
opener = urllib.request.build_opener(urllib.request.ProxyHandler({}))
with opener.open("http://127.0.0.1:11434/api/ps", timeout=5) as r:
    print(r.status, r.read().decode("utf-8", "replace"))
```

禁代理探测（urllib 写法，或直接用 raw socket，后者天然免疫）。现状盘点：

| 探针 | 是否免疫 | 依据 |
|---|---|---|
| `start_tuned_ollama.py` | ✅ | `port_open()` 用 `socket.socket().connect()`（89–98 行），全程无 urllib（53 行 `import urllib.request` 是**死导入**） |
| `ollama_watchdog.py:healthy()` | ✅ | 显式 `ProxyHandler({})`，启动前 `env.pop("HTTP_PROXY")` |
| `engine/llm.py` | ✅ | 第 123 行 `build_opener(ProxyHandler({}))` |
| `xq_ollama_probe.py` | ❌ | 第 19 行裸 `urlopen`，注入代理下必假阴性 |
| `Hermes/ollama_watchdog.ps1` | ❌ | `Invoke-WebRequest` 走系统代理；误判后 kill 全树 |
