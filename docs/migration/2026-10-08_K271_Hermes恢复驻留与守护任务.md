## 死亡实验（root cause 定稿）

DETACHED 启动的 server.py **稳定死于启动后 ~1-2 分钟，零 traceback**。单变量对照：

| 实验 | 配置 | 结果 |
|------|------|------|
| 基线 | DETACHED + stdout/stderr→文件 | ✗ 活 1-4 分钟静默死（T+100s 复现） |
| B | 前台 + 同文件句柄（110s 观测） | ✓ 全程存活 |
| A | DETACHED + 全 DEVNULL（80s 观测） | ✓ 全程存活 |

**结论**：继承的文件日志句柄在 launcher 退出后于 DETACHED 会话中失效，python 缓冲 flush 写无效句柄时炸解释器、stderr 同坏=零日志。生产配方=**DETACHED + stdio 全 DEVNULL**（server 自身无文件日志，可用性优先）。

另：powershell -File 包 launcher + DETACHED = **启动瞬间静默秒死**（零输出），powershell 中转层整体弃用。

## 教训与配方（复用价值）

- **DETACHED 驻留配方修正**：之前记忆配方「stdout/stderr 重定向文件」在 powershell 中转+长跑服务场景有毒——**长跑 DETACHED 服务 stdio 一律 DEVNULL**，要日志用服务自身落盘能力（本例 server 无，接受）。
- 启动器幂等用 **socket 探测端口**而非进程名/命令行匹配（免 CIM 查询、免误判）。
- 驻留三坑记忆更新：坑① pythonw+DETACHED 秒死、坑④ powershell+DETACHED 秒死、坑⑤ DETACHED+文件句柄=延迟 1-2 分钟静默死。
