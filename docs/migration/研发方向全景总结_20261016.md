## 一、使命与定位

**一句话**：把"指定账号的视频号内容"变成"可训练、可检索、可预警的结构化情报"，作为老田量化情报工作站（news_collector / 知识图谱 / 三线联动）的新增信号源。

三层定位（对应老田的三点需求，已收敛为一个中台的三个层次）：

| 层 | 需求原话 | 能力 |
|----|---------|------|
| 管理面 | "管理针对的对象、什么时间发" | 监控对象注册、账号发帖时间线、评论区数据整理 |
| 采集面 | "对所有需要的微信监控、数据结构化" | 账号级持续监控 → 视频/评论自动采集 → ASR+OCR 双通道结构化 |
| 分析面 | "好评差评的全网总结" | 评论情感分类、跨源舆情聚合、账号异动日报 |

**非目标**（明确不做）：Tokens 售卖、对外数据服务（自用训练合规敞口最小化）、全平台铺开（v2 只做深视频号，跨平台 Phase 4）。

## 二、技术路线（已定，不再摇摆）

### 2.1 采集双轨

```
路线 D（主力，~90%流量）         路线 B（兜底+实时）
sph 分享链接                     Fork res-downloader core/
 → 元宝Cookie解析链               → Go headless 服务
 → mediaUrl+urlToken              → goproxy MITM 嗅探
 → 分片下载                       → JS注入抓 decode_key
 → ISAAC64 解密(128KB XOR)        （专用隔离采集机，根证书不离机）
✅ 无证书/无代理/可服务器化        ✅ 覆盖直播回放/边看边采
⚠️ Cookie 会过期(401热更新机制)   ⚠️ 需微信PC登录态+封号风险管控
```

### 2.2 结构化管线（对视频来源零耦合——PoC 关键解耦）

```
明文 mp4 → ffmpeg → ┬ 音频16k wav → SenseVoice-Small ASR（NPU 产能匹配）
                    └ 1fps 抽帧+CLAHE → PaddleOCR（硬字幕/画面文字）
双通道时间戳对齐交叉验证 → StructuredDoc JSON
 → 合规层（白名单/PII脱敏/MD5+MinHash去重）
 → PG(osint_前缀) + Qdrant(osint_video_v1) + 知识图谱(VideoNote节点)
 → 训练语料 / 量化情报信号
```

### 2.3 v2 新增组件（监控中台化）

TargetRegistry（对象管理）→ AccountWatcher（时间线发现）→ CommentCollector（评论采集）→ SentimentAnalyzer（qwen 情感分类）→ PulseReport（好评差评日报，与 news_collector 跨源合并=全网总结）。

### 2.4 关键技术事实（已验证，写死在架构里）

1. 视频号**无公开 API**——评论/账号时间线依赖 finder 门户 Cookie（T06 探路验证）或采集机嗅探
2. 解密算法=ISAAC64 PRNG(decode_key 播种)生成 128KB 密钥流与前 128KB XOR——已多语言公开，真正要维护的是 decode_key 获取链路
3. res-downloader core/ 与 Wails GUI 可分离（resd-mini 实证），Apache-2.0 允许闭源商用（保留声明+修改标注+低调分发）
4. ASR 首选 SenseVoice-Small（280MB、CPU 2×实时、中文原生带标点、可 NPU）；OCR 首选 PaddleOCR PP-OCRv4

## 四、待老田拍板的决策点（合并清单，共 12 项）

**v1 架构 §8（8 项）**：
1. 采集机选型——建议独立 VM/廉价机，不与开发机混用（根证书=整机 HTTPS 可解密）
2. 元宝 Cookie 维护人——飞书卡片 ≤30 分钟响应
3. 白名单 v1——法务圈"财经时事口播类"账号
4. ASR 宿主——PoC 用 Win11 CPU，量产切 ARM NPU
5. embedding 模型——bge-m3（1024 维）
6. PoC 验收线——CER≤8% / OCR≥90%
7. 原始 mp4 保留——白名单内 90 天、隔离区即删
8. 队列 API——独立 8300 端口

**v2 路线图 §4（4 项）**：
9. 门户 Cookie 与元宝 Cookie 同一维护人
10. 评论昵称 PII——入库保留、导出训练前哈希化
11. "全网"范围——先视频号做深
12. 管理界面——v2 飞书卡片+API 起步，T09 再上 Web

**建议**：1/3/7 需要你亲自定（涉及合规与资源）；其余 9 项如无异议按建议默认值执行。
