# 老田的AI助手 · 换机迁移包

创建时间：2026-10-15

## 目录

- `项目主体/老田的AI助手/`：主项目完整副本，包含 `.git`、项目数据、历史归档、现有 worktree、运行产物和配置。
- `外部依赖/`：项目引用的主仓外部目录，复制完成后按本说明恢复。
- `迁移说明/`：复制日志、校验清单和新电脑恢复指南。

## 当前策略

1. 只复制，不移动、不删除原始文件。
2. 使用 Windows Robocopy 保留文件内容、时间和目录结构。
3. 原项目中的 `.git`、缓存、数据、备份、worktree 都保留；换机后可以先恢复完整项目，再按需清理。
4. `C:\Temp`、`C:\aios`、`D:\new_tdx64` 等跨盘目录不直接塞入项目主体，统一放到 `外部依赖/` 并在恢复指南中说明原路径要求。

## 新电脑恢复顺序

1. 将本迁移包复制到新电脑，例如 `E:\老田的AI助手_迁移包_20261015\`。
2. 将 `项目主体\老田的AI助手` 放到目标路径，建议仍为 `E:\老田的AI助手`，这样现有配置和脚本改动最少。
3. 将 `外部依赖` 内目录按恢复指南放回对应盘符；如果盘符不同，先不要启动计划任务。
4. 安装 Python 3.11、Git、Node.js、Docker、Ollama、通达信及其他运行依赖。
5. 先运行 `tools\check_ports.py` 和 `ops\health_check.py`，再逐项恢复计划任务。
6. 不要直接把旧电脑的密钥、Token、代理凭据用于公开环境；迁移前后应检查 `config/`、`.env*` 和加密文件。

## 注意

- 迁移包不是自动可启动的系统镜像；Windows 服务、计划任务、Docker 容器、注册表、系统 PATH、Python 包和 Ollama 模型仍需要在新电脑重建。
- 复制过程中如果日志出现 `FAILED` 或 `ERROR`，以 `迁移说明` 中的日志和校验清单为准。
