## 一、技能三态分类

系统的技能分类是**双轴**设计，由包内容**自动推导**，不需要手工维护分类字段：

| 轴 | 含义 | 取值 | 推导逻辑 |
| --- | --- | --- | --- |
| **安全轴** `trustLevel` | 决定安装信任门槛与执行权限 | `markdown_only` / `assets` / `scripts_executables` | 扫描包内文件清单：有 `scripts/` 下脚本 → `scripts_executables`；有资源文件 → `assets`；仅 Markdown → `markdown_only`（`company-skills.ts: deriveTrustLevel`） |
| **展示轴** `pageEntry` | 决定是否带浏览器页面入口 | `html/index.html`（相对路径）或空 | 读 SKILL.md frontmatter `page:` 声明，且该文件必须存在于包内清单，否则忽略（`deriveSkillPageEntry`） |

三类技能对应关系：

| 技能形态 | trustLevel | pageEntry | 举例 |
| --- | --- | --- | --- |
| 纯 MD 描述型 | `markdown_only` | — | 各类方法论/清单技能 |
| 脚本执行型 | `scripts_executables` | — | 月末关账日历等脚本技能 |
| **自带页面型** | `scripts_executables` | `html/index.html` | 股票图谱分析 |

**铁律**：带页面的技能必须同时是 `scripts_executables` 级（页面数据桥要执行 python）；`pageEntry` 不改变安全轴语义，两者正交。

## 二、技能包目录结构

```
<skill-name>/
├── SKILL.md              # 唯一入口，frontmatter + 使用说明（必需）
├── scripts/
│   ├── ingest.py         # 数据采集/建库脚本：Agent run 时执行（页面型可选）
│   └── api.py            # 数据桥脚本：页面请求时由 server spawn（页面型必需）
├── html/
│   └── index.html        # 浏览器页面入口（页面型必需，frontmatter page: 指向它）
└── references/           # 参考文档（可选）
```

约定：

- `scripts/`、`references/`、`assets/`、`html/` 是保留目录名（文件分类按目录前缀推导）。
- 页面及其依赖（js/css/图片）**必须自包含**放在 `html/` 内，不得引用外网 CDN（见 CSP 约束）。
- 数据库等**运行时数据不得写在技能包目录内**（包升级/重装会被整体替换），用公司隔离目录（见 §五）。

## 三、SKILL.md frontmatter 规范

```yaml
---
name: 股票图谱分析                  # 必需，技能显示名
description: 一句话描述……            # 必需，40–300 字符（进商城目录的硬约束）
page: html/index.html               # 页面型技能必需：页面入口相对路径
api: scripts/api.py                 # 可选：数据桥脚本路径，缺省 scripts/api.py
tags:                               # 可选：搜索标签
  - stock
  - 可视化
---
```

规则：

- `page` 路径必须以包根为基准、**存在于包内**，导入时校验失败会被静默忽略（技能退化为无页面型）。
- `page` / `api` 路径禁止 `..` 逃逸与绝对路径。
- 正文（frontmatter 以下）写给 Agent 看：脚本用法、参数、汇报格式约定。

## 四、html 页面开发规范

### 4.1 运行环境（安全模型）

页面经服务端路由 `GET /api/companies/:companyId/skills/:skillId/page/*` 提供，响应带：

```
Content-Security-Policy: sandbox allow-scripts allow-same-origin
X-Content-Type-Options: nosniff
```

含义与约束：

- **脚本可执行**（`allow-scripts`），可以渲染交互内容（canvas/ECharts 等）。
- **同源可访问**（`allow-same-origin`）：可以带 cookie `fetch` 数据桥接口（同源鉴权自动通过）。
- **沙箱隔离**：无顶层导航、无弹窗、表单提交受限；**外网请求受限**——所有 JS/CSS/数据必须自包含或走数据桥。
- 页面以新标签打开（`window.open(url, "_blank")`），入口由系统自动挂载（见 §六），技能**不需要**自己注册路由。

### 4.2 数据获取（数据桥）

页面内所有数据都通过数据桥取：

```js
// 页面位于 /api/companies/<companyId>/skills/<skillId>/page/html/index.html
// 相对路径 ../../api/ 正好命中数据桥路由 /api/companies/<companyId>/skills/<skillId>/api/*
fetch("../../api/graph", { credentials: "include" })
  .then((r) => r.json())
  .then(render);
```

- 请求转发：server spawn `python api.py`，把请求上下文以 JSON 写入 stdin，取 stdout JSON 返回。
- 超时 30 秒、输出上限 8MB、脚本路径固定来自 frontmatter `api`（页面不可指定执行任意脚本）。
- 空数据时返回带 `empty: true` 的结构，页面应给出引导提示（如「Agent 运行 ingest 后可查看」）。

## 五、api.py / ingest.py 契约

### 5.1 api.py（数据桥脚本）

```python
# stdin:  {"path": "graph", "method": "GET", "query": {...},
#          "body": {...}, "companyId": "...", "skillId": "..."}
# stdout: JSON（普通对象=200 响应；或 {"statusCode": n, "body": ..., "headers": {...}} 信封）
```

实现要点：

- **stdlib only**（sqlite3/json/sys）；30 秒内必须退出。
- 按 `path` 分发端点（如 `graph` / `summary`）；未知端点输出 `{"statusCode": 404, "body": {...}}`。
- 查询语义（只读）；写数据由 ingest.py 负责。
- 数据库连接用只读模式：`sqlite3.connect(f"file:{db}?mode=ro", uri=True)`。

### 5.2 ingest.py（数据脚本）

- 由 Agent 在 run 中执行（SKILL.md 正文写明用法），或人工运行。
- 写入**公司隔离数据目录**（server 侧同款派生规则）：

```
~/.zerobound/instances/default/skill-data/<companyId>/<skillId>/<name>.db
```

- Agent 执行时通过环境变量 `ZB_COMPANY_ID` / `ZB_SKILL_ID` 拿上下文（与数据桥传入的 companyId/skillId 一致，两边落到同一个库）。
- 换数据源（TDX/akshare 等）只改 ingest.py 的取数函数，写库 schema 不动。

### 5.3 Python 运行时

- 宿主机需有 `python`（可用环境变量 `ZEROBOUND_SKILL_PYTHON` 覆盖可执行名）。
- 每请求 spawn（冷启动 ~50ms），毫秒级查询足够；高并发场景再演进常驻 worker。

## 六、系统挂载点（技能作者无需开发）

带页面技能安装并挂到 Agent 后，系统自动出现的入口：

| 入口 | 位置 | 条件 |
| --- | --- | --- |
| 「打开页面」按钮 | Agent 详情 → Skills 标签页技能行 | 技能 `pageEntry` 非空 |
| 「技能页面」横幅 | Agent 对话页顶部（汇报文本上方常驻 chip） | 该 Agent **已勾选**该技能（desired） |
| **技能页面卡片** | **汇报平台首页**（汇报区块下方，一技能一卡，卡片显示技能名/描述/使用员工 chip，员工点击进其对话页） | 公司存在 `pageEntry` 非空技能（无则整块隐藏）；数据走 `skills?include[]=pageUsers`（单请求附 `pageUsers` 员工明细） |
| 页面 URL | `…/skills/:skillId/page/html/index.html`（可直接分享/收藏） | 同公司鉴权通过 |

Agent 汇报照旧输出四段式文本；页面是文本汇报的补充视图，**Agent 无需在汇报里声明任何链接**。

## 七、开发与调试流程

1. **建包**：复制 `skills/stock-graph-analysis/` 为模板，改 name/description/脚本。
2. **本地自测脚本**（不经服务端）：

   ```bash
   ZB_COMPANY_ID=<companyId> ZB_SKILL_ID=<skillId> python scripts/ingest.py --source demo
   echo '{"path":"summary","companyId":"<companyId>","skillId":"<skillId>"}' | python scripts/api.py
   ```

3. **安装到租户**：包须位于「公司受管技能目录」内才能本地导入（工作区边界防护）：

   ```bash
   cp -r <你的技能包> ~/.zerobound/instances/default/skills/<companyId>/<slug>
   curl -X POST http://127.0.0.1:3100/api/companies/<companyId>/skills/import \
     -H "Content-Type: application/json" \
     -d '{"source":"~/.zerobound/instances/default/skills/<companyId>/<slug>"}'
   ```

4. **验证推导**：列表接口应返回 `pageEntry` 与 `trustLevel: scripts_executables`：

   ```bash
   curl http://127.0.0.1:3100/api/companies/<companyId>/skills | jq '.[] | select(.pageEntry)'
   ```

5. **验证页面与数据桥**：

   ```bash
   curl -i http://127.0.0.1:3100/api/companies/<companyId>/skills/<skillId>/page/html/index.html
   curl -X POST http://127.0.0.1:3100/api/companies/<companyId>/skills/<skillId>/api/summary -d '{}'
   ```

6. **挂到 Agent**：UI 上勾选，或 API：

   ```bash
   curl -X POST "http://127.0.0.1:3100/api/agents/<agentId>/skills/sync?companyId=<companyId>" \
     -H "Content-Type: application/json" \
     -d '{"mode":"add","desiredSkills":["<skill key>"]}'
   ```

   （注意 `mode:"add"`，`replace` 会清掉已有技能。）

7. **浏览器验证**：Agent 对话页顶部出现「技能页面」chip；Agent 详情 Skills 行出现「打开页面」。

## 八、安全边界（开发者必读）

- 页面 = 技能包签发的可信代码，信任级别与脚本执行同级（安装 `scripts_executables` 技能即视为接受）。
- CSP sandbox 把页面能力收窄为「跑脚本 + 同源 fetch」；HTML 强制 `attachment` 防注入的老规则不适用于本通道（本通道显式声明 `page` 才开）。
- 数据桥只执行**包内声明路径**的脚本，stdin 传请求、stdout 收 JSON，超时/限量双保险；页面无法让 server 执行任意命令。
- 数据按 companyId/skillId 目录隔离，跨公司不可见；包目录视为只读代码，数据一律走 skill-data 目录。
- 技能包内 `.env`、密钥类文件**禁止**入库（导入扫描含密钥外联模式会拒收）。

## 九、已知限制

- **Windows 开发机**：`ensureZeroBoundSkillSymlink` 在无符号链接权限的 Windows 上 EPERM，导致技能同步到 opencode 运行时的物化步骤报错（desired 状态仍会持久化，页面链路不受影响）。Linux/部署环境无此问题。
- Agent 真实 run 中执行 ingest.py 需要 Agent 运行时正常加载技能；受上一条限制，Windows 本机可用人工方式灌数（§七.2）验证页面。
- 每请求 spawn python 的冷启动开销在高频轮询场景需要加缓存（当前 30s 超时上限内可自查 TTL 缓存方案）。
