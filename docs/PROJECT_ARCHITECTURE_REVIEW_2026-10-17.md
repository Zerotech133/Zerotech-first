## 3. 架构分层复盘

### D1 数据采集与存储

Tushare、TDX、雪球、股吧、情报及外部源进入统一数据池，再落地 Parquet/SQLite/PG/MySQL/Neo4j 等存储。当前唯一 live 数据根为 `quant_backtest/data`；数据根的历史冲突已解决，但后续文档必须明确“读源、写源、镜像、快照”四种语义。

### D2 分析与信号

缠论、九维选股、弱于板块、三线联动、KG PageRank/概念热度共同形成分析层。weak 产线的 SOP 最完整，适合抽取为其他业务域的标准模板。RiskGuard 仍需持续校准，不能把审计观察结果写成已解决结论。

### D3 决策与执行门禁

模拟仓、策略记分卡、影子验证、人审转正和审批凭据形成决策层。当前应严格区分 signal、decision、approval、execution，避免页面或报告把“建议”写成“已执行”。

### D4 Agent Platform

统一任务账本、幂等、审批、事件回放、证据仓、知识/Skill/使用账本和多业务域 wiring 已形成平台骨架。M0/M1/M2 验收资料是当前事实的重要组成，后续应以一个里程碑总索引替代跨文件搜索。

### D5 展示与交互

门户人类统一入口为 8734（portproxy → nginx）；8080 仅为容器/局域网反代链路。8091 为门户 API，8093 为组织注册表数据面，8791 为数据大屏，8787 为 Hermes。导航由 `DOMAIN_NAV_GROUPS → export_nav.py → static/nav.js` 生成。`/org` 已收编新版静态页，`/approvals` 已补齐 nginx 反代，当前导航扫描 77 个路径除 CowAgent 上游离线 502 外均可达。

### D6 运维与治理

计划任务、守护、日志、审计、工作区清理和迁移恢复构成治理层。最有价值的工程资产是判例记录：它们包含根因、修法、验证和预防。问题是判例入口分散，且旧环境路径和新环境路径偶有混用。

## 4. 文档问题分级

### P0：当前使用者找不到唯一事实

- 端口、数据根、启动方式分散在 README、计划文档、审计和脚本中。
- 历史复盘中的“已完成/待完成”可能与 2026-10-17 运行态不同。
- Hermes、8791、8093 缺少与门户同等粒度的当前运行手册。

### P1：材料重复但结论不一致

- 复盘报告、迁移报告、研发计划和验收报告均会重复描述同一组件。
- `docs/plans/` 以日期命名，读者难以知道哪个计划已 superseded。
- `quant_backtest/docs/ai_operator/phase*` 完整但缺跨阶段总入口。

### P2：历史证据未归档分层

- 旧路径、旧端口、旧服务状态仍出现在部分说明中。
- 历史草稿和交付物与当前运行文档混放。
- 不宜直接删除，必须先做引用/脚本依赖扫描。

## 5. 建议的文档目标结构

```text
docs/
├── PROJECT_DOCUMENTATION_INDEX.md       # 当前总索引
├── PROJECT_ARCHITECTURE_REVIEW_*.md    # 架构复盘
├── current/                            # 当前架构、端口、数据根、运行态快照
├── runbooks/                            # 故障与人工操作
├── audit/                               # 审计、验收、判例
├── plans/                               # 仍有效的计划
├── migration/                           # 换机/恢复证据
├── domains/                             # 按领域聚合入口
└── archive/                             # 明确 superseded 的历史材料
```

第一阶段只新增入口和索引，不搬移文件；第二阶段扫描依赖后再归档，避免破坏脚本链接和用户习惯。
