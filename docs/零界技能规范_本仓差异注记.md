## 二、两套「技能」不是一回事

| 维度 | 零界终端技能（本规范） | 本仓 Agent 工位技能 |
| --- | --- | --- |
| 分类 | 双轴自动推导：`trustLevel`（安全）× `pageEntry`（展示） | 按席位/工位归属组织，无 trustLevel 推导 |
| 入口 | `SKILL.md` frontmatter 含 `name` / `description`（40–300 字符）/ `page` / `api` / `tags` | `SKILL.md` 为主，无 `page:` / `api:` 声明 |
| 执行 | server spawn `python api.py`（stdlib only，30s / 8MB） | 主进程内 Python 模块、脚本、计划任务，依赖 pandas / parquet / xtcloud |
| 数据 | `skill-data/<companyId>/<skillId>/*.db`，只读 sqlite | 本地 parquet / SQLite / PostgreSQL，全局共享，无公司隔离 |
| 页面 | `html/index.html` 自包含、CSP sandbox、同源 fetch 数据桥 | nginx 静态页 + `/api/*` 动态 API，可引外部资源 |
| 挂载 | 系统自动出「打开页面 / 对话页 chip / 汇报首页卡片」 | 门户路由白名单 + 手动挂导航 |
| 汇报 | 四段式文本不变，页面是补充视图，不写链接 | 由各工位自行输出 |

**结论**：本仓 24 份 SKILL.md **不适用**本规范的三态分类与数据桥契约；不要拿 `agent_platform/skills/_template/` 当 `skills/stock-graph-analysis/` 用。

## 三、运行时链路对照

```
零界终端：  html/index.html --同源 fetch ../../api/*--> server spawn api.py
                                                      --只读 sqlite--> skill-data/*.db
                                                      <-- stdout JSON -- 页面渲染
            写入侧：Agent run 执行 ingest.py --------^

本仓 8091： jev_graph.html --/api/jev/graph--> portal_api.py（常驻进程）
                                              --pandas/parquet/xtcloud--> 数据仓
                                              <-- JSON ----------------- 页面渲染
            写入侧：tools/*_fetch.py 盘后快照 --------^
```

两者**形态相似、约束不同**：都是「采集层写、渲染层读」的物理隔离（与我们判例口径一致），
但零界的 `api.py` 是**每请求冷启动的 stdlib 只读脚本**，本仓 8091 是**常驻的胖 Python 进程**。
这是迁移时最大的一堵墙，不是换个 URL 就能过。

## 四、若把 JEV 页面做成自带页面型技能，必须先过的约束

| # | 约束 | 对 JEV 的影响 |
| --- | --- | --- |
| 1 | `api.py` **stdlib only**、30 秒、8MB | 现 `/api/jev/graph` 依赖 pandas / parquet / xtcloud，不能整体搬进 `api.py` |
| 2 | 只读 sqlite（`mode=ro`） | 需由 `ingest.py` 先把分钟/资金/社交/Δmin 快照**落成 `skill-data/*.db`**，页面只查库 |
| 3 | 页面自包含、禁外网 CDN、CSP sandbox | 现有 `jev_graph.html` 的外链 JS/CSS、顶层导航、弹窗、表单需逐项核查并内联/改造 |
| 4 | 数据按 `companyId/skillId` 隔离 | JEV 现为全局共享数据；多租户场景要按公司切库，口径（三旗标、两档覆盖率）需保持一致 |
| 5 | 页面 URL 走 `/api/companies/.../page/html/index.html` | 与现有 `http://127.0.0.1:8091/jev-graph` 不是同一入口，导航与分享链接要重做 |
| 6 | 包目录只读、数据不入库 | 快照文件不得写进技能包；沿用「采集器输出快照、渲染层只读」的分工 |

**建议**：先做「JEV 快照 → sqlite」的 `ingest.py` 原型并本地自测，页面改造排在其后；在 3100 终端位置确认前，**不动** 8091 现有页面与 `/api/jev/graph`。
