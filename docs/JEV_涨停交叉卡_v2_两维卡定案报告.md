## 一、这一版改了什么

| 项 | v1（四维平铺） | v2（两维主卡） |
|---|---|---|
| 卡面结构 | 四维一张表 | **主维（资金+席位）** 在前，**附表（时间+叙事）** 在后 |
| 验收指标 | ≥3 维"有值"率 | **`acceptance.verdict`**：pass / wait / fail |
| 已知率 | 当主指标用 | 只作附注，**必须与四态计数同行**，禁止单独引用 |
| 时间维缺失 | 拖累整张卡 | 不参与验收 |
| 盘中出卡 | 资金维判 `unavailable` → 全 fail | 当日未收盘判 `pending` → `wait` |

### 1.1 为什么两维是"定案"而不是"妥协"

四维平铺有个隐含假设：四维精度可比。实际不可比——

- **叙事维**的公告/研报**本身没有时分**，精度就是天。拿它参与验收，等于要求它做到
  它做不到的事。
- **时间维**在小票上缺失是采集层的结构问题，`jev_cross` 无权修。

主维两维都满足「收盘后必然可得」：`ts_moneyflow` 收盘终值、`ts_hm_detail` T+1 早间。
它们才是这张卡能稳定交付的部分。

### 1.2 验收三档（不拿百分比当结论）

| 档 | 条件 | 卡面写法 |
|---|---|---|
| `pass` | 主维全部 `ok`/`none` | **通过** |
| `wait` | 无 unavailable/partial，但有 `pending` | **等数据（T+1）** |
| `fail` | 主维出现 `unavailable` 或 `partial` | **不通过** |

`none`（确认无记录）算已知——「涨停但当天没上龙虎榜」是确认事实，不是缺数据。

## 二、实测（三个交易日，各 100 张卡）

| 交易日 | 主维通过 | 等数据 | 不通过 | 通过率 | 全四维已知率（仅参考） | 时间维 `ok` |
|---|---:|---:|---:|---:|---:|---:|
| 11-10 | 100 | 0 | 0 | **100%** | 75.5% | 2 / 100 |
| 11-11 | 100 | 0 | 0 | **100%** | 77.0% | 8 / 100 |
| 11-12 | 0 | 0 | 40 | **0%** | 1.2% | 0 / 40 |

11-12 全 fail 是**正确的**：当日 `flow` 与 `seat` 快照都没采，两维都 `unavailable`。
这一行是 verdict 有判别力的证据——如果换成"已知率"，11-12 会显示 1.2%，
和 11-10 的 75.5% 只是数字大小差别；而在 verdict 下，它是"全废卡"，需要立刻补采。

### 2.1 样卡（920157.BJ 宇特光电，+29.99%，北交所 30% 档）

```
| 验收（主维：资金+席位） | **通过**｜已知 2/2（100.0%） |
| 四态明细 | 有值 2 · 确认无 1 · 部分 0 · 待补 0 · 取不到 1（全四维，含附表） |

**主维**（参与验收）
| 资金 flow | 有 | eod | ts_moneyflow | main_net=-1824.0; net_mf=0.0; main_buy=3011.2; main_sell=4835.2 |
| 席位 seat | 有 | T+1 | ts_hm_detail | n_seats=3; seat_net=1439.5; by_group={inst=-371.4, geo=1516.8, persona=294.2} |

附表（**不参与验收**：精度天然低于主维）
| 时间 time | 取不到 | minute | stk_mins | — |
| 叙事 narrative | 无该票记录 | date | stock_notice/stock_report | — |
```

注意这张卡的两个细节：
- `net_mf=0.0` 是北交所无覆盖，note 明写「背离判不了」——**不把"不知道"写成"没背离"**；
- 席位 `top_buyer=思明南路` 是营业部名（L2 底线内），自然人指向已匿名化为 `PSN_hash`。

### 2.2 盘中：新增 `pending` 语义（为 11-16 接盘中准备）

`ts_moneyflow` 是收盘终值，盘中必然没有。原实现无快照就判 `unavailable` → fail，
盘中每一张卡都会 fail，而它们只是"还没到"。现在按 `_session_open()` 区分：

- 当日 + 未过 15:30 → `pending`，note「当日未收盘，收盘后重跑即有（不需要补采）」；
- 查历史日 → 仍 `unavailable`（已收盘还没有 = 真缺）。

盘中两维都是 `pending` → verdict = `wait`，不是 fail。

## 三、归因修正（推翻本报告 v1 的一个判断）

v1 写「本地 `stk_mins` 只覆盖中证800」。**这是错的**，本次逐票核对后修正：

本地有 **34,298 个月文件**，2026-11 的有 **1,100 只票**（全市场 5,500+，约 20%）。
对涨停/触板池逐票查「该日是否有分钟行」，是三层不同情况：

| 交易日 | 涨停池 | 有当日分钟 | 有月文件但缺当日 | 无月文件 |
|---|---:|---:|---:|---:|
| 11-06 | 52 | **39（75.0%）** | 1（1.9%） | 12（23.1%） |
| 11-10 | 118 | 4（3.4%） | 31（26.3%） | 83（70.3%） |
| 11-11 | 112 | 8（7.1%） | 24（21.4%） | 80（71.4%） |

三层含义完全不同：
1. **无月文件 ≈70%**：从没采过这只票（不在 1,100 只里）；
2. **有月文件缺当日 ≈21–26%**：采过、但月文件停在更早的日期（存量不同步）；
3. **11-06 的 75%**：证明采集能力本身存在。

**所以问题不是"小票采不到"，是"没有按日闭环"。** 这个区别决定处置方式：
不需要换数据源，需要一个日更任务 → `docs/需求单_小票分钟覆盖_采集工位_v1.md`。

### 3.1 远端兜底为什么救不了（已实测，不再重试）

`jev_mins_fetch --day 20261110 --limit 100`（188 秒）：

```
取数完成 98 只，{'merged': 1, 'already': 2, 'empty': 0, 'fail': 0,
                'partial_skip': 97, 'via_xtcloud': 1}
```

- `ts_stk_mins`：对当日涨停小票基本无存量（98 只成功 1 只）；
- `ts_rt_min`：237 根、缺 15:00 收盘那根，采集工具**刻意拒写**——这个拒写是对的，
  写进去会把残缺日固化成"已补齐"，尾盘封板会永久判错。

## 四、DoD 对照（新口径）

| 项 | 目标 | 实测 | 判定 |
|---|---|---|---|
| 主维通过率 | ≥95% | 11-10 **100%**、11-11 **100%** | **达成** |
| 主维不得有 `unavailable`/`partial` | 0 | 0 | 达成 |
| `pending` 显式标注不冒充数据 | 100% | 100%（席位 T+1） | 达成 |
| 附表时间维覆盖 | — | 2% / 8% | **不达，转需求单**（非本线可解） |
| 卡面只陈述不结论 | 0 处 | 0 处（门禁扫描 8 个词） | 达成 |

**关于"已知率 100%"**：11-10/11-11 的主维已知率也是 100%，但它**不作为验收结论**。
理由写在裁定 C 里，测试 `test_known_rate_alone_would_self_deceive` 给了反例：
「资金有值+席位待补」与「资金缺+席位有值」主维已知率都是 50%，
一个该等、一个该修，百分比分不开，verdict 分得开。

#40 的规避里写着「自然人指向不进任何文档」。写完这句，我按它扫了一遍全仓——
