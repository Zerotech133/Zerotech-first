> 依据：`docs/OSINT收集方法学习_2026-11-11.md`（C1 情报周期/PIR、收集矩阵），L3 落地（2026-11-11 老田批准）。
> 本表由 OSINT1（马良）维护**覆盖状态**；PIR 内容（情报需求本身）由 **A0／老田裁定定义**，INTEL0 马超只受理登记、不裁决（依据 `agent_platform/registry/org.json` 与 `agent_platform/hr/INTEL0/resume.yaml`）。

## 机制
- **PIR = 需要持续用开源情报回答的优先问题**；先于采集，决定"采什么、从哪采、看什么指示器"。
- 本席职责：登记 PIR、映射其到源与采集队列、维护覆盖状态；**不定义 PIR 内容**（内容裁定归 A0／老田，越界问题不碰）。
- 覆盖状态三档：**未覆盖 / 部分覆盖 / 已覆盖**（依据现有 OSINT 桥与采集队列判定）。
- 未来可扩展：PIR ↔ code 映射盘点（在 `strategy_picks_summary.py` 之上叠加，纯只读）。

## 源 ↔ PIR 覆盖盘点（只读现状，依据现有队列）
- **irm/sse 公司回复**：覆盖"公司自述类"PIR（计划/投产措辞）→ 已有 OSINT 桥（k_stock / 侯风 / 两池 / 缠论队列驱动）
- **淘股吧 / 雪球**：覆盖"市场传闻 / 情绪类"PIR → 同上三源采集器
- **新闻流 / 研报**：覆盖"公开报道 / 政策类"PIR → 由 `news_collector.py` 快讯管线覆盖
- **缺口提示**：PIR 一旦定义，若对应源未被现有队列覆盖，本席在覆盖状态标"未覆盖"并上报，不擅自扩源（扩源归上级裁定）。
