## 二、三源的实际接口（不是设计稿，是当前代码）

### 2.1 图谱（马钧 / 构建席 KGMAP1）

| 项 | 值 |
|---|---|
| 入口 | `portal/api_intel_graph.py` → `build_view()` → `GraphView.dossier(code)` |
| 模块位置 | `quant_backtest/intel_graph_view.py`（84 行）/ `intel_relation_rules.py` / `intel_seat_shadow.py` |
| 边来源 | ① `co_occurrence`：`ts_top_inst` **末 2 分区**席位两两共现（2,591 条）② `holding`：`tushare_curated/top10_holders.parquet` tail 300（300 条） |
| 实测规模 | 2,891 条边 / **134 只票** / 边类型仅 co_occurrence+holding |
| 每票边数 | 中位 10 条（41 只票），最多 15 条（12 只票） |
| 判定 | 全部 `candidate_only`，不落库不缓存，毫秒级合成 |

**断点（P1）**：`portal/api_intel_graph.py:13` 直接 `from intel_graph_view import GraphView`，
但模块在 `quant_backtest/` 下且未把该路径注入 `sys.path`。在 portal 目录里导入必失败：

```
ModuleNotFoundError: No module named 'intel_graph_view'
```

修法一行：在 `api_intel_graph.py` 顶部把 `parents[1]/quant_backtest` 插入 `sys.path`。
本次未改（属生产文件），桥接层自行注入了路径。

**覆盖窄的原因不是 bug，是口径**：只取末 2 分区席位 + 股东尾部 300 行，
本质是「最近两天上龙虎榜的票 + 最近公告十大股东的票」。要覆盖全市场，
需要放开分区数并改成分批流式，代价是响应时间从毫秒级升到秒级。

岗位定义写的是「把七个源头的数据拿回来」。实测落盘位置：

| 维 | 源 | 位置 | 覆盖（48 只 T2） | 性质 |

| D3 | 淘股吧 | `data/taoguba/<code>.jsonl` | 7/48（14.6%） | 定向队列 |
| D4 | 雪球定向 | `news_collector/data/xq_timeline/` | 6/48（12.5%） | 定向队列 |
| D5 | 千股千评 | `news_collector/data/qianping/qianping_<basis>.jsonl` | **44/48（91.7%）** | **全市场日快照 5,204 家** |

D5 未覆盖的 4 只全是北交所（920663/920504/920819/920964.BJ）——**源边界，不是漏采**。

D5 字段（这是本次最有价值的增量，之前完全没被消费）：

```

inst_part 机构参与度 / main_cost 主力成本 / dist_maincost 距主力成本 / turnover_pct 换手
```

### 2.3 因子（蒋琬 / FACTOR1）

| 项 | 值 |
|---|---|
| 日报 | `research/reports/factor_daily_<date>.json`，11-10 版：6 因子 + 2 衰减告警 |
| 日报因子 | `vol_20`(IC −0.1008, t −1.15, 四关 PASS) / `mom_20`(−0.0844) / `liq_neg`(0.0755 新候选) / `rev_5`(0.0586 **四关 FAIL**) / `amihud`(0.0491 新候选) / `mom_120`(−0.0402) |
| 计算库 | `tools/research/factor_lib.py`，**288 个因子**，`FACTORS[name].compute(panel)` |
| 本次取用 | `vol20` / `mom20` / `max_ret20` / `rev5`（前者 P67 已实测显著，后两者与日报同族） |
| 面板 | 5,598 只 × 85 天，基准日 20261110 |

**口径坑**：日报的因子名（`vol_20`/`mom_20`/`mom_120`）与 `factor_lib` 的 key（`vol20`/`mom20`）**不是同一套命名**，`mom120`、`turn20`、`amihud`、`liq_neg` 在 factor_lib 里**不存在**。桥接层只用 factor_lib 存在的 key，不做名字臆测映射。

## 三、覆盖率口径订正（重要）

`docs/策略中台选股池读取与OSINT覆盖对照_2026-11-11.md` 结论是「426 只信号池覆盖 129 只（30.3%）」。
本次实测证明：**这个 30% 是「四源定向队列覆盖率」，不是「OSINT 覆盖率」。**

48 只 T2 的对照：

| 算法 | 结果 |
|---|---|
| 只算 D1~D4（旧口径） | 有数据 9 只 → **18.8%** |
| 算满七维（新口径） | 有数据 **48 只 → 100%** |

差异原因：D1~D4 设计上是「定向监控队列」——只采持仓 + 近期 BUY 的票，
本来就不该覆盖全市场。而 D5/D6/D7 是全市场源，一直存在、一直没被算进覆盖率。

**这个口径错会直接误导决策**：按 30% 去补 297 只的四源采集，等于给一个
本来就不打算做全市场的定向队列提全市场要求；而真正该做的是把 D5/D6/D7
接进证据链——它们的边际成本接近零（已经采完了）。

读法（**只是观察，不是验证**，4 只票不构成统计证据）：

- 云南白药在千评里是全市场前 5%（267/5204）、关注度 92、机构参与 0.314，
  三个独立维度都指向「有人在看且在买」；因子侧是「极低波（2.1）+ 强动量（85.8）+ 近期回调（rev5 7.7）」。

- 招商公路千评 rank 1641（后 1/3）、机构参与 0.147，是全组最弱，与它「有形态没强度」的定性吻合。

## 六、用法

```bash
cd quant_backtest

# 单票/指定票
python intel_bridge.py --codes 000538.SZ,000429.SZ --basis 20261110

# 整份清单（按 tier）
python intel_bridge.py --from-picks ../portal/data/todays_picks.json \
    --tiers T1,T2 --basis 20261110 --out ../portal/data/evidence_cards.json
```

输出结构：`{code, verdict, graph{coverage,edges,top_edges}, osint{dims_hit,dims{7维各自},...}, factor{values_pct}}`。
`verdict` 四档：`full`（三源齐）/`partial`（两源）/`factor_only`（仅因子）/`none`。

**未命中一律写 `coverage: "miss"` + `reason`，不填 0、不填默认中值。**
