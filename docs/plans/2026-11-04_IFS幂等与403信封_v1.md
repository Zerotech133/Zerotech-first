## 一、G1：D1 写接口幂等重放

### 1.1 覆盖接口

| 接口 | 方法 | interface_id | 幂等范围 |
|---|---|---|---|
| `/api/d1/decision` | POST | `d1.decision.create` | 全部 create |
| `/api/d1/handoff` | POST | `d1.handoff.create` | `action_name=create/handoff`（ack 不受影响） |
| `/api/d1/meeting` | POST | `d1.meeting.create` | `action=create`（vote/finalize 不受影响） |

### 1.2 幂等键来源（优先级从高到低）

1. 请求头 `Idempotent-Key`
2. 请求头 `X-Idempotent-Key`
3. 请求头 `X-Request-Id`（仅当合法 `req-<32hex>`；非法则忽略、由 envelope 生成新 id）
4. 请求体 `idempotency_key` / `idempotent_key`
5. 请求体 `request_id`（仅当合法 `req-<32hex>`）

格式：`^[A-Za-z0-9][A-Za-z0-9._:-]{7,127}$`（8–128 位）。**显式键（1/2/4）非空但格式非法 → 400 `bad_idempotency_key`（fail-visible），不静默降级为无幂等。**

### 1.3 语义

- **同键重放**（HTTP 200）：
  - 不重复写账本；
  - 响应 = 首次结果 + `idempotent_replay=true` + `idempotency_key` + `original_request_id`（首次 request_id）；
  - 外层 envelope 重新生成当前请求的 `request_id`/`source`/`data`/`warnings`（旧顶层字段同样保留）；
- **同键不同请求体**（HTTP 409）：`idempotency_conflict`（error/v1 + error_detail.code=`conflict`），拒绝覆盖首次结果；
- **键缺失**：**完全保持现有行为**（无缓存、无新增字段、响应逐字节级兼容除 envelope 外不变）；
- **坏键**（HTTP 400）：`bad_idempotency_key`（error/v1 + `error_detail.code=invalid_parameter`）；
- 重放不改变 paper-only/`not_a_trade` 语义；无执行字段。

### 1.4 缓存实现（`portal/ifs_idempotency.py`）

- **进程内内存缓存**：不落盘、不联网、不写生产数据；`OrderedDict` LRU 上限 `MAX_ENTRIES=512`，TTL `TTL_S=6h`；
- 并发：按 `(interface_id, key)` 粒度锁串行化同键请求（check-then-write 原子），避免并发重复写；
- 请求体指纹（sha256 前 16 hex）用于同键不同体冲突检测；
- `request_id_for()` 同一请求内稳定（首次重放可追 `original_request_id`）；
- 进程重启后缓存失效（**已知限制**，见 §五接线项：后续单做持久化幂等存储）。

### 1.5 响应示例（重放）

```json
{
  "ok": true,
  "schema_version": "d1_decision/v1",
  "request_id": "req-<本次请求id>",
  "source": {"interface_id": "d1.decision.create", "...": "..."},
  "data": {"...首次结果副本 + idempotent_replay..."},
  "warnings": [],
  "decision": {"decision_id": "D1-20261104-xxxxxxxxxx"},
  "idempotent_replay": true,
  "idempotency_key": "decision-key-0001",
  "original_request_id": "req-<首次请求id>"
}
```

## 二、G2：403 鉴权失败统一 error/v1

三处 token 闸门（本机放行；反代/局域网需 `X-Portal-Token`）统一改走
`portal/ifs_envelope.py::auth_error()`：

1. `do_POST` 早分支变更端点（`_EARLY_TOKEN_PREFIXES`）；
2. `do_POST` 变更类 POST 闸门（`_MUTATION_POSTS`，含 D1 三个写接口）；
3. `do_GET` 动作端点闸门（`_ACTION_GETS`）。

响应（HTTP 403）：

```json
{
  "ok": false,
  "schema_version": "error/v1",
  "request_id": "req-<32hex>",
  "error": "forbidden: 缺失或不匹配的 X-Portal-Token（…原文案…）",
  "error_detail": {
    "code": "forbidden",
    "message": "…原文案…",
    "retryable": false,
    "details": {"legacy_code": "forbidden: …", "http_status": 403}
  },
  "warnings": []
}
```

- **旧 `error` 字符串逐字保留**（旧脚本/嵌入页面兼容）；新增 `error/v1 + request_id + error_detail`；
- `X-Request-Id` 响应头由 `Handler._json()` 回写（与 body.request_id 一致）；
- 未登记 interface 的闸门（非 D1 路径）不带 `source`，仍满足 error/v1。

## 三、兼容性

| 场景 | 迁移前 | 迁移后 |
|---|---|---|
| 无幂等键的写请求 | 原响应 | 完全不变（含旧字段/错误码/HTTP 状态） |
| 带幂等键首次写 | — | 原响应 + envelope（旧字段保留） |
| 带幂等键重放 | （会重复写） | 首次结果 + `idempotent_replay=true`，不重复写 |
| 403 鉴权失败 | `{"error": "forbidden: ..."}` | 旧 `error` 保留 + `ok/schema_version/request_id/error_detail/warnings` |
| 非 D1 写接口 | 原样 | 幂等逻辑不接管（仅 D1 三接口） |

## 五、接线项 / 已知限制

| # | 项 | 说明 |
|---|---|---|
| 1 | 幂等缓存持久化 | 当前进程内（LRU 512/TTL 6h），重启失效；后续单可落 `portal/data/` 专用 SQLite/Redis（需单独立单，避免写生产账本） |
| 2 | 前端幂等键传递 | 门户/脚本可在 POST 时带 `Idempotent-Key`（nginx 默认透传 header）；页面无需改造 |
| 3 | 其它写接口 | 幂等框架仅接 D1 三接口；`/api/sim/confirm` 等后续按需接入（各自幂等语义不同，需单独立单） |
| 4 | 分布式一致性 | 多进程/多实例部署时内存缓存不共享；当前单进程 8091 适用（持久化后解决） |
| 5 | 幂等键长度/字符 | 8–128 位 `[A-Za-z0-9._:-]`；如需其它格式调整 `KEY_PATTERN` 即可 |
