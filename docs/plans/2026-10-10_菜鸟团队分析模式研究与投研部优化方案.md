## 一、菜鸟团队分析模式还原（源码级+生产实证）

### 1.2 生产实证数据（十表挖掘）

- 辩论功能（ai_team）**仅试验 2 次（06-22/07-21）后停摆近 3 个月**——功能在，决策质量闭环没有，用户不用
- final_decision 唯一样本：SELL@自报置信 85，T+20 实际 **+23.1% 反向**——自报置信 ≠ 胜率，无校准机制
- 自动跟单 -24.22%；人工跟单胜率 29% **低于信号本身 36%**——链路末端的执行损耗吃掉信号价值

## 二、对照结论（谁该学谁）

| 维度 | 菜鸟 ai_team | 现投研部 | 裁决 |
|---|---|---|---|
| 结构化输出契约 | Schema 注入+Parser，强 | D1 靠正则 parse（N7：嵌套 JSON 不支持） | **学菜鸟**（P0） |
| 收敛判据 | 词频余弦单条件（坑3） | sim>0.8 单条件+双条件方案预写 | **两边都错，上双条件**（已排 10-15） |
| 置信度校准 | 无（坑4 实证反向） | conf-vs-ret 有计算、无常态报告 | **我们补上，形成差异化优势**（P0） |
| 立场记账 | 键名写死反转（坑1） | agent_id+phase | 保持 |
| 决策质量闭环 | 无 → 停摆 3 个月 | 三判据影子评估+校准包机制 | 保持，**这是投研部存在的核心理由** |
| 工具自取 | AGENT 模式生产实证「优于堆上下文」 | 全员静态 ctx 注入 | **学菜鸟**（P1，中期） |
| 降级韧性 | degraded 三态+NPE 隐患 | "[降级]"文本+硬ened | 保持 |
| 记忆/RBAC | 无（角色表只有人设） | 四级 namespace+RBAC | 我们独有，保持 |

## 三、优化方案（按优先级）

### P0-A 结构化输出契约（解禁日随校准包一并做，治 N7）
D1/T1/T2 的输出从「JSON 自由文本+正则解析」改为菜鸟式 Schema 硬约束：
- prompt 侧：明示字段与类型（已有雏形），关键在**解析侧**：interpreter 加 `parse_structured(text, schema)`——先 `json.loads`，失败剥 markdown 围栏再试，仍失败按字段级正则降级提取，全失败才记 parse_fail（当前 run_shadow.parse_decision 只有最后一级）
- 好处：嵌套 JSON 不再炸（N7 销案）、字段缺失显式化、D1 的 target_range 可校验 [低,高] 序

### P0-B 置信度校准闭环（差异化优势，10-15 后常态化）
菜鸟用 2162 条指令回填证明了「自报置信不可信」；我们已有同款数据管道（影子账本+后验收益），补最后一步：
- eval_shadow 加「conf 校准表」：按 conf 分桶 [0.4-0.5/0.5-0.6/0.6-0.7/0.7+]，各桶算实际胜率与均值收益 → 输出 reliability 曲线
- 挂进 A0 日报固定节（每周一频次足够）；桶内样本 <8 不出结论（防小样本误读）
- 校准结果反哺 B8：若 9b 的自报 conf 与胜率系统性脱钩（大概率），D1 契约的 conf 直接用「校准映射后的 conf'」而非原始自报值——**这是比「调分档锚点」更根本的 B8 解法**

### P0-C 收敛双条件（已排 10-15，本文档补菜鸟对照论据）
词频余弦（菜鸟）与字符 bigram（我们）对「立场塌缩」同样失明——B10 双条件（sim>0.8 **且** 双方立场仍对立）是两系统共同解。菜鸟 D3 源码 diff 若采纳，其 first_role 字段正好是我们 _stance() 的服务端版本，两边数据可互校。

### P1-A 工具自取模式（中期，参照菜鸟 AGENT 模式生产实证）
当前 N1/F1/D1 全员静态 ctx（quote_snapshot 注入）。分两步：
1. 近期：D1 ctx 从「全量行情文本」瘦身到「决策要素清单+数据指针」，正文数据靠 N1/F1 结论压缩——省 token 且逼分工
2. 中期：给 N1 挂工具自取（读 news.db 近 24h 情绪样本）、F1 挂财报指针——「工具自取优于上下文堆砌」直接抄作业；注意 9b 工具调用可靠性弱于 deepseek，须先过冒烟再换装

### P1-B 双引擎互证（利用云侧复活）
K-STOCK-084 后 typesafe 恢复。菜鸟侧若复活 ai_team（8.3-4 待决策），其 final_decision 可送我方 eval 管道做后验校准（8.3-5 建议的我方闭环方案）——两套团队分析共享一个校准基础设施，样本翻倍。

### P2 不做清单（防止范围蔓延）
- 不抄菜鸟五节点 Schema 全家桶（我们只有辩论+决策两类节点，五种是过度设计）
- 不做 is_parallel/wait_all_complete（我们拓扑天然串行，并行收益 < 复杂度成本）
- 不抢 ai_team 复活的编排位（菜鸟宿主定位不变，互证即可）
