# 交易员训练与上岗体系 v0.3
> STATUS: declared



日期：2026-10-09 ｜ 状态：已落地（引擎+管线+名册+测试全绿） ｜ 关联：K-STOCK 模拟仓 v0.3、K280 平台化

## 一、概念定位（用户拍板）

- **选股机器人 ≠ 交易员**。策略源回答「**买什么**」（AI 值班 / 量子双刀 / 青萍之末 → picks JSON）；
  交易员回答「**怎么买、买多少、何时卖**」（执行参数档案 + 独立子账本）。
- **交易员市场 × 策略市场正交组合**：同一条 picks 信号，不同交易员按各自档案处理，互不串味。
  新增交易员零引擎改动（一份 JSON 档案 + 一个子账本）。
- `main` 主交易台是基准（live）；训练员是「实习雇员」，将来像青萍之末的选股市场一样**可挑选、可雇佣**。

## 二、交易员档案（`k_stock/paper/trainees/*.json`）

| 字段 | 含义 |
|---|---|
| `id` / `name` / `style` / `desc` | 标识与风格说明（市场上架展示用） |
| `status` | `design`（论证中）→ `training`（模拟盘实习）→ `live`（上岗） |
| `initial_cash` | 子账本初始资金（独立核算） |
| `params.max_pos_pct` / `max_total_pct` | 单票/总仓风控上限（覆盖引擎默认，各户独立） |
| `params.stop_dist_pct` | 买入后自动挂止损的距离（成本锚定；已有止损不覆盖） |
| `params.conf_floor` | BUY 置信度门槛（引擎 `exec_run(min_conf=)` 过滤；SELL 不受限） |
| `graduation` | 毕业标准：`min_days` / `max_drawdown_pct` / `min_verify_pass_rate` / `bench` |

**现有三名**：

| id | 名 | 风格 | 单票 | 总仓 | 止损 | conf门槛 | 状态 |
|---|---|---|---|---|---|---|---|
| taishan | 稳如泰山 | 防守型 | ≤12% | ≤60% | -4% | ≥0.70 | training |
| chaser | 追风者 | 趋势型 | ≤16% | ≤90% | -8% | ≥0.60 | training |
| gunner | 快枪手 | 短线型 | ≤8% | ≤40% | -3% | ≥0.75 | design（T+1 短打可行性论证中） |

## 三、训练三级火箭

```
① 档案定义    trainees/*.json（执行参数 + 毕业标准）
② 模拟盘实习  同一条 picks run 落多个子账本（ref 按 @账户 分段互不冲突）
              每日 routine：settle → auto-stops（新仓挂初始止损）→ check-stops → mark
③ 验收上岗    board 对比 main 基准 → 达标改 status=live；live 期回撤失控 → 降回 training 复训
```

**每日例程**（与 main 主闭环同节奏，automation 07:05 主闭环后追加 `trainee.py routine`）：
子账本撮合昨日 pending → 按档案给新持仓挂止损 → 止损触发检查 → 权益快照（board 证据链）。

## 四、验收标准（graduation 执行口径）

1. 实习 ≥ `min_days`（20 个交易日，权益快照计数）
2. 区间最大回撤 ≤ `max_drawdown_pct`
3. 对账通过率 = `min_verify_pass_rate`（100%，资金链零差错）
4. 相对 `bench`（main 基准）累计收益超额 > 0（风险调整指标 Sharpe/Sortino 挂账 v0.4）
5. 上岗动作：档案 `status: training → live`；此后可参与「雇佣」（v0.4：把某策略源路由到其档案参数）
