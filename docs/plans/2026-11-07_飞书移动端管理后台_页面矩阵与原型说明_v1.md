## 0. 一页结论

飞书移动端分成**两个入口、两个职责**，不再混在一个 H5 里：

| 入口 | 使用者 | 职责 | 边界 |
|---|---|---|---|
| `/m/*` 业务投影（16 路由） | 订阅者、业务查看者 | 看简报、自选、持仓、情报、订阅等 | 只读投影 + 受控回写；不进入管理操作 |
| `/m/admin` 移动管理台（本文件） | OPS/审批人/审计员 | 推送、审批、目标、死信、通道、任务、审计 | 受管控制面；所有写操作走审批/决策账，不直接调 8097 |

本文件先冻结**页面矩阵、角色、数据源、写边界、分阶段**；原型 v0.1 覆盖 8 个一级模块、12 个页面，剩余详情页标为 v0.2，不假装已完成。

## 1. 定位与设计原则

### 1.1 定位

`/m/admin` 是零界 OS 的**移动管理控制面**，不是第二个业务后台：

- 移动端只负责“看状态、做审批、发起受控操作”，不复制业务数据、不做独立报表。
- 认证复用 portal token / 飞书卡片签名 token；权限复用现有角色，不新建一套权限系统。
- 所有状态来自 8097/8091 或权威文件；页面不持有第二份真源。
- 所有写操作：预览 → 记录 → 审批 → 执行；失败关闭（closed on failure）。
- 不连接 8097/8091 的 mock 原型不得产生任何副作用。

### 1.2 设计原则

1. **移动优先**：390px 为基准，360/430 不溢出；44px 触控高度；底部 5 tab。
2. **先判断后操作**：首屏是“今天是否正常、有什么待办”，不是数据大屏。
3. **风险前置**：危险操作二次确认；失败、降级、DOWN 用文字说清，不只靠颜色。
4. **可审计**：每个写动作显示“审批单号 / 决策账记录 / 证据等级”。
5. **不堆功能**：管理台只放 8 个一级模块；业务查看页留在 `/m`，不塞进底部导航。

## 2. 用户与角色

| 角色 | 典型人员 | 可看 | 可写 | 说明 |
|---|---|---|---|---|
| `ops_admin` | 田/OPS 负责人 | 全部模块 | 发起、审批、重试、配置变更（均走审批） | 最高权限；不绕过决策账 |
| `ops_operator` | OPS 值班 | 总览、推送、审批、目标、死信、任务 | 发起推送/重试/目标变更申请 | 不能改通道密钥、不能改设置 |
| `reviewer` | 审批人 | 审批、审计 | 通过/拒绝（按策略） | 只看与自己相关的审批 |
| `auditor` | 审计/风控 | 审计、证据、通道状态 | 只读、导出申请 | 不参与执行 |
| `subscriber` | 订阅客户 | `/m/*` 业务投影 | 无 | 不进入 `/m/admin` |

角色来源：portal 现有账号/角色；飞书卡片 token 只携带 `page=brief` 等最小权限，不携带管理员角色。管理员进入 `/m/admin` 仍需 portal 会话或短期管理 token。

## 5. 关键流程

### 5.1 推送

```text
选目标 → 选模板 → 预览卡片（不发） → 记录草稿 → 提交审批
→ reviewer 通过 → 8097 执行 → 证据回写 → 失败进死信
```

- 移动端不直接调用 `/api/send`；只调用“预览/记录/审批”接口。
- 预览必须显示：目标组、预计人数、模板版本、签名状态、预计发送时间。
- 失败关闭：任一步失败，状态为 failed，不自动重试。

### 5.2 审批

```text
申请 → 系统校验 → 待审批 → reviewer 通过/拒绝 → 生成已批准记录 → 执行闸
```

- 通过只生成“已批准”记录；执行仍由 8097/决策账按原闸门完成。
- 高风险审批（批量、客户域、密钥）要求二次确认 + 证据等级。
- 审批人不能审批自己发起的申请（四眼原则）；原型以提示占位，落码时强制。

### 5.3 死信重试

```text
死信 → 查看失败原因/证据 → 提报重试审批 → 通过 → redelivery → 成功/再次死信
```

- 重试也是一次推送，必须留原消息 ID、重试次数、幂等键。
- 不吞失败；再次失败仍进死信并计数。

### 5.4 目标与通道

- 目标变更走审批；`authorization.json` 为推荐唯一授权真源，`push_targets.json`/`push_subscribers.json` 只做投影。
- 通道配置（bot/路由/密钥）不由移动端直接改；只展示状态和申请入口。
- 8081 公网门 DOWN 时，移动端只在内网/本机 token 下使用；不启公网。

## 6. 数据与 API 契约（草案）

> 以下是页面所需字段，不是最终 API；落码前由 F2 通道契约冻结。

| 页面 | 读取 | 写入 | 关键字段 |
|---|---|---|---|
| 总览 | health/聚合 | 无 | success_rate、p95、dead_rate、pending_approvals、bots_online、recent |
| 推送列表 | 推送账本 | 无 | id、title、target、channel、status、owner、at |
| 推送详情 | 推送账本 | 重试申请 | id、status、sent/failed、timeline、evidence |
| 审批列表 | 决策账 | 无 | id、title、risk、status、requester、at |
| 审批详情 | 决策账 | approve/reject | policy、scope、evidence、timeline |
| 目标 | authorization | 变更申请 | group、owner、domains、count、quota、expires |
| 死信 | dead_letters | 重试申请 | id、reason、recipients、attempts、last_error |
| 通道 | feishu_registry/health | 配置申请 | port、status、bots、routes、heartbeat |
| 任务 | job manifest | 暂停/恢复申请 | name、schedule、next、owner、last |
| 审计 | 决策账/audit | 无 | action、actor、target、evidence、time |
| 设置 | env/session | 安全策略 | user、role、token_ttl、ports |

统一要求：

- 所有写请求带 `Idempotency-Key`、`actor`、`approval_id`、`evidence_level`。
- 错误码：`AUTH_REQUIRED`、`FORBIDDEN`、`VALIDATION_FAILED`、`APPROVAL_REQUIRED`、`GATE_CLOSED`、`CONFLICT`。
- 列表分页：`cursor` + `limit`；默认 20，最大 50。
- 不返回密钥、完整 token、收件人手机号；脱敏规则与 H5 一致。

## 7. 权限与写边界

1. **认证**：管理页必须 portal 会话或短期管理 token；飞书卡片 `t` 只证明“页面可看”，不证明“可管理”。
2. **授权**：角色校验在 BFF 做，页面隐藏按钮不等于授权；后端必须再校验。
3. **写操作**：只允许“申请/审批/重试”三类；不提供直接发送、直接改库、直接改配置。
4. **二次确认**：批量 >50 人、客户域、密钥轮换、暂停任务必须二次确认并写审计。
5. **越权**：任何角色都不能审批自己发起的申请；不能绕过 8081/8097/8091 闸门。
6. **数据最小化**：移动端不缓存敏感数据；退出/过期清理本地 token。

## 9. 验收与测试

### 9.1 原型验收

- 390×844 / 360×800 / 430×932 无横向溢出；底部 tab 固定且不遮挡内容。
- 8 模块/11 页面可点击；返回栈正确；无 JS error。
- 所有按钮：有反馈（toast/页面）或无操作说明，不出现死点击。
- 不发起网络请求；不生成真实 token；不写生产。

### 9.2 落码验收

- 路由进入 page manifest；`/m/admin` 不出现在业务 H5 底部导航。
- 未登录 401；无角色 403；越权审批 403；所有写操作有审计记录。
- 推送/审批/死信 E2E：预览→记录→审批→执行→证据；失败 closed。
- 目标单一真源：每个收件人可回溯授权行/过期时间。
- 8081 DOWN 时不开放公网；m_link disabled 时页面 token 不可用。
