# 从「数据仓学到的策略」到「选股能力」v1
> STATUS: pending_approval（路线图建议稿；MVP 排序未验证、/api 接线待批；owner: DSH/策略线；2026-11-01 W2 账本清零补标）



> 2026-11-01 · 目标：把研究台账里的结论变成**每日可运行、可回溯、可审批的选股能力**，而不是一次性报告。
> 现状：台账 36 条（backtested 6），但**没有一条以「选股清单」形态在产品中运行**。

## 一、先明确「选股能力」的定义

输入：日期 + 策略 id + 参数（top N、行业上限、风控阈值）
输出：**候选清单**（代码/名称/行业/分数/入选理由/触发因子/数据快照/风险标注/策略版本/证据链接）
并且必须同时具备：可回测、可监控、可审批、可回滚、可归因。

## 二、五层架构（S0–S5）

```
S0 策略注册与准入   策略 id/版本/来源假设/validation/weights/审批状态/有效期（strategy_registry）
S1 信号层（PIT）    因子计算：估值/质量/量价/资金/事件（数据仓：daily、daily_basic、fina、forecast、moneyflow、hk_hold、anns）
S2 打分与排序       规则型（H14 规避）/ 加权复合（动量+反转+拥挤）/ 事件型（H18 预告修订）
S3 组合约束与风控   行业≤3、ST/流动性/涨停过滤、单票上限、回撤熔断、停牌处理
S4 服务化          每日选股任务 → JSON → 门户 /selection.html / 只读 API / Agent 工具 / 飞书（需批）
S5 监控-归因-生命周期 影子盘净值/IC 跟踪/衰减告警/季度评审/下线归档
```

## 六、本轮 MVP（已跑通）

`tools/research/selection_engine.py`（v1.1）：
- **L1 过滤（已验证）**：ST/次新/低价/低流动性/涨停不可买；**H14 质量陷阱剔除**（高估值层 + ROE 层内前 20%）；ROE≤0 剔除；
- **L2 排序（未验证，MVP）**：动量20d 0.45 / 5日反转 0.25 / 低换手 0.20 / ROE 层内中性 0.10；
- **L3 约束**：每行业 ≤3，top 20；
- 输出 `research/reports/selection_mvp_<date>.json`（含 factors/weights/validation/disclaimer）。

实测 2026-10-30：输入 5,571 只 → 过滤后 2,585 只候选 → 20 只入选（行业分散，附分数与理由）。

## 八、服务化与接口（沿用 v1.1 契约）

- 每日任务：生成 `selection_<strategy>_<date>.json`（静态快照，零重启可读）；
- 门户：`/selection.html`（读静态 JSON，卡式展示 + 理由 + 风险标注）；
- Agent 工具：`selection_engine.py --date --strategy --top --json`（只读，输出统一信封可扩展）；
- HTTP：`/api/selection/today` 预留（与 KB Read API 同批接线审批）；
- 推送：选股日报接飞书（需确认时间/群）。

## 九、风险与红线

1. **MVP 排序因子未验证**：只作流程演示，不得当策略上线；
2. **H14 是规避非 alpha**：只做过滤/惩罚，禁止「买最低 ROE」；
3. **复权/停牌/PIT**：daily 未复权，需接 `adj_factor` 或改用复权价（P0 修）；
4. **容量/成本**：小市值+高换手组合容量有限，必须过成本/滑点评估；
5. **红线**：未过影子盘 + 人工批准 → 不得实盘、不得对外发布「荐股」。
