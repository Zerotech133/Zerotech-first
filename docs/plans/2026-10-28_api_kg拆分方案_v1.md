## 二、目标形态（3 层）

```
portal/kg/
  __init__.py                 # 导出 pages/service 的薄入口
  kg_pages_canvas.py          # canvas/canvas_v2 页面（~900 行）
  kg_pages_events.py          # events/doc/battle 页面（~900 行）
  kg_pages_misc.py            # ask/lexicon/flow/label/card/shadow/company/map/lineage 页面（~1,300 行）
  kg_service.py               # label/card save+diff、resonance 等数据逻辑（~500 行）
  kg_html.py                  # _cell/_href/_ago/pills 等 HTML 片段（~300 行）
api_kg.py                     # 瘦身为路由 mixin（目标 ≤1,200 行；只 import+委托）
```

- `api_kg.Handler` 保留为 mixin，方法体改为委托 `kg_pages_*`/`kg_service`；
- `portal_api.py` 的多继承与顶层 import **不改签名**（保持 `api_kg.Handler` 可导入）。

## 三、迁移步骤（每步一个工单，纯移动）

1. **契约测试先行**（P1，0.5 天）：对 5~6 个核心页面做 golden 断言（HTTP 200 + 关键 DOM id/片段 + 结构 hash），以及 `Handler` 方法集快照（`_mixin_integrity.py` 已保底）；
2. **抽 HTML 片段层**（0.5 天）：`kg_html.py`（`_cell/_href/_ago/pills` 等纯函数）——风险最低；
3. **抽 service 层**（0.5 天）：label/card save/diff/resonance；
4. **抽页面层**（1~2 天）：按 canvas / events+doc+battle / misc 三批迁 `_kg_*_page`，每批后跑 golden；
5. **收口**（0.5 天）：api_kg.py 只留路由方法；更新门禁基线（FROZEN 行数下调）；`tools/check_portal_split.py` 通过。

## 四、验收 / 回滚

- 验收：`api_kg.py ≤1,200`；`portal/tests` 291 绿；页面 golden 不变；`_mixin_integrity.py --check` 方法集零缺失；`check_portal_split` PASS；
- 回滚：每步单 commit，`git revert` 即回；页面层迁移可先"双份并存"再切换。

## 五、风险

| 风险 | 缓解 |
|---|---|
| 页面内联 JS/CSS 与 Python 变量耦合 | golden 断言 + 纯移动不改字符串 |
| 多继承方法解析顺序（MRO）变化 | 保持 `class Handler(...)` 继承顺序不变，只改方法归属 |
| 8091 常驻服务热改风险 | **不在服务运行时合并**；合并后按重启流程换血验证 |
| 并行会话改动 api_kg（今日已增长 5,841→5,912） | 拆分单需要短窗口 + 文件级互斥（公告板登记） |
