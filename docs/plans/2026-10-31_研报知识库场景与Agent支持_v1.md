## 二、使用场景清单（按 ROI 排序）
| # | 场景 | 用法 | 现状/成本 |
|---|---|---|---|
| 1 | **投研问答（带引用）** | 问行业/公司问题，答案必须带书名+页码；资料不足答「未覆盖」 | ✅ 立即可用（RAG 112/462） |
| 2 | **Agent 工具检索** | 其他 Agent 调 `kb_reports_search.py --query ... --json` 取 claim+出处 | ✅ 已实现（只读 CLI） |
| 3 | **假设生成器** | 知识单元 → 可测假设（数据映射+四关），进入 hypotheses 台账 | ✅ 流程已跑通（H24-H36，均 rejected 但流程可复用） |
| 4 | **研报观点抽取** | 提取评级/目标价/盈利预测/风险提示（title+context） | ⚠️ report_rc 已有 1.73M 条评级/预测（H34-H36 已测） |
| 5 | **行业链/主题图谱** | 从研报文本抽 公司-行业-概念-事件 关系 → 图谱（GraphRAG/LightRAG 思路） | 中期（需实体抽取+图谱） |
| 6 | **交叉验证/事实核验** | 公告/数据（我们已有 anns_pdf 2,614 份、news、financials）对照研报说法 | P1（数据齐） |
| 7 | **每日/每周研报简报** | 新研报→摘要+关键数字+与持仓/研究标的关联 | P1（可用学习卡/简报模板） |
| 8 | **学习卡/知识库课程** | 知识单元 → Q/A 卡、主题学习路径（每天 1-3 张） | ✅ 已实现（learning_cards.py） |
| 9 | **幻觉抑制/引用审计** | RAG 回答强制引用；抽检接地率（golden_spotcheck 99.4%） | ✅ 工具已备 |
| 10 | **因子/事件研究** | 研报覆盖度/评级变更/盈利上修 → 事件研究（H34-H36 已做，OOS-only 需 walk-forward） | 已有结论，继续需数据/方法改进 |
| 11 | **写作/公众号素材** | 结合 [研报] 生成科普/投研笔记（须人工审+引用） | P2（合规敏感） |
| 12 | **合规/PII 检查** | 入库前脱敏、引用可追溯、版权内部使用 | ✅ 标准已含 |

## 三、对 Agent 的支持（接口设计）
| 方式 | 说明 |
|---|---|
| **工具注册** | `agent_platform/registry/skill_registry.json` 登记 `kb_reports_search`（kind=tool，ref=`tools/kb_corpus/kb_reports_search.py`） |
| 调用协议 | `python tools/kb_corpus/kb_reports_search.py --query "主题" --top 8 --json`，输出 JSON（book/chapter/pages/concept/claim/evidence/score） |
| 使用纪律 | 回答必须带出处；证据不足答未覆盖；知识单元为 LLM 抽取，重大结论需人工对照原文 |
| 扩展 | 未来可加 MCP server 包装（[agent-library](https://pypi.org/project/agent-library/) 思路）或门户 `/api/kb_reports/ask`（需 8091 重启） |

## 四、变成人类可学习的知识
| 产物 | 说明 |
|---|---|
| 学习卡 | 每日 N 张 Q/A + 出处页码 → `C:/项目/知识库/60_学习卡/cards_YYYYMMDD.md` + 门户 JSON |
| 主题路径 | 按 concept 聚类成「量学/研报方法论/行业研究」学习路径（后续可生成） |
