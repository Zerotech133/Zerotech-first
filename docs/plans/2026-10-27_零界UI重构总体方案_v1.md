## 0. 一句话方案

把「按工具平铺的 89 个入口」重构为 **「1 个今日工作台 + 5 个领域驾驶舱 + 3 条横向能力（命令/证据/告警）」**，
每条业务都用**统一实体链**（日期→标的/信号→任务/决策→证据→报告→复盘）串起来；
页面从「终点页」变成「链路节点」，导航从「目录」变成「任务起点」。

## 1. 对系统的整体理解

### 1.1 系统是什么

零界不是普通后台，而是**一个人的 AI 公司 / 个人 OS**：

- 人类入口：8734（nginx → 容器内静态门户 + 8091 反代），只有一个入口；
- API/服务：8091 门户 API、8795 LLM 网关、8796 军团命令、各领域计算/数据服务；
- 角色：老田（A0）是唯一决策者；AI 席位/军团 Agent 提供建议、执行与回报，**零执行权在建议面**；
- 资产：量化信号/回测/持仓、情报/知识图谱、内容草稿、研发工单/审计、审批/决策、证据包；
- 数据落盘：`work/`（运行态）、`docs/`（判例/计划）、`portal/data/`（账本）、任务/事件层。

### 1.2 当前前端规模（实测）

| 维度 | 数值 |
|---|---|
| 导航域（top sections） | **5**（量化/情报/创作/研发/运维） |
| 导航入口 | **89**（88 个不同路由，`/org` 在两个域重复） |
| 普通静态页 | 63 页带统一顶栏；5 个定型页自带导航 |
| 量化入口 | **42**（5 组，策略资产单组 14 个） |
| 情报入口 | **27**（知识图谱单组 13 个） |
| 运维入口 | 15；创作 3；研发 2 |
| 外部/未接入口 | CowAgent/智策 OS 等 external、多个 🚧 软链 |

### 1.3 页面类型（按角色）

| 类型 | 例子 | 现状问题 |
|---|---|---|
| 入口首页 | `/os-entry`、`/os-board` | 信息多但缺少「任务/证据」主线 |
| 域驾驶舱 | `/quant-drill`、`/intel`、`/dev`、`/ops`、`/creator` | 指标堆叠、入口列表化 |
| 工作台（操作） | `/premarket`、`/picks.html`、`/bt-signals`、`/paper`、`/afterhours` | 相互跳转靠人工记忆，不带上下文 |
| 分析/明细 | `/sa`、`/bt-*`、`/kg/*`、`/audit` | 同一标/任务无法从 A 页带到 B 页 |
| 工具/系统 | `/ops`、`/sys-health`、`/dashboard`、`/approvals` | 与业务链脱节，只在故障时被想起 |

## 2. 对研发计划的解读

### 2.1 能力底座（P0/P1）与 UI 的关系

| 计划 | 已完成 | 对 UI 的要求 |
|---|---|---|
| P0-1 MCP / P0-2/3 证据 / P0-4 评估 / P0-5 护栏 | ✅ | 证据包/引用/来源分级应成为 UI 的「证据抽屉」，不是后台日志 |
| P0-6 Phoenix | 🟡 | trace 要能在页面「查看链路」里打开 |
| P1-1 L5 引用 grounding | ✅ | 咨询卡必须显示来源，不能只给结论 |
| P1-2 BM25 M1 | ✅ 观察中 | 检索质量/延迟属于系统状态，应进「运维/系统」而非业务页 |
| P1-3 memory v0 | ✅ 未启用 | 记忆命中/不使用要在咨询/复盘页可解释 |
| P1-4 决策记录 / C1 / C3 | ✅ | `decision_id`/`card_id`/`adoption_id` 必须贯穿页面，形成「建议→决策→采纳→复盘」链 |
| 观察期/11-03 | ⏳ | 不阻塞 UI 方案；新 UI 必须给观察指标留位置（检索命中/延迟/异常） |

### 2.2 UI/UX W1–W4（已完成）给本次重构的资产

- W1：tokens + nav.css + 焦点/动效；
- W2：状态模板 + OS 页色彩收敛 + skip link；
- W3：命令面板 + 密度 + 键盘审计 + 真机 CDP；
- W4：视觉基线、warn-only UI 审计门、A11y 清单。

**结论**：底座够用，下一步不是继续「美化单页」，而是**信息架构与页面联动**。

## 3. 当前 UI 为什么「线路不清晰、链条不明确」

| # | 症状 | 证据 | 根因 |
|---|---|---|---|
| 1 | 导航像工具目录 | 89 入口/42 量化/14 策略资产 | 按系统模块建导航，不按用户任务 |
| 2 | 页面之间没有上下文 | 路由基本不带 `symbol/date/task/trace` | 无实体 ID 传递规范 |
| 3 | 同一实体多页重复 | `/org` 两处；`/bt-*` 多入口；外部 localhost 链接 | 没有 canonical route/去重 |
| 4 | 首页只做汇总 | `/os-entry` 是指标/卡片，不是「今天做什么」 | 缺少任务队列与下一步行动 |
| 5 | 领域互相绝缘 | 量化信号不会链到情报/研发；审计只在 ops | 无跨域旅程设计 |
| 6 | 结果无法追溯 | 报告/通知/采纳无统一证据入口 | 证据/决策/采纳没有 UI 主链 |
| 7 | 维护成本高 | 单文件页、页面间复制、不同状态样式 | 缺页面模板/组件层（W1-W4 已打底） |

## 4. 目标信息架构：1 + 5 + 3

```
┌──────────────────────────────────────────────────────────────┐
│ 顶部：今日 | 量化 | 情报 | 创作 | 研发 | 运维         ⌘K 搜索 │
├──────────────────────────────────────────────────────────────┤
│ 1 今日工作台（L0）                                            │
│   今日建议 / 待决策 / 风险告警 / 我的任务 / 最近证据 / 复盘待办 │
├────────────── 5 个领域驾驶舱（L1） ───────────────────────────┤
│ 量化驾驶舱 | 情报驾驶舱 | 创作驾驶舱 | 研发驾驶舱 | 运维驾驶舱 │
│  每个驾驶舱 = 今日队列 + 核心链路 + 最近结果/异常 + 证据入口   │
├────────────── 3 条横向能力（L2 页面共用） ────────────────────┤
│ ① 命令/搜索：全部 89 入口与实体（⌘K）                          │
│ ② 证据/链路：source → evidence → decision → adoption → review │
│ ③ 告警/审批：风险/通知/审批/审计统一进出                        │
└──────────────────────────────────────────────────────────────┘
```

### 4.1 页面层级

- **L0 今日工作台**（`/os-entry` 重构为 `/today`，旧路由 301 保留）
- **L1 领域驾驶舱**：每域一页（`/quant`、`/intel`、`/creator`、`/dev`、`/ops`）
- **L2 任务工作台**：预演/选股/信号/持仓/复盘；情报流/JEV/KG；创作；研发任务；运维健康
- **L3 明细/证据/详情**：个股、事件、任务、决策、审批、审计、报告
- **横向页**：命令面板、全局搜索、证据抽屉、告警中心、审批中心

> 旧 URL 不做大迁移；先做「新壳 + 旧页嵌入」，逐页替换。

### 4.2 导航规则

1. 顶部固定 6 个：今日 + 5 域；其余进 ⌘K 或领域侧栏；
2. 每个领域最多 **5 个任务组**、每组 ≤7 项；超出的进「更多」或搜索；
3. 当前页高亮 + 面包屑（今日 / 量化 / 盘前 / 个股 605100）；
4. 所有旧入口从「目录」迁到 **命令面板索引**（100% 覆盖 89 入口）；
5. 外部 localhost 链接统一收进「系统入口」分组，并标注「外部」。

### 4.3 今日工作台（首页重设计）

| 区域 | 内容 | 主要联动 |
|---|---|---|
| ① 今日建议 | 诸葛亮规则建议/P1 决策，最多 5 条 | 点击 → 领域工作台（带 `suggestion/decision_id`） |
| ② 待我决策 | C1 质询卡、approval、通知待确认 | → `/approvals`、`/audit`、决策详情 |
| ③ 风险/告警 | 数据锚/任务失败/护栏 | → `/sys-health`、`/audit`、领域页 |
| ④ 我的任务 | 今日 doing/到期工单 | → `/dev`/任务详情 |
| ⑤ 最近证据/结果 | 报告/通知/采纳回填 | → 证据抽屉/报告页 |
| ⑥ 复盘待办 | review-due 决策/日报 | → 决策/复盘 |

## 5. 实体链与跨页联动规范

### 5.1 统一实体 ID

| ID | 产生 | 展示页 | 下游 |
|---|---|---|---|
| `date` | 业务日 | 所有量化/情报/报告 | 页面上下文 |
| `symbol/code` | 选股/个股 | `/picks`, `/sa`, `/paper`, `/bt-report` | 信号/持仓/复盘 |
| `signal_id` | 信号 | `/bt-signals` | 个股/模拟仓/复盘 |
| `strategy_id/backtest_id` | 策略/回测 | `/strategies`, `/bt-opt` | 报告/决策 |
| `task_id`（TID） | 任务/工单 | `/dev`, `/approvals`, `/audit` | 证据/决策/复盘 |
| `trace_id` | 执行 | `/sys-health`, `/ops`, 通知 | 证据/审计 |
| `report_id` | 报告 | `/bt-report`, `/intel`, 通知 | 复盘 |
| `decision_id`（DR） | 决策 | `/today`, `/audit`, 建议卡 | 采纳/复盘 |
| `card_id`（ZQ） | C1 质询 | `/audit`, `/today` | 决策/整改 |
| `adoption_id`（C3） | 采纳 | 决策/建议卡 | 复盘/趋势 |
| `evidence_id` | 证据包 | 所有详情 | 证据抽屉/审计 |
| `approval_id` | 审批 | `/approvals` | 任务/审计 |

### 5.2 URL 上下文约定（不破坏旧路由）

```
?date=2026-10-27&symbol=605100&signal_id=S-...&task_id=WO-...&trace_id=...&decision_id=DR-...
&from=/premarket        # 返回链路
```

页面加载时读上下文 → 高亮/筛选 → 写「链路条」；不自动执行任何动作。

### 5.3 五条标准旅程（页面联动主干）

**A. 每日开盘（量化）**
```
/today → /quant（驾驶舱）
  → /premarket（盘前）→ /picks.html（今日选股）
  → /bt-signals（信号）→ /sa?symbol=…（个股）→ /paper（模拟仓）
  → /sellpoint（卖点）→ /afterhours（盘后）→ /bt-report?date=…（报告）
  → /today（复盘待办/证据）
```

**B. 情报到动作（情报）**
```
/today → /intel → /intel/stream → /bt-jev → /kg/events?entity=…
  → /push/ 或 /notify-command（订阅/通知）
  → /audit（证据/判断）→ /today
```

**C. 研发到交付（研发）**
```
/today（我的任务）→ /dev → 任务详情 → /approvals（审批）
  → /audit（审计/证据）→ /today（结果/复盘）
```

**D. 系统异常（运维）**
```
/today（风险）→ /sys-health → /ops（控制台）
  → /audit（证据）→ /approvals（如涉及）→ /today（关闭/复盘）
```

**E. 建议到采纳（横向）**
```
建议卡（decision_id/card_id）→ 决策记录 → 领域执行页（task/trace）
  → 结果/证据 → C3 采纳（adoption_id）→ 决策复盘
```

### 5.4 全量页面联动矩阵

- 89 个入口全部逐条列出：**领域/分组/页面/路由/层级/上游/下游/关键ID/备注**；
- 见 [2026-10-27_前端页面联动矩阵.md](2026-10-27_前端页面联动矩阵.md) / `.csv`；
- 矩阵是**方案基线**：后续页面改造按矩阵补 `from`/实体参数，并补测试。

## 7. 视觉与组件规范

- 沿用 W1-W4：tokens.css、nav.css、ui_states.css、ui_palette.css/js；
- 新增页面模板：
  - `PageShell`：顶栏/面包屑/标题/链路条/主区/证据抽屉；
  - `EntityHeader`：标的/任务/决策统一头部（ID/状态/来源/时间）；
  - `ChainBar`：`来源 → 判断 → 决策 → 执行 → 结果 → 复盘` 可点击；
  - `EvidenceDrawer`：来源/引用/证据包/trace；
  - `StatusTile`：红/黄/绿语义 + 文字（禁止只靠颜色）；
  - `Empty/Loading/Error`：复用 W2；
  - `CommandPalette`：W3 已就绪，扩展到全部 89 入口与实体搜索。
- 密度/焦点/动效/对比度/A11y 按 W4 清单执行；
- 图表/表格遵守 Grafana 原则：一屏回答一个问题、层级下钻、避免仪表盘蔓延。

## 8. 分阶段实施方案（建议 4 周）

| 阶段 | 时间 | 交付 | 验收 |
|---|---|---|---|
| **P0 路由/ID 基线** | 2 天 | 89 入口 canonical 表、重复/外链清单、上下文参数约定、旧路由 301 名单 | 矩阵 CSV 定稿；`/org` 去重；命令面板可索引 89 入口 |
| **W1 新壳 + 今日** | 1 周 | 顶部 6 项导航、面包屑、链路条、今日工作台（读现有 API） | 首页可在 3 次点击内到达任一域；skip/focus/palette 真机通过 |
| **W2 量化主线** | 1 周 | 量化驾驶舱 + 盘前→选股→信号→持仓→复盘 5 页带上下文 | 旅程 A 全程 `date/symbol/signal_id` 不丢；无死链 |
| **W3 情报/研发/运维** | 1 周 | 三个驾驶舱 + 证据抽屉 + 告警/审批入口 | 旅程 B/C/D 贯通；证据可回到来源 |
| **W4 全量收口** | 1 周 | 其余页面嵌入/重定向、全局搜索、视觉基线更新、A11y/UI 审计门 | 89 入口 100% 可达；warn=0；视觉基线更新 |

**原则**：先壳后页、先主线后长尾、旧 URL 保留、逐页替换、每阶段可回滚；不引入新前端框架（继续静态页 + 原生 JS + tokens），避免一次性大迁移风险。

## 9. 度量与验收

- 任务时间：从 `/today` 到目标页面/动作 ≤3 次点击、≤60 秒；
- 联动覆盖：矩阵中「下游」链接覆盖率 ≥90%；死链 0；
- 上下文完整：量化旅程 `date/symbol/signal_id` 在 5 页间保留率 100%；
- 可发现性：⌘K 覆盖 89/89 入口；用户不用记 URL；
- 可访问性：skip 第一、focus 可见、A11y 清单过、UI 审计 warn=0；
- 可维护性：页面模板复用率、单页重复样式下降、视觉基线稳定。

---

## 10. 风险与需拍板的决策

1. **范围**：先做「1+5」主壳，还是先做量化主线？建议先壳+今日，再量化。
2. **首页定义**：`/os-entry` 改名 `/today` 并保留旧路由，是否接受？
3. **导航层级**：顶栏 6 项（今日+5 域）是否最终定稿？
4. **旧页处理**：长尾页先嵌入/重定向还是原样保留？建议保留可访问，逐步替换。
5. **页面 owner**：量化/情报/研发各页改造需要领域 owner 验收，不能只 UI 改。
6. **数据可用性**：实体链依赖 `signal_id/task_id/decision_id` 在 URL/API 中存在；缺的先用 `date/symbol` 兜底。
