## 三、要素③：不可逆点

1. **飞书 bot 断线期消息不补推**：WebSocket 长连接模式下，断开期间飞书侧事件不重投。若期间有客户发「开通」类指令，该条丢失，无人知晓、无回执。→ 建议避开商务沟通时段，或由老田指定窗口。
2. **8091 重启期间若有进行中的写事务**（订阅账本 sqlite），被强杀可能残留未提交事务。风险低（当前 observe 模式写入极少），但不可回滚。
3. **8787 static 目录无版本控制**：一旦重启后新进程读取到损坏文件，只能靠步骤 0 的物理备份恢复。
4. **marker 文件一次性自毁**：若在 marker 被消费前重复创建，可能触发两次换血；执行中不得重复 touch。

## 五、要素⑤：回滚预案

### 回滚原则（重要，勿用 `git checkout` 整目录）

工作树当前有 50+ 个他方在途改动（`portal/api_legion_ops_v2.py`、`portal/legion.html`、量化链多文件等）。**禁止 `git checkout <commit> -- portal/` 或 `git reset --hard`**——那会连带抹掉其他工位未提交的工作，违反多工位互斥协议。

### 分级回滚

| 失败点 | 回滚动作 | 恢复时间 |
|---|---|---|
| nginx 起不来 | `Copy-Item C:\Temp\feishu_pre_restart_20261020\nginx.conf C:\项目\老田的AI助手\portal\nginx.conf -Force` → `docker exec ai-portal nginx -s reload` | <1min |
| 8787 起不来 | `Copy-Item C:\Temp\feishu_pre_restart_20261020\static ... -Recurse -Force` → 再 `schtasks /run /tn "HermesWebUI-Guard"`；期间走 8788 | 2min |
| 8091/8097/bot 起不来 | 直接重跑一次对应步骤（代码未变动，重启不改变版本）；仍失败则回退代码 |
| 新代码有 bug 需回退 | `git log --oneline --grep="FB-\|FC-\|FD-\|FE-\|G-A\|G-B\|H-A\|H-B\|H-C\|J-A\|J-B\|J-C\|K-A\|K-B" ac28be7a^..HEAD` 取清单 → `git revert --no-commit <逐笔>` → 单独 commit → 重跑步骤 1-5 | 15~30min |
| 全盘失败 | 保留老田决策：维持旧服务继续跑（旧进程未被代码变更影响，因为服务是进程内加载），直到下一次窗口 | 立即 |

**关键事实**：服务重启前，磁盘代码再新也不影响在役进程。所以「不重启 = 零风险」，任何时候不批准都不会恶化现状。
