# 上半：JEV 能力账本 v2

## 〇、定位（钉死，不再摇摆）

### JEV 是什么

> **JEV = OSINT 多维信号收集 + pattern 识别 + 演化推演引擎**。
> 不是预测器（不做"这只票明天涨不涨"的单点判断），
> 不是荐股（不做买卖决策），
> 不是爬虫（只读快照）。
>
> **JEV 做的事**：收集资金、社交、结构、时间等多维度信号 → 识别异常组合 pattern（比如"主力接而全档逃 + 散户追捧 + 雪球机构沉默 + 消息追认"）→ 查历史案例库 → 推演出这条因果链在历史上曾走到了哪些分支、各自概率多少、哪些信号节点会触发分化 → 给出推演结论和观察节点。

### JEV 不做什么

- ❌ 爬虫 / 数据采集（红线：采集是下属工位，JEV 只读快照）
- ❌ 荐股 / 买卖点 / 组合管理
- ❌ 实时盯盘告警（属 RiskGuard / 盯盘机器人）
- ❌ 无条件单点预测（"这只票 3 天后回落"）—— 这是预测器的事，推演引擎只做"当 pattern X 出现时，历史上的演化路径分布"

### 为什么之前的验证"lift ≈ 0"是方法错了，不是方向错了

| 之前的错误假设 | 正确的理解 |
|---|---|
| 把 JEV 当预测器考核（lift = 判伪后 3 天回落率 vs 基线） | JEV 是推演引擎，考核指标是 **pattern 覆盖率 × 演化路径概率分化度** |
| 只测了资金背离单个维度 | 11-06 判例是**三个维度组合**同时命中的 pattern（主力接而全档逃 + 散户追捧 + 雪球机构无视），单维度 lift≈0 不代表组合 pattern 没信号 |
| 结构维度只有 52/725 有值 | 三维度事实上退化成了单维度测试，结论根本不成立 |
| 没 Δmin 时间维度 | "价格先行 vs 消息追认"是推演因果方向的核心（谁先动、谁追认），缺了等于用半只眼睛看 |
| 验证器指标错了 | "3 天后回落率"是单点对错；推演关心的是 **pattern 出现后，历史上有多少种演化路径、各自概率多少、在哪分化** |

### 2.3 11-06 判例的再定性

11-06 那次（股吧散户追捧 + 雪球机构无视 + 主力接而全档逃 + 消息追认 → 散户接盘、涨得不实）是 **JEV 推演引擎的一次原型验证**：
- ✅ 多维信号组合识别到了一个 pattern（"散户接盘型"）
- ✅ 事后推演这个 pattern 的演化路径是"回落"——实际也确实回落了
- ❌ 但**没有大规模验证**这个 pattern 在历史上的普适性
- ❌ 资金背离 lift +1.1% ≈ 0 的结论是**单维度测试**，完全不能用来否定组合 pattern

**正确的推断**：
- 11-06 判例有效 → 说明 JEV 的推演逻辑方向是对的
- 大规模单维度 lift ≈ 0 → 说明**必须补完缺失的维度（Δmin + 社交历史）、跑组合 pattern 回测**，才能得到真正的结论
- 当前状态 = 推演引擎的**原型已验证、大规模未验证**

## 四、验证器重设计（从 lift 考核 → 推演能力考核）

> 原验证器考核"lift = 判伪后回落率 vs 基线"——这是把 JEV 当预测器。
> 新验证器考核"推演能力"——pattern 覆盖率 × 演化路径概率分化度。

### 原验证器（弃用）
- `jev_validator.py` 跑 triangulation / money_only 模式
- 输出："判伪集合 N 日回落率 vs 全涨停基线 → lift"
- 问题：考核单点对错，不考核推演能力；且数据不全（结构维度 52/725、社交历史 0），结论本身就不成立

### 新验证器（需实现）

**考核指标**（两个维度）：

| 指标 | 定义 | 合格线 | 说明 |
|---|---|---|---|
| **pattern 覆盖率** | 5000+ 只涨停样本中，被至少一个 pattern 命中的比例 | ≥ 60% | 低于 30% 说明 pattern 定义太窄或信号维度不够 |
| **演化路径概率分化度** | 每个 pattern 下，最大分支路径概率 − 次大分支路径概率（pp） | ≥ 20pp | 低于 5pp 说明所有路径概率差不多，推演无价值 |
| **分化节点密度** | 有多少个 pattern 存在明确的信号分化节点（比如"Δmin > 60 分钟时，路径 A 概率从 80% 降到 40%"） | 至少 3 个有分化节点的 pattern | 无分化节点 → 推演只能给一个平均结论，不具备实战价值 |

**验证流程**：
```
1. 补完 Δmin 时间维度 + 社交历史快照 → 凑齐三维度 + Δmin 信号
2. 枚举 5-10 个候选组合 pattern（从判例中提取）
3. 对 5000+ 只涨停样本跑 pattern matcher → 每个 pattern 的命中率
4. 统计每个 pattern 下各票的后续演化 → 路径分布 + 分化节点
5. 输出覆盖率 / 分化度 / 分化节点密度 → 与合格线对比
```

**首轮已跑但无效的报告**（方法错了，结论作废）：
- `quant_backtest/reports/jev_validator_20261110_money_only.{json,md}` — money_only 3 日 lift +1.1% ≈ 0，**单维度测试，作废**

## 六、判定闸（推演引擎能力收敛的触发条件）

> 这不是"停止投入"，而是"正式钉死 JEV 是什么 / 不是什么"——一旦触发，定位写死，不再摇摆。
> **核心思想**：推演引擎的价值 = pattern 能覆盖多少场景 × 覆盖到的场景能不能分化出有概率差的路径。

### 闸位 A：推演引擎成立（通过 → 继续深化）

**三条同时满足**：
1. Δmin 时间维度可用性扫描通过（至少 30% 样本有分钟级时间戳）
2. 三维度 + Δmin 组合后，**pattern 覆盖率 ≥ 60%**（5000+ 只中被至少一个 pattern 命中）
3. 至少 **3 个 pattern 存在明确的演化路径分化**（最大分支概率 − 次大分支 ≥ 20pp，且有信号触发分化节点）

**通过后的动作**：
- JEV 正式定为"OSINT 多维信号推演引擎"
- 深化 pattern 库（从 5-10 个扩展到 20-30 个）、接入更多维度、上线推演 API

### 闸位 B：推演引擎收敛为"语义层方向因子"（不通过 → 收敛）

**任意一条满足**：
1. Δmin 可用性扫描失败（分钟级时间戳覆盖率 < 10%，或 stk_mins 数据不可用）
2. 三维度 + Δmin 组合后，**pattern 覆盖率 < 30%**（大部分样本无法被任何 pattern 命中）
3. 所有 pattern 下**演化路径概率分化度 < 5pp**（所有路径差不多，推演不出来东西）

**触发后的动作**：
- JEV 正式收敛为"**语义层方向因子 + 多维信号只读工具**"
- 语义层方向解读（52.5% 准确率的弱信号）保留作为组合级因子
- 三维度信号收集保留作为 OSINT 工具
- **pattern 推演引擎放弃**，不再投入相关研发

### 闸位状态
**条件①（Δmin 可用性）已满足**（2026-11-10 扫描：新闻真实分钟级 81%、价格活源覆盖到 2026-11）；条件②③待阶段 P 完成后（P6）评估。
