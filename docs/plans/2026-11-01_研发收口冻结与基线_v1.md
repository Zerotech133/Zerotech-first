## 1. 五步执行

### 第 1 步：18:00 起停止新开 worktree/新并行单

```text
禁止：
  devtask.py new（新 worktree/分支）
  新 Team 任务/新 teammate/新并行开发单
  非 P0 的新功能开发
允许：
  已有分支提交/合并/回滚
  P0 修复（需 Lead 明示）
```

### 第 2 步：18:00–20:00 owner 处置 WIP

所有 owner 在 20:00 前对自己 active 单完成三选一：

```text
A. 提交：commit + commit message 带 TID
B. park：写清 park 分支/原因/恢复条件，标 review，不合并
C. abort：devtask.py drop <TID> "原因"，分支/worktree 回收
```

禁止：

```text
- 直接覆盖他人 WIP
- 用 git stash 隐藏后不登记
- 把未提交改动留在主区过夜
```

### 第 3 步：20:00–22:00 单 merge lane 排空

```text
只允许一个 merge 操作在跑；优先级：
P0 安全/部署回归（已完成的不重复）
P1 已有测试证据、无冲突的未合并分支
P2 文档/计划
P0 修复优先于新功能
```

合并要求：

```text
- 先合 master 解冲突（分支内）
- devtask.py merge 过 fast gate
- 失败即停，不绕 DEVTOOL_MERGE_GATE=0
- 不合的写清 park/abort，不留隐性未合并
```

## 3. 风险与处置

| 风险 | 处置 |
|---|---|
| 外部 Agent 继续开新单 | 只认 18:00 冻结通知；新增单不纳入本轮 baseline |
| 主区脏 WIP 被覆盖 | 不 checkout/restore 他人文件；owner 自己提交/park |
