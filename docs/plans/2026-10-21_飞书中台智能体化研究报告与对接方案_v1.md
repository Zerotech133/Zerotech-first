## 一、诚实审计：智能体现在在哪里、起了什么作用

### 1.1 中台本体六个核心模块的智能含量扫描（grep 实证）

| 模块 | 智能体参与 | 实证 |
|---|---|---|
| 出向推送 8097 | **零** | 纯模板渲染（card_templates 8 模板字面量），无模型调用 |
| 入向 WS bot | **零** | handle_cmd 是关键词前缀路由（开通/查询/巡查/撤销/止盈止损…），无理解能力 |
| 入向网关 W43 | **零** | `classify()`（inbound_gateway.py:253-268）= 四条正则：URL 提取/确认 token/6 位代码/≥30 字文本，其余 unclear |
| 订阅账本 | 不适用（账本就该纯工程） | — |
| 到期提醒 | **零** | 三层纯函数（collect/plan/dedupe），规则式，本应如此 |
| 勾稽自检 | 不适用 | — |

**结论一：中台本体是「纯工程管道」，智能体在管道内零参与。** 用户在飞书里发的任何非指令文本，要么落知识库投喂、要么回澄清卡——**没有任何一个字被模型理解过**。

### 1.2 仓库里真实存在的智能体资产（雄厚，但与中台断连）

| 资产 | 能力 | 位置 | 与中台的连接现状 |
|---|---|---|---|
| **军团 LLM 绑定层** | Ollama 多模型自动路由（qwen3.6:35b 判读/qwen3.5:9b 部门/NovaMax 特种/bge-m3 嵌入）+ 降级三态 normal/degraded/failed | `agent_platform/engine/llm.py`（MODEL_PROFILES + chat()） | **零连接**——中台无一文件 import 它 |
| **军团解释器** | 意图解释+规则兜底（LLM 不可用不中断） | `agent_platform/engine/interpreter.py` | 零连接 |
| **军团消息桥** | bridge_inbox inbox/processed、adapters（business/event/codex_bridge） | `agent_platform/bridge_inbox/`、`adapters/` | alerts 总线单向（军团→中台出向），无回程 |
| **诸葛亮 zhuge** | reviewer+军师 SOUL、OpenClaw 载体、GPT6.0 绑定（OPENAI_API_KEY 待注入） | `deliverables/s20-zhuge-workspace-20261021/` | 零连接 |
| **进化层 harness2** | 经验库五域骨架（Z1 赵云 profile 0 条目，首条须走 Z4 签字链） | `C:/项目/harness2` + `~/.hermes/profiles/zhaoyun/` | 零连接 |
| **模型管理面** | 绑定注册/切换/GLM 探针/服务态 | `portal/api_model_admin.py`（set_binding/_glm_probe/_local_models） | 有页面，但管理的是军团侧模型，与中台管道无涉 |
| **OS 建议引擎** | 六源聚合规则版（df82485e，纯函数不调模型——刻意为之） | `portal/` OS 线 | OS 线资产，未进中台链路 |
| **审计 AI** | glm-4.5-flash 独立通道（api_misc.py:569-570） | portal | 独立支线，未复用为通用底座 |

**结论二：断层的准确描述——不是没有智能体底层，是中台从未接线。** 底层四件套（LLM 路由/解释器/消息桥/SOUL）全部在仓、全部在役（军团自己用），但飞书中台的每一滴水都不流经它们。

### 1.3 由此推导的「缺乏的能力」（按用户可感知排序）

1. **意图理解**：用户在飞书发「帮我看下今天亏最多的票」「这个链接讲什么的」「我不想要早盘提醒了」——现在是 unclear 澄清卡或知识库投喂，应走 LLM 意图分类→动作路由。
2. **会话记忆**：跨轮对话（「刚才那只票再看看周线」）——现在每条消息独立处理，无上下文。军团 data/ 有 checkpoints/knowledge_pending 等存储骨架可复用。
3. **主动服务**：诸葛亮模型（主动告诉老田今天该做什么）——OS 建议引擎是雏形但规则版，中台无主动触达循环。
4. **内容生成**：出向卡片文案是模板字面量——日报/预警的「人话摘要」应经 9b 生成（军团已在用同款做判读）。
5. **multi-agent 协同**：客户问题应能派单给军团席位（田丰归口→工位执行→回执卡片）——bridge_inbox 的 inbox/processed 就是为此设计的，但飞书侧无人投递。

## 二、对接架构：三层接线（不停留表面的具体含义）

**设计原则**：不新建第二套 LLM 调用——一律复用军团 `engine/llm.py`（成熟的多模型路由+降级三态+超时档位）；中台只加「接线层」，智能仍然住在 agent_platform。

```
飞书用户 ⇄ WS bot / HTTP 回调
   │
   ▼
┌─ 中台接线层（新增，三件）─────────────────────────────┐
│ ① inbound 意图层：classify() unclear/长文本 →          │
│    engine/llm.py chat("qwen3.5:9b", 意图分类 prompt)   │
│    → 结构化 {intent, entities, confidence} → 动作路由   │
│    （降级三态：LLM 挂了回落现行正则，链路不断）          │
│ ② 会话记忆层：open_id → 近 N 轮上下文                   │
│    （复用军团 checkpoints 存储模式，sqlite/文件均可）     │
│ ③ 出向智能渲染层：日报/预警 → 9b 生成「人话摘要」        │
│    （模板兜底：llm_ok=false 时回模板字面量，判例已有）    │
└──────────────────────────────────────────────────────┘
   │
   ▼
agent_platform（真智能体底座，不动）
   engine/interpreter（意图解释+规则兜底）
   bridge_inbox（④ 派单通道：中台→军团席位的任务投递+回执）
   zhuge SOUL（⑤ 管理咨询位：老田的「为什么/该怎么办」类问题）
   harness2 经验库（⑥ 远期：接线质量本身进经验沉淀）
```

**六条接线，编号 L1-L6：**

| # | 接线 | 底层（真对接谁） | 验收判据（不停留表面） |
|---|---|---|---|
| L1 | 入向意图理解 | engine/llm.py qwen3.5:9b（意图分类，结构化输出） | 真实消息经模型分类出 intent+entities；对比正则基线的 unclear 率下降；降级实测（停 Ollama→自动回正则） |
| L2 | 会话记忆 | 军团 checkpoints 模式复刻（open_id 键，N 轮窗口） | 「刚才那只票」代词消解成功；跨轮上下文进 prompt 有实证（请求体留痕） |
| L3 | 出向智能摘要 | engine/llm.py 9b（日报/预警人话化） | 发出的卡片含模型生成段+llm_ok 标记；模板兜底路径实测 |
| L4 | 派单通道 | bridge_inbox 投递（中台→军团）+ 回执卡片 | 客户问题→田丰归口→工位执行→飞书回执卡全链一次演练留证 |
| L5 | 诸葛亮咨询位 | zhuge SOUL + OpenClaw（GPT6.0，待 OPENAI_API_KEY） | 老田在飞书发管理类问题→转诸葛亮→回答回卡片（key 到位后） |
| L6 | 经验沉淀 | harness2（Z4 签字链） | 接线运行数据（误分类/澄清率）进经验库首条（远期，不阻塞前五条） |

**刻意不做**：不在中台内直接 import openai/zhipu SDK 造第二调用层（违反复用原则且失去降级三态保护）；不做「假智能」——不是每条消息都过模型，规则能路由的（指令/代码/URL）不过 LLM，只有 unclear/长文本进 L1。

### 度量（怎么证明「没停留在表面」）

- L1 上线后周报：unclear 率（基线→现值）、意图准确率（人工抽检 20 条）、降级触发次数
- L3 上线后：含 llm_ok 标记的卡片占比、模板兜底率
- L4 演练：一次全链留证（投递→执行→回执，各有 id 可查）
- 拒绝口径：任何一层若只写了个「调用函数」但没有真实模型往返+降级实测，视为未完成

## 四、风险与边界

1. **9b 的意图分类质量未知**——WA.1 先跑 50 条真实历史消息做离线评测再上线；不够好就升 35b 判读（MODEL_PROFILES 已有档位）。
2. **LLM 延迟**：意图层加 3s 超时档（llm.py 的 timeout 机制现成），超时即降级正则。
3. **成本**：全本地 Ollama，零 API 成本；仅诸葛亮 GPT6.0 走 key。
4. **安全**：L1 输入进 prompt 前走 W43 门禁①隔离声明（inbound_gateway.py:187 既有）；L4 派单走既有 approvals 链，不新增权限面。
5. **不动的**：账本/勾稽/提醒三模块保持纯工程（智能加进去反而引入不可解释性）；enforce 闸门判定不进 LLM（门禁 A 的判定可解释性要求）。
