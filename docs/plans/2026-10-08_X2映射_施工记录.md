### 2.2 实现要点

- 规则表（设计稿 §3.2）落为代码常量：`MARKET_SUFFIX`（SH/SZ/BJ 直配）+ `PREFIX_SUFFIX`（92/4/8→.BJ，6/5/11→.SH，0/3/12/1→.SZ 兜底推导）；规则推导不出的码直接入 `unmatched_queue`。
- 对齐引擎 `align_rows()` 严格按设计稿 §3.1 四步：`ts_code_confirm`(conf=1.000) → `rule`(conf=0.990) → `ts_code_mismatch`/`dst_not_found` 入队。init/incr/mock 共用同一函数（§4 要求同一规则函数）。
- 写入 `entity_map` 为 upsert（先查后 insert/update），每次 insert/update 均写 `map_audit`（old_row/new_row jsonb 快照）。
- `unmatched_queue` 入队走 `ON CONFLICT … WHERE status='open' DO NOTHING`（同一实体只排一次队）。
- `incr`：`update_time > 水位` 增量谓词；`list_status='D'`（退市）→ `status='disabled'`，历史映射保留；跑完推进水位。strategy/user 增量按设计稿 §4 定调（精选制/mobile 归并）留待后续接入。
- 临界证券全集 S：优先 PG `public.stock_basic.symbol`（含 ts_code 风格归一化），为空回退 Neo4j `Security.ts_code`（kg_client，可选依赖失败不挂死）。当前临界 `public.stock_basic` 为 0 行，真 init 前需确认 Neo4j Security 可达或先跑临界证券同步。
- `mock-test` 任何 DB 异常：打印错误 → 尽力清理测试 schema → 干净退出，不挂死、不抛栈。
