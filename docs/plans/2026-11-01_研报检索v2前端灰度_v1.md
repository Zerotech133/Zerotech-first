# 研报检索 v2 前端灰度方案（portal/kb_reports.html）v1

- 日期：2026-11-01
- 支线：wave8 / task-21（U：研报检索 v2 前端灰度）
- 状态：已交付（未 commit；仅改 `portal/kb_reports.html` + 新增测试/文档，后端与数据源不动）
- 关联：wave7 支线 T `tools/kb_corpus/search_v2.py`（评测 precision@5 0.76→1.00）

## 1. 目标与范围

将 wave7 的 v2 检索能力以**纯客户端**方式移植到研报知识库页面，并保留旧逻辑作为回退：

| 需求 | 实现 |
|---|---|
| 多字段加权（concept/claim/evidence/chapter，权重同 v2） | 内联 `SEARCH_V2_WEIGHTS`（concept 1.0 / claim 0.85 / evidence 0.6 / chapter 0.45 / book 0.15） |
| 同义词/别名（复用 synonyms_v2.json） | 内联 `SYNONYMS_V2`（23 组镜像自 `tools/kb_corpus/synonyms_v2.json`，测试做一致性校验） |
| 短语 / 多词 AND / OR / `-排除` | 内联 `v2Parse`（同 Python 版语法与语义） |
| 按书/章节分组 + 相关度 | `v2GroupResults`（best + 0.3×其余分）+ 分组卡片渲染（组相关度、命中数、组内前 3 条） |
| v1/v2 切换（默认 v2，旧逻辑回退） | `#engine` 下拉（v2 默认选中 / v1）+ `render()` 按 `ENGINE` 分发 + v2 异常自动回退 |
| 保留既有区块 | 搜索框/过滤按钮、学习卡、今日简报、H18 区块、加载降级逻辑全部保留 |

不改：`portal/static/kb_units_all.json`（498 单元数据源）、`tools/kb_corpus/search_v2.py`、旧检索器 `kb_reports_search.py`、后端路由。

## 2. 灰度策略

1. **入口级灰度（本次）**：页面下拉切换引擎，默认 v2；用户可秒级切回 v1。
2. **自动回退**：`render()` 在 `ENGINE==='v2'` 时 `try{ renderV2() }catch → 提示 + renderV1()`，
   任何前端异常（数据缺失/逻辑 bug）都不会出现空白页，保证可用性不劣化。
3. **零后端变更**：不新增接口/不改服务；v2 完全在浏览器内计算（498 单元，毫秒级），无额外网络请求。
4. **可追溯**：页面注释标注同义词源路径与 Python 实现文件；测试守护权重/同义词与后端一致。

## 3. 实现要点

### 3.1 页面改动（portal/kb_reports.html）

- 搜索行新增 `<select id="engine">`：`v2`（默认 selected）/ `v1`；
- 新增内联 JS 段（约 13.8KB，`/* ===== 检索引擎 v2 ... ===== */`）：
  `SEARCH_V2_WEIGHTS`、`SYNONYMS_V2`（标记块 + 源路径注释）、`v2Tok / v2Expand / v2Parse /
  v2TermFieldScore / v2UnitScore / v2SearchUnits / v2GroupResults / v2UnitHTML / renderV2`；
- `render()` 改为分发器：v2 优先，异常/切换回 v1（原 `render` 逻辑重命名为 `renderV1`，内容未改）；
- 新增 `.grp/.grp-head/.unit/.score` 样式（复用既有配色变量）；
- 使用提示补充 v2 语法与切换说明。

### 3.2 与 Python v2 的对齐

| 维度 | Python (`search_v2.py`) | 前端 (`kb_reports.html`) |
|---|---|---|
| 字段权重 | `DEFAULT_WEIGHTS` | `SEARCH_V2_WEIGHTS`（测试断言相等） |
| 分词 | 中文 bigram + 英文数字词 | `v2Tok` 同规则 |
| 同义词表 | `synonyms_v2.json`（23 组） | `SYNONYMS_V2`（测试断言逐组相等） |
| 查询语法 | OR 分支 → AND 词 → 短语/`-排除` | `v2Parse` 同正则/语义 |
| 单元打分 | 字段加权 + 覆盖率因子 + 短语加分 | `v2UnitScore` 同公式（1e-4 取整） |
| 分组 | best + 0.3×其余 | `v2GroupResults` 同公式 |

## 5. 回退方案

| 场景 | 操作 |
|---|---|
| v2 结果异常/性能问题 | 页面下拉切回 `v1`（旧逻辑原样保留） |
| v2 前端 JS 抛错 | `render()` catch → 自动 `renderV1()`，状态栏提示已回退 |
| 需要整页回滚 | `git checkout portal/kb_reports.html`（本次未 commit，无历史污染） |

## 6. 局限

- 同义词表在页面内**内联镜像**一份：改 `synonyms_v2.json` 后需同步页面（测试会失败提醒，不会静默漂移）；后续可改为 `/static/synonyms_v2.json` fetch。
- 前端仍是 bigram 词法匹配（与 Python v2 同算法），无 IDF/向量语义；同义扩展靠词表。
- 分组相关度为启发式（组内 best+0.3×其余），超长章节（图表目录类）可能偏弱。
- 未做浏览器端 e2e（无 Playwright 环境）；当前验证为静态一致性 + node 语法 + HTTP 200。
- 评测沿用 wave7 的 10 查询小基准（P@5 0.76→1.00），前端与后端结果**逻辑一致但未逐查询做 JSON 对拍**（同义词/权重/语法有测试守护）。

## 7. 后续建议

1. 用 Playwright/真实浏览器做 v2 交互 e2e（切换、分组渲染、回退路径）；
2. 同义词表迁到 `portal/static/` 并由页面 fetch（消除内联同步成本）；
3. 扩大评测集（30-50 查询）并把「引擎 v1/v2」埋点上报，观察真实用户检索命中率。

## 软 AND 同步（wave13 / task-37，2026-11-01）

- 背景：后端 `search_v2.py` 已在 wave12 合入软 AND（默认 `and_mode=soft`、`soft_cov=0.5`、`synonym_weight=0.6`），本次把前端内联 JS 引擎同步到同一默认，消除前后端口径不一致。

| 项 | 同步前（wave8） | 同步后（wave13，默认） |
|---|---|---|
| AND 语义 | strict（全部查询词必须命中） | **soft：命中词覆盖率 ≥ 0.5**（2 词查询允许 1 词命中，按加权覆盖率排序；`strict`/`any` 保留为可选项） |
| 同义词/别名命中 | 权重 1.0（与原名同权） | **×0.6**（原词命中优先） |
| 默认模式 | strict | **soft**（与后端 `DEFAULT_AND_MODE` 一致） |
| 回退 | 无独立 AND 选项 | `#and-mode` 下拉：soft（默认）/ strict / any；v1 引擎切换保留 |

实现要点：

- 新增常量 `SEARCH_V2_AND_MODES` / `SEARCH_V2_DEFAULT_AND_MODE='soft'` / `SEARCH_V2_SOFT_COV=0.5` / `SEARCH_V2_SYNONYM_WEIGHT=0.6`，与 Python 默认逐一对应；
- `v2TermScore()` 统一单词打分（同义词命中乘 0.6），`v2UnitScore()` 按 `AND_MODE` 判定命中（strict 全词 / soft 覆盖率≥0.5 / any ≥1 词），未命中词按 0 分参与加权平均；
- 搜索行新增 `#and-mode` 下拉（默认 soft），切换即重渲染；结果栏显示 `AND:${AND_MODE}` 便于核对前后端一致；原有 v1/v2 引擎切换、异常自动回退 v1、学习卡/简报/H18 区块全部保留。

回归与验证：

- 测试 `tools/tests/test_kb_search_frontend.py` **8 passed**：新增软 AND 断言（默认 soft / soft_cov=0.5 / synonym_weight=0.6 / strict 回退 / `#and-mode` 控件 / 与 Python 默认常量对齐），原有 v2 挂载点、权重一致、同义词逐组一致、既有区块保留、`node --check` 内联 JS（3 个脚本块）均通过；
- HTTP 200 验证：`GET http://127.0.0.1:8734/kb_reports.html?ts=verify` → 200，返回页面含 `SEARCH_V2_SOFT_COV`/`SEARCH_V2_SYNONYM_WEIGHT`/`id="and-mode"`/`value="soft"` 标记；
- 前端与后端默认值由测试守护（JS 常量 == `search_v2.DEFAULT_*`），后续改默认值会测试失败提醒同步。

局限：前端为内联镜像实现（无共享模块），默认值/同义词表靠测试防漂移；本次未改后端 `search_v2.py`，也未做浏览器端 e2e（无 Playwright 环境）。
