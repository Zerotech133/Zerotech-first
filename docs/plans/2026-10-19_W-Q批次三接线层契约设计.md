## 1. G1 上游重试楔死（Cluster-A：route_outbox.py + agent_reporting.py）

### 1.1 裁决一：control_epoch 来源（缺口①）

**结论：`report()` 新增必填关键字参数 `control_epoch: int`（无默认值）；同时在 RouteOutbox 新增只读查询 `epoch_floor()` 供调用方取下界。拒绝端口注入方案。**

```python
# route_outbox.py 新增（只读）
def epoch_floor(self, envelope: EvidenceEnvelope) -> int:
    """返回该 envelope 身份当前受控 epoch 下界；未登记过则 0。"""

# agent_reporting.py 修改
def report(self, envelope, outbox, *, report_kind: str,
           receiver_agent_id: str, report_id: str,
           control_epoch: int,                      # 新增必填
           now: datetime) -> AgentReport: ...
```

理由：
1. **epoch 的权威在 watch 运行时调用方**，不在 reporter——reporter 无状态、无撤销感知，它不该假装知道 epoch。端口注入会让 reporter 在 report() 内部隐式读 outbox，掩盖"调用方必须声明其所知 epoch"这一责任。
2. **失败关闭默认**：必填无默认 = 旧调用点全部被现有测试暴露并被迫显式化（`test_report_resolves_sector_agent_and_binds_intent` 等需补参，属"按契约本意应更新"）；即使调用方传了落后 epoch，outbox.plan() 的 floor 单调检查（EPOCH_STALE）兜底；撤销身份（revoke 后）沿用既有规则"必须严格大于 floor"，但这只是必要非充分条件，旧键仍被 `_revoked` 封锁。
3. `epoch_floor()` 仅返回身份下界，不授予撤销后重用旧键的能力：未撤销身份调用方传 `= floor`；若 `outbox.revoke_envelope` 已撤销旧键，调用方需以**新冻结证据版本、不同 F9 幂等键及新 report_id**启动另一份报告，再传满足撤销检查的 epoch（通常 `> floor`）；在原 envelope+route+target 上即便 `floor+1` 仍必拒，不能把抬 epoch 等同于旧报告复活。

### 1.2 裁决二：重试形态（缺口②）

**结论：拒绝"同 intent 复活"（finish UNKNOWN→READY_OFFLINE 会重写终态 attempt 语义，不可取）；采用「代际 supersede」——同一 (envelope, route, target) 幂等键下，规划携带 `generation` 的新 intent 替换槽位，attempt 账本跨代延续。**

关键依据 F9/F10：幂等键**不含** intent_id。若把 intent_id 纳入键来区分重试意图，`_key_for`（intent_id="draft" 草稿）将使 claim/finish/get_* 全部查询路径失效，改动面穿透 contracts.py（冻结面）。因此：

```python
# route_outbox.py 修改
def plan(self, envelope, *, route, target_type, target_id,
         policy_version, control_epoch, intent_id,
         created_at, valid_until,
         generation: int = 0,
         report_fingerprint: ReportFingerprint | None = None) -> RouteIntent:
    # generation==0 普通调用保持既有行为；reporter 首代传 fingerprint 并与 plan 原子登记
    # generation>0 的 QUANT_UPSTREAM_REPORT 必须传与首代完全一致的 fingerprint
```

supersede 语义（仅在幂等键已存在同身份 intent 时进入分支）：
- 允许 supersede 的唯一条件：`existing.status == UNKNOWN` **且** `generation == existing.generation + 1` **且** 新 intent_id 与该键全部历史 intent_id 不同，**且 key 从未被撤销、`control_epoch == first_intent.control_epoch`、受信 report_fingerprint 与首代完全相同**。撤销身份不能沿用旧键、旧报告或旧 ack；撤销后报送属于另一个需要新冻结证据版本与新键的新报协议（本批不将 revoke 视为 retry）。
- 效果：`_intents[key]` 换成新 intent（新 intent_id、新 generation、status=READY_OFFLINE、created_at=本次 created_at）；`_attempt_nos[key]` **不清零**——attempt 上限 3 跨代共享，重试总量仍有界；旧 intent 对象移入新增的 `_intent_history`（append-only 审计），`get_intent()` 恒返回最新代。首代还固化不可变 `_origin_created_at[key] = first_intent.created_at`，只供 §3 的同报告回执窗口下锚读取，不回填或修改后代 intent.created_at / 原 ack 时间。
- 其余一切现状（同参重放幂等、字段不一致 INTENT_CONFLICT、ACCEPTED/CLAIMED/CANCELLED 上的键碰撞冲突）原样保留——对已收口（ACCEPTED_VERIFIED）意图请求换代一律 INTENT_CONFLICT。
- `generation=0` 默认使既有全部 key 推导与 plan 行为逐字节不变 → 既有 outbox 回归零影响。

```python
# agent_reporting.py 修改
def retry_report(self, envelope, outbox, prior: AgentReport, *,
                 generation: int, control_epoch: int,
                 now: datetime) -> AgentReport:
    """同一原 AgentReport 身份规划下一代意图（新 intent_id）；
    返回 prior 原对象（其 created_at 仍是首次报告时间），不能构造 created_at=now
    的新 AgentReport，否则 sector 同 report_id 的派生 payload hash 改变并撞
    RECEIPT_CONFLICT。后代 RouteIntent.created_at 则如实为本次 now。
    失败关闭前置校验（经 outbox.get_attempts 只读查询）：
    前代存在且其终态为 UNKNOWN，否则 RETRY_NOT_PERMITTED。"""
```

- intent_id 命名规则：generation==0 → `f"report-{report_id}"`（不变）；generation>0 → `f"report-{report_id}-g{generation}"`。`_intent_ids` 映射保留全部历史 → 旧 intent_id 复用被 INTENT_ID_CONFLICT 拒绝。
- **幂等键不撞首**的完整回答：键不含 generation/intent_id（F9），重试走的是"同键换代"分支而非新键插入，故根本不存在"新键与首键相撞"问题；首 intent 的 UNKNOWN 记录被移入历史而非篡改，终态语义对单个 intent 记录仍然成立（模块语义表述由"UNKNOWN 意图终局"精化为"UNKNOWN attempt 裁定终局；意图账本可由显式下一代计划继任，attempt 历史与上限延续"）。
- 上游幂等红利（F8）：**仅同一未撤销报告的代际重试**才复用同一 report_id；sector `inbox.accept()` 幂等返回原 receipt/原 ack。旧 ack 的 `acked_at` 早于新代 `intent.created_at` 是正常事实，**绝不伪造或改写时间戳**；凭首报告固定时间锚与每次独立验证当前活性的真 ack 收口（见 §3.1 的修订窗口）。若 report 内容、发送/接收主体、首报时间或 epoch 发生变化，**不是同报告重试**，不可使用此豁免。
- **撤销边界特别注意**：同一 envelope+route+target 在 `revoke_envelope` 后被 `_revoked` 标记，而其 F9 幂等键不含 epoch，单凭传 `floor+1` 无法在同键上创建合法新 intent；sector 若 revoke 该 report_id，`inbox.accept` 也不可再按该 id 受理（F8）。所以该调用只能服务于**全新的冻结证据版本/新键 + 新 report_id**，或先设计独立撤销后复报协议；本批**禁止**以 supersede 绕过 `_revoked`，不可承诺"撤销后同 envelope 的 report() 一定成功"。§1.1 的 epoch 参数只解决硬编码 0 导致的过早拒绝，不授予被撤销键的复活权。

### 1.3 裁决三：DEFINITELY_REJECTED 可达性（缺口③）

**结论：新增独立可选端口 `AgentRejectionPort`，不改动 `AgentAckPort` 语义；构造函数以 `rejection_port=None` 可选注入，缺省 = 现状（DEFINITELY_REJECTED 经 reporter 不可达，保守）。**

```python
# agent_reporting.py 新增
@dataclass(frozen=True)
class AgentRejectionEvidence:
    rejection_ref: str          # 受信撤销凭证引用（如 upstream receipt_id）
    verification_source: str    # 非空受信来源标签
    observed_at: datetime       # 撤销观察时刻（UTC aware）

class AgentRejectionPort(Protocol):
    def verify_rejection(self, report: AgentReport, *,
                         now: datetime) -> AgentRejectionEvidence | None: ...

class AgentUpstreamReporter:
    def __init__(self, sender, directory, ack_port,
                 rejection_port: AgentRejectionPort | None = None): ...
```

`claim_and_confirm` 判定顺序（先 ack 后 rejection）：
1. ack_port 验证通过 → `finish(ACCEPTED_VERIFIED, ...)`（现状不变）；
2. 否则 rejection_port 非 None 且 `verify_rejection` 产出证据 → `finish(DEFINITELY_REJECTED, external_message_id=evidence.rejection_ref, verification_source=evidence.verification_source, observed_at=evidence.observed_at)` → outbox 回 READY_OFFLINE（F4 受控重试路径首次经 reporter 可达）；
3. 否则 UNKNOWN。

理由：扩展 AgentAckPort 为 union 返回值会迫使全部现有端口实现与 6+14 例测试改签名（侵入面大）；新端口可选注入是纯增量、默认关闭。权威证据来源（约定，不在本批实现）：sector 侧 `UpstreamInbox.revoke()` 之后，watch 侧经受信查询通道（如 `is_revoked(report_id)` 的桥接视图）取得撤销事实。注意：撤销观察时刻可以早于本次 claim（sector 先撤、watch 后重试），该路径依赖 §3 的 G4 窗口放宽才能保住收据——两缺口在 finish 窗口处合流，必须同批落地。

### 1.4 两种撤销的清晰边界

| 操作 | 状态改变 | 对原 report_id/ack 与重试的裁决 |
|---|---|---|
| `outbox.revoke_envelope(envelope, epoch=E)` | outbox 身份 floor 抬升；原幂等键进入 `_revoked` | 即使显式传 E+1，原键因 F9 不含 epoch 也**不可** supersede 或 claim。原 ack 不得跨 epoch 复用；新冻结证据版本/新键/新 report_id 是另一份报告，不在本批自动重试。sector receipt 即使仍 active，也**不足以**解除 outbox 撤销。 |
| `sector.inbox.revoke(receipt_id)` | sector 原 report_id 被标记永久撤销；原 receipt `is_active=False`；ledger_epoch 抬升 | 即使 outbox 未撤销、outbox epoch 不变，原 ack 也不再 current-active，不得收口 ACCEPTED；同 report_id `inbox.accept()` 抛 `RECEIPT_REVOKED`。不得靠给 outbox 传更高 epoch 复活 sector 已撤销收据。 |

**ReportFingerprint 的可执行存取契约**：定义 `ReportFingerprint(report_id, report_kind, event_id, evidence_version, envelope_hash, sender_agent_id, receiver_agent_id, created_at)` 不可变数据结构；首代 `AgentUpstreamReporter.report()` 在完成身份验证后通过 `RouteOutbox.plan(..., report_fingerprint=fingerprint)` 一次原子事务写 `_report_fingerprints[key]` 与意图（出错二者都不写），不能另开非原子登记 API。`retry_report(prior)` 拿 prior 的完整 8 字段构造同一 fingerprint；outbox.plan 对 `generation>0` 强制 fingerprint 非 None 且与登记值全字段相等、`control_epoch == first_intent.control_epoch`、`key not in _revoked`；否则在更新任何状态前拒绝。直接调用 outbox.plan 不能绕过血缘检查。**指纹只证明"报告字段同一"，不证明"ack 真实且当前有效"**；后者必须经 §3.1 的受信验证端口。

### 1.5 撤销时当前 attempt 悬挂的同簇一致性裁决（补充）

当前 route_outbox.revoke_envelope() 对 CLAIMED intent 写 UNKNOWN、但对应 attempt 仍 CLAIMED（F4 外另一个簿记不一致）；该 attempt 不可能再 finish，且若 retry_report 仅判前代 attempt UNKNOWN，会给人造成"撤销与普通 UNKNOWN 同义"的错误印象。**最小裁决：在 Cluster-A 的 route_outbox.py 同批修正，无须另立项**：

- 预检同一 envelope 身份将要撤销的全部 key：每个 CLAIMED intent 恰有一条 `idempotency_key == key` 且 `intent_id == intent.intent_id` 且 `outcome == CLAIMED` 的当前 attempt；若查无/多条/不匹配，则 `REVOKE_ATTEMPT_INCONSISTENT` 且 `_epochs/_revoked/_intents/_attempts/_attempt_nos` **全不变**，避免半撤销。
- 预检全过后，在同一个内存事务更新 epoch、标记 key 撤销、把 CLAIMED intent 与其当前 attempt **同步**置 UNKNOWN，attempt.receipt=None；不构造回执、不调用 finish、不改 attempt_no 和 `_attempt_nos`，旧 key 仍 `_revoked`，不能以此 UNKNOWN 进入同键 supersede。READY_OFFLINE intent 仍 CANCELLED；先前已终结 attempt 不改写。
- `finish` 错误码兼容：旧测试 `test_cancel_and_revoke_fail_closed` 对撤销后 attempt 的断言是 `ATTEMPT_NOT_CURRENT`。若直接改 attempt.outcome 为 UNKNOWN 会因现有校验顺序变成 `ATTEMPT_UNKNOWN`；调整 finish 判定顺序：查到 attempt 后，若其 key 已 revoked 先抛 `ATTEMPT_NOT_CURRENT`，再检查 attempt.outcome==CLAIMED；普通历史已结束 attempt 仍抛 `ATTEMPT_UNKNOWN`。撤销不赋予已结束 attempt 新的 outcome，也不改变既有 UNKNOWN 终态与跨代 3 次总预算。

测试补充：单 CLAIMED 双账同步 UNKNOWN/receipt=None、attempt_no 不变；二次 finish 仍 ATTEMPT_NOT_CURRENT；同身份多 target 都正确收口；active attempt 缺失/重复/intent_id 不匹配须整批无状态变更；READY_OFFLINE→CANCELLED 且历史已终结 attempts 不动；撤销 key 即使有 UNKNOWN attempt 也不可调用 retry_report 换代。

### 1.6 G1 不变量清单

- I1：`control_epoch` 在 report() 必填；reporter 自身从不推导 epoch。
- I2：outbox epoch 单调不回退（既有）；撤销身份的新意图 epoch 严格大于 floor（既有）。
- I3：同一幂等键上，UNKNOWN attempt 裁定永不重写；换代只前进（generation 严格 +1）且仅允许自 UNKNOWN；首代 `_origin_created_at[key]` 固定不可回填，后代真实 created_at 仍如实递增；撤销键不得换代。
- I4：attempt 上限 3 跨代共享，任何代际组合都无法突破 ATTEMPTS_EXHAUSTED。
- I5：report_id 跨代不变（保上游幂等红利）；intent_id 跨代必变；历史 intent_id 永不复用。
- I6：DEFINITELY_REJECTED 仅可由"端口独立验证的撤销证据"触发；无端口 = 不可达。
- I7：reporter 恒定产出 ACCEPTED_VERIFIED / DEFINITELY_REJECTED / UNKNOWN 三者之一，不再有第四种收口。

### 1.7 G1 错误码（新增）

| 错误码 | 抛出点 | 含义 |
|---|---|---|
| `RETRY_GENERATION_INVALID` | outbox.plan | 同键换代但 generation != existing+1（跳代/回退） |
| `INTENT_ID_REUSE` | outbox.plan | 换代时新 intent_id 与该键历史 intent_id 重复（与既有 INTENT_ID_CONFLICT 区分） |
| `RETRY_NOT_PERMITTED` | reporter.retry_report | 前代不存在、或前代终态非 UNKNOWN |
| `REJECTION_EVIDENCE_INVALID` | reporter | 端口产出的证据字段非法（空 ref/空 source/naive 时间） |
| `REPORT_FINGERPRINT_REQUIRED` | outbox.plan | QUANT_UPSTREAM_REPORT 已登记血缘的 generation>0 换代未提交指纹 |
| `REPORT_FINGERPRINT_MISMATCH` | outbox.plan | 换代指纹与首代登记值任一字段不等 |
| `RETRY_EPOCH_CHANGED` | outbox.plan | 同键换代时 control_epoch 与首代不等（旧 ack 禁跨 epoch） |
| `RETRY_KEY_REVOKED` | outbox.plan | key 已经 outbox.revoke_envelope，不可换代 |
| `REVOKE_ATTEMPT_INCONSISTENT` | outbox.revoke_envelope | 将撤销的 CLAIMED intent 找不到唯一匹配当前 CLAIMED attempt；全事务不变 |

## 2. G2 类型映射缺位（Cluster-B：新中立桥接包）

### 2.1 裁决六：适配器落点与形态

**结论：新建中立组合根包 `quant_backtest/agent_bridge/`（纯函数 + 正式映射表），单向依赖 agent_bridge → watch_dispatch、agent_bridge → quant_sector.upstream_inbox；两个核心包均不得 import agent_bridge。拒绝 duck-typed-Protocol-only 与 quant_sector 内落点两个方案。**

理由：
- Protocol-only（零 import）做不到：适配器的职责就是**构造**目标类型，最终必须 import 具体类型；纯 duck-typing 只会把 `type(...) is X` 校验（F7，upstream_inbox.py:181）变成运行期哑弹。
- quant_sector 内落点：让 quant_sector import watch_dispatch 直接违背隔离约束（W-Q2 豁免仅限 dual_gate 对 canonical/contracts 的既有 import，不为新代码开先例）。
- 中立包：零核心改动、依赖方向单一（组合根层），既有的 e2e 测试层翻译函数可原样保留或后续替换（不强制迁移）。

```python
# quant_backtest/agent_bridge/mapping.py（新文件）
```

## 3. G4 跨组件时序降级（Cluster-A）

### 3.1 裁决四：回执窗口

**修订裁决（2026-10-19，解决首 ack 早于重试意图的时间锚矛盾）：ack 先于 claim 是合法业务序列；同 report_id 的代际重试也可复用原 ack，但只能依据「不可变首报告创建时刻」为下锚，绝不可用新代创建时刻拒绝旧真 ack，亦绝不可伪造 ack 时间。**

```python
# route_outbox.py 首代 plan 固化一次；同键换代保持不变
_origin_created_at[key] = first_intent.created_at

# finish（只对 QUANT_UPSTREAM_REPORT 的受信同报告血缘适用）：
receipt_not_before = _origin_created_at[key]
valid_time = receipt_not_before <= observed_at <= now
# 其他路由/非同报告血缘不享受沿用原 ack 的下锚：
# receipt_not_before = intent.created_at（或保留原 claim_at 窗口）
```

**同报告血缘的精确判定（不可凭仅相同 route/target/key 推定）：**
1. key 必须等于已登记首代键，`generation` 连续 +1，既有与后代都未被 outbox 撤销，`control_epoch == first_intent.control_epoch`（任何 epoch 变化禁止旧 ack 沿用）。
2. 重试的 `AgentReport` 与首次记录的值在 `report_id/report_kind/event_id/evidence_version/envelope_hash/sender.agent_id/receiver.agent_id/created_at` **完全相同**。首代 plan 时由 reporter 固化上述 `ReportFingerprint` 于 outbox 侧的只读关联表（仅原 QUANT_UPSTREAM_REPORT 路由）；不能单凭 `get_intent()` 的 envelope 字段核验 report_kind/sender/created_at——这些字段不在 RouteIntent。由 `retry_report` 先比对 fingerprint 再调用 plan，outbox plan 拒绝带不一致 fingerprint 的换代请求，避免直接绕过 reporter 调 plan；鉴于现有 plan 对通用调用方的签名兼容需求，新 fingerprint 为**仅换代时必填的可选 kw 参数**，首代 reporter 调用时登记，其他 plan 原样。最小方案也可将 fingerprint 作为 RouteOutbox 只读登记方法在 reporter.report() 首代规划后同原子路径写入；实现必须保证登记与 plan 原子完成，不能留下 UNKNOWN 而无 fingerprint 的中间态。
3. 每一次 `claim_and_confirm` 仍调用 `AgentAckPort.verify(ack, original_report, now)`，端口必须在**当前时刻**独立核对该精确 report 对应 sector receipt 仍 active（`is_active`）且不存在撤销；只比对 ack 字段的简单 BindingAckPort 测试桩**不能充当此受信路径**。若端口无法证明当前活性 → UNKNOWN，不借旧 ack 补偿。`verified.acked_at` 保持原值不重写，`RouteReceipt.observed_at` 如实记录它。
4. outbox `finish()` 必须强制（非只 reporter 约束）只对该已登记同报告血缘使用首报下锚；直接调 finish(outcome=ACCEPTED_VERIFIED) 但无血缘/无可信 provenance 时，不得因 `_origin_created_at` 存在就得到跨代旧时间豁免。**最小可验证签名建议**：`finish(..., verified_ack: VerifiedAgentAck | None = None)`，其中 `VerifiedAgentAck` 只能由持有受信 `AgentAckPort` 与 inbox 当前活性读端口的组合根生成，含 `report_fingerprint/ack_id/acked_at/verification_source/receipt_id/checked_at`，outbox 用信任端口再验当前活性（**不可仅检查调用者可构造的数据类**）；`verified_ack is None` 时仍执行原 claim 窗口（兼容 10 例通用 outbox 测试）。受信通过时，首代也使用 origin_created_at（修 G4），后代使用原首报锚（修 G1）；拒绝证明过期/伪造/身份不等的旧 ack。另一等价实现是一体化 outbox-bound 端口，不强制采用具体数据类。若无法做到不可绕过，则先维持 UNKNOWN、不开放代际旧 ack 路径。这是实现门槛，不允许以测试桩假装达成。

论证：
- 首报告的 `created_at` == 首代 intent.created_at（report() 以 `created_at=now` 调 plan）。后代真实 `intent.created_at` == retry_now，明显晚于原 ack.acked_at；旧版 §3 双锚 `intent.created_at <= observed_at` 与 §1.2 同 report_id 重试相互矛盾，现已修正为首报不可变锚。
- **下锚性质未弱化**：ack 不能早于其所确认的**首报告存在**。claim_at 是本地取号簿记，后代 created_at 是本地重试簿记，二者均非该原报告的存在时刻。上锚 `observed_at <= now`、expired/stale 门（finish.now 必须仍在后代 claim 租约内与后代 intent 窗口内）全部保留。
- 这只放宽"受信的同一报告当前有效原 ack"这一窄路径；仅以人工构造的 external_message_id/verification_source/observed_at 调 outbox.finish 仍可能满足结构窗口，所以 **AgentAckPort 的真实活性校验与不可绕过的 outbox provenance 绑定是准入条件**，否则整个设计只能保守拒绝，不称为防伪已完成。
- G4 首代 sector 先 accept 后 watch claim 时，`origin_created_at == intent.created_at`，窗口自然保留真 ack；跨代旧 ack 由同一规则处理，无补偿、无篡改 UNKNOWN attempt。
- `test_receipt_outside_claim_window_forces_unknown` 的 `observed_at=T-1s` 仍早于首报锚 T，必为 UNKNOWN，负例原样保留。

**附带同型缺陷声明（不在本批范围）**：quant_sector/dispatch_ledger.py 的 finish 同样使用 claim 窗口语义（模块 docstring 第 15-17 行自述）。其受理（inbox.accept）按定义先于 dispatch plan/claim，理论上有同款降级风险；其 19 例测试固化现状。建议：另开审计切片核实其 observed_at 实际取值后决定是否同步双锚化，本批不动。

### 3.2 G4 不变量清单

- I11：回执双锚 `receipt_not_before <= observed_at <= now`，首代及无继任血缘的意图下锚=intent.created_at；仅同一未撤销报告的已登记重试血缘下锚=不可变 origin_created_at。租约与时效门不变。

## 4. G3 收据绑定不验（Cluster-B：signal_pool.py）

### 4.1 裁决五：绑定校验端口与 fail-closed 迁移

**结论：每调用注入只读绑定端口 `ReceiptBindingPort`，`mark_accepted` 新增必填关键字参数 `binding_port`——一次性切失败关闭（未注入即拒），不做过渡期可选放行。**

```python
# signal_pool.py 新增
@dataclass(frozen=True)
class AttemptBinding:
    attempt_id: str
    external_message_id: str
    outcome: str                 # 仅接受 ACCEPTED_VERIFIED_OUTCOME
    route: str
    event_id: str
    evidence_hash: str
    evidence_version: int

class ReceiptBindingPort(Protocol):
    def binding_for(self, attempt_id: str) -> AttemptBinding | None: ...

def mark_accepted(self, signal_id: str, *, receipt: AcceptanceReceipt,
                  binding_port: ReceiptBindingPort) -> SignalPoolEntry: ...
```

校验链（全过才 CLAIMED→ACCEPTED；任一失败抛错并**保持 CLAIMED**，租约不回收）：
1. `binding_port.binding_for(receipt.attempt_id)` 非 None；
2. `binding.outcome == ACCEPTED_VERIFIED_OUTCOME`；
3. `binding.external_message_id == receipt.external_ref`；
4. `binding.route == receipt.route == "QUANT_UPSTREAM_REPORT"`（字面镜像常量，延续本模块不 import route_outbox 的纪律）；
5. `binding.(event_id, evidence_hash, evidence_version) == entry` 对应三元组——**收据不能跨信号复用**（伪造的核心面，单靠 1-4 挡不住"拿别条真链收据伪造本条"）。

**为什么每调用注入而非构造注入**：绑定校验需要 (outbox, envelope) 上下文；SignalPool 构造时只有 store，无 envelope。每调用注入让端口天然持有当次信号的封套上下文，调用方（组合根/e2e）用 `OutboxBindingAdapter(outbox, env)` 构造一次性视图，端口无状态、可测。

**为什么一次性失败关闭而非过渡期可选放行**：`binding_port=None` 缺省放行等于把伪造洞保留在默认路径上，本次修复即失去意义。迁移面实测（一次性、夹具级）：
- test_watch_dispatch_signal_pool.py：6 处 `mark_accepted` 调用点补 `StubBindingPort`（显式命名的测试桩，仅聚焦状态机；新增负例再覆盖端口语义）——断言本身不变；
- test_wq_pool_upstream_e2e.py：`run_accepted_chain` 的 `mark_accepted` 换用真实 `OutboxBindingAdapter(outbox, env)`（由 §2 的 agent_bridge 提供，G2/G3 在此合流）——e2e 由"翻译测试"升级为"真绑定验证测试"，是增强不是破坏；
- 既有 24 例池测试中其余 18 例不触 mark_accepted，零影响。

## 9. UNCLEAR 与假设

1. **119 例口径**：实测相关面为 128/150 例（取决于是否计入 contracts/projection/integration 三文件）。本设计以逐文件用例级清单落实影响面（§6），聚合口径差异不影响任何裁决。
2. **AgentRejectionPort 的权威证据通道**：sector 撤销事实如何到达 watch 侧（轮询 is_revoked？事件回传？）属运行时接线，不在本批离线契约内；本设计只定义证据形状与验证端口。
3. **retry 上界 3 的产品语义**：attempt 上限跨代共享沿用 outbox 既有 `_MAX_ATTEMPTS=3`；若产品要求"每代独立 3 次"，须另行设计独立总预算与防滥用审计，而不能简单把 `_attempt_nos` 键改为 (key, generation)（那会使代际重试无总量上限）。本设计按"总量有界"保守取值。
6. **当次 ack 活性与 outbox 受信 provenance**：现有测试 `BindingAckPort.verify` 仅核五字段，不能证明 inbox receipt 当前未撤销；outbox.finish 只收用户可填写的字符串/时间，不能自己证明端口已验证。故 §3.1 双锚旧 ack 复用的生产资格必须等待不可绕过的可信绑定端口/证明 token 设计与实现；若该能力未落地，**先只允许首代 G4 窗口修正，代际旧 ack 仍保守 UNKNOWN**，不得宣称 G1②链已闭环。
4. **dispatch_ledger 同型窗口缺陷**：未实测其 observed_at 实际取值，仅声明同型风险并建议独立审计切片（§3.1）。
5. **假设**：contracts.py 的 RouteIntent 允许新增 `generation` 字段语义于 plan 层承载而**不**改 RouteIntent 数据类本身（generation 只存于 outbox 槽位管理与 key 无关）——若实现时发现需入 dataclass，须回归核对 F10 的草稿 key 推导路径。
