# 问答候选问题库 v1（2026-11-01）

> 任务单：task-29（wave10 · AC 问答候选问题库，retrieval-only 批量生成）。
> 关联：`tools/kb_corpus/kb_qa.py`（RAG 问答）、`tools/kb_corpus/kb_read_api.py`（498 知识单元只读接口）、
> `portal/static/kb_qa_samples.json`（wave7 的 5 条人工样本）、`portal/static/kb_qa_questions.json`（本任务候选问题库）。

## 1. 背景与目标

wave7 的问答样本只有 5 条（3 条 LLM 回答 + 1 拒答 + 1 降级演示），缺少**规模化候选问题**用于：

1. retrieval-only 检索自检（问题→知识单元命中率/覆盖度）；
2. 后续 `--answer N` 批量生成问答样本（默认不跑，控 LLM 成本）；
3. 门户/评测/回归的问题集基线。

本任务新增 `tools/kb_corpus/kb_qa_bank.py`：从 **498 知识单元（463 研报 + 35 书籍）** 用模板确定性生成
**20–40 条候选问题**（默认 32），每条带来源 `unit_id/书名/章节/页码/主题`，按主题分组去重。**默认不调 LLM。**

## 2. 生成规则

```
kb_read_api.load_units()（498 条，只读，无网络）
   │
   ├─ ① 主题分类（concept+claim+chapter 关键词规则，7 类）：
   │     AI算力/半导体 · 新能源/电池 · 消费/医药 · 金融/资本市场 · 宏观/策略/贸易 ·
   │     量化/技术分析 · 其他/综合
   ├─ ② 模板问题（4 类：是什么 / 影响如何 / 数据多少 / 风险 + 主题专属模板）
   │     例："{concept}的核心结论与主要依据是什么？"
   │         "{concept}对产业链或行业格局的影响如何？"
   │         "{concept}涉及哪些关键量化指标或时间表？"
   │         技术上："{concept}的技术升级路径与价值量变化如何？"
   ├─ ③ 去重：问题文本归一化（去标点/空白）后全局唯一；同主题同概念最多 2 条（第 2 条换问题类型）
   └─ ④ 分组截取：按主题轮转取满 limit（钳制 20..40），保证主题分布均衡
```

每条问题记录字段：

| 字段 | 说明 |
|---|---|
| `id` | `qk_` + 问题文本归一化 sha1 前 10 位（稳定可复现） |
| `question` | 模板生成的问题文本 |
| `type` | 问题类型：是什么/影响如何/数据多少/风险/主题专属 |
| `theme` | 主题分类 |
| `source_unit_id` | 来源知识单元 ID（可直接 `kb_read_api get-unit --id`） |
| `book` / `chapter` / `page_start` / `page_end` | 出处元数据 |
| `concept` / `claim_snippet` / `evidence_snippet` / `source` | 概念、主张/证据摘要、来源（研报/书籍） |
| `answer`（可选） | 仅 `--answer N` 时对前 N 条附加：answer/citations/confidence/fallback/citation_check |

## 4. 使用方式

```powershell
# ① 生成候选问题库（默认 dry-run，不调 LLM；写 research + portal 双份）
C:\项目\py312\python.exe -X utf8 tools\kb_corpus\kb_qa_bank.py build --dry-run

# ② 指定条数（钳制 20..40）
... build --dry-run --limit 24

# ③ 显式对前 N 条生成答案（会调本地 Ollama，默认不跑；逐条走 kb_qa.ask）
... build --answer 5

# ④ 用问题库做 retrieval 自检（逐条 --retrieval-only 只读检索，不调 LLM）
#    for q in questions: kb_qa.py ask "<question>" --retrieval-only --json
```

## 5. 后续扩样计划

1. **retrieval 覆盖度评估**：对 32 条逐一 `--retrieval-only`，统计命中率/无命中问题（无命中问题说明知识库缺料或问题模板失配）；
2. **回填答案样本**：挑 retrieval 命中的问题 `--answer N` 生成答案样本，扩到 20–30 条示范问答；
3. **人工筛选**：模板与概念偶有语义错配（如「板块周度表现」+「量产时间表」），`--answer` 前可人工筛一批高质量问题；
4. **门户展示**：`portal/static/kb_qa_questions.json` 可仿「问答示例」区块做问题列表（待页面任务）；
5. **去重增强**：同义概念（如「AI 算力」/「算力」）可加同义词归并，减少近义问题重复。

## 6. 限制与边界

1. 模板生成=**规则式**，不保证每条问题在知识库中有充分材料；需配合 retrieval 自检；
2. 主题分类为关键词规则，边界样本可能归入「其他/综合」；
3. 页码/来源取自知识单元元数据（`page_start..page_end`），同一单元多问题共享页码；
4. 候选问题仅用于检索/问答评测与研究，不构成投资建议；答案生成需人工复核。
