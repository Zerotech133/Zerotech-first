## 二、发现的问题（按优先级）

### P0-1 数据双轨：浏览器 localStorage vs 服务端 daily_briefs

- 手动“13部门运行”把结果存浏览器；
- 07:50 任务把结果写 `deliverables/daily_briefs/<date>/`；
- `/briefing` 当前不显示服务端结果（snapshot 无 briefing）；
- 换浏览器/换人即看不到，无法作为 A0 正式日报。

**影响**：日报不可共享、不可审计、不能作为决策依据。

**优化**：服务端为唯一真源；前端只读服务端 briefing；手动运行也写服务端。

### P0-2 07:50 自动任务未验证

- 任务只注册、未首跑；
- Interactive only（需用户登录 Windows）；
- 无失败通知；13 次云端调用失败可能只落日志。

**优化**：11-03 手动 `/Run` 一次验证；失败写 `dev_events`/通知；加 1 次重试与 20 分钟超时。

### P0-3 浏览器本地库绕过 manifest/exclude

- 网页文件选择器直接扫所选文件夹，不读 `library.json`；
- 若用户选 `_local_libraries` 父目录，可能读到其他用户目录；
- 浏览器 consent 与服务端 `.consent` 是两套。

**影响**：本地隐私边界可能被用户误操作突破。

**优化**：网页只允许选 `<user>/`；读取并应用 manifest 的 `sources/exclude`；长期改为桌面桥调用，网页不直接扫盘。

### P1-1 两套 13 部门运行逻辑

- `tools/hq_daily_run.py`（服务端，07:50）与 `briefing.html` 内联 JS（浏览器手动）各自维护 prompt/parser；
- 容易出现字段/行为漂移。

**优化**：抽成统一服务端接口，前端只触发和展示。

### P1-2 决策/研究题噪声

- 重复/过泛；A0 速览只计数，未排序。

**优化**：去重（标题相似）、按红黄/影响/紧急度排序，Top 5 决策清单 + 研究题合并。

### P1-3 个人版早报/对话未服务端持久化

- 页面个人早报、部门对话存 localStorage；
- 云端 A0 个人早报工具可写 `personal_briefs/`，但网页没接。

**优化**：个人早报按 user 写服务端；对话历史按 user 落库/对象存储，权限隔离。
