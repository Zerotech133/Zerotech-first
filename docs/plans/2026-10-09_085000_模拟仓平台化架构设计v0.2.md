# 模拟仓平台化架构设计 v0.2（2026-10-09 08:55）
> STATUS: unspecified（owner: TBD；2026-11-07 前补状态或标 superseded）



> 需求来源：老田 08:48 产品定义——模拟持仓是**一个完整平台**，分自动/手动买入；策略源可插拔（青萍之末、量子双刀、AI 团队……）；要手动止损；要历史持仓；未来多个 Agent 各当交易员。
> 基线：v0.1.x 已交付单账本引擎（两步撮合/T+1/费率/两条风控/快照/灾备/只读前端页）——本设计只做**增量演进，不推翻**。

---

## 一、核心抽象：Picks 协议（一个接口打通所有策略源）

所有策略源——无论 AI 团队、量子双刀、青萍之末还是人——只负责产出同构的 picks，**平台统一负责怎么买**（风控/费率/T+1/幂等/撮合全部复用现有引擎）：

```json
{
  "strategy": "qingping | double_knife | ai_team | manual | agent_<id>",
  "ts": "2026-10-09T15:30:00",
  "picks": [
    {"stock": "600519.SH", "side": "BUY", "confidence": 0.73, "note": "信号详情"}
  ]
}
```

| 策略源 | 现状输出形态 | 接入方式 | 工作量 |
|---|---|---|---|
| **ai_team**（现有） | poc_*.json（exec_run 已在读） | 现有路径，仅补 strategy 标记 | ~0 |
| **量子双刀** | quant_double_knife.py 信号（21 诊断列，已移植进 engine/） | 新 adapter：跑信号 → 产 picks JSON → 复用 exec | 小（信号已就绪，T-009 回测并行验证） |
| **青萍之末** | qianping.db 的 signals 表（SQLite，扫描器产信号行） | 新 adapter：读 signals → 产 picks JSON → 复用 exec | 中（需选库+信号字段映射） |
| **手动** | CLI buy/sell（已有） | v0.2c 升级到前端下单（写路径） | 鉴权先行 |
| **未来 Agent 交易员** | 各自团队决策产物 | 各写一个 adapter，strategy=agent_<id> | 按需 |

**设计铁律**：策略源永远不直接碰账本——只有 engine 的 `_settle_fill` 一个写入口（现状保持），策略产出 picks 后走同一 exec 链。多策略不会引入第二套交易语义。

## 二、Schema 演进（全部向后兼容，ALTER 加列 + DEFAULT）

```sql
ALTER TABLE orders    ADD COLUMN strategy  TEXT DEFAULT 'manual';   -- 策略来源
ALTER TABLE orders    ADD COLUMN account_id TEXT DEFAULT 'main';    -- v0.3 多账户，现在先立列
ALTER TABLE orders    ADD COLUMN order_kind TEXT DEFAULT 'market';  -- market | stop
ALTER TABLE positions ADD COLUMN strategy  TEXT DEFAULT 'manual';
ALTER TABLE positions ADD COLUMN account_id TEXT DEFAULT 'main';
ALTER TABLE positions ADD COLUMN stop_price REAL;                   -- 手动止损价（NULL=未设）
-- account 表单行 → 多行（v0.3 启用）：account_id/name/owner/initial_cash
```

旧行自动归 `main`/`manual`，零迁移成本；`verify` 对账逻辑不变（仍按全局合计）。

## 三、止损设计（两层，口径与两步撮合制自洽）

**① 手动止损（v0.2a 本期）**：
- `positions.stop_price` 字段；CLI `paper/cli.py stop <code> <price>`（前端 v0.2c 跟进）
- 检查点挂在每日 settle 之后：湖内最新收盘价 < stop_price → 自动生成 SELL pending（`order_kind='stop'`，strategy 标 `stop_loss`），次日开盘撮合——**与现有 T+1/两步制语义一致，不引入未来函数**（模拟仓无盘中实时价，触发用收盘口径是唯一诚实的选择）
- 止换单同样过风控与 ledger 对账，无特权路径

**② 自动止损规则（v0.3+，按策略可配）**：ATR 跟踪止损 / 固定比例 / 信号失效离场（如双刀入场确认条件破坏）——参数进 config，复用同一检查点。

## 四、历史持仓（前端，数据已就绪）

- **每日快照回看**：positions_snapshot 已按日固化（date+stock 主键）——前端加日期选择器，查任意历史日快照（建仓→加减仓→清仓轨迹）
- **生命周期视图**：ledger 聚合某票全链（买入均价/已实现盈亏/持有天数）
- **策略维度**：持仓表/订单表/权益曲线按 strategy 筛选分组——每个策略源独立看清业绩

## 五、多 Agent 交易员（v0.3，本设计先立骨架）

- **子账户制**：每 Agent 一个 account_id，独立初始资金、独立持仓、独立权益曲线；风控阈值按子账户总资产计算（单票 20% 是子账户口径，不是全局）
- **排位看板**：复用 `curve()` 多账户收益率 PK——「哪个交易员赚钱」一目了然
- 与 K-STOCK-002 蓝图天然对齐：AI 投研团队就是交易员（T1/T2/D1 是团队内分工），多团队=多交易员，合流后的平台直接挂多个团队账户
- **权益快照表扩展**：equity_marks 加 account_id（DEFAULT 'main'），5 日窗判据链不受影响

## 六、前端写路径（v0.2c，鉴权是硬前置）

- 现状：portal_api 无登录态，/paper 只读是刻意设计——**开写路径=公网可下单，必须先补鉴权**
- 方案建议：HMAC token 鉴权（CowAgent 9899 同款，K272 先例，口令运行时读 config 永不入库）；写接口（下单/撤单/设止损）全验 token，读接口保持开放
- **⚠️ 落地修正（2026-10-09 11:50，v0.2c 实施时）**：独立 HMAC 方案作废，改为**复用全站 `_MUTATION_POSTS` + X-Portal-Token 闸门**（本机 `_is_local_req` 放行 / 局域网须 token）——统一机制优于第二套机制，且 /paper 走 nginx 静态服务本就拿不到 token 注入；出处：台账 `docs/ops/2026-10-09_K-STOCK_模拟仓v0.1.md` v0.2 平台化上线段
- 下单表单：策略下拉（manual/qingping/double_knife）+ 股票 + 方向 + 数量 + 止损价（可选）
- 手动买入与自动买入同链路：前端产 picks → exec → 风控 → 撮合，无特权

## 八、拍板点（4 项）

1. **青萍之末接入方式**：建议**只移植信号逻辑成 adapter**（量子双刀 K-STOCK-018 纯移植先例，零改动承诺），不复活整个 FastAPI 项目；库选 归档2 的 qianping.db schema。备选：发布包版本 / 重启原项目
2. **止损成交口径**：触发=湖内最新收盘价检查、成交=次日开盘价（两步制一致）。若你要求「触发即当日价成交」需引入盘中价源，破坏无未来函数设计——不建议
3. **写路径鉴权**：HMAC token（建议，CowAgent 先例）vs 简单口令 vs 仅内网开放
4. **多账户列现在加 vs v0.3 加**：建议现在加（DEFAULT 列零成本零风险，避免 v0.3 再迁移）
