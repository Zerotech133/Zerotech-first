## 2. P2 交付清欠与合并

**目标**：清掉阻塞主线的未合并交付，所有合入有真实 SHA、门禁结果和回执。

**范围**：W1 试点、Catalog PERSIST、W0 doing/review、主工作区脏改动隔离。

**关键交付**：
- W1：ADR 结论、rebase 到最新 master、kernel_guard 解除、完整 fast 门通过、21:40 窗口合入；无 ADR 则不硬合，顺延 11-09。
- Catalog PERSIST：rebase 和对账已完成，等待 DATA1/A0 审批后按 306 口径恢复，不提前写生产数据根。
- W0：按 owner 逐单核销，优先 close/merge 已有证据的 doing；review 13 单终裁；不批量改状态伪造达标。
- 主区脏改动：按目录/owner 分类，隔离到 worktree 或独立提交；禁止 `git add -A`、`reset --hard`、`git clean -fdx`。

**验收**：每个合入有 merge SHA + 门禁日志 + 回执；W0 达到 doing≤8 / worktree≤20 / parked≤8；无“合入 0 却写 PASS”。

## 5. P5 验收复盘与路线固化

**目标**：用一次全量回归和一份总复盘收口本周期，不拿旧基线当当前结论。

**关键交付**：
- 全量回归在当前 master 上跑一次，记录通过/失败/跳过和耗时。
- 汇总 P1–P4 的回执、合并 SHA、数据对账、未关闭风险。
- 更新 ROADMAP v4，明确下一周期目标和唯一优先级。
- 全量回归、HZ 最终验收、W0 收口三项未完成前，不得对外宣称本周期完成。

**验收**：全量回归 0 失败（允许的已知 skip 单独列出）；ROADMAP 更新；所有未关闭项有 owner 和截止时间。

## 6. 执行节奏

- 按 1→5 推进；P1/P2 在每个窗口优先，P3 在审批后执行，P4 按日运行，P5 只在 P1–P4 证据齐后收口。
- 所有碎片任务必须标注归属 P1–P5；不属于任何一条主线的任务不插队。
- 每日只报一次总进度；不逐条播报定时器。异常才即时报告。
- 纪律不变：不造假、不补数据、不绕门禁、不 force、不 `DEVTOOL_MERGE_GATE=0`；共享仓提交只用显式 pathspec。
