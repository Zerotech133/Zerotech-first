## 三、路由表 / 限流 / 缓存设计

| 方法 | 路径 | 参数 | 行为 |
|---|---|---|---|
| GET | `/api/kb/qa` | `q`（必填，≤200 字符）、`topk`（1..20，默认 8）、`mode`（`retrieval` 默认 / `generate`）、`cache`（`0` 跳过缓存） | 200 统一信封：`data{question,answer,citations[],confidence,retrieved[],citation_check,mode,topk}` + `meta{mode,topk,cache_hit,elapsed_ms,llm_called,rate_limit}` |

| 项 | 设计值 |
|---|---|
| 限流（进程内滑动窗口/60s） | retrieval 60 次/分；generate 6 次/分（独立计数） |
| 超时 | retrieval 20s；generate 120s（LLM 慢，仅显式开启） |
| 缓存 | 同 `(mode,q,topk)` 10 分钟 TTL，进程内 LRU 上限 200 条；`cache=0` 绕过 |
| 错误码 | `INVALID_ARGUMENT`(400) / `METHOD_NOT_ALLOWED`(405) / `NOT_FOUND`(404) / `RATE_LIMITED`(429) / `NOT_READY`(503，kb_qa 加载失败) / `UPSTREAM_UNAVAILABLE`(503，检索/LLM 异常或超时) / `INTERNAL`(500) |
| 只读性 | 端点无写操作、无文件写入、无任务创建；retrieval 不调 LLM |

> 限流/缓存为**进程内**实现（单实例 8091 足够）；多实例部署需换 Redis/令牌桶（不在本提案）。

## 十、multi 灰度预接线（wave18 / task-53，2026-11-01）

状态：**仅修改预接线文件 `portal/api_kb_qa.py` 与其测试/文档；未注册 8091、未重启任何服务，`WIRED=False` 保持**。以下为批准接线后的 multi 灰度方案（预置，待 L2 审批执行）。

### 1. 参数与默认值

| 项 | 预置值 | 说明 |
|---|---|---|
| `mode` | `retrieval`（默认）/ `single` / `multi` | HTTP 默认只读检索（零 LLM 成本） |
| 生成默认 | **`multi`** | `mode=multi` 为生成默认（多单元聚合，与 CLI 一致）；`single` 需显式 |
| 兼容别名 | `mode=generate` → `multi` | 旧调用不破坏，response.meta 记 `mode_alias` |
| `meta` 新增 | `mode` / `k` / `clusters` / `llm_called` | 便于前端/埋点区分模式与成本 |
| 超时 | retrieval 20s / single 120s / multi 300s | multi prompt 更长（≤3 簇×3 单元） |
| 限流（每分/通道） | retrieval 60 / single 6 / multi 6 | 生成通道独立限流，防打爆本地 Ollama |
| 缓存键 | `(mode, question, topk)` | 不同 mode 互不串味 |

### 2. 成本估算（相对 single）

- **LLM 调用次数**：每查询仍 1 次（multi 只是 prompt 聚合，不增加调用数）；
- **prompt 规模**：single 约 topk 个单元片段；multi ≤3 簇×3 单元≈9 片段，估算 **prompt tokens +50%~80%**、生成长度 +20%~40% → 单次延迟约为 single 的 **1.5~2x**；
- **本地 Ollama 成本**：电费/GPU 占用为主，无 API 计费；主要风险是**占用时长**与并发排队，故 multi 限流 6 次/分、超时 300s；
- **限流保护**：retrieval 60/分可承受前端默认只读；生成通道 6/分（single 与 multi 各 6）。

### 3. 灰度策略（批准接线后）

1. **阶段 0（接线后立即）**：前端默认 `mode=retrieval` 只读 → 零 LLM 风险，验证路由/缓存/限流/信封；
2. **阶段 1（小流量 multi）**：仅问答页「生成」按钮/内测白名单传 `mode=multi`，观察延迟、`meta.llm_called`、失败率（503/fallback）；限流 6/分，可随时停；
3. **阶段 2（multi 生成默认）**：前端生成入口默认 `mode=multi`，`single` 保留为显式回退；
4. 每阶段以 429 率、503 率、P95 延迟、引用校验（citation_check）四项为 go/no-go 依据。

### 4. 回滚

- **接口级回滚（无需重启）**：调用方改 `mode=single`（旧单单元生成）或 `mode=retrieval`（只读）；
- **默认回滚**：若批准接线时把生成默认设为 multi，回滚只需把前端生成入口默认改回 `single`（后端参数保持兼容，无需改 handler）；

- 本次交付**不注册路由、不重启**，因此当前回滚成本为零（仅文件级未接线状态）。
