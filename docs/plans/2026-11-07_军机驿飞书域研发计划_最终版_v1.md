## 1. 定位、目标与非目标

### 1.1 定位

飞书是零界的**管理型通道**（不是单纯 webhook，也不是第二入口）：

- 对外：把已产生的判断、简报、任务、审批卡送到飞书；接收飞书回调与指令。
- 对内：把“谁在什么时间收到什么、是否送达、失败后如何补、谁批准了什么”写进同一套决策账与证据链。
- 对人：H5 业务查看页（`/m/*`）是零界状态的**只读投影 + 受控回写**；移动管理台（`/m/admin`）与 PC 控制台（`/hq/admin`）是同一 OS 的**受管控制面**，写操作仍走审批/决策账，不是第二套业务后台。
- 对机器：Hermes、DSH、OpenHands、OpenClaw 都是 runtime adapter，统一登记，不各自直连飞书。

### 1.2 目标（按优先级）

| 优先级 | 目标 | 可验证结果 |
|---|---|---|
| P0 | 现有飞书能力不退化 | 8097/8091 健康；W4 回执项保持；H5 `/m` 16/16 路由可用；无新增 critical |
| P0 | 收口旧计划与旧资产 | 本文件生效；旧计划归档可恢复；活动代码/数据零误删 |
| P1 | 飞书成为 C8 受管通道 | Q1 影子组合 + manifest + 契约 + 单一真源设计通过评审 |
| P2 | 安全与可观测闭环 | 公网只走 8081；K3 span/指标；签名与密钥轮换；失败可归因 |
| P3 | H5 页面、移动/PC 管理面与调度纳管 | `/m` 业务投影进 page manifest；`/m/admin` 与 `/hq/admin` 页面矩阵冻结并进同一 manifest；定时任务进入 job manifest |
| P4 | 商业化预留可评审 | 订阅/收银台接口与账本预留，不施工、不对外承诺 |

### 1.3 非目标（本轮明确不做）

- 不做“飞书独立站”、不做第二套业务数据后台、不新建独立权限系统；`/m/admin` 与 `/hq/admin` 只做受管控制面，复用现有认证/角色/决策账。
- 不在 11-16 前改 8097/8091 运行逻辑，不重启常驻服务，不迁移生产账本。
- 不新开公开隧道，不把 8734 直接暴露到公网。
- 不在 Q2 前做订阅收费、客户域、生产服务器迁移。
- 不删除任何活动代码、运行数据、当前 worktree、生产审计账本。

## 3. 最终架构与边界

### 3.1 目标态（文字图）

```text
飞书用户 / 群 / 审批卡
        │
        ├── 出向：8734 → 8097（唯一 egress）→ 飞书 OpenAPI
        │        └─ 决策账 / 证据 / 死信 / 补达
        │
        └── 入向：飞书 WS / HTTP 回调（W43）→ 8091（唯一 ingress）
                 └─ 8734 宿主 → 决策 / 任务 / H5 投影

公网 H5：手机 → m_public_gate(8081, token/OIDC) → 8091 → 8734
内部 H5：8734 内网 / 本地 token → 8091（不经过公网）
Hermes 8787：runtime adapter，只读接入，不直连飞书
```

### 3.2 六条铁律（继承并固定）

1. **双闸门单向**：出向只经 8097，入向只经 W43/8091；不得反向直连。
2. **不建第二账**：决策、证据、死信、订阅状态只写现有账本；新面只能读投影。
3. **证据四级**：没有证据不宣称成功；`api_accepted` 不等于 `receiver_verified`。
4. **域隔离**：owner / 客户 / 测试域不混发；测试不得写生产收件人。
5. **页面分层**：业务 H5 是只读投影；`/m/admin` 是受管控制面，所有回写走审批/决策闸，不能直接改生产。
6. **closed on failure**：失败默认关闭，不自动重试成风暴；补达必须受控、幂等、可审计。

### 3.3 四通道边界（继承 10-14 判例，不能再漂移）

- **A 自建 OpenAPI**：唯一出口 `news_collector/feishu_client.py`；计划任务推送、计量。
- **B 自建 lark-cli 子进程**：常驻 bot / 指令；权威实体 `bin/lark-cli.exe`；必须受 watchdog。
- **C Trae Lark 插件**：仅人在场会话；**禁生产推送、禁常驻、不计入通道 SLA**。
- **D portal HTTP 回调**：只做入向接收与验签（`/feishu/event`）；不承担出向。
- **五红线**：C 禁生产推送；C 禁常驻；B 必须走仓库内 `bin/lark-cli.exe`；身份不混用；写生产资源必须显式确认/白名单留痕。

### 3.4 接口契约（v0 目标，不是今天实装）

**出向 `POST /api/send`（仅内网 / 内部 key）：**

```json
{
  "channel": "feishu",
  "target_domain": "owner|customer|test",
  "recipient_id": "open_id or chat_id",
  "template": "daily_brief|alert|approval|task",
  "payload": {},
  "evidence_level": "api_accepted|receiver_verified",
  "idempotency_key": "uuid",
  "task_id": "T-YYYYMMDD-xxx"
}
```

**审批/决策链：**

```text
preview → record → approve → execute
   │         │         │         └─ 执行闸默认关闭；B2/B5 证据齐后由 A0 开启
   │         │         └─ 必须有 signed card callback + 人工样本
   │         └─ 同一决策账；不得旁路
   └─ 只生成预览，不产生副作用
```

**入向：**

- W43/8091 验签后写入 `m_events` / `inbound_tickets`；不直接触发生产写。
- 未识别 intent 走 `r.fallback.clarify`，不猜测执行。

**H5：**

- 公共入口必须 `m_public_gate` + token/OIDC；禁止 8734 直曝。
- 页面 token 最小权限、短期、可撤销；`m_links` 仅在命名隧道安全门通过后启用。
