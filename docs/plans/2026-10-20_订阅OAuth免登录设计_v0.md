## 一、定位与目标

客户订阅面 `/my-subscription`（my_subscription.html + nginx 前门路由，收编 538f1ac1）当前打开即匿名态：页面能展示，但无法回答"你是谁"，因此订阅变更类受控回写（总纲 §4.1 按钮）缺少 actor 身份，订阅闸（FC-C）的 owner 识别也无从锚定。

本设计稿回答四件事：

1. 客户在飞书内打开页面时，如何**免登录拿到身份**（飞书自建应用网页免登，授权码模式取 open_id）；
2. `/my-subscription` 如何**自动带身份**渲染与提交；
3. 拿到的 open_id 与**订阅闸 owner 识别如何复用**（同一身份口径，不建第二账）；
4. 安全边界在哪里（code 换 token 服务端持密、state 防 CSRF）。

## 二、免登链路（授权码模式）

```
[客户浏览器]                [中台 portal_api]                  [飞书开放平台]
打开 /my-subscription
  │ 无会话 → 302 授权页
  │──────────────────────────────────────────────►  飞书授权页（用户已登录则免操作）
  │ ◄────────────── 授权码 code（含 state）──────────
  │ 回跳 /my-subscription?code=xxx&state=yyy
  │──────────── code+state 上送 ────►
  │                                 服务端持 app_secret
  │                                 code 换 user_access_token → 取 open_id
  │                                 （token 不落浏览器）
  │ ◄── 签发中台自持会话（HttpOnly Cookie）+ 订阅状态渲染 ──
  │ 后续请求带 Cookie，页面按钮回写带 actor=open_id
```

要点：

- **免登体验**：客户已在飞书客户端内，授权页静默通过，全程无密码输入、无人工登录表单；
- **授权码模式而非隐式模式**：code 只能用一次且短时效（飞书侧 5 分钟口径，实施时以官方文档为准），换 token 动作只发生在服务端；
- **会话自持**：换到 open_id 后，中台签发自有会话票据（HttpOnly + Secure + SameSite），后续请求不再依赖飞书 token——飞书 token 短时效且中台不需要代表用户调飞书 API，故不持久化 user_access_token。

## 三、/my-subscription 自动带身份

| 环节 | 口径（草案） |
|---|---|
| 未带会话打开 | 只读模式渲染公共摘要（档位说明、"待定价"等既有口径），顶部展示"飞书内一键确认身份"入口，不显示任何他人订阅数据 |
| 带会话打开 | 以 open_id 查订阅账本（FC-B），渲染本人订阅状态；变更按钮可见可用 |
| 按钮回写 | 走 W43 唯一入口（与 I5 受控回写契约同构，actor=open_id，"人→OS"与"页面→OS"同构），不直改订阅账本 |
| 会话过期 | 显式降级回只读模式并提示重新确认身份，closed on failure，不伪造登录态 |

## 四、与订阅闸 owner 识别的复用关系

- 订阅闸（FC-C）按 owner 识别订阅关系，owner 口径即飞书 open_id（订阅账本 FC-B 以 open_id 为键）——免登取得的 open_id **同一口径直通复用**，不做二次映射、不建身份对照第二账（铁律：不建第二账）；
- 复用收益：免登确认的身份=订阅账本的 owner=闸门放行的主体，三者一码贯通；客户在页面看到的"我的订阅"与闸门实际放行的订阅天然一致，无身份漂移；
- 边界：open_id 是应用级标识，同一客户在不同飞书应用中 open_id 不同——中台只认本自建应用的 open_id，注册表/账本均以此为准（如未来换应用形态涉及 union_id，另立设计稿另批）。

## 五、安全边界

| 项 | 口径 |
|---|---|
| app_secret 保管 | **服务端持有，永不下发浏览器**；配置走既有密钥管理口径，不硬编码、不入前端 bundle |
| state 防 CSRF | 服务端签发随机 state（一次性、短时效、与会话种子绑定），回跳时强校验，不匹配即拒绝——防授权码注入与跨站伪造 |
| code 单次消费 | 每个 code 只尝试换取一次；换失败显式报错重走授权，不重试复用 |
| token 不落前端 | user_access_token 仅在服务端内存瞬时使用，不持久化、不进 Cookie、不进日志 |
| 会话票据 | HttpOnly + Secure + SameSite；只承载 open_id 引用与签名，不携带密钥；有效期与续期口径待议定 |
| 最小权限 | 自建应用权限范围仅申请"获取用户身份（open_id）"所需 scope，不申请消息/通讯录等额外权限 |
| 审计 | 每次免登确认（成功/失败）落审计记录：open_id、时间、结果、来源 IP；失败显式留痕不静默 |
