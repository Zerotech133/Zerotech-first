## 一、场景定义（客户视角走一遍）

```
客户在飞书里发：「帮我看看 605100 现在能进吗」
   │
   ▼ ①意图层（L1）：9b 分类 → {intent: "stock_consult", code: "605100", domain: "quant"}
   ▼ ②路由表（AIR）：quant 域 + 未订阅 → 三岔口
   │    ├─ 已订阅+额度内 → 派单司马懿席（bridge_inbox）→ 回执卡「已转盯盘官，预计 5 分钟」
   │    ├─ 已订阅+超额度 → 回执卡「今日 20 次已用完，明日续答」
   │    └─ 未订阅 → observe 留痕 → **个性化引导卡**（不是通用模板）
   ▼ ③反推层（画像）：本次查询进 customer_interest 聚合
        → 「该客户 7 天内第 6 次查个股，从没订过」→ 商机信号入 sub_admin 商务面
```

**与现状的差别一句话**：现在客户发这句话只会收到「澄清卡」（unclear）或被静默投喂知识库——**没有任何商业行为发生**。

## 二、模块一：客问智能路由（AIR = AI Router for Inbound）

### 2.1 意图分类词表（L1 结构化输出，9b 本地零成本）

```json
{"intent": "stock_consult|watch_setup|subscription_qa|billing|complaint|feed|smalltalk|unclear",
 "entities": {"code": "605100", "topic": "买点", ...},
 "domain": "quant|ops|business|knowledge",
 "confidence": 0.86}
```

### 2.2 域路由表（谁接活——全部映射到军团既有席位，不造新岗）

| intent | domain | 路由目标 | 回执形态 | 订阅闸 |
|---|---|---|---|---|
| stock_consult（个股咨询） | quant | 司马懿席（盯盘官转派张郃工位） | 派单卡→结果卡 | 是（news.*/quant.*） |
| watch_setup（盯票/预警词设置） | quant | 许褚营 G1 触发器 | 操作确认卡 | 是 |
| subscription_qa（我的订阅/额度） | business | **中台自动**（查账本直答，无需 Agent） | 摘要卡 | 否 |
| billing（账单/续费/退款） | business | 中台自动 + 人工兜底（账单类不瞎答） | 摘要卡/转人工卡 | 否 |
| complaint（投诉/不满） | — | **田丰归口**（bridge_inbox 派单，最高优先级） | 已受理卡+工单号 | 否（投诉永远受理） |
| feed（长文投喂） | knowledge | 知识库既有链路（不变） | 已入库卡 | 否 |
| smalltalk/unclear | — | 澄清卡（带 3 个建议指令，从画像生成） | 澄清卡 | 否 |

### 2.3 派单协议（复用 bridge_inbox，零新建）

投递 `bridge_inbox/inbox/`：`{type: "customer_ticket", open_id, intent, entities, msg_id, deadline_min: 5}`；军团侧田丰归口分发（既有 approvals 链）；执行完经 8097 出向回结果卡（引用原 msg_id 可追踪）。**超时升级**：5 分钟无回执→中台自动发「稍等」卡→15 分钟→升级田丰。

## 三、模块二：查询反推（画像 + 商机信号）

### 3.1 数据地基已在（只差聚合层）

| 已有留痕 | 字段 | 反推价值 |
|---|---|---|
| entitlement_log | open_id, kind, allowed, reason, ts | 每次闸门判定=一次真实需求表达 |
| inbound observe 留痕 | route="subscription_gate" | 未订阅者的每一次尝试 |
| blocked(subscription_required) | 出向被闸记录 | **最强商机信号**（想要但没权限） |
| L1 意图层上线后 | intent/entities | 兴趣域+标的级画像 |

### 3.2 customer_interest 聚合表（新增，sqlite，中台域）

```sql
CREATE TABLE customer_interest (
  open_id TEXT, day TEXT,
  domain_quant INTEGER, domain_business INTEGER, domain_knowledge INTEGER,
  consult_count INTEGER,          -- 咨询次数
  blocked_count INTEGER,          -- 被闸次数（商机核心）
  top_codes TEXT,                 -- 高频标的 JSON ["605100","300750"]
  top_topics TEXT,                -- 高频主题 JSON ["买点","财报"]
  updated_at TEXT,
  PRIMARY KEY (open_id, day)
);
-- 周聚合视图：interest_7d（滚动窗口，画像用）
```

### 3.3 商机信号定义（sub_admin 商务面新增区块）

| 信号 | 规则 | 强度 |
|---|---|---|
| **热客户** | 7 天 consult≥5 且 blocked≥2（想要没权限） | ★★★ 立即跟进 |
| 潜客 | 7 天 consult≥3 无订阅 | ★★ |
| 到期前活跃 | 订阅 end≤7 天且 consult≥3 | ★★（流失预警反用） |
| 静默流失 | 曾活跃（周≥3）→ 本周 0 | ★ 回访 |

### 3.4 个性化引导卡（替换通用 subscription_guide）

被闸时不再发通用模板，而是：**「您本周 6 次查询 605100 买点——订阅盯盘档后，这类问题由盯盘官实时解答，首月 ¥XX」**（数据取自 customer_interest；定价仍是占位符则只说权益不报价）。

### 3.5 隐私边界（红线）

- 画像只存**行为统计**（次数/频次/域分布），**不存聊天原文**（原文只在既有知识库链路，画像层只拿 intent 枚举+实体）
- 画像不出中台域：不进军团、不进出向卡片明文（引导卡只回客户本人）
- 客户可说「查我的记录」→ subscription_qa 意图直答统计摘要（透明化）
