## 一、执行摘要

本方案将此前对话形成的业务设想，与已经完成开发的历史项目统一起来，目标不是把旧脚本简单改名为 Agent，而是把现有资产收敛为一个可持续运行的：

> **以 Hermes 为主管、以多 N Agent 为执行单元、以动态组合模拟交易市场为验证场、以全程证据链为底座、以日报/周报/月报和蒸馏样本为进化机制的量化智能交易中台。**

最终业务动线：

```text
策略研究与选股
    ↓
股票池
    ↓
实时盯盘与外围情报触发
    ↓
虚拟投研机构多维核实
    ↓
投研计划、持仓规则、风控计划、交易授权
    ↓
交易智能中台动态选择交易 Agent
    ↓
模拟市场撮合与动态组合管理
    ↓
成交、持仓、盈亏、异常与反事实评估
    ↓
日报 / 周报 / 月报
    ↓
策略、Agent、路由与小模型持续进化
```

本方案坚持五条底线：

1. **策略 Agent 不直接交易**：负责研究、选股、提出候选观点。
2. **盯盘 Agent 不直接改变投研方向**：负责发现异动、变化、信号源和复核触发。
3. **投研机构不直接操作账户**：负责事实核实、多维辩论、计划和授权。
4. **交易 Agent 不得越权**：只能在授权的方向、仓位、期限、止盈止损和失效条件内执行。
5. **任何决策必须可溯源**：买入、持有、加仓、减仓、换仓、卖出均必须保留证据、授权、执行和结果链。

### 2.2 现状事实与主要技术债

- `quant_backtest` 是源码、数据仓、实验脚本、日志、报告和缓存混合目录；约 26.6 万文件，主要为 Parquet 和 JSON，不能直接作为干净产品包。
- 数据中台实际实现已经明显超过部分历史设计文档，存在文档状态漂移，需建立“实现真源 + 设计文档同步”机制。
- 现有执行引擎已有较强审计能力，但动态组合、组合级再平衡、模拟市场和多交易 Agent 路由仍需形成统一主链。
- MASS 已有任务、判读和证据治理经验，但历史审计暴露出 merge 防呆、结论落盘、存量收编和僵尸任务等工程治理问题；新量化链不能重复这些缺陷。
- 历史存量收编仍需分批处理：源码/契约/文档入库，运行态/缓存/第三方依赖/凭据绝不入库，嵌入式独立仓库单独治理。

## 三、目标架构

### 3.1 四大业务域

#### A. AI 策略研究域

每种策略是一个可独立运行、可独立评价、可独立升级的 Agent：

- 缠论/趋势
- 动量/因子
- 情绪/事件
- 量子双刀
- 知识图谱增强
- 基本面/估值
- 未来新增策略

策略 Agent 职责：

- 读取指定数据与情报
- 生成股票池和候选组合
- 提供选股理由、分数、置信度、证据引用
- 每日上报研究报告、新假设、新方案和实验结果
- 接受实际交易结果反馈
- 进入影子验证、版本评价和升级流程

**可扩展性原则：新增策略 = 注册一个新的策略 Agent，不是修改交易主链。**

策略必须以插件方式接入统一的 `StrategyAgentContract`。新增第 N 个策略时，只新增自己的策略包、配置、Agent 注册项和测试，不修改盯盘、投研、组合、风控、执行、结算等公共内核。公共系统只依赖契约和注册表，不依赖具体策略名称。

每个策略 Agent 必须有独立的：

- `strategy_id`：永久身份；同一策略改逻辑不得复用旧身份。
- `strategy_version`：代码、参数、提示词、模型和依赖版本。
- `strategy_family`：趋势、动量、因子、缠论、事件、基本面等能力分类。
- `capability_manifest`：可读数据、支持市场、时间周期、输出动作和资源需求。
- `input_schema/output_schema`：输入输出契约，禁止直接返回私有结构。
- `evidence_policy`：必须引用的行情、情报、回测和风险证据。
- `isolation_scope`：独立任务、缓存、日志、账本和资源配额。
- `lifecycle_state`：`DRAFT → EXPERIMENT → SHADOW → APPROVED → ACTIVE → RETIRED`。

策略 Agent 只输出标准化的 `CandidateProposal`、`ResearchReport` 和 `StrategySignal`，不直接写股票池最终状态、不直接发起订单、不直接修改组合。股票池、投研授权和交易动作由公共控制层完成。

策略数量增加时，平台自动完成：注册、能力校验、数据权限检查、契约测试、历史回放、影子运行、指标评价、资源配额和版本晋级；不得为每个策略复制一套 Hermes、盯盘、投研和交易主流程。

#### B. AI 盯盘观察域

由盯盘 Hermes 主管管理，持续观察股票池、持仓和授权状态：

- 价格、成交量、盘口和技术状态
- 板块和市场联动
- 新闻、公告、事件和外围情报
- 支撑/压力、回撤和授权失效
- 持仓风险、组合敞口和流动性

输出两类信息：

1. 给交易团队的实时执行信息：异动、变化、执行窗口和异常。
2. 给投研机构的研究触发信息：需要核实的新事实、原假设失效、策略冲突和新机会。

#### C. AI 虚拟投研机构

由投研 Hermes 主管组织多角色研究：

- 看多
- 看空
- 技术
- 情绪
- 基本面
- 事件
- 风险
- 仓位与组合

输出一份可执行的投研计划与交易授权单，而不是一句“可以买/卖”：

- 方向与置信度
- 入场条件和价格区间
- 目标仓位、最大仓位和持仓周期
- 加仓、减仓、止盈和止损条件
- 失效条件、撤销条件和有效期
- 风险预算和人工确认条件
- 证据引用、看多/看空分歧和最终结论

#### D. AI 交易智能中台

由交易 Hermes 主管管理，负责动态编排交易 Agent，不固定绑定单一交易员。

交易 Agent 至少有两个维度：

- 风险风格：保守、中立、激进
- 持仓周期：超短线、短线、波段、中线、长线

中台根据实时数据、投研授权、市场状态、组合风险、Agent 历史绩效和当前资源动态选择和编排 Agent。

交易团队内部角色：

- 组合经理 Agent：资金、仓位、组合冲突和风险预算
- 执行交易员 Agent：订单拆分、下单、撤单、补单和成交跟踪
- 执行风控 Agent：订单前检查、流动性、价格、制度和熔断
- 运营结算 Agent：账户、现金、持仓、成交和盈亏核对
- 复核 Agent：执行质量、授权一致性和异常归因

### 3.2 四类公共控制面

| 控制面 | 主要职责 |
|---|---|
| 数据控制面 | 行情、基本面、情绪、事件、持仓、时间戳、来源、质量、可见性 |
| 任务控制面 | 触发、排队、并行、超时、重试、幂等、升级、额度和资源 |
| 风险控制面 | 仓位、敞口、流动性、T+1、涨跌停、熔断、人工确认、最终否决 |
| 证据复盘面 | 观点、数据快照、辩论、授权、订单、成交、持仓、盈亏、反事实和版本 |

### 3.3 平行空间动态模拟交易市场

这是系统的核心验证场，不等于静态回测：

- 使用真实情报和实时/历史数据
- 使用虚拟资金、虚拟账户和模拟撮合
- 模拟手续费、滑点、延迟、流动性和交易制度
- 支持多策略、多组合、多交易 Agent 并行
- 支持日内动态买卖、加仓、减仓、换仓和再平衡
- 支持实时绩效、风险和反事实评估
- 所有运行都进入证据仓和报告系统

## 四、核心业务动线与状态机

### 4.1 标的生命周期

```text
候选发现
  → 股票池
  → 盯盘观察
  → 触发投研复核
  → 投研授权
  → 进入组合
  → 持仓管理
  → 加仓 / 减仓 / 换仓 / 止盈 / 止损
  → 退出
  → 复盘
  → 反馈策略与 Agent
```

### 4.2 交易决策状态

```text
WATCH
  → RESEARCH_TRIGGERED
  → RESEARCH_PENDING
  → AUTHORIZED
  → RISK_CHECKED
  → ORDER_PENDING
  → PARTIALLY_FILLED / FILLED / REJECTED
  → HOLDING
  → REBALANCE_PENDING
  → EXIT_PENDING
  → CLOSED
  → REVIEWED
```

每次状态变化必须是 append-only 事件，禁止只更新最终状态而丢失中间过程。

### 4.3 动态组合管理规则

买卖不由选股策略单独决定，而由以下共同计算：

```text
选股信号
+ 投研授权
+ 实时行情
+ 外围情报
+ 回撤类型
+ 支撑/失效条件
+ 当前持仓
+ 组合相关性
+ 风险预算
+ 交易风格与周期
+ 执行质量
```

回撤必须区分：

- 正常回撤：趋势和逻辑未破坏，可继续持有或分批加仓。
- 风险回撤：跌破支撑、负面情报或风险阈值触发，减仓/止损。
- 结构性回撤：相对行业和市场持续走弱，考虑换仓。

## 五、滚动回测与模拟市场设计

### 5.1 选股即回测

进入股票池时同步生成动态回测卡：

#### 按日窗口

- 1—30 天，每天滚动计算
- 次日收益、胜率、最大有利/不利波动
- 触发止盈/止损的时间
- 日内成交、滑点和持仓路径

#### 按月窗口

- 1—12 个月，按月滚动计算
- 月度收益、胜率、最大回撤
- 持仓周期、组合稳定性
- 不同市场状态下的表现

### 5.2 回测和模拟必须统一口径

回测、纸面模拟和未来实盘模拟必须复用同一套：

- 数据可见性规则
- 交易日历
- 订单模型
- 成交模型
- 手续费和滑点
- T+1 和涨跌停
- 持仓与现金账本
- 事件和证据结构

避免出现“回测盈利、模拟交易亏损，但无法解释口径差异”的问题。

### 5.3 反事实评估

每次卖出后自动比较：

- 实际卖出结果
- 不卖的 1/3/5/10/20 日结果
- 只减仓一半的结果
- 换仓到候选标的的结果
- 不同交易 Agent 风格的执行结果

用于判断：正确止损、正确止盈、过早卖出、误杀、未及时卖出和错误换仓。

## 六、全程证据链设计

### 6.1 统一交易追踪键

每次判断、授权、订单、成交和复盘至少绑定：

```text
trace_id
 event_id
 timestamp
 symbol
 portfolio_id
 position_id
 strategy_id / strategy_version
 agent_id
 hermes_id
 market_snapshot_id
 intelligence_snapshot_id
 decision_type
 decision_reason
 evidence_refs
 risk_rules_hit
 authorization_id
 order_id
 fill_id
```

### 6.2 买入证据包

- 为什么进入股票池
- 哪个策略产生
- 使用哪个策略版本
- 当时 1—30 日、1—12 月回测快照
- 技术、基本面、情绪、事件证据
- 看多、看空和风险意见
- 入场、仓位、止盈、止损、失效条件
- 投研授权与风险检查
- 订单、成交、滑点和未成交原因

### 6.3 卖出证据包

- 卖出准确时间和市场快照
- 当日异动和外围情报
- 原买入前提是否失效
- 哪条策略、情报或风控规则触发
- 哪个 Agent 提出、哪个 Hermes 审批
- 组合状态、回撤、相关性和资金占用
- 卖出授权、订单、成交和滑点
- 卖出后实际结果与反事实结果
- 最终评价和策略反馈

### 6.4 事实与解释分离

- 事实层：价格、成交量、指标、新闻、持仓、回撤、阈值。
- 判断层：Agent 观点、投研意见、风控意见、Hermes 结论。
- 结果层：订单、成交、盈亏、反事实、归因。

不能用事后生成的自然语言解释替代当时真实存在的事实和决策记录。

## 七、研发分期与计划

### M0：架构冻结与历史资产映射（P0）

目标：先不重写核心代码，建立新架构与旧资产的对应关系。

交付物：

- 量化整体架构图
- 四大业务域和四类控制面清单
- 旧模块→新域映射表
- 数据源和服务目录
- 交易事件与证据 schema 草案
- Agent/Hermes 注册表草案
- 历史资产收编/ignore/待定清单

验收：

- 每个现有核心模块都有归属或明确待定原因。
- 不存在“直接下单但没有授权”的未解释入口。
- 不把运行产物、缓存和凭据纳入源码收编。

### M1：统一契约与证据底座（P0）

目标：先把所有未来能力接到统一契约上。

重点：

- `CandidatePoolItem`
- `StrategyResearchReport`
- `WatchSignal`
- `ResearchDecision`
- `TradeAuthorization`
- `PortfolioAction`
- `OrderIntent`
- `Fill`
- `PositionEvent`
- `ReviewResult`
- `EvidenceRef`
- `TraceEvent`

交付物：

- 版本化 JSON Schema/Typed DTO
- append-only 事件账本
- trace_id 贯穿策略→投研→交易→复盘
- 证据引用和快照存储
- 事件查询和单笔交易回放接口

验收：

- 任意模拟买卖可回放完整链路。
- 缺失关键证据时，事件进入异常状态，不得静默成功。
- 原始事件不可覆盖，重复事件具备幂等键。

### M2：策略研究 Agent 与股票池（P0）

目标：把现有策略接入标准研究接口，并验证“新增策略不改主链”的扩展能力。

**M2 的架构验收不是接入多少策略，而是能否用同一套注册、契约、隔离和评估流程接入第 3 个策略。**

重点：

- 复用 `strategy_layer` Signal/Registry/Adapter
- 通过注册表接入缠论、趋势、动量、因子、情绪/事件、知识图谱等策略 Agent
- 形成策略能力清单、数据权限和资源配额
- 形成股票池和候选组合
- 每日研究上报
- 1—30 日和 1—12 月滚动回测卡
- 策略版本和实验记录
- 完成第 3 个策略的独立接入演练，证明不修改公共交易主链

验收：

- 每个策略每日有研究报告。
- 每个入池标的都有来源、理由、回测和证据。
- 新假设必须可进入实验/影子流程，不得直接替换正式策略。

### M3：情报/数据接入与 AI 盯盘（P0）

目标：将情报中枢、情报服务和数据服务接入盯盘与投研触发。

重点：

- 复用 `datamart` 统一读层
- 接入市场、基本面、情绪、事件、新闻、持仓和账户数据
- 统一时间戳、来源、质量和可见性
- 股票池盘中监控
- 持仓和授权监控
- 异动、前置因素和信号源输出
- 投研复核触发器

验收：

- 盯盘输出能够同时到达投研和交易队列。
- 每个异动均绑定数据快照和来源。
- 数据延迟、缺失或冲突可见，不伪装为正常信号。

### M4：虚拟投研机构与交易授权（P1）

目标：将多维 AI 讨论变成可执行计划。

重点：

- 看多/看空对立角色
- 技术/情绪/基本面/事件/风险角色
- 证据引用和分歧记录
- 研究结论、持仓规则和风控计划
- 授权有效期和撤销机制
- 投研 Hermes 审批

验收：

- 只有获得有效授权且通过风险检查的任务才能进入交易队列。
- 授权单明确方向、仓位上限、入场、退出、失效和有效期。
- 角色分歧和缺证据状态不被隐藏。

### M5：交易智能中台与多 N Agent（P1）

目标：实现按风格、周期和市场状态动态路由交易 Agent。

重点：

- 保守/中立/激进 Agent
- 超短/短线/波段/中线/长线 Agent
- 组合经理、执行、风控、结算和复核 Agent
- 角色能力注册、评分和路由规则
- 并行任务、资源预算、超时、重试、冲突处理
- 交易 Hermes 统一编排

验收：

- 同一授权可以在不同交易风格下进行可比模拟。
- 路由理由、Agent 版本、资源和结果全量留痕。
- Agent 不得突破授权方向、仓位和风险边界。

### M6：平行空间动态模拟交易市场（P1）

目标：形成实时数据驱动的组合级模拟交易闭环。

重点：

- 虚拟账户和资金
- 模拟撮合、滑点、延迟和流动性
- 组合构建、加减仓、换仓和再平衡
- 回撤、支撑、失效、风险预算
- 日内交易状态机
- 反事实评估
- 多组合、多策略、多 Agent 并行

验收：

- 系统可连续运行一个完整交易周期。
- 每次组合变化都有触发原因和授权依据。
- 可按标的、组合、策略、Agent 和交易日回放。

### M7：运营报告、策略升华与蒸馏（P1）

目标：将运行结果转化为组织学习能力。

报告：

- 日报：当天信号、授权、成交、风险、盈亏和异常。
- 周报：策略/Agent/风格/周期表现与错误归因。
- 月报：版本、稳定性、回撤、市场状态适应性和升级建议。

蒸馏：

- 保存完整上下文，不只保存最终买卖标签。
- 记录为何路由、为何选择风格、为何拒绝执行、为何卖出。
- 将高质量决策链筛选成训练样本。
- 建立大模型教师→模拟市场验证→小模型候选→影子评测→升级的流程。

验收：

- 报告数据可从事件账本重算。
- 蒸馏样本可回指原始交易证据。
- 小模型上线前必须经过影子对照，不能直接替换生产 Agent。

### M8：生产化治理与渐进式接管（P2）

目标：在模拟市场充分验证后，再考虑真实交易接口或更高自动化等级。

前提：

- 证据链完整率达到目标
- 模拟成交和回测口径一致
- 风险否决和人工升级稳定
- Agent 路由可解释
- 数据新鲜度和质量可监控
- 运行故障可恢复

在此之前，默认只允许研究、回测、纸面和模拟交易，不直接接管真实资金。

## 十、关键风险与控制措施

| 风险 | 控制措施 |
|---|---|
| 把旧脚本直接包装为 Agent，职责不清 | 先契约、后编排；所有 Agent 必须声明输入、输出、权限和证据 |
| 选股策略越权交易 | 策略只输出候选观点，交易必须有投研授权和风控通过 |
| 组合买卖无法解释 | 组合管理器每次动作写入触发因子、规则命中和授权引用 |
| 回测与模拟口径不一致 | 统一数据可见性、成交、费用、日历、T+1 和账本内核 |
| 多 Agent 意见冲突 | 由投研/交易 Hermes 汇总；保留分歧，不静默覆盖 |
| 实时数据缺失造成假信号 | 数据健康门控；缺失则降级、暂停或升级，不伪装正常 |
| 过早蒸馏错误行为 | 只蒸馏经过复盘确认、证据完整且样本外稳定的轨迹 |
| 历史存量混入缓存/凭据 | 源码、文档、契约与运行态分离；凭据、Cookies、模型缓存一律隔离 |
| 任务并发造成重复交易 | 幂等键、状态机、订单锁、组合级互斥和可恢复任务 |
| 研究方案未经验证直接上线 | 发现→实验→影子→对照→审批→升级，禁止跳级 |

## 十二、最终产品定义

这个系统最终不是：

- 一个选股器
- 一个回测脚本
- 一个盯盘机器人
- 一个交易机器人
- 一个报告页面

而是：

> **一个由 Hermes 主管组织多个研究、盯盘、投研和交易 Agent，在真实情报与数据驱动下，于平行模拟市场中动态管理组合、全程保存证据、持续复盘和训练蒸馏的量化智能交易操作系统。**

核心闭环为：

```text
研究发现
  → 选股入池
  → 滚动回测
  → 盯盘触发
  → 投研核实
  → 交易授权
  → 动态组合
  → 模拟成交
  → 全程溯源
  → 复盘归因
  → 策略升华
  → 小模型蒸馏
```

本文件作为整体方向和研发计划基线。后续所有历史代码调整、模块归位和新工单拆解，都应引用本基线中的业务域、控制面、状态机和证据链定义。

## 十三、复盘修订项（v1.1，2026-10-18）

对 v1.0 复盘后，补充以下强制性设计，作为后续正式工单拆解的前置约束：

### 13.1 从“四大业务域”升级为“业务域 + 运行控制层”

原四大业务域保持不变，但不得直接串联调用。新增明确的运行控制层：

```text
数据/情报 → 质量与时钟门 → Regime 快照 → 业务域决策
                                      ↓
                    组合决策 → 风险政策 → 订单执行 → 结算复盘
```

业务域负责提出事实、研究、建议和授权；控制层负责数据可用性、权限、组合预算、风险否决、撮合、结算和恢复。Hermes 位于编排面，不得成为控制层事实的替代品。

### 13.2 运行模式与可复现性成为一等概念

系统必须显式区分 `BACKTEST`、`REPLAY`、`SHADOW`、`SIM_MARKET` 四种模式。每次决策绑定 `decision_bundle_id`，至少锁定：策略版本、模型/提示词版本、数据快照、Regime 快照、规则配置、费用与撮合配置、运行模式和代码版本。

模式之间只允许传递封存快照，不共享可变“最新数据”查询，不允许跨模式写入原始事实账本。影子建议进入模拟市场时，必须重新生成模拟模式的决策包。

### 13.3 组合决策与执行分层

将交易链固定拆为：

```text
Decision → Portfolio → Risk Policy → Execution → Settlement
```

- Decision：解释为什么想做什么。
- Portfolio：解释资金、仓位、暴露和冲突如何分配。
- Risk Policy：决定是否放行，拥有硬否决权。
- Execution：只负责订单意图、撮合、滑点、部分成交和撤单。
- Settlement：只负责现金、持仓、费用、盈亏和事实核对。

任何 Agent 或 Hermes 都不得跨层写入另一层的事实账本；交易 Hermes 不能提高授权上限，执行层不能自行改变方向。

### 13.4 Hermes 运行时权限与降级语义

四个 Hermes 需要登记可读域、可写事件、可发起 proposal、可批准 authorization、资源预算、超时策略、人工升级条件和 kill switch。默认规则：超时、缺证据、数据冲突和版本缺失均为 `BLOCKED` 或 `DEGRADED`，不允许隐式放行。

### 13.5 阶段编号统一

为避免与 agent_platform 的 M0-M6、数字军团的 M0-M5 混淆，量化路线统一使用 `QT-M0` 至 `QT-M8`；外部项目沿用其自身前缀，不另建重复账本或重复事件链。

### 13.6 多策略 Agent 工厂与首个 MVP

未来增加策略的标准动作不是修改主流程，而是向平台注册一个新的 AI 策略 Agent。每个策略 Agent 由独立策略包组成，并通过统一注册表进入平台：

```text
strategy_package
  → Strategy Agent 注册
  → 能力/权限/资源校验
  → 契约测试与历史回放
  → SHADOW 影子运行
  → 增量价值/冲突评估
  → 人工批准
  → 灰度 ACTIVE
```

平台公共主链只消费标准契约，不允许出现 `if strategy_name == ...` 的业务分支。新增策略不得修改盯盘、投研、组合、风控、执行和结算主流程；策略之间的差异必须通过 `capability_manifest`、版本配置和证据策略表达。

首个纵切仍收缩为：一个市场、一个组合、一个模拟账户、一个交易风格、一个主策略和一个挑战策略。挑战策略只做影子对照，不直接触发授权。但 M2 的架构验收必须增加“第 3 个策略接入演练”：在不修改公共交易主链的情况下完成注册、运行、回放、影子评估和撤退。

以上修订不改变原有“真实资金交易另行评审”的红线，只是将数据质量、时钟、模式隔离、组合预算、Hermes 权限和多策略可扩展性从原则提升为硬门禁。
