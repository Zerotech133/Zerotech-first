## 1. 能力与数据流

```
问题 ──► 检索融合 ──────────────────────────────► 生成 ──► 引用校验 ──► 答案+引用+置信
         ├ kb_read_api.cmd_search        （知识单元 498 条：研报+书籍）
         └ kb_read_api.cmd_corpus_search （RAG chunks 4926 条：C:/项目/知识库/50_RAG/rag_index_corpus.json）
                  └ 归一化融合：unit 权重 1.0 / chunk 0.35，chunk 需命中≥2 个问题词（降噪），
                    按 unit_id + 原文前缀去重，取 topk（默认 8）
                          └ 本地 Ollama qwen3.5:9b（/api/chat，stream=false，think=false，timeout=300s）
```

- 检索：直接复用 `kb_read_api.py` 的 `cmd_search` / `cmd_corpus_search`（统一信封），失败按无命中处理（不抛错、不编造）；
- 生成：prompt 强制「只依据检索材料回答；每结论引用 [unit_id] 与页码；无依据必须回答不知道」；
- 失败降级：Ollama 不可用/超时/空内容 → 规则式摘录前 2 条材料 + 引用（`fallback=true`，`confidence=low`，不编造）。

## 2. 引用规范（citations）

| 字段 | 说明 |
|---|---|
| `unit_id` | 知识单元稳定 ID（kb_read_api 计算，12 位 hex）或 RAG chunk id |
| `book` | 书名/研报 ID（chunk 为语料视频/来源 ID） |
| `chapter` | 章节（chunk 为空） |
| `page` / `page_end` | 知识单元 `page_start`/`page_end`；chunk 为 chunk_index；缺失显示 `?` |
| `origin` | `units`（知识单元）或 `corpus`（RAG 语料） |
| `text` | 原文片段（截断 300 字） |

- 只输出 **answer 中实际以 `[unit_id]` 标注且命中检索材料** 的引用；未知/编造 ID 记入 `citation_check.hallucinated_citations`（已剔除）；
- 回答未标注任何引用时 `citation_check.citation_missing=true`，置信降级；
- 置信说明（`confidence.level/reasons`）：`high`=≥2 条可核验引用且无未知引用；`medium`=1 条；`low`=无引用/存在未知引用/规则降级；`none`=拒答或无检索命中。

## 5. 能力边界

1. **只回答知识库材料覆盖的问题**：材料不足时按规范拒答，不做模型自身知识补全；检索无命中直接拒答（不调 LLM）。
2. **语料噪声**：corpus RAG 含视频评论等噪声 chunk，已用「命中≥2 问题词 + 低权重」降噪；对非研报/书籍主题仍可能召回到弱相关内容，引用需人工核验。
3. **页码口径**：知识单元页码为 `page_start..page_end`，同一单元内多事实共享区间；chunk 页码为 chunk_index，非原 PDF 页码。
4. **LLM 幻觉**：已做引用 ID 校验与无依据拒答约束，但长回答仍可能表述过度；`confidence` 仅为启发式说明，**不能替代人工复核**。
5. **不构成投资建议**：本工具是研究辅助；回答仅摘录/归纳知识库材料。

## 9. multi 默认模式（2026-11-01 wave18 AZ，A/B 落地）

依据 wave17 AW A/B 结论（v3 问题库前 30 条：single 可答率 33.3% → multi 80%，McNemar p=0.000122，
回退 0 条，单条耗时比 1.03×，5/5 判定达标），`kb_qa.ask` 默认模式切换为 **multi（多单元聚合）**。

### 9.1 默认值与用法

- `ask(question, topk=8, mode="multi")`：默认 multi；`mode="single"` 保持旧单单元行为；`retrieval_only=True` 仍为纯检索（与 mode 无关）。
- CLI：`python tools/kb_corpus/kb_qa.py ask "问题"` → 默认 multi；`--mode single` 或 `--single` 切回旧行为；`--k N`（默认 8，multi 内部钳制 5–8，兼容旧 `--topk`）。
- payload 新增：`mode`（multi/single/retrieval）、`k`、`clusters`（multi 的聚类摘要）、`direct_fact_markers`/`inference_markers`（multi 区分直接事实/推断）。

### 9.2 回退（灰度安全）

- multi 加载/执行异常（模块缺失、检索/LLM 异常、超时等）→ **自动回退 single**：payload `mode="single"`、`multi_fallback=true`、`multi_fallback_error=<原因>`，保证可用性；
- multi 检索无材料时按原有规则直接拒答（不调 LLM）。

### 9.3 成本

| 项 | single | multi |
|---|---|---|
| LLM 调用 | 1 次/问 | 1 次/问（检索+聚类为本地计算，无额外 LLM） |
| prompt 长度 | 较小 | 更长（≤3 簇 × ≤3 单元，top-8 检索） |
| 单条耗时（A/B 实测） | 8.35s | 8.61s（≈1.03×） |
| 可答率（A/B n=30） | 33.3% | **80%** |

成本增量主要来自更长输入 token 与聚类检索，本地 Ollama 无云成本；multi 允许推断，引用/直接事实仍需人工复核。

### 9.4 灰度建议

1. 当前为 CLI 默认 multi；HTTP 接口（待 8091 接线提案批准）建议先以 `mode` 参数暴露、默认 multi 但保留 single 回退，并做影子对比；
2. 页面/agent 调用如需确定性输出，可显式 `--mode single`；
3. 后续扩样到 50 条问题复跑 A/B（`kb_qa_multi_ab.py run --n 50`）验证稳定性后再全量。

验证：`python -m pytest -q tools/tests/test_kb_qa.py` → **16 passed**（含默认 multi/single 兼容/回退/参数校验/CLI 开关）；
`test_kb_qa_multi.py` 回归 → **6 passed**；实测 CLI 默认 multi：`mode=multi, k=8, clusters=3, citations=2, confidence=high, 9.98s`；
`--single`：`mode=single, clusters=0, citations=3, confidence=high, 11.05s`。

## 10. multi + guard 出口（2026-11-01 wave20 CA，质量守卫生效）

依据 wave19 BE 质量守卫（`tools/kb_corpus/kb_qa_guard.py`：引用可解析硬门 / 推断比例 ≤0.6 / 被引单元 ≥2），
在 `kb_qa.ask(mode="multi")` **返回前默认接入 guard**（single / retrieval_only 不受影响）。

### 10.1 默认行为与参数

- `ask(..., mode="multi", guard=True, on_guard_fail="fallback")`：默认开启守卫、默认 fallback；
- `on_guard_fail`：`fallback`（默认，不通过→回退为「可核验知识单元摘录」，`fallback=true`）｜`mark`（仅标记不改答案）｜`refuse`（拒答）；
- `guard=False`：完全绕过守卫（灰度对比/旧行为复现），payload 标 `guard_enabled=false`、`guard_action="disabled"`；
- CLI：`--no-guard` 绕过；`--on-guard-fail fallback|mark|refuse`（默认 fallback）；`_print_human` 显示「质量守卫：passed/action/issues」；
- multi 失败仍回退 single（`guard_action="multi_fallback_single"`）；guard 自身不可用时**不阻断问答**（`guard_action="guard_unavailable"` + `guard_error`，原答案保留）。

### 10.2 payload 字段（multi 出口新增）

`guard_enabled` / `guard_passed` / `guard_issues` / `guard_action` / `citation_valid` / `citation_invalid` /
`citation_resolvable_rate` / `inference_ratio` / `inference_heavy` / `distinct_cited_units`
（single/retrieval 不新增这些字段，保持向后兼容）。

### 10.3 成本与灰度

- guard 为**后处理**，零额外 LLM 调用；fallback 会降低可答率（wave19 实测 67%→50%）但把不合格答案替换为可核验摘录；
- 灰度建议：默认 `fallback`；需要观察期可切 `mark`（不降可答率、保留 raw 答案）并统计 `guard_passed` 率；`refuse` 仅在严格场景使用；
- HTTP 接口（待 8091 批准）建议沿用 `on_guard_fail=fallback` + `guard=false` 灰度开关。

验证：`test_kb_qa.py` → **22 passed**（含 guard pass/fallback/refuse/mark、guard=False、guard 不可用、payload 字段、CLI 开关）；
`test_kb_qa_multi.py` + `test_kb_qa_guard.py` 回归 → **11 passed**；实测 CLI 默认 multi+guard：
`mode=multi, k=8, clusters=3, guard_enabled=true, guard_passed=false, action=fallback, issues=[inference_heavy], citations=2`。

## 11. guard 标记解析口径（2026-11-01 wave27 CS）

`kb_qa_guard` 新增 `marker_mode` 参数，默认 **strict_line**：

- **strict_line（默认）**：只统计**行首/句首明确标注**的标记——
  `【事实】`/`【直接事实】`/`【推断】`（含项目符号 `- `、编号 `2. ` 前缀），以及 `事实：`/`推断：` 前缀行；
  排除 markdown 标题（如 `## 推断`）、`【推断】如下` 标题行、说明文字、few-shot/示例行（含「示例」「few-shot」等词）与 ``` 代码块内容；
- **legacy（兼容/对比）**：旧行为，子串匹配（会把段标题里的「推断」也计入）——可用于复现历史结果，不建议新链路使用；
- 返回 payload 增加 `marker_mode` 字段；`compute_guard_metrics` / `apply_guard` 均支持该参数。

**修复动机**：wave26 prompt v3 的【事实摘录】/【推断】分段导致段标题被 legacy 计入推断 → inference_ratio=1.0 → 全量 fallback。
**离线重评（guard_marker_fix_20261101）**：修复后 inference_ratio 1.0→0.8，guard 通过率 0%→10%、可答率 0%→10%——
改善有限，**v3 prompt 仍不值得合入**（保留 v1；如需继续，应同时改模型标注行为/guard 阈值，并扩样）。
