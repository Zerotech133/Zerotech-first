# 知识库每日自动化 v1

> 2026-11-01 · 目标：把知识库日常分散的四个脚本（学习卡摘要、研报面板、入库状态、问答检索冒烟）收口成**一条可编排、可巡检、失败隔离**的每日任务，
> 每次运行落一份状态台账 `research/reports/daily_kb_status.json`，并给出门户静态产物的刷新清单。

## 一、背景

知识库侧已有多个独立脚本，此前需人工逐个执行：

| 脚本 | 作用 | 门户产物 | 消费页面 |
|---|---|---|---|
| `tools/kb_corpus/learning_digest.py run` | 学习卡（每日5张/去重排序）+ 简报摘要 + 策略结论 | `portal/static/kb_learning_digest.json` | `/kb_reports.html` |
| `tools/research/panel_daily.py run` | 研报面板刷新 + 变更摘要 + 状态台账 | `portal/static/report_panel.json` | `/selection.html` |
| `tools/kb_corpus/kb_ingest_status.py` | PDF 知识入库状态 | `portal/static/kb_ingest.json` | `/kb_ingest.html` |
| `tools/kb_corpus/kb_qa.py ask … --retrieval-only` | 问答检索冒烟（不调 LLM） | （无静态产物，仅校验检索链） | — |

问题：漏跑、顺序不定、失败无记录、门户数据陈旧不可见。本任务新增编排器收口。

## 二、编排链

```
daily_kb.py run
  ├─ 1. learning_digest run        → portal/static/kb_learning_digest.json
  ├─ 2. panel_daily run            → portal/static/report_panel.json
  │                                   （panel_daily 内部同时追加 research/reports/report_panel_daily_status.json）
  ├─ 3. kb_ingest_status           → portal/static/kb_ingest.json
  └─ 4. [--with-qa] kb_qa ask <检索冒烟问题> --retrieval-only --json
                                    → 仅校验检索链（无 LLM、无静态产物）

每次运行结束 → research/reports/daily_kb_status.json（状态台账）
```

- 步骤定义在 `build_steps(with_qa)`，可按 `--steps a,b` 过滤（保持定义顺序）；
- 单步超时默认 900s（`--timeout` 可调），超时记为 `rc=124` 并继续后续步骤；
- 子进程统一用 `sys.executable -X utf8`（生产环境 = `C:\项目\py312\python.exe`），工作目录=仓库根。

## 三、状态台账 Schema（`research/reports/daily_kb_status.json`）

| 字段 | 类型 | 说明 |
|---|---|---|
| `schema_version` | int | 台账版本（当前 1） |
| `generated_at` | str | ISO 时间（带时区） |
| `mode` | str | `run` / `check_only` |
| `ok` / `rc` | bool/int | 全步成功 / 最终退出码（有错误=1） |
| `with_qa` | bool | 是否跑了问答检索冒烟 |
| `steps_requested` | list | 本次请求的步骤名（含过滤） |
| `duration_seconds` | float | 总耗时 |
| `steps[]` | list | 每步：`name/desc/script/args/command/rc/ok/elapsed_seconds/started_at/outputs/stdout_tail/stderr_tail/error` |
| `steps[].outputs[]` | list | 输出快照：`path/exists/mtime/mtime_epoch/size`（**含输出 mtime**） |
| `latest` | dict | 各产物最新快照（learnig_digest/panel_daily/kb_ingest/panel_daily_status/kb_qa_samples） |
| `portal_refresh` | list | 门户刷新清单（见下） |
| `errors` | list | 失败隔离后的错误汇总（步骤名 + rc + 摘要） |
| `warnings` | list | 非致命提示（如步骤脚本缺失） |
| `disclaimer` | str | 免责声明（**必须含「不构成投资建议」**，`--check-only` 强制校验） |

## 四、失败隔离与超时

- 每一步在 `run_step()` 内兜住所有异常：`TimeoutExpired`→`rc=124`、`FileNotFoundError`→`127`、其他异常→`-1`；
- **单步失败不中断后续步骤**；错误写入 `steps[i].error` 与顶层 `errors`，最终 `ok=false / rc=1`；
- 状态台账**无论成败都会写盘**（供巡检/看板追踪）；
- 记忆口诀：*失败只记录、后续照跑、账要落盘*。

## 五、CLI

```powershell
cd C:\项目\老田的AI助手

# 1) 全量编排（3 步）
C:\项目\py312\python.exe -X utf8 tools/kb_corpus/daily_kb.py run

# 2) 附加问答检索冒烟（4 步，不调用 LLM，约 2~3s）
C:\项目\py312\python.exe -X utf8 tools/kb_corpus/daily_kb.py run --with-qa

# 3) 只跑部分步骤 / JSON 输出 / 自定义台账路径
C:\项目\py312\python.exe -X utf8 tools/kb_corpus/daily_kb.py run --steps learning_digest,kb_ingest_status
C:\项目\py312\python.exe -X utf8 tools/kb_corpus/daily_kb.py run --json
C:\项目\py312\python.exe -X utf8 tools/kb_corpus/daily_kb.py run --status tmp\daily_kb_status.json

# 4) 轻量巡检：只读现有状态 JSON，校验 schema/免责声明，不执行子脚本
C:\项目\py312\python.exe -X utf8 tools/kb_corpus/daily_kb.py --check-only
C:\项目\py312\python.exe -X utf8 tools/kb_corpus/daily_kb.py check --json

# 5) 内嵌测试
C:\项目\py312\python.exe -X utf8 -m pytest -q tools/tests/test_daily_kb.py
```

退出码：`0`=成功；`1`=有步骤失败 / check 校验失败；`2`=参数错误（如未知 `--steps` 名称）。

## 六、门户刷新清单（`portal_refresh`）

| static JSON | 生产步骤 | 消费页面 | 区块 |
|---|---|---|---|
| `portal/static/kb_learning_digest.json` | learning_digest | `/kb_reports.html` | 📚 学习卡（每日 5 张）/ 📰 今日简报 |
| `portal/static/report_panel.json` | panel_daily | `/selection.html` | 研报候选（多智能体） |
| `portal/static/kb_ingest.json` | kb_ingest_status | `/kb_ingest.html` | 知识入库状态 |
| `portal/static/kb_qa_samples.json` | kb_qa samples（手动/可选） | （暂无页面消费，备用） | 问答示范样本 |

> 门户读静态 JSON、无需重启服务；刷新后浏览器带 `?ts=` 直读最新文件。面板/入库页若做缓存需强刷（Ctrl+F5）。

```powershell
# 示例 A：PowerShell 注册每日 07:30（在审批后由人工执行）
$py    = 'C:\项目\py312\python.exe'
$repo  = 'C:\项目\老田的AI助手'
$args  = "-X utf8 $repo\tools\kb_corpus\daily_kb.py run --with-qa"
$action  = New-ScheduledTaskAction -Execute $py -Argument $args -WorkingDirectory $repo
$trigger = New-ScheduledTaskTrigger -Daily -At 07:30
$settings = New-ScheduledTaskSettingsSet -StartWhenAvailable -ExecutionTimeLimit (New-TimeSpan -Minutes 30)
Register-ScheduledTask -TaskName 'ZeroBound-KB-Daily' -Action $action -Trigger $trigger `
  -Settings $settings -Description '零界知识库每日刷新（学习卡/研报面板/入库状态）' -User $env:USERNAME

# 示例 B：schtasks（等价）
schtasks /Create /TN "ZeroBound-KB-Daily" /SC DAILY /ST 07:30 /F ^
  /TR "\"C:\项目\py312\python.exe\" -X utf8 \"C:\项目\老田的AI助手\tools\kb_corpus\daily_kb.py\" run --with-qa"
```

运维要点：

1. 用**绝对路径**（计划任务默认工作目录非仓库根）；`daily_kb.py` 内部已 `cwd=仓库根`，但启动命令仍建议显式路径；
2. 出问题先看 `research/reports/daily_kb_status.json` 的 `steps[].error / errors`；再跑 `--check-only` 做快速体检；
3. 回滚：`Unregister-ScheduledTask -TaskName 'ZeroBound-KB-Daily' -Confirm:$false`（同样属宿主级操作，需审批）；
4. 日志：可给命令加 `>> C:\项目\老田的AI助手\logs\kb_daily.log 2>&1`（长跑输出落文件，遵循仓库红线）；
5. 无需重启 8091/门户：所有产物是静态 JSON，页面下次 fetch 即最新。

## 十、限制与后续

1. **编排器不修改子脚本**：每个步骤的成败取决于被调脚本自身契约（rc/产物路径）；子脚本改 CLI 需同步本编排。
2. **`--with-qa` 只做检索冒烟**（`kb_qa ask --retrieval-only`，不调 LLM、不产出 `kb_qa_samples.json`）；完整问答样本仍走 `kb_qa samples`（含 LLM，较慢，未纳入每日默认链）。
3. **panel_daily 会向自己的状态台账追加运行记录**（`report_panel_daily_status.json` 增长），属正常行为；如担心无限增长，可在其脚本内做截断（不在本任务范围）。
4. 未接 8091 HTTP 接口：日报状态/门户刷新清单可通过静态文件读取；如需 API 需走门户接口审批。
5. 计划任务安装属宿主级操作，**本次未注册**，待人工审批后按 §7 示例执行。
