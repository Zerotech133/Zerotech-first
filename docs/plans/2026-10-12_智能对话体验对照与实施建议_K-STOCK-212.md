## 1. 目标与边界

目标是让零界的本地聊天入口具备“可理解、可恢复、可追溯”的工作流：用户能明确当前角色和模型，知道回答是否在思考、是否引用了知识库来源，并能从历史会话恢复工作。

本轮只优化交互层和状态表达，不改变 Ollama API 协议、RAG 检索算法或模型路由策略。联网搜索在后端未接通前只作为禁用/待接入状态展示，不能伪装成已生效能力。

## 2. 参考项目提炼

### 2.1 菜鸟（thunder-model-admin）

源码确认的可复用模式：

1. 角色、模型、会话三者分离。角色决定工作目标，模型是执行资源，会话保存上下文。
2. 会话标题和消息列表可持久化，空会话有欢迎态，执行中有明确加载态。
3. 思考过程、停止生成、清空、回到顶部、消息操作都是显式控件。
4. AI 分析节点使用结构化输出约束；异常时保留已生成内容并进入 degraded 状态。
5. 工具自取数据，触发上下文保持精简，避免把所有行情或文档一次性塞入提示词。

### 2.2 Open WebUI

可复用模式：

- 本地记忆和 RAG 证据在回答附近显示；
- 工作流状态和多模型切换可见；
- 对本地服务离线、索引未就绪等状态给出可理解反馈。

### 2.3 LobeHub

可复用模式：

- Agent/项目上下文独立于单条消息；
- 长期记忆是可管理的工作区能力，而不是隐式拼接；
- 团队/角色协作通过明确的上下文边界表达。

### 2.4 LibreChat

可复用模式：

- 推理过程默认折叠，用户需要时再展开；
- 复制、重试、会话搜索、上下文开关、附件和分支恢复是高频操作；
- 流式中断后保留已显示文本，并允许继续处理。

## 4. 设计原则

1. **状态先于装饰**：连接、思考、检索、生成、失败、取消都用可读状态表达。
2. **证据贴近回答**：RAG 来源与回答同一视觉上下文，默认摘要，展开后显示来源元数据。
3. **可恢复优先**：任何流式异常都保留已有内容；重试从原问题重新发起，不覆盖原消息。
4. **能力诚实**：未接入的联网搜索、附件解析等入口必须标“待接入”或禁用。
5. **遵守平台壳**：继续使用 portal/static/tokens.css、统一 nav.js 和短屏化规则，不在页面内自绘第二套视觉系统。
6. **上下文可控**：默认保留当前会话上下文；用户关闭后只发送当前问题，避免隐式污染。

## 5. 下一批实现顺序

### P1：RAG 来源卡片详情

- 展开显示文档标题、片段、相似度、索引版本、更新时间；
- 支持复制引用片段；
- 无来源时明确显示“本次回答未命中知识库”。

验收：来源字段缺失时页面不报错；同一回答可展开多个来源；移动端不横向溢出。

### P1：Markdown 与代码块

- 对回答正文做安全 Markdown 渲染；
- 代码块提供复制按钮；
- 保留纯文本降级，禁止执行脚本或原始 HTML 注入。

验收：标题、列表、代码块、行内代码可读；恶意 HTML 被转义；流式增量渲染不破坏未闭合代码块。

### P2：附件与会话治理

- 附件入口先支持本地文本/Markdown；
- 会话支持置顶、重命名、删除；
- 删除前给出可撤销提示，持久化结构向后兼容。

验收：附件元数据进入消息记录；删除/恢复刷新列表；旧版 localStorage 可迁移。

### P2：断线恢复与消息排队

- 为每条流式请求记录 request id 和最后已显示片段；
- 断线时保留部分回答，提供继续/重试；
- 同一会话多条发送按序排队，避免上下文乱序。

验收：模拟断网后页面不丢消息；刷新后能识别未完成消息；重复提交不会产生双份记录。

## 6. 暂不采用的做法

- 不复制菜鸟的五节点策略编排到聊天页；当前产品重点是本地助手，不是投研工作流编排。
- 不在前端伪造联网搜索结果或“已联网”状态。
- 不引入第三方前端运行时；保持零第三方依赖与内嵌 HTML 交付。
- 不把长期记忆直接混入每次请求；记忆应先有独立的可见、可控数据结构。

## 7. 验证要求

每一批改动都先补页面契约测试，再运行：

    python -m unittest AI/111111/test_web_ui.py
    python -m unittest discover -s AI/111111
    python -m py_compile AI/111111/web_ui.py
    git diff --check

真实联调时确认：

- http://127.0.0.1:8899/ 返回 200；
- Ollama 服务不可用时连接徽标和错误文案正确；
- RAG 有命中和无命中两条路径都能完成；
- 浏览器辅助功能树能看到会话、思考、来源、复制、重试和上下文开关。

## 8. 结论

菜鸟提供了角色分离、结构化输出和降级态的工程范式；Open WebUI、LobeHub、LibreChat补齐了证据、记忆、推理折叠和恢复操作。零界当前聊天页已经吸收了第一层高价值能力，后续应优先做来源详情、Markdown/代码块和可恢复流式消息，把“能聊”推进到“可持续工作”。
