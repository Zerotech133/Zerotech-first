## 二、背景与问题（为什么必须补这两刀）

### 2.1 ⑤：v0 旧验收单是「历史工具缺口」，不是黄忠的举证缺陷

- v0 版验收工具（2026-10-28 前）只落「全局最新」基线/红队结果，**不落** `evidence.baseline.age_hours` / `evidence.baseline.stale` / 顶层 `max_evidence_age_hours`；v1 工具（A 单 `WO-HZ-ACCEPT-EVIDENCE-20261030`，2026-10-30 落地）才写入这些年龄字段。
- v2 §2.2⑤ 要求「证据完整率 100% + 年龄 ≤48h」，旧单缺年龄字段时按原口径一律 ✗，导致 ⑤ 长期被历史单钉死：**2026-10-30 复核实测 完整率 33.3%（3/9）**，其中 6 张为 v0 旧单，无法判定「是否超龄」而非「确实超龄」。
- 拍板判断：这类单**不应计入 ⑤ 分母**，同时**保留历史台账**（可溯源、可人工抽查），等 11-04 前的新口径 PASS 单（带年龄字段）补齐后按新单判定。

### 2.2 ③：v1.0 实现与 v2 标准不一致

- v2 §2.2③ 明确：自然 REJECT<20 时「5% 阈值无统计意义 → 按**逐单人工复核，确认无误拒**判定通过」。
- v1.0 复核工具在自然 REJECT<20 时**一律 pending**（根本没读 `reject_review*.json`），导致老田/赵云已完成签字复核的演练 REJECT 样本不被采信，③ 永远无法转 ✓。
- 现网数据即典型：自然 REJECT 0 单、演练 REJECT 1 单，`work/huangzhong/reject_review_20261030.json` 已覆盖该演练单、复核结论「确认拒收（0 推翻）」，旧实现仍判 pending。本单修正为读清单、按覆盖度与推翻数判定。

## 三、拍板规则（落入口径）

### 3.1 ⑤ legacy v0 豁免

**legacy 判定（PASS 单，满足任一即 legacy）**：

1. `evidence.baseline.age_hours` 缺失（非数值）；
2. `evidence.baseline.stale` 缺失（非布尔）；
3. 顶层 `max_evidence_age_hours` 缺失（非数值）。

**处理**：

- `exempt`（默认）：legacy 单**不进 ⑤ 分子与分母**——`complete_count` / `total` / `completeness_rate` / `fresh_count` 均只按非 legacy 单计算；`detail` 增 `legacy_policy`、`legacy_detected_count`、`legacy_excluded{count, files, samples}`；报告 MD 同步展示豁免数量与文件清单；`measured` 末尾追注「legacy v0 豁免 N 单」。
- 若**无非 legacy PASS 单**：⑤ 判 **pending**（"无非 legacy PASS 单可判"），不得因豁免而误判 ✓。
- `count`（旧行为）：legacy 单计入分母，缺字段照判 ✗（仅回溯/对账用，不作为 11-04 复核默认口径）。
- **历史台账保留**：`work/huangzhong/acceptance_*.json/.md` 不删除、不改写、不补造年龄字段；legacy 单仍计入 ① PASS 样本量（① 口径不变），**仅 ⑤ 豁免**。

### 3.2 ③ 逐单人工复核判定

**自然 REJECT ≥20 单**：原逻辑不变——误拒绝率 = 复核推翻 REJECT 单 / REJECT 总单（含演练单），<5% → ✓，清单不完整 → pending，≥5% → ✗。

**自然 REJECT <20 单**（逐单人工复核口径）：

| 复核清单状态 | 判定 | 说明 |
|---|---|---|
| 覆盖全部 REJECT（自然+演练）且推翻 = 0 | **✓** | measured 记「自然 REJECT N<20；逐单复核 0 推翻（清单 m 条）」 |
| 清单不完整（有 REJECT 未见结论） | pending | 补齐 `reject_review*.json` 后重跑 |
| 有推翻（overturned=true） | **✗** | 误拒单须作废重验/修正后重新复核（本口径要求 0 推翻） |
| 无任何 REJECT 样本 | pending | 无可复核对象，不虚判达标 |

- 复核清单格式沿用 v1.0：`work/huangzhong/reject_review*.json`，每行至少含 `sha`/`file` + `overturned`（或 `result`/`结论` 等可由工具识别的等价字段）+ 复核人/证据依据；**谁复核、结论、证据依据由老田/赵云签字落盘，工具只读不代批**。
- 匹配键：commit sha8 优先，其次验收单文件名；自然 REJECT 单与演练台账 REJECT 条目合并去重后作为「全部 REJECT」集合。

## 六、回滚方式

1. **口径回滚（不改代码、不重启）**：⑤ 用 `--legacy-v0-policy count` 即回旧行为；若需把 ③ 也回旧行为，由于 ③ 无独立 CLI 开关，回滚方式为 revert 本单提交（`git revert <WO-HZ-POLICY-20261030 commit>`）。
2. **数据回滚：无必要**——本单不改 `work/huangzhong/` 下任何验收单/证据/台账；复核报告由工具重新生成覆盖，旧报告文件保留可查。
3. **风险与约束**：③ 依赖人工复核清单的真实性（工具无法识别伪造结论），与 v2 同口径，须由老田签字 + 赵云抽查兜底；若 11-04 后发现新单被误判为 legacy，应检查验收工具版本（v1 起强制写 `max_evidence_age_hours`）并在报告中单列说明。
