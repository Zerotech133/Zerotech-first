### 1.2 拓扑（数据流与告警流）

- 备份数据流：容器 →（pg_dump \| gzip）→ 分叉：① 主链 宿主 `Test-Gzip` 全量校验 → AES 加密 `.enc` → mirror keep-4 → 异地字节一致 → vault 14d；② 副链 宿主 `gzip.open` 收流 → `backups/db/YYYY-MM-DD/` + manifest。
- 治理数据流：`Get-ScheduledTask` / schtasks 只读 → `task_inventory.py` 快照/diff/stats → JSON 台账；产物 → `backup_format_gate.py`（魔数 / 8 MiB 探针 / sha256）→ 判据。
- 告警流（**实施期设计，本轮零调用**）：脚本 → `alert_fail_wrap.py::main(code, 摘要, 第三参=日志路径)` → `alert_fail.py` → 飞书；失败 → 本地 `ALERT_PENDING/`。
- **无常驻采集器、无网络监听、无 trace 上报端点**（候选 A 硬约束）。

### 1.3 环境划分与发布窗口避让

单环境（本机即生产），无预发/测试/灰度。pytest 与自建夹具在 `C:\Temp` 级旁路运行、只读现存产物，**不连生产库、不写 `backups/db`**。旁路新文件与既有产物物理同盘但语义隔离：新文件路径全新、既有产物只读、绝不改写。

**发布窗口约束（承接 W-12）**：团长单写者独占窗口，须避开本机并行作业，并避开 06–09 点 76 个 Ready 早高峰、07:45 `\BackupDaily` 加密主链、07:56–08:33 与 10:08–10:25 备份写入窗口；建议工作日上午，留足 T+48h 观察。与 AL-03 / AL-06 / 场景 5 的窗口护栏共用同一组只读判据。

### 1.4 可追溯凭据：留痕与核验两路拆开

本轮新增文件**不提交 git**（ADR-09 + W-12 v1.3 口径），发布可追溯凭据 = **发布单模板（W-12 v1.3 内）+ 逐文件 sha256 清单（W-13，团长生成）+ FF06 接入点（W-09）** 三件套。但「留痕」与「核验」是两路，**不得写成「本轮完全不用 git」**：

#### 2.3.2 哈希算法同口径（T-10 已终裁 A，防误触发 FF05）

**T-10 已由团长形式终裁 ② 采纳 A（全量 sha256）**，不再是「待终裁」。B2 口径固定为：

#### 2.3.4 B4 语义裁定与 M09 冲突消解（已裁定，非待确认）

**团长裁定**：B4 =「**密钥内容零读取，元数据只读不算**」。理由：本轮硬边界是「不执行 `.enc` 解密、不读密钥内容、不外送」；`os.stat` 的 mtime / ACL 属**元数据只读**，不构成内容读取。与 W-12 §4.2 G6④「AES 密钥零读取、Unprotect-File 零调用、无新增 .enc 产物」、§5 回滚验证「`~/.backup_aes_key` mtime 未变、无新增 .enc」完全一致。

**冲突消解（M09 与 B4）**：M09 的「sha256 指纹核对」必须读取文件内容，与「零读取」自相矛盾，故——
1. **发布窗口内暂停 M09 的哈希采集**；B4 改以「密钥文件 mtime / ACL 未变 + 无 `Unprotect-File` 调用痕迹 + 无 `.enc` 解密产物」证明零读取；
2. **窗口结束后 M09 恢复**，且实施期恢复须标注「D0 后实施期运维常态」、指纹值不写进发布单 / 日志 / 飞书正文；
3. **依据 W-12 §4.3「判据必须可签」原则，B4 定稿为该原则的第三个应用实例（发布侧消息确认，W-12 未追加）**：若把「零读取」定义成连元数据 / 哈希都不能碰，基线将永远无法取证 → **假红 / 纸面阻塞**。该理由在 W-14 登记，避免同类矛盾复现。注：W-12 §4.3 现仅载「两处同源缺陷」（G0-b 第③项、AC-02），**本第三实例仅由 Phase 3 与 Phase 4 往来消息确认、未写入 W-12**；W-12 口径已冻结，本方案不改写、不追加，此处仅作原则引用而非章节引用。

### 3.3 第三参契约（TD-08 修复口径，新模块强制）与 IT-01

`alert_fail_wrap.py::main` 第三参的**真实语义是「错误日志文件路径」**，不是详情正文。`miss_check.py:353-357` 曾把 `json.dumps(miss)` 传入，被 `os.path.isfile()` 判非文件后静默丢弃 → 只剩 `MISS×3` 摘要、详情永久丢失。新模块强制：
1. 第三参 = 真实存在的 UTF-8 日志文件绝对路径（`os.path.isfile()==True`），详情写进该文件；
2. 摘要走 `code` 字段：单行、不含 `|`、≤120 字符；
3. 正文不含 dump 内容、webhook、密钥内容/指纹、任何凭据；
4. 单测须覆盖「传 JSON 字符串被拒」与「传真实路径详情到达」两条用例。

**IT-01 登记**：TD-08「告警正文可达」已从本轮 AC/门禁移除，登记为**实施期契约测试 IT-01**（Q7 授权后、D0/D4 后执行）。本轮 Checklist 项 6/7 是「禁令 / 零调用」**前置核验**，不是运行态验收动作；本轮不做正文可达性验收。

### 3.4 告警本身失败的降级路径 + ok 不翻转

- 发送失败（非 2xx / 超时 / 异常）→ **绝不回写 `manifest.ok`**：质量判定 `quality_ok = f(rc, 魔数, 8 MiB 探针, sha256)` 由本地校验独立决定，与 `alert_delivery` 正交，分设两个字段；网络失败只翻转 `alert_delivery=false`，**不得因网络失败把坏产物翻成 ok=true、也不得把好产物翻成 ok=false**。
- 同时写本地 `ALERT_PENDING/<ts>_<code>.md`（旁路、UTF-8、含 code 单行摘要 + 真实日志路径 + 不含凭据正文）；下一次调度或每月 1 日复核扫描该目录补发，补发成功标记 delivered 后归档（不删除留痕）。
- **开关 OFF / 免打扰抑制同样只影响送达，不影响质量判定与三联一致性**。
- 设计态声明：本轮不推真实告警、不落 ALERT_PENDING 运行态文件，以上为降级设计。

### 3.5 告警治理纪律

① 文案四要素（哪个对象/什么指标/当前值/建议动作）齐备；② 同类聚合、抑制级联（主链 rc≠0 时不再逐个重发 `.enc` 体积/异地一致性告警，合并为一条主链事件）；③ 副链超龄、两库真空等持续态按 7 天收敛；④ 每月复盘**「误报率 + 推送频次越界次数」双指标**，误报率 >30% 的规则必须调优。

### 3.6 告警频率红线与单一出口（D0/D4 后实施期运维常态）

## 四 故障应急预案（9 场景 · 发现 → 定位 → 恢复 → 复盘）

> **九场景通用禁止动作（每场景均适用，显式复述）**：① 不得顺手启用/新增/修改/禁用任何 Windows 计划任务（含 `\DbDumpDaily`、`\CainiaoPull`）；② 不得顺手改 `ops/db_dump_daily.py` 的 `DUMPS`/`KEEP_DAYS` 或 `miss_check.REGISTRY` 或 `b4_restore_drill.py`/`backup_daily.ps1`；③ 不得删除或改名任何坏档/既有产物、不得改写 `backups/db` 内容；④ 不得跑 `.enc` 解密演练（D0 未批准）。另：不得触碰 `10.205.0.118`、不得 commit。恢复动作一律「只读取证 + 旁路标记 + 报团长待裁定」，不制造新状态。

**场景 1 假绿（manifest ok=true 但产物非 gzip）**
- 识别信号：AL-10 / AL-07 / AL-08 / AL-11；魔数 ≠1f8b 或 8 MiB 探针失败，而 `manifest.ok=true`、`rc=0`；指纹比对不一致（AL-09 时升 P0）。

- 立即动作：① 用 `backup_format_gate.py` 只读复验魔数 / 8 MiB / sha256，输出三值对照；② 对该批次打**只读旁路隔离标记**（新建 flag 文件，不改 manifest——硬边界），从演练候选集排除；③ 写 ALERT_PENDING 并按设计态路由备查；④ 同批次其它产物全量复验，统计假绿数量。
- 禁止动作：四条通用红线全适用；特别不得改既有 `manifest.json` 把 ok 改成 false（属改写既有产物，延 D4 后）。

- 复盘项：为何写入侧只信 rc 不信魔数（R3）；阶段 2「写入即验」闸门设计是否覆盖该路径；10-29 同类是否同源。

**场景 2 10-29 坏档被演练选中**

- 恢复判据：本次演练改用合法档且结论标注「10-29 已隔离」、flag 可读、拦截动作有记录。

**场景 3 主链 `.enc` 解不开（密钥丢失/损坏）**

**场景 4 两库真空持续（cainiao_mysql / quant_pg 无备份）**

## 六 SLO / SLA 映射（非在线服务，映射为「每次调度可观测性 100%」）

### 6.1 为什么不适用在线 SLA

参考文件 §六的 99.0/99.5/99.9% 可用性、月停机预算、第三方拨测，度量对象是「用户侧请求成功率」。本系统无请求、无在线时长、无用户会话，套用即纸面达标（违反 ADR-02）。故映射为**按调度单元的「可观测性」SLO**。

### 6.2 可量化定义

- **统计单元**：一次被观测的调度/产物事件 = 一次 07:45 主链、一次人工副链 dump、一次 `\JevRestoreDrill` 演练、一次 `task_inventory.py` 快照 diff、一次格式闸门校验、一次发布窗口门禁。
- **must 项**：主链 rc、`.enc` 产物、副链产物、格式闸门四项（魔数 / 8 MiB / sha256 / 假绿）、容器前置、告警到达、月度复核、发布期零状态基线 B1~B4。
- **「可用」判定（三联一致性）**：任一 must 项若实际质量 `ok=false`，必须**同时**满足三件事：① `manifest.ok=false`（或旁路勘误明确标注不可恢复）；② 该次调度 `rc≠0`（或闸门拦截码非 0）；③ 告警到达（或 `ALERT_PENDING` 已落且后续补发成功；发布窗口内则为「发布单异常项已记录 + 团长人工口径已通知」）。**三者缺一即判该次调度「观测不可用」**。
- **SLO 公式**：`可观测性 = (must 调度总数 − 三者缺一的不可用数) / must 调度总数 × 100%`，目标态 **100%**（承诺值不虚高、不预留无法度量的余量；本机统计单元离散可数，故直接取 100%）。
- **误报口径**：实际 `ok=true` 却出现 `manifest.ok=false` / `rc≠0` / 误发告警，计入误报数；月度误报率 >30% 的规则强制调优。
- **月度人工复核 ≥1 次**：对齐 `\JevRestoreDrill` 每月 1 日；核对项 = 当日 must 清单、`manifest/rc/告警` 三联一致性、`ALERT_PENDING` 清零、`MAX_AGE_DAYS=8` 判定、M1~M6 现状、TD-01~TD-09 缺口登记更新。度量方式 = 人工签名的复核记录文件（旁路）+ 快照 diff，**非第三方拨测**（无拨测对象）。
- **SLA 三件套**：承诺值「每次调度可观测性 100% + 月度复核 ≥1 次」；统计口径「调度单元离散计数，must 项三联一致性，按自然月归集」；度量方式「JSON 台账 + 复核记录 + 快照 diff + 三件套，人工复核签名，团长月审」。

### 6.3 本轮诚实声明（防纸面达标）
