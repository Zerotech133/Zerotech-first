## 3. W1：认证边界 + Hermes 基线（P0）

### W1-1 IDE 认证闭环（最高优先）

**问题**：`/lde/`、`/lde/rw`、`/ide.html`、`/extensions/`、`/agent_ide_bundle.json` 未登录可访问；LDE `/rw` 直接发 session。

**动作**：

1. nginx `/lde/` 加 `auth_request /_auth_guard`；
2. `location = /ide.html` → 302 `/ide`（或同样认证）；
3. `/extensions/`、`/agent_ide_bundle.json` 纳入认证；
4. LDE 要求网关身份头（session owner 不再由客户端自报）；
5. 回归测试：
   - 未登录 `/lde/`、`/lde/rw`、`/lde/api/ide/scope`、`/ide.html`、`/extensions/app.js` → 302/403；
   - 登录后 `/hermes/`、LDE 正常；
   - 直连 8103/8787 不再能无身份写。

**验收**：上述矩阵全绿；无新增 502；回滚方案=去掉 auth_request + reload。

**估时**：1–2 天；需老田批准 nginx reload（L2）。

### W1-2 Hermes 基线 git 化

**动作**：

1. `hermes-webui-next` 初始化 git，首 commit = 当前上游快照；
2. 记录 upstream repo/commit/date、MIT license；
3. 定制补丁/连接器单独 commit 或 `patches/`；
4. `hermes-webui` 回滚基打 tag；
5. 写 `UPSTREAM.md`（升级/回滚/重放流程）。

**验收**：`git status` 干净；`git diff` 能看出定制；换机可按快照复现。

**估时**：0.5–1 天；不改运行态。

### W1-3 T1/T2 真实 prompt 复验

**动作**：

1. 用真实 T1/T2 prompt 做 JSON-first vs 现状 A/B；
2. 指标：`degraded_reasons.length`、JSON 完整率、延迟；
3. 过 `change_gate`（citation/质量）+ 延迟对照；
4. 通过后才改生产 prompt。

**验收**：真实 prompt 下 JSON-first 的 JSON 完整率 ≥90%，延迟不高于现状。

**估时**：1–2 天（含模型运行）。

### W1 Gate G1

```text
未登录 IDE 端点全部 302/403
Hermes git 基线可复现
T1/T2 真实 prompt A/B 有结论
```

## 4. W2：memory v1 + 多文件事务设计

### W2-1 memory v1（诸葛亮）

**目标**：从“有代码、默认关”变成“可评测的只读记忆”。

**范围**：

- 只记 lesson / preference / commitment 三类；
- 写入策略：候选→确认→过期/纠正；
- 默认关，显式开关；
- 20 条记忆检索集，命中 ≥90%；
- 错误记忆可删除/过期。

**不做**：自动写全量对话、第二本账、默认开启。

**估时**：2–3 天。

### W2-2 多文件事务设计

**目标**：一次 preview 支持 N 文件，统一 diff，原子 confirm/回滚。

**设计产出**：

- API：`write/preview` 支持 files[]；`confirm` 校验全部 sha 后原子提交；
- 失败：任一文件失败全回滚；
- 审计：transaction_id、文件清单、diff 摘要；
- 与工单锁/undo 的关系。

**验收**：设计评审通过；接口契约测试骨架落地。

**估时**：2 天设计 + 1 天骨架。

### W2 Gate G2

```text
memory 20 条检索 ≥90%
多文件事务接口契约冻结
```
