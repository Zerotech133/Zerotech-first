# 学习卡审核工作流 v1（60 候选 → decisions → 合并）

> 2026-11-01 · 目标：把「学习卡候选审核」从两份 md 各自勾选，收口成**一条可校验、可预览、可回滚**的工作流：
> 统一清单 → 人工 decisions → dry-run 合并预览 → `--apply`（备份+校验）→ 可选合并进学习卡。
>
> 背景：学习卡候选共 **60 张**（wave11 AE 20 张 + wave16 AV 40 张，均 `pending_review`），按分析缺口产生，需人工审核后才能进 `portal/static/kb_learning_cards.json`。

## 一、流程总览

```
AE 审核稿(20) + AV 概念卡(40)
        │  card_review.py build --write
        ▼
research/reports/card_review_checklist_20261101.{json,md}   ← 统一清单（60 条，☐通过/☐修改/☐驳回）
        │  人工审核 → 填写 decisions.json
        ▼
card_review.py decide --decisions decisions.json            ← dry-run：校验 + 更新状态 + 合并预览
        │  （确认预览新增/跳过/冲突）
        ▼
card_review.py decide --decisions ... --apply [--merge]     ← 写清单；--merge 时备份+写+校验学习卡
```

**安全默认**：`build` 需 `--write` 才写清单；`decide` 默认 dry-run 不写盘；`--apply` 才写清单；`--merge` 才动 `portal/static/kb_learning_cards.json`（写前备份 + 写后校验）。**当前未执行 apply**（等人工 decisions）。

## 二、统一清单（`card_review_checklist_20261101.json`）

| 字段 | 说明 |
|---|---|
| `review_id` | `REV-20261101-NNN`（AE 在前 001-020，AV 在后 021-060） |
| `source` | `AE` / `AV`（保留来源，proposals 为不可变快照） |
| `source_card_id` | AE 的 `PROP-...` / AV 的 `CP2-...`（decisions 可用它作键） |
| `theme` / `angle` / `angle_cn` | 主题；AV 三角度（概念定义/关键事实/影响传导），AE 无角度 |
| `q` / `a` / `concept` | 卡片问题/答案/概念 |
| `source_ref` / `unit_id` / `book` / `chapter` / `page_start` / `page_end` / `evidence` | 出处与可追溯证据（60/60 可追溯） |
| `review.checkboxes` | `{pass, revise, reject}` 初始全 false |
| `review.decision` | `{verdict, notes, reviewer, reviewed_at}`（decide 后填充） |
| `status` | `pending_review` → `approved_for_merge` / `needs_revision` / `rejected` |

- JSON 用于机器流转/统计；MD 用于人工勾选（每卡带 Q/A/出处/证据/理由 + ☐审核位）。
- **AE/AV 两份 proposals 不修改**：审核决定落在统一清单（可审计、可回滚），避免污染来源快照。

## 三、decisions JSON 格式

```json
{
  "reviewer": "审核人",
  "decided_at": "2026-11-01T12:00:00+08:00",
  "decisions": {
    "REV-20261101-001": "pass",
    "REV-20261101-002": {"verdict": "revise", "notes": "答案需补充数据来源"},
    "PROP-20261101-003": "reject",
    "CP2-20261101-001": "pass"
  }
}
```

- key 支持 `review_id` 或源 `card_id`（`PROP-*` / `CP2-*`）；
- verdict 仅允许 `pass|revise|reject`；`notes` 可选；
- **允许子集**：未出现的卡片保持 `pending_review`（会输出告警 `部分未决策`）；
- 未知 id / 非法 verdict → 校验失败、退出码 1；**支持 Windows 编辑器 BOM**（`utf-8-sig` 读取）。

## 四、状态映射与统计

| decision | status | checkboxes |
|---|---|---|
| pass | `approved_for_merge` | pass=true |
| revise | `needs_revision` | revise=true |
| reject | `rejected` | reject=true |
| （未填） | `pending_review` | 全 false |

`decide` 输出统计：pass / revise / reject / pending 数量 + `reviewed_at`；清单 `summary.decision_stats` 同步更新。

## 五、命令

```powershell

C:\项目\py312\python.exe -X utf8 tools/kb_corpus/card_review.py decide --decisions decisions.json --apply

# 4) 同时合并 approved 卡进学习卡（备份+写后校验；需要人工审批后执行）
```

退出码：`0`=成功/校验通过；`1`=校验失败或写后校验失败。

## 六、dry-run 合并预览（复用 `card_merge` 纯函数）

`decide` 会用 `card_merge.plan_merge / build_merged_payload / validate_merged` 计算：

- `approved_cards`：pass=true 的卡数；
- `plan_stats`：`would_add`（预计新增）/ `skipped_concept_exists`（现有卡优先去重）/ `skipped_duplicate_in_batch` / `resulting_cards`；
- `inserted`：将新增的卡片（review_id/theme/concept）；
- `validation`：合并后 schema/数量/现有卡顺序/重复校验。

预览确认后才 `--apply --merge`；`--merge` 流程：读 base → 备份 `research/reports/kb_learning_cards.<ts>.bak.json` → 写 → 重读校验（失败则记录错误并拒绝）。

## 八、测试覆盖（`tools/tests/test_card_review.py`，6 项）

1. 清单汇总（AE/AV 顺序、review_id 连续、☐审核位、可追溯、MD 勾选列）；
2. decisions 校验（两种键、未知 id、非法 verdict、子集告警）；
3. 状态映射（pass/revise/reject → status/checkboxes/reviewed_at，原清单不被就地修改）；
4. dry-run decide 不写盘 + 合并预览统计/校验；
5. `--apply --merge`（tmp）：写清单、备份、合并、写后校验、现有卡顺序保留、无 approved 不写 base；
6. 真实清单 60 条 CLI check + decide CLI dry-run（真实学习卡 SHA256 不变）。

## 九、限制与后续

1. **人工审核是必需环节**：本工作流只做汇总/校验/预览/合并，不自动判定卡片质量。
2. **当前未 apply**：等人工填写 decisions 后，按 §五 步骤执行；`--merge` 属数据变更，需按仓库纪律审批 + 备份。
3. AV 概念卡是 claim/evidence 模板化改写，reviewer 应重点核对「影响传导」角度是否过度归纳。
4. 合并后 `learning_cards.py` 重跑会覆盖 `kb_learning_cards.json`，需在其后执行合并或给生成器加保留人工卡机制（同 wave12 风险提示）。
5. 统计/批次数量变化时（如后续新增候选），需同步更新清单 `TOTAL_EXPECTED` 与测试断言。
