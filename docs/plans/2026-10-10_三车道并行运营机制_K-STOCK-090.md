# 三车道并行运营机制（K-STOCK-090）——开发、还债、优化互不影响
> STATUS: declared



> 2026-10-10 深夜 · 回答老田「如何一边开发一边还债一边做优化」· 本项目已用血汗换来的四条既有纪律是本机制的地基：078 并行线避让 / 裁决窗冻结 / automation 漏跑前科 / 三源存源纪律

## 一、核心思想：按「变更性质」分道，不按「项目」分道

同一个 K-STOCK 线里混着三种性质完全不同的变更，混在一起才互相伤害。分道标准不是"做什么"，而是"动什么"：

| 车道 | 变更性质 | 动什么 | 典型事项 | 前缀 |
|---|---|---|---|---|
| 🚀 **开发道** | 加法 | 只加新文件/新路由，不碰在产文件 | /algo、市场部 Agent、gzh 宣发 | `K-STOCK-xxx` |
| ⚒️ **还债道** | 搬法 | 搬代码不改逻辑，独占窗口 | P4 拆分、回测口径常量化、路径收敛 | `P4-批N` |
| 🎚️ **优化道** | 参数法 | 只动配置/阈值/prompt，不动结构 | B8 分档、RiskGuard 校准、JEV prompt v2 | `TUNE-xxx` |

**为什么这样分能互不影响**：三种变更触碰的文件集合天然不相交——开发道写新文件、还债道搬旧文件、优化道只动 json/配置层。唯一的冲突点是 portal_api.py 这种在产大文件，用下面的独占令管死。

## 二、四条隔离纪律（互不影响的机制本体）

### 纪律 1：文件独占令——同一时刻同一文件只归一条道

- 谁在改 portal_api.py，另一道就不许碰它（今天 /algo 与并行线 build_pick_verdicts 的避让就是实例）。
- 执行方式：Workspace 长期记忆 + 每日开工 `git status` 三秒核查；违反道的变更挂账不提交。

### 纪律 2：时间窗分域——冻结期换道不停车

结合现有节点链：

- **裁决窗（10-13~15）**：开发道停车（已有冻结令），优化道全速（影子判据/校准正是这三天的事），还债道只做**准备**（写脚本/写断言/预演，不碰生产文件）。
- **解禁后（10-16 起）**：开发道恢复（批 C 扩编），还债道 10-17 开闸（P4），优化道降为每周节奏。
- **每天的三段节奏**：晨（07:50 晨检自动化）＝核对三道产物 mtime → 白天＝开发道 → 晚间＝还债道搬一批（每批一 commit，可单批 revert）→ 周末＝优化道大动作。

### 纪律 3：写操作分级——automation 只跑「读和备份」，人工才动「代码和参数」

automation 有漏跑前科（09:10 cowbridge 实锤），且半夜自动改代码会与人工窗口撞车。定死：

- ✅ automation 允许：晨检/探活/备份/影子跑批/日报推送/告警（只读或只写 data 产物）。
- ❌ automation 禁止：改代码（P4 施工 automation 化取消，改为脚本批量搬+人工过目）、改阈值、改 prompt——**优化道的参数变更也必须人工窗口+TUNE 前缀提交**，因为参数就是策略的一部分，改参数=改策略。

### 纪律 4：每道独立验收门——不许用别人的门当自己的护身符

| 道 | 验收门 | 未过怎么办 |
|---|---|---|
| 开发 | py_compile + 页面冒烟 + probe-all 不掉点 | 挂账，不带病上线 |
| 还债 | route_baseline 三件套 **+ AST 方法集断言**（K-STOCK-089 第四道门） | 单批 revert |
| 优化 | 判据数据（影子样本/桶样本 n≥8/盲测对齐率） | 回滚参数，等样本 |

## 三、冲突裁决：优先级定死，不临场吵

**裁决窗事项 > 还债 > 开发 > 优化。**

理由：裁决窗是全项目的节拍器（10-15 双判据决定两线合流），它误了全链顺延一周；还债是"越晚越贵"的复利债；开发是增量；优化没有样本就没有发言权，本就该等。

举例套用：影子期有人想加新页面（开发道）——冻结令挡住→挂账到 10-16；P4 施工中有人想调 RiskGuard 阈值（优化道）——文件独占不冲突（阈值在 json/配置层）→ 可以并行，走 TUNE 提交。

## 四、防失衡：每周日「三道盘点」十分钟

三个数字各看一眼，防止任何一道饿死或霸道：

1. **债余量**：portal_api.py 行数（目标轨迹：23,398 → 批3 后 ~15K → 收尾 <5K）；回测口径散点数；路径硬编码数。
2. **开发吞吐**：本周新路由/新模块数、自动化托底链上新增了几环。
3. **优化证据量**：影子账本行数、校准桶样本数——**证据不够的优化道自动降优先级**，避免"拍脑袋调参"抢走还债时间。

## 六、一句话总结

**互不影响的本质不是"多线程"，是"分性质+分文件+分时间+分门"：新东西只加新文件（开发道）、旧债只搬不改（还债道）、参数只动配置层（优化道），同一个文件同一时刻只归一道，冻结期换道不停车，automation 永远不碰代码。**
