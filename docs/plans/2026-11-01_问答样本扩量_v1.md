# 问答样本扩量 v1（2026-11-01）

> 任务单：task-39（wave13 · AM 问答样本扩量）。上游：wave7 `kb_qa_samples.json`（5 条样本）、wave10 `kb_qa_questions_20261101.json`（32 条候选问题库）。
> 本文档记录「问题库 → 10–15 条新问答样本 → 与旧样本合并 15–20 条」的选取策略、成本、失败处理与替换方式。

## 1. 背景与目标

门户静态问答样本原只有 5 条（3 真实回答 + 1 拒答 + 1 降级演示），不足以展示问答能力覆盖面。本任务用 wave10 的 32 条可追溯候选问题扩量：
新增 12 条样本（覆盖 7 主题），与旧 5 条去重合并为 **17 条**，写回 `portal/static/kb_qa_samples.json`（页面 `/kb_reports.html` 静态区块自动消费）。

## 2. 数据流与选取策略

```
research/reports/kb_qa_questions_20261101.json（32 条，7 主题）
   │ ① 主题轮转选题：每轮每主题取 1 条（均衡覆盖），钳制 10–15 条 → 本次选 12 条
   ▼
逐条串行 kb_qa.ask（生成模式 qwen3.5:9b，topk=8，单条 timeout=300s，整体 deadline=600s）
   │   失败处理：调用异常/超时 → kb_qa 内部规则摘录降级（fallback=true）；deadline 用尽 → 余下 skipped
   ▼
research/reports/kb_qa_samples_expanded_20261101.json（新样本 + 汇总）
   │ ② 备份：portal/static/kb_qa_samples.json → research/reports/kb_qa_samples_backup_20261101.json（仅首次，不覆盖）
   ▼
合并：原 5 条（优先）+ 新样本（按问题文本归一化去重，无答案/失败样本不入池）→ 17 条
   ▼
portal/static/kb_qa_samples.json（保持原 schema：kind/model/endpoint/topk/disclaimer/kb/samples）
```

选取原则：覆盖 7 主题（AI算力/半导体、新能源/电池、消费/医药、金融/资本市场、宏观/策略/贸易、量化/技术分析、其他/综合），轮转保证每轮每主题 1 条，避免单一主题扎堆。

| 指标 | 值 |
|---|---|
| 选题/请求 | **12 条**（7 主题轮转，10–15 允许区间内） |
| 成功（有答案+有引用+非降级+非拒答） | **6** |
| 降级（fallback，规则摘录） | **0** |
| 无依据（confidence=none / 明确拒答） | **6** |
| 跳过（deadline） | **0** |
| 平均引用数（已作答样本） | **2.08 条/题** |
| 串行耗时 | **97.16s**（12 次本地 LLM 调用） |
| 合并结果 | 原 5 + 新 12 = **17 条**（15–20 区间内） |

无依据 6 条的特点：多为「…的结论在什么条件下会被证伪？」「…数据是多少」类问题——检索能召回来源单元（wave11 自检 @5=100%），但材料只给定性描述，LLM 按「无依据必须说不知道」的 prompt 规则拒答（部分仍给出 1–3 条引用说明材料范围）。这暴露的是**问题模板对证据要求高于知识单元覆盖**，不是检索失败。

## 4. 成本与超时控制

- 成本：每个新样本 1 次本地 Ollama 调用（无云成本）；本次 12 次 ≈ 97s（负载正常时 ~8s/次）。
- 单条超时 `--timeout 300`（与 wave7 口径一致）；整体 `--deadline 600`：超时则余下记 skipped，**不中断已生成样本**。
- 串行执行（`serial=true`），避免并发挤占 Ollama；如需加速可后续改小并发 + 队列。
- `--dry-run` 只做选题 + 备份 + 空 expanded 输出，**不调 LLM**（用于测试/演练）。

## 5. 失败处理与替换方式

| 场景 | 行为 |
|---|---|
| 单条 LLM 调用异常/超时 | `kb_qa.ask` 内部降级为规则摘录（`fallback=true`，confidence=low），样本仍记录并注明原因；批量不中断 |
| 整体 deadline 用尽 | 余下问题记 `skipped`，输出 `run.skipped`；已有样本照常合并 |
| 无依据/拒答 | 计入 `no_evidence`，答案保留（明确说不知道），不视为失败 |
| 无答案（异常且无 fallback 内容） | 合并时跳过，不计入门户样本数 |
| 重复问题 | 按归一化问题文本去重，**原样本优先** |
| 需要回滚 | 用 `research/reports/kb_qa_samples_backup_20261101.json` 覆盖回 `portal/static/kb_qa_samples.json`（门户静态文件直读，无需重启 8091） |

替换命令：

```powershell
# 重新扩量（默认 12 条，串行生成并合并）
C:\项目\py312\python.exe -X utf8 tools\kb_corpus\kb_qa_expand.py run --limit 12

# 只演练选题/备份，不调用 LLM
... run --dry-run

# 回滚门户样本（如需）
Copy-Item research/reports/kb_qa_samples_backup_20261101.json portal/static/kb_qa_samples.json -Force
```

## 6. 限制与后续

1. LLM 拒答率 50%（6/12）：候选问题模板（「什么条件下证伪/数据是多少」）对证据要求高于单条知识单元信息量；后续可改写模板为更贴 claim 的问题，或在问题库生成阶段过滤「数据多少/证伪」类高风险模板；
2. 新样本仅 6 条成功进入「有效回答」层，若要求 15–20 条**成功样本**，需扩选更多候选问题（如 20 条）或调整问题库；
3. 引用页码来自知识单元 `page_start`（粒度较粗，同单元共享页码），人工复核仍必需；
4. 样本为静态快照：知识库/模型更新后需重跑 `kb_qa_expand.py run` 刷新；页面区块无需重启服务；
5. 未接入 HTTP 实时问答（待 8091 审批，见 `docs/plans/2026-11-01_问答HTTP接线L2提案_v1.md`）。
