> 红线：本契约只做**隔离树合成数据**验证，禁止启动 8795、禁止真投递、禁止审批与交易副作用。

## 一、范围

| 项 | 内容 |
|---|---|
| 生产方 | 司马懿 QS1（量化出口） |
| 归口方 | 田丰 A0（军团团长/归口） |
| 通道 | ① 同进程 inbox（`agent_platform/gateway/inbox_gateway.py`）② HTTP 8795（对外网关，**本期不启动**） |
| 交付物 | 契约文本 + 测试骨架 + （后续）实现 |

**为什么必须先定契约**：W1/W2/W3/W5 已合并，但"谁把状态交给谁、答复怎么关联回原报告"没有成文规则；
W4 是这条链的**归口段**，不定清楚就会出现"入箱了没人消费 / 重复投递 / 答复找不到原单"。

## 二、必须区分的两种通道

| 维度 | 同进程 inbox | HTTP 8795 |
|---|---|---|
| 实现 | `inbox_gateway.submit/consume/deliver/receipt` | 网关 HTTP 端点（本期**禁止启动**） |
| 身份 | 调用方进程内可信，`source` 由调用点显式传入 | 需鉴权头 + 来源白名单 |
| 幂等键 | `(kind, payload_digest, source)` | 同上，另加 HTTP 幂等头 |
| 失败语义 | 直接抛异常/返回状态 | 返回 4xx/5xx + 不落账 |

**验收要求**：同一 payload 从两条通道进入，`msg_id` 必须**不同**（通道隔离），
但 `report_id`/`trace_id` 必须**相同**（业务同源）。

---

## 三、消息信封（最小字段集）

| 字段 | 必填 | 说明 |
|---|---|---|
| `msg_id` | 由 inbox 生成 | 全局唯一，`deliver()` 与 `receipt()` 的检索键 |
| `kind` | ✅ | 消息类型（如 `stock_consult_result` / `risk_verdict`） |
| `payload` | ✅ | 业务体，参与幂等摘要 |
| `source` | ✅ | `qs1` / `a0` / `external`（决定通道语义） |
| `report_id` | ✅（业务单） | 生产方给出的报告标识，答复必须回引 |
| `trace_id` | ✅ | 贯穿链路；缺失即视为契约违例 |
| `submitted_at` | 由 inbox 生成 | UTC ISO |

---

## 四、生命周期状态机

```
submitted → accepted → consumed(处理中) → answered → delivered → receipt
                ↘ rejected(reason 必填)          ↘ expired(无消费者超时)
```

| 状态 | 触发 | 谁可触发 |
|---|---|---|
| `submitted` | `inbox_gateway.submit()` | 生产方 QS1 |
| `accepted` | 归口受理（写 accepted_by） | A0 |
| `consumed` | `consume(msg_id, answered_by=...)` | A0 |
| `answered` | 写入答复体 + 回引 `report_id` | A0 |
| `delivered` | `deliver(msg_id, channel=...)` | A0/通信层 |
| `rejected` | 拒接，`reason` 必填 | A0 |
| `expired` | 超时无消费者（阈值见 §六） | 系统 |

---

## 五、关联规则（本契约的核心）

1. **答复必须回引**：`answered` 记录的 `report_id` 必须等于原提交的 `report_id`，
   否则 `receipt()` 返回 `linked=false`。
2. **trace_id 贯穿**：提交→消费→答复→投递四步的 `trace_id` 必须一致；
   任一环缺失 → 该环 `status=unknown`，不得用默认值冒充。
3. **同进程与 HTTP 不共享 msg_id**，但共享 `report_id`/`trace_id`；
   `receipt()` 应能按 `report_id` 聚出两条通道的全部消息。

## 六、负例（缺一不算过）

| 编号 | 负例 | 期望 |
|---|---|---|
| N1 | 提交后无消费者 | 超过 `T_expire` 转 `expired`，且 `receipt.alive=false` |
| N2 | 同一 payload 重复提交 | 返回**原 msg_id**，`receipt.duplicate=true`，不产生第二条记录 |
| N3 | 归口拒接 | `status=rejected`，`reason` 非空；重复拒接幂等 |
| N4 | 答复缺 `report_id` | 拒收，`linked=false`，不写 answered |
| N5 | `trace_id` 缺失 | 契约违例：`status=unknown`，禁止回填默认值 |
| N6 | 通道混用（同 payload 走 inbox 与 8795） | 两条记录、两个 msg_id、同一 report_id |
