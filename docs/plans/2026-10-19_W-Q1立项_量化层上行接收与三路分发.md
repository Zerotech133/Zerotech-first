## 1. 背景与定位

盯盘侧已交付单一上行路（watch_dispatch：G0 契约 `72a1f331`、G1 outbox `4fc8dbd2`、层级修订 `850f2476`、W-Q0 Agent 上报 `6f5fd26f`）。上行路的终点是量化交易层的**受理席**——目前该角色只有语义（QS1，见注册表接线协调包），原立项时尚无模块；截至 2026-10-20 离线模块已建，但真实受理 endpoint 仍未接通。W-Q1 的历史目标是补上量化侧：**收进来、签收回执、再分三路送出去**。

层级铁律重申：三路分发（飞书信息/投研研判/交易所观察）是量化交易层的职责；盯盘永不直连。分发不等于下单。

## 2. 目标

1. 量化层新增**上行受理模块**（建议落点 `quant_backtest/quant_sector/`，独立包）：
   - 当前离线接口为 `UpstreamInbox.accept(report, *, now) -> UpstreamReceipt`，其 `ack` 字段为 agent 级 ACK（`ack_id`、`acked_at`、`verification_source`）；这是与 watch 侧 `AgentAckPort.verify` 配合的离线回执，不是生产受理根。
   - 幂等：同一 `report_id`+`envelope_hash` 重复受理返回同一回执及 ACK；冲突（同 id 异内容）拒绝，不产生新回执。
   - 账本 append-only：受理台账只进不退，撤销只加撤销记录。
2. 量化层新增**三份独立分发账**：
   - 路由枚举：`FEISHU_INFO` / `RESEARCH_REVIEW` / `EXCHANGE_OBSERVATION`——**只在量化层存在**；watch 侧契约中这些路由仍非法（ROUTE_INVALID），两侧行为互不破坏。
   - 每路独立 plan/claim/finish、独立幂等键、独立回执时间窗；复用 watch_dispatch 同款语义（租约、UNKNOWN 不自动重试、仅独立证实的 DEFINITELY_REJECTED 受控重试上限 3、epoch 只进不退）——**语义复制、代码独立，不 import watch_dispatch**（防反向依赖；如日后抽公共冻结库另行立项评审）。
3. 分发前置校验：任一路分发前必须持有"该事件已受理"的台账引用；未受理事件不可分发。

## 3. 非目标（明确不做）

- 不实现真实飞书/投研/交易所接口（G3 范畴，阻断中）；适配器端口留空、默认禁用。
- 不改 watch_dispatch 任何冻结模块（指纹 `417d430b…` 等保持不动）。
- 不做授权/下单语义：受理≠授权，ACK 永不升格为交易许可（那是双门 W-Q2 的事）。
- 不碰 strategy_registry 权重、线上 picks、PG、真实交易。

## 4. 契约草案（关键数据结构与不变量）

```
UpstreamReceipt   := { receipt_id, report_id, envelope_hash, sender_agent_id,
                       accepted_at, ack: AgentAck, ledger_epoch }
DispatchIntent    := { intent_id, receipt_id, route ∈ {FEISHU_INFO, RESEARCH_REVIEW,
                       EXCHANGE_OBSERVATION}, target_ref, created_at }
DispatchAttempt   := { intent_id, attempt_no(≤3), claimed_at, lease_until,
                       outcome ∈ {ACCEPTED_VERIFIED, UNKNOWN, DEFINITELY_REJECTED, CANCELLED},
                       external_message_id?, observed_at? }
```

不变量：
1. ACK 只由受理席出具，`acked_at ≥ accepted_at`；`verification_source` 必填。
2. 三路账互不引用对方的 attempt；一路 UNKNOWN 不阻塞另两路。
3. 任何 `DispatchVerdict` 无 `trading_permitted` 概念；`EXCHANGE_OBSERVATION` 仅"送交易员观察候选"。
4. 时间字段一律 UTC 带时区；半开时窗约定与 watch 侧一致。

依 `docs/plans/2026-10-19_许褚盯盘营信号池设计_多Agent协作底座.md`：盯盘营侧新增营级信号池（append-only，去重+生产者署名），作为本模块受理台账的**上游**——上行官从池中取号走 QUANT_UPSTREAM_REPORT，本模块受理出 ACK 后，池内条目经"上行回执回写"点闭环（ACCEPTED_VERIFIED→池 ACCEPTED；UNKNOWN/DEFINITELY_REJECTED→池回 OPEN）。本模块无需改契约，仅约定：ACK 出具时携带的 `report_id` 可被池端反查（既有字段已满足）。未来多盯盘 Agent 扩编对本模块透明（受理按事件，不感知生产者数量）。
