## 一、gzh 凭证核验结论：⚠️ 凭证缺口实锤，A4 假设需修正

**核验方法**：全仓 grep（`api.weixin.qq.com` / `appid` / `secret` / `cgi-bin` / `GZH_*`，覆盖 .py 与 docs）。

**实测结果**：

| 通道 | 凭证形态 | 状态 |
|---|---|---|
| 飞书机器人 | `news_collector/send_feishu.py` 读 apps 表 appId/appSecret | ✅ 10-08 实测 Intraday/EOD 双 SEND_OK |
| 企业微信 webhook | `send_wecom.py` 硬编码 qyapi webhook key | ✅ 在位（仅 webhook，非群发） |
| **微信公众号 MP 群发 API** | **无任何 appid/secret/token 痕迹** | ❌ **缺口** |

**结论**：
1. 「gzh 发布 API 复用 news_collector 凭证链」**不成立**——news_collector 只有飞书+企业微信，公众号是另一套独立凭证体系（MP appid/secret + access_token + IP 白名单 + 群发/发布权限）。
2. A4 市场部 M1 的「过审稿走 gzh 公众号既有基建发布」需修正为：**基建尚未存在，批 D 前须先向老田索取公众号 MP 凭证**（appid+secret），并在服务端出口 IP 配白名单。
3. 建议批 D 准备清单增补：①索要 MP 凭证 ②试打 `/cgi-bin/token` 验权限 ③确认账号类型（认证服务号才有完整群发 API；订阅号受限）。
