## 一、目标

让 `/api/dw/*` 读接口真正支持 `pg_table`（智策 PG 5446 `public.v2_*`），并保持旧 API 兼容：

1. `/api/dw/stats` v1 字段语义/数值不变，新增 `stats_v2`（pg / contract_artifacts /
   connector_status）；
2. `/api/dw/list` 支持 `kind=pg_table` 等过滤；
3. `/api/dw/get?id=pg_...` 返回 connector/physical/ref_aliases/status；
4. `/api/dw/sample?id=pg_...` 走只读 PG；DSN 不可用显式 `connector_unavailable`（不假绿）；
5. `/api/dw/search` 能检索 pg 表；`/api/dw/query` 对 pg 显式 `not_supported`，不拼接任意 SQL。

## 二、接口清单（本单落地）

| 接口 | 参数 | pg_table 行为 | 关键响应/错误 |
|---|---|---|---|
| `GET /api/dw/stats` | — | 附加 `stats_v2`/`pg`/`contract_artifacts`/`connector_status` | v1 字段原样保留；`stats_v2` 失败不改 v1，附 `stats_v2_error` + `stats_version=v1` |
| `GET /api/dw/list` | `kind`/`kinds`（`pg_table`、`contract_artifact`、`all`、`file` 别名、逗号多选）、`domain/q/registered/exposed/limit` | `kind=pg_table` 返回 pg 行；默认（无 kind）仍只文件级（向后兼容） | 空结果 `state=no_data`，reason 含 kind；未知 kind 也不假绿（空结果显式） |
| `GET /api/dw/get` | `id`（dataset_id；兼容 `dataset/pg/<table>`、`<table>` 别名经 resolve_ref） | 返回完整行 + `pg` 元数据块：`connector/physical/ref/ref_aliases/status/available/registered/exposed/row_estimate/relkind/connector_status/connector_error/read_only/query_supported=false/sample_supported=true` | 未登记 404 `state=not_found` |
| `GET /api/dw/sample` | `id`、`n=1..20` | registry 白名单物理名 + 只读 `SELECT * ... LIMIT`（registry 内核）；成功返回 columns/sample/connector/physical | DSN 缺失/驱动缺失/连接失败 → **503 `ok=false, error=connector_unavailable, connector_status=missing_dsn|driver_missing|connector_unavailable, state=connector_unavailable`**；契约产物不可用 → 503 `contract_artifact_unavailable` |
| `GET /api/dw/search` | `q` 必填、`kind`（默认 `all`，可收窄 file/pg_table/…）、`limit` | 默认检索含 pg/契约产物；`kind=pg_table` 只搜 pg | 缺 q 400；空结果 `state=no_data` |
| `GET/POST /api/dw/query` | `id`、`where/order/since/columns/limit/offset/count` | 显式 **409 `state=not_supported`**：`detail.carrier=pg_table`、`carrier=pg_table`、`query_supported=false`、`hint` 指 sample/get；**不接受任意 SQL**（`sql/raw_sql/statement/query` 参数 → 400） | 400 参数非法 / 403 越权 / 404 未登记 / 409 载体不支持 / 503 内部错 |

统一保留 DWH-105 三态：`data_date/state/reason`；错误体带 `code`。

## 三、兼容与安全

- **旧 API 兼容**：`stats` 的 v1 六个字段（inventory/total/registered/exposed/by_domain/
  by_kind）名称与数值不变；`list` 无 `kind` 参数时仍只返回文件级；`search` 从「仅文件级」变为
  默认 `all`（新增结果，字段不变；如消费方需旧口径可传 `kind=file`）——**行为变化已在本单显式登记**。
- **不假绿**：pg 不可用/不在实例/未发现一律显式状态（missing_dsn/driver_missing/
  connector_unavailable/table_missing/metadata_unreadable），`available` 才可 sample。
- **无任意 SQL**：API 只转发结构化参数到 `dataset_registry.query/sample`；query 对 pg 不发 SQL；
  sample 的表名经过 registry `PG_SCHEMA_WHITELIST`（public）+ `_TABLE_RE`（v2_* 命名）+ 发现集合校验。
- **只读**：无写 PG/无写业务数据；route 集合不变（仍 `GET/POST prefix /api/dw/`），route baseline
  无需变更。

**风险点**：
1. `search` 默认范围变化（文件级 → all）：新增 pg/契约产物结果；如消费方敏感可传 `kind=file`
   恢复旧口径（本单未改前端 dw.html，避免隐性展示变化）。
2. `/sample` 的 pg 失败状态由 503 internal_error 变为 503 `connector_unavailable`（更精确，
   属兼容性改善；调用方若按 error 字符串分支需知会）。
3. pg 元数据依赖 registry 探测时点（进程内缓存）；DSN/实例恢复需重启或重建 registry（registry
   侧既有行为，本单未改）。
4. stats_v2 的 `all` 口径沿用 registry「不假绿」定义（只计 available pg/active 契约产物），
   与 v1 total 不可直接相加（文档已说明）。
