# Trae CN 能力对标 × 数字军团增强方案（K-ORG-086）
> STATUS: frozen（只读保留）



> 2026-10-15 04:40 · 主控起草 · 调研源：trae.cn 官网 + docs.trae.cn 更新日志 + SOLO 深度解析（2026）
> 定位：**借鉴而非照抄**——Trae 是「单开发者的 IDE」，我们是「持久数字组织」，借鉴其产品化机制补我们的纵深。

## 一、Trae CN 能力全景（调研摘要）

| 能力 | 内容 |
|---|---|
| SOLO 模式 | SOLO Coder（复杂项目：读全项目→定位→修改→**浏览器验证**→提交）＋ SOLO Builder（从零原型，实测 4 分钟 MVP、92% 一次跑通） |
| Agent 模式 | 一个窗口统筹多项目，按任务分配 Agent 并行推进，实时进度呈现 |
| @Agent 体系 | 自定义智能体=提示词+工具集+自动运行开关+**命令黑名单** |
| #Context 协议 | #Web（联网）/ #Doc（文档集，1000 文件 50MB）/ #File——**结构化引用替代散文粘贴** |
| Rules 系统 | user_rules.md（跨项目）+ project_rules.md（项目级）——「规则即上下文」，分层文件化注入 |
| MCP 生态 | 内置市场，工具自由装配进智能体 |
| CUE | Tab 链式补全、修改点预测、多行 diff |
| 模型路由 | 按任务类型与成本选模型（豆包 Code/DeepSeek/GLM + API Key 自定义） |

## 二、对照差距：我们已有 vs 缺

**已有且不输 Trae**（不动）：持久岗卡（Trae 智能体会话级）、spec 冻结/金样本/AST gate 治理（Trae 无）、QA1 只读 fail-closed（Trae 黑名单是反向等价物）、四级降级模型链、飞书推送。

**真差距六项**（按价值排序）：

### T1 规则分层体系（对标 Rules 系统）⭐ 最高价值
- **现状痛点**：K 编号纪律、pathspec 提交、回收站删除、三源同步……全部判例散在主控 memory 里，**靠主控人脑带**；29 岗卡只有 charter，判例未系统化注入——QA1 昨天能抓我们，是因为它读了 spec，而不是因为它装着组织铁律。
- **增强**：建 `agent_platform/rules/` 两层——`org_rules.md`（全局铁律：判例机器化，所有岗注入）＋ 每岗 `rules` 字段（岗级规则，注册表扩展）。加载链=org_rules → team_rules → 岗 rules，对齐 Trae「规则即上下文」。
- **落点**：`_persona()` 注入第 6 通道；org_supervision 加「规则文件在位」体检项。

### T2 证据引用协议（对标 #Context）
- **现状痛点**：SEC2/QA1 证据包是自由文本（git show --stat 原样引用已是进步，但仍是散文）。
- **增强**：定义 `#ev:commit:<sha>` / `#ev:file:<path>@<sha>` / `#ev:trace:<工单>` 引用语法，spec/评审/证据包统一用；消费端（agent_coder prompt 组装）解析引用→自动附原文。降幻觉、省 token、可机检。

### T3 QA-RUN 浏览器验证闭环（对标 SOLO Coder 工作流，即 080-N4）
- SOLO Coder 的标准收尾是「打开浏览器验证修复效果再提交」——我们 QA 止步 smoke。Trae 的内置预览页「实时读控制台日志」给了产品形态参照。
- **增强**：N4 实施时明确闭环五步=起服务→HTTP 探活→行为断言→控制台/日志扫描→结论入轨迹。判据产品化（今天 8093 探活那套 urllib 直连配方就是雏形）。

### T4 工具权限二维矩阵（对标 自动运行+黑名单，即 080-N9）
- Trae 是「自动运行开关＋命令黑名单」一维；我们升级为 **岗×操作级二维矩阵**：读=自动放行、写=岗级白名单、危险操作=全局禁（回收站例外）。QA1 单岗白名单推广为矩阵配置文件 `agent_platform/rules/tool_matrix.json`。

### T5 门户多工单并行视图（对标 Agent 模式统筹窗）
- e2e 现为单工单串行。Trae 展示了「多任务分配多 Agent 并行＋进度实时呈现」的产品形态。
- **增强**：工单看板加「生产线并行区」——多 e2e 工单并行跑（worktree 隔离已支持），门户实时显示各工单阶段（开单/产码/质检/merge）。**押后**：先单线正验站稳再开并行。

### T6 知识文档集批量挂载（对标 #Doc）
- knowledge_docs 现 8 部、agent_learn 一次一部。借鉴 #Doc：`/api/agent/learn` 支持 `docs: [批量列表]`，岗位一次挂载整个方向（如 DEV 线挂全部工程文档）；配合检索式按需注入（防 prompt 膨胀）。

## 三、排期建议（并入 080 计划节奏）

| 项 | 窗口 | 依赖 |
|---|---|---|
| T1 规则分层 | **一轮 10-15~17**（正验后即做，纯配置+注入链） | 无 |
| T2 证据引用协议 | 二轮 10-17~24（随 spec 判据 EARS 化一起，同属「结构化」主题） | N5 |
| T3 QA-RUN 闭环 | 二轮（=N4，本方案给它对标参照） | 正验收口 |

| T6 文档集挂载 | 三轮（轻量） | 无 |

## 四、边界声明

- 不引入 Trae 本身做运行时（我们岗位体系自研且已持久化，Trae 是 IDE 形态、会话生命周期，不匹配数字组织需求）
- 不追改冻结链：T1/T2 均只对**新工单**生效，072 金样本不动
- 风险：T1 规则机器化要防「规则膨胀」——org_rules 上限 50 行，超了进 knowledge_docs 走学习通道
