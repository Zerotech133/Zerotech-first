### 步骤 4：nginx 加 location + 热重载（方案 i，唯一配置变更）

在 `portal/nginx.conf` 的 `location = /api/state` 块**之后**追加：

```nginx
    # 飞书事件回调（2026-10-21 WO-FS-147）：方案 i 反代 8091。硬前置已核：
    # fail-closed 补丁 23fb992f + Encrypt Key 已注入，未签名请求 403。
    # = 精确匹配面最小；飞书侧回调地址配 http://<本机公网/内网>:8080/feishu/event
    location = /feishu/event {
        set $h host.docker.internal;
        proxy_pass http://$h:8091;
        proxy_connect_timeout 3s;
        proxy_read_timeout 15s;
    }
```

```powershell
docker exec ai-portal nginx -t
docker exec ai-portal nginx -s reload
# 验证：经 nginx 的未签名请求同样 403（非 503——Key 已配）；其余四管理面不回归
curl --noproxy '*' -s -o NUL -w "via_nginx=%{http_code}`n" -X POST http://127.0.0.1:8080/feishu/event -H "Content-Type: application/json" -d '{}'
curl -s -o NUL -w "ops-board=%{http_code}`n" http://localhost:8080/ops-board
```

### 步骤 5：飞书后台配回调地址（老田侧）

后台 → 事件与回调 → 请求地址配置：`http://<可达本机的地址>:8080/feishu/event`。保存时飞书发 url_verification 握手，8091 会原样回 challenge（合法签名自动通过）。

## 二、要素②：影响面

| 对象 | 影响 | 时长 |
|---|---|---|
| 8091 | 换血期间 `/api/*` 短暂不可用 | 5~15s |
| nginx | reload 平滑无中断 | <1s |
| bot/8097/8787 | 不动 | 0 |
| config.json | 追加一项（不覆盖 apps[0]） | 持久 |

## 三、要素③：不可逆点

1. **Key 重置后旧值立即失效**——若飞书侧仍有别处引用旧 Key（无证据，但需知悉）会断。
2. nginx 开口后 `/feishu/event` 对可达 8080 的网络暴露（有验签+时间窗双闸，且 fail-closed 已测）。
3. 8091 换血期写事务强杀残留风险（低，observe 模式写入极少）。

## 五、要素⑤：回滚预案

| 失败点 | 回滚动作 |
|---|---|
| 8091 起不来 | 重跑步骤 3 一次；仍失败则删 config.json 新增项（回到无 Key 态=503 拒绝，安全） |
| nginx 起不来 | `git checkout HEAD -- portal/nginx.conf` + `docker exec ai-portal nginx -s reload` |
| 回调握手失败 | 后台删回调地址即回到纯 WS 模式；本机侧零改动 |
| 全盘 | 无不可逆生产损害：不批准 = 保持 503 拒绝态，优于现状（原降级 200） |
