## 一、定位与目标

I5 军团侧（联动层）需要把"人的判断/确认"反推入 OS。按总纲铁律 5，这类回写**不直接改业务账**，必须经唯一入向闸进 OS，保证"人→OS"与"页面→OS"同构：唯一入口、全审计、可裁决。

本契约回答四件事：

1. 回写请求长什么样（信封 schema）；
2. 谁有资格发（白名单席位清单来源）；
3. 允许发什么（动作白名单：建议/标记/申请，三类均无直接执行权）；
4. 发了之后去哪（W43 受理 → 审计 → 决策账落点）。

## 二、信封 schema（草案）

复用邓芝松耦合设计稿的「标准信封 + domain 一级路由」约束，回写信封与出向通知信封同构，字段如下（v0 草案，字段增删待军团侧议定）：

```json
{
  "envelope_version": "1",
  "direction": "inbound_writeback",
  "domain": "<一级路由域，与 P2 分域改造后的 domain 口径一致>",
  "source": {
    "seat": "<军团席位标识，须在白名单注册表内>",
    "channel": "<I5|portal_page|...>",
    "trace_id": "<军团侧链路追踪 ID>"
  },
  "actor": {
    "identity": "<操作人身份（open_id/席位账号），禁止匿名>",
    "role": "<操作人角色>"
  },
  "action": "<suggest | mark | request 三选一>",
  "target": {
    "object_type": "<回写对象类型：信号/工单/订阅/通知记录/...>",
    "object_id": "<回写对象标识>"
  },
  "payload": { "<与 action 匹配的受控负载>" },
  "request_id": "<幂等键，重试复用同一 request_id>",
  "timestamp": "<ISO8601，发起时刻>",
  "audit": {
    "reason": "<回写理由，必填>",
    "evidence": "<依据/出处引用，可空但建议填>"
  }
}
```

schema 纪律（沿用总纲铁律）：

- **不建第二账**：信封只携带"判断与依据"，不携带业务事实终值；业务事实仍由各平台账本持有，OS 裁决后才落账。
- **closed on failure**：信封校验失败/W43 不可用时显式拒绝并回执错误码，军团侧重试有界（建议 ≤3 次、指数退避），不造数、不假绿；被拒请求军团侧标注缺源留痕。
- **幂等**：同 request_id 重复受理只记一次审计，第二次起返回首次受理回执。

## 三、白名单席位清单来源

席位白名单**不由中台硬编码**，来源为军团侧「接口统一注册表挂靠」（总纲 §〇 松耦合五原则第 4 条）：

| 项 | 口径（待议定） |
|---|---|
| 清单持有方 | 军团侧注册表（I5 维护），中台只消费 |
| 下发方式 | 注册表下发/拉取至中台缓存，含席位标识+允许的 action 集+有效期 |
| 校验点 | W43 受理时校验 source.seat 在册且未过期、action 在该席位允许集内 |
| 失效语义 | 过期/下线席位来信按白名单外处理：显式拒收+告警（走 8097 通知），不入审计主账只入拒收日志 |
| 变更纪律 | 白名单变更走注册表，中台不改代码——未来拆分席位=改注册表+路由配置，通道零改动 |

## 四、动作白名单：三类，均无直接执行权

| action | 语义 | OS 侧处理 | 能否直接改变业务状态 |
|---|---|---|---|
| `suggest` | 建议：军团对某对象提出处置建议（如"该预警建议降级"） | 进待裁决队列，人工/规则裁决 | **否** |
| `mark` | 标记：对某对象打标（如"已阅/误报/需跟进"） | 落审计+对象标记投影，不改业务账 | **否** |
| `request` | 申请：请求 OS 执行某受控操作（如"申请重放通知"） | 进审批流，批准后由 OS 侧既有通道执行 | **否**（批准后走 OS 既有路径，非回写直接执行） |

约束：

- 三类动作在 schema 上互斥，一个信封一个 action；
- 无"execute/直接写"类动作，本契约 v0 明确**不开放**，若未来需要另立契约另批；
- 动作集演进只能走注册表下发，不允许军团侧私带新 action 名（未知 action 一律显式拒收）。

## 五、审计与决策账落点

链路：**军团 I5 → W43 唯一入口（受理+白名单/信封校验+限频）→ 审计记录 → 裁决 → 决策账**。

| 落点 | 内容 | 说明 |
|---|---|---|
| W43 受理记录 | 全量信封+受理结果（接受/拒收+原因码） | 回写全审计的"受理侧"证据，铁律 3 口径：受理 ≠ 裁决 ≠ 落账，分级记录 |
| 审计账 | 每笔回写的 actor/source/action/target/reason/evidence | 追加只写，禁止改写 |
| 决策账（DD-5 口径） | 裁决结论（采纳/驳回/挂起）+裁决人+时间 | 决策账 OS 入口（DD-5）为本人指挥面既有挂账项，回写裁决结果在此落账 |
| 拒收日志 | 白名单外/限频超限/信封非法 | 单独留存，不与合法回写混账 |

## 六、复用 W43 唯一入口（不新建通道）

- W43 入向受理器（portal/inbound_gateway.py，在役）为**唯一入口**，本契约不建第二入向通道；
- W43 内部按信封 `domain` 一级路由字段分流（与 P2 分域改造口径一致）；
- I5 回写在 W43 中作为独立意图类别受理，与既有 ticker 意图等并列，共用订阅校验/白名单校验/限频设施；
- 页面受控回写（总纲 §4.1：重放/分诊/订阅变更/盯票设置按钮）与本契约走**同一入口同一审计**，军团回写只是 actor 来源不同——"人→OS"与"军团→OS"同构。

## 七、rate limit（限频，口径待议定）

| 维度 | 建议 v0 口径 |
|---|---|
| 限频键 | 席位 × action 双维度（如 seat=X & action=request 单独限额） |
| 建议初值 | suggest/mark 宽（分钟级数十次）；request 严（每小时个位数），上线后按实测调 |
| 超限行为 | 显式拒收（原因码 rate_limited）+ 8097 告警（运维域），被拒请求不进入裁决队列 |
| 豁免 | v0 不设豁免；critical 类回写需求如有，另议 |
