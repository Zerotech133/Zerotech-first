## 一、评估闸门 `tools/change_gate.py`

### 设计

- 不自己跑 LLM；由 `eval_harness` / `promptfoo` / `p0_eval_runner` 产出分数后传入；
- `snapshot`：保存 prompt 快照 + 分数 + 模型 + 指标，作为基线；
- `check`：当前分数低于基线（超出容差）→ 退出 1；
- `rollback`：恢复基线 prompt，当前版本留 `.bak`；
- 只写 `work/eval_gate/`。

### 用法

```powershell
# 先跑一次评测，拿到分数（示例）
python tools/p0_eval_runner.py --limit 10 --json --no-write

# 建基线
python tools/change_gate.py snapshot --name ai1-prompt `
  --prompt agent_platform/evals/prompts/zhuge.md `
  --score 0.90 --metric pass_rate --model ollama/qwen3.5:9b `
  --note "P0-4 golden baseline"

# 改 prompt/模型后：重新评测，再 check
python tools/change_gate.py check --name ai1-prompt --score 0.86 --tolerance 0.02
# 退出 1 = 回归，禁止合并/上线

# 回滚 prompt
python tools/change_gate.py rollback --name ai1-prompt `
  --prompt agent_platform/evals/prompts/zhuge.md
```

### 最小纪律

1. 改 prompt/载体前先有基线；
2. 改完必须出新分数；
3. 分数退步超容差 → 不合并；
4. 回滚后重跑评测。

## 二、trace 运营化 `tools/trace_ops.py`

### 用法

```powershell
# 汇总最近 100 个 LLM span（默认 match=llm）
python tools/trace_ops.py --json

# 巡检：无数据或错误率 >5% 返回 1
python tools/trace_ops.py --check

# 落日报告
python tools/trace_ops.py --report
```

输出：span 数、错误数/错误率、P50/P95/max 延迟、span 名称分布、告警。
