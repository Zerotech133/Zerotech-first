# K-STOCK-211 代码审计与研发进度计划

> **For agentic workers:** 本计划按 `superpowers:executing-plans` 执行；每项完成后必须有测试或只读证据。

**目标：** 修复数据仓候选来源审计的错误阻断文案，核对历史回补、数据质量和发布门禁进度，并把剩余阻断项转成可执行任务。

**架构：** 来源回执进入 staging，RunStore 负责运行生命周期，候选发布目录保存隔离 parquet；registry 资格、资源锁、发布锁、发布后指纹和回读对账共同决定是否允许生产发布。候选验证与生产发布分离，`production_write=false`、`global_activation=false` 是本计划的固定约束。

**技术栈：** Python 3.11、SQLite、Parquet、pytest、PowerShell、Git worktree。

**依据：** `docs/audit/2026-10-13-全面代码审计与数据质量审查_K-STOCK-211.md`、`docs/plans/2026-10-11_历史数据回补进度_K-STOCK-116-history.md`、`work/full_history_candidate_manifest_20261013.json`。

## 全局约束

- 没有真实来源回执时不补零、不复制邻日、不写生产。
- 候选回补必须经过来源回执、RunStore、资源锁、发布锁、发布后指纹和回读唯一键核验。
- `production_write=false`、`global_activation=false` 持续生效，直到 registry 资格和旧写者接管均有证据。
- 端口严格检查发现第三方监听时只记录，不擅自杀进程或登记平台端口。

## 审查重点

- 审计原因必须与门禁实际状态一致，不能用固定文案覆盖通过或失败原因。
- 历史批次必须可恢复，不能重复日期或产生资源锁残留。
- 健康扫描要区分最新断面缺口、历史窗口累计缺口和来源待核验状态。
- 缺失测试夹具不能被误报成生产代码修复完成。
- 生产发布前必须能证明旧写者已接管或停写。
