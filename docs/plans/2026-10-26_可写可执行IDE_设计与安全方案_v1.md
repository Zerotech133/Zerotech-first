## 一、定位与边界

**目标形态**：在现有**只读施工台**之上，增加两类受控能力——

1. **受控写代码**：在指定 worktree/分支内编辑文件，改动可见、可 diff、可回滚；
2. **受控执行**：在限定沙箱内跑命令（测试/构建/只读诊断），输出与退出码留痕。

**不做（写死）**：

- ❌ 不做无人值守自主开发（AI 自己领单→改→合并闭环）；
- ❌ 不开放 master 直写（必须走 worktree + 评审门）；
- ❌ 不把 principal 私钥 / API key / `_vault/secrets` 暴露给 IDE 或执行环境；
- ❌ 不默认联网执行、不做多租户、不做公网暴露；
- ❌ 不替代现有 DSH 会话执行体（IDE 是"人机同屏施工台"，不是第二执行体）。

## 二、总体架构（三层 + 一道闸）

```
┌──────────────────────────── 浏览器（Edge App 窗口）────────────────────────────┐
│  ide.html 扩展：文件树/编辑器/终端面板 + 「需人工确认」弹窗                        │
└───────────────────────────────┬───────────────────────────────────────────────┘
                    HTTPS? 否：仅 127.0.0.1（本机回环）
┌───────────────────────────────▼───────────────────────────────────────────────┐
│  IDE 后端（agent_platform/legion_ide/，独立 8103，feature flag）                 │
│  ┌─────────────┐  ┌──────────────┐  ┌──────────────┐  ┌─────────────────────┐  │
│  │ 作用域校验   │→ │ 工单级排他锁  │→ │ 写/执行适配器 │→ │ 审计（events/工单）  │  │
│  │ scope_guard │  │ task_lock    │  │ writer/exec  │  │ auditor             │  │
│  └─────────────┘  └──────────────┘  └──────┬───────┘  └─────────────────────┘  │
└─────────────────────────────────────────────┼─────────────────────────────────┘
                                  ┌──────────▼──────────┐
                                  │ 沙箱执行层（分级）    │
                                  │ L0 命令白名单        │
                                  │ L1 受限用户/容器     │
                                  │ L2 本机完整（人批）   │
                                  └─────────────────────┘
```

**关键原则**：作用域校验与审计在**后端强制**（前端只是 UI），任何绕过前端的请求同样被拦。

## 三、四个决策点（请拍板）

### D1 写权限作用域

| 选项 | 内容 | 评价 |
|---|---|---|
| **A（推荐）** | 仅允许写 `task/<TID>` worktree 内的受控路径：`agent_platform/`、`ops/`、`docs/`、`tools/`、`portal/`（排除 `.git/`、`_vault/`、`node_modules/`、二进制/密钥文件）；**master 根目录只读** | 与"一单一 worktree"纪律同构；改动天然可 diff/回滚；风险最低 |
| B | A + 额外白名单目录（如 `deliverables/`、`quant_backtest/` 指定子目录） | 适合产出文档/报告；需逐个目录签字登记 |
| C | 全仓可写（仍禁 `.git`/`_vault`） | 不推荐：越权面大、误伤其他会话 |

**推荐 A**。写操作一律要求：目标文件在某 worktree 内、该 worktree 有对应 doing/review 工单、当前会话持有该工单锁。

### D2 执行权限与沙箱

| 选项 | 内容 | 评价 |
|---|---|---|
| **A（推荐起步）** | **白名单命令**：只读诊断（git status/diff/log、tasklist、dir、python -m pytest 指定目录）、构建（npm/pnpm 指定脚本）；**命令 + 参数模式**双重白名单；默认禁网络 | 实现快（~1 天）、风险可控；覆盖 80% 日常（跑测试/看 diff） |
| B | **受限用户/容器**：独立低权用户或 Docker 容器，只挂载当前 worktree，禁网络/禁凭据；超时/CPU/内存/输出上限 | 中（2–4 天）；适合"跑任意命令" |
| C | 本机完整权限（等同 DSH 会话） | 不默认开放；仅人工逐次批准 |

**推荐路线：D2-A 起步 → 需要"任意命令"时升级 D2-B。**
**审批人**：L1 白名单内免批；L1 边界外/联网/L2 动作（改计划任务、注册表、服务、宿主重启）**必须老田五要素批准**，IDE 只发起"批准请求"不放行。

### D3 审计与签字

| 选项 | 内容 | 评价 |
|---|---|---|
| **A（推荐）** | 每次写/执行都落 `portal/data/dev_events.jsonl`（扩展 `code_action` / `code_observation` 事件，含工单号、worktree、文件、diff 摘要、命令、退出码、耗时）+ 工单 note 摘要；**不要求人签**（merge 仍过评审门） | 与现有开发回流纪律一致；审计可查、可回放 |
| B | 写操作需人签（Ed25519，Z 链） | 过重：每次编辑都签，人会放弃使用 |
| C | 仅 merge 前人工评审（不落 events） | 不推荐：丢过程证据，违背"全量回流"立宪 |

**推荐 A**；另外**跨域/危险动作**（改 `_vault`、改任务计划、执行 L2）仍走 Z 链/人工签字。

### D4 并发冲突

| 选项 | 内容 | 评价 |
|---|---|---|
| **A（推荐）** | **工单级排他锁**：编辑/执行前 acquire `.worktrees/<TID>/.ide.lock`（含 pid/会话 id/心跳/过期 15min）；同一工单同一时刻只允许一个写入者；DSH 会话也遵守（advisory）；merge 仍单线 | 简单可靠，冲突早失败、提示清晰 |
| B | 仅 git 冲突检测（写前 pull/写后 diff） | 会"写时爽、合时炸" |
| C | 不处理 | 不可接受 |

**推荐 A**；锁被占用时 IDE 明确提示"该工单正被 DSH 会话编辑（含进程/时间）"，不静默等待。

## 四、接口草案（v1 范围）

| 方法/路径 | 作用 | 安全要求 |
|---|---|---|
| `GET /api/ide/scope` | 返回可写 worktree 列表 + 每单状态 | 只读 |
| `POST /api/ide/read` | 读文件内容 | 路径必须在作用域内 |
| `POST /api/ide/write` | 写/补丁文件 | 作用域 + 锁 + 大小上限（≤1MB）+ 编码 UTF-8 + 审计 |
| `POST /api/ide/exec` | 提交命令 | 白名单校验 + 锁 + 超时（默认 120s）+ 输出上限（256KB）+ 审计 |
| `GET /api/ide/exec/<id>` | 结果/输出 | 会话可见 |
| `POST /api/ide/lock` / `DELETE` | 获取/释放工单锁 | 心跳续期；超时回收 |
| `GET /api/ide/audit?task=` | 本单编辑/执行历史 | 只读 |

**本地安全**：仅绑 127.0.0.1；Origin 校验（只接受 `http://127.0.0.1:8103`）；启动时生成**会话令牌**（随机 32B，写入服务内存 + 首屏注入），所有写/执行请求必须带 `X-IDE-Session` 头（防其他本机进程/浏览器 CSRF）；令牌仅存内存不落盘。

## 五、安全威胁模型（必须覆盖）

| # | 威胁 | 对策 |
|---|---|---|
| T1 | 路径穿越 / 符号链接逃逸 | 解析后 `resolve()` 必须仍在 worktree 根之下；拒绝 symlink 目标越界 |
| T2 | 越权改 master / 他人 worktree | 作用域校验（D1）+ 锁（D4） |
| T3 | 命令注入 / 危险命令 | 白名单 + 参数模式匹配；禁 shell 拼接；禁 `rm -rf`/`del /f`/`format`/`shutdown`/`schtasks`/`reg`/`net user` 等 |
| T4 | 凭据泄露 | 执行环境不注入 `_vault/secrets`/环境密钥；读取文件 deny 规则；输出审计前脱敏（复用 scan_secrets 规则） |
| T5 | CSRF / 他进程调用 | 会话令牌 + Origin 校验 + 仅回环 |
| T6 | 资源耗尽 | 超时/CPU/内存/输出上限；并发执行数=1 |
| T7 | 审计缺失/篡改 | events append-only（现有事件层）+ 工单 note 双写；审计接口只读 |
| T8 | 误合并 | 写操作只改 worktree；merge 仍过 devtask 评审门（四守卫） |

**Kill-switch**：环境变量 `IDE_RW=off`（默认 off）——关闭所有写/执行 API，只留只读页；一键回退。

## 六、分阶段与验收

| 阶段 | 内容 | 预估 | 验收 |
|---|---|---|---|
| **R0 骨架** | feature flag + 作用域/lock/审计模块骨架 + 会话令牌 + 只读 `/api/ide/scope` | 0.5 天 | `IDE_RW=off` 时所有写/执行 403；单测覆盖 |
| **R1 受控编辑** | 文件树/编辑器 UI + read/write + diff + events 审计 + 工单锁 | 1 天 | 越界/穿越/无锁写被拒；成功写产生 `code_action` 事件与工单 note；测试 ≥20 条 |
| **R2 白名单执行** | 命令白名单 + 超时/输出上限 + 终端面板 + `code_observation` 事件 | 1–1.5 天 | 危险命令/越界参数被拒；pytest 白名单可跑并留痕；kill-switch 生效 |
| **R3 沙箱升级** | 受限用户/容器执行（按 D2-B） | 2–4 天 | 无网络/无凭据挂载；资源配额生效；逃逸反例测试 |
| **R4 审批链（按需）** | 危险动作发起五要素批准请求；Z 链签字入口 | 按需 | 无批准不执行 |

**建议先做 R0+R1+R2（约 2.5–3 天）**，验证"写+跑测试"闭环后再决定是否投入 R3。

## 八、风险与暂不做

- **风险**：写权限放大"AI 改坏代码"的影响面——靠 worktree 隔离 + 评审门 + 审计 + kill-switch 对冲；**执行沙箱是长尾风险**，R2 白名单必须按"最小命令集"起步，逐个加白。
- **暂不做**：自动合并、自动派单、跨机执行、公网访问、IDE 内跑任意脚本、AI 自主决定执行内容。
