## 一、任务单数据模型

```json
{
  "task_id": "T-20261015-001",
  "opened_by": "A0 | dept/invest/D1 | system/monitor",
  "assigned_dept": "dev | invest | strategy | trading",
  "assigned_agent": "DEV1 | null(部门长派)",
  "title": "T1 prompt 立场强制校准",
  "body": "Day0-4 观测到倒戈 2/5 票，校准靶点见 docs/plans/2026-10-08_Day0辩论质量基线",
  "severity": "P1",
  "status": "open",
  "created_at": "...",
  "due": "2026-10-16",
  "links": ["docs/plans/...", "run_id/..."],
  "closure_note": "完成时必填：改了什么/如何验证/影响面"
}
```

## 二、状态机

```
open ──→ assigned ──→ doing ──→ done
  │           │           └──→ blocked ──→ doing（解除后）
  └──→ cancelled（开单方撤回）
rejected（被派方拒接：须写理由，A0 仲裁）
```

流转规则：
- 只有 assigned_dept 的成员与 A0 可变更状态（RBAC 对齐 memory grants 模式）
- `done` 强制 `closure_note`（防"口头完成"）
- `blocked` 必须写阻塞原因（A0 日报自动汇总阻塞单）
- P0 事件开单直达 `doing`（跳过派单等待，事后补 assigned）

## 三、存储与接口

- **存储**：`data/org/tasks/` 按 `tasks_<YYYYMM>.jsonl` 追加（对齐 memory 的 append-only 语义 + 状态快照行）；RBAC 复用 MemoryStore 模式（dept 隔离，A0 全读）
- **接口**：`engine/tasks.py` 零依赖 CLI——
  - `task.py open --to dev --title ... --sev P1 --body ...`
  - `task.py ls [--dept dev] [--status open]`
  - `task.py move <task_id> doing|done|blocked --note ...`
- 验收：单元自测覆盖状态机全转移+越权拒绝（对齐 smoke 风格）

## 四、与汇报三通道联动（K-ORG-001 §4）

1. **日报**：a0_chief 新增「任务单」段——未闭环单按 severity 降序列出（P0 即时已在事件通道，不重复）
2. **事件**：P0/P1 事件自动开单（如 run_shadow failed≥1 → 开单 to dev 附 last_run.log 摘录）
3. **问询**：A0 被问「XX 进度」时以任务单状态为准答（不凭记忆猜）
