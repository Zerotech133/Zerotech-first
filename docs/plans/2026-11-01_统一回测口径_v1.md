## 1. 背景与目标

复权、T+1、涨跌停、停牌、成本、再平衡、IC 这些口径原先散落在多个脚本里，各自实现、互相对不上：

- `tools/research/selection_engine.py`：只做「当日截面过滤 + 排序」，复权公式是内联片段（`close × adj_factor`），不含净值/成本/涨跌停可交易性回测；
- `tools/research/portfolio_build.py`：只做「选股 → 组合权重」（逆波动、单票 5%、行业 30%、波动率目标），不产出 NAV；
- `tools/research/shadow_ledger.py`：有简版影子盘（T+1 收盘调仓、成本 30bp×换手），但无复权缺失处理、无涨跌停/停牌约束、无 IC/基准，且换手定义与其它脚本不统一。

目标：把上述口径**收口到一个可被因子库/策略库批量调用**的回测工具 `bt_harness.py`：

1. 输入统一为 `DataFrame[date, ts_code, score]`（信号日收盘可知，PIT）；
2. 输出统一为 NAV 序列 + 总收益/年化/MDD/年化波动/平均换手/持仓数/IC/errors + 基准对照；
3. 后续因子库（支线 A `factor_lib.py`）、量学战法规格（支线 B `research/strategy_specs/*.yaml`）只需把信号落成该 DataFrame 即可批量回测。

## 2. 口径总览

| 项目 | 口径 |
|---|---|
| 信号 | `factor_df[date, ts_code, score]`，date 为信号日收盘（PIT，不得含未来数据） |
| 建仓时点 | **信号日 T 的下一交易日 T+1 收盘**建仓；T 当日及之前收益不计入 |
| 持有期 | 持至下一个调仓日的 T'+1 收盘；调仓日先结算当日收益再换仓 |
| 权重 | 等权 top_n；涨停/停牌不可买 → 顺延下一名；候选不足则按实际数量等权 |
| 复权 | 复权价 = `close × adj_factor`；收益一律用复权价计算 |
| 涨停不可买 | `pct_chg ≥ 阈值` 或 `limit_list_d.limit == "U"`；阈值：主板 9.5 / 创业板·科创板 19.5 / 北交所 29.5 / ST 4.5 个百分点 |
| 跌停不可卖 | `pct_chg ≤ -阈值` 或 `limit_list_d.limit == "D"`；不可卖 → 保留原持仓继续持有 |
| 停牌/缺价 | 当日无该股票行情 = 停牌：不可买/不可卖；持仓估值冻结不变，复牌日一次性计入累计涨跌 |
| 不可卖仓名额 | 停牌/跌停保留仓**占用 top_n 名额**：本期新买数量 = top_n − 不可卖仓数，保证组合持仓数恒 ≤ top_n；每笔均在 errors 记录 |
| 再平衡 | `weekly`：每个 ISO 周内最后一个有因子的交易日发信号；`daily`：每个交易日发信号。无下一交易日/超区间的信号跳过并记录 |
| 成本 | 成本 = 换手 × `cost_bp`/10000 × NAV；换手 = `Σ|w_target − w_drift|`（双边口径，0~2，全换仓=2.0），与 `shadow_ledger.py` 的 `COST=0.003×换手` 一致；`cost_bp` 为单边成本，全换仓收 2×cost_bp（往返） |
| 总收益 | `NAV_end / NAV_begin − 1`（NAV_begin=1.0） |
| 年化 | `(1+总收益)^(252/首个建仓日后的交易日数) − 1` |
| MDD | 逐日 `NAV / 历史峰值 − 1` 的最小值（对峰值比较，不是对起点） |
| 年化波动 | 首个建仓日之后日收益 std(ddof=1) × √252 |
| Sharpe | 首个建仓日之后日收益均值/std × √252（rf=0，仅参考） |
| 平均换手 | 各调仓事件双边换手的算术均值（无调仓则 null） |
| 持仓数 | 每日持仓只数（含不可卖保留仓）；上限 = top_n |
| IC | 仅当因子近似全市场（单日截面中位数 ≥ `min_ic_cross_section=100`）才计算，否则 `null`。日度截面 `corr(score_t, ret_{t+1})`，`ret_{t+1}=复权收盘价(t+1)/复权收盘价(t)−1`；输出 Pearson 均值、Spearman 均值、IR、胜率、有效日数 |
| 基准 | 同窗口「等权全市场（复权价、日频等权再平衡）」总收益/MDD/年化波动；另给组合相对基准的 `beta_vs_benchmark`、`corr_vs_benchmark`、`excess_return` |

## 3. 逐项口径说明

### 3.1 信号与 T+1 建仓（防前视）

- `factor_df` 的 `date` 必须是**信号日**（该日收盘后才知道因子值）。回测器在 T 日收盘读取信号，在**下一交易日 T+1 收盘**按当日收盘价成交，因此：
  - T 日收盘→T+1 日收盘这段收益**不计入组合**（正确做法）；
  - 组合收益从 T+1 收盘→T+2 收盘才开始累计；
  - 涨跌停/停牌判定用 **T+1 当日**的 `pct_chg`/行情，符合「T+1 收盘能不能买」的真实约束。
- 期末信号（信号日已是数据末日、无 T+1 行情）不建仓，记 `entry_out_of_range`。
- 用例 `test_t1_entry_does_not_count_signal_day_return`：信号日 T 后一天涨 10%，若错误当日建仓 NAV 会变 1.1，实测 NAV(T+1)=1.0。

### 3.2 复权

- 复权价 = `close × adj_factor`（后复权口径，等价于前复权收益序列），所有收益、IC、基准均用复权价。
- `adj_factor` 缺失按 1.0 兜底；daily 无该股票当日行 = 停牌（NaN），不补价。
- 已用 `pct_chg` 做一致性抽检：2026 年多个交易日「复权收益 − pct_chg」均值差 ≈ 0，口径与源数据自洽。

### 3.3 涨跌停

- 判定双通道：`pct_chg` 阈值 + `limit_list_d` 名单（二者任一命中即算）。
- 阈值按板块走（避免把 20% 板的 +10% 误判成涨停）：

| 板块 | 代码前缀/名称 | 阈值（百分点） | 依据 |
|---|---|---|---|
| 主板 | 000/001/002/600/601/603/605 | 9.5 | 10% 板 |
| 创业板 | 300/301 | 19.5 | 20% 板 |
| 科创板 | 688/689 | 19.5 | 20% 板 |
| 北交所 | 4/8/920 | 29.5 | 30% 板 |
| ST/退 | stock_basic.name 含 ST/退 | 4.5 | 5% 板（仅主板；双创/北交所按板块阈值） |

- `limit_list_d.limit`：`U`=涨停、`D`=跌停、`Z`=炸板（盘中打开，收盘可成交，**不**剔除）。
- 数据现状：`limit_list_d` 仅 2025-09-01 起有文件、且部分日期（如 2026-10-30）同步滞后为空 → `pct_chg` 阈值自动兜底，两通道互补。
- 已知局限：ST 判定用当前 `stock_basic` 名称（非 PIT）；历史 ST 涨停以 `limit_list_d` 名单弥补。

### 3.4 停牌/缺价与不可卖处理

- 缺价定义：该交易日 daily 无该股票行（或 close 非有限值），即停牌/停牌未复牌。
- 调仓日处理：
  - 持有且当日停牌 → **不可卖**：保留原持仓市值（估值冻结），记 `sell_suspended`，占 top_n 名额；
  - 持有且当日跌停 → **不可卖**：保留原持仓（当日收益已按跌停价结算），记 `sell_limit_down`，占 top_n 名额；
  - 目标候选当日停牌 → 不可买，顺延，记 `buy_suspended`；
  - 目标候选当日涨停 → 不可买，顺延，记 `buy_limit_up`。
- 持有期每日：缺价则持仓估值不变（收益记 0），记 `valuation_frozen`；复牌日按「复牌价 / 停牌前最后价」一次性计入累计涨跌（真实可交易性更差，此处理偏保守）。
- 不可卖仓占名额：`slots = top_n − 不可卖仓数`，因此组合持仓数恒 ≤ top_n（`rebalances[].n_holdings`、`nav[].n`、`max_holdings` 均可核验）；不可卖仓占满时记 `no_buy_slots`。
- errors 明细按 `max_errors`（默认 200）截断，`error_summary` 始终给全量分类计数。

### 3.5 再平衡

- `weekly`：按 ISO 周（`isocalendar().year/week`）取周内**最后一个有因子值的交易日**为信号日；正常数据下即周五（或节假日前的最后交易日）。
- `daily`：每个有因子值的交易日都是信号日。
- 每个信号日映射到「下一交易日 T+1 收盘」执行；两个信号映射到同一执行日不可能（交易日序列单射）。
- 回测区间 `[start, end]`：NAV 序列覆盖区间内全部交易日；首个建仓日前 NAV=1.0（空仓不计成本）。

### 3.6 成本与换手

- 换手（双边）：`turnover_t = Σ_i |w_target,i − w_drift,i|`，其中 `w_drift` 为调仓前持仓市值权重（已含当日收益）。全换仓 = 2.0，只建仓一次 = 1.0，维持不动 = 0。
- 成本：`cost_t = turnover_t × cost_bp/10000 × NAV_before`，从组合净值中扣除（实现上从新买入目标等比例缩水，忽略二阶误差）。
- 与现有脚本对齐：`shadow_ledger.py` 用 `turnover=Σ|Δw|`、`COST=0.003`，本工具同一定义，故「30bp」在两者中含义一致（单边费率）。
- 成本构成建议：`cost_bp` 由调用方按「佣金 + 印花税 + 滑点」的单边合计给出（例如佣金 2.5bp + 滑点 10~20bp；印花税 5bp 只在卖出，可按单边近似计入）。
- 用例 `test_cost_deducted_by_turnover`：同一信号，cost_bp=0/30/100 时 NAV 严格递减；100bp 场景末值 ≈ 0.9702（含首次建仓 1.0×1% + 全换仓 2.0×1%×0.99）。

### 3.7 收益/风险指标

- 总收益、年化、MDD、年化波动、Sharpe 定义见上表。
- **MDD 与总收益相等的说明**：MDD 是「逐日 NAV 对历史峰值的最小回撤」。若 NAV 全程未创出新高（峰值始终是首日 1.0），则 `MDD = NAV_end/1.0 − 1 = 总收益`，这就是本 demo 的情形，**不是用了错误累计序列**。为便于复核，输出 `mdd_detail`（峰值日/峰值 NAV/谷底日/谷底 NAV/回撤），并有测试 `test_mdd_measured_against_peak_not_total_return` 构造「总收益 +10%、MDD −25%」的路径验证两者可分离。

### 3.8 IC

- 门槛：因子单日截面中位数 ≥ `min_ic_cross_section`（默认 100）才计算，否则 `ic = null`（小样本/单票信号不算 IC）。
- 计算：对回测区间内每个有因子的交易日 t（且 t+1 仍在数据内）：
  - `x = score_t`，`y = 复权收盘价(t+1)/复权收盘价(t) − 1`；
  - 有效样本 ≥ 5，算 Pearson `ic` 与 Spearman `rank_ic`；
  - 有效天数 ≥ 3 才输出汇总。
- 汇总字段：`mean`（Pearson 均值）、`mean_rank`（Spearman 均值）、`ir`/`rank_ir`（均值/std）、`n_days`、`win_rate`。
- 注意：IC 用的是 **T→T+1 日收益**（因子日报标准口径），而组合是 T+1 收盘建仓、收益从 T+1→T+2 起计，二者相差一天，IC 只用于因子评价，不直接等于组合可实现 alpha。

### 3.9 基准与超额

- 基准 = 同窗口「等权全市场、复权价、日频等权再平衡」：每个交易日对当日有价个股取复权收益等权平均后复利。
- 输出 `benchmark.{total_return, annual_return, mdd, vol_ann, trading_days}` 与 `excess_return = 组合总收益 − 基准总收益`。
- 另输出 `beta_vs_benchmark`、`corr_vs_benchmark`（组合日收益对基准日收益回归），用于判断组合表现是否只是基准 beta 放大。

## 5. 与现有脚本的关系

| 现有脚本 | 已有能力 | 与本工具关系 |
|---|---|---|
| `selection_engine.py` | 当日截面过滤 + 排序 + 内联 `close×adj_factor` | **复权口径被收编**（同公式）；其过滤/排序可产出 `factor_df` 或候选清单，交给 bt_harness 做带约束回测。它自身不做净值/成本/涨跌停回测。 |
| `portfolio_build.py` | 选股 → 逆波动/上限/波动率目标权重 | **互补**：它解决「权重怎么配」，本工具解决「按统一可交易性口径出净值」。其等权 top_n 口径即本工具默认；逆波动权重尚未接入（v1 只做等权，见 §9）。 |
| `shadow_ledger.py` | 简版影子盘：T+1 收盘调仓、30bp×换手、NAV/MDD | **超集**：本工具保留其 T+1 与「成本=换手×30bp」定义，补齐复权缺失/涨跌停/停牌/持仓上限/IC/基准/errors。后续影子盘可切换到 `run_backtest` 的同一口径，避免两套数字。 |
| 量化仓旧引擎（`quant_backtest/backtest_engine_v2.py`、`backtest.py` 等） | 完整老引擎 | 本次**不动**，属历史资产；bt_harness 定位为「因子库/策略库统一评测口径」，不替代生产交易引擎。 |
| 支线 A `tools/research/factor_lib.py`（开发中） | 因子表达式/PIT/IC 评测 | `compute_named_factor` 在非内置因子名时会尝试复用其 `compute_factor(name, market=...)`；因子输出 `[date, ts_code, score]` 即可直接 `run_backtest`。 |
| 支线 B `tools/research/strategy_specs.py` + `research/strategy_specs/*.yaml` | 24 个量学战法机器可读规格 | 战法信号落成 `factor_df` 后可批量调用本工具回测（见 §6 批量示例）。 |

## 6. 使用示例

### CLI（demo 即此命令）

```bash
C:\项目\py312\python.exe -X utf8 tools/research/bt_harness.py run \
  --factor mom20 --start 20260101 --end 20261030 \
  --top 50 --cost-bp 30 --rebalance weekly
# 默认输出 research/reports/bt_harness_demo_20261101.json
```

其它参数：`--lookback 25`（因子前置交易日缓冲）、`--min-ic-cs 100`、`--include-holdings`（调仓事件附 `holdings`/`target` 代码列表，便于核验）、`--out <path>`、`--quiet`。

### Python API（单因子）

```python
import sys
sys.path.insert(0, r"C:\项目\老田的AI助手\tools\research")
from bt_harness import load_market, compute_named_factor, run_backtest

market = load_market("20260101", "20261030", lookback_days=25)   # 只加载一次
factor_df, desc = compute_named_factor("mom20", market)          # 或自备 factor_df
report = run_backtest(factor_df, "20260101", "20261030", top_n=50, cost_bp=30,
                      rebalance="weekly", market=market, label="mom20")
print(report["total_return"], report["mdd"], report["avg_turnover"], report["benchmark"])
```

### 批量调用（因子库/策略库）

```python
reports = {}
for name, fdf in factor_batch.items():          # fdf: DataFrame[date, ts_code, score]
    reports[name] = run_backtest(fdf, "20260101", "20261030", top_n=50, cost_bp=30,
                                 rebalance="weekly", market=market, label=name)
# 汇总成 DataFrame 可直接比较：total_return / annual_return / mdd / avg_turnover / ic_mean
```

> 性能：`load_market` 加载 2026 全年 198 个交易日 + 前置缓冲约 5~7 秒（本机实测 demo 全流程 5~6s，其中行情加载约 4~5s）；`run_backtest` 单因子 < 1s。market 对象可复用，批量调用不要重复加载。

### 归因核验（为什么动量 top50 在 2026 亏 68%，不是引擎 bug）

1. **2026 是熊市**：同期指数区间收益（20260105→20261030 收盘）上证 −10.55%、深证 −21.66%、沪深300 −15.52%、创业板 −26.74%；等权全市场基准 −16.17% 与指数互相印证。
2. **组合买的是极端追高股**：41 个信号日 top50 的 mom20 均值 **+71.65%**（中位 +70.8%，最大 +106.1%），即买入的是过去 20 日已翻倍级别的极端股；泡沫破裂时这类仓位跌幅远超市场。
3. **动量本窗口无预测力**：IC 均值约 0（rank IC −0.028），top50 相对市场无 alpha；beta 1.19 只解释约 19pp 的基准跌幅放大，剩余是极端多头仓位的独立崩塌。
4. **独立实现交叉复核**：用纯 pandas 向量化另写一版「周频信号 → 次日收盘等权 top50 → 持有一周」（不加上涨跌停/停牌/成本约束）得总收益 **−58.66%**（期均 −1.93%），与本引擎 cost=0 的 −63.82% 同向同量级；差异来自本引擎的涨停不追、跌停/停牌保留、持仓上限等真实约束（更保守）。
5. 结论：−68.58% 是该数据/该因子/该口径下的真实结果，不是持仓重复累加或 NAV 计算错误；同时它也说明**简单 mom20 top50 在该窗口不可用**（这正是统一回测口径要暴露的问题）。

复核要点自查：
- 持仓数：`nav[].n` 与 `rebalances[].n_holdings` 全程 ≤ 50（`max_holdings = 50`）；不可卖保留仓计入名额。
- MDD：`mdd_detail` 给出峰值/谷底日期与 NAV；测试构造了「总收益 +10% / MDD −25%」路径证明公式正确且两者可分离。
- 基准：`benchmark.total_return = −16.17%`，`excess_return = −52.40pp`，`beta_vs_benchmark = 1.19`。

## 9. 已知局限与后续

1. **权重**：v1 只做等权 top_n；逆波动/波动率目标（`portfolio_build.py`）未接入，后续可新增 `weights_provider` 参数。
2. **成交价**：T+1 收盘价成交、涨跌停按收盘状态判定；盘中打开涨跌停、集合竞价滑点未建模。成本为换手线性近似，未含冲击成本/最低佣金。
3. **停牌估值**：缺价日估值冻结、复牌一次性计入累计涨跌；真实停牌期间不可交易，此处理偏保守。退市不做清算减值（缺价后估值冻结）。

5. **新股首日**无涨跌幅限制未单独处理。
6. **IC 时点**：T→T+1 日收益口径（因子日报标准），与组合 T+1 收盘建仓差一天；仅用于因子评价。
7. **基准**：等权全市场（日频再平衡），非市值加权指数；如需沪深300 基准可后续加 `--benchmark-index` 参数。
8. **批量**：市场矩阵一次性加载可复用；若批量因子很多，建议按「加载一次 market → 循环 run_backtest」。
