## 一、目标与非目标

**目标**：把 `Handler.do_GET/do_POST` 的 if/elif 分派逐步改为**有序路由表**驱动，减少 `portal_api.py` 体积与分支圈复杂度；行为逐字等价。

**非目标**：
- 不改任何 route 语义/响应（本单零行为变更）；
- 不合并/拆分业务 handler 方法（已在 A5 纯移动批次完成）；
- 不动动态路径解析（如 `?query`、`#hash` 由原逻辑处理）；
- 不做“统一路由框架”（避免过度设计）。

## 三、设计（有序表 + 回退，最小风险）

### 3.1 数据模型（新模块 `portal/route_table.py`）

```python
# 精确路由：dict 查找 O(1)
EXACT_GET = {
    "/": "_portal_page",
    "/api/health": "_api_health",
    # ...（由草案 + 人工复核生成）
}
EXACT_POST = {...}
# 前缀路由：保持原 if/elif 顺序（先长后短由生成器排序并人工确认）
PREFIX_GET = [
    ("/api/zhuge/review/", "self._zhuge_review"),
    # ...
]

def match_get(path: str): ...
def match_post(path: str): ...
```

- **表项值**为 handler 名字符串（`self._xxx`）或 `callable`；
- 兼容 **OR 条件**（`path == A or path.startswith(B/)`）：生成器拆成多条表项，同一 handler；
- 兼容 **多值 in 条件**：展开为多个 exact 表项；
- **未识别/含复杂逻辑的分支保持原 if/elif 块**（表项为 `None` 时回退）；
- `do_GET` 变为：`handler = match_get(path); if handler: 调用；else: 原分支块`。

```python
def match_get(path):
    h = EXACT_GET.get(path)
    if h is not None:
        return h
    for prefix, h2 in PREFIX_GET:      # 有序
        if path.startswith(prefix):
            return h2
    return None
```

### 3.2 开关（灰度为先）

- 环境变量 `PORTAL_ROUTE_TABLE`：`0`（默认，走原 if/elif）| `1`（表优先，未命中回退原分支）；
- 上线步骤：合入默认 off → 本地/预发 `=1` 全量回归 → 观察 24h → 默认 on → 下一窗口删除旧分支；
- 回滚：`=0` 或 revert 开关提交（表模块可保留）。

### 3.3 代码组织

- `portal/route_table.py`：表 + `match_*` + 生成时校验（导入期断言表内 handler 均存在）；
- `portal/portal_api.py`：do_GET/do_POST 只保留"表命中→调用；否则原逻辑"的薄壳；
- 新 handler 只进表 + 新 `api_*.py`，**禁止再往 portal_api 加 if/elif**（行数门继续兜底）。

## 五、风险与回滚

| 风险 | 缓解 |
|---|---|
| 前缀顺序错（overlap） | 生成器按原代码顺序输出；B4b 专项测试锁顺序 |
| OR/in 条件拆分错 | 草案 JSON 保留 `line`，人工逐条复核；对拍测试兜底 |
| 复杂分支误表化 | `unparsed`/`None` 回退原代码，不强行表化 |
| 性能 | dict O(1)；前缀列表 ≤30，线性可接受 |
| 回滚 | `PORTAL_ROUTE_TABLE=0` 即时回退；表模块无副作用可保留 |
