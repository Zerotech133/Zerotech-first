## 0. 一页结论

**要建的不是“五个会聊天的 AI”，而是“一套人类在环的指挥部运行系统”：**

```text
老田思想/目标
  → 田丰拆解为任务 DAG 并派给五角色
  → 诸葛亮挑战前提 / 赵云复核证据 / 黄忠验收 / 关羽代码审计
  → 田丰汇总共识与分歧
      ├─ L0/L1 共识 → 自动执行（带证据、回滚、审计）
      └─ 不共识 / P0 / L2 → 飞书定版卡 → 老田选 A/B/C → 回写执行
  → 全链路 decision/trace 账 → 复盘进化
```

四条硬边界：

```text
1. 五角色是参谋/审计/验收，不是签字人；M4 四签仍由 QA1/GUANYU/VERIFY1/ARCH1 + A0 完成。
2. L2（生产/资金/审批/宿主机/上线/删除）永远人工定版，AI 只给建议。
3. 没有证据的“共识”不算共识；没有回滚的自动执行不准上线。
4. 不把“五个 AI 投票”冒充“组织验收”。
```

| 诸葛亮（AI1） | 反向质询、pre-mortem、找反例、挑战前提 | 不拍板、不写生产代码 |
| 赵云（ZHAOYUN） | 独立证据复核、审计、经验归档、进化建议 | 不做业务决策、不改生产 |
| 黄忠（HUANGZHONG） | 验收标准、抽样、质量终检、建议放行/拒收 | 不代签、不修代码 |
| 关羽（GUANYU） | 代码审计、技术债、门禁、整改建议 | 不自行合并、不碰生产 |
| 老田 / ARCH1 | 定版、L2 授权、最终责任 | 不被 AI 替代 |

### 3.2 统一输出契约（RoleOpinion v1）

```json
{
  "schema": "hq_role_opinion/v1",
  "topic_id": "HQ-20261101-001",
  "role": "ZHUGE|ZHAOYUN|HUANGZHONG|GUANYU|TIANFENG",
  "round": 1,
  "position": "support|conditional|oppose|abstain",
  "recommendation": "一句话结论",
  "evidence": [
    {"kind": "file|command|test|live|hash", "ref": "...", "digest": "sha256:...", "verified": true}
  ],
  "risks": ["P0/P1 风险，必须可执行"],
  "conditions": ["附条件通过时必填"],
  "escalate": false,
  "escalate_reason": "",
  "created_at": "2026-11-01T10:00:00+08:00"
}
```

规则：

```text
1) 每条 evidence 必须有可复核 ref/hash；无证据不得写 verified=true
2) oppose 必须给替代方案或明确“不可接受原因”
3) conditional 必须给可验收条件
4) escalate=true 时田丰必须出飞书卡，不得内部消化
```

## 4. 工作流设计

### W-C1 角色运行时与契约（P0）

交付：

```text
agent_platform/command_hq/role_contract.py
  - RoleOpinion v1 校验/序列化/去重
  - 五角色适配器：tianfeng/zhuge/zhaoyun/huangzhong/guanyu
  - 角色 model/tool/prompt 绑定表（复用 org/registry，不新造身份）
  - 统一“只出意见，不执行”边界
```

验收：

```text
五角色对同一 topic 各产出合法 RoleOpinion；schema 测试；无证据禁止 verified
```

### W-C2 指挥部编排器（P0）

交付：

```text
agent_platform/command_hq/orchestrator.py
  - 输入：老田思想/目标 + 约束
  - 田丰拆解：task DAG（owner/依赖/验收/风险级别）
  - 并发派单：五角色按视角执行（可异步等待）
  - 汇总：共识/分歧/需升级项
  - 状态机：draft→debate→consensus|escalated→decided→executing→done|rolled_back
  - 复用 mission_planner/worker/devtask/approval_control，不重造
```

验收：

```text
一条真实思想（如“M4 会诊”）能跑出 DAG+五意见+汇总；重跑幂等
```

### W-C3 讨论、共识、飞书定版（P0）

交付：

```text
agent_platform/command_hq/consensus.py
  - 轮次/同题去重/反对保留/分歧聚类
  - 共识判定：
      L0/L1：田丰+黄忠+关羽 3/5 且无 P0 反对 → auto_ready
      含 L2/风险：强制 escalate
  - 飞书定版卡：topic/选项 A/B/C/推荐/风险/截止
  - 回写：decision_id/选择/理由/执行 owner
  - Feishu 回调 → decision ledger；老田沉默不默认同意
```

验收：

```text
同一分歧跑两次得到同一 decision_id；飞书卡 dry-run 可渲染；
老田点选可回写；无选择超时→blocked，不自动执行
```

### W-C4 L0/L1 自动执行与安全门（P1）

交付：

```text
agent_platform/command_hq/execution_gate.py
  - L0/L1/L2 分类（复用 K-STOCK-416/approval_control）
  - L0/L1：共识+证据+回滚→自动执行 devtask/只读/测试/文档
  - L2：强制人工，AI 只能出建议
  - 执行前后证据、rollback 命令、kill switch、审计日志
  - 每单最大 blast radius 白名单
```

验收：

```text
L0/L1 演练 1 例成功+回滚；L2 注入 1 例被 100% 拦截；无 kill switch 不准执行
```

### W-C5 M4/验收会诊（P0，立即）

交付：

```text
M4 会诊包：
  田丰：目标/边界/建议
  诸葛亮：最可能假的 5 点
  赵云：独立证据复核（live/hash/test/rollback）
  黄忠：验收结论（接受/附条件/拒收）
  关羽：代码/门禁/技术债风险
  → 一页 packet 给 QA1/GUANYU/VERIFY1/ARCH1
```

验收：

```text
五角色意见齐全；证据可复核；不代签、不伪造 4/4；
四签窗口用 packet，而不是再开一堆报告
```

## 6. 指标


## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 五个 AI 同族自证 | 模型/prompt/上下文隔离；诸葛亮必须异族（GPT6 恢复或明确 relay 标签）；人类终审 |
| 角色互兼/黄忠无否决权 | 黄忠必须能拒收/附条件；角色不可兼任建设者 |
| 假共识 | 证据门槛；oppose 必须带替代方案；L2 强制升级 |
| 自动执行爆炸半径 | 白名单+blast radius+kill switch+回滚；先 L0 再 L1 |
| 飞书卡被当默认同意 | 超时=blocked；沉默不执行；一次一议 |
| 编排器变成新巨石 | 复用 mission_planner/worker/devtask/approval_control，新增只做编排/契约 |
| 计划再通胀 | 只在 v2 下做专项；不做新 IDE 功能；每 Gate 有验收/负责人 |
