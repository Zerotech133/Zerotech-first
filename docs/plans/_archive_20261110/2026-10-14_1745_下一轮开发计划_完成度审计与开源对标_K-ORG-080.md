## 二、开源社区对标（2026-10-14 调研）

### 2.1 OpenHands 验证栈（Verification Stack，80k+ stars）——四层防线
| 层 | OpenHands 做法 | 我方现状 | 判定 |
|---|---|---|---|
| L1 Critic Model | 小模型对轨迹打分，低分轨迹重选（AUC 0.69，准确率 57.9%→73.8%） | 无 | **缺口** |
| L2 Code Review Skill | 10 场景结构化清单评审 + 🟢🟡🔴 风险评级 | QA1 只读审查（062a）+ 清单式（测试规范知识库） | ✅ 形态相当 |
| L3 QA Agent | **真跑软件**：起服务/开浏览器/跑 CLI，Understand→Setup→Exercise→Report | 仅 smoke（rc0+合法 JSON），无行为级实测 | **缺口** |
| L4 Iterate Skill | 读 CI 结果→解析评审意见→修→推→循环至全绿 | repair-rounds 已有（SEC2 自动返修实证） | ✅ 但只吃 SEC2/QA1 结论，不消费 L3 实测结果 |

### 2.2 规范驱动开发（GitHub Spec Kit 111k stars / AWS Kiro / BMAD）——SDD 三件套
| 实践 | 业界做法 | 我方现状 | 判定 |
|---|---|---|---|
| spec→design→tasks 分层 | requirements/design/tasks.md 三文件链 | devtask spec 单文件混写 | **缺口**（可轻量化） |
| 宪法 constitution | 跨切面铁律每次任务必读 | 三底线/纪律散在岗卡与哨文件 | ⚠️ 可收敛成 constitution.md |
| 验收判据结构化 | EARS 句式（WHEN…THE SYSTEM SHALL…）可 lint 可测 | spec 内自由文本（072 靠 QA1 人读） | **缺口** |
| 冷读者验证 | 新会话只读 spec 冷启动执行，证明 spec 自含 | 彩排即冷读者（worktree 新检出）✅ | ✅ 已是无意实践 |
| spec 漂移检测 | CI 断言验收场景仍与测试相连 | 金样本纪律覆盖单次运行，无持续断言 | ⚠️ 低优先 |
| 反模式「agent 改 spec」 | 严禁产码方改 spec | e2e 中 DEV1 无 spec 写权限 ✅ | ✅ 已制度化 |

### 2.4 规模化控制面（OpenHands Control Plane / CSA Agentic Trust）
| 实践 | 我方现状 | 判定 |
|---|---|---|
| 沙箱隔离+最小权限 | QA1 只读白名单（062a 判例）；其余岗无系统化工具白名单 | **缺口**（白名单应矩阵化推广全岗） |
| 审计日志 | devtask 事件流+监督体检 ✅ | ✅ |
| 成本归因 | 无工单级 token/时长台账 | **缺口** |
| 非人身份认证 | 岗位身份卡（076 画像注入）✅ | ✅ |

### 2.5 对标总结：三个真缺口
1. **实跑验证层（QA-RUN）**——业界最强调的「agent 真跑软件」，我们止步于 smoke；
2. **验收判据结构化（EARS 化）**——QA1 人读自由文本，改为逐条机器可断言；
3. **工单级成本台账 + 全岗工具白名单**——控制面从 QA1 单岗推广到全岗。
