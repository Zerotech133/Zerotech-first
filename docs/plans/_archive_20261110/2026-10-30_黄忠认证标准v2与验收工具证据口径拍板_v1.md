| ⑥ | 独立复核 | 赵云抽查 **3 单一致（3/3）** | 随机可复现、逐项核对；不一致单作废重验 | 抽查记录（抽签种子 + 核对表） |

### 2.2 判定细则（逐条）

**① ≥10 单 PASS 验收**

- 计数单位 = 一次针对**具体 commit** 的独立验收；同一 commit 多次验收只计最新一单（防重复注水）。
- 手工单、日更单、抽检回填单均可计入认证样本；但**抽检回填单不计入覆盖率 KPI**（沿用决策包第六节选项 4 口径）。
- 统计窗口 = 观察期启动（2026-10-28）至认证评审日；验收单必须真实落盘于 `work/huangzhong/acceptance_<sha8>.json/md`。
- 不计入：演练单（②）、OBSERVE/REJECT 单、证据不满足⑤的单。

**② ≥1 次真实受控拒收演练**

- 必须是**真实**的 REJECT 或 OBSERVE 判定（由工具对真实证据判定产生），**禁止造数据**（禁止手改 passed/failed 数值、禁止伪造红队通过率）。
- 演练单本身计入 REJECT/OBSERVE 样本与「拒收路径可用」证明，**不计入 PASS 样本与覆盖率 KPI**。
- 至少 1 次；建议 REJECT、OBSERVE **各 1 次**（加分项，不作硬性要求）。操作口径见第五节附则。
- 必须附《受控拒收演练记录》：手段、证据来源（git sha/路径/生成时间）、工具命令原文、实际 verdict 与 reason、证据年龄、回滚与复位证明（命令 + 复跑 rc）、见证人（赵云或老田 ≥1 人）。

**③ 误拒绝率 <5%**

- 定义：误拒绝率 = （人工复核后被推翻的 REJECT 单）/（REJECT 总单，含演练单）。
- 与 charter KPI 的「拒绝准确率」互为补数：拒绝准确率 = 复核确认有效的 REJECT / 总 REJECT；两者之和 = 100%。
- 小样本口径：自然 REJECT 样本 <20 单时，5% 阈值无统计意义 → 按「**逐单人工复核，确认无误拒**」判定通过；自然 REJECT 样本 ≥20 单时按 <5% 硬指标。当前 0 个自然 REJECT，演练后将产生首批可复核样本。
- 复核记录须落认证材料（谁复核、复核结论、证据依据）。

**④ 漏放 = 0（PASS 后 7 天事故）**

- 对每张 PASS 单检查其**生效后 7 天窗口**：窗口内发生与该 commit 相关的事故（含 `git revert`、事故单、生产异常、回滚记录）即计漏放。
- 判定：满 7 天窗口的 PASS 单中漏放数必须 = 0；**未满窗单不阻塞认证**但列为认证后跟踪项；若认证评审日满窗 PASS 单为 0，则本条不通过（须等到至少 1 张满窗）。
- 当前最早 PASS 为 2026-10-28，满窗点 ≈ 2026-11-04，与决策包「11-04 才满窗」判断一致。

**⑤ 证据链完整率 100% + commit 级/显式绑定 + 年龄 ≤48h**

- 每单必备字段（8 项，缺一即该单判 OBSERVE、不计 PASS）：
  1. 被测 commit（真实存在，`git cat-file -e <sha>` 可验证）；
  2. 基线证据来源路径 + `generated_at` + `age_hours`；
  3. 红队证据来源路径 + `generated_at` + `age_hours`；
  4. 工具命令原文（可复跑）；
  5. verdict + reasons；
  6. `rollback_point`（`git revert <sha>`）；
  7. `mode=observe` / `blocking=false` 保持；
  8. 人工签字位（老田）。
- 证据口径：必须是 **commit 级/显式绑定**（A 单 `--baseline`/`--redteam` 显式指定，`evidence_scope=explicit`），或工具默认最新证据且**年龄 ≤48h**（A 单 `--max-evidence-age-hours` 默认 48）。
- 证据缺失/不可读/超龄 → **OBSERVE**（不编造、转人工补证），不得判 PASS。
- 48h 是**认证口径**（工具默认门）；接 merge 前置/阻断时的**运行口径**按 R3 收紧为 ≤24h（见 4.2），原则是「运行门严于认证门」。

**⑥ 赵云抽查 3 单一致（3/3）**

- 赵云（平台质量门/治理审计）从 ≥10 单 PASS 中**随机抽 3 单**，抽签过程可复现（记录随机种子/方法）。
- 逐项核对：① commit 与工单真实对应；② 证据文件可读且生成时间吻合；③ 结论可用验收单给定命令复现；④ 回滚点有效；⑤ 无越权动作。
- 3/3 一致 = 通过；任一项不一致 → 该单作废重验并记录差异，认证材料补齐后重抽。
- 抽查记录落 `work/huangzhong/` 或认证包（认证材料向老田呈报时必须附）。

## 五、附：受控拒收演练操作口径

> 目标：在**不造假数据**的前提下，让黄忠真实产出一张 OBSERVE 或 REJECT 验收单，证明「拒收路径可用、证据可复核、复位可验证」。

### 5.1 四原则

1. **真实证据**：证据必须来自仓库真实产物或真实代码状态（历史报告、历史 commit、真实测试失败）。
2. **只动一次性载体**：临时目录或独立 worktree；**不动 master 工作区、不合并、不推送**。
3. **可回滚且必须复位**：演练后必须复位并留证（命令 + 复跑结果）。
4. **演练单标识**：标注 `drill`，不计入 PASS 样本与覆盖率 KPI。

### 5.2 三种允许手段（任选其一即达标；建议 REJECT 与 OBSERVE 各 1 次）

| 手段 | 做法 | 期望 verdict | 现成真实证据源 |
|---|---|---|---|
| 1. 历史失败证据·显式绑定 | 用 A 单 `--redteam` 显式绑定**历史上真实未达标**的红队报告 | **REJECT** | `work/p1/redteam/redteam_20261027_150225.json`：total=2、passed=1、failed=1、**pass_rate=0.5**（2026-10-27T15:02:25，真实历史产物） |
| 2. 证据超龄·显式绑定 | 用 `--baseline`/`--redteam` 绑定生成时间早于 48h 的真实证据 | **OBSERVE** | 当前基线 `agent_platform/data/test_baseline/latest.json`（`generated_at=2026-10-28T00:09:51`，已 >48h）；或任一历史红队报告（10-27） |
