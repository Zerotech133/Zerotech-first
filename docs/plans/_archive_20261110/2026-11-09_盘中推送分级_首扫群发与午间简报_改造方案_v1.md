## 1.1 客户单聊优先（多客户模型）

| 层面 | 内容 | 接收形态 | 当前实例（老田=首个客户） | 未来多客户 |
|---|---|---|---|---|
| 客户面 | 个股分析、异动提醒、个性化首扫/午间/收盘简报 | **单聊 open_id**（一人一会话） | 老田个人单聊 | 每个客户绑定自己的 open_id；各发各的，不混群 |
| 运营面 | 池级公共摘要、团队心跳、运营统计（不含任何客户持仓/个性化结论） | 群 chat_id（可选） | 量化群（默认） | 可保留为团队视图，或整体关闭 |
| 禁止 | 客户分析内容进群、A 客户内容发给 B 客户 | — | 由路由表 + 客户绑定校验拦截 | 同上，按 customer_id 隔离 |

落地含义：

- `receivers.json` 增加 `customer_id` 维度（现在是 name/type/id/note；后续加 `scope: customer|ops` 与 `customer_id`）。
- `push.routes` 由「alert/brief」升级为「**customer**（单聊）/ **ops**（群，可选）」；当前实例两者可都指向老田个人 + 量化群，但语义分开。
- 客户分析类消息只解析 `scope=customer` 的接收人；找不到就 fail-closed，绝不回落群。
- 多客户上线时，首扫/午间/收盘的“池级摘要”默认也改为**每客户单聊各发一份**；群只保留团队运营视图（可开关）。

## 2. 改动点（代码级，本次不实施）

### C1. 配置结构：新增 `push.routes`（向后兼容）

文件：`C:\项目\analysis_work\intraday_watch_config.json`

```json
"push": {
  "kind": "watch:realtime",
  "enabled": true,
  "receiver": "个人",                  // 保留：缺省/客户面回落（单聊）
  "routes": {
    "customer": "个人",                 // 客户分析/异动/个性化简报 → 单聊 open_id
    "ops": "量化群"                      // 仅公共摘要/运营视图 → 群 chat_id（可置空=关闭）
  }
}
```

- 不配 `routes` 时行为完全等同今天（全部走 `receiver`），便于回滚。
- 校验：`routes.customer` 必须是 `scope=customer` 的 open_id；`routes.ops`（若配）必须是 `scope=ops` 的 chat_id；任一名不在 `receivers.json` → 启动 fail-fast（不静默回落个人/群）。
- 老配置里的 `alert`/`brief` 键保留别名映射：`alert→customer`、`brief→ops`，避免已写配置失效。

### C2. payload 增加「类别 → 接收人」解析

文件：`analysis/intraday_watch.py`

- `to_push_payload()`（约 L1587–1612）：异动 payload 的 `receiver` 由 `routes.alert` 解析（默认 `push.receiver`）。
- `build_open_scan_payload()`（约 L1849–1884）：`receiver = routes.brief`；卡片标题不变。
- 收盘小结 payload（约 L1931–1970）：`receiver = routes.brief`。
- `build_midday_payload()`（R4 新增）：`receiver = routes.brief`，`rule="midday_summary"`。

### C3. `push_via_hub()` 支持按 payload 分组发送（核心改动）

文件：`analysis/intraday_watch.py`（约 L1782–1820）

现状：一次调用只 `resolve_receiver(receiver or push.receiver)`，**所有 payload 发同一个接收人**。
目标：

1. 按 `payload["receiver"]` 分组（缺省回 `routes.alert`/`push.receiver`）；
2. 每组解析 `receivers.json` 得到 `receive_id` + `receive_id_type`（`open_id`/`chat_id`）；
3. 逐条 POST 8097 `/api/send`（hub 是单消息入口：`content` + `receive_id` + `receive_id_type`，见 `portal/push_admin_server.py:1233`）；
4. 汇总 `ok` 结果，`pushes` 流水按 payload 各自记录 `sent`；
5. 任一接收人解析失败 → 该组 fail-closed，不回落个人、不静默改投。

### C4. 首扫卡：群发 + 保持“每交易日一次”

- `maybe_open_scan()`（约 L1885–1920）：接收人改为 `routes.ops`（公共摘要，不含客户个性化）；多客户上线后改为按客户逐份发单聊（`routes.customer`）。KV `open_scan_done:<date>` 逻辑不变；失败不置标记、下轮重试。
- 个人侧不再产生任何 `open_scan` 消息（无重复）。

### C5. 收盘小结：群发

- `maybe_close_summary()`（约 L1979–2000）：接收人改 `routes.brief`；KV `close_summary_done:<date>` 不变。

### C6. 午间简报（R4，可选新增）

- 触发：交易日 **11:28–11:35** 之间首个 tick；KV `midday_done:<date>`；失败不置标记。
- 内容：上午收盘/涨跌幅（池内 5 只，按涨跌排序取前 3/后 3）+ 上午触发计数（分规则）+ 板块前三 + 一句风险提示。
- 接收人：`routes.brief`（群）；个人不收。
- 不新增计划任务：引擎 09:25–11:30 常驻，lunch 休眠循环仍在跑，11:30 附近 tick 可触发；若引擎 15:10 收工前退出，11:30 不受影响。

### C7. 去重与“个人不重复”

- 个人只收 `alert` 类（C2 路由保证）。
- 同一 tick 同时有摘要与异动时：摘要发群、异动发个人，天然不重复。
- `pushes` 表新增可选列 `receiver`（`ALTER TABLE pushes ADD COLUMN receiver TEXT`，纯增量，旧库可读），用于审计“这条发给了谁”；不加也能跑（payload 里已有 receiver）。
- 冷却/指纹逻辑不变（仍按 code+rule+fingerprint）。
