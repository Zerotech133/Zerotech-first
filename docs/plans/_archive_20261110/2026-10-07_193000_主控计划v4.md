## 一、项目定位（一句话 + 三层展开）

**临界**：基于**缠论**与**菜鸟量化系统**的全盘数据整理与量化决策工程，以多 Agent 协作为生产方式，目标 = 可信数据 → 可解释信号 → 可审计决策的端到端闭环。

- **数据层**：菜鸟量化（thunder-model，ts_* 系列表）+ Tushare + 本地仓，经 KG-TushareSync/TdxSync 双通道汇入 PostgreSQL（数据城池）与 Neo4j（元子图谱）。
- **信号层**：缠论多级别（1F/5F/30F）+ weak/strong 板块强弱 + 九维 + 联动 + RPS + JEV 等策略族，strategies.json 统一注册（现 11 卡）。
- **决策层**：门户 portal（总线）+ 飞书推送链 + ai_operator 记忆/审计底座（在建）+ weak 复盘进化循环。

**命名宪章**（老田 10-07 钦定）：项目总名=临界；图谱=元子；数据仓=数据城池；数据联动=数据血缘。

## 四、工作方法（定型为六条）

1. **注册制开工**：新 Agent/新服务先登记（PACT §四）再动工；端口先登记后占用。
2. **写入窗口制**：Neo4j 大批量写入互斥登记；Ollama 交互优先、批量深夜单飞行；维护窗口联席+双方停看门狗。
3. **版本化保护律**：任一线交付即 git 入库；跨线代入库须「内容零修改+来源与授权标注+py_compile/测试验证」三条件。
4. **金样本闸门前置**：新信号/新参数先金样本+对照回测，过了才量产（strong 21 例、缠论联立草案均此模式）。
5. **单一事实源**：策略注册 strategies.json、基建状态 /dev.html+health.json、进度台账 INTEL_RD_PLAN.md+本文件、协定量 AGENT-PACT；禁止旁路。
6. **冲突上报制**：两侧行为冲突 → 立即报老田+给方案，不擅自裁决（老田指示）。
