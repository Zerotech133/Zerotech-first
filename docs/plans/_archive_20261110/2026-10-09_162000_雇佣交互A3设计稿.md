> **一句话定义：雇佣 = 把某个策略源的执行路由给某个交易员档案。雇佣是配置面，不是交易面——门户永不直接触发下单。**

---

## 0. 语义与边界（老田已拍板的概念延伸）

- 选股机器人（策略源）回答「买什么」，交易员回答「怎么买」。**雇佣交互 = 在两者之间建立路由关系**：
  - 双刀（每日 14:40 扫描 → poc_qd_*.json）雇给追风者 → 每日主闭环时追风者子账本自动接双刀信号；
  - AI 团队（17:10 影子产物 → poc_*.json）雇给稳如泰山 → 同理。
- **main 主交易台恒在**，是基准不参与雇佣；交易员市场上架全部档案：
  - `live` → 可雇佣；
  - `training` → 展示实习成绩（board 四账本），不可雇；
  - `design` → 灰显（如快枪手，T+1 论证未过）。
- 雇佣 ≠ 下单。**真正的落单只在每日 07:05 automation 单写入口**（settle→exec→check-stops→mark），门户雇佣动作只改一个 git 跟踪的注册表文件——可审计、可回滚、无即时资金风险。

## 1. 注册表 `k_stock/paper/hires.json`（三源纪律：存源，页面/CLI 只读渲染）

```json
{
  "_note": "雇佣关系注册表（K-STOCK-039 A3）。雇佣=策略源→交易员路由，落单仍只在 07:05 单写入口。",
  "hires": [
    {"trader": "chaser", "source": "qd", "status": "active",
     "hired_at": "2026-10-11T09:00:00", "note": "首单雇佣：双刀信号接趋势型交易员"}
  ]
}
```

- `source` 键：`qd`（双刀）/ `ai_team`（AI 值班）/ 预留 `qpzm`（青萍 adapter B1 落地后接入）。
- **一个 source 可雇多名交易员**（同信号多风格分流，正交组合本意）；**一个交易员可被多源雇佣**（engine ref 幂等键天然防重，多源同票也不冲突）。
- 双侧校验：只有 `status=live` 的交易员允许写入 `active` 雇佣（CLI 与 API 各自校验，不依赖单点）。
- 注册表损坏（JSON 坏/字段缺）→ 路由层 **fail-closed 到「无雇佣」**（当日不路由），绝不中断 07:05 主闭环。

## 2. CLI（trainee.py 扩展，~80 行）

```
python k_stock/paper/trainee.py hire chaser --source qd     # 校验 live → 写注册表
python k_stock/paper/trainee.py fire chaser --source qd     # status=ended（保留历史行）
python k_stock/paper/trainee.py hires                       # 雇佣关系列表
```

- `exec_for` 增 `--source` 路由参数：不传 = 现行为不变（AI 通道喂全部 training/live）；传 `--source qd` = 只喂 `hires.json` 里 active 且 source 匹配的交易员，run 取最新 `poc_qd_*.json`（ai_team 取最新非 qd 的 `poc_*.json`）。
- 单测 3 例：live 校验拒绝 / 注册表损坏 fail-closed / source 路由选取正确 run 文件。

## 3. 门户 API（portal_api.py，~60 行）

| 端点 | 方法 | 说明 |
|---|---|---|
| `/api/paper_hires` | GET | 投影：交易员 × 雇佣状态 × board 摘要（复用 board 计算） |
| `/api/paper_hire` | POST | `{trader, source, action: "hire"\|"fire"}`；**加入 `_MUTATION_POSTS`**（本机回环放行、局域网须 X-Portal-Token——与 paper_order/paper_stop 同全站口径，零新增鉴权机制） |

**安全设计（对应拍板 #3，建议老田按此点头）**：
1. 门户写路径 = 只改 `hires.json` 配置（MUTATION 鉴权同口径），**不提供任何即时下单端点**——「门户下单」的原始需求被「雇佣路由 + 次日 07:05 自动执行」覆盖，风险从交易面降为配置面；
2. 注册表入 git，每次雇佣/解雇可 diff 可回滚；
3. 每日落单证据链不变（ledger + ref 幂等 + equity_marks）。

## 4. 门户 UI（paper.html 交易员市场 tab，~80 行）

- 交易员卡按 status 分态：
  - `live` 未雇 → 「雇佣 ▾」（策略源下拉：量子双刀 / AI 值班 / 青萍(置灰待 B1)）→ confirm 二次确认 → POST → 刷新；
  - `live` 已雇 → 「已雇 · 量子双刀」徽标 + 「解雇」；
  - `training` → 「实习中」+ board 四账本数据（26c1312 已接）；
  - `design` → 灰显「论证中」。
- main 主交易台卡固定置顶，无雇佣按钮。
