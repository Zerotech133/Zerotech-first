## 4. 需修项 / 发现（未越界修）

### 4.1 【已最小修】HEAD 原返回 501

- 现状（修前）：`BaseHTTPRequestHandler` 无 `do_HEAD` → 501 `Unsupported method ('HEAD')`，浏览器/代理的 HEAD 探测会误判出口层不可用；
- 修复：`watch_admin_server.py` +6 行 `do_HEAD` 委派 `do_GET`（`_send()` 已对 HEAD 抑制 body；只读、不改业务语义/不增写路径）；测试 `test_server_head_no_body` 锁定。

### 4.2 【需后续单】snapshot 构建仍触发一次诊断日志写盘（严格“无写盘”未达标）

- 实测 stack：`_zone5_backtest` → `_read_backtest` → `portal/api_backtest_jobs.py::get_backtest` → `portal/api_common.py::log_exc` → `open(r"C:\Temp\portal_api_error.log", "a")`（last_backtest.json 缺失时 append 1 行错误日志）；
- 性质：非业务数据/非生产写，但违反出口层「严格只读」目标；`api_backtest_jobs.py`/`api_common.py` **不在本单写域**（本单仅 server/tests/docs），故基线测试显式记录该已知缺口（断言业务写盘=0、诊断日志写 ≤1），并在本文件登记；
- 建议后续单：读路径 `log_exc` 降级/注入只读 logger/`WATCH_ADMIN_READ_ONLY` 开关；修好后把 `test_real_snapshot_no_write_and_loopback_only` 收紧为 `violations == []`。

### 4.3 【外部阻塞，非本单改动】语法门被既有文件 BOM 阻断

- 全仓语法门本次 FAIL：`tools/finetune/build_cloud_bundle_v4.py` line 1 `invalid non-printable character U+FEFF`；
- 溯源：HEAD 与主仓磁盘首字节均 `EF BB BF`；该文件最后一次提交 `7334b6c64 2026-11-04 07:36 K-ORG-AUTODL-V4-20261104`（**另一会话今日 07:36 引入**），非本单改动（本单 `git status` 仅 server+test）；
- 本单文件单独跑语法门 **PASS**（命令见 §3）；合并前需该文件 owner 去 BOM（本单不越界修）。

### 4.4 其他观察（非缺陷）

- snapshot 的 HTTP 探测是 `WatchAdminAggregator._http_get_json` **类方法**（非模块级 seam）：基线用 `monkeypatch.setattr(WatchAdminAggregator, "_http_get_json", fake)` 免网络；后续可选把探测抽成可注入依赖（非必须）；
- 7 模块中 `watch_admin_route_ackdash` 仅 API_ROUTES、无 HTML_ROUTES（与其「纯数据面板」定位一致，测试按设计断言）；
- snapshot 缓存用 `time.monotonic()` + 15s 窗口、`replay_at` 强制绕过缓存（测试已锁）。
