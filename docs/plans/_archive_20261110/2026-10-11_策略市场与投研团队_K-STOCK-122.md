## 三、总体架构

```
策略市场页（独立页 /market-strategy）
  ├─ 12 策略卡（strategies.json 全量，含方法论标签：尾盘买入/缠论+量能…）
  ├─ 下钻一层 → 单策略详情（tagline 展开 + metrics 记分卡 + 最新信号/胜率摘要）
  └─ 订阅（免费，price 字段预留商业化）
        ↓ 订阅集 = 组合（portfolio）
        ├─ 分支①：聘交易员 → hire(portfolio 维度) → trainee 自动模拟跟单
        └─ 分支②：手动模拟买卖 → paper 账本手动下单
        ↓（两分支均接入）
投研团队每日复盘会（三 Agent 博弈）
  ├─ 分析师 Agent = strategist 升级：对组合内策略给建议（选/换/加权）
  ├─ 操盘手 Agent = trainee/盯盘体系：对持仓给盯盘输入（异动/风控）
  └─ 投研经理 Agent = judge 升级：汇总双输入 → 主持复盘会 → 会议纪要 JSON 沉淀
```

## 四、分期开发

### M1 策略市场独立页（1 天量）
- 路由 `/market-strategy`（nginx + portal_api 静态挂载），新页 `portal/market_strategy.html`。
- 数据源：strategies.json 直读，新增 API `GET /api/strategy_market`（返回 12 策略 + 每策略订阅数 + 关联详情链接）。
- 卡片：名称/tagline/badge/status 徽标/方法论标签（从 tagline 与 metrics 提取关键词：尾盘买入、缠论+量能、RPS 强势池、共振、微动前置等）。
- 导航：paper.html 侧栏 + home.html 入口挂「策略市场」。

### M2 下钻一层详情（1 天量）
- 单策略详情面板（页内下钻或 `?id=xxx` 锚点）：strategies.json 该条全量 + 动态战绩：
  - 最新信号：pick_details / 各策略产物 JSON 按 id 映射（chanlun→缠论扫描产物、double_knife→qd_scanner 产物…）；
  - 胜率摘要：pick_verdicts 按策略聚合（命中率/样本数/近 5 日）；
  - status_note 风险提示（shadow 态必须显著标注"研究态·不构成选股依据"）。
- API：`GET /api/strategy_detail?id=xxx`（static 字段 + 动态战绩合并）。

### M3 订阅与组合（1~2 天量）
- 订阅表：`k_stock/paper/subscriptions.json`（无账号体系期单用户：`{"portfolios":[{"id":"pf_001","name":"我的组合","strategies":["double_knife","chanlun"],"created_at":...,"price":0,"paid":false}]}`）。**price 字段现在就埋**，商业化时只改值+加支付。
- API：`POST /api/portfolio_subscribe`（勾选策略生成/更新组合）、`GET /api/portfolios`。
- UI：策略卡「订阅」按钮 → 已订阅集合区「我的组合」（免费徽标：`免费体验 · 未来商业化收费`）。

### M4 组合双分支（1~2 天量）
- **聘交易员分支**：hire 扩展 portfolio 维度——`hires.json` 条目加 `portfolio:"pf_001"`；交易员档案绑定组合后按组合内策略信号自动模拟跟单（exec_for 信号源从单策略改为组合策略集并集，tier_gate 纪律参数照常生效）。
- **手动模拟分支**：组合详情页给出「手动下单」入口，跳 paper.html 已有手动下单链路，账本标记来源=组合。
- UI：组合卡两个按钮「聘交易员自动跟」（跳交易员市场，带 portfolio 参数）/「手动模拟买卖」（跳 paper 下单）。

### M5 投研团队三 Agent 每日复盘会（2~3 天量，K-STOCK-100 M4 前置）
- **分析师 Agent**（strategist 升级）：输入=组合内策略近期信号与战绩 → 输出策略级建议（继续/降权/替换），落 `reports/analyst_latest.json`。
- **操盘手 Agent**（trainee 盯盘升级）：输入=组合持仓实时异动 + tier_gate 触发记录 → 输出盯盘纪要（减仓/持有/风控动作建议），落 `reports/trader_latest.json`。
- **投研经理 Agent**（judge.py 升级）：每日复盘会（settle 后 routine 尾，复用 judge 调度点）：
  1. 读 analyst_latest + trader_latest + 当日成交/评审；
  2. LLM 主持（复用 8098 网关 + Ollama，account=judge 计量）；若双输入分歧（如分析师要加仓、操盘手要减仓）→ 记录**博弈分歧点**及经理裁决与理由；
  3. 产出会议纪要 `reports/review_minutes/YYYY-MM-DD.json`：`{date, attendees:[analyst,trader,manager], inputs:{analyst,trader}, disagreements:[], resolutions:[], action_items:[]}`；
  4. action_items 回流：降权策略→订阅提醒、风控动作→tier_gate 参数微调建议（人工确认后生效，不自动改参数）。
- 沉淀：会议纪要 JSON 全量留存 = **蒸馏语料核心增量**（K-STOCK-100 M4 语料来源），页面上 paper.html 侧栏加「今日复盘会」块（纪要摘要+分歧点+决议）。
- **飞书推送到手机（老田 10-11 追加，M5 固定收口步骤）**：
  - 复盘纪要落盘后立即推送，复用 `portal/feishu_card_v2.send_card` 通道（push_picks_digest 同款，默认个人 open_id 免 Tailscale 直达手机，可选抄送群）；
  - 新脚本 `k_stock/paper/push_review_minutes.py`：读当日 `reports/review_minutes/YYYY-MM-DD.json` → 组装飞书折叠卡：
    - 首屏：日期 + 三方出席徽标 + 经理一句话总评（LLM 生成）；
    - 折叠层①：分析师建议（策略级：继续/降权/替换）；
    - 折叠层②：操盘手盯盘纪要（减仓/持有/风控动作）；
    - 折叠层③：**博弈分歧点与决议**（分析师 vs 操盘手冲突条目 + 经理裁决理由）——这是最有复盘价值的部分，单独成层；
    - 尾部：action_items 清单 + 「详见 /market-strategy 组合页」链接。
  - 调度：挂在复盘会 routine 尾（纪要写盘成功后才推），推送失败仅记日志**不阻塞**复盘会主流程；
  - 卡片风格对齐 push_picks_digest（markdown 折叠卡，手机速览版）。

## 六、风险与边界

1. **shadow 态合规**：未验证策略订阅页必须带 status_note 原文（研究态不构成选股依据），沿用交易员市场合规脚注风格。
2. **组合跟单信号源**：M4 中 trainee 跟单从单策略扩展为组合并集，需防同一标的重复信号（并集去重规则：同标的多策略信号取优先级最高者，规则写入 exec_for）。
3. **复盘会成本**：三 Agent 每日一次 LLM 调用，走 8098 网关计量（llm_cost account 分别 analyst/trader/manager），日成本可控（Ollama 兜底）。
4. **商业化预留**：subscriptions.price/paid 现在埋字段，未来接支付不改表结构。

### M6 周报 / 月报（0.5~1 天量，老田 10-11 追加）
- **周期总结生成**（复用复盘会数据面，无需再开 LLM 大会）：
  - 脚本 `k_stock/paper/period_summary.py`：`--weekly` / `--monthly` 两种模式；
  - 数据源：周期内 equity_marks（净值曲线/回撤）、成交账本（笔数/胜率/盈亏比）、judge_reviews（评审等级分布）、review_minutes（分歧点统计+决议执行率）、tier_gate 触发记录（纪律执行情况）；
  - 输出 `reports/summary/weekly-YYYY-Www.json` / `monthly-YYYY-MM.json`，结构固定四段：
    1. **成绩**：净值变化、胜率、最佳/最差持仓；
    2. **存在的问题**：评审低分归因、tier_gate 拦截分布、纪律违规点；
    3. **下步大致工作方向**：由投研经理（judge LLM）基于问题段生成 3~5 条；
    4. **待裁决事项**：需老田拍板的项（如策略转正、参数调整）。
- **飞书推送**：复用 send_card，折叠卡四层对应四段（问题与下步方向单独成层）；周报每周日 20:00 推、月报每月末最后一日 20:00 推（挂计划任务，同 review_minutes 推送配方）。

### M7 手机端止盈止损指令回路（1~2 天量，老田 10-11 追加）
- **底座已具备**：`portal/feishu_bot_ws.py` 已有文本指令通道 `handle_cmd` + 卡片按钮回调 `on_card`（card.action.trigger）+ 看门狗驻进程（FeishuBotWatchdog 每 5 分钟拉起）——手机→服务的双向回路零新增基建，只扩指令集。
- **指令集**（P2P 给机器人或群里 @）：
  - `止盈 605100 8%` / `止损 605100 -5%` → 对指定持仓设置止盈/止损线；
  - `止盈单` / `止损单`（无参数）→ 回发当前全部持仓的止盈止损线卡片，每只股票带「修改」按钮（on_card 回调回填指令模板）；
  - `撤线 605100` → 撤销该持仓止盈止损线。
- **执行链**：handle_cmd 新增分支 → 解析指令 → 写 `k_stock/paper/exit_rules.json`（`{account, code, kind:tp/sl, trigger_pct, set_at, source:feishu}`）→ settle/tick 例行检查时由 trainee 盯盘层消费：触线即按模拟撮合出单并回推飞书确认卡（「已触发止损 605100 · 成交价 xx」）；
- **安全边界**：
  - 指令回卡确认（设置成功/失败均回飞书，含当前持仓与线位快照）；
  - 白名单：仅老田 open_id 可下指令（复用机器人现有鉴权）；
  - 模拟仓语义：exit_rules 只影响 paper 账本撮合，不动实弹；
  - 与 tier_gate 关系：exit_rules 是**持仓级**主动线，tier_gate 是**账本级**纪律熔断，两层独立、exit_rules 触发不豁免 tier_gate。
