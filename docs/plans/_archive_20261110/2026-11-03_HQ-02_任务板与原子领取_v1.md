# HQ-02 解决方案：`/hq/tasks` 任务板 + 原子领取（checkout）v1

- 日期：2026-11-02｜状态：数据层/契约已落地，API/UI 待 W3 接
- 依赖：ADR-021（原方案为主线）、HQ-01 组织/角色模型
- 目标：解决“多 Agent 抢同一单/重复执行/任务状态不可见”，不引入第二控制面

## 一、问题

现有 `.worktrees/tasks.json` 2047 单（done=1902、aborted=135、parked=8、doing=1、review=1），但：
1. 无原子领取：两个 Agent 可同时把同一单改 doing；
2. 无 lease/owner 冲突规则；
3. `/hq` 无任务板只读视图；
4. 任务状态与 devtask/merge 的关系未统一。

## 二、数据模型（tasks.json 增量字段，向后兼容）

```json
{
  "<task_id>": {
    "status": "parked|doing|review|done|aborted",
    "owner": "D1",
    "revision": 3,
    "claimed_at": "2026-11-02 23:40:00",
    "lease_until": "2026-11-03 01:40:00",
    "desc": "...",
    "branch": "task/...",
    "worktree": ".worktrees/..."
  }
}
```

新增字段均为可选；旧单无 `revision/lease` 视为 0/无租约。

## 三、状态机

```
parked/ready/todo ──claim──> doing ──submit──> review ──complete──> done
        ^                        │                 │
        └──────release───────────┘                 └──reject──> doing
doing/review ──abort(L2)──> aborted（终态）
done/aborted：不可 claim；重开走 L2 + 新 revision
```

规则：
- **单任务单 owner**；`doing/review` 只有 owner 可续租/提交/释放；
- **lease 过期**不自动改状态，但允许新 owner 在“确认无执行”后接管（需 event + 审批）；
- **force release** 仅部门 lead/ARCH1，记事件；
- 所有变更 `revision += 1`，用于 CAS/乐观锁。

## 四、API 契约（W3 接 8091 或独立 HQ 服务）

| 方法 | 路径 | 语义 | 失败码 |
|---|---|---|---|
| GET | `/hq/tasks?status=&owner=&stale=` | 任务列表/筛选 | 400 |
| GET | `/hq/tasks/board` | doing/review/parked 分栏 | — |
| POST | `/hq/tasks/{id}/claim` | body `{owner, lease_minutes}`；CAS 领取 | 404/409 busy/410 terminal/423 owned |
| POST | `/hq/tasks/{id}/renew` | 续租（仅 owner） | 403/409 |
| POST | `/hq/tasks/{id}/submit` | doing→review（仅 owner） | 403/409 |
| POST | `/hq/tasks/{id}/release` | doing/review→parked（owner/lead） | 403/409 |
| POST | `/hq/tasks/{id}/complete` | review→done（merge 门后） | 403/409 |

响应统一：`{ok, code, task, revision}`；冲突返回 409 + 当前 owner/status，不静默覆盖。

## 五、原子性实现（生产落盘必须如此）

1. **唯一写入者**：只有 HQ 服务写 tasks.json；Agent 不直接改；
2. **文件锁**：Windows `msvcrt.locking` 或 `portalocker` 排他锁，锁文件 `task_hq.lock`；
3. **read-modify-write**：锁内读最新 → 校验 status/owner/revision → 写临时文件 → `os.replace`；
4. **CAS**：请求带 `revision`（可选）；不匹配返回 409，防丢更新；
5. **审计**：每次 claim/release/submit/complete 写 `dev_events`（task_claim/task_release/task_submit/task_complete）；
6. **迁移**：W3 先 JSON+锁；W4 可迁 PG，`task_hq` 表带 `UNIQUE(task_id)` + `revision`。

当前已实现 **纯函数契约**（`tools/hq_task_contract.py`）：
- `claim`/`release`/`submit_review`/`is_lease_active`；
- 不写文件、不修改入参；测试覆盖 claim/冲突/终态/续租/释放；
- CLI `--id/--owner` 只做演练，返回决策不落盘。

## 六、UI（`/hq/tasks` 页面）

- 三栏：doing / review / parked；卡片显示 owner/age/lease/stale；
- 顶部：WIP、stale、无 owner、无 branch/worktree；
- 操作：领取/续租/提交/释放（按权限显隐）；冲突 toast 显示当前 owner；
- 统一 nav/manifest（HQ-06），不新开第二入口。

## 七、验收（DOD）

1. 并发领取同一单：**1 成功、1 409**（2 线程/2 进程测试）；
2. 同一 owner 重复 claim = 续租，不重复执行；
3. 终态不可领取；release 后可再领；
4. 所有变更 revision+1，事件可查；
5. `/hq/tasks` 与 tasks.json 状态一致，无写绕过；
6. 不新增端口/第二入口；原 devtask/merge 流程不破坏。
