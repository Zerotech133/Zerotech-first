## 二、工位任务

### P-A（WO-FS-141）：dispatch 接入买点/退订真 handler + 治空转伪装成功

1. `portal/card_actions.py` dispatch 内新增分支：
   - `subscribe_buypoint` → 归一 act 原样，调
     `subscribe_from_card(value, operator=who)`；
   - `unsubscribe_buypoint` → **先把 value["act"] 归一为 "unsubscribe"**
     再调（防误订阅，这是本单最重要的口径差）；
   - sys.path 注入与 api_misc 同款（幂等，已在则不重复插）；
   - import 失败/执行异常 → `(False, 明确错误)`，**closed on failure，
     绝不返回 True**；返回值取 `(ok, msg)`，card 丢弃并留注释说明
     （WS 链暂无更新卡通道，回执由 subscribe_from_card 内部确认卡承担）。
2. 治 :311-313 空转：迁移完的两个动作从「老链」分支移出后，该分支
   **保留给其余仍走老链的动作**（先盘点注册表里还有哪些 handler 标
   「老链/HTTP」，逐一确认无人依赖后才能动；本波只允许把「返回 True」
   改为「返回 False + 明确文案『老链动作未迁移，HTTP 链可达时由 8091
   处理』」——**伪装成功是 fail-open 缺陷，必须治**；若盘点发现某动作
   确有 HTTP 老链在役且 bot 侧永远不会收到它，则在注册表 handler 字段
   加注释记账，不改返回值）。
3. 测试：新建 `portal/test_card_actions_dispatch.py`，至少 10 例：
   - subscribe_buypoint 正确转发 value 与 operator（monkeypatch
     subscribe_action.subscribe_from_card 捕获入参，**不真发不真写**）
   - unsubscribe_buypoint 的 act 被归一为 "unsubscribe"（防误订阅，重点例）
   - ok/msg 透传；第三返回值 card 不外泄
   - subscribe_action import 失败 → (False, …)，不 True
   - handler 抛异常 → (False, …)，不 True
   - sys.path 注入幂等（重复 dispatch 不产生重复路径项）
   - 空转分支不再对 subscribe_buypoint/unsubscribe_buypoint 触达
   - 静态断言：dispatch 对未迁移老链动作不再返回 True 伪装成功
     （或按盘点结论固定实际行为）
   - 审计：log_event 被调用且 result 非空
   - 既有注册表语义不破坏（ACTIONS 键集不变）
   注意：本仓无 card_actions 既有 pytest 测试文件（git ls-files 仅
   模块本体），你需要自建夹具；subscribe_action 是量化侧模块，测试里
