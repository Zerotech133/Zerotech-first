# portal 大文件拆分守则 v1（2026-10-28 · 关羽）
> STATUS: frozen（只读保留）



> 背景：全代码审计发现 portal 巨型文件——`api_backtest.py` **6,135 行**、`api_kg.py` **5,841**、`api_misc.py` 2,710、`api_chanlun_pages.py` 2,328、`api_portfolio.py` 2,322；`portal_api.py` 已 4,596/5,200（88% 预算）。
> 目标：**先冻结、后拆分、禁止继续变大**；拆分为独立工单，不在本守则内动业务代码。

## 一、硬性规则（对"新增/修改"生效）

1. **新 handler 一律落新文件**：`portal/api_<domain>.py`（或 `portal/<domain>/api.py`），**禁止**在 `portal_api.py` 追加 handler；
2. **单文件规模**：
   - 新建 `portal/*.py`：**≤1,200 行**；超过则拆分；
   - 冻结名单（存量巨型文件）**只减不增**：`api_backtest.py`、`api_kg.py`、`api_misc.py`、`api_chanlun_pages.py`、`api_portfolio.py`；
   - `portal_api.py` 维持既有预算 **≤5,200 行**（评审门已检查），只改不扩；
3. **路由注册集中化**：`portal_api.py` 只允许"import + register route"，不允许业务逻辑（存量例外冻结）；
4. **拆分优先级**（按行数/风险）：
   - P1：`api_backtest.py`（回测编排）、`api_kg.py`（图谱查询）→ 按领域拆 `api_backtest_{design,exec,report}.py` 等；
   - P2：`api_misc.py`、`api_chanlun_pages.py`、`api_portfolio.py`；
5. **拆分工单要求**：先冻结现状（增快照/契约测试）→ 纯移动（不改行为）→ 独立评审 → 一次一个文件；回滚=单 commit revert。

## 二、守卫脚本（本单已落）

`tools/check_portal_split.py`：
- 检查 `portal_api.py` ≤ 5,200；
- 检查 `portal/api_*.py` 非冻结文件 ≤1,200 行；
- 冻结名单内文件只提示"不得增长"（记录当前基线）；
- 退出码 1 = 违规（供 test_gate/CI 使用）。

用法：`python tools/check_portal_split.py`

## 三、纳入流程

- 建议加入 `tools/test_gate.ps1 -Suite portal`（或 merge 前手动跑）；
- 新增文件首行注释注明所属领域与拆分来源（例：`# split from api_backtest.py (2026-10-28)`）。

## 四、验收口径

- 新 PR/工单：无新增 handler 进 `portal_api.py`；新文件 ≤1,200 行；
- 拆分单：行为零变化（对照契约测试）+ 文件行数下降；
- 每季度复盘冻结名单（只允许缩短，不允许加长）。
