## 一、结论先行

### 1. 最高优先级不是多 Agent，而是交易可信底座

未来量化产品的第一目标不是“让更多 Agent 参与交易”，而是做到：

> **每一次入池、买入、持有、加仓、减仓、换仓、卖出，都有完整、不可覆盖、可回放的证据链，并且任何越权交易都能被阻断。**

因此优先级顺序为：

```text
P0 证据、状态、权限、风险和模拟账本
    ↓
P1 股票池、滚动回测、盯盘、投研授权和动态组合
    ↓
P2 多 N Agent 动态路由、报告、蒸馏和规模化运营
    ↓
P3 真实交易适配与更高级自动化
```

### 2. 第一阶段只做一个可闭环的最小纵切

不建议先把所有旧策略、所有情报源和所有交易风格一次性接入。建议选择：

- 2 个已有策略
- 1 个情报源
- 1 个统一数据源
- 1 个模拟账户
- 1 个交易风格
- 1 个完整标的生命周期

先打通：

```text
入池 → 回测卡 → 盯盘触发 → 投研授权 → 模拟买入
→ 持有 → 模拟卖出 → 反事实 → 复盘 → 日报
```

### 3. 真实资金交易不在当前路线图内

在证据完整、风险阻断、模拟市场连续运行和回放能力没有通过前，范围只包括研究、回测、纸面和模拟交易。

## 二、评估方法与约束

### 2.1 使用的框架

本次采用：

1. **MoSCoW**：确定发布门槛，区分必须有、应该有、可以有和本阶段不做。
2. **加权评分**：适合当前内部平台阶段，避免虚构用户数量。评分维度如下：
   - 业务/交易价值：35%
   - 风险与可信度贡献：30%
   - 战略对齐：20%
   - 近期可行性：15%
3. **依赖门控**：只要某项是下游能力的硬前置，即使表面 RICE/价值不最高，也必须前置。
4. **RICE 校准预留**：待 M0 获取真实运行量、策略数、交易事件量和维护成本后，再补充 Reach、Impact、Confidence、Effort 的数值版。

### 2.2 评分口径

每个维度 1—5 分：

- 1：低
- 3：中
- 5：高

加权总分：

```text
价值评分 = 业务价值×35% + 风险贡献×30% + 战略对齐×20% + 可行性×15%
```

注意：**分数不是唯一排序依据**。P0 安全、审计、状态和风险门槛具有强制优先级；高分但依赖未满足的功能不得提前开发。

## 三、功能分层总表

| 优先级 | 发布含义 | 功能范围 | 进入条件 |
|---|---|---|---|
| P0 / Must | 缺失即不能进入动态模拟交易 | 事件账本、trace、领域契约、状态机、授权、风控阻断、虚拟账户、订单成交、数据可见性、回放 | 必须先完成 |
| P1 / Should | 形成可用的智能交易闭环 | 股票池、滚动回测、盯盘、情报接入、投研机构、动态组合、交易 Agent 路由、反事实、报告 | P0 通过后分批做 |
| P2 / Could | 提升规模化和学习效率 | 多市场、多账户、复杂路由、成本优化、小模型蒸馏、自动策略组合优化、运营大屏 | P1 稳定后做 |
| P3 / Won't now | 当前范围外 | 直接真实下单、完全无人值守、未经影子验证的小模型替换 | 暂不做 |

MoSCoW 的“Must”严格控制在核心发布范围内，避免把所有想法都标成必须。

## 五、依赖关系与关键路径

```text
领域契约 / Schema
    ↓
事件账本 + trace + 状态机 + 幂等
    ↓
授权单 + 风控阻断 + 虚拟账户/订单账本
    ↓
股票池 + 入池证据 + 滚动回测
    ↓
数据/情报接入 + 盯盘触发
    ↓
虚拟投研 + 交易授权
    ↓
动态组合 + 单一风格模拟执行
    ↓
反事实 + 日报
    ↓
多 N Agent 路由 + 周报/月报
    ↓
蒸馏样本 + 小模型影子路由
    ↓
生产级真实交易适配
```

### 关键路径上的不可跳过门槛

1. 没有 Schema，不接入新 Agent。
2. 没有 trace 和事件账本，不开放组合动态买卖。
3. 没有授权单和风控阻断，不进入交易队列。
4. 没有统一成交口径，不比较回测与模拟收益。
5. 没有卖出证据和反事实，不评估策略优劣。
6. 没有影子评测，不让小模型接管。
7. 没有模拟市场连续运行，不考虑真实资金接口。

## 六、路线图

> 本路线图以阶段门槛为主，不绑定虚假的日历承诺。M0 结束后再根据实际团队容量和测试结果换算为迭代周期。

### 阶段 0：基线与切片（M0）

**目标：** 把历史资产映射到新架构，选出最小闭环。

**范围：**

- 盘点 `strategy_layer`、`execution_engine.py`、`datamart.py`、AI Operator、Gatekeeper、研究院工具
- 确认 2 个试点策略
- 确认 1 个情报源和 1 个数据源
- 冻结领域对象和事件 schema
- 确认只读、模拟和未纳入范围的边界

**出口标准：**

- 完成旧模块→新域映射表
- 试点范围不超过一个纵切
- 所有直接交易入口完成定位
- 没有凭据、缓存和运行态被纳入源码计划

### 阶段 1：可信底座（M1）

**目标：** 任意一笔模拟交易都能被完整回放。

**优先交付：** P0-01 至 P0-09。

**出口标准：**

- 事件 append-only
- trace_id 贯穿
- 交易状态机可恢复
- 重复任务/重复订单幂等
- 授权外交易全部阻断
- 单笔入池→成交→持仓→卖出→复盘可回放

### 阶段 2：选股与滚动回测（M2）

**目标：** 选股不再只输出名单，而是输出带证据和动态回测的候选对象。

**优先交付：** P1-01、P1-02、P1-03、P1-04。

**出口标准：**

- 每个入池标的有来源、理由、版本和证据
- 1—30 日按日回测可更新
- 1—12 月按月回测可更新
- 策略每日研究报告可查询
- 新假设不直接覆盖正式策略

### 阶段 3：盯盘与投研授权（M3/M4）

**目标：** 从候选池进入“实时触发—多维核实—正式授权”。

**优先交付：** P1-05、P1-06、P1-07。

**出口标准：**

- 每个异动绑定数据快照和来源
- 盯盘事件可同时进入投研和交易队列
- 投研报告保留看多/看空分歧
- 授权单明确方向、仓位、期限、入场、退出和失效条件
- 证据不足或数据冲突时暂停授权

### 阶段 4：动态组合与单风格模拟（M5/M6）

**目标：** 先用单一交易风格验证动态组合，再扩展多 N Agent。

**优先交付：** P0-06、P1-08、P1-09、P1-10、P1-11。

**出口标准：**

- 虚拟资金、现金、持仓、订单和成交一致
- 支持加仓、减仓、换仓、止盈、止损和再平衡
- 每次动作有触发原因和授权引用
- 卖出事件有反事实评估
- 模拟市场可连续运行一个完整交易周期
- 可从事件账本重算日报

### 阶段 5：多 N Agent 交易中台（M7）

**目标：** 根据实时数据、市场状态、风险偏好和持仓周期动态路由。

**优先交付：** P2-01、P2-02、P2-03。

**出口标准：**

- 路由理由可解释
- 同一授权可在不同风格/周期下进行可比模拟
- Agent 冲突不会静默覆盖
- 交易 Hermes 可处理超时、重试、降级和人工升级
- 组合级资金冲突有明确仲裁规则

### 阶段 6：报告与学习闭环（M8）

**目标：** 把运行变成策略和 Agent 的持续进化机制。

**优先交付：** P2-04、P2-05、P2-06。

**出口标准：**

- 日报、周报、月报均可由账本重算
- 策略、Agent、路由和执行质量可分别评价
- 蒸馏样本可回指原始证据
- 小模型只以影子方式运行
- 小模型异常可一键回退到教师/规则路径

### 阶段 7：生产化增强（后续）

**范围：** P2-07 至 P2-10，之后才评估 P3。

**前置条件：**

- P0 全部通过
- 动态模拟市场连续稳定
- 证据完整率和可回放率达到 100% 目标
- 授权外交易为 0
- 风控绕过为 0
- 关键异常可恢复
- 小模型影子对照稳定

## 七、首个 MVP 的严格范围

### MVP 目标

证明一条完整、可信、可回放的最小业务闭环，而不是展示所有能力。

### MVP 包含

- 2 个现有策略 Agent
- 1 个股票池
- 1 个情报源
- 1 个统一数据源
- 1 个虚拟账户
- 1 个交易组合
- 1 个交易风格 Agent
- 1 个投研授权流程
- 1—30 日滚动回测
- 基础动态持仓和卖出逻辑
- 完整 trace 和证据卡
- 日报

### MVP 不包含

- 真实资金下单
- 多账户
- 复杂多 Agent 竞合
- 全部市场和全部数据源
- 自动策略升级
- 小模型接管
- 复杂 UI 大屏

### MVP 验收场景

至少完成以下场景并可回放：

1. 标的进入股票池并记录入池证据。
2. 盯盘发现异动并触发投研复核。
3. 投研形成授权并通过风控。
4. 模拟买入并产生持仓事件。
5. 正常回撤下继续持有。
6. 触发止盈、止损或失效条件并卖出。
7. 卖出后生成反事实结果。
8. 日报从事件账本重新计算。
9. 模拟重复任务不产生重复订单。
10. 缺失关键证据时交易被阻断。

## 十、路线图治理机制

1. 每周重新检查一次依赖、风险和实际产出，不按旧计划机械推进。
2. 每个阶段必须有出口门槛，未通过时只修复当前阶段，不提前扩展 Agent 数量。
3. 每个新功能同时登记：业务价值、风险贡献、数据依赖、证据要求、回滚方式和维护成本。
4. 技术债和工程治理预留 10%—20% 的研发容量，尤其是存量收编、测试、日志、备份和可恢复性。
5. 研究型功能采用“发现→实验→影子→对照→审批→升级”，禁止从研究直接进入正式执行。
6. 任何涉及真实资金的功能必须重新评审，不因模拟结果良好自动放行。
7. 每季度或每个大阶段结束后重新进行 MoSCoW 和评分复审。

## 十二、复盘优化版（v1.1，2026-10-18）

本节是对 v1.0 的二次复盘结论。原则不是推翻原路线，而是把若干“写在原则里、尚未形成独立门禁”的内容，提升为可执行的架构层、阶段门和验收项。

### 12.1 复盘结论：当前方案的七个结构性缺口

| 编号 | 缺口 | 影响 | 优化决定 |
|---|---|---|---|
| R1 | 组合决策、订单执行、成交结算仍有混合倾向 | Agent 可能把“应该买”直接变成“怎么下单” | 拆成 Decision、Portfolio、Execution、Settlement 四层；任何层都不能跨层越权 |
| R2 | 市场状态/Regime 只是未来高级能力 | 同一策略在趋势、震荡、极端风险环境下被错误比较 | 前置为 P0.5：先做最小状态标签和状态快照，不先做复杂预测 |
| R3 | P0 没有把数据质量、时钟、版本联锁写成独立门禁 | 证据存在但可能是过期、穿越或不可复现的数据 | 增加 Data Quality Gate、Clock Gate、Reproducibility Lock |
| R4 | “回测、模拟、影子、回放”边界不够硬 | 训练/评估数据泄漏，模拟结果被误当实盘能力 | 明确四种运行模式、独立命名空间和禁止跨模式写入规则 |
| R5 | Hermes 权限描述偏组织化，缺少运行时权限 | 主管可能成为隐含的万能决策者 | Hermes 只编排、授权在契约中生效；加入 kill switch、升级、租约和人工接管 |
| R6 | 100% 指标较多，但缺少“不可适用/延迟/降级”语义 | 数据缺失时为了达标而伪造完整性 | 指标拆成完整性、及时性、可用性、可解释性四类；允许明确 BLOCKED/DEGRADED |
| R7 | M 编号与 agent_platform、数字军团路线存在撞车 | 工单和验收可能引用错误阶段 | 以后使用 QT-M0…QT-M8；外部平台使用 AP-M，数字军团只作为适配来源，不另立账本 |

### 12.2 优化后的目标架构

```text
数据与情报控制面
  → 数据质量/时钟/来源门禁
  → 市场状态层（Regime Snapshot）
  → 策略研究层（候选与观点）
  → 盯盘观察层（事实变化与触发）
  → 投研层（事实核实、分歧、授权建议）
  → 组合决策层（资金、暴露、相关性、再平衡）
  → 风险政策层（硬否决、人工升级、熔断）
  → 订单执行层（拆单、撮合、滑点、成交）
  → 结算与复盘层（现金、持仓、归因、反事实）
  → 策略/Agent 评价与蒸馏
```

Hermes 主管位于编排面，不位于账本、风控或成交事实的写入面。四个 Hermes 均必须通过统一的 Proposal/Authorization/Intent 接口工作，不能直接 import 或调用账户、库存、撮合和结算内核。

### 12.3 优先级调整

#### 新增 P0.5：不可跳过的运行可信门

P0.5 不追求复杂能力，只保证 P1 的结果可比较、可复现：

1. **数据质量门**：来源、发布时间、采集时间、缺失率、延迟、冲突和可用性分级。
2. **时钟门**：事件时间、可见时间、执行时间、结算时间分离；禁止使用未来可见字段。
3. **版本联锁**：策略、提示词、模型、数据快照、规则配置、费用/撮合配置共同形成 `decision_bundle_id`。
4. **运行模式隔离**：`BACKTEST`、`REPLAY`、`SHADOW`、`SIM_MARKET` 使用独立 root、账本和权限。
5. **恢复门**：任务重启、重复投递、部分成交、账本损坏和断点恢复均有演练记录。

#### P1 拆分为四条链，而不是一条“动态交易”功能

- **P1-A 研究链**：股票池、滚动回测、入池证据、策略研究报告。
- **P1-B 观察链**：情报快照、盯盘异动、触发升级、数据冲突暂停。
- **P1-C 决策链**：投研授权、组合预算、Regime 约束、组合冲突仲裁。
- **P1-D 执行链**：订单意图、模拟撮合、部分成交、结算、日报重算。

其中 P1-C 必须先于 P1-D；不能先实现“能下模拟单”，再补组合级预算和冲突仲裁。

#### 原有功能的重新归位

| 原功能 | 原归类 | 复盘后归类 | 调整理由 |
|---|---|---|---|
| 股票池与入池证据 | P1 | P1-A | 仍是研究链起点 |
| 1—30 日/1—12 月回测 | P1 | P1-A + P0.5 | 必须绑定时间可见性和版本联锁 |
| 情报/盯盘 | P1 | P1-B + P0.5 | 数据质量和冲突处理是前置 |
| 动态组合管理 | P1 | P1-C | 属于决策，不属于执行 |
| 单一风格模拟执行 | P1 | P1-D | 只能消费授权和组合动作 |
| 多 N Agent 路由 | P2 | P2，但路由框架接口在 P1-C 预留 | 先固定一个交易策略，不提前制造竞合复杂度 |
| 高级 Regime 识别 | P2 | 最小标签 P0.5；高级预测 P2 | 先保证可解释，不提前做黑盒预测 |
| 运行健康与恢复 | P0 | P0 + P0.5 加强 | “能发现失败”不等于“能恢复失败” |

### 12.4 四种运行模式必须物理隔离

| 模式 | 输入 | 是否产生交易账本 | 允许用途 |
|---|---|---:|---|
| BACKTEST | 历史数据 | 独立回测账本 | 策略研究，不代表实时能力 |
| REPLAY | 已封存历史事件 | 只读重放/复核账本 | 回放和回归，不得补写原始事实 |
| SHADOW | 当时可见实时数据 | 影子决策账本 | 观察策略/Agent，不产生模拟成交 |
| SIM_MARKET | 实时或历史回放流 | 独立模拟账户账本 | 撮合、持仓、组合和执行验证 |

跨模式传递只能传递显式封存的输入快照，不能共享可变缓存、最新行情查询或最终标签。`SHADOW` 的建议可以进入 `SIM_MARKET`，但必须产生新的 `decision_bundle_id`，不能把影子结论伪装成模拟成交事实。

### 12.5 Hermes 主管的权限与升级契约

每个 Hermes 必须登记：`hermes_id`、可读域、可写事件类型、可发起的 proposal、可批准的 authorization、最大资源预算、超时策略、人工升级条件和 kill switch。统一规则如下：

- 策略 Hermes：可发布候选和研究报告，不得发布订单意图。
- 盯盘 Hermes：可发布事实变化和触发，不得修改授权方向。
- 投研 Hermes：可形成授权建议；超过仓位、风险或证据阈值必须人工确认。
- 交易 Hermes：可编排订单意图；不得提高授权上限，不得绕过风险否决。
- 风控/结算服务：拥有最终否决和事实落账权，不接受自然语言覆盖。

超时不等于同意；缺证据不等于低置信度放行；冲突未解决时默认 `BLOCKED`，而不是默认选择多数意见。

### 12.6 多策略扩展原则：新增策略就是新增一个 AI Agent

用户侧的核心扩展模型必须固定为：

```text
新增策略
  = 新增策略包
  + 新增 Strategy Agent
  + 新增注册表配置
  + 新增契约/回放/影子测试
  - 不修改公共交易主链
```

平台不能把策略名称写死在盯盘、投研、组合、风控或执行代码中。公共主链只识别标准化的候选提案、研究报告和策略信号；策略差异通过注册表、能力清单和版本化配置表达。

每个策略 Agent 必须独立拥有：

- `strategy_id` 与 `strategy_version`
- 策略家族、市场和周期能力声明
- 数据读取权限、资源预算和超时策略
- 输入/输出 Schema 与证据要求
- 独立运行目录、日志、缓存、指标和账本命名空间
- `DRAFT/EXPERIMENT/SHADOW/APPROVED/ACTIVE/RETIRED` 生命周期

新增策略的标准上线流水线：

```text
创建策略包
  → 注册 Strategy Agent
  → Schema/权限/资源校验
  → 历史回放
  → 影子运行
  → 与现有策略做增量价值和冲突评估
  → 人工审批
  → 灰度激活
  → 可回滚退役
```

策略 Agent 只能提出候选和研究结论，不能直接写最终股票池、投研授权、组合状态或订单。这样未来增加 10 个、50 个策略时，增加的是 Agent 数量和注册配置，而不是复制 10 套业务流程。

### 12.7 MVP 再收缩：一个主策略 + 一个挑战策略

原 MVP 的“两策略 Agent”保留，但明确角色：

- 1 个主策略：负责形成正式候选链。
- 1 个挑战策略：只做对照和影子建议，不能直接触发交易授权。

首个闭环只允许一个市场、一个组合、一个模拟账户、一个交易风格、一个 Regime 标签集。验收重点从“功能很多”改为“同一事件在四种模式下可解释、可复现、可回放”。

### 12.8 新增发布门槛

在原 P0/P1 门槛基础上，新增：

| 指标 | 目标 |
|---|---:|
| `decision_bundle_id` 覆盖率 | 100% |
| 未来数据穿越样本 | 0 |
| 模式越权写入 | 0 |
| 数据质量门误放 | 0 |
| 重启恢复后现金/持仓账本差异 | 0 |
| 关键配置无版本号 | 0 |
| 冲突证据未升级却进入授权 | 0 |
| Hermes 越权调用账户/撮合内核 | 0 |

收益、胜率和 Agent 一致性不作为早期硬放行门槛；必须同时报告样本量、市场状态、费用口径、置信区间和数据缺失情况，避免把小样本偶然收益误判为能力。
