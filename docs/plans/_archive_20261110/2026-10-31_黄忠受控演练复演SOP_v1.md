## 一、演练目的（为什么需要复演）

1. **证明拒收路径可用**：黄忠验收工具能对真实证据产出 REJECT/OBSERVE 判定，而非「只会 PASS」。
2. **证明证据可复核**：构造手段有真实来源（历史红队报告 / 历史基线 / 缺失证据），verdict 与
   reason 与证据一致，任何人可用命令复跑。
3. **证明复位可验证**：演练不改代码、不改证据文件、不 merge，正式验收历史不受污染
   （正式 PASS 样本 / 覆盖率 KPI / 日更台账不因演练变化）。
4. **11-04 复证**：复核会需能一键重演并核对台账，避免「只有 10-30 一次性人工记录」。

> 红线：**禁止造数据**（禁手写/篡改 baseline 的 passed/failed/error，禁伪造红队 pass_rate）。
> 本工具只「绑定真实证据并复述同一判定规则」，不生成虚假测量值。

## 二、两种 kind 的受控构造方法

构造是否成立，按 `tools/huangzhong_accept.py` **同一判定规则**推导真实证据将判的 verdict，
只有「预期 verdict == 请求 kind」才允许 apply（否则工具拒绝且零写入）：

| kind | 预期 verdict | 构造成立条件（与 accept 同口径） | v2 §5.2 手段 | 现成真实证据源示例 |
|---|---|---|---|---|
| `observe` | **OBSERVE** | 无硬失败，且基线/红队**缺失、不可读或超龄 >48h** | 手段2·证据超龄/缺失显式绑定 | `work/p1/redteam/redteam_20261027_155916.json`（pass_rate=1.0，生成于 10-27，早已 >48h） |
| `reject` | **REJECT** | 基线 `failed>0`/`error>0`，或红队 `pass_rate<0.8`（硬失败优先） | 手段1·历史失败证据显式绑定 | `work/p1/redteam/redteam_20261027_150225.json`（total=2/passed=1/**pass_rate=0.5**） |

- 默认证据 = 全局最新（`agent_platform/data/test_baseline/latest.json` + `work/p1/redteam/` 最新报告）；
  **默认证据新鲜时不可用于演练**（会判 PASS）→ 工具拒绝 apply 并提示用 `--baseline` / `--redteam` 显式绑定。
- 显式绑定（推荐复演用法，证据只读、不复制、不改动）：

```powershell
# OBSERVE：绑定 10-27 真实超龄红队报告（pass_rate=1.0 但已超龄 → OBSERVE）
--redteam work\p1\redteam\redteam_20261027_155916.json

# REJECT：绑定 10-27 真实失败红队报告（pass_rate=0.5 → REJECT）
--redteam work\p1\redteam\redteam_20261027_150225.json
```

## 三、口令与 dry-run 流程（先看后写）

工具要求**确认口令**，防止误触：

| kind | 确认口令（`--confirm`） |
|---|---|
| observe | `DRILL-OBSERVE` |
| reject | `DRILL-REJECT` |

```powershell
cd C:\项目\老田的AI助手

# 1) 默认 dry-run（零写入）：先看「将写什么」
C:\项目\py312\python.exe -X utf8 tools\huangzhong_drill.py `
  --kind observe --confirm DRILL-OBSERVE --dry-run --json `
  --redteam work\p1\redteam\redteam_20261027_155916.json

# 2) 确认计划无误后再 apply（写演练单 + 台账条目）
C:\项目\py312\python.exe -X utf8 tools\huangzhong_drill.py `
  --kind observe --confirm DRILL-OBSERVE --apply --json `
  --redteam work\p1\redteam\redteam_20261027_155916.json
```

- 不传 `--apply` 即 dry-run（默认），只打印计划，**不写任何文件**；
- `--dry-run` 与 `--apply` 同时给 → 拒绝且零写入；口令错误 → 拒绝且零写入；
- 前置不成立（预期 verdict ≠ kind）→ dry-run 打 warning 仍显示计划；**apply 拒绝且零写入**；
- 已有同日同 kind 演练单或台账同 file 条目 → **幂等跳过**，不重复写、不重复台账；
- 退出码：`0`=成功（dry-run 计划 / 已写入 / 幂等跳过），`1`=拒绝（零写入）。

可用参数：`--work-dir`（默认 `<repo-root>/work/huangzhong`）、`--repo-root`、
`--baseline` / `--redteam`（显式证据）、`--commit`（默认 `git rev-parse HEAD`）、
`--witness`（默认「待老田/赵云签字」）。

## 四、apply 写入产物与台账字段

### 4.1 演练单（只写新文件，不覆盖正式验收单）

`work/huangzhong/acceptance_drill_<kind>_<YYYYMMDD>.json`（同日同 kind 幂等，文件名即幂等键）：

- `drill=true`、`kind=OBSERVE|REJECT`、`mode=observe`、`blocking=false`；
- `commit`：演练目标 commit（默认当前 HEAD）；
- `evidence`：基线/红队真实证据的 `path/generated_at/age_hours/stale/pass_rate` +
  `construction`（受控手段、预期 verdict、理由、判定规则、证据来源）；
- `verdict` / `reasons`：与 accept 工具同规则推导（REJECT 硬失败优先；OBSERVE 缺失/超龄）；
- `rollback_point`：无生产变更（只读演练）；复位=回收站删除本单/台账条目（需批准）；
- `witness`、`reproduce_command`（复跑 accept 的命令原文）、`note`（drill 不计入 PASS/KPI）。

### 4.2 台账条目（追加，不覆盖既有台账）

`work/huangzhong/drills/drill_ledger_<YYYYMMDD>.json`（同日追加；缺失则新建，
`schema=huangzhong_drill_ledger/v1`）：

| 字段 | 说明 |
|---|---|
| `drill_id` | `DRILL-<YYYYMMDD>-<VERDICT>-01` |
| `drill` / `kind` / `verdict` | 固定 `true` / `OBSERVE,OBSERVE` 或 `REJECT,REJECT` |
| `method` | 受控手段（v2 §5.2 手段1/2） |
| `commit` / `target_commit` | 演练目标 commit |
| `file` / `acceptance_report` | 演练单仓库相对路径（如 `work/huangzhong/acceptance_drill_observe_20261031.json`） |
| `reason` / `reasons` | 判定理由（与演练单一致） |
| `evidence_sources` / `evidence_source` / `evidence_generated_at` / `evidence_age_hours` / `evidence_pass_rate` | 真实证据来源与元数据 |
| `witness` | 默认「待老田/赵云签字」 |
| `created_at` / `generated_at` / `result_at` | 生成时间 |
| `reproduce_command` | 复跑 accept 的命令原文 |

- **不写** `daily.jsonl` / `events.jsonl` / `incidents.jsonl`；不写任何正式 `acceptance_<sha8>.json`；
- 既有台账（如 `drill_ledger_20261030.json`）不做任何修改；同日追加保留原 `note/schema` 并更新 `updated_at`；
- 已有台账坏 JSON/结构异常 → apply 拒绝且零写入（**不自动覆盖坏台账**，先人工修复）。

## 五、与认证 v2 ②/③/④ 的关系

- **②（≥1 次真实受控拒收演练）**：`drills/drill_ledger_*.json` 中 `verdict∈{REJECT,OBSERVE}` 条目 ≥1 即达标；
  本工具产物可直接被 `tools/huangzhong_review.py` 的 ② 计数（台账 `kind/verdict`、`acceptance_report` 字段已对齐）。
- **①（PASS 样本）/覆盖率 KPI**：演练单 `drill=true` 且台账列出 → **不计入 PASS 样本、不计覆盖率**
  （`huangzhong_review.py` / `huangzhong_go_no_go.py` 均按台账排除）。
- **③（误拒绝率）**：演练 REJECT 进入 REJECT 样本池（v2 §2.2③ 分母含演练单），需人工复核记录
  （`work/huangzhong/reject_review*.json`）；不得用「演练 REJECT」冒充自然拒收。
- **④（漏放）**：演练单不属于「对真实 commit 的正式 PASS 验收」，**不进入漏放 7 天窗口**（review 工具
  只对非演练 PASS 单计满窗）。
- **见证与归档**：11-04 复核材料需附《受控拒收演练记录》（首演见 `docs/plans/2026-10-30_黄忠受控拒收演练记录_v1.md`）；
  复演后由赵云/老田在记录或台账核对栏签字（本工具 `witness` 默认「待签」）。

## 六、复位与留证

1. **留证**：apply 的 JSON 输出、演练单 JSON、台账条目、`reproduce_command` 复跑输出；建议另存
   `deliverables/` 证据副本（与 10-30 首演同规格）。
2. **复跑验证**：用演练单内 `reproduce_command` 或在主仓执行
   `python -X utf8 tools\huangzhong_accept.py --commit <sha> --redteam <证据> --json`，
   确认 verdict/reason 与本演练单一致（证明非工具故障、可复现）。
3. **复位**：演练**无代码/证据变更**，无需回滚；如需清理演练产物，须经老田/赵云确认后
   **回收站删除**演练单与台账条目（Windows 删除一律进回收站，禁 rm/del）。
4. **不污染生产**：apply 前 dry-run 核对路径；apply 后用
   `python -X utf8 tools\huangzhong_review.py --json` 确认 ① PASS 计数 / KPI 未因演练变化
   （演练单应在 `excluded_drills` 中）。

## 七、禁止事项（红线）

1. **禁止造数据**：不得手写/篡改基线/红队 JSON 的数值，不得伪造 `pass_rate`；本工具只绑定真实证据。
2. 禁止用本工具生成「对真实 commit 的正式验收单」（只允许 `acceptance_drill_*` 演练单）。
3. 禁止 `--apply` 到错误目录：只写 `<work-dir>`（默认 `work/huangzhong/`）；**不写 daily/events/incidents**。
4. 禁止删除/覆盖既有 `acceptance_*.json`、`drills/drill_ledger_*.json`（幂等键=文件；坏台账先修后跑）。
5. 禁止把演练单冒充 PASS 样本、计入覆盖率 KPI 或自然拒收；禁止未见证即签「已演练」。
6. 禁止在 8796 等线上服务、生产数据、计划任务、凭据上做演练；禁止对 master 工作区回退或 merge 演练分支。
7. 禁止跳过 dry-run 直接 apply（复核/见证场景必须先看计划再写）。

## 八、11-04 复核快速复演清单

```powershell
# 1) 复演 OBSERVE（先 dry-run）

# 2) 复演 REJECT（先 dry-run）

# 3) 见证确认后逐个 --apply，并在《受控拒收演练记录》补本次复演条目/签字
```
