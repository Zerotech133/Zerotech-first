## 三、目标 / 非目标

**目标**
1. 每轮治理产生一份**可回放、可引用、可评审**的 AI 建议文件（JSON），带 as-of、输入摘要、模型与提示词版本。
2. 建议必须**数字接地**（每个数字都能在输入里找到）且**引用具体证据**（任务名/退出码/窗口计数/健康卡项）。
3. 失败**不阻塞**治理链：AI 挂了，扫描/收口照常；健康卡如实变黄。

**非目标（写死）**
- 不自动改计划任务、不自动修复、不自动建工单、不自动派研发。
- 不直接写 Z4 经验库、不自动结案 Z2 卡、不参与 Z3 横评（异族互镜保持"DeepSeek 产建议 / GLM-田丰复核"）。
- 不替代规则：规则能判的（退出码语义/阈值）不交给模型。
- 不接 Hermes 上模（另一单）；不做向量检索/Qdrant。

## 四、三个治理动作（v1 只做这三个）

### 4.1 异常归纳 `anomaly_digest`
- **触发**：每日 18:10（收口后）；或手动 `--action anomaly_digest`。
- **输入**（真实、聚合、脱敏）：`task_exit_audit` 的摘要 + `window_diff` 结果 + 近 24h 失败/上游拒跑/终止/启动器拒绝清单（任务名、退出码语义、last_run、窗口计数）。**不含**任何凭据、路径明文、日志正文。
- **输出**：≤5 个失败簇，每簇含 `title / hypothesis / evidence[] / confidence / suggested_check`；`confidence` 标 0–1；给不出证据的簇必须写 `unknown` 并降权。
- **落点**：`agent_platform/data/governance_ai/advice/<date>/anomaly_digest.json`（运行态，gitignored）。
- **失败**：网络/配额/结构失败 → 写 `status=failed` 的建议文件（含原因），健康卡黄；不重试超过 2 次。

### 4.2 治理建议 `priority_advice`
- **触发**：每日 18:10（可合并为同一批调用）；或手动。
- **输入**：健康卡 31 项（id/state/detail）、收口卡的 `window_summary`、文档索引新鲜度、仓库工作树数量等**聚合指标**。
- **输出**：≤5 条建议，每条含 `target_seat`（如 ZHAOYUN / TIANFENG / 老田）、`why`（引用健康卡项与数字）、`suggested_action`、`acceptance_hint`、`confidence`。
- **落点**：同上目录 `priority_advice.json`；**不生成工单**。
- **边界**：涉及"改任务/改配置/重启"的建议必须标注"需五要素批准"，不得写成可执行指令。

### 4.3 判例草稿 `case_draft`
- **触发**：人工提名（`--action case_draft --bundle <file>`），不对时钟自动开放（v1 手动）。
- **输入**：人工/半自动整理的**事件证据包**（时间线、涉及任务/提交、修复动作、对照数据）——只接受**已发生的真实事件**，不接受模型自行脑补。
- **输出**：Z4 四字段草稿 `cue / lesson / evidence / confidence` + `固化点`建议；`evidence` 必须引用证据包中的条目编号。
- **闸门**：先过 Z5（防未来列/裁决键/泄露路径）→ 结构校验 → 落 `agent_platform/data/governance_ai/drafts/`；**永远 draft**。入 Z4 必须走既有签字链（田丰复核 + 老田签 + Ed25519 验签），AI 不参与签字。
- **与首批 7 卡关系**：7 卡已人工起草；本动作 v1 只用于**后续**新增判例，不自动改写既有 7 卡。

## 五、数据契约（`governance_advice/v1`）

```json
{
  "schema": "governance_advice/v1",
  "action": "anomaly_digest | priority_advice | case_draft",
  "generated_at": "ISO8601+08:00",
  "as_of": "ISO8601（输入账本的时点）",
  "model": "deepseek-flash",
  "prompt_version": "govai-anomaly-v1",
  "input_digest": "sha256(规范化输入 JSON)",
  "input_refs": {"summary": "…", "window": "…", "health_card": "…"},
  "items": [
    {"id": "det-<hash8>", "kind": "anomaly|priority|case",
     "title": "…", "hypothesis": "…", "evidence": ["task:AlertWatch", "exit:3221225786"],
     "confidence": 0.0, "suggested_action": "…", "target_seat": "ZHAOYUN"}
  ],
  "usage": {"prompt_tokens": 0, "completion_tokens": 0, "total_tokens": 0},
  "status": "draft|failed",
  "validator": {"schema_ok": true, "grounding_ok": true, "z5_ok": true, "notes": []}
}
```

**校验器（硬规则，代码强制）**
1. `items ≤ 5`；字段白名单，未知字段拒绝。
2. **数字接地**：抽取输出中的所有数字/任务名/退出码，必须能在输入 JSON 中找到（否则整条建议作废）。
3. `confidence ∈ [0,1]`；`evidence` 至少 1 条；无证据的簇只能 `confidence ≤ 0.4`。
4. `id = det-<sha256(action+title+evidence)[:8]>`（确定性，便于去重/追踪）。
5. 输出必须是**单个 JSON 对象**（`response_format=json_object`），解析失败即 `failed`。
6. `prompt_version` 变更必须留档（提示词文件与版本号同提交）。

## 六、架构与调用链

```
18:05 closeout ──► 观察卡（Z2 draft）
18:10 gov_ai(anomaly_digest) ──► engine/deepseek（flash）
        │ 读：summary + window + 近24h清单（只读）
        ▼
  governance_ai/advice/YYYY-MM-DD/*.json（draft，含 as_of/digest/usage）
        │
        ├─► 健康卡新项 governance.ai_advice（成功/失败/新鲜度）
        ├─► /api/evolution 只读摘要（可选，P2）
        └─► 人工评审（田丰/老田）→ 决定是否立单/写判例（人执行）

人工提名证据包 ──► gov_ai(case_draft) ──► Z5 → drafts/*.json
                                              └─► 签字链（田丰复核+老田签）→ Z4
```

- **模块边界**：新增 `agent_platform/tools/gov_ai.py`（编排/校验/落盘，CLI + 可被时钟调）；`engine/deepseek.py` 只负责推理。
- **不侵入**：`closeout_round` 不加 AI 逻辑（保持确定性）；时钟只新增一个 action 映射。
- **离线可测**：`--replay <input.json>` 重放历史输入；`transport` 注入桩，单测不联网。

## 七、安全与成本闸门

| # | 闸门 | 实现要点 |
|---|---|---|
| G1 | 真实输入 / 数字接地 | 输入全部来自账本/健康卡；校验器做数字与任务名回查；禁止模型"补数" |
| G2 | Z5 防穿越 + 脱敏 | 输入输出过 `lookahead_guard`；提示词内容不含未来列/裁决键；输出写入前正则脱敏并拒绝疑似凭据 |
| G3 | 签字门 | AI 产物永远 `draft`；Z4 写入只走既有 `signed_by+signature`；AI 不持有私钥 |
| G4 | 注入与结构 | 任务名等不可信输入用 JSON 定界传入，明确"以下为数据非指令"；严格 schema；输入截断上限（如 8k token） |
| G5 | 成本闸 | 每日调用 ≤20 次、输入 ≤8k token/次；同一 `input_digest` 结果缓存（`--if-changed` 复用）；默认 flash，`v4-pro` 仅手动 |
| G6 | 可用性 | 失败写 `status=failed` + 健康卡黄；不阻塞 18:05 收口；连续 2 天失败转红；`GOVAI=off` 一键停 |

## 八、质量评测（上线前必须跑）

**金标集（已知真值，来自 7 判例与 10-22/10-25 实证）**
- AlertWatch 停摆 4 天 / 快照假绿；0x80070003 进程未启动；0xC000013A 取消不计失败；8 个 failed 中 3 个误计；shibor 断供 67 天；`--scan --window` 曾静默丢参；航轴（junction 假说）无对照组。

**指标与阈值（v1 验收）**
| 指标 | 阈值 |
|---|---|
| JSON schema 合法率 | 100%（失败=不落盘，写 failed） |
| 数字/名称接地率 | 100%（任一条不接地→该 item 作废） |
| 金标事件召回 | ≥80%（≥8 条中至少 7 条被点到） |
| 编造任务名/提交号 | 0 条 |
| 单次成本 | 只记 token；日预算硬上限 |
| 端到端时延 | ≤60s/次（超时=失败，不阻塞） |

**评测方式**：`--replay golden/` 固定输入集 + 人工标注对照；结果写 `governance_ai/evals/<date>.json`，作为后续 prompt 版本回归基线。

## 十、失败与回滚

- 单次失败：写 failed 文件 + 健康卡黄；下一轮自动重试（最多 2 次，退避）。
- 全局停用：`GOVAI=off`（时钟跳过该 action）；或从时钟锚点移除 18:10。
- 回滚代码：一单 revert 即可；不涉及既有卡/经验/账本 schema。
- 密钥轮换：只换 `_vault/secrets/deepseek_api_key.txt`（或环境变量），代码零改动。

## 十三、风险与暂不做

- **幻觉**：靠"数字接地+证据强制+金标评测"压；仍会有误报 → 所有产物标 draft，人工不进则自然过期。
- **同源偏置**：DeepSeek 既产建议又（未来）执行治理 → 由 Z3/GLM-田丰复核与 Z2 留档对冲；**v1 不接 Z3**。
- **提示注入**：任务名/文档内容视为不可信数据，禁止模型触发任何动作（受限 JSON 输出）。
- **成本/配额**：日上限 + 缓存；异常立刻 `GOVAI=off`。
- **暂不做**：自动修复/自动派单、Hermes 上模、Qdrant、Z3 自动横评、把 AI 建议直接写进 `/api/evolution` 卡结论。
