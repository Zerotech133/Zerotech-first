## 一、推演起点：六环节动线 × 当前能力对照

业务动线：**选股入池 → 盯盘触发 → 投研核实与授权 → 风控和交易执行 → 成交反馈 → 复盘进化**

| 环节 | 已有资产 | 缺口 | 严重度 |
|---|---|---|---|
| ① 选股入池 | 强/弱扫描（strong_scan/weak_scan）、15+ 策略本体、chanlun 三市场信号池、kg_boost 热度 | 策略各自为战，聚合层仅挂 2 个（kg_boost/chan_monitor 各 0.5） | **P0** |
| ② 盯盘触发 | 雪球舆情六环（18:00~19:35 自动化）、quant_engine 盯盘、linkage 三线联动 | RiskGuard 四规则误杀（213 样本拦截后验 +0.65% vs 放行 -0.25%）待重校准 | P1 |
| ③ 投研核实与授权 | council_shadow（K55-C4 分歧度-前向收益影子对照）、stock_council 多 Agent 雏形 | 投研机构无"核实→授权→输出投研计划"闭环；无 decision_bundle_id 全链 | **P0** |
| ④ 风控和交易执行 | execution_engine（GTC/PER_ORDER 状态机）、SIM_MARKET 三段式边界（G2 加固后 101 tests）、智策 Executor 四实现 | G1 导入规范未统一（顶层/包名混载类身份分裂）；授权→预算→风控→订单未接同一 trace | **P0** |
| ⑤ 成交反馈 | daily_ledger / trial_ledger / shadow_ledger 账本三件套 | 账本与订单、授权未打通；无反事实评估 | P1 |
| ⑥ 复盘进化 | weight_updater、shadow_weekly_report、月度 PIT 重放、小模型蒸馏池 | 策略 Agent 每日向 Hermes 主管上报研究方案的机制未建 | P2 |

**推演结论**：P0 缺口全部指向同一件事——**策略插件化收编 + 授权链贯通**。收编不是新工程，是把已验证的策略本体装进已有的插件契约（StrategyAgent.propose → Verdict）。

## 二、策略收编流水线（每策略固定五步，零主链改动）

```
[策略本体] → S1 Manifest注册 → S2 Agent化 → S3 历史回放 → S4 影子评估期 → S5 授权进聚合层
```

| 步骤 | 内容 | 验收标准 |
|---|---|---|
| **S1 Manifest 注册** | 声明策略身份/版本/能力/数据权限/资源预算/运行模式（复用 agent_platform strategy_registry + Manifest 机制） | 显式装配，不扫目录；Config 审核过 |
| **S2 Agent 化** | 包一层 `StrategyAgent.propose(context) -> Verdict`；策略只建议，不写账户/订单 | 契约测试过；SHADOW-only 输出 no_execution=True |
| **S3 历史回放** | REPLAY 模式跑既有回测期，输出与本体回测基线对账（信号一致率 ≥99%） | 回放报告 + 差异清单归档 |
| **S4 影子评估** | SHADOW 模式与聚合层并行最少 **10 个交易日**，记分位/置信/与前向收益相关性 | shadow_weekly_report 周报给出转正/延期/淘汰建议 |
| **S5 授权进聚合** | weight_updater 给初始权重；进 registry.enabled；进日报/周报口径 | 聚合层 e2e 测试绿；**全程零公共主链 diff** |

**铁律复述**：S1~S5 全程不改盯盘/投研/组合/风控/执行/结算公共主链——收编一个策略的 diff 必须只落在新策略包 + 配置 + 测试。

## 四、四域建设与动线贯通（与收编批次并行）

### 域一 · AI 策略研究（Hermes 主管 + 策略 AI 军团）
- W1 起：每策略 S2 Agent 化后即注册进 Hermes 主管辖区；**每日上报机制**（策略 Agent 向 Hermes 提交：今日信号摘要 + 研究新方案 + 参数调优建议）——对应用户"每种策略每天要给主管上报，不断升华"。
- 月度：策略述职（S4 影子周报 + 月度 PIT 重放成绩 → 晋升/降级/淘汰）。

### 域二 · AI 盯盘（Hermes 主管的盯盘 Agent）
- W2：RiskGuard 四规则重校准落地（213 样本误杀数据集重训阈值）——这是盯盘 Agent 输出可信的前置。
- W3：盯盘触发信号接入投研机构的输入队列（雪球异动 → 投研核实工单）。

### 域三 · AI 虚拟投研机构（多 Agent 研讨 → 投研计划）
- W2~W3：以 council_shadow（K55-C4）为底，建最小投研会：看多/看空/技术面/情绪面 4 席 Agent 对候选股研讨 → 输出投研计划（仓位规律 + 风控计划）→ **投研授权与 Verdict 分离**（Verdict≠放行，投研授权是独立票据）。
- W4：投研授权接入 decision_bundle_id——同一 trace 贯通授权/预算/风控/订单（即 G3 门）。

### 域四 · AI 交易智能中台
- W1（前置硬门）：**G1 导入规范统一**——execution_engine 收敛为唯一包路径，Bar/OrderIntent 类身份单一化（需协调公共执行链在途改动的会话，禁止裸迁）。
- W2~W3：**G2 可信证据**——市场状态/交易日历/涨跌停来源证据化（SimMarketStatusEvidence 的 source 接真实数据源，静态夹具仅留演示测试）。
- W4：**G3 授权链**（与域三合流）→ **G4 最小纵切**：一个市场 + 一个组合 + 一个模拟账户 + 主策略 + 影子挑战策略，跑通入池→授权→模拟买卖→反事实→复盘→账本重算。
- G4 过门后：开放多策略 × SIM_MARKET 日常模拟调度（日报/周报/月报 + 蒸馏样本沉淀）。**未过门禁止接日常调度，禁止宣称生产就绪。**
