## 一、现状盘点（写代码板块功能链全景）

```
田小皮(A0)派单 → tasks.json 工单 → agent_coder.py(生成) → 验收器 → 落盘仓库 → QA1质检 → git入仓
                                        ↑
                          chat_cloud(智谱flash) / chat(本地9b兜底)
```

| 环节 | 现状 | 缺口（对照业界最优） |
|---|---|---|
| 任务上下文 | 只给人设 system + 单条 task prompt | **无仓库上下文**——Agent 不知道代码库里有什么，产出靠猜 |
| 生成方式 | 单轮补全，整文件重写 | 无编辑协议——大文件改动整文件重写易「改一处丢一处」 |
| 质量门 | 验收器=JSON键/关键词/篇幅检查 | **无执行验证**——不跑 py_compile、不跑测试，语法错也入库 |
| 迭代能力 | 一次生成定生死，失败即退回 | 无「生成→跑测试→带错误重试」回路 |
| 落盘方式 | 直接写工作区，主控人工提交 | 无独立 commit 粒度，无法按单回滚 |
| 模型通道 | chat completions（flash 免费档） | **未打通 Anthropic 兼容端点**——Claude Code CLI+智谱 Key 可跑 GLM-4.6（工具型 Agent），比裸补全强一个量级 |
| 人设利用 | 仅作 system prompt 文本 | 27 岗人设无工具授权、无行动能力（只产出文本） |
| 轨迹留痕 | 黑板 decision.jsonl 记结论 | 无 Action/Observation 过程轨迹，出问题无法回放定位 |
| 沙箱 | 无 | Agent 产出直接进主仓库工作区，无隔离 |

**结论：当前是「单发补全器」，不是「编码 Agent」。五项结构性缺口：仓库上下文、编辑协议、执行验证、迭代回路、工具通道。**

## 二、开源调研结论（四路范式 + 一个合流点）

### 2.1 Aider（结对编程范式，15 亿 token/周实跑）
- **RepoMap**：tree-sitter 提符号 + PageRank 排重要性，把全仓库压成 1-2K token 的「地图」注入上下文——解决「改哪个文件」的定位问题
- **编辑协议**：SEARCH/REPLACE 三定界符块，模型只输出改动片段；14 种编辑格式按模型能力自动切换，弱模型整文件兜底
- **自动提交 + 自动测试**：每次成功编辑独立 git commit（弱模型写 commit message）；auto-test/auto-lint 失败自动回滚重试
- **惯例文件**：仓库根放 AIDER.md/CLAUDE.md 记项目纪律，自动读入
- **架构师/编辑者分工**：强模型出方案、便宜模型落编辑——成本砍半

### 2.2 SWE-agent（普林斯顿，ACI 接口设计）
- **核心发现：接口设计 > 模型**。同一个 GPT-4：裸 bash 3.8% vs 定制 ACI 12.5%（3 倍）
- **ACI 三原则**：①观察有界（100 行窗口，禁止 cat 全文）②**编辑即 lint**——编辑命令先过语法检查，不过则拒收并把错误喂回去（把坏编辑挡在门口）③错误结构化（固定格式一行，不吞 stderr）
- 失败不崩溃：超步数/超预算自动 submit 已有部分产出（残局也是产出）

### 2.3 OpenHands（开源 SWE-bench 榜首，事件流架构）
- **事件流 = 唯一记忆**：Action（封闭词汇表：跑命令/改文件/读文件/收尾）→ 沙箱执行 → Observation 回注流，每轮从流重建上下文
- **Runtime 才是硬工程**：模型选动作容易，沙箱执行难——一切动作进一次性 Docker，worst case 丢容器不伤主机
- 长任务上下文压缩（旧事件摘要化）
- **与我们 events.py 9 类事件账本同构**——吸收成本最低的一路

### 2.4 Claude Code（headless + 子代理 + 钩子）
- **无头模式**：`claude -p --output-format json --allowedTools "Read,Edit,Bash" --append-system-prompt 人设`——天然是「27 岗人设 → 子代理」的载体（`--agents` JSON：description/prompt/tools/model 四字段，与我们 bundle 人设一一对应）
- **确定性钩子**：PreToolUse 拦危险命令，模型文本无法绕过（比 prompt 纪律硬）
- `--bare` 模式：跳过自动发现，脚本化调用结果可复现
- session resume（`--resume <session_id>`）支持多步工作流接续

### 2.5 ⭐ 合流点：智谱 Anthropic 兼容端点（本次调研最大收获）
智谱官方提供 `https://open.bigmodel.cn/api/anthropic`，配智谱 API Key 即可让 **Claude Code CLI 跑 GLM-4.6**：
```json
// ~/.claude/settings.json
{ "env": {
  "ANTHROPIC_BASE_URL": "https://open.bigmodel.cn/api/anthropic",
  "ANTHROPIC_AUTH_TOKEN": "<智谱Key>",
  "ANTHROPIC_MODEL": "glm-4.6"
} }
```
**「智谱的 K」与「Claude Code 的 K」不是二选一，是一条路**：Claude Code 的 ACI/工具/子代理外壳 + 智谱的模型与计费。上一单（K-ORG-033）沙箱拦 claude spawn 的问题，由 worker/计划任务侧执行即可绕开。
