## 一、目标与数据流

W2 缺口：D1 handoff 即使产生，也没有定时消费器把它 arm 成 watch_plan（watch_plans=0）。
本单补一个「扫描 → 自动 arm → 过期回收」的只读/显式路径扫描器：

```text
d1_handoffs.jsonl（只读；显式 --ledger 或 D1_HANDOFF_LEDGER）
   │  逐行 read_handoff_rows（坏行/坏 JSON → fail-visible，不静默跳过）
   ▼
对含 watch_plans[] 的 handoff：consumer.consume_handoff(row, path=plans)
   ├ 新 plan → 写 watch_plans.jsonl：future→armed / 已过期→expired
   ├ 同 plan_id 同 receipt → duplicates（幂等，不重复写）
   └ 同 plan_id 不同 receipt → plan_id_conflict（拒覆盖，记 item error）
   ▼
consumer.expire_due(path=plans)：到期 planned/armed → expired（每轮回收）
   ▼
status JSON（显式 --status 原子写；--dry-run 零写）
```

**只做 arm/回收**：不触发、不建 confirmation、不写 trigger ledger、不下单、不实盘、不写 D1 decisions。

## 二、写边界（默认零写生产）

- handoff/plan 账本**必须显式** `--ledger`/`--plans` 或 env
  （`D1_HANDOFF_LEDGER` / `D1_WATCH_PLAN_LEDGER`）；两者皆无 → 报错
  `handoff_ledger_required` / `plan_ledger_required`，**不使用生产默认路径**；
- live：写 plan 账本（consume + expire_due）；
- `--dry-run`：只读 handoff/plan 账本做**预览**（`would_create/would_arm/would_expire`），
  不调 consume/expire_due、不写 plan/status；
- status 仅显式 `--status` 且非 dry-run 时原子写（tmp+replace + fsync）；
- 坏 handoff 账本行/坏 JSON → `handoff_ledger_corrupt`（fatal）；单条 handoff 非法 /
  plan_id 冲突 → per-row `error_details`（继续处理其余行，fail-visible）。

## 三、status schema（`watch_plan_autoarm_status/v1`）

```json
{
  "schema": "watch_plan_autoarm_status/v1",
  "ok": true, "degraded": false,
  "run_id": "ar-20261104114108-b763c7", "last_run": "2026-11-04T11:41:08+08:00",
  "dry_run": false, "mode": "once",
  "handoff_ledger": "...", "plan_ledger": "...",
  "handoffs_scanned": 1, "handoffs_with_plans": 1, "plans_seen": 1,
  "created": 1, "armed": 1, "expired": 0, "duplicates": 0, "updated": 0,
  "errors": 0, "error_details": [],
  "results": [{"receipt_id": "...", "created": 1, "armed": 1, "expired": 0,
               "duplicates": 0, "updated": 0, "errors": 0}],
  "would_create": 0, "would_arm": 0, "would_expire": 0,
  "status_written": true,
  "paper_only": true, "not_a_trade": true, "executes": false
}
```

语义：
- `ok`：无 fatal（路径缺失/坏账本/status 写失败）；`degraded`：有 item 级错误（fail-visible）；
- `errors`/`error_details`：fatal 之外的逐条错误（handoff_invalid/plan_id_conflict/consume_failed/
  expire_failed 等，最多 20 条明细）；
- `created/armed/expired/duplicates/updated` 为 consumer 账本语义（`updated` 含 expire_due 更新）；
- dry-run 只填 `would_*`，`created/armed` 恒 0；
- `paper_only=true/not_a_trade=true/executes=false`（无执行字段）。

## 四、幂等与过期

- 幂等键 = `plan_id`：重复扫描同一 handoff → `duplicates` 计数、不重复写 plan；
- plan 状态机：`planned → armed`（consume）/ `planned|armed → expired`（consume 时已过期或
  `expire_due`）；`triggered`/`cancelled` 不被 autoarm 改动；
- 同 plan_id 不同 receipt → **fail-closed 拒覆盖**（item error，保留先到者）；
- `expire_due` 每轮执行（含 handoff 空时）：只改 `planned/armed` 且 `expires_at<=now` 的行。

## 五、命令

```powershell
# live：扫描 handoff → arm + 过期回收，写显式 status
python -X utf8 -m agent_platform.watch_plan_autoarm --once `
  --ledger agent_platform/data/d1_handoffs.jsonl `
  --plans agent_platform/data/watch_plans.jsonl `
  --status agent_platform/data/watch_engine/autoarm_status.json --json

# dry-run：只读预览（零写）
python -X utf8 -m agent_platform.watch_plan_autoarm --once `
  --ledger agent_platform/data/d1_handoffs.jsonl `
  --plans agent_platform/data/watch_plans.jsonl --dry-run --json

# env 方式（等价；无 --ledger/--plans 时读取）
#   D1_HANDOFF_LEDGER / D1_WATCH_PLAN_LEDGER
```

退出码：`0`=ok 且无 item 错误；`1`=fatal 或 item 错误（fail-visible）；`2`=用法错误。
`--once` 为 MVP 单轮语义；定时循环由调度器周期调用（本单不建计划任务、不启停服务）。

## 七、接线项（Lead）与残余

1. **定时调度**：建议盘前/盘中每 5–10 分钟跑一次 `--once`（或由调度器/常驻进程周期调用），
   计划任务/服务属 L2，需审批；本单未建计划任务、未启停服务。
2. **生产路径**：显式传 `--ledger agent_platform/data/d1_handoffs.jsonl`、
   `--plans agent_platform/data/watch_plans.jsonl`（或对应 env）；**未配置不写生产**。
3. **status 消费**：建议 `--status agent_platform/data/watch_engine/autoarm_status.json`，
   供页面/监控只读；本单不新增 API/路由（route baseline 不变）。
4. **全链接线**：autoarm（本单）→ watch_runner（quote/条件/trigger）→ watch_alerts（告警）
   由调度器串成完整盯盘链；三单均只 commit，需 Lead 合并/接线/换血。
5. **残余**：
   - handoff 增量扫描为全量重扫（幂等但 O(n)），量大后可加水位/cursor（未做）；
   - plan_id 冲突只记错误不自动裁决（人工处理）；
   - handoff 无 watch_plans 的 v1 行直接忽略（不消费/不改 ack）。

## 八、回滚预案

| 层 | 动作 | 验证 |
|---|---|---|
| 代码 | `git revert <commit>`（仅新增 autoarm + 测试/本文件） | 既有 handoff/consumer 测试 rc0；无调用方 |
| 数据 | 本单不写生产；如接线后产生 plan 账本变更，按既有 F3 回滚口径归档显式生成文件 | confirmation/paper/outcome 账本 digest 不变 |
| 调度 | 未接线；停止调度即停止自动 arm；已有 armed plan 可由 consumer/引擎继续只读消费 | 不产生新 plan |
| 服务 | 本单未启停服务 | 端口/服务不变 |

**风险点**：
1. 全量重扫 handoff：当前量小可接受；量大时 duplicates 计数会持续上升（非错误）；
2. 自动 arm 会把**未来到期**的 handoff 计划直接置 armed（无人工二次确认）——这是 W2 设计目标，
   但计划本身仍受 engine 条件/人工门约束（arm 不等于交易）；
3. plan_id 冲突 fail-visible 但不自动解决；坏 handoff 行会阻塞整轮（fatal，需修账本）；
4. status 写失败会把 ok 置 false（fail-visible），不影响已完成的 arm 结果（幂等可重跑）。
