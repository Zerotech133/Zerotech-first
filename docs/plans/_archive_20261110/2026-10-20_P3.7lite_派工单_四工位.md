## L-A 客户面安全加固（WO-FS-101）

**问题（实测证据）**：`portal_api.py:3930` `/api/subscription/status` 仅校验 `open_id` 必填，无 key 无 token；响应含 `open_id` 明文与账本内部细节。知悉他人 open_id 即可查其档位与额度。

**规格**：

1. **字段最小化**（默认生效，无需配置）：响应只保留客户本人需要的字段。
   - 实测页面依赖面：`my_subscription.html` 仅读 `.status` / `.plan_id` / `.start` / `.end`（已 grep 确认），最小化后必须仍能正常渲染。
   - 移除/脱敏项：`open_id` 明文（改回显掩码，复用 `feishu_bot_ws.py` 的 `mask_open_id` 语义——若为私有函数，在本文件内实现同样规则的纯函数，不 import 私有符号）、任何金额/内部 reason 细节。
2. **可选 key 闸**（默认关，配置开启即生效）：读环境变量 `PORTAL_SUB_STATUS_KEY`，非空时要求请求头 `X-Portal-Key` 匹配；不匹配返回 401 与 `{"error":"unauthorized"}`。未配置该环境变量时**行为与现在完全一致**（保证不破坏既有调用方）。
3. **页面同步**：`my_subscription.html` 若读到了掩码后的 open_id，不得回显明文；提示文案明确「本页不含金额信息，购买/续费请往飞书」。
4. **测试**（新建文件，≥8 例）：字段最小化白名单断言／掩码不回明文／无 key 配置时零行为变化／配置 key 后错 key 401／对 key 通过／open_id 缺失 400／页面渲染所需四字段仍在／静态断言（端点不接收写参数）。

## L-B 订阅到期提醒（WO-FS-102）

**背景**：当前订阅只有自然到期（`expire_sweep`），**没有任何到期前提醒**——客户会在毫无预兆时失权，商业上是硬伤。此能力不依赖 M3 收银台（M3 上线前提醒文案引导「联系开通」，上线后改购买链接即可）。

**规格**：

1. 新建 `portal/renewal_reminder.py`，提供**纯函数**（零 IO，便于离线测试）：
   - `due_for_reminder(subscribers, now=None, lead_days=(3, 1)) -> list[dict]`：入参为 `list_subscribers()` 返回结构，输出待提醒项（含 `open_id`、`plan_id`、`end`、`days_left`、`stage`），去重规则：同一 `(open_id, plan_id)` 在同一天同一 `stage` 只提醒一次（stage 由 lead_days 档位决定）。
   - `build_reminder_text(item) -> str`：生成提醒正文，含剩余天数与「续费/联系开通」引导，**不含任何金额**（定价未定）。
2. `card_templates.py`：追加注册 `subscription_expiring`（建议橙色，标题「⏳ 订阅即将到期」）。**只追加**，不改写既有 kind 与既有测试断言（FC-C 快照判例）。
3. **不接排程**（定时任务需老田五要素批准），只交付能力 + 调用入口说明。发送侧不得真发；测试全部用桩。
4. **测试**（≥8 例）：T-3 命中／T-1 命中／T-10 不命中／同日同 stage 去重／已过期不提醒／跨档位不串（basic 与 premium 独立算）／正文不含金额与明文 open_id／`subscription_expiring` 已注册且色彩标题正确。

## L-D 订阅账本勾稽自检（WO-FS-104）

**背景**：商业化前必须能自证账本自洽。当前无任何跨表校验工具。

**规格**：

1. 新建 `tools/reconcile_subscription.py`（**只读**，绝不写库）：
   - 校验项：①`subscription` 行引用的 `open_id` 在 `subscriber` 存在 ②`plan_id` 在 `plan` 存在 ③`start <= end` ④状态与时间自洽（`status=active` 但 `end < now` 的行 → 报「待清扫」；`status=expired` 但 `end >= now` → 报「状态与时间矛盾」）⑤`entitlement_log` 中 `allowed=1` 的 `kind` 前缀能对应到某个 `plan` ⑥`payment_order` 若存在 `paid` 行但无对应 `subscription` → 报「漏单」。
   - 输出：JSON（`{"ok": bool, "checked": n, "issues": [{"code","detail"}]}`）+ CLI 人类可读摘要；`--json` 切换。
   - **fail-visible**：任一校验项执行异常必须计入 `issues` 并标注 `code="check_failed"`，**禁止静默归零**（项目既有 fail-open 禁令）。
2. 测试（≥8 例）：干净库零 issue／孤儿 open_id／未知 plan／start>end／active 但已过期／expired 但未到期／paid 无订阅漏单／异常注入时 check_failed 而非零。
3. 明确边界：本工具只读、不修复、不删行；修复动作一律另立工单。
