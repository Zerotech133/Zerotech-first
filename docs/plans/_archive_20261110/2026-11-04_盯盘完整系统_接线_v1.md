## 二、watch_engine status 兼容别名（API 契约）

API（`portal/api_d1_handoff.py::_watch_engine_status`）读取 status JSON 并期待：

| API 期望字段 | 本单提供 | 说明 |
|---|---|---|
| `engine_state` | ✅ 新增 | 正常轮 `running`；本轮失败 `error`（API 归一化小写） |
| `last_tick_at` | ✅ 新增 | 本轮时间戳（ISO8601，带时区） |
| `heartbeat_at` | ✅ 新增 | = `last_tick_at`（API 也认 last_heartbeat_at 等） |
| `armed_count` | ✅ 新增 | 本轮扫描的 armed plan 数（= 原 `armed`） |
| `tick_count` | ✅ 新增 | 单轮引擎：旧 status 文件读 +1；runner 跨进程累计（见下） |
| `started_at` | ✅ 新增 | 首轮/进程启动时刻；同一 status 文件跨轮保持 |
| 旧字段 | 保留 | `run_id/last_run/scanned/armed/waiting/triggered/errors/hits/would_trigger/expired/results/ok/dry_run/paper_only/executes/...` 全部不变 |

其它 API 可透出字段（`mode/pid/interval_s/version/note/reason`）由 runner 通过
`extra_status` 注入；API 只透出白名单标量，嵌套 `results` 不会被返回。

**API 读取路径**：`WATCH_ENGINE_STATUS_PATH` env 覆盖；默认
`agent_platform/data/watch_engine/status.json`。`engine_state=unavailable` 表示文件缺失；
`stale=true` 表示心跳超过 180s（API 默认阈值）。本单不启动服务，API 由门户进程既有路径读取。

## 三、watch_runner 运行命令

```powershell
# 1) 离线 fixture（测试/灰度；绝不网络）
python -X utf8 -m agent_platform.watch_runner --once `
  --plan-ledger agent_platform/data/watch_plans.jsonl `
  --trigger-ledger agent_platform/data/watch_triggers.jsonl `
  --data-dir agent_platform/data/trading_bot `
  --quotes-json C:\Temp\quotes.json `
  --status agent_platform/data/watch_engine/status.json

# 2) 显式网络快照（真实行情；只在明确选择时启用）
python -X utf8 -m agent_platform.watch_runner --interval 30 --max-ticks 120 `
  --plan-ledger agent_platform/data/watch_plans.jsonl `
  --trigger-ledger agent_platform/data/watch_triggers.jsonl `
  --data-dir agent_platform/data/trading_bot `
  --quote-source snapshot `
  --status agent_platform/data/watch_engine/status.json `
  --lock agent_platform/data/watch_engine/runner.lock

# 3) dry-run（只报告，不写 status/ledger/confirmation）
python -X utf8 -m agent_platform.watch_runner --once `
  --plan-ledger ... --quotes-json ... --dry-run --json
```

参数语义：
- `--quotes-json <file>`：离线 fixture（`{symbol: quote}` 或 `{"quotes": {...}}`），加载一次；
- `--quote-source snapshot`：每轮调用 `news_collector.quote_snapshot.fetch_quotes(codes)`
  （**网络**；显式选择才启用；返回 `{engine_symbol: {"last","ts","name","pct"}}`）；
- `--quote-source none`（默认）：不提供 provider → 引擎返回 `quote_provider_required`
  （不猜价、不建确认，不发起网络）；
- `--once` / `--interval N`（互斥）；`--max-ticks` 限轮次；`--lock` 可选单实例锁；
- `--status <path>`：**仅显式时**写（引擎原子写）；缺省不写任何 status（默认不写生产）；
- `--dry-run`：零写（status/ledger/confirmation 都不写）。

退出码：`0`=最后一轮 ok；`1`=引擎/行情/锁失败（fail-visible）；`2`=用法错误。

**tick 累计**：runner 每轮把 `tick_count = 旧 status.tick_count + 本轮序号` 传给引擎；
同一 status 文件跨进程续号；`started_at` 沿用旧值。单轮引擎自身也按「旧 status +1」兜底。

**单实例锁**：`--lock <path>` 用 `O_CREAT|O_EXCL` 创建；已存在 → `runner_locked` 失败
（不自动删锁/不杀进程，需人工确认旧进程退出后删除锁文件）；正常退出/异常均释放自建锁。

## 四、quote source 与网络边界

| source | 网络 | 用途 | 备注 |
|---|---|---|---|
| `none`（默认） | ❌ | 安全默认/接线前 | 引擎 `quote_provider_required`，不写确认 |
| `quotes-json` | ❌ | 测试/灰度/人工报价 | fixture 文件，静态加载 |
| `snapshot` | ✅（显式） | 真实盯盘 | `news_collector.quote_snapshot.fetch_quotes`；快照含 `price/ts/name/pct`，**无 prev** → cross 条件会 ambiguous（需 provider 补前值，后续项） |

## 六、接线项（Lead）

1. **真实行情源**：`--quote-source snapshot` 为显式网络入口（新浪快照，含 ts 供
   `max_age_s` 时效条件）；如改用其他 feed，只需替换 provider（实现
   `provider(symbols) -> {symbol: quote}`）；cross 条件需补 prev（当前快照无 prev）。
2. **调度**：`--interval 30 --max-ticks ...` 由调度器/常驻进程接线（L2 审批，含
   计划任务/端口/告警）；建议盯盘时段运行、盘后停；本单未建计划任务、未启停服务。
3. **status 路径**：建议 `WATCH_ENGINE_STATUS_PATH=agent_platform/data/watch_engine/status.json`
   并在 `watch_runner --status` 写同路径，供已合入的 `/api/d1/watch-plans` engine 块读取
   （API 只读；本单未改 API/未重启门户）。
4. **trigger ledger**：生产启用需 `--trigger-ledger`/`WATCH_TRIGGER_LEDGER_PATH`，
   否则只建 confirmation 无 trigger_id（既有 consumer/adapter 行为）。
5. **告警层**：watch_alerts（task-63）如需消费 engine 命中事件，建议后续在 runner 内注入
   alert sink（本单边界不接线；当前 runner 只调 engine，不直接推告警）。
6. **人工门**：命中只建 pending 确认，approve/reject 仍走 `/api/sim/confirm`；runner 不禁用/不绕过。

| 层 | 动作 | 验证 |
|---|---|---|
| 代码 | `git revert <commit>`（watch_engine 别名小改 + 新增 watch_runner/tests/本文件） | 既有 watch_engine 43 tests rc0；旧字段/评估逻辑不变 |
| 数据 | 本单不写生产数据；如接线后已产生显式 status/trigger ledger/confirmation，按既有 F3 回滚口径归档/删除显式生成文件 | 交易/paper/outcome 账本 digest 不变 |
| 调度 | 未接线；停止调度进程 + 设置 `--quote-source none`/dry-run 即停写 | 不产生新 confirmation |
| 服务 | 本单未启停服务；API 读取 status 为既有只读逻辑，无需重启即可显示（有文件即读） | 端口/服务不变 |

**风险点**：
1. `--quote-source snapshot` 有网络（新浪免费接口）；仅显式启用，失败 fail-visible
   （engine 返回 quote_unavailable，runner 退出码 1，不静默假绿）；
2. 快照无 prev → cross 条件 ambiguous（后续 provider 补前值/缓存推导）；
3. 单实例锁为 advisory 文件锁（非 OS 强制）；stale 锁需人工清理，不自动杀进程；
4. tick_count 依赖显式 status 文件续号；不写 status 时（dry-run）仅本次进程内计数；
5. status 文件为原子写（tmp+replace），API 读取侧已有坏文件/超限防御（既有实现）。
