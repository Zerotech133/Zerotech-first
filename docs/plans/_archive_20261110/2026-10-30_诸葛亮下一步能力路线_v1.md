## 四、推荐下一步（不要一次全做）

### 第 1 周：评估闸门 + trace 运营化

- 把现有 golden 扩到 50 条，接 `promptfoo`/`seat_eval` 到改 prompt/载体的流程；
- Phoenix trace 默认注入 8795（`PHOENIX_TRACE=1`）并补 token/成本字段；
- 验收：一次 prompt 变更自动出前后分数；trace 可按失败率筛选。

### 第 2 周：记忆 v1

- 先不装 Mem0，用现有 JSONL/SQLite 加“写入策略 + 过期 + 纠正 + 检索评测”；
- 只允许 lesson/preference/commitment 三类；默认关闭，显式开关；
- 验收：20 条记忆检索集命中 ≥90%、错误记忆可删除/过期。

### 第 3 周：采纳闭环

- 把 C1/C3 账本接上“建议→采纳/拒绝/回滚”；
- 周报展示采纳率、返工率、建议被忽略原因；
- 验收：每条建议有状态，可追到 decision_id。

### 第 4 周：受控外部取证

- MCP fetch 白名单 + 引用格式（URL/抓取时间/来源等级）；
- 外部内容一律视为不可信数据，不得当指令；
- 验收：3 个来源、无来源显式“未取得”、注入样本不改变系统行为。

### 第 2 个月：规划/反思 + 红队运营化

- LangGraph 最小工作流（只读）；
- promptfoo red team/PyRIT 定期跑，报告进周报。

### 第 3 个月：辩论/兵棋/成本路由（按需）

- 只做结构化建议，不做自动派单/执行。

## 六、本轮代码审计修复（附）

- `p0_trace`：失败调用设置 span ERROR + 记录异常；CLI 失败返回非 0；`force=True` 绕过失败负缓存。
- `zhuge_rag`：索引写盘改为临时文件 + `os.replace` 原子替换，避免并发读到半截 34MB JSON。
- `test_api_intel_graph`：`top_inst_group` 可见性告示按语义豁免问句断言，不放软禁词红线。
- 更早修复：静态页绕过、next 注入、OIDC state 绑定/MODE 关闸/registry 错误、红队 dry/空窗口、memory 默认值等。

## 七、结论

**诸葛亮下一步不该再加“会聊天”的能力，而该补“可验证的判断质量”。**

优先级一句话：

> **先评估闸门，再记忆运营，再采纳闭环，最后才是外部取证/规划/辩论。**

这四项做完，诸葛亮才从“工具齐全的军师”变成“判断可追溯、经验可复用、建议可验收的军师”。
