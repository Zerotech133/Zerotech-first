# 知识库每日推送准备 v1（飞书 payload · dry-run）

> 2026-11-01 · 目标：把每日「学习卡（5张）+ 今日简报 + 研报候选 + 门户入口」组装成**飞书交互卡片 payload**，
> 产出可人工审阅的推送快照；**本任务只准备 payload（dry-run），不接 webhook、不发送、不发起任何网络请求**。
>
> 安全边界：默认且唯一模式 = dry-run；真实发送属于「对外消息推送」能力，需按仓库审批纪律另立任务并完成 webhook 接线审批后实施。

## 一、数据流

```
portal/static/kb_learning_digest.json ──┐   （学习卡5张/简报摘要/策略结论）
portal/static/report_panel.json ────────┼──→ tools/kb_corpus/kb_daily_push.py build
portal/static/kb_daily_briefing.json ───┘   （digest 缺失时兜底）
                                                     │
                                    ┌────────────────┴─────────────────┐
                                    ▼                                  ▼
              research/reports/kb_daily_push_<date>.json    portal/static/kb_daily_push.json
              （当日推送快照，人工复核/存档）               （门户/后续推送消费者读取的静态副本）
```

- 输入全部为**已存在的门户静态 JSON**，脚本不触网、不调 LLM、不写其他页面；
- 输出两份内容相同的 JSON：research 快照按日期留档，portal 副本供后续接线使用。

## 二、输出 Schema

### 2.1 顶层字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `schema_version` | int | payload 版本（当前 1） |
| `date` | str | 推送日期 `YYYYMMDD`（`--date` 可覆盖，缺省取 digest.date/当天） |
| `generated_at` | str | 生成时间（ISO 带时区） |
| `dry_run` | bool | **恒为 true**（脚本禁止真实发送） |
| `network` | str | **恒为 `"none"`**（无网络请求） |
| `disclaimer` | str | 免责声明（必须含「不构成投资建议」） |
| `sources` | dict | 三路输入快照：`digest/panel/briefing` → `{path, exists, mtime, size}` |
| `summary` | dict | 推送摘要：title/headline/cards_count/candidates_count/reports_reviewed/rejected_count/strategy_takeaway/portal_links |
| `feishu_payload` | dict | **飞书 webhook payload**：`{msg_type: "interactive", card: Card 2.0}` |
| `card_text` | str | 纯文本降级版（飞书 text 消息/邮件/日志预览） |
| `meta` | dict | generator/network_calls=0/inputs_ok/fallbacks/out/portal_out/note |

### 2.2 飞书卡片结构（Card 2.0，与 `tools/approval_card.py` 同风格）

```json
{
  "msg_type": "interactive",
  "card": {
    "schema": "2.0",
    "config": {"width_mode": "default", "summary": {"content": "零界知识库日报 2026-11-01"}},
    "header": {
      "title": {"tag": "plain_text", "content": "📚 零界知识库日报 · 2026-11-01"},
      "subtitle": {"tag": "plain_text", "content": "DRY-RUN · 未发送（学习卡/简报/研报候选）"},
      "template": "blue"
    },
    "body": {"elements": [
      {"tag": "markdown", "content": "**日期**：2026-11-01\n**摘要**：…\n**策略结论**：…"},
      {"tag": "markdown", "content": "**📚 学习卡（每日 5 张）**\n1. **问题** 答案（出处）\n…5 张"},
      {"tag": "hr"},
      {"tag": "markdown", "content": "**🧠 研报候选**：N 个（评审 X 篇 / 拦截 Y 篇）\n- 标题（日期 · 页数 · 一致性）"},
      {"tag": "hr"},
      {"tag": "markdown", "content": "**🔗 门户入口**\n[📚 学习卡 / 今日简报](http://127.0.0.1:8734/kb_reports.html)\n[🧠 研报候选面板](http://127.0.0.1:8734/selection.html)\n[📊 知识入库状态](http://127.0.0.1:8734/kb_ingest.html)"},
      {"tag": "markdown", "content": "<font color='grey'>…不构成投资建议…</font>"}
    ]}
  }
}
```

要点：标题=知识库日报+日期；摘要=简报 headline + 策略结论 takeaway；**学习卡 5 张全量**；研报候选=panel.candidates（最多 5）；门户链接固定含 `/kb_reports.html` 与 `/selection.html`（附 `/kb_ingest.html`）；末尾强制免责声明。

## 四、接入飞书 webhook 的步骤与审批要求（**本次未接线**）

> 当前 `kb_daily_push.py` **没有 send 分支**。接入真实推送应另立任务，流程建议如下：

1. **通道确认（先读判例）**：飞书侧新能力选路遵循 `docs/plans/2026-10-14_飞书自建底座与Lark插件分工边界_K-STOCK-395.md`（**插件禁生产推送/禁常驻**）；复用既有发送通道 `news_collector/send_feishu.py`（`send_content(content, msg_type="interactive", kind=...)`），不新起常驻服务、不引入第三方 SDK。
2. **payload 人工复核**：用本脚本 `build --json` 产出卡片，人工确认标题/摘要/学习卡/候选/链接/免责声明；建议连续 2~3 天抽检。
3. **接线实现**：新增 `--send` 分支（默认仍 dry-run）：校验 `check` 全绿 → 调 `send_content(payload["feishu_payload"], msg_type="interactive")` → 记录发送结果；webhook URL/secret 只从既有配置或环境变量读取，**禁止明文入库**（过 `tools/scan_secrets.py` 门）。
4. **审批（L2，五要素一次一议）**：命令全文 + 影响面（发到哪个群/人、频率、失败重试）+ 不可逆点（消息不能撤回/会被转发）+ 替代方案（先发测试群）+ 回滚预案（关闭 `--send`/环境变量开关）。按 `AGENTS.md §7` 与 `K-STOCK-416` 治理规范取得人类明确批准；**沉默≠同意**。
5. **灰度与监控**：先发测试群 1~3 天 → 正式群；记录 `sent_at/ok/message_id/错误`；失败重试 ≤2 次、超限只告警不刷屏；内容为空（0 卡片且 0 候选）时**不发送**。
6. **定时化**：审批通过后可挂到 `tools/kb_corpus/daily_kb.py` 的编排链尾部（作为可选步骤，如 `--with-push`），或独立计划任务；**本任务未改 daily_kb.py**。

## 五、失败降级

| 场景 | 行为 |
|---|---|
| digest 缺失/损坏 | 学习卡为空、摘要降级为 briefing 兜底；`meta.inputs_ok=false`、`meta.fallbacks` 记录原因；payload 仍通过 schema 校验 |
| panel 缺失/损坏 | 研报候选为空，卡片显示「今日暂无进入候选的研报（详见门户）」 |
| briefing 缺失 | 仅在 digest 也缺时影响 headline；卡片显示「今日暂无新简报」 |
| payload 校验失败 | `check` 退出码 1，并逐条打印错误（如 dry_run 被篡改、缺免责声明、卡片元素缺失） |
| （未来接线后）发送失败 | 建议：记录错误→重试≤2→失败只告警；**不得阻塞**每日编排主链（推送是旁路） |

## 八、限制与后续

1. **未发送**：没有任何 send 分支/webhook 配置；真实推送需按 §四 走接线+审批。
2. **候选为空时是否推送**：建议接线时加「内容阈值」（例如 5 卡 + ≥1 候选才发；或仅简报变更时发），避免每日噪音。
3. **门户副本暂未被页面消费**：`portal/static/kb_daily_push.json` 目前仅作为后续消费者/排查用静态文件；如需页面展示需另立页面任务（不动其他页面）。
4. **未接入编排**：`daily_kb.py` 未改；后续可增可选步骤（`--with-push`）并保持「推送失败不阻塞主链」。
5. **链接 base URL**：默认 `http://127.0.0.1:8734`（本机门户）；若对同事/外部推送需换可访问地址（`--base-url`），并按对外信息规范审批。
