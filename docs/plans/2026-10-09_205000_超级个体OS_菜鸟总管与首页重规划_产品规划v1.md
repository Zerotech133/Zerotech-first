### 1.2 关键洞察

## 二、菜鸟总管设计（新首页核心）

### 2.1 定位

> **菜鸟 = 平行空间的自己**：不只是一个聊天框，是整个 AI 公司的 CEO 分身——组织团队、管理架构、分配任务、汇报结果、向老田（human）汇报与请求审批。

- 人格锚：`chief_of_staff`（org.json 已有）→ 升格 `ceo_avatar`；称呼/语气/记忆由四级记忆承载
- 运行锚：本地 qwen3.5:9b 默认（已验证判读质量），llm_binding 可切云端（字段已有，UI 暴露开关）
- 权限锚：对老田=汇报+请求审批；对部门 lead=派单（tasks 工单）；对 Agent=只读监督

### 2.2 新首页 = 菜鸟驾驶舱（三段式）

```
┌─────────────────────────────────────────────────┐
│ 🐣 菜鸟对话条（常驻）：自然语言指挥                  │
│    「今天各部门什么情况」/「让投研部看看XX票」/「批准」│
├─────────────────────────────────────────────────┤
│ 📊 公司驾驶舱：五部门状态灯                          │
│  量化交易部●绿  情报中枢●绿  自媒体部●黄  研发部○灰  │
│  运维部●绿     （点部门→该部详情页）                 │
│  今日要事：4d 首跑✓ / 裁决窗倒计时 / 影子 Day3       │
├─────────────────────────────────────────────────┤
│ ✅ 待老田审批（菜鸟代收）：任务单 / 雇佣申请 /        │
│    裁决窗决议 / 异常告警（P0 即时）                  │
└─────────────────────────────────────────────────┘
```

- 技术形态：**新文件 `portal/home.html` + `/api/home_*` 轻接口**（投影只读模式，同 portal_status 纪律），不进 portal_api.py 巨石；菜鸟对话后端走 agent_platform a0_agent.py 扩展
- 菜鸟四类意图路由（一期）：
  1. **查**（只读）→ 投影 API：账本/排名/新鲜度/组织状态
  2. **派**（写任务单）→ engine/tasks.py 七态工单
  3. **审批**（转呈老田）→ pending 列表 + 一键批
  4. **问**（知识）→ KG + 记忆检索 + 新闻详情
- 二期再扩：多轮上下文 / 主动汇报（P0 即时） / 菜鸟自己写日报

## 四、松耦合架构四原则（强规范）

1. **注册表存源**：一切配置（org/hires/团队/模型绑定）= JSON 文件 + git 跟踪 + 单写入口 API + 页面只读投影（hires.json 已验证的模式，全面推广）
2. **契约先行**：跨模块只认数据契约（poc\_* picks 协议 / D1 schema / tasks 工单），不互相 import 内部实现——新增源/账本/部门零引擎改动（041/042 已验证）
3. **适配器隔离**：外部世界（行情源/模型/推送）一律 adapter 层（qd/qpzm/us_market 模式）——换源不动引擎；**模型接入同理**：llm_binding 三段式 + provider adapter
4. **投影只读**：所有门户页 = 只读投影（portal_status 模式），写操作走显式 API + 鉴权（\_MUTATION_POSTS 模式）；**新功能新文件**，portal_api.py 巨石冻结增量

## 五、一致性规范（老田点名的标准化流程）

### 5.1 资产详情标准（一只股票进去怎么展示）

**全站统一股票详情卡 `/kg/stock/{code}`**（页面已存在，推广为唯一样式），五区固定：

```
① 行情区   最新价/涨跌/分时K（数据源标注+新鲜度时间戳）
② 信号区   各策略源对该票的全部信号（双刀/青萍/9dim/缠论，含 conf 与日期）
③ 账本区   各模拟盘该票持仓/成本/盈亏/止损（多账本并列）
④ 事件区   该票 KG 事件时间线（利好/利空/公告，溯源链接）
⑤ 新闻区   相关新闻列表 → 点开进「内容流水线」（5.2）
```

任何页面出现股票代码 → 统一链接到详情卡；新增页面必须复用该卡组件。

### 5.2 内容流水线标准（新闻 → 详情 → OCR → 数仓）

```
采集（news_collector，已跑）
 → 去重与溯源登记（source/url/时间戳，可溯）
 → 详情落盘（原文归档，knowledge_docs/）
 → OCR/抽取（本地 bge-m3 + qwen 结构化抽取，输出 JSON schema：
    {doc_id, entities[], event_type, sentiment, key_facts[], ts}）
 → 结构化入数仓（带 lineage 字段：源 URL→文档→结构化记录 三级可溯）
 → KG 事件索引（图谱可见）→ 菜鸟/情报简报可引用
```

每一步**产物可溯、失败可重跑、schema 版本化**——现状是采集厚、抽取管道散，此为情报中枢首个工程化任务。

### 5.3 模型接入标准

- `llm_binding = {provider: ollama|claude|..., model, params}` 三段式，org.json 每个 agent 独立声明
- 换模型只改注册表一行；上线前**实测推理时长**（35b 教训已入册）；降级链路显式（A0：9b 本地，云端作 backup_binding）
