# 评测集资产管理 v1（研报检索 search_v2）

- 日期：2026-11-01
- 支线：wave14 / task-42（AP：冻结评测集 v2 资产化）
- 关联规范：[检索评测标注规范 v1](2026-11-01_检索评测标注规范_v1.md)
- 资产目录：`research/reports/eval_sets/`
- 工具：`tools/kb_corpus/eval_registry.py`（freeze / verify / list / load）

## 1. 原则

1. **冻结不可变**：评测集一旦 freeze 生成资产，其内容（标注、查询、语法）不可原地修改；
   任何标注变更必须**新建版本**（v3、v4…），旧版本资产保留用于结果对照。
2. **内容可校验**：资产带 `content_hash = sha256(规范化内容)`，任何字节级改动都会导致 verify 失败；
   时间戳（`frozen_at`/`updated_at`）不参与 hash，保证重复导出 hash 稳定。
3. **规范先行**：freeze 前按《检索评测标注规范 v1》校验（n≥60、每查询 ≥1 个 grade-2、题型覆盖与配额），
   不合规拒绝入库（CLI 返回非 0）。
4. **只读导出**：资产从 `eval_search_v2_ext2.all_queries()` **只读**导出；不修改源数据。
5. **结果可追溯**：评测报告引用 `set_id + content_hash`，保证「哪一版评测集得出的结论」。

## 2. 资产 schema（schema_version = eval_set.v1）

```json
{
  "schema_version": "eval_set.v1",
  "set_id": "eval_set_20261101_v2",
  "version": 2,
  "name": "研报检索评测集 v2（89 条，分级标注 2/1/0，冻结）",
  "frozen_at": "2026-11-01T...+08:00",
  "source": "eval_search_v2_ext2.all_queries()（wave10 冻结 89 查询，未重新标注）",
  "n_queries": 89,
  "type_distribution": {"主题": 44, "AND": 10, "同义词": 8, "OR": 8, "短语": 6, "排除": 5, "短查询": 5, "长查询": 3},
  "annotation_policy": {"policy_ref": ".../检索评测标注规范_v1.md", "grades": {...}, "frozen": "...", ...},
  "queries": [
    {"id": "Q01", "q": "量柱分类", "type": "主题", "source": "wave9",
     "graded": {"2": ["量柱"], "1": ["量学", "涨停"]},
     "expected_units": [{"unit": 1, "grade": 2}, {"unit": 0, "grade": 1}]}
  ],
  "content_hash": "sha256(规范化内容) = 1fa417f9…"
}
```

- `expected_units`：由标注关键词在 498 单元文本上展开（unit=单元索引，grade=2/1），
  供审计/复算，评测时不反向依赖检索器结果；
- hash 覆盖 `schema_version/version/set_id/annotation_policy/queries` 五部分（sort_keys 紧凑 JSON）。

## 3. manifest（research/reports/eval_sets/manifest.json）

记录当前所有版本的索引：

| 字段 | 说明 |
|---|---|
| version / set_id / file | 版本号、资产 id、文件名 |
| content_hash | 资产内容 sha256 |
| created_at | 冻结时间 |
| n_queries / type_distribution | 规模与语法分布 |
| source / annotation_policy_ref | 来源与标注规范版本 |
| validation_ok | freeze 时规范校验是否通过 |

## 4. 版本管理流程

```
① 新增/变更标注（按规范 v1：先声明后标注、冻结前不得看检索结果调参）
      ↓
② 在代码/数据源中形成新查询集（不改旧资产）
      ↓
③ python tools/kb_corpus/eval_registry.py freeze --version <新版本号>
      → 导出 eval_sets/eval_set_<日期>_v<N>.json + 更新 manifest（校验不过则拒绝）
      ↓
④ python tools/kb_corpus/eval_registry.py verify       # hash/结构/规范复核
      ↓
⑤ 评测报告引用 set_id + content_hash；结论标注所用版本
      ↓
⑥ 冻结后只读：如需修正标注 → 回到 ①，生成 v<N+1>，旧版本保留
```

**新增评测集步骤（操作清单）**：

1. 更新 `eval_search_v2_ext2.py`（或新数据源）中的查询/标注，先跑规范自检；
2. `eval_registry.py freeze --version <N+1>`（自动校验 n≥60/grade-2/题型配额，失败退出非 0）；
3. `eval_registry.py verify` 全绿后，才允许用新版本跑对比评测；
4. 在对应评测报告 MD 中写入 `set_id`、`content_hash`、版本号与规范版本；
5. 禁止修改已 freeze 的 `eval_set_*.json`、`manifest.json` 中历史条目（manifest 只追加新版本）。

## 5. CLI

```powershell
C:\项目\py312\python.exe -X utf8 tools/kb_corpus/eval_registry.py freeze
C:\项目\py312\python.exe -X utf8 tools/kb_corpus/eval_registry.py verify [--file xxx.json]
C:\项目\py312\python.exe -X utf8 tools/kb_corpus/eval_registry.py list
C:\项目\py312\python.exe -X utf8 tools/kb_corpus/eval_registry.py load --version 2 --summary
```

- `freeze`：只读导出 + 算 hash + 规范校验 + 写资产与 manifest（校验失败返回 1）；
- `verify`：单文件或目录全量校验（hash 不匹配 / 结构缺失 / 规范不达标都会报错）；
- `list`：读取 manifest 列出全部版本；
- `load --version N`：加载资产并默认校验 hash；`--no-verify` 仅调试用。

## 6. 规范校验清单（freeze/verify 强制执行）

| 校验项 | 规则 |
|---|---|
| 规模 | n ≥ 60 |
| 分级标注 | 每条查询 grade-2 关键词 ≥1；grade 只允许 {2,1}；关键词非空且不重复 |
| 题型覆盖 | 主题 / 同义词 / AND / OR / 短语 / 排除 均存在 |
| 题型配额 | 主题 ≥40%n；同义词 ≥8；AND ≥8；OR ≥8；短语 ≥4；排除 ≥4；短查询 ≥3；长查询 ≥3 |
| 唯一性 | id、查询文本不重复 |
| expected_units | 每条查询展开非空（审计用） |
| hash | 重算 sha256 == 存储 content_hash |

> 题型分布 主题44/AND10/同义词8/OR8/短语6/排除5/短查询5/长查询3，校验通过。

## 7. 局限与后续

- 资产为 JSON 单文件（约 160KB，含 expected_units 展开），未做压缩/分片；如评测集扩到数百条可考虑分片；

- 后续建议：把 `eval_registry.py verify` 接入 CI/test_gate；评测报告自动带 set_id+hash 头部。

- `header_json(set_version)` → 可直接嵌入评测报告 JSON 的 `meta.eval_set`；
- CLI：`eval_report_header.py header --version 2 [--format markdown|json]`、`list`；
- 建议后续所有评测报告（wave9/10/12 等）在生成时统一调用 `make_header`，报告头部固定携带 `set_id + content_hash + annotation_policy_ref`，实现结论可追溯。
