## 1. 三件套规范（所有写门户静态 JSON 的脚本必须遵守）

| # | 要求 | 实现要点 |
|---|---|---|
| 1 | **写前备份** | 目标已存在时，写前 `shutil.copy2` 到 `research/reports/backups/<name>.<ts>.bak.json`（时间戳含微秒防撞）；备份后立即校验备份 sha == 写前目标 sha，不一致则中止 |
| 2 | **读-合并-写** | 先读旧文件（容忍缺失/损坏），按业务主键合并，保留旧记录与旧顶层未知字段；禁止整文件替换 |
| 3 | **原子写** | 同目录 `<name>.tmp` 写入 + `flush`/`fsync` + `os.replace` 原子替换；任何异常清理 tmp |
| 4 | **sha/条数校验** | 序列化后记录 sha256；写 tmp 后校验 tmp sha + 合法 JSON；落盘后校验目标 sha 与条数（与合并后期望一致）；失败回滚备份/抛错，不覆盖目标 |

统一返回报告字段（`safe_write.v1`）：
`schema/path/backup/sha_before/sha_after/counts_before/counts_after/merged_added/merged_kept/read_errors/atomic/tmp_removed`。

## 2. 两个脚本的改法

### 2.1 morning_brief_push.py（h18_watch.json）

- 新增 `safe_write_json()` + `_merge_watch()` + 公开 `merge_watch_payload()`；
- 合并主键：**items 按 `(ts_code, ann_date)`**——新数据优先、旧独有项追加保留；
  顶层旧未知字段保留，`generated_at/date/items` 以新为准；
- `refresh()` 末尾写 `WATCH` 改为 `safe_write_json(WATCH, payload, merge_fn=_merge_watch, counts_fn=_watch_counts)`；
- `selection_daily.json` 当前只读（由 `tools/research/selection_daily.py` 写）；
  预留 `_merge_selection_daily()`（按 `date` 顶层、`picks` 按 `(ts_code/code, date)` 合并），未来写入时复用；
- CLI/接口不变：`main([--send] [--refresh])`、`build_text()`、`refresh()` 返回值均不变。

### 2.2 panel_export.py（report_panel.json）

- 新增 `safe_write_json()` + `merge_panel_payload()` + `_panel_counts()`；
- 合并主键：**report_id**（缺失退化 id/title/date）——`reports/candidates/rejected/page_issues/review.items`
  分别按主键合并；新数据优先并保留其顺序，旧独有行（历史研报/被拒记录/复核项）追加保留；
- 顶层旧未知字段保留；`summary` 已知字段新优先，`reports/candidates/rejected` 计数按合并后重算；
- `export_panel()` 写盘改为 `safe_write_json(..., merge_fn=merge_panel_payload,
  validator=validate_portal_payload, counts_fn=_panel_counts)`；写后返回**合并后**门户 payload；
  `SafeWriteError` 转 `PanelExportError` 以保持 CLI 错误路径不变；
- CLI 不变：`export [--input --out --check]` / `check [--out]`，输出格式不变。

### 5.1 统一工具 `tools/kb_corpus/safe_json.py`

```python
from safe_json import backup_then_atomic_write, SafeJsonError
report = backup_then_atomic_write(path, payload, backup_dir=None, validator=None)
```

- **写前备份**：目标已存在时 `copy2` → `research/reports/backups/<stem>.<%Y%m%d_%H%M%S_%f>.bak.json`，校验备份 sha == 写前目标 sha（不一致抛错、不继续）；
- **原子写**：同目录 `.<name>.<pid>.<rand>.tmp` → `flush`/`fsync` → `os.replace`；异常清理 tmp；
- **校验**：序列化后立即 `json.loads`（不可序列化/非法结构 → 抛错、目标/备份均不动）；写入前调用可选 `validator(parsed)`（业务校验失败 → 抛错、目标不动）；落盘后再次解析目标，失败自动回滚备份（若存在）；
- **返回报告**（`safe_write.v1`）：`schema/ok/path/backup{path,sha256,bytes,source_sha256}/sha_before/sha_after/bytes/atomic/tmp_removed/validated/written_at`。
