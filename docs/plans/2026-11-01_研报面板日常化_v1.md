## 1. 目标与边界

把「手动 `python tools/research/panel_export.py export`」升级为可定时执行的日常任务：**刷新门户静态 JSON → 校验 → 记状态 → 输出变更摘要**。

- 不修改 `panel_export.py` 与 `selection.html`，运行器通过 importlib 复用其构建（`build_portal_payload`）与校验（`validate_portal_payload` / `check_portal_json`）函数；
- 不改门户 API/路由，不重启任何服务，不改其他页面；
- 只写三个路径：`portal/static/report_panel.json`（数据刷新）、`research/reports/report_panel_daily_status.json`（状态台账）、临时 `.tmp`（原子写中间文件）。

## 2. 运行方式

```powershell
# ① 日常刷新（发布门户 JSON + 校验 + 台账 + 变更摘要）
C:\项目\py312\python.exe -X utf8 tools\research\panel_daily.py run

# ② 巡检模式（定时任务用：只校验现有门户 JSON，不重写；源文件更新则提示 stale）
C:\项目\py312\python.exe -X utf8 tools\research\panel_daily.py run --check-only

# ③ 干跑（只构建+校验，不写门户文件，仍记台账）
C:\项目\py312\python.exe -X utf8 tools\research\panel_daily.py run --dry-run

# 可选路径覆盖（默认值即上表）
... run --source research/reports/report_panel_v3_20261101.json \
         --portal portal/static/report_panel.json \
         --status research/reports/report_panel_daily_status.json
```

退出码：`0`=成功（门户 JSON 已发布/校验通过）；`1`=失败（源缺失、构建校验不通过、发布后校验不通过、check-only 时门户 JSON 缺失或损坏）。

输出示例（本次实测）：

```

[panel_daily] candidates=1 rejected=2 reports=3 page_invalid=1 generated_at=2026-11-01T08:09:36+08:00

[panel_daily] change: 候选 1→1（Δ+0）；页码越界 1→1（Δ+0）
```

## 3. 状态台账（`research/reports/report_panel_daily_status.json`）

结构：`{"schema_version":1,"updated_at":...,"runs":[...],"latest":...}`；`runs[]` 保留最近 60 条（可 `max_runs` 调整），`latest` 为最新一条，便于门户/巡检直接读。

每条 run 记录：

| 字段 | 说明 |
|---|---|
| `run_at` / `mode` / `ok` / `errors` | 运行时间、模式（`run`/`check_only`）、成功与否、失败原因 |
| `source` / `source_meta` | v3 面板 JSON 路径 + 文件 mtime/size |
| `portal` / `portal_meta` | 门户 JSON 路径 + 发布后 mtime/size |
| `source_generated_at` | 上游面板生成时间（数据新鲜度依据） |
| `candidates` / `candidate_ids` / `rejected` / `reports` | 候选数/候选 ID、被拦截数、评审篇数 |
| `page_invalid_facts` / `legacy_union_invalid_facts` | 精确页码越界数、v2 宽口径对照 |
| `review_checkboxes` | 人工复核待勾选位数量 |
| `disclaimer_ok` | 免责声明字段完整性 |
| `validation` | `{ok, errors, checked_at}`（复用 panel_export 校验：必需字段/免责声明/候选长度一致） |
| `change` | 与上次运行对比：候选 prev/cur/Δ、added/removed、页码越界与被拦截变化 |
| `stale` / `stale_note` | 仅 check-only：源文件比门户 JSON 新时提示需跑一次 run |
| `elapsed_seconds` / `dry_run` | 耗时与干跑标记 |

变更摘要规则：候选按 `candidate_ids` 集合求新增/移除；页码越界/被拦截数按计数差；`has_prev=false` 表示首次运行。差异文本会提示「页码越界增加，需人工复核」。

## 4. 定时建议（仅建议，未创建计划任务）

| 频率 | 命令 | 用途 |
|---|---|---|
| 每个交易日 08:30（或上游 v3 面板生成后） | `panel_daily.py run` | 发布当天候选 + 记录变更 |

| 面板数据更新后（手动触发） | `panel_daily.py run` | 立即刷新门户展示 |

```powershell

  "C:\项目\py312\python.exe -X utf8 C:\项目\老田的AI助手\tools\research\panel_daily.py run" /F
```

建议在任务后追加一条串联命令做巡检：`run ; if ($LASTEXITCODE -ne 0) { ...告警... }`，失败即告警（面板 JSON 不会被坏数据覆盖，旧数据继续展示）。

## 5. L2 说明：静态页无需重启 8091

- `portal/static/report_panel.json` 是**静态文件**：门户静态资源由 nginx/静态文件服务直接按路径读盘返回，Python 侧 `portal_api.py`（8091）不负责编译/缓存该 JSON；
- `selection.html` 里的 `fetch('/static/report_panel.json?ts=...')` 带时间戳参数，浏览器不会命中旧缓存；
- 因此 `panel_daily.py run` 写盘成功后，**浏览器刷新 `http://127.0.0.1:8734/selection.html` 即看到新数据，不需要重启 8091**；只有修改 Python API/路由/模板代码时才需要重启 8091；
- 本流程仅做本地文件写入（数据发布），不重启服务、不改端口/配置/计划任务，属 **L2 级本地文件操作**，按 AGENTS.md 无需人工审批；发布校验失败时退出非 0，不覆盖旧门户 JSON。
- 验证方式：`Invoke-WebRequest http://127.0.0.1:8734/static/report_panel.json` 应 200 且 JSON 含 `disclaimer`；页面 `http://127.0.0.1:8734/selection.html` 200。
