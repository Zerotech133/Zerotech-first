# docs/plans/ · 现行方案与计划归置区

本目录存放**仍在生效**的方案、计划、路线图、设计稿。判断标准：文件描述的是"接下来要做什么"，
读它的人是为了照着执行，而不是为了追溯某次判断的依据。

## 一、收录范围

- 自 2026-10-18 起，所有新产出的现行方案稿（研发方案、路线图、优先级、施工设计、立项草案）直落本目录。
- 2026-10-18 前已在库的历史计划件保持原位、原文件名不动，不做批量重命名。
- 已被新版取代的旧稿不移出本目录，仅在文件头部加取代注记（见《2026-10-18_文档直落新规.md》⑤）。

## 二、命名规范

- 格式：`YYYY-MM-DD_主题.md`，日期为首选归档日，主题用中文短语，不含空格。
- 主题相同的同日多份文件，可加序号或版本后缀区分，如 `..._路线图v2.md`。
- 图纸类附属件（`.mermaid`）与主文档同名同前缀，成对存放。

## 三、与 docs/audit/ 的分工

| 目录 | 收什么 | 判断问句 |
|---|---|---|
| `docs/plans/` | 现行方案、计划、路线图、设计稿 | 这份文件是我**接下来要照做**的吗？ |
| `docs/audit/` | 取证、审计、盘点、复盘、一次性报告、裁决依据 | 这份文件是**某次判断的证据**吗？ |

同一件事的两类产物分开存：方案进 plans/，对该方案的审计结论进 audit/，互不替代。

## 四、本目录的维护约定

- 新增文件必须能被 `docs/PROJECT_DOCUMENTATION_INDEX.md` 索引到，或在同批次补录索引。
- 归位类副本须在头部注明"与原件一致、仅作仓内归档"，避免与仓库外原件形成双版本漂移。
