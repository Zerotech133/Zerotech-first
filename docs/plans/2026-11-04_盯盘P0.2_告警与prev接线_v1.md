## 一、两条缺口与本次补法

| 缺口 | 补法 |
|---|---|
| G4：engine 命中后没有写 `watch_alerts` | runner 对每个 `triggered` result 调 `watch_alerts.emit_event`：显式 alert 账本才写；默认 **dry-run + dispatch not_sent**（不接 Feishu、不推送） |
| G3：snapshot provider 无 prev → cross 条件永远 ambiguous | `SnapshotProvider` 在**同一 runner 进程内**缓存 symbol→上次 last；下一 tick 给 quote 注入 `prev`；首轮无 prev → 仍 ambiguous（不猜） |

数据流（一次 tick）：

```text
watch_runner.run_once
  ├─ engine.evaluate_once(...)              # 既有：armed plan → 条件 → consumer.trigger_plan
  │     └─ results[*].status == "triggered" # 命中且已建 pending 确认
  ├─ apply_alerts(status, alert_ledger)     # 本单新增
  │     ├─ 从 result + plan.conditions 构造 watch_alert/v1（action/observed/threshold/quote_as_of）
  │     ├─ 有 --alert-ledger/env → emit_event(ledger_path, dry_run=False)（去重落账）
  │     └─ 无账本 → emit_event(dry_run=True)（返回事件/回执，不落盘，dispatch=not_sent）
  └─ 把 alerts_* 计数补写回显式 --status 文件（原子重写；dry-run 不写）
```

## 二、alert 接线规则

- 启用方式（二选一，均可选）：
  - CLI：`--alert-ledger <watch_alerts.jsonl>`；
  - env：`WATCH_ALERT_LEDGER_PATH`（CLI 未给时读取）。
- **默认不写**：未给账本 → 每个 triggered 结果仍构造事件并走
  `watch_alerts.emit_event(dry_run=True, ledger=None)`，返回 `status=dry_run`、
  dispatch 恒 `not_sent`（本模块无网络/无 Feishu）。
- **字段来源**：`plan_id/symbol` 取 engine result；`action` 取 plan conditions
  （BUY/SELL/买/卖等归一为 BUY/SELL，缺省 `watch`）；`observed`/`threshold` 取 result
  （十进制字符串规范化）；`quote_as_of` 取本次 tick 时间（status.last_tick_at）。
- **去重**：由 `watch_alerts.dedupe_key = sha256(plan_id|symbol|action|observed_bucket)`
  保证同事件同账本只写一行；重复 run 时 plan 已 `triggered`（engine 不再命中），
  正常不会重复；人工重放同一 status 结果 → `alerts_deduped` 计数（测试覆盖）。
- **失败可见**：事件构造/落账/分发异常 → `alerts_failed += 1` + `alert_errors[]`
  （code/message），不阻断 runner、不静默；runner 退出码仍按 engine 结果。
- **范围限制**：`watch_alert/v1` 的 `threshold` 必须标量；`range` 条件命中时
  threshold 是 `[lo, hi]` → 该结果记 `alerts_failed`（code `unsupported_threshold`），
  不伪造标量阈值（后续如需要可扩展 alert 契约）。

## 三、snapshot prev 跨轮缓存

- `build_provider("snapshot")` 返回 `SnapshotProvider`（不再是无状态函数）：
  - 每次 tick 调 `_snapshot_quotes(symbols)`（网络；测试 monkeypatch）；
  - 缓存本进程内 `symbol → 上一次合法 last/price/close/...`；
  - 下一 tick 若 quote 未带 `prev`：注入 `prev = 缓存值`；
  - quote 自带显式 `prev` 时不覆盖；只有拿到合法当前价才更新缓存；
  - **首轮无 prev** → 引擎 cross 条件按 `condition_ambiguous` 处理（不猜）；
  - `--once` 单轮保持现状（没有上一 tick，因此单轮 cross 仍 ambiguous）；
  - 缓存只在进程内：runner 重启后首轮重新 ambiguous（可后续做跨进程持久化）。
- `quotes-json`（离线 fixture）/`none` provider 行为不变（无跨轮 prev）。

## 四、status / summary 新增 alert 计数

engine status 文件（显式 `--status`）与 runner summary 增加（engine 本身不改，由 runner 补写）：

| 字段 | 含义 |
|---|---|
| `alerts_enabled` | 是否配置 alert 账本（bool） |
| `alert_ledger` | 账本路径（未配置 null） |
| `alerts_emitted` | 写入账本事件数（written） |
| `alerts_deduped` | 账本已有同 dedupe_key、未重复写（duplicate） |
| `alerts_dry_run` | 无账本时构造但未落盘的事件数 |
| `alerts_not_sent` | dispatch.status=="not_sent" 的事件数（MVP 恒为已处理事件数） |
| `alerts_failed` | 构造/落账/分发失败数 |
| `alert_errors` | 前 10 条失败 `{plan_id, code, message}`（fail-visible） |

runner summary 额外有 `alerts` 子对象（累计 + enabled/ledger/errors）和同名顶层累计字段；
`last_status` 保留本 tick 计数。

## 七、接线项（Lead）与残余

1. **真实分发未接**：dispatch 恒 `not_sent`；Feishu/真实通知需 L2（凭据/白名单/限频/
   回执对账/去重 TTL/回滚演练）另单立项，本单不推送。
2. **alert 账本生产路径**：建议 `WATCH_ALERT_LEDGER_PATH=agent_platform/data/watch_alerts.jsonl`
   与 `--alert-ledger` 同路径；未配置时保持 dry-run 零写。
3. **range 条件 alert**：watch_alert/v1 threshold 为标量；range 命中会记 `alerts_failed`
   （unsupported_threshold），如要覆盖需扩展 alert 契约（另单）。
4. **snapshot 网络**：`--quote-source snapshot` 仍是显式网络入口（新浪快照）；cross 依赖
   prev 缓存，首轮/单轮 ambiguous 为诚实语义；跨进程续 prev 需后续持久化（未做）。
5. **调度**：interval/常驻仍由调度器接线（L2 审批）；本单未建计划任务、未启停服务。
6. **人工门不变**：engine 只建 pending confirmation；approve/reject 仍走 `/api/sim/confirm`。

## 八、回滚预案

| 层 | 动作 | 验证 |
|---|---|---|
| 代码 | `git revert <commit>`（仅 watch_runner 改动 + 测试/本文件） | 既有 watch_runner 16 tests + engine 43 tests rc0；alert 不再写、snapshot 回无状态 |
| 数据 | 本单不写生产；如已接 alert 账本，删除/归档显式生成 `watch_alerts.jsonl`（append-only）即可 | confirmation/paper/outcome 账本 digest 不变 |
| 调度 | 未接线；停调度或加 `--dry-run` 即停写 | 不产生新 confirmation/alert |
| 服务 | 本单未启停服务 | 端口/服务不变 |

**风险点**：
1. alert 账本与 trigger/plan 账本一样为 append-only；去重只按 dedupe_key（同档 observed 2 位小数），
   同 plan 不同价格档会产生不同事件（预期）；
2. snapshot prev 缓存只在 runner 进程内，重启/单轮 → 首轮 ambiguous（不猜）；
3. alert 失败不阻塞触发（fail-visible 而非 fail-fast）——保证 paper 链路可用性，
   但需监控 `alerts_failed`；
4. status 文件由 engine 先写、runner 再原子重写补 alert 计数（同一 tick 两次原子写，窗口极小）；
5. 真实分发/告警限频未实现，禁止在没有 L2 审批前接 Feishu。
