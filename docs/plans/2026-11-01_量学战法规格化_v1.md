## 三、Schema（v1，每个 YAML 顶层字段）

| 字段 | 类型 | 必填 | 说明 |

| `name` | str | ✅ | 中文战法名（沿用 registry 名称，必要时补全别名） |
| `source` | str | ✅ | 书名：《伏击涨停（修订升级版）》/《涨停密码（修订升级版）》 |
| `chapter` | str | ✅ | 章节；跨章战法列出全部相关章（如「第10–13章」） |
| `page_start` / `page_end` | int | ✅（与 `evidence_page` 至少一组） | **印刷页码**区间（书内页脚页码） |
| `evidence_page` | int | ✅ | **OCR 全文页序**（`=== 第N页 ===` 的 N），用于回查原文 |
| `evidence_quote` | str | ✅ | 原文短引文（生成时已做「去空白后必须是该 OCR 页子串」校验） |
| `type` | enum | ✅ | `形态` / `事件` / `过滤器` / `概念` |
| `computability` | enum | ✅ | `A`=日线 OHLCV 可直接计算；`B`=需画线/次级算法/人工判读；`C`=概念框架/需多基因组合 |

| `exit_rule` | str | ✅ | 持有期/止损/止盈规则 |
| `test_status` | enum | ✅ | `tested_rejected` / `tested_backtested` / `untested` / `concept` |
| `tested_ref` | str\|null | ✅ | 已测时指向研究报告路径（相对仓库根，必须存在）；未测/概念为 `null` |
| `h_ids` | list[str] | ✅ | 关联假设编号（如 `["H29"]`）；无则 `[]` |
| `notes` | str | ✅ | 原文摘要 + **简化定义** + 已测结论（多行 block） |
| `updated_at` | str | ✅ | `YYYY-MM-DD` |

### 3.1 页码约定（重要）

- `page_start`/`page_end` 一律写**书的印刷页码**（书内页脚 = 目录页码，便于人工翻 PDF 对照）。
- `evidence_page` 写 **OCR 文本的页序号**，两者换算关系经逐页核对：

| 书 | 换算 | 例 |
|---|---|---|
| 伏击涨停 | OCR 页 = 印刷页 + 18 | 第8章印刷 73 页 → OCR 第 91 页；黄金柱印刷 74 页 → OCR 第 92 页 |
| 涨停密码 | OCR 页 = 印刷页 + 20 | 第12章印刷 110 页 → OCR 第 130 页；第4章印刷 27 页 → OCR 第 47 页 |

- 例外：两书前言/序言用罗马数字页码，`evidence_page` 直接给 OCR 页序（如「量柱七形态」序言证据为 OCR 第 6 页；「涨停基因」前言为 OCR 第 8–9 页）。
- 校验时可这样回查：

```powershell
# 看「黄金柱」证据页（OCR 92 页）
> STATUS: declared（active：规格库 v1 交付（24 YAML + 校验 CLI + 10 测试，研究用非策略/非买入信号），strategy_registry 回填为后续建议；2026-11-01 PLANSTAT 补标）


C:\项目\py312\python.exe -X utf8 -c "import re,pathlib; t=pathlib.Path(r'C:\项目\PDF\_ocr\伏击涨停(2).txt').read_text(encoding='utf-8'); p=re.split(r'=== 第(\d+)页 ===\s*$', t, flags=re.M); print(p[2*92-1][:500])"
```

### 3.2 「简化定义」纪律

原书大量定义依赖画线、分时、人工辨柱，无法直接计算。每个 YAML 的 `notes` 里有明确的
`简化定义：` 段落——说明该战法被简化成了什么可计算口径；`params` 中所有阈值都可在该段找到依据。
**引用方不得把简化口径当作原书定义**；一旦回测发现口径歧义，回到 `evidence_page` 对照原文修订。

### 3.3 文件命名 / ID 规则

- 文件名：`^\d{3}_[^/\\]+\.yaml$`，三位序号 = `id` 中的 `nn`（`LX02_*` → `002_*.yaml`）。
- `id` 正则：`^LX\d{2}_[A-Z0-9_]+$`；校验器强制 id 唯一、序号与文件名一致。
- 新增规格必须同时更新 `EXPECTED_COUNT`（`tools/research/strategy_specs.py`）、测试中的 `EXPECTED`/状态分布断言与本文档。

**结论落到规格字段上的含义**

- 6 个 tested 规格的 `test_status` 一律为 `tested_rejected`，`tested_ref`/`h_ids` 指向报告与假设编号，`notes` 记录数值——因子库读到 `tested_rejected` 时**只能用于反向/规避研究或过滤器证据，禁止当买入信号**。
- H28 已探索「反向规避」容量：规避组合年化超额 **-1.52%**（日频 t=-0.84；OOS t=-3.19），**不构成可用策略**。因此量学规格目前的正确定位是：**知识/特征框架 + 反向风险标注**，而非 alpha 来源。
- H29 的教训（PIT/前视撤回）已固化进本规格：所有 `entry_rule` 必须写明确认日与入场时点（如黄金柱「T+3 收盘确认、T+4 入场」），禁止把后 3 日信息放到 T 日。

### 6.3 接入约定（给因子库/策略库/Agent）

1. **params 是唯一调参入口**：因子函数从 YAML `params` 读阈值，不把魔法数字写死在代码里；改参数必须回写 YAML 并更新 `updated_at`。
2. **entry_rule/exit_rule 是人/LLM 可读伪代码，不是可执行 DSL**：因子实现须单独写函数、自己做 PIT 对齐；不要把 `entry_rule` 字符串交给 `eval`。
3. **状态门禁**：`untested` → 仅研究脚本可用；`tested_rejected` → 反向/规避/过滤器证据；`concept` → 特征映射框架，不单独出信号；`tested_backtested`（目前 0 项）才可进策略候选。
4. **可计算化分级使用**：A 级（9 项）优先做因子回测；B 级需先补画线/王牌柱识别算法；C 级（5 项）作为 LLM 知识检索与组合框架，不直接量化。
5. **证据链**：任何引用必须能落到 `tested_ref`（报告）或 `evidence_page + evidence_quote`（原书 OCR），便于复核。
6. **命名建议**：因子/特征命名 `lx_<id_slug>_<feature>`（如 `lx_golden_pillar_top_hold`），参数来自对应 YAML。
