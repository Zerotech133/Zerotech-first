## 1. 背景与问题

旧检索器 `tools/kb_corpus/kb_reports_search.py`：
- 只对 **concept/claim** 两个字段做中文 bigram 重叠计数（BM25-lite），evidence/chapter 不参与；
- 无同义词/别名：查「太阳能」找不到「光伏」单元、查「IDC」找不到「数据中心」单元（实测 v1 precision@5=0.76）；
- 无 AND/OR/短语语法，多词查询退化为「词袋重叠」，容易召回跑偏；
- 结果平铺，无按书/章节聚合，长报告难以按章节定位。

## 2. 目标与验收

| 目标 | 验收 |
|---|---|
| 多字段加权（concept/claim/evidence/chapter，权重可配） | CLI `--weights-json` + 默认权重；测试 `test_weighted_fields` |
| 同义词/别名扩展（20 组常用词，数据放 JSON） | `synonyms_v2.json` 22 组；测试 `test_synonym_expansion` |
| 短语 / 多词 AND / OR / 排除 | `parse_query` + `test_query_syntax_and_semantics` |
| 按书/章节分组 + 相关度打分 | `group_results` + `test_grouping` |
| 10 查询小评测 precision@5/覆盖率（v1 vs v2） | eval 报告 + `test_eval_schema` |
| CLI `search --q --topk --explain` | `test_load_units_and_cli` |

## 3. 架构

```
units(JSON/jsonl)
   │ load_units()
   ▼
SearchV2(units, synonyms, weights)
   ├─ tokenize()          中文 bigram + 英文/数字词
   ├─ SynonymTable        词→组内全部别名（JSON 内置，可 --synonyms 覆盖）
   ├─ parse_query()       OR 分支 → AND 词 → 短语/排除标记 + variants
   ├─ search_units()      OR 取最高分支分；AND 必须全词命中
   ├─ group_results()     (book, chapter) 聚合 + 组相关度
   └─ search()            统一 payload（matches/groups/parsed/weights）
evaluate(engine, queries) → precision@5 / 覆盖率（v1 复刻基线 vs v2）
```

### 3.1 打分

- 单词在字段 f 的匹配分：短语/别名整词包含 = 1.0；否则按查询词 bigram 与字段 bigram 的重叠率 × 0.7；
- 单元分 = Σ_f w_f × 字段命中分 ÷ (Σ_f w_f × 词数)，并乘以覆盖率因子 `0.8+0.2×(命中词/总词)`；
- 短语/整词在 concept/claim 精确命中 → 额外 `PHRASE_BONUS×0.5`；
- OR 分支：取分支最高分；AND 分支：任一词缺失该分支不匹配；`-词`：任一字段命中即过滤；
- 字段默认权重：concept 1.0 / claim 0.85 / evidence 0.6 / chapter 0.45 / book 0.15。

### 3.2 查询语法

| 语法 | 语义 | 示例 |
|---|---|---|
| `词1 词2` | AND（都命中） | `大模型 应用` |
| `a|b`、`a OR b`、`a 或 b` | OR（任一分支） | `光伏|钠电池` |
| `"短语 词"` | 短语整体匹配 | `"三维互动" 量学` |
| `-词` | 排除 | `钠电池 -储能` |

## 4. 数据兼容

- 默认数据：`portal/static/kb_units_all.json`（498 单元，字段 concept/claim/evidence/chapter/book/p1/p2）；
- `--data` 传目录时自动扫描 `*/knowledge_units.jsonl`（兼容 `C:\项目\PDF\_ingest_reports` 结构）；
- 同义词表：`tools/kb_corpus/synonyms_v2.json`，格式 `{"groups": [["光合词1","别名2",...], ...]}`；未登录词按自身处理。

## 5. 小评测（10 查询）

方法：人工标注 10 条查询及「相关知识关键词」；precision@5 = top5 中包含任一关键词的单元占比；覆盖率 = 关键词集合在 top5 中被命中的比例。v1 基线为旧检索器逻辑的等价复刻（concept×2 + claim×1 bigram 重叠），v2 为本文件。

结果（498 单元，topk=5）：

| 版本 | precision@5 | 关键词覆盖率 |
|---|---|---|
| v1（旧检索器） | 0.760 | 0.733 |
| **v2（新版）** | **1.000** | **0.883** |
| 提升 | **+0.240** | **+0.150** |

典型提升来源：
- 同义词：`IDC` v1 0.00 → v2 1.00；`钠离子电池` v1 0.40 → v2 1.00（组内 钠电池/钠离子）；
- 多字段：`量柱分类` v1 0.40 → v2 1.00（evidence/chapter 参与加权）；
- AND/OR/短语：`量线 支撑`、`光伏|钠电池` 保持 1.00 且覆盖率提升（0.75 → 1.00）。

> v2 precision@5=1.0 是 10 条人工标注查询的小样本冒烟结果，不代表全量统计显著性；查询与标注规则可见 `search_v2.py::EVAL_QUERIES`，可复跑。

## 7. 取舍与局限

- 中文仍是 **bigram** 粒度的词法匹配，未接分词/IDF/向量召回；对语义改写（「低换手」↔「换手率低」）仍靠同义词表覆盖；
- 同义词表为内置 22 组（研报/书籍常见词），未做自动挖掘；新增词只需改 JSON，不改代码；
- AND 语义是严格的「全词命中」，长查询可能过严；评测中的短语+AND 场景已标注该行为；
- 分组相关度 = 组内最高分 + 0.3×其余分之和，是启发式；对超长章节（图表目录类）可能偏弱；
- 未修改旧脚本 `kb_reports_search.py`、未改 `kb_reports.html` 前端 → 当前为**并行可用**的新检索器，前端接入需另立项（建议下一步做 `/api/kb_reports_search?engine=v2` 灰度）；
- 小评测为人工标注 10 条，precision@5=1.0 偏乐观；正式效果评估需扩大查询集（30-50 条）并做相关性分级。

## 8. 结论

v2 在 10 查询冒烟基准上 precision@5 0.76→1.00、覆盖率 0.733→0.883，同义词/多字段/AND-OR 三个能力均有实测收益；实现只新增文件、不动旧脚本与前端，可安全并行上线试用。建议下一步：接入前端（灰度）、扩大评测集、按需把同义词表迁到可配置数据目录。

## 评测扩展（wave9 / task-24，41 条人工标注查询）

- 样本：41 条（主题/同义词/AND/OR/短语/排除）；数据 498 单元；topk=5
