# 学习卡与简报门户化 v1

> 2026-11-01 · 目标：把已有的「学习卡（每日知识）」「研报简报」「本轮策略研究结论」三条内容线**汇总成一份每日学习摘要**，
> 并挂到研报知识库页面 `portal/kb_reports.html`，让人类打开门户即可看到**今日 5 张学习卡 + 今日简报要点 + 策略结论**，不再只看到裸搜索框。

## 一、背景与问题

- `portal/kb_reports.html` 原本只有「研报知识单元搜索」（fetch `kb_units_all.json`）；
- 上游已有两份静态数据：
  - `portal/static/kb_learning_cards.json`（`tools/kb_corpus/learning_cards.py` 产出，随机抽卡，无排序/去重）；
  - `portal/static/kb_daily_briefing.json`（`tools/kb_corpus/daily_briefing.py` 产出，研报简报）；
- 本轮策略实验结论已沉淀为 `knowledge_docs/选股策略研究结论_20261101.md`，但页面不可见；
- 缺一个**合并层**：日报级去重/质量排序、摘要压缩、页面只读接口。

## 二、数据流

```
portal/static/kb_learning_cards.json ─┐
portal/static/kb_daily_briefing.json ─┼─→ tools/kb_corpus/learning_digest.py run
knowledge_docs/选股策略研究结论_20261101.md ─┘        │
                                                      ▼
                                    portal/static/kb_learning_digest.json
                                                      │  (静态文件，浏览器直接 fetch)
                                                      ▼
                                    portal/kb_reports.html
                                    ├─ 📚 学习卡（每日 5 张）
                                    └─ 📰 今日简报（含策略结论要点）
```

- **页面不依赖后端接口**：digest 是静态 JSON，更新后无需重启 8091/门户进程，刷新页面即生效；
- 生成器把三路输入做**容错降级**：学习卡缺失→用简报知识单元兜底；简报缺失→空摘要；策略结论缺失→降级为空要点，均写入 `meta.fallbacks`。

## 三、输出 Schema（`portal/static/kb_learning_digest.json`）

| 顶层字段 | 类型 | 说明 |
|---|---|---|
| `date` | str | 生成日期 `YYYYMMDD`（`--date` 可覆盖） |
| `cards` | list | **每日 5 张**学习卡（主题去重 + 质量排序） |
| `briefing` | dict | 今日简报摘要（headline/docs_count/unit_count/highlights/note） |
| `strategy_notes` | dict | 本轮策略研究结论要点（title/takeaway/points/key_findings/status_table） |
| `meta` | dict | generator/version/generated_at/cards_input/cards_selected/fallbacks/inputs/note |

`cards[i]` 字段：`rank`（1..5 连续）、`topic_key`（归一化主题，唯一）、`q`、`a`、`concept`、`source`、`evidence`（截断 240 字）、`quality_score`（0–100）。

`briefing.highlights[i]`：`doc`、`pages`、`chapter`、`concept`、`claim`（最多 5 条，跨文档去重）。

`strategy_notes.points`：关键实测结论表格 + 方法论教训 + 后续裁决（最多 10 条，去 Markdown 标记）。

生成示例（2026-11-01 实跑）：`cards=5`、`highlights=5`、`points=10`，文件约 9.8KB。

## 四、去重与质量排序规则（纯函数，确定性）

1. **主题归一化** `normalize_topic()`：去空白/标点/括号引号、转小写。例：`AI 算力需求` → `ai算力需求`。
2. **主题去重**：按质量分从高到低遍历；
   - 归一化主题完全相同 → 跳过；
   - 两主题中文长度均 ≥6 且互为子串 → 视为近重复（如「AI 原生安全」vs「AI 原生安全体系」）→ 跳过。
3. **质量分** `quality_score()`（0–100，启发式、无随机）：
   - 答案长度 40–220 字 +15；20 字以上 +8；过短 −15；>400 字 −5；含 `.../…` 截断 −6；
   - 证据长度：每 20 字 +1（上限 +12）；<30 字 −10；
   - 主题命名 4–30 字 +6；纯 ASCII −2；
   - 出处含《书名》+5、含页码 `pN` +4、研报流水号 `rp_*` −1；
   - 答案数字/数据密度：每个数字 +0.5（上限 +5）。
   - 同分按输入顺序稳定排序（保证每日结果可复现、不随进程变化）。
4. 测试覆盖：重复主题只保留一张、近重复剔除、薄卡排最后、分数降序、rank 连续。

## 五、页面区块（`portal/kb_reports.html`）

### 5.1 结构

在**搜索区之后**（`#results` 之前）新增两栏 digest 区，保持原有搜索/筛选/结果结构不变：

| 区块 | 挂载点 id | 标题 |
|---|---|---|
| 学习卡 | `#learning-cards` / 列表 `#learning-cards-list` / 状态 `#lc-meta` | 📚 学习卡（每日 5 张） |
| 今日简报 | `#daily-briefing` / 列表 `#daily-briefing-list` / 状态 `#bf-meta` / 策略结论 `#strategy-note` | 📰 今日简报 |

- 卡片显示：rank 徽标、Q、A、出处 + 质量分；简报显示：headline + 要点（concept/claim/doc/页码/章节）；策略结论显示：takeaway + 前 3 条要点。
- 页面原有「使用提示」「H18 业绩预告修订观察」区块保留；nav/其他页面未改。

### 5.2 Fetch 与降级链

```text
fetch /static/kb_learning_digest.json        ← 主源（digest）
   ├─ 失败 → fetch /static/kb_learning_cards.json   （学习卡兜底，截前 5 张）
   ├─ 失败 → fetch /static/kb_daily_briefing.json   （简报兜底，每篇取 1 条要点）
   └─ 再失败 → 区块内降级文案：
        「学习卡暂时无法加载（无摘要且原始数据缺失），请稍后刷新」
        「今日简报暂时无法加载（无摘要且原始数据缺失），请稍后刷新」
```

- 所有 fetch 带 `?ts=` 时间戳避免浏览器缓存；
- 渲染前做 HTML 转义（`esc()`），防止知识单元文本破坏页面；
- 内联 JS 已用 `node --check` 验证语法。

## 九、限制与后续

1. **质量分为启发式规则**（答案/证据长度、出处可读性、数据密度），不是模型评分；后续可接入 LLM 打分或人工收藏反馈做重排。
2. **客户端只展示前 5 张 / 前 5 条要点**；digest 的 `meta` 保留输入统计，便于排查「为什么今天只有 N 张」。
3. **上游数据更新频率决定内容新鲜度**：学习卡/简报文件由 `learning_cards.py`、`daily_briefing.py` 生成（本任务不修改），digest 每次运行读取当时快照。
4. **未做**：页面端「换一批/展开全部/收藏」交互、按日期归档、HTTP API（静态 JSON 已够用，新增接口需走 8091 审批）。
5. **并行编辑说明**：本任务期间 `portal/kb_reports.html` 已被同 wave 的另一改动（原始简报/学习卡/H18 区块）修改；本次将其中的原始简报/学习卡两区块**升级为 digest 驱动区块**（功能覆盖，避免同页重复展示），H18 区块保留；未改其他页面与 nav。
