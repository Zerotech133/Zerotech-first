# 每日 08:00 部门负责人早会制度 v1

- 生效：2026-11-04 起｜时间：**每日 08:00–08:20**（07:50 早报截止）
- 主持：A0 田丰｜签准：老田（L2/终裁）
- 目标：13 位部门负责人各自总结军团/部门情况与工作要点，向老田提供**可决策事项**，不把早会开成流水账。

## 一、会前 07:50：异步早报（所有负责人）

每位负责人提交 1 份 JSON：

```yaml
lead: DATA1
dept: data
legions: [data-warehouse]
status: green|amber|red
highlights: [3 条以内工作要点]
blockers: [阻塞/证据缺口]
decision_requests: [需要老田/A0 决策的事项]
evidence: [命令/rc/文档/链接]
```

- 模板：`python tools/hq_dept_brief.py --template --out deliverables/daily_briefs/<date>/template.json`
- 采集：`python tools/hq_dept_brief.py --collect deliverables/daily_briefs/<date> --out deliverables/daily_briefs/<date>/rollup.json`
- 无证据必须标“需查证”，不得编数；无事项写空数组。

## 二、08:00–08:20：现场会（6 人上限）

| 席位 | 人员 | 职责 |
|---|---|---|
| 主持/汇总 | A0 田丰 | 早报速览、红黄、决策聚类、派单 |
| 固定 | 老田 | 终裁/L2 |
| 动态 1–5 | 当日 **red/amber 或带决策请求** 的部门负责人 | 说明阻塞、给选项 |

> 13 位负责人都提交早报，但现场只请最需要决策的 5 位，避免 13 人流水会。

### 固定议程

1. 早报速览（13 份，A0 5 分钟）
2. 红黄军团/阻塞与证据缺口（5 分钟）
3. 各部门工作要点（每人 ≤3 条，5 分钟）
4. 需 A0/老田决策事项聚类（5 分钟）
5. 今日决策清单：结论 + owner + due + 验收（5 分钟）

## 三、会后 08:20–08:25：决策清单

输出到 `/hq` 议程：

- 决策：一句话结论 + owner + due + 验收标准
- 派单：决议 → 任务申请（不自动执行）
- 未决：进明日早会红标，不静默丢失

## 四、参会矩阵

| 角色 | 是否上桌 |
|---|---|
| 老田 | 固定主持/终裁 |
| A0 田丰 | 固定汇总 |
| red/amber 负责人 | 按早报动态上桌 |
| 其余负责人 | 异步早报，不上桌 |
| AI1/赵云/关羽/黄忠 | 需要质询/审计/验收时临时邀请 |

## 五、工具与页面

- 早报工具：`tools/hq_dept_brief.py`
- 会议页：http://127.0.0.1:8734/meeting → 「部门早会 · 08:00」模板
- 会议系统：HQ Meeting v2（`dept_morning` 类型，attendees ≤6）
- 本制度不自动发飞书、不自动派单、不代批 L2。

## 六、验收

- 连续 5 个工作日：13/13 早报提交、08:00 会议纪要、每日决策清单；
- 决策事项有 owner/due/验收；无证据不通过；
- 18:00 对账引用当日早会决策。
