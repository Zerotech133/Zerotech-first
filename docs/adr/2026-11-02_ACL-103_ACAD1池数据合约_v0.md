- **日期**：2026-11-02
- **关联**：ADR-015（平台内核契约与组合模型，K0/K5、§5/§6/§7）、ADR-017（唯一框架与黄金路径，§6 禁止 `C:\Temp` 当契约）、`platform/kernel_v1.yaml`（K5 数据/证据层）、ADR-016（唯一宿主）、ADGS v1.1 试点 ACL-103（治理道）、兄弟单 ACL-101/ACL-102（已交付证据）、DWH-104（数据仓暴露面盘点，数据口径参照）

## 一、背景与问题

ACAD1 池是军团组合（`acad1-legion`）对外承诺的核心数据产品，被 D1 裁决、黄忠验收、门户页面、Hermes 等跨组合消费。当前存在四个结构性问题：

1. **同一"ACAD1 池"两个数字（双池未收口）**：生产页 `/api/acad1/pool` 走门户 JSON 池（**19 只，数据日 10-30**，`ACAD1-REC-20261030`）；智策 PG `v2_acad1_pool`（**101 行，最新 10-31，30 只**）；两池并行、无对账。`dw_adapter.py` 默认读 PG 旧池，与当前 30 卡 **CN 12 只仅 4 只重合**；按当前 30 卡核对数据仓覆盖 **27/30**（HK 缺 `07552`、CRYPTO 0/2）。（来源见 §三）
2. **没有"可用契约"**：`acad1-legion/manifest.yaml` 已声明 `spec.data.contract: acad1-pool/v1` 与 SLA（freshness 1d / pool_max 30 / evidence≤26h / data_date lag 1d），但**主区无契约文件**；契约草案（ODCS v3.0.2，id `zerobond.selection.v2_acad1_pool`，version 0.1.0，status draft，10 字段 + 质量规则 + agentPolicy）已提交在 parked 分支，因并行 merge 竞态未落 master。→ 声明与事实脱节，违反 ADR-015 §6"声明必须被执行点消费"。
3. **无 allowed_use/PII/PIT/freshness 约束**：下游（D1/黄忠/页面/Agent）无法机器判定"这份池能不能用于方向性结论/冻结候选/对外展示"；证据包与部分上游走 `C:\Temp` 绝对路径，无 schema/版本/保留期（ADR-017 §6 明令禁止把 `C:\Temp\*.json` 当契约）。
4. **不决策的代价**：双池会持续污染 11-16 复审判定的 M5（组合 Q）与 H（组合质量）指标；契约登记落点不定会使 K5 内核冻结范围与 `kernel_guard` 生效范围漂移；证据无法复核，等于"rc=0 当产出"。

## 二、决策（Proposed，D1–D8）

> 以下为**建议决策**；未获 A0 拍板前不进入实现。标 🔴 的为需 A0 明确拍板项（§七）。

### D1 🔴 唯一真源：PG `v2_acad1_pool` 为真源，JSON 池降为只读投影

- `PG 5446 / zhice_os_v2 / v2_acad1_pool` = ACAD1 池**唯一真源**（写入/发布口径以它为准）。
- 门户 JSON 池保留为**只读投影**：必须携带 `source_pool=projection` 与 `data_date`；不得再作为池真源、不得作为 enrichment 默认源；投影落后真源时**显式 stale，不静默 rc=0**。
- `dw_adapter.py` 及同类消费方改为"读真源"或显式 `--pool-file` 读投影（实现单另开，不在本 ADR）。
- 备选（若 A0 不采纳）：JSON 为真源、PG 同步；代价是 PG 已成为 101 行/30 只事实源、D1 与页面多处读 PG，反转成本更高。**建议采纳 PG 真源**（与可行性研究 §P2 推荐一致）。

### D2 契约文件落点：`agent_platform/catalogs/contracts/v2_acad1_pool.odcs.yaml`

- 沿用现有 ODCS 契约目录与格式（该目录现已有 9 份 `.odcs.yaml` 契约：adj_factor/daily/daily_basic/hk_hold/index_daily/margin_detail/moneyflow/moneyflow_hsgt/youtube_quant_corpus，实测清单见证据）。
- `compositions/acad1-legion/manifest.yaml` 的 `spec.data.contract: acad1-pool/v1` **只作引用点**，不内嵌 schema、不双写字段（与 ACL-102"SLA 四字段唯一落点 `spec.data.sla`、不双写 spec.slo"同一纪律）。
- 备选：放到组合目录内（`compositions/acad1-legion/contracts/`）；缺点是与现有 9 份契约目录分裂、`contract_export.py` 生成器与消费方需双路径支持。**建议 catalogs 统一目录**。

### D3 🔴 契约标识与版本

- `apiVersion: v3.0.2`（ODCS）；`kind: DataContract`；`id: zerobond.selection.v2_acad1_pool`；`name: v2_acad1_pool`；`domain: selection`。
- `version`：`0.1.0`（draft，现状）→ A0 批准 + 契约文件入主区后升 **`1.0.0`（Accepted）**；status `draft` → `active`（与现有契约 status 字段语义对齐，实施单同批）。
- manifest 侧 `contract: acad1-pool/v1` 与 ODCS `id` 的映射表写入契约文件头注释，避免两套标识漂移（映射：`acad1-pool/v1` ↔ `zerobond.selection.v2_acad1_pool@1.0.0`）。

### D4 契约 schema 字段（ODCS 映射）

| # | 字段 | 类型 | 必填 | 说明 / 口径 |
|---|---|---|---|---|
| 1 | `pool_date` | date | ✅ | 池数据日（与 `data_date` 可同值，不同则必须解释） |
| 2 | `market` | enum | ✅ | CN/HK/US/CRYPTO（与 30 卡配额 CN12/HK10/US6/CRYPTO2 一致） |
| 3 | `code` | string | ✅ | 证券代码；卡片 `candidate_id` → `code` 映射（合约 v0 已定） |
| 4 | `name` | string | ✅ | 名称；禁止"代码当名称" |
| 5 | `strategy` | string | 否 | 策略/战法来源（v1 策略 ref 或文本，P1 后再结构化） |
| 6 | `signal_type` | string | 否 | 信号类型（如 BUY/AVOID/NEUTRAL） |
| 7 | `score` | number | 否 | 分数；须带 `score_scale` 说明（禁 raw/归一混用） |
| 8 | `data_date` | date | ✅ | 数据日；freshness 判定基准（≤24h，`data_date_lag_days=1`） |
| 9 | `evidence_ref` | string | 条件 | 方向性结论/候选冻结**必填**（路径+sha256 或证据包 id） |
| 10 | `created_at` | timestamp | 条件 | 记录落库时间（审计用） |
| 11 | `source_pool` | enum | ✅（新增） | `pg` / `projection`——D1 的落地字段，杜绝两池混淆 |

- **质量规则（v1）**：①唯一键 `(pool_date, market, code)`；②核心字段 `completeness=1.0`；③`data_date` freshness ≤24h、`data_date_lag_days` ≤1；④方向性结论必须带 `evidence_ref`；⑤`pool_max=30` 且超限**显式报错、不静默截断**；⑥同一 `(data_date, market)` 下配额与发布口径一致（CN12/HK10/US6/CRYPTO2）。
- **PIT/时点口径**：`data_date`（数据日）+ `as_of`（可选，查询/导出时点，v1 建议一并定义）满足 point-in-time 复核；不得用"采集时点"替代数据日。

### D5 agentPolicy 最小集（ODCS 扩展；v0 仅登记，不宣称已强制）

| 项 | 最小集 | 说明 |
|---|---|---|
| `allowedUse` | `research` / `selection_review` / `watchlist_monitoring` | 研究、复核、观察名单监控 |
| `prohibitedUse` | `order_execution` / `real_trading` / `auto_approval` / `personal_data_export` | 禁止下单/实盘/自动审批/个人数据导出 |
| `PII` | `none` | 池字段不含个人数据 |
| `residency` | `CN` | 数据驻留 |
| 方向性决策 | `directional_decision` / `candidate_freeze` 需 `evidence_ref` + **human approval** | 人工复核不自动通过/否决（与 ACL-104/签核纪律一致） |
| `maxRowsPerQuery` | `500` | 防批量外泄/误用上限 |

- ⚠️ **执行点诚实声明**：当前平台**没有运行时 agentPolicy 策略引擎**（`agent_policy` 自述不接线，见可行性研究 §二）。v0 的 agentPolicy 是**登记 + 只读校验**（契约 lint / 回归测试），不是运行时强制；"强制"落点（Agent 运行时 / MCP 网关 / API 层）列入 W3 实现单。🔴 A0 需确认是否接受"登记≠强制"的阶段性口径，或要求先接一个最小强制点再 Accept。

### D6 PIT/freshness/配额口径（与 manifest、ACL-101/102 一致）

- SLA 四字段**唯一落点** = `compositions/acad1-legion/manifest.yaml` `spec.data.sla`：`freshness_days=1` / `pool_max=30` / `evidence_max_age_h=26`（=1 天 data_date 滞后×24h + 2h 日管线余量）/ `data_date_lag_days=1`；本契约不双写 SLA，只引用。
- 30 卡证据年龄三态：fresh（≤26h）/ stale（>26h）/ **unknown（缺时点，fail-visible，不按 fresh 计）**（ACL-101 已加 4 例回归固化）。
- 台账/证据链：`evidence_ref` 必须可定位到文件/URL + sha256；`C:\Temp` 路径作为**过渡期临时引用**，P2 收敛为契约目录（ADR-017 §6）。

### D7 🔴 契约登记（K5）：是否把本契约加入内核冻结清单

- 建议在 `platform/kernel_v1.yaml` **K5 数据/证据**新增：
  - `path: agent_platform/catalogs/contracts/v2_acad1_pool.odcs.yaml`，`kind: contract`，`status: planned → existing`；
  - 登记后，本文件改动须带 ADR 号（`kernel_guard` 拒收无 ADR 变更；ADR-015 §7）。
- **时机**：A0 批准本 ADR 且契约文件入主区后登记；在此之前保持 draft，`kernel_guard` 不覆盖（避免拦在途实现单）。
- 备选：契约不冻结（仅组合级声明）——缺点是口径变更无门禁、跨组合消费不可审计。**建议登记**。

### D8 双池对账口径（只定口径，不实现）

- 对账三要素：**池数**（同日两池数量）、**数据日**（pool_date 差异）、**成员哈希**（排序后 code 集合 sha256，判断"数字相同但成员不同"）。
- 差异处理：任一要素不一致 → 告警（进周报/事件层），**禁止静默 rc=0**；`ACAD1-REC-*` 投影必须可追溯到真源 `pool_date`。
- 对账脚本/告警属 W3/P2 实现单（本 ADR 只定义口径与阈值建议：池数差 >0 或成员哈希不一致即告警）。

## 四、与 ADR-015 / K5 的关系

- **ADR-015 §5 单一真源**（ADR-015:65）："池/数据口径以数据契约为唯一来源"——本 ADR 的 D1（PG 真源）+ D2/D3（契约唯一定义）是它的落地；JSON 投影不得成为第二真源。
- **ADR-015 §6 声明必须被执行点消费**（ADR-015:67）：manifest 已声明 `contract: acad1-pool/v1` 却无契约文件、无消费点——本 ADR 为其补上"可校验契约 + 消费点清单（§五）"，否则该声明应视为无效声明。
- **ADR-015 K5 行**（ADR-015:48）："数据/证据：dataset registry 契约（含 pg_table）、数据契约、证据包 schema、血缘"——ACAD1 池契约属 K5 的"数据契约"；登记与否见 D7。
- **kernel_v1.yaml K5**（:148-166，owner DATA1，status partial）：当前 artifacts 仅 dataset_registry.py（contract）、知识全链路标准（contract）、dataset.schema.json（planned）、evidence_bundle.schema.json（planned）；**ACAD1 池契约未列入**——D7 的登记动作即新增条目。
- **ADR-017 §6**（:26）：禁止 `C:\Temp\*.json` 当契约——本 ADR 要求 `evidence_ref` 可追溯并给出 Temp→契约目录的收敛路径（P2），与 DWH-103 ADR 的 `contract_artifact` 登记协同。
- **与 DWH-103 ADR 的耦合**：ACAD1 池契约里的 `dataset/pg/v2_acad1_pool`、`dataset/file/acad1_evidence_bundle` 等 ref 的可解析性依赖 DWH-103 的 `pg_table` / `contract_artifact` 登记模型；两份 ADR **建议同批预审、同批 A0 拍板**（分开批会造成 ref 无法解析的中间态）。

## 六、迁移与回滚

**迁移（Proposed→实现，分四段，每段独立验收）**：
1. **本 ADR**：ARCH1 预审 + A0 拍板 §七 P1–P8 → 状态 Accepted；不动代码。
2. **契约入主区**： parked 分支 `WO-ACAD1-CONTRACT-20261101` rebase → 契约文件 + 30 卡校验回归入 master（status draft、v0.1.0）；同时补一个轻量 ODCS YAML 校验测试（不新增外部依赖）。
3. **契约生效**：version 1.0.0 / status active + manifest/K5 同批登记；SLA 唯一落点复核；ACL-101/102 回归全绿。
4. **接线实现单**（另开）：dw_adapter 池源、投影标注、证据目录契约化、双池对账告警。

**回滚**：
- 契约：status 回 `draft`、version 回 0.1.0；K5 条目撤回；manifest `contract` 字段回退（一轮提交内）。
- 唯一真源切换若在实现阶段发现问题：**保持 JSON 投影只读可用**作为临时回退面（回退窗口 ≤ 试点剩余期），并立即恢复 PG→JSON 对账告警，禁止静默切换。
- 全程不删分支/不删契约历史；回滚以新提交 revert，不做 `reset --hard`。
