## 三、当前真实缺口（不能靠页面替代）

1. **会议已多日未开**：最近会议 2026-10-29，`draft` 多；需要恢复每日晨会/作战会/验收会；
2. **角色意见没有持续生产**：`RoleOpinion v1` 契约在，但没有“今日议题→五角色各出意见”的日常运行；
3. **议程分类偏弱**：当前数据 24 条“其他”、研发 2、挖掘 1；需要会议模板强制带 `kind/owner/due/decision`；
4. **商业化未闭环**：有租户/套餐/试用/回访，但没有收入/发票/续费；不能宣称营收；
5. **调度未闭环**：会议决议→派单已有 API，但“会议→任务→验收→记忆”的自动链未跑通。

## 四、让五角色真正发挥的运行模型

### 4.1 每日 15 分钟晨会（morning）

| 角色 | 固定输出 |
|---|---|
| 田丰 | 今日三优先 + DAG + 派单 |
| 诸葛亮 | 反向质询 3 条：前提/反例/失败模式 |
| 赵云 | 证据缺口/审计风险/经验归档 |
| 关羽 | 研发/技术债/门禁风险 |
| 黄忠 | 验收闸口/抽样结论/放行或拒收建议 |

### 4.2 每周作战会（operation）

议题必须带：`kind`（研发/挖掘/分析/商业）、owner、due、evidence、decision。

### 4.3 验收会（acceptance）

黄忠主检；赵云复核证据；关羽看代码；诸葛亮质疑；田丰汇总给 A0 终裁。

### 4.4 会议→任务

`decision → order → task`：所有决议必须有 owner/due；未派单的决议进入 `orders_pending`，在 `/hq` 议程中红标。

## 六、验收与边界

- 新增 API/UI 需 8091 重启生效；页面未登录仍 302；
- 所有模型只读：不执行角色、不自动派单、不写商业库；
- 五角色意见/会议记录是“客户端声明”，需真实运行/证据后才能标 verified；
- 商业指标来自本地底座，未接收入前只讲租户/试用/回访。
