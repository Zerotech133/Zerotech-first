## 二、指挥部 v1 职责（六面）

1. **军团账本**：读 `compositions/registry.json` + manifests → 军团清单/owner/版本/Q/健康；
2. **席位目录**：org/hr/teams/skill 注册表 → 谁在编、绑定模型、权限；
3. **任务/派单**：`.worktrees/tasks.json` + schedules + mission dispatch → 目标→DAG→派单；
4. **运行/事件**：trace/dev_events/run/event 聚合（ADR-014 P2 继续）；
5. **审批/治理**：L2 五要素、kernel/composition 门禁、例外台账；
6. **质量/健康**：Q1–Q4、健康探针、回滚、证据包。

## 三、军团叠加协议（HQ-only）

```
A0/指挥部（唯一指挥面）
  ├─ 军团 A（composition）── seats/data/pages/jobs/SLA/Q
  ├─ 军团 B（composition）── ...
  └─ 军团 C（composition）── ...
共享：一个宿主 零界 / 一个入口 8734 / 一个认证 OIDC / 一个调度台账 / 一个组合账本
禁止：第二宿主/入口/认证/调度/DB；军团不得自建平台
```

叠加步骤：
1. 建 `compositions/<id>/manifest.yaml`（owner/seats/skills/data/pages/jobs/SLA/status）；
2. 登记 registry（版本/生命周期同批）；
3. `composition validate --all` warnings=0、`plan --strict` findings=0；
4. Q1→Q2 评审（健康探针/SLO/回滚/≥1 测试）；
5. 接入 HQ 视图（本工具）→ 派单（CMD-04）；
6. WIP≤6、同一共享文件单 owner、显式 pathspec、Lead 合并。
