## 2. 提炼出的 10 个模式（对零界可直接用）

1. **设计令牌先行**：颜色/字号/间距/圆角/阴影/动效全部语义化（我们已有 tokens.css 起点）。
2. **行为与样式分离**：导航、弹层、命令面板只写行为；颜色只读 token，避免 nav.js 这类生成器硬编码。
3. **可访问性默认**：`lang`、焦点可见 `:focus-visible`、`aria-live`、键盘可达、降低动效。
4. **状态四件套**：empty / loading(skeleton) / error / success，每个异步区域都要有。
5. **命令面板**：高频操作一个入口（类似 shadcn Command / Linear），减少深层导航（Hick 定律）。
6. **仪表盘讲故事**：一屏回答一个问题；RED/USE；层级下钻；别把所有指标堆首页（Grafana）。
7. **信息密度可切换**：舒适/紧凑两档，尊重不同任务（浏览 vs 值班）。
8. **色彩克制**：语义色（涨跌/状态）与品牌色分离；大色块只留给「需要立刻行动」。
9. **导航收敛**：>7 个并列入口收下拉（现有规则），面包屑 + 顶栏两层，Jakob 定律保持一致。
10. **可度量**：Doherty <400ms 反馈；首屏 skeleton；关键操作埋点（PV/点击/失败）。

## 3. 当前门户静态审计（2026-10-27）

用本轮新增工具实测：

```powershell
python tools/ui_ux_audit.py portal/os_entry_v9_prod.html portal/static/nav.js portal/static/tokens.css --markdown
```

| 指标 | os_entry_v9_prod.html | nav.js | tokens.css |
|---|---|---|---|
| 原始 hex | **36** | **19** | 20（tokens 源，允许） |
| CSS 变量 var(--) | 有 | 少 | 定义源 |
| 内联 style | 0 | **13** | 0 |
| aria-/role | 6 / 2 | **0 / 0** | 0 |
| focus-visible | 2 | **0** | 0 |
| skeleton | **0** | 0 | 0 |
| prefers-reduced-motion | **0** | 0 | 0 |
| 文件形态 | 单文件、JS 压缩 | 自动生成 | 69 行 |

**主要差距**

- `nav.js` 仍硬编码 19 个 hex + 13 处内联 style，且无 aria/focus：**违反「tokens.css 唯一视觉源」**；根因在生成器 `tools/export_nav.py` / 导航数据，不在手改页面。
- `os_entry` 有 `aria-live`/`focus-visible` 起点，但**没有 skeleton、没有 reduced-motion**，首屏刷新仍是文字提示；36 处 hex 说明页面内仍有自绘色。
- **`os_entry` 未引用 `tokens.css`**（审计 `tokens_link` warn）：53 处 `var()` 可能来自页面内联定义，不是全站单一事实源；这是最该先修的一处。
- `tokens.css` 只有颜色/少量语义，**缺 spacing/typography/radius/shadow/motion/z-index** 令牌；组件层未抽象。
- 无组件清单/无视觉回归：页面是「单文件 + 内联 CSS/JS」，改版回归成本高。
- 未见命令面板/密度切换；高频入口依赖多级导航，值班场景效率有提升空间。

## 4. 30 天落地计划（建议）

### 第 1 周：设计系统地基（低风险）
- 扩展 `tokens.css`：spacing/type/radius/shadow/motion/focus-ring 语义层；
- 修 `nav.js` 生成器：输出 class + token，去掉 19 hex/13 inline style；保留现有 DOM 结构；
- 加 `:focus-visible` 全局样式与 `prefers-reduced-motion` 媒体查询；
- 用 `ui_ux_audit.py` 将 warn 数纳入评审（目标：nav.js warn=0）。

### 第 2 周：状态与组件
- 抽出 Empty/Loading(Skeleton)/Error/Toast 四类静态模板；
- 首页异步区域加 skeleton/aria-live/重试按钮；
- 建立 6 个基础组件规范（Button/Card/Badge/Table/Command/Drawer），先文档后实现；
- 键盘走查：Tab 顺序、焦点陷阱、Esc 关闭。

### 第 3 周：指挥台效率
- 命令面板原型（快捷键 `Ctrl+K`，搜索导航/动作，不执行危险操作）；
- 首页信息分层：今日必看 → 领域建议 → 原始来源；按 Grafana 原则删减非行动指标；
- 数据表密度切换（舒适/紧凑）与列冻结/排序规范。

### 第 4 周：度量与固化
- 加静态 UI 审计到合并门（仅 warn 不阻断，先观察）；
- 关键页面视觉快照（人工 3 张基线图）与 a11y 清单；
- 用 task time / 首屏时间 / 误点率做一次小样本对比，再决定是否引入组件框架。

## 5. 快速审查清单（每次改 UI 必过）

- [ ] 颜色/间距/圆角全部来自 tokens（新增 hex 需说明理由）
- [ ] `<html lang>` / viewport / tokens.css 引用齐全
- [ ] 键盘可达：Tab 顺序合理、`:focus-visible` 可见、Esc/Enter 行为明确
- [ ] 异步区域有 empty/loading/error 三态，`aria-live` 播报
- [ ] 动效尊重 `prefers-reduced-motion`；无自动播放/闪烁
- [ ] 导航只两层；>7 入口下拉；当前页高亮
- [ ] 移动端 375px 可用（短屏检查）
- [ ] 文案行动化：说「下一步做什么」，不堆指标
- [ ] 跑 `python tools/ui_ux_audit.py <files> --markdown`，warn 有解释

## 6. 边界

- 本轮不引入 React/组件框架，不改生产页面；先修 token/生成器与状态模板，避免大迁移；
- Emoji 图标保留现状（低成本），但交互控件的 aria-label 必须补；
- 颜色语义继续遵循：涨跌中式红涨绿跌、状态国际惯例红坏绿好。
