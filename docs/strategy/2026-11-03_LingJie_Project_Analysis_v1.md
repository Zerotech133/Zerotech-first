# 零界（LingJie）项目整体分析与战略校准 v1

- 日期：2026-11-03｜定位：**情报世界的超级个体 · 一个人可治理的 AI 工作 OS**
- 结论：**原材料很强，但横向过度建设、纵向验证不足；最优路径不是再加能力，而是收敛为“一条情报闭环 + 两个亮点 + 五个作战单元 + 一个驾驶舱”。**

## 一、先把目标翻译成可检验的定义

> 一个人拥有一支可治理的情报队伍 = 一个人能在**一个入口**里，让一队分工明确的 AI 完成“**采集→核验→分析→决策→交付→记忆**”，并且每一步都**可追溯、可审计、可回滚**。

四个关键词：

| 关键词 | 含义 | 检验标准 |
|---|---|---|
| **一个人** | 不是企业平台，是个人驾驶舱；人力只做决策/例外 | 每日 1 个入口、≤3 次点击进入任务 |
| **情报队伍** | 不是 77 个席位，是 5–6 个有输入/输出/SLA 的作战单元 | 每个单元 Q2，能独立交付 |
| **可治理** | 不是每步审批，是证据+审计+例外升级 | 每个结论有来源/血缘/责任人 |
| **情报世界** | 以数据血缘承载事实、关系、经验 | 结论可回放到数据行/文档/版本 |

**“沙算系统”**：项目仓库暂无此命名的实现。我理解它指“执行编排层”；现有对应物是 `agent_platform（席位/任务/技能）+ legion_command（军团编排）+ HQ（指挥/审批/预算）`。建议正式定义其边界，**不要在这三者之外再造第四套调度**。

## 三、七个核心矛盾

### 1. 广度 vs 深度

95 个页面、17 个部门、77 个席位、6 个军团，但 **Q2 只有 1 个 PASS**。这是“组织图繁荣、作战单元不足”。  
**优化**：把 77 席收敛为 5–6 个作战单元；其余角色作为技能/工具，不再单独占“军团”。

### 2. 治理 vs 个体效率

ADGS、W1–W4、Q1–Q4、L1/L2、四签、evidence pack——体系正确，但一个人每天面对这些会**被流程拖死**。  
**优化**：**例外治理**。常规走自动门（validate/test/Q2 probe），只有宿主机/安全/数据口径/永久例外才 L2 五要素；审批从“每步”改为“异常/高风险”。

### 3. 数据血缘 vs 证据消费

血缘/KG 是资产，但 agent 的结论是否强制引用 `source_id/data_date/lineage/method`？目前更多是“可以查”，不是“必须带”。  
**优化**：定义 **Evidence Contract v1**：任何结论/决策/报告必须带证据五元组；没有证据的输出标 `unverified`，不得进入决策/发布。这是“情报”与“聊天”的分界线。

### 4. 平台 vs 工作 OS

K0–K8、组合、Q 等级是平台架构语言；用户需要的是“今天该看什么、该决定什么、谁在做、证据在哪”。  
**优化**：把平台术语藏在底层；驾驶舱只呈现**任务/证据/决策/风险**四个对象。`/hq` 继续做，但要从“数据看板”升级为“今日行动面”。

### 5. 情报队伍 vs Agent 名单

77 席不等于队伍。队伍需要：使命、输入、输出、SLA、Q2、失败处理、记忆。  
**优化**：只保留 5 个作战单元：
1. **情报侦察**（采集/核验/来源可信度）
2. **数据情报**（血缘/质量/口径/数据集）
3. **量化研究**（策略/回测/归因/决策）
4. **软件交付**（devtask/实现/测试/发布）
5. **验收与风控**（Q2/审计/回滚/合规）
6. 平台运维（宿主/Hermes/调度/可观测）作为支撑，不单独算作战单元。

### 6. 两个亮点 vs 场景分散

量化研究 + 软件开发是亮点；但若同时铺开更多场景，会稀释“情报闭环”。  
**优化**：两条旗舰闭环先做到可复用：
- **每日情报决策闭环**：问题→证据→分析→决策→跟踪→记忆；
- **软件交付闭环**：需求→工单→实现→测试→合并→审计。  
其他场景只在这两条闭环跑通后接入。

### 7. 边端主权 vs 单点可靠性

本地部署带来主权，但 8091 重启依赖管理员、session 内存、页面 302/401 掉线；个人 OS 的“可用性”就是产品力。  
**优化**：先做受监督服务 + 会话持久化 + 健康门，再谈能力扩展。

## 四、目标架构（收敛后）

```
L3 驾驶舱（一个人）
   /hq（今日行动） + /intel（情报决策） + 命令面板
L2 作战单元（5 个）
   侦察 / 数据情报 / 量化研究 / 软件交付 / 验收风控
L1 情报底座（可追溯）
   数据血缘 + KG + 契约 + evidence + 经验/记忆
L0 执行底座（沙算层）
   零界宿主 + Hermes + agent_platform + 调度/任务/审批
```

**一个入口、五个单元、一条证据链、两条旗舰闭环。**

## 五、验证指标（换掉虚荣指标）

**North Star：每周“可追溯决策闭环”数量**  
= 有证据五元组、有 owner、有结论、有后续跟踪的决策数。

| 指标 | 目标 |
|---|---|
| 可追溯决策/周 | 从当前基线起，W3 前 ≥5/周 |
| 证据覆盖率 | 决策/报告 ≥90% 带 source/lineage |
| 活跃作战单元 Q2 | W3 前 3/5，W4 前 5/5 |
| 决策周期 | 从提问到结论 ≤1 天（日常情报） |
| 一次通过率 | 交付/报告返工 ≤20% |
| 驾驶舱 | 1 入口，≤3 点击到任务/证据 |
| 可靠性 | 8091 连续 7 天无人工重启 |

**不把页面数、席位数、refs 数、Q1 数量当成绩。**

## 六、30/60/90 天路线

### 0–30 天：止血 + 收敛

1. 8091 受监督服务 + 会话持久化 + 重启健康门；
2. 冻结新增页面/席位/组合；宣布 5 个作战单元；
3. `/hq` 从看板升级为今日行动面（待办/风险/证据/决策）；
4. 定义 Evidence Contract v1 + 一个真实情报闭环跑通；
5. Q2 证据包：4 个 Q1 指定 owner/日期。

### 30–60 天：两条旗舰闭环

1. 每日情报决策闭环（量化/研究）端到端；
2. 软件交付闭环（devtask→发布→审计）端到端；
3. 5 个作战单元 Q2 到 3 个；
4. 导航从 100+ 收敛到 5–6 组 + ⌘K 搜索；
5. 数据血缘在决策页可下钻。

### 60–90 天：治理与规模化

1. 5/5 Q2；W3 出口；
2. 证据/决策/经验自动入记忆；
3. 其他场景只通过“接入单”进入；
4. 指标周报；每月组合账本审计。

## 七、需要 A0 拍板的 5 件事

1. **确认 5 个作战单元名单**，其余席位降为技能/工具（不再单独军团）；
2. **North Star 改为“每周可追溯决策闭环”**，不把页面/席位/refs 当成绩；
3. **冻结新增功能到稳定性/Q2 完成**；
4. **Evidence Contract 强制**：无证据结论不得进决策/发布；
5. **正式定义“沙算系统”**：明确它是 `agent_platform + legion_command + HQ` 的编排层，不另起第四套。

## 八、停止清单

1. 停止新增页面、军团、席位、组合；
2. 停止把“自动证据 6/6”当 Q2 PASS；
3. 停止常规事项四签/重审批，改为例外治理；
4. 停止在 W3 前继续加基础设施；
5. 停止用“组织图规模”证明进展。

## 九、一句话结论

**零界不是“更多 AI 员工”，而是“一个人可治理的情报决策系统”。**  
现在最缺的不是能力，而是**收窄**：一条证据链、五个作战单元、两条旗舰闭环、一个驾驶舱。把 77 席的组织图，收敛成 5 支真正能打仗的情报小队，零界才从“平台项目”变成“超级个体的工作 OS”。
