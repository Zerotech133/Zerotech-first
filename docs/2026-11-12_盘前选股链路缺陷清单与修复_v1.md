## 1. P0 阻断项（会造成「不出报告 / 出假报告」）

### P0-1 T+1 辅助源落后被判成硬失败 `[已修·已验证]`

- **现象**：两融 / 涨跌停等 T+1 源天然落后 1 个交易日，落后超过允许天数后，
  校对把它们和 `must` 源一起判 `problem`，整条盘前链路不出报告。
- **根因**：`tools/preopen/audit_preopen.py` 旧代码 `elif sp["role"] == "soft"` 只放行
  `soft` 一种角色，`t_plus_1` 掉进 `else` 与 `must` 同判 `missed`。
  角色分类的全部意义就是让「降级」与「阻断」分开，靠 `else` 兜底等于没分类。
- **修法**：`elif sp["role"] in ("soft", "t_plus_1")`，统一走 `warn` + 能力降级，
  并把「可用于什么、不可用于什么」写进告警文案（明确「不参与选票」）。
- **验证**：`audit(--target <D>)` 对 T+1 源落后 2 日应返回 `verdict=warn` 而非 `fail`。

### P0-2 0 行分片三因混淆 `[已修·已验证]`

- **现象**：`limit_list_d/d_<D>.parquet` 是 0 行空表，被读成「涨停停更」；
  而另一处「本地连分片都没有」被报成同一句话，补数方向完全相反。
- **根因**：`max_date()` 只看分片内 `max(date_col)`，0 行分片返回空值，
  与「没跑采集」在数据结构上不可分辨。项目铁律⑧已明确：判停更要三件齐
  （产物 max(date) / 上游 start_date 探测 / 写入链路）。
- **修法**：新增 `shard_diagnostics(sub, date_col, target, cal)`，
  按近 4 个交易日逐个分片区分 `empty_days`（有分片但 0 行 = 上游给空）与
  `absent_days`（连分片都没有 = 本地漏跑），写进 `sources[].empty_days/absent_days`
  与告警明细；分片名带不了日期时返回空诊断，**不猜**。
- **验证**：11-12 的 `limit_list_d` 应报 `empty_days` 含目标日，不得报「停更 N 天」。

### P0-3 龙虎榜「能力降级」与「V1b 实际生效」并存的假告警 `[已修·已验证]`

- **现象**：校对说龙虎榜缺目标日、能力降级，选票产物却显示 V1b 上榜过滤已生效
  （源端补拉成功）。报告把已解决的问题又报一遍，读者无法判断名单干不干净。
- **根因**：两者是两套视角 —— 校对本只读本地分片，选票 `toplist_filter` 会
  `fetch_recent()` 向源端补拉。11-12 实测源端 asof=20261111 可取 134 条。
- **修法**：`run_preopen.py` 在拿到选票产物后，以 `toplist_filter.status` 为准改写校对结论：
  `OK` 时移除「龙虎榜」相关降级告警，替换为「本地缺、源端已补拉、V1b 生效（来源 X）」；
  非 OK 时追加「上榜过滤未生效」显式告警。**只改报告结论，不改选票判定**。

### P0-4 `--skip-pick` 只看文件存在就复用 `[已修·已验证]`

- **现象**：11-12 08:27 用 11-11 的 json 出了一份抬头写 11-12 的报告，
  外观与当天新算完全一致，转发后无法分辨。
- **根因**：`reused = bool(a.skip_pick and os.path.exists(pick_json))`。
- **修法**：复用前校验两条溯源字段 —— `data_day == day` 且
  `chain_policy_v == POLICY_V`；不满足则 `rc=3` 阻断，并写
  `steps[].error = stale_reuse`，打印「请去掉 --skip-pick 重算」。
  溯源从「打印一行让人自己看」升级为「能阻断」。
- **验证**：拿 11-11 的产物以 11-12 目标日跑 `--skip-pick`，必须 rc=3。

### P0-5 涨停两套口径 + 官方表落后被当成当日交叉验证 `[已修·已验证]`

- **现象**：报告「数据体检」里的涨停家数与「筛选路径」里被剔除的昨日涨停数对不上；
  校对还冒出一条「自算比官方多 2 只涨停」的当日告警。
- **根因**（两处叠加）：
  1. `audit_preopen.limit_counts()` 用「收盘价触及涨停价（含首日新股单列）」，
     服务于**情绪统计**；`rate()` 用 `limit_up = (high == close) and chg > 0.09`，
     服务于**次日开盘不可买入**。两者用途不同，报告却未标注，读者以为是同一个数。
  2. 实测 `off_max = 20261110`（落后目标日 **2 个交易日**）；11-12 的
     `d_20261112.parquet` 是 0 行空表，但 `max_date()` 会跳过 0 行分片。
     于是交叉验证拿两天前的历史表与历史自算比对，「自算独有 2 只（新股/边界）」
     被当成**当日问题**告警，报告也只写日期、不写「这是历史日」。
     （另需防御：哪天 `cmp_day` 恰好选中 0 行分片，同样会出假告警 ——
     官方给空 ≠ 官方确认没有涨停。）
- **修法**：判定抽成纯函数 `limit_cross_check(target, cmp_day, lag_days, fu, off)`：
  - `off.empty` → `official_empty=True`，跳过差异比对并明确告警；
  - `cmp_day != target` → `is_target_day=False` + `lag_days`，差异只记进
    `cross_check`，**不进当日 warns**；render / H5 标「历史日 …，不是当日问题」；
  - 只有同日比对才允许差异告警。
  - render 与 H5 各加一句口径说明（收盘触板 = 情绪 / 封板且涨幅超 9% = 剔除）。
- **验证**：11-12 校对 warns 中「自算比官方多 2 只」消失；`cross_check` 带
  `is_target_day=False, lag_days=2, note=历史比对`；H5 两个口径分别标注。

### P0-6 口径版本 `POLICY_V=4` 与底层产物 `chain_policy_v=3` 错配 `[已修·已验证]`

- **现象**：`--skip-pick` 复用时，任何当前合法产物都会因版本不符被永久阻断（假阳性）。
- **根因**：`tools/preopen/run_preopen.py:57` 写 `POLICY_V = 4`，而
  `zerobound-kg/factor_proto/_preopen_pick15_v2_adj.py:347` 产物写 `chain_policy_v: 3`、
  `fg_daily_chain.py:68` 写 `REFINE_POLICY_V = 3`。三处本应一致，且注释里已写明
  「改动任何会改变名单的口径才 +1」。本轮没有改 `rate()` 口径，不该升版本。
- **修法**：`POLICY_V` 回落到 **3**；补 `tools/tests/test_preopen_gate_fixes.py`
  断言三处数值一致（防止下次又只改一处）。
- **边界**：若将来真改了过滤/复权/打分，必须三处一起 +1，测试会强制这一点。

### P0-7 精排日与共识包日期硬编码，每日名单不推进 `[已修·已验证]`

- **现象**：`_preopen_pick15_v2_adj.py:31-32` 默认 `PKG_DIR="20261109"`、
  `ASOF_LAST="20261110"`。不显式传参就永远产出 11-10 数据日的同一份名单；
  11-13 盘前若不察觉，会拿两天前的票当新票发。
- **根因**：脚本是「只读分析件」出身，参数是写死的；虽已支持 `--pkg/--asof`，
  但默认值没有随日推进，也没有「默认值是否过期」的提示。
- **修法**（不改打分）：把默认值改为**自动取最新可用**，但必须满足两条：
  ① `asof` 只取 `ts_daily` 里真实存在的最后交易日（不顶替、不猜测）；
  ② `pkg` 取 `strategy_center_inbox/` 下最新目录，并在产物里显式写
  `package_lag_days`，让「池子滞后」可见而不是静默。
  `--pkg/--asof` 显式传参优先，历史复现能力保留。
- **验证**：不带参数运行，`refine_date` 应为 11-12 且 `package_asof` 仍为 11-10，
  产物里 `package_lag_days` 有值；与显式传参结果逐票一致。

### P0-8 行业数据断供，一个空列表干掉整份报告 `[已修·已验证]`（11-13 反哺抓到）

- **现象**：11-13 盘前全流程 [2/5] 选票成功、15 只落盘，
  [3/5] 简报抛 `IndexError: list index out of range`，整轮 rc=3，
  报告没出来 —— 而它只是缺了一个**非必需**的行业板块。
- **根因**：`build_preopen_report.collect()` 只要 `SECTOR` 文件存在就塞
  `d["sector"]`，哪怕 `cur = sc[sc.trade_date == day]` 是 0 行，
  于是 `top=[]` / `bottom=[]` 但 dict 仍 truthy；`derive()` 里
  `t = s["top"][0]` 直接崩。板块上游自 10-22 后再没抓过（铁律⑧：
  上游断供 / 本地漏跑 / 架构停更是三件事，措辞必须分开）。
  H5 同段渲染也用了 `s["top"]` / `s["bottom"]`，同样假设非空。
- **修法**：
  - `collect()`：`len(cur)==0` 时不设 `sector`，改设 `sector_missing`，
    文案写「最新只到 X 日、未接上数据日 Y；上游未产出，不是本地漏跑，
    也不是架构停更」。
  - `derive()` / `render()`：分支收紧为 `sector and top and bottom`；
    否则写一句降级说明 / 出一张 warn 卡片，**不静默、不崩**。
- **验证**：11-13 报告正常生成；验收脚本断言「本节略过」出现在 H5；
  变异检验把分支改回 `if d.get("sector")` 后
  `test_derive_survives_empty_sector` 必须 FAIL（实测 KILLED）。
- **教训**：这是「反哺」真正的价值 —— 前面 12 项都是读代码读出来的，
  这一项只有把修复后的链路真跑一遍才暴露。**非必需数据块必须能降级**，
  否则上游一次断供就等于整个 Agent 停摆。

## 2. P1 展示口径与合规项（不阻断，但会误导读者）

### P1-1 「量比」名不副实 `[已修·已验证]`

- `build_preopen_report.py:571` 展示 `量比 %.2f`，取的是 `vr`。
- 实际 `vr = vols[-1] / mean(vols[-21:-1])`，是**当日成交量 / 前 20 日均量**；
  标准「量比」是分时口径（当日每分钟均量 / 过去 5 日每分钟均量）。两者不是一回事。
- 修法：改为「量能倍数 <b>x</b>（当日量 ÷ 前 20 日均量）」，术语压进抽屉说明。

### P1-2 「四项加权」把因子取值当权重展示，且动量口径自相矛盾 `[已修·已验证]`

- `build_preopen_report.py:566-569` 写「评分由四项加权：量能健康 0.xx、
  当日收涨确认 0.xx、均线趋势 x、动量位置 x（动量以池内排序名次计）」，
  实际打印的是 `vol_h / confirm / trend / r10` 这**四个因子的取值**，不是权重。
- 真实口径：`score = 0.10*mom_rank + 0.10*trend/2 + 0.45*vol_h
  + 0.00*liq + 0.35*confirm`，有效系数 `0.45*vol_h + 0.35*confirm
  + 0.10*mom_rank + 0.05*trend`。
- 且文案说「动量以池内排序名次计」，展示的却是 `r10`（原始 10 日动量 %）；
  名次 `mom_rank` 在产物 `full_rated` 里有，但 `top15_adj` 的 `cols` 没带出来。
- 修法：抽屉里分两行 —— 「权重」给固定系数（含 trend 的 /2 说明），
  「本票取值」给因子值；动量同时给 `r10` 与 `mom_rank`，
  缺失时显示「未记录」而不是拿 `r10` 冒充名次。

### P1-3 「流动性无区分度已剔除」措辞不实 `[已修·已验证]`

- `build_preopen_report.py:579`：v5 里 `liq` 的权重是 **0.00**，因子仍在公式中，
  并没有「剔除」。写成剔除，等于宣称改了模型结构。
- 修法：改为「流动性因子权重置 0（分层实测无区分度）」，与 P1-2 的权重行对齐。

### P1-4 模块注释硬编码「82 → 79 → 15」 `[已修·已验证]`

- `build_preopen_report.py:10` 用固定数字举例。池子数、剔除数每天不同，
  固定示例会被后来人当成契约值，也可能被复制进正文。
- 修法：改为符号化表述「共识池 → 剔除昨日涨停 → 剔除龙虎榜 → 参与打分 → 入选 15」，
  数字一律由产物字段现算（页面已是现算，注释同步）。

### P1-5 v5 打分口径缺预判单 `[已修·已验证]`

- 规范 `docs/2026-11-11_调参实验预判规范_v1.md`：产生新信号假设的实验开跑前
  必须有 `quant_backtest/experiments/<EXP>/precheck.yaml`。v5（参数层第 6 组）
  是 11-12 实跑后才补的权重，没有预判单。
- 修法：回填 `P71_v5_backfill/precheck.yaml`，按真实分层结果填
  `spread` 上限 / 放弃线 / 证伪条件，`attempts.total_trials=6`、
  `cost_sensitivity` 按 0.20/0.30/0.50 三档 derived；`verdict` 应为 `abandon`
  或至少「止血不等于 alpha」。**回填只为留痕，不代表事后信息可事先预知**
  （与 P69_backfill 同一处理）。

## 3. P2 仅记录、不改代码 `[仅记录]`

### P2-1 `vol_h` 二值化造成头部同分退化
`vol_h` 只有 0 / 0.5 / 1 三档，权重 0.45；`confirm` 二值、权重 0.35。
两者合计 0.80，头部票很容易同分，排序实际由 `mom_rank`（0.10）决定，
而 `mom_rank` 分层实测是倒 U 型（Q1 +0.645 / Q3 +1.082 / Q5 +0.505）。
这解释了 11-12 复盘里「Top1-5 反而最差」的一部分。属模型结构问题，
**不在本轮改**（改了就破坏 11-13 与历史可比性）。

### P2-2 共识池包滞后
`strategy_center_inbox` 只有 11-06 / 11-09 / 11-10 三个目录，
11-12 精排用的是 11-10 的包，滞后 2 个交易日。这是**上游断供**，
不是本地漏跑、也不是架构停更，三者必须分开写。
本轮只在产物里加 `package_lag_days` 让它可见，不造池、不补包。

## 4. 非缺陷、但必须留痕（已在事件账）

11-12 盘后复盘：15 只开盘→收盘 -1.265%，全市场 -1.514%，
扣 0.30% 成本后 -1.565%；**评分排序反向**：Top1-5 -2.50%（胜率 0%）、
Top11-15 -0.52%（胜率 60%），全池 score~收益 rho = -0.083 / -0.145。
结论是「波动收窄 + 市场 beta」，不是选股 alpha。

按自进化账本单位，它作为 `drift` 挂到 `signal_day=20261111` 的既有事件
（幂等键 `(id, exec_day)`），**不新开流程账**；`SCORE_RANK_INVERTED` 归 `param`
方向，只记账 + 质询，永不自动提调参建议（六次实验已否决参数层）。
单日、极端普跌日，按 20 天判决门槛只登记观测。
