### 6.1 三层信源结构（M1，冲突时上层覆盖下层）
| 层 | 源 | 性质 |
|---|---|---|
| 1 核验层 | 交易所公告、irm/sse 的**公司回复**（reply_content） | 可核验事实 |
| 2 主干证据层 | 新闻流、机构研报原文 | 报道与分析 |
| 3 参照层 | taoguba/xq/股吧帖文、**无回复的投资者提问** | 情绪与传闻 |

### 6.2 事实状态词法标注（M2/M3，FS 判据机械部分）
- 词表：plan=计划措辞（拟/计划/预计/争取/规划/筹备/意向/有望/目标…）、fact=事实措辞（已完成/已投产/已签署/获得/落地/中标…）、mixed/neutral。
- **标注附命中词与原句 quote，必须人工复核后才可引用**；词法≠事实裁定。
- 工具：`news_collector/fact_type_annotate.py`（只读源 → `data/fact_type/{src}/{code6}.jsonl`，标注粒度 = ref_id × field）。

### 6.3 传闻-澄清对账底表（M4）
- 工具：`news_collector/rumor_verification.py` → `data/rumor_check/reconciliation_<时刻>.json`。
- 每 code 列官方端/传闻端计数与最新引用；**「核验结论」栏一律留空**（status=pending），由分析岗填写——本席止于对账，不裁事实。
- 首跑（2026-11-10）：632 code，两端齐备 102 / 仅官方 1 / 仅传闻 529。

### 6.4 输出纪律（M5/M9/M10）
1. 任何数字必须带**口径与出处**列（判例：164 池 489 vs 593 开关口径差）。
2. 引用公司说法固定句式「据公司公告（公告号）/据互动易问答（ID）」，计划措辞（拟/预计/争取）**保留原样，不得压缩为已发生**。
3. 重大盘点末尾固定附「未采用项」+「局限性声明（五项模板）」。
