## 〇、三条不可协商

1. **K5 阶段一只打标签，不加权。** 权重不是"觉得重要就多给"，必须有标定依据。没有标定前给权重，等于把主观偏好写死进历史数据，以后无法回溯。
2. **K8 不剔除周期日，只做分层。** 把周期日过滤掉会把真实信号一起过滤。正确做法是分两组各自统计，再比较。
3. **席位只到营业部/席位层，不下钻自然人。** 已实测取证（§3.2）。

## 一、K5 · 四窗口口径

### 1.1 窗口定义（写死，不再讨论）

时间基准 **Asia/Shanghai**，交易日。窗口归属按**成交时间戳**落点，左闭右开。

| 窗口 | ID | 起止 | 归属规则 | 为什么异常 |
|---|---|---|---|---|
| 竞价可撤段 | `auction_free` | 09:15:00 – 09:19:59 | 挂单可撤 | 虚假申报密集段：**看得见摸不着**，撤单成本为零 |
| 竞价不可撤段 | `auction_lock` | 09:20:00 – 09:25:00 | 不可撤 | 真实意图暴露，挂了就得成交 |
| 开盘五分钟 | `open5` | 09:30:00 – 09:34:59 | 连续竞价 | 隔夜信息的承接/砸盘意图在最初五分钟内集中释放 |
| 盘中 | `intraday` | 09:35:00 – 14:56:59 | 连续竞价 | 基线。**默认参照组** |
| 尾盘竞价 | `close_auction` | 14:57:00 – 15:00:00 | 收盘集合竞价 | 直接决定收盘价（做净值/做图形/做排名） |
| **不计入** | `after_hours` | 15:05:00 – 15:30:00 | 科创板盘后固定价格交易 | 非连续竞价、非集合竞价，单独记账，**不参与任何窗口统计** |

### 1.2 边界情形（这些不写死，实现时必踩）

| 情形 | 口径 |
|---|---|
| 集合竞价的成交时间戳 | 记为 `09:25:00` 那一笔，归 `auction_lock`；**不得**因"时间戳是 09:25"就归到盘中 |
| 09:25:00 – 09:29:59 | **静默期，无成交**。若出现记录，属数据异常，标记 `suspect_ts` 并单列，不静默丢弃 |
| 停牌期间 | 无记录；窗口标签仍按时间赋，不做特殊处理（停牌是"没有"，不是"异常"） |
| 临时停牌（科创/创业 30%、60% 档） | 同上。但「复牌首笔」单独打 `resume` 标，供后续分析 |
| 北交所 | 集合竞价时点与沪深一致，窗口定义通用 |
| 半日市 | A 股无常规半日市；若遇特殊安排（如跨年），当日整体标 `special_session` 并**排除出周期统计** |
| 时间戳精度 | 分钟级数据只能赋到窗口，**不能赋到秒级事件**；喊"09:31:47"这类结论必须有秒级数据支撑，否则不许写 |

### 1.3 阶段划分（写死，防越界）

- **阶段一（现在）**：只打窗口标签，输出 `window` 字段。统计时按窗口分组展示，**权重一律相等**。
- **阶段二（有标定数据后）**：用"该窗口异动后 N 日的实际强度"回归标定权重。标定前**禁止**任何硬编码权重（如"开盘五分钟 ×2"）。
- **禁止**：把窗口标签当过滤器用（"只看盘中"）。窗口的价值在于**对比**，不在筛选。

## 二、K8 · 周期口径

### 2.1 六个标签（互不排斥，可叠加）

| 标签 | 定义 | 依据 |
|---|---|---|
| `futures_expiry` | 股指期货最后交易日＝合约到期月**第三个周五**，遇法定节假日**顺延至下一交易日** | 中金所股指期货合约规则 |
| `option_expiry` | 股票期权到期日＝到期月**第四个星期三**，遇法定节假日顺延 | 上交所/深交所期权规则 |
| `month_end` | 当月**最后一个交易日**（L1）；另设 `month_end_3`＝最后 3 个交易日（L3 窗口） | 资金面/考核惯例 |
| `quarter_end` | 3/6/9/12 月最后一个交易日 | 考核/报表 |
| `half_year_end` | 6/12 月最后一个交易日（与 `quarter_end` 叠加） | 同上 |
| `pre_holiday` | 连续休市 ≥3 个自然日的长假前最后一个交易日 | 春节/国庆/五一/清明/端午/中秋/元旦 |

### 2.2 三条硬约束

1. **不做剔除，只做分层。** 统计输出必须同时给「周期日组 / 非周期日组 / 全样本」三行。任何只给全样本的统计，视为口径未达标。
2. **回填即重算，禁止新旧混用。** 历史数据一旦打上周期标签，**所有历史结论必须整体重算**。新旧口径混在一张表里，等于给自己造了一个永远对不上的基线（同族判例 #20「重采基线不连带收口口径＝只绿一天」）。
3. **只标已公布年度。** 节假日安排依赖国务院年度通知，2027 年安排未公布前，**不得**用"往年规律推测"生成标签——标不出来就留空 `unknown`，不猜。

### 2.3 已知不确定点（先记账，不解决）

- 期货交割日"遇法定节假日顺延"的**顺延链**：长假导致第三个周五整天休市时，顺延到下一个交易日；但若顺延后与期权到期日重合，两个标签叠加，不做合并。
- 月末 L3 窗口的边界：L3 指"最后 3 个交易日"，**含**月末当天。即 L1⊂L2⊂L3，统计时三档分别出，不取并集。
- 年报/季报披露截止日（4-30 / 8-31 / 10-31）属**消息面**周期，不进 K8 资金面口径；若要，另立 `K8b 披露周期`，不与资金面混算。

## 三、席位边界（红线，带实测取证）

### 3.1 允许 / 禁止

| 允许 | 禁止 |
|---|---|
| `hm_orgs`（营业部/分公司/总部/机构专用/股通专用）作为**标签** | 把 `hm_name`（如"T王""章盟主"）与任何自然人身份做**关联映射** |
| `hm_name`（市场绰号、类型标签）作为**分类维度** | 引入任何外部身份信息（户籍/实名/联系方式）补全绰号 |
| `reason` 归一化后的**上榜族** | 对"某个游资是谁"下任何结论、写进任何产品 |
| 席位级别的**聚合统计**（几个营业部同向） | 下钻到营业部**客户明细**（本仓无此数据，将来有也不接） |

### 3.2 实测取证（2026-11-11，`ts_hm_detail` 当日全量）

| 检查项 | 结果 |
|---|---|
| `hm_orgs` 去重数 | 51 |
| 其中呈自然人形态（不含"证券/营业部/专用/分公司/总部/基金/资管/席位"字样） | **0 条** |
| `hm_name` 去重数 | 26 |
| 高频 `hm_name` | 机构专用 45 / 量化基金 31 / T王 29 / 深股通专用 22 / 温州帮 18 / 沪股通专用 17 / 量化打板 12 / 低位挖掘 4 / 章盟主 4 / 呼家楼 3 |

**结论**：`hm_orgs` 层是干净的机构标识；`hm_name` 是**类型标签 + 市场绰号**的混合体（"呼家楼"是地名、"章盟主"是江湖绰号），**不含实名**。边界可以定在"营业部/席位层"，且有取证支撑，不是凭印象。

### 3.3 为什么这条边界必须写死

数据里没有实名，不代表用起来不会越界。**一旦开始回答"这个人是谁"，就必须引入外部信息，那一步就已经出圈了**。所以红线不设在下钻动作上，设在**提问方式**上：允许问"哪类席位在接"，禁止问"哪个人在接"。

## 四、两表接入设计（探针实测，未落代码）

### 4.1 字段与体量（实测）

**`ts_top_list`（龙虎榜，107,021 行）**

| 字段 | 含义 | 备注 |
|---|---|---|
| `ts_code` / `trade_date` / `name` | 标的与日期 | — |
| `close` / `pct_change` | 收盘、涨跌幅 | — |
| `net_amount` / `l_buy` / `l_sell` / `amount` | 净额、前五买入、前五卖出、成交额 | **个股级汇总** |
| `reason` | 上榜原因 | 见 4.2 坑 |

> ⚠️ **重要**：`ts_top_list` **没有营业部字段**（实测 `has_org_field=false`）。要席位级必须走 `ts_hm_detail`。两张表不是"详略两版"，是**两个不同对象**（个股汇总 vs 席位明细）。

**`ts_hm_detail`（游资/席位明细，151,838 行）**

| 字段 | 含义 |
|---|---|
| `trade_date` / `ts_code` / `ts_name` | 日期、标的 |
| `buy_amount` / `sell_amount` / `net_amount` | 该席位买入/卖出/净额 |
| `hm_name` | 类型标签或市场绰号（26 个/日） |
| `hm_orgs` | 营业部名称（51 个/日） |

### 4.2 三个必踩的坑（实测）

1. **`reason` 同一含义多种写法**。11-11 的 12 种里就有「前五只证券」与「前5只证券」、「有价格涨跌幅限制的日换手率达到20%」与「当日换手率达到20%」、创业板「达到20%」/主板「达到7%」/北交所「达到30%」。**不归一化就没法分组统计**，必须建映射表（映射表落 `config/`，不进代码）。
2. **当日不可用（T+0 延迟）**。11-12 23:23 查当日：`ts_top_list` 0 行、`ts_hm_detail` 0 行，而 `ts_limit_step`（连板晋级）当日已有数据。
   → **定性：龙虎榜/游资明细只能做事后归因，不能进盘中链路**。任何"盘中看游资"的设计在这一层就已经不成立。
3. **日期过滤可用**（与 `ts_stk_mins` 相反）。`20261111` 与 `2026-11-11` 两种格式都返回正确 `total`（75 / 209）。**不需要**像分钟线那样倒序抓再本地筛——这条要写进客户端注释，否则后来的人会照着分钟线的坑去绕路。

### 4.3 覆盖度（实测 2026-11-11）

| 指标 | 值 |
|---|---|
| `ts_top_list` 行数 / 去重标的 | 75 / 75（1 标 1 行） |
| `ts_hm_detail` 行数 / 去重标的 | 209 / 74 |
| 席位明细对龙虎榜的标的覆盖 | **74/75 = 98.7%** |
| `hm_name` / `hm_orgs` 去重 | 26 / 51 |

平均一只票 2.8 个席位记录——说明**席位明细不是全席位，只有上榜的前五买卖席位**。这一点必须写进口径：**"跌幅/涨幅前五"是抽样，不是全量**，任何"某游资今天买了多少"的结论都受此限。

### 4.4 落盘设计（待实施，先定形状）

- 一表一日一快照：`data/top_list/YYYYMMDD.parquet`、`data/hm_detail/YYYYMMDD.parquet`
- 幂等：按日覆盖 + 写前备份；**参考判例 #27**——不能"目标日已有 ≥N 行就算补齐"，必须"该日 `_fetched_at` 晚于收盘且行数与远端 total 一致"才算补齐
- 采集与消费分离（JEV 职责边界）：采集是 `tools/*_fetch.py`，`portal/jev_*.py` 只读快照
- 回填范围：先只回 11-01 起（够 T-191 交叉卡用），不做全历史（107k 行全量回填无必要，且无对应分析需求）

## 五、与 K3/K4/K9 的对应（接上第四辑）

| 第四辑条目 | 本口径提供的解 | 还缺 |
|---|---|---|
| K3 多次累积大额 | `ts_hm_detail` 按 `hm_orgs` 累计净额 | 跨日累计口径（窗口多长？建议：连续 5 个交易日滚动） |
| K4 频繁 | 同一 `hm_orgs` 在同一票上出现次数 | 出现次数≠对倒，需与分钟级同步成交对齐才能判对倒 |
| K9 对手分布 | `hm_name` 分类 + `reason` 族 | 分类映射表（26 个标签归成"机构/量化/游资/股通/其他"五族） |

**注意**：K4 的"频繁"在龙虎榜数据上**只能看到上榜日的席位**，非上榜日看不到。所以"同一营业部连续 5 天出现在同一票"这个结论，**分母是"该票上榜的天数"，不是"该票交易的天数"**。分母写错，频率就全是假的。
