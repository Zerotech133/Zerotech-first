## 4. null_owner FAIL 归因（重要，非本轮 E2E 造成）

`--strict` 报 20 行归属 NULL：`v2_trade_plan` 5 + `v2_order_intent` 5 + `v2_position` 5 + `v2_approval_request` 5，**全部产生于 2026-09-07 22:21:50–51 同一调度周期**（plan_id 形如 `plan-cand-v1-crypto-sv-3-BNB/USDT-202609071421`，即内置公共策略 v1-crypto-sv-3 的 CRYPTO 采集/计划作业）。

- 根因：本机 scheduler 以 **legacy 模式**在跑，legacy 执行链路（orchestrator 经路=真实交易）**设计上不写** user_strategy_id/account_id；这些行是回填完成**之后**调度器新生成的（回填本身已完成且经查无 cross_user/orphan 等缺陷，其余 7 项全 PASS）。
- 该 FAIL 正是 0024 NOT NULL 门存在的意义：**先切 enforced（runbook 阶段动作）→ 调度器停止产 NULL 行 → 清残留/复跑 strict 8/8 → 才允许 upgrade 到 0024**。本任务纪律禁止改 env 切模式/重启服务/删改既有行，故如实记录为环境态 FAIL，不属本轮 E2E 回归（20 行时间戳早于本轮所有旅程的首个写操作）。
