## §1 UAC 操作清单表

今日实测取证基线：8787 当前监听进程 PID 49536（python.exe，**SessionId=1，Owner=DESKTOP-ARF447U\t**）——即 Guard30 用户态拉起的进程属于交互用户身份，**用户态可杀**；只有「由 Services 会话（session-0）SYSTEM 身份启动的旧 8787 实例」用户态 taskkill 拒绝访问（restart_hermes_8787.ps1 头注释 + start_hermes_bg.py L52 守卫注释双重印证）。

| # | 操作 | 触发频率 | 现有路径 | 所需权限 | 能否用户态替代 |
|---|------|---------|---------|---------|--------------|

## §2 高权限自愈任务设计（Gate 0 后注册的方案稿）

### 2.1 任务规格

| 项 | 取值 | 理由 |
|---|---|---|
| 任务名 | `Hermes8787-KillSvc` | 与 Guard 三件命名风格一致；Svc= privileged service action |
| Principal | `UserId=SYSTEM`，`LogonType=S4U（ServiceAccount）`，`RunLevel=Highest` | SYSTEM session-0 令牌可杀任何会话进程（含旧 SYSTEM 8787）；S4U 免密码免弹窗；今天 8787 的用户态实例它同样杀得动，单任务覆盖三态 |
| 触发方式 | **无时间触发器**，仅被转调（Start-ScheduledTask）或管理员手动触发 | 白名单化核心之一：不存在定时误杀窗口 |
| Action | `C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe` `-NoProfile -ExecutionPolicy Bypass -File "C:\项目\老田的AI助手\Hermes\hermes_kill_8787.ps1"` | **Execute 固定指向专用白名单脚本，不携带任何参数**——任务不接受输入、不提供任意命令执行（验收③核心） |
| Settings | `ExecutionTimeLimit=PT5M`；`MultipleInstances=IgnoreNew`；`DisallowStartIfOnBatteries=false`；`StartWhenAvailable=false` | 快进快出、防并发重复杀、电池机不停 |
| 权限边界 | 注册后确认 ACL：作者账户 `t` 持有 Start 权限（默认即有） | 保证任意普通用户态进程/Guard 可 Start-ScheduledTask 转调（无 UAC） |

### 2.2 动作白名单脚本 `hermes_kill_8787.ps1`（约束要点）

脚本内**只做**以下固定逻辑，逐条即验收③的白名单边界：

1. **无 param 块**：不接受任何参数、不读环境变量控制字、不 eval/Invoke-Expression 任何外部输入；
2. **按端口找 PID**：`Get-NetTCPConnection -LocalPort 8787 -State Listen` 取 `OwningProcess`（复用 kill8787.ps1 的 netstat 法亦可，取前者更结构化）；
3. **杀前身份核对**（防误杀）：`Get-CimInstance Win32_Process` 核对该 PID 的 `CommandLine` 必须匹配 `hermes-webui-next\server.py`（或回滚基 hermes-webui\server.py），**不匹配则记日志拒杀退出**——即使端口被别的进程占用也不会错杀；
4. **taskkill /F /PID**：仅此一个破坏性命令，目标 PID 来自第 2/3 步的硬校验；
5. **端口释放确认**：最多等 10s（复用 restart_hermes_8787.ps1 L27-34 配方），超时如实记日志不谎报；
6. **幂等**：8787 无监听 → 直接 exit 0（拉活交给 Guard30，本任务**只杀不拉**——kill8787.ps1 判定的最佳实践形态：提权侧最小动作，拉活留在用户态伴生守护）;
7. **固定日志路径**：`C:\aios\Hermes\kill_svc.log`，每步落盘（时间戳、PID、rc），供转调方与验收②取证。

### 2.3 转调方式

任何普通进程/守护/交互会话执行：

```powershell
Start-ScheduledTask -TaskName 'Hermes8787-KillSvc'
```

无需提权、无 UAC 弹窗（对计划任务的 Start 是写任务状态，作者账户默认有权）。**高权限只存在于任务进程内部**，转调侧零提权——R7 设计稿"普通进程只转调、不自行提权"的落地形态。

## §3 转调链路设计（Guard30 / N1 晨检 → KillSvc → Guard30）

### 3.1 8787 三态判定与处置路径

| 态 | 现象（判定口径） | 处置 | 所需权限 |
|---|---|---|---|
| A 进程消失 | `Get-NetTCPConnection -LocalPort 8787 -State Listen` 为空 | 直接 `Start-ScheduledTask HermesWebUI-Guard30`（现有路径） | 用户态，**已覆盖** |
| B 进程僵死 | **端口有 LISTENING 进程 且 HTTP 真探连续失败**：`Invoke-WebRequest http://127.0.0.1:8787/api/observe/state -TimeoutSec 5` 连续 3 次（间隔 20s，共约 1 分钟窗口）全部超时/5xx | `Start-ScheduledTask Hermes8787-KillSvc` → 等端口释放（最多 60s 轮询）→ `Start-ScheduledTask HermesWebUI-Guard30` | 转调无 UAC；杀 SYSTEM 僵尸由任务内部高权限完成 |
| C 端口被占 | 端口有 LISTENING 但 PID 的 CommandLine **不匹配** server.py（含 #3 身份核对不过） | 同态 B 转 KillSvc——白名单脚本第 3 步身份核对通过（匹配 server.py 的 8787 owner）才杀；不匹配则只记日志告警**拒杀**，人工介入 | 转调无 UAC；非白名单目标一律不动手 |

### 3.2 防抖（避免杀活进程）——判定口径硬约束

1. **双条件齐备才判僵死**：进程存在（端口 LISTENING）**且** HTTP 真探连续 3 次失败。TCP 通但 HTTP 不响应 = 半死，同样计入僵死（真探口径沿用 restart_hermes_8787.ps1 第 4 步 `/api/observe/state`）；
2. **单条件不动作**：仅探测失败但端口无监听 → 态 A，走 Guard30 拉活；仅进程存在探测正常 → 健康态零动作；
3. **杀前二次核对**：KillSvc 脚本内部身份核对（CommandLine 匹配 server.py）是最后一道闸，转调方判定错了也杀不到白名单外进程；
4. **冷却窗**：转调方记录上次触发时间戳于状态文件（如 `C:\aios\Hermes\killsvc_lasttrigger`），**10 分钟内不重复触发**（KillSvc 实际耗时 <1min，Guard30 拉活 ~25-40s，10min 足够整链收敛）；
5. **ExecutionTimeLimit=PT5M + IgnoreNew**：任务自身兜底防僵尸任务堆积；
6. **Guard30 天然防抖**：30min 伴生周期本身错开冷却窗，二者叠加后实际触发频率上限为每 30min 一次。

### 3.3 转调方实施载体（Gate 0 后二选一，另单定）

- **轻量版**：Guard30 拉起链的 start_hermes_bg.py 前置探测处，探测失败且进程存在时 subprocess 调 `schtasks /Run /TN Hermes8787-KillSvc`（与 Start-ScheduledTask 等价，均无 UAC）；
- **独立版**：N1 晨检/联动层一期自愈任务内嵌 §3.1 判定逻辑转调（推荐——不动 start_hermes_bg.py 判过线的幂等语义，只读探测无副作用）。

## §4 注册与演练步骤（**Gate 0 后执行**，现阶段禁止）

### 4.1 注册命令全文（管理员 PowerShell 一次性）

```powershell
# 前置：白名单脚本已落盘 C:\项目\老田的AI助手\Hermes\hermes_kill_8787.ps1（内容=§2.2 七条约束）
$action  = New-ScheduledTaskAction -Execute 'C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe' `
           -Argument '-NoProfile -ExecutionPolicy Bypass -File "C:\项目\老田的AI助手\Hermes\hermes_kill_8787.ps1"'
$principal = New-ScheduledTaskPrincipal -UserId 'SYSTEM' -LogonType S4U -RunLevel Highest
$settings = New-ScheduledTaskSettingsSet -ExecutionTimeLimit (New-TimeSpan -Minutes 5) `
            -MultipleInstances IgnoreNew -DisallowStartIfOnBatteries:$false -StartWhenAvailable:$false
Register-ScheduledTask -TaskName 'Hermes8787-KillSvc' -Action $action -Principal $principal -Settings $settings -Force
# 核验（只读）：
Get-ScheduledTask -TaskName 'Hermes8787-KillSvc' | Select-Object TaskName, State
(Get-ScheduledTask -TaskName 'Hermes8787-KillSvc').Actions | Format-List Execute, Arguments   # 确认无参数注入面
```

> 无触发器注册：`Register-ScheduledTask` 不传 `-Trigger` 即为纯手动/转调触发。注册动作用管理员（判例 #5：SYSTEM/S4U 任务须提权注册），**注册是一次性**，之后全生命周期零 UAC。

### 4.2 验收②演练步骤（安全模拟挂死，不伤真服务）

1. **准备诱饵僵死进程**（模拟态 B 且进程身份可白名单匹配）：临时把真 8787 优雅停掉（当前实为用户身份进程，用户态可杀），再起一个诱饵监听者——用同一 server.py 路径的 python 起一个「只绑端口不响应 HTTP」的最小脚本（或直接 `python server.py` 后挂起其 HTTP 线程的等效最小仿制品），保证诱饵 CommandLine 含 `server.py` 以通过白名单核对；
2. **触发转调**：在**非提权**普通 PowerShell 里执行 `Start-ScheduledTask -TaskName 'Hermes8787-KillSvc'`；
3. **断言**：① 全程无 UAC 弹窗；② `C:\aios\Hermes\kill_svc.log` 出现「found PID→identity OK→killed rc=0→port freed」；③ 30s 内 `Start-ScheduledTask HermesWebUI-Guard30` 拉活，`/api/observe/state` 200；
4. **反向断言（验收③）**：诱饵脚本换成 CommandLine 不含 server.py 的普通端口监听（如 `python -m http.server 8787`），重复步骤 2——日志应出现「identity mismatch, refuse to kill」，端口占用原样保留，**证明白名单拒杀生效**；
5. **恢复现场**：重新 Start-ScheduledTask Guard30 拉回真服务，核验 console 卡片可见。
