# 敏捷开发与治理标准 v1（ADGS v1）

- 状态：**Proposed（待 A0 拍板）**
- 日期：2026-11-02
- 适用：零界全项目开发（人类 + AI Agent + 军团席位 + 外部协作者）
- 上位文件：`AGENTS.md`（宪法）> 本标准（开发节奏与门禁元标准）> 专项标准（质量分级/版本发布/安全/L2）
- 关联：ADR-015（内核契约）、ADR-016（唯一宿主）、ADR-017（黄金路径）、ZBF v1 框架总纲
- 一句话：**价值先行、分级治理、自动化门禁、证据验收、波次交付、WIP 受限。**

## 一、为什么需要这个标准

项目已有大量资产（8,042 tracked files / 4,139 py / 1,673 测试 / 307 计划 / 53 worktree / 18 parked），但过去 40 天反复出现同一组问题：两套栈并行、声明不接执行、没有唯一排期源、WIP 膨胀、merge 竞态、并行清理事故、rc=0 当产出。敏捷开发本身没问题，问题是**没有"既快又稳"的轨道**。

本标准的定位：**不搞瀑布、不加会议，给敏捷加两条轨道和四道闸。**

## 二、五条原则（冲突时按顺序）

1. **价值优先**：可工作的增量 > 完整文档；但"能演示"必须能"被证据证明"。
2. **分级治理**：风险越高，门禁越重；不许用同一把尺子卡所有事。
3. **自动化优先**：能机器判定的不靠人工；能用模板的不手写。
4. **单一真源**：战略/排期只有 ROADMAP v4；组合只有组合账本；数据口径只有数据契约。
5. **小批量与 WIP 限制**：同时在做的事越少，交付越快；WIP 超限即停新开。

## 三、敏捷节奏（轻量、异步、可交付）

| 节奏 | 内容 | 产出 | 时长 |
|---|---|---|---|
| 每日 | 10 分钟对账：在做/WIP/阻塞/今日交付 | 对账一行 + 阻塞清单 | 10 min |
| 双周 | 迭代计划（周一）+ 评审（周五）+ 回顾（双周） | 迭代目标 + 可演示增量 + 复盘 1 页 | 1h/0.5h/0.5h |
| 每周 | 波次评审（W1/W2/W3/W4 进度） | 波次状态 + KPI | 30 min |
| 每月 | 组合账本审计 + KPI + 质量分布 | 月度复盘 1 页 | 1h |
| 每季度 | Kernel Review（内核版本/组合兼容/替换演练） | 框架修订 ADR | 2h |

**波次而非瀑布**：W0 收编 → W1 组合纳管 → W2 单栈 → W3 解耦 → W4 组合化。每个波次结束必须有**可运行增量 + 证据 + 回执**。

## 四、工作项标准（一单到底）

### 4.1 类型

| 类型 | 用途 | 默认车道 |
|---|---|---|
| Epic | 一个波次/一条业务线目标 | 治理道（进 ROADMAP v4） |
| Story | 可交付用户价值（组合/页面/产品） | 标准道 |
| Task | 工程执行项（≤3 天） | 快速/标准道 |
| Bug | 缺陷修复（附复现） | 快速/标准道 |
| Spike | 限时调研（≤2 天，产出结论） | 快速道 |
| Incident | 线上故障（先止血） | 紧急道 |
| Governance | 治理/文档/门禁/制度 | 快速道 |

### 4.2 必填字段（缺一不接单）

`title / owner / value（解决谁的什么问题）/ acceptance（可验证）/ risk（低中高）/ lane（车道）/ write_scope（写域）/ deps（依赖）/ kernel_impact（是否内核）/ rollback（回滚）`

### 4.3 就绪定义（DOR，6 条）

1. 价值与验收可一句话说清；2. 影响面/写域已声明；3. 依赖已就绪或无阻塞；4. 车道已判定；5. 测试/证据方式已定；6. 规模 ≤L（超过则拆）。

### 4.4 完成定义（DOD，8 条，缺一不算完成）

1. 验收标准逐条通过；2. 测试/检查有记录（命令+rc）；3. 证据包入库（见 §8）；4. 文档/回执同批；5. 组合/任务账本已登记；6. 回滚步骤可用；7. 无残留（worktree/临时文件/临时配置）；8. owner 签字（人类或授权 Agent）。

## 五、双车道（标准的核心）

### 5.1 判定表

| 变化内容 | 车道 | 最少门禁 | 审批 | 时限 |
|---|---|---|---|---|
| 文档、注释、测试补充、低风险组合字段 | **快速道** | lint/语法 + 定向测试 + secret scan | 自动 | ≤1 天 |
| 组合新增/变更（非内核）、页面包、通道、数据包小版本 | **标准道** | 快速道门 + `composition validate` + 组合 gate | owner + ARCH1 异步 review | ≤3 天 |
| 内核契约/schema/口径、跨组合接口、认证权限、数据源接入、外部依赖 | **治理道** | 标准道门 + `kernel_guard` + ADR + 专项测试 | A0 + ARCH1（双签） | ≤1 周 |
| 重启服务/改计划任务/凭据区/nginx/宿主机 | **L2 道** | 五要素 + 维护窗口 + 回滚演练 | 老田/A0 | 按窗口 |
| 线上故障（Incident） | **紧急道** | 先止血；24h 内补 ADR/复盘/证据 | owner 自主 + 事后审计 | 立即 |

### 5.2 规则

1. 车道由 **owner 判定、ARCH1 复核**；判定错误视为流程事故；
2. 快车道**不排队**，治理道**不插队**；
3. 同一工作项跨车道时必须拆单；
4. 紧急道不得成为常规通道（月度审计，超过 3 次/月即复盘）；
5. 不允许"先改主链再补单"；不允许绕过门禁（`DEVTOOL_MERGE_GATE=0` 仅回滚/紧急并留痕）。

## 六、门禁矩阵（G0–G4，全自动优先）

| 门 | 内容 | 工具 | 失败处理 |
|---|---|---|---|
| G0 本地预检 | 语法/ruff/定向测试/secret | `check_syntax`、ruff、pytest 定向、`scan_secrets` | 修复后重跑 |
| G1 快车道门 | 路由/预算/导航/端口/Mixin/导入边界 | `devtask merge` 内置九门 | 阻断 |
| G2 组合/治理门 | composition validate + kernel guard + 专项测试 | `composition.py`、`kernel_guard.py` | 阻断 |
| G3 L2 门 | 五要素（命令/影响面/不可逆/替代/回滚） | 人工审批 + 回滚演练 | 未批不执行 |
| G4 发布门 | 健康探针 + SLO + provenance + KPI | 发布脚本/健康检查 | 回滚 |

**门禁纪律**：新增失败一律阻断；flake 隔离修复，不静默放行；"门禁绕过"进月度审计。

## 七、WIP 与并发治理（防失控）

| 项 | 上限 | 超限动作 |
|---|---|---|
| 全平台 doing | ≤ 5 | 停止新开，先收口 |
| 单人/单 Agent 并行写 | ≤ 2 | 排队，禁止多线切换 |
| worktree | ≤ 10 | 先 merge/回收，再新开 |
| parked | ≤ 5 | 逐项定性（续/停/归档） |
| worktree 寿命 | ≤ 7 天 | 超期升级 owner/ARCH1 |
| 单次改动范围 | ≤ 20 文件或 ≤ 500 行（不含生成物） | 超限拆分 |

**并发写域规则**：
1. 任务单必须声明 `write_scope`；重叠即冲突，先协调；
2. 共享文件（AGENTS/ROADMAP/ADR/registry）同一时段只允许一个 owner 写；
3. **禁止在共享仓执行 `git clean -fdx` / `reset --hard`**（11-02 两次清掉未跟踪文件的教训）；
4. merge 竞态时以"先到先得 + 后到 rebase"处理，禁止强推覆盖；
5. 每日固定 merge 窗口（建议 11:00–12:00、17:00–18:00），窗口外只提交不合并。

## 八、证据与完成（无证据不算完成）

**证据包**（每个工作项必须）：

```text
work_item: <TID/ID>
owner / lane / date
commands: <命令全文>
result: rc=0 + 关键输出摘要
artifacts: <文件/URL/截图路径 + sha256（可选）>
acceptance: 逐条勾选
rollback: 步骤
residual: 0（worktree/临时文件/临时配置）
signoff: <owner>
```

**三条铁律**：
1. `rc=0` 不等于有产出（空候选/空结果必须显式说明）；
2. 缺口/失败如实写，不粉饰、不补造；
3. 回执与证据同批；事后补证不算完成。

## 九、质量分级（门禁强度挂钩）

沿用 ZBF v1 的 Q1–Q4：

| 级别 | 条件 | 门禁强度 |
|---|---|---|
| Q1 已登记 | schema + owner + 版本 | 自动门禁 |
| Q2 可运行 | 引用可解析 + 健康 + SLO + 回滚 + 测试 | 自动 + 抽样评审 |
| Q3 可治理 | 数据契约 + 诊断 + 审计 + 替换说明 | ARCH1 评审 |
| Q4 可进化 | 替换演练 + 退役路径 + 季度评审 | 双签 + 演练 |

`active` 至少 Q2；对外/关键至少 Q3；平台核心/长期 Q4。

## 十、度量与看板（少而准）

| 指标 | 定义 | 首季目标 |
|---|---|---|
| Lead time | 工作项从接单到 DOD | 快速道 ≤1 天；治理道 ≤1 周 |
| WIP | doing 数 | ≤5 |
| 变更失败率 | 回滚/返工占比 | ≤10% |
| 逃逸缺陷 | 上线后 P0/P1 | 0 |
| 组合 Q 分布 | Q1–Q4 数量 | active 全部 ≥Q2 |
| 组合账本覆盖 | 在册/实际 | 100% |
| 内核变更数 | 月变更契约文件 | ≤5 且 100% ADR |
| 覆盖率 | fast 门覆盖 | ≥30% |

周报自动生成（或半自动），只报异常与缺口，不堆数字。

## 十一、角色与 RACI（敏捷小队）

| 角色 | 职责 | 关键产出 |
|---|---|---|
| A0/老田 | 产品负责人、最终拍板、L2/例外审批 | 优先级/验收/批准 |
| ARCH1 | 平台架构、治理道评审、门禁维护 | 架构决策/门禁 |
| 领域 owner（席位/人类） | 需求、实现、验收证据 | 工作项 + 证据包 |
| QA（独立） | 独立验收、回归 | 验收报告 |
| 执行 Agent/工人 | 按单执行、按写域提交 | 提交 + 证据 |
| 人类审批 | L2/凭据/停服/例外 | 五要素批准 |

**双周仪式**：计划（周一 30min，只定目标不做详细设计）→ 每日对账（10min）→ 评审（周五 30min，演示+证据）→ 回顾（双周 30min，1 页）。会议不超时；文档先行、异步评审为主。

## 十二、例外与升级

| 场景 | 规则 |
|---|---|
| 框架不适用 | ADR-017 例外流程：ADR + A0 + 临时 adapter + 90 天回归 |
| L2 操作 | 五要素 + 维护窗口 + 回滚演练，老田批准 |
| 紧急 hotfix | 先止血；24h 内补 ADR/复盘；月度审计 |
| 标准冲突 | 安全 > 治理 > 速度；冲突写 ADR 修订 |
| 升级路径 | owner → ARCH1 → A0；响应 SLA：P0 15min、P1 4h、P2 24h |

## 十三、落地与验收（标准也是渐进式）

### 第 1 步：W0（1–2 天）
1. 发布 ROADMAP v4（唯一战略/排期源）；
2. 资产分级台账（Active/Candidate/Legacy/Archive）；
3. WIP 清理：worktree 53→≤10、parked 18→≤5；
4. AGENTS.md 增加本标准的"强条款"（车道/WIP/禁止 clean）；
5. ADR/文档漂移修订。

### 第 2 步：W1（1–2 周）
1. 工具：`composition.py`、`kernel_guard.py`、五类 resolver、模板；
2. 工作项模板/证据包模板/周报模板落地；
3. 度量看板（周报自动）；
4. 试点 2 个（1 个军团组合 + 1 个产品组合），用本标准跑 1 个双周迭代。

### 第 3 步：验收（试点双周后）
- [ ] 试点迭代按时交付 ≥1 个可演示增量；
- [ ] 所有工作项有车道/DOR/DOD/证据包；
- [ ] WIP 未超限、worktree 未超 10；
- [ ] 门禁无绕过；内核变更 100% ADR；
- [ ] 度量看板可查；
- [ ] 复盘 1 页 + 标准修订建议。

### 第 4 步：季度修订
标准版本化（v1.1/v2），变更走 ADR 或标准修订记录；不允许"口头改标准"。

```markdown

  - [ ] ...
```

### B. 每周对账模板

```markdown
## <日期> 周对账
在做: <5 项以内>
本周交付: <已 DOD 项 + 证据链接>
阻塞: <项 + owner + 需要谁>
WIP/ worktree / parked: <数字 + 是否超限>

```

### C. 车道速查

```text
改文档/测试/低风险组合字段 → 快速道
加/改组合、页面、通道、数据包 → 标准道
改内核契约/schema/口径/认证/外部依赖 → 治理道（ADR+双签）
重启/计划任务/凭据/nginx/宿主机 → L2 道（五要素+窗口）
线上故障 → 紧急道（先止血，24h 补证）
```
