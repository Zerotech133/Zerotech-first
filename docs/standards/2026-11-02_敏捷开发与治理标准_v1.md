# 敏捷开发与治理标准 v1.1（ADGS v1.1，试行）

- 状态：**Accepted（试行 2026-11-03 ~ 2026-11-16）**；复审 2026-11-16 由 A0+ARCH1 按试点数据定稿 v1.0 正式版或出 v1.2
- 日期：2026-11-02（v1.1 定稿五件事：试行状态 / WIP 分阶段 / 复核分级 / merge train / 试点范围）
- 适用：零界全项目开发（人类 + AI Agent + 军团席位 + 外部协作者）
- 上位文件：`AGENTS.md`（宪法）> 本标准（开发节奏与门禁元标准）> 专项标准（质量分级/版本发布/安全/L2）
- 关联：ADR-015（内核契约）、ADR-016（唯一宿主）、ADR-017（黄金路径）、ZBF v1 框架总纲、ROADMAP v4
- 一句话：**价值先行、分级治理、自动化门禁、证据验收、波次交付、WIP 受限。**

## 一、为什么需要这个标准

项目已有大量资产（8,042 tracked files / 4,139 py / 1,673 测试 / 307 计划 / 53 worktree / 18 parked），但过去 40 天反复出现：两套栈并行、声明不接执行、没有唯一排期源、WIP 膨胀、merge 竞态、并行清理事故、rc=0 当产出。敏捷本身没问题，问题是**没有"既快又稳"的轨道**。

本标准的定位：**不搞瀑布、不加会议，给敏捷加两条轨道、四道闸。**

## 二、五条原则（冲突时按顺序）

1. **价值优先**：可工作的增量 > 完整文档；但"能演示"必须能"被证据证明"。
2. **分级治理**：风险越高，门禁越重；不许用同一把尺子卡所有事。
3. **自动化优先**：能机器判定的不靠人工；能用模板的不手写。
4. **单一真源**：战略/排期只有 ROADMAP v4；组合只有组合账本；数据口径只有数据契约。
5. **小批量与 WIP 限制**：同时在做的事越少，交付越快；WIP 超限即停新开。

## 三、敏捷节奏（轻量、异步、可交付）

| 节奏 | 内容 | 产出 | 时长 |
|---|---|---|---|
| 每日 | 10 分钟对账：在做/WIP/阻塞/今日交付 | 对账一行 + 阻塞清单 | 10 min |
| 双周 | 迭代计划（周一）+ 评审（周五）+ 回顾（双周） | 迭代目标 + 可演示增量 + 复盘 1 页 | 1h/0.5h/0.5h |
| 每周 | 波次评审（W0/W1/W2/W3/W4 进度） | 波次状态 + KPI | 30 min |
| 每月 | 组合账本审计 + KPI + 质量分布 | 月度复盘 1 页 | 1h |
| 每季度 | Kernel Review（内核版本/组合兼容/替换演练） | 框架修订 ADR | 2h |

**波次而非瀑布**：W0 收编 → W1 组合纳管 → W2 单栈（L1）→ W3 解耦 → W4 组合化。每个波次结束必须有**可运行增量 + 证据 + 回执**。

## 四、工作项标准（一单到底）

### 4.1 类型

| 类型 | 用途 | 默认车道 |
|---|---|---|
| Epic | 一个波次/一条业务线目标 | 治理道（进 ROADMAP v4） |
| Story | 可交付用户价值（组合/页面/产品） | 标准道 |
| Task | 工程执行项（≤3 天） | 快速/标准道 |
| Bug | 缺陷修复（附复现） | 快速/标准道 |
| Spike | 限时调研（≤2 天，产出结论） | 快速道 |
| Incident | 线上故障（先止血） | 紧急道 |
| Governance | 治理/文档/门禁/制度 | 快速道 |

### 4.2 必填字段（缺一不接单）

`title / owner / value（解决谁的什么问题）/ acceptance（可验证）/ risk（低中高）/ lane（车道）/ write_scope（写域）/ deps（依赖）/ kernel_impact（是否内核）/ rollback（回滚）`

### 4.3 就绪定义（DOR，6 条）

1. 价值与验收可一句话说清；2. 影响面/写域已声明；3. 依赖已就绪或无阻塞；4. 车道已判定；5. 测试/证据方式已定；6. 规模 ≤L（超过则拆）。

### 4.4 完成定义（DOD，8 条，缺一不算完成）

1. 验收标准逐条通过；2. 测试/检查有记录（命令+rc）；3. 证据包入库（见 §八）；4. 文档/回执同批；5. 组合/任务账本已登记；6. 回滚步骤可用；7. 无残留（worktree/临时文件/临时配置）；8. owner 签字（人类或授权 Agent）。

## 五、双车道（标准的核心）

### 5.1 判定表

| 变化内容 | 车道 | 最少门禁 | 审批 | 时限 |
|---|---|---|---|---|
| 文档、注释、测试补充、低风险组合字段 | **快速道** | lint/语法 + 定向测试 + secret scan | 无人工（ARCH1 周抽 10%） | ≤1 天 |
| 组合新增/变更（非内核）、页面包、通道、数据包小版本 | **标准道** | 快速道门 + `composition validate` + 组合 gate | owner 自判 + ARCH1 **事后抽检 ≥20%/周** | ≤3 天 |
| 内核契约/schema/口径、跨组合接口、认证权限、数据源接入、外部依赖 | **治理道** | 标准道门 + `kernel_guard` + ADR + 专项测试 | ARCH1 **预审** + A0 批准 | ≤1 周 |
| 重启服务/改计划任务/凭据区/nginx/宿主机 | **L2 道** | 五要素 + 维护窗口 + 回滚演练 | 老田/A0 | 按窗口 |
| 线上故障（Incident） | **紧急道** | 先止血；24h 内补 ADR/复盘/证据 | owner 自主 + 事后审计 | 立即 |

### 5.2 规则

1. 车道由 **owner 自判、ARCH1 抽检复核**；误判视为流程事故，进周报；
2. 快车道**不排队**，治理道**不插队**；
3. 同一工作项跨车道时必须拆单；
4. 紧急道不得成为常规通道（月度 >3 次即复盘）；
5. 不允许"先改主链再补单"；不允许绕过门禁（`DEVTOOL_MERGE_GATE=0` 仅回滚/紧急并留痕）。

### 5.3 复核与例外分级（v1.1 定稿）

| 场景 | 审批 | 报备/记录 |
|---|---|---|
| 快速道 | 无人工；自动门 | 周抽检 10% |
| 标准道 | owner 自判；ARCH1 每周抽检 ≥20% | 抽检结果进周报 |
| 治理道 | ARCH1 **预审** + A0 批准（先 ADR 后实现） | ADR + 双签 |
| L2 道 | A0 批准 | 五要素 + 维护窗口 |
| **小例外**（≤2 周、不触内核/安全/数据口径/外部依赖） | **ARCH1 单签** | 24h 内报备 A0，进例外台账 |
| **大例外**（内核旁路/永久方案/跨系统接口/外部依赖） | **A0 + ARCH1 双签** | ADR-017 例外流程 + 90 天回归 |
| 紧急 hotfix | owner 自主止血 | 24h 内补 ADR/复盘，月度审计 |

## 六、门禁矩阵（G0–G4，全自动优先）

| 门 | 内容 | 工具 | 失败处理 |
|---|---|---|---|
| G0 本地预检 | 语法/ruff/定向测试/secret | `check_syntax`、ruff、pytest 定向、`scan_secrets` | 修复后重跑 |
| G1 快车道门 | 路由/预算/导航/端口/Mixin/导入边界 | `devtask merge` 内置九门 | 阻断 |
| G2 组合/治理门 | composition validate + kernel guard + 专项测试 | `composition.py`、`kernel_guard.py` | 阻断 |
| G3 L2 门 | 五要素（命令/影响面/不可逆/替代/回滚） | 人工审批 + 回滚演练 | 未批不执行 |
| G4 发布门 | 健康探针 + SLO + provenance + KPI | 发布脚本/健康检查 | 回滚 |

**门禁纪律**：新增失败一律阻断；flake 隔离修复，不静默放行；"门禁绕过"进月度审计。

## 七、WIP 与并发治理（v1.1 定稿：分三阶段）

| 阶段 | 时间 | doing | worktree | parked | worktree 寿命 |
|---|---|---|---|---|---|
| **W0 止血** | 11-02~11-04 | ≤8 | **≤20** | ≤8 | ≤14 天（超期必须 owner 定性） |
| **试点校准** | 11-03~11-16 | ≤6 | ≤15 | ≤5 | ≤10 天（可 ARCH1 延一次） |
| **季度目标** | 12-31 | ≤5 | ≤10 | ≤5 | ≤7 天 |

**计数口径（防玩数字）**：
- `doing` = TaskStore `doing` 单数 + 活跃 worktree 中未提交改动的任务数，两个都统计；
- **L2/事故单不计入 WIP 配额**，走独立令牌；
- 新开 worktree 前必须"先回收/合并一个"（令牌制，P1 由 `devtask.py` 强制）；
- 超期 worktree 自动标黄进周报，**不自动删除**。

**merge train（v1.1 定稿）**：
- 主窗口 **16:30–17:00**；次窗口 **21:40–22:10**；周五可按需加一班（18:00 前结束）；
- **禁并期**：09:15–15:05、17:10–18:40、20:00–20:20、21:20–21:40；
- **文档/组合声明（无服务变更）随时合并**，不占窗口；
- train 规则：窗口开始按 FIFO 依次 rebase→merge，每班上限 6 个；失败退回 owner 排下一班；窗口外只提交不合；
- 紧急事故走 L2，随时可合，但留痕。

**并发写域规则**：
1. 任务单必须声明 `write_scope`；重叠即冲突，先协调；
2. 共享文件（AGENTS/ROADMAP/ADR/registry）同一时段只允许一个 owner 写；
3. **禁止在共享仓执行 `git clean -fdx` / `reset --hard`**（11-02 两次清掉未跟踪文件的教训）；
4. merge 竞态时以"先到先得 + 后到 rebase"处理，禁止强推覆盖。

## 八、证据与完成（无证据不算完成）

**证据包**（每个工作项必须）：

```text
work_item: <TID/ID>
owner / lane / date
commands: <命令全文>
result: rc=0 + 关键输出摘要
artifacts: <文件/URL/截图路径 + sha256（可选）>
acceptance: 逐条勾选
rollback: 步骤
residual: 0（worktree/临时文件/临时配置）
signoff: <owner>
```

**三条铁律**：1. `rc=0` 不等于有产出（空候选/空结果必须显式说明）；2. 缺口/失败如实写，不粉饰、不补造；3. 回执与证据同批，事后补证不算完成。

## 九、质量分级（门禁强度挂钩）

沿用 ZBF v1 的 Q1–Q4：Q1 已登记（自动门禁）→ Q2 可运行（自动+抽样评审）→ Q3 可治理（ARCH1 评审）→ Q4 可进化（双签+演练）。
`active` 至少 Q2；对外/关键至少 Q3；平台核心/长期 Q4。

## 十、度量与看板（少而准）

| 指标 | 定义 | 首季目标 |
|---|---|---|
| Lead time | 工作项从接单到 DOD | 快速道 ≤1 天；治理道 ≤1 周 |
| WIP | doing 数 | 按 §七 分阶段 |
| 变更失败率 | 回滚/返工占比 | ≤10% |
| 逃逸缺陷 | 上线后 P0/P1 | 0 |
| 组合 Q 分布 | Q1–Q4 数量 | active 全部 ≥Q2 |
| 组合账本覆盖 | 在册/实际 | 100% |
| 内核变更数 | 月变更契约文件 | ≤5 且 100% ADR |
| 覆盖率 | fast 门覆盖 | ≥30% |

周报自动生成（或半自动），只报异常与缺口，不堆数字。

## 十一、角色与 RACI（敏捷小队）

| 角色 | 职责 | 关键产出 |
|---|---|---|
| A0/老田 | 产品负责人、最终拍板、L2/大例外审批 | 优先级/验收/批准 |
| ARCH1 | 平台架构、治理道预审、标准道抽检、门禁维护 | 架构决策/门禁/抽检报告 |
| 领域 owner（席位/人类） | 需求、实现、验收证据、车道自判 | 工作项 + 证据包 |
| QA（独立） | 独立验收、回归 | 验收报告 |
| 执行 Agent/工人 | 按单执行、按写域提交 | 提交 + 证据 |
| 人类审批 | L2/凭据/停服/大例外 | 五要素批准 |

**双周仪式**：计划（周一 30min，只定目标不做详细设计）→ 每日对账（10min）→ 评审（周五 30min，演示+证据）→ 回顾（双周 30min，1 页）。会议不超时；文档先行、异步评审为主。

## 十二、例外与升级

- 例外分级见 §5.3；大例外走 ADR-017 例外流程；
- 标准冲突：**安全 > 治理 > 速度**；冲突写 ADR/修订记录；
- 升级路径：owner → ARCH1 → A0；响应 SLA：P0 15min、P1 4h、P2 24h。

## 十三、试点（v1.1 定稿）

- **标准试点（双周 11-03~11-16）**：`acad1-legion`（军团组合）+ `data-warehouse`（数据/工作流组合）；范围限定"日常迭代 + 证据 + DOD"，不混入 13 卡复核/双池迁移；
