# 版本与发布流程 v1（D6）

- **状态**：草案（本机 git，暂无远端镜像/发布通道）
- **参考**：[AutoGen CONTRIBUTING](https://github.com/microsoft/autogen/blob/main/CONTRIBUTING.md) 的版本齐步/发布/分诊实践、Keep a Changelog
- **定位**：单机个人平台，**不追求对外版本号**；但需可追溯、可回滚、变更可读。

## 一、版本号规则（个人平台简化 SemVer）

| 场景 | 版本动作 | 例子 |
|---|---|---|
| 架构/契约级变更（org 结构、端口、数据根、凭据区） | minor + 1（记录 ADR） | `0.1.0 → 0.2.0` |
| 常规功能/修复批次（当日多次合并） | date-based build 标记，不强制 bump | `0.2.0+build.20261027` |
| 热修（P0 线上故障） | patch +1 | `0.2.1` |
| 有对外发布/镜像时 | 切 SemVer + tag（`v0.2.0`） | 届时另行立宪 |

> 原则：**一个 merge 一个 CHANGELOG 条目**；版本号只在"批次收口"时 bump，避免每条合并都改版本。

## 二、发布检查单（本机部署仍适用）

1. `git status` 干净；目标分支为 master 且评审门全绿；
2. 测试：`python -m pytest portal/test_m_links.py tools/test_check_ports_json.py -q` +
   受影响套件（见 `docs/testing.md`）；
3. 门禁：`python tools/check_ports.py --strict`、`_mixin_integrity.py --check`、`unify_nav.py --check`、
   `tools/ruff_ratchet.py --check`；
4. 文档：`CHANGELOG.md` 有本批摘要；架构/接口变更同步 ADR/specs；`DOCS_INDEX --check` rc=0；
5. 服务生效（如涉及）：按 L2 五要素执行；验"新进程出生时间 > 文件 mtime"；
6. 打 tag（可选，本机）：`git tag v<ver>-<date>`；回执落 `deliverables/`。

## 三、回滚

- 代码：`git revert <merge-commit>`；L2 服务变更按对应回执的回滚段执行；
- 数据：按 manifest 逆向 Move（不删除）；
- 发布记录：CHANGELOG 保留历史，不删条目。

## 四、分诊（triage）简化版

- 每日一次（或 C6 日报时）：看 `doing` 单、失败用例、`guard_fail` 事件；
- 新失败：修 or 正式登记基线（`tools/test_baseline.json`），**不许静默加白**；
- 每周：`devtask.py prune --dry-run` 清已合并 worktree/分支（人工确认后 apply）。
