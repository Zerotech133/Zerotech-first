# 席位「真成员化」标准 v1（工具 + 授权 + 触发 + 审计 + 回滚）

> 2026-10-26 · 判例：`HERMES_UI（糜竺）` 真成员化（工单 WO-HERMES-UI-REAL-20261026，merge f5b28ced）
> 目的：**防止"组织架构里有一张卡，但永远不动"**。任何新席/老席要声称"能跑起来"，必须过这五维；
> 五维是**可检查**的，不靠口头描述。审计器：`agent_platform/tools/seat_realness.py`。

## 1. 五维验收（缺一不算真成员）

| # | 维度 | 通过判据（可检查） | 证据落点 |
|---|---|---|---|
| 1 | **授权（身份）** | org.json 有 profile + `agent_platform/hr/<ID>/resume.yaml` + prompt 文件存在 | 三件套路径 |
| 2 | **工具** | org `tools` 非空，且每个工具有实现（`agent_platform/tools/<tool>.py` / `tools/<tool>.py` / 平台内置白名单 events/devtask） | 工具文件路径 |
| 3 | **触发** | 有明确的运行入口：计划任务（`HermesUI-Probe`）、或事件驱动钩子；**不能只有人工手动跑** | 任务名 + `LastTaskResult=0` |
| 4 | **审计** | 近 `--days` 天 `dev_events` 有该席事件（agent==ID 或 task==ID） | `portal/data/dev_events.jsonl` |
| 5 | **回滚** | prompt/安装单写明回滚（关键字：回滚 / kill switch / Uninstall / 对应环境变量），且实际可执行 | prompt 段落 + 安装器 `-Uninstall` |

## 2. 反模式（只做卡片的典型）

- 只往 org.json 加 `agent_id`，没有 HR/prompt/工具 → **空卡**；
- 有 LLM 绑定但 `tools=[]` → **只会聊天，不会干活**；
- 有工具但无任何触发 → **永远需要人手动点**；
- 跑起来了但无事件 → **出问题查不到**；
- 有审计但没有 kill switch/卸载路径 → **想停停不掉**。

## 3. 一席落地模板（5 步，按顺序）

```text
① 身份：org.json 加 profile（charter/attributes/grade/llm/none）+ hr/<ID>/resume.yaml + prompts/<role>.md
② 工具：写最小工具（只读/幂等/退出码契约），org 授 tools=[...] + memory_grants
③ 触发：安装器脚本（S4U + 电池可跑 + 间隔），L2 五要素批准后安装
④ 审计：工具内 emit dev_events（kind 按域：patrol_verdict/code_observation/…）
⑤ 回滚：kill switch 环境变量 + 安装器 -Uninstall + prompt 写明
```

## 4. 审计器用法

```powershell
cd C:\项目\老田的AI助手
# 单席（有定时任务时带 --task）
python agent_platform/tools/seat_realness.py --seat HERMES_UI --task HermesUI-Probe
# 全组织扫描（无 --task 时"触发"维会显式失败，提醒未验证）
python agent_platform/tools/seat_realness.py --all --limit 80
# JSON 输出（供看板/CI）
python agent_platform/tools/seat_realness.py --seat HERMES_UI --task HermesUI-Probe --json
```

退出码：`0` = 5/5；`1` = 有缺口；`2` = 自身错误（可直接进 CI/评审门）。

## 5. 判例：HERMES_UI（糜竺）

| 维度 | 通过证据 |
|---|---|

## 6. 与评审门的关系

- 「触发」维若涉及计划任务 → **安装动作属 L2**，必须五要素人工批准（K-STOCK-416）；安装器可入库但在门禁中会被 L2 拦，需 `--l2-ack` 并附五要素；
- 建议：**先完成 ①②④⑤ 并合入仓库，③ 单独走 L2 批准**——本判例即此顺序，且证明可行。
