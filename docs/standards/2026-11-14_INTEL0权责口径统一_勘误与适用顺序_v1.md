## 三、适用顺序（冲突时按此判）

```
1. agent_platform/registry/org.json（组织注册表）
2. agent_platform/hr/INTEL0/resume.yaml（席位档案）
3. 已签批的 SOP / 协议 / 契约
4. 草案、手册、登记表、工单、会议纪要（不得扩权）
```

- **任何低层级文件不得给 INTEL0 授予裁决权**；既往草案中的「情报主管」「复核裁定」「主管签字」一律按 §一 解释。
- 上行路径（INTEL_UPSTREAM_REPORT → INTEL0 受理 → A0 裁决）保持不变，本单只纠正「受理被写成裁决」的措辞，不改数据链路、不改计划任务、不改代码。

## 四、历史文件处置原则

1. **台账／工单／回执类 append-only**：不改写历史行、不倒填签字、不回滚已结算事件；以「更正记录」追加说明效力。
2. **仍在使用的活草案／登记表**：允许做最小措辞修订，并在文末加一行「口径修订」注记，保留原文差异可追溯。本次同步修订 3 份：`核验流转草案.md`、`PIR_register.md`、`采集情报_板块手册.md`。
3. **历史结论／方法论文档**：保留原文，靠本单索引解释，避免为了统一措辞而重写历史。
4. **新增授权一律走签批**：SOP v0.2 的签批栏空置，等 A0／老田 + QA1 落字；未签批前不得宣称 SOP 已生效。

## 五、生效与复核

- 本单自落盘起适用于**解释与引用口径**：今后引用「马超／INTEL0 有权裁定 X」一律视为无效引用。
- 不改变既有任务、消息、计划任务的归属；不触发任何生产配置变更。
- 复核点：SOP v0.2 签批时，由 QA1 核对本单 §二 的 8 条是否已在 v0.2 中消化。**状态（2026-11-14 更新）：已并入 v0.2（A0 批准生效，QA1 会签待补）**。
