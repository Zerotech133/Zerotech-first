# 原文件与 Word 入库规范 v1（学习项目专用）

> 制定：2026-11-02｜**流程 Owner：DATA1 张松（兰台令）**｜执行：DATA2 刘巴｜审批：DATA1；A0 仅仲裁；老田立项/终验
> 配套：`docs/standards/2026-11-02_学习项目标准化流程_v1.md`（S0–S8）
> 铁律：**学习入库 ≠ 数据仓治理**。本规范只写「学习命名空间」，绝不触碰数据仓（dw）目录/注册表/任务。

## 一、你（老田）只需要做一件事：投递
把文件放到唯一入口：

```
C:\项目\知识库\05_学习源件\_inbox\
```

| 类型 | 支持 | 说明 |
|---|---|---|
| Word | `.docx` | 段落+表格+内嵌图片自动抽取（python-docx） |
| PDF | `.pdf` | 登记+哈希+排队走现有 OCR 流水线（大文件不复制，记录原路径） |
| 文本 | `.md` / `.txt` | 直接抽取入库 |
| 老 Word | `.doc` | 不支持直读：请另存为 `.docx` 后投递（或转 PDF） |

可选命名：`<日期>_<项目名>_<主题>.<ext>`（如 `20261102_老木创业笔记_第二章.docx`）；不按命名也能识别（自动生成项目名）。

## 二、你会得到什么（自动落盘）
| 产物 | 路径 |
|---|---|
| 源件副本（PDF 例外，仅登记） | `知识库\05_学习源件\<project_id>\source\` |
| 文本抽取（Word/文本） | `知识库\20_清洗\<project_id>\text\*.md` |
| 文件清单（hash/来源/时间） | `知识库\05_学习源件\<project_id>\manifest.json` |
| 项目元数据 | `知识库\05_学习源件\<project_id>\meta.json`（namespace=learning，status=intake_pending） |
| 项目登记 | `agent_platform/registry/learning_projects.json`（owner=DATA1） |
| 入库回执 | `research/reports/learning_intake_<date>.{json,md}` |

之后按 SOP 自动推进：S2 清洗（PDF OCR/转写）→ S3 知识单元 → S4 治理 → S5 提炼（学习卡候选）→ S6 标准化 → S7 发布 → S8 归档。

## 三、怎么触发入库（手动 / 自动）
- **手动（推荐先跑一次）**：
  ```powershell
  C:\项目\py312\python.exe -X utf8 tools/kb_corpus/learning_intake.py scan          # 只看不写
  C:\项目\py312\python.exe -X utf8 tools/kb_corpus/learning_intake.py ingest --write # 真入库
  ```
- **自动（待你批准后注册）**：`ZeroBound_LearningIntake` 每 30 分钟扫 inbox；`ZeroBound_LearningPipeline` 每日 20:00 推进后续阶段。

## 四、与数据仓治理的隔离（硬约束）

| 约束 | 实现 |
|---|---|
| 目录隔离 | 学习只写 `知识库\05_学习源件\`、`知识库\20_清洗\<project>\`；**不写** `00_数据仓`、`01_数据分包`、`40_索引`、`50_RAG`、`portal/static/kb_units_all.json` |
| 注册表隔离 | 只写 `learning_projects.json`；**不写** `tools/datawarehouse/*` 的任何 registry/manifest/catalog |
| 任务隔离 | 不触发、不修改任何 `ZeroBound_Daily*`/数据仓 ETL 任务 |
| 代码隔离 | 工具内路径白名单断言：任何写入路径必须落在 4 类允许目录内，否则直接报错（`SafetyError`） |
| 验证 | 每次入库后跑 `tools/datawarehouse/metadata_consistency.py`（必须 PASS）+ `git status` 无数据仓文件变更 |

> 数据仓（dw）继续由张松与 DATA 团队按既有治理体系管；学习入库只是**旁路新增**，不改 dw 口径/资质/权限/血缘。

## 五、去重与重入
- 以文件 SHA256 为准：同 hash 已入库 → 跳过（幂等）；
- 同名不同 hash → 视为新版本（manifest 追加 version 记录）；
- 入库失败 → 文件留在 inbox，回执标注原因；不删除源件。
