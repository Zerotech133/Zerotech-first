# PDF 知识入库标准（v1）

> 编号：2026-10-31_PDF知识入库标准_v1 · 工单 WO-PDF-INGEST-20261031
> 能力：`tools/kb_corpus/pdf_ingest.py`（scan / ocr / structure / distill / verify / index / all）
> 适用范围：项目内**扫描版/文本版 PDF 文档**（教材、研报、白皮书、公告汇编等）→ 知识库

## 一、输入分级（scan 自动判定）

| 类型 | 判定 | 处理通道 |
|---|---|---|
| `text` | 抽样页有文本层（≥300 字/页） | 直接抽取（pypdf），无需 OCR |
| `scanned` | 抽样页 <100 字/页（图片扫描） | OCR（PyMuPDF 200dpi 渲染 + RapidOCR ONNX） |
| `mixed` | 介于两者之间 | 逐页判定：有文本用文本，否则 OCR |

## 二、标准流程（六步）

1. **scan**：类型探测 + 页数 + SHA256 → `manifest.json`；
2. **ocr**：逐页渲染/识别，落 `ocr.jsonl`（逐页可续跑）+ `ocr.txt`；
3. **structure**：章节标题识别（第X章/节/篇/讲、序言/附录、Chapter）→ `structure.json`（标题+页码，单调递增校验）；
4. **distill**：按章节聚合文本（≤9000 字/章）→ 本地 qwen3.5 蒸馏 → **知识单元**（concept/claim/evidence/章节/页码）；
5. **index**：生成摘要 md 入 `knowledge_docs/PDF入库_<书名>.md` → 重建 RAG 索引；
6. **verify**：质量标准验收（见下）。

## 三、产出物规范

```
C:/项目/PDF/_ingest/<书名>/
  manifest.json          # 类型/页数/大小/SHA256
  ocr.jsonl              # {page, text} 逐页
  ocr.txt                # 逐页全文（=== 第N页 === 分隔）
  structure.json         # {book, pages, chapters:[{title,page}]}
  knowledge_units.jsonl  # {schema_version,book,chapter,page_start,page_end,concept,claim,evidence,source,confidence,sha1}
  verify.json            # 验收结果（阈值/逐书检查）
```

知识单元 schema（v1）：
```json
{"schema_version":1,"book":"string","chapter":"string","page_start":1,"page_end":1,
 "concept":"string","claim":"string","evidence":"string","source":"ocr+llm","confidence":"medium","sha1":"16hex"}
```

## 四、验收标准（verify 自动判定，全绿才可入库）

| 指标 | 阈值 | 说明 |
|---|---|---|
| 页面覆盖 | ≥95% | OCR/文本页数 / PDF 页数 |
| OCR 质量 | ≥100 字/页 且 乱码率 <2% | 扫描版必需；文本层书按文本抽取折算 |
| 章节结构 | ≥5 章 | 结构抽取成功标志 |
| 知识单元 | ≥10 条且**引用完整率 100%** | 每条必须含 book/chapter/page_start |
| 可复现 | 脚本+产物落盘、OCR 可续跑 | 见产出物目录 |

## 五、版权与合规

- 仅限**内部研究/检索**使用；不得再分发全文或大规模摘录；
- 摘要/知识单元须注明来源书名与页码；OCR 存在误差，引用原文需对照 PDF；
- 有明确授权/公开许可（如白皮书）的文件在 manifest 标注 `license` 后可扩展对外使用范围。

## 六、失败处理与成本

| 情况 | 处理 |
|---|---|
| OCR 依赖缺失（pymupdf/rapidocr） | verify 报错；按 README 安装（阿里云 pypi） |
| 某页 OCR 失败 | 记录空文本继续；verify 覆盖率不足则失败 |
| 章节识别不足 | 人工补 structure.json（允许手工编辑，需注明） |
| 大文档成本 | OCR ≈4–6s/页（CPU）；蒸馏 ≈1–2s/章；建议夜间/后台跑 |
| Ollama 卡在别的模型 | 先 `api/generate {model, keep_alive:0}` 卸载再 embed/chat（判例 2026-10-31） |
