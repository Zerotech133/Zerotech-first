# 质量分级 v1（Bronze / Silver）

- **日期**：2026-10-27｜**依据**：O2 优化项；参考 Home Assistant [Integration Quality Scale](https://contributors.home-assistant.io/core/quality-scale/) 的分级思想（不照搬规则）
- **工具**：`tools/quality_scale_check.py`（只读）｜**配置**：`agent_platform/config/quality_scale.json`
- **对象三层**：**席位**（seat）/ **工具**（tool）/ **集成**（integration，对外服务/常驻组件）

## 一、为什么要分级

我们的现状是"存在性校验"（有没有文件/端口/测试），但"好到什么程度"没有标准：
新工具/新席位/新集成容易停在"能跑"，无法横向比较、无法作为准入/升级依据。
分级后：**Bronze = 可用底线**（可自动检查），**Silver = 可运维/可诊断**；Gold/Platinum 暂不定义（避免过度工程，参见 ADR-013）。

## 二、规则（checker 可自动判定）

### Bronze（9 条，缺一即不达标）

| # | 规则 | 判定方式 |
|---|---|---|
| B1 | 有 owner | 字段非空 |
| B2 | 有文档且路径存在 | `docs` 列表非空、每个路径存在 |
| B3 | 有测试/验收证据且路径存在 | `tests` 列表非空、每个路径存在 |
| B4 | 权限默认只读；写权限需 L2 标记 | `risk=read-only` 或 (`risk=write` 且 `l2_approved=true`) |
| B5 | 集成端口已登记 | `port` ∈ `tools/check_ports.py::REGISTRY` |
| B6 | token 只从 env 注入 | 有 `token_env` 时须为大写环境变量名；`transport=http` 无 `token_env` 判失败 |
| B7 | 有回滚说明 | `rollback` 非空 |
| B8 | 有事件/归因 | `events` 非空 |
| B9 | 失败可见 | `fail_visible=true` |

### Silver（6 条，在 Bronze 基础上）

| # | 规则 | 判定方式 |
|---|---|---|
| S1 | 有健康检查 | `health` 非空（URL/命令） |
| S2 | 有可执行验收命令 | `acceptance` 非空 |
| S3 | 有版本 | `version` 非空 |
| S4 | 有诊断取证 | `diagnostics` 非空 |
| S5 | 有备份责任人 | `backup_owner` 非空 |
| S6 | 文档有深度 | `docs` ≥ 2 份（参考 + 操作/说明） |

## 三、当前基线（2026-10-27 实测）

`python -X utf8 tools/quality_scale_check.py`：

| 层 | 数量 | Silver | Bronze | 未达标 | 说明 |
|---|---:|---:|---:|---:|---|
| 席位 | 8 | 8 | 0 | 0 | ARCH1/DEV1/DEV5/QA1/D1/ST1/WA1/QS1 均 Silver |
| 工具 | 10 | 0 | 10 | 0 | 全部缺 S6 `docs_depth`（只有 1 份文档）→ 下一步补第二份文档即升 Silver |
| 集成 | 6 | 6 | 0 | 0 | 8734/8091/8796/8795/8787/feishu_bot 均 Silver（端口已登记/健康命令/验收） |
| **合计** | **24** | **14** | **10** | **0** | `--strict` rc=0（无对象掉出 Bronze） |

> 诚实说明：checker 只验证"证据存在/字段齐全/端口登记"，**不代跑服务**；Silver 是声明级+存在性，不等于运行时验证。后续可加"health 真探测/acceptance 真跑"（O5 夜跑）。

## 四、用法

```powershell
python -X utf8 tools/quality_scale_check.py            # 人读
python -X utf8 tools/quality_scale_check.py --json     # 机器读
python -X utf8 tools/quality_scale_check.py --strict   # 任一对象未达 Bronze → rc=1
```

新增对象：在 `agent_platform/config/quality_scale.json` 的 `objects` 增加条目（字段见 §二），跑 checker；**合并门/夜跑后续接入**（D2 框架已就绪）。

## 五、升级路径

- 工具缺 S6：补一份 how-to/参考文档（`docs/` 或工具 README），`docs` 列表填 2 份 → Silver；
- 新工具默认按 Bronze 登记；要 Silver 必须有 health/acceptance/diagnostics/backup_owner；
- 集成/席位变更时同步更新本配置，**质量等级下降要在回执里说明**；
- Gold/Platinum 待 O3（扩展契约）与 O7（诊断包）落地后再定义。

## 六、与其它优化项关系

- O3 扩展契约：`quality_scale.json` 的 tool 对象未来由 manifest 生成；
- O4 实现/验收分离：Silver S2 的 acceptance 命令应由非实现者确认；
- O5 E2E/夜跑：把 checker `--strict` 与 health 真探测纳入夜间基线；
- O7 诊断包：`diagnostics` 字段统一指向 `tools/diagnostics.py`。
