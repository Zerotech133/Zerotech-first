## 一、提案 A：博主实体层（水镜席位实体细化）

**缺口**：现模型 Source 为 **feed 级**（MERGE key=source_url，一源一节点），帖子作者只是 IntelItem 上的属性，**没有博主节点**——无法做博主级声量/情绪聚合，蒋琬的因子假设清单拿不到「谁在说什么」的维度。

**Schema**（沿用 Source/IntelItem 家族，不破坏现有查询）：

```cypher
(:IntelAuthor {author_key, platform, uid, name, followers, verified, first_seen, last_seen})
(:IntelItem)-[:AUTHORED_BY]->(:IntelAuthor)
(:IntelAuthor)-[:ACTIVE_IN]->(:Source)          // 同一博主多个 feed 归并
```

- `author_key = platform::uid`（MERGE 幂等键，沿 IntelItem 的 data_source::ext_id 同款口径）
- 回填：从 xueqiu_status 表 user 字段（uid/昵称/粉丝数）+ guba 作者字段，一次性 backfill（预估 1-2 千作者量级）
- 增量：intel_link 的 upsert_intel_batch 扩展一步 AUTHORED_BY MERGE（同批事务，不新增链步）
- 影响面：新增节点/边类型，**不动**既有 Source/IntelItem/MENTIONS——JEV dump schema 向后兼容（L2 级通知）
- 因子价值（通知蒋琬）：博主级声量因子（粉丝加权提及）、KOL 情绪分歧度、跨博主共振检测

## 二、提案 B：研报知识单元入图（韦昭线补全）

**缺口**：数据册已登记 `research_reports_kb`（100 份研报 / 498 知识单元 / RAG 462 记录）与 `strategy_classics_kb`（SEPA 18 条单元），但两者**不在 SOURCE_REGISTRY**，图谱里查不到——郑玄做图谱细化时投研问「某股有哪些研报结论」只能出库外查。

**Schema**：

```cypher
(:KnowledgeUnit {unit_key, kb, unit_id, title, digest, ts, doc_uri})
(:KnowledgeUnit)-[:DERIVED_FROM]->(:Source)      // 指向研报文档级 Source
(:KnowledgeUnit)-[:ABOUT]->(:Security)           // symbol 消歧走 symbol_direct（研报有代码标注，不用 fuzzy）
(:KnowledgeUnit)-[:ABOUT]->(:Concept)            // 可选：主题概念关联
```

- `unit_key = kb::unit_id`；消歧策略：研报知识单元自带标的代码 → `symbol_direct`（免 fuzzy_3level 的歧义成本）
- 证据链：`doc_uri` 指向研报原文/anns_pdf 切片，配合满宠 MDC-R03 四态分账（证据指针一致性由郑玄负责核对）
- 回填：498 + 18 = 516 单元一次性；增量随 KB 更新（登记官 DATA1 数据册变更时联动）
- 影响面：新增 KnowledgeUnit 家族，L2 级通知；query_recipe 扩展建议：

```cypher
MATCH (ku:KnowledgeUnit)-[:ABOUT]->(:Security {symbol:$code})
RETURN ku.kb, ku.title, ku.digest, ku.doc_uri ORDER BY ku.ts DESC
```
