## 一、术语与登记字段（IFS 通用）

| 术语 | 定义 |
|---|---|
| **owner** | 接口唯一负责人（席位，如 D1/TR1/ACAD1）；对契约、SLO、变更负责 |
| **consumer** | 接口消费方（席位或系统）；影响面评估与版本协商对象 |
| **source_of_truth** | 该接口数据的唯一真源（PG 表/账本/目录/数据集）；投影不是真源 |
| **schema** | 数据契约版本（如 `d1_handoff/v2`），响应必须带 `schema_version` |
| **auth** | 认证方式（`portal-token` / `portal-token+roles` / `internal-only` / `mcp-config` / `manifest`） |
| **write** | 是否产生持久化写副作用（GET 恒 false） |
| **paper_only** | 是否仅模拟/影子（平台恒 true；**不可缺省**，实盘订单恒 0） |
| **SLO** | 延迟 p95 / 错误率上限 / 可用性；按 SLO 档位登记 |
| **status** | 接口生命周期：`draft`（未达 v1）/ `v1`（已按 IFS 维护）/ `deprecated`（计划收敛）/ `retired`（已下线） |

登记表字段全集（IFS-02 强制）：`id / method / path / owner / consumer / source_of_truth / schema / auth / write / paper_only / SLO / status`（+ 可选 `ids`（ID chain 产出/消费）、`remediation`（整改单）、`notes`）。

## 三、IFS v1 条款（IFS-01 ~ IFS-14 定稿）

> 每条含：**强制条款**（MUST/禁止）、**验证方式**（可执行）、**registry 关联字段**、**整改映射**。`MUST` 违反 = 评审门拒绝/不接单。

### IFS-01 单一真源（Single Source of Truth）

- **MUST** 每个接口登记 `source_of_truth`，声明唯一真源（PG 表/账本/目录/数据集）。
- **MUST** 同一事实只能有一个可写源；其余均为只读投影，并显式标注 `source_mode=projection` + `stale`。
- **MUST** 池的唯一真源 = 智策 PG `zhice_os_v2.public.v2_acad1_pool`（ADR-018 契约 `zerobond.selection.v2_acad1_pool@1.0.0`）；门户 JSON 池仅投影。
- **禁止** 同一事实多源可写（双写）；**禁止** 投影数据被当作官方池消费（须带 `source_mode`）。
- **验证**：registry 每条 `source_of_truth` 非空且 kind 合法；接口响应 `source.source_mode` 正确；对账脚本比对真源 vs 投影差异并显式告警。
- **关联**：`source_of_truth`、`SLO`；**整改** F2（`WO-IFS-ACAD1-20261103`、`WO-IFS-DW-20261103`）。

### IFS-02 接口注册表（Registry before code）

- **MUST** 每个接口先登记 `INTERFACE_REGISTRY_v1.yaml` 再写代码；无登记不接单、不评审、不上线。
- **MUST** 登记字段 12 项齐全（见 §一），且 `id` 唯一、`(method, path)` 唯一。
- **MUST** 新增/变更接口同批更新 registry 与 composition manifest / route baseline（IFS-11）。
- **MUST** `status` 严格取 `draft/v1/deprecated/retired`；未满足 IFS-03~IFS-12 不得标 `v1`。
- **禁止** 私起服务/私增端口（端口铁律 §1）；**禁止** 未登记接口被页面/Agent 引用。
- **验证**：`python -X utf8 -m pytest tools/tests/test_interface_registry_contract.py -q`（接口数≥20、字段/枚举/唯一性/矩阵一致性）。
- **关联**：全部字段；**整改** F0（`WO-IFS-REGISTRY-20261103`）。

### IFS-03 统一响应 envelope

- **MUST** 成功响应含 `ok=true / schema_version / request_id / source / data / warnings`（+ 建议 `generated_at`）。
- **MUST** 失败响应含 `ok=false / schema_version=error/v1 / request_id / error{code, message, retryable, details}`。
- **MUST** `warnings` 无告警也必须是 `[]`；`data=null` 仅限 `ok=true` 且 warnings 说明。
- **禁止** `ok=true` 内藏 error；**禁止** 空数组/0 值冒充“无数据”；**禁止** 泄露堆栈/凭据。
- **验证**：契约测试用 `validate_envelope()` / `validate_error()` 断言（`tools/tests/test_interface_registry_contract.py`）；JSON Schema：`docs/standards/schemas/interface_envelope_v1.schema.json`、`interface_error_v1.schema.json`。
- **关联**：`schema`、`SLO`；**整改** F1（`WO-IFS-ENVELOPE-20261103`）。

### IFS-04 统一 ID chain

- **MUST** 全链 11 实体：`pool_id → card_id → case_id → decision_id → handoff_id → watch_plan_id → trigger_id → confirmation_id → trade_id → outcome_id → training_episode_id`（完整定义见 ID chain 文档）。
- **MUST** 每个实体只有一个权威生成方（registry `id_chain.entities[*].generator.interface`）；下游必须携带上游 ID。
- **MUST** 禁止 `code` 代替 `case_id/decision_id`；禁止 `receipt_id` 与 `handoff_id` 双名混用（`receipt_id` 仅兼容读）。
- **MUST** 缺口显式登记（registry `id_chain.gaps`），不得用别名/临时字段绕过。
- **验证**：集成测试按链逐跳校验（F7 `WO-IFS-E2E-20261103`）；契约测试校验顺序/邻接/生成方/无空洞。
- **关联**：`ids.produces/consumes`；**整改** F3/F4/F5（`WO-IFS-HANDOFF/WATCHCONS/TRIGGER/CONFIRM/PAPER/OUTCOME/TRAIN`）。

### IFS-05 写边界与 paper_only

- **MUST** `paper_only=true` 不可缺省；handoff 写入禁止执行字段：`order / qty / quantity / broker / execute / trade_id / fill / account`。
- **MUST** handoff 响应/记录带 `not_a_trade=true`；GET 不得产生写副作用。
- **MUST** 任何执行动作必须经 `confirmation` + `risk_gate`；`trading_permitted=false` 恒成立；实盘订单恒 0。
- **MUST** `paper_only=false` 或携带执行字段 → 400（`not_paper` / `execution_field_forbidden`）。
- **验证**：写接口契约测试含「执行字段注入 → 400」「无确认直接执行 → 拒绝」用例；registry `write/paper_only` 校验（契约测试断言 30 接口 paper_only 恒 true）。
- **关联**：`write`、`paper_only`；**整改** F3/F4（`WO-IFS-KILL-20261103` 等）。

### IFS-06 幂等（Idempotency）

- **MUST** POST 接口接受 `Idempotency-Key`（或等价上游 ID），同 key 重复请求返回同一 ID/同一记录（200 + `warnings[].code=idempotent_replay`）。
- **MUST** decision / handoff / confirmation / trade 四层各自按上游 ID 幂等（映射见 ID chain 文档 §七）。
- **MUST** 同 key 但参数不同 → 409 `duplicate`；状态冲突 → 409 `conflict`。
- **验证**：契约测试同 key 两次请求断言同 ID；重复 approve 断言不重复记账（F4 `WO-IFS-KILL-20261103`）。
- **关联**：`notes` 幂等键说明；**整改** F4。

### IFS-07 数据契约（数据仓对接）

- **MUST** 接口数据必须登记 `dataset_registry`/数据目录，声明 `contract / version / freshness / owner / retention`。
- **MUST** 只读投影不得直接读未登记文件；PIT/freshness 由数据仓统一提供（`as_of` 与采集时间分离）。
- **MUST** 缺数据显式 `data_unavailable`/`null`，不造数（不填 0 充数）。
- **验证**：D1 data ref `resolve-ref` 全部 OK（F2 验收）；registry `source_of_truth.kind/ref` 与数据目录一致。
- **关联**：`source_of_truth`；**整改** F2（`WO-IFS-DW-20261103`、`WO-IFS-NOBUILD-20261103`）。

### IFS-08 认证与授权

- **MUST** 人类入口唯一 = 8734；同源 portal-token / auth_request；不引入第二套认证。
- **MUST** 写接口声明 roles（`portal-token+roles`）；`paper_only` 写接口同样鉴权。
- **MUST** MCP 工具必须登记 `agent_platform/legion_mcp/servers.json`，声明 `risk=read-only`（写风险工具默认拒绝）。
- **MUST** 8787 的 401 是登录门，不判故障；不得为绕 401 私开端口/私加 token。
- **验证**：契约测试 auth 用例（无 token→401、roles 不足→403）；MCP `tool_count=1` 且登记（F6）。
- **关联**：`auth`、`owners` 目录；**整改** F6（`WO-IFS-MCP-20261103`）。

### IFS-09 版本与兼容

- **MUST** 每个响应带 `schema_version`；新增字段向后兼容；破坏性变更 → v2 + 90 天双版本。
- **MUST** 不允许静默改字段语义；组合 manifest 版本与接口版本同批更新。
- **MUST** 错误信封固定 `error/v1`，错误码只增不删（废弃码保留映射一个周期）。
- **验证**：契约测试断言 envelope `schema_version` 存在且与 registry `schema` 同族；版本变更需 ADR。
- **关联**：`schema`；**整改** F1/F6。

### IFS-10 可观测

- **MUST** `request_id`（+ `trace_id`）全链；审计日志（`audit.jsonl` / `dev_events.jsonl`）记录 interface_id/ok/error.code/latency。
- **MUST** health probe 登记；SLO 按矩阵采集（latency/error）；失败必须 fail-visible，不得假成功。
- **MUST** 接口异常掩码堆栈，只回 `internal_error` + request_id 供追查。
- **验证**：审计抽样；SLO 周报（latency p95/error rate）；契约测试断言失败响应含 request_id。
- **关联**：`SLO`、`status`；**整改** F6（`WO-IFS-ROUTE-20261103`）。

### IFS-11 组合登记（Composition）

- **MUST** 接口必须出现在 composition manifest `spec.interfaces.exposes`；页面进 page manifest / route baseline；任务进 job manifest。
- **MUST** active 组合 Q2；关键接口 Q3；`lusu-d1-flow` 必须补齐 `POST /api/d1/decision`、`/api/d1/handoffs` 等暴露面。
- **MUST** 组合 manifest 与 registry 同批维护（`compositions/registry.json`）。
- **验证**：`python -X utf8 tools/composition.py check`（若存在）/ manifest 校验；F6 验收 Q2 可查。
- **关联**：registry 与 manifest 双向引用；**整改** F6（`WO-IFS-COMPOSITION-20261103`）。

### IFS-12 契约测试

- **MUST** 每个接口至少覆盖：schema 校验、成功/失败/错误码、幂等、auth、端到端 1 条。
- **MUST** 测试离线可跑（不依赖真实服务/生产数据），失败即阻断。
- **MUST** 测试骨架随本规范交付（`tools/tests/test_interface_registry_contract.py`），后续接口复用 `validate_envelope()/validate_error()`。
- **验证**：`python -X utf8 -m pytest tools/tests/test_interface_registry_contract.py -q`；F1 `WO-IFS-CONTRACT-TEST-20261103` 扩模板。
- **关联**：`status=v1` 的前置条件；**整改** F1。

### IFS-13 唯一执行入口与执行边界

- **MUST** 唯一执行路径 = `trading_bot_flow`（decide/auto_execute）+ `/api/sim/confirm` 人工门；paper 唯一写入入口 = `paper.execution.record`（内部契约）。
- **MUST** `/api/paper_order`、`/api/paper_direct_open`、`/api/paper_stop` 标记 `deprecated`，迁移期只兼容不扩展（F4 收敛）。
- **MUST** 触发→确认→执行必须携带四 ID（`decision_id / handoff_id / watch_plan_id / trigger_id`）；缺 ID 拒绝执行。
- **MUST** `PAPER_KILL` kill switch 生效时写接口返回 `kill_switch_active`（503，不自动恢复）。
- **禁止** 任何接口直连实盘/券商；实盘订单恒 0。
- **验证**：paper 入口扫描（`git grep paper_direct_open` 仅登记不新增）；F4/F7 验收。
- **关联**：`status=deprecated`、`write`；**整改** F4（`WO-IFS-CANONICAL-20261103` 拍板 + `WO-IFS-PAPER-20261103`）。

### IFS-14 生命周期与整改闭环

- **MUST** `status` 生命周期：`draft → v1 → deprecated → retired`；每次变更同批更新 registry + 本规范变更记录。
- **MUST** 整改按 F0–F7 计划逐段验收（每段有证据包：命令+rc+产物+验收勾选+回滚+无残留）。
- **MUST** `retired` 接口保留一个周期只读映射；`deprecated` 接口在 registry 标注替代接口与下线日期。
- **MUST** 无证据不算完成（ADGS v1.1 §7）；`rc=0` 不等于有产出。
- **验证**：registry `status` 统计与矩阵一致；F0 出口检查（规范/registry/ID/owner/执行路径明确）。
- **关联**：`status`、`remediation`、`plan_phases`；**整改** 全阶段。

## 四、接口准入与接单流程（无 registry 不接单）

```text
① 需求 → 查 registry 是否已有接口（复用优先）
② 新增：登记 registry（12 字段 + ids + source_of_truth + owner/consumer/SLO）
③ 定 schema（envelope + data schema）→ JSON Schema/文档
④ 定 ID（chain 上位置；produces/consumes 显式）
⑤ 定 auth/roles/write/paper_only（写接口必须 roles + 幂等键）
⑥ 写契约测试（离线；成功/失败/错误码/幂等/auth）
⑦ 更新 composition manifest / route baseline / job manifest
⑧ 评审门：契约测试 + 只读/paper_only 检查 + 端口铁律
⑨ 上线后：SLO 采集 + 审计留痕 + 版本变更记录
```

**例外**：紧急 hotfix 24h 内补登记与测试（ADGS v1.1 §10 紧急道），不得长期缺登记。
