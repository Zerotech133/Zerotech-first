# 交付台账与 WIP 上限 v1（§6.2）

- **日期**：2026-10-28｜**依据**：老田批准 §6.2（内部交付业绩口径）
- **目的**：把"内部交付业绩"变成可周度对照的运营数据；控制交付席在制品；让非研发部门也能按人报告。
- **工具**：`tools/wip_check.py`（WIP 只读检查）、`tools/delivery_ledger.py`（台账 init/check/summary）

## 一、WIP 上限（交付型席位）

1. 交付型席位（研发部/质量部/产品部/项目部门）**doing + review ≤ 3**；
2. 超过 3 由 ARCH1 在派单时拦截；例外需在任务 note 写明理由与预计清空日期；
3. 编排层（DSH-Lead/ZHAOYUN 等）与值守/研究席位不适用（其产出不走任务板或为批处理）；
4. 检查：`python -X utf8 tools/wip_check.py --strict`（只读 tasks.json + org.json，超限 rc=1）；
5. 建议频率：每日/每次派单前（可并入 merge 门或夜跑，warn 起步）。

## 二、非研发部门交付台账（周度）

研究/情报/运行体/市场/法务/产品设计等席位，产出常为报告/巡检/值守，未进任务板。
从 **2026-11-02（周一）** 起按周登记，模板字段：

| 列 | 必填 | 说明 |
|---|---|---|
| `week` | ✅ | `YYYY-Www`，如 `2026-W45` |
| `date` | ✅ | 交付日期 `YYYY-MM-DD` |
| `dept` | ✅ | 部门名（org.json 口径） |
| `seat` | ✅ | 席位 ID（如 ACAD1/ST1/TR1） |
| `deliverable` | ✅ | 交付物名称（一句话） |
| `type` | ✅ | report/patrol/task/runbook/other |
| `evidence` | 建议 | 路径或回执/链接（只写引用，不贴密钥） |
| `acceptance` | 可选 | 验收人/验收方式 |
| `status` | 建议 | done/partial/blocked |
| `note` | 可选 | 备注 |

- 每周一 09:00 前登记上一周；`python -X utf8 tools/delivery_ledger.py --summary --week <week>` 出按部门/席位汇总；
- 周报并入周一 09:30 C6 之后的"部门交付周报"（同一时段）；
- 依赖 triage（P3d，只读不阻断）：`python -X utf8 tools/weekly_dep_triage.py --week <上周ISO>`，其 Markdown 段并入周报。

## 三、周度节奏

| 时间 | 动作 |
|---|---|
| 周一 09:00 | 汇总上周台账 + 跑 WIP 检查 + 依赖 triage（warn-only）+ 出部门交付周报 |
| 周一 09:30 | C6 指标日报（已有定时） |
| 周一 10:00 | 部门负责人复核/调整（参照报告调配） |

## 四、工具用法

```powershell
# WIP 检查（只读）
python -X utf8 tools/wip_check.py
python -X utf8 tools/wip_check.py --strict      # 超限 rc=1

# 台账
python -X utf8 tools/delivery_ledger.py --init --week 2026-W45
python -X utf8 tools/delivery_ledger.py --check --week 2026-W45
python -X utf8 tools/delivery_ledger.py --summary --week 2026-W45
```

台账文件：`agent_platform/data/dev/delivery_ledger/<week>.csv`（运行态数据，不入 git）。

## 五、边界

- 不修改 org.json 编制/权限；不按台账数字直接裁撤；
- 台账只记交付事实，不贴凭据/客户敏感信息；
- 周报为"内部交付"口径，不是销售收入（销售口径需另建台账）。
