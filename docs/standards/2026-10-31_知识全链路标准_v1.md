# 知识全链路标准 v1：入库 → 知识库 → 模型 → 策略反推

> 编号：2026-10-31_知识全链路标准_v1 · 承接：`2026-10-31_PDF知识入库标准_v1`、语料库 P0–P6、research 四关
> 目的：**任何新资料入库后，按本流程走，不再每次重新设计**。
> 原则：知识可溯源、模型不轻训、策略必过四关、一切可复现。

---

## 一、五层能力地图（总览）

```
L0 摄入  PDF/语料/公告 → 规范化文本+结构+知识单元
L1 组织  知识单元 schema / 章节-页码引用 / （可选）知识图谱
L2 知识库 RAG 索引（向量+BM25+RRF）→ 检索/问答/引用
L3 模型  embedding/reranker 微调（条件触发）；LLM 不训、只做 RAG+Prompt
L4 策略  知识单元 → 可测特征 → 假设 → 四关回测 → 台账/监控
L5 治理  血缘/版本/评测/备份/上线/重训（已有：catalog+lineage+BackupDaily+stat_utils）
```

每层都有**固定产物 + 验收阈值**；不达阈值不进入下一层。

---

## 二、L0 摄入层（已标准化）

| 项 | 标准 |
|---|---|
| 输入 | PDF（扫描/文本）、YouTube 语料、公告库 |
| 工具 | `tools/kb_corpus/pdf_ingest.py`（scan/ocr/structure/distill/verify/index/all）；语料库 `tools/kb_corpus/*` |
| 产物 | `_ingest/<book>/`：manifest / ocr.jsonl / structure.json / knowledge_units.jsonl / verify.json |
| 门槛 | 页面覆盖≥95%、OCR≥100字/页且乱码<2%、章节≥5、知识单元引用完整率 100% |
| 升级方向（开源） | 当前 OCR=PyMuPDF+RapidOCR；**布局感知解析**可升级为 [MinerU](https://github.com/opendatalab/MinerU)（中文/表格/公式友好）、[Docling](https://www.ibm.com/think/news/doclings-rise-llm-ready-data)（IBM，LLM-ready 结构化）或 [Marker](https://github.com/datalab-to/marker)（PDF→Markdown）；**选择规则**：表格/公式>10 处或阅读顺序混乱 → 上布局解析；纯扫描老书 → OCR 先行 |

## 三、L1 知识组织层

**知识单元 schema v1（已是标准）**：
```json
{"book":"","chapter":"","page_start":1,"page_end":2,"concept":"","claim":"","evidence":"",
 "source":"ocr+llm","confidence":"medium","sha1":""}
```

标准：
- 每条必须可溯源（book+chapter+page）；无源断言禁止入库（判例：H19 无源标题情绪 → rejected）；
- 章节结构（structure.json）与页码单调性校验；
- 去重：同 claim 归一化后唯一（sha1）；
- （可选）知识图谱：当需要**多跳推理/实体关系**（人-事-股-概念）时，用 [GraphRAG](https://github.com/microsoft/graphrag)、[LightRAG](https://github.com/HKUDS/LightRAG)、[KAG](https://github.com/OpenSPG/KAG) 或 [HippoRAG2](https://cloud.tencent.com.cn/developer/article/2505959)；**规模 <10 万知识单元且问答以单跳为主 → 不上图谱**（成本/收益不划算）。

## 四、L2 知识库层（RAG，已有）

| 项 | 标准 |
|---|---|
| 索引 | 向量（bge-m3, 1024d）+ BM25 + **RRF 融合**；chunk 300–500 字/重叠 10–20% |
| 引用 | 答案必须带来源（book/章节/页码 或 video_id/时间戳）；资料不足答"未覆盖" |
| 评测 | golden set ≥50；Recall@5≥0.6、引用正确率≥0.9（RAGAS 口径见 L5） |
| 事实 | 当前语料库 12 文档/66 记录 v3、Recall@5 0.74–0.83；**检索不是瓶颈，内容深度才是**（弃答率 60%）→ 优先补内容（Phase3 转写/布局解析），而非调参 |

## 五、L3 模型层（该训才训）

### 5.1 决策矩阵（RAG vs 微调）

| 需求 | 首选 | 理由 |
|---|---|---|
| 知识时效/可溯源问答 | **RAG** | 更新即生效、可引用、成本低 |
| 输出格式/语言风格稳定 | Prompt/Few-shot → 必要时 LoRA | RAG 不解决风格 |
| 领域术语/隐式知识（不在文档里） | LoRA/继续预训练 | RAG 检索不到 |
| 检索召回差（同义/专业词） | **embedding 微调** | 性价比最高的小模型训练 |
| 排序差（相关文档排在后面） | **reranker 微调** | 先看通用 reranker 是否已有效；我们实测 bge-reranker-base 通用版 **-2.4pp**，不微调不上线 |
| 9B 模型本地 CPU 训练 | ❌ 不可行 | 127GB 内存无 GPU；LoRA 需 GPU/云 |

参考：[RAG vs Fine-Tuning 决策指南（SiliconFlow）](https://www.siliconflow.com/zh/blog/rag-vs-fine-tuning-decision-guide)、[Boldare 对比](https://preview.boldare.com/blog/rag-vs-fine-tuning/)。

### 5.2 Embedding 微调（条件：RAG Recall@5 <0.6 且数据足够）
- 数据：query–positive（golden/near-dup）+ hard negatives（BM25 top-k 非正例）；≥5,000 组；
- 工具：[sentence-transformers](https://github.com/UKPLab/sentence-transformers)、[FlagEmbedding](https://github.com/FlagOpen/FlagEmbedding)（bge 官方微调脚本）；
- 评估：Recall@5/MRR 相对基座 **+3pp 以上**才上线；否则回滚；
- 产出：模型卡（基座/数据/epoch/评测/回滚点）+ 索引重建。

### 5.3 Reranker 微调（条件：通用 reranker 无效且标注对≥2,000）
- 工具：FlagEmbedding reranker finetune；评估 nDCG@5；
- 红线：**未微调的通用 reranker 不许直接上**（已有判例：-2.4pp）。

### 5.4 LLM 领域适应（LoRA/QLoRA，最后手段）
- 工具：[PEFT](https://github.com/huggingface/peft)、[Unsloth](https://github.com/unslothai/unsloth)、LLaMA-Factory；
- 数据：高质量指令对 ≥1,000（来源需许可）；严格 train/eval 隔离；
- 当前阶段：**不训练**（无 GPU；RAG+Prompt 已够用）；若未来上 GPU，先做 0.5B–1.5B 小模型实验；
- 风险：灾难性遗忘、幻觉增加、评测成本 → 训练后必须过 L5 评测与人工抽检。

### 5.5 训练数据治理（强制）
- 许可白名单 + 来源记录 + PII 扫描（Presidio/正则）+ 近重复（MinHash）+ 时间切分防泄漏；
- 训练集/评测集按来源/时间去重隔离；模型版本入注册表（`agent_platform/registry/`），可回滚。

## 六、L4 策略反推层（知识 → 策略）

### 6.1 三步法
1. **特征化**：把知识单元转成可计算特征/事件定义（示例见 6.2）；
2. **假设化**：生成「标的 × 信号 × 持有期 × 方向」的可测假设，登记 hypotheses.db；
3. **验证**：四关（PIT/OOS/成本/容量）+ 统计修正（重叠/前视，见 `research/MEETING.md` 与 `tools/research/stat_utils.py`）→ 台账状态。

### 6.2 示例：量学知识单元 → 特征（H24+ 候选）
| 知识单元（《伏击涨停》） | 可计算特征 | 假设模板 |
|---|---|---|
| 量柱七形态（高/低/平/倍/梯/缩/金） | 5/10/20 日量比、量能斜率、缩量比 | 倍量柱后 5 日超额收益？ |
| 黄金柱/将军柱/元帅柱 | 突破平台+量能结构（N 日新高+缩量回踩） | 金线支撑（回踩不破）后 10 日胜率？ |
| 金线战法（踩顶/踩腰/踩脚） | 均线/成本线回调深度分位 | 强势股回踩 10 日线后 20 日收益？ |
| 价升量缩 | 价涨量缩（divergence）事件 | 价升量缩后 5 日反转？ |
| 极阴次阳 | 大阴后次日阳线（实体覆盖≥50%） | 极阴次阳后 3/5 日反弹？ |
| 兵临城下/冲关守关 | 前高附近放量试探（N 日高点距离） | 试关/破关事件后 20 日收益？ |

### 6.3 LLM 辅助假设生成（可选）
- 开源参考：[Agentic-AI-for-Quantitative-Research-and-Alpha-Discovery](https://github.com/QuantSingularity/Agentic-AI-for-Quantitative-Research-and-Alpha-Discovery)（9-agent 假设生成→泄漏感知回测）；
- 纪律：LLM 只做**假设草稿**，必须人工审 + 四关；禁止直接下单/实盘；每条假设登记 evidence_path。

### 6.4 策略反推的产出标准
- 台账：`research/hypotheses.db`（status/conclusion/evidence_path）；
- 报告：`research/reports/<H>_*.md`（必含数据窗口/方法/结果/局限/统计修正）；
- 决策：例会按 `research/MEETING.md` 复核清单 6 条逐项打勾。

## 八、新资料入库后的标准动作（SOP 12 步）

1. 放文件到 `C:/项目/PDF`（或语料目录）；
2. `pdf_ingest.py scan` → 判定 text/scanned/mixed；
3. `ocr`（仅 scanned）→ 可续跑；
4. `structure` → 章节/页码，人工抽检目录；
5. `distill` → 知识单元（先 `--chapters 10` 试点，抽检准确率≥90% 再全量）；
6. `verify` → 全绿才继续；
7. `index --rebuild-rag` → 摘要入 knowledge_docs + 重建索引；
8. 跑 golden 评测（Recall@5 / 引用正确率）；
9. 特征化：知识单元 → 特征映射表（写入报告）；
10. 假设登记 + 四关回测（注意前视/重叠修正）；
11. 台账/报告/例会复核 6 条；
12. 上线前：备份 + 版本登记 + 驾驶舱/页面展示。

**不满足任一步门槛 → 停在该层，禁止带病入库**。

## 十一、成本与风险

- OCR 4–6s/页、蒸馏 1–2s/章（CPU）；embedding 微调需 GPU（租用成本另计）；
- 风险：版权（仅内部）、OCR 误差、LLM 抽取幻觉（必须页码引用+抽检）、训练数据泄漏（时间切分）、RAG 评测口径失真（校准）；
- 红线：不训练=不承诺效果；未过四关=不实盘；知识单元无源=不入库。
