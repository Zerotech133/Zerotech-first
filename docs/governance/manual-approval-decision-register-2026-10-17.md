## 一、统一批准规则

### 1. 当前默认权限

允许：

- 单域代码开发，且不写共享生产面；
- 只读审计、自动化测试、文档整理；
- Mock、Shadow、离线实验；
- 不写 live 数据根的验证脚本。

冻结：

- 新增跨域大功能；
- 未登记的 nginx、端口、计划任务、Neo4j、Ollama、Hermes state 或 live 数据写入；
- 未备份的账本迁移、删除、状态修正、字段补齐；
- 批量 E 盘到 C 盘路径替换；
- 直接重启生产服务或以 8787 生产实例处理 8788 验证实例问题。

### 2. 任何批准必须同时具备

1. 明确的决策选项和范围；
2. 指定批准人、执行人和观察人；
3. 变更窗口及共享资源登记；
4. 变更前快照、哈希或现场探测；
5. 测试、运行证据和回滚方案；
6. 变更后复核以及文档更新。

### 3. 统一签批字段

| 字段 | 填写要求 |
|---|---|
| 决策编号 | 使用 `DEC-YYYYMMDD-NN`，不得复用 |
| 决策项 | 只批准一个清晰范围，不打包隐含授权 |
| 选择 | `批准`、`拒绝`、`暂缓` 或 `补证据后再议` |
| 批准人 | 项目负责人/管理员/领域负责人实名 |
| 执行人 | 具体 Agent 或人员 |
| 窗口 | 开始、结束、时区 |
| 前置证据 | 文件路径、现场探测时间、SHA-256 等 |
| 放行条件 | 可验收的命令、HTTP、测试或哈希结果 |
| 回滚 | 明确回滚命令、快照或恢复点 |
| 结果 | 执行后填写；未执行写“未执行” |
