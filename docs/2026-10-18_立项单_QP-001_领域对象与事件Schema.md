## 2. 目标

一句话：冻结 QT 量化线的交易领域对象与事件的版本化 Schema（v1），作为后续所有 QT 工单（事件账本、授权单、虚拟账户账本等）的共同契约基线。

## 3. 范围

### In（做）

1. 盘点并定义交易领域对象 Schema：策略/信号、入池证据、授权单、订单、成交、持仓、账户、风控否决、复盘记录等核心对象。
2. 定义事件 Schema（EventEnvelope 口径）：事件类型、`trace_id`、`decision_bundle_id`、版本号、来源、时间戳、证据引用等必填字段。
3. 落实 v1.1 强制约束：对象归属 Decision / Portfolio / Risk Policy / Execution / Settlement 五层的哪一层（§13.3，任何对象不得跨层写入）；运行模式字段 `BACKTEST / REPLAY / SHADOW / SIM_MARKET`（§13.2）。
4. Schema 版本化机制（版本号、变更规则、冻结流程）。
5. Schema 以文档+机器可读格式（如 JSON Schema 或 Pydantic 模型定义稿）双形式冻结，落点在本仓 docs/design 或约定目录。

### Out（不做）

- 不实现事件账本、幂等键、trace 存储本身（QP-002 范围）。
- 不实现授权单与风控逻辑（QP-003 范围）。
- 不重构任何历史模块代码（`quant_backtest/` 各模块仅作现状输入，不动其代码）。
- 不接入任何新 Agent（ Schema 冻结前的红线，路线图 §五门槛 1）。

## 4. 仓内现状输入（真实路径）

- `quant_backtest/strategy_layer/`（signal.py、adapter.py、strategy_registry.json 等）：存量信号/策略注册现状，Schema 需覆盖其信号对象并规划映射。
- `quant_backtest/execution_engine.py`、`quant_backtest/datamart.py`：存量成交与数据面现状。
- `quant_backtest/ai_operator/`：存量回放/人工复核/来源签名能力。
- `agent_platform/docs/audit/2026-10-17_M0事实源与适配器盘点.md`：已提出 EventEnvelope / ObjectEnvelope 外包思路（事件账需补 `event_id`、`object_ref`、`revision`、`event_hash`、`causation_id`），QP-001 的事件 Schema 应与该盘点口径衔接。
- 现状确认：仓内**尚无**统一的交易领域对象 Schema 文件（QT 线此前零立项），本单为首次建立。
