# 后峰盘前 Agent · 职责与日报 SOP v1

> 2026-11-12 起草。回答老田三个问题：这个 Agent 干什么、每天怎么干、对后峰能带来什么。
> 落地代码：`tools/preopen/`（run_preopen.py 为唯一入口）；调度：`tools/scheduled/preopen_task.ps1`。

---

## 一、一句话定位

**它是后峰平台的「开盘前质量守门员 + 简报编辑」。**

不选股、不交易、不改数据。它每天只做三件事，做完就退场：

1. **确认地基能用** —— 逐源核对数据是否真的到了目标交易日，并给出「能出报告 / 有保留地出 / 不许出」的判决；
2. **把昨天的信号变成今天能发的东西** —— 精选名单 + 市场背景 + 口径说明，一份可全文转发的简报；
3. **记账** —— 每份简报的名单都落进台账，将来用真实超额检验，而不是用回忆评价。

---

## 二、它不该是什么（先把边界钉住）

| 容易滑向的角色 | 为什么不行 |
|---|---|
| 「AI 选股机器人」 | 选股是策略层的活（`_preopen_pick15_v2_adj.py`）。Agent 去调因子、改权重，等于让质检员改配方，出了事分不清是策略错还是执行错。 |
| 「全能投研助理」 | 什么都答 = 什么都答不准。盘前只有 40 分钟窗口，它必须只回答一个问题：**今天这份名单能不能发。** |
| 「数据修复工」 | 发现数据缺失就自动去补，看似勤奋，实则危险：补进来的数据没经过口径校验，比缺数据更糟。它只负责**报告缺了什么**，补不补由人定。 |
| 「研报写手」 | 券商研报靠观点取胜，我们靠可追溯取胜。学它的**结构**（结论先行、风险前置），不学它的**话术**（目标价、评级）。我们没有投顾资质，写「买入」是越界。 |

## 三、每日时间轴

| 时点 | 动作 | 依据 |
|---|---|---|
| 04:26 | （已有）tdx 全量同步落 `ts_daily` / `ts_adj_factor` | 本机既有链路，非 Agent 职责 |
| **08:10** | **Agent 起跑**：校对 → 选票 → 简报 | 见下 |
| 08:13 左右 | 出简报 H5，人工过目 | 实测全流程 2~3 分钟 |
| 08:15–09:15 | 转发窗口 | 集合竞价前必须能发出去 |
| 09:30 | 开盘，名单进入执行观察 | 口径是「开盘买」，不是盘中追 |

**为什么卡 08:10 而不是更早或更晚**：更早（08:00 前）不必要，04:26 同步完成后数据已稳定；更晚（08:30 后）行情接口开始吐当日数据，此时重跑选票会混入未收盘的当日 bar，盘前必须只认上一个交易日。

### 三步的具体判据

**第 1 步：校对（`audit_preopen.py`）**

不是「看一眼最新日期」，而是按每个源的**角色**分别判：

| 角色 | 含义 | 判定 |
|---|---|---|
| `must` | 精排命脉（个股日线、复权因子、指数日线） | 必须等于目标交易日，否则阻断 |
| `soft` | 缺了能跑但降级（龙虎榜） | 缺则告警，脚本可自愈补拉 |
| `t_plus_1` | 交易所频率就是 T+1（涨跌停名单、两融） | 落后 1 个交易日属`pending`，**不报警** |

然后做**结构断言**而不是只数行数：价格自相矛盾、涨跌幅越界、前收盘与上一交易日对不上、零成交。

最后做**交叉验证**：用日线自算涨跌停，去对交易所官方名单。对不上就说明自算规则失效，情绪数字不可信。

**第 2 步：选票（外部脚本）**

Agent 只负责推参数：共识池取 `strategy_center_inbox` 最新包，精排日取日线最新日。不碰打分逻辑。

**第 3 步：简报（`build_preopen_report.py`）**

按券商盘前晨报的骨架组织：结论先行 → 市场回顾 → 名单 → 筛选路径 → 台账 → 数据体检 → 风险 → 免责。

比券商多两块：**筛选路径可追溯**（82→79→15，每层剔了谁、为什么）、**台账真实超额**（历史批次到底跑赢没有，负的照实列）。

## 四、三种结局，三种处理

它的价值全在**区分**这三种，而不是笼统报「失败」：

| 判决 | 触发 | Agent 动作 | 是否发告警 |
|---|---|---|---|
| **通过** rc=0 | 全部 must 到位、结构无异常 | 出报告 | 否 |
| **有条件通过** rc=1 | 有 soft 缺失 / 交叉验证有边界差异 | **照常出报告**，把告警原文写进报告第 6 节 | 否（告警疲劳比漏报更危险） |
| **阻断** rc=2 | 任一 must 源未到、或结构断言发现坏价 | **不出报告**，写清缺哪张表、落后几个交易日 | 是（飞书） |
| 脚本失败 rc=3 | 选票脚本报错、包缺失 | 不出报告，保留日志 | 是 |

**「不出报告」是设计，不是失误。** 没有报告是显性的，坏数据做出来的报告是隐性的——后者更贵。

## 五、职责清单

**做：**

1. 每交易日盘前跑一次，产出 `deliverables/preopen_report_<执行日>.html`；
2. 校对结论必须能追溯到具体数据源、具体日期、具体断言；
3. 名单进台账（沿用 `cohorts/`，不另起一套）；
4. 缺数据、缺产物、口径变更，一律在报告里写明，不静默绕过；
5. 每次运行的结论落 `preopen_run_*.json`，供事后复盘「那天为什么这么判」。

**不做：**

1. 不改策略参数、不调权重、不做因子研究；
2. 不自动补数据（只报告缺口）；
3. 不对外发送 —— 转发是人的动作，Agent 只产出可转发的文件；
4. 不在盘中重跑（会混入未收盘数据）；
5. 不写「买入/卖出/目标价」（无投顾资质）。

## 六、怎么衡量它干得好

| 指标 | 口径 | 当前基线（2026-11-12 实测） |
|---|---|---|
| **时效** | 从起跑到报告落盘 | 端到端 2~3 分钟（选票 25 秒 + 校对 8 秒 + 渲染 3 秒） |
| **诚实度** | 告警是否全部进了报告 | 2 项告警（龙虎榜缺当日、自算多 2 只）全部写进第 6 节 |
| **不漏判** | 自算涨跌停 vs 官方名单 | 官方独有 0 家（11-10 校验），漏判率 0% |
| **可复现** | 同一数据日重跑结论是否一致 | 除时间戳外逐字段一致（11-12 验证） |
| **阻断准确** | rc=2 是否真的不该出报告 | 尚无 rc=2 样本，待观察 |
| **台账完整** | 每份简报的名单是否都已入册 | 7 个在册批次，无遗漏 |

**不建议拿「报告阅读量」当指标** —— 那个和报告质量无关，和转发对象有关。

## 七、对后峰平台意味着什么

后峰现在的闭环是：**选票 → 逐日跟踪 → 超额结算 → 降级判定**。

缺的恰好是最前面那一环 —— **每天确认地基还在**。现在这一环由老田本人承担：每天早上先问一句「数据正常吗」。Agent 的第一个价值，就是把这句话变成不需要人问。

三件事因此改变：

1. **从「有信号」到「有可交付的信号」**。以前信号在库里，要人去挖；现在每天 08:13 有一份能直接发出去的东西。平台的产出从「数据」变成「产品」。
2. **从「事后追溯」到「事前设防」**。数据坏了，当天 08:10 就知道，而且知道坏在哪张表、落后几天。以前是收盘后结算出不来才发现。
3. **从「凭印象评价」到「有账可查」**。每份名单都进台账，30 个交易日后能回答「这个策略到底有没有超额」，而不是靠记忆和感觉。

一句话：**后峰从「一个台账页面」变成「每天可交付的研究产品」，中间差的就是这个 Agent。**
