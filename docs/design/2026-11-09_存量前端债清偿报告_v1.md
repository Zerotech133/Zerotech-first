## 5. 内联样式收口：中止 + 事故复盘（重要）

**决策：批量替换不做，机制保留。** 理由见下。

分析结论：全站 1853 处内联 style（1910 为初测含误计），其中 1001 处
（54%）是 ≥3 次重复的单一属性串，本已提取 18 个原子工具类登记进
tokens.css（.mt-4~16 / .mb-8,12 / .fs-11,12,16 / .hide / .clickable /
.flex1 / .c-dim, c-muted, c-green）。

**事故经过**：首次批量替换脚本犯低级错误——只向标签插入 class 却
**没有移除原 style 属性**，替换循环永不收敛，触发守卫前已对 81 页
执行约 105 万次重复前插，文件膨胀（dataops.html 42KB→337KB），
且污染深入 JS 模板字符串。

**恢复过程（三层）**：
1. 正则剥除 class=" 前插重复 + 清空属性 → 文件大小全部回落；
2. 第二轮按 class 属性内部 token 迭代剥除 → 残余 5 处（确认为 paper.html
   原生合法的 clickable 用法，非污染）；
3. **与 git HEAD 全站对账**（逐文件比对工具类出现次数）发现两文件误删：
   逆向把页面**原生合法的** `class="hide"`（customer.html ×2）、
   `class="clickable"`（dw.html ×6）当作污染剥掉。按 HEAD 原文锚点
   逐一恢复，复测计数 HEAD=now 全平；customer #main 复测
   `display:none` 生效；6 页回归冒烟 JS 错误全 0。

**教训（已写工作日志，跨会话有效）**：
- 文本级批量替换 HTML 前，必须先证明「替换后模式消失」——即脚本要
  同时完成"加新、删旧"，否则必死循环。写替换脚本先在**单文件单副本**
  上验证收敛性（替换前后文件字节数变化、pat 计数归零）再全站跑。
- 逆向修复必须以 git HEAD 对账验证，不能只看"看起来恢复了"。
- 沙箱内起本地 HTTP 服务会被 SYSTEM 残留进程抢端口（8095/8096 均有
  无 CommandLine 的 python 监听并抢答 404），测试实例必须选冷端口
  并先 netstat 确认空闲。
