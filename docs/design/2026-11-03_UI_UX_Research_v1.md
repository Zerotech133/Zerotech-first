# 零界 UI 风格与用户体验研究 v1

- 日期：2026-11-03｜范围：portal 104 页、tokens、UI Kit、nav、`/hq`、登录页
- 结论：**视觉底子不差，问题是“页面各自为战 + 导航过载 + HQ 缺任务型交互 + 状态语义冲突”**；优化方向是 **Calm Command Center（冷静指挥台）**，不是再换一套皮肤。

## 一、现状审计（有证据）

### 1.1 做得对的部分

- `portal/static/tokens.css`：GitHub Dark 基底、语义色、间距/字号/圆角、焦点、阴影、动效、`prefers-reduced-motion`，方向正确；
- `portal/static/ui/ui.css`：已有 UI Kit v0.1（page/btn/badge/card/tabs/table/toolbar/search/skeleton/empty/error/drawer/toast），能力足够；
- `nav.css`：统一顶栏、下拉、焦点、reduced-motion；
- 登录页：OIDC/passkey + 密码兜底，说明清楚；
- 全站焦点样式、暗色基调、数据密集风格与“个人 AI 公司”定位一致。

### 1.2 主要问题

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| P1 | **UI Kit 未被采用** | `/hq` 全页内联 CSS，未引 `ui.css`；登录页引 `ui.css`+`os_theme.css`；各页自绘 | 同类组件多套皮肤，改一处不同步 |
| P1 | **导航过载** | `nav.js` 约 100+ 链接、6 个一级分组；“指挥”组 7+ 入口 | 找入口靠记路径，移动端/DOM 重 |
| P1 | **页面宽度/字体不统一** | tokens `--page-w:1080`、`ui-page:1210`、`/hq:1180`、登录 520 | 跨页跳转视觉跳动 |
| P2 | **状态色与涨跌色冲突** | `--color-up` 与 `--color-err` 都是红 `#f85149` | 在数字军团语境，红色既表示“涨”又表示“故障” |
| P2 | **HQ 缺任务型交互** | `/hq` 只有 5 tabs + 静态表；无搜索/筛选/排序/刷新/轮询/详情抽屉/骨架屏 | 看到问题后无法快速定位/处理 |
| P2 | **错误态不可恢复** | 未登录时 `/hq` 只显示“加载失败 HTTP 302/401”，无登录 CTA/重试 | 用户卡死 |
| P2 | **可访问性不足** | 自绘 tabs 无 `role=tablist/tab/tabpanel`、无方向键；表格无 caption/aria-sort；11px 字偏小 | 键盘/读屏用户不可用 |
| P2 | **登录态体验被内存 session 拖累** | 登录页明示“8091 重启或 1 小时后失效”；SessionStore 内存 | 重启即掉线，Q2 验收也受阻 |
| P3 | **页面 shell 采用率低** | W3 基线：104 HTML 中 page_shell 仅 2（1.9%） | 统一导航/主题无法自动覆盖 |
| P3 | **性能感知** | `/hq` 一次性拉全量 snapshot（冷启动数百 ms），无缓存/骨架 | 首屏空白、重复加载 |

### 1.3 现状评分（1–5）

| 维度 | 分 | 说明 |
|---|---:|---|
| 视觉一致性 | 2 | tokens 有，但页面/主题多套 |
| 导航可发现性 | 2 | 入口多、缺搜索/角色化 |
| 状态可见性 | 3 | 有 KPI/风险，但缺定义/时间戳/刷新 |
| 错误恢复 | 2 | 失败无登录 CTA/重试 |
| 可访问性 | 2 | 焦点有，tabs/表格/字号不足 |
| 移动体验 | 2 | 卡片两列，但宽表/导航仍重 |
| 设计系统复用 | 2 | UI Kit 在，采用率低 |
| 性能感知 | 3 | 数据真实，缺骨架/缓存 |

## 二、外部原则（对标）

Nielsen 10 条可用性原则中，最相关的是：
1. **系统状态可见**（加载/最后更新/刷新中/失败原因）；
2. **系统与真实世界一致**（“军团/任务/审批/预算”而非内部字段名）；
3. **一致性**（同类组件同一套 tokens/kit）；
4. **识别优于回忆**（搜索/最近/收藏，而非记 100 个路径）；
5. **错误可识别、可诊断、可恢复**（401 给登录 CTA，失败给重试）；
6. **灵活高效**（键盘、快捷入口、批量操作）。

来源：[Nielsen Norman Group — 10 Usability Heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/)

## 三、目标风格：Calm Command Center

**不是“炫酷大屏”，而是“看得清、找得到、点得动、错了能恢复”的指挥台。**

- 基底：GitHub Dark（保留 tokens）；
- 大面积留白 + 细边框 + 低饱和，去掉 neon/玻璃拟态/多层渐变卡片；
- 高密度但可读：正文 13px、表格 12.5px、KPI 数字 tabular-nums；移动端 14px/44px 触控；
- 统一内容宽 **1210px**（`ui-page`），登录页单独窄版；
- 两级导航 + 全局搜索/命令面板（⌘K/Ctrl+K）；
- 状态用“图标+文字+颜色”，不只靠颜色；涨跌色与状态色分离；
- 所有页面共用 `tokens.css` + `ui.css` + `nav.js` + `shortscreen.js`。

## 四、信息架构与导航

### 4.1 全站壳

```
┌ 顶栏：零界 · 搜索/⌘K · 通知 · 当前身份 · 用户菜单 ┐
├ 左侧或二级导航：指挥部 / 军团 / 数据 / 研究 / 系统 ┤
└ 主内容：面包屑 + 页头 + 内容区 + 页脚 ┘
```

- 一级分组控制 5–6 个，不再把 100 个入口铺成胶囊；
- 导航只保留“角色相关”入口（A0/ARCH1/军团/数据/QA），其余收进“更多”/搜索；
- 面包屑只两层：`指挥部 / 任务`；
- 深链可收藏、可分享；当前路径高亮。

### 4.2 命令面板（P1，最高体验收益）

- `Ctrl/Cmd+K`：搜页面、任务、军团、审批、API；
- 支持动作：跳转、复制链接、打开任务、切换自动刷新；
- 键盘优先，鼠标可用；空结果给“最近访问”。

## 五、`/hq` 交互重设计

### 5.1 页面结构

```
页头：零界指挥部 | 数据源 live/静态 | 最后更新 06:02 | 刷新 | 自动刷新开关
KPI：席位 77 | WIP 2 | 审批 40 | Credits | 唤醒 3（可点击下钻）
Toolbar：搜索任务/agent | 状态筛选 | 军团筛选 | 保存视图
Tabs：组织 / 任务 / 审批 / 预算 / 心跳（ARIA tablist）
内容：表格（排序、行点击抽屉、分页/虚拟滚动）
空/加载/错误：骨架屏 / 无数据引导 / 401 登录 CTA + 重试
```

### 5.2 必做交互

1. **加载骨架**：首屏 5 张 KPI 骨架 + 表格三行骨架；
2. **401 恢复**：显示“未登录，去登录 → next=/hq”，登录后回跳；
3. **刷新/轮询**：手动刷新 + 30s 自动刷新，悬浮暂停；显示最后更新时间；
4. **搜索/筛选/排序**：任务按 owner/status/age 过滤；审批按类型/决策人；
5. **详情抽屉**：任务/审批/席位点击打开 `ui-drawer`，不跳页；
6. **键盘**：tabs 左右键、`/` 聚焦搜索、`r` 刷新、Esc 关抽屉；
7. **状态定义**：WIP/stale/lease/approved 加 tooltip/图例；
8. **移动**：KPI 2 列、表格横向滚动、tabs 可横滑、抽屉全屏；
9. **可访问性**：`role=tablist/tab/tabpanel`、`aria-selected`、`aria-sort`、`aria-live` 更新时间。

## 六、设计系统落地方案

### 6.1 tokens v2（增量，不重做）

- `--type-*`：12/13/14/16/20/28；
- `--space-*`：4/8/12/16/24/32；
- `--radius-*`：6/10/14；
- `--status-ok/warn/err/info` 与 `--market-up/down` **语义分离**；
- `--page-w:1210` 全站唯一；
- 状态组件必须带 icon/text，不只靠颜色。

### 6.2 组件层

- 以 `ui.css` 为唯一组件源，页面禁止再写按钮/卡片/表格基础样式；
- `/hq` 改为 `ui-page + ui-page-head + ui-kpi + ui-toolbar + ui-tabs + ui-table + ui-drawer + ui-skeleton`；
- 登录页、OS entry、军团页逐步替换内联样式；
- 新增页面必须通过 tokens/nav/shortscreen 三件套（W3 页面 manifest）。

### 6.3 页面 shell

- 把 `ui-page`/页头/导航/页脚固化为 shell；
- 104 页中优先迁移 top 20 入口页；
- 页面 manifest 记录 `shell/theme/width/owner`，route baseline 自动比对。

## 七、优先级与工期

| 优先级 | 动作 | 工期 | 验收 |
|---|---|---|---|
| **P0 快赢** | `/hq`：骨架/401 CTA/刷新/搜索/筛选/ARIA/抽屉；统一用 `ui.css` | 2–3 天 | 未登录可恢复；键盘可操作；Lighthouse a11y≥90 |
| **P1 设计系统** | tokens v2 + shell + nav 角色化 + 命令面板 | 1–2 周 | 新页面 100% 复用；nav 入口≤6 组；⌘K 可搜 |
| **P1 登录体验** | 会话持久化 + OIDC 主入口 + 错误恢复 | 1 周 | 8091 重启不掉线；登录失败有原因/重试 |
| **P2 全站迁移** | top 20 页 → 所有页；移动端；表格密度 | W3/W4 | page_shell 采用率≥80%；移动 375px 可用 |
| **P2 可观测** | UX 指标：任务成功/耗时/错误恢复/CLS | 持续 | 周报趋势 |

## 八、UX 指标（建议）

- 首次找到目标入口时间（导航/搜索）；
- `/hq` 任务定位到详情 ≤2 次点击；
- 401 恢复成功率；
- 登录成功率/重试率；
- 页面 LCP/CLS、接口 p95；
- 移动端可用性（375px 无横向溢出）；
- 键盘完成核心流程比例。

## 九、不要做

1. 不换皮、不引入 React/Vue/组件框架（当前无框架是优势）；
2. 不做大屏霓虹/玻璃拟态/多层渐变卡片；
3. 不把 100 个入口继续平铺；
4. 不用红色同时表达“上涨/故障”而不加图标/文字；
5. 不用无 ARIA 的自绘 tabs/表格；
6. 不先迁移全部 104 页——先 shell + top 20 + 新页面强制。

## 十、结论

**零界不缺设计 token，缺的是“设计系统的采用 + 以任务为中心的信息架构 + 错误可恢复”。**
最优路径：

> **保留 GitHub Dark/UI Kit → 统一 shell/tokens v2 → `/hq` 先做任务型交互 → 导航角色化 + ⌘K → 再全站迁移。**

这比“重做一套新 UI”成本低、风险小，且直接改善 Q2/HQ 的日常使用体验。
