## 0. 一句话

**统一的是"设计系统 + 壳 + 清单 + 门禁"，不是一个皮肤。** 零界正式允许 **2 个主题**（浅色驾驶舱、深色 OS）+ **1 套移动 H5 套件** + **2 个适配器例外**（Hermes、Quant React）；其余页面必须使用统一 tokens、UI Kit、官方壳与导航规则。

## 1. 适用范围

适用于 8734 同源入口下的全部人类可见页面：
- `portal/*.html`（含 `/`、`/portal`、`/zero_proto.html`、`/os-entry`、`/hq` 等）；
- 移动端 `/m/*`（H5 套件）；
- 页面包（Quant React 等）与适配器 UI（Hermes 等）按 §3.5 例外规则接入；
- 不含：纯 API/JSON、运维脚本输出、外部产品自带 UI（RAGFlow/Neo4j 等）。

## 2. 分层模型（四层 + 一清单）

| 层 | 内容 | 单一真源 |
|---|---|---|
| **统一层** | 语义色（涨跌/状态分离）、字号/间距/圆角/页宽、动效、焦点、空/错/加载态、A11y | `portal/static/tokens.css` + `portal/static/ui/ui.css` |
| **主题层** | `light-cockpit`（浅色驾驶舱）、`dark-os`（深色 OS）；H5 移动主题 | `tokens-base` + `theme-*` 覆盖层（新增） |
| **壳层** | `cockpit-shell` / `os-shell` / `h5-shell`：head 资产、页头、面包屑、页脚、导航挂载点 | `portal/_templates/page_shell_v1.html` + `page_shell_gen` 资产清单 |
| **导航层** | 深色 OS：`nav.js`（角色化，两级）；浅色驾驶舱：自有 6 项（白名单）；H5：`m.js` 壳导航 | `portal/api_common.py::DOMAIN_NAV_GROUPS` → `tools/export_nav.py` 生成 `nav.js` |
| **清单层** | 页面清单（§6）+ 路由基线（`portal_route_inventory`） | 页面 manifest + `route_baseline` |

## 3. 主题与例外（正式版）

### 3.1 官方主题

| 主题 ID | 适用 | 规则 |
|---|---|---|
| `light-cockpit` | `/zero_proto.html`（人看首页） | 白底/青蓝；自有 6 项导航；**不加载 `/static/nav.js`**（防双导航，既有判例） |
| `dark-os` | `/os-entry`、`/os-board`、`/hq`、专业工作台 | 深海军蓝（OS 定版视觉令牌）；加载 `nav.js`；页内视图 tabs |
| `h5` | `/m/*` | `m.css`+`m-os.css`+`m.js`；移动优先；复用统一语义色子集 |

> 旧 GitHub Dark 页面（`tokens.css` 基底）属于 `legacy-dark`，迁移到 `dark-os` 或 `light-cockpit`；`/os-board` 等已知偏差列入迁移清单，不再默认保留"双皮肤"。

### 3.2 允许的适配器例外（必须登记，不得新增第二设计语言）

| 例外 | 说明 | 桥接要求 |
|---|---|---|
| Hermes WebUI（8787） | 独立单文件 UI（`style.css` 约 542KB），作为运行适配器 | 必须通过 CSS 变量/tokens 注入对齐语义色与字号；入口从 8734 同源反代进入；不新增端口/域名 |
| Quant React（`/quant/`） | 页面包（构建产物） | 构建期注入 tokens 变量；不得在页面内另建色彩体系 |

例外须在页面清单中 `theme: adapter:<id>`，并写替换/退役说明；新增例外需 A0 批准（ADR-017 例外流程）。

## 4. 设计令牌（tokens）规范

1. **单一真源**：唯一物理文件 `portal/static/tokens.css`；`picks_public/static/tokens.css` 等副本由构建/同步生成，不允许手工维护（副本 hash 必须与真源一致，并纳入门禁）。
2. **分层**：primitive（`--gray-*`/`--red-*` 等）→ semantic（`--bg-*`/`--text-*`/`--border-*`/`--market-*`/`--status-*`）→ component 变量由 UI Kit 定义。
3. **语义拆分（tokens v2 增量）**：
   - 市场：`--market-up`（红涨）、`--market-down`（绿跌）；
   - 状态：`--status-ok/warn/err/info` 与市场色分离；
   - 字号 `--type-12/13/14/16/20/28`；间距 `--space-4/8/12/16/24/32`；圆角 `--radius-6/10/14`；页宽 `--page-w:1210px`。
4. **禁止**：页面内新增硬编码 hex/rgb 颜色；页面 `<style>` 覆盖基础组件外观；主题差异必须通过 token 覆盖实现。
5. **主题覆盖**：`theme-light-cockpit.css` / `theme-dark-os.css` 只覆盖 token，不写页面布局。

## 5. 组件（UI Kit）

1. `portal/static/ui/ui.css` 为**唯一组件源**（btn/badge/card/tabs/table/toolbar/search/skeleton/empty/error/drawer/toast）；
2. 页面只做"组合 + 业务样式"，禁止复制组件基础样式；
3. 组件必须内置状态：hover/focus-visible/disabled/loading/empty/error；异步区必须有 `aria-live`；
4. 新增组件先入 `ui.css`（带示例 + 键盘/a11y 说明），再由页面引用；
5. 图表主题统一读 tokens；不新建图表色板。

## 6. 壳与页面准入（三件套升级为"三件套 + 清单"）

1. 所有页面必须含：`tokens.css`（含主题覆盖）、统一壳资产（`os_theme.css`/`ui/ui.css`/`ui.js`/`nav.js` 按主题选择）、`shortscreen.js`（h2≥6 必接）；
2. 新页必须由 `tools/page_shell_gen.py --new` 生成，禁止从旧页复制；
3. 页面必须登记到页面清单（§7），未登记页面不得上线；
4. 页面宽度统一 `ui-page`（1210px），移动端 375px 无横向溢出；
5. 错误/空态必须含"原因 + 恢复入口"（401 给登录 CTA、失败给重试），不允许白屏/裸 500。

## 7. 导航规范

1. **两级上限**：sticky 顶栏 + 页内面包屑；禁止平铺胶囊长条；
2. 深色 OS：`nav.js` 一级 6 域（量化/个股/情报/创作/开发/系统）；域内 >7 入口必须下拉；
3. 浅色驾驶舱：固定 6 项（首页/会议指挥/情报全谱/业务域/产品建设/系统），不加载 nav.js；
4. H5：`m.js` 壳导航 + 入口页；
5. 导航数据唯一源 `DOMAIN_NAV_GROUPS`；`nav.js` 为生成物，禁止手改；
6. P1 提供 ⌘K/Ctrl+K 全局搜索（页面/任务/军团/审批），搜索结果带最近访问。

## 8. 状态、加载、错误与可访问性

1. 异步页面必须有：骨架屏（首屏）、错误态（原因+恢复）、空态（引导）；
2. 状态展示 = 图标 + 文字 + 颜色，不允许只靠颜色；涨跌色与状态色不得混用；
3. A11y 基线：`:focus-visible` 全局可见；tabs/table 使用 ARIA；`aria-live` 播报异步更新；支持 `prefers-reduced-motion`；图标按钮有 alt/aria-label；
4. 键盘：核心流程可不用鼠标完成；禁止正 tabindex；保持 skip-link；
5. 字号：正文 ≥13px，表格 ≥12.5px，移动 ≥14px；对比度满足 WCAG AA。

## 9. 性能与资产

1. 第三方库单一副本 + 内容哈希 + 长缓存；**ECharts 全站只保留一份**，G6 等大库按需懒加载；
2. CSS/JS 变更必须过资源预算门（初始建议：单页 JS ≤ 300KB gzip 首屏，全站 vendor 去重）；
3. 页面静态资源禁止重复引入（同一 asset 只允许一次）；
4. 首屏数据接口与快照分离，避免一次性大 JSON 阻塞渲染（HQ 后续优化）。

## 10. 页面清单（Page Manifest）与生命周期

每页登记字段（v0）：

```yaml
id: page/zero_proto
path: /zero_proto.html
family: cockpit
theme: light-cockpit
shell: cockpit-shell
nav: cockpit-own
auth: none
status: active        # active | legacy | review | archived
owner: A0
apis: []
visual_baseline: docs/visual_baseline/...png
note: 人看首页
```

生命周期：`active`（生产）→ `legacy`（保留入口，待迁移）→ `archived`（重定向/移出 webroot）；`review`（评审稿）不得对公网开放。清单由 `page_manifest` 与路由基线对账（W3）。

## 11. 门禁与验收指标

| 门 | 工具 | 阻断 |
|---|---|---|
| 令牌单一源 | tokens hash 检查 | 第二副本/漂移 |
| 三件套+清单 | `page_shell_gen --check --all`、`unify_nav --check`、manifest 校验 | 缺资产/重复/未登记 |
| UI 静态审计 | `ui_ux_audit`（改动页 + 预算） | 新增 warn 超预算 |
| 短屏化 | h2≥6 + shortscreen 扫描 | 新页违规 |
| 视觉回归 | `ui_visual_gate`/`ui_visual_baseline` | 基线未更新/差异超阈 |

## 12. 变更流程

1. 修改本文（主题/导航/令牌语义/例外）→ `UI-UNIFY` 系工单 + A0/ARCH1 评审；
2. 新增主题/例外 → ADR-017 例外流程（ADR + A0 批准 + 90 天回归）；
3. 页面迁移按波次（top 20 → 域页 → 其余），每批截图 + 回滚；
4. 与框架 K6 同步：本文变更若涉内核契约（tokens schema/页面清单 schema），需 ADR 号（kernel_guard）。
