# 模拟仓工作台 /paper · 整体设计 v1

- 日期：2026-10-27
- 工单：`WO-LEGION-PAPER2-20261027`
- 类型：深色专业工作台（双版本中的「深屏」侧），不是浅色驾驶舱
- 原则：**整体换骨架/视觉；保留全部 DOM ID 与交易 JS**，不改业务逻辑、不扩 portal_api

## 1. 页面目标

模拟仓不是行情展示页，而是「从接待到上岗」的纸面交易工作台。用户进来要回答：

1. 今天我的模拟仓怎么样？（资产/收益/仓位/现金/快照日）
2. 经理今天说了什么、计划是什么、哪里触发风控？
3. 下一步去哪：选策略 → 组团队 → 跑回测 → 上岗？
4. 我的持仓和历史在哪里看？

## 2. 信息架构

```
全局导航（nav.js）
└─ 页面头（身份 + 5 个 KPI）
└─ 上下文条（面包屑 / 纸面环境 / 只读行情 / 刷新）
└─ 五个工作区（sticky tabs）
   ├─ 接待大厅：值班经理简报 / 今日计划 / 止损哨兵 / 组合 / 成交
   ├─ 策略中心：策略卡墙 / 执行台 / 自然语言生成策略
   ├─ 交易员市场：投资总监 / 经理阵营 / 操盘手 / 组合回测 / 价目
   ├─ 持仓：按策略分组的快照表
   └─ 历史：日期选择 / 净值曲线 / 历史账本
└─ 页脚（纸面声明 / 数据源 / 刷新）
```

## 3. 视觉方向

- 深海军蓝底 `#080e19`，面板 `#0f1c2e`，抬升 `#14263a`；
- 主高亮青 `#6bd7e5`，预警琥珀 `#e5c07b`，风险红 `#ff8d85`，正向绿 `#64d6a0`；
- 中文标题「模拟仓」30px，页面 eyebrow 11px 大字距；
- KPI 数字 24px，等宽数字；辅助说明 11–12px；
- 卡片 14px 圆角、1px 描边、轻阴影；表头浅底、行 hover；
- 按钮统一 8px 圆角，主按钮青底深字，次按钮透明描边。

## 4. 布局

- 内容容器 `max-width: 1360px`；桌面 1440 下左右留 24–28px；
- 页面头：左侧身份（2/3）+ 右侧 5 个 KPI（1/3，5 列等宽；≤1100 换行）；
- 上下文条一行：面包屑 + 状态标签 + 数据源；
- Tabs：sticky，圆角分段条，激活项青底深字；
- 接待大厅：首屏接待卡全宽，下面「今天的事」两列；内部机制折叠；
- 策略中心：4 列卡墙（≤1200 三列、≤900 两列、≤600 一列），执行台全宽；
- 交易员市场：经理/操盘手卡片自适应 260px；
- 持仓/历史：表格卡片化，移动端横向滚动；
- 页脚：版本 + 免责声明 + 数据源 + 刷新。

| `.exec-panel` | 执行台卡 |
| `table.data/.sig-table` | 表头/行/hover/数字对齐 |

## 6. 状态与可访问性

- loading：`.empty` 虚线卡 + “读取中…”（沿用现有 JS）；
- error：JS 若输出错误文本，保持可见，不隐藏；
- 键盘：所有 tab/按钮/摘要可 Tab；focus-visible 青色 2px；
- `aria-label` 顶部导航、`aria-current` 当前页、KPI `aria-live`、主区 `role=main`；
- `prefers-reduced-motion` 关闭过渡。

## 7. 技术约束

- 保留全部 DOM ID（`kpis`、`duty-*`、`plan-body`、`stops-body`、`strat12-grid`、`exec-*`、`agent-grid`、`pos-body`、`hist-body`、`nav-curve` 等）；
- 保留现有 81KB 交易 JS，不重写接口；
- 新增 `portal/static/paper_workbench.css`；页面只新增 shell 结构与 class；
- 现有 inline style 先保留（避免破坏动态输出），后续再做 token 化迁移；
- 无新端口、无 L2、无执行权。
