# 后峰盘前 Agent · 自进化与 Hermes 底座 v2

> 定位：**v1（职责与日报 SOP）的下位补充**，不替代 v1。
> v1 回答「它每天做什么」，本文回答「它怎么一天比一天强」。
> 立项：2026-11-12，老田指出 v1 遗漏了自进化 / 事情化 / 发现问题 / Hermes 底座四项。

---

## 一、v1 漏在哪

v1 把 Agent 做成了「守门员 + 编辑」，每天判一次通过/阻断，然后出报告。
它的问题是：**同一天的第 100 次和第一次完全一样**。

具体表现有三处，都是硬伤：

| 症状 | 后果 |
|---|---|
| 每天的判断不落账 | 三个月后无法回答「这套东西到底有没有用」，只能凭印象 |
| 同一个问题反复出现也不升级 | 告警天天刷，人把它训练成背景色，真正的异常来时就看不见了 |
| 发现问题只查单点 | 单表都到、价格都对，但「名单和昨天一模一样」这种关系级故障查不出来 |

一句话：v1 是**静态检查器**，不是 Agent。检查器不会因为昨天踩过坑而变聪明。

## 二、四个能力，各自落到哪

### 2.1 事情化（`tools/preopen/event_log.py`）

**事情 ≠ 日志。** 日志记「发生了什么」，事情记「我当时怎么想、结果如何、差在哪」。

每天落一件 `EV-HF-<数据日>`，字段对齐赵云经验库的四字段口径：

```
expect    我事前预期什么        ← v1 完全没有
actual    实际发生了什么
obs       可判定的观测项（供规则匹配）
surprise  哪一处是我没料到的    ← 学习入口
action    我做了什么
candidates 候选教训（cue/lesson/confidence，status=candidate）
```

`expect` 是这套东西的地基。**没有预期就没有「差」**，没有差就没有学习——
v1 只记 actual，所以它永远不知道自己判断得准不准。

存量不匹配就留空：`empty_reason` 明确写「未匹配既有教训规则，不生成候选」。
自动生成的教训绝大多数是正确但无用的鸡汤，写进经验库只会稀释真知识。

### 2.2 发现问题（`tools/preopen/detect_drift.py`）

和 `check_products` / `audit_preopen` 分工：那两者查**单点**（某表到没到、某天价对不对），
本模块查**关系**（两次运行之间、两个池之间、评分与名单之间）。

**单点全绿而关系已坏，是最常见的失效形态**——因为监控总是按单项建的。

五类检测，全部要求「数字 + 影响 + 动作」三件齐：

| 检测 | 查什么 | 今天实测 |
|---|---|---|
| `NAME_STALE` | 名单与上一份逐只相同 → 形式上每天跑，内容没变 | 数据不足，明天起生效 |
| `BOUNDARY_FUZZY` | 「取前 15」的截断边界分差过小 → 名单对参数极敏感 | gap 0.0159 vs 阈值 0.015，**恰好不触发**（正确行为） |
| `UNIVERSE_SHRINK` | 参与打分的股数骤降 → 选票宇宙静默缩水 | 未触发 |
| `POOL_SYSTEMATIC` | 同池跨批次同向偏离 → 系统性而非运气 | **命中**：auto 池 3/4 期为负（−0.46/−0.45/−0.86/+0.27） |
| `POOL_INCOMPARABLE` | 两池样本量悬殊却并排比超额 | **命中**：auto 均 64 只 vs main 均 3 只，差 22 倍 |

两条命中都是 v1 报告里**照原样并排展示**的数字。第二份产物（今天）的台账里
`main +6.60%` 与 `auto −0.37%` 并排，读者只会得出「小池更准」这个错误结论。

每条发现必须带 `so_what`（所以呢）。只有数字没有影响的告警，接收方无法判断要不要管，
久之全部忽略——这是告警系统失效的通用死法。

### 2.3 自进化（`tools/preopen/evolve.py`）

从事件账里聚合模式，够格才立假设。三条硬约束写在代码里，不是写在文档里：

**Ａ. 建议有状态机**
```
proposed → accepted / rejected → done → verified / failed
```
新一期生成前先读旧建议：还挂着的（accepted 未 done）不重复提；已 failed 的不自动重提。
不做这条，机器就永远在提第 1 条建议——因为没人有义务记着三个月前提过什么，
**但机器自己必须记住**。

**Ｂ. 方向分流：参数类默认拒提**

| 允许提 | 记录但拒提 |
|---|---|
| 时点闸门（何时不交易）、采集链路、告警治理、表达口径、供给完整性 | 选股参数/口径（因子权重、score_mode） |

依据不是偏好，是已被验证六次的事实：P63/P64/P66/P68/P69 六个旋钮调的是同一个 β
（1.184，t=10.39），全部否决；唯一能过预判门禁的是「何时不交易」（+0.371pct）。
**继续往参数方向进化，是在同一个 β 上做第七次实验。**

**关于「不断调校」——记录它，但不发起它**

`PARAM_DRIFT` 规则专门盯 `score_mode` / `score_weights` 的变化（当前指纹：
`v5`，`mom_rank .1 / trend .1 / vol_h .45 / liq 0 / confirm .35`）。
它做三件事，**唯独不做第四件**：

| 做 | 说明 |
|---|---|
| 记 | 权重一变，事件账里立刻留痕，带变更前后完整权重 |
| 质询 | 变更后台账必须按口径分段，不可跨口径累计超额 |
| 提示 | 变更前应有 precheck 对照，否则超额变化是无头案 |
| **不发起** | 不会自动建议「把 vol_h 从 .45 调到 .40」——那正是被证伪六次的方向 |

所以「调校」这个动作**被记账、被质询、但不被机器代劳**。
这样做的实际好处：以后回头看超额曲线，能分清「市场变了」还是「配方变了」。


**Ｃ. 不自动跑实验**
产出 `precheck.yaml` 骨架（15 处 TODO），填不满会被 `experiment_precheck.py` 判 incomplete，
跑不起来。这是设计：填了就等于我替老田做了「信息上限估计」这个判断。

门檻：`event` 类 ≥3 次、`state` 类 ≥5 次。偶发不算。

**Ｄ. 台账：给人看的那一面（`--digest`）**

前面三条全是给机器守的规矩。但自进化如果只能敲命令看，它就不会有人看第二眼；
没人看，等于没进化。所以第 5 步每天出一份 `preopen_evolve_<执行日>.md/.html`。

它回答的不是「我发现了什么」，而是**「现在这套东西够不够格下结论」**，判决只有三态：

| 判决 | 触发 | 含义 |
|---|---|---|
| 没料 | 事件账为空 | 无从判断，先跑流程 |
| 在学，还不足以下结论 | 账龄 < 20 天 | 看到的「规律」可能是这几天行情特征，不是策略特性 |
| 可评估 | 账龄 ≥ 20 天 | 跨行情阶段，开始能分辨策略问题与短期行情 |

**两本账必须分开报，混着说会高估证据：**

| 账 | 量 | 能回答 | 不能回答 |
|---|---|---|---|
| 流程账（事件账） | 当天 1 天 | 流程有没有出岔、判了什么 | 策略赚不赚钱 |
| 选票账（台账 `cohorts/`） | 4 个信号日 | 票后来涨跌、相对大盘多少 | 流程是否健康 |

今天实测的判决是「**在学**」：流程账 1 天、选票账 4 个信号日，两本都短。
**这个结论本身就是价值** —— 它挡住了「用 4 个批次的数字去论证策略有效」这种自欺。

20 天这条线不是拍的：A 股一个月约 20 个交易日，跨过它才会遇到至少一次
不同性质的行情阶段（趋势/震荡/急跌）。此前任何「稳定超额」都无法排除是单一阶段特征。

### 2.4 Hermes 底座

**接什么**（三个真实接入点，都是体系里已有的）：

| 接入点 | 位置 | 用途 |
|---|---|---|
| 席位 profile | `~/.hermes/profiles/<席>/` | SOUL（人格与红线）、`SEAT_CARD.json`（职务与能力）、`memories/MEMORY.md`（长期记忆） |
| 经验库 | `~/.hermes/profiles/zhaoyun/experience/stock_screen/` | 四字段经验的**唯一事实源**，赵云写、策略影子读 |
| 调度 | `~/.hermes/profiles/<席>/cron/` | 每日触发（与 Windows 计划任务二选一，不双跑） |

**不接什么（关键）**：执行入口 `run_preopen.py` 保持**纯 Python，不依赖 hermes CLI**。

实测 `hermes -z` 在本机报 `Gateway inaccessible: service_manager_unavailable`
（gateway 用 schtasks 托管，被安全策略挡）。如果每天出报告依赖它，
它一挂今天就交白卷。所以：

```
Hermes 管「记忆 + 人格 + 调度」   ← 挂了，报告照出，只是当天不记账
Python 管「执行 + 判定 + 渲染」   ← 挂了，Hermes 侧能看到，因为调度没回执
```

两边解耦，谁挂谁不连带。这比「把一切都塞进 Agent 框架」更可靠——
**可靠性来自依赖少，不来自架构漂亮**。

## 四、进化闭环的五个闸

```
① 每日运行 → 事件账（expect/actual/surprise）
② 聚合门檻   event≥3 次 / state≥5 次         ← 偶发不算
③ 方向分流   参数类拒提                       ← 六次证伪
④ 预判门禁   precheck 三块必填，净上限≤0 即弃   ← P-1 级规范
⑤ 签字       老田 approval_gate              ← 无签字不生效
```

**任何一环缺失，进化的结果不采信、不进台账。** 这与 2026-11-11 立的预判规范同源：
"没预判单就跑的实验，结果不采信"。

第 ④ 闸的现实意义：六张参数层单子全过不了，所以第 ③ 闸早就该把它们挡住——
两个闸是冗余的，**故意冗余**。因为第 ③ 闸靠规则，第 ④ 闸靠数字，规则会写错，数字不会。

## 七、怎么衡量它变强了（可验收）

| 指标 | 现状（2026-11-12） | 30 个交易日后应有 |
|---|---|---|
| 事件账覆盖 | 1 天 | ≥30 天，无缺日 |
| 候选教训 | 2 条（均未达门檻） | ≥1 条走完五闸、写入 `stock_screen` |
| 关系级发现 | 2 条（池间不可比、auto 池倾向为负） | 首条被处置（接受或驳回），不留挂起 |
| 判断准确率 | 无法计算（无历史 expect） | 能算：**昨日 verdict=ok 的次日有没有暴露问题** |
| 重复告警 | 未统计 | 同一告警连续 3 日 → 自动降级为题单 |

第四行是真正的进化指标。**它衡量的是「我说正常，事后看是不是真正常」**——
v1 完全没有这个能力，因为它不记自己说过什么。

## 九、它明确不做的

- **不做「AI 选股」** —— 越界改配方，出事分不清是策略错还是执行错
- **不自动调参** —— 参数层已六次证伪，自动调参等于自动生产第七次失败
- **不自动改阈值** —— 风控域只读，防「温水煮青蛙式降标准」
- **不编教训** —— 无规则支撑就留空
- **不追热点写观点** —— 只写数据能支撑的话，无支撑就写「未覆盖」
