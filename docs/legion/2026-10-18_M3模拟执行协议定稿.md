## 1. payload schema 定稿（模拟工单载荷字段表）

模拟域工单 payload 由 `adapters/sim_converter.py::intel_to_sim_order()` 产出（双输入单输出），schema 如下。字段分三类：**必填**（缺一即非法载荷）/ **可选** / **禁止键**（出现即非法，机审拦截）。

### 1.1 必填字段

| 字段 | 层级 | 类型 | 取值约束 | 说明 |
|---|---|---|---|---|
| `kind` | payload 顶层 | str | 恒 `"sim-order"` | 模拟工单标记（转化器 `SIM_ORDER_KIND`） |
| `sim_domain` | payload 顶层 | str | 恒 `"paper"` | 模拟域标记（转化器 `SIM_DOMAIN`）；M4 执行器插槽前仅此一域 |
| `verdict_ref` | payload 顶层 | str | 非空，指向 `Verdict.id` | **唯一血统入口**。影子建议件 id（INTEL-SH-*）不得出现在 payload 任何位置，intel 血统由裁决件 `judged_intel_refs` 字段承载（M3-A0） |
| `lineage` | payload 顶层 | dict | 见下 | 三元组血统注记，供 WO 审计事件承载与三段机器回放 |
| `lineage.verdict_id` | lineage 内 | str | 等于 `verdict_ref` | 裁决件 id 冗余注记 |
| `lineage.wo_id` | lineage 内 | str | 转化时为空串（回填位） | 建单方回填位；append-only 纪律下不做 UPDATE，回放侧以 `work_order` 行 id 补全（见 §4 对照说明） |
| `lineage.intel_lineage` | lineage 内 | str | 恒 `"verdict.judged_intel_refs"` | intel 血统**指针**（指向裁决件字段），intel id 本体不进 payload |
| `lineage.replay` | lineage 内 | str | 恒回放链说明 | `WO -> verdict_ref -> 裁决件 -> judged_intel_refs -> 影子件` |
| `derived` | payload 顶层 | dict | 见下 | 自 intel 提取的**非血统**业务要素，供模拟执行侧使用 |

`derived` 允许键（转化器现产出）：`symbol` / `subject` / `source` / `captured_at` / `confidence`。不含任何影子件 id。

### 1.2 可选回填字段（done 转移结算回执，不进建单 payload）

以下三字段在 `executing→done` 转移时随 `Transition.reason` 以 JSON 结算回执落档（落点：`audit_event` 的 `wo.state_change` 事件 `payload.reason`，见 §4）。**三项全部为模拟数字，与任何真实行情接口零耦合**；M4 换真执行器前仅承载模拟撮合产物：

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `simulated_fill_price` | number 或 null | >0 或 null | 模拟成交价（模拟撮合产物） |
| `slippage_assumption` | number | ≥0 | 滑点假设（固定假设值，非行情数据） |
| `holding_period` | str | 非空 | 模拟持仓期标记（如 `"T+1"`） |

### 1.3 禁止键（命中即非法载荷）

| 禁止项 | 口径 | 拦截层 |
|---|---|---|
| `INTEL-SH-*` 前缀引用 | payload 递归**任意层级**（嵌套 dict/list 全下钻）的键名或字符串值不得出现 `INTEL-SH-` 前缀引用——影子件 id 血统只由裁决件 `judged_intel_refs` 承载，payload 零影子引用 | G3 建单闸（`paperclip/app.py::create_wo()`，W20 落码）：命中即 `HTTPException(422)` 拒单并留痕 |
| G2 黑名单键：`order` / `quantity` / `action` / `risk_passed` / `stance` | 执行指令与裁决结论语义键禁止复制进 payload——**结论单源真值不复制**：`risk_passed`/`stance` 只读裁决件原件；`order`/`quantity`/`action` 属执行指令语义，模拟域由执行器按裁决派生，不经 payload 传递。全集口径沿用 `adapters/shadow_intel.py` `BLACKLIST_KEYS`（含 `qty`/`verdict`） | 转化器侧 G2 校验（`validate_shadow_intel()`）+ `tools/check_sim_isolation.py` 机审（W20） |

### 1.4 落档形态样例（回放侧所见 = work_order 行 + payload 列）

```json
{
  "wo_id": "WO-2026-0101",
  "payload": {
    "kind": "sim-order",
    "sim_domain": "paper",
    "verdict_ref": "VERD-2026-0007",
    "lineage": {
      "verdict_id": "VERD-2026-0007",
      "wo_id": "WO-2026-0101",
      "intel_lineage": "verdict.judged_intel_refs",
      "replay": "WO -> verdict_ref -> 裁决件 -> judged_intel_refs -> 影子件"
    },
    "derived": {
      "symbol": "600000",
      "subject": "缠论一买判读",
      "source": "st1-chan-analysis",
      "captured_at": "2026-10-18T09:30:00+08:00",
      "confidence": 0.62
    }
  }
}
```

done 转移结算回执（`Transition.reason`，JSON 字符串）：

```json
{"simulated_fill_price": 10.86, "slippage_assumption": 0.0005, "holding_period": "T+1", "note": "D3a settle-extra 1 分，模拟数字与真实行情零耦合"}
```

## 2. paper-* 模拟预算科目与 default 物理分账协议

### 2.1 科目规则

1. 模拟域工单一律使用 `paper-*` 前缀科目（如 `paper-exec-01`），建单时 `WoCreate.account_id` 显式传入；**禁止**模拟工单落 `default` 科目。
2. `paper-*` 科目首次被扣减/充值时由既有 `_account_id()` 播种机制自动开户（`INSERT OR IGNORE`，额度 0，靠 topup 入账）；充值走 `POST /budget/{account}/topup`（approver 角色）。
3. est_cost 查表纪律：模拟工单 `est_cost_cents` 一律 `lookup_est_cost("sim-exec")` = **1 分**（名义记账档，本地模拟动作零 API 支出）；表外场景抛 ValueError，禁止静默默认值。

### 2.2 物理分账与零交叉铁律

- `budget_ledger` 按 `account_id` 外键物理分行，`paper-*` 与 `default` 各自维护独立余额链（`current_balance` 按 account 取最新 `balance_after`）；
- **模拟流水不进 default，真实科目（M4 换真执行器后）不混模拟流水**——样例推演以「paper-* 科目流水与 default 余额零交叉」为验收口径（§3）；
- 审计哈希链全局共用一条（append-only），事件 `payload.account_id` 字段区分科目，不因分账拆链。

## 3. 全流程样例工单纸面推演（draft→done 全轨迹）

设定：科目 `paper-exec-01` 充值 100 分；工单 `WO-2026-0101`（payload 见 §1.4），`est_cost_cents = lookup_est_cost("sim-exec") = 1`，`account_id = "paper-exec-01"`。执行期 1 次模拟撮合动作（D2 计量 1 次）。

### 3.1 状态机轨迹（409 计数 = 0）

| 步 | 动作 | API 调用 | 状态迁移 | 闸判定 |
|---|---|---|---|---|
| 0 | 科目开户充值 | `POST /budget/paper-exec-01/topup` 100 分（approver） | — | — |
| 1 | 建单 | `POST /wo`（title/ payload /est=1/account_id=paper-exec-01，operator） | → `draft` | G3 闸（W20 落码后）：payload 零 INTEL-SH- 引用，放行 |
| 2 | 提交 | `transition to=submitted`（operator） | `draft→submitted` | submit 闸：est=1 > 0 ✓ |
| 3 | 批准 | `transition to=approved`（approver） | `submitted→approved` | approve 闸：余额 100 ≥ est 1 ✓ |
| 4 | 开工 | `transition to=executing`（operator） | `approved→executing` | **D1 预扣** 1 分 ✓ |
| 5 | 模拟撮合 | `POST /wo/WO-2026-0101/meter` cost_cents=1（system） | — | 仅 executing 态可计量 ✓（**D2 补扣**） |
| 6 | 结算完工 | `transition to=done`（system，actual_cost_cents=2，reason=结算回执 JSON） | `executing→done` | **D3a 结算**：actual 2 > est 1 → 补扣差额 1 分 |

### 3.2 paper-exec-01 预算流水（逐笔，余额序列 100→99→98→97）

| 笔 | 扣减点 | budget_ledger.reason | delta（分） | balance_after |
|---|---|---|---|---|
| 1 | —（充值） | `topup` | +100 | 100 |
| 2 | **D1 预扣** | `wo:WO-2026-0101:pre-hold` | −1 | 99 |
| 3 | **D2 补扣** | `wo:WO-2026-0101:meter` | −1 | 98 |
| 4 | **D3a 结算** | `wo:WO-2026-0101:settle-extra`（2−1=1） | −1 | 97 |

**勾稽**：D1（1 分）+ D2（1 分）+ D3a（1 分）= 总支出 3 分；100 − 3 = 97 ✓，余额序列逐笔可对。

**结算口径说明**（零改码承载的约定，不改 app.py 任何语义）：D2 补扣为执行期按动作计量（每次模拟动作 1 分，流水与动作一一对应——执行完成条件 B 的计量口径）；D3a 为终态按 `actual_cost_cents` 申报结算（`actual < est` 退差额 / `actual > est` 补差额 / 相等零退补），二者为独立调整轴。工单全生命周期现金总支出勾稽公式 = **D1 预扣 + ΣD2 补扣 + D3 退补净额**，逐笔以 budget_ledger 为准（账实相符的锚是账本流水，非申报值）。

### 3.3 审计事件序列（同一哈希链，`/audit/verify` ok=true）

```
budget.credit(topup paper-exec-01 +100)
wo.create(WO-2026-0101)
wo.state_change(draft→submitted, operator)
wo.state_change(submitted→approved, approver)
budget.spend(pre-hold −1)          ← D1，先扣后迁
wo.state_change(approved→executing, operator)
budget.spend(meter −1)             ← D2
budget.spend(settle-extra −1)      ← D3a
wo.state_change(executing→done, system, reason=结算回执 JSON)
```

回执三字段（simulated_fill_price / slippage_assumption / holding_period）随末条 `wo.state_change` 事件的 `payload.reason` 落档，全部模拟数字。

### 3.4 零交叉验证

推演全程 `default` 科目**零流水**（budget_ledger 无任何 account=default 行，余额恒为开户值 0）；4 笔流水全部 `account_id = paper-exec-01`。paper-* 科目流水与 default 余额零交叉成立——M4 换真执行器时真实科目不混模拟流水。

### 3.5 执行完成双条件（W18 落档定义）

- **条件 A（状态机）**：合法走完 `draft→submitted→approved→executing→done` 全程，409 非法流转计数 = 0（本样例 §3.1 六步全过闸）；
- **条件 B（计量）**：meter 全程计量——每次模拟动作（模拟撮合/模拟持仓登记/模拟平仓）经 `/wo/{id}/meter` D2 补扣 1 分，流水与动作一一对应、账实相符（本样例 1 动作 1 笔 meter 流水）。
