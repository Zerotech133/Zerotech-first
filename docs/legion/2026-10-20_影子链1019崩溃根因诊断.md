## 〇、一句话结论

## 二、复现（系统临时目录，未触碰真实账本）

### 2.1 复现受限说明（须先声明）

生产同款形态是 `cmd /c "... > log 2>&1"`。本次诊断中 **`cmd.exe` 在 Bash 与 PowerShell 两个工具侧均被安全策略拦截**（实测返回 `Command blocked for security: cmd.exe cannot be used from ...`），因此**无法 100% 原样跑生产那条命令行**。

处置：改用 `ctypes` 直接调 Win32 `CreateFileW`，**复刻 `cmd.exe` 重定向所使用的那组句柄语义**（`GENERIC_WRITE` + 共享模式仅 `FILE_SHARE_READ`）。这正是 cmd 重定向的共享模式，且是冲突的**充分必要机制**，故复现等价性成立。

脚本落点：`%TEMP%\shadow_repro\repro_share.py`（**不在仓库内、不在生产路径**）。

### 2.2 复现输出（实测原文）

### 2.3 复现得出的三条硬结论

1. **异常形态逐字命中生产**：`PermissionError` / `errno=13` / `Permission denied`，底层 `winerror=183`（`ERROR_SHARING_VIOLATION`）。**证实是共享冲突，不是 ACL 权限**。若是目录只读或 ACL 问题，winerror 会是 5（`ACCESS_DENIED`）而非 183。
2. **重试必然徒劳**：§2 场景 3 的 5 次重试 5 次全败。占用句柄**全进程期持有**，不存在"退避后自然释放"的窗口。**这直接证伪了 10-19 当晚"加重试即可"的初判**（见 §六 最小加固建议）。
3. **与 CWD/目录权限无关**：场景 4 释放句柄后立刻 SUCCESS，同一目录同一路径。目录可写性从未是问题。

**结论：L367 与 CWD 无关。** 工作目录为空（实测 `WorkingDirectory : （空）`）也不影响，因为路径不依赖 CWD。

### 3.3 是否存在两个实例并发

**结论：否，且被三重机制排除。**

1. `AgentShadowDaily` 的 `MultipleInstances = IgnoreNew`（实测）→ 任务级重复触发被系统直接忽略，**不可能有两个任务实例并存**。

3. 崩溃时刻的 traceback 显示 python **在 L367 即刻退出**（`LastTaskResult=1`），此后至当日结束无第二实例迹象。

**但请注意区分**：③ 中"两个实例"这一假设从一开始就与证据矛盾——若真是两实例抢文件，第二个实例的 traceback 也会指向自己的某一行；实测 traceback 只有一条、且形态是共享冲突。

唯一占用者就是**同一条链路的外层**：


## 五、是否可复发 + 判据化建议

### 5.1 判定：结构性脆弱，非偶发 —— 证据强度**强**

判据化论证（每条都可独立证伪，本次全部未被证伪）：

| # | 判据 | 观测 | 结论 |
|---|---|---|---|
| J1 | 崩溃是否 100% 必现？ | 场景 2 复现必现；场景 3 重试 5/5 全败 | 必现 |
| J2 | 触发条件是否恒定存在？ | ps1 L25 `cmd /c ... > last_run.log 2>&1` **至今未改** | 恒定存在 |
| J3 | 是否曾成功过？ | **从未成功过**——10-19 是历史首跑即崩；10-20 靠 catch 存活 | 从未 |
| J4 | 偶发假设能否解释现象？ | "瞬时独占锁"需假设锁恰好在 17:10:02 出现且恰好持续整个进程期——**与复现矛盾**（场景 4 显示句柄必持续） | 解释力为零 |
| J5 | 现状是否带隐患？ | 现状靠 `except PermissionError: return None` 存活。**删掉这一行即复发** | 高危 |

**J1+J2+J3 三条合起来 = 「首次执行必崩、修复仅遮蔽未消除」。**

### 5.2 最小化加固建议（**建议，不实施**）

按"改动面 / 收益"排序，**均未实施**：

**S1（推荐，最高优先）：消除重复打开，而非捕获它。**
`run_shadow.py` 在 `sys.stdout.isatty()` 为 False 时才自开日志；既然外层已用 `2>&1` 把 stdout/stderr 重定向进同一个文件，**自开就是纯多余动作**。二选一即可根治：

- **S1-a（推荐，改 ps1 一处）**：ps1 `run` 分支**不重定向到 `last_run.log`**（如改为重定向到 `last_run.console.log`，或直接不重定向由 Python 自管）。→ Python 自开日志正常工作，两侧不再冲突，**根因消除**。
- **S1-b（改 Python 一处）**：`_redirect_run_log()` 检测到"stdout 已被重定向到本文件"时直接返回 `None`（不靠捕获异常）。→ 语义更明确，但仍留着"两处管同一文件"的隐患。

**S2：把日志打开点移出崩溃主干。**
当前 `log_f = _redirect_run_log()` 失败会终止整个 run（L439 后紧接业务主链）。**建议日志失败绝不阻断落账**——5 标的判决比日志重要。（注：当前 `_redirect_run_log` 已返回 `None` 不抛，故此项在修复后已满足；此条是对 `shadow_ledger.jsonl` 打开点仍 fail-visible 的边界提醒。）

**S3：`shadow_ledger.jsonl` 打开点加锁 + 原子替换。**
现 `9d8b074c` 给账本加了「5 次有界重试」（`LOG_OPEN_MAX_ATTEMPTS=5`）。但 §2 场景 3 已证明：**对共享冲突重试必然徒劳**。建议该打开点改为 **单次 open + 失败即 fail-visible**，或改 `os.replace` 原子落盘，**不要用重试伪装确定性**。

**S4：`>` 截断改 `>>` 追加。**
现状每次运行截断 `last_run.log`，**10-19 的事故 traceback 被 10-20 那次跑物理覆盖**（§4.2）。建议改追加，保留排障历史。

**S5：低优先（非本次根因，防御性）。**
`run_shadow` 启动时写一个 PID 锁文件到 `%TEMP%`，避免人工补跑与计划任务撞车。当前 `IgnoreNew` 只保护任务级，人工 `python run_shadow.py` 不受保护——10-20 03:47 那次是**非常规时刻**的运行，值得留意来源。

| **① 路径权限/属性问题**（目录只读/文件被占用） | **❌ 否** | 复现场景 4：同一目录同一文件，句柄释放后立刻 SUCCESS。目录从未只读。winerror **183**（共享冲突）而非 5（访问拒绝）。PS1 亦无只读属性证据 |
| **② 并发写冲突**（两实例同写一文件） | **⚠ 半成立，但性质需重述** | "冲突"成立；"**两实例**"不成立。占用者是**同一实例链路的外层 shell**（父进程 `cmd.exe` 持有句柄 → 子进程 `python` 再开）。`MultipleInstances=IgnoreNew` 已排除双任务实例 |
| **③ 脚本对 CWD 敏感** | **❌ 否** | L367 路径由 `Path(__file__).parent` 派生为**绝对路径**；`WorkingDirectory` 为空亦不影响。复现场景 1/4 均在任意 CWD 下正常 |

### 精确定性（第四类，原三选一未覆盖）

> **④ 包装器/被包装脚本的自相冲突（same-process-chain self-conflict）**
> `shadow_automation.ps1` 的 `cmd /c ... > last_run.log` 与 `run_shadow.py:367` 的 `open(last_run.log,"a")` 争抢同一文件的写句柄，二者是**父子进程关系**而非并发关系。冲突窗口 = 子进程整个生命周期，**必然必现**。

**这是本次诊断的收敛结论：原三选一都不精确，真因是第四类。**
