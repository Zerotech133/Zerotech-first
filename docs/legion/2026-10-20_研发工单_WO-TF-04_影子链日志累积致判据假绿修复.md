## 一、问题（lead 已复核）

`agent_platform/tools/check_trigger_chain.py` 的 `_judge_shadow_log`（约 `:243-251`）：
```python
for line in reversed(text.splitlines()):
    if line.startswith("shadow day "):
        ...
        if re.search(r"'done':\s*[1-9]", tail): return PASS, ...
```
**取的是文件里最后一条 `shadow day ` 行**。WO-TF-02 已把 `last_run.log` 由「每日覆盖」改为「跨日累积」（单一写入者 + 追加语义），于是：**今日崩溃（今日无收尾行）而历史有成功行时，会读到历史那条并判 PASS ⇒ 假绿**。改前每日覆盖时，今日崩溃判 FAIL。

## 二、改动要求

唯一可改文件：`C:/项目/老田的AI助手/agent_platform/tools/check_trigger_chain.py`

1. **按日期定位当日/最近一次**：从 `shadow day <YYYY-MM-DD> done: {...}` 行中**取日期最大者**（最近一次运行），而不是"最后一条出现"。
2. **禁止历史成功冒充今日通过**：若取到的日期 **早于今日**，**不得判 PASS**；须判为非 PASS 并在文案中**显式写出该行的日期**（如「最近一次影子跑为 2026-10-17，今日无收尾行」），使陈旧成功无法被读成今日成功。具体判 PASS/WARN/FAIL 的措辞由你按本文件既有语义定，但**必须让"今日未跑/今日崩了"在结果里看得见**。
3. **文案必须带日期**：返回的说明里包含所依据那行的日期，便于回看。
4. **不得引入新依赖、不得改其它判据**；`_judge_shadow_log` 以外的函数**零改动**。

## 三、验收判据（必须实跑并给数字）

1. **今日崩溃场景**：夹具日志 = 历史有成功行（日期 D-1）+ 今日无 `shadow day` 行 ⇒ **不得判 PASS**（当前实现会判 PASS，这是修前证据）。
2. **今日成功场景**：夹具日志含今日 `shadow day <今日> done: {'done': 3}` ⇒ 判 PASS 且说明含今日日期。
3. **仅历史成功**（无今日行、且历史行日期更早）⇒ 非 PASS 且文案含该历史日期。
4. **多日累积 + 今日成功在中间位置**（日志里今日行不是最后一条，例如其后还有别的东西）⇒ 仍按**日期**取到今日那条并判 PASS（**这是本次修复的核心：不能只取"最后一条"**）。
5. **零 done 的今日行**（今日跑过但 done=0）⇒ 判非 PASS（沿用既有"零 done"语义）。
6. **既有回归**：`agent_platform/tests/` 下与 check_trigger_chain / observe_point / observation_point 相关的既有测试**零回归**（给数字）。
7. 改动面：`git status --porcelain` **只应出现这一个文件**。
