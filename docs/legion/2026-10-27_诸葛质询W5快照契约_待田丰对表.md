## 1. 落点与文件命名（消费端约定）

```
C:\项目\digital-legion-sandbox\plans\
  2026-10-27_plan.json          # 推荐：每日计划快照（日期_plan.json）
  latest.json                   # 可选：最新快照别名（与当日快照同内容）
  plan_YYYY-MM-DDTHHMMSS.json   # 可选：多次快照历史
```

- 消费端 glob：`*_plan.json` / `plan_*.json` / `latest.json`；按文件 mtime 新→旧取**第一个可用**（坏 JSON / 空快照跳过并 warning）。
- 前缀：文件必须位于 `sandbox_repo_prefix`（白名单 YAML 的 `sandbox_repo_prefix`）内；`--strict-sandbox` 时不在前缀内直接拒绝。
- 写入方式（生产端）：**先写 `.tmp` 再原子 rename**，避免消费端读到半文件；保留最近 N 份（建议 7），不无限增长。

## 2. 最小数据格式（顶层三选一，消费端已兼容）

```json
{
  "plan_id": "PLAN-20261027-A0",
  "generated_at": "2026-10-27T08:30:00+08:00",
  "source": "tianfeng_hermes",
  "items": [
    {"task_id": "WO-EXAMPLE-20261027", "title": "示例任务", "status": "doing",
     "owner": "A0", "project": "general", "deadline": "2026-10-28", "last_update": "..."}
  ]
}
```

- 也可直接顶层数组 `[...]`，或 `{"tasks":[...]}` / `{"plan":[...]}` / `{"doing":[...]}`（消费端 `normalize_items` 兼容）。
- 必填：`task_id`（或映射 key）、`title`/`desc` 至少一个、`status`；其余字段透传。
- 建议 `status=doing`（消费端 tasks 源默认过滤 doing；快照源默认不过滤，可 `--filter-status doing` 强制）。
