## W12 影子产出契约化（shadow_ledger → IntelItem 适配层）

- **目标**：把既有 shadow_ledger.jsonl 判决行（m5.v1 影子行）适配为 contracts `IntelItem` 形态，使影子产出进入军团情报流时**自带机器可校验的建议性边界**。适配层是**单向只读转换器**：读影子账本 → 产 IntelItem，绝不反向写账本。
- **适配层设计**：
  1. **形态**：新增 `digital-legion/adapters/shadow_intel.py`（预研稿，零依赖仅标准库 + contracts）：`shadow_row_to_intel(row: dict) -> IntelItem`；
  2. **字段映射**：`id="INTEL-SH-<date>-<run_id>"`（影子件专用前缀，W14 流向校验的锚点）；`source="shadow-chain"`；`captured_at` 取影子行时间戳；`symbol` 取影子行标的；`confidence` 取影子行置信度（缺省 0.5）；`tags=["shadow-suggest", "legacy-shadow"]`（必含，作为机器可识别的建议件标记）；
  3. **payload.legacy_shadow 引用式载荷**：不复制影子行全量，只存引用键（`run_id` / `date` / `status` / `degraded` 计数 / 要点摘录 ≤N 条）——账本本体始终只在 `agent_platform/data/shadow/` 一处，适配层只持指针（[M1单] W7 已按此口径预留该字段）；
  4. **附加校验 `validate_shadow_intel()`**：在 `IntelItem.validate()` 之上追加影子件专项——tags 必含 `shadow-suggest`；payload.legacy_shadow 必含 run_id 引用；payload **禁止出现执行指令黑名单键**（`order` / `quantity` / `action` / `risk_passed` / `stance` 等）——出现即校验失败。
- **铁律②③机器可校验边界（本单核心设计，四处闸门）**：
  | 闸门 | 层级 | 机制 |
  |---|---|---|
  | G1 类型级 | 适配层模块 | 源码**禁止 import `contracts.verdict`**、禁止出现 `Verdict(` 构造——静态检查（grep/ruff import 约束）即可机审；影子件类型系统里根本没有裁决件这一形态 |
  | G2 字段级 | IntelItem 实例 | `validate_shadow_intel()` 黑名单键校验：`risk_passed` / `stance` 是 Verdict 独有字段，影子件 payload 一旦携带即拒——Verdict 语义无法借尸还魂 |
  | G3 流向级 | 消费侧 | 执行组只认 risk_passed 件（铁律②原文）——影子件无 risk_passed 字段天然不具裁决资格；paperclip 建单 API 侧（M2+ 实装时）拒绝 payload 引用 `INTEL-SH-*` 前缀件的工单 |
  | G4 检查级 | 自动化 | W16 交付 `check_shadow_isolation.py`：对适配层源码 grep G1、对全部影子 IntelItem 产物跑 G2、对影子产出落盘文件 grep `risk_passed` 零命中——三查全绿才算隔离成立 |
- **交付物**：适配层设计稿（本 W 段落即稿）+ `shadow_intel.py` 函数签名与映射表（预研稿）+ 3 条样例转换（真实影子行脱敏样例 → IntelItem dict）。
- **验收**：3 条样例逐条过 `IntelItem.validate()` + `validate_shadow_intel()` 零错误；G1~G3 设计逐条可机审（G4 脚本稿可对样例跑通）。
- **依赖**：contracts `intel.py`（已冻结）；shadow_ledger.jsonl m5.v1 行 schema（[影子审计]，只读对表）。
- **风险**：影子行 schema 若在门3 后演进（m5.v2），映射表需版本化——设计上按 `schema_version` 字段分派映射函数，预研稿即留版本分派点。
- **规模**：0.5 天。

