## W7 心跳定义与产出物

- **目标**：定义田丰「心跳」——每日一次唤起田丰 profile（本地 Ollama `qwen3.5:9b` @ 127.0.0.1:11434），产出**今日情报简报**，整合影子军团前日产出，全部条目以 contracts `IntelItem` 形态落盘。心跳是**调度接线**（定时唤起既有 profile 能力），不是新框架：不新增运行时、不改 Hermes 源码（K-ORG-112 公理），田丰 SOUL/权限边界原样沿用 [双profile稿] §2。
- **交付物**：
  1. **简报文件**：`~/.hermes/profiles/tianfeng/memories/intel/YYYY-MM-DD/brief.json`——内含 1..N 条 `IntelItem`（至少 1 条当日总览条目），逐条字段对齐 `digital-legion/contracts/intel.py`：`id`（约定 `INTEL-<date>-<seq>`）、`source="tianfeng-heartbeat"`、`captured_at`（ISO8601）、`subject`（非金融主题）或 `symbol`、`payload`、`confidence`、`tags`；
  2. **影子整合段**：`payload.legacy_shadow` 引用前日影子军团判决行（`agent_platform/data/shadow/shadow_ledger.jsonl` 只读摘录：date/symbol/status/degraded 计数与要点）——**只作建议性情报引用，不得携带执行指令、不得改写影子账本**（铁律②：影子只有建议权；铁律③：田丰执行相产的是情报件，不产裁决）；
  3. **运行记录**：`~/.hermes/profiles/tianfeng/plans/heartbeat/YYYY-MM-DD.md`——每次心跳一条记录（起止时间/模型/条数/degraded 计数/结果 OK|degraded）；
  4. **校验脚本**：只读小脚本，逐条跑 `IntelItem.validate()`，输出条数与错误清单（空错误列表=合法）。
- **验收**：
  1. 简报样例文件（可手工跑一次产出）逐条过 `IntelItem.validate()` 零错误；
  2. 简报头部统计段含：条数、degraded 计数、引用影子判决行数——三项均可机器解析；
  3. 同日重跑幂等：同 id 覆盖不追加（幂等键 `date+seq`，口径参照 `strategy.py` idempotency_key_rule 惯例）；
  4. 落盘位置仅限 tianfeng profile 内 memories/plans 指定子目录（新增子目录属本单授权），零触碰周一主链与 data/ 账本（影子账本只读）。
- **依赖**：[田丰回执]（profile 就绪）；Ollama `qwen3.5:9b` 在位。
- **规模**：0.5 天。

## W8 触发机制二选一（方案A vs 方案B，终选留过会）

- **目标**：定「每日一次唤起田丰」的触发机制，逐维对比后给推荐项；**终选由过会拍板，本单不定案**。
- **方案A：Hermes cron jobs.json 接线**
  在 `~/.hermes/profiles/tianfeng/cron/jobs.json`（现 `[]` 占位）注册每日心跳 job，由 Hermes 主进程内 cron 模块唤起。
  - **依赖**：**[追认清单] 第九项授权窗口**——cron 归属活动 profile，`active_profile` 不切到 tianfeng 则 job 不生效；而写入 `active_profile` 即切换并**重启运行中 8787 Hermes**，须选业务空窗授权执行。
  - **风险**：8787 重启影响 default 会话与进行中任务；心跳长任务与 WebUI 同进程，推理期占用 Hermes 主进程资源。
  - **回滚**：`active_profile` 写回 `default` + `jobs.json` 清空为 `[]`，重启还原（[追认清单] 第九项已给回滚口径）。
  - **授权需求**：第九项授权窗口 + 过会终选，授权链最重。
- **方案B：Windows 计划任务外挂调 hermes_cli**
  新增一条 Windows 计划任务（对既有 Agent* 四条链**只增不改**），每日定时以命令行显式指定 profile=tianfeng 调 hermes_cli 心跳入口（`HERMES_HOME` 指向或 `--profile` 参数，以 hermes_cli 实测为准，施工时对表落实）。
  - **依赖**：不切 profile、不重启 8787；**无需第九项授权窗口**。需一次 cli 侧对表（确认 cli 可独立按 profile 跑任务且写入严格限定在 tianfeng 目录）。
  - **风险**：与 Hermes 主进程并行做 Ollama 推理——11434 已 tuned par=2，由 W9 时点错峰保证不与影子主链撞车；cli 写入面须实测确认不外溢。
  - **回滚**：删除该条计划任务即净，零残留，回滚成本全场最低。
  - **授权需求**：过会终选 + 新增一条计划任务备案，授权链最轻。
- **对比表**：

| 维度 | 方案A（cron jobs.json） | 方案B（计划任务外挂） |
|---|---|---|
| 依赖 | 第九项授权窗口（切 profile 重启 8787） | 仅 cli 对表；不依赖任何授权窗口 |
| 风险 | 8787 重启业务面影响；同进程资源争用 | 并行推理争用（靠时点错峰消解）；cli 写入面需实测 |
| 回滚 | 写回 default+清空 jobs+重启 | 删一条计划任务即净 |
| 授权需求 | 最重（授权窗口+过会） | 最轻（过会+备案） |
| 演进性 | 心跳内化 Hermes，M2+ 可挂质询定时化同链 | 外挂形态，M2+ 若内化需二次迁移 |

- **推荐项**：**方案B**。理由：①与「不碰运行中服务」红线天然相容，不被第九项授权窗口排期卡脖子，M1 可独立推进；②回滚成本最低且零残留；③田丰心跳当前只有「出简报」一件事，独立进程足够，不值得为它付 8787 重启代价；④方案A 可作为 M2+ 心跳内化（与质询定时化同链）时的演进项，不是放弃。
- **验收**：对比表与推荐结论过会，终选结论回填本单；被否方案留档不删。
- **依赖**：[追认清单] 第九项（方案A 前置）、第六项 6A（见「前置依赖」节）。
- **规模**：0.5 天（含 cli 对表实测 0.25 天）。

## W10 断链降级（田丰不可达）

- **目标**：田丰不可达（Ollama 11434 无响应）时，心跳降级为**显式可计数的占位留痕**，不静默失败。
- **教训引用**：门3 已知 P1 bug——degraded 联动判据方向反了，真降级不计数导致假绿（[护航单] 17:25 段：5 票全降级仍可能 10/10 PASS）。本单铁律：**降级必须显式可计数；任何一次心跳执行（成功或降级）都必须留下可解析痕迹，无痕迹=施工不合格。**
- **触发**：心跳启动探活 `http://127.0.0.1:11434` 连续 3 次失败，或单次推理超时，判田丰不可达。
- **降级动作**：
  1. 写**降级占位件**：`~/.hermes/profiles/tianfeng/memories/intel/YYYY-MM-DD/degraded.json`——JSON 形态，字段含 `status="degraded"`、`reason`、探活记录（时间/错误/次数）、`degraded=true`（机器可读布尔，验收脚本直接解析计数）；
  2. 运行记录 `plans/heartbeat/YYYY-MM-DD.md` 追加一行 `degraded` 事件（结果列非 OK）；
  3. **不静默**：不吞异常、不空转退出——退出码与日志均反映降级态。
- **恢复**：次日心跳自动重试正常链路；降级当日**不补跑**（避免撞既有任务链窗）。
- **影响面**：只降级「当日简报」一环；不碰执行主链、影子账本、Paperclip、运行中服务（与 [双profile稿] §6 降级铁律同口径）。
- **验收**：断链演练一次（见 W11-3），占位件落盘、`degraded` 字段可被脚本计数、留痕完整。
- **依赖**：W7（落盘目录与运行记录格式由 W7 定）。
- **规模**：0.5 天（含演练脚本 0.25 天）。
