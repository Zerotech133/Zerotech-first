## 3. 设计要点四条

### 要点 1：只读收编（append 式账本的只读读）

| 项 | 口径 |
|---|---|
| 读什么 | **D 日全量行**（主收编对象）+ **D-1 日全量行**（对照/补齐），两日均只读 |
| 为什么读两日 | D 日零行时（§5），D-1 日行提供"上一交易日的最后可引用状态"，避免简报出现无锚点的空段；D-1 日行仅作 `legacy_shadow.prev_day_ref` 对照计数，不重复计入本轮 `rows` |
| 怎么读 | `open(path, "r", encoding="utf-8")` 逐行 `json.loads`，**不落中间文件、不加锁、不 truncate、不 rewrite**（红线 1：账本零变更） |
| 收编键 | 账本 `date` 字段**等值匹配** D 日，**不用 `ts` 切日**。理由（实测）：`ts` 折本地时区后落在 17:12–17:15，若按"D-1 08:30 至 D 08:30"时间窗切日会整段漏行；`date` 是账本自带的交易日语义键，唯一可靠 |
| 写什么 | 只写 D+1 简报（`…\memories\intel\<D+1>\brief.json`，[M1单] W7 授权目录内）与运行记录（`…\plans\heartbeat\<D+1>.md`）；账本零写 |
| 幂等 | 简报同 `date+seq` 覆盖不追加（[M1单] W7 验收 3），故同一 D+1 重跑不产生第二份简报、不产生第二份影子引用 |

### 要点 2：降级即留痕（degraded 计数如实携带，不静默吞）

1. **D 日行带 `degraded=true`** → D+1 简报 `legacy_shadow.refs[]` 对应条目**原样携带** `degraded: true`，条目照常入段，**不因降级而剔除、不改写为 false**。
2. **计数三处一致**：`legacy_shadow.degraded` = `stats.degraded_count`（W13 §3.3 口径：影子链 + ST1 合计）= 简报运行记录 `plans\heartbeat\<D+1>.md` 的 degraded 列。三处不等即验收 FAIL（W14 §6.2 C4 同口径）。
3. **不得静默升级**：`parse_ok=false` 的行（实测样本 `run_id=76cf6d30358f` 即 300750 行 `parse_ok=false`、`recommendation=null`、`confidence=null`）属**解析失败但非降级**，必须单独携带 `parse_ok=false` 并在 `points` 中如实说明"该行无方向/无置信"，**不得用 0.5 默认值伪装成正常判读**（与 W13 §2.3 #11"缺证即按降级计"同一保守取向）。
4. **教训锚**：门3 已知 P1 bug——degraded 联动判据方向反了导致"5 票全降级仍 10/10 PASS"（[M1单] W10 教训引用）。本稿的对应防线是**计数三处交叉相等**，而非单点布尔。

### 要点 3：时点错峰（08:30 与 16:40–18:00 全段安全隔离）

| # | 约束 | 本稿执行 |
|---|---|---|
| 1 | 周一 17:00-18:00 全段禁排（[M1单] W9 硬约束 1） | 本稿不排任务；扩写中一切"可在 17 点做"的设想一律作废，收编动作只允许在 08:30 |
| 2 | 16:40–18:00 既有链全段避让（W9 硬约束 2） | 08:30 距该段最近端点 8 小时 10 分钟（16:40），距最远端点 8 小时 40 分钟（17:10） |
| 3 | 周六凌晨预演段（05:55 前后）避让 | 08:30 距 05:55 为 2 小时 35 分钟；预演段若延后，08:30 仍不与其重叠 |
| 4 | 门3 观察窗内两链均不新增动作（[M2单] 第 147/149 行） | 17:10–17:45 全段零写入；本稿连"读账本"都不在该窗内做（读动作安排在 D+1 08:30） |
| 5 | 首跑不得落在门3 观察日及预检时段（W9 硬约束 3） | 首个候选环 D+1 = 2026-10-20 08:30（§2 末） |

> 一句话：**17 点是影子链和门3 的地盘，08:30 是心跳的地盘，两边都不越界。** 这不是时间偏好，是"读的时点必须离开写的时点"的结构性隔离。

### 要点 4：环闭合验收锚点

| 项 | 口径 |
|---|---|
| 锚点键 | `run_id`（账本行级唯一，**实测为 12 位十六进制，每行一个**，非每批次一个） |
| 闭合条件 | 连续 2 个 D 日的**全部** `run_id`，在各自 D+1 简报 `legacy_shadow.refs[].run_id` 中逐条命中；命中率 100% 才算闭合 |
| 不闭合的合法例外 | D 日零行（§5）→ 该日 `rows=0`，无 `run_id` 可对，**不计入分母**，也不判失败；须以 `rows=0` 显式留痕 |
| 反查方向 | 简报出现账本中不存在的 `run_id` = **伪造引用**，FAIL（比漏引更严重，属数据失真） |
| 环宽 | 单环 = 1 个 D 日；验收窗口 = 2 环（连续 2 个 D 日），与 [M2单] W15 设计要点 4 及 W16 验收项 3 一致 |

## 4. run_id 追踪表

### 4.1 表结构（字段名具体，逐行一条影子行）

一条账本行 = 一条追踪记录。字段 8 项，命名与机器类型如下：

### 5.2 为什么零行也是可解析痕迹（与 W10 同构）

- [M1单] W10 铁律原文：**"任何一次心跳执行（成功或降级）都必须留下可解析痕迹，无痕迹=施工不合格。"**
- 本稿把这条铁律向前推一格：**影子链的"无"也必须是可解析的"无"**——`rows=0` 是 `int` 零，不是 `null`、不是键缺失、不是 `[]`（W13 §3.1 硬约束 2 原文：不得用 `null` 代替空结构）。
- 判定差别正是价值所在：`rows=0` = 心跳跑了、账本确实空 = 合法；`legacy_shadow` 键缺失 = 心跳没跑或代码漏写 = **FAIL**。两者机器可区分。
