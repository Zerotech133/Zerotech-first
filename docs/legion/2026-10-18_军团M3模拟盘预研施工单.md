## W17 模拟盘定义与边界（组织层演练协议）

- **目标**：定义军团组织层「模拟盘」的完整形态与硬边界，使 M3 成为可派工、可验收的独立里程碑；核心是把「影子建议权」与「模拟执行」之间的组织链路定死为五段链路。
- **定义（五段链路，本单总纲）**：

```
影子建议件（INTEL-SH-*，M2 T+1 环产出，只有建议权）
  → RiskGuard 预演裁决（风控部，纸面规则集 + 人工/规则初审）
  → Verdict(risk_passed=true)（风控部产出，铁律③唯一合法转化件）
  → Paperclip 工单开单（payload 引用 verdict_ref，查 [6A表] 填 est_cost）
  → 模拟环境跑完整 WO 状态机（D1 预扣 / D2 计量 / D3 结算全程记账）
  → 模拟执行报告（done 态产出，状态机轨迹 + 三扣减点流水 + 哈希链锚点）
```

- **边界（四条，逐条可机审）**：
  1. **不接真实 broker**：模拟执行件不产生任何对外网络交易请求；「执行」动作全部是本地模拟回填（W18 协议）；
  2. **不动 quant_backtest 交易域**：`quant_backtest` 策略参数、交易域数据、Phase3 订单/经纪/状态机代码零触碰；模拟盘走的是 paperclip 组织壳状态机，不是量化交易状态机；
  3. **资金面全部模拟数字**：预算科目沿用 paperclip 账面扣减（[6A表] 量级口径），不发生任何真实付款；
  4. **G3 流向闸门延续**：`INTEL-SH-*` 前缀件仍不得开单——工单 payload 不得出现 `INTEL-SH-*` 引用（含引用式载荷），只允许携带 `verdict_ref`；影子件的血统信息留在 Verdict 件（`judged_intel_refs` 字段）与审计链中，不进工单 payload。
- **RiskGuard 预演 ≠ RiskGuard 本体**：预演裁决是风控部在军团侧的**预演脚本**——规则集复用 quant_engine RiskGuard 四规则的**语义**作纸面规则集对表，但不改 quant_engine 一行（铁律③物理分离 + 本单红线 2）。预演裁决权在风控部，策略/研究侧不得自产 Verdict（[M2单] 追认口径：Verdict = 风控裁决件，decided_by=风控部）。
- **交付物**：模拟盘定义与边界稿（本 W 段落即稿）+ 五段链路各环节责任方对照表（谁产出/谁消费/权限锚点）。
- **验收**：链路五段逐段有明确责任方与权限锚点；边界四条逐条可机审表述（网络出口零 / 路径前缀零 / 账面口径 / payload 键校验各一）；与铁律②③原文无冲突。
- **依赖**：[M2单] W12~W14（影子件形态与四闸门）；[Paperclip稿] 三扣减点；quant_engine RiskGuard 四规则语义（只读对表）。
- **风险**：预演规则集与 RiskGuard 实装（M5）语义漂移——设计上把规则集独立成版本化纸面件（rule-set v1），M5 实装时以同一份规则集为基线对照，漂移可 diff。
- **规模**：0.5 天。

## W18 模拟执行件设计（payload 模拟执行协议）

- **目标**：定义模拟执行件在工单 payload 中的协议：什么算「执行完成」、模拟回填哪些字段、est_cost 怎么填——使「模拟执行」成为机器可判定的事实而非自由文本。
- **协议设计**：
  1. **执行完成定义（双条件，缺一不算 done）**：
     - 条件 A：WO 状态机**合法走完** `submitted→approved→executing→done`，全程非法流转 409 计数为 0（[app.py] 静态转移表天然保证，轨迹留审计链）；
     - 条件 B：**meter 全程计量**——executing 态内每次模拟动作（模拟撮合、模拟持仓登记、模拟平仓）都经 `/wo/{id}/meter` D2 回执补扣（[app.py] L360~380），补扣流水与模拟动作一一对应、账实相符；
  2. **payload 必填字段**：`verdict_ref`（指向合规 Verdict 的 id，risk_passed=true——G3 延续，payload 禁含 `INTEL-SH-*` 引用）、`sim_domain`（固定值 `"paper"`，标记模拟域工单）；
  3. **模拟回填字段**（done 转移时随 `reason`/结算回执落档）：`simulated_fill_price`（模拟成交价，取行情快照参考价）、`slippage_assumption`（滑点假设，静态参数，rule-set v1 内定档）、`holding_period`（模拟持仓期）——三项全部为**模拟数字**，与任何真实行情接口零耦合；
  4. **模拟预算科目隔离**：模拟域工单 account_id 用 `paper-*` 前缀科目，与既有 `default` 科目物理分账——M4 换真执行器时真实科目不会混入模拟流水；
  5. **est_cost 查表纪律**：一律查 [6A表] §3 填数（ST1 场景 25 分 / GPT 6.0 场景 300 分 / 名义场景 1 分），表外场景零预扣；
  6. **模拟执行报告**：done 态产出，含状态机全轨迹（审计 seq 锚点序列）、D1/D2/D3 三扣减点流水摘录、`/audit/verify` 校验锚点——报告是 W20 验收的对账输入。
- **交付物**：模拟执行协议稿（本 W 段落即稿）+ payload schema（字段表：必填/可选/禁止键三类）+ 1 条全流程样例工单（draft→done 全轨迹纸面推演，含三扣减点逐笔流水）。
- **验收**：样例工单满足双条件执行完成定义；payload schema 与 [app.py] `WoCreate`/`Transition` 模型无字段冲突（零改码可承载）；禁止键清单含 `INTEL-SH-*` 引用与 G2 黑名单键（`order`/`quantity`/`action`/`risk_passed`/`stance`）。
- **依赖**：W17（五段链路与边界）；[app.py]（复用不改造）；[6A表] §3（est_cost 查表）。
- **风险**：模拟回填字段未来与 M4 真实执行器字段对不上——设计上把回填字段组声明为「执行器模拟实现」的输出接口，M4 只换执行器实现、协议字段向后兼容（W21 预留详述）。
- **规模**：0.5 天。

## W19 与 M2 的编排关系（影子件→模拟盘转化器）

- **目标**：定影子建议件进入模拟盘的**唯一合法通道**——铁律③「研究/执行/风控物理分离」在 M3 的落点：影子件绝不直开单，必须经风控裁决转化；并给编排时序。
- **编排链与时序**：

```
（承 M2 T+1 环）
D+1 日 08:30  田丰心跳收编影子建议件 → 简报合流段（[M2单] W15，不动）
D+1 日 白天   影子建议件 → 人工或规则初审（预演期人工审，实装后规则初审）
            → RiskGuard 预演裁决（风控部，rule-set v1）
            → Verdict(risk_passed=true/false)（风控部产出）
            → risk_passed=true 者进入 W19 转化器 → 开模拟工单
            → risk_passed=false 者留档，不开单（拒裁件也是审计留痕件）
```

- **转化器设计点（铁律③唯一合法通道）**：
  1. **形态**：预研稿 `digital-legion/adapters/intel_to_sim_order.py` 函数签名 `intel_to_sim_order(intel: IntelItem, verdict: Verdict) -> wo_payload`——**输入两件、输出一 payload**；`verdict` 缺失或 `risk_passed != true` 即拒绝转化（拒转也要留痕）；
  2. **引用式载荷**：转化产物只携带 `verdict_ref`，影子件本体不进 payload 全量、**payload 零 `INTEL-SH-*` 引用**（G3 延续，同 W18 禁止键）；intel 血统由 Verdict 件 `judged_intel_refs` 字段承载，审计链可回溯全链（intel → verdict → WO 三件血统链）；
  3. **转化器三不**：不产 Verdict（Verdict 只能由风控部 RiskGuard 预演产出）、不改写 verdict 结论（risk_passed 原样透传）、不绕 G2 黑名单键校验（`validate_shadow_intel()` 口径沿用）；
  4. **类型级闸门沿用（G1）**：转化器模块**禁止 import `contracts.verdict` 的构造侧**——它只**读** Verdict 实例，绝不构造（构造权唯一在风控部）；静态 grep 机审与 [M2单] G1 同口径；
  5. **状态留存**：转化前后三件（IntelItem / Verdict / WO）全部落档，id 三元组写入 WO 审计事件——任何一单模拟工单都能机器回放出「哪条影子建议、经哪次裁决、走哪条状态机」。
- **交付物**：转化器设计稿（本 W 段落即稿）+ 函数签名与校验清单 + 血统链追踪表格式（intel_id ↔ verdict_id ↔ wo_id 对照，机器可解析）。
- **验收**：1 条样例（影子件 → 规则初审 → Verdict(risk_passed=true) → 转化 → payload）全链纸面推演通过；2 条负样例（无 Verdict 直转 / risk_passed=false 强转）均被拒且留痕；payload grep `INTEL-SH-` 零命中。
- **依赖**：W17（链路定责）；W18（payload schema）；[M2单] W12/W14（IntelItem 形态与 G1~G4 闸门）；[M2单] W15（T+1 时序，编排链上游）。
- **风险**：规则初审实装前的**人工审**环节是流程瓶颈且可能漏审——预演期接受人工（M3 本就是演练），但初审动作必须留痕（谁审、何时、依据哪条规则），无留痕的人工审视为未审；实装后切规则初审时人工审降级为抽检。
- **规模**：0.5 天。

## W20 模拟盘验收（预研收口，四项全绿）

- **目标**：M3 预研整体验收口径定稿；全部验收动作**只读**（对样例数据与纸面推演），不触碰影子链与运行中服务。
- **验收项（四项）**：
  1. **连跑 N 工单全程状态机无卡死**：按 W18 样例连跑 N=10 单（纸面推演或沙盘环境），每单 `submitted→approved→executing→done` 全程 409 非法流转计数 0、无非预期阻塞态；其中至少 1 单走 `executing→rejected` 分支验证 D3b 全退（[app.py] L341~343）；
  2. **审计哈希链完整**：N 单全轨迹落审计后 `/audit/verify` 重放全绿（[app.py] L97~110），每单可按审计 seq 锚点序列回放状态机轨迹；
  3. **预算对账零误差**：逐单核对 D1 预扣 + D2 meter 补扣 + D3 结算（退差额/补扣/全退）三段流水 vs budget_ledger 余额序列 = 0 差异；硬停演练按 [6A表] §3 末段名义小额定值法（例：quota 充 100 分、建单 est_cost=200 分）真实复现 approve 闸与 D1 闸 402 + 独立审计落盘各一次；
  4. **影子件直开单攻击双拦**：构造三类攻击样例——①payload 直接引用 `INTEL-SH-*` 件、②payload 无 `verdict_ref`、③`verdict_ref` 指向 `risk_passed=false` 的 Verdict——每类攻击被**两道独立闸**拦截：G3 建单闸（建单 API 校验，实装落点）+ W20 三查脚本机审（grep payload 禁止键 + verdict 合规性校验 + 血统链完整性），双拦全红、无旁路。

- **验收**：上述四项逐条留痕，收口结论回填本单；脚本本身只读（只 grep 只校验，不写任何文件）。
- **依赖**：W18（协议与样例）、W19（转化器与血统链）、[M2单] W16（G1~G4 既有闸门复用）。

- **规模**：0.5 天。

## W21 与 M4/M5 的接口预留

- **目标**：预留 M4 能力层与 M5 RiskGuard 灰度的挂接点，M3 **只留槽位不预支实现**——防止为未来需求过度设计，同时保证 M4/M5 接入时 M3 协议零破坏性变更。
- **M4 能力层挂点（执行器抽象槽位）**：
  1. W18 协议中的模拟回填字段组（`simulated_fill_price` / `slippage_assumption` / `holding_period`）即「执行器」接口的**模拟实现**输出；M4 挂真实能力（broker 对接、量化系域能力）时**协议不变、只换执行器实现**——模拟执行器换真执行器，payload 字段向后兼容，`sim_domain` 从 `"paper"` 切换为真实域标识；
  2. 模拟预算科目 `paper-*` 前缀隔离即为此预留：M4 真实执行器接真实预算科目时，模拟流水与真实流水天然不混账，对账口径各自独立；
  3. 铁律①同构性注记：执行器插槽化与「策略是插件不是框架」同构——M3 状态机是框架、执行器是插件，M4 不改框架只插插件。
- **M5 RiskGuard 灰度关系（预演 → 灰度的升级链）**：
  1. M3 的 RiskGuard 预演裁决（rule-set v1 纸面规则集 + 人工/规则初审）是 M5 的**前驱**：M5 把预演裁决升级为 RiskGuard 实装灰度——规则集从纸面对表升实码（W17 风险项已留版本化基线，可 diff）、裁决权从预演脚本升真实门禁；
  2. 灰度期间（M5 排期）模拟盘继续作为**无风险演练场**：同一规则集在预演侧与灰度侧双轨跑，裁决结果**对照记录**——两侧结论不一致即灰度异常信号，对照表是 M5 灰度验收的输入；
  3. M5 灰度完成后预演裁决退役，模拟盘的 verdict 来源切到实装 RiskGuard，五段链路其余四段零变更。
