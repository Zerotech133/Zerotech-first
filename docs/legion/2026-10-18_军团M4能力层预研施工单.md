## W22 能力供给面定义与边界（对外能力面总纲）

- **目标**：定义军团组织层「能力层」的完整形态与硬边界：什么算一个「能力件」、供给面由哪几层构成、对外（跨域/跨仓）暴露什么、不暴露什么；把 M3/M5/推送线三条边界定死为可机审条款。
- **定义（能力件四要素）**：一个能力件 = ①StrategyAgent 声明面注册项（能力目录内）+ ②执行插槽绑定（W24）+ ③调用闸组合（读域白名单直调 / 写域双闸）+ ④血统追踪义务（W25）。不满足四要素的「能力」不进目录、不可被跨域调用。
- **三层构成**：
  1. **能力目录**（声明层）：StrategyAgent 注册项清单，只描述能力与边界，不含实现（铁律①同构：目录是框架面，能力实现是插件面）；
  2. **执行插槽**（执行层）：复用 [M3单] W18 payload 协议与 WO 状态机，能力调用=一次合法工单执行（D1/D2/D3 全程计量记账）；
  3. **追踪面**（审计层）：血统链（W25）+ 审计哈希链锚点（[app.py] L97~110 复用）。
- **边界（四条，逐条可机审）**：
  1. **与 M3 边界**：M4 承接 [M3单] W21 执行器插槽接口声明（字段级），**不重造状态机、不新增 WO 状态、零改 paperclip 一行**；能力件执行就是「换执行器实现」，payload 字段向后兼容（W24 对表验证）；`paper-*` 科目隔离延续，能力域科目前缀另立（W24），模拟流水与能力流水天然不混账；
  2. **与 M5 边界**：M5 灰度对象是裁决规则集 v1→v2 双轨（[M5单] W27），M4 零涉及——M4 只向 M5 声明**事件级依赖**「能力件执行面是灰度对照的输入面之一」（[M5单] §0 已把 M4 收口列为其硬前置事件）；M4 不建对照账本、不碰规则集、不预支双轨/熔断机制；
  3. **与推送线边界**：对外客户触达（六市场推送矩阵、内容审批闸）归 [W32~W35推送单]；M4 能力供给面**不含任何客户触达通道**，两线目录互不引用；
  4. **与量化主线边界**：quant_engine/quant_backtest 能力只读对表（如 RiskGuard 四规则语义已由 [M5单] W28 对表），M4 不包装、不代理、不旁路任何量化域能力；若未来挂接，属执行主线逐件过会事件。
- **前置依赖**：[M3单] W17/W18/W21；[M5单] §0（边界对表）；[W32~W35推送单] 头部（编号与触达边界对表）。

## W25 跨域能力调用编排与血统追踪（intel→verdict→WO→能力件→回执）

- **目标**：定跨域能力调用的**唯一合法通道**与时序编排：调用链五环逐环定责，血统链全程可机器回放——铁律③「研究/执行/风控物理分离」在 M4 的落点。
- **调用链（五环，本 W 总纲）**：

```
输入件（IntelItem / ResearchReport，含影子件经 M3 转化器产出的合规件）
  → Verdict(risk_passed=true)（风控部产出，铁律③唯一合法转化件）
  → 能力调用编排（校验 verdict_ref + slot_binding + 幂等键 → 开 WO）
  → 能力执行插槽（W24 协议执行，D1/D2/D3 全程计量）
  → 能力回执（done 态产出：状态机轨迹 + 三扣减点流水 + 输出件 IntelItem/ResearchReport 落档 + 审计 seq 锚点）
```

- **编排设计点**：
  1. **编排器三不**：不产 Verdict、不改写 verdict 结论（risk_passed 原样透传）、不绕 G2 黑名单键校验——与 [M3单] W19 转化器三不同口径；
  2. **血统链四元组**：`intel_id ↔ verdict_id ↔ wo_id ↔ receipt_id` 对照落档（[M3单] W19 三元组扩展一环），机器可解析；任何一次能力调用可回放出「哪条输入、经哪次裁决、走哪张工单、产出哪份回执」；
  3. **回执契约化（禁平行契约）**：情报型回执落 IntelItem（`contracts/intel.py` L12~22 字段原样，`source="capability-<capability_id>"`、tags 必含 `capability-receipt`）、研判型回执落 ResearchReport——**不发明第三种回执契约**；回执 payload 同受 G2 黑名单键校验；
  4. **引用式载荷**：编排产物只携带 `verdict_ref` / `wo_ref`，输入件本体不进 payload 全量（[M2单] W12 引用式载荷同口径）；
  5. **跨仓只读面**：跨域调用若涉 agent_platform 侧数据，只经只读适配（task_adapter.py 口径），编排器对跨仓写路径零触碰。
- **前置依赖**：W23（registry 与 slot_binding）；W24（插槽协议）；[M3单] W19（转化器与三元组血统链）；[M2单] W12（引用式载荷）。
- **涉及路径与模块**：预研稿 `digital-legion/adapters/capability_dispatch.py`（函数签名槽位声明：`dispatch(intel, verdict, capability) -> wo_payload`，输入两件一声明、输出一 payload，实装另授权）；血统链追踪表格式落本文件。
- **交付物**：编排与血统追踪设计稿（本 W 段落即稿）+ 四元组追踪表格式 + 1 条全链纸面推演样例（输入件→裁决→开单→插槽执行→回执→血统表回填）。
- **验收判据（可机检优先）**：样例四元组可被脚本解析且回放闭环；2 条负样例（无 Verdict 直调 / risk_passed=false 强调）均被拒且留痕；回执样例 grep `INTEL-SH-` 零命中、黑名单键零命中；`capability_dispatch.py` 稿 grep `contracts.verdict` 构造侧 import 零命中（G1）。
- **回滚方式**：预研阶段 = 废弃设计稿；实装期 = 编排器停机即通道关闭（能力调用全部走编排器单一入口，无旁路设计），停机不退已开工单（按状态机正常走完或 rejected 全退）。
- **与三铁律的关系**：铁律③本 W 核心落点（编排只流转不裁决，五环责任方逐环物理分离）；铁律②（影子件不经 M3 转化器+裁决永不出现在输入侧）；铁律①（编排器是框架面固定件，能力件可插拔）。
- **风险**：血统四元组跨 WO 状态机与回执落档两处存储，存在两表失同步风险——设计上四元组以 WO 审计事件为准源（[app.py] L350~352 事件 payload 扩展槽），回执表为投影；实装期以 /audit/verify 全绿为一致性巡检锚点。
- **规模**：0.5 天。
