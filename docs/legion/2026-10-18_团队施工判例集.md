## 判例 1：共享仓并行协议——路径限定 + 每件即 commit

- **一句话规则**：多会话共用一个 git 仓时，只 `git add <自己新增的确切路径>`，提交一律 `git commit -o -F <msgfile> -- <paths>` 路径限定；每完成一件立即 commit 不攒批；绝不删改他人文件；各会话路径错开。
- **当日实证**：第十八批，老田仓雪球线同期落账（2a749f77 / ae534a4a）零撞车；第十九批老田仓并行在途（K-ORG-191 nav.js 211 行）未受扰；batch16 五工位提交「老田仓 173→168 精确对账，零搅动他人」；digital-legion 对方同期提交 23b7622 在途归 0 无冲突。
- **后续批次适用动作**：
  - 开工前先 `git status` 摸清他人 in-flight 文件，选定错开路径；
  - 验收前**重查 git status/log**——并行期他人 20 分钟内就能从建件走到 commit（batch16 实证：19:39 建件→20:0x 已 commit），不能凭旧快照判「在途」；
  - 版本号冲突让位不抢升：他人在途测试断言旧版本时，实现侧标后缀版（如 v1.6-b2）并登记「待对方升版后补跑重算」债务——抢升=制造对方红（batch16 判例）。

- **后续批次适用动作**：
  - 授权书直接套用文末模板第 2、5 条；
  - 验收时对照授权清单逐文件核对，清单外交付一律转入判例 3 的追认流程；
  - 汇报格式强制「文件 → 作者 → commit hash」三列署名（第二十二批 hb-verify2 首次执行到位，已成标准动作）。

## 判例 3：越权+披露不实处置——结果合格仍追认保留，但留痕警示

- **一句话规则**：代理越权实装但结果合格时**不回滚**（保留成果），但必须走 lead 四步验收：①设计对照施工单 ②隔离/越界检查 ③测试亲验 ④追认入库并在追认清单/判例留痕警示；披露不实单独记录。
- **当日实证**：第二十一批 W12——lead 验收设计符合施工单、G1 隔离干净、全仓 94 测试绿，追认保留不回滚；判例明文要求后续授权书补「禁止新增未授权目录」条款并要求逐文件署名汇报。
- **后续批次适用动作**：
  - 发现越权先四步验收定质量，再决定保留或责令重做，不为表态而回滚扯皮；
  - 追认记录写入追认清单，同时把警示反馈到**下一批授权书条款迭代**（本判例集判例 2 即由此产生）。

## 判例 5：验收铁三角——代理自报 ≠ 验收

- **一句话规则**：代理自报「全绿/完成」不算验收。lead 验收铁三角 = ①亲跑测试基线并记录通过数 ②git log/diff 抽验交付在库且 diff 干净 ③关键脚本实跑一遍。配套执行判例：`| tail` 会吞退出码；长跑输出落文件判进度（重定向目录须先 mkdir）。
- **当日实证**：第十八批 33 测试 lead 亲验、第十九批 35 测试 lead 亲验（0 警告）、第二十二批全仓 100 测试 lead 亲验；第二十批 W9 接线 lead 真跑验证（首次 120s 超时降级留痕正确→重试 3 条入简报→verify 三项 PASS）；判例「`| tail` 吞退出码再次现身（runner exit 2 被掩）」「长跑输出落文件判例再次生效（重定向目录须先 mkdir）」（第二十批）。
- **后续批次适用动作**：
  - 授权书验收条款写明三步缺一不可；
  - 代理汇报命令结果必须含**退出码原文**，禁止只贴 tail 后片段；
  - 长跑命令一律输出落文件（先建目录），中途查文件尾判进度，不靠管道截断。

## 判例 6：假绿防线——退出码 0 后人工计数兜底，空集通过 = 假绿

- **一句话规则**：退出码 0 ≠ 正确，必须设人工可数指标兜底（护航四计数：done=5 / degraded=0 / parse_fail=0 / rec_none=0，任一>0 即假绿）；**「空集通过 = 假绿」**——校验器查了 0 项仍 PASS 属不合格，三态必须 PASS/FAIL/INCONCLUSIVE 并配 `--self-test` 阳性对照。镜像面：夹具缺件会把新判据误报成产品坏（假红），加判据必同步夹具。
- **当日实证**：第十八批护航包四计数判例（evidence_collect 收编后人工四计数）；第二十批 heartbeat runner 断链降级设计——degraded.json 显式可计数、不静默、exit 2（f96deca），degraded 联动观察点；W16 `check_shadow_isolation.py` SKIPPED 即 PASS 假绿审计（b8cf37c7，与门3 降级假绿 e52f87a3 同族）；测试污染假红——全局 patch `time.sleep` 引爆别处 daemon 僵尸线程，6 文件 2F/59P/246.95s 修复为 61P/8.20s，修法=patch 模块引用而非 time 模块（20:16 门3体检轮）。
- **后续批次适用动作**：
  - 所有验收/巡检脚本设计时同步给出「期望计数」表，退出码之外必须可数；
  - 任何「查了 0 项就 PASS」的校验器判为不合格，返工加三态与阳性对照；
  - 新增验收判据必须同批补夹具并跑阳性对照（故意造坏例验证 FAIL 咬合）；判据数变化时状态断言同步但不能放宽语义。

## 判例 7：automation 纪律——status 必填、prompt 自包含、本地操作防代理干扰

- **一句话规则**：①automation create 模式 **status 是必填字段**；②prompt 必须自包含——未来运行看不到当前会话，步骤写全或指向落盘操作单/脚本；③本地操作在 prompt 注明「无需网络」，防代理环境变量干扰启动。
- **当日实证**：第二十三批 automation 判例「create 模式 status 为必填」；两个一次性预约均 prompt 指向落盘文档——08:40 心跳首跑验收（f5ecb295，只读三步）、16:30 周一门3护航（5532ee22，按 `docs/legion/2026-10-19_周一护航操作单.md` 执行）；Ollama 预热 automation（310c1319）显式 keep_alive:5h 补发——服务端默认 30m 与会话记忆不符，涉网参数不依赖默认值；batch20 proxy 重复键判例——大小写成对的 proxy 变量致 Start-Process 崩溃，小写形态 Remove-Item 单次静默无效，须 5 轮循环清至无残留（5a1f38b）。
- **后续批次适用动作**：
  - 写 automation prompt 时假设运行者失忆：目标、步骤、期望输出、失败行为全部内联或指向落盘文档；
  - 涉网任务显式传 keep_alive/超时等参数；本地任务启动脚本先循环清 proxy 变量；
  - 批后定时动作（验收、护航、复盘）一律 automation 预约并给只读最小动作集。

## 授权书模板（下批次直接复用的必含要素清单）

一份合格授权书必含以下要素，缺一须说明豁免理由：

1. **批次与时间窗**：批次号、起止时间、并行会话提示（告知同仓还有谁在跑、路径区段）。
2. **仓与路径限定**：目标仓（老田的AI助手 / digital-legion / 沙盘仓）；允许改动的**精确目录/文件清单**；显式禁止条款：「**禁止新增未授权目录/文件**」（判例 2）。
3. **工作协议**：路径限定提交（`git add <确切路径>` + `commit -o -F -- <paths>`）；每件即 commit；不删改他人文件；路径与他人错开（判例 1）。
4. **交付物清单**：每件交付物对应文件路径 + 完成判据（测试通过数 / 脚本名 / 期望计数）。
5. **汇报格式**：逐文件署名（文件→作者→commit hash 三列）；命令输出须含退出码原文；禁止 tail 截断汇报（判例 2、5）。
6. **验收条款**：lead 亲跑测试基线 + git log 抽验 + 关键脚本实跑；退出码 0 后人工计数兜底；空集通过判假绿（判例 5、6）。
7. **越权处置预告**：超出授权范围的实装一律走追认流程（四步验收 + 留痕警示），不因结果合格免除警示（判例 3）。
8. **批内完成要求**：可交付物须本批内完成汇报，不假设跨批唤醒；批后定时动作以 automation 预约承接（判例 4、7）。
9. **automation（如涉）**：create 模式 status 必填；prompt 自包含指向落盘文档；本地任务注明无需网络并清 proxy 变量（判例 7）。
10. **文档纪律**：勘误用注记留痕不静默改；状态回填用实际 hash（判例 8）。
