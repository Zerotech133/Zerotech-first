## 三、异常升级/降级判读口径（判读统一，禁止各自发挥）

1. **心跳 degraded ≠ 失败**：探活 3 连败/推理超时/有效条目为 0 → 写 degraded.json、退出码 2，这是**被设计捕获并如实落盘的降级**，判据 H4 记「降级被正确记录」而非 FAIL。当日不补跑（由计划任务接线方判定），次日自动恢复。只有「该降不降」（静默失败、无 degraded.json 也无产物）才判 FAIL。
2. **LastRun=1999/11/30 非故障**：LastResult=0x41303 = 任务重建后从未到点，属首跑前预期形态；以 NextRunTime 是否落在预期时刻为准（如 AgentShadowDaily 应为 2026-10-19 08:30/17:10 档）。
3. **周末 PENDING 中性**：周末任务 7/7=PENDING 属中性口径，PENDING ≠ 通过也 ≠ 失败；巡检退出码 1（全 PENDING）= 在推进，等待勿重跑。
4. **退出码矩阵**（`tools/check_observation_point.py`，操作单实核）：0=无 FAIL 且有 PASS；1=全 PENDING 中性；2=存在 FAIL 按逐项 evidence 定位。
5. **假绿四计数兜底**：门 3 已知 P1 bug（monday_checkpoint.py:371 降级判据方向反），退出码 0 不等于真绿，必须人工四计数（done/degraded/parse_fail/rec_none），任一 >0 判假绿、PASS 作废、按 P1 上报，不进评估样本。
6. **升级路径**：单机制单日异常 → 本台账登记 + 报 lead；跨日复发或主链依赖（Ollama daemon 连接拒绝、计划任务缺失/禁用）→ 报 lead 走系统处置（须老田拍板，不擅自重建/重跑）。
7. **红线**（操作单四条全程有效）：不手动跑 AgentShadowDaily；PENDING ≠ 通过；不动计划任务；真仓 data/ 只观察不试写（evidence_collect 唯一例外）。
