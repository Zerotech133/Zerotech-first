# K-STOCK-211 全面代码与数据完善实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 在不打开生产写入的前提下，修复已确认的门户回归，建立可审计的来源资格与历史数据补齐流水线，并让健康看板区分最新断面、窗口累计缺口和来源待核验状态。

**架构：** 读层继续通过 `data_integrity`、`data_health` 和 `warehouse_dashboard` 生成只读快照；写层统一由 RunStore 计划、资源锁、发布锁和回读指纹控制。所有补齐任务先产出逐键来源回执和候选分片，再由资格门决定是否允许发布。

**技术栈：** Python 3.11、SQLite、Parquet、pytest、现有 TDX/Tushare 适配器、portal HTML/JSON 看板。

**规范依据：** [2026-10-13 审计报告](../audit/2026-10-13-全面代码审计与数据质量审查_K-STOCK-211.md)、[数据缺口实施计划](2026-10-13-data-gap-completion.md)。

## 全局约束

- `production_write=false`、`global_activation=false` 保持关闭，直到每个批次取得真实来源回执、RunStore、资源锁、发布锁、发布后指纹和回读对账。
- 缺少来源资格时返回 `blocked`；禁止补零、复制邻日、把任务 `done` 当成数据 `up_to_date`。
- 每批历史补拉 20～50 个交易日，回执必须可恢复、幂等且记录请求范围、来源、返回行数和样本哈希。
- Windows 长跑输出落 `work/`；不删除生产文件；提交信息包含 `K-STOCK-211`。
