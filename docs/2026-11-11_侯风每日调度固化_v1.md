# 侯风每日调度固化 + 主选标签纠偏（2026-11-11）

## 一、背景：为什么必须改调度

侯风 11-10 之后没有新信号，根因不是策略，是**每日链路缺了"拉数"这一环**：

- `pull_daily_delta.py` 全仓唯一调用方是 `rerun_asof_when_ready.py`（手工执行器）
- `FactorDaily 18:10` 跑的 `auto_pipeline.py` 十步里没有拉数据
- `selection_20261109.json` 的 mtime = 11-10 09:07，是人早上手工跑的

更关键的是**结构性冲突**：tushare `margin_detail` 沪市 T+0、深市 T+1。
当天 18:10 跑，深市两融必然为空，`select_asof.margin_gate`（asof 日非空数 / 近 5 日均 ≥ 80%）
必然拒绝。实测：

| 时点 | asof | 两融非空 | 结果 |
|---|---|---|---|
| 2026-11-10 23:01 | 20261110 | 1,679 / 3,536 = 47.5%，全 SH | 闸门拒 |
| 2026-11-11 早上 | 20261110 | SH 2,018 / SZ 2,119 / BJ 352 | 通过 100% |

所以 select 只能放在**次日早上**，不能放盘后。

## 二、改了什么

### 2.1 新增计划任务 `houfeng_daily_signal`

| 项 | 值 |
|---|---|
| 触发 | 周一至周五 **08:40 / 09:40 / 10:40**（三点互为重试） |
| 动作 | `powershell -WindowStyle Hidden -NoProfile -ExecutionPolicy Bypass -File "C:\项目\老田的AI助手\tools\scheduled\houfeng_daily_task.ps1"` |
| 工作目录 | `C:\项目\老田的AI助手` |
| 身份 | `t` / Interactive / Limited |
| 设置 | StartWhenAvailable=开，MultipleInstances=IgnoreNew，单次上限 20 分钟 |

**为什么三个触发点**：深市两融具体几点发布没有历史日志可查，不赌单一时点。
脚本幂等，第一次成功后续自动跳过。

### 2.1b 计划任务 `houfeng_snap_daily`（15:10 快照 + 尽力结算）

| 项 | 值 |
|---|---|
| 触发 | 周一至周五 **15:10** |
| 动作 | `houfeng_snap_task.ps1 -Phases "settle,snap,health"`（默认值，可省） |
| 设置 | StartWhenAvailable=开，IgnoreNew，单次上限 30 分钟 |

**为什么是 15:10**：`snap()` 用实时行情接口取「现价/今开/昨收」，15:00 收盘后接口返回的现价
即收盘价，15:10 足够稳定，不必等 tushare 日线。目的是**尽早出一份收盘快照**，页面早一个半小时可用。

**但 15:10 结不了当日的账**（2026-11-11 判例，此前的说法「15:10 跑才能让当日到期项真正结算」是错的）：
同一时刻 `adj_factor` 取得到、`daily` 取不到。铁证在缓存文件 mtime ——
`mktcache/adjf_20261111.parquet` 15:10:05（说明确实进了结算循环）、
`daily_20261111.parquet` 15:50:21（日线此刻才拉到）。结算读的是日线，所以当日到期项只能记「待结算」。

**顺序不可颠倒**：`--settle` 先跑，`--snap` 才能让 `rolling_alpha()` 读到最新样本并落盘。
结算抛异常不阻断快照（快照本身仍有价值）。

### 2.1c 计划任务 `houfeng_settle_daily`（16:40 当日结清 + 第二个快照）

| 项 | 值 |
|---|---|
| 触发 | 周一至周五 **16:40** |
| 动作 | `houfeng_snap_task.ps1 -Phases "settle,snap" -Log C:\Temp\houfeng_settle_task.log -Tag houfeng_settle` |
| 设置 | StartWhenAvailable=开，IgnoreNew，单次上限 30 分钟 |
| 不做的 | 数据巡检（同日同批数据，15:10 那趟已检，重复无信息） |

两个作用：
1. **当日结清**：16:40 当日日线已发布（11-11 实测 15:50 就能拉到），到期项落到当天，台账 ts 不再晚一天；
2. **让价格守卫 R1 有对象**：R1 判据是「同日两轮收盘后快照互比 >1pp 即坏价」，
   一天只跑一次时这一级永远不触发，必须同日两次运行。

两趟共用一份脚本，靠 `-Phases` 选阶段；`settle` 幂等、`snap` 覆盖写 `status_latest.json`，
所以 15:10 跑完 16:40 再跑是安全的 —— 第二次顺手补齐第一次的待结算项。

### 2.2 主逻辑（`tools/scheduled/houfeng_daily_task.ps1`）

```
① token 前置检查（TUSHARE_MCP_TOKEN 无 .env 兜底，缺失 exit 5）
② asof = 主工程 data/tushare/daily 末片日期；若末片=今天则退一片
③ 陈旧守卫：asof 离今天 > 5 自然日 → exit 4（上游断了，跑了没意义）
④ 幂等守卫：当日两个 selection 都已存在 → 跳过 ⑤⑥，直接 ⑦
⑤ pull_daily_delta --asof <asof> --start <asof>（只增补，靠去重覆盖）
⑥ select_asof（先 ZKG_POOL=auto，再 main）
   任一池输出含 [FATAL] → exit 3，留给下一个触发点重试
⑦ cohort_track.py --register（幂等）
```

**不预探测两融覆盖**：刻意不复刻闸门口径，直接让 `select_asof` 自己判。
自造口径是这个项目反复踩过的坑（水位盘点误判、IC 算错都源于此）。

**不做的事**：不跑快照（开盘前快照无意义）、不广播、不改任何策略参数。

### 2.3 注册器（`tools/scheduled/install_houfeng_daily_task.ps1`）

默认只打印动作，`-Apply` 才落地；同名任务已存在时 exit 2，**不覆盖**。

### 2.4 主选标签纠偏

代码是 `k >= 2`（`select_asof.py:224` 硬编码），页面原先写"三条全中"，数字错。

| 位置 | 改前 | 改后 |
|---|---|---|
| `houfeng_template.html:188` | 主选（三条全中） | 主选（多因子共识） |
| `cohort_track.py:45` POOLS | 主选·三条全中 | 主选·多因子共识 |
| `cohort_track.py:464` batches | 三条全中（本页主选） | 多因子共识（本页主选） |
| `houfeng_template.html` 批次列表底部 | 无 | 新增门槛说明 |

门槛说明文案（仅当页面有主选批次时渲染）：

> 「主选·多因子共识」的门槛：至少 2 个因子同时看多才入选。当前主选池只有 2 个因子在跑，
> 所以实际条件是「两个都中」，而不是「三选二」。
