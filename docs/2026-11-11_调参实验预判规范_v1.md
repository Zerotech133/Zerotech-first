**立规日期**：2026-11-11
**适用范围**：`quant_backtest/` 下所有会产生新信号假设、或调整策略参数/仓位的实验
**门禁实现**：`quant_backtest/experiment_precheck.py`

## 一、为什么立这条规矩

P63 地板 / P64 提权 / P64 阈值 / P66 仓位 / P68 排除项 / P69 质量因子——六次实验，全部否决。

六个旋钮调的是同一个 β（1.184，t=10.39，R²=0.800）。这不是"六次没调对"，是**同一个假设被验证了六遍**。其中至少五次，在开跑之前就能判定上限不足：

| 实验 | 事前的可判定信号 | 事后结论 |
|---|---|---|
| P69 质量因子 | 最优多空 spread 毛值 0.259% < 双边成本 0.30% | 6 因子 IC 全 < 0.0123，分层反向 |
| P68 排除项 | 排除项 = 降敞口的笨办法，条件 IC 方向未知 | 五档全负，分档倒 U |
| P64 提权 | 提权使 wsum 变大，阈值 75 含义必然漂移 | IS 单调升、OOS 单调降 |
| P66 仓位 | 连续仓位靠减半仓，仍吃满负期望 | 输 1.8~2.4pct |

白工的代价不只是算力。**六份互不相干的报告撑不起一条知识线**——因为度量口径各不相同（当量倍数 / 总资金净值 / 多空 spread / 同笔数对齐收益 / IC），任何一次结论都不能累积到下一次。

所以规矩的核心不是"多写一份文档"，是**把顺序倒过来：先证明这层有上限，再动手跑**。

## 二、三件事怎么填

### 第一件：信息上限（`cap`）

问的是：**这层信息理论上最多能解释多少收益，且已扣掉交易成本。**

三种估计方法，按优先级排列。**首选 A，只用 A 有困难时才退到 B/C。**

#### 方法 A：完美分层毛收益法（`method: spread`，首选）

```
净上限 = 最优分位多空毛 spread − 双边成本
```

做法：

1. 取该层信号，在每个截面上按信号值分 N 档（N 默认 10，样本少时 5）
2. 算 top 档与 bottom 档在持有期内的平均收益差 = `spread_gross_pct`（**不扣成本**）
3. 减 `cost_pct`（A 股日频选股口径默认 **0.30pct**：双边佣金 + 印花 + 冲击）

**为什么这是首选**：它是直接测量，不含主观参数。而且它给的是**上限**——你已经用了完美分层的排序，实盘只可能更差。上限都小于成本，实盘不可能赚。

**一个必须说清的限定**：这**不是**"完美预知未来"的 oracle 上限。oracle（用未来收益排序）会给出任何信号都很漂亮的虚高数，不能用作判据。这里用的是"该信号自身排序"的分位收益。

若信号是二值分组（如闸门开关），`quantiles: 2`，spread = 两组平均收益差。

#### 方法 B：基本面法则（`method: fundamental_law`，辅助）

```
IR = |IC_ub| × √BR
年化超额 = IR × σ_portfolio
```

- `IC_ub` 用 **95% 置信上界**，不用点估计（点估计带乐观偏差）
- `BR`（breadth）= 每年独立决策次数。季度信号取 `期数 × 有效独立仓位数`（默认按 50 个仓位估），不要用"股票数 × 期数"，那会把 IR 算到虚高一个量级
- `σ` 用组合年化波动，A 股日频选股约 20%

**为什么只做辅助**：`BR` 的取法有主观空间，取大了就会得出"看起来有戏"的数（P69 用 BR=20000 能算出 3.5%/年，与实测 spread 为负直接矛盾）。

> **冲突处理**：A 与 B 结论矛盾时，**以 A 为准**。A 是测量，B 是带参数的估算。

#### 方法 C：可解释方差法（`method: variance`，兜底）

```
上限 = R² × 全市场收益方差
```

只在该层信号无法做分档（如连续暴露、无横截面排序）时使用。

### 第二件：放弃线（`abandon`）

问的是：**上限低于多少，我直接不跑。**

```
threshold_pct: 0.0        # 底线：覆盖不了成本就弃
threshold_pct: 0.5        # 保守：低于无风险利率一半就弃
```

`rationale` 必须写清为什么取这个数。**不许写"视情况而定"**。

### 第三件：证伪条件（`falsify`）

问的是：**如果假设成立，我应该在数据里看到什么；如果不成立，应该看到什么。**

硬要求：

- `if_true` **至少 2 条，每条必须含数值**（门禁会正则检查有没有数字）
- `if_false` **至少 1 条**——只写"成立时看到什么"是不完整的，必须同时写"失败时看到什么"
- `monotonicity_rho_min`、`t_min`、`is_oos_sign_agree` 必须给数

这一条的作用是**防止事后讲故事**。P64 那次全窗口 1.31x 很好看，但 IS 单调升、OOS 单调降——如果事前写了"IS/OOS 符号必须一致"，这个结果当场就会被判死，不用等到写台账。

### 第四件（强烈建议）：口径自证（`selfcheck`）

不是三件事之一，但没有它，前三条都可能建在错的数上。

要求指定**一个已知结果作为参照物**，新实现必须对上：

```yaml
selfcheck:
  reference: P67 已测因子 maxret20，IC = -0.0668（t = -5.42）
  tolerance_pct: 5
```

P69 首版 IC 只有参考值的 1/4，靠对 P67 已知因子反证才发现「只对 x 取秩、y 用原始收益」算成了混合 Pearson。**没有参照物的新实现，大概率带着口径错误产出"看起来有结论"的结果**——NW 协方差 t 虚高到 1070、`excess_mean` 逐笔加权 vs 按月等权差 0.5pct、P68 两版切片口径错，都是这个模式。

### 第五件：多重检验记账（`attempts`）· 2026-11-11 补

问的是：**这组假设是同族第几次尝试。**

```yaml
attempts:
  family: 参数层 - 选股规则与阈值
  total_trials: 6          # 含历史同族累计
  correction:
    applied: false
    method: none           # bonferroni / bh_fdr / deflated_sharpe
```

为什么必须记：**六张参数层单子共用同一段样本**（202509-202609），实际上是同一个假设被验证了六遍。当时是逐张独立判否，没有按 6 组打折——按单次 5% 显著计，族错误率上界 ≈ 26%（1-0.95^6）。结论方向没错（六张都是负的），但**记账方式错了**：不能把 6 次相关尝试当成 6 个独立发现。

门禁规则：

| 情形 | 结果 |
|---|---|
| `total_trials > 5` 且 `applied: false` | **警告**，并给出族错误率上界，要求结论降为「存疑」或补校正 |
| `total_trials ≤ 5` 未校正 | 不警告（组数未过阈值，不打折） |
| `applied: true` 但 `method` 不是有效方法 | **报错**（标校正却不给方法＝绕过门禁） |
| `total_trials` 未填 | 警告 |

### 第六件：成本敏感性（`cost_sensitivity`）· 2026-11-11 补

问的是：**成本从 0.20 到 0.50pct，结论会不会翻。**

```yaml
cost_sensitivity:
  mode: derived            # derived / measured / not_applicable
  grid_pct: [0.20, 0.30, 0.50]
```

三种模式：

- **`derived`（默认，推荐）**：用 `cap.inputs.spread_gross_pct` 减各档成本自动算三档净上限，**不用自报**——省掉一个可以糊弄的字段
- **`measured`**：手工填 `net_upper_pct` 三档；若自报的 `flips` 与三档数字矛盾 → **报错**
- **`not_applicable`**：成本网格不适用（如闸门那种两组对照），**必须写 `reason`**，否则等于跳过

判定口径：三档中有的一档越过放弃线、有的没越过 → 判「翻转」，并给出最早击穿的档位，结论标为**脆弱**（只在更低成本假设下成立）。

> 为什么盯 0.50 档：0.30 是简化值，真实冲击成本随规模变化。若结论在 0.50 档（成本上浮 67%）就崩，它只是一条边缘，不能写成"已验证"。

## 三、门禁怎么用

```bash
cd quant_backtest

# 1. 开实验前生成预判单
python experiment_precheck.py init P70 \
    --layer "事件驱动-龙虎榜资金跟随" \
    --hypothesis "龙虎榜净买入前10%的票,次日起5个交易日可获超额"

# 2. 填完校验（0=可做 1=不完整 2=劝退）
python experiment_precheck.py verify P70

# 3. 看全部预判单状态
python experiment_precheck.py list
```

在调参脚本里当硬门禁用：

```python
from experiment_precheck import require_pass
require_pass("P70")   # 没预判单或未通过，直接 raise，实验跑不起来
```

退出码约定：

| 码 | 含义 | 该怎么办 |
|---|---|---|
| 0 | 通过 | 可以开跑 |
| 1 | 不完整 | 补全三块必填 |
| 2 | **预判劝退** | 上限 ≤ 放弃线，**这个实验不该开始** |

`--strict` 会把"selfcheck 未填""成本敏感性未做""多重检验未校正"也算不通过。

### verify 的固定尾部：reality-check 格式复核记录

每次 `verify` 末尾固定输出一段四行复核 + 一段汇总，写法与人工核对台账时一致，可直接贴进复盘正文或台账：

```
── 质量门复核（reality-check 格式）──
ITEM: P69_backfill · 公开季度财务 - 质量因子… · A股存在可交易的质量溢价…
VERDICT: 不成立
EVIDENCE: 净上限 -0.041% vs 放弃线 +0.000%；成本敏感性 0.20档+0.059 0.30档-0.041 0.50档-0.241；
          同族第 6 组、未校正（族错误率上界 26%）；自证基准 P67 maxret20 IC=-0.0668（容差 5%）；
          样本门槛 每期≥30 只 / ≥12 个截面
NOTE: 净上限未过放弃线，属信息上限不足而非填单不完整 → 实验不应开始

复核范围：  meta / cap / abandon / falsify / selfcheck + attempts + cost_sensitivity
成立：0 条 · 不成立：1 条 · 存疑：0 条
自动不放行触发项：净上限 <= 放弃线
最终判定：  不放行
```

判定映射与 reality-check 一致：

| 预判结果 | VERDICT | 最终判定 |
|---|---|---|
| `pass` 且无建议项 | 成立 | 可交付 |
| `pass` 但有建议项 | 成立 | **有条件交付**（需跟进项随行） |
| `abandon` | 不成立 | 不放行 |
| `incomplete` | 存疑 | 不放行 |

`--json` 下同一份记录放在 `gate` 键里，供脚本读取。

## 四、已做的验证

用两份历史数据回填，确认门禁不是纸老虎：

| 预判单 | 净上限 | 放弃线 | 判定 | 同族记账 | 成本三档 | 与真实历史是否一致 |
|---|---|---|---|---|---|---|
| `P69_backfill`（质量因子） | −0.041% | 0.0% | **劝退（rc=2）** | 第 6 组未校正 → 族错误率上界 26% | 0.20→+0.059 / 0.30→−0.041 / 0.50→−0.241，**0.30 档即翻负** | 一致：P69 实跑后否决 |
| `GATE_backfill`（环境闸门） | +0.371% | 0.0% | 通过（rc=0） | 第 1 组，未超阈值 | 标 `not_applicable`（两组对照，无单笔成本） | 一致：闸门是唯一反复证实的正贡献 |

**这个对照本身就是结论**：六张参数层的单子都过不了，唯一能过的是「何时不交易」。alpha 在时点，不在选股。

**新增两列读出来的东西**：

- P69 的毛 spread 0.259 只够覆盖 0.20 档成本，0.30 基准档下就是负的——这条早就该在跑之前看出来，不必等 6 因子 IC 测完
- 闸门的 +0.371 不能拿成本档去压：它不是可交易组合的 spread，硬算会得出"0.50 档翻负"的假警报。**这也是为什么 `not_applicable` 必须允许存在，且必须写理由**

## 五、什么情况下不用填

不产生新信号假设的改动，免填：

- 数据口径修复、补数、换源（如本次 tdx → 同花顺板块平移）
- 纯工程改动（性能、日志、监控、告警）
- 已有结论的复现验证（但仍需 `selfcheck`）

**判定标准**：改动会不会改变"买什么 / 买多少 / 何时不买"的决策输出。会，就必须填。

## 六、违规怎么办

- 没有预判单就跑的实验：**结果不采信，不进台账**（台账只记录通过预判的结论）
- 预判单与实验脚本的关系：预判单必须先于实验脚本提交，git 历史即审计线索。同一次 commit 提交两者，视为无效

## 七、已知边界（这条规矩管不到什么）

1. **它管不了"没想到"**。预判只能挡住"想清楚了但上限不够"的实验，挡不住"根本没想到还有这条路"。P63~P69 六次都困在参数层，真正的缺口是没人问"参数层之外是什么"。
2. **上限法依赖信号定义的正确性**。信号本身写错（比如 P69 首版 IC 只取单边秩），上限算得再规范也是错的。所以 `selfcheck` 不是可选项。
3. **成本假设 0.30pct 是简化值**。真实冲击成本随规模变化，大资金口径要另行标定。
4. **它不解决度量不统一**。六次实验六种度量的问题，需要另行建立统一的收益口径（建议：一律用「组合层总资金口径的年化超额 + 最大回撤」，逐笔均值只作辅助）。
5. **`attempts` / `cost_sensitivity` 是记账，不是信息**。它们不产生新 alpha，只让结论的可信度可被追溯：同族第几组、成本档是否撑得住。记账做得好，也只是让"否决"这个结论更硬一点。
