# 00 · 总体愿景与设计原则

## 1. 系统目标

zhice-OS V2 是一个**个人/小团队使用的多市场量化交易操作系统**，覆盖：

- 多市场行情接入与实时展示
- 策略研究、回测、注册、审批、版本管理
- 候选池 → 交易计划 → 风控 → 执行 → 持仓 → 复盘 → 学习
- 模拟盘与未来实盘双轨
- 统一账户、资产、跨市场绩效视图
- 系统运行、运维、审计、自动化

## 2. 与 V1 的关系

| 项目 | V1 | V2 |
|---|---|---|
| 定位 | 验证闭环 | 可扩展的工程化底座 |
| 架构 | 模块 + 工作流函数 | 领域内核 + 端口适配器 + 事件驱动 |
| 多市场 | 已有雏形 | 一等公民 |
| 策略 | 内置策略 + 外部研究引擎 StrategySpec | 统一 StrategySpec |
| 执行 | simulated_broker | BrokerPort，模拟/实盘可插拔 |
| 实时 | REST 轮询 | REST + WebSocket/SSE |
| 前端 | 页面集合 | feature 化模块 |

## 3. 设计原则

### 3.1 保留功能，重切边界

V1 已经有的功能全部保留：

- CN 闭环
- 多市场数据
- 外部研究引擎融合
- 策略注册/审批
- 模拟成交/复盘/学习
- 前端工作台

V2 不删功能，而是把边界切得更清晰。

### 3.2 领域驱动

业务规则放在 `domain/`，不依赖 FastAPI/SQLAlchemy。

### 3.3 市场是配置，不是分支

不要到处写 `if market == "CN"`。

所有市场差异通过 `MarketProfile` / `MarketContext` 注入。

### 3.4 策略是数据，不是代码

策略以 `StrategySpec` 描述，执行器以插件形式注册。

### 3.5 可观测性优先

每个用例都有 trace、日志、事件留痕。

### 3.6 渐进演进

V2 可以独立起步，也可以逐步从 V1 迁移。

## 4. 成功标准

- 同一套核心代码可驱动 CN/US/HK/CRYPTO
- 新增市场不需要复制代码
- 新增策略不需要改主流程
- 模拟盘与实盘只差一个 BrokerAdapter
- 复盘、学习、报告不再散落在主流程中
- 实时行情页面具备分时、多周期K线切换
