# GenAI 可观测字段映射 v1（ADR-005 P1）

- **状态**：P1 映射表（只读/文档）；P2 代码开关默认关（`DSH_OTEL_ENABLED=1` 才生效）
- **依据**：`ADR-005`（原文链接 `adr/ADR-005-agent-observability-otel-genai.md` 已失效）、[OTel GenAI semantic conventions](https://opentelemetry.io/docs/specs/semconv/gen-ai/)
- **实现**：`agent_platform/observability/genai.py`（`llm_span` / `wrap_llm`）；`engine/llm.py::make_llm` 单点包装
- **兼容**：既有 `agent_platform/observability/trace.py`（SQLite spans）字段本已"兼容 OTel GenAI semconv"，本映射是**对齐口径**，不迁移存量数据。

## 一、Span 命名与层级

| 层级 | span name | 说明 |
|---|---|---|
| LLM 调用 | `chat <model>` | 由 `make_llm` 包装的每次 `chat()` 产生 |
| 工具调用（后续） | `execute_tool <tool_name>` | MCP/本地工具边界，P2 再接 |
| Agent 运行（后续） | `invoke_agent <seat>` | 席位/链路级，能挂父子关系时再接 |

## 二、属性映射（现有字段 → gen_ai.*）

| 现有字段/来源 | OTel GenAI 属性 | 备注 |
|---|---|---|
| provider 前缀（ollama/glm/openai/deepseek…） | `gen_ai.system` | 如 `ollama`、`deepseek` |
| binding 模型名 / `model` | `gen_ai.request.model` | 如 `qwen3.5:9b` |
| 操作类型（chat/embedding） | `gen_ai.operation.name` | 当前只发 `chat` |
| 响应实际模型（后续） | `gen_ai.response.model` | 由 provider 返回时补 |
| token 用量（perf_ledger） | `gen_ai.usage.input_tokens` / `gen_ai.usage.output_tokens` | P2 接 |
| 工具名（MCP/本地） | `gen_ai.tool.name` | P2 接 |
| 错误类型（LLMError） | `error.type` + span status=ERROR | P2 接 |
| 既有 trace_links / perf_ledger / checkpoints | 保留原字段 | 不做破坏性替换 |

## 三、开关与上线阶段

| 阶段 | 动作 | 验收 | 风险 |
|---|---|---|---|
| P1（本单） | 映射表 + `genai.py` 适配层 + 单测；默认关 | `python -m pytest agent_platform/tests/test_genai_otel.py -q` 通过；默认 no-op | 无 |
| P2 | 关键链路开 `DSH_OTEL_ENABLED=1`（单进程试验），接 token 用量/错误 | span 可导出（console exporter）、主链路延迟无显著变化 | 需 opentelemetry 依赖 + 可能少量性能开销 |
| P3 | 接后端（Phoenix/Langfuse/Datadog 任一），做面板/告警 | 面板可查；与 M4 账本对账一致 | 需 L2（新服务/端口） |

## 四、约束

- 默认关，任何异常都不得反噬 LLM 主链路（`llm_span` 吞异常）；
- 不在 span 里写 prompt 原文/凭据（只写模型、工具名、用量、错误类型）；
- 采样率由 opentelemetry SDK 配置，不在本层硬编码；
- 新增属性必须先更新本映射表（文档与代码同一批提交）。
