# Agent 运行契约 P2 设计稿（run_id 透传 / fallback 聚合 / tool span）

- **状态**：设计稿（待评审；**不写运行时代码**，实现另行拆单）
- **日期**：2026-10-27｜**归属**：O6 P2；上级 [ADR-014](../adr/ADR-014-agent-run-contract.md)
- **前置审计**：`deliverables/2026-10-27_trace_status口径审计_v1.md`（253 failed=attempt 级，不是任务级）

## 一、目标

1. 一次**逻辑任务/对话回合** = 一个 `run_id`，跨 fallback/重试保持同一 run；
2. fallback 的每次尝试作为**同一 run 的 attempt event**，不再各开独立 trace；
3. 工具调用补 `tool.call`/`tool.result` span（同 run_id）；
4. 存量 trace 数据不破坏（schema 只增列，旧行 `run_id=NULL`）；
5. P1 派生视图升级为任务级统计（成功=存在一次成功 attempt）。

**非目标**：不引消息队列/新数据库；不重写 trace/dev_events；不改 status 语义（`ok`/`error` 仍是 attempt 级）。

## 二、run_id 定义与生成点

- 格式：`run_<ULID>`（26 字符，时间有序；stdlib 实现或 uuid4 hex 均可，建议 ULID 以便排序）；
- **唯一生成点**（避免多层重复生成）：
  1. `agent_platform/engine` 的任务入口（无统一入口时新增 `run_scope` 包装层）；
  2. `agent_platform/legion_command/serve.py` 的 HTTP 请求 handler 入口（每个请求一个 run；MCP 端点同）；
  3. 飞书 bot 的命令入口（P2 可选，复用 legion_command 的 run_id）。
- 其余层从 **contextvar** 读取，不自行生成；缺失时回退：生成独立 run_id（记录 `run.meta.fallback_generated=true`），保证不崩。

## 三、透传机制（contextvars）

```python

def new_run_id() -> str: ...
def current_run_id() -> str | None: ...
@contextmanager
def run_scope(run_id: str | None = None):
    token = _RUN_ID.set(run_id or new_run_id())
    try:
        yield _RUN_ID.get()
    finally:
        _RUN_ID.reset(token)
```

- 异步/线程场景：contextvars 在线程池中不自动传播 → 若 engine 使用线程池，`run_scope` 内提交任务时显式 `copy_context().run(...)`（P2b 实现注意）。
- 进程边界（spawn 子进程）：通过环境变量 `AIOS_RUN_ID` 传给子进程，子进程 `run_scope(os.environ["AIOS_RUN_ID"])`。

## 四、trace schema 增量迁移

```sql
-- 幂等：PRAGMA table_info(spans) 无 run_id 才执行
ALTER TABLE spans ADD COLUMN run_id TEXT;
CREATE INDEX IF NOT EXISTS idx_spans_run_id ON spans(run_id);
```

- 旧行 `run_id=NULL`：读取端按 `COALESCE(run_id, 'trace_'||trace_id)` 回退分组；
- 不新建 `runs` 表（P2 先派生；若需 run 级元数据再 P3 加表）；
- `record()/span()` 的 INSERT 改为命名列（避免 `VALUES(?,...)` 与 ALTER 列顺序耦合）。

## 五、fallback 聚合

- 现状（审计结论）：一轮治理请求按 flash→v4-pro→ollama 尝试，每次尝试各写一条 trace（1 span/trace），失败率虚高；
- P2：
  - 入口生成 `run_id`；每个尝试 `record(name="llm.attempt", kind="llm", run_id=run_id, attrs={attempt:n, model, status, error})`；
  - 保留 `trace_id` 每尝试一个（用于与现有 span 兼容），但 **run_id 相同**；
  - `Run` 派生：按 `run_id` 分组；`status` 聚合规则：任一 attempt ok → `succeeded`；全 error → `failed`；
  - `Event` 派生：每个 attempt 一条 `llm.request`/`error` 事件（seq 顺序）。
- 兼容：旧数据无 run_id → 按 trace_id 派生（attempt 级），在 summary 标记 `level="attempt"`；新数据标记 `level="task"`。

## 六、tool span

- 在工具调用包装处（engine/tool runtime、legion_command tool handler）加：
  `with tr.span("tool.<name>", kind="tool", attrs={"tool.name": name, "tool.args_digest": sha8(...)}) as sp:`；
- 成功/失败由 context manager 自动记 `ok`/`error`；
- 大参数不入库（只存摘要/长度）；敏感字段不写（复用 O7 脱敏思想）。

## 七、开关与回滚

- 开关：`AIOS_RUN_ID=off` 关闭 run 上下文（默认 on；关闭后行为与现状一致）；
- 迁移只增列/索引，无数据删除；回滚=代码 revert + 忽略新列；
- trace 写入失败始终 fail-open（不影响主链路）；日志记录 `trace_write_failed`。

## 八、实施拆单（P2a-P2d）

| 单 | 内容 | 验收 |
|---|---|---|
| **P2a** | `trace.py`：schema 迁移 + run_id API + 单测 | 旧 DB 可平滑升级；contextvar 传递正确；旧行可读 |
| **P2b** | `engine` 任务入口接 run_scope + attempt 记录 | 一次任务=1 run；fallback 3 次=同 run 3 attempts |
| **P2c** | `legion_command` 请求/MCP 入口接 run_scope + tool span | 请求级 1 run；tool span 出现 |
| **P2d** | P1 view 升级：按 run_id 聚合任务级统计 + e2e 验证 | 任务成功率/时延/成本可读；e2e 通过 |

## 九、测试计划

- 单测：`run_scope` 嵌套/缺失回退/线程池 copy_context；schema 幂等；fallback 聚合状态；旧数据 NULL 分组；
- e2e：一次真实治理请求 → `run` 1 条 + `attempt` ≥1 + 全 error 时 run=failed；
- 回归：现有 `tools/run_contract_view.py` 对旧 DB 仍产出 370 runs（attempt 级）；
- 性能：INSERT 增列 <5ms/span（现状已 SQLite WAL）。

## 十、风险与待确认

1. 线程池传播（engine 若有）需逐点确认；
2. bot 入口是否纳入 P2（建议先 engine+legion_command，bot 复用）；
3. 默认开关建议 on；如担心风险可先 `AIOS_RUN_ID=off` 灰度一周；
4. run 级元数据（输入/输出摘要）是否 P2 落盘还是仅派生（建议 P2 只派生，P3 再落 runs 表）。
