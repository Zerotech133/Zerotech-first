## 二、按 MCP 最佳实践逐条对照

| 风险类 | 我们的状态 | 动作 |
|---|---|---|
| **confused deputy**（代理被第三方授权混淆） | 本仓库无 MCP OAuth 代理；tushare-http 为直连外部 API + 静态 token | 保持"无动态注册/无代理"；如未来接 OAuth 代理，先审 client_id/consent |
| **token passthrough** | ✅ 不向第三方转发客户端 token；token 只从 env 读取 | 禁止把 `TUSHARE_MCP_TOKEN` 传给其他 server/请求体 |
| **SSRF** | http server 仅有 tushare 固定 URL；stdio 本地脚本限定 root | 新增 http server 时校验 URL 白名单/协议；stdio 代理路径限制 |
| **session hijack** | 本机单用户、stdio 为主；8796 不对外网 | 不暴露 MCP 端口到公网；事件/日志不写 token |
| **local server compromise** | 本地 stdio 脚本（`tools/mcp_ro_*`）只读、白名单 root | 新工具默认 read-only、路径白名单、不读凭据 |
| **scope minimization** | 🟡 tushare `allow_tools="*"` | 收窄为只读工具白名单（如日线/基本面查询），写类工具永不开放；需改 `servers.json` + 重启 8796（L2） |

## 三、结论与后续

- **通过**：token 仅 env、无 URL 泄露、全部 read-only、无明文；
- **待办 1**：tushare `allow_tools` 白名单化（建议先列实际在用工具；改配置需重启 8796，L2 五要素）；
- **待办 2**：X5 token 轮换（外部重置 + 本地 vault/env + 8796 重启），是当前最高优先安全项；
- **待办 3**：把 `tools/mcp_security_check.py` 加入夜跑/门禁（D2 的 `night_test_baseline` 或 `test_gate` 可选步骤）。
