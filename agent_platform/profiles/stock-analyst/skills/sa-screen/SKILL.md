# 条件选股（sa-screen）

## 何时用

- 用户给出**筛选条件**（估值/成长/质量/行情/行业/ST/数量/排序），想要一份候选清单；
- 用户想先看"系统把条件理解成什么"（可解释预览），再决定是否真的筛选；
- 用户从复盘结论出发想找同类股票（例如"轻工制造、PS 历史分位低于 50%、营收同比转正"）。

## 怎么做（先预览、后筛选、不自动批量）

1. **解析预览** → `sa_screen(text="<用户原话>")`：
   - 返回 `spec`（universe / filters / rank_by / limit）、`notes`（命中的解析规则）、`unmatched`（未识别片段）；
   - 这是**只读预览**，不会筛选、不会提交分析任务。
2. **与用户确认**：用一句中文复述 `notes` 里的条件；`unmatched` 非空时必须回问补齐，**不要自行假设**。
3. **确认后筛选** → `sa_screen(dsl=<上一步确认后的 spec>)`：
   - 返回 `candidates`（代码/名称/行业/metrics/reasons/risk_tags）、`matched`、`warnings`、`as_of`、`disclaimer`；
   - 引擎未就绪（H2a 未合并）会返回 503「选股引擎未就绪」，如实告知，不要手工拼 DSL 硬凑。
4. **按需分析**：只对用户点名的候选调用 `sa_batch(codes=[...])`；**禁止**对整份候选自动批量分析（避免误触发批量任务）。
5. **输出**：候选表（代码/名称/行业/命中理由/风险标签）+ `as_of` + `warnings`（数据缺字段/股票池为空等）+ 固定声明。

## 注意

- 解析失败/空文本返回 400；字段非法/算子非法返回 400（error/errors 里有具体字段名）；
- 字段白名单可由服务端 `GET /api/analysis/internal/screen/fields` 查询，但工具面优先用 `sa_screen` 的预览结果；
- 筛选引擎口径：数据按 `as_of` 截止（财务按公告日 ann_date，PIT）；不要用外部印象补全 `warnings` 里缺失的字段；
- **不构成投资建议**，不给买卖/收益预测；固定声明："筛选结果仅供研究，不构成投资建议；历史数据不代表未来。"
