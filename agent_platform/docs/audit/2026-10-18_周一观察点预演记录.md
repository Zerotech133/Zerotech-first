## 一、预演路径选择：降级合成路径

**选了降级合成路径，理由**：

1. `run_shadow.py` 真跑依赖 `OllamaLLM` + 实时行情全链路（`make_context`/`quote_snapshot`/`kline_daily`，见 `run_shadow.py:378-384`），单票实测 4~38 分钟（monday_checkpoint.py:40-44 实测分布），5 篮子 28~69 分钟；周日预演行情源与 LLM 状态不可控，且预演目标是验证「strategy 装配→落账→replay→观察项」链路而非辩论主链质量。
2. 合成路径精确复刻 `run_shadow.py` done 分支的 strategy 域调用序列（`run_shadow.py:405-430`）：`build_default_registry()` → `codex_bridge.load_registered(reg)` → `registry.run(sid, sctx)` → `record_verdicts(vs, root=隔离根, trade_date, run_id)`——四步与周一现场同一代码路径。
3. `SHADOW_DATA_ROOT` 是现成的隔离阀（`run_shadow.py:52-64`），`record_verdicts` 的 root 显式必填（`strategy_registry.py:177-182` 无 root 拒绝落盘安全阀）——隔离语义有双重防线。

## 四、发现的问题

1. **【非阻塞·判读须知】`strategy_runs.jsonl` 判决行无 `schema_version` 字段，观察项「m5.v1 行数」恒报 0。** `record_verdicts`（`strategy_registry.py:214-220`）落账行不含 `schema_version` 键；`m5.v1` 是 shadow_ledger 行的标记。周一现场看到 `[observe] strategy_runs：N 行 / m5.v1 0 行` 属**预期形态**，不要误判为首跑行契约缺失。若希望观察项对 strategy 账本有意义，后续可让判决行也带 schema_version 或调整观察项文案（需另行拍板，本预演未改动任何代码）。
2. **【非阻塞·口径须知】monday_checkpoint 无 root/隔离语义。** main() 硬编码真仓路径，且运行即 append 真仓 `data/shadow/monday_checkpoint.log`（设计内 outbox 行为，非污染）。预演因此走编程调用而非 main()。周一现场 main() 正常运行即可，两观察项读真仓路径。
3. **【非阻塞】`strategy_replay` join 依赖 shadow_ledger 已有 m5.v1 行**：周一 17:10 首跑先落 shadow_ledger，17:25 replay 视图 join 才有命中；17:25 前若只看 strategy_runs 单侧，hit_rate 显示 n/a 属正常时序。
