## 二、本轮修复（4 项，全部复现→修→回归）

### 1.【真 bug】personal_wiring.delete_schedule 幂等重放失效
- **现象**：CLI 默认路径（不传 store）首次删除成功后，重试同一次删除误报
  「schedule 不存在（无凭据，不伪造）」——违反其 docstring 承诺的
  「崩溃后重试安全」。根因：行 138 `store.list(...) if store else []`
  在 store=None 时跳过探查。
- **修复**：探查前自建 ApprovalStore（finally 关闭）。既有 12 用例全传
  store 因此漏网；新增 test_delete_replay_without_store_cli_path。

### 2.【高】replay_query._load_approvals 静默建库
- **现象**：经 ApprovalStore 打开（mkdir+建表+列迁移写路径）且无 exists
  预检——approvals.db 一旦缺失，任何一次 /api/unified/replay 都会在
  只读查询路径凭空建空库。14:45 判例（approvals_registry 已绕开）同源漏网。
- **修复**：exists 预检 + `file:...?mode=ro` 直连 + 手写 SELECT。
  `_load_idem_rows` 同款改 mode=ro。真实仓读数 30 条与账本一致。

### 3.【高】EvidenceStore 写路径被只读端点复用
- **现象**：/api/unified/evidence 每次 GET 经 EvidenceStore.__init__ 执行
  mkdir + WAL PRAGMA + CREATE TABLE + commit（写事务）。
- **修复**：新增 `read_only=True` 构造参数（mode=ro、跳过 DDL/WAL、
  库缺失抛 FileNotFoundError 不建库），默认 False 写方语义不变。
  注：WAL 库只读连接会重建 -shm/-wal 空附属文件（SQLite 固有行为，
  数据零写入）。api_unified 调用侧改造待并行会话静止（见三-3）。

### 4.【低】sys.path 无限增长
- api_approvals.py / api_replay.py 的 ImportError 兜底每请求
  `sys.path.insert(0, ...)`——加 `not in sys.path` 判重。

新增测试：tests/test_readonly_surface_fixes.py（4 用例）+ personal 1 用例。
