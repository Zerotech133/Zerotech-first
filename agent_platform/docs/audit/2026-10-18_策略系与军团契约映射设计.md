## 1. 字段映射表

三态定义：**直接映射**=语义与形态基本同形可直取；**需适配器**=有对应物但需变换/组合/派生；**缺口待补**=一侧无对应物，需 QT-M0 拍板。

### 1.1 影子账本行（m5.v1）↔ contracts.IntelItem（影子研判建议=情报条目）

| 影子账本行字段 | IntelItem（语义稿） | 三态 | 说明 |
|---|---|---|---|
| date + ts | observed_at | 需适配器 | epoch float → ISO8601，两字段合一 |
| symbol / name | content（payload 原样） | 直接映射 | 结构化载荷原样保留 |
| symbol + name | title（"600519 贵州茅台"） | 需适配器 | 组合派生 |
| run_id | source_ref（"shadow_ledger:<run_id>"） | 需适配器 | 加前缀格式化，对齐 evidence_collect 派生法 |
| recommendation / confidence / score / target_range / price_at_decision | content | 直接映射 | 决策载荷原样入 content |
| parse_ok / degraded / status | tags | 需适配器 | 质量标记转标签（如 "degraded"、"parse_ok=false"） |
| latency_s / dk_*（enrich_row 扩展） | content extras | 直接映射 | 观测字段原样保留 |
| schema_version | （无对应） | 缺口待补 | 建议 content.schema_version 保留，防 v0/m5.v1 两代行混淆 |
| （无源 ID） | item_id | 需适配器 | 无源 ID 不伪造判例：派生 sha256("shadow_ledger:<run_id>\|<symbol>")[:16]，同输入恒同 ID=幂等 |
| （无摘要字段） | summary | 缺口待补 | **D1 rationale 未落影子账本**（build_ledger_row 不含 rationale 字段）——情报条目缺结论摘要，建议补账本字段或从 run_id 回查辩论 trace |

小计：直接 3 / 需适配器 5 / 缺口 2。

### 1.2 控辩审 verdict ↔ contracts.Verdict

现链「verdict」有两个物理形态：① 控辩审 D1（evaluator）输出的决策 JSON（recommendation/confidence/target_price_range，parse_decision 提取，落影子行）；② 策略件 engine Verdict（strategy_registry）。两者映射到契约 Verdict 的不同侧面：

| 现链结构 | contracts.Verdict（语义稿） | 三态 | 说明 |
|---|---|---|---|
| T1 role=bull / T2 role=bear | stance | 直接映射 | strategy_registry.STANCES=("bull","bear","neutral") 已显式对齐控辩审（strategy_registry.py:43） |
| D1 role=evaluator | Verdict 的产出者语义 | 直接映射 | 汇总结论件由独立评审判者产出，角色形态一致 |
| D1 输出 recommendation（大写，影子口径） | action/建议档 | 需适配器 | 大小写归一（STRONG_BUY→strong_buy）；**影子有 WATCH 第 6 档，契约五档枚举接不住** → 越档部分见缺口② |
| D1 输出 confidence | confidence | 直接映射 | [0,1] 同形 |
| D1 输出 rationale | rationale | 需适配器 | 有对应物但**未落账**（build_ledger_row 丢 rationale），需从 D1 输出取或补落账字段 |
| score = REC_SCORE[档]×confidence（K-ORG-129） | （无对应字段） | 缺口待补 | 连续化评分是评估链关键量（J2 Spearman），契约 Verdict 语义稿无 score 位 |
| target_price_range | （无对应字段） | 缺口待补 | 建议契约补 extras/payload 或扩展协议 |
| verdict_key(strategy_id,symbol,trade_date) | idempotency_key | 需适配器 | 值可直接赋用（sha1[:16]，三方对账已锚定此键），需显式桥接声明 |
| run_id / trace_id | evidence_ids / report_ids | 需适配器 | 回查锚点转引用列表 |
| parse_ok=false / degraded 行 | Verdict 有效性门槛 | 缺口待补 | 坏样本要不要出 Verdict 件（建议：不出，只出 IntelItem 带 degraded 标签） |
| **risk_passed** | risk_passed | **缺口待补（最关键）** | **现链零产出方**：RiskGuard 在引擎侧无代码件（仅 org.json 提及），影子行只有 parse_ok/degraded 质量标记。谁在哪个环节填 True 必须周二拍板（见 §3 铁律③核对） |

小计：直接 3 / 需适配器 4 / 缺口 4。

### 1.4 命名撞车警告（开工前必读）

AP 已有 `agent_platform/contracts/__init__.py`（M0 统一对象模型），其中 **IntelItem / ResearchReport / Verdict 与 digital-legion contracts v1 四协议同名**，且含义不同：

| 名 | AP contracts M0 | 军团 contracts v1（语义稿） |
|---|---|---|
| Verdict | 汇总结论件（subject/action/rationale/confidence/evidence_ids/decision_id，action 默认 neutral） | 影子/策略立场产出件（stance/risk_passed） |
| IntelItem | 情报输入（title/summary/source/content/tags） | 情报条目（影子研判建议） |
| ResearchReport | 研究报告（evidence:List[Evidence]/fact_hash） | 策略岗位报告件 |

三套 Verdict 并存：AP contracts.Verdict（汇总件）/ engine strategy_registry.Verdict（策略件）/ legion contracts v1.Verdict。**适配器必须显式命名空间隔离**（`from legion_contracts import Verdict as LegionVerdict`），且 QT-M0 须拍板：情报部数据流的权威 schema 归 legion contracts v1，AP contracts M0 的同名对象是否退役/更名/收敛为同一 schema。不拍板则 import 混淆与双口径漂移几乎必然发生。

## 2. 适配器设计（签名级，不实现）

- 落位：`agent_platform/engine/legion_adapter.py`（引擎侧，组织层**禁止** import 引擎任何件——依赖单向：`legion_adapter → engine 只读` + `legion_adapter → legion_contracts(schema)`）。

## 3. 三铁律核对

| 铁律 | 映射方案核对 | 结论 |
|---|---|---|
| ① 组织与引擎分离：新代码只允许出现在 contracts 和 Paperclip 壳，组织层不 import 引擎 | 适配器放引擎侧、组织层只消费 contracts 形态产物，依赖严格单向（legion→不 import engine；adapter→contracts schema）。**张力点**：engine/legion_adapter.py 严格字面上是"引擎目录里的新代码"——辩护：它是纯投影零状态函数，性质等同 contracts 的引擎侧边界壳，非业务逻辑；且判例在先（adapters/evidence_collect.py 即引擎侧投影件）。是否追认为"contracts 边界壳豁免"列入开放点① | **不违反**（1 处字面张力待追认） |
| ② 策略是插件：不建第二套策略运行时 | 适配器零执行语义：不 register、不 propose、不建运行时；超时包裹（strategy_runtime 隔离门）与注册表原样复用；契约的 StrategyAgent 注册语义直接以 list_manifests 投影表达 | **不违反** |
| ③ 影子无执行权：执行组只认 risk_passed 件，保持物理分离 | **risk_passed 在现链由谁产出：没有人。** 引擎侧无 RiskGuard 代码件（全仓 grep 仅 org.json 提及），影子行只有 parse_ok/degraded 质量标记，GateDecision 抽象（True/False/None）存在但无投研链挂接。映射方案的处理：适配器产出的 Verdict 件 risk_passed **恒 None**，本层无写 True 通道；置 True 的唯一路径=验收链（RiskGuard，军团 M3 接影子流水线时落码），执行组侧校验 idempotency_key+risk_passed=True 才可动。物理分离成立的前提是**验收链代码独立于策略/影子/适配器三个模块**——现状满足（三者均无验收逻辑），未来落码时须保持 | **不违反**（risk_passed 产出环节缺位为最大缺口，见开放点②） |

## 4. 开放点清单（周二 QT-M0 开工会追认）

1. **适配器落位追认**：engine/legion_adapter.py 作为"contracts 引擎侧边界壳"是否豁免铁律①的"新代码只允许 contracts+Paperclip"字面限制（两案：a. 追认豁免；b. 落 digital-legion/contracts 侧、以引擎只读 schema 对表）。
2. **risk_passed 产出环节定义**（最关键）：验收链（RiskGuard）落码里程碑、产出形态（建议 GateDecision.decision 的 True/False/None 三值）、写入权隔离的机器校验方式（建议：适配器与验收链分仓/分目录 + verify 工具比对 risk_passed=True 件的验收签名）。
3. **三套 Verdict 收敛**：AP contracts M0 Verdict / engine strategy_registry.Verdict / legion contracts v1 Verdict 的权威源与命名空间策略（情报部数据流权威 schema 归 legion，AP 侧同名对象退役/更名/映射别名，三选一）。
4. **影子六档 WATCH 与契约五档冲突**：WATCH（L4 存疑观察）在契约侧的归宿——a. 契约扩六档；b. WATCH 只出 IntelItem 不出 Verdict（推荐，弱负证据不构成建议档）；c. 映射为 hold+低置信。同时 target_price_range / score（K-ORG-129 连续化）在契约 Verdict 无字段位的补法（extras/协议扩展）。
5. **ResearchReport 现链无对应物的补法**：建议以 run_id 为聚合锚（一次影子 run 的多策略 verdict + D1 决策 → 一份 ResearchReport，report_id 从 run_id 派生，evidence=verdict 投影），与 evidence_collect 的 source_ref 派生法同构；QP 线策略报告未来同构复用。
6. **failed / parse_ok=false 行的情报语义**：不产 IntelItem（推荐）还是产带 degraded 标签的条目；D1 rationale 未落影子账本是否补账本字段（涉及 m5.v2 schema，动账本需另立工单，非本设计范围）。
7. **契约 timeout / idempotency / 授权的字段级口径**：现引擎口径（runtime 统一 10s+fail-open；幂等在账本层 verdict_key；RunAuthorization 授权快照）与语义稿表达的差异，以 JJ 路落盘版为准对表，差异开工前清零（不留适配债，对应研发计划 P1 合流件）。
8. **lifecycle 是否入契约**：引擎四态门（experimental/active/deprecated/retired + 回放显式放行）比语义稿表述更严，建议契约全文采纳引擎口径。
