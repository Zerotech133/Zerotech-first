## ① 提交方式

### 1.1 提交物形态：单文件源码，无独立 md 工单档

以码为准（`adapters/codex_bridge.py:479-482`）：提交物是**一份策略源码文本 + 一个 submit_id**，由受理侧调用 `process_submission(bridge_dir, submit_id, source, registry, ...)` 传入。bridge 自己在 `bridge_inbox/inbox/<submit_id>/` 落件并命名为 `strategy_<submit_id>.py`——**源码文件名由 submit_id 决定，不是 strategy_id**。

- **没有强制提交 md 档**：试点成功件 `processed/20261018_sma20_rsi14/` 下只有 `strategy_20261018_sma20_rsi14.py` 一个文件；
- 「工单说明」由**文件头 docstring 承担**（见 1.3）；
- **拒档 md 是 bridge 自动生成的**（被拒后才有，见 ④），不是作者提交的。

### 1.2 submit_id 命名

实现层对 submit_id 无格式硬校验，但按日归档、限频计数、processed/rejects 目录名都以 submit_id 为目录名，沿用试点惯例：`<YYYYMMDD>_<策略短名>`（如 `20261018_sma20_rsi14`）。submit_id 必须唯一——同一 submit_id 重复提交会与 `bridge_inbox/inbox/<submit_id>/` 目录名冲突。

### 1.3 源码文件结构（受理成功的最低配置）

```python
# -*- coding: utf-8 -*-
"""<策略逻辑一句话> + <阈值来源>            ← 文件头 docstring，供审计留痕
   （试点件见 strategy_20261018_sma20_rsi14.py:2-15）"""
from statistics import fmean                ← 只准 import 白名单模块（门 3）
from strategy_registry import StrategyAgent, Verdict

<模块级常量 / 纯函数辅助>                     ← 可选，无状态

class <任意类名>(StrategyAgent):             ← 恰好一个 StrategyAgent 子类（门 5）
    strategy_id = "codex_<名字>"            ← 类属性，codex_ 前缀字符串字面量
    stance = "neutral"                      ← 类属性，bull/bear/neutral 字面量

    def propose(self, context):
        ...
        return Verdict(strategy_id=self.strategy_id, symbol=symbol,
                       recommendation=..., confidence=..., stance=...,
                       score=..., rationale=...)
```

注意：静态门只检查 `strategy_id` / `stance` 是**类属性字面量**（`adapters/codex_bridge.py:180-188`），运行时由 `propose` 返回的 Verdict 再次校验（见 ③）。

## ② 六道静态门逐条清单

静态校验入口 `validate_source`（`adapters/codex_bridge.py:107-194`），**全部命中项一次性返回**（一条提交会同时收到所有拒绝原因）。以下行号均指 `adapters/codex_bridge.py`（commit aba47e39 时点）。

### 门 1：行数 / 字节上限（:67-68, 114-119）

- **规则原文**：`MAX_LINES = 300`、`MAX_BYTES = 16 * 1024`。行数按 `text.count("\n") + 1` 计（:114），字节按 UTF-8 编码长度计（:115）。
- **通过写法**：源码 ≤ 300 行且 ≤ 16384 UTF-8 字节。
- **常见死法**：超限提示为「行数 N 超上限 300」「字节 N 超上限 16384」。注意中文注释吃字节快——300 行未必 16KB，但长 docstring + 中文 rationale 模板容易顶到字节上限。

### 门 2：语法可解析（:121-125）

- **规则原文**：`ast.parse(text_src)` 失败即拒。
- **通过写法**：合法 Python 源码。
- **常见死法**：「语法错误：xxx（line N）」——Codex 生成代码常见于括号不配对、缩进混用。

### 门 3：import 白名单（:50-54, 128-140）

- **规则原文**（:50-54）：
  ```python
  IMPORT_ALLOWLIST = frozenset({
      "math", "statistics", "collections", "itertools", "functools",
      "typing", "dataclasses",
      "strategy_registry",  # 宿主契约模块（StrategyAgent/Verdict）
  })
  ```
  `ast.Import` 与 `ast.ImportFrom` 都查（:129-140），按**顶层模块名**核对（`name.split(".")[0]`，:132/:137）。白名单外一律拒——白名单制而非黑名单制（模块头拍板注释 :4、:49）。
- **通过写法**：只 import 上述 8 个模块（含子模块，如 `from collections import deque`、`from statistics import fmean` 均按顶层 `statistics`/`collections` 放行）。
- **常见死法**：`import os`、`import json`、`import re`、`import pandas`、`import numpy`、`import datetime`——**json / re / datetime 都不在白名单内**，纯计算场景请用白名单内模块替代或内置类型直算。
- **双保险**：即使静态门漏过，exec 沙箱与子进程试跑里还有受限 `__import__`（:86-94、子进程 runner :249-255）再次拦截同一份白名单。

### 门 4：危险字面调用（:57-61, 141-150）

- **规则原文**（:57-61）：
  ```python
  DENY_CALLS = frozenset({
      "eval", "exec", "compile", "__import__", "open",
      "globals", "locals", "vars", "getattr", "setattr", "delattr",
      "system", "popen", "write_text", "write_bytes",  # attribute 尾名
  })
  ```
  扫所有 `ast.Call` 节点：函数是 `Name` 且名字命中即拒（:145-146）；函数是 `Attribute` 且**属性尾名**命中即拒（:147-150）。
- **通过写法**：零反射、零 IO、零动态执行——纯计算。
- **常见死法**：
  - `open(...)` 读配置 → 拒；
  - `Path(...).write_text(...)` → 属性尾名 `write_text` 命中，拒；
  - `os.system(...)` → 尾名 `system` 命中，拒；
  - `getattr(obj, "method")` → 拒（哪怕不是攻击，一律拒）；
  - `{k: globals()[k] ...}` → 拒。
  报错格式：「禁用调用 eval()（line N）」/「禁用方法 .write_text()（line N）」。

### 门 5：接口签名（:151-188）

对**模块顶层**（`tree.body`）做 AST 核对：

1. **恰好一个** `StrategyAgent` 子类（:152-158）：0 个或 ≥2 个都拒，报「文件必须恰好定义一个 StrategyAgent 子类，实得 N」；
2. **禁 `__init__`**（:176-177）：「禁止定义 __init__（插件须无状态，§2.2）」——插件必须无状态，配置一律用类属性 / 模块常量；
3. **必须有 `propose`**（:178-179）：缺则报「缺少 propose(self, context) 实现」；
4. **`strategy_id` 必须是 `codex_` 前缀的字符串字面量类属性**（:180-184）：
   - 通过：`strategy_id = "codex_sma20_rsi14"`；
   - 死法：`strategy_id = "sma_rsi14"`（无前缀）、`strategy_id = "codex_" + name`（非常量，AST 判非 `ast.Constant`）、写在 `__init__` 里（类体 Assign 才被识别，且 `__init__` 本身禁定义）；
5. **`stance` 必须是 `bull` / `bear` / `neutral` 字面量类属性**（:185-188）：死法：`stance = STANCE_BULL`（变量引用）、`stance = "bullish"`（非法档位）。

判别依据（:161-175）：类体里的 `ast.FunctionDef`/`AsyncFunctionDef` 记为方法；`strategy_id`/`stance` 只认类体的直接赋值（`Assign` 单目标 `Name`，或带值 `AnnAssign`）。

### 门 6：凭据形态正则（:64-65, 190-193）

- **规则原文**（:64-65）：
  ```python
  CRED_PATTERN = re.compile(
      r"(?i)(api[_-]?key|secret|token|password|credential)\s*=")
  ```
  对**全文**（含 docstring、注释）做一次 `search`（:190-193），命中即拒：「命中凭据形态 'xxx'（R2：Codex 零凭据）」。
- **通过写法**：源码里不出现上述词后跟 `=` 的组合。
- **常见死法**：**注释也会中招**——`# api_key = 从环境读取`、docstring 里写 `password = 必填` 都会被拒。写文档示例请用 `api_key 值` 这类不带 `=` 的表述，或换词（如「鉴权串」）。

## ③ 沙箱试跑须知（M3，静态门之后、注册之前）

静态过关后，`process_submission` 调 `sandbox_trial(source, timeout_s=10.0)`（`adapters/codex_bridge.py:330-391`）在**一次性子进程**内试跑 `propose`（:491-496，拒绝 stage=沙箱试跑）。

### 3.1 能用什么

- **受限 builtins 白名单**（子进程 runner :258-262，与宿主 `_SAFE_BUILTINS` :71-83 同表）：`abs all any bool dict divmod enumerate filter float int len list max min range reversed round set sorted str sum tuple zip` + 异常类 `ValueError TypeError KeyError IndexError ZeroDivisionError ArithmeticError Exception` + `__build_class__`（class 语句依赖）。
  - **没有的**：`print`、`isinstance`、`hasattr`、`super`、`open`、`id`、`type`、`format`、f-string 之外的字符串格式化都行但注意 `print` 不可用；
  - `isinstance` 不可用意味着**不能在插件内自查类型**——直接假定契约成立或用 try/except 上述白名单异常兜底；
- **受限 `__import__`**（:252-255）：仍只放行 ②门 3 同一份白名单；
- **契约模块**：`from strategy_registry import StrategyAgent, Verdict`（runner :243 宿主注入，PYTHONPATH 指向 `engine/`，:344-347）。

### 3.2 试跑 context 与必须产出的结果

- **合成试跑数据固定**（:225-228）：
  ```python
  SANDBOX_TRIAL_CONTEXT = {
      "symbol": "TRIAL/USDT",
      "closes": [100.0 - 0.5 * i for i in range(40)],   # 40 点匀速缓跌
  }
  ```
  即 40 根收盘价的缓跌序列。插件必须在这份数据上正常出结果——样本门槛设计要 ≤40 才能走到非降级分支（试点件门槛 21）。
- **propose 必须返回 `Verdict` 实例**（runner :287-292）：返回 None/dict/tuple 即拒：「propose 返回 'dict'，非 Verdict」；
- **必须过 `Verdict.validate()`**（runner :293）+ 宿主侧出口再验（:311-327），字段口径见 `engine/strategy_registry.py:23-24, 39-47`：
  - `strategy_id`：`codex_` 前缀（宿主再验 :314-315）；
  - `symbol`：非空（:316-317）——从 `context.get("symbol", "")` 取，试跑时是 `TRIAL/USDT`；
  - `recommendation`：五档枚举 `strong_buy / buy / hold / sell / strong_sell`（:318-319）；
  - `confidence`：数值且 ∈ [0, 1]（:320-324）；
  - `stance`：三档 `bull / bear / neutral`（:325-326）；
- **样本不足降级 hold**：closes 不足时返回合法 hold Verdict 而非抛异常（试点件 :51-55 范式）。

### 3.3 超时口径（Windows）

- 默认墙钟 **10 秒**（`sandbox_timeout_s=10.0`，:330/:455）；超时进程被 `kill()` 击杀（:356-363），报「试跑超时 10s 被击杀（墙钟口径，Windows 无 rlimit，语义覆盖 CPU 上限）」；
- **含义**：死循环 = 必被击杀拒收；propose 内做重计算（大循环、递归展开）务必在 10 秒内完成；
- **不要在 propose 里 `print`**：即使 builtins 里没有 print（调用会 NameError），试跑协议也只认 `__BRIDGE_RESULT__` 标记行（:268-271），任何多余 stdout 都无影响但报错会走 stderr 尾部展示（:368-373）；
- **崩溃必留痕**：runner 对一切 `BaseException` 转 fail-visible 标记行（:304-307），错误串截 300 字符；
- 试跑耗时随注册事件入账（`registrations.jsonl.sandbox_ms`，:505）。

## ④ 限频与归档说明

### 4.1 每日限频（实现比设计稿新增）

- `process_submission(..., daily_limit=None)`（:453-455）：显式传入 `daily_limit` 时启用；`None` = 不限频（向后兼容，:466-467）。上限数值由受理侧调用方决定，作者侧无法绕过；
- **计数口径**（`_daily_usage`，:426-450）：**当日 registrations + rejects 合计**——
  - `bridge_inbox/rejects/<YYYYMMDD>/` 下的 `.md` 档数（一提交一档）；
  - `data/codex_bridge/registrations.jsonl` 中 `registered_at` 以当日 `%Y-%m-%d` 开头的行数；
  - 两者都用**本地日期**（`_today()` :396-398）；
- 达上限即拒（:469-477）：stage=限频，「当日受理已达上限 N（registrations+rejects 合计已用 M，本地日期 D），限频拒绝受理」。**限频拒绝时 inbox 不落件**（检查在任何落盘之前）。

### 4.2 被拒后去哪看原因

- **拒档自动生成**（`write_reject`，:401-416）：`bridge_inbox/rejects/<YYYYMMDD>/<submit_id>.md`，内容含 `阶段`（限频 / 静态校验 / 沙箱试跑）、时间、逐条编号的 `命中规则`；
- **静态门 / 沙箱门被拒时**，inbox 落件目录整体移入 `rejects/<YYYYMMDD>/<submit_id>/`（:487-488, :494-495）——拒档目录里能直接看到你的源码原件；限频拒绝则 inbox 不动、只有 md 档；
- **只读浏览工具 `tools/list_rejects.py`**：
  ```bash
  python tools/list_rejects.py --rejects-root bridge_inbox/rejects   # 按日摘要表
  python tools/list_rejects.py --rejects-root bridge_inbox/rejects --show <submit_id>
  python tools/list_rejects.py --rejects-root bridge_inbox/rejects --stats
  ```
  注意：工具默认根已对齐 bridge 实际落点 `bridge_inbox/rejects`（lead 修正 d42a4483，早期版本误指 data/codex_bridge/rejects 需带参覆盖——该警告已失效，现直接跑即可）。
- **通过不发通知**：受理成功的证据是 `processed/<submit_id>/` 目录 + `data/codex_bridge/registrations.jsonl` 新行（含 `submit_id / strategy_id / registered_at / sandbox_ms`，:501-507）。
- **修订重提**：改完代码用**新 submit_id** 重新提交（inbox 不覆盖）。

## ⑥ 红线（逐条平移自设计稿 §1，bridge 模块头 :7-8 复述）

| # | 红线 | 对作者意味着 |
|---|---|---|
| R1 | **单向通道**：bridge 只进不出 | 插件不得有把 AP 内部状态/账本/凭据外传的逻辑；实际上白名单 + 禁调用已使外传在技术上不可写 |
| R2 | **Codex 零凭据** | 源码不得出现任何凭据形态（门 6 正则）；Codex 运行环境本身也不持有凭据 |
| R3 | **零执行权** | 策略只产建议（Verdict）；`execution_allowed` 恒 False；不得新增执行路径 |
| R4 | **只读 propose** | `propose(context)` 只读不写，不碰任何域账本（落账只能走 AP 侧 `record_verdicts` 正门） |
| R5 | **注册权在 AP 侧** | Codex 只交代码；注册由 bridge 校验器完成，Codex 永远拿不到 Registry 句柄；同 `strategy_id` 重复注册 = 漂移拒绝（`register_from_source` :197-218 复用 StrategyRegistry 语义），改版必须换新 ID（如 `codex_trend_v2`） |

**作者侧自查口诀**：只做计算、无 IO 无网络无凭据、不碰执行路径。技术上：只 import 八件白名单、不用任何 DENY_CALLS 名字、全文不出现凭据词 `=`、`propose` 纯函数式返回 Verdict、样本不足降级 hold。
