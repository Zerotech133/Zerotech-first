## 二、每工具小节

### 1. check_trigger_chain.py（agent_platform/tools/，落地 commit d30e91d4）

- **参数**：`--repo-root`（必填，agent_platform 根）；`--print-config`（可选，只打印任务名/日志路径/Ollama 等配置常量后退出，退出码 0，不做检查）。
- **检查项**：a 任务注册面（直读 `C:\Windows\System32\Tasks\` 下三任务 XML，校验触发时间 17:10/17:25/17:35、周一触发、命令锚点、Enabled）；b 上次运行结果（last_run.log 收尾行 done≥1 / monday_checkpoint.log 末行 EXIT=0 / chief_last_run.log 含 SEND_OK；日志缺失=UNKNOWN 中性）；c daemon 存活（Ollama 127.0.0.1:11434 socket 决定性 + watch-daemon 留痕信息性不翻转状态）；d 幂等根（data/ 存在且可读，只读不 mkdir）。
- **输出示例**（摘自源码 print 语句）：`[PASS] a_task_registration —— AgentShadowDaily 17:10 周一~五 锚点齐`；`汇总: PASS 4 / UNKNOWN 0 / FAIL 0`；`结论: 无 FAIL 且有 PASS——链路就绪，可放行（退出码 0）`
- **依赖**：系统任务 XML 直读（不走 Get-ScheduledTask，沙箱更稳）；Ollama 端口探测（run_shadow 的 LLM 硬依赖）。

### 2. check_observation_point.py（agent_platform/tools/）

- **参数**：`--data-root`（必填，=agent_platform/data，显式 root 纪律）。无其他参数。
- **五项判据**：a last_run.log 含 `[strategy]` 成功标记；b strategy_runs.jsonl 带 run_id 行数 ≥1；c monday_checkpoint.log 含两个 `[observe]` 段标记；d shadow_ledger.jsonl 含 m5.v1 行；e verdict_key 三方对账（复用 verify_strategy_ledger.verify()）。
- **输出示例**：`汇总: PASS 2 / PENDING 3 / FAIL 0`；`结论: 无 FAIL 且有 PASS——可放行（退出码 0）`
- **依赖**：**同目录 verify_strategy_ledger（判据 e 直接复用其 verify()，幂等键算法同源纪律）**——两件须同在 tools/ 下。

### 3. verify_strategy_ledger.py（agent_platform/tools/）

- **参数**：`--data-root`（必填；无 root 拒绝运行）。
- **三项对账**：① verdict_key 重算一致（防手编辑/字段漂移）；② run_id 双向可查（判决行 run_id 命中影子 m5.v1 索引；反向孤儿 run_id 只提示不 FAIL——bars 缺失 fail-open 合法）；③ 证据 idempotency_key 集合覆盖全部 verdict_key。
- **输出示例**：`[PASS] ①verdict_key 重算一致`；`结论: 全部 PASS`。空账本打印 `[中性] ... 退出码 0`。
- **依赖**：`engine.strategy_registry.verdict_key`（唯一复用的生产实现，import 只读）。

### 4. gate3_verdict.py（⚠ 位于上级仓 `老田的AI助手/tools/`，不在 agent_platform/tools/）

- **参数**（全可选）：`--base`（默认真仓 agent_platform）；`--date YYYY-MM-DD`（默认今天）；`--trace-links`；`--log`（巡检日志路径）；`--no-cross-check`（隔离环境）；`--skip-tasks`（异地环境跳过计划任务查询）。
- **判据结构**：核心项动态（首跑未发生 7 项 / 已发生 11 项，与巡检 SUMMARY 同口径）+ 增补项单列（坏行检查等，不参与交叉核对）。
- **输出示例**：`[PASS] 影子首跑已发生（最新交易日 > 2026-10-14）  — 最新=2026-10-19`；`复核结论: 11/11 全过`；`退出码 0`
- **依赖**：唯一复用 `adapters.trace_link.replay_trace`（锚点链解析）；其余判据为独立重写（不 import monday_checkpoint——第二意见纪律）。

### 5. list_rejects.py（agent_platform/tools/）

- **参数**（全可选）：`--rejects-root <dir>`（缺省自动定位 bridge_inbox/rejects，与 bridge 实际拒档落点一致〔d42a4483 修正，原误指 data/codex_bridge/rejects〕，兼容旧版扁平布局）；`--show SUBMIT_ID`（打印完整 md 档）；`--stats`（按 stage 汇总计数）。**--show 与 --stats 互斥**（同给退出码 2）。
- **输出示例**：`日期        submit_id          stage      拒绝原因首行（截 60 字符）`；`[汇总] 共 3 条拒档记录。`
- **依赖**：无（纯文件系统只读浏览）。

### 6. scan_secrets.py（agent_platform/tools/）

- **参数**（全可选）：`--paths <文件/目录...>`（缺省=--git-status 模式：git status untracked+modified 清单，须在 git 仓内，否则退出码 2）；`--strict`（命中即退出码 1，供 pre-commit）。>1MB、二进制文件自动跳过并报告。
- **输出示例**：`a.py:12 | SK_KEY | sk-a1***XY`（片段自动脱敏，前 4 后 2）；`[汇总] 扫描 42 个文件，命中 0 处；跳过 1 个（二进制/超 1MB/不可读）。`
- **依赖**：git CLI（--git-status 模式）；无其他。

### 7. run_strategy_shadow.py（agent_platform/tools/，⚠ 在途件）

- **参数**：`--manifest`（必填，策略清单 JSON）；`--config`（必填，策略配置 JSON）；`--root`（必填，**显式隔离根**）；`--context-json`（必填，内联 JSON 上下文）；`--evidence-path`（可选，JSONL 证据落盘路径）。
- **输出形态**：stdout 一行 JSON（验证结果 dataclass 序列化）；失败时 stderr 一行 `ERROR: <原因>`。
- **依赖**：`engine/shadow_strategy_runner.py`（同仓在途件，同样归属未定）。
- **只读性说明**：验证本身不执行交易；但 `--evidence-path` 有写面（落证据文件），现场使用必须 `--root` 指向隔离目录（SOP 红线 4：演示永不落真仓）。

## 四、交叉核对结果（文档间不一致，以工具源码为准）

1. **gate3_verdict 退出码 2 名存实返（已修复，2026-10-18 U 路对齐）**：原 docstring 写「2=无法判定（数据缺失）」但 `main()` 只有 `return 1`（有 FAIL）与 `return 0`（全过）两条路径。裁决：**改 docstring 对齐代码**——全仓无任何调用方依赖退出码 2（healthcheck_all 的 TOOL_SPECS 不含 gate3_verdict，无 subprocess 聚合面）；且工具设计上数据缺失/查询异常一律判 FAIL（第二意见不中性放行），「无法判定」层与实现哲学相悖。现 docstring 已明示「有效语义仅 0/1，无退出码 2」，测试已锁死该口径。
2. **check_observation_point / check_trigger_chain / verify_strategy_ledger / list_rejects / scan_secrets** 五件的退出码描述在 SOP 手册、军团M4M5规划稿、凭据泄漏扫描报告与各自源码 docstring 间**口径一致**，无冲突。
3. **run_strategy_shadow 退出码为文档空白**：SOP 手册与其他审计文档均无记载（在途件未入文档），本卡退出码口径直接取自源码，待归属定后补文档。
4. **同类检查两种实现法并存（差异提示，非矛盾）**：check_trigger_chain 用任务 XML 直读（判例：沙箱常拦 Get-ScheduledTask），gate3_verdict 用 PowerShell Get-ScheduledTaskInfo 查询任务状态。两者都只读，方法不同是刻意的判例取舍，现场不必强行统一。
