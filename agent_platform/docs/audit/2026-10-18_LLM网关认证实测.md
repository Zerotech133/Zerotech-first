### 2.2 主机层与路径层证据

| 探测 | 结果 |

**判定：`192.168.5.155` 与本机不在同一可达网段，网关主机当前不可达（网络层）。** 这与"key 是否有效"是两个独立问题。

### 2.3 HTTP 层（只读 GET `/v1/models`）

全部为 **GET**，无写请求。

| # | 代理 | 携带 key | 结果 | 耗时 |
|---|---|---|---|---|
| 1 | 禁用（`ProxyHandler({})`） | 否 | `URLError/TimeoutError` | 5023 ms |
| 2 | **走系统代理**（`127.0.0.1:62512`） | 否 | **HTTP 403** | **2 ms** |
| 3 | 禁用 | 是（env key） | `URLError/TimeoutError` | 5009 ms |
| 4 | **走系统代理** | 是（env key） | **HTTP 403** | **15 ms** |
| 5 | 禁用（复测） | 是（注册表 key，PowerShell 直发） | `WebException`（超时） | 5156 ms |

**代理影响对照（关键）**：

- 走代理：**2—15 ms 就返回 403**。这不是网关的 403，是本地代理 `127.0.0.1:62512` 自己拒绝转发该内网目标（它拒绝后立即回包）。
- 禁代理：稳定 5.0s 超时触顶。
- 结论：**"2s 失真"在本机复现为"毫秒级假快"**——带代理的任何耗时数字都不能作为连通性证据，且代理会把"网络不通"伪装成"HTTP 403 认证失败"，**极易误判为 key 无效**。`llm_client.py` L28-29 的 `ProxyHandler({})` 是必要且正确的，本次所有有效结论均取自禁代理路径。

## 四、结论

1. **网关当前不可达（网络层）**。`192.168.5.155` 不在本机 `192.168.0.0/24` 网段，且无到 `192.168.5.0/24` 的在链路路由，流量沿默认路由被送往 `192.168.0.1 → 172.21.x` 上游后丢失；8 个候选端口全部 3s 超时、ping 100% 丢包，与 key 无关。
2. **本次未能完成"哪把 key 对网关有效"的裁决**——因为触发条件（拿到网关的 200 或 401）根本未发生。
3. **"两把 key"在现状下实际只有一把可测**：env / 注册表 / 唯一 `.bak_with_key` 三处**完全一致**，均为 `sk-ms1****`/len=24；扫描报告所称旧 `sk-s` key 在可读范围内**不存在**。
4. **代理会制造假 403（2ms）**，若不做禁代理对照，极易把网络问题错判成 key 失效——本次已用禁代理路径取证。
