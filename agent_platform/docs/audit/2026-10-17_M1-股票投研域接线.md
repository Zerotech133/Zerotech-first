## 一、领域语义定稿

| 分工 | 载体 | 读写权 |
| --- | --- | --- |
| 执行底账（不动） | `agent_platform/data/checkpoints.db`（runs/checkpoints/traces） | 接线层**只读**（sqlite `mode=ro` URI） |
| 审批态真源（补齐） | `agent_platform/data/invest/runs_index.json` | 接线层唯一写路径 |
| 审批凭据账本 | `agent_platform/data/approvals/approvals.db` | engine/approvals（M0 既有） |

- 投研域此前**只有执行态没有审批态承载物**（run_invest 跑完 decision 躺在 checkpoints 里，采纳与否无凭据）——runs_index.json 是**补齐真源**而非第二账本：checkpoints 记执行，runs_index 记采纳，职责分离。
- 状态机：`drafted`（研究完成已登记）→ `reviewed`（复核通过）→ `adopted`（采纳，用户级承诺）；`reviewed` 可打回 `drafted`；`adopted` 终态冻结。
- `register_run` 只接受 checkpoints.db 中 `status=done` 且存在 `d1_decision` 决策快照的 run（无源/未完成/无决策/决策空一律显式拒绝——无源 ID 不伪造）。
- **决策指纹**（投研域特有）：登记时对 D1 决策全文 sha256；审计时重算比对——登记后 run 被重跑覆盖（checkpoints 是 INSERT OR REPLACE）或决策被篡改会显式暴露「指纹漂移」。这是对 checkpoint 覆盖写特性的一致性兜底。

## 二、接线六铁律（与 GZH/Academy 同款）+ 一项新判例

1. 状态真源不动（执行底账只读；审批态真源唯一）
2. 单一写路径（状态变更只能经 `approve_transition`，先落 Approval 凭据）
3. 禁止跳级（drafted→adopted 拒绝：研究/复核/采纳分离）
4. 终态冻结（adopted 后零转移）
5. 幂等（键 `invest:<run_id>:<from>→<to>`，重放零副作用）
6. 审计回放比对（reviewed/adopted 必须有凭据，越门显式列出）
7. **★新判例：轮次化幂等键**——打回后重批（`reviewed→drafted→reviewed`）是**新的一轮批准**，必须留新凭据（`#r2` 后缀），不得重放第一轮凭据。原因：同 (from,to) 二次批准的幂等键与首轮相同，会被 store.record 误判为重放，第二轮 decided_by/reason 丢失。实现：落凭据前数账本中同 (target,from,to) 凭据数 n，n>0 则键加 `#r{n+1}`；catch-up（凭据落库真源滞后的崩溃窗口）改由「最新凭据恰为本次转移」显式判定，不再依赖 record 的重放标志。

> ⚠ 遗留：GZH/Academy 存在同一缺口（打回后重批走 catch-up 误放，第二轮不留痕）。
> 本轮按并行撞车协议未回灌其文件（前轮交付、其测试全过），列为待统一项，
> 建议下一轮把 invest 的轮次化逻辑回灌 gzh_wiring/academy_wiring 并补测试。

## 五、CLI 用法（用户动作）

```
python domains/invest_wiring.py list    --root ..
python domains/invest_wiring.py report  --root ..
python domains/invest_wiring.py register <run_id> --root ..        # 执行完成后登记
python domains/invest_wiring.py approve <run_id> reviewed  --by 老田 --reason "复核通过" --root ..
python domains/invest_wiring.py approve <run_id> adopted   --by 老田 --reason "采纳" --root ..
python domains/invest_wiring.py approve <run_id> drafted   --by 老田 --reason "打回" --root ..
```

后续可选：`run_invest.py` 执行完成后自动 `register_run`（本轮保持执行入口零侵入，待用户拍板）。
