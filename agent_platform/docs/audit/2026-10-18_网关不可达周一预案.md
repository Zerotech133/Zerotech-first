## 五、网关恢复后的对表操作单

前提：老田确认网关 192.168.5.155 接入方式（同段/VPN/base_url 未变）。

### 步骤 1：连通性探测（无副作用）
```
ping -n 2 -w 3000 192.168.5.155
python -c "import socket; [print(p, (lambda s: (s.settimeout(3), s.connect(('192.168.5.155', p)), 'OPEN'))(socket.socket(socket.AF_INET, socket.SOCK_STREAM))) for p in (8081,)]"
```
任一 OPEN 即继续；全 FAIL 则停在网关侧排障，不动 key。

### 步骤 2：注册表在位 key 实测（最小请求，不落响应体）
用当前注册表值（sk-ms1***9b2c）发一次最小认证请求，只记 HTTP 状态码：
```
python -X utf8 -c "import os,winreg,json,urllib.request; k=winreg.QueryValueEx(winreg.OpenKey(winreg.HKEY_CURRENT_USER,'Environment'),'LLM_API_KEY')[0]; r=urllib.request.Request('http://192.168.5.155:8081/v1/models',headers={'Authorization':'Bearer '+k}); op=urllib.request.build_opener(urllib.request.ProxyHandler({}));
try:
    resp=op.open(r,timeout=10); print('HTTP',resp.status)
except Exception as e:
    print('HTTP', getattr(e,'code','ERR'), type(e).__name__)"
```
判读：`HTTP 200` → sk-m 有效，**注册表现状即正确，结案**（跳到步骤 4）；`HTTP 401/403` → 走步骤 3。

### 步骤 3：sk-s 侧处置（仅当 sk-m 401/403 且老田从网关侧拿到有效 key）
sk-s 已无本地副本——**不存在"切回 sk-s"这个选项**，只能由老田在网关机/管理面确认有效 key 明文，然后：
