## 一、为什么做（盘面核出的大事）

做 S33 编制工具时核对一致性，发现组织真源 `org.json` 里 **`agents`（名单）与 `agent_profiles`（档案）严重脱节**：

| 指标 | 实测 |
|---|---|
| 席位名单（agents） | **63** |
| 有档案（agent_profiles） | **29** |
| **有名无档** | **34（54%）** |
| 主官 17 个 | 档案齐备 **8**，异常 **9** |
| 整部门零档案 | **7 个**（🅰回测／🅱数据／🅲下版本设计／运行体／研究院／情报／通信客服） |

**这直接解释了老田最初的问题为什么答不出来**：沙盘此前只按 `agent_profiles` 出人，
于是情报部显示「0 员」——而它名单里明明有 5 人（XQ1／TDX1／BEACON1／INTEL0／MANCHONG1）。
**缺口被界面藏起来了，比缺口存在更糟。**

另外发现两处更硬的断点：
- `ops_runtime` 主官 = **A0A**，但 A0A **连该部门的 agents 名单都不在**（跨部门指挥链，真源无登记）；
- `chief_line` 主官 = **A0**（田丰），同样不在名单、无席位档案。

## 二、实施内容

### 1. `engine/org_audit.py`（只读审计）
- 严格只读，不写任何真源（有专门用例比对字节哈希）。
- 检出 7 类缺口，**严重度口径写死在代码里**（避免各处解释不一）：
  | 码 | 级别 | 含义 |
  |---|---|---|
  | `DEPT_NO_PROFILE` | P1 | 整部门零档案——无法回答职责/模型/档级 |
  | `LEAD_NULL` | P1 | 主官空悬，该营无签字人 |
  | `LEAD_NO_PROFILE` | P1 | 主官无档案 |
  | `LEAD_OUT_OF_DEPT` | P2 | 主官不在本部门名单（指挥链跨部门） |
  | `DUPLICATE_CN_NAME` | P2 | 中文名重复（存量 4 对） |
  | `GHOST_SEAT` | P2 | 部分席位有名无档 |
  | `LEAD_UNREGISTERED` / `ORPHAN_STAFF` | P2/P3 | 主官未登记档案 / 真编外 |
- **口径修正（本单一处实质判断）**：初版把 A0、A0A 判成「编外」——错的。
  他们是跨部门主官，属「主官在真源未登记席位档案」，另立 `LEAD_UNREGISTERED`；
  真编外另计。两集合互斥有专门用例守着。
- CLI 双模式：人读摘要 / `--json`；`--strict` 有 P1 时非零退出（可供 CI 用）。

### 2. `GET /api/org/audit`（只读端点）
供界面与外部消费；异常时不吞，返回 `audit_failed` + 类型名。

### 3. **快照席位口径修正（关键）**
`snapshot.py` 由「只按 agent_profiles 出人」改为 **「agents 名单 ∪ profiles」**：
名单优先、档案补全字段，无档案的标 `has_profile=False`，并给每部门加
`seats_listed / seats_profiled / lead_profiled`。schema 升 **1.2**（新增字段向后兼容）。

### 4. 沙盘把缺口画出来
- 无档席位：虚线框 + 灰字 + `·无档` 标注 + `title` 提示；
- 部门头：显示 `档案 x/y`，主官无档加琥珀 `·无档`，空悬显示 `主官待任`；
- 图例增一项「有名无档」；
- 点开无档席位：抽屉直接说明「该席位只有名字，职责/模型/档级/工具均未登记，
  无法回答它在干什么也无法派工；补齐须田丰归口、老田裁定，走 org_enroll（需签字）」，
  并写明**工具不代填职责——造出来的职责比没有更糟**。
