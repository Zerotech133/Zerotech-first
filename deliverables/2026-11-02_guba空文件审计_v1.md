## 三、成因判定（证据链）

### 3.1 代码机制（`quant_backtest/guba_crawl.py`）

| 位置 | 行为 | 后果 |
|---|---|---|
| L46-59 `fetch_page()` | `try: requests.get + 正则取 article_list ... except Exception: return []`；**页面无 `article_list` 标记也 return []** | 网络异常 / 限流页 / 验证页全部**静默变成"空"**，无任何日志、无法区分 |
| L81-86 `_atomic_jsonl()` | 写 tmp → `os.replace`，**无条件写**（rows 为空也写 0 字节） | 空结果 → 生成 0 字节文件（原子写，不会半截） |
| L89-123 `crawl()` | 合并 old+got 后**无条件** `_atomic_jsonl(path, old)`；无"无数据不落盘"判断 | 首次尝试即失败 → 创建空占位 |
| L107-114 翻页 | 1.5s/页、无退避、无重试、无 429/403 处理；失败即 `break` | 连续 60 只请求触发站方限流后整段失败 |
| L126-150 `pool_codes()` | 近 30 天缠论池按**信号日序**取前 60 只 → **每天顺序基本固定** | 头部码反复成功、尾部码反复失败（饥饿） |
| L153-190 `main()` | 无失败计数/无失败率断言/永远正常返回 | 任务 rc=0 假绿 |

启动器 `quant_backtest/start_guba_crawl.ps1`：`--pool --pages 2 --limit 60`；仅当 `rc≠0` 才调 `alert_fail_wrap`；无输出级断言。**采集器 rc 永远 0 ⇒ 告警链从未触发**。

### 3.6 放大/掩盖因素

1. **假绿监控**：status log 28 次运行 **28 次 exit=0（0 次非零）**；launcher 只按 rc 告警 → 从未告警；`GubaCrawl` 11-01 LastTaskResult=0 但当日 53/60 失败；

## 五、建议处置（本轮不执行删除）

### P0 采集器修复（L1 代码变更，另立单；本单只给建议）

1. **空结果不落盘**：`crawl()` 在 `old` 与 `got` 均空时**跳过 `_atomic_jsonl`**（不创建空文件）；已有文件无变化时也不重写（保留 mtime 语义）。
2. **失败可分辨 + 留痕**：`fetch_page` 返回 `(rows, status)`，status ∈ `{ok, no_marker, http_4xx/5xx, exception}`，每码每页打印状态；区分"限流页/验证页"（无 article_list）与网络异常。
3. **退避 + 重试 + 顺序抖动**：检测到 `no_marker`/429/403 时指数退避（30s→60s→120s，最多 2 次重试）；每轮随机化 code 顺序；单轮码数下调（如 ≤15）并拆多窗口（如 17:50、20:00、次日 07:00），避免尾部饥饿。
4. **失败率断言 + 告警**：每轮输出 summary JSON（`attempted/succeeded/failed/empty/new_posts/max_ts/duration`）；**失败率 > 20% 时 rc≠0** → 现有 `alert_fail_wrap guba_crawl` 链自动告警；沿用 `start_guba_crawl.ps1` 的告警封装。
5. 可选：对 `no_marker` 页面落 1 份样本到 `C:\Temp`（去敏感）供后续判定限流页特征。
