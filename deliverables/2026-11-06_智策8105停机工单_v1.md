## 二、根因链（四环，环环有据）

1. **守护设计是 fail-closed**：`zhice_api_guard_once.py` 头注释写明 ACL-104（2026-11-02）——
   8105 启动前强制跑只读迁移 preflight，`rc≠0` 就 **不起 8105**，防止「DB 迁移链与仓库 head 不一致时带病启动」。
2. **preflight 比较三方**：迁移目录里算出的 head（`0051`）、本仓 `tools/zhice_migration_preflight.py` 里硬编码的
   `DEFAULT_EXPECTED`（仍是 `0050`）、DB 实际 `alembic_version`（`0050`）。
   三方里两方是 0050、一方是 0051 → `head_mismatch` → rc=1。
3. **守护因此拒绝启动** → 8105 持续 DOWN。
4. **下游连带**：nginx `location ^~ /quant-api/` → `host.docker.internal:8105`，上游死 → 502 →
   portal live 契约用例拿到 502 而非 401。

一句话：**不是 8105 坏了，是「代码已经走到 0051，库还停在 0050，而门禁不许这种状态启动服务」。**

**一条容易误判的补充**：`0051` 在 zhice 仓里是**未跟踪文件**（`git status` = `??`），但**不能据此认定它是「没做完的 WIP」** ——
该目录 48 个文件被 git 跟踪、实际有 50 个，`0050` 同样未跟踪，说明这个仓的迁移文件本来就不走 git 提交纪律。
「未跟踪」在这里是常态，不是半成品的证据。判断它是否可用，只能看内容与库的现状（见第四节实测）。

## 五、处置方案（三选一，我推荐 A）

### 方案 A（推荐）：落库 0051 + 同步 expected

**① 命令全文**

```powershell
# 1) 落库（在 zhice 仓 code/ 下，用该仓自己的 venv）
cd C:\项目\zhice-os-v2-windows-20260920\code
.\.venv\Scripts\python.exe -m alembic upgrade head

# 2) 同步本仓 preflight 的期望值（两行，必须与 ① 同单，否则 preflight 会转成 db_revision_mismatch）
#    tools/zhice_migration_preflight.py
#      DEFAULT_EXPECTED        "0050" -> "0051"
#      DEFAULT_REQUIRE_RANGE   "0046-0050" -> "0046-0051"

# 3) 手工触发一次守护（不必等 5 分钟轮询）
Start-ScheduledTask -TaskName 'ZhiceAPI8105Guard'
```

**② 影响面**
- 一条 `ALTER TABLE`（DROP + ADD 唯一约束），表 700 行，无重写数据、无列变更、无数据迁移；
- 落库后 8105 可启动，`/quant-api/*` 恢复；
- 本仓两行常量变更属代码变更，需走门禁与提交。

**③ 不可逆点**
- DDL 本身可回滚（`downgrade` 已验证不会失败）；**真正不可逆的是「顺序」**：
  只改 expected 不落库 → preflight 从 `head_mismatch` 变成 `db_revision_mismatch`，仍然 fail-closed，
  等于白改一次还多一类告警。**两件事必须同一次做完。**
- 若 0051 是他人未完成的 WIP，落库等于替别人签收了他的设计 —— 这是需要 owner 确认的部分。

**④ 替代方案**
- **B：把 0051 移出 `code/migrations/versions/`**。head 自动回落 0050，preflight 立刻 PASS，8105 起来。
  代价：11-05 那个跨市场冲突 bug 继续挂着，且文件是别人 12:53 提交的，动它等于否掉别人的工作。
- **C：只改 `DEFAULT_EXPECTED` 不落库**。**不可行**，理由见 ③。

**⑤ 回滚预案**
```powershell
cd C:\项目\zhice-os-v2-windows-20260920\code
.\.venv\Scripts\python.exe -m alembic downgrade 0050   # 约束退回 (pool_date, code)
# 本仓常量改回 0050 / 0046-0050
```
回滚判据：`preflight` 重新 PASS 且 `alembic_version=0050`。若 downgrade 报重复行（当前 0 重复，理论上不会），
说明落库期间新写入了跨市场同 code 数据 → 停下，按数据问题单独处理，不许静默删行。
