# 数据盘活方法论：分拆 · 连接 · 串联 · 能力 · 研发计划

日期：2026-11-06
范围：quant_backtest 数据仓 306 张登记表 + 项目现有能力层
性质：方法论定稿（非结论汇编），所有数字均为本轮实测

---

## 0. 一句话结论

**数据盘不活，不是因为数据少，是因为 306 张表按"来源"摆放、按"主题"检索，而它们唯一能产生价值的方式是按"可连接性"摆放。**

现有 306 张表分属 11 个 channel、53 个物理目录、4 种 schema 习惯。同一件事实（日线）存在 3 份物理副本，行数相差 4.3 倍，没人知道哪份是权威。治理元数据设计了三轴（`market` / `event_date_kind` / `available_after` / `calendar`），**实测 306/306 全部为 None**——schema 有，值一个没有。

所以本轮不做新采集、不做新模型。只回答五件事：怎么拆、怎么连、怎么串、缺什么能力、按什么顺序研发。

## 1. 实测基线（先说清现状，再谈方法）

### 1.1 元数据：设计完备，回填为零

`warehouse_registry.json` 每条记录 23 个字段，设计质量不低（含 `policy_evidence`、`session_cutoff`、`verification_rule`、`pending_fields`）。但四个**决定可连接性**的字段实测全空：

| 字段 | 含义 | 实测 |
|---|---|---|
| `market` | 属于哪个市场 | 306/306 = None |
| `event_date_kind` | 日期是发生日还是披露日 | 306/306 = None |
| `available_after` | 何时起可被使用（PIT 基石） | 306/306 = None |
| `calendar` | 用哪套交易日历 | 306/306 = None |

而 `pending_fields` 字段已经诚实地把这四项列进了待办。这说明**不是没想到，是停在设计阶段没落地**。

资格状态分布（这部分是有内容的）：

| 状态 | 数量 | 含义 |
|---|---|---|
| evidence_ok | 187 | 取证通过 |
| evidence_partial | 34 | 部分通过（如 lag=11>7 超期） |
| unknown | 60 | 未取证 |
| deprecated | 16 | 已废弃 |
| planned | 9 | 计划中 |

**关键：`evidence_ok` 只证明"文件存在且能读"，不证明"时点正确、口径一致、跨表可连"。** 这两件事完全不同，现在被一个字段混在了一起。

### 1.2 同名表三副本，但覆盖范围差 4.3 倍

"日线"这一件事实，物理上存在三份：

| 路径 | 行数 | 列数 | 备注 |
|---|---|---|---|
| `tdx/ts_daily` | 4,270,430 | 12 | 多一列 `_fetched_at` |
| `tushare/daily` | 18,407,840 | 11 | 全历史 |
| `tushare_v2/daily` | 4,923,952 | 11 | 与 tdx 最接近 |

**这不是冗余备份，是三个不同时间范围的同名表。** 使用者若以为是"三份互备、取其一"就会静默用错覆盖范围——用 `tdx/ts_daily` 做 2010 年回测会得到空结果而不报错。

这比"副本内容冲突"更危险，因为冲突至少能被对账发现，覆盖范围差异不会。

**另一处实证**：`us_daily` 的 24,211 个 parquet 文件之间 `trade_date` 类型不一致（部分 VARCHAR），DuckDB 直接读会抛 `Conversion Error`，必须 `union_by_name=true` 才能读。这就是"没有统一取数层"的直接代价——每个下游脚本都要自己踩一遍。

### 1.3 跨市场 ID 桥只有 211 只

唯一现成的跨市场映射表是 `ts_stk_ah_comparison`：**211 只 A+H**。

| 分母 | 覆盖率 |
|---|---|
| A 股 5,400 只 | 3.9% |
| 港股 3,034 只 | 7.0% |
| 美股 20,077 只 | 0% |

**结论：跨市场连接靠 ID 走不通。** 96% 的标的不存在 ID 桥。想做"美股→A 股"的映射，只能靠产业链语义，不能靠 join。

而语义通道是有的且规模够大：`ts_ths_member` **382,731 条成员关系**、`ts_ths_index` **1,666 个概念板块**。这是目前唯一可用的跨市场连接底座。

### 1.4 研报 291 万行可用，但"修正"信号被噪声淹没

`report_rc` 实测：2,910,978 行、2010-01-01 至 2026-10-30、5,701 只标的、192 家机构。

字段完整度（2025 年以来 33.2 万条）：

| 字段 | 有值数 | 占比 |
|---|---|---|
| `tp`（目标价） | 266,526 | 80.3% |
| `pe` | 281,814 | 84.9% |
| `rating` | 326,620 | 98.4% |
| `max_price` | 12,097 | **3.6%** |

**字段陷阱**：`tp` 和 `max_price` 名字都像目标价，实际一个是主用字段、一个基本是空壳。同名不同义。

**修正率实测 97.3%**（29.0 万对同股票同机构连续预测，28.2 万对 eps 发生变化）。

这个数字高得反常，说明 eps 字段几乎每次都变——大概率是"滚动年度预测"口径，而非真实的盈利预测修正。**直接用 `eps != prev_eps` 当修正信号，等于把 97% 的正常调仓都当成事件。**

评级分布更极端（2025 年以来）：

| 评级 | 条数 | 占比 |
|---|---|---|
| 买入 | 171,028 | 51.5% |
| 增持 | 70,710 | 21.3% |
| 推荐 | 24,536 | 7.4% |
| 优于大市 | 10,706 | 3.2% |
| 跑赢行业 | 10,064 | 3.0% |
| 强烈推荐 | 8,761 | 2.6% |

前两档占 72.8%，前六档占 89%。**评级水平本身几乎没有信息量，只有评级变化和偏离共识的程度有信息量。**

### 1.5 自我纠正：南向持股也断了

上一轮我写"南向持股完整存活（2020-2026）"，**这是错的**。本轮实测 `hk_hold` 按 exchange 分组：

| exchange | 标的数 | 最新日期 |
|---|---|---|
| SZ | 2,207 | 2026-09-30 |
| SH | 2,128 | 2026-09-30 |
| HK | 1,093 | 2026-11-04 |

**沪深港通（南向）持股在 2026-09-30 停止更新**，只有港股本地披露还在走。停更时间线因此变成四条：北向 2024-08、转融通 2024-09、QMT 2026-10、南向 2026-09。

上一轮据此推的"身份研究唯一土壤是港股 CCASS"这条，**前提被削弱了**：CCASS 走的是港交所披露，与沪深港通口径不同，理论上仍可用，但不能再用 `hk_hold` 作为它的替代验证源。

### 1.6 时间纵深极度不对称

| 市场 | 起始 | 跨度 | 行数 |
|---|---|---|---|
| 美股 `us_daily` | 1973-01-01 | **53 年** | 4,350 万 |
| A 股 | 1990 年代 | ~30 年 | 1,840 万（daily） |
| 研报 `report_rc` | 2010-01-01 | 16 年 | 291 万 |
| 港股 `hk_daily` | 2021-01-04 | **5 年** | 280 万 |
| 两融 | 2023-07 | 3 年 | 277 万 |

美股 53 年能做的事，港股 5 年做不了。**这是资产也是陷阱**——用美股长周期结论套 A 股，会犯制度差异错误（做空机制、退市率、投资者结构全不同）。

## 2. 分拆方法论：怎么拆

### 2.1 第一原则：按可连接性拆，不按主题拆

现在的事实组织方式是：

```
data/tdx/       (56 张)  ← 来源
data/tushare/   (61 张)  ← 来源
data/xueqiu/    (10 张)  ← 来源
data/知识库/     (27 张)  ← 来源
```

这是**最差的一种组织方式**，因为它把"同一实体的不同侧面"分散在 4 个渠道、3 种 schema、4 种日期格式里。每次跨源分析，都要重新解决"这两个 ts_code 是不是同一个""这两个 trade_date 能不能对齐"。

正确的拆法是问三个问题，而不是问"这属于行情还是财务"：

1. **它用什么键连到别的表？**（主键轴）
2. **它在什么时刻可以被知道？**（时点轴）
3. **它能算出什么粒度的东西？**（粒度轴）

三轴都答得出来的表，才是可用的表。答不出来的，是"存着的数据"，不是"资产"。

### 2.2 三轴定义与判定规则

**轴 1 · 主键轴（Key Axis）**

| 主键类型 | 连通能力 | 现有表 |
|---|---|---|
| `ts_code` | 与行情/财务/因子全连 | 大部分 |
| `ts_code + trade_date` | 面板数据，可做横截面 | 行情类 |
| `broker` / `seat` | 连到参与者网络（弱，重名） | top_inst、fut_holding、block_trade |
| `holder_name` | 连到自然人（最弱，归并率低） | top10_holders、share_float |
| `concept_id` | 跨市场语义连接（唯一可行） | ths_member |
| 无主键 | **不可连，降级为参考资料** | 部分 news、yt_* |

判定规则：**主键必须是已登记的实体 ID 或可解析到实体 ID 的字段。** 自由文本（如 `buyer`/`seller` 营业部全名）必须先进实体解析，才能参与连接。

**轴 2 · 时点轴（Point-in-Time Axis）**

这是当前最大的缺口（306/306 空）。定义三个时间：

| 时间 | 含义 | 例子 |
|---|---|---|
| `event_time` | 事件发生 | 2026-11-04 收盘 |
| `publish_time` | 对外披露 | 龙虎榜 T+1 晚 |
| `ingest_time` | 我们入库 | T+2 凌晨 |

**回测必须用 `publish_time`，不能用 `event_time`。** 现在三者在系统里是混的。

判定规则：每张表必须声明 `event_date_kind ∈ {occur, publish, period_end, snapshot}`，并给出 `lag_days`（publish - event）。

具体分级（本轮实测归纳）：

| 类型 | 典型 lag | 代表表 | 回测用法 |
|---|---|---|---|
| 实时 | 0 | 分笔、分钟线 | 可当日用 |
| T+0 盘后 | 0 | 日线、资金流 | 收盘后可用 |
| T+1 | 1 日 | 龙虎榜、大宗交易 | 次日起可用 |
| T+1 晚 | 1 日 | 两融明细、北向持股 | 次日起可用 |
| 季度 | 30~90 日 | 财报、fina_indicator | **必须用 `disclosure_date` 不用 `end_date`** |
| 快照 | ∞ | `cb_basic.conv_price`、`stk_pledge` | 只能当期用，不可回填历史 |
| 静态 | — | `stock_basic`、`ths_index` | 需版本化，否则幸存者偏差 |

**"快照"这一类最危险**：`ts_cb_basic.conv_price` 只有一个当前值，没有历史。用它算 2020 年转股溢价率，等于用 2026 年的转股价算 2020 年的数。

**轴 3 · 粒度轴（Grain Axis）**

| 粒度 | 现有 | 能算什么 | 不能算什么 |
|---|---|---|---|
| 3 秒分笔 | 5,217 只 / 9 年 | 主动买卖、大单拆分、VWAP 偏离 | 逐笔委托、撤单 |
| 1 分钟 | 33,998 parquet / 1.496 亿行 | 日内动量、量价背离 | 盘口深度 |
| 日 | 1,840 万 | 因子、截面 | 日内路径 |
| 季 | 财报 | 基本面因子 | 短期事件 |
| 事件 | 龙虎榜/大宗/研报 | 事件研究 | 连续时间序列 |

判定规则：**粒度决定上限，不可上采样。** 3 秒分笔无法还原成逐笔，日线无法还原成分钟。"能不能算"这个问题，答案在粒度轴上，不在算力上。

### 2.3 五个实体：306 张表重新归类

不按来源分，按"它描述谁"分：

| 实体 | 定义 | 归入的表（示例） | 数量级 |
|---|---|---|---|
| **Instrument 标的** | 可交易的合约 | stock_basic、cb_basic、opt_basic、etf_basic、fund_basic、us_basic、hk_basic、index_basic | ~40 |
| **Venue 场所** | 交易所、券商、营业部 | stock_basic.exchange、top_inst、fut_holding、block_trade.buyer/seller | ~15 |
| **Agent 参与者** | 谁在动 | top_list、top10_holders、share_float、stk_holdertrade、xq_inner_trade、moneyflow | ~30 |
| **Event 事件** | 什么时候发生了什么 | anns_d、research_report、report_rc、block_trade、limit_list_d、irm_qa、cctv_news、major_news | ~40 |
| **State 状态** | 某时点的量 | daily、daily_basic、fina_indicator、cyq_perf、margin_detail、hk_hold、index_weight | ~120 |

剩下 ~60 张（news 原始、yt_* 知识库、paper_* 交易记录、quant_* 中间态）不属于五实体，归类为**"非结构化素材"**和**"自产运行态"**，单独处理，不参与实体连接。

**这个归类最重要的产出不是分类本身，而是暴露了一个事实**：State 类 120 张占 40%，但 Agent 类只有 30 张且质量最差（归并率 0~10%）。**数据重心严重偏在"价格"上，"人"这一侧几乎没有可用连接。** 而情报价值恰恰在"人"。

### 2.4 数据格（Cell）：命名与 manifest

一个数据格 = 三轴交点，是最小可调度 / 可校验 / 可授权单元。

命名规范：

```
{entity}.{attribute}@{grain}[.{market}]
```

例：

| cell id | 含义 |
|---|---|
| `instrument.daily_ohlcv@D.CN` | A 股日线 |
| `instrument.daily_ohlcv@D.US` | 美股日线（53 年） |
| `agent.seat_flow@event.CN` | 龙虎榜席位流水 |
| `event.analyst_forecast@D.CN` | 研报预测（291 万行） |
| `state.margin_balance@D.CN` | 两融余额 |
| `event.block_trade@event.CN` | 大宗交易（含买卖方席位） |

每个 cell 必须带一张 manifest（不是 registry 的一条记录，而是 cell 的契约）：

```yaml
cell: instrument.daily_ohlcv@D.US
physical: [tushare/us_daily]        # 权威源，唯一
fallback: []                         # 备用源（必须声明覆盖差异）
key: [ts_code, trade_date]
event_date_kind: occur
lag_days: 0
calendar: NYSE
available_from: 1973-01-01
available_to: 2026-11-04
license: internal_only
quality: {lag_max: 1, schema_version: 3, union_by_name: true}
owner: data
```

**关键字段是 `physical` 单值 + `fallback` 必须声明覆盖差异**。现在三副本的情况，正确做法是：`tushare/daily`（1,840 万，全历史）为权威，另两份降级为 fallback 并写明"仅覆盖 20XX 起"。

### 2.5 分拆的产出物

| 产出 | 形态 | 作用 |
|---|---|---|
| cell 清单 | `data/cells.yaml`（~180 个 cell） | 替代 306 条 registry 作为唯一入口 |
| cell manifest | 每 cell 一节 | 承载 PIT / 许可 / 覆盖 |
| 实体映射表 | `entity_map.parquet` | 主键 → 实体 ID（含置信度） |
| 冲突台账 | `conflicts.jsonl` | 多源不一致记录 |

306 张表映射到 ~180 个 cell（因为存在同义重复：ts_cb_daily 与 cb_daily、ts_daily 三副本）。

## 3. 连接方法论：四种连法，现在只做了一种

### 3.1 四种连接的严格区分

| 类型 | 依据 | 严格程度 | 现状 |
|---|---|---|---|
| **同一性连接** Identity | ID 相等或实体解析 | 最高 | 只做了 ts_code 一种，覆盖率 3.9%（跨市场） |
| **时间性连接** Temporal | 时点对齐 | 高（PIT 一错全错） | 未做，元数据全空 |
| **因果性连接** Causal | 机制假设 | 中（需验证） | 未做 |
| **行为性连接** Behavioral | 共现 / 相似 | 低（易过拟合） | 部分做了（席位共现设计稿） |

**四种连法不能混用。** 现在的代码里它们是同一个 `merge`，这是最大的方法论错误。

### 3.2 同一性连接：可连率是硬约束

| 连接 | 手段 | 可连率 | 结论 |
|---|---|---|---|
| A 股内部 | ts_code | ~100% | 可用 |
| A 股 ↔ 港股 | ts_stk_ah_comparison | **3.9%** | 样本太少，只能做个案 |
| A 股 ↔ 美股 | 无 | 0% | **必须靠概念语义** |
| 席位 ↔ 游资 | 名称匹配 | 10.5%（692 组重名） | 不可用 |
| 股东 ↔ 自然人 | 名称匹配 | 0.0% | **完全不可用** |

**这是本轮最硬的结论：跨市场、跨主体的连接，ID 路线已经走到头了。3.9% 和 0.0% 不是"还能优化"，是"此路不通"。**

唯一可走的替代路线是**概念语义连接**：`ts_ths_member` 382,731 条成员关系、1,666 个概念。用法是：

```
美股 NVDA → 概念「AI算力」→ 1666 个概念中匹配 → A 股成员（如 300308 中际旭创）
```

代价是精度低（概念板块由同花顺人工维护，粒度粗、更新滞后），收益是**覆盖率从 0% 提到 60%+**。这是一个明确的取舍：宁要 60% 覆盖的粗连接，不要 0% 覆盖的精确连接。

### 3.3 时间性连接：PIT 是唯一不可妥协的

时间性连接的规则只有一条：**连接时刻 t 的信息，只能用 `publish_time <= t` 的数据。**

现在做不到，因为 `available_after` 全空。具体后果举例：

- 用 `fina_indicator.end_date` 当可用日 → Q1 报告 4 月 30 日才披露，但 4 月 1 日就"用上了" → **前视 30 天**
- 用 `cb_basic.conv_price` 当历史 → 用 2026 年转股价算 2020 年溢价率 → **前视最多 6 年**
- 用 `hk_hold` 最新快照当 2024 年持仓 → 停更后数据不更新，但代码不报错 → **静默错误**

第三条最危险。`hk_hold` 在 2026-09-30 停更，任何依赖它的策略从 10 月起都在用过期数据，**而且不会报错**。

### 3.4 因果性连接：用假设表，不用 join

因果连接的正确形态不是 SQL，是**假设登记**：

```yaml
hypothesis: H-021
claim: 信用利差走阔 → 高杠杆行业资本开支下修 → 12 个月内跑输
evidence_required: [shibor, 财务杠杆, 资本开支, 行业收益]
falsifiable_by: 利差走阔后 12 个月，高杠杆组超额收益 >= 0
status: untested
```

项目里已有 `research_hypotheses` 表，但本轮实测它没有三元组结构（假设 / 证据 / 置信度）。**因果连接的载体是假设台账，不是宽表。**

### 3.5 行为性连接：最容易被过度解读

席位共现网络、行为指纹都属于这一类。设计稿已存在（90 日窗口内近 30 日边权 ×2）。

风险已在上轮标注：**解读 Agent 极易"过度拟人化"**——把统计共现说成"资金集团协同"。防御手段是强制声明：行为连接只能产出"疑似关联"，不能产出"确认关联"，且必须给出反例率。

## 4. 情报视角的串联：四层传导，不是一张宽表

### 4.1 为什么不能 join

用户问的"A 股 / 美股 / 港股 / 信用 / 研报怎么串"，最直觉的做法是建成一张大宽表。**这条路必须否掉**，原因有三：

1. **频率不同**：信用是月度、美股是日度、研报是不定期、A 股分笔是 3 秒。对齐到最低频率，样本从 1,521 万条塌缩到几百个月度观测。
2. **时区不同**：美股 T 日收盘 = 北京时间 T+1 凌晨。对齐规则一错，全部前视。
3. **因果层级不同**：利率变化对个股的影响经过 3~4 个中间环节，直接回归只会得到近零相关，然后被误读为"无影响"。

### 4.2 四层传导链

| 层 | 内容 | 现有数据 | 更新频率 | 作用 |
|---|---|---|---|---|
| **L0 信用与利率** | 货币市场、信用利差 | `shibor` 1.6 万、`shibor_lpr` 6.4 万、**信用债 缺** | 日 | 定折现率与资金成本 |
| **L1 海外映射** | 美股、港股、汇率 | `us_daily` 4,350 万 / 53 年、`hk_daily` 280 万、`fx_daily` | 日 | 定风险偏好与估值锚 |
| **L2 产业与预期** | 研报、财报、产业链 | `report_rc` 291 万、`research_report`、`ths_member` 38.2 万 | 不定期 | 定盈利预期与传导时滞 |
| **L3 A 股个股** | 量价、资金、席位 | 3 秒分笔 9 年、1 分钟 1.5 亿行、龙虎榜、大宗 | 3 秒~日 | 交易执行与风控 |

**串法：上层做条件化（conditioning），下层做横截面（cross-section）。**

不是 `JOIN`，是 `WHERE`。具体：

```
L0 给 L3 打 regime 标签（宽松/紧缩）
L1 给 L3 打风险偏好标签（risk-on / risk-off）
L2 给 L3 打预期修正标签（上修/下修）
→ 在同一个标签内，才做 L3 的截面选股
```

这样每层都保住了自己的频率，样本不被塌缩，且规避了跨层直接回归的伪相关。

### 4.3 三个可落地的串联范式

**范式 A：事件传导链（研报 → 个股）**

```
研报上修（report_rc，tp 变化 > 5%）
→ 同概念板块内其他标的（ths_member）
→ 观察 T+1 ~ T+5 的超额收益扩散
```

价值：把"分析师预期修正"从单票信号升级为**板块扩散信号**。研报 291 万行、16 年历史，样本量足够。当前 97.3% 的假修正率必须先做阈值清洗（建议 `|Δtp/tp| > 5%` 才算真修正）。

**范式 B：跨市场映射链（美股 → A 股）**

```
美股某概念龙头单日涨幅 > 5%
→ 概念匹配（ths_member 1,666 个板块）
→ A 股成员次日开盘溢价 / 日内动量
```

价值：ID 桥只有 3.9%，但概念桥能覆盖 60%+。这是唯一现实的跨市场通道。
风险：概念板块由人工维护，存在"事后归类"（某票涨了才被加进热门概念），会产生前视。**必须用 `ths_member` 的历史版本，不能用当前快照。**

**范式 C：资金意图链（大宗 → 席位 → 后续）**

```
大宗折价率（实测：卖方为"机构专用" → 0.00%；营业部对营业部 → -5.07%）
→ 卖方席位（实体解析）
→ 该席位 90 日内其他标的的行为
```

价值：大宗折价率是"紧迫程度"的连续度量，优于龙虎榜 794 万的二元开关。
前提：席位实体解析必须先做（当前归并率 10.5%）。

### 4.4 情报分析的真正门槛：假设管理

情报分析（intelligence analysis）的标准方法论是**竞争性假设分析（ACH）**：列出所有互斥假设，逐条用证据打分，找"最能区分假设的证据"，而不是"最支持某假设的证据"。

项目现状：有 `research_hypotheses` 表，但没有 ACH 结构。缺的是三元组：

| 元素 | 现状 |
|---|---|
| 假设集（互斥、可证伪） | 部分有 |
| 证据-假设打分矩阵 | **无** |
| 区分性（diagnosticity）度量 | **无** |

**没有 diagnosticity 度量，就无法判断一条证据到底有没有用。** 这是"情报视角"与"数据视角"的分水岭：数据视角问"这个信号准不准"，情报视角问"这个信号能不能区分两个假设"。

### 5.2 四个缺口，按阻塞程度排

**缺口 1：统一取数层（Reader）—— 最阻塞**

现状：每个脚本自己写 `read_parquet('.../**/*.parquet')`。后果已经实测到：`us_daily` 因 schema 漂移直接抛异常，必须加 `union_by_name=true`；三副本覆盖不同，谁也不知道该读哪份。

**没有 Reader，后面每一个实验都在重复交同一笔税。**

**缺口 2：实体解析（Entity Resolution）—— 闸门**

归并率 0.0% 意味着：所有"同一个游资""同一个股东"的结论都是错的。而 Agent 类 30 张表全是靠人名/席位名连接的。**这是整个"人"这一侧的地基，现在是 0。**

**缺口 3：PIT 治理 —— 静默错误源**

`hk_hold` 2026-09-30 停更却仍被读，`fina_indicator` 用 `end_date` 而非 `disclosure_date`——这些错误**不会报错**，只会让回测结果虚高。

**缺口 4：事件研究引擎 —— 价值放大器**

龙虎榜、大宗、研报、公告、停复牌全是事件型数据，现在没有统一的事件窗口对齐器。每做一个事件研究就要重写一遍 T-20..T+20 的对齐逻辑。

### 5.3 一个判断题

"需不需要足够的能力"这个问题，答案是：**不需要更多能力，需要更少但更基础的四个能力。**

现有 15 个 Agent（治理 v2 后）、306 张表、271 个因子——**能力不缺广度，缺的是共同的底座**。再加 3 个采集器、5 个因子，只会让重复劳动税更高。

## 7. 九条你没想到的

### 7.1 三副本不是备份，是三个覆盖范围 —— 必须声明权威源

实测 `tdx/ts_daily` 427 万 / `tushare/daily` 1,840 万 / `tushare_v2/daily` 492 万，**差 4.3 倍**。

这不是"冗余"，是"三个不同时间段的同名表"。谁读错谁的回测就少 15 年数据，而且**不报错**。

行动：每个 cell 必须声明唯一 `physical`，其余降级为 `fallback` 并写明覆盖起止。

### 7.2 研报修正率 97.3% 是假信号，必须阈值化

29.0 万对连续预测中 28.2 万对的 eps 发生变化。这个比例说明字段口径是"滚动预测"，改一点就算变。

直接当信号用，等于把 97% 的正常更新当事件——**信号被噪声完全淹没**。

行动：改用 `|Δtp/tp| > 5%` 或 `|Δeps/eps| > 3%` 作为真修正阈值，先验证阈值合理性。

### 7.3 评级水平零信息量，只有变化有

"买入"+"增持" = 72.8%，前六档 = 89%。评级是个几乎不退档的标签。

行动：`rating` 不能当因子（截面上人人都是买入）；`rating` 的变化方向、以及**偏离同业共识的程度**才有信息量。

### 7.4 同名不同义：`tp` 与 `max_price` 差 22 倍

`tp` 有 80.3%，`max_price` 只有 3.6%。名字都像目标价，实际一个是主字段、一个是空壳。

行动：字段级也要做"同名不同义"的登记，不能只看表名去重。

### 7.5 跨市场 ID 桥 3.9%，语义桥 38.2 万条 —— 路线必须换

A+H 只有 211 只。想连美股，ID 路线直接归零。

而 `ths_member` 有 382,731 条成员关系、1,666 个概念。**这是唯一现实的跨市场通道，精度低但覆盖高。**

行动：放弃"精确 ID 映射"幻想，接受"概念语义 + 置信度"的粗连接。

### 7.6 时间纵深不对称 53 年 vs 5 年 —— 长周期结论不可跨市场套用

美股 1973 起，港股 2021 起。美股能做的 10 年周期检验，港股做不了。

行动：任何"美股验证过的规律"迁移到 A 股/港股，必须标注样本期差异；A 股制度（T+1、涨跌停、做空受限）与美股根本不同。

### 7.7 信用是真真空 —— 全库无债券表

用户问"信用怎么串"，实测答案是：**没有信用数据。**

`shibor` 1.6 万行、`shibor_lpr` 6.4 万行只是货币市场利率，**不是信用利差**。全库 grep `bond|yc_|credit|rating` 结果为空。

行动：L0 层现在是缺的。要么外部接中债/中证估值，要么承认 L0 只能做"利率"不能做"信用"。

### 7.8 治理会反噬 —— 新增能力必然带新增 Agent

本方法论新增 Reader / EntityResolution / EventStudy / Regime 四个模块，按项目历史规律，每个模块天然带 1~2 个 Agent，**Agent 数会从 15 顶回 22+**。

行动：这四个模块必须是**库函数，不是 Agent**。准入闸：增量熵可量化 / 维护成本 < 决策改善 / 有失效预案。

### 7.9 情报视角的门槛不是数据，是区分性（diagnosticity）

数据视角问"这个信号准不准"；情报视角问"这个信号能不能区分两个互斥假设"。

一个 90% 准确的信号，如果两个假设下都出现，区分性为零，情报价值为零。

行动：`research_hypotheses` 需要补 ACH 三元组（假设集 / 证据-假设打分矩阵 / 区分性），否则"情报视角"只是换了个词说数据。

### 解决的三个真问题
1. **同名表跨根目录重名**：`daily` 同时位于 `tushare/daily`(1,840 万/1991起) 与 `tushare_v2/daily`(492 万/2023起)；`ts_daily` 更出现在 `tdx/` + 两个 `tushare_staging/tail_fill*` 目录。注册表 `physical_tables` 仅是名字，无法唯一定位。Reader 全盘解析候选目录，**默认取非 staging 副本并集** → 拿到 1991 起的超集覆盖，从根上消灭"读错副本 → 静默少样本"。
2. **多目录必须用数组语法**：`read_parquet('a','b',union_by_name)` 在 DuckDB 会报 `read_parquet(VARCHAR,VARCHAR)` 不匹配，必须 `read_parquet(['a','b'],union_by_name)`。这是单目录读取碰巧不暴露、多副本并集必崩的真 bug，已修。
3. **日期列注册表缺失**：`report_rc` 注册表 `date_column=None`，真实是 `report_date`。Reader 增加自动探测（按 `*_date` 命名规则），不再依赖人工登记。

### 四类"读越界报错"异常
`UnknownAssetError` / `OutOfBoundsError` / `EmptyResultError` / `ColumnError` —— 全部替代了原先"返回空 DataFrame 让下游静默踩坑"的默认行为。

### 一个实测发现（顺带）
`us_daily` 美股用裸符号（如 `A`=Agilent、`AAPL`），不是 A 股的 `代码.SH` 格式。跨市场连接时主键形态不同，P2 实体解析需注意。

### P0 之后建议的下一步
P1 元数据回填（把 `market`/`available_after` 等 4 个空字段从 306 降到 0）可直接消费 Reader 的 `info()`/`coverage()` 半自动生成；P2 实体解析、P3 事件引擎、P4 跨层条件化均建立在 Reader 之上，无需重复写取数代码。
