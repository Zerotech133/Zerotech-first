# V100 显卡训练与部署方案（2026-11-03）

> 场景：若自有/可用 V100（16GB 或 32GB，PCIe/SXM2）→ 替代云 4090 方案，成本归零
> 结论：**V100 32GB 训练 Qwen2.5-14B-Instruct（QLoRA SFT+DPO），V100 16GB 训练 Qwen2.5-7B-Instruct；部署 14B/7B AWQ-int4（Ollama/vLLM）**

## 一、V100 关键约束（决定方案）
| 项 | V100 特性 | 影响 |
|---|---|---|
| 显存 | 16GB / 32GB（HBM2） | 16G → 7B QLoRA；32G → 14B QLoRA |
| 精度 | **无 BF16**，FP16 有 Tensor Core | 训练配置必须 `bf16: false, fp16: true` + loss scaling |
| 算力 | FP16 Tensor ~125 TFLOPS（SXM2） | 约为 4090 的 50-70%；本项目数据小，全流程仍约 1.5-5h |
| 架构 | Volta sm70 | **FlashAttention-2 不支持** → `attn: sdpa/eager`；bitsandbytes 4bit 可用但比 Ampere 慢 |
| 部署 | vLLM 对 Volta 支持有版本限制 | 优先 Ollama/llama.cpp；vLLM 需实测；AWQ-int4 转换可在 V100 上做 |

## 二、模型选择（对应本知识库）
| 显存 | 推荐模型 | 方法 | 理由 |
|---|---|---|---|
| **V100 32GB** | **Qwen2.5-14B-Instruct**（主） | QLoRA r32/α64 + DPO | 方案原定正式模型；32G 可安全跑 14B QLoRA（seq 2048, batch1×ga16） |
| V100 32GB（stretch） | Qwen2.5-32B-Instruct（可选） | QLoRA r16, seq 1024, grad ckpt | 4bit 权重 ~18GB，32G 勉强；仅当 14B 效果不足再试 |
| **V100 16GB** | **Qwen2.5-7B-Instruct**（主） | QLoRA r32/α64 + DPO | 4bit ~4.5GB + 激活，稳定；14B 只能 seq 768-1024 极限跑（风险） |
| 7B/14B 共用 | 7B 先行冒烟 → 14B 正式 | 同方案 D1→D3 | 与训练方案 v1 的「7B 三职」一致 |
| 备选 | Qwen3-8B/14B（若已有权重且 LLaMA-Factory 支持） | 同上 | 需重验 chat template；不建议临时换型 |

**不推荐**：V100 上全参微调（7B fp16 权重+优化器 >16-32G）、CPT（语料不够）、72B（显存不够）。

## 三、训练配置差异（相对方案 v1 的 4090 配置）
| 参数 | 4090 版 | **V100 版** |
|---|---|---|
| `bf16` | true | **false** |
| `fp16` | false | **true**（+ loss scaling 自动） |
| `flash_attn` | fa2 | **disabled**（用 sdpa/eager） |
| `cutoff_len` | 2048 | 14B@32G：2048；14B@16G/32B：**1024** |
| `per_device_train_batch_size` | 2 | **1**（V100 32G 可试 2） |
| `gradient_accumulation_steps` | 8 | **16** |
| `gradient_checkpointing` | true | true（必须） |
| `learning_rate` | 7e-5（14B） | 同（fp16 下可略降 10%） |
| `lora_rank/alpha` | 32/64 | 同；32B 用 16/32 |
| DPO | bf16 true | fp16 true；`pref_beta 0.1` 不变；eval batch 1 |

## 四、时间与成本估算（本项目数据）
| 任务 | V100 32G 14B | V100 16G 7B | 4090 参考 |
|---|---|---|---|
| D1 冒烟（10%，2 epoch） | 10-20 分钟 | 5-10 分钟 | 2-5 分钟 |
| D2/D3 全量 SFT（2,678 条，3 epoch ≈ 74 万 tokens） | **2.5-4h** | **1.5-2.5h** | 0.5-1h |
| D4 拒绝采样（k=8×641，本地或 V100） | 2-4h（批量推理） | 1-2h | 1-2h |
| D5 DPO（1 epoch） | 0.5-1h | 0.3-0.5h | 0.2-0.5h |
| 全流程 | **约 1 天** | 约半天 | 约 3-4h |
| 成本 | **¥0（自有卡）/ 租用约 ¥1-2/h** | 同 | ¥1.5-2.5/h |

## 五、部署方案
| 模型 | 量化 | 服务 | 显存 |
|---|---|---|---|
| 14B SFT/DPO | AWQ-int4（~9GB）或 Q4_K_M GGUF | Ollama / llama.cpp；vLLM 需验证 Volta 支持 | 32G 可跑 fp16 14B（~28G 紧）或 int4 |
| 7B SFT/DPO | AWQ-int4（~4.5GB） | Ollama / vLLM | 16G 富余，可并发 |
| 推理冒烟 | — | 先 Ollama 注册 GGUF，再评估 vLLM | — |

**部署建议**：训练产物 `merge → AWQ-int4 → GGUF(Q4_K_M)`；V100 上优先 Ollama（CUDA 支持稳），vLLM 仅在验证 sm70 可用后采用。

## 六、建议路线（有 V100 后修订）
1. **不再租云**：预算从 ¥50-240 降为 **¥0**（自有卡）；若租 V100 约 ¥1-2/h；
2. 32G：直接 **7B 冒烟（可选）→ 14B 正式 SFT + DPO**；16G：**7B SFT + DPO**，14B 仅在必要时极限试；
3. 数据侧不变：D0 已完成（2,678 条 SFT + 105 held-out）；用 V100 补 C 到 950-1050、DPO 拒绝采样；
4. 通用回混 F 类仍需引入（BELLE/Firefly/COIG）——与卡无关；
5. 本地 9B 可继续做数据生成/裁判（省 V100 时间）。

## 七、待定信息

- 是自有卡还是租用（决定成本）；PCIe/SXM2 与驱动/CUDA 版本（CUDA 12.x 支持 V100；建议 12.1+）；
- 是否允许 Linux 环境（V100 训练建议 Linux；Windows 下 LLaMA-Factory CUDA 也可但要试）。
