### 2.2 实控人 —— 唯一真缺口

图里完全没有。现在的"人"只有三层：`chairman`（董事长）、`manager`（总经理）、`secretary`（董秘）。

**实控人 ≠ 董事长。** 这是本质区别：
- 董事长是**治理角色**，会换，可以是职业经理人
- 实控人是**所有权终点**，通常不变，决定公司行为

补法上要注意三件事：

| 事项 | 说明 |
|---|---|
| **形态** | 实控人可能是自然人、可能是法人（集团公司）、可能是国资（无实际控制人） |
| **要带比例** | 只存"谁是实控人"没用，必须带 `holding_pct` 和 `control_path`（直接持股 / 多层股权穿透） |
| **要带时点** | 实控人会变。必须 `validStart/validEnd`，否则回溯会用到未来信息 |

> 如果只补"名字"不补"比例+时点"，它进不了因子，只能当标签看。这是补数时最容易浪费钱的地方。

### 2.4 龙虎榜 —— 数据最全，浪费最狠

`TradeAction` 实测：

| 项 | 值 |
|---|---|
| 记录数 | **431,277** |
| 时间跨度 | 2023-07-31 ~ 2026-10-16 |

| 字段 | `amount`（成交额）、`side`（**0=卖 179,504 / 1=买 251,773**）、`trade_date`、`source` |
| `-EXECUTED_BY->` Seat | 431,277（100%），涉及席位 **13,165 / 13,166** |
| `-TARGETS->` Security | 418,954（97.1%） |
| `-LOCATED_AT->` Location | **346,083** |
| `-OCCUPIED_BY->` HotMoney | **83,150（仅 19.3%）** |
| `<HAS_TRADED-` TradeDate | 431,277 |

**`side` 和 `amount` 都在。** 我上一轮说"要先 dry-run 确认有没有买卖方向和金额"——**答案是全有，游资净买入强度可以直接算，不用等**。

但要注意那个 **19.3%**：43 万条成交里只有 8.3 万条能连到游资，**34.8 万条（80.7%）挂着普通营业部，没有主体**。

这 80.7% 不是废数据——它们是**尚未被识别的资金主体**。识别方法不是买数据，是补映射：

```
Seat(营业部名) --映射表--> HotMoney(游资名)
```

现在的 `Seat.hm` 只覆盖 13,166 个席位里的 **120 个（0.9%）**。剩下 13,046 个营业部是空白的。

> 这条映射表是可以**从行为反推**的：同一营业部若长期与某游资的其他席位同日同向、且成交额分布相似，即可高置信度归属。这叫行为聚类，不需要外部数据源。**这是"事"维第一个真正的因子工程活。**

### 2.5 人维 —— 物化 100%，但没做实体归并

这是本文第二硬的发现：

| 项 | 值 |
|---|---|
| `Company` 有 `chairman` | 6,265 |
| 其中有 `SERVES_AS` 高管边 | **6,265（100.0%）** ✅ |
| `SERVES_AS` 边总数 | **701,499** |
| `Person` 节点 | 192,031 |
| 不同姓名数 | **192,031** |
| **同名归并率** | **0.0%** ⚠️ |

再看一个刺眼的数字：

| 任职公司数 | 这样的"自然人"有几个 |
|---|---|
| 149 家 | 1 |
| 137 家 | 1 |
| 132 家 | 2 |
| 124 家 | 1 |
| 120 家 | 3 |
| 114 家 | 1 |

**一个人当 149 家 A 股上市公司的董事长，不可能。** 这不是"能量大"，是**实体没归并**：同一个人在不同公司被拆成不同节点，或者多个同名的人被当成同一个人。

> 这直接废掉了 8 个图特征里最重要的一个：`person_shared`（共享高管关联的其他公司数）。**如果同一个人的节点都不唯一，这个特征测的就不是人脉，是噪声。**
>
> **所以 `person_shared` 现在跑出来的数不能信。** 这是我在上一轮没查到的，必须更正。

人维归并是三档难度：

| 档 | 方法 | 能解决 | 风险 |
|---|---|---|---|
| **D1** | 姓名 + 生日 + 学历 + 国籍 四元组精确匹配 | 同名但生日不同的（大部分） | 低 |
| **D2** | 姓名 + 任职公司所属集团 | 集团内兼任 | 中 |
| **D3** | 姓名 + 任职时间不重叠（排他） | 同名不同代 | 中 |

**先跑 D1 就够。** `Person` 已有 `birthday/gender/edu/national` 四个字段，正好是为归并准备的——**字段早就留好了，只是没跑**。

## 4. 补数据优先级（按"每元投入的因子增量"排）

| 优先级 | 动作 | 成本 | 立刻解锁什么 | 风险 |
|---|---|---|---|---|
| **P0** | 补齐 22 个游资节点（`Seat.hm` → `HotMoney`） | **10 分钟，零新增数据** | 游资覆盖 21→43，翻倍 | 零（纯加节点+边） |
| **P1** | `person_shared` 前置：`Person` D1 归并（姓名+生日+学历+国籍） | 半天 | 8 个图特征从"噪声"变"可用" | 低（先 dry-run 看合并了多少） |
| **P2** | 营业部→游资 行为聚类，攻 80.7% 无主体资金 | 3–5 天 | 龙虎榜可用资金 19.3%→60%+ | 中（需人工抽验聚类质量） |
| **P3** | 实控人补齐（天眼查，**带 holding_pct + control_path + validStart**） | 采购 + 2 天 | 所有权传导链，全新一类关系 | 中（口径不一，国资/无实控人要特判） |
| **P4** | 补 2023-07 之前的龙虎榜（现只有 776 个交易日） | 采购 | 样本外延长 | 低 |

**P0 是唯一"今天就能做完且必然有收益"的项。** P1 是它的必要前置——如果人维不归并，即使补齐游资，`person_shared` 仍是噪声。

## 5. 治理完能立刻算的 6 个「事」维因子（零新增数据）

`TradeAction` 已有 `amount + side + trade_date + seat + hotmoney + security + location`，这六个因子**今天就能算**：

| # | 因子 | 定义 | 用到的边 |
|---|---|---|---|
| **E1** | 游资净买入强度 | `Σ(amount \| side=1) − Σ(amount \| side=0)` 按标的×日 | `TARGETS` + `side` |
| **E2** | 席位集中度 | 单标的当日 Top1 席位占比（HHI） | `EXECUTED_BY` |
| **E3** | 游资连续上榜天数 | 同一游资在标的上的连续交易日数 | `OCCUPIED_BY` + `trade_date` |
| **E4** | 游资风格胜率 | 该游资历史上榜后 5 日收益均值（`wr_win_rate` 已在 Seat 上，可上卷） | `OCCUPIED_BY` + 收益 |
| **E5** | 异地资金占比 | `LOCATED_AT` 省份 ≠ 公司 `province` 的成交额占比 | `LOCATED_AT` + `Company.province` |
| **E6** | 事件-资金共振 | 当日 `Security-[:INVOLVES]-Event` 数 × 净买入强度 | `INVOLVES` + E1 |

注意 **E5 是唯一同时用「地」和「物」两维的因子**——`LOCATED_AT` 34.6 万条边 + `Company.province` 100% 填充，两边数据都齐，只差一个减法。

> 这六个因子全部落在「事」维或跨维，**正是现在 271 个因子完全空白的地方**。而且不需要买任何数据。

## 6. 一句话总结

> **你缺的不是数据，是"把已有数据变成边、把边变成因子"这两道工序。**
>
> 天眼查已在图里 100%，龙虎榜 43 万条带买卖方向，地域 34.6 万条全接好——**七项资产六项接好，零项入因子**。
> 真正的采购需求只有两个：**实控人**（带比例和时点）、**2023-07 前的历史**。
> 其余的，是 10 分钟到 5 天的工程活。
