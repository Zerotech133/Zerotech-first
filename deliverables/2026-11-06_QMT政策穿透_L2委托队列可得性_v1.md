# QMT 政策穿透：Level-2 委托队列到底还能不能拿到

> 触发：老田质疑"QMT 现在政策变了，这个数据你确定能拿得到？"
> 方法：官方 SDK 源码级验证 + 券商通知原文比对 + 本机环境实测
> 结论前置：**接口存在，路径被掐断。上一轮我说"3~8 万/年买不到"是错的，但真相不是"能拿到"，而是"拿到了也用不了"。**

---

## 一、一句话结论

把"能不能拿到"拆成五个独立问题，因为它们的答案完全不同：

| 问题 | 答案 | 依据 |
|---|---|---|
| ① SDK 里有委托队列接口吗 | **有，而且比想象强** | `xtquant-250807.1.2` 源码 |
| ② L2 是白送的吗 | **不是**，QMT 默认只给 L1 五档 | 券商通知 + 多源一致 |
| ③ 现在还能开吗 | **miniQMT 不能**；大 QMT 能，10~50 万 + C4 + 备案 | 2026-07-06 起停新开 |
| ④ 拿到的数据能进我们库吗 | **不能**，沙箱已封死 | 2026-10-23 全量生效 |
| ⑤ 有历史能回测吗 | **没有**，跨交易日清理 | 官方文档明写 |

**四个答案里三个是"不能"。所以：**

- 想做**研究/因子/行为指纹** → **做不到**，别投钱。
- 想做**盘中人工看单票封单真假** → **可以做**，但要接受数据出不来。

## 二、我上一轮错在哪（三处，全部纠正）

| # | 上轮说法 | 实际 | 严重度 |
|---|---|---|---|
| 1 | "委托队列是交易所不对外发的 L1 东西，只有 L2 有，3~8 万/年" | 价格说高了两个量级：**30~60 元/月**，资产达标常赠送。我说"贵"是错的 | 中 |
| 2 | "先别买，等 3 秒数据跑出指纹看能不能替代" | 建议本身没错，但理由错了。真正的否决理由是**沙箱封死 + 无历史**，不是贵 | 中 |
| 3 | 隐含假设"券商通道拿到就能用" | **完全没算政策变量**。2026-07 和 2026-10 连出两刀 | **高** |

第 3 条是根子上的错：我把 QMT 当成"数据源"来评估，但它现在被重新定义成了**封闭策略执行器**。数据源和执行器，评估维度完全不同。

## 三、政策时间线（这才是老田问的"变了"）

| 时间 | 事件 | 影响 |
|---|---|---|
| 2024-05 | 证监会《证券市场程序化交易管理规定（试行）》发布 | 确立"先报告、后交易" |
| 2024-10-08 | 上述规定施行 | 程序化交易进入备案制 |
| 2025-04 | 沪深北《程序化交易管理实施细则》发布 | 高频认定：单账户每秒申报+撤单 ≥300 笔或单日 ≥2 万笔 |
| 2025-07-07 | 上述细则施行 | 高频差异化收费（流量费、撤单费） |
| **2026-07-06** | **多家券商停止 miniQMT 新开户** | xtquant 外接通道对新户关闭；存量"暂不影响"、后续专项通知 |
| **2026-10-08** | **券商推送《[重要]内置Python策略功能调整》** | 三条禁令，见下 |
| **2026-10-23** | **盘后全量生效**（存量也覆盖） | 管理端权限控制，不升级客户端也躲不掉 |

### 2026-10-08 通知三条禁令（原文口径）

> 一、关闭内置 Python 策略文件读写功能
> 涉及本地文件读写的功能（包括但不限于 open()、read()、write() 及相关第三方库）均无法使用。
>
> 二、关闭内置 Python 策略外部网络连接功能
> 涉及策略发起的网络连接（包括但不限于 HTTP、TCP、UDP 等）、局域网或本机数据库连接（包括但不限于 MYSQL、Redis、SQLite 等）以及与局域网内其他设备进行网络通信……均会被禁止。
>
> 三、取消登录页的独立交易选项

**唯一豁免**："使用内置 python，且不与外部进行任何交互的策略不受上述调整影响。"

**已确认执行**：国金证券、国投证券（社区多源印证，截至 2026-10-20 口径）。

### 关键推论：这三条打的不是"取数"，是"出口"

这一点必须看清，否则会误判：

- 禁令**没有**禁止你读行情。`get_market_data_ex`、`download_history_data`、L2 订阅接口**全部不受影响**。
- 禁令封的是 `open/to_csv/json.dump/pickle/sqlite3/requests/socket/pymysql/redis`。

**换句话说：政策允许你看，不允许你把看到的东西带走。**

监管口径讲得很直白——"策略可以是黑盒，但必须是封闭的黑盒"。

对我们的直接杀伤：**L2 数据进了 QMT 沙箱，就再也出不来。** 我们所有下游（parquet、Neo4j 图谱、因子库、回测）全部依赖"数据落盘"，这条路断了。

## 四、委托队列确实存在（源码级证据，不是文章转述）

本机实测：`pip download xtquant` 成功，得到 **`xtquant-250807.1.2-py3-none-any.whl`（34.4 MB）**，PyPI 版本总数 19 个，最新两版上传于 **2026-07-21**（即 miniQMT 停新开之后仍在维护存量）。

解开包后 AST 解析 `xtdata.py`，L2 相关函数共 6 个（**这是源码签名，不是文档抄来的**）：

```
get_l2_quote(field_list, stock_code, start_time, end_time, count)      # L2 快照
get_l2_order(field_list, stock_code, start_time, end_time, count)      # L2 逐笔委托
get_l2_transaction(field_list, stock_code, start_time, end_time, count)# L2 逐笔成交
subscribe_l2thousand(stock_code, gear_num, callback)                   # 千档盘口
subscribe_l2thousand_queue(stock_code, callback, gear_num, price)      # 千档委托队列 ★
get_l2thousand_queue(stock_code, gear_num, price)                      # 千档队列取数 ★
```

官方 `doc/xtdata.md` 的 period 枚举（第 141~147 行）：

| period | 含义 |
|---|---|
| `l2quote` | level2 实时行情快照 |
| `l2order` | level2 逐笔委托 |
| `l2transaction` | level2 逐笔成交 |
| `l2quoteaux` | level2 实时行情补充（总买总卖，含**撤单总量**） |
| **`l2orderqueue`** | **level2 委买委卖一档委托队列** |
| `l2thousand` | level2 千档盘口 |

### 这个数据结构直接回答"每手多少手"

`subscribe_l2thousand_queue` 文档给出的真实返回样例（原文照抄）：

```python
{'000001.SZ': [{'time': 1733120970090,
  'bidGear': [1, 2], 'bidPrice': [11.36, 11.35],
  'bidVolume': [[91, 100, 100, 100, 20, 100, 50, 29, 3, 51, 12, 308, 8, 20, 10, 5, 1, 1, 3, 12,
                 100, 100, 10, 62, 2, 35, 300, 51, 9, 100, 100, 10, 131, 5, 30, 4, 20, 30, 5, 20,
                 20, 12, 5, 3, 19, 11, 9, 5, 10, 5], [...]],
  'askGear': [1, 2], 'askPrice': [11.37, 11.38], 'askVolume': [[...], [...]]}]}
```

买一档下直接是 **50 个逐笔手数**：`91, 100, 100, 100, 20, 100, 50, 29, 3, 51, 12, 308, ...`

- 能看到"是单笔 308 手大单，还是 100 个散户小单拼出来的封单"——这正是"看穿真假封单"。
- `price` 参数支持**指定价格 / 价格列表 / 价格区间**，可以直接盯涨停价那一档。
- 这是**打板、封单质量判断**的核心数据，我在上一轮完全低估了它。

### 但有一个致命的东西它给不了

**A 股的委托队列只有"手数"，没有"谁"。**

对比：`xtdata.py:736` 有 `'brokerqueue': (1820, 0, '港股委托经纪人队列')` —— 港股能看到**具体哪个经纪商**在排队。**A 股没有这个**。

所以老田上一轮问的"陈小群每手多少手" —— 队列能给**手法分布**；但"这 1 个亿是不是他的" —— 队列**答不了**。

**委托队列解决"手法"，不解决"身份"。** 而您真正卡住的是身份。

## 五、五道门，逐门实测

### 门 1：L2 权限不是跟着 QMT 送的

QMT 开通只赠 **L1 五档**。L2（十档、逐笔、委托队列）是**独立增值权益**：

- 默认路径：单独付费，**市场常规 30~60 元/月**（年费数百到上千）。
- 免费路径：资产达标（10~50 万，视券商）由客户经理赠送。
- 坑：券商 APP 的普通看盘 L2 **不能对接 Python 接口**，必须单独申请"量化终端专用 API 版 L2"。

### 门 2：开通通道在收窄

- **miniQMT（xtquant 外接）**：2026-07-06 起新户默认不含；存量分批清理。这是唯一能自由读写文件的通道，**正在消失**。
- **大 QMT（内置 Python）**：可开，门槛 20 日日均 10 万（部分券商）/ 50 万（完整版）+ C4 + 6 个月经验 + 签署程序化风险揭示书 + **交易所侧程序化报备**。
- 线下营业部基本只受理 50 万完整版；10 万 MiniQMT 名额收紧到线上客户经理通道。

### 门 3：数据出不来（最致命）

2026-10-23 后，大 QMT 内置策略**不能写文件、不能连库、不能发网络请求**。

三条出路全部受限：

| 出路 | 可行性 |
|---|---|
| 策略直接落盘 parquet | ❌ 拦截 open/to_parquet |
| 写 SQLite/Redis/MySQL | ❌ 双重点名封堵 |
| 起 HTTP 服务给外部拉 | ❌ 禁 socket/端口监听 |
| **客户端手工导出** | ⚠️ 界面导出"资金/持仓/委托/成交"仅覆盖**交易数据**，L2 行情能否导出**未验证** |
| **等数据商白名单** | ⚠️ 官方称在评估万得/聚源/财汇/tushare，**个人自建服务明确不放行** |
| **PTrade** | ❌ 云端受控环境，数据更出不来 |

结论：即便开通、即便拿到，**也无法进入我们的自动化管线**。

### 门 4：没有历史

官方文档 `doc/xtdata.md:118` 原文：

> "level2 数据实时部分用 subscribe_XXX 订阅，用 get_l2_XXX 获取。**level2 函数无历史数据存储，跨交易日后数据清理**"

三个 `get_l2_*` 接口的备注全是同一句："**需要缓存中有接收过的数据才能获取到**"。

含义：
- 开通当天往前，**一条都没有**。
- 无法回测、无法验证、无法与 9 年历史分笔对齐。
- 想要历史 L2，只能向数据商买（如 CMES 一类，2018 年起，按天计费）。

### 门 5：沪市结构性残缺

| 市场 | 逐笔成交 | 逐笔委托 | 委托队列 | 撤单明细 |
|---|---|---|---|---|
| **深市**（000/002/300/301） | ✅ | ✅ | ✅ | ✅ |
| **沪市**（600/601/603/605/688） | ✅ | **❌** | 3 秒快照、仅买一卖一 | **❌** |

上交所 L2 只开放逐笔成交 + 十档，**不推逐笔委托、不推实时撤单**。这是交易所底层披露规则，不是券商权限问题，买多少钱都补不上。

A 股约 5,200 只，沪市约 2,300 只（含全部 688 科创板、601/603 大盘蓝筹）。**近一半标的拿不到委托流**——而这半边恰好是大资金主战场。

推论：任何"看穿主力真买假买"的研究，在沪市标的上**先天失效**，会系统性偏向深市中小盘，直接污染结论。

## 六、Tushare 有没有 L2？（决定要不要碰 QMT 的岔路口）

有二手文章称"Tushare Pro 有 Level-2 十档和逐笔成交，需高积分"。**我去查了官方接口文档，这个说法不成立。**

Tushare 官方 `document/2` 行情部分只有：日线、**中高频分钟行情**、**Tick 级行情**（无文档链接）、大单成交、复权因子、停复牌、每日指标。

**没有 Level2、没有十档、没有逐笔委托、没有委托队列。**

项目侧交叉验证：全仓 `grep` 本项目 tushare 调用，只有 7 个接口（daily/namechange/index_daily/fut_mapping/fut_daily/fund_adj/adj_factor），无任何 L2 调用；`data/` 下 181 张远端表 + 本地全部资产也无 L2。

**结论：Tushare 不是 L2 替代路径。** 想要 L2，A 股只有两条：券商 QMT（被政策掐）或数据商（要花钱买历史）。

## 七、这对我们的实际含义

### 7.1 明确否决：不要为"委托队列"开 QMT / 买 L2

理由三条，任一条独立成立即可否决：

1. **无历史** → 不能回测，做不了因子（我们全部研究依赖回测）。
2. **不能入库** → 进不了 parquet / Neo4j / 因子库，等于数据不存在。
3. **沪市残缺** → 覆盖不全，任何结论都有系统性偏差。

再加一条软的：即便拿到，也**只给手数不给身份**，解不了我们真正卡住的"哪个 1 亿是陈小群的"。

### 7.2 唯一合理用法：盘中人工辅助

如果哪天确实需要，只在一个场景成立：**打板/盯单票时，人眼看封单队列真假**（是 308 手大单还是 100 个散户小单）。

- 形态：QMT 客户端里跑个纯内循环脚本，屏幕上打印/画出队列，**人看**。
- 不以任何形式依赖自动导出。
- 这是"决策辅助工具"，不是"数据资产"。

### 7.3 现有资产反而更值钱

对比一下我们**已经有的**和**想买的**：

| 维度 | 已有 3 秒分笔（pytdx） | QMT L2 委托队列 |
|---|---|---|
| 历史 | **9 年（回溯到 2017）** | 0（开通日起） |
| 全市场 | **5,217 只** | 仅深市完整 |
| 自动入库 | **✅ 79.6MB/日** | ❌ 沙箱封死 |
| 成本 | **0** | 30~60 元/月 + 10~50 万验资 |
| 粒度 | 3 秒聚合 | 毫秒逐笔 + 队列 |
| 能否识别身份 | 否 | **也不能** |

**取舍很清楚：多出来的那点粒度，换不到"历史 + 全市场 + 自动化"这三样。而这三样才是研究的地基。**

### 7.4 一个被忽略的现成替代：`cyq_perf`

我们已有 `tushare/cyq_perf`（**280 日 × 5,571 股**），字段实测：

```
ts_code, trade_date, his_low, his_high,
cost_5pct, cost_15pct, cost_50pct, cost_85pct, cost_95pct,
weight_avg, winner_rate
```

例：`000001.SZ 20250901` → cost_50pct=11.2、winner_rate=49.96%。

这直接回答"委托队列"想回答的**一半问题**——套牢盘在哪、抛压多大、获利盘比例。虽然粗（日频、不带逐笔结构），但**免费、有历史、能入库、全市场覆盖**。

**建议：先把 `cyq_perf` 接进因子库，比买 L2 的现实收益高一个量级。**
