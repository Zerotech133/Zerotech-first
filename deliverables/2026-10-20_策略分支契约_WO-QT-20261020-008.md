## 1. 统一策略接口（StrategyBranch）

```
StrategyBranch（ABC 语义）
  branch_id : str                     # 分支标识（同时是隔离模拟账账户段）
  PERMISSION : dict                   # 权限声明（定义时强制，见 §3）
  decide(signal, context) -> dict     # 决策入口（必须实现）
  review(signal, decision, context)   # 复盘钩子（默认实现，可覆写 _deviation）
```

- **决策入口输入**：`signal` = 合法信号点记录（已经 -005 `normalize_signal` 规范化）；`context` = combo 上下文 `{combo_id, combo_entry（-003 注册表条目）, plan_con（-006 计划账连接，按分支取用）, now}`。
- **决策输出**（`make_decision` 标准结构）：`{execute: bool, reason_code, reason, action, plan_version, basis}`——执行/放弃 + 理由 + 依据链。Runner 侧对决策结构做二次校验（残缺决策 closed on failure）。
- **复盘钩子输出**：`{branch_id, signal_id, decided_action, action, reason_code, plan_version, basis_chain, deviation, branch_schema_version}`——依据链与偏差逐字段可并排对比。

## 2. 两个内置分支语义

### 2.1 follow_research（跟随投研）

```
信号触发 → as_of_plan(combo_id, stock, at_time=signal.triggered_at)
  反查该 combo+stock 在信号时刻生效的投研预案（-006 禁回写口径：
  生效时点 ≤ 信号时刻的版本才可引用）
  ├─ 无已生效版本           → 放弃 reason_code=no_plan_effective（留痕）
  ├─ 预案方向与信号冲突     → 放弃 reason_code=plan_conflict（分歧留痕）
  │   （plan_json["action"] ∈ BUY/SELL/HOLD，与信号 action 不一致即冲突，
  │    如 plan 持有 HOLD、信号 SELL）
  └─ 方向一致               → 执行并引用 plan_version（reason_code=plan_aligned）
```

- 依据链：`signal → as_of_plan → direction_check`。
- persona 置信门槛等落单守卫交由 -005 `consume_signal` 统一把关，本分支不重复实现风控。
- 偏差语义：`plan_conflict`（预案与信号方向分歧）/ `no_plan_effective`（无预案可跟随，选择不行动）。

### 2.2 aggressive_direct（激进直响）

```
信号触发 → 直接按 persona 参数响应（复用 -003 combo_registry persona v1）
  ├─ BUY conf < conf_floor → 放弃 reason_code=conf_floor（该买才买）
  └─ 否则执行（SELL 不受限门槛——该卖还得卖，与 -005/exec_run 口径一致）
```

- **不依赖投研预案、不引用 plan_version**——其偏差语义即 `no_plan_reference`（结构性无预案对照），与跟随分支的分歧在复盘层并排可见。
- 参数同源四元组注册表（persona_params 唯一定义处），不自带第二套风控定义。
- **「激进」仅指决策路径激进（直响不等待投研），不绕过任何权限**——permission 声明与真实出口钳制同 follow_research 完全一致。

## 3. 权限声明强制（BLOCK 边界）

分支接入必须带 `PERMISSION` 显式声明，三项**逐键精确匹配**，缺失/任一不符即拒绝：

| 字段 | 强制值 | 语义 |
|---|---|---|
| `sim_only` | `True` | 分支只允许在隔离模拟环境运行 |
| `real_notify` | `False` | **真实通知 BLOCK**（通知出口未过门） |
| `prod_exec` | `False` | **生产执行 BLOCK**（激进≠绕过真实交易权限） |

- 强制时机为**类定义时**（`__init_subclass__` 钩子）：缺声明连子类都建不出来，比实例化时才拦更早；注册口与 `create_branch` 再各验一道（防运行期篡改类属性）。
- 零真实出口断言（单测实证）：全链路在 `socket`/`urlopen` 钳制下跑通（任何网络出口即炸）+ 真实回执账/拒单账文件零写入 + 源级无通知/网络出口字样。

## 4. 分支注册制（对齐 -003 松耦合验收）

```python
register_branch(cls)        # 注册（可作装饰器）；同 id 重复注册显式拒绝
unregister_branch(id)       # 注销（测试/下线用）；未注册显式抛错
create_branch(id)           # 实例化；未注册 closed on failure，不静默落默认
registered_branch_ids()     # 已注册清单（注册序）
```

- 新增策略分支 = 定义新 `StrategyBranch` 子类（带 branch_id+PERMISSION）+ `register_branch` 一行——**不改 BranchRunner 分发与任何账本代码**即插即用（单测 `test_register_third_branch_pluggable` 以动态注册 hybrid 第三分支实证：同信号三分支平行响应、三账本隔离）。

## 5. 隔离模拟账（平行比较主入口 BranchRunner）

```
runner.feed_signal(record, combo_id, plan_con=None, now=None) -> dict
  # 同一信号喂所有已注册分支（平行响应主入口）
runner.compare_reviews(record, combo_id, plan_con=None) -> dict
  # 复盘钩子只读并行对比（不落单、不回执、不留痕）
```

- **信号规范化与 combo 解析在分发层一次性把关**（closed on failure：非法信号/未注册 combo 直接抛错，不进任何分支）。
- **落单账户**：`account_id = f"{combo_id}@{branch_id}"`（ref 幂等键按 @账户 分段，与 -005 多账户互不串味同机制）——两分支各自独立账本，互不串账。
- **落单复用 -005 `consume_signal` 全守卫**（契约校验/时效/persona/combo 注册表/幂等/快照 fail-visible），本模块零新写账本或风控逻辑。
- **回执契约（对齐 -007）**：分支的实质决策（执行**与**放弃都是决策结果）统一入 `trader_action` 回执，`actor=f"branch:{分支标识}"`，`plan_version` 仅跟随分支携带；同 (signal_id, receipt_kind, actor) 重复喂入被 -007 幂等拒绝，Runner 显式标记 `receipt_status=already_recorded`（不静默重写、不中断平行比较）。
- **分歧留痕**：放弃决策 payload 带 `decided_action=abstain + reason_code + basis`——plan_conflict 与激进直响的分歧在共享回执账双留痕可对比（定纲：反例与分歧是最有价值的训练资产）。
- **单分支故障隔离**：分支内部契约违例 → 留痕（branch_error，append-only jsonl）+ 该分支 `status=error` 显式标记，不静默吞掉、不拖垮其他分支（回执账本就是并行独立入账语义）。
