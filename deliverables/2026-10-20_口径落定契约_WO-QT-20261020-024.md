### 1.2 为什么必须拆（口径事实）

- **命中率与胜率是分母不同的两个量**：胜率分母 = 已回填后验的样本数 n；命中率分母 = **可判定方向样本数**（方向判定不依赖后验回填）。两者不可互相顶替。
- **可判定样本 ≠ 判错样本**：快照缺 `plan_version` 印记（如激进直响分支本就不跟预案）或缺合法 `orders` 动作 → 该样本**不可判定**，**剔出分母并留痕**（`hit_rate_unjudged`），**不记为判错**——记错是冤枉数据、凭空压低命中率；当命中则是造假。唯一正解是剔出分母。
- **无依据时绝不用胜率顶替、绝不填 0**：命中率判不出 → `hit_rate = None` + `hit_rate_status = pending` + note。0 会被读成「一条都没判对」，是造数。

### 1.3 三态与门槛（与既有三态门同族）

| 情形 | hit_rate | hit_rate_status | 说明 |
|---|---|---|---|
| 全部样本不可判定 | `None` | `pending` | 无可判定方向样本（缺 plan 印记/缺合法动作） |
| 可判定样本 < `MIN_SAMPLE`(30) | `None` | `insufficient` | `insufficient_direction_sample`，低于门槛不下结论 |
| 可判定样本 ≥ 30 | 数值 | `computed` | 分母 = 可判定样本数；分子 = 方向一致数 |

- 状态词族与既有 `pending_backfill` / `insufficient_sample` 同一词汇体系。
- 对比 API `compare_baselines`：命中率不可判定的一侧 → **不出差异结论**（不拿 null 与数值相减）。

工位在 RPC 超时前留下半成品，其中 `_hit_rate_block()` 的「全部不可判定」分支**返回 `hit_rate = 0.0`**，与该函数自身文档「两种情况都**不填 0**」及用例期望相矛盾——**0.0 会被读成「一条都没判对」，是造数**。主会话接管时改为 `None`（附注释说明改动原因），6 个失败用例随之全绿（69 passed）。
