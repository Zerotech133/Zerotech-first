## 二、议题提炼口径（成文定义）

```python
mine_topics(*, snapshot_db=None, posterior=None, reviews=None,
            plan_db=None, ledger_path=None, persist=True) -> dict
render_markdown(mined) -> str
riskguard_reserved_topics(records=None, calibration_log=None) -> dict
dissent_metrics(plan_db=None, info=None) -> dict
```

| 参数 | 含义 | 缺省行为 |
|---|---|---|
| `snapshot_db` | -004 决策快照库路径 | `None` → 无样本输入 |
| `posterior` | 后验收益（显式/人工喂入，契约见 §三） | `None` → 全部样本标待回填 |
| `reviews` | -008 `compare_reviews` 输出（单条或列表） | `None` → 无分支输入 |

| `ledger_path` | 议题账 jsonl 路径 | `k_stock/data/meeting_topics.jsonl` |
| `persist` | 是否入账 | `True`；`False` = 干跑（供 -009 汇报器预览） |

### 2.1 三类来源

| `source_type` | 输入 | 提炼口径 | 本单状态 |
|---|---|---|---|
| `most_profitable` | -004 快照 + 后验收益 | 可用样本中后验**最高**者 | **已实现** |

| `riskguard_reserved` | 1.1 校准账（未接入） | 见 §六 | **只留接口，未实现** |

### 2.2 偏差类型取值（可审计，`deviation_type_source` 明示来源）

| 分支状态 | 偏差类型取自 | `deviation_type_source` | 理由 |

| **放弃**（`decided_action=abstain`） | `reason_code` | `"reason_code"` | `plan_conflict` / `conf_floor` 等放弃原因码才是真正可讨论的分歧语义；-008 激进分支的 `deviation.type` **恒为** `no_plan_reference`，取它会盖掉 `conf_floor` 这一可分辨信息 |

## 三、不造数原则（硬约束）

| 情形 | 行为 | 状态词 |
|---|---|---|
| 快照后验**未回填** | **该样本不可用**：不参与最赚/最亏排序、不出议题；显式列入 `suppressed.posterior_pending`（附 `snapshot_id`/`run_ref`/`stock` 等可回放引用） | `pending_backfill` |
| 可用样本 **< 2 个** | **不构成样本对**，不出议题（单样本自称既最赚又最亏是退化输出），出 note 说明 | — |
| 后验喂入**缺 `unit`** | 显式抛 `TopicMinerError(posterior_invalid)` | — |
| 后验 `value` 为 `None`/字符串/bool | 显式抛 `posterior_invalid`（**不得当作 0**） | — |
| 分支无偏差类型 | 不出议题 | — |
| 两率**分母 0** | 两率均 `null` + `note`，**不填 0 充数** | `empty` |
| -006 未接入 | 两率 `null` + `not_wired` | `not_wired` |

**关键取舍说明**：绝不用 `0` 充当「最亏样本」——0 会被读成「打平」，属造数；样本不可用即不出议题。

## 四、议题账 schema（append-only）

**存储选型**：`jsonl` append-only（与 -007 回执账同风格）——天然 append-only，账本层零 UPDATE/DELETE 语义。

```
k_stock/data/meeting_topics.jsonl     # 默认路径（测试一律注入 tmp 路径）
```

**自校验防改写**：每行带 `entry_sha256`（对除自身外全部键排序后取 sha256）。读账时逐行校验，任一行与自校验不符 → **显式抛 `ledger_corrupt`**，不静默重算、不跳行（对齐 -007 `ReceiptLedgerTampered` 判例）。

### 4.1 条目字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `topic_schema_version` | int | 当前 `1` |
| `topic_id` | str | `tp-{source_type}-{fingerprint[:16]}`，**由指纹派生**（同指纹必同 id） |
| `source_type` | str | 四类来源之一 |
| `fingerprint` | str | 去重指纹（见 §五） |
| `subject` | dict | `combo_id` / `stock` / `branch_id` / `signal_id` / `snapshot_id` |
| `sample_ref` | dict | `snapshot_id` / `run_ref` / `stock` / `combo_id` / `branch_id`（**样本引用**） |
| `deviation_type` | str | 偏差类型 |
| `deviation_type_source` | str | 偏差类型取自哪个字段（可审计） |
| `evidence` | dict | **证据摘要（可回放引用）**：快照议题带 `run_path`/`orders`/`plan_version`/`signal`/后验；分支议题带 `basis_chain`/`deviation`/`reason` |
| `suggested_review_target` | dict | **建议复盘对象**：`role`（`combo_owner_research` / `branch_owner`）+ `combo_id` + `branch_id` + `reason` |
| `status` | str | 恒 `draft`（本模块只出草案） |
| `meeting_initiated` | bool | 恒 `false`（发起权不归本模块） |
| `mined_at` | str | 提炼时刻 ISO |
| `entry_sha256` | str | 行自校验指纹 |

### 4.2 append-only 语义

只追加，**无 update / delete 路径**（模块内无 UPDATE/DELETE 语句，无 `write_text`）。更正议题 = 追加新记录，**既有行逐字节不变**（测试以 `startswith(before)` 断言）。刻意不选「允许就地更正」——改写会抹掉「曾经提过什么」的证据，与 -006「反例与分歧是最有价值的资产」同源。

## 五、去重口径

**指纹** = sha256(`[source_type, combo_id, stock, branch_id, deviation_type]`)。

**标的刻意不含 `signal_id`**：同一分支在同一标的上重复出现同一偏差 = **同一个议题**（重复分歧正是更该开会的原因），不因换信号而变成新议题。

| 场景 | 行为 | `dedup_reason` |
|---|---|---|
| 账内已存在同指纹 | 不重复提、**不写行**，返回既有条目 | `same_fingerprint_in_ledger` |
| 本轮内多候选同指纹 | 只提一次，第二次记 existing | `duplicate_candidate_in_this_round` |
| -006 已讨论过（signal_id / stock 命中） | **抑制**，不入账，列入 `suppressed.already_discussed` | `already_discussed_in_meeting_ledger` |

**顺序纪律**：本轮内重复**先于**账内查重判——本轮自己刚写进去的行不是「既有议题」，标错会让汇报口径误读为「历史上已开过题」。

## 七、分歧保全率 / 分歧转化率（两率并列，算式明示）

呼应 -014 `divergence_formula` 风格，**算式写进输出字段**：

| 指标 | 算式（输出字段值） | 含义 |
|---|---|---|
| **分歧保全率** | `meetings_with_dissent / meetings_total` | 有会前分歧记录的会议占比——分歧有没有被保全下来 |
| **分歧转化率** | `conclusions(revise+veto) / meetings_total` | 分歧导致结论改动的比例（与 -014 分歧率同口径） |

**分母 0 → 两率均 `null` + `note`**（「不以 0 充数」），状态 `empty`。

### 7.1 诚实提示：该指标的结构性边界（重要）

-014 已指出：-006 的 `dissent` **写入时强制非空**，故不能用「有无 dissent」当分歧判据（恒为真 = 废指标）。本单的**分歧保全率**同样受此约束，故在输出中**显式带 `preservation_tautology_note`**：

> -006 写入时强制 dissent 非空，故正规写入口入账的保全率**结构性为 1.0**；低于 1.0 说明存在 **-006 强制之前的历史行 / 外部写入行 / `dissent_json` 被写成空列表**——**该指标即用于咬住这处保全破口**。

即：保全率的价值**不在衡量"记得记分歧"**（那由 -006 强制保证），**而在检出"分歧没被记下来"的破口**。测试以绕过 -006 写入口插入空 `dissent` 行验证该咬合行为（保全率跌破 1.0）。

### 7.2 已讨论议题判重（口径保守）

`-006 topic_type=signal` → `topic_ref` 即 `signal_id`，原样入集；`topic_type=stock_date` → 按分隔符取首段作标的代码入集（-006 未固化该格式，取首段是**保守的候选匹配**：宁可多判重，也不把已上过会的议题重新提一遍）。

## 八、失败语义（closed on failure）

一律**显式抛 `TopicMinerError(reason_code, msg)`**，禁静默降级、禁跳行：

| `reason_code` | 触发 |
|---|---|
| `posterior_invalid` | 后验喂入缺 `unit` / `value` 非法 / 结构错 / 键非法 |
| `reviews_invalid` | -008 复盘缺 `signal_id` / `reviews` 非 dict / 分支项非 dict |
| `snapshot_db_missing` / `snapshot_db_unreadable` | 快照库不存在 / 不可读 |
| `snapshot_table_missing` | 库中无 `decision_snapshots` 表 |
| `snapshot_query_failed` / `snapshot_corrupt` | 查询失败 / `orders_json`·`context_json` 非法 |
| `plan_ledger_query_failed` | -006 会议账查询失败 |
| `dissent_corrupt` | 某会议 `dissent_json` 非法或非 list |
| `ledger_corrupt` | 议题账行非法 / 缺 `entry_sha256` / sha256 不符（**被改写**） |
| `riskguard_records_invalid` | RiskGuard 喂入非 list/tuple |

**合法「无数据」不抛**（区别于契约违例）：`plan_db=None`、快照库表缺失且未请求、`posterior=None` → 标 `not_wired` / `pending_backfill` 出数。
