## 背景与定位

飞书中台由另外的 agent 开发（研发计划 v1 / 智能体化方案 v1 的 L1-L6 接线由其消费）。军团侧职责 = **提供稳定的对外门面**，让飞书板块零侵入接线：不 import 军团内部模块、不感知军团内部结构变化。

## 范围（IN）

1. **`agent_platform/gateway/` 新包**（全部新文件，零改既有代码）：
   - `envelope.py`：标准信封规约（schema_version/source/kind/payload/idempotency_key/ts + 校验函数）
   - `llm_gateway.py`：LLM 稳定门面——`chat(binding, system, user)` → 信封 `(ok, text, status, degraded, latency_ms, binding)`；复用 `engine/llm.py make_llm`（降级三态语义原样透传，不建第二调用层）
   - `inbox_gateway.py`：任务投递门面——`submit(kind, payload, source)` 写 bridge_inbox inbox（幂等键去重）+ `receipt(id)` 回执查询
   - `serve.py`：HTTP 服务（127.0.0.1:8795）：POST /llm/chat、POST /inbox/submit、GET /inbox/receipt/{id}、GET /health
2. **测试** `agent_platform/tests/test_gateway.py`：信封校验先红后绿；llm 门面用 MockLLM；降级实测（LLMError→ok:false 信封，不抛穿）
3. **契约文档** `docs/plans/2026-10-21_军团对外接口契约_v1.md`：给飞书 agent 的对接说明书

## 范围外（OUT）

- 不改 engine/llm.py、bridge_inbox、inbound_gateway、portal 任何既有文件
- 不起常驻服务（serve.py 只交付代码+用法，挂载另走五要素）
- 不做鉴权（本机回环 only；鉴权随飞书板块接实例化时另议）
- 不碰飞书侧任何代码（那是另外 agent 的域）

## 验收判据

1. py_compile 全绿；test_gateway.py 先红后绿（含降级路径）
2. 服务单测：POST /llm/chat 真实往返（MockLLM 注入）+ 降级信封
3. inbox 幂等：同 idempotency_key 二次 submit 返回同 id（replayed）
4. 契约文档含端点/信封/错误码/降级语义/最小 curl 例
