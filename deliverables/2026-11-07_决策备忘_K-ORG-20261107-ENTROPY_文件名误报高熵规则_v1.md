## 一、为什么改措辞消不掉（我试了两次提交，白费）

`HIGH_ENTROPY` 的候选抽取是「连续 ≥20 个 `[A-Za-z0-9_=]`」。文档正文里引用测试文件名：

```
portal/test_legion_live_boot_p0.py
```

其中 `test_legion_live_boot_p0` 恰好 **24 字符**，全小写字母+数字+下划线，正好落进高熵字符集。**只要正文提到这个文件，无论怎么改写句式都会命中**——被命中的是文件名本身，不是措辞。

---

## 二、现有两套机制，各自的适用边界

### 1. `EXEMPT_PATH_PATTERNS`（按路径整文件豁免，全规则生效）

已有 5 条，其中 **3 条就是为了 HIGH_ENTROPY 文件名误报加的**：

| 现存模式 | 加它的原因（原文） |
|---|---|
| `scan_secrets_allowlist.tsv` | "长文档名触发 HIGH_ENTROPY；它不是凭据载体" |
| `project_wiki.md` | "生成物会列模块文件名；非凭据载体" |
| `docs/plans/PLAN_REGISTER_*.md` | "文件名可能触发 HIGH_ENTROPY 误报" |
| `portal/static/dw_snapshot.json` | "evidence 文件名含哈希段会触发 HIGH_ENTROPY 误报" |

**先例很明确，但注意：这 4 条全部是「生成物」。** `deliverables/*.md` 是手写文档，把整个路径免掉 = 该目录内**所有规则**都不再检查（真凭据漏检），不合理。

### 2. `scan_secrets_allowlist.tsv`（按 `path:line:rule` 单条豁免）

pre-commit 实际就是走这条：`python tools/scan_secrets.py --baseline tools/scan_secrets_allowlist.tsv`（`.git/hooks/pre-commit:145`）。

**局限**：key 含行号。文档一改行号就失效，表现为"新增命中"。现有 135 行里绝大多数是代码/取证值，正是靠这个机制；但用在**会持续编辑的交付文档**上，等于每次改都要补一行。

## 三、实测影响面（决定选哪条路）

对全仓 tracked 文件（10,488 个，跳过二进制）跑扫描器原逻辑，把 `HIGH_ENTROPY` 判为 True 的 1,503 个候选逐个套用候选新判据：

| 变体 | 判据 | 会新豁免 |
|---|---|---|
| V1 | 全小写字母+数字+下划线（非纯 hex/纯数字） | **117** |
| V2 | V1 且必须含下划线 | 114 |
| V3 | 候选左侧紧邻 `/` **或** 右侧紧跟文件扩展名 | 27 |
| **V4** | 候选左侧紧邻 `/` **且** 右侧紧跟文件扩展名 | **13** |

全仓命中总数 1,135。V1/V2 一次豁免 10% 的命中，太宽；V4 只动 13 个，且全部落在"文档里列文件名"这一形态（`deliverables/*.md`、`docs/*.md`、`quant_backtest/INTEL_RD_PLAN.md` 等），**包括本次的目标行**（已逐行验证：目标行 left=True / right=True）。

## 四、推荐：V4（治类，不动全局豁免、不依赖行号）

理由：
1. 与现有规则**同一设计哲学**——文件里已有大量"看上下文形态"的判例（被引号包裹且后接冒号→字典键名；候选被当函数调用→代码名；含点号→路径/域名）。
2. **三条同时满足才放行**：全小写字母数字下划线 + 左侧有 `/` + 右侧紧跟扩展名。混合大小写的 token 天然不在范围内。
3. 不依赖行号，文档反复编辑不会复发。
4. 影响面 13 处，可逐一人工复核后再合入。

**建议插入位置**：`tools/scan_secrets.py` 的 `is_high_entropy_candidate()` 内，紧接"含点号 → 多为标识符/路径/域名"那条之后、纯 hex 分支之前。

```python
    # 2026-11-07 K-ORG-20261107-ENTROPY：文档里引用「带扩展名的路径成分」必然命中。
    # 例：portal/test_legion_live_boot_p0.py —— 文件名主体 24 字符、全小写+数字+下划线，
    # 正好落在高熵字符集内，改措辞消不掉（命中的是文件名本身）。
    # 三条同时满足才豁免：全小写候选 + 左侧紧邻 '/' + 右侧紧跟文件扩展名；
    # 混合大小写 token 不在范围内，URL 路径末端裸 token 也不在（无左侧 '/' 或无双侧闭合）。
    if re.fullmatch(r"[a-z0-9_]{12,}", cand) \
            and re.search(r"[/\\]" + re.escape(cand), line) \
            and re.search(re.escape(cand) + FILE_EXT_RE, line):
        return False
```

配套常量（挨着其它模块级 regex 定义）：

```python
FILE_EXT_RE = r"\.(?:py|md|json|tsv|csv|txt|log|ya?ml|js|ps1|html?|sh|sql|cfg|ini)\b"
```

**可选加固**：再与一条 `and "://" not in line`，把"URL 里带扩展名的全小写段"也排除在外。代价是"同一行既有 URL 又有文件路径"的文档行仍会命中；本次目标行不含 `://`，加固后仍被覆盖。

## 五、另外两条路（不推荐，供对照）

| 方案 | 做法 | 为什么不推荐 |
|---|---|---|
| A. allowlist 单条登记 | 在 `scan_secrets_allowlist.tsv` 加一行 `deliverables/…md:<行号>:HIGH_ENTROPY` | 行号敏感，**这份文档每次编辑都要补一行**；治标不治本 |
| B. 路径豁免 `deliverables/*.md` | 仿生成物先例加进 `EXEMPT_PATH_PATTERNS` | 该目录整文件**全规则**豁免，真凭据进交付件就再也不会被报；与"生成物才整文件豁免"的既有边界冲突 |
