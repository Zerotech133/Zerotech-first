## 二、为什么测试侧也必须改

这些测试的形态统一是「自己起一个 `127.0.0.1:<port>` 服务，再去打它」，但用的是原生 `urllib.request.urlopen`。而 urllib **根本不豁免回环**：

```python
>>> urllib.request.proxy_bypass("127.0.0.1")
False
```

本机实测环境里就带着 `HTTP_PROXY=http://127.0.0.1:58735`（`getproxies()` 读注册表拿到）。代理一旦严格（拒转 / 挡死 / 502），这些测试的失败信息会指向「服务不可用」，而不是「代理不通」——排障方向直接跑偏。这与盯盘 `_hub_call`、`legion_command/safe_http` 是同一个失效形态，只是发生在测试侧。

## 五、三个必须说清楚的设计决定

### 1）import 插在各文件自己的 `sys.path` 调整**之后**

不能统一插在 `import urllib.request` 后面——那些文件是把 `sys.path.insert(0, ROOT/"portal")` 写在 import 块**下面**的，插早了 `from safe_urlopen import safe_urlopen` 直接 `ModuleNotFoundError`。6 处上下文实测各命中对应副本：

| 上下文 | 解析到的实现 |
|---|---|
| `portal/`（根级 7 个） | `portal\safe_urlopen.py` |
| `portal/tests/` | `portal\safe_urlopen.py` |
| `quant_backtest/` | `quant_backtest\safe_urlopen.py` |
| `agent_platform/tests/` | `agent_platform\safe_urlopen.py` |
| `tools/tests/` | `tools\safe_urlopen.py` |
| `tests/e2e/` | `tools\safe_urlopen.py` |

其中 `tools/tests/` 与 `tests/e2e/` 的树根不在 `sys.path` 上，各多加一行 `sys.path.insert(0, str(<ROOT|REPO> / "tools"))`；`quant_backtest/` 依赖 pytest 把测试文件目录放进 `sys.path[0]`（同目录的 `import kg_events_portal` 已证明这条成立）。

### 2）mock 约定逐个核过，换实现没击穿任何桩

23 个文件里**没有一个**打桩 `urlopen`。唯一的例外是 `portal/test_notification_decision.py`，它的 `monkeypatch.setattr(nd.urllib.request, "urlopen", ...)` 打的是**被测模块内部**的调用，与本文件自身的取数请求不冲突；本文件那 15 处换成 `safe_urlopen` 后，mock 仍在原来的位置生效（`test_group_info_*` 的 3 个桩目标不变）。

### 3）死导入按 AST 判定清理，且「宁可留着」

替换后 13 个文件的 `import urllib.request` 变成死导入（`F401` 属 `F` 类，会被 ruff ratchet 卡）。清理规则不是简单删，而是：

- 代码里已完全不引用 `urllib.*` → 该文件所有 `import urllib.*`（含函数内局部 import）全删；
- 仍引用 `urllib.error.URLError` 等 → **只有**在「另有一条被用到的 urllib import 兜住 `urllib` 名字」时才删，否则保留。

这条兜底是踩坑换来的：`tools/tests/test_card_review_page.py` 只用 `urllib.error.URLError` 却只 import 了 `urllib.request`（靠 CPython 的传递导入才能跑）。第一版脚本直接删 `import urllib.request`，会让 `except urllib.error.URLError` 变成 `NameError`——被兜底断言拦下了。

## 十、踩坑记录

1. **`git show HEAD:file` 不能用来判行尾**：仓库开了 CRLF 规范化，HEAD 里的 blob 是 LF，工作区是 CRLF。拿它对比会把并行 Agent 改的文件（`portal/portal_api.py`、`tools/kb_corpus/*`）全判成「行尾变了」，噪声淹没真结论。正确做法是直接读工作区字节数。
2. **shell 的 `VAR=val cmd` 前缀在 Windows 上不可靠**：`getproxies()` 读注册表，前缀设的 `HTTP_PROXY` 未必生效。第一版死代理对照因此得出「safe_urlopen 也失败」的错误结论——真相是那一刻 8091 恰好不可达（两个原因都报 10061，长得一模一样）。改成进程内 `os.environ` 赋值 + 打印 `getproxies()` 自证，结论才干净。
3. **两者都返回 10061 时无法区分「代理死」与「服务死」**：这是这类对照最容易被骗的地方。要么先探活目标端口，要么把目标换成本机一个确定在跑的服务。
4. **删死 import 的兜底断言救了一次**：`test_card_review_page.py` 只用 `urllib.error.URLError` 却只 import 了 `urllib.request`，直接删会 `NameError`。
5. **补丁脚本第一版把 `sys.path.insert` 与 import 块拼在一行**（block 少了前导换行），生成 `...parents[2]sys.path.insert(...)` 语法错误。断言 `ast.parse` 立刻拦住，没落到磁盘。
6. **`--check` 与 `--apply` 的幂等顺序**：同批 5 的教训复用——先判「已替换」再断言原串次数，否则重跑必挂。
