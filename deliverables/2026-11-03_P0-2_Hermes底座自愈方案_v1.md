## 三、根因

1. **om-metadata = 认证链失效（非网络/非桥接代码）**
   - 桥接 `om_mcp_bridge.py` 工作正常（能连 8585、能回 JSON-RPC），但 OM 对 Bearer 判 401。
   - config token 与 `.hermes_bot_jwt` 同值且均为 2026-10-17 生成；OM 容器/MySQL 于今日重启（Up 2h）后**认证链（admin JWT + Bot generateToken）未重建**；`.hermes_bot_jwt` 未随之刷新 → 旧 Unlimited token 在 OM 侧不再有效。
   - OM 2.0.5 的 Bot 链语义见部署目录 `recreate_auth_chain.py`：`user(isBot=true, authMechanism=JWT) → bot 实体 → PUT /users/generateToken/{id} {"JWTTokenExpiry":"Unlimited"}`，脚本**幂等可重跑**。
2. **zhice-selection = 脚本文件从未落地**
   - `agent_platform/tools/zhice_selection_mcp.py` 在仓库/工作区/`git log` 中均不存在（`git log -- agent_platform/tools/zhice_selection_mcp.py` 空；`reload` 后每轮 spawn 失败）；上游 8105 API 完好 → 仅缺 stdio MCP 包装层。

### 5.1 设计（复用并扩展 `tools/datawarehouse/hermes_mcp_probe.py`）

| 项 | 设计 |
|---|---|
| 数据源 | **解析 `~/.hermes/config.yaml` 的 `mcp_servers`**（13 个，command/args/env 全部来自配置，不硬编码；避免与 Hermes 实际配置漂移） |

| 输出 | `research/reports/hermes_health_<YYYYMMDD>.json`：`{tool, generated_at, config, timeout_s, servers:[{name,ok,init_ok,tool_count,tools,error,duration_s,env_keys}], summary:{servers_total,ok,failed,tools_total}, all_ok, readonly}` |
| 退出码 | **0=13/13 全绿；2=有异常**（沿用现有 probe 的 rc2 语义，便于计划任务/告警判定） |
| 失败可见 | 每个失败 server 记 `error`+`stderr_tail`（脱敏）+`duration_s`；summary.failed 列名单 |
| 今日基线 | 已实跑：`research/reports/hermes_health_20261103.json`（11/13 ok、98 tools、failed=[om-metadata,zhice-selection]、rc=2），与 Hermes 背景一致 → 口径可用 |

**补丁要点（供后续代码单，替换现有 4 项硬编码 SERVERS）**：
```python
# 旧：SERVERS = [("dw-governance", ...), ...4 项]
# 新：从 Hermes config 动态生成 13 项
cfg = yaml.safe_load(Path(os.environ["USERPROFILE"], ".hermes/config.yaml").read_text("utf-8"))
SERVERS = [(name, spec.get("command"), list(spec.get("args") or []),
            dict(spec.get("env") or {})) for name, spec in (cfg.get("mcp_servers") or {}).items()]
OUT = REPORTS / ("hermes_health_%s.json" % datetime.now().strftime("%Y%m%d"))
# probe(): 每 server 8s；initialize→initialized→tools/list；失败重试 1 次；返回 rc=0/2
```
