# WO-GAME/W-Q 持久线性化实施规格（G2 跨账本 ACK 后撤销原子性）

**状态**：老田已批设计方向（单一持久 owner+同库事务）；本规格为只读设计，未写码。

## 一、两 strict xfail 定位与根因

测试 `quant_backtest/tests/test_upstream_ack_authority.py:353-425`（same/cross 两代际）；实测 23 passed, 2 xfailed（状态健康在案）。

并发窗口（watch_dispatch/route_outbox.py finish() L309-439）：
1. L384-396：outbox 在窗口校验后调用 `authority.active_ack(...)`（经 agent_bridge/upstream_ack_authority.py 读 UpstreamInbox）；
2. 权威读返回 True 的瞬间至 outbox 落 RouteReceipt（L425-430）之间存在**非原子间隙**——此刻 UpstreamInbox.revoke()（upstream_inbox.py L257-270，epoch+1、写 _revoked）可并发提交；
3. outbox 只在回调后复查**自身**内部一致性（L398-421 全是私有状态），**不重读 inbox 的 revoked 状态**；
4. 结果：已撤销收据仍以 ACCEPTED_VERIFIED 落凭据（L424-430 无 inbox 二次确认）。

辅助证据：test_game_fanout_independent_qa.py:239（扇出层同款窗口）；internal_signal_fanout.py docstring L12-17 明文"NOT an atomic fence…BLOCKED until the unique durable owner, shared transaction or durable CAS"。

## 二、单一持久 owner 落点

新建 `quant_backtest/quant_sector/settlement_arbiter.py`（或并入 dispatch_ledger.py 扩表），三张表：
- upstream_receipts（收据+revoked+ledger_epoch，承接 UpstreamInbox 状态外置）；
- route_attempts（承接 outbox._attempts/_revoked 落库）；
- arbiter_fence（owner 租约：owner_id/lease_until/heartbeat_at，CAS 续租）。

RouteOutbox.finish 与 UpstreamInbox.revoke 的**写路径全部改经 arbiter**；内存对象保留为投影/缓存，读路径不动（对既有 569 测试零破坏的关键）。落点选 quant_sector（被 ACK 方）而非 watch_dispatch。

## 三、同库事务形态

SQLite 单文件 arbiter.db，`isolation_level=None` + **`BEGIN IMMEDIATE`**（写锁先取）：
- `finish(ACCEPTED_VERIFIED)`：BEGIN IMMEDIATE → ①SELECT receipts → ②revoked 或 epoch 漂移则 ROLLBACK 返回 UNKNOWN（xfail 断言满足）→ ③否则同事务 INSERT route_attempts + UPDATE fence heartbeat → COMMIT。revoke 与 finish 在同一写锁下串行化。
- `revoke()`：BEGIN IMMEDIATE → UPDATE receipts SET revoked=1, epoch=epoch+1 → INSERT 撤销流水 → COMMIT。
- CAS fence：所有写事务第一句 `UPDATE arbiter_fence ... WHERE lease_until < ?now OR owner_id=?`，受影响行数=0 则 FAIL-FAST（fail-closed，不重试不降级）。
- WAL + busy_timeout 5s + FK ON。

## 四、undo 补偿路径（fail-closed 总原则）

- 读收据/见撤销失败 → ROLLBACK → finish 显式返回 UNKNOWN、receipt=None（与现行 lease 过期处理一致，无新状态发明）；
- 写凭据/COMMIT 失败 → 事务自动回滚，**凭据不存在即无下游消费**；不做自动补偿重试（G2-P1 recovery 契约已声明"reclaim/retry requires separately designed contract"）；
- 下游防误读：消费方读凭据时 JOIN receipts.revoked 过滤——撤销后到达的旧凭据不生效。

## 五、验收标准

1. 两 xfail 转正（摘标记后 passed）；
2. 既有测试全绿（quant_backtest 全量 + strategy_layer 569 基线）；
3. **并发竞态变异测试**：两进程对同一收据并发 {finish ‖ revoke}，合法终态仅两种：a) finish 先 COMMIT → 凭据在且 revoke 流水在（被 revoked 过滤遮蔽）；b) revoke 先 COMMIT → finish 返回 UNKNOWN 无凭据；**禁止"凭据在且无撤销记录"或"双凭据"**；N≥100 次无违例；
4. CAS fence 变异：伪造过期租约的第二 owner 写入被拒；
5. 撤销后旧凭据不可消费的回归用例。

**边界**：实施须另立工单并按 W-Q 纪律走"离线单测→双进程竞态台→老田拍板后才可谈生产接线"。扇出层同款窗口（test_game_fanout_independent_qa.py:239）不在本范围，建议后续复用同一 arbiter。
