## 一、改动

### 1. `tools/datawarehouse/dataset_registry.py`（query 引擎 P2）

- **jsonl / json 行级引擎**（`_query_jsonl` 重写 + `_iter_json_docs`）：
  - 支持 `where`（字段白名单=首批 ≤200 文档推断的键；算子 = != > >= < <= in like，值不拼 SQL）、`order`（≤2 键，按字符串稳定排序）、`count`（流式计数）、`since`（**行内时间列优先**，无时间列时按**文件 mtime** 回退并在 evidence 标 `since_mode=file_mtime`）；
  - 流式读：jsonl/ndjson 逐行、`.json` 整个数组/对象、`.gz` 魔数嗅探；坏行跳过；
  - 上限：limit≤1000（沿用）、单次扫描 `QUERY_JSONL_SCAN_LINES=200000` 行/10s（超限 `truncated=True` 可见）；`order` 匹配行 > `QUERY_JSONL_ORDER_ROWS=100000` → `QueryNotSupported`（边界保留，不静默）；未知字段 → 400 + `allowed_fields`。
- **mixed / nested 文件级引擎**（新增 `_query_files` + `_discover` 扩展 `files_meta`）：
  - 载体判定：目录内**纯 jsonl/json** → 行级 `dir_jsonl`；**json + 其他文件混布** → 文件级 `dir_files`；无行级文件但有文件（mixed/nested/语料层）→ 文件级；空目录 → `dir_empty`(N/A)；
  - 文件级四维：只列**已登记文件**（相对 path/name/ext/size/mtime/depth，不读文件内容），支持 where/order/since/limit/offset/count；目录发现深度 ≤4、文件清单上限 5000（`truncated` 可见）；
  - 只读：全部 stat/读取，不写文件、不建索引。
- **not_supported 边界保留**：`pg_table` / `contract_artifact` 在任何路径解析前直接 `QueryNotSupported`（fail-visible；顺带修正 P1 中这类载体先触发越权路径解析的顺序问题）；空目录 → `no_data`；有审计日志（`C:\Temp\dw_query_audit.log`，env 可关）。

## 六、风险与口径说明

1. **jsonl 字段白名单**来自首批 ≤200 文档：稀有字段可能被判 400（可显式传 `columns` 或扩大扫描窗口改进）；
2. **jsonl order** 需流式全扫匹配行（≤100k），超限 `not_supported`（建议先 where 收窄；cursor/排序下推属 P3）；
3. **jsonl since** 无行内时间列时按**文件 mtime**（evidence `since_mode=file_mtime` 显式可见，不猜行内时间）；
4. **文件级载体只列文件**（不枚举目录、不读内容、不建索引）：语义=L/P/F/A 文件级四维，非行级数据查询；
5. nested 深度 ≤4、文件清单上限 5000、目录遍历 ≤2000：超限 `truncated=True` 可见，不静默截断；
6. 扫描上限/超时（jsonl 200k 行/10s、parquet 2M 行/10s、文件 5000）——大目录结果可能 truncated，但四维证据仍按「count 可达 + truncated 显式」口径记录。
