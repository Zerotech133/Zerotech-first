# 量化知识库微调训练方案 v1

> 日期：2026-11-03｜Owner：DATA1 张松（数据/知识线）｜算法执行：ARCH1 + DSH｜审批：老田
> 依据：学习数据后流程统一标准 v2、知识治理报告 v1、已治理数据导出 v1（2204 单元/400 卡/Top100 结论/27 多源）
> 边界：**微调不替代四关**；输出为研究/知识能力，不构成投资建议。

## 一、目标与非目标
### 目标
1. 让本地模型（qwen 系列）在**量化知识问答**上更准确：概念解释、战法要点、因子/回测常识、风控边界；
2. 回答**必须可溯源**（引用来源/卡片），不确定时明确拒答或标注「单源/低置信」；
3. 与 RAG 互补：RAG 负责取最新/长尾事实，微调负责术语、口径、拒答风格与结构化输出。

### 非目标
- 不做「荐股/择时」输出；不生成买卖建议；
- 不用微调替代数据仓/四关；不追求通用能力提升；
- 本期不做 35B 全参微调（资源不允许）。

## 二、数据现状（训练可用 vs 缺口）
| 资产 | 数量 | 质量 | 微调用途 |
|---|---|---|---|
| 知识单元（已治理） | 2,204 | 元数据过滤+去重；溯源 100% | SFT 语料/QA 生成底稿 |
| 学习卡（已审计） | 400 | 0 问题、可追溯 100% | QA 对（concept→a）直接可用 |
| 有效结论 Top100 | 100 | 置信分级（高5/中24/低71） | 事实型问答/引用样本 |
| 多源概念（人工签批） | 27 | 高/中置信 | 评测集（概念一致性） |
| 方法论卡片 | 8 | 8 博主风格 | 风格/边界样本 |
| 原始来源 | 12 份（2.05MB+） | 有 sha256 | 留出集/溯源验证 |

**缺口（必须补）**：
1. **Instruction 数据不足**：直接可用的 QA 仅约 400–600 条；QLoRA 有效微调建议 ≥3,000 条 → 需「文档→指令」合成 + 人工抽检；
2. **无评测集**：需构建 200 条人工标注评测集（准确/引用/拒答/幻觉）；
3. **无拒答样本**：需要「不构成投资建议/需过四关/数据不足」的负样本；
4. **风格不统一**：博主口语风格需清洗为规范答题体。

## 三、训练数据构造方案
### 3.1 任务类型与配比
| 任务 | 占比 | 数据来源 | 示例 |
|---|---|---|---|
| 概念解释（是什么） | 35% | 400 卡 + 单元 | 「什么是均线粘合？」 |
| 战法/方法要点（怎么做） | 25% | 单元 + 方法论卡 | 「平台突破的确认条件？」 |
| 因子/回测常识 | 15% | 因子报告 + 结论 | 「平台整理因子的 IC 怎么算？」 |
| 数据口径/PIT | 10% | 数据字典 + 治理报告 | 「为什么不能用未来数据？」 |
| 拒答/边界 | 10% | 规则模板 | 「帮我推荐明天涨停股」→ 拒绝 |
| 引用/溯源 | 5% | 卡片/结论 | 「这条结论来自哪里？」 |

### 3.2 样本格式（JSONL，ChatML）
```json
{"messages":[
  {"role":"system","content":"你是零界量化知识助手。只依据提供的知识库回答；给出引用；不确定时说明置信度；不构成投资建议。"},
  {"role":"user","content":"什么是均线粘合？"},
  {"role":"assistant","content":"均线粘合指 MA5/MA10/MA20/MA60 相互靠近、离散度低。常用度量：std(MA5,MA10,MA20,MA60)/MA20。它描述的是「方向待选择」状态，不直接等于买入信号。\n来源：学习卡《均线粘合》；置信：多源（6 源）。"}
]}
```

### 3.3 数据生成流水线
1. **直接转换**：400 卡 → 400 条 QA（q/a/来源自动填充）；
2. **LLM 合成**：从 2,204 单元按主题抽取 → qwen3.5:9b 生成 3–5 个问答对 → 规则过滤（答案必须来自原文）→ 人工抽检 10%；
3. **结论转述**：Top100 结论 → 「结论+置信+可执行性」问答；
4. **拒答模板**：投资建议/预测个股/保证收益/无来源问题 → 统一拒答话术；
5. **去重与防泄漏**：概念去重（复用 knowledge_dedupe）、按来源博主切分 train/val/test（防泄漏）；
6. **规模**：目标 **3,000–4,000 条** SFT（训练 2,700 / 验证 300 / 测试 200 人工标注）。

### 3.4 数据质量门
- 抽样 10% 人工复核（事实正确、引用可查、不越界）；
- 答案必须能在知识库找到依据（否则丢弃）；
- 禁止出现个股买卖建议、收益承诺、未来数据；
- 每条样本带 `source` 字段（卡号/单元/来源文件+行号）。

## 四、基座与微调方法
| 方案 | 配置 | 可行性 |
|---|---|---|
| **A. qwen3.5:4b + QLoRA（推荐先用）** | 4bit NF4、LoRA r=16/α=32、lr 2e-4、2 epochs | 7.2GB VRAM 可跑通，1–2 小时/千条 |
| B. qwen3.5:9b + QLoRA（4bit + CPU offload） | 同上，batch=1 + grad accumulation | 显存紧，慢 2–3 倍，可夜间跑 |
| C. 云端微调（如提供） | API/托管 | 需确认服务与数据合规；暂不依赖 |
| D. RAG-only（基线） | bge-m3 + Top-k | 零训练成本，作为对照 |

**结论**：先 A 做 pilot（1,000 条），验证数据/流程；再决定是否上 9b。

### 训练参数（pilot）
- 框架：PyTorch + peft + transformers（或 llama.cpp LoRA）
- max_seq_len 2,048；packing 开；grad ckpt 开
- batch=2 × grad_acc=8；lr 2e-4 cosine；warmup 3%；epochs 2
- 早停按验证 loss + 人工评测

## 五、评估方案
| 指标 | 方法 | 目标 |
|---|---|---|
| 概念准确率 | 200 条人工标注测试集 | ≥85% |
| 引用可追溯率 | 回答中来源能对上知识库 | ≥95% |
| 拒答正确率 | 50 条越界问题 | ≥90% |
| 幻觉率 | 无依据陈述占比（人工） | ≤5% |
| 结构化输出 | JSON/要点格式合规 | ≥95% |
| 对照 | RAG-only vs SFT vs SFT+RAG | 后者不低于前者 |

**评测集独立**：从训练切分出的博主/书里各留 20%，另加 50 条人工编写边界题。

## 八、风险与合规
1. **幻觉/越界**：拒答样本 + 输出约束 + 上线影子期；禁止买卖建议；
2. **数据泄漏**：按来源切分，评测集不进训练；
3. **数据不足**：先 4b pilot，不足不硬上 9b；
4. **合规**：学习资料版权/来源标注；不传播原文长段落；不构成投资建议；
5. **模型漂移**：版本+评测基线，季度复评。

## 九、验收标准（DOD）
- [ ] SFT 数据集 ≥3,000 条，10% 人工抽检通过；
- [ ] 200 条测试集：概念准确≥85%、引用≥95%、拒答≥90%、幻觉≤5%；
- [ ] SFT+RAG 优于 RAG-only（至少 2 项指标）；
- [ ] 模型/数据/adapter 版本化，可回滚；
- [ ] 老田抽检 50 条签收；
- [ ] 边界声明与拒答话术上线。

## 十、当前结论
**可以启动，但先补数据**：现有 400 卡 + 2,204 单元只够 pilot；正式微调需先合成到 3k+ 并建 200 条评测集。建议按 P0→P1 先跑 4b QLoRA pilot，再决定 9b。
