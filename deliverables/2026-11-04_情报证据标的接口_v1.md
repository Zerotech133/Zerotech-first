## 2. 契约（v1）——exact / candidate 严格分离

| 类别 | origin layer | 判定依据 | 是否计入覆盖 |
|---|---|---|---|
| **exact** | `text_extract` | title/content 含 A 股 6 位代码字面（`SH600519`/`600519.SH`/`600519` 等） | 是 |
| **exact** | `stocks_code` | `news.stocks` 字段条目本身是 A 股代码字面（采集侧结构化精确代码） | 是 |
| **candidate** | `text_name_map` | title/content 命中名称表股票名 → 代码（名称推断） | 否 |
| **candidate** | `stocks_name_map` | stocks 字段名称条目经名称表映射 | 否 |
| **candidate** | `jev_model_code` | JEV（LLM 判定）`companies` 中的代码字面——**模型层，仍为候选，不升级 exact** | 否 |
| **candidate** | `jev_model_name` | JEV `companies` 名称经名称表映射 | 否 |

硬规则：
1. **candidate 永不升级 exact**；同一新闻同一标的存在 exact 证据时，候选条目被丢弃（不重复、不升级）。
2. **exact 只认"字面代码"**：文本/`stocks` 字段自身含 A 股代码；任何经名称映射或模型推断的结果一律 candidate。
3. **JEV 模型层一律候选**（即使 `companies` 值是代码字面）：遵循 IL-13「名称/模型仅候选」；
   模型层当前贡献 15,855 个候选 origin。若要升 exact 属口径变更，需 ADR/评审，不在本单。
4. **provenance**：每条关系含 `news_id / source / ts / title / url`（news 表无 url 字段 → 置 null，待源链接入）
   + `origins`（layer/rule/derived/matched_name/model）+ `staging_confirmed`。
5. **稳定分页**：`--code` 的 exact/candidate 两个列表各自按 `(ts DESC, news_id ASC, target ASC)` 排序，
   `--limit/--offset` 可复跑；两分类分页互不混合（JSON 中 `exact`/`candidate` 两个独立分页对象）。
6. **fail-visible**：空结果正常返回空列表（rc=0）；坏 stocks/jev JSON、staging 坏行/不一致、
   名称表缺失（candidate 层不可用）、回源抽样 <95% 均写入 `failures`/`warnings` 并置
   `partial_failure=true`；`--strict` 时 rc=3。坏行不中断、计数真实、给样本。
7. **只读**：`file:<abs>?mode=ro` + `query_only=1`；无写 SQL；不写 news.db / 生产库 / 不起停服务。
8. **质量闸**：staging 对拍（前序 v1 产物 vs 当前离线抽取，2016 口径）与回源抽样（按 news_id 重取行 +
   锚点校验）双保险。

## 7. 只读证据（无 news.db / 生产库写入）

1. 连接一律 `sqlite3.connect("file:<abs>?mode=ro", uri=True)` + `PRAGMA query_only=1`；
   工具内无 INSERT/UPDATE/DELETE/DDL；JSON 输出 `readonly=true` 且 `db.uri` 含 `mode=ro`。
2. 测试 `test_readonly_uri_and_no_db_write`：运行前后临时库 SHA256 不变；对工具连接执行
   INSERT/UPDATE 均抛 `sqlite3.OperationalError`；`PRAGMA query_only==1`；`readonly_uri` 含 `mode=ro`。
3. 生产活库无法做前后哈希归因（其它进程在写），故对 news.db 副本做字节级验证：
   `--db <副本> --stats --json` rc=0，副本 SHA256 前后一致：`85c7586d4826b5ed…`。

## 8. 未做 / 风险（如实）

1. **portal API 属 IL-13 后半**：`portal/api_intel_evidence*` 未在本单实现（另单）；本工具是
   其数据/契约基础，可直接 import 或子进程消费其 JSON。
2. **provenance.url 为空**：news 表无 url 列，当前用 id/source/ts/title 回源；如需原文链接需
   接源表/原文抓取表（另单）。
3. **JEV 模型层口径**：`jev.companies` 即使给代码字面也一律 candidate（遵循"模型仅候选"）；
   若业务要把它当精确证据，属口径变更需 ADR/评审。
4. **candidate 召回有天花板**：依赖本地名称表（11,311 条，2026-10-08 快照、gitignored 数据根），
   词表/别名不足会漏召回；名称歧义 9,348 行 ambiguous 未做人工消歧。
5. **指数/数字巧合风险**：exact 仅认"字面 6 位 A 股代码"，`000001`（上证指数 vs 平安银行）等
   指数代码无法从数字本身区分（`000852` 等同理）；如用于交易域需加指数黑名单/语境判定。
6. **92 开头北交所新码不支持**：按 canonical 口径（60/68/90→SH、00/30→SZ、8/4→BJ），
   `920xxx` 返回 None 并 rc=2（`--code 920964` 实测），需口径升级后同步支持。
7. **性能**：`--stats`/`--sample` 全量扫描约 5.5s（12 万行 × 文本抽取 + 名称匹配 + JEV 解析），
   `--code` 走 SQL LIKE 预筛约 0.6s；portal 高频调用需另做缓存/进程内索引（未做）。
8. **时间过滤**依赖 `news.ts` 文本字典序（格式统一 `YYYY-MM-DD HH:MM`，快照内无坏格式）；
   无 ts 行在范围过滤时排除并计入 `rows_missing_ts`（fail-visible）。
9. **排序/分页**按 `(ts DESC, news_id ASC, target ASC)` 稳定；跨快照新增新闻会使 total 变化，
   分页一致性只在同一快照/同一 command 内保证。
10. 未做 `--since/--until` 与 `--sample` 的生产组合实跑证据（工具支持且单测覆盖分页/过滤；
    抽样命令在无过滤下验证）。
