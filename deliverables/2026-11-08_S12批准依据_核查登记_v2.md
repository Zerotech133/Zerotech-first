## 3. 为什么 v1 会漏检（检索方法缺陷，两层）

### 3.1 工具层：Glob / Grep 静默跳过 gitignore 目录

| 事实 | 证据 |
|---|---|
| `zerobound-kg/` 是**独立 git 仓库** | 目录内有 `.git`（目录，非 worktree 指针文件） |
| 主仓**不跟踪**它的任何内容 | `git ls-files zerobound-kg/ \| wc -l` = **0** |
| 主仓 `.gitignore` 明确排除整个目录 | `git check-ignore -v` → `.gitignore:265:zerobound-kg/` 命中 |

因此 `Glob **/*APPROVAL*20261108*` 与 `Grep` 均**无匹配且不报错** —— 工具遵循 ignore 规则，
把整棵子树当成不存在。这是**静默跳过**，不是「文件不存在」。

**教训**：在含独立子仓/被 ignore 子树的仓库里做「全仓检索」，不能只用 Glob/Grep；
必须补 `git -C <sub> ls-files` 或直接 `ls` 到受忽略目录，否则结论会系统性偏向「不存在」。

### 3.2 我自己层：没交叉核对 registry 的 `ticket` 字段

`strategy_registry.json` 的 `approval.ticket` 早已写明路径线索 **「（factor_proto/）」**。
v1 核查只读了 `ledger.jsonl` 的 `approved_by`，没有回到 registry 交叉核对 `ticket`。
**两个引用方都指向同一份文件，其中一处已给出目录名，我却只查了另一处。**
