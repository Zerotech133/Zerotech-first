## 2 五要素

### 2.1 命令全文

一条 dry（不提权也能跑，只读），一条 apply（**提权**），一条回滚（**提权**）。

```powershell
# ① 干跑：看现状 + 看将写什么，不动任何东西（不需要提权）
powershell -NoProfile -ExecutionPolicy Bypass -File C:\aios\ops\fix_watchdog_8099_20261107.ps1 -DryRun

# ② 应用（在「以管理员身份运行」的 PowerShell 里执行）
powershell -NoProfile -ExecutionPolicy Bypass -File C:\aios\ops\fix_watchdog_8099_20261107.ps1 -Apply

# ③ 回滚
powershell -NoProfile -ExecutionPolicy Bypass -File C:\aios\ops\fix_watchdog_8099_20261107.ps1 -Rollback
```

只想要三端口（不含 9899）：第 ② 条加 `-NoCow`。

脚本自身已做的三件事（无需你另跑）：

1. **备份**：`backups\watchdog_20261107\task_8099_<时间戳>.xml`（UTF-16，能直接回灌）；
2. **改完自证**：重新 `Export-ScheduledTask` 逐项比对 `args / picks 守卫 / WorkingDirectory / 执行上限 / 登录类型`，任一项不符即 `exit 1` 并提示回滚；
3. **立刻触发一次并观察 60s**：8095 是否 LISTEN、`C:\Temp\watchdog_9899.log` 尾部、下次触发时间与 rc。

脚本是**纯 ASCII**：任务名靠 `Get-ScheduledTask | ? TaskName -like '*8099*'` 解析，路径全走 `C:\aios`
junction（与仓库根同一 inode），所以不受 PS 5.1 中文编码影响。

### 2.2 影响面

| 项 | 评估 |
|---|---|
| 每跳开销 | 四口都活着时 = 4 次本机 TCP 探活，**约 10ms**，无 sleep |
| 首次执行 | 拉起 `publish_schedule_server.py --bg`(8095) 与 `CowAgent app.py`(9899)。**8095 不补跑**：命中判据是「`HH:MM` 精确匹配 + 当日去重」，错过不追 → 首个动作在下一个 16:45 或 23:45 |
| 最坏耗时 | 四口全死 **99.0s**（替身时钟实测：3×18s + cow 45s，预算在 99s 处截断），上限 PT3M=180s，余量 81s。**无预算时这轮是 132s，会顶爆 PT2M** |
| 对 8097/8099 | 活着直接 return；8097 另有独立任务（PT5M），本单是冗余加固 |
| 失败模式 | `Set-ScheduledTask` 是单次原子替换；被拒时任务保持原状，不会半改 |

### 2.3 不可逆点

| 点 | 缓冲 |
|---|---|
| Action 被覆盖 | 改前 XML 两份独立留存（`backups\watchdog_20261107\` + 脚本每次运行新存一份）；`-Rollback` 一条命令还原 |
| 执行上限 PT2M→PT3M | 回滚脚本同批改回 PT2M；上限放宽只影响"卡住时多占一次触发槽"（`IgnoreNew` 不会堆积） |
| 8095 恢复出报 | 16:45/23:45 会真跑一键链，线上若仍滞后会**发飞书红卡**——这是恢复设计行为，红卡本身即信息 |
| **8099 短暂受影响** | 改完即触发一次，本次执行会以新 Action 跑（正常约 1–2s，因为 8099 活着）。若新代码有异常，最多影响一跳，下一跳（5 分钟后）仍会跑（Action 已是新串，需回滚才恢复） |
| 不涉及 | 不改文件、不改触发器、不改身份、不重启机器、不碰 10.205.0.118 |

### 2.4 替代方案（含为何不选）

| 方案 | 结论 | 理由 |
|---|---|---|
| **A 新建独立任务「8095 看护」** | 不选 | 本机 `schtasks.exe` 命中 WorkBuddy 沙箱程序黑名单（不可绕过）；且多一个任务多一处漂移 |
| **B 并入 8097 守护任务** | 不选 | 同样要改 Action，且让 8097 的守护依赖 8095 状态，耦合方向错 |
| **C 压 cow 宽限 60s→30s 再并入** | **不采用（V1 建议，已否决）** | 压宽限=拿"假复活失败"换安全：CowAgent 冷启慢时会在 30s 判失败而进程其实还活着。真病根是"任一守卫可吃满自己宽限、串行叠加"，用**全局预算**（`BUDGET_S=100s` monotonic 截止）解决，不弱化任何单口判据 |
| **D 只手动拉起 8095** | 不选 | 会再次裸死（10-15 以来的形态）；且会话拉起的进程随会话结束被收割，会造"拉过=修好"的假绿 |

### 2.5 回滚预案

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File C:\aios\ops\fix_watchdog_8099_20261107.ps1 -Rollback
```

回滚把 Action 还原为 `m.guard_km_hub()`、上限还原 `PT2M`。**回滚判据**（一条命令验真）：

```powershell
$x = [xml](Export-ScheduledTask -TaskName 'AI工作站知识库守护8099')
$a = $x.Task.Actions.Exec.Arguments
"main=" + ($a -like '*m.main()*') + " km=" + ($a -like '*guard_km_hub()*') + " limit=" + $x.Task.Settings.ExecutionTimeLimit
```

期望：应用后 `main=True km=False limit=PT3M`；回滚后 `main=False km=True limit=PT2M`。

> 回滚**不会**关掉已拉起的 8095/9899——端口保持现状，要停需另跑 `taskkill`。
> XML 级回灌（更彻底）：`Register-ScheduledTask -TaskName 'AI工作站知识库守护8099' -Xml (Get-Content <备份>.xml -Raw)`，需提权。
