## 二、汇报口径五段（成文定义）

```python
build_report(combo_ids=None, *, plan_db=None, registry_path=None, ledger=None,
             receipts=None, reviews_by_combo=None, posterior_by_combo=None,
             findings=None, month=None, snapshot_db=None, clock=None) -> dict
render_markdown(report) -> str      # 015 推送侧可直接贴
render_json(report) -> str          # 稳定 JSON（键排序，供归档复现比对）
```

| 参数 | 含义 | 缺省 |
|---|---|---|
| `combo_ids` | 组合 id 列表 | `None` → 二三四段标「未接入」 |
| `plan_db` | -006 版本账/会议账 sqlite 路径 | `None` → 一段标「未接入」 |
| `registry_path` / `ledger` / `receipts` | -003 / -011 / -007 账路径（透传 -013） | 各模块默认 |
| `reviews_by_combo` | `{combo_id: -008 compare_reviews 输出}` | `None` → 三段无分支留痕 |
| `posterior_by_combo` | `{combo_id: 后验收益}` | 缺 → ROI `pending_backfill` |
| `findings` | **-0.2 每日三查 findings 列表**（只读消费） | `None` → 五段标「未接入」 |
| `month` | 成本归月 `YYYY-MM` | 当月 |
| `snapshot_db` | -004 快照库路径（透传 -013） | `None` → 不读 |
| `clock` | 报表生成时刻 ISO 文本 | `None` → 当前时刻 |

### 段一 · 本期研究了什么（读 -006）

| 字段 | 口径 |
|---|---|
| `plan_versions_total` / `plan_stocks_total` / `plan_combos_total` / `plan_chained_total` | 预案版本数 / 覆盖个股 / 覆盖组合 / 版本链续版数（`prev_version` 非空） |
| `meetings_total` | 会议场次 |
| `conclusions` | 结论分布（`maintain` / `revise` / `veto`，-006 白名单） |
| **`divergence_rate`** | **分歧率 = 结论非 `maintain`（`revise`+`veto`）的会议占比** |
| `dissent_items_total` | 会前分歧条目合计（`-006` 写入时 `dissent` 必填非空） |

**分歧率为何不取「有无 dissent」**：-006 的 `dissent` 是写入必填项，恒为真，当判据即废指标。故取「结论是否因分歧而改动」，并在 `divergence_formula` 字段把算式**明示写进输出**，不靠读者猜。

会议场次为 0 → `divergence_rate = null` + `divergence_note` 说明（**不以 0 充数**——0 会被读成「零分歧」，是造数）。

### 段二 · 模拟达到什么（读 -013）

逐组合：收益 / 收益状态 / 当月成本 / ROI / ROI 状态。**ROI 三态直通**：

| roi_status | 呈现 | 说明 |
|---|---|---|
| `computed` | 数值（`is_number=true`） | 收益 − 算力成本，单位可比 |
| `pending_backfill` | **原样透出状态词**，不填 0 | 后验收益缺失 |
| `unit_mismatch` | **原样透出状态词**，不填 0 | 收益与成本单位不可相减 |
| 其他（未登记口径） | 原值 + `（未登记口径）` | 不臆断语义 |

**绝不把 null 当 0 渲染成「打平」**——0 的语义是「白干且不亏」，与「不知道」是两回事。测试断言 ROI 列不含 `| 0 |`。

### 段三 · 各分支状态对比（读 -008 + -007）

逐分支（跨组合按 `branch_id` 聚合）：`decisions` / `executed` / `abstained` / `divergence_traces` / `posterior_available` / `posterior_pending_backfill` / `reason_codes` 计数 / `plan_versions`。

- **分歧留痕口径**：该决策带 `deviation` 记录（-008 输出 `deviation` 非空），明示于 `divergence_formula`；
- **四类回执 4/4 达成率**：`-007` `completeness`，`rate_4_of_4 = signals_full_4_of_4 / signals_total`，分母 0 → `null`。

### 段四 · 成本与预算（读 -011 口径，经 -013）

逐组合：预算 / 当月累计 / 剩余 / 超预算 / 预算是否已登记。合计：

- `cost_accumulated` 照实求和；
- `budget` —**任一组合预算未登记则合计记 `null`**（不可把部分组合的预算之和当全量预算），`budget_complete=false` 并列出 `unregistered_combos`；
- `over_budget_count` / `unregistered_count` 如实计数。

### 段五 · 红黄绿告警（只读消费 -0.2 三查 findings）

| severity | 灯色 | 类别映射 |
|---|---|---|
| `P0` | 🔴 红 | `ledger_freshness` → 账本断线；`consumer_chain` → 消费链停摆 |
| `P1` | 🟡 黄 | 同上 |
| `P2` | 🟢 绿 | 同上 |

- 账号命中 `acceptance_check.HK_ACCOUNTS` 的条目另打**灰度标**（类别前缀「灰度/」，口径引 -0.2 不另立名单），对应工单点名的**灰度异常**；
- 零 findings → `verdict = 全绿`（**不虚报异常**）；
- 未知 `severity` → 绿（不误报为红）；未知 `check` → 「其他三查项」（不臆造类别名）。

### 章节缺失显式标注（禁静默省略）

每段带 `status` 三态 + `reason`：

| status | 含义 | Markdown 呈现 |
|---|---|---|
| `ok` | 有数据 | 正常出表/出数 |
| `not_wired` | 未接入（未喂入数据源） | `（未接入：<reason>）` |
| `no_data` | 已接入但源内无数据 | `（无数据：<reason>）` |

**五段标题恒出现**——宁可写「未接入」，也不让读者把「没数据」误读成「本期无异常」。这是本单最容易被绕过的一条，故列为硬验收。

## 三、DRYRUN 边界（本单铁律）

1. **只生成文本**：模块无任何推送代码路径，Markdown 头部恒带 `DRYRUN — 未推送真实出口（015 待授权）`；
2. **零真实出口**：stdlib-only（`json`/`re`/`sqlite3`/`datetime`/`pathlib` + 板块内模块），**禁 import 飞书 SDK**；全链路在 socket/urlopen 钳制下跑通（沿用 -008 判例）；源级断言无 `feishu`/`webhook`/`urlopen`/`urllib`/`requests.`/`socket`/`httpx`/`aiohttp`/`notify_`/`send_message`/`lark` 字样；AST 核对 import 白名单；
3. **输出永远不含实盘字段**：`_assert_no_live_fields` 递归守卫——键名命中 `(^|[_-])(live|real|realized|broker|settled|actual)([_-]|$)` 或含「实盘」即抛 `ReportError(live_field_forbidden)`。**只查键名不查值**：值里自然可能出现这些词（如 `scope.out_of_scope` 显式列出「不含」清单），但键一旦叫 `live_pnl` 就是口径越界；
4. **payload 即 015 的输入形状**：`outlet.pushed=false` / `outlet.target=null` / `outlet.pending_ticket="WO-QT-20261020-015"`。

### 失败语义（closed on failure）

| reason_code | 触发 |
|---|---|
| `combo_ids_invalid` | `combo_ids` 非 list/tuple |
| `upstream_review_failed` | 上游 -013 抛错（组合未注册 / 账本损坏），带 `[原 reason_code]` 透传 |
| `findings_invalid` | findings 非 list 或元素非 dict |
| `dissent_corrupt` | -006 `dissent_json` 非法 / 非 list |
| `plan_ledger_query_failed` | -006 查询失败 |
| `live_field_forbidden` | 输出命中实盘字段 |

一律显式抛 `ReportError`，**禁静默降级、禁填 0 充数**。
