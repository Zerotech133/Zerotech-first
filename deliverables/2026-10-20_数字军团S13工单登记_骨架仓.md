## WO-LEGION-S13-01 · `file_lock` 锁文件句柄在 Windows 多进程竞争下偶发 EACCES

| 触发现象 | 全量回归 `514 passed / 1 failed`：`tests/test_gate_persistence.py::test_cross_process_append_keeps_ledger_parseable` |

### 现象（实测）

`4 子进程 × 8 条并发 submit` 时，子进程在 `roles/base_agent.py:788` `fh = lock_path.open("a")` 抛：

```
PermissionError: [Errno 13] Permission denied: '...\ledger.jsonl.lock'
```

异常经 `_append_locked` → `submit` 上抛，子进程 `returncode=1`，该次落单**失败**。

### 复现率（实测，非估计）

单测独立重跑 11 次：**3 次失败 / 8 次通过（≈27%）**。三次失败堆栈形态完全一致，同一定位点。
日志：`C:/项目/logs/legion/s13_repro1.log`。

### 已执行的根因排除（实测证据）

| 假设 | 实验 | 结果 | 结论 |
|---|---|---|---|
| msvcrt 区间锁与 `open("a")` 冲突 | 4 进程 × 300 轮 `open("a")`+`LK_LOCK`/`LK_UNLCK` | 1200 次 0 失败 | 排除平台锁本身 |
| `%TEMP%` 目录属性/实时扫描 | 同探针改到 `%TEMP%` 下重跑 | 2400 次 0 失败 | 排除 TEMP 目录特异 |
| 真实路径高频压力即复现 | 真实 `ApprovalGate.submit`，4 进程 × 60 轮 × 2 trial | 480 次 0 失败 | 排除"仅高并发即触发" |
| pytest 时序特有 | 仅 pytest 下 8 轮即 27% 复现 | 复现 | **成立** |

探针：`logs/legion/probe_filelock_eacces.py`、`logs/legion/probe_real_submit.py`；结果：`probe_result.log`、`probe_temp.log`、`probe_real.log`。

**根因判定（保留不确定）**：`CreateFile` 在「多进程几乎同时首次创建同一锁文件 + CPU 密集 import 竞争」的窄窗口下返回 `ERROR_ACCESS_DENIED`，CRT 映射为 `EACCES`。
已确认**不是** `LockFile` 区间锁冲突，**不是** 目录属性，**不是** 单纯高频。剩余未解释的是「为何仅 pytest 环境的启动时序命中」——`pytest` 下 4 个子进程同时 import prometheus/fastapi，`open` 恰好落在创建窗口内。

### 处置方案（不改锁语义、不改账本格式）

`file_lock` 打开锁句柄改为**有限次退避重试**：

- 仅对 `PermissionError`（EACCES）重试，`FileNotFoundError` 等其它异常立即上抛（不掩盖真故障）。
- `LOCK_OPEN_RETRIES = 5`，退避 `5/10/20/40 ms`（合计上限 ≈75ms），复用本文件既有 `PENDING_REPLACE_BACKOFF_S` 的指数退避风格。
- **重试成功须留痕**：`LOG.warning` 记录 `attempts`，使"环境有竞争"可被运维观测，不静默吸收。
- **耗尽后抛原异常**（保留 errno 与路径），**绝不降级为无锁**——跨进程互斥是账本正确性的前提，退成无锁等于用正确性换可用性。

### 明确不采纳

- ✗ 降级无锁（`file_lock` 已有 fallback 分支仅用于「平台锁模块不可用」，不得为 EACCES 复用）。
- ✗ 放宽测试断言（`returncode == 0` 是该用例的核心断言，放宽即失去检出能力）。
- ✗ 加重试期间"先写后校验"或"失败转 pending 重投"——本函数职责只是取锁，落单失败须在调用方可见。

### 验收判据

1. `test_cross_process_append_keeps_ledger_parseable` 连续 **20 次** 全绿（修复前 11 次 3 红）。
