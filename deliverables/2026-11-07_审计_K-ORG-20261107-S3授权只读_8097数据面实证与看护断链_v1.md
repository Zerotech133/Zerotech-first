## 4 缺陷① 重新定性：cwd 不是根因（状态：异常，且比预想更深）

原判「改一行 cwd 就能修」不成立。三条实证（均在 `quant_backtest/` 下执行）：

| # | 命令 | rc | 输出 |
|---|---|---|---|
| A | `git add -n _manifest.json`（现状） | **128** | `fatal: pathspec '_manifest.json' did not match any files` |
| B | `git add -n data/tushare/_manifest.json`（cwd 修好） | **1** | `The following paths are ignored by one of your .gitignore files: quant_backtest/data` |
| C | `git status --short -- data/tushare/_manifest.json` | 0 | **空** → 脚本恒判 `no_diff` |

根因有两层，不止一层：

1. **路径层**：`run()` 写死 `cwd=str(QB)`（`quant_backtest/`），却 `git add "_manifest.json"` —— 真实文件在 `data/tushare/_manifest.json`。
2. **可见性层（更硬）**：`_manifest.json` 所在的 `quant_backtest/data/` 被 `.gitignore:27` **整体忽略**，且 `git ls-files` 证实该文件**从未被跟踪**。所以即便路径改对，`git add` 仍 rc=1；`git status` 仍空；报告仍写 `no_diff`。
3. **信号层**：`git add` 的 rc **未被检查**，失败被吞，最终以「manifest 无变更」形态输出。

**假信号实证**：今天 13:09:11 那次运行（正是补 11-05/11-06 日线 5573 行的那次）报告为
`{"status":"OK","git_commit":"no_diff"}` —— 数据确实写了，却对外声称「无变更」。

**另需注意**：即使强行恢复自动提交，会与 **2026-11-06 主工作区只读治理**相撞（`.git/hooks/pre-commit` WB-GUARD，audit 模式，已留痕 164 行）。每夜从主工作区自动提交 = 每天往违规台账里加记录。
