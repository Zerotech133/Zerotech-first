- 设计工位：ws-doc（纯文档工位，未改任何代码）｜日期：2026-10-19
- 性质：**本稿仅设计，不实施、不动生产**。文中一切"建议/拟"均为设计稿，落地前须按 §七 走报批；未获批准前不写任何证据链库、不改任何接线代码。

## 一、状态机现状与证据

### 1.1 状态机本体（已入库，未接线部分只读沿用）

- 四态定义与合法跃迁表：evidence_chain.py:43-58。**线性链，其余一律非法**：

```
None → pool_in → authorized → pool_out → result → (终态，无后继)
```

- 非法跃迁抛 IllegalTransitionError（evidence_chain.py:65-70、170-171）；同 entry+state 重放同内容 → outcome=replayed 幂等返回（152-158）；同 entry+state 不同内容 → ConflictError 粘性，须人工介入（73-81、162-169）。
- 幂等键格式 `evidence:<entry_id>:<to_state>:<payload_hash[:16]>`（make_idempotency_key，evidence_chain.py:94-96），哈希取 canonical JSON 的 sha256（84-91）。
- entry_id=`{strategy}:{trade_date}:{symbol}`（make_entry_id，evidence_chain.py:99-101），strategy 段由 evidence_intake 以 contributions 键排序"+"连接保证可重现（evidence_intake.py:39-47）。
- append-only：evidence_events 只增不改不删，DDL 触发器强制；evidence_state 为投影，可 rebuild_state 全量重建（evidence_chain.py:14-15、249-277）。
- 写入事务 BEGIN IMMEDIATE + COMMIT/ROLLBACK（evidence_chain.py:175-200）——原子写判例沿用。

### 1.2 pool_in 态：已接线（现状）

- 接线点：SignalAggregator.run() 成功路径尾部，persist 完成/降级后的完成点，evidence_intake.record_pool_intake(trade_date, result)（aggregator.py:461-469，提交 2efa8282）。
- closed on failure 铁律：证据链是观测层，任何失败（模块缺失/库打不开/单票异常）一律内部捕获、WARN 降级继续，绝不向融合主链抛异常（evidence_intake.py:17-20；aggregator.py:462、467-469）。
- 幂等：同日同票同内容重跑 → replayed 不重复记账；ConflictError 捕获计 conflict 跳过，绝不外抛（evidence_intake.py:13-15、160-162）。
- 测试安全联锁：pytest 进程未显式给 db_path 时拒绝默认库（evidence_intake.py:70-84、129-133）。

### 1.3 后三态：均未接线（本稿设计对象）

- 全仓 grep `transition(` 调用点：仅 evidence_intake.py:154（pool_in）与 xunyou.py 只读查询（read_evidence_state，xunyou.py:297-312，get_state/get_history，纯只读不写）。authorized/pool_out/result 无任何写入方。**待核实**：是否存在计划中的其他工位接线稿（本稿未读到他方设计在途件）。

## 二、authorized 态设计（人工授权留痕）

### 2.1 语义

authorized = 该入池票获得"出池/后续动作"的授权单引用。evidence_chain.py:45 已定义语义："授权：出池/后续动作的授权单引用"。

### 2.2 触发方纪律（荀攸只读红线）

- **荀攸（xunyou）只读不写**：xunyou.py 对证据链仅有 read_evidence_state 只读工具（xunyou.py:297-312，EvidenceChainStore(read_only=True)）；荀攸的定位是 RESEARCH_ONLY_NOT_PRODUCTION / BLOCK_CUTOVER（export_xunyou_latest.py:5-7）。**授权态的写入方必须是人工（老田）或上级代理，绝不可能是荀攸自身**——这是"参谋只读、指挥授权"的角色分离，建议在接线实现中硬编码校验 actor 白名单（如 `actor in {"laotian", "superior-agent"}`），传入其他 actor 直接拒绝记账。
- 人工授权动作来源（现状盘点，均带证据）：agent_platform 审批体系（evidence_chain.py:9 自述幂等键"对齐平台 approvals 判例"）。**待核实**：portal/approvals 或 agent_platform approvals 是否已有"选股票池授权"类审批单型可挂靠（本稿未逐页排查审批单模板注册表）。

### 2.3 payload 规范（设计）

```json
{
  "approval_ref": "<审批单号或批准凭据 ID>",   // 必填：指向人工批准凭据，可回查
  "approver": "laotian",                       // 必填：触发者（与 actor 一致性校验）
  "approved_at": "<ISO8601>",                  // 必填：批准时点
  "scope": "pool_out",                          // 授权范围（本机四态下即出池授权）
  "_meta": {"symbol": "...", "trade_date": "...", "strategy": "..."}  // 投影列沿用
}
```

- **幂等性**：天然获得——同一张批准单重复导入时 payload 全同 → replayed（evidence_chain.py:152-158）；批准单号不同即 payload_hash 不同 → 同 entry+state ConflictError 粘性人工介入（162-169），恰好把"一票两张冲突授权单"拦下来交给人工。建议批准单号唯一化由上游审批体系保证。
- **留痕查询**：get_history(entry_id) 即可回放"谁选的（pool_in payload）→ 谁批的（authorized payload）"全链（evidence_chain.py:220-224）。

## 三、pool_out 态设计（触发点枚举）

语义（evidence_chain.py:46）：出池=移出清单，附原因。entry 生命周期上 pool_out 发生在该票**不再在后续有效清单中**之时。触发点枚举与数据来源：

| # | 触发点 | 数据来源与判定 | 调用时机建议 |
|---|---|---|---|
| 1 | **TOXIC 降档出池** | 毒层判定已有判例：picks 链 `TOXIC_EXCLUDE`（portal/build_todays_picks.py:60）、信号层 `TOXIC_DOWNGRADE`/`TOXIC_SCORE_CAP` 毒层 score 封顶 60（docs/plans/2026-10-19_选股策略独立化与选股Agent_M0计划.md:117、149 `_toxic_reason`）。对 signals_combined 链，毒层票在**融合/信号产出时即被降档**（降档发生在 pool_in 之前）——故本触发点对证据链的正确接线位是：**降档票的 pool_in payload 内标注 toxic_reason（evidence_intake.build_intake_payload 增字段），而非事后 pool_out**；若某票先入池、次日复查才发现毒层属性，才走 pool_out(reason="toxic_recheck") | 复查任务（如 a4_xunyou_vs_picks_probe 同源的盘后对拍作业）发现时点；actor=system |
| 2 | **过期闸门出池** | picks 链有 ">4 天整源闸门"判例（deliverables/StrongEod恢复0630_五要素报批单_20261019.md:63 TodaysPicks 实证）。signals_combined 链是否有等价 N 天过期闸门：**待核实**（grep quant_backtest 未见 xunyou 链 4 天闸门实现）。建议设计：盘后作业读取 evidence_state 中停留 pool_in/authorized 超 N 交易日的条目，批量 transition pool_out(reason="expired", payload={"days": N})。N 值沿用 4 交易日判例或由老田拍板 | 每日盘后作业尾部（17:45 荀攸作业之后）；actor=system |
| 3 | **同票替换出池** | 融合链已有 superseded 机制：同票预聚合传入被覆盖明细，写入 contributions[sid]["superseded"]（aggregator.py:477-480；xunyou.py:105-108 superseded_total 统计）。接线：次日融合若对同 symbol 产生新信号（新 entry_id，因 trade_date 不同自然隔离），**旧 entry 是否出池取决于业务语义**——建议保守：旧 entry 保留至过期闸门出池（触发点 2），pool_out(reason="superseded") 仅在人工确认替换语义时使用。payload 带 superseded_by=<新 entry_id> | 触发同票替换确认时；actor=system 或人工 |
| 4 | **人工移除** | 老田直接指令移除（如风控约谈、黑名单）。payload 必填 reason 文本与人工凭据（同 §二 authorized 的 approval_ref 纪律） | 即时；actor=laotian |

**通用纪律**：pool_out 的 payload 必带 `reason`（非空字符串）——与 transition 的 payload 非空校验（evidence_chain.py:144-145）叠加；reason 进哈希，改口重报即 ConflictError，杜绝"事后改理由"。

## 四、result 态设计（outcome 后验回填）

### 4.1 回填时机

- **T+5 收盘数据可得之后**：信号日 D 的 T+5 窗在 D+2 执行日（EXEC_LAG=2 判例，combined_verdicts.py:46）之后 5 个交易日收盘形成。建议接线：**每日盘后作业在跑后验（combined_verdicts 落盘）之后**，扫描 evidence_state 中 state=pool_out 且窗口已满的条目，逐条 transition(result)。
- 注意与**口径收敛拍板联动**：本态 payload 的收益字段 **outcome 回填采用拍板后的权威口径**（见 deliverables/后验口径收敛拍板包_20261019.md §四推荐方案 A：exec-d2-open-20261010 可成交口径）。payload 必须内嵌口径标注字段，防止未来口径演进后历史账本语义失真。

### 4.2 payload 规范（设计）

```json
{
  "caliber_id": "exec-d2-open-20261010",      // 权威口径 id（拍板后引用）
  "window": "t5",                              // 回填窗
  "ret": <float>,                              // 权威口径收益（百分数 2 位）
  "exec_day": "YYYYMMDD",                      // 执行日（+2 开盘判例）
  "benchmark": {"mid": <float>, "ex": <float>} // 超额对照（benchmark 可得时；不可得显式 null，禁造数）
  "_meta": {...}                                // 投影列沿用
}
```

- 收益数值来源：combined_verdicts.json 落盘档 per_code[sym].win[w]（combined_verdicts.py:337-377）——只回收不重算，与"不造数"判例一致；该档缺失/该票 pending 时**跳过不回填**（不硬凑，同 combined_verdicts.py:341-343 pending 纪律），等下个作业日重试（幂等键保证重试安全）。
- exdiv：按 verdicts 口径记 void（combined_verdicts.py:345-347），payload 带 `"void": "exdiv"`、ret=null。

### 4.3 终态语义

result 为终态（TRANSITIONS 中 S_RESULT: ()，evidence_chain.py:57）。回填后该 entry 账本封卷；后续如需更正，只能以新事件追账（append-only 判例），不允许改写。

## 五、接线点建议

| 态 | 调用模块（拟） | actor | closed on failure 落法 |
|---|---|---|---|
| authorized | 新增 strategy_layer/evidence_authorize.py（或并入审批桥接模块）；由人工授权动作的登记端调用 | laotian / superior-agent（白名单校验） | 授权登记是**人因动作的留痕**，失败应**显式报错给操作者**（这是唯一不适用静默降级的态——留痕失败还继续走，等于授权没发生却假装发生了）；但不反噬被授权的业务动作本身 |
| pool_out | 新增 strategy_layer/evidence_pool_out.py；挂每日盘后作业（荀攸作业链尾部）与人工移除入口 | system / laotian | 完全复刻 evidence_intake 判例：try/except 全捕获、WARN 打印、计数摘要返回、绝不外抛（evidence_intake.py:87-171 全函数模式照抄） |
| result | 新增 strategy_layer/evidence_result_backfill.py；挂后验落盘之后的盘后作业尾部 | system | 同上 closed on failure；**后验统计失败时证据链回填整体跳过**（观测层失败不反噬主链，也不互相反噬） |

- **接线点物理位置建议**：三态均作为独立作业模块挂在盘后链尾部（与 aggregator.py:461-469 的 pool_in 内联接线不同——后三态是日结性质，不应内联进融合主循环）。
- **库路径解析**：沿用 evidence_intake._resolve_db_path 判例（显式入参 → EVIDENCE_CHAIN_DB → 默认库；pytest 拒默认库，evidence_intake.py:70-84）。
- **只读消费**：荀攸侧继续只用 read_evidence_state 只读口（xunyou.py:297-312），后三态接线**不给 xunyou 增加任何写入口**。
