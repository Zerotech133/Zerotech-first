## 一、为什么做（盘面核实的真缺口）

沙盘的虚席招募此前**只能投一张工单**到 bridge_inbox 就结束——系统里**没有任何工具**能真正把人加进编制。
org.json 的 `agent_profiles` 是组织真源（17 部 29 员），靠手改 JSON 入编既无校验也无痕迹：
历史上已攒出 **4 对重名**（司马懿 QS1/T2、满宠 DEV4/MANCHONG1、马良 COMM1/COWBRIDGE、陆逊 BACK1/R3），
账面混淆就是这么来的。

老田要的「新 Agent 到底干嘛」在数据上就是 `charter_detail`——所以本工具把「职责必须写清」做成了**准入门槛**，不是选填项。

## 二、实施内容

### 1. `engine/org_enroll.py`（编制工具）
- `build_plan()` **只读**校验 + 产出变更计划；`apply_plan()` 写入；`rollback()` 还原。
- **准入校验（10 项，全部 fail-visible）**：
  | 校验 | 拒绝理由 |
  |---|---|
  | 部门存在 | `unknown dept: X（可选 ...）` |
  | 席位代号格式 | 须大写字母开头、2~16 位（`dev9` 被拒） |
  | 代号全局唯一 | 扫 org.agent_profiles + dept.agents + **hr 目录**，报占用位置 |
  | **中文名不得重名** | 报出被谁占用 + 历史 4 对重名的教训 |
  | role_profile 非空 | 这是「这 Agent 干嘛」的答案，不许留白 |
  | **duty ≥ 10 字** | 写不清职责就不许入编（否则新席无法被指挥） |
  | binding 在词表 | 5 种合法绑定，越界即拒 |
  | grade 在词表 | E1/E2/E3 |
  | 工单号必填且前缀合法 | 无单不写码 |
  | 放行人必填 | 改组织真源须老田签字 |
- **写路径四道保险**：① 执行前 TOCTOU 复核 id 唯一性（计划生成后真源若被改即拒）
  ② **先备份**到 `registry/backups/org-<时间戳>.json` ③ 原子写（`.tmp` + `replace`）
  ④ **写后自检**（新员在目标部门 / 总数 +1 / **其他 16 个部门深比较一字未动** / 部门顺序不变），
  任一不符**立即用备份回滚**再报错——绝不留半成品。
- 回滚：`--rollback <备份>`，须放行人；备份不可解析则拒绝覆盖真源；**hr 档案不自动删**（防误删履历）。

### 2. `POST /api/org/preview-enroll`（只读预览）
沙盘虚席弹窗提交时先调它——重名/编号占用/职责过短/绑定越界当场被拒。
**HTTP 层没有任何入编写路径**：组织真源不经 HTTP 落地，这是红线，故界面只能到「计划」为止。

### 3. 沙盘虚席弹窗改造
- 增「席位代号」输入（原表单缺此项，根本无法定位新席）。
- 模型下拉补 `value`（原 option 文本带中文说明，直接当 binding 会被词表拒）。
- 提交顺序：校验预览 → 通过才投编制工单 → 界面明确写出**「真入编须老田在命令行签字执行」**并直接给出该条命令。
  不再像原来那样含糊宣称「→ 建 hr 档案 + org 入编 → 沙盘自动落位」（当时并无此能力，属过度承诺）。
