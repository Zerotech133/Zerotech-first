## 二、改动（qualify_probe.py，+226 行）

### 2.1 新增常量

```python
JSONL_SUFFIXES = (".jsonl",)
JSONL_DATE_CANDIDATES = ("_fetched_at", "fetched_at", "created_at", "date", "ts",
                         "trade_date", "pub_date", "ann_date", "updated_at")
MAX_JSONL_FILES = 40            # 抽样文件上限（跳过 0 字节空文件后按 mtime 新→旧 + 含最大文件）
MAX_JSONL_LINES_PER_FILE = 2000 # 单文件流式行数上限（超限 truncated=true，不静默全量）
```

### 2.2 新增函数

| 函数 | 职责 |
|---|---|
| `_is_jsonl_store(entry)` | store 判定：`layout=="jsonl"` 或 store 后缀 `.jsonl` |
| `_iter_jsonl(store)` | 递归列 `*.jsonl` → (文件, 顶层文件数, 一级子目录名)，与 `_iter_parquet` 同构 |
| `probe_jsonl_store(store, entry, max_files, max_lines_per_file)` | **只读**流式探针：文件数/抽样行数/最新 mtime/日期列 max；缺失/空目录/全不可读 → fail-visible 标记 |

关键实现点：
1. **抽样上限**：跳过 **0 字节空文件**后按 `mtime 新→旧` 取前 `MAX_JSONL_FILES=40` 个，并保证含最大文件；每文件最多流式读 `MAX_JSONL_LINES_PER_FILE=2000` 行（超限 `truncated=true`）；
2. **日期列 max**：catalog `date_col` 优先（guba=`ts`）；**catalog 缺失或数据中不存在**时依次尝试 `JSONL_DATE_CANDIDATES`；命中 → `latest_source=jsonl_candidate_max`；均无 → `no_date_column`（下游 partial，不假绿）；
3. **max 归一**：复用 `date_parser()/norm_date()`（支持 `YYYY-MM-DD HH:MM:SS`、日期/时间戳等）；
4. **证据字段**：`jsonl.file_count / empty_files / nonempty_file_count / files_scanned / rows_sampled / lines_sampled / latest_mtime / latest / latest_file / date_col_used / date_source / schema_first30 / truncated / bad_lines / broken_files / error`；
5. **fail-visible reason**：`store_missing` / `jsonl_error` / `no_jsonl` / `zero_rows_sampled` / `jsonl_bad_lines`（全坏行）/ `jsonl_all_empty`（全空文件），并对 `no_latest_date`/`no_date_column`/`stale_gt_*` 走既有下游判定。

### 2.3 `probe_table` 接入

在 sqlite 分支之后、parquet 之前新增 jsonl 分支（sqlite 语义不变）：

- `card["jsonl"]` 证据块；`sample_strategy="jsonl_stream"`；`files_on_disk=file_count`；`rows_sampled`/`schema_first30` 等按实测；
- 日期可判时 `latest_source=jsonl_max`（catalog date_col）/`jsonl_candidate_max`（候选列）；
- `_summary()` / `_unsupported_reason()` 增加 jsonl 文案；`date_policy.note` 补 jsonl 探针口径（失败/空目录/坏行原因可见）。

### 2.4 实现中发现的真实坑（已修）

- 首版按 mtime 抽样时，guba 的 **432 个文件里有 237 个是 0 字节文件且 mtime 最新**（11-01 17:57）→ 抽 40 个全是空文件，日期 max=None，会误判 stale/no_date；
- 修正为**跳过空文件抽样**后：抽样 40/195 个非空文件、5148 行，`latest=20261101`；
- 交叉验证：全量只读扫描 432 文件共 **25,835 行**（与 catalog `rows=25835` 完全一致），真实 max ts=**20261101**，与抽样 max 相同 → 抽样代表性可接受；同时 `empty_files=237` 作为数据质量证据保留（正常应为 0，建议 DATA1 核实/清理）。
