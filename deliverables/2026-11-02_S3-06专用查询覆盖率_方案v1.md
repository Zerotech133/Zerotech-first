## 三、通用 query 能力设计（v1）

### 3.1 契约（三面统一，同一 engine）

```text
query(dataset_id, *, where=None, order_by=None, limit=100, offset=0, since=None,
      columns=None, count=False) -> {
  ok, dataset_id, kind, carrier, state: ok|no_data|not_supported|stale,
  columns: [...], rows: [[...]], count: int|null,
  next_offset: int|null, has_more: bool, truncated: bool,
  evidence: {engine, elapsed_ms, scanned_rows, scanned_bytes, where_applied, order_applied, since_applied}
}
```

- HTTP：`GET/POST /api/dw/query`（挂在既有 `/api/dw/` dispatcher 内，不新增顶层路由；仍需 8091 重启生效 = L2）；
- CLI：`dataset_registry_cli.py query --id ... --where 'trade_date>=20260101' --order-by trade_date:desc --limit 50 --offset 100 --since 2026-01-01`
- MCP：`dw-governance` 增第 6 个工具 `dw_query`（Hermes 需 `/reload-mcp` = L2；CLI 立即可用）。

参数语义：
- `where`：**结构化的 `[{field, op, value}]` 数组**，`op ∈ {=, !=, >, >=, <, <=, in, like}`；字段必须在白名单内；不支持原始 SQL 字符串（防注入）；
- `order_by`：`[{field, desc?}]`，字段白名单 + 最多 2 个键；
- `since`：时间下界；行级载体按时间列（dtype 日期/时间/`*_date`/`*_at`）过滤，目录/文件级载体按文件 mtime 或 `d_YYYYMMDD` 分区名过滤；
- `limit`：默认 100，上限 **1000**；`offset`：上限 **100 000**（深翻页建议 cursor/keyset，二期）；
- `columns`：投影白名单（parquet 可下推，SQLite 降低 IO）；
- `count`：返回总数（parquet 走 metadata/row-group，SQLite 走 `COUNT(*)`，均有超时）。

### 3.2 载体适配

| 载体 | 查询实现要点 |
|---|---|
| `sqlite_table` | `sqlite3.connect(f"file:{p}?mode=ro", uri=True)`；`PRAGMA table_info` 取字段白名单；参数化 WHERE；`ORDER BY` 白名单；`LIMIT/OFFSET` 夹取；`since` 自动挑时间列（无则拒绝并给 allowed_fields）；`PRAGMA query_only=ON` |
| `dir_parquet` | pyarrow `dataset(path).to_table(filter=..., columns=..., use_threads=...)` + `slice(offset, limit)`；schema 优先 `catalog.json` 的 store→schema（231/233 命中），否则读首个 parquet footer 自推断；date 分区（`d_YYYYMMDD.parquet`）转 `since` 下推；单次扫描行数/字节上限 |
| `dir_jsonl` | 逐行流式扫描（gzip 嗅探），先做 `since`（行内时间字段优先，无则文件 mtime），再 `offset/limit`；单次扫描字节上限 64MB |
| `dir_mixed` / `dir_nested` | 按扩展名路由到 parquet/sqlite/jsonl 子引擎；非结构化文件退化为**文件级 query**（列表/分页/条件=glob 前缀+扩展名+since/全量=迭代清单，带扫描上限）；`dir_nested` 限定深度（≤2） |
| `corpus_layer`（14） | 层索引（`yt_*` 层目录）+ 文件级 query；若层有 RAG/检索接口（yt_rag）可直连只读接口；不做跨层 join |
| `pg_table`（DWH-103 v2，7 张） | 复用现有只读 DSN/session；参数化 SELECT + 字段白名单（`information_schema.columns` 一次性缓存）；只读事务 |
| `contract_artifact`（4） | **不支持 row query**（单文件/小 JSON）：返回 `not_supported` 并给 artifact 采样入口，避免假覆盖 |

### 3.3 安全边界（只读 + 白名单 + 上限）

1. **路径**：复用 `dataset_registry.ALLOWED_ROOTS`（10 个根，不含 `C:\Temp`），解析后必须在其内；`contract_artifact` 仅显式清单；
2. **字段/排序白名单**：仅载体 schema 暴露的列；未知字段 → `400 + allowed_fields`（fail-visible）；
3. **算子白名单**：上表 8 个算子；值全参数化；`like` 限前缀/子串、长度 ≤64；
4. **行数/扫描上限**：`limit≤1000`、`offset≤100000`、单次 `scanned_rows≤2,000,000`、`scanned_bytes≤512MB`、超时 10s（可配）；超限返回 `truncated=true` + 明确 reason（不静默截断）；
5. **只读**：SQLite `mode=ro` + `query_only`；PG 只读 session；parquet/jsonl 只读打开；**禁止** DDL/DML/ATTACH/PRAGMA 写；
6. **审计**：每次 query 追加 JSONL 到 `C:\Temp\dw_query_audit.log`（dataset_id/kind/参数摘要/耗时/行数/是否截断；不记录数据内容/凭据）；
7. **失败不假绿**：数据集不可查询 → `409 not_supported` + reason（**不得回退成 sample 假装成功**）；空结果 → `state=no_data` + reason（沿用 DWH-105 三态）。

### 4.2 KPI 阶梯（S1 30% / S2 55% / S3 80%）如何落地

覆盖率 = 四维就绪数据集数 / 有效分母（建议 310，见 §五）。按同一 engine **按优先级分批开量**即可得到阶梯：

| 批次 | 累计就绪 | 覆盖率 | 开量对象（按优先级） |
|---|---:|---:|---|
| S1 | 95 | 30.3% | 42 SQLite + 53 个 parquet 目录（优先：已登记 ∧ exposed ∧ 接口数据域 ∧ 体积/行数大） |
| S2 | 173 | 55.1% | 再 +78 个 parquet 目录（登记表 + 雪球/公告/财务核心） |

## 五、验收口径（"≥80%" 如何计算）

### 5.1 单数据集"专用查询就绪"判定（四维证据，全部自动断言）

在**同一 dataset_id** 上通过官方入口（HTTP/CLI/MCP 任一，优先 HTTP）实测：

| 维度 | 判定证据 | 不合格示例 |
|---|---|---|
| L 列表 | 返回 `rows` 非空（行级）或 `files` 非空（文件级），顺序稳定（连续两次一致或按白名单字段排序） | 只回 top_entries ≤20 |
| P 分页 | `limit=k, offset=0` 与 `offset=k` 两页 **内容不同且各非空**（或 `has_more` 正确翻转；翻到末页 `has_more=false`） | 无 offset 参数 / 只回样本 |
| F 条件 | 用白名单字段做条件查询，结果 ⊆ 无条件结果且严格小于全集（或返回空+`no_data` 且 reason 可解释） | 条件被忽略、返回与无条件相同 |
| A 全量 | `count` 可达（或 `count_estimate` + 翻页遍历可达末页），且 `truncated=false`（或以显式 `truncated` + 上限说明） | 截断无标记 / 无 count |
| 只读 | 查询前后数据集 mtime/rows 不变（同 dataset 二次查询幂等） | — |

- **L∧P∧F∧A 全过 → 该 dataset 计 1**；任一不通过 → 计 0，并记录失败原因（进缺口清单）；
- **失败/空/不支持必须显式**（`not_supported`/`no_data` + reason），不计为通过。

### 5.2 覆盖率公式（写死进验收脚本）

```
有效分母 D = 314 − N/A
  N/A = 无数据/非数据集（当前建议：3 个空目录 + tushare..git = 4）→ D = 310
覆盖率 = #(四维全过数据集) / D
```

- 同时输出 **raw 口径 /314** 与 **clean 口径 /D**（315 与 310 两列都记录，避免"换分母凑数"）；
- 目标：**clean ≥ 80%（且 raw ≥ 80%）**；S3 验收时两口径同时达标；
- 覆盖率 JSON 字段：`generated_at, total_raw, denominator, excluded[{id,reason}], ready, coverage_raw_pct, coverage_clean_pct, by_domain, by_kind, by_carrier, failures[{dataset_id, failed_dims, reason}]`。

### 5.3 其他验收门

1. `pytest tools/datawarehouse/tests` 全绿（含新增 ≥15 query 用例；不引入新的 known）；
2. `tools/check_syntax.py --fail-on-warning` PASS；
3. 只读/白名单负向测试：越权路径、未知字段、超上限、写语句全部被拒（4xx + reason）；
4. 性能：单次 query P95 ≤ 1.5s（parquet 目录 ≤3s），大目录/大 JSON 有界；
5. 覆盖率脚本可复跑（同 commit 两次结果一致，除 data_date 外）。
