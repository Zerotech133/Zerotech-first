## 零、本单为何是「解阻塞」而非「等数据」

3.5「训练基线」原计划依赖 **≥2 周快照积累**（D-1 决策快照）。但当前 **D-1 零积累**——`k_stock/data/paper.db` 尚无 `decision_snapshots` 表 = **今日零落单**。继续等会空转。

本单走**解阻塞路径**：**先把口径与评估框架建起来，数据回填后自动生效**。

| 硬约束 | 本单执行 |
|---|---|
| 绝不造数 | 无后验 → `pending_backfill` 六项指标全 null，**绝不返回 0% 胜率 / 0 收益** |
| 绝不因无数据充数 | n < 门槛 → `insufficient_sample` 全 null + note，**低于门槛不出结论** |
| 禁吹功 | 差异不显著 → 明确写「**无显著差异**」；任一侧样本不足 → **不下结论** |

**当前 `paper.db` 实况**：`build_baseline` 走只读连接遇无表会**显式抛 `snapshot_table_missing`** 并注明「今日零落单，口径已就位、等数据回填自动生效」——不静默返回空基线冒充「已评估且为零」。

## 二、基线指标口径（六项，算式全部写进输出字段）

```python
build_baseline(variant, *, dimension=DIM_BRANCH, snapshot_db=None,
               posterior=None, min_sample=MIN_SAMPLE) -> dict
compare_baselines(a, b, *, dimension=DIM_BRANCH, snapshot_db=None,
                  posterior=None, min_sample=MIN_SAMPLE,
                  alpha=0.05) -> dict
backfill_posterior(posterior, snapshot_id, *, unit, value, source=None) -> dict
attach_cost_view(baseline, review) -> dict
render_markdown(baseline) -> str
render_comparison_markdown(comparison) -> str
```

### 2.1 样本口径

- **一个样本 = 一条决策快照**（-004 `decision_snapshots` 一行 = 一次落单决策）；
- **分支维度**（`DIM_BRANCH`，默认）：按 `account_id = combo@branch` 归集 —— **-008 分支隔离账 / -011 `branch_account_ids` 口径**；
- **组合维度**（`DIM_COMBO`）：按 `combo_id` 归集（-003 四元组注册表口径）；
- 快照按 `ts, snapshot_id` 排序（净值曲线的时间序由此确定，**同 ts 时以 snapshot_id 兜底保证可复现**）。

### 2.2 六项指标定义

| 指标 | 算式（写进输出 `*_formula` 字段） | 说明 |
|---|---|---|
| **样本量 n** | `count(可用样本)` | 可用 = **已回填后验**的快照数；待回填样本不计入 n，另计 `samples_pending_backfill` |
| **命中率** | `count(后验收益 > 0) / n` | 强调「信号判对否」 |
| **平均收益** | `sum(后验收益) / n` | 同单位算术平均（**不做单位归一化**——单位混喂显式标 `unit_consistency.consistent=false`） |
| **最大回撤** | `max over t of (peak_t − equity_t) / peak_t` | 净值曲线按 `ts` **复合累乘** `eq *= (1 + r)`，起点 1.0；回撤锚在**峰值**而非起点 |
| **胜率** | `count(后验收益 > 0) / n` | 强调「钱赚到了吗」 |
| **盈亏比** | `平均盈利 / abs(平均亏损)` | 无亏损样本 → `None` + note（**不填 0**） |

**口径说明（诚实提示）**：

- **命中率与胜率同算式、不同语义**：两者都以「后验收益 > 0」为判据，但前者回答「这套决策判对了吗」、后者回答「钱赚到了吗」。**口径相同是刻意的**（同一批样本的两个视角），不是重复造指标——若未来把「命中」独立定义为「方向与预案一致」，需另立工单并改口径字段，**不得在本字段上悄悄改定义**。
- **最大回撤只在收益率口径下出数**：单位为金额（CNY 等）时**不做复利还原**（金额累加 ≠ 收益率复利，混算即造数）→ `max_drawdown = null` + note。已单测咬住（`test_amount_unit_no_compounding_drawdown`）。
- **平盘样本（value = 0）**：既不计胜也不计负，单列 `breakeven`，且**不计入命中/胜率分子**。
- **n 的分子分母口径**：`n` 只数**可用样本**，命中率/胜率的分母是 `n`（不是快照总数）——待回填样本一律不进分子分母，避免「未回填被读成没赚到」。

### 2.3 样本量门槛

- **`MIN_SAMPLE = 30`**：`n < 30` → `status = insufficient_sample`，**六项指标全 null** + note（含 `待回填样本 N 个`）；
- 门槛**可配**（`min_sample` 参数），且校验 `>= 1` 的 int（`0`/负/非 int/bool → 抛错）；
- 门槛判据是 **`n < min_sample`**（严格小于）：**n = 30 = 门槛时出数**（边界已单测咬住）；
- 30 是本单定的**口径值**（呼应「快照积累」的现实量级），**非统计 magic number**；老田可拍板调整，改常量即可，输出口径同步。

### 2.4 `pending_backfill` 语义（与 -013/-016 同一词汇族）

**绝不用 0 充当「没有」**——`0` 会被读成「打平」「白干且不亏」，属造数。

| 情形 | `status` | 六项指标 | note |
|---|---|---|---|
| 该维度**无快照样本** | `empty_sample` | 全 `null` | 「无决策快照样本（D-1 零落单）」 |
| 有快照但**全部无后验** | **`pending_backfill`** | 全 `null` | 「N 个快照全部无后验收益回填 → pending_backfill，不以 0 充数」 |
| 部分回填、`n < 门槛` | `insufficient_sample` | 全 `null` | 「可用样本 n=N < 门槛 30 … 待回填样本 M 个」 |
| 部分回填、`n ≥ 门槛` | `computed` | 出数 | 只用已回填样本；待回填样本仍列 `pending_samples`（可回放引用） |

词汇一致性已单测钉死：`baseline.STATUS_PENDING == combo_review.ROI_PENDING_BACKFILL == topic_miner.POSTERIOR_PENDING == "pending_backfill"`。

## 三、对比 API（`compare_baselines`）与禁吹功纪律

### 3.1 前置门（顺序纪律：先门后检验）

**样本量/数据前提门严格先于任何检验短路**——`n` 不达门槛时 `test = None`（连检验都不跑，绝不拿小样本算个 p 值出来说事）。

| 门 | 触发 | `verdict` | 是否下结论 |
|---|---|---|---|
| **数据门** | 任一侧 `pending_backfill` | `pending_backfill` | **否** |
| 样本门 | 任一侧 `empty_sample` | `empty_sample` | **否** |
| **样本量门** | 任一侧 `insufficient_sample` | `insufficient_sample` | **否** |
| **可比性门** | 两侧 `unit` 不同 | `unit_mismatch` | **否**（不混算） |
| 检验门 | 达门槛且单位可比 | 见 §3.2 | 视显著性 |

### 3.2 显著性判据（**简化口径，已显式注明**）

| 项 | 口径 |
|---|---|
| 方法 | **Welch t 检验**（不假设等方差），自由度 **Welch–Satterthwaite** 近似 |
| p 值 | t 分布双尾，**数值法**（正则化不完全 Beta 函数 `_betai`，Lentz 连分式展开）；**无 scipy 依赖** |
| 判据 | `p < alpha`（默认 `alpha = 0.05`）→ `significant_difference`；`p >= alpha` → **`no_significant_difference`** |
| 方差 0 且均值相等 | `t=0, p=1` → **无显著差异**（如实写，不编造显著性） |
| 方差 0 且均值不等 | `t=±inf, p=0` → **确定性差异**（照实出数，不装看不见） |

**简化之处（诚实提示，写在输出的 `significance_note` 常量里，恒随结果下发）**：

> 显著性判据当前为**简化口径**：均值差用 Welch t 检验（不假设等方差，自由度 Welch–Satterthwaite 近似），p 值为数值法 t 分布双尾近似（无 scipy）；**未做多重比较校正**（批量扫描多分支时假阳性会膨胀）。批量对比需另立口径。

p 值精度已单测对表：`_t_sf_two_sided(2.228, df=10) = 0.0500`（t 分布临界值表 t₀.₀₅,₁₀ = 2.228）；`df → ∞` 时退化为正态（`_t_sf_two_sided(1.96, 1e7) ≈ 0.05`）。

### 3.3 禁吹功纪律（三条，均已单测）

1. **不显著即写「无显著差异」**：`p >= alpha` → `verdict_text` 明确写「**无显著差异** … 差异在样本噪声范围内，**不得据此宣称任一侧改进**」；
2. **任一侧样本不足 → 不下结论**：`verdict = insufficient_sample`，`test = None`，notes 记「样本量前提未达 → 禁止宣称改进」；
3. **显著 ≠ 更优定论**：即使 `p < alpha`，`verdict_text` 仍注明「统计显著 ≠ 策略优劣定论，仍需结合样本量与回撤审阅」，notes 记「不构成『策略更优』定论——须结合样本量/回撤/成本审阅」。

**逐分支逐一对比是本单的主要用法**（每个分支一批样本单独比），假阳性膨胀风险小；**批量扫描「哪个分支最好」需另立多重比较口径**（见 §六）。

## 四、数据接入与回填接口

### 4.1 -004 快照（只读）

- 连接：`sqlite3.connect(f"file:{path}?mode=ro", uri=True)`，**纯 SELECT**；
- **不调 `decision_snapshot.ensure_table`**——那是 -004 的写路径（且 -012 已裁定「表已存在时不执行任何 DDL」，本单更不碰建表）；
- 快照库不存在 → 抛 `snapshot_db_missing`；表不存在 → 抛 `snapshot_table_missing`（附「今日零落单 / 口径已就位、等回填自动生效」说明）；查询失败 → 抛 `snapshot_query_failed`；
- `snapshot_db=None` → 返回 `empty_sample`（合法「无输入」，非违例）。

### 4.2 后验收益喂入（**复用 -016 口径**，缺 unit 抛错）

```python
{"snapshots": {"<snapshot_id>": {"unit": "pct",       # 必填：缺 unit → 抛错
                                 "value": 0.12,       # 必填：数值（bool/None/字符串 → 抛错）
                                 "source": "settle:run-xxx"}}}
```

- **同一词汇族、同一必填键**：与 -016 `topic_miner._validate_posterior` 逐条对齐（`unit` 非空字符串必填、`value` 必须是真数值）；
- **空映射 / `None` = 全部待回填**（合法「无数据」，非契约违例，与 -016 判例一致）；
- **绝不默默取 0**：`value=None` 抛 `posterior_invalid`（`0` 会被读成打平）；`value=True` 抛（`bool` 是 `int` 子类，防 `True` 被当 `1`）。

### 4.3 回填接口 `backfill_posterior`（**数据回填后自动生效的接线口**）

```python
post = baseline.backfill_posterior(post, snapshot_id, unit="pct", value=0.05,
                                   source="settle:run-xxx")
```

- **就地追加进新映射并返回，不改传入对象**（无隐式副作用，已单测）；
- `unit` 必填（同 -016）；`snapshot_id` 须非空；`value` 须为数值；
- **回填后无需改任何代码**：`build_baseline` / `compare_baselines` 下一轮调用即读到新值——单测 `test_backfill_interface_wires_data_without_code_change` 咬住「回填前 `pending_backfill`（胜率 `None`）→ 回填后同 API 直接出 `win_rate = 0.666667`」。

### 4.4 成本/ROI 视图（-013 只读复用）

- `baseline.cost_view` **默认 `None`** + note 注明口径唯一定义处（不臆造 ROI）；
- `attach_cost_view(baseline, combo_review.build_review(...))` 只**搬运** `-013` 已算好的 `roi` / `cost` 字段，**不重算**；`-013` 侧为 `pending_backfill` / `unit_mismatch` 时本视图同样不出数（照实透传状态）；
- 输入非 dict 或缺 `roi` 字段 → 抛 `cost_view_invalid`。

## 五、失败语义（closed on failure）

一律**显式抛 `BaselineError(reason_code, msg)`**，禁静默降级、禁填 0 充数：

| `reason_code` | 触发 |
|---|---|
| `posterior_invalid` | 喂入缺 `unit` / `value` 为 `None`·字符串·bool / 结构错 / `snapshot_id` 为空串 |
| `snapshot_db_missing` / `snapshot_db_unreadable` | 快照库不存在 / 不可读 |
| `snapshot_table_missing` | 库中无 `decision_snapshots` 表（今日零落单） |
| `snapshot_query_failed` | -004 快照表查询失败 |
| `dimension_invalid` / `variant_invalid` / `min_sample_invalid` | 维度非 `branch`/`combo` / variant 为空 / 门槛非 `>=1` 的 int |
| `cost_view_invalid` | 成本视图输入非 dict 或缺 `roi` |

**合法「无数据」不抛**（区别于契约违例）：`snapshot_db=None` → `empty_sample`；`posterior=None` 或空映射 → `pending_backfill`。
