# 多策略可插拔链路重设计（数据底座 × 策略组合 × 前端反馈）

> 2026-10-17 · 定位：把现有「单一策略下游」升级为「多策略可插拔组合 + 前端统一反馈」
> 原则：**底座按数据品类建，不按策略建**；现有三层资产零废弃，纯增量改造。

---

## 一、总体分层（L0–L5）

```
L0 采集层（不变）   TushareSync / TdxSync / XueqiuSync / AdjFactorSync / JevFeed / GoldShadow
L1 存储层（不变）   PG 5442 主库 · Neo4j 图谱 · MySQL 3307 只读镜像 · DuckDB 湖 · Parquet 快照
L2 情报服务层（不变） MCP Server 10 工具 · KG 打分(kg_scores parquet) · Jev 事件门禁
L3 策略适配层（新增） StrategyAdapter 统一契约 → 标准信号 Signal
L4 组合裁决层（新增） RiskGuard 共享风控前置 + SignalAggregator 加权融合
L5 前端反馈层（扩展） 8791 仪表盘：策略面板 + 组合建议 + 反馈闭环
```

## 二、L3 策略适配层：统一契约

```python
@dataclass
class Signal:
    symbol: str          # 000338.SZ
    action: str          # buy / sell / hold / watch
    score: float         # 0~100 标准化
    confidence: float    # 0~1
    rationale: str       # 人话依据（前端直接展示）
    strategy: str        # 来源策略 id

class StrategyAdapter(Protocol):
    strategy_id: str
    def score(self, trade_date: str) -> list[Signal]: ...
```

首批注册四个插槽：

| 插槽 | 来源 | 现状 |
|---|---|---|
| `dual_blade` 量子双刀 | Scanner→Screener→Signal 现有产出 | 包装即接入（改造量最小） |
| `chan_monitor` 盯盘缠论 | 缠论打分 + RiskGuard 拆出 | RiskGuard 移至 L4 共享 |
| `kg_boost` 图谱社区打分 | KGAnalysis 的 Louvain/PageRank 分位 | **现成的**，parquet 已落湖，写 20 行 adapter 即可 |
| `llm_agent` AI 选股 | 本地 Ollama + MCP 工具调用 | 预留位，Jev 门禁同款引擎 |

## 三、L4 组合裁决层

1. **RiskGuard 前置共享化**：四条规则（市场质量/流动性冲击/事件风险/仓位集中度）从盯盘机器人中解耦为独立服务，**所有策略信号先过风控再进融合**。当前 213 样本误杀校准工作直接在此层做，收益全策略共享。
2. **SignalAggregator 加权融合**：`组合分 = Σ w_i × score_i`；冲突时（如一买一卖）输出分歧标注而非强扭。权重 w_i 来源见第五节反馈闭环。
3. **裁决输出**：组合 Signal + 各策略独立意见 + 分歧标记，一并写 `signals_combined` 表供前端消费。

## 四、L5 前端（8791 仪表盘扩展）

- **策略开关面板**：注册表驱动，启停某策略即时生效（aggregator 每次运行读启用集合），策略热插拔。
- **信号对比视图**：每只股票一行，各策略评分并排列出 + 组合分高亮 + rationale 悬浮展示。
- **反馈控件**：采纳/驳回按钮 → 写 feedback 表；支持对单策略「降权/静默」。
- **分歧看板**：展示策略间最大分歧标的，这是人工研判价值最高的入口。

## 五、反馈闭环（前端 → 策略权重的进化机制）

双通道：
1. **显式反馈**：用户采纳/驳回落 `feedback` 表（signal_id, action, ts）。
2. **隐式反馈**：每日收盘后跑「信号 vs 次日实际收益」后验对比（复用 RiskGuard 校准的基础设施）。
3. **权重更新器**（每周日自动）：`w_i ← f(后验收益, 用户采纳率)`，EWMA 平滑防单周噪声；权重存 PG，前端可视化当前权重构成。

闭环效果：某策略连续跑输 → 自动降权 → 组合自动变好；用户无需手工调参。

## 六、每日节奏（落地后的时间线）

```
05:50 数据自然节奏 → 06:00 XmapSync → 07:00 KGAnalysis 出图
07:30 各策略并行 score（互不阻塞，失败降级跳过）
07:45 RiskGuard 风控 → SignalAggregator 融合
08:00 仪表盘出「今日组合建议」+ 各策略意见
盘中  盯盘机器人实时监控（chan_monitor 高频模式）
收盘后 隐式反馈入库；周日权重进化
```

## 八、定位升维：从「数据底座」到「置信度血缘纽带」（2026-10-17 定稿）

> 用户裁定：本项目不只是数据供给层，本质是**数据→信息→情报三级血缘上逐跳计算置信度的纽带**。
> 下游拿到的不是一个数，而是「这个数有多可信、从哪来、经过谁」。

### 8.1 三级置信链

| 层 | 内容 | 置信因子 |
|---|---|---|
| 数据层 Data | Tushare/TDX/雪球原始行 | 源可靠度 · 新鲜度 · 完整度 |
| 信息层 Information | 复权因子 · Xmap 实体对齐 · 派生表 | 加工可靠度 · 双源交叉验证 |
| 情报层 Intelligence | KG 打分 · Jev 事件分级 · 策略信号 | 模型后验 · 回测胜率 |

### 8.2 置信度传播三规则（每一跳计算）

1. **融合增益**：独立双源一致 → 置信提升（如 tushare 与 TDX 行情互证，跨源一致是最高置信证据）。
2. **时间衰减**：按数据品类设衰减曲线（行情分秒级衰减、基本面日级、图谱周级）。
3. **事故惩罚**：血缘链上任一环节出事故（token 断供/翻倍 bug/任务 rc≠0）→ 下游自动降置信，**复检通过才恢复**——把「失败必告警」升级为「**降置信必告警**」。

### 8.3 与已有资产的对账

**已有地基（零废弃）**：
- quant-pg 血缘账本（job_run + lineage_edge）→ 血缘可追溯的账本已建成
- XmapSync 实体对齐（5480 全 matched）→ 血缘「同名同物」的关键件
- Signal.confidence 字段（P1 契约）→ 置信度有现成载体
- RiskGuard 后验校准 / 周日权重更新器 → 情报层置信因子的数据源

**缺口（需新建）**：
- 每表/快照的 confidence 元数据列 + 传播引擎（`confidence.py`，预计 200 行内）
- 告警语义升级：rc!=0 才告警 → 置信跌破阈值也告警
- 前端置信徽章：每个信号显示置信度（如 0.92 ● 绿），点击展开完整血缘链

### 8.4 板块定位语（对外口径）

**「从数据到决策的置信度纽带」**——能力平台定位的最佳实证：底座按数据品类建、置信按血缘传播、策略按置信消费，任何 AI 选股策略插上来即继承整套可追溯信任体系。
