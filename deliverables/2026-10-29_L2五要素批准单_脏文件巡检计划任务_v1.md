> 依据：`docs/plans/2026-10-19_Agent危险操作治理规范_K-STOCK-416.md`（L2=宿主机持久化面）。
> 申请事项：创建**每 2 小时**运行的 Windows 计划任务，执行只读巡检 `check_dirty --strict`，超阈值写事件层告警。
> 状态：**待老田签名**（未签名不执行；本单本身不动宿主机）。

## 一、命令全文（签名后执行，完整复制）

```powershell
# 1) 前置：脚本就位（签名后由 P25 单合并，路径固定）
#    C:\项目\老田的AI助手\tools\dirty_watch.ps1

# 2) 创建计划任务（当前用户，LIMITED 权限，无需管理员）
schtasks /Create /TN "ZeroBound\CheckDirty2H" /TR "powershell -NoProfile -ExecutionPolicy Bypass -File \"C:\项目\老田的AI助手\tools\dirty_watch.ps1\"" /SC HOURLY /MO 2 /RL LIMITED /F

# 3) 立即跑一次验证
schtasks /Run /TN "ZeroBound\CheckDirty2H"
# 4) 查看结果
schtasks /Query /TN "ZeroBound\CheckDirty2H" /V /FO LIST
type C:\Temp\dirty_watch_<今日日期>.log
```

**巡检脚本行为**（`tools/dirty_watch.ps1`，签名后落地）：
1. 执行 `python tools/check_dirty.py --strict --max-age-hours 4 --json`（只读 `git status` + 文件 mtime + `git log` 查 owner）；
2. 超阈值（跟踪脏文件 >4h 且非已登记 WIP）→ 写日志 `C:\Temp\dirty_watch_<YYYYMMDD>.log`，并经 `tools/events.py emit --kind patrol_verdict --agent GUANYU` 发事件；
3. 正常 → 仅追加一行 OK 到日志（不打扰）；
4. 不杀进程、不写数据根、不改 git、不重启服务。

## 二、影响面

| 面 | 影响 |
|---|---|
| 宿主机 | 新增 1 个计划任务（当前用户上下文，LIMITED）；每 2 小时短暂运行（<5s，git 只读） |
| 代码/数据 | **零写入**（仅读 git 状态/文件 mtime；写 C:\Temp 日志 + 事件层 jsonl 追加） |
| 服务/端口 | 不涉及；不重启任何服务 |
| 磁盘 | 日志按天滚动，约 <10KB/天 |
| 权限 | 无需管理员；任务可随时删除 |
| 干扰 | 与并行开发无冲突（只读）；git 只读不会触发 index.lock |

## 三、不可逆点

1. **计划任务注册**（可删除，属可逆）；2. 日志文件（可删）；3. 事件层追加（只增，不可改历史——但属审计性质）。**无数据/代码不可逆影响**。

## 四、替代方案与已尝试

| 方案 | 已做/结论 |
|---|---|
| 手动看板 `python tools/check_dirty.py` | 已有；靠人记得跑 → 今天实测仍出现 17 个跟踪脏文件 >4h |
| 并入 `test_gate fast` | 可行但仅覆盖合并时点；夜间/长窗口无人合并时无效 |
| 并入 devtask merge 前置 | 只覆盖合并动作，不覆盖"长期占着不合并" |
| 2h 计划任务（本单） | 唯一能覆盖"无人操作窗口"的低成本方案；只读、可逆、无需管理员 |

## 五、回滚预案

```powershell
# 一键回滚（30 秒）
schtasks /Delete /TN "ZeroBound\CheckDirty2H" /F
Remove-Item C:\Temp\dirty_watch_*.log -ErrorAction SilentlyContinue   # 可选
# 验证：schtasks /Query /TN "ZeroBound\CheckDirty2H" → 报"任务不存在"
```
