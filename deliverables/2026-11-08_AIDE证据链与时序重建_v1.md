## 一、现场取证：那两条新闻到底怎么进来的

老田问「命中点在哪」。查库结果：**没有命中点，是模型自由发挥的代码**。

## 二、三层根因（三段全断，不是单点 bug）

### ① 判定层：prompt 给了开放式填空

`news_collector/news_ai.py:699`

```
"companies 只填明确关联的A股代码（6位数字），无则空数组。"
```

只给了「明确关联」四个字，**没给股票名录、没要求文本出现、没有后置校验**。
9b 模型在「A股代码」这个空格上，填了训练集里最高频的票（300750 / 600519）。
更关键的是：这些新闻的 `stocks` 列是 `None`（预筛明确说「没匹配到任何标的」），
**LLM 却自己补了一个**——预筛的判断被模型覆盖了。

### ② 聚合层：裸 LIKE 无条件采信

`portal/api_jev_story.py:82`（改前）

```python
"AND (n.jev LIKE ? OR n.stocks LIKE ?) "
(since, '%"companies": ["%' + code6 + '%', '%' + code6 + '%', ...)
```

只要 JSON 字符串里出现 `"companies": ["300750`，就算命中。**没有回读原文**。
`api_jev_target.py` 的 `_sentiment` / `_judgments`、`api_jev_intraday.py` 同款写法。

### ③ 展示层：没有任何「命中依据」字段可摆

接口不返回命中词、不返回原文片段，页面只能显示 `local / conf 0.8`。
用户看到的是一列「利多 0.8」，自然要问「凭什么」。

## 三、修了什么

### 3.1 新增 `portal/jev_hit_basis.py`（证据链本体）

纯字符串面判定，不调模型、不改历史数据、不重跑 13.7 万条判定。

四档裁决，全部可解释：

| verdict | 条件 | keep | 页面标签 |
|---|---|---|---|
| `text_confirmed` | 标题或正文出现公司全名/代码 | 是 | 文本确证 |
| `industry_only` | 未点名个股，但出现**该股所属行业**的用词 | 是（标注） | 板块级 |
| `code_only` | 只有 `jev.companies` 有代码，文本零痕迹 | **否** | 无支撑（剔除） |
| `none` | 连代码都没有 | 否 | — |

行业词不是凭感觉认的：取自 `stock_basic` 的 `industry` 字段 + 一张**收敛型**同义词表
（宁德时代 industry=`电气设备`，认可「电力设备/电池/动力电池/储能/锂电/新能源」；
**不认**育种、种业、医疗——所以 1.1/1.2 两条被判 `code_only` 而不是被「行业关联」救回来）。

输出体（每条事件都带，可悬停看原文片段）：

```json
{"verdict":"code_only","keep":false,"level":1,
 "terms":{"name":[],"short":[],"code":[],"industry":[]},
 "hit_text":"",
 "why":"jev.companies 绑定了 300750，但标题与正文未出现「宁德时代」、代码或所属行业词 → 无文本支撑的代码绑定（疑似模型幻觉），不予采信"}
```

### 3.2 三个聚合接口接入

| 文件 | 改动 | 新字段 |
|---|---|---|
| `api_jev_story.py` | SQL 增取 `content`；逐条 `verify`；`keep=False` 跳过 | `timeline[].basis`、`hit_audit` |
| `api_jev_target.py` `_judgments` | 同上；`total/dist/net_bias` 只统计通过的 | `judgments.hit_audit`（含 `dropped_samples`） |
| `api_jev_target.py` `_sentiment` | 热度只统计有支撑的消息 | `sentiment.hit_audit` |

`hit_audit` 结构（这就是老田要的「账」）：

```json
{"raw":685,"kept":294,"dropped":391,"keep_rate":0.429,
 "by_verdict":{"text_confirmed":187,"industry_only":107,"code_only":391,"none":0},
 "rule":"文本须出现公司名/代码/所属行业词之一；仅 jev.companies 有代码而文本零支撑 → 判为幻觉并剔除"}
```

### 3.3 时序：把「一排等距柱子」换成「谁先发生」

**问题一：影响区间在重复计数。**
旧代码按「事件」累加样本，同一交易日 25 条事件 = 同一个收益被算 25 次。
老田截图「1 日 P25~P75 = +1.43%~+3.12% 而中位也是 +1.43%」「5 日样本 15 却 +9.14%~+9.14%」，
就是单日行情被复制出来的假分布。

改为：**按事件所属交易日去重，一个交易日一个观测**；同一天多空相抵视为方向不明不计；
D0 落在周末/节假日时顺延到下一交易日（旧代码是 `dl.index(d0)` 直接失败丢弃，
而公告、研报恰恰多发在非交易时段）；百分位改线性插值（旧 `chgs[int(n*0.25)]` 小样本会撞车）。

**问题二：样本不足也印结论。**
新增 `sufficient` 门槛（独立交易日 <5 不给区间）。实测 300750：

| 窗口 | 独立交易日 | 旧口径 | 新口径 |
|---|---:|---|---|
| 1 日 | 4 | +1.43% 中位，同向 80% | **样本不足，不给区间** |
| 3 日 | 3 | +1.97% 中位，同向 95% | **样本不足，不给区间** |
| 5 日 | 1 | +9.14% 中位，同向 87% | **样本不足，不给区间** |

**问题三：看不出是哪条新闻、哪类来源带来的。**
新增 `sequence`：按交易日归并、日内按分钟排序，每条标 `role`（lead=当日首条 / follow=跟随）、
`gap_min`（距前一条几分钟）、`source_cn`、`basis_verdict`。非交易日的消息挂在
「待验证 + 原始日期」下，不假装已验证。页面渲染成 `●00:00 › ○09:54 › ○10:22`，
悬停即见具体标题与渠道。

### 3.4 让解读能点名事件（老田批「解读不专业」）

旧 facts 只喂聚合计数，模型自己在结论里写：
> 「摘要未展开事件类型及人/地/事/物/组织明细，**无法点名具体事件**」
> 「地域、板块、产业链环节未提供」

不是模型偷懒——facts 首句括号里一直是空的（`d.get("verdict","")[:0]` 恒为空）。
现在补：

1. **标的名/行业/地域**：`标的 300750.SZ（宁德时代／电气设备／福建）`
2. **事件明细 14 条**：`10-31 12:58 利多 conf=0.8 经营订单 | 上海电气与宁德时代签署战略合作协议… | 确证·命中「宁德时代」`
3. **传导流 6 个交易日**：`2026-11-03：25 条，首条 00:00、末条 21:09，净倾向 +23，当日 3.80%`
4. **样本不足如实说**：「事件后 3 日：独立交易日样本 3 个，不足以下区间结论（不可拿单日行情当规律）」

同一模型（deepseek-flash）改后实测输出：

> 【事件面】60个事件中利多57、利空0…最关键为**曾毓群称用AI加速电化学发现、上海电气与宁德时代签署算电协同等七大领域战略合作**。
> 【时间线】10/30盘后交易与资金消息起步，10/31技术表态+合作签约，11/2净买入超7亿，**11/3集中爆发25条**并盘中涨超5%…11/6价格转跌3.73%。
> 【空间面】标的在福建，事件地域涉及上海、澳大利亚、北京、湖南、兰州；产业链集中于**储能16、动力电池7、锂电4、光伏4、电网2**。
> 【研判】属**超跌修复而非趋势反转**…下一步盯：11/6下跌后下一交易日能否收复跌幅。

facts 长度 367 → 1957 字符，prompt_tokens 496 → 1478，单次成本 ¥0.0034 → ¥0.0068（空闲时段）。

## 五、没做的四件，以及为什么

| 老田要求 | 状态 | 卡在哪 |
|---|---|---|
| 分原创 / 首发 / 转发 | **未做** | `news` 表只有 `source`（渠道名），没有 `is_original` / `first_seen` / `repost_of`。要做需改表结构 + 采集层去重指纹（同标题多源 = 转发），属数据层改造 |
| 研报 / 公告 / 股吧 / 雪球 | **部分** | 现有 source 只有 chinanews / 东财 / 新浪 / 华尔街见闻 / 通达信 / report（研报，仅几条）。股吧、雪球无采集器 |
| 知识图谱关联（谁领涨谁跟随 / 同比环比） | **未做** | 需新接口 + 产业关系边。现有只有 `stock_basic.industry` 和「同条新闻共现」，够起最小版，但需先定边口径 |
| 盘中实时监控（热点→加关注→推票） | **未做** | 需订阅表 + 分钟级轮询 + 推送，属新建模块 |

`_sediment()` 的过期判据仍是 `age = 今天 - trade_date ≤ 1`：
**每个周一、每个节后第一天，昨晚生成的卡都会被判过期丢掉**。这条没动，因为要改的是研判卡取用策略，
需要老田定口径（按交易日算还是按自然日算）。
