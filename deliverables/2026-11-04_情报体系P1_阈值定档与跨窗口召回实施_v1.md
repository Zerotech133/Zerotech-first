## 1. 这一轮的输入与判断

上一轮收尾时我提了两件待裁定的事：阈值取 0.85 还是 0.75、LLM 判定器怎么部署。你说"按计划实施"，我按上一轮明确表达的倾向执行——**取 0.75**，理由是危害不对称：

- 0.85 下 5 处拆散，失效形态是**事件从日报里消失**（英伟达、台积电拆散后各剩 1 个来源，够不上 `independent_sources >= 2` 的入报门槛），读者根本不知道这事发生过；
- 0.75 下 1 处拆散 + 1 处误合并，误合并是**可观测、可事后补**的（`over_merge_count` 一查就出来，且已定位到具体配对）。

但我没有只改一个数字。阈值是口径问题，一旦上线就要能不改代码回退，所以：

| 改动 | 内容 |
|---|---|
| 常量定档 | `RECHECK_SIMILARITY` 0.85 → **0.75**，注释写清对照数据与失效形态 |
| 配置化 | 新增 `config.settings.story_recheck_similarity`，环境变量 `STORY_RECHECK_SIMILARITY` 可覆盖 |
| 解析函数 | `resolve_recheck_similarity()`：配置优先，配置层不可用或越界时回落常量并留 warn，**不因一个阈值配置项让进程起不来** |
| 注入点 | `StoryGrouper(recheck_similarity=...)` 仅供标定脚本与单测，生产不传（否则配置项会被静默忽略） |

## 2. 缺陷四：一个阈值被用在两种不可比的度量上

改完常量，`test_degrade_reason_merges_with_embed_degrade` 立刻红了。这个红不是测试太脆，是真缺陷：

嵌入层挂掉时相似度退回字符二元组 Jaccard。用例里那对文本 Jaccard = **0.786**（近乎同句改写），原来落在 `[0.60, 0.85)` 里会进判定器，判定器故障 → `judge_failures=1` → 降级原因留痕。

阈值降到 0.75 后，0.786 ≥ 0.75 → **直判同、跳过判定器** → `judge_failures` 从 1 变 0 → **降级原因凭空消失**。运维只看到"合并率正常"，判定后端掉线这件事无痕。

根因：`RECHECK_SIMILARITY` 同时被用于向量余弦和字符 Jaccard。这两个分布根本不可比——余弦 0.60 处同事件 recall=1.00，而 Jaccard 在"同一事件、不同表述"上常只有 0.1–0.3。

**修法**（口径彻底分离，不是给测试打补丁）：

| 常量 | 值 | 用途 |
|---|---|---|
| `RECALL_SIMILARITY` | 0.60 | 向量口径候选召回门 |
| `RECHECK_SIMILARITY` | **0.75** | 向量口径直判同门 |
| `RULE_DIRECT_SIMILARITY` | **0.85** | 文本口径直判同门（独立常量，沿用原值） |
| `RULE_JACCARD` | 0.35 | 文本口径候选召回门 |
| `SIMILARITY_GATES` | `{vector: 0.60, text: 0.35}` | 召回门按口径取，**从 `story_recall` 上移为算子持有** |

配套改动：`_similarity()` 拆出 `_similarity_detail()` 返回 `(相似度, 口径)`，`_best_candidate()` 返回三元组，`_decide(..., mode)` 按口径选阈值。口径名一路带到 `rationale`，事后能看出结论是余弦下的还是 Jaccard 下的。

顺带修掉一个同源问题：文本口径的**召回门**原来也用 0.60，等于嵌入降级那一轮绝大多数真候选被挡在门外，合并率断崖下跌且不报错。现在按 `SIMILARITY_GATES` 走 0.35。

## 3. 跨窗口召回：实现、护栏、真机验证

### 3.1 护栏参数不是拍出来的

先跑探针拿到本语料的 6 对跨窗高相似配对，余弦分布如下（`scripts/story_split_probe.py`，向量覆盖 100%）：

| 余弦 | 配对 | 判定 |
|---|---|---|
| 0.932 | 中芯国际产能利用率（2d vs 35d） | 真同一事件 |
| 0.923 | 隆基绿能硅片提价（3d vs 25d） | 真同一事件 |
| 0.904 | 欧盟对华电动车关税（1d vs 30d） | 真同一事件 |
| 0.797 | 华信科技处罚 vs 立案（2d vs 20d） | 真同一事件 |
| 0.757 | 华信科技处罚决定书 vs 立案（1d vs 20d） | 真同一事件 |
| **0.642** | **隆基绿能"增持"vs"涨价"（6d vs 25d）** | **假阳（同一公司、不同事件）** |

真分裂最低 0.757，假阳 0.642，两侧余量各约 0.06。取**中点 0.70** 作为跨窗合并的余弦门：`CROSS_WINDOW_MIN_SIMILARITY = 0.70`。

值得记一笔的是：这条假阳**有实体交集**（都是"隆基绿能"），而 5 条真分裂也都有。所以实体重叠排不掉它——这与 `RuleJudge` 删除 `ent_overlap` 分支是同一个坑（单实体集合重合率恒 1.0，是必要条件不是充分条件）。真正的判别力在余弦，实体只作准入门槛。

### 3.2 结构

新增一条独立路径，插在窗内两路之后、独立事件之前（窗内证据时间更近，能合就不该越窗）：

```
_load_anchors()      窗口外 window_days × 3 天内的【已归属】单元，unit_key 游标分页
      ↓
_cross_candidates()  同 story 只保留最新成员作代表（成本折中，注释写明）
      ↓
cross_window_admit() 纯函数准入判定，三条件缺一不可
      ↓
_decide_cross()      准入即判同，通道名写进 rationale
```

`GroupResult` 新增 `anchors_loaded` / `cross_window_merged` 两个回报字段：只有 `anchors_loaded=0` 才能区分"没开跨窗"和"开了但窗外确实没历史"。

时间带边界 `CROSS_WINDOW_DAYS_MULTIPLIER=3` 与探针的 `SPLIT_FAR_MULTIPLIER` **改为同一个常量**（探针引用算子），避免两边各写一份漂移成"测出来没事、上线却越界合并"。

### 3.3 真机验证（构造窗外 8 条历史锚点）

本机验证库窗外 42 天内 8 条事实**从未被聚类过**（`with_story=0`）——这揭示了跨窗口召回的真实前提：**旧事件必须已被历史轮次处理过**。一次性灌入的语料不满足，所以造了锚点（先备份 `osint_story` / `osint_story_member`，验证后已完整恢复）。

实跑结果：

```
units_scanned 42  anchors_loaded 8  cross_window_merged 4
stories_created 0  stories_reused 25  members_added 42  degraded false
```

4 条并入明细（全部走 `entity+similarity` 通道）：

| 窗内事实 | 并入的历史事件 | 余弦 | 语言跨度 |
|---|---|---|---|
| 茅台提价 20%，飞天出厂价上调 | 35 天前 | 0.903 | 中 |
| 隆基绿能再度提价，硅片价格上调 5% | 25 天前 | 0.923 | 中 |
| 中芯国际产能利用率超 90% | 35 天前 | 0.932 | **中英（SMIC）** |
| 欧盟对华电动车加征关税落地 | 30 天前 | 0.904 | 中 |

窗内口径复核（只统计 42 条窗内事实，与基线同口径）：**29 事件 / 拆散 1 / 误合并 1 —— 与不开跨窗完全一致**。

### 3.4 这个"没变化"必须说清楚

跨窗口召回**没有减少窗内口径的拆散**，原因有两条，都不是机制问题：

1. 探针的 `split_candidate` 是"高相似跨窗对"，不等于"真被切裂"。华信科技那 2 对，窗内两条事实自己先合并了（1d 那条挂到 2d 那条上），根本不需要跨窗——探针把它们计为候选，是探针口径的天然局限；
2. 唯一剩余的拆散 **S11 是窗内竞争性归属问题，不是窗口切割**。三条光伏事实：9 天前"组件价格跌破成本线"、8 天前"价格战延续、协会召集座谈"、3 天前"光伏行业协会发布自律倡议书"。3 天前那条被并进 9 天前的（相似度更高），8 天前那条被 `RuleJudge` 判无关、自开事件。跨窗召回对这个场景完全无效。

**跨窗口召回的真实价值是"防止跨月事件各自计数导致热度低估"，不是"减少拆散"。** 这两件事我之前混着说了，这里更正。

## 4. 缺陷五：删成员边重算归属会直接崩在唯一约束上

构造跨窗场景时把 `osint_story_member` 清空重跑，算子直接崩：

```
duplicate key value violates unique constraint "osint_story_story_key_key"
```

`osint_story.story_key` 由种子事实唯一确定，且有唯一约束。正常增量运行时 `NOT EXISTS` 会把已归属事实排除，同一条种子永远不再来——**所以单测和首轮真跑都看不见这个坑**。

但只要发生"重算归属"，它必然触发：

- 修误合并：删掉错误成员边让事实重新参与聚类；
- **调阈值后重跑**（今天这一轮就是从 0.85 改到 0.75）；
- 人工重置某条事实的归属。

更糟的是崩溃是**半截**的：前几条成员边已写入，后面的没了，库里留下半成品状态。

**修法**：`_INSERT_STORY` 加 `ON CONFLICT (story_key) DO UPDATE`（刷新 title/summary/时间/entities/topics/model_version），并用 PostgreSQL 的 `xmax = 0` 区分"新建"与"复用"，回报拆成 `stories_created` / `stories_reused` 两个计数——不拆的话，重跑会让 `stories_created` 虚报成又建了一批新事件，运维从日志里看不出这轮到底是新建还是复用。

修复后同一操作的结果：

```
stories_created 0  stories_reused 25   ← 25 个事件全部复用，零崩溃
```

## 5. 一次自我纠错（留档）

真机跑到第一版时 `cross_window_merged` 只有 4，而探针说有 5 对真分裂。我查库看到三对实体字面不一致——`SMIC` vs `中芯国际`、`隆基绿能股份有限公司` vs `隆基绿能`、`欧盟` vs `欧盟委员会`——据此判断"实体护栏过严"，加了一条"余弦 ≥ 0.90 免实体条件"的通道。

**这个依据是错的。** 打日志再看准入明细：

```
ADMIT ch=entity+similarity sim=0.903 ent=['moutai'] vs ['moutai']
ADMIT ch=entity+similarity sim=0.923 ent=['longi']  vs ['longi']
ADMIT ch=entity+similarity sim=0.932 ent=['smic']   vs ['smic']
ADMIT ch=entity+similarity sim=0.904 ent=['eu']     vs ['eu']
```

`_entity_keys_for()` 里已经接了别名归一，运行时两侧都是 `smic`/`longi`/`eu`——**实体门根本没拦住它们**，那 4 条本来就合上了。我拿的是 `osint_knowledge_unit.entities` 的原始值，中间隔着一层归一没看到。

放宽的前提不成立，通道已删除。这段写进 `cross_window_admit` 的 docstring 并留了一条测试（`test_skips_when_no_shared_entity`，余弦 0.95 无实体仍不得合并）防止它被重新加回来。

教训：**别拿库里的原始字段推断运行时行为**，中间可能隔着一层归一。

## 8. 仍需你拍板

**一、跨窗口召回开不开。** 我按"默认关闭"交付了，因为它的收益（跨月事件热度不再低估）需要连续运行多轮才能体现，而它的风险（42 天跨度上误合并，污染 `independent_sources` 且事后极难发现）是当场就发生的。真机只证明了"机制正确、护栏按设计工作"，没有证明"开着比关着好"。要判断这一点，得跑一段真实数据看 `over_merge_count` 的变化。我的建议是**先在生产 dry-run 两周，比对 `cross_window_merged` 的明细再决定**。

**二、LLM 判定器怎么部署。** 三选一：只在高价值候选对开（`independent_sources >= 2`）/ 走云端 API / 仅用于离线标定。上一轮的数据是：定向 6 对里 5 个真拆散全判对（含中英同题、字符相似度≈0 的硬例），但单次 14–33 秒，全链路 7 分 38 秒没跑完。本机 iGPU 这条路，常规路径用不了。

**三、S11 那处拆散怎么处理。** 它现在是唯一残留，根因是 3 天前的"自律倡议书"比 8 天前的"价格战座谈"更像 9 天前的"跌破成本线"，抢了归属位。可选解法：(a) 有实体交集的候选按相似度排序时加"时间近邻"权重；(b) 允许一条事实同时属于多个事件（改 schema，成本高）；(c) 接受它，用人工复核补。我倾向 (a)，但要先在语料上标定权重，不能拍。
