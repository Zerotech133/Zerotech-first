## 二、日常用法

```bash
# 一条命令跑完盘后分析（最新交易日）
python -X utf8 tools/research/daily_pipeline.py

# 指定日期 + 数据降级也判失败
python -X utf8 tools/research/daily_pipeline.py --date 20261105 --strict

# 只跑市场结构（约 15s，日常最常用）
python -X utf8 tools/research/daily_pipeline.py --skip-screening

# 单跑市场分析，只算不写
python -X utf8 tools/research/market_analysis.py --date 20261105 --no-write
```

**必须在主工作区跑**：`daily_screening.py` 的 REPO 是硬编码的，在 linked worktree 里跑仍写主工作区的
`data/`，且 worktree 缺 gitignore 掉的数据根（已实测假红）。

## 三、契约（写进代码，不靠口头约定）

| 项 | 规则 |
|---|---|
| 涨跌停口径 | **不读 `limit_list_d`**（11-04 起是 0 行空壳），按板块规则 + pct_chg 判定：北交所 30%、创业板/科创板 20%、主板 ST 5%、其余 10%，容差 0.15pct |
| 分桶标签 | 写实际区间（`>=9.9%`），不写"涨停"——创业板涨 15% 会落进去，与涨停家数不是一个口径 |
| 指数缺失 | **不回退到昨日**，`index` 直接为空并在 `degraded` 标注；宁可没有，不拿昨天的冒充今天 |
| 空壳表 | 判 `empty` 而不是 `ok` —— 文件在但 0 行才是 `limit_list_d` 那种静默故障 |
| `daily` 缺失 | 直接 `SystemExit`，不产出半份报告 |
| 退出码 | `0` 产出完整（可含 degraded）；`1` `--strict` 且有 degraded；`2` 数据根不可读 |

11-05 实跑核对：`n=5571 / 上涨 87.4% / 中位 +2.02% / 涨停 92 / 跌停 2 / 成交 21351 亿 /
degraded=index_daily,limit_list_d`，与手工分析逐项一致。

## 四、测试覆盖（9 条，2.5s）

| 用例 | 防的是什么 |
