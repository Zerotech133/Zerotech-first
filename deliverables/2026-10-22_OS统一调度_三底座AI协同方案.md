## 一、核心思路（一句话）

**OS 不是「第四个调度者」，而是唯一的调度面：四个智能体全部降级为 OS 的「执行单元」，通过一条全公开的协同总线（既有四账本）交换事实，通过共享底座层（Z 系引擎/经验库/审批闸）实现互助与进化——谁也不直接指挥谁，一切调度经 OS 可见、经老田可签。**

## 二、先回答「DeepSeek Harness 有没有问题」

**底座本身没问题，三个前提要守住：**

1. **Harness 是框架不是模型**——它是任务执行框架（cron/重试/隔离/落盘），DeepSeek 是它将来承载的模型。今天 WO-DEV 治理线已验证框架可用（15+ 单、判例质量全项目最高）。真正的风险从来不在底座，在**接缝**（今晚 C1-C5 五实证）。
2. **异族隔离是优势不是负担**——DeepSeek（执行）/GLM（复核）/GPT-6.0（建议）三模型互不同源，任何一家的系统性偏差会被另外两家看见。这是你 10-21 模型异族编制裁决在调度域的自然延伸。
3. **它的边界要写死**——Harness/赵云只产建议与证据（V3.1 裁定），生产变更仍走五要素。底座越强，越要锁死权限，不是锁死能力。

## 四、统一协同总线（怎么不混乱）

**不建新系统。总线 = 已在跑的四账本 + 两条既有纪律：**

```
① tasks.json 工单账本   —— 派工/收口/验收（devtask 五守卫）
② task_exit_ledger      —— 计划任务退出码（窗口统计：新增/持续/修复）
③ 治理健康卡            —— 21 项检查，红黄绿
④ DOCS_INDEX            —— 文档现行性唯一索引
＋ S1-S5 五同步规        —— 收工即收口/TTL/索引同提交/一话题一归档/跨仓成对
＋ 五要素红线            —— 生产/系统/凭据类唯一放行通道
```

**「公开」的实现**：四账本全部是仓内明文 JSON/JSONL，任何角色任何时刻可读；OS 状态灯已实时消费②③——**公开不是新功能，是既有事实**。

**「不混乱」的实现**：各写各段（工单段/账本段/文档段原子写+回读校验）+ 异族互镜（下一节）+ OS 可见（§六）。

## 五、三个协同能力怎么实现（彼此辅助/修 bug/进化）

### 5.1 彼此辅助 = 经验互读
Z4 经验库五域（E1 量化/E2 防穿越/E3 横评/E4 沉淀/E5 supervision）全角色可读：赵云的治理判例、WorkBuddy 的施工判例、田丰的复核判例同库不同域。**A 踩过的坑写一条经验，B 遇到同场景先查库**——这就是「彼此辅助」，无需角色间私聊。

### 5.2 彼此修 bug = 异族互镜工单
新工单类型 **MUTUAL-REVIEW（互审单）**：
- 赵云（DeepSeek）产出的治理证据 → 田丰（GLM）复核签名后才可结案
- WorkBuddy 施工的代码 → 赵云跑 Z5 防穿越断言 + 判例检查
- 诸葛亮的建议草案 → 田丰核对建议与账本事实的一致性
- **分歧即报告**：互审不一致时自动升级 OS「待老田裁决」区——分歧不是故障，是异族互镜在工作

### 5.3 快速进化 = 判例签准即全员生效
```
任何角色发现判例 → Z2 实验卡（发现/证据/建议）→ 田丰复核 → 老田 OS 签字
→ 判例入 Z4（全员可读）+ 固化进对应工具（健康卡新检查项/守卫规则/测试断言）
→ 全员下次执行自动应用（不需逐个通知——它们读的是同一本账）
```
进化速度的瓶颈只剩你的签字节奏（这正是决策书「批量授权时段」要解决的）。

## 六、OS 调度面怎么建（你看得见、可调度）

**三层递进，全部复用 v9 生产稿骨架：**

### 第一层 · 看得见（本周可落，零新后端）
OS 大屏新增「军团调度视图」：
- 四角色状态卡（在做什么工单/底座心跳/模型绑定/key 状态）——数据源 tasks.json + 健康卡，静态直服
- 地基状态灯已有 → 扩为四角色各自的红黄绿
- 互审分歧队列（MUTUAL-REVIEW 不一致项 + 待签 Z2 卡）——这就是「待老田裁决」专区

### 第二层 · 可调度（工单化调度，不建新协议）
OS 上每个待办 = 一张工单。调度动作全部映射既有命令：
- 「派单」= devtask new（owner 落对应席位）
- 「催办」= 工单状态刷新 + 飞书提醒（走既有通道）
- 「签准」= approval_gate 卡片（OS 内嵌审批视图——这是 OS 从看板升格操作入口的最后一公里，与既有规划同向）
- **不发明新调度协议**：OS 是工单账本的「读写面」，不是新的大脑

### 第三层 · 自动协同（常态运转）
双锚自治轮（赵云 08:46 扫描/17:55 收口）+ 老田会话时归口（田丰）+ 互审单流转 + 月度 Z3 横评出「协同健康报告」（谁的建议被采纳多/谁的误报率高/分歧率趋势）——**调度日志本身也是账本，全程可回放**。

## 七、防混乱六锁（C1-C5 + 新风险）

| 锁 | 防什么 |
|---|---|
| ①四账本唯一总线，禁私聊通道 | 防信息旁路（角色间点对点必然产生第二本账） |
| ②S1-S5 同步规 | 防 C1-C5（过期快照/收口滞后/索引赛跑/修半拉/碎片化） |
| ③异族互镜 + 分歧升级 | 防单模型系统性误判静默扩散 |
| ④MUTUAL-REVIEW 双签制 | 防自审自签（执行者不结案，复核者不施工） |
| ⑤五要素不动 | 生产/系统/凭据仍唯一放行通道，底座再多也无可乘之隙 |
| ⑥调度全留痕 | 每个调度动作是账本一行，可回放可审计——混乱无处积累 |
