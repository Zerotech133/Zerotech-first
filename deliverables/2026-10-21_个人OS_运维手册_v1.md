## 4. 已知判例（运维红线）

1. **宿主 curl 必须 `--noproxy '*'`**：本机系统代理（127.0.0.1:59403）会拦截 localhost 请求并伪造 502/200，任何对 8080/8091 的探测都必须加 `--noproxy '*'`，否则结论不可信。
2. **DETACHED 孤儿进程 40-90s 被环境回收**：不可作常驻服务。WO-OS-05 期间 8094 并存实例被回收即此判例，别再尝试用 detached 进程跑 portal_api 副本。
3. **8091 是 SYSTEM 会话进程，用户态不可杀**：taskkill/Stop-Process 用户态均无效，重启/重载需宿主重启或管理员权限窗口。这是 /api/zhuge/brief 404 挂账的直接原因（路由代码在基线，实例未加载）。
4. **nginx 改配 reload 即生效，无需重启容器**：改 portal/nginx.conf 后先 `docker exec ai-portal nginx -t` 校验，再 `docker exec ai-portal nginx -s reload`；不要动容器本身（挂载是宿主文件，容器重启不丢配置但不必要）。

## 5. 回滚预案

场景 A：/os-entry 回旧页（os_entry.html）

- 还原 nginx.conf 一行并 reload（WO-OS-05 commit 8b9f8628 的 diff 即此一行）：
  - 现行（312 行）：`location = /os-entry { try_files /os_entry_v9_prod.html =404; add_header Cache-Control "no-cache"; }`
  - 回滚为：`location = /os-entry { try_files /os_entry.html =404; add_header Cache-Control "no-cache"; }`
- 然后：`docker exec ai-portal nginx -t && docker exec ai-portal nginx -s reload`
- 旧页 os_entry.html 及 v4~v8 全部保留在 portal/ 可直访，无需找回

场景 B：v9 页面本身出缺陷滚代码

- `git -C C:/项目/老田的AI助手 revert <对应 commit>`（v9 相关提交见第 7 节台账）
- 静态文件在挂载目录，git 还原工作区文件即生效（Cache-Control: no-cache，刷新即可），无需 reload
