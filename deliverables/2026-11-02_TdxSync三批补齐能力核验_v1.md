## 1. 增量逻辑核验（代码证据）

| # | 结论 | 代码证据（`quant_backtest/tdx_sync.py`） |
|---|---|---|

| 2 | **无窗口上限**：`while True` 逐页拉 `PAGE=5000`，直到空页/翻完（`offset >= total` 且 total>0）→ **backlog 全部拉完** | `:197-228`、`:42`（PAGE=5000）、`:43`（FLUSH_PAGES=40） |
| 3 | 重叠日去重：丢弃 `<= 本地 max date` 的行 | `:212-219` |
| 4 | `--tables` 与 `--all` 同路径：都进 `_run_sync`→`sync_parquet_table`，**仅表集合不同** | `:593-623`（`tables = a.tables.split(",")` 或 remote 全集）、`:160` |
| 5 | **无需显式日期/窗口参数**：CLI 只有 `--all/--tables/--include-rtmin/--status/--missing-keys-json/--backfill-receipt`，**没有 start/end/lag 参数** | `:524-532` |
| 6 | ⚠️ **增量模式零行不报错**：`if latest is None: 全量三查(carry 假完成拦截) else: pass`，注释「增量零新行=正常完成，不设闸不误杀」 | `:233-258`（关键 `:255-258`） |
| 7 | 表级异常会聚合为非零退出（`_run_sync` 返回 1）→ 任务 Last Result=1；但**零行不算异常** | `:603-623`、`:566-567` |
| 8 | 三批共用进程级互斥锁；已有实例在跑时打印 `[lock] SKIP` 并**正常返回 0**（静默跳过） | `:431-505`（`_core_lock_acquire`）、`:560-561`（`if not acquire(): return`） |
| 9 | 启动前先探远端 `/api/data/status`，失败重试 5×30s 后抛（进程退出非 0） | `:570-590`（`_remote_tables_with_retry`）、`:559` |
| 10 | 表按远端 rows 升序排（小表先跑，尽快见产出） | `:601-602` |
| 11 | sqlite 三表（公告/新闻/研报）同样按本地 max 日期增量 | `:290-336`（`_sqlite_latest_date` + `start_date=latest`） |

**→ Q1 回答**：默认就是「从本地 max date 增量拉到远端最新」（自动补齐 backlog）；`--tables` 批次完全适用；**不存在日期窗口/增量参数需要显式指定**（脚本无此类参数）。唯一要显式的是"表集合"，即三批已配置的 `--tables`。
