## 二、链路拆解（回答「入库后怎么用」）
```
L0 摄入  pdf_ingest / 语料 pipeline → 文本+结构+知识单元（已标准化）
L1 组织  知识单元 schema（book/chapter/page/claim/evidence）+ 可选知识图谱
L2 知识库 bge-m3 向量 + BM25 + RRF；引用可溯源；golden 评测
L3 模型  RAG 优先；仅在「检索差/排序差/风格需求」时训 embedding/reranker；LLM 不轻训（无 GPU）
L4 策略  知识单元→特征映射→假设登记→四关回测→台账/例会
L5 治理  catalog/血缘/备份/评测/版本/回滚（全部已有）
```

## 三、开源调研结论（关键取舍）
1. **PDF 解析升级**：当前 PyMuPDF+RapidOCR 对纯文字扫描书够用；遇表格/公式/阅读顺序问题 → 用 [MinerU](https://github.com/opendatalab/MinerU)（中文/表格/公式友好）、[Docling](https://www.ibm.com/think/news/doclings-rise-llm-ready-data)（IBM LLM-ready 结构化）或 [Marker](https://github.com/datalab-to/marker)（PDF→Markdown）。
2. **RAG vs 微调**：知识时效/可溯源 → RAG；风格/格式 → Prompt→LoRA；[决策指南](https://www.siliconflow.com/zh/blog/rag-vs-fine-tuning-decision-guide)、[对比](https://preview.boldare.com/blog/rag-vs-fine-tuning/)。
3. **微调触发条件（写进标准）**：embedding 微调需 Recall@5<0.6 且三元组≥5k（工具 sentence-transformers/FlagEmbedding），提升≥3pp 才上线；reranker 通用版已判无效（-2.4pp），未微调不上；LLM LoRA 需 GPU，当前不训。
4. **知识图谱**：单跳问答不上图谱；多跳/实体关系才用 [GraphRAG](https://github.com/microsoft/graphrag)/[LightRAG](https://github.com/HKUDS/LightRAG)/[KAG](https://github.com/OpenSPG/KAG)/HippoRAG2（[对比](https://cloud.tencent.com.cn/developer/article/2505959)）。
5. **策略假设生成**：可参考开源 [Agentic-AI-for-Quant](https://github.com/QuantSingularity/Agentic-AI-for-Quantitative-Research-and-Alpha-Discovery)（9-agent 假设→泄漏感知回测），但只做草稿，必须四关+人工审。

## 四、实测：检查器对两本书的验收
```
{"ok": true, "books": {"伏击涨停(2)": {"page_coverage": true, "ocr_quality": true, "structure": true, "units": true}, "涨停密码(2)": {...全部 true}}, "next_steps": 5}
```
- 指标：伏击涨停 page_coverage=1.0、ocr_chars/page=832、chapters=141、units=20、引用完整率=1.0；
- next_steps 自动给出后续 5 步（golden 评测→特征映射→假设四关→例会复核→备份登记）。

## 五、以后新资料的标准动作（照做即可）
1. PDF 放入 `C:/项目/PDF` → 跑 `pdf_ingest.py all --rebuild-rag`；
2. 跑 `pipeline_check.py --ingest-dir C:/项目/PDF/_ingest` → 必须 ok=true；
3. 按 next_steps 走：golden 评测 → 特征映射 → 假设登记/四关 → 例会 6 条复核 → 备份/登记；
4. 需要训练时，先按标准「触发条件」判断，不满足一律不训（RAG+Prompt 兜底）。
