## 研究 #R3 · 阈值锯齿（JEV_NIGHT_MIN_BACKLOG）实证

### 当前状态

- **阈值真实位置**：`jev-eval/start_jev_night.ps1:26` PowerShell 变量 `$minBacklog = 500`（env 覆盖名 `JEV_NIGHT_MIN_BACKLOG`）；**不是** Python 常量（tools/jev_night.py 无 MIN_BACKLOG 定义）
- 阈值作用：管**夜批启不启**——`if ($pending -lt $minBacklog) SKIP`（start_jev_night.ps1:48）；入队器独立运行（jev_review_queue.py:93 INSERT OR IGNORE），不归它管
- 复核队列：pending=200 / resolved=100 / unreviewed_legacy=10,425
- 最新入队：2026-11-07 14:24（距今天 **7 天**，满 24h 约 6.9 天）
- 过去 3 天新入队：0

### 阈值锯齿是什么

MIN_BACKLOG 只决定夜批跑不跑，入队数不该呈现"卡在 500 附近"的形态。**阈值真的在卡**的表现是：pending 累积但夜批连续 SKIP；**阈值没在卡**的表现是：pending 与入队都为 0（上游就没在写）。

### 观察计划（三列，因果模型修正）

| 观察项 | 取值 | 含义 |
|---|---|---|
| pending 是否累积 | 上升 / 持平 / 下降 | 入队器有没有在写 |
| 夜批是否 SKIP | SKIP / RUN | `$pending -lt $minBacklog` 时被跳过 |
| 入队器当日是否写入 | 0 / >0 | queued_at 当日新增 |

**裁定条件**：
- pending 累积 + 夜批连续 SKIP → 降 MIN_BACKLOG 到 100（阈值真在卡）
- pending 与入队都为 0 → 查上游（阈值不是瓶颈）
- 夜批 RUN 但 pending 不涨 → 夜批在清空队列（不是阈值问题）

  - **如果模型有系统性偏差**（conf 集中在 0.3-0.4），pass 率可能掉到 70-80%
