# 策阅板块重整 v2：策略发现 → 推荐池 → 鲁肃军团判断

- **日期**：2026-10-30
- **目标**：把分散的“策略页 / 选股页 / 池子 / 议会”重整为**一条单流程**
- **边界**：只做研究/推荐/判断，不接下单、不承诺收益；鲁肃军团判断≠自动交易

## 〇、名称说明

现有编制中 **鲁肃 = D1 量化交易部最终决策官**（非通信部；见 `docs/audit/2026-10-27_鲁肃与阚泽定名判例.md`）。
用户所说“鲁素德军团”，本文按 **“鲁肃军团 / D1 决策链”** 落地；若另有所指，以 A0 修正为准。

## 一、现状问题

| 问题 | 证据 |
|---|---|
| 入口分散 | `/strategies`、`/picks`、`/picks_public`、trade_pool、council 各自一套 |
| 池子口径不统一 | `todays_picks.json` 有 531 条、重点池 31、共振池 0，但缺少统一“推荐单”状态 |
| 策略与池子脱节 | 13 条策略在策略台账，推荐池未回写“来源策略/证据/时效” |
| 决策链不显形 | 鲁肃/ D1 的准入、否决、仓位意见没有统一队列与理由字段 |
| 时效风险 | 当前选股快照日 **2026-10-28**，已落后 2 天；不得把旧池当新信号 |

## 二、目标流程（唯一主链）

```
① 策略发现（只允许健康策略）
   策略信号 + 证据 + 数据日 + 时效 + 风险标记
        ↓ 去重/合并/分层/过期
② 推荐池（唯一候选池）
   推荐单：来源策略、分层、推荐理由、时效、状态=pending/审议/通过/否决/过期
        ↓ 只允许 pending + 未过期
③ 鲁肃军团判断（D1 最终决策）
   审议意见（攻防/风控/数据）→ 鲁肃决定：通过/观察/否决
        ↓ 通过后仍不自动下单
   研究结论/纸面观察 → A0 签（实盘才需）
```

## 三、数据契约（前后端统一）

### 1. 策略信号 `StrategySignal`
`signal_id, strategy_id, code, name, signal(买/观察/回避/卖), score, evidence[], data_date, generated_at, freshness_days, risk_flags[], trace_id`

### 2. 推荐单 `PoolItem`
`item_id, code, name, sources[], tier(重点/高价值/观察/拥挤), reason, first_seen, last_seen, data_date, expiry_date, status(pending/reviewing/approved/rejected/expired), risk_flags[], decision_ref`

### 3. 决策记录 `DecisionRecord`
`decision_id, item_id, decider=鲁肃(D1), verdict(通过/观察/否决), reasons[], risk_checks[], position_hint, decided_at, acad1_review, a0_sign(仅实盘)`

## 四、角色/RACI

| 环节 | 负责 | 说明 |
|---|---|---|
| 策略发现 | ST1 / STRAT1 / 原策略 owner | 只输出信号；健康状态由 ACAD1 台账管 |
| 推荐池 | ACAD1（治理）+ 量化中台（实现） | 去重/分层/时效/来源可追溯；池子唯一 |
| 鲁肃军团判断 | D1 鲁肃（最终）+ 攻防/风控/数据席意见 | 不通过不得入池；通过≠下单 |
| 研究治理 | ACAD1 | 月度评审、策略状态、No-Go/补证 |
| 实盘签批 | A0/老田 | 仅实盘/对外发布需要 |

## 五、板块页面（v2 原型）

三列/三步，全部中文：
1. **策略发现**：健康策略数、今日候选数、策略新鲜度；
2. **推荐池**：重点池/高价值池/观察池/拥挤警报数量、来源、时效、过期风险；
3. **鲁肃军团判断**：待审议队列、已通过/观察/否决、理由与风险；
4. 点击任意卡片看详情（来源策略、证据、时效、状态、决策链）；
5. 明确“当前快照日”和“过期不可用”提示。

## 六、迁移步骤

| 阶段 | 动作 | 验收 |
|---|---|---|
| M0（本次） | 架构 + 静态板块页；不改数据/代码 | 页面可看、规则清楚 |
| M1 | 新建统一 `recommendation_pool` 适配器，从 `todays_picks` 迁移 531 条 | 池子状态/来源/时效齐 |
| M2 | D1 决策队列：pending → 审议 → 通过/观察/否决；写决策记录 | 鲁肃可审、理由留痕 |
| M3 | 旧页面 `/picks` 等改为只读视图或跳转；不双写 | 单一入口 |
| M4 | 接入实盘/推送前，ACAD1 + A0 评审 | 未签不实盘 |

## 七、硬规则

1. 不健康策略（维护中/失败）不得进推荐池；
2. 过期池不得当新信号；页面必须显示数据日/剩余时效；
3. 推荐池“通过”≠下单；实盘/对外另签；
4. 鲁肃否决不得被策略页绕过；
5. 所有决策必须留理由和风险检查项，不能只留结果。
