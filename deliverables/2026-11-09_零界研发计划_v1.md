## 1. 计划目标

### 1.1 总目标

在 12 周内，把零界从“能跑但证据不足”推进到“**可发布候选（RC）**”：

- 全量测试从 **39 failed / 2 errors** 降到 **0 failed / 0 errors**（或经书面批准的明确例外）；
- 路由、注册表、静态快照、审计报告等**契约基线零漂移**；
- 鉴权从“列举式默认放行”改为“**默认拒绝 + 显式注册**”；
- B 阶段三个未闭合判据（B-1/B-3/B-6）有明确结论：通过或书面判定不通过；
- README/ARCHITECTURE/AGENTS/产品说明书**口径一致**；
- 性能达到内部 SLO；发布/回滚演练通过。

### 1.2 非目标（本周期不做）

- 不追求“功能数量翻倍”；不新开大模块。
- 不把研究策略包装成“可实盘”；不对外承诺收益。
- 不做“一次性大提交/全仓格式化”；不覆盖并行会话工作。
- 不在未审批情况下重启生产 8091/改 nginx/发布 10.205.0.118。

## 3. 研发原则（硬约束）

1. **一单一事**：一个任务单只做一个可验收变更；不混重构、不混格式。
2. **一任务一 worktree**：并行任务不共享工作区；不覆盖其他会话未提交改动。
3. **显式 pathspec**：只 `git add <明确路径>`；禁止 `git add -A`、`commit -a`、`reset --hard`、`clean -fdx`。
4. **证据优先**：每个“完成”必须附命令、输出、文件路径、时间；没有证据不算完成。
5. **质量门不绕过**：失败测试不能靠 skip/xfail 变绿；例外须 A0 书面批准并写进发布说明。
6. **默认只读**：审计/压测不改生产、不重启；需要发布时走 L2 五要素审批。
7. **口径唯一**：产品定义以 `PRODUCT_BASELINE v1.2` 为唯一源；对外口号以 A0-DEC-20261107 为准；旧文档只归档。
8. **可回滚**：每次发布/迁移前有备份、回滚命令、验证清单。

```
冻结窗口 → 建任务单 → 独立 worktree → 实现/测试 → 证据包 → 评审 → 分批提交 → 质量门 → 发布候选
```

| 角色 | 人/席位 | 职责 |

### W4（12-08 ~ 12-12）性能与可运维性

**目标**：达到 M2。

- 部署 factor freshness 缓存（需批准）并复测；必要时把 health 拆成“轻/重”。
- `/health` 并发优化：线程池/多进程/反代缓冲，目标 p95 <200ms。
- nginx：修 CRLF、`absolute_redirect` server 级、白名单；发布前 dry-run。
- 发布/回滚演练：备份→重启→health→回滚。

**验收（M2）**：性能表达标；nginx 结构测试通过；回滚演练有记录。

### W5-W6（12-15 ~ 12-26）B 阶段收口与文档统一

**目标**：达到 M3/M4。

- B 阶段剩余缺口修复；若不能通过，A0 书面判定“B 不通过”并调整路线。
- 文档统一：README/ARCHITECTURE/AGENTS/首页/产品说明书同一口径；旧文档加 `STATUS: archived/superseded`。
- 建立 `docs/DOC_INDEX.md` 唯一入口：当前有效/历史归档/已取代。
- 发布说明模板、用户手册、运维手册。

**验收**：B 阶段有结论；文档入口唯一；产品说明书 v1.1 评审通过。

### W7-W8（12-29 ~ 01-09）数据/量化证据链

**目标**：不要求 alpha，但要求“研究链路可审计”。

- 因子库 288 因子：catalog/health/compute 契约稳定；compute 缓存/超时/并发有测试。
- 策略中心：14 条策略状态与注册表一致；S12 影子盘有台账。
- 研究产物统一 schema：`schema_version/generated_at/source_commit/data_cutoff`。
- 数据仓：PIT、退市、复权、两融覆盖有校验；缺失数据必须显式 WARN。

**验收**：任取一个研究结论可追到数据/代码/提交；策略状态无“口头 approved”。

### W9-W10（01-12 ~ 01-23）稳定性与 SLO

**目标**：达到 M5。

- 7 天稳定性观察：8091/8734/计划任务/日报无 P0；错误率、延迟、任务成功率有台账。
- 容量：并发 50/100 压测；限流/超时/降级。
- 备份恢复演练：数据仓、catalog、策略注册表。
- 监控：health、任务失败、数据新鲜度、端口。

**验收**：SLO 达标；恢复演练通过；监控有告警。

### W11-W12（01-26 ~ 02-06）发布候选

**目标**：达到 M6。

- RC 冻结：只修 P0/P1，不加功能。
- 全量回归 + 验收清单 + 发布说明 + 回滚脚本。
- 外部用户试用（小范围）；收集反馈；决定 GO/NO-GO。
- 若 GO：发布 v1.0；若 NO-GO：写“未通过项 + 下一周期计划”。

**验收（M6）**：发布评审会通过；回滚可用；无 P0/P1 未闭环。

## 9. 风险与应对

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| 并行会话继续改同一文件 | 高 | 基线反复漂移 | 冻结窗口 + owner 表 + 独立 worktree |
| 测试隔离问题导致“假绿” | 高 | 发布判断错误 | 分套件 + 随机顺序 + 隔离目录 |
| 修基线掩盖真实缺陷 | 中 | 质量下降 | 基线变更必须附 diff 说明/评审 |
| B 阶段判据无法短期闭合 | 中 | 发布延期 | 允许“书面不通过”，调整路线，不造假 |
| 性能优化引入新并发 bug | 中 | 生产不稳定 | 先本地/预发压测，再灰度 |
| 文档再次分叉 | 高 | 用户/团队误解 | 单一入口 + 旧文档归档 + 评审 |
| 生产重启窗口风险 | 中 | 服务中断 | L2 审批、备份、回滚演练 |

## 10. Definition of Done

一个任务只有同时满足以下条件才算完成：

- [ ] 代码/文档改动在独立 worktree，路径明确，未覆盖他人。
- [ ] 有对应测试/验收命令，且通过。
- [ ] 有证据包（命令、输出、文件路径、时间）。
- [ ] 有回滚点/回滚命令。
- [ ] 评审通过（至少 1 名非作者）。
- [ ] 更新任务单/台账；不把“口头完成”当完成。
