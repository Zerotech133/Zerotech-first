# devtask 沙箱开关 v1（L1 收口）

> 工单：`WO-SANDBOX-WIRE-20261027` ｜ 日期：2026-10-27 ｜ 状态：**已实现**
> 目标：把 ⑧ Agent 沙箱接进 devtask，让 DEV/ARCH1 席可以 opt-in 在 Docker 隔离环境执行命令；**不改变现有命令行为**。

## 1. 用法

```powershell
# 干跑（零容器，只输出 docker 命令计划）
python tools/devtask.py sandbox --cmd "python3 -c 'print(1)'" --dry-run

# 实跑（仓库只读挂载 / network none / cap-drop / 超时）
python tools/devtask.py sandbox --cmd "python3 -c 'print(1)'"

# 可选参数
#   --image <镜像>       默认本地已有 openmetadata/ingestion（含 python3.12）
#   --network none|bridge  默认 none；bridge 仅排障且打印告警
#   --timeout 120
```

## 2. 安全边界（与 agent_sandbox 一致）

- 仓库 `/workspace:ro` 只读；仅 scratch `/work:rw`；`--network none` 默认；
- `--cap-drop ALL`、`no-new-privileges`、rootfs `--read-only`、`/tmp` tmpfs；
- 不碰生产容器/compose/计划任务/网络；超时自动 `docker rm -f`。

## 3. 实测（2026-10-27）

- `pytest agent_platform/tests/test_devtask_sandbox.py` → **2 passed**；
- dry-run：输出计划，`--network none`、`:ro`；
- 实跑：`python3 -c 'print(7)'` → **ok/rc=0/1.49s/stdout=7**；
- 现有 devtask 命令（new/list/merge/port/...）行为不变。

## 4. 边界与后续

- 沙箱是 **opt-in**，未强制所有 dev 单默认走容器（强制执行需另批，且要评估性能）；
- Docker daemon 访问仍是宿主级能力，沙箱只限制容器内；
- 后续：CPU/内存配额、egress allowlist 代理、容量化 benchmark 纳入 ARCH1 eval。
