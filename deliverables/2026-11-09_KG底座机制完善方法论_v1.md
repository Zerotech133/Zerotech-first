# KG 底座机制完善方法论 v1

> 2026-11-09 · 老田裁定定位原文：KG = 数据仓的结构化枢纽与通报台——监控、挖掘整理入库、切成最小颗粒、变成因子、全程可溯源/可想象/可推理。大家从 KG 过一道，因为所有信息已结构化，分析速度因此提起。
>
> 本文档回答一个问题：**这套机制靠什么运转，以及它如何自我完善。**

---

## 一、机制全景：六层流水线 + 一个自愈环

```
[采集 A 组] ——原样数据——→ ① 源心跳层（监控通报）
                                 ↓
                            ② 入库治理层（校验、写门、对账）
                                 ↓
                            ③ 颗粒化层（实体/边/本体，1.6M 节点）
                                 ↓
                            ④ 因子化层（图知识 → 可计算量）
                                 ↓
                            ⑤ 消费层（缠论池/回测/看板/人）
        ↑                            ↓
        └────── ⑥ 自愈环（判例→用例→回归→制度化）←──────┘
```

**核心设计判断**：KG 不拉数据、不碰采集。它的输入端契约是「源头给我新鲜数据，我告诉别人断没断」；它的输出端契约是「任何人来问，我有结构化的答案，且答案可溯源」。中间的一切——颗粒化、因子化——都是在这两个契约之间做增值。

## 二、逐层完善方法论（现状 · 缺口 · 演进路径）

### ① 源心跳层 —— 监控与通报

**现状**：source_fresh 对账每日跑；完备度通报 v1 已出（七条断供归因 + A 组行动请求）；因子表带 data_gap_days。

**方法论要点 ——「通报五问」固定句式**：
每一条断供，通报必须答全五问，缺一问就不算闭环：
1. **缺什么**（哪张表/哪个源，停在哪天）
2. **数据点在哪**（哪个采集器、哪个脚本、哪台机器负责）
3. **为什么以前有现在没了**（归因到具体故障：调度消失 / 脚本失传 / 上游断供 / 周末口径）
4. **谁认领**（采集 A 组 / xtcloud / 缠论组自身，写名字不写「相关方」）
5. **多久恢复**（有承诺时限，次日通报对账昨天的承诺）

**已踩出的口径纪律**（都是真坑换来的）：
- 周末与无日期列表要加宽限，否则 37 项告警里 34 项是噪音——**告警噪音本身就是故障**，会训练人忽略告警
- 断供天数必须用 tx_created（Date 类型）算，字符串 max 会误判（`202610-01` 畸形格式活样本）
- 通报里区分「空白=真没有」与「空白=设计口径」（雪球 33,481 帖仅 24,754 入图是"只收带股票提及"的设计，不是丢失）

**演进路径**：通报五问落成固定模板 → 承诺时限对账自动化 → 最终每条断供自动路由到认领组。

### ② 入库治理层 —— 校验、写门、对账

**现状**：KG_WRITE_ACK 写门；MERGE 索引先行；Cypher 词法校验防注入；晨链对账 latest.json。

**方法论要点 ——「三道门」**：
1. **进门校验**：日期合法性、字段类型、必填项——非法数据进隔离区，不带病入库（news.db 畸形 ts `2026-10-16` 就是没这道门的后果）
2. **写门放行**：所有写入走唯一入口，带 ack 确认，越轨写可被 drift 检测抓到（今晨 drift 3 条定性为合法新增——**能证明"没越轨"和能发现"越轨了"是同一套机制**）
3. **出门对账**：水位 vs 库内总量 vs 图内总数三方对账，数字精确相等才算闭合（138,729 三方一致是当日零漂移的硬证据）

**口径纪律**：凡统计先声明口径——「记录数 vs 唯一股」差 263 笔加仓；「标签拆分计数 vs 总量」差 531；不声明口径的数字不许进通报。

**演进路径**：进门校验补齐日期类 → 隔离区带每日盘点 → 对账三方化推广到全部源。

### ③ 颗粒化层 —— 实体 / 边 / 本体

**现状**：55 类实体 / 60 类关系 / 160 万+ 节点；kg_viewer 四层联动台（直方图/时空/时间刷/传导）；114 个索引。

**方法论要点 ——「切颗粒的三个标准」**：
1. **可独立问**：一个最小颗粒必须能单独回答一个问题（席位带胜率 → "哪个席位胜率高"一问即答）
2. **可组合**：颗粒之间靠边组合出复杂答案（IntelItem→Security→MarketEvent 传导链 = 三种颗粒两条边）
3. **可溯源**：每条边能回答"从哪来"（词典 94 + 人工救回 3 = ABOUT 97，边数本身带出处）

**数据质量即颗粒质量**：act_name 5,572 条污染（实控人名混进证券简称）说明——**上游一个字段的病，会污染一整类颗粒**。清洗方法论是"先改名（controller_name 承认它是什么）再重建（namechange 恢复它该是什么）"，两档修复正是这个顺序。

**演进路径**：本体词典化（每类实体/关系一段中文定义入库）→ 颗粒质量抽检制度（每周随机 N 条边人工核真伪）。

### ④ 因子化层 —— 图知识变可计算量（当前最大缺口）

**现状**：情报因子表 v0 首出（men_total / men_7d / last_mention / 四源 data_gap_days），1,424 只持仓股全覆盖；席位胜率、传导密度等图谱独有量已在图内、尚未因子化。

**方法论要点 ——「因子三级成熟度」**：
- **F0 可查**：图里查得到（今天手工出表即此级）
- **F1 可算**：每日自动流出、带断供标注、可直接 join 回测（15:40 日更管道已达此级）
- **F2 可用**：经回测验证有区分度（IC/分层收益），正式进因子库被策略引用——**没过回测的因子只是"有趣的数字"，不配进策略**

**图谱独有因子 ≠ 行情因子的复述**。席位胜率、情报增量、社区传导密度、事件密度——这些是行情数据算不出来的，是 KG 的差异化价值所在，也是因子化优先序的第一原则：**先做行情侧算不出的，再做行情侧算得出但图里更便宜的**。

**演进路径**：F1 已达 → 下一件是 F2 验证框架（因子表 × 回测引擎的 IC 快速检验）→ 建正式因子库目录（每个因子一段元数据：来源边、计算口径、验证结论）。

### ⑤ 消费层 —— 让大家真的"从 KG 过一道"

**现状**：8797 人话工作台（全中文、真实口径、空就是空）；/flow 传导视图；因子表 CSV；通报 md。

**方法论要点 ——「消费体验三律」**：
1. **说人话**：界面中文、口径人话（"有关联就是有，没有就是没有"）——工具门槛每高一分，消费就少一分
2. **空也是答案**：查无数据要明示"图内暂无此节点的关系边（真实为空）"，区分"没有"和"没查到"
3. **伸手即得**：因子 CSV 进回测目录、通报进 deliverables——消费者不需要懂图，拿文件就能用

**演进路径**：缠论组定池 → KG 出池完备度+因子的固定套餐 → 反过来收集消费侧的真实提问，**高频提问固化为标准视图**（/flow 就是这么来的）。

### ⑥ 自愈环 —— 机制怎么自我完善（本方法论的核心）

**这是今天全天实际运转过、且被证明有效的那个环**：

```
故障/坑 → 判例入库（写清楚根因与规矩）→ 规矩变成用例（回归锚点）
       → 用例挡住复发 → 高频判例上升为制度（工具/流程/编排）
```

**今天的完整实例**：
- H1 闸门 FAIL（多进程共写 tmp 撞锁）→ 判例 → 当天产出 common_filelock.py + 8 进程并发自测 → 两处写点加固 → **这类故障从"会复发"变成"结构上不可能"**
- 上午审查→修复→用例闭环：3 个真 BUG → 8 组 48 断言全过 → P2 --plan 真实回归 94 边零漂移。**修复必须留用例，没有用例的修复等于没修**（下次改代码一样会踩回去）

**判例制度的四条纪律**（全部来自真实踩坑）：
1. 判例写"根因 + 规矩"，不写"以后小心"——可执行的规矩才有用（"f-string 多行拼接只有首段带 f 会静默变字面量" ✓；"注意字符串拼接" ✗）
2. 判例必须带复现/验证手段（断言锚点、字节复核、ord 复核）——数字类结论禁止凭打印判断（数字串味判例 10↔68 的教训）
3. 已犯的坑要有制度性防线：heredoc 串味 → Write 工具铁律；失传脚本 → 建议加"worktree 有主仓无"周扫描；文件锁 → 公共工具
4. 判例入工作日志 + 回归用例**双落点**——日志管人记，用例管机器挡

## 三、成熟度模型（机制在哪一级，往哪级走）

| 级别 | 特征 | 本机制现状 |
|---|---|---|
| **L0 手工** | 人肉跑、人肉看、坏了靠碰 | —— |
| **L1 自动** | 定时跑、有告警、有对账 | 晨链/日更/通报/因子已达 ✓ |
| **L2 有契约** | SLO 明确、告警去噪、断供有认领时限 | 通报五问半自动，时限对账未建 ◇ |
| **L3 自愈** | 缺陷→用例→回归全自动闭环；推理补盲区 | 判例环已人工运转，制度未代码化 ◇ |

**结论：机制整体在 L1.5，成熟区在监控与治理（接近 L2），幼弱区在因子验证与推理（L1 初）。**

## 四、北极星指标（怎么衡量机制在变好）

不看做了多少功能，看五个数：
1. **告警信噪比**：真断供数 / 总告警数（今天 37 项里真断供 3 → 宽限口径后应 >50%）
2. **通报五问答全率**：每条断供归因是否答全五问（目标 100%）
3. **判例复发率**：同类坑是否二犯（有回归用例的判例应趋近零复发）
4. **因子 F2 占比**：进因子库的图谱因子中经回测验证的比例（当前 0/N，是下一阶段主攻）
5. **消费侧依赖度**：缠论/回测/看板每天从 KG 拿走多少次数据（从 0 增长即证明"大家从 KG 过一道"落地）

## 五、近期路线图（按方法论排的序，不是按活多活少）

1. **L2 补课**：通报五问模板化 + 认领时限对账（把通报从"报告"升级为"契约"）
2. **因子 F2 验证框架**：因子表 × 回测 IC 快检——这是"变成因子"从口号变能力的临门一脚
3. **推理起步**：传导链自动发现（情报组合 → 行情后果的统计挖掘），先跑一只池内股的全链验证
4. **进门校验补齐**：日期类隔离区，终结畸形时间入库
5. **判例环代码化**：worktree 失传脚本周扫描 + 颗粒质量周抽检，让自愈环自己转起来
