## 一、接线方案设计

### 1.1 时序硬约束

简报器只读池档 `reports/xunyou_pool_{date}.json`（`xunyou_brief.py:235-236` 默认拼 `REPORT_DIR`，`REPORT_DIR` 定义于 `strategy_layer/xunyou.py:40`），池档由工作日 17:45 automation「荀攸盘后作业与股票池产出」（id `22e101fe-a101-4335-8c70-d66a53e6c01c`，rrule `FREQ=WEEKLY;BYDAY=MO,TU,WE,TH,FR;BYHOUR=17;BYMINUTE=45`，ACTIVE，本工位只读 view 实证）产出。**简报必须在当日池档落盘之后运行**，否则池节降级（见 §四.2）。

### 1.2 两种方案对比

| 维度 | 方案 A：同链追加（改 17:45 automation prompt，链末追加简报命令） | 方案 B：独立 automation 错峰（新建 18:10 automation） |
|---|---|---|
| 顺序保证 | 同一 prompt 内顺序执行，天然池后 | 晚 25 分钟调度 + 同源串行队列按到期序执行（实证见 §四.1），双保险 |
| 变更面 | **修改已批准的在产 automation**（prompt 全文重写、重新报批），链中含 PG 写库（融合链 `SignalAggregator.run`，M0 计划:259），研究留痕与生产写库耦合在同一会话 | 零触碰既有 automation；新增实例自带独立开关 |
| 只读纪律 | 简报与写库作业同会话，Agent 上下文混杂，纪律边界靠 prompt 约束 | 简报独立会话，prompt 全程 RESEARCH_ONLY，边界干净，利于"无越权"审计举证 |
| 失败隔离 | 简报异常需 prompt 里加"不影响盘后作业结论"条款，语义变复杂 | 简报失败（实际上不抛异常，见 §1.4）不影响 17:45 链任何环节 |
| 排队风险 | 无新增排队（搭既有链） | 加入同源串行队列，可能被长任务占槽延迟（判例 64 分钟，§四.1）；延迟只影响留痕时点，不影响正确性 |
| 回滚 | 需恢复原 prompt（要有原 prompt 备份） | 删除新 automation 一条命令 |
| 审计留痕 | 与盘后作业混在一条 run 记录 | 独立 run 记录，逐日对应，试运行台账干净 |

**结论：推荐方案 B。** 决定性理由：①M0 计划 B2 验收标准是"Agent 连续 5 个交易日只读日报无越权"（M0 计划:88），独立只读会话让"无越权"举证最干净；②铁律"改计划任务/automation 前须老田批准"——方案 A 动的是在产任务，方案 B 是纯增量，风险不对称；③回滚成本一条命令。方案 A 仅在"同源串行排队延迟被实证不可接受"时作为备选（届时另行报批）。

### 1.3 触发方式（automation prompt 全文见 §三 要素①）

- 调度参数：`FREQ=WEEKLY;BYDAY=MO,TU,WE,TH,FR;BYHOUR=18;BYMINUTE=10`（工作日 18:10，与 17:45 链同 BYDAY 口径）。
- **不传 `--date`**：CLI 默认当日（`xunyou_brief.py:266-267`），避免 Agent 会话内手算日期出错。
- 不传 `--out-dir/--pool/--evidence-db/--posterior`：全部走默认路径（`xunyou_brief.py:268-274`），与 17:45 链产物路径同一事实源。
- 运行目录：沿用 17:45 链的写法——automation `cwds=C:/项目`（17:45 链实证），prompt 内嵌"工作目录 `C:/项目/老田的AI助手/quant_backtest`"，命令 `-m strategy_layer.xunyou_brief` 与该链 `-m strategy_layer.xunyou` 同构。

### 1.4 失败语义：接线层不重试、不告警升级的理由

1. **简报器 closed on failure 已内建**：模块头声明"任何一节缺料/异常均降级占位（DEGRADED + 文案），绝不抛异常中断整份简报"（`xunyou_brief.py:15-16`）；逐节由 `_guarded` 包裹，单节源抛异常降级占位、整体继续（`xunyou_brief.py:135-141`，单测 `tests/test_xunyou_brief.py:150-163` 覆盖）。
2. **CLI 恒成功**：`main()` 正常路径返回 0（`xunyou_brief.py:286`），缺料不改变退出码——调用方无从"失败"，自然无需重试。
3. **重试反而有害**：简报对给定输入是确定性产物，重试产出相同；若因池档未产出而重试，会把"真实降级状态"从留痕中抹掉，恰恰破坏试运行要观测的数据。更危险的是任何"补跑生产者"的冲动——prompt 中显式禁止。
4. **人工可见性已足够**：automation run 记录 + 每日简报文件本身就是留痕；试运行期验收靠人工抽读（§二.3），不需要告警链（简报不直连飞书，章程 `xunyou.py:5-6`；飞书自动推送属 Sprint C4，M0 计划:94）。

### 1.5 产物去向与消费面

- 产物仅两份：`quant_backtest/reports/xunyou_brief_{date}.md` + 同名 `.json`（`xunyou_brief.py:251-257`，原子写 `:217-221`）。
- **试运行期间不接 portal、不发飞书**：`portal/tools/export_xunyou_latest.py` 只认 `xunyou_pool_*.json`（`export_xunyou_latest.py:32`），简报文件天然不进看板数据源，无需任何防护；C4 飞书推送未到拍板时点。
- 消费面 = 老田/工位每日人工抽读 `reports/` 留痕（§二.3 清单），试运行 5 日满后随验收包一并呈报。

## 四、风险节

### 4.1 同 sourceKey 串行排队延迟（判例实证）

判例：automation id `90a901b3`（16:40 快照）被同源任务 `4c4ba572`（15:57 开跑、约 78 分钟）占槽，调度器持续 `skip same-source ... (serialized, max 1); keep due for next tick`，直至 17:44:25 才 dispatch——延迟约 64 分钟，任务未丢失（`deliverables/A4观测悬案诊断_HK缺池与1640排队_20261019.md:38-50`）。

对本接线的影响与对策：
- 18:10 简报可能与 17:45 链及长任务（雪球小时轮 `4c4ba572`/`8f86a61e`、30 分钟轮 `a970ff01` 等）排队，实际执行时点可能晚于 18:10。**延迟只影响留痕时点，不影响正确性**（简报器无超时敏感逻辑，读的是当日池档文件）。
- **错峰设计的正面价值**：同源串行 + 晚于 17:45 调度 = 排队按到期序释放的实证观察下（判例中 17:15 后按 16:30→16:40→16:40 到期序依次执行，同上文），**即使 17:45 链被大幅延迟，简报也会排在其后**——同源串行反而是时序保障，而非纯风险。
- 若试运行期实测排队常态化超过 1 小时，备选：微调至 19:05（19:00 雪球日报后空窗）或方案 A 同链追加（另行报批）。调度器同源判定与到期序的内部规则为实证观察，**待核实**（见 §五）。

### 4.2 池档未产出时的降级表现

简报照产、池节占位：`_pool_section` 对缺档返回 `{"status":"DEGRADED","reason":"池档未产出"}`（`xunyou_brief.py:43,51-53`），MD 渲染为降级文案（`:166-168`），整份简报不中断（单测 `tests/test_xunyou_brief.py:110-118`）。触发场景：17:45 链失败/被延迟到简报之后/法定假日。台账按"当日事实"记录，不算越权。

### 4.3 evidence_chain.db 未启用时的表现

默认路径 `quant_backtest/data/evidence_chain.db`（`evidence_chain.py:39`）**当前实测不存在**（B1 证据链建库属 Sprint B 待办，M0 计划:84），且后验档 `portal/data/combined_verdicts.json`（`combined_verdicts.py:42`）当前实测也不存在。因此试运行初期**预期三节中仅池节 OK，证据节/后验节恒 DEGRADED**（"证据链未启用或不可读" `xunyou_brief.py:44,84-86`；"后验档未产出" `:45,103-105`；两分支均有单测 `tests/test_xunyou_brief.py:122-133,137-146`）。读取走 `file:?mode=ro` 只读连接（`xunyou.py:261`），缺库时优雅降级、不建库不写 WAL——这正是真实状态的如实留痕；B1 建库、B3 后验引擎扩展（M0 计划:86）落地后对应节自动转 OK，**接线无需任何改动**。
