3. **写接口按文档无鉴权**：`POST /api/data/update`、`/download`、`/stop`、`/token` 文档明确“无需鉴权”；本次没有实际触发写接口，避免改变对方数据/凭证。若 48088 不是严格内网白名单，任何人都能替换 Tushare token、触发 245GB 下载或停止采集。
4. **计数口径互相矛盾**：`/api/data/status` 的 `ts_daily.rows=8,230,600`，`/api/data/table/ts_daily` 的 `total=19,166,919`，且 `total_exact=false`；`data-sources` 也是 19,166,919。分页不能依赖 `total`。

## 三、文档问题分级

### P0：接入前必须处理

1. **无鉴权 + HTTP + 写接口**
   - `POST /api/data/update`、`/download`、`/stop`、`/token` 可改变数据/凭证。
   - 建议：48088 只监听内网/VPN；写接口加 admin token 或 mTLS；至少只允许 localhost/白名单；不要沿用“免鉴权”描述。

2. **板块接口静默停更**
   - `tdx_sector_daily`、`tdx_sector_min` 最新 20261022，rank 返回空数组而不是 503。
   - 建议：修采集器；在修复前让板块接口返回 `503`/明确 `unavailable`，不要返回 200 空数据。

3. **历史分钟线断层**
   - `ts_stk_mins` 停在 2026-10-28，`ts_rt_min` 却在实时更新。
   - 建议：补 `rt_min -> stk_mins` 的按日归档任务；文档明确“rt_min 是实时缓存，不是历史分钟库”。

### P1：影响正确使用

4. **计数不可信**
   - `status.rows`、`table.total`、`data-sources.rows` 三套数字不一致；`total_exact=false` 未写入文档。
   - 建议：统一以 `COUNT(*)` 或明确的估算口径输出；分页按 `offset` 递增直到空，不按 `total` 计算页数。

5. **文档静态快照过期**
   - 文档日期 2026-11-05，表内日期 20261104；`ts_daily` 行数/大小均过时。
   - 建议：删除静态行数，改为“以 `/api/data/status` 实时返回为准”；文档只保留字段/口径。

6. **`/api/status` 的 connected/trading 语义不清**
   - `connected=false`、`trading=false`，但 `rt_min.active=true` 且刚更新；调用方无法判断是“行情断开”还是“仅主连接未建”。
   - 建议：拆分 `quote_connected`、`collector_active`、`trading_session`，并给每个数据源单独的 `freshness`。

7. **重接口没有限流/异步**
   - `/api/backtest/screen` 全市场约 7.5 秒；`/api/data/table` 单次最多 5000 行但可被反复拉取；`/api/data/download` 可触发 245GB。
   - 建议：加超时、并发限制、请求 ID；全市场选股改为异步 job + 轮询；导出单独限流。

### P2：文档/契约完善

8. **“tbl 上表 30 张表名之一”与实际 181 张矛盾**，应改为“181 张，见 `/api/data/status`”。
9. **空表/空列未标记不可用**：`ts_limit_list_d`、`ts_index_member`、`ts_rt_k`、`ts_opt_mins`、`ts_hibor/libor/shibor` 等 0 行或空表，文档仍按普通表列出。
10. **日期语义**：文档说“date ≥ 最大日期走实时”，但板块接口在 `date=20261111` 时仍返回 20261022 的空结果；需要统一返回 `as_of`、`stale`、`stale_reason`。
11. **错误格式只有 `{"error":...}`**，没有错误码/请求 ID/重试建议；建议补 `code`、`request_id`、`retryable`。
12. **无 OpenAPI/版本化**：文档是 Markdown 快照；建议导出 OpenAPI 3.0，版本号与 `/api/status` 的 `version` 对齐。

## 四、接入建议

### 建议接入的部分

- **日线/基础/资金/财务/公告**：走 `/api/data/table/{tbl}`，按 `start_date/end_date` 分段，`limit<=5000`，用 `offset` 递增直到空；不要依赖 `total`。
- **实时分钟**：只把 `ts_rt_min` 当“盘中快照”，按 `code` 或最新时间读取；不要当历史分钟库。
- **数据覆盖核对**：用 `/api/backtest/data-sources` 做辅助核对，但最终以 `/api/data/status` + 实际表查询为准。
- **因子/回测**：`/api/backtest/factors`、`/api/backtest/health` 可用于能力发现；全市场选股不要同步调用，改为异步任务。

### 暂不接入的部分

- `/api/tdx-sector/*`：板块日线/分钟停在 20261022，rank 返回空；修复前不要用于策略。
- `/api/data/update|download|stop|token`：无鉴权，禁止从业务系统调用；只允许运维在内网人工执行。
- `ts_stk_mins`：历史分钟不可用；需要先补 10-28 之后的归档。

## 五、给对方的修复清单

1. 给写接口加鉴权/白名单，关闭公网直连；HTTP 改 HTTPS 或只走内网。
2. 修 `tdx_sector_daily/min` 采集；修复前 rank/members 返回 503，不返回空 200。
3. 补 `ts_rt_min -> ts_stk_mins` 日归档；监控 `ts_stk_mins` 最新日期。
4. 统一三套计数口径，文档标注 `total_exact` 的含义；分页改为 offset 直到空。
5. 文档改为动态口径：删除静态行数/日期，只保留字段、参数、口径和示例。
6. `/api/status` 拆分行情连接、采集器、交易时段、各源 freshness。
7. 加限流/超时/请求 ID；全市场选股异步化。
8. 输出 OpenAPI，标注空表/不可用表。
