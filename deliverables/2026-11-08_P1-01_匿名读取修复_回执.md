## 1. 漏洞与根因

审计 `P1-01`（`deliverables/2026-11-08_全仓代码审计报告_v1.md`）：

- `portal/portal_api.py:2021-2029` 在 `:2033` 全局 GET 鉴权闸门之前分派 `/api/flow/artifact`；
- `portal/nginx.conf:353` 将 `/api/flow/` 列入公开白名单，无 `auth_request`；
- `portal/api_flow.py:689-747` 的 `_flow_artifact` 只做 `..` 拒绝和 `abspath/commonpath` 判断，未做 token 校验；
- 审计时 8091/8734 均可无 token 读取 `portal_api.py`、`api_flow.py`、`api_common.py`、`work/tune_requests.jsonl`。

## 2. 修复内容

文件：`portal/api_flow.py`，`_flow_artifact(self, qs)` 开头、读取 `p` 之前：

```python
if not self._check_portal_token():
    self._json({"ok": False, "error": "unauthorized",
                "message": "forbidden: 缺失或不匹配的 X-Portal-Token"}, 403)
    return
```

`_check_portal_token()` 沿用既有口径：本机直连/本机浏览器（`_is_local_req()`）放行；反代+局域网必须 `X-Portal-Token` 常量比对。原有路径 `..`/白名单校验保留，失败关闭发生在任何文件读取之前。

新增回归测试 `portal/test_api_flow_artifact_auth.py`：

1. 匿名请求 → 403，且响应不包含文件内容；
2. 带合法 token → 200，返回 `portal_api.py` 文本；
3. 带合法 token 但 `p=../` → 仍 400（路径校验未被绕过）。
