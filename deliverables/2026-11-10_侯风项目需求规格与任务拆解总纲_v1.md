# A · 需求规格化

> 适用场景：任何执行者拿到此规范，无需额外咨询即可理解"侯风每日作业系统"要做什么、不做什么、如何验收。所有策略口径以 `M2_FROZEN.json`（v3c 重冻）为单一事实源。

## A.1 需求背景

侯风是一个 **A 股日频选股系统**，研究期自 2025 年底启动，2026-11-07 完成 M2.1 口径冻结（老田签字确认），2026-11-10 完成全项目代码审计并修复 9 项 P1 缺陷（**策略口径零变更**）。

| 项目 | 事实 |
|---|---|
| 定位 | 环境闸门 × 动量共振 × 低波加权 × 短持有 的 A 股日频选股 |
| 产出 | 每日"开闸/关闸 + 30 只买入清单" |
| 对外发布 | H5 产品族（8080 端口 `/houfeng/`），9 页 + 9 数据包 |
| 冻结口径 | M2.1，v3c 重冻（引擎 b8631e8e / 裁判 690505da） |
| 审计结论 | 0 P0、9 P1 全部修复、31 P2（生产链修 11 项）；22/22 单测通过，门禁全过，端到端选股链演练通过 |
| 唯一入口 | `_qpzm_rd_20261106/daily_run.py`（唯一每日作业入口） |
| 收益裁判 | `quant_backtest/portfolio_sim.py`（md5 690505da）——引擎虚拟净值已废弃 |

## A.2 核心目标（不可变更的设计约束）

| # | 目标 | 约束说明 |
|---|---|---|
| G1 | **唯一口径** | 只认 `M2_FROZEN.json`，不提供池切换、不提供口径降级、不支持运行时参数覆盖 |
| G2 | **不迭代策略** | 策略参数（top_n/hold/cost/排序键/加权方案/闸门阈值）一律从冻结文件读取，代码中**不写任何策略默认值** |
| G3 | **响亮失败** | 引擎指纹漂移（exit 3）、数据不全（exit 4）、产物与口径矛盾（exit 5）、选股子进程崩溃（exit 6）一律非零退出，绝不"少一点也能出" |
| G4 | **状态化输出** | 闸门关闭是合法状态（只观察，不出买入清单），不是故障；但绝不因此修改口径或降级参数 |
| G5 | **单一事实源** | 收益/回撤唯一裁判：`portfolio_sim.py`；引擎 `qpzm_backtest.py` 只产信号集，虚拟净值已废弃 |

## A.3 功能描述（五道关研判主干，不可跳过、不可并行）

```
① 环境闸门  breadth<0.40 或 med20<-3% → 关闸（只出影子信号，不开新仓）
② 共振过滤  tech(4策略×25±10) × RPS 复合 × env 打分，buy_th=75 / obs_th=50
③ 硬线过滤  drop_p1：RPS50 分位 <50 的候选剔除（过滤后不足 10 只保池）
④ 排序取整  score 降序取 top30（score 不可动，三连证伪 score_resid/rps 均失败）
⑤ 出场规则  T+1 开盘买入 → 持有 5 个交易日收盘卖出（一字板 exact 判定剔除）
```

**"研判中盘"不存在**：五道关之间没有任何人工裁量环节。所有历史改进尝试（debeta 排序、全局止损、TP/SL 价格计划）都已在 M2_FROZEN.json 的 `rejected` 清单中否决，防止"换个日子再试一次"。

### F1 · 环境闸门（gatekeeper v3）

| 维度 | 规格 |
|---|---|
| 触发条件 | `breadth < 0.40`（上涨家数占全市场比例）**或** `med20 < -3%`（20 日中位数涨跌） |
| 行为 | `env_safe = False` → 关闸期只出影子信号，不开新仓 |
| 输入 | 全市场广度指标、中位数涨跌（由 `portfolio_sim.build_matrices()` 内部计算） |
| 输出 | `env_safe` 布尔值，落账到 `daily/*.json` 的 `meta.env_safe` |
| 冻结口径 | `gate: env 闸门 v3_breadth40_med20` |

### F2 · 共振过滤

| 维度 | 规格 |
|---|---|
| 参数 | `buy_th = 75`（买入阈值），`obs_th = 50`（观察阈值），`gate_on = True` |
| 算法 | 4 技术策略 × 25±10 窗口 × RPS 复合打分（由引擎内部计算） |
| 实现 | **直接调用** `portfolio_sim.build_matrices()`，**不复制公式** |
| 输出 | BUY[t] 布尔候选集、SC[t] 打分、RPS50[t] 分位、VOL20[t] 波动率 |

### F3 · 硬线过滤（drop_p1）

| 维度 | 规格 |
|---|---|
| 规则 | 剔除 RPS50 分位 < 50 的候选 |
| 保池约束 | 过滤后不足 10 只则当日不过滤（全保留） |
| 冻结口径 | `drop_p1 = true`（M2.1 入场过滤启用） |

### F4 · 排序取整

| 维度 | 规格 |
|---|---|
| 排序键 | **score 降序**——三连证伪：debeta 排序 −109.8pp、rps 排序失败、score_resid 排序失败 |
| 取整 | `top_n = 30` 只 |
| 实现 | `np.argsort(-np.nan_to_num(SC[t, cand], nan=-1e9), kind="stable")[:top_n]` |

### F5 · 出场规则

| 维度 | 规格 |
|---|---|
| 买入 | T 日收盘信号 → T+1 开盘买入（真实成交价未知，用 T 日收盘价估算手数） |
| 持有 | `hold = 5` 个交易日 |
| 卖出 | T+5 收盘卖出 |
| 一字板处理 | `limit_mode = exact` 判定，无法成交的剔除 |
| 声明 | **跌停无法卖出未建模（高估方向）；竞价必成假设（高估方向）**——属策略已知风险 |

## A.5 门禁链（daily_run.py 唯一入口）

```
① 冻结检查（exit 3） → load M2_FROZEN.json → 正则提取 form.engine / form.portfolio_sim 的 md5
   → 比对本地文件 md5_8 → 指纹不符直接拒绝

② 数据检查（exit 4） → 扫 data/ashare/*.parquet 的 trade_date 列
   → 覆盖数 ≥ 5000 / 信号日 ≤ 最新交易日 / 数据新鲜度 ≤ 10 天

③ 选股子进程（exit 6） → subprocess 调 paper/_pick_live.py，传递 7 个参数：
   --signal / --capital / --top-n / --max-weight / --cost / --drop-p1 / --lot-fill / --limit-mode

④ 产物自洽 verify（exit 5） → 检查 7 项：
   env_safe 为 False 时 picks 必须为空 / picks ≤ top_n / hold / cost / drop_p1 / lot_fill / limit_mode

⑤ 与上一交易日 diff → 统计 entered / exited / kept

⑥ 产品页 md5 断言（只读，不进门禁链） → portal/houfeng/ 与 dashboard/ 18 个文件逐位一致
```

### 六类退出码精确定义

| 退出码 | 触发阶段 | 触发条件 | 响亮消息 | 处置 |
|---|---|---|---|---|
| **0** | 全部完成 | 门禁通过 + 选股完成 + verify 通过 | 打印漏斗统计、资金利用率、diff | —— |
| **2** | init / data | 参数错误 / 冻结文件缺失 / 无法自动取最新交易日 / 子进程超时 | 明确告知哪一步失败 | 人工处置 |
| **3** | frozen | 引擎/裁判指纹与冻结文件不符 | 处置二选一：回滚 git 或重新冻结（须老田签字） | **最高优先级**，先解决再谈选股 |
| **4** | data | 信号日数据覆盖不足 / 当日数据尚未落地 / 数据断供（>10 天） | "不切换口径、不借用次日数据——缺数据的日子就是不出票" | 检查上游数据 |
| **5** | verify | 闸门关闭却有 picks / picks 超 top_n / hold/cost/drop_p1/lot_fill/limit_mode 不符冻结 | "产物与冻结口径矛盾" | 排查子进程 |
| **6** | pick | _pick_live.py 非零退出 / 超时（>1800s） / 未产出文件 | 打印 tail 8 行 stdout + stderr 最后 1500 字符 | 排查子进程 |

## A.6 非功能需求

| 维度 | 规格 |
|---|---|
| **日志** | 每次运行 stdout 同时落盘 `daily/logs/YYYYMMDD_HHMMSS.log`；失败落盘 `daily/_FAIL_<signal>_<ts>.json`（含 exit_code / stage / errors / frozen 参数） |
| **可追溯** | 冻结文件必须记录 `frozen_at / frozen_by / refreeze_* 历史 / rejected 清单 / evidence / disclosures` |
| **耗时** | 数据扫描 ≤ 10s（扫 5816 个 parquet 的 trade_date 列）；选股子进程 ≤ 1800s；完整流程 ≤ 2200s |
| **原子性** | 产物写入用 Python `json.dump` + `allow_nan=False`；_pick_live.py 写 `_raw_YYYYMMDD.json`（临时名确认成功后重命名） |
| **只读性** | daily_run.py 本身**不修改**任何数据文件、不写任何 parquet、不清理旧产物（清理是运维任务） |
| **跨环境** | 路径拼接用 `os.path.join`；子进程调 `sys.executable`（兼容虚拟环境） |
| **跨平台** | 当前仅在 Windows 运行，但代码本身无 Windows 专有 API |
| **数据门禁** | MIN_COVER = {"daily": 5000}——**只有 daily 一项**（审计修复：移除原错误包含的 moneyflow/daily_basic，引擎根本不读） |
| **新鲜度** | MAX_STALE_DAYS = 10（覆盖国庆/春节最长假 9 天） |

## D.2 Regime 判别器引擎级五窗口验证

### D.2.1 背景

审计文档第七节标记为"另行立项"：**Regime 判别器**是一个宏观环境分类模块，计划在引擎层面验证"五个窗口（牛市/熊市/震荡/反弹/下跌中继）下闸门与选股的表现差异"。

### D.2.2 需求规格

| 维度 | 规格 |
|---|---|
| **目标** | 验证 Regime 识别是否能：(1) 在牛市/反弹期开闸更激进；(2) 在熊市/下跌中继期关闸更严格；(3) 提升整体收益/回撤 |
| **输入** | (1) Regime 判别器模型（尚未实现或在 maintenance/ 目录）；(2) M2_FROZEN v3c 引擎/裁判；(3) 历史 36m 数据 |
| **输出** | (1) 五窗口下 combo vs equal 对比表（收益/回撤/sharpe/参与率）；(2) 各 Regime 下闸门关闭天数比例；(3) 判别器命中率 vs 事后 Regime 标签（专家标注） |
| **验收标准** | (1) 至少 3 个窗口收益/回撤有统计显著差异（p < 0.1）；(2) 判别器命中率 ≥ 60%（随机分类 5 窗口 = 20%）；(3) **不改 M2_FROZEN.json**——除非五窗口全过 + 老田签字 + 重冻 |
| **边界条件** | (1) 不嵌入 daily_run.py（是研究型任务，不是生产链）；(2) 结论可能是"Regime 没用"——这也是可接受的结果；(3) 不修改 portfolio_sim.py / qpzm_backtest.py（除非五窗口验证通过并触发重冻） |
| **优先级** | **另行立项（研究型）** |
| **预计耗时** | 3-5 天 |
| **阻塞依赖** | (1) R1-R3 完成（本周任务）；(2) Regime 判别器模型初稿完成 |

### D.2.3 五窗口定义（待确认）

| Regime | 定义（候选） | 事前判别信号（候选） |
|---|---|---|
| 牛市 | 指数 MA200 上 + MA50>MA200 + breadth>0.6 | 指数站上 MA200 且均线多头 |
| 熊市 | 指数 MA200 下 + MA50<MA200 + breadth<0.3 | 指数跌破 MA200 且均线空头 |
| 震荡 | MA200 走平（斜率 < 5%）+ breadth 0.3~0.6 | MA200 斜率接近零 |
| 反弹 | 指数从局部低点回升 < 20% + 成交量放大 | 短期 V 形反转信号 |
| 下跌中继 | 指数 MA200 下 + 反弹 < 10% 后再破低 | 反弹无力 + 再创新低 |

**注**：以上窗口定义为候选，需老田或投资专家确认后固化。

### D.2.4 与闸门的关系

当前闸门 v3 的唯一触发是 `breadth<0.40 or med20<-3%`。Regime 判别器的目标是**前置**到闸门之前——如果能在熊市/下跌中继期更早关闸（在 breadth 跌破 0.40 之前），就可能提升整体表现。

```
当前：  breadth<0.40 or med20<-3% → 关闸
目标：  Regime == 熊市 or 下跌中继 → 提前关闸（且阈值可更低或不同）
```

**关键约束**：当前闸门 v3 的实验已经通过冻结——如果 Regime 判别器被证实有效，将作为**闸门升级**的候选方案（需走冻结流程）。在验证阶段，Regime 仅用于诊断（不改变实际闸门行为）。
