### 4. 真 bug：`glm` 通道 400，与"模型不存在"无关

`gateway/llm_gateway.py` 先 `make_llm(binding)` 正确剥了前缀（`GLMCloudLLM(model="glm-5.3")`），
随后又 `llm.chat(..., model=binding)` **把整串 `glm/glm-5.3` 当模型名发回去** → 智谱 HTTP 400。

对照实验（同一 key、同一端点）：

| 调用方式 | 结果 |
|---|---|
| `GLMCloudLLM("glm-5.3").chat(..., model="glm/glm-5.3")` | **400** |
| 同实例不传 model | 200 |
| 直连 `glm-5.3` / `glm-5.3-flash` / `glm-4.6` | 全部 200（含 max_tokens=16384 + system） |

⇒ **S38「glm-5.3-flash 模型名不存在」的判例是这条传参缺陷造成的误判**，S39 据此把 INTEL0 从
`glm-5.3-flash` 改档 9b 属于基于错误证据的决策。

修复后真实探针（走 gateway，与会议层同路径）：

```
glm/glm-5.3        ok=True   1243ms
glm/glm-5.3-flash  ok=True   6893ms
ollama/qwen3.5:9b  ok=True   1915ms
```
