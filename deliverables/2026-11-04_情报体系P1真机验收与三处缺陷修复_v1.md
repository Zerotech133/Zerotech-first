# 情报体系 P1 真机验收与三处缺陷修复 v1

**日期**：2026-11-04
**范围**：P0 事件层 + P1 三线（LLM 判定器 / 实体别名 / 跨窗口探针）的首次真实数据库验收
**结论一句话**：P1 代码上线前必须修的三处缺陷已全部修掉；事件层的对外契约第一次真正跑通，日报能输出"3 家来源 | 宁德时代发布麒麟电池"；但**阈值配置需要你拍板**，因为两种配置在真值语料上各有 5 处与 1 处错误，方向相反。

## 1. 为什么这一轮非做不可

P0 与 P1 的全部验收项都标着"待目标机验证"，理由是"本机无 PG 实例、Ollama 崩溃"。这一轮先核了这条前提——**不成立**：

- 本机 `127.0.0.1:5432` 有 PostgreSQL 在监听，只是项目 `.env` 指向了不存在的 5448；
- Ollama 早已自行恢复，`qwen3.5:9b` 与 `bge-m3` 都在。

于是起了一个隔离实例（`osint-verify-pg`，端口 5448，密码与 `.env` 完全一致，未改动任何既有配置），把"待验证"变成"已验证"。

**这一步的价值不在于省掉一趟目标机**，而在于：**离线单元测试对事件层的两块核心逻辑结构性失明**（详见 §3）。带真值语料的真库运行，一次就挖出三个会让 P1 上线即坏的缺陷。

## 3. 三处缺陷（全部由真库运行暴露，全部已修）

### 3.1 建事件用 `fetch_all` 写库，写入被静默回滚

`StoryGrouper._create_story` 用 `db.fetch_all` 执行 `INSERT INTO osint_story ... RETURNING story_id`。

而 `fetch_all` 内部是 `engine.connect()`，**退出上下文即回滚**。于是：

- 语句"成功"了；
- `RETURNING` 返回了一个自增 ID（序列的 `nextval` 不受事务回滚影响）；
- 那一行**并不存在**；
- 故障推迟到下一条成员边插入时，以外键冲突的形式炸出来，现场与真因相距极远。

首次真实运行报的就是：

```
insert or update on table "osint_story_member" violates foreign key constraint
DETAIL: Key (story_id)=(1) is not present in table "osint_story".
```

**已实证，不是推断**：

```
fetch_all 返回: [{'story_id': 2}]
fetch_all 之后库内行数: 0        → 写入丢失
insert_returning 返回: [{'story_id': 3}]
insert_returning 之后库内行数: 1  → 写入生效
```

**修复**：
- `common/db.py` 新增 `insert_returning()`（显式事务 + COMMIT），作为"写入并取回值"的唯一正确入口；
- `fetch_all` 的 docstring 加死警告，说明它会回滚、且 `RETURNING` 会返回指向空行的假 ID；
- `_create_story` 改用 `insert_returning`。

**防再犯**：两份测试里各自维护的 `FakeDB` 已合并为 `tests/fakes.py` 一份，并给假库加了结构性护栏——`fetch_all` 收到 `INSERT INTO osint_story` 直接 `AssertionError`。原先的两份副本正是这个缺陷能藏住的原因。

### 3.2 消费出口的 SQL 无法被 PostgreSQL 解析

`knowledge/story_query.py` 的 `_LIST_SQL` 用了 `:param::int` / `:param::text` 写法：

```sql
AND (:min_sources::int IS NULL OR s.independent_sources >= :min_sources::int)
```

SQLAlchemy 的 `text()` 识别不出这种绑定参数，生成出的 SQL 里 `:min_sources` 原样保留，数据库直接语法错误：

```
psycopg.errors.SyntaxError: syntax error at or near ":"
```

**影响面**：`/api/v1/stories`、`/api/v1/stories/{id}`、`/api/v1/brief/daily` 三个端点，以及 `daily_brief` / `list_stories` / `find_story_by_key` 全部 500。也就是说，**P0 的消费出口从来没真正打开过**——它只是"写完了"。

**修复**：改为 `CAST(:min_sources AS integer)` 三处。修复后 `daily_brief` 返回 5 条事件，其中：

```
3 家来源 | 宁德时代发布麒麟电池，整车续航突破一千公里
2 家来源 | 华信科技信披违规案落地，公司被罚三千万元
```

**这正是 P0 验收的唯一硬指标**——"日报里出现'这个消息有 N 家独立来源在说'"。到今天才第一次成立。

### 3.3 规则判定器把"共享任一实体"判成同一事件

`RuleJudge` 的实体规则：`ent_overlap = |交集| / min(|左|, |右|)`，阈值 0.5。

分母是**较小实体集的大小**，于是单实体事实恒为 `1/1 = 1.0`。规则实际退化为"**只要共享任一实体就是同一件事**"。类 docstring 写的是"宁可漏合不可误合"，代码做的恰好相反。

在带真值语料上，这一条**独立制造了 6 处误合并**，全部是"同一家公司、不同事件"：

| 并入的事件 | 被误并的事实 | 余弦 | 文本 Jaccard |
|---|---|---|---|
| 英伟达发布新一代显卡 | 英伟达三季度财报超预期 | 0.7203 | 0.086 |
| 贵州茅台上调出厂价 | 贵州茅台前三季度营收增长一成 | 0.6894 | 0.077 |
| 特斯拉召回部分进口车型 | 特斯拉 CEO 减持套现十亿美元 | 0.6208 | 0.050 |
| 恒瑞医药集采落标 | 恒瑞医药创新药获批上市 | 0.5906 | 0.063 |
| 央行开展 MLF 操作 | 央行发布三季度货币政策执行报告 | 0.6958 | 0.143 |
| 宁德时代三季度净利增长 | 宁德时代董事辞职 | 0.6090 | 0.061 |

**文本证据全部只有 0.05–0.14**，远低于 `RULE_JACCARD=0.35`，却被实体规则强行拉进同一事件，直接把 `independent_sources` 抬高——这让"有几家独立来源在说"这句话变成假话。

**修复**：实体重合**只用于候选召回，不再单独构成判定结论**。判不了就返回 `unrelated`，把判断权交给 LLM 或人工。同时把 `decided_by` 从冒充的 `llm_recheck` 改成如实的 `rule`（含 schema CHECK 迁移，幂等 DROP+ADD）。

**效果**：误合并 **6 → 0**。

## 4. 这三处缺陷为什么能同时存活

共同点：**它们的失败都需要真实 PostgreSQL 参与**。

| 缺陷 | 假库为何测不出 |
|---|---|
| 写入回滚 | 假库只比对 SQL 片段，不模拟事务语义 |
| SQL 语法错 | 假库按片段直接返回构造好的行，SQL 从未被解析 |
| 实体规则 | 单测里的"实体"样例是精心构造的对称集合，恰好绕开了单实体退化 |

处置：新增 `tests/test_pg_integration.py`，默认 `skip`，设 `OSINT_TEST_PG=1` 开启。它把三件事钉成可执行断言：

1. `insert_returning` 必须真的落库（不只是返回 ID）；
2. `fetch_all` 写库**确实**会回滚（把反直觉行为写成文档，防止有人再误用）；
3. 消费出口的四条 SQL 与 `v_story_brief` 视图必须能被真库解析并返回行。

视图测试刻意不只断言"不报错"——插入一条满足全部条件的行，要求视图**必须把它查出来**。条件写错时返回 0 行同样不报错，只测"能查"等于没测。

## 5. 阈值标定：两种配置，方向相反

对 50 条带真值事实做全对比较（22 对正例 / 1203 对负例）：

```
正例：min=0.6433  mean=0.8339  max=0.9325
负例：min=0.2676  mean=0.4336  max=0.8240
重叠区间：+0.1807
```

阈值敏感性：

| 阈值 | recall | 误命中 |
|---|---|---|
| 0.60 | 1.000 | 31/1203 |
| 0.75 | 0.909 | 1/1203 |
| 0.85 | 0.591 | 0/1203 |

端到端配置对照（真值：32 个事件）：

| 配置 | 事件数 | 拆散 | 误合并 | 独立来源数正确 | 耗时 |
|---|---|---|---|---|---|
| **0.85 + 规则 v2** | 34 | 5 | **0** | 9/9 | 6 秒 |
| **0.75 + 规则 v2** | 29 | **1** | 1 | **13/13** | 6 秒 |
| 0.85 + LLM（6 对抽样） | — | **0** | 1（可争论） | — | 195 秒 |

**读法**：

- 0.85 保守：不误合并，但 5 个真事件被拆成两半。其中 S04（英伟达）、S08（台积电）拆完两半各只剩 **1 个来源**，于是**够不上简报的 `independent_sources >= 2` 门槛，整个事件在日报里消失**。拆散的危害不只是"少算来源"，是"事件不见"。
- 0.75 激进：事件数最接近真值，来源数 13/13 全对，但放进 1 处误合并（组件价格战 ‖ 协会自律倡议，余弦 0.824）。
- LLM：**5 个真拆散全部判对**（含"麒麟电池中/英"、"台积电中/英"这类字符相似度为 0 的对）。唯一与预期不符的那一对，它给的理由（"均为主体行业协会呼吁停止低价竞争"）本身站得住，可算可争论而非错误。

**这是本轮唯一需要你拍板的取舍**，见 §8。

## 6. LLM 判定的真实容量

本机 iGPU 实测（模型已驻留、`think:false`、`keep_alive:2h`）：

- 单次判定 **14.3 / 18.4 / 29.6 / 26.7 / 32.5 / 29.8 秒**，均值 ≈30 秒；
- 42 条事实的全链路跑到 **7 分 38 秒仍未完成**，已完成 8 次判定，主动中止。

生产机是 20 vCPU **纯 CPU、无 GPU**，只会更慢。按 30 秒/次、一轮 50 次估算，单轮 ≈25 分钟；若用它覆盖复核区间全部候选，**每轮一小时以上**，跑不完 cron 周期。

**结论**：LLM 判定器**不能作为常规路径**，只能二选一用作——高价值候选的定向复核，或离线标定。这条已用实测坐实，不需要再在目标机上试。

## 7. B、C 两线的真实归属

### B 线（实体别名）：基建可用，但对本轮收益为 0

已灌入 31 条人工确认别名（`CATL`/`宁德时代`→`catl`、`NVIDIA`/`英伟达`→`nvidia`、`TSMC`/`台积电`→`tsmc` 等），归一已验证生效：

```
CATL        原始=['catl']            归一=['catl']
宁德时代      原始=['宁德时代']         归一=['catl']
中国光伏行业协会  原始=['中国光伏行业协会']   归一=['cpia']
光伏行业协会    原始=['光伏行业协会']      归一=['cpia']
```

**但重跑后聚类结果一字未变**（34 个事件、拆散 5、误合并 0，与未灌别名完全一致）。

原因很清楚：别名只影响**候选召回**（"这两条该不该拿来比"），而拆散的根因在**判定环节**（"比完之后判不判同一件事"）。S01 中英两条本来就因 topic 相同而进了候选，卡在文本 Jaccard ≈ 0 上被判无关。修掉实体规则后，别名连判定的边都沾不上。

**所以 B 线的价值边界要写清**：它是"跨语言/跨写法召回"的**必要不充分条件**。没有它，LLM 看不到该看的对；有它但没有能作判断的判定器，收益为 0。

另有两个已发现的覆盖缺口：

- 回填脚本只剥法定后缀，把 `宁德时代新能源科技股份有限公司` 归成 `宁德时代新能源科技`——**这个形态谁也不用**，等于没收敛；真正的短名在 `[candidate]` 里等人工确认；
- **中英别名（CATL/NVIDIA/TSMC）完全不在回填能力内**，而本轮 5 处拆散有 3 处正是它们。

### C 线（跨窗口探针）：可用，且结论明确

首次运行返回 `split_unit_ratio=0` 是**假象**——`vector_coverage=0`（Qdrant 无数据）时它退回字符二元组，而字符相似度在"同事件不同表述"上系统性偏低，把裂缝整批漏掉了。

已给探针加"现算向量"兜底（Qdrant 缺向量时用 bge-m3 直接算，可 `--no-embed-fallback` 关闭），重跑后：

```
vector_coverage=1.0  similarity_mode=vector
units_scanned=42  history_scanned=8  comparisons=336
split_candidate=6   split_unit_ratio=14.29%
```

Top 分裂（余弦 / 时间差）：

| 余弦 | 时间差 | 事实 |
|---|---|---|
| 0.9323 | 33 天 | 中芯国际产能利用率（两篇） |
| 0.9231 | 22 天 | 隆基绿能硅片提价（两篇） |
| 0.9044 | 29 天 | 欧盟对华电动车关税（两篇） |
| 0.7968 | 18 天 | 华信科技立案 → 处罚 |
| 0.7574 | 19 天 | 华信科技立案 → 处罚决定书 |
| 0.6418 | 22 天 | 隆基增持 ‖ 隆基提价（假阳） |

**判断**：跨窗口召回**值得上**，14.29% 的窗口事实存在窗口外同事件，且相似度普遍在 0.90 以上（远高于阈值）。但必须带"同主体不同事件"的护栏，因为 6 条里有 1 条是仅实体重合的假阳。

## 8. 需要你裁定

### 裁定一：阈值配置（影响日报能否出现真实事件）

| 选项 | 拆散 | 误合并 | 后果 |
|---|---|---|---|
| 甲 维持 0.85 | 5 | 0 | 4 个真事件被拆，其中 2 个因来源数归 1 **在日报中消失** |
| 乙 下调至 0.75 | 1 | 1 | 事件数与来源数最接近真值，代价是 1 处"相关但不相同"被并 |
| 丙 0.85 + LLM 定向复核 | 0（抽样验证） | 0（抽样验证） | 质量最好，但每轮多 25–60 分钟，纯 CPU 生产机不现实 |

我的倾向是**乙**：拆散会让事件从日报里消失，这是"采了没人吃"的复发；而误合并的那 1 处是同一行业协会的两条相关动态，读者受损有限。但这涉及你对"宁可多报还是宁可漏报"的口径，我不替你定。

### 裁定二：LLM 判定器的部署形态

实测已排除"全量常规路径"。剩下三条：

- 甲 只对 `independent_sources >= 2` 的高价值候选开（成本可控，打在要害）；
- 乙 改走云端 API（延迟解决，但要算钱和出网合规）；
- 丙 生产只跑规则，LLM 仅用于离线标定与人工复核辅助。
