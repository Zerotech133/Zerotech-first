## 四、历史代码治理（Legacy Code Governance）

### 4.1 分级模型（L0~L3）

| 级别 | 定义 | 动作 | 例子 |
|---|---|---|---|
| **L0 活跃主线** | 被服务/产线/测试引用 | 正常维护；新代码守则 | agent_platform/portal/quant 主线 |
| **L1 冻结** | 仍被引用但不再演进 | 只修 bug；禁止扩展；登记 owner | 5 个巨型 API 文件（拆分期）、旧版脚本 |
| **L2 归档** | 无引用但保留证据 | 移入 `archive/`（或保留原地+README 标注），只读 | `quant_backtest/archive` 17 py |
| **L3 回收候选** | 无引用、无证据价值 | 回收站 + 判例留档 + L2 批；**一次一议** | 一次性调试脚本、失效副本 |

### 4.2 盘点与工具（已具备/待建）
- 已有：`tools/gen_entrypoints.py`（入口 1,153 基线）、`docs/ops/entrypoints_v1.tsv`、`tools/check_dirty.py`、`docs/audit/2026-10-28_外部子系统边界判例_v1.md`；
- 待建：`docs/ops/legacy_registry_v1.md`（L1~L3 登记表：路径/级别/owner/最后引用/处置/证据）；`tools/legacy_scan.py`（引用链扫描：谁 import 它、计划任务是否引用）。

### 4.3 流程
1. 新代码只进 L0；旧代码被替代后 30 天内登记 L1，并在 3 个月内决定 L2/L3；
2. L3 删除前必须：引用链实证（grep 全仓 + 计划任务 + 文档）→ 快照/回收站 → 判例文档 → L2 审批；
3. 每月一次"归档评审"（A0 主持，30 分钟）：处理 L1→L2、L3 候选；
4. **不搞大规模迁移**：历史代码优先"原地冻结 + 标注"，成本最低、风险最小。

### 4.4 历史代码 KPI（季度）
- L1/L2 登记覆盖率 100%；无 owner 的 L1 = 0；
- 活跃入口数季度下降 10%（归档低频脚本）；新代码 100% 落新文件（portal 守则）。

### 5.1 现状与已有机制
- 规模：55.9GB / 265,328 文件；顶层 tdx（21.6GB）、tushare（12.9）、tushare_curated（7.2）、.prev（7.2 重复）、v2/staging/anns_pdf/bt2…

### 5.2 缺口
1. **lifecycle 字段未强制**：部分表无 lifecycle → qualification 欠账；
2. **重复/演练副本未登记**：`tushare_curated.prev` 7.2GB、`archive_US_wo092_20261021`、`bt2_rehearsal_1014`；
3. **保留窗口未定**：热/温/冷分界、anns_pdf 等文档类数据保留期；
4. **备份覆盖与恢复演练**：cainiao/quant_meta 缺口，季度演练缺记录；
5. **血缘/影响面**：`lineage_impact.py` 存在但无常态报告；删表/改 schema 前的影响面靠人。

### 5.3 治理规则（建议立宪）
1. **数据资产必须登记**：新数据落湖必须进 catalog（schema/owner/lifecycle/store）；
2. **生命周期四态**：`active / planned / deprecated / archived`，deprecated 后 90 天进 archived（只读，压缩）；
3. **保留窗口**：热（近 90 天，在线）/ 温（1 年，本地）/ 冷（归档，压缩保留）；anns_pdf 等按业务 3 年；
4. **删除纪律**：结构性删除 = L2 审批 + 快照（catalog_snapshot + manifest）+ 回收站；`kg_sync_task.log` 先读后写（现有纪律）；
5. **备份**：周增量 + 月全量；季度恢复演练（抽样 1 表：恢复→校验→回执）；
6. **元数据日报**：sha/计数/新鲜度/备份覆盖 4 项进每日事件层。

### 5.4 数据治理 KPI（季度）
- catalog 登记率 100%、lifecycle 覆盖率 100%；
- 数据根"无主目录" = 0；重复副本 = 0；
- 备份覆盖 100%、季度演练 ≥1 次；数据漂移告警响应 < 1 天。

## 七、优化建议（三线结合）

- **代码线**：先拆 portal 五巨头（守则+守卫已就位）；长函数新代码 ≤80 行；新 handler 落新文件；API 契约测试先行。
- **数据线**：catalog 为唯一权威；lifecycle 强制；`.prev`/演练副本必须登记；备份演练定期；元数据日报。
- **流程线**：质量闸 → 合并队列（自动）；脏文件协议 → 看板+提醒；审批分级（自动执行包/人工 L2）；事件归因（GUANYU/席位）。
- **治理线**：月度归档评审（30 分钟）与季度复盘并轨；所有 L3 删除必须"引用链+快照+判例+批准"四件套。

## 十、结论

- **代码层面**：可守（指标已达 0/0/0/0 级别），剩下是"结构债"与"存量治理"；
