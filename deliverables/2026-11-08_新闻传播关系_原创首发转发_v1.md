## 一、动手前先摸底：同一个"重复"里藏着四种东西

137,774 行、11 个源。按最朴素的做法（标题去重）会立刻撞墙：

| 现象 | 样本 | 真实语义 |
|---|---|---|
| 同标题 23 次 | 「南向资金净买入额达10亿港元。」 | **模板快讯复读**，每天定时播报，不是转发 |
| 同标题 6 次跨 5 天 | 「韩国交易所启动SIDECAR机制，暂停KOSPI程序化卖盘。」 | **同一句话的多次独立发生**，每波各有首发与转发链 |
| 同标题 1~3 分钟内跨源 | 「电动自行车CCC认证新规11月1日起实施」16:20 东财 → 16:23 中新网 | **真转发** |
| 同源同 ts 两条一模一样 | 中新网 16:23 两条、17:00 两条 | **采集重复**（滚动/财经两个频道各抓一次） |
| 同标题但正文各写各的 | 「我国面向全球的自贸网络已经初步成型」15:14 新华社稿 / 17:29 发布会实录 | **同题异稿**，不是转发 |

**判据不能只看标题。** 必须叠三个维度：正文相似度、时间间隔、是否跨源。

### 关键发现：id 里本来就藏着"同一篇文章"

```
cns:finance:c06b804f021b2d1a
cns:scroll :c06b804f021b2d1a   ← 同一个 hash，不同频道
```

`INSERT OR IGNORE` 拦不住，因为 id 前缀不同。按 id 精确解析（只对 `<媒体>:<频道>:<hex>` 取末段 hash）后：**1563 条采集重复，1.1%，全部来自 chinanews，跨源 0 条**。

> 踩坑记录：第一次用 SQL `substr(id, length(id)-15)` 取尾段，得到 61623 条（44.7%）——**假数字**。库里 69,593 条 id 长度 < 20（`sina:5201263`、`wsc:3196448`），对短 id 取"尾 16 位"等于取整串，长短不一的 id 相互错位比较。改成按 id 结构解析后回落到 1563。

### 关键发现：跨源同题基本就是同一篇稿

对 2101 组跨源同题对算正文 3-gram Jaccard：

| 分位 | p10 | p25 | 中位 | p75 | p90 |
|---|---|---|---|---|---|
| Jaccard | 0.38 | 0.79 | **1.00** | 1.00 | 1.00 |

≥0.85 占 72%，≥0.50 占 87%。**阈值取 0.50**。

### 关键发现：原创证据只在 chinanews 成立

| 源 | 带中新电头 | 正文以「【】」开头（转载体例） |
|---|---|---|
| chinanews | **64%** | 1% |
| eastmoney | 0% | **81%** |
| sina | 0% | **43%** |
| wallstreetcn | 0% | 1% |

所以 `original` 只认「首见 + 电头指向本媒体」，其余一律 `first`（首见但出处未证实）——**不猜**。

## 二、七档口径

| kind | 含义 | 参与方向统计 |
|---|---|---|
| `original` | 原创：轮内首见，正文电头指向本媒体 | ✅ |
| `first` | 首发：轮内首见，无法证明原创 | ✅ |
| `column` | 栏目复用：同源同标题但正文差异大（每日盘前速递/南向资金） | ✅ |
| `repost` | 转发：跨源、≤24h、正文相似 ≥0.5 | ❌ |
| `retell` | 同题异稿：跨源但正文各写各的 | ❌ |
| `dup` | 采集重复：同指纹，或同源 30 分钟内重复抓取 | ❌ |
| `recur` | 周期复读：同源同一句话再次播报 | ❌ |

**必须分轮**：同标题按 24 小时断裂切轮，每轮内部独立判定。否则 10-30 那波的首发会被拿去跟 10-13 的基准比，判成「相距 24497 分钟的 retell」，一次真首发就此消失。

**必须区分 `column`**：`【美股盘前要闻速递】` 每天一条、内容全新，只是复用标题。判 `recur` 等于把 20 天的信息压成一条。实测有 11,144 条属此类（8.1%）。

## 三、改法

1. **字段**（`news` 表，ALTER + 索引 `idx_news_ofp`/`idx_news_okind`）
   `origin_kind` / `origin_fp`（标题组指纹，可一查列出整条传播链）/ `repost_of` / `lag_min` / `origin_ev`（人话依据）
2. **判定库** `news_collector/news_origin.py`：纯标准库、不调模型、不联网
   - `norm_title`（带【】取【】内文）与 `norm_text`（剥【】留主体）**必须分开**——title 与 content 的【】语义相反，实测新浪把「【标题】正文前段」整段塞进 title
   - `article_fp`（id hash 优先）/ `jaccard` / `classify_group`（分轮）/ `judge_and_write`（增量）
3. **采集侧入库即判**：`insert_items` 插入成功后立刻 `judge_and_write`，失败静默不阻断入库
4. **下游去重**：`api_jev_story` 新增 `dedup` 账；方向统计、影响区间、传导流净方向一律只算独立事件
5. **展示**：判定表新增「角色」列（原创/首发/转发 ΔN m/栏目/重复/复读/异稿）；`_facts` 把去重结果喂给模型
