# /legion 与 /legion-api/ 登录保护 · L2 五要素批准单 v1

- 工单：`WO-GUANYU-P98-20261030`（代码/配置已提交，**reload 未执行，等批准**）
- 背景：`/legion`（军团大屏）与 `/legion-api/`（军团 API 同源反代）当前**无登录保护**，
  而同文件 `/model_admin`、`/devops`、`/os-entry` 等均已加 `auth_request /_auth_guard`；
  实测未登录可达页面与 ops/topics 数据（本机 8734 入口）。
  另：写接口"本机经反代免 token"已由代码层守卫堵住（`legion_write_guard`），
  nginx 层 auth_request 属**纵深防御/一致性修复**。

## 一、命令全文（批准后执行）

```powershell
docker exec ai-portal nginx -t
docker exec ai-portal nginx -s reload
```

- 配置来源：`portal/nginx.conf`（容器挂载源，只读挂载）；本次变更：
  1. `location = /legion` 增加 `auth_request /_auth_guard;` + `error_page 401 = @login_required;`
  2. `location ^~ /legion-api/` 增加同上两行（与 `/model_admin` 对齐）。

## 二、影响面

- `ai-portal` 容器 nginx **graceful reload**（不中断已有连接，秒级）；
- 仅影响 `/legion`、`/legion-api/*` 两条路由：未登录由 200 变为 **302 `/login?next=...`**；
  已登录（cookie 有效）行为不变；
- 其它全部路由（`/`、`/devops`、`/os-entry`、`/hermes/`、`/api/*`、`/lde/` 等）配置不变；
- 若有脚本/外部探针未带会话访问 `/legion-api/*`，reload 后会被 302 拦（预期行为；当前已知仅 legion.html 同源调用，带 cookie）。

## 三、不可逆点

**无**。配置在 git 中可 revert；reload 可重复执行；回滚不丢数据。

## 四、替代方案与已尝试

| 方案 | 说明 |
|---|---|
| 仅代码守卫（**已合入**） | `legion_write_guard`：跨站 Origin/Referer 写请求一律拒绝，堵 CSRF；不拦未登录读 |
| 本方案（nginx auth_request） | 读+写统一登录保护，与其它敏感页一致；需 reload（本批准单） |
| 后端逐接口加鉴权 | 改动面大、易漏，不采用 |

## 五、回滚预案

```powershell
# 1) 若已提交：git revert <commit>（恢复 portal/nginx.conf）
# 2) 重新加载
docker exec ai-portal nginx -t
docker exec ai-portal nginx -s reload
# 3) 验证回滚：未登录 /legion 恢复 200
```
