## 0. 一句话定义

把当前“两个 JSON + 一张日报”的情绪数据，升级为数据仓的**三个稳定粒度数据产品 + 一个运行清单**，让所有角色按同一个口径查询、追溯和复用；KG 只是发布后的只读消费端之一。

## 1. 目的与问题

### 1.1 要解决的问题

1. 情绪数据目前是文件契约，不是数据仓表/视图；角色各自解析 JSON，口径不一致。
2. 没有稳定主键、粒度、字段类型、空值语义和版本字段，无法做跨日比较。
3. 没有 freshness、质量规则、目录登记、owner、血缘，出问题无法定位。
4. 没有区分“全量口径”和“历史回填口径”，历史数据容易被误读。
5. KG 若直接读 JSON，会把“数据仓未治理”的状态固化到图里。

### 1.2 不解决的问题

- 不替代张松部门的数据采集、清洗、质量治理。
- 不把情绪包装成交易信号，不承诺预测收益。
- 不把帖子/新闻原文写入数据产品。
- 不定义 KG 节点/边；KG 侧另发只读消费通知。
- 不解决上游 `e互动` 当前无生产者的问题，只如实标注缺口。

## 2. 数据产品总览

| 产品 | 粒度 | 主键 | 更新 | 保留 |
|---|---|---|---|---|
| `sentiment_stock_daily` | 股票 × 交易日 | `(trade_date, code)` | 每日 08:30 前 | 2 年 |
| `sentiment_market_daily` | 交易日 | `(trade_date)` | 每日 08:30 前 | 5 年 |
| `sentiment_source_daily` | 交易日 × 来源 | `(trade_date, source)` | 每日 08:30 前 | 5 年 |
| `sentiment_ingest_manifest` | 每次 ingest | `ingest_run` | 每次运行 | 2 年 |

建议物理命名：

- 表：`sentiment_stock_daily`、`sentiment_market_daily`、`sentiment_source_daily`
- 运行清单：`sentiment_ingest_manifest`
- 只读视图：`v_sentiment_stock_daily`、`v_sentiment_market_daily`、`v_sentiment_source_daily`

## 3. 来源与口径

### 3.1 上游文件

| 文件 | 生产者 | 用途 |
|---|---|---|
| `news_collector/data/sentiment_cards.json` | `sentiment_card.py` | 个股 × 来源的情绪分布卡 |
| `news_collector/data/market_sentiment.json` | `market_sentiment.py` | 当日市场级指数 |
| `news_collector/data/market_sentiment_history.jsonl` | `market_sentiment.py` | 市场级日快照（append-only，同日覆盖） |

### 3.2 来源枚举

| source | 中文 | 是否有极性 | v1 状态 |
|---|---|---|---|
| `guba` | 股吧 | 是 | 有 |
| `taoguba` | 淘股吧 | 是 | 有 |
| `irm` | 互动易 | 是 | 有 |
| `e_interaction` | e互动 | 是 | **当前无生产者，允许空** |
| `xueqiu` | 雪球 | 是 | 有 |
| `news` | 新闻流 | 否（仅声量） | 有 |

> 现行 `market_sentiment.py` 的权重表包含“e互动 0.10”，但 `sentiment_card.py` 当前没有 e互动采集函数，实测卡中 `e互动` 为 `null`。本契约不伪造该源；缺失时按剩余权重归一，并在 `weights_json.effective` 中记录实际权重。

### 3.3 计算口径

- `polarity`：单源内按样本 `n` 加权的情绪极性，范围 `[-1, 1]`；无样本为 `NULL`。
- 个股 `polarity`：各极性源 `polarity` 按 `n` 加权平均；无任何极性源为 `NULL`。
- 市场 `index`：`50 + 50 × Σ(w×polarity_w)/Σw`，范围 `[0,100]`；无极性源为 `NULL`。
- `breadth_pct`：有极性标的中 `polarity > 0` 的占比；无样本为 `NULL`。
- `state`：`极度谨慎/谨慎/中性/乐观/极度乐观/unknown`，按 `market_sentiment.py` 现行状态机。
- `mention_volume`：新闻流命中该标的的条数；不是帖子总量。
- `n_samples`：各极性源样本数之和 + 新闻流样本数。

## 4. `sentiment_stock_daily` 逻辑 Schema

| 字段 | 类型 | 空 | 键/约束 | 说明 |
|---|---|---|---|---|
| `trade_date` | DATE | 否 | PK | 交易日，`YYYY-MM-DD` |
| `code` | CHAR(6) | 否 | PK | 6 位 A 股代码，如 `000995` |
| `ts_code` | VARCHAR(12) | 是 | IDX | 规范代码，如 `000995.SZ`；能匹配 `stock_basic` 时必填 |
| `name` | VARCHAR(32) | 是 |  | 证券简称 |
| `mention_volume` | INTEGER | 否 | >=0 | 新闻流声量 |
| `n_sources` | SMALLINT | 否 | 0–6 | 非空来源数 |
| `bullish` | INTEGER | 否 | >=0 | 各源看多合计 |
| `neutral` | INTEGER | 否 | >=0 | 各源中性合计 |
| `bearish` | INTEGER | 否 | >=0 | 各源看空合计 |
| `polarity` | DECIMAL(6,4) | 是 | [-1,1] | 跨源 n 加权极性 |
| `sources_json` | JSON/TEXT | 否 | 合法 JSON | 来源明细，见 §4.1 |
| `model_ver` | VARCHAR(32) | 否 |  | 如 `sentiment_card_v1` |
| `generated_at` | TIMESTAMP | 否 |  | 上游生成时间，Asia/Shanghai |
| `source_file` | VARCHAR(256) | 否 |  | 上游文件相对路径 |
| `source_hash` | CHAR(64) | 否 |  | 上游文件 SHA256 |
| `ingest_run` | CHAR(36) | 否 | IDX | 本次 ingest UUID |
| `is_backfill` | BOOLEAN | 否 | 默认 false | 是否回填 |
| `quality_status` | ENUM | 否 | `pass/warn/fail` | 单行质量结论 |

### 4.1 `sources_json` 契约

```json
{
  "guba": {
    "n": 77,
    "bullish": 26,
    "neutral": 31,
    "bearish": 20,
    "polarity": 0.121,
    "denoise": {"total": 77, "kept": 77, "spam_repeat": 0, "spam_promo": 0, "fomo": 0}
  },
  "taoguba": {
    "n": 69,
    "bullish": 25,
    "neutral": 31,
    "bearish": 13,
    "polarity": 0.144,
    "views": 0,
    "denoise": {"total": 69, "kept": 69, "spam_repeat": 0, "spam_promo": 0, "fomo": 0}
  },
  "irm": {
    "n": 1,
    "bullish": 0,
    "neutral": 1,
    "bearish": 0,
    "polarity": 0.133,
    "answered": "1/1"
  },
  "e_interaction": null,
  "xueqiu": null,
  "news": {"n": 16}
}
```

字段规则：

- 键只能是 §3.2 的 `source` 枚举；缺失源写 `null`，不省略。
- `n >= 0`；`bullish + neutral + bearish = n`（若有极性）。
- `news` 只有 `n`，无极性字段。
- `answered` 保留 `"已答/总数"` 字符串，不拆成比率，避免改变上游语义。
- `denoise` 保留上游对象；无该源时为 `null`。

## 5. `sentiment_market_daily` 逻辑 Schema

| 字段 | 类型 | 空 | 键/约束 | 说明 |
|---|---|---|---|---|
| `trade_date` | DATE | 否 | PK | 交易日 |
| `market` | VARCHAR(16) | 否 | PK/默认 `A_SHARE` | 市场标识 |
| `index` | DECIMAL(5,1) | 是 | [0,100] | 市场情绪指数 |
| `state` | VARCHAR(16) | 否 | 枚举 | 五档 + `unknown` |
| `breadth_pct` | DECIMAL(5,1) | 是 | [0,100] | 情绪广度 |
| `n_codes` | INTEGER | 否 | >=0 | 当日情绪卡覆盖标的数 |
| `n_samples` | INTEGER | 否 | >=0 | 六源样本数 |
| `sources_json` | JSON/TEXT | 是 | 合法 JSON | 各源市场级聚合；历史回填可为 null |
| `news_volume` | INTEGER | 是 | >=0 | 新闻流样本数 |
| `weights_json` | JSON/TEXT | 否 | 合法 JSON | 名义权重 + 实际有效权重 |
| `model_ver` | VARCHAR(32) | 否 |  | 如 `market_sentiment_v1` |
| `coverage` | ENUM | 否 | `full/history_only` | 是否含来源明细 |
| `generated_at` | TIMESTAMP | 否 |  | 上游生成时间 |
| `source_file` | VARCHAR(256) | 否 |  | 上游文件 |
| `source_hash` | CHAR(64) | 否 |  | 上游 SHA256 |
| `ingest_run` | CHAR(36) | 否 | IDX | ingest UUID |
| `is_backfill` | BOOLEAN | 否 | 默认 false | 是否回填 |
| `quality_status` | ENUM | 否 | `pass/warn/fail` | 单行质量结论 |

`sources_json` 示例：

```json
{
  "guba": {"n_total": 48321, "n_active": 812, "bullish": 21000, "neutral": 19000, "bearish": 8321, "polarity_w": 0.081, "breadth_pct": 52.1, "bull_bear_ratio": 2.52},
  "taoguba": {"n_total": 9200, "n_active": 300, "bullish": 4300, "neutral": 3100, "bearish": 1800, "polarity_w": 0.12, "breadth_pct": 55.3, "bull_bear_ratio": 2.39},
  "xueqiu": {"n_total": 7800, "n_active": 420, "bullish": 3600, "neutral": 2600, "bearish": 1600, "polarity_w": 0.09, "breadth_pct": 50.5, "bull_bear_ratio": 2.25},
  "irm": {"n_total": 1200, "n_active": 90, "bullish": 500, "neutral": 500, "bearish": 200, "polarity_w": 0.05, "breadth_pct": 48.2, "bull_bear_ratio": 2.5},
  "e_interaction": null,
  "news": {"n_total": 16000, "n_active": 900}
}
```

`weights_json` 示例：

```json
{
  "nominal": {"guba": 0.40, "taoguba": 0.20, "xueqiu": 0.20, "irm": 0.10, "e_interaction": 0.10},
  "effective": {"guba": 0.4444, "taoguba": 0.2222, "xueqiu": 0.2222, "irm": 0.1111},
  "missing": ["e_interaction"],
  "sum_effective": 1.0
}
```

规则：

- `coverage=full`：有当日 `market_sentiment.json`，包含来源明细。
- `coverage=history_only`：仅从 `market_sentiment_history.jsonl` 回填；`sources_json`、`news_volume`、`weights_json` 可为 null；不得补造。
- 历史行 `n_codes` 若上游历史文件没有，允许 `NULL`；v1 只对 `2026-11-12` 之后要求非空。

## 6. `sentiment_source_daily` 逻辑 Schema

| 字段 | 类型 | 空 | 键/约束 | 说明 |
|---|---|---|---|---|
| `trade_date` | DATE | 否 | PK | 交易日 |
| `source` | VARCHAR(24) | 否 | PK | §3.2 枚举 |
| `source_label` | VARCHAR(16) | 否 |  | 中文名 |
| `has_polarity` | BOOLEAN | 否 |  | 新闻流 false |
| `n_total` | INTEGER | 否 | >=0 | 样本数 |
| `n_active` | INTEGER | 否 | >=0 | 活跃标的数 |
| `bullish` | INTEGER | 否 | >=0 | 看多 |
| `neutral` | INTEGER | 否 | >=0 | 中性 |
| `bearish` | INTEGER | 否 | >=0 | 看空 |
| `polarity_w` | DECIMAL(6,4) | 是 | [-1,1] | 样本加权极性 |
| `breadth_pct` | DECIMAL(5,1) | 是 | [0,100] | 该源标的广度 |
| `bull_bear_ratio` | DECIMAL(8,2) | 是 | >=0 | 多空比 |
| `model_ver` | VARCHAR(32) | 否 |  | 来源模型版本 |
| `generated_at` | TIMESTAMP | 否 |  | 上游生成时间 |
| `ingest_run` | CHAR(36) | 否 | IDX | ingest UUID |

规则：

- 只为“当日有数据”的来源建行；缺失源不建 0 行，避免把“没采到”误读成“中性”。
- `n_total=0` 不建行；若上游明确返回零样本，写入 `quality_status=warn` 并保留。
- 新闻流 `has_polarity=false`，`bullish/neutral/bearish` 写 0，`polarity_w/breadth_pct/bull_bear_ratio` 为 null。

|---|---|---|

## 8. 主键、约束与索引

### 8.1 主键/唯一

```sql
ALTER TABLE sentiment_stock_daily
  ADD CONSTRAINT pk_sentiment_stock PRIMARY KEY (trade_date, code);

ALTER TABLE sentiment_market_daily
  ADD CONSTRAINT pk_sentiment_market PRIMARY KEY (trade_date, market);

ALTER TABLE sentiment_source_daily
  ADD CONSTRAINT pk_sentiment_source PRIMARY KEY (trade_date, source);
```

### 8.2 检查约束

```sql
-- 通用
CHECK (trade_date <= CURRENT_DATE)
CHECK (quality_status IN ('pass','warn','fail'))

-- stock
CHECK (code ~ '^[0-9]{6}$')
CHECK (mention_volume >= 0 AND n_sources BETWEEN 0 AND 6)
CHECK (bullish >= 0 AND neutral >= 0 AND bearish >= 0)
CHECK (polarity IS NULL OR polarity BETWEEN -1 AND 1)

-- market
CHECK (index IS NULL OR index BETWEEN 0 AND 100)
CHECK (breadth_pct IS NULL OR breadth_pct BETWEEN 0 AND 100)
CHECK (n_codes >= 0 AND n_samples >= 0)

-- source
CHECK (n_total >= 0 AND n_active >= 0)
CHECK (bullish >= 0 AND neutral >= 0 AND bearish >= 0)
CHECK (polarity_w IS NULL OR polarity_w BETWEEN -1 AND 1)
```

### 8.3 索引

```sql
CREATE INDEX idx_sent_stock_code_date ON sentiment_stock_daily (code, trade_date);
CREATE INDEX idx_sent_stock_date ON sentiment_stock_daily (trade_date);
CREATE INDEX idx_sent_market_date ON sentiment_market_daily (trade_date);
CREATE INDEX idx_sent_source_date ON sentiment_source_daily (trade_date);
CREATE INDEX idx_sent_manifest_date ON sentiment_ingest_manifest (trade_date, status);
```

### 8.4 JSON 校验

- `sources_json`、`weights_json` 必须是合法 JSON 对象；数组/字符串/null 不接受。
- 入库前由 loader 做一次 schema 校验；数据库层若支持 JSON 类型，再加 `IS JSON` 约束。
- 不允许在 JSON 中放帖子正文、URL 参数中的 token、用户隐私字段。

## 9. Freshness / SLA

| 项 | 约定 |
|---|---|
| 上游生成 | `SentimentSnapshot` 每日 08:00 启动 |
| 数据产品发布 | 每日 **08:30** 前（Asia/Shanghai） |
| 失败重试 | 09:15 一次；仍失败则保留上一交易日数据并告警 |
| 新鲜度判定 | 最新 `trade_date` 应为上一交易日；落后 >1 个交易日为 `late` |
| 可用性目标 | 月度 99%（允许上游 source 失败导致单源缺失） |
| 延迟标记 | `quality_status=warn`，不删除旧数据 |

`late` 不阻塞查询，但必须在 `sentiment_ingest_manifest.error_msg` 和目录健康页可见；消费端不得把旧日期当当日数据。

## 10. 数据质量规则

### 10.1 阻断级（fail，不发布）

1. 主键重复。
2. `trade_date` 非法/未来日期。
3. `index` 越界、`breadth_pct` 越界。
4. `bullish/neutral/bearish` 负数。
5. `sources_json` 非法 JSON，或含未知 source 键。
6. `n_codes` 与当日 `sentiment_stock_daily` 去重 code 数不一致（`full` 口径）。
7. `source_hash` 与上游文件不一致（同一次 ingest）。

### 10.2 告警级（warn，发布但标注）

1. 单源缺失（尤其 `e_interaction` 长期为空）。
2. 单日 `n_codes` 偏离 30 日均值 ±40%。
3. `index` 与上一交易日变动 >25 点。
4. `n_samples=0` 或 `n_codes=0`。
5. 历史回填行缺 `sources_json`（`coverage=history_only`，属预期，但需标注）。

### 10.3 抽样核对

每日随机 5 只股票 + 市场指数，逐字段对照 `sentiment_cards.json` / `market_sentiment.json`；差异即 fail。抽样结果写入 `sentiment_ingest_manifest.error_msg` 或独立质检表。

## 11. 血缘、版本与回填

### 11.1 血缘

```text
sentiment_cards.json / market_sentiment.json
  → source_file + source_hash
  → sentiment_* 表
  → v_sentiment_* 只读视图
  → 消费端（KG/投研/策略）
```

每行必须能追到：`source_file`、`source_hash`、`generated_at`、`model_ver`、`ingest_run`。

### 11.2 版本

- 契约版本：本文 `v1.0`；字段变更走 §14。
- 模型版本：`model_ver` 必填；`market_sentiment_v1`、`sentiment_card_v1` 起步。
- 权重版本：`weights_json` 入行；禁止只改代码不标记版本。

### 11.3 回填

| 产品 | 回填范围 | 口径 |
|---|---|---|
| `sentiment_market_daily` | 最近 60 个自然日，以 `market_sentiment_history.jsonl` 为准 | `coverage=history_only`，`is_backfill=true`；不补造 sources |
| `sentiment_source_daily` | 仅前向，自 2026-11-12 起 | 历史 JSONL 没有 source 明细 |
| `sentiment_stock_daily` | 仅前向，自 2026-11-12 起 | 没有历史 cards 快照，禁止伪造 |

> 结论：**市场级可回填 60 天；个股级和来源级从 2026-11-12 起 forward-only。** 任何“历史个股情绪”查询必须返回“无数据”，不得用当前快照倒填。

## 12. 访问与 RACI

| 角色 | 职责 |
|---|---|
| 张松（DATA1） | 数据产品 owner，签收契约、口径、SLA |
| 马岱 | 主办：建表/视图、loader、回填、质检、目录登记、验收 |
| 马良/OSINT | 上游生产者：按时产出 cards/market，保证 `generated_at` 与文件完整 |
| 陈群（DATA3） | 独立质量抽查，出具质检结论 |
| 马钧（DEV1/KG） | **只读消费者**；发布后按视图接入，不直接读 JSON、不写生产图 |
| 投研/策略/风控 | 通过只读视图/API 查询，不持有写权限 |

权限：

- 生产者/数据仓：读写。
- 消费者：只读视图；禁止直接写基表。
- KG：只读视图；不授予写图权限。
