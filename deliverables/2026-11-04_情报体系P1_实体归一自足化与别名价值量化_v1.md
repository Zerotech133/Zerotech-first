## 2. 缺陷六（严重）：别名链断开，同一实体落到两个 canonical

### 现象与机理

`resolve()` 只跳一层。若库里同时存在两条各写一半的行：

```
中国人民银行 -> pboc              # 人工录入的正式 slug
人民银行     -> 中国人民银行       # 回填脚本按规则推导的长名
```

则 `resolve({'人民银行'})` 得 `{'中国人民银行'}`，而 `resolve({'中国人民银行'})` 得 `{'pboc'}`——**同一主体的两种写法落到两个不同 canonical**，实体交集判空。

实测复现：

```
map = {'中国人民银行': 'pboc', '人民银行': '中国人民银行'}
resolve({'人民银行'}) = {'中国人民银行'}
resolve({'中国人民银行'}) = {'pboc'}
两者相等？ False
```

### 危害等级

这是本模块开宗明义要防的错误，且它**不报错、不告警**，只表现为"独立来源数偶尔偏大"——热度分母失真，事后极难定位。之所以至今没爆，纯粹因为现有 31 条全部直指 slug，没有一条是链。

而本轮新增的"分布包含"规则**必然**产出链（它按定义就是 `短名 → 长名`），不修就会在第一次上生产时引爆。

### 修复

`knowledge/entity_alias.py` 新增 `_flatten_alias_chains()`，在建表期做传递闭包：

- `a → b → c` 压平成 `a → c`；
- 环形链（`a ↔ b`）整组剔除并记 ERROR——无法判定谁是 canonical，与二义键同一取向：宁可漏归一，不可错归一；
- **自指（`catl → catl`）不是环**，是恒等映射，必须视为终止点。

处理顺序有硬依赖：**先剔二义键，再压平链**。反过来的话一条二义键会让经过它的链断在半路，压平结果取决于读表顺序。

### 自纠一处

第一版把 `catl → catl` 判成环并剔除，导致 `tests/test_entity_alias.py` 两条测试直接红——而模块文档里本来就写着"`catl → catl` 天然幂等"。修法是先把自指项从遍历图中摘出（保留在结果里），否则 `a → b` 加 `b → b` 时 `b` 会被误判成环（它回到的是自己，不是 `a`）。

| 输入 | 修复前 | 修复后 |
|---|---|---|
| `catl → catl` | 剔除 | `{catl: catl}` |
| `a → b`, `b → b` | 剔除 | `{a: b, b: b}` |
| `a ↔ b` | 剔除 | `{}`（正确） |
| `a → b → c` | `{a: b, b: c}` 断链 | `{a: c, b: c}` |

## 3. 新增规则：分布包含（distributional containment）

### 规则

`short` 是 `long` 的严格子串，且满足全部三条，才判定 `short → canonical(long)`：

1. `docs(short) ⊆ docs(long)`（含短名的文档**全部**也含长名）；
2. `|docs(short)| >= 2`；
3. 长度 >= 3、两侧都不在通用词黑名单。

### 为什么这条证据够硬

真机语料实测：

| 配对 | 含短名 | 含长名 | 同时 | 判定 |
|---|---|---|---|---|
| 中国人民银行 / 人民银行 | 4 | 4 | 4 | ✅ 配对 |
| 中国光伏行业协会 / 光伏行业协会 | 2 | 2 | 2 | ✅ 配对 |
| 欧盟委员会 / 欧盟 | 2 | 1 | 1 | ❌ s14-02 含"欧盟"不含"委员会" |
| 宁德时代新能源科技 / 宁德时代 | — | 0 | 0 | ❌ 长名正文从未出现 |

**反向检验**：`银行` ⊂ `中国人民银行` 在字符串上成立，但含"银行"的文档远多于 4 条，`docs(银行) ⊄ docs(中国人民银行)`，自动拒绝。`中国`/`协会` 同理。这一条是规则能自动跑而不出事的关键——它把"子串"这种弱证据升级成了"分布等价"这种强证据。

### 干净库自推能力

清空别名表（纯函数模拟，不碰真库）后脚本能自推 **7 条**：

```
人民银行              -> 中国人民银行        (containment)
光伏行业协会           -> 中国光伏行业协会     (containment)
华为技术有限公司        -> 华为技术           (suffix)
宁德时代新能源科技股份有限公司 -> 宁德时代新能源科技 (suffix)
比亚迪股份有限公司       -> 比亚迪            (suffix)
贵州茅台酒股份有限公司     -> 贵州茅台酒         (suffix)
隆基绿能股份有限公司      -> 隆基绿能           (suffix)
```

较改动前的 5 条增加 2 条，全部来自分布包含。

## 4. 两处实现 bug（我的，已修）

### 4.1 singleton 用错了计数口径

第一版按"名字在标题/正文出现的文档数"判定孤例，结果漏掉了 `TSMC`/`SMIC`/`Tesla`。

原因很具体：`TSMC` 那条事实的标题是"台积电美国工厂量产4nm"，正文里**根本没有 `TSMC` 这个串**，按文档出现次数算是 0。而它们正是"同一主体两种语言写法"的典型，是人工最该核对的一批。

改为按 `entities` 字段频次计数。修正前后：

```
修正前 singletons=3：CATL, NVIDIA, 欧盟委员会
修正后 singletons=15 → 过滤已归一后 = 6：CATL, NVIDIA, Tesla, TSMC, SMIC, 欧盟委员会
```

### 4.2 候选清单被噪音淹没

第一版 dry-run 输出 8 条候选，其中 6 条其实早已被括号/后缀规则或既有别名表解决。候选是给人工看的清单，混进已解决项会让人对整份清单失去信任。

新增 `_filter_resolved_candidates()`：两侧**同时**命中接受集合才剔除。

```
修正前：detected=5 candidates=8 singletons=3
修正后：detected=7 candidates=0 singletons=0
```

本机归零是正确结果（全部已被别名表覆盖），价值体现在干净环境。

## 5. 第三类候选：短名是 canonical 的前缀

干净库自推出 7 条后，仍有一个缺口：`华为`（3 条事实）、`贵州茅台`（2 条）、`宁德时代`（3 条）这三个**高频**实体没被归一。

根因是结构性盲区：后缀规则产出的 canonical 是**剥后缀的中间形态** `华为技术`，而这个串在正文里一次都没出现，于是 `华为 ⊂ 华为技术` 永远拿不到分布证据，被判 `containment_unproven`。

后果不轻：`华为` 与 `华为技术有限公司` 两种写法实体交集为空，候选召回直接失败。

新增 `suggest_short_form_candidates()`，只出候选不做自动配对——"前缀相同"是弱证据（`中国` ⊂ `中国人民银行`、`苹果` ⊂ `苹果手机` 都不是同一实体），够不上写库门槛。干净库产出 3 条：

```
宁德时代 -> 疑似属于「宁德时代新能源科技」 ['宁德时代新能源科技股份有限公司']
华为     -> 疑似属于「华为技术」 ['华为技术有限公司']
贵州茅台  -> 疑似属于「贵州茅台酒」 ['贵州茅台酒股份有限公司']
```

## 6. 一个必须说清的数：别名值多少

对比"用别名"与"不用别名"，窗口内 42 条事实：

| 指标 | 不用别名 | 用别名 |
|---|---|---|
| 实体键被改写的条数 | — | **37 / 42（88%）** |
| 实体交集非空的配对 | 23 | **55（+139%）** |
| **真同事件对中实体交集为空** | **13 / 16（81%）** | **0 / 16（0%）** |

最后一行是关键：**不用别名时，81% 的真同事件根本召回不到**；用别名后 100% 召回。

但聚类结果仍然是 29 事件 / 拆散 1 / 误合并 1，一个数没变。

### 结论的准确表述

召回已不是瓶颈，**瓶颈 100% 在判定环节**。上一轮"别名是必要不充分"从定性变成了定量：必要（不归一就丢 81% 召回），但不充分（召回补齐后结果不变，说明判定环节把该合的拒了）。

这也意味着：**继续在别名上投入不会改善拆散**。剩下的唯一拆散 S11 是窗内竞争性归属（3 天前的"自律倡议书"占用了 9 天前"跌破成本线"的归属位），要靠时间近邻加权解决，与实体归一无关。
