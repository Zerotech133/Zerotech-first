# 本地数据库迁移实施 SOP

**版本**：v1.0
**适用范围**：`C:/项目/zerobound-kg/ingestion/`
**目标**：在本地完成一套可重复、可审计、可回滚的 PostgreSQL 迁移演练，再决定是否进入生产灰度。

## 0. 成功定义

只有同时满足以下条件，才算“本地迁移演练完成”：

1. 生产 SQLite 源身份已确认并有最新备份；
2. writer 在全量 staging 期间已冻结；
3. staging schema 与生产 schema 隔离；
4. Quant/TDX 全量行数、key 集合、版本 hash 集合一致；
5. 二次回放不新增重复版本；
6. 失败事务可回滚且无半成品；
7. 独立读取配置能查询 staging/PG；
8. PG 不可用时可回退 SQLite；
9. 连续两次只读双跑通过；
10. 生产指针仍未切换，等待人工批准。

## 2. 阶段一：准备与冻结（S0/S1）

### 2.1 记录 writer 状态

```powershell
Get-ScheduledTask -TaskName 'ChanlunScan','QuantMetaSync','KgDailySync' |
  Select-Object TaskName,State,Principal,Actions
```

记录到报告：

- 任务状态；
- 最近运行结果；
- Action；
- 恢复命令；
- 维护窗口和责任人。

### 2.2 管理员窗口冻结

```powershell
Disable-ScheduledTask -TaskName 'ChanlunScan'
Disable-ScheduledTask -TaskName 'QuantMetaSync'
Disable-ScheduledTask -TaskName 'KgDailySync'
```

必须复核：

```text
ChanlunScan    Disabled
QuantMetaSync  Disabled
KgDailySync    Disabled
```

未全部 Disabled 时：

```text
只允许小样本只读实验，禁止全量 staging 和发布。
```

### 2.3 建立最新备份

备份内容：

- PostgreSQL `quant`、`tdx_info`、必要 `meta` schema；
- `meta.sync_state`；
- `meta.migration_log`；
- SQLite 源文件；
- manifest/config；
- writer 状态快照。

每个文件必须记录：

```text
realpath / size / mtime / SHA256
```

PG dump 必须执行：

```text
pg_restore -l <dump>
```

并保存 checksum。

## 5. 阶段四：Quant staging 回放（S4）

目标 schema：

```text
quant_trial_20261017
```

范围：

- `chanlun_pool`；
- `nine_dim_fina`；
- 其余 quant 表只读校验。

实现要求：

1. SQLite 使用 `mode=ro`；
2. PostgreSQL 单事务写入 staging；
3. 主键集合先对账；
4. 使用 `ON CONFLICT DO NOTHING` 或明确 key-aware upsert；
5. 不写 `meta.sync_state`；
6. 不修改现役 `quant`；
7. 失败即 rollback；
8. 二次回放零新增；
9. 完成全量 digest 对账。

尚未授权前不得执行：

```text
quant.chanlun_pool 生产补写
quant.nine_dim_fina 生产补写
```

## 6. 阶段五：类型化 schema 设计（S2）

先在 staging 建议：

- 日期字段：`date` 或 `timestamptz`；
- 数值字段：先保留原始 text，同时增加 typed shadow 列；
- 正文：`text`；
- 版本字段：`version_hash text NOT NULL`；
- 来源：`source_system text NOT NULL`；
- 批次：`ingest_run_id uuid/text NOT NULL`；
- 采集时间：`_fetched_at timestamptz`。

类型转换必须先输出：

```text
总行数 / 可转换行数 / 失败行数 / 失败样例
```

失败行不能静默丢弃。

## 9. 回滚 SOP

### staging 回滚

仅允许删除本次明确创建的 schema：

```sql
DROP SCHEMA <本次试验schema> CASCADE;
```

删除前必须：

1. 查询 schema 对象清单；
2. 与报告中的对象清单一致；
3. 确认不是 `quant`、`tdx_info`、`tdx_archive_20261017`；
4. 记录删除时间和操作者。

### 数据回滚

- staging 事务失败：自动 rollback；
- PG 正式镜像变更：使用新 dump 恢复到隔离库先验证；
- `sync_state`：按变更前导出恢复；
- 指针：始终保持 SQLite，未批准不修改。
