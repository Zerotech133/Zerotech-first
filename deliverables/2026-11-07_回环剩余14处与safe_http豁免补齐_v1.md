## 一、先说 P0：第 7 份漏网副本

上一份交付件里写的「六份同步副本」是错的。`agent_platform/legion_command/safe_http.py`
是**第 7 份独立实现**，也是唯一没跟上 2026-11-06 回环豁免的一份：

```python
def safe_urlopen(url, *args, **kwargs):
    ...
    return urllib.request.urlopen(url, *args, **kwargs)   # 只有 scheme 校验，没有代理处理
```

**为什么它必须单独存在**：`legion_command` 有双入口 —— `import legion_command.serve`（包形态）
和 `python serve.py`（脚本形态，此时 `legion_command/` 在 `sys.path[0]`）。脚本形态下若这里也叫
`safe_urlopen.py`，会遮蔽其它树的同名副本，出现「改了根目录那份、这个入口不生效」。故改名
`safe_http.py`。

**影响面**：7 个模块 12 处调用，全部打本机服务 ——

| 文件:行 | 目标 |
|---|---|
| `serve.py:883`、`:901` | `127.0.0.1:11434/api/tags`（Ollama 探活） |
| `openhands_engine.py:96`、`:198` | `8771` / `8770` OpenHands |
| `mission_planner.py:179`、`mission_worker.py:249` | `8796` 模型网关 |
| `keypool.py:215`/`543`/`585`/`605` | `8796` / `11434` 密钥池探活 |
| `tianfeng_view.py:44`、`mcp_bridge.py:46` | `8787` Hermes |

**为什么扫描器一直没报**：`scan_loopback_urlopen.py` 判 `GUARDED` 的依据是「这行调的是
`safe_urlopen`」。这 12 处在源码形态上完美符合 → 计入 GUARDED，永远不进 VICTIM 清单。
和盯盘 `_hub_call` 是同一失效形态：代理一严格，`serve.py` 显示"本机无模型"、`tianfeng_view`
显示 Hermes 挂了，日志里看不到任何与代理有关的字样。

**修法**（不新增第 8 份副本）：保留文件名，内部改为委托载入 `agent_platform/safe_urlopen.py`
（与 `hermes_auth._load_safe_urlopen` 同款 spec 载入），实现只留一份。若委派失败，兜底仍保留
scheme 校验并 fail-visible，不静默放行。

## 三、测试对齐（6 处，2 文件）

改 `urlopen` 会击穿「靠 patch `urllib.request.urlopen` 禁网」的防护：`safe_urlopen` 对回环走独立的
`ProxyHandler({})` opener，patch 全局 `urlopen` 拦不住 → 测试真连本机服务。判例：
`test_reranker_degrade_rule_only`、`test_web_chat.py` 上一轮就是这么红的。

## 六、踩到的坑（写下来省下一次）

1. **`ops/rotate_push_secrets.py` 插入锚点选成字典内的键**，导入块插进 `KEY_SPECS = {` 里面 →
   `SyntaxError`。脚本的 `ast.parse` 落盘前校验拦住了，没写坏文件。锚点改 `PORT = 8097`。
2. **`portal/api_health_portal.py` 缩进判断错一级**（`if http_path:` 是 8 空格不是 12），
   `count==0` 当场报错，没误改。
3. **补丁脚本重跑顺序错**：先做 `count` 断言再判"已替换过"，导致第二次 apply 在已改过的文件上报错。
   改成"old 出现 0 次且 new 已存在 → 跳过"。插入同理。
4. **`feishu_bot_ws.py` 导入放函数内** → 模块无 `safe_urlopen` 属性，2 条测试 `AttributeError`。
   已回退重做，改模块级。（这就是"改一处验一处"的价值，静态看完全合理。）
5. `calls_total` 从 354 涨到 355 是基线变动（HEAD 已从 `336b783f3` 推进到 `e202e07e4`，
   并行工作新增了一处调用），不是本次改动引入；同口径对比用 `e202e07e4` 检出做的。
6. **"顺手清理未用 import"的判据自己写错了**：写的是 `if "urllib." not in text` —— import 行
   本身含 `urllib.`，条件永远为假，两个已无引用的 `import urllib.request` 根本没删掉（F401 会卡
   ratchet）。改成「先排除 import 行本身再判是否还被引用」才对。复核方式：`grep -n urllib <file>`
   应只剩真的还在用的行（`kpi_report.py` 保留，因为 L428 还在用）。
