## 二、机制层（方法论要点）

- **三道门纪律**：进门校验（日期/实体/词典）→ 写门（水位+幂等 MERGE+写门 ACK）→ 出门对账（通报+承诺对账）。
- **自愈环**：故障 → 判例 → 用例 → 制度化。判例不进用例库等于没修。
- **通报五问契约**：缺什么 / 数据点在哪 / 为什么以前有现在没了 / 谁认领 / 多久恢复；逾期自动 🔴 置顶进通报头部。
- **因子三级**：F0 可查 → F1 可算 → F2 可用（|RankIC|≥0.03 且 ICIR≥0.3 且分层单调 ≥60% 截面）。未过验证不配进策略；untested 也是结论。

## 五、判例库（当日新增/升级）

2. **strptime 盲区**：%m/%d 不做范围校验 → 一律 `date()` 二次钳制
3. **★ 串味升级**：数字对串味（10↔68、16↔91）**不限于 stdout**——Write/Edit 传输层同样会串。测试/补丁/日志的日期字面量一律 chr() 码点构造
4. **日期口径混用**：跨格式字符串直接比较恒真恒假（'-'<'0'）——比较前必须归一同格式
5. **调试纪律**：改代码前必须实测目标查询本体，不凭中间打印推断；提交成败以 `git log` 复核为准，不信 exit code 单值
