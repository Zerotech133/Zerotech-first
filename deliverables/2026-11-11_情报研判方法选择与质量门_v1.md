# 情报研判方法选择与质量门（一页表）

版本：v1（草案）｜日期：2026-11-11｜适用：军情司/情报域研判  
维护：军情司 INTEL0｜复核：A0/QA1（待确认）  
定性：工作方法参考，不替代证据、L2/L3 签批和既有验收。

> **一句话**：情报是在特定决策/行动场景下，经目的性加工、验证和传递，能降低不确定性并影响行动的知识。方法只保证判断可解释、可复核、可修正，不制造伪精确；情报价值最终由行动结果检验。

## 一、方法选择表

| 研判情境 | 首选方法 | 做法与产出 | 主要局限 | 质量门 |
|---|---|---|---|---|
| 事项很多，只需快速粗排 | 排序式投票 | 每人对候选排序，合并成总顺序；只输出先后 | 只有顺序，没有“重要多少”；不适合定权重 | G1/G5 |
| 候选较少、后果重大，需要相对权重 | 成对比较 | 所有候选两两比较（1–9 标度）；输出顺序+相对权重；AHP 场景加一致性检验 | 比较次数多；赋权标准仍需人定；“一致”不等于“正确” | G1/G3/G5 |
| 已有明确标准，需反复评分/考核 | 加权排序 | 先定标准与权重，再逐项打分；输出加权分+分项分+权重表 | 标准和权重仍是人为选择；容易把评分当客观事实 | G1/G3/G5/G6 |
| 事件相互耦合、数据少、需推演连锁反应 | 交叉影响分析 | 建影响矩阵→评影响方向/强度（主观概率或德尔菲）→算影响值→蒙特卡罗模拟；输出情景与敏感变量 | 初始概率高度主观；模拟不消除不确定性；不适合替代因果验证 | G1/G3/G5 |
| 重大方案、评估或判断定稿前 | 事前分析（premortem） | 假定数月/数年后已失败，反推失败原因；输出前五大失败模式、预警信号、缓解责任人 | 只揭示风险，不直接给解法；需与缓解计划绑定 | G4 |
| 最终研判发布前、团队自检 | 结构化自我批评 | 从反方质疑假设、不确定性来源、分析流程、关键假定、证据诊断力、异常证据、信息空白、环境变化、替代模型、欺骗指标；输出修正后的置信度 | 要求成员从支持者转为批判者；缺心理安全会流于形式 | G3/G4/G5 |

**组合规则**

- 日常队列：**加权排序 + 排序式投票**；先粗排，再按标准打分，不要用两两比较处理上百项。
- 高价值/高风险取舍：**成对比较 + 加权排序**；权重、标准和比较记录必须留痕。
- 强耦合事件：**交叉影响 + 情景分析**；概率用区间/情景表达，不给单点“精确值”。
- 重大方案定稿前：**事前分析**；失败模式要落到预警指标和责任人。
- 发布前：**结构化自我批评/红队**；独立复核，不能作者自评后直接放行。
- 数据充分且可做因果识别时：优先定量模型、实验或因果检验；交叉影响只能作情景补充，不能冒充证据。

**禁止事项**

1. 没有明确标准就加权评分，制造“客观”假象；
2. 没有概率来源就输出单点概率或“精确预测”；
3. 把排序当结论、把评分当证据；
4. 用作者自评代替独立挑战；
5. 把“情报成品”降格为“信息汇编”却不标注。

## 二、质量门（G0–G6）

| 门 | 必答问题 | 不过怎么办 |
|---|---|---|
| **G0 问题门** | 决策问题、客户/使用人、截止时间、责任人是否明确？ | 退回信息需求，不启动研判 |
| **G1 方法门** | 为什么选这个方法？输入数据、时间、成本、局限是否写明？ | 补方法说明；无方法记录不得进入分析 |
| **G2 证据门** | 来源、数据时点、血缘、采集方法、证据强度是否可追溯？高风险议题是否有第二来源？ | 标为“信息产品”；补证后再升级为情报成品 |
| **G3 推理门** | 关键假定、替代解释、反证/异常证据、信息空白、欺骗指标是否显性化？ | 退回研判，不得用“综合判断”掩盖缺口 |
| **G4 挑战门** | 是否做事前分析/结构化自我批评/红队？是否有独立复核人和异议记录？ | 不得发布；作者自评不算挑战 |
| **G5 表达门** | 置信度（高/中/低）及依据、不确定性区间、行动建议、责任人/时限是否完整？ | 只能发“暂定版”，标注有效期和复核人 |
| **G6 反馈门** | 决策/行动结果、复盘结论、基线和假设是否回流更新？ | 建跟踪项；逾期未复盘则降级该结论 |

**发布规则**

- G0–G6 全过，才可作为正式情报成品发布。
- G2/G3/G4 任一不过：**不得发布**。
- 仅 G5 不过：可发“暂定版”，必须带**有效期、置信度依据、复核人**。
- 紧急情况下先行动：可发“预警版”，但须在行动后补证据、补挑战、补复盘；不能把紧急当永久豁免。
- **质量门 ≠ L2/L3 签批**；需要人工签批的，仍按既有治理流程执行。

## 三、情报成品最小字段

```yaml
decision_question:   # 要支持的具体决策/行动
customer_owner:      # 使用人/责任人
deadline:            # 决策截止时间
answer:              # 研判结论（一句话）
confidence:          # high | medium | low + 依据
method:              # 选用的方法及理由
assumptions:         # 关键假定
alternatives:        # 竞争性假设/替代解释
disconfirming_evidence:  # 反证与异常证据
information_gaps:    # 信息空白
early_warning:       # 预警指标/触发条件
action_recommendation:   # 建议行动
feedback_due:        # 复盘时间与责任人
```

## 四、方法操作卡

- **排序式投票**：先固定候选集和排序规则；每人独立排序；合并时记录并列/弃权规则；只输出顺序，不输出权重。
- **成对比较**：候选控制在 5–9 个；两两比较用 1–9 标度；记录比较矩阵；用 AHP 时报告一致性比率，超阈值则重做或降级结论。
- **加权排序**：标准示例为影响、时效、证据强度、可行动性、成本；权重合计为 1；逐项 1–5 分；必须做敏感性检查，说明“权重变化是否翻转结论”。
- **交叉影响分析**：先列事件与影响方向，再给影响强度/概率区间；标明专家来源；蒙特卡罗输出情景分布，不输出单点概率；报告最敏感变量。
- **事前分析**：统一提问“假设 6/12 个月后失败，最可能为什么？”；输出前五大失败模式、早期信号、缓解动作、责任人；不把“想到了”当“已控制”。
- **结构化自我批评**：至少回答十问——关键假定、不确定性来源、分析流程漏洞、证据诊断力、异常证据、信息空白、环境变化、替代模型、文化知识、欺骗指标；由独立复核人签字，记录异议和置信度调整。

## 五、快速判定

```text
问题不清?           → G0 退回
数据充分且可因果识别? → 定量/实验，交叉影响只作情景补充
项目多、只需粗排?     → 排序式投票
项目少、后果重大?     → 成对比较 + 加权排序
有明确标准、需考核?   → 加权排序 + 留痕
事件强耦合、数据少?   → 交叉影响 + 情景
重大方案定稿前?       → 事前分析
发布前?               → 结构化自我批评/红队 + G0–G6
```

**底线**：主观概率、评分和模拟只能把不确定性摆到桌面上；不能替代证据、独立判断和人工责任。
