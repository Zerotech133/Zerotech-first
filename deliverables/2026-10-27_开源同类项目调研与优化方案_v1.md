## 0. 一页纸结论

1. **我们不是缺功能，是缺“闭环证据”**：开源同类项目（尤其在 Agent 组织、投研、评测、记忆四条线）主要赢在三件套——**SOP 化、评测化、可追溯**；我们的强项是真实组织/账本/数据/工单，弱项也正好是这三件套。
2. **最值得抄的不是框架代码，是“接口与纪律”**：MetaGPT 的「Code = SOP(Team)」、TradingAgents 的「分析师→多空辩论→风控→组合经理 + 记忆结算」、Qlib 的「因子/IC/Point-in-Time」、TheAgentCompany 的「真实工作 benchmark + 结果/子检查点双评分」、Graphiti 的「事实带有效期 + episode 溯源」。
3. **我们已有底座不要换**：devtask/worktree/AGENTS、事件账本、seat 能力卡与 5 维真实度、数据仓与 LCS-1 假设链——这些比大多数开源项目更“像真公司”；**在其上做薄适配层**，不要 fork MetaGPT/CrewAI/LangGraph 当内核。
4. **P0 八项（2 周，最高杠杆）**：①评测门（golden set + CI）；②Agent trace/成本观测；③Policy-as-code（tool_matrix+审批单源）；④记忆 v2（core/archival/recall + 时间图溯源）；⑤LCS-1 基线对照（Qlib Alpha158/IC/RankIC/Point-in-Time）；⑥研究流水线状态机（checkpoint/resume+审批暂停）；⑦数据血缘（OpenLineage 风格 run/job/dataset+冻结回执）；⑧代码 Agent 沙箱+内部 benchmark（OpenHands/TheAgentCompany 风格）。
5. **P1/P2**：TradingAgents 式投研图（映射到研究院 8 席）、NautilusTrader/Lean 型执行引擎评估（不重造）、Graphiti 时间图接研究证据链、内部席位 benchmark 与晋升挂钩。
6. **60 席不是资产，是成本**：开源项目示范「少量角色 + 清晰 SOP + 可评测」远胜「人海 + 各自为战」；建议常开 4–6 实席（研究院 4 + 研发 2），其余按需唤醒。
7. **不抄清单**：不要把 MetaGPT/ChatDev/CrewAI/LangGraph 直接搬成内核；不要 60 个自主 Agent 常开；不要把 LLM 输出当证据；不要自研订单路由/撮合；不要用 GraphRAG 静态摘要替代动态事实。
8. **验收口径**：每项优化必须带「可复现命令/产物/评分」，并进入 seat realness 第 6 维（评测），否则只算文章不算能力。

## 2. 八个经验簇（开源怎么做 → 我们能学什么）

### 2.1 SOP-as-code：组织不是“角色列表”，是“产物交接协议”

- **MetaGPT**：把软件公司的 SOP 物化成角色（PM/架构师/项目经理/工程师）+ 结构化产物（user story、竞品分析、需求、数据结构、API、文档），核心哲学 `Code = SOP(Team)`；支持 CLI/库、Data Interpreter、Debate、Researcher 等用法（[README](https://github.com/FoundationAgents/MetaGPT)）。
- **ChatDev**：1.0 是虚拟软件公司（CEO/CTO/程序员），按 ChatChain/Phase/Role 组织“研讨会”；2.0 变成零代码编排平台（YAML workflow、可视化画布、Python SDK、Docker、Human-in-the-loop、incremental development）；MacNet 用 DAG 支持上千 Agent 拓扑，puppeteer 用可学习编排器调度（[README](https://github.com/OpenBMB/ChatDev)）。
- **TheAgentCompany**：把“真实公司”做成 175 个 Docker 任务镜像（/instruction/task.md + /utils/eval.py + /workspace），覆盖 SWE/PM/数据/HR/财务/行政；评分=**结果评估（主）+ 子检查点（次）**，支持 deterministic 与 LLM-based evaluators（[README](https://github.com/TheAgentCompany/TheAgentCompany)）。
- **可抄**：①每个席位=输入契约+产物 schema+交接门；②SOP 可执行化（YAML/状态机），不是 prompt 里写一段话；③“子检查点”打分（不是只看最终交付）；④人机协作模式（Human-in-the-loop）。
- **我们的落点**：`AGENTS.md`/seat capability cards 已接近“角色卡”，但缺**产物 schema + 子检查点评分**；建议给研究院 8 阶段每阶段定义 `input/output/checkpoints`（JSON schema 入 git），席位交付物按 schema 自动校验。

### 2.2 评测驱动：没有 benchmark 的“能力”不可信

- **TheAgentCompany**：用真实工具链（GitLab/Plane/ownCloud/RocketChat）+ 175 任务，结果+子检查点双评分，可扩展任务/评估器（[README](https://github.com/TheAgentCompany/TheAgentCompany)）。
- **promptfoo**：开源 LLM evals + red teaming，CI/CD 集成，本地运行（[README](https://github.com/promptfoo/promptfoo)）。
- **Inspect AI**：UK AISI 的评测框架，内置 200+ evals，支持多轮、工具、模型评分（[README](https://github.com/UKGovernmentBEIS/inspect_ai)）。
- **Langfuse**：trace + prompt 管理 + evals + datasets + playground，可自托管（[README](https://github.com/langfuse/langfuse)）。
- **可抄**：①每个席位/工具一条“golden set”（输入+期望产物/判据）；②CI 门（合并前跑）；③失败基线清单（我们已有测试基线雏形）；④red teaming 用例（越权/注入/外发）。
- **我们的落点**：seat realness 目前 5 维（授权/工具/触发/审计/回滚）→ **加第 6 维“评测”**（golden set 通过率+基准分）；`agent_platform/tools/seat_realness.py` 扩展；`agent_platform/evals/behaviors.json` 可升级为 dataset。

### 2.3 投研多 Agent：并行分析 → 多空辩论 → 风控 → 组合决策

- **TradingAgents**：分析师团队（基本面/情绪/新闻/技术）**并行**工作，研报齐后进入研究辩论；研究员团队含**多头/空头**结构化辩论；交易员综合报告做决策；风控团队评估波动/流动性，组合经理批准/拒绝；LangGraph 实现，支持 checkpoint resume、每 ticker SQLite 断点；**决策记忆日志**：每次决策在持有期结束后结算真实收益与相对基准 alpha，生成反思，供后续 PM 读最近决策与跨票教训；回测按 ticker×date grid，每格用决策日之后首个收盘入场，按区域基准算 alpha；强调 **point-in-time integrity**（历史日期只读当时已发布数据；SEC EDGAR 按 filed 日期；Yahoo 历史报表 withheld）；`--checkpoint` 断点恢复；免责声明“研究用途，非投资建议”（[README](https://github.com/TauricResearch/TradingAgents)）。
- **可抄**：①席位映射：分析师×4（基本面/情绪/新闻/技术）→ 我们 INTEL1/PROD1/STRAT1 等；多头/空头辩论 → 我们 T1/T2 五虎；风控团队 → 风控三师；组合经理 → 老田/A0；②**决策后结算**（持有期结束算 alpha 并写反思）→ 我们的 LCS-1 回测报告缺“决策→结果→反思”闭环；③point-in-time 纪律 → 我们的冻结回执/S3 对账要强化 as-of；④checkpoint/resume → 研究流水线长任务可恢复。
- **我们的落点**：LCS-1 补证链（Spec/Freeze/Harness/回测/评审）正好是对标物；BACK1 回测清单里的 S3 对账、成本×1.5、预注册出场与它同源；可把“多空辩论/风控/组合经理”显式写进 LCS-1 评审记录（角色已在组织里）。

### 2.4 数据驱动 R&D：假设→实验→反馈的自进化

- **RD-Agent(Q)**：数据中心的因子-模型联合优化；假设-实验-反馈循环；宣称在真实股票市场、成本 <$10 下 ARR 约为基准因子库 2×、因子数少 70%+；支持从财报提取因子、模型实现；MLE-bench 排名领先（[README](https://github.com/microsoft/RD-Agent)）。
- **Qlib**：数据层/表达式引擎/Alpha158/Alpha360/模型 zoo/回测/在线服务；**Point-in-Time 数据库**；`qrun` 一条配置跑全流程；IC/RankIC 分析；支持监督学习/市场动态建模/RL；RD-Agent 自动因子挖掘（[README](https://github.com/microsoft/qlib)）。
- **可抄**：①LCS-1 必须有**基线对照**（Alpha158 / 动量 / 简单均线），否则“图形先行更好”只是故事；②IC/RankIC/分组收益作为标准报告；③PIT 数据版本；④假设登记→实验→反馈的循环（我们的 ACAD1 已接近，但缺机器可读实验台账）。
- **我们的落点**：`quant_backtest` 已有数据/回测引擎；建议新增 `quant_backtest/baseline_factors.py`（Alpha158 子集 + IC/RankIC）与 LCS-1 增量对比；`nine_dim_history`/walk-forward 产物补齐。

### 2.5 研究=实盘同构：同一套策略代码跑回测与实盘

- **NautilusTrader**：Rust 原生事件驱动、确定性；研究/回测/实盘**同一套策略与执行算法代码**；多资产多交易所适配器；支持 quote/trade/bar/orderbook 纳秒级回测；LGPL-3.0；只做单节点回测与实盘，UI/分布式/AI 工具不在 OSS 范围（[README](https://github.com/nautechsystems/nautilus_trader)）。
- **可抄**：①回测与模拟盘共用同一执行/撮合接口（我们已有 paper engine，但信号→落单未接线）；②不要把“回测引擎”和“实盘执行”写两套；③执行引擎评估清单：NautilusTrader（LGPL，注意许可证）vs QuantConnect Lean（C#，未取到 README，暂不评）vs 现网 paper engine。
- **我们的落点**：D14 解锁前先定“执行引擎选型”单（评估不实施）；LCS-1 harness 只做研究回测，不接实盘。

### 2.6 记忆/上下文：不是聊天历史，是带时间与出处的“事实”

- **Letta (MemGPT)**：有状态 Agent + 记忆学习；现 letta-code 提供 agent harness/TUI/App Server/channels/SDK（[README](https://github.com/letta-ai/letta)）。
- **Graphiti**：时间化上下文图（context graph）：实体/关系/事实带**有效期**（何时为真、何时被取代）、**episodes** 保存原始数据并让所有派生事实可溯源；增量构建、不需要全图重算；混合检索（语义+BM25+图遍历）；支持 Neo4j/FalkorDB/Neptune（[README](https://github.com/getzep/graphiti)）。
- **可抄**：①记忆分层 core/archival/recall；②研究结论必须挂 episode 溯源与有效期（“当时为真，后来被推翻”要保留）；③矛盾事实自动失效而非删除；④混合检索（我们已有 BM25 观察期，可接图）。
- **我们的落点**：`seat memory/capability cards` 升级为统一 memory 服务（namespace + provenance + validity）；LCS-1 事件/席位/公告证据用时间图存“何时可得、何时失效”，直接服务 as-of 回测。

### 2.7 可观测与治理：trace、策略、策略即代码

- **Langfuse**：LLM 应用 trace、prompt 管理、evals、datasets、playground；自托管；MIT（ee 目录除外）（[README](https://github.com/langfuse/langfuse)）。
- **OPA**：CNCF 毕业的策略引擎；Rego 声明式规则；服务通过查询 OPA 得到 allow/deny 并执行；可集成 K8s/Terraform/Docker/SSH 等（[README](https://github.com/open-policy-agent/opa)）。
- **可抄**：①每次 Agent 运行一个 trace_id，记录模型/工具/耗时/token/成本，链到事件账本；②把 `tool_matrix.json` + L0/L1/L2/L3 审批规则收敛为**单源策略文件**（先 Python 决策器，后 OPA/Rego）；③策略自带单测（allow/deny/边界），改策略=跑测试；④审批决策留痕可审计。
- **我们的落点**：`agent_platform/rules/tool_matrix.json`、`dev_events.jsonl`、`trace_log`、五要素审批 → 统一“策略层 + trace 层”；`seat_realness` 审计维升级为“有 trace/策略决策证据”。

### 2.8 执行沙箱与数据血缘：让 Agent 敢跑、数据说得清

- **OpenHands**：Agent Canvas 控制台；Agent Server REST；可在本地/Docker/VM/云运行；automations 定时/webhook；支持多后端切换（Claude Code/Codex/Gemini/ACP）；Docker 沙箱/多沙箱并发；默认 loopback、API key、自托管安全警告（[README](https://github.com/OpenHands/OpenHands)）。
- **OpenLineage**：开放血缘标准，定义 run/job/dataset 实体与 facets；Marquez 参考实现；集成 Spark/Airflow/dbt/Flink 等（[README](https://github.com/OpenLineage/OpenLineage)）。
- **可抄**：①代码 Agent 在容器沙箱跑（工作区挂载+网络出口白名单），不是直接改宿主；②每个数据任务发 run/job/dataset 血缘事件（输入表/输出表/版本/facets），冻结回执可挂 lineage；③automation 事件驱动（但需审批门）。
- **我们的落点**：ARCH1/DEV 席已有 worktree，但未隔离；DATA1 冻结回执可加 OpenLineage 事件；`quant_backtest/data/catalog.json` 已有表/新鲜度，缺 run 级血缘。

## 4. 优化方案（分层）

### 4.1 五条原则

1. **底座不换**：devtask/worktree/AGENTS/事件账本/seat 真实度是资产，开源框架只做“薄适配”，不 fork 当内核。
2. **证据优先**：每个优化自带可复现命令/产物/评分；无证据不算完成（延续 C 阶段纪律）。
3. **先评测后扩张**：新席位/新工具先上 golden set，再谈 5/5；不靠“有代码/有配置”判真。
4. **人机有界**：高风险（外发/交易/删除/系统）仍 L2 人工；Agent 只做可回滚动作。
5. **少而精**：常开 4–6 实席（研究院 4 + 研发 2），其余按需唤醒；60 席是组织图不是并发预算。

## 5. 不抄 / 反模式（同样重要）

1. **不要把 MetaGPT/ChatDev/CrewAI/LangGraph 直接当内核**：它们的 SOP/编排是“示例”，我们的账本/工单/数据才是资产；薄适配即可。
2. **不要 60 席全开**：开源项目有效组织多为 4–10 个角色；我们 60 席 = 组织图，不是并发目标。
3. **不要 LLM 当证据**：TradingAgents 自己写“研究用途，非投资建议”；我们的“结论分级/事实与解释分离”要保留。
4. **不要自研撮合/订单路由**：Nautilus/Lean 类引擎验证充分，自研风险高；先评估再选。
5. **不要 GraphRAG 静态摘要替代动态事实**：Graphiti 的“有效期+episode 溯源”才是我们需要的（研究证据会变）。
6. **不要绕过审批/沙箱**：OpenHands 自己反复警告“无沙箱=Agent 可访问你整个文件系统”；我们 L2 五要素不能省。
7. **不要追框架版本**：LangGraph/Langfuse 等迭代快，锁版本、薄封装、留退出路径。
