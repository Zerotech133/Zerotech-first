## 〇、总判

**代码面健康、交付质量高，但战略面「唯一战略源」已失守、生产面调度在无声腐烂、节奏面投入与风险错配。** 三面各自独立发酵，互相放大：战略源过期 → 各线各自为战 → 任务选择偏差 → P1 地基停摆 → 展示层越漂亮风险越隐蔽。优化方案因此不是补丁清单，而是**重建三层秩序：战略源刷新 → 生产地基修复 → 研发节奏再平衡**。

## 一、五个系统性问题（带证据）

### P-A 战略源失守（治理层，最高优先）

ROADMAP v1 停在 10-12，治理规则明文「本文件是唯一战略源」。但此后十天诞生的三大主线——**军团组织治理（S13~S45，31 单）、个人 OS（WO-OS-01~30）、通信/飞书中台（WO-FS-148 系 + 商业化）**——全部没有进入模块矩阵。模块矩阵最后一行还停在「10-19~25 批 D 面谈」。后果：各线只能拿历史授权或自行判断优先级，正是任务选择偏差的制度性温床。

### P-B 调度面无声腐烂（生产层）

30 个计划任务 13 个非零退出且**零告警闭环**（失败只写 stderr，计划任务不采集）；QuantWatchdog 因乱码路径**从未成功运行过**；AlertWatch 自己 Exit=1（告警看门狗告不了自己）；晨报任务名不副实（实跑会议回填，晨报停更 10-15）。全项目审计定性：这是当前唯一「系统性」级别缺陷。

### P-B' 心跳链断四天（生产层，est_cost 冻结根因）

根因已实测定位：纯 CPU Ollama（size_vram=0，~12 tok/s）被分钟级调度任务抢占，推理超时。INFER_TIMEOUT 加到 300s 仍不够——**继续加超时不是解法**。连带后果：intel 产物停 10-18 → est_cost 解冻三前置持续不满足 → 量化线 M0 卡死。

### P-C 投入与风险错配（节奏层）

S33~S45 十三单全在组织治理（P3）；同期 P1 三项（心跳、周一巡检 0xC000013A、触发链预检）四天零进展。OS 板块一天 30 单。原因不是能力，是**P1 全卡「需授权/需真机验证」而 P3 在授权内可无限推进**——制度使然，自觉无解。

### P-D 工程资产未入库（卫生层）

225 个未提交改动（219 未跟踪，含 26 个 quant_backtest 测试 + 16 份治理文书）持续多日。测试和治理文档是资产，不入库 = 磁盘故障即失忆。工单账本 288 单中 aborted 45（16%）、在途 3 单 owner=unknown-agent。

### P-E 门面跑在地基前（产品层）

个人 OS 七源中 alerts/notify/晨报三源底层数据链正处 P1 故障区；审批队列未接（「待本人决策」空壳）；诸葛亮真模型待 key。OS 的价值上限 = 最弱数据源的上限。

## 二、优化方案（五条主线）

### 方案一：ROADMAP v2 立宪刷新（治 P-A，一天工作量）

在 v1 治理规则不变的前提下更新模块矩阵与时间线，把三条新主线正式收编：

| 新增/更新模块 | 已达里程碑 | 下一里程碑 | 验收口径 | 状态 |
|---|---|---|---|---|
| 个人 OS（唯一入口） | v9 生产切换、七源、证据契约 | 审批队列接入 + 真模型对照 | WO-OS 工单链 + 手册 v2 | 🟢 高速 |
| 军团组织与调度 | 编制 P1/P2 清零、68 席全档 | **调度面修复（P1 地基）** | 计划任务全零退出 + 告警闭环 | 🔴 修复期 |
| 通信/飞书中台 | 鲁肃部 K1-K3、意图路由 0.96 | 商业化上线检查清单 v0.3 过会 | 上线检查清单 | 🟡 |
| 量化总纲（QT 线） | 契约层收口多单 | M0 心跳解冻 | est_cost 三前置 | 🔴 卡 P-B' |

同步动作：时间线过期项（批 D 面谈、P5c 复验）更新实态；**v2 发布即宣布 v1 冻结**（沿用立宪惯例）。

**验收**：BLOCKERS 清单、看板日报、各线工单自此只引 v2；grep 全仓无「按 ROADMAP v1 推进」的新增引用。

### 方案二：调度面修复三步走（治 P-B/P-B'，本周内）

**第一步·告警闭环（新能力，建议列 P0）**：任何计划任务非零退出 → 统一上报通道（进 OS 通知源 + 飞书告警卡），消灭「失败无人知」。这是三步中唯一的新代码，其余全是配置修复。

**第二步·六个配置修复**（全部待五要素，O1-O6 修复包已备好草案）：
- O1 QuantWatchdog 乱码路径→真实路径（附 ASCII 路径转发脚本的替代方案，规避中文路径再被编码破坏）
- O2 AlertWatch 非法触发器日期 `2026-10-16`
- O4 周一巡检 0xC000013A（10-26 前必须真机验证，窗口剩 4 天）
- O5 触发链预检 Exit=2
- O6 LegionW42MorningBrief 改名或补真晨报任务

**第三步·心跳根修（错峰而非加超时）**：
- 实测一轮 infer 耗时分布（当前 12 tok/s 纯 CPU）→ 三选一：调度错峰（心跳独占窗口）/ LLM 调用串行化配额 / 心跳换小模型（4b）
- 同时给 degraded.json 补「耗时与并发上下文」字段——现有落盘答不了「慢在哪、几个任务在抢」，不足以定修法
- 建议与 OS 挂账#1（晨报挂载）**合并审批**：晨报恢复即心跳链路的端到端验收载体

**验收**：30 任务全部 Exit=0 或有告警留痕；心跳连续 3 日 non-degraded；est_cost 前置②③转绿。

### 方案三：任务选择偏差的制度化矫正（治 P-C）

三件套机制，写进 ROADMAP v2 工程治理规则：

1. **P1 衰减升级**：P1 级事项每 48 小时无实质进展，自动置顶 BLOCKERS 清单并标注阻塞原因（需授权/需真机/需决策）——让「卡住」可见，而非靠复盘事后点名。
2. **授权批量节奏**：老田每日固定一个时段（建议 09:00 晨会后）一次性处理 BLOCKERS——把「等授权」从离散等待变为批量吞吐，P1 不再因「等一句话」停四天。
3. **P3 配额**：组织治理类（P3）工单不得超过当日新开工单的 50%——不是否定 P3 价值（编制 P1/P2 清零是真成果），而是防止它成为绕开 P1 的舒适区。

**验收**：BLOCKERS 清单每日清空率进入看板日报；P1 平均滞留时长环比下降。

### 方案四：工程卫生三日清（治 P-D）

1. **入库**：219 未跟踪文件分类处置——测试/治理文书/契约文件一律 git add（pathspec 精确指定，遵守并行 git 判例）；运行产物确认 .gitignore 覆盖。
2. **工单收口**：45 个 aborted 单按归档口径批量处理（K-ORG-064 系历史重试残留，不清理只归档标注）；3 个 unknown-owner 单由田丰认领或显式废弃。
3. **8091 重启滞后判例入册**：凡「代码进基线但需重启生效」的改动，验收口径显式区分「代码级 PASS」与「现网生效」两栏（本次 zhuge 路由滞后 8 小时）。

**验收**：`git status` 未跟踪 < 10；工单账本 owner=unknown 清零；看板日报增加「未入库资产」计数。

### 方案五：产品主线收敛——OS 变成地基的探头（治 P-E）

个人 OS 不再仅是「门面」，反向利用其七源归集能力：

1. **数据链健康上屏**：OS 建议引擎已有「锚 stale」类 P1 建议——把它升格为固定的「数据地基状态灯」视图（心跳/告警/晨报/调度四链路红黄绿），地基断了一定在首页可见。**门面的漂亮从此倒逼地基修复，而非掩盖它。**
2. **审批队列接入立项**（下一批 WO-OS 单之纲）：OS 从看板升格为操作入口的最后一公里；接入后老田的签准动作收敛到唯一入口，方案三的授权批量节奏也就有了载体。
3. **诸葛亮真模型对照**（待 key）：规则引擎与 GPT-6.0 输出并排评审再定切换，沿用「Demo 先行→拍板→生产替换」纪律，不直接切换。
4. **证据供数扩展**：推动各板块补 completed_at（WO-OS-26 已确认六域全缺），从量化域开始（其工单账本最规整）——「今日结果」从 1/7 真实源走向全覆盖。

**验收**：OS 首页出现地基状态灯且与计划任务实态一致；审批动作在 OS 内闭环一例；结果页真实源 ≥3。
