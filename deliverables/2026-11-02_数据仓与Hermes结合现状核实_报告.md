## 三、为什么“结合没有实现”这个判断基本成立
Hermes 现在只能通过 `dataops_query` 看到「数据地图摘要/拓扑/实体」三张视图；
它**不能**查询：新鲜度异常清单、质量检查、manifest 缺项、备份 receipt、血缘影响面、资质覆盖、run_all 日检结论；
而它以为的「仓库目录」仍来自旧 8791 的 210 表口径——与新数据仓 256 表/92 display 不一致；
调度上，数据仓日检（06:30 run_all / 快照刷新）完全在 Hermes 之外。

## 五、验收标准
1. Hermes 提问「数据仓现在多少表、哪些数据滞后、资质 unknown 多少、备份是否断档」→ 全部返回真实数据（来自新 registry/tools）；
2. MCP 工具数新增 ≥8（dw_*），全部只读、无写能力；
3. `warehouse_catalog` 不再返回旧 210 表口径（或明确标注 legacy）；
4. 数据仓日检结论在 Hermes 可查（run_all summary）；
5. 无新增 Windows 计划任务（除既有日检），重启 8787 需 L2 批准。

## 六、风险
- 8787 重启/ reload 需老田/L2 五要素批准；先以新会话（MCP stdio 每次会话重载）验证，不动常驻进程；
- Python311 运行时：MCP server 用系统 Python311，新建脚本需兼容或改用 venv；
- 只读边界：任何 trigger/写操作禁止（现有 `trigger_task` 仅针对 8791 旧任务，不扩到数据仓）。
