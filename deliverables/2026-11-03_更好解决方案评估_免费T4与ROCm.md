# 更好解决方案评估（本机 vs 免费 T4 vs 云 GPU vs 本机 Linux/ROCm）

> 日期：2026-11-03｜背景：D1 7B QLoRA 冒烟原方案需租 AutoDL 4090；老田问「有没有更好解决方案」
> 结论：**有。最优路线是「免费 T4 跑 7B 全流程 + 云 24G 仅用于 14B」；本机 Linux/ROCm 作为中长期免费能力实验，不进关键路径。**

## 一、候选方案对比
| 方案 | 成本 | 时间 | 风险 | 结论 |
|---|---|---|---|---|
| **A. 免费 T4 16G（Colab/Kaggle）跑 7B QLoRA** | **¥0** | 冒烟 10 分钟 / 全量 ~30-60 分钟 | 免费额度/会话中断；需断点续训 | **⭐ 推荐先试**：7B QLoRA 在 16GB 已验证可行（[7B QLoRA on 16GB 教程](https://explore.n1n.ai/blog/fine-tune-qwen-7b-qlora-16gb-gpu-2026-06-21)、[免费 GPU 7B 微调 recipe](https://export.arxiv.org/abs/2504.15610)） |
| **B. 云 3090/A5000 24G（AutoDL 等）** | 卡费 ~¥10-25（全流程） | 5-10h | 低 | 7B/14B 都可；比 4090 更便宜，推荐作为 14B 主力（[AutoDL 指南](https://github.com/JoeyYu23/autodl-guide)） |
| C. 云 4090（原方案） | 卡费 ~¥11-25 + 裁判 ¥10-45 | 5.5-10h | 低 | 可行但非最优；仅 14B 需要时用 |
| **D. 本机 Linux + ROCm（Strix Halo gfx1151）** | **¥0（长期）** | 搭建 1-2 天 + 训练时间 | **中高**：需原生 Ubuntu/ROCm nightly、内核/驱动适配 | **中长期最佳**：社区已验证 27B+ LoRA（[Strix Halo 微调指南](https://github.com/h34v3nzc0dex/strix-halo-llm-finetune-guide)）；AMD 官方有 Ryzen ROCm 限制说明（[AMD 文档](https://rocm.docs.amd.com/projects/radeon-ryzen/en/docs-7.1.1/docs/limitations/limitationsryz.html)）；4bit QLoRA on ROCm 支持仍在合入（[bitsandbytes PR](https://github.com/bitsandbytes-foundation/bitsandbytes/pull/1857)）；**不能装在当前 Windows/WSL 生产机上，需外置盘 Ubuntu 或维护窗口，故不进关键路径** |
| E. 本机 CPU 7B LoRA 冒烟 | ¥0 | 2.5-5h | 慢、无 4bit | 可做「管线校验」，不如 A 直接 |
| F. 托管微调（百炼/方舟等） | 按 token 计费，未知 | 快 | 需账号/数据上传 | 备选，待确认额度 |
| **G. RAG-first + 7B-only（架构更优）** | ¥0-20 | 快 | 低 | **建议并行**：小知识库事实召回优先 RAG；SFT 只学格式/拒答/风格，7B 足够，14B 非必需 |

## 二、推荐组合（省钱 + 保进度 + 长期能力）
### 阶段 1（本周，¥0）：免费 T4 跑 D1/D2
- 7B QLoRA（16GB 可跑）：D1 冒烟 10% 子集 → D2 全量 7B SFT；
- 数据量小（2,678 条，平均 97 tokens），T4 全量约 30-60 分钟/epoch；
- 用 Kaggle/Colab 的持久盘 + checkpoint 续训，规避会话中断；
- 产出：7B adapter + held-out 评测（本地 9B 可做裁判）。

### 阶段 2（按需，~¥10-25）：云 24G 跑 14B D3
- 仅当 7B 验证「数据/流程有效」且确有 14B 需求时；
- 3090/A5000 24G 足够 14B QLoRA，比 4090 便宜；AWS/阿里按量+自动关机。

### 阶段 3（长期，¥0）：本机 Linux+ROCm 实验
- 用外置 SSD 装 Ubuntu（不动 Windows 生产环境），按社区指南装 ROCm 7.x + PyTorch + bitsandbytes；
- 目标：本机 14B/27B LoRA 长期免费训练；
- **只在非生产时段做，失败不影响 D1/D2**。

### 并行（现在就能做，¥0）
- 本机 9B（34 tok/s）做 C 类补量、D4 裁判、评测；
- RAG 基线 + 提示词先上线，与 SFT 对比，避免「为微调而微调」。

## 三、为什么不推荐「纯本机 Windows CPU 全量训练」
- 7B fp32 CPU 全量约 40-55h/3 epoch，进度不可控；无 bitsandbytes 4bit；
- 14B 更慢；iGPU 训练在 Windows 无 PyTorch 后端（torch-directml 实验性、算子覆盖不足）；
- 免费 T4 比本机 CPU 快 20-50 倍且 0 成本，没有理由死守本机。

## 四、风险与对策
| 风险 | 对策 |
|---|---|
| 免费 T4 会话中断 | checkpoint 每 50 step + 断点续训；数据/代码放 Drive/Dataset |
| T4 显存 16G 极限 | 7B QLoRA + grad ckpt + paged optimizer；batch 1×ga16；max_seq 2048→1536 兜底 |
| 免费额度限制 | 备选 Kaggle 双账号/时段；仍不够则转云 3090（¥1/h） |
| ROCm 实验失败 | 独立外置盘，不碰 Windows；失败即弃，不影响主线 |
| 14B 非必需却被计划绑定 | 先用 7B 出评测结论，再决定是否 14B（ROI 驱动） |

## 五、建议决策
| 选项 | 说明 |
|---|---|
| **① 推荐** | 先免费 T4 跑 7B D1/D2（¥0）→ 用结果决定是否花 ¥10-25 上 14B |
| ② 保守 | 直接云 3090/4090（¥10-25，跳过免费额度折腾） |
| ③ 长期 | 本机外置盘 Ubuntu+ROCm 实验（1-2 天，非关键路径） |
| ④ 架构 | RAG-first：先把 RAG+提示词+9B 评测跑出来，SFT 只做格式/拒答 |

**我的建议：①+④ 并行，②作为兜底，③等你同意维护窗口再启动。**
