## 一、基准参照：chanlun 池模式与探针字段消费

任何五策略落盘契约都应先对齐两个既有事实：

**1. chanlun 池（第一档基准）**

- 池文件：`quant_backtest/data/chanlun_pool.jsonl`（CN）+ `chanlun_pool_us.jsonl` / `chanlun_pool_hk.jsonl`，定义于 `quant_backtest/chanlun_scan.py:57,75`，Adapter 默认消费三条市场池（`quant_backtest/strategy_layer/adapters/chan_monitor.py:51-53,91`）。
- 行结构（`chanlun_scan.py:406-426 _make_row`）：`market / code / name / period / type / dt / price / detect_date / lag / entry_px / … / source / first_seen`。实测样例行：
  ```json
  {"market":"CN","code":"000001.SH","type":"3买","dt":"2025-10-13","detect_date":"2025-10-31",...,"source":"backfill","first_seen":"2026-09-26T14:13:28Z"}
  ```
- 写入方式三层保障：
  - 进程互斥：msvcrt 字节锁 `_pool_lock`（`chanlun_scan.py:798-825`，`.lock` 伴生文件）；
  - 幂等：锁内读-改-写，按 `(code, type, dt)` 去重键（`chanlun_scan.py:828-841 _commit_new_rows`），SQLite PK 双写在锁外（840）；
  - 原子写：tempfile + `os.replace`（`chanlun_scan.py:355-361`）。

**2. 探针对账所需字段（`strategy_layer/a4_readonly_probe.py`）**

| 字段 | 探针消费点 | 说明 |
|---|---|---|
| `detect_date` | :43, :119-125（`_day` 校验 :23-30） | **必须 `YYYY-MM-DD` 严格格式**，非法值触发 `INVALID_DETECT_DATE`/`INVALID_SOURCE_DATE` |
| `code` | :33-36 `_market`（按后缀分市场），:43 | 须带 `.SH/.SZ/.BJ/.US/.HK` 后缀 |
| `type` | :124, :210, :300-301 | 信号类型标签，事件对账键组成部分 |
| `dt` | :210, :300-301 | 信号日，事件对账键 `(type, dt)` + `detect_date` 组成事件身份 |

探针文件级验收状态机（:80-136）：`MISSING / EMPTY / NO_OBJECT_ROWS / MALFORMED_ROWS（bad_json 或 non_object）/ UNREADABLE / OK`，另有 `INVALID_DETECT_DATE` 行级计数（:119-125）。批次健康（:48-66）：单市场混日期 → `INVALID_BATCH_DATE`，age>4 日 → `STALE`。

**结论：五策略最小契约 = 对齐 chanlun 的 JSONL 逐行模式，每行至少含 `detect_date/code/type/dt` 四字段。**

## 六、cross（三线共振 · 特殊处理）

**现状证据**

- **无任何落盘**：`quant_backtest/cross_poll.py:56-57` ——`CACHE_TTL = 60` 进程内缓存 `_CACHE`；`build_cross`（:288-392）聚合结果仅驻内存（:391 写缓存返回）。`quant_backtest/linkage_collect_daily.py:10-14` 明文自证"cross_poll 无落盘产物（build_cross 结果仅进程内缓存）"，其每日采集只能进程内调用取 topn。

**草案建议（cross 特殊处理）**

1. **语义定位先拍板**：cross 是**五源派生策略**（k≥3 共振），非独立扫描源。两种定位：
   - **定位 a（推荐）**：cross = 派生池，其"真相源"是其余策略的池文件；落盘仅为**审计对账与探针可检**（回放某日共振结论）。契约要求低：快照级即可。
   - **定位 b**：cross = 独立信号源（含 Agent 信号、未来多源），则须与五策略同级契约。当前事实是派生（STRATEGIES 全部读其余产物，`cross_poll.py:309-326`），草案按 a 展开，b 须先有独立信号源落地再升级。
2. **落盘路径与格式**：`quant_backtest/data/cross_pool.jsonl`，每行一只共振票：`detect_date / code / type（= state: long/short/mixed）/ dt（= detect_date）`，复用字段 `n_hit/net_score/market/name/hits 摘要（各 sid+dir）`。**build_cross 的 topn 受 k_gate 降档影响（blocked 时产空，:356-376），池行建议落 `stocks` 中 `n_hit ≥ k` 的全量共振票而非仅 topn**，否则 blocked/降档日的空 topn 会与"真实共振"混淆——是否额外落 `src_state/k_gate` 元行（每池每日一行 meta）待拍板。
3. **写入方式**：在 `build_cross` 出口（:391 缓存写入处）追加旁路落盘：当日文件已存在且 `detect_date` 相同 → 按幂等键 `(code, type, detect_date)` 覆盖合并；整文件 tempfile + `os.replace` 原子替换。注意 build_cross 被门户请求级高频调用（TTL 60s），落盘须**仅在池内容变化时写**（比较当日内存摘要哈希），防门户流量放大 IO——实施细节拍板后定。
4. **复用 / 缺口 / 验收**：
   - 可直接复用：stocks 行全部字段、k_gate/src_state 元数据；`hits[].dt` 已存在但取自各源（五源补齐后自动改善）。
   - 上游补采缺口：**cross 无自有缺口，其数据质量完全承袭五源**——五源落盘契约落地前，cross 池的 `detect_date` 只能取观察日（build 时刻），审计价值有限；契约验收分两阶段（先观察日语义、后真实信号日语义）。
   - 验收判据：池文件存在且逐行合法；`detect_date` 全合法；行集合 = 当日 `stocks` 中 `n_hit ≥ k` 子集（进程内对账或重放对账）；`k_gate.mode` 与当日池行数一致性（blocked 日池行数为 0 或 meta 行明确标注）。

## 七、通用验收判据汇总（探针文件级）

五策略（含 chanlun 共六池）统一按 `a4_readonly_probe.py` 状态机验收：

1. 文件存在（非 `MISSING`）、非空（非 `EMPTY`）；
2. JSONL 逐行合法对象（无 `BAD_JSON` / `NON_OBJECT`；weak 若走 CSV 旁路投影则池侧无此问题）;
