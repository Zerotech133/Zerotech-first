## 二、本单 P1 修复（含测试）

### P1-1 排序数值语义（`dataset_registry.py`）

| 项 | 内容 |
|---|---|
| 问题 | ① `_query_jsonl` 排序 key 为 `str(value)` → 数值列 `'10'<'9'` 乱序；② `_query_files` 仅 `size/depth` 做数值特殊处理，其余数值字段仍 `str()`；③ 三载体（jsonl/files/parquet）None 键 `(is_none, v)` + `reverse=desc` 在**降序时把 None 排到最前** |
| 修复 | 新增模块函数 `_order_key(value)`（bool→0/1、int/float→float、其余→str）与 `_sorted_rows(rows, field, desc)`（有值行类型感知排序 + None/缺字段行固定置末尾）；`_query_jsonl` / `_query_files` / `_query_parquet` 三处排序统一改用该函数 |
| 影响面 | 仅排序 key/顺序，不改过滤/分页/count；无数据读写 |
| 测试 | `test_jsonl_order_numeric_not_lexicographic`（[100,10,9,2,None] desc / [2,9,10,100,None] asc）；`test_files_order_size_numeric_not_lexicographic`（9B vs 100B desc → [100,9]） |

### P1-2 G6 缺证据边界（`final_acceptance.py`）

| 项 | 内容 |
|---|---|
| 问题 | `collect_g6` 把 `snapshot 不可读`、`dw_snapshot_daily.log 不可读`、`catalog 不可读` 归入 `problems` → 返回 **fail**；按"缺数据 fail-visible → unknown，不硬编码"口径应为 **unknown**（FAIL 应只用于"观测到错误值"） |
| 修复 | `problems`（观测错误）与 `missing`（证据缺失）分离：snapshot/log/catalog 缺失进 missing；snapshot 缺失时跳过 catalog 版本比对；`problems` 优先 fail，否则 missing → `_gate("G6","unknown",...)`，全有证据且正确 → pass |
| 测试 | `test_g6_missing_evidence_returns_unknown`（缺 dw_log → unknown；三者全缺 → unknown）；既有 `test_g6_stale_snapshot_or_version_mismatch_fail` 仍 fail（观测到错误值） |
