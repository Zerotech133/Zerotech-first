## 一、G-01 零买入 vs 断供区分（021 根因表 CH-03 §4）

**口径**：qd/qpzm 通道「闸门收紧零买入」是风控正确行为（环境闸门 `safe=true` 才产出，`qpzm_adapter` 零买入契约性 raise 不落盘），不是断线。

**机制**：台账 `channel_frequency.json` channels 条目新增**可选**字段 `zero_buy`：

```json
"zero_buy": {
  "declared": true,
  "reason":   "为什么零买入（必填留痕）",
  "evidence": "闸门状态/账本记录证据（必填）",
  "approved_by": "谁拍的（必填）"
}
```

- 声明后：该通道零产物/业务日期超期 → 显示「**业务零产出（闸门收紧，非断线）**」独立状态，判黄**不判红**，与「上游断供」（红）明确分开。声明内容（reason/evidence/拍板人）全文进 finding evidence。
- 未声明：沿用现状，超期照旧判红，**缺省不放宽**。
- `declared` 非真 → 视同未声明（草稿不算数）。
- 声明只挡红不挡绿：闸门放开当日有产出仍判绿。
- 与 `pending_mount`/`enabled=false` 语义互斥不混同：停用是「决定不做」，pending_mount 是「没做」，zero_buy 是「风控正确地没产出」。

## 二、G-02 补跑件口径（021 根因表 CH-04）

**口径**：「业务日期旧但落盘新」（补跑件）与「真断线 N 天」是两个语义，必须可区分。

**机制**：
1. H2 各档 evidence 一律增列产物 mtime（如「落盘 mtime 2026-10-20 05:14」）；
2. 业务日期落在红档（>2×阈值）但 mtime 在阈值内新落盘 → 判黄并显式标「**补跑件待口径确认**」，不判红；
3. 业务日期与落盘都旧 → 真断线，照旧判红（豁免不误伤）；
4. 补跑件的业务日期口径（按业务日还是落盘日）**终裁待老田**，裁定前一律黄态显性化，不放宽成绿。

## 三、CH-08 雪球假绿根治：内容级检测

**口径**：H5 日期判绿只证明「件在且新」，不证明「内容可用」。021 实测 `xunyou_brief_20261020.json` 日期当日但内容降级（pool/evidence/posterior 三段全 DEGRADED、cutover_verdict=BLOCK_CUTOVER）而自检给绿——假绿比断线更危险。

**机制**：H5 对最新产物 JSON（glob 形态下为提供最新日期的那个具体文件）追加只读内容扫描：
- 命中任一 `*.status == "DEGRADED"`（并引用同级 reason/detail）或 `cutover_verdict` 以 `BLOCK_` 开头 → 判黄「**形式在、内容降级**」，证据引用具体字段（如 `sections.posterior.status=DEGRADED（后验档未产出）`），**不得再假绿**；
- 无命中 → 正常内容仍绿（证据注明「内容无降级标记」，不放宽现状）；
- JSON 不可解析仍走原路径落红（日期判定兜底，不重复报错）。
