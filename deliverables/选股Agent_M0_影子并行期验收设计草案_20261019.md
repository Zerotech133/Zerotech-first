## 2. 先锁定“同日、同市场、同筛选阶段”的比较契约

每个比较单元以 `(trade_date, market, stage, snapshot_id)` 标识；比较前记录并核验：交易日历及非交易日 gate、市场及证券代码规范、旧链归档 `scan_run_date/trade_basis`、新链 `trade_date`、两边源批次 `detect_date` 与数据可得截止时点、规则与代码版本、筛选条件、去重与集合语义。两边必须处于**同一个交易日、同一市场、同一截止信息集、同一已定义筛选阶段**才生成集合指标；文件生成时间不能替代交易基准日。跨日或阶段不同只出“口径差异/不可比”，不得补算一个有通过含义的 Jaccard。

阶段对照须先审批映射：例如“旧链归档 `stocks` 全量”只能对“新链相应全量候选且同样包含/排除相同标签规则”的阶段；“新链 `action=buy`”只能对旧链经过**已定义并留痕的等价买入/消费筛选**后的集合。当前旧链全量含影子标注不拦截（A4 报告 `:27-41`），而新链池只保留 buy（`xunyou.py:44-65`），所以这对现成文件没有等价阶段。若旧链无可复现等价阶段，标记 `STAGE_UNMAPPED`，只做各阶段各自统计与逐票解释，绝不凭名称相似强行配对或回写旧链筛选结果。ST/PIT、停牌与过滤、代码映射、买卖方向与分档规则有歧义时同样阻断集合可比。对齐成功后报告交集、各自独有、并集、覆盖率及 Jaccard（交集/并集；空并集单列不可定义），按市场/阶段分别披露分母，不跨市场混算；指标用于诊断，不预设“越像越好”，新策略本来可能有可解释的差异。

## 3. 观察记录与验收流水（仅拟议）

1. **事前冻结比较契约**：审批比较阶段映射、必到市场清单与可豁免范围、旧链发布/新链观测时间窗口、数据与规则版本、逐票归因分类、异常升级人和观察期判据。旧链产物只读抓取；新链在经授权的隔离研究环境生成，固定研究标记和 `BLOCK_CUTOVER`；严禁自动将研究文件移入 `portal/data/picks_history/` 或生产消费目录。
2. **每批留可复核证据**：保存旧归档和每个策略源文件的路径、字节 SHA-256、大小/读取状态、抓取时间及冻结快照 ID；旧链若要称“已消费”，另留消费者读取的版本、时间及回执，缺失时保持“旧链归档观察”。记录新池文件 hash、运行代码/配置版本、trade_date、scan_run_date、trade_basis、源事件 dt、PIT 可得时间及其版本、市场批次 detect_date/rows/FRESH 状态、所选批次与归档批次的映射。manifest 校验不等于生产原子快照；需分别核对抓取前后 hash/冻结范围与可重放性。`a4_comparison_contract.py:146-168` 已约束观察 manifest 的路径/状态/hash 摘要，`:177-184` 仍明确仅 `PROBE_ONLY_NOT_PRODUCTION_ATOMIC_SNAPSHOT`。
3. **PG 回执对账**：由获批的只读通道核对相关日期/批次的 PG 记录、行数、写入时间、策略与贡献、superseded/分歧计数、幂等/替换范围，并与冻结的研究输出对应；不能把“PG 有行”当作持久化完整或生产获准。现有 `quant_backtest/reports/a4_pg_receipt_report.json:4-33,114-131` 仅单次 SELECT 快照，所列归档日无 PG 行，且 20261017/18 的非交易日 gate 尚需业务确认；回执常态化仍待办。**本设计不授权写 PG，更不授权用研究作业改写既有权威记录。**
4. **先判可比、再判差异**：现有 A4 `inspect` 与 `evaluate_comparison` 只可作为**探针观察字段的自洽性初筛**；`COMPARABLE_WITHIN_PROBE` 不等于双方 PIT 可得截止时点一致、等价筛选阶段已映射或 PG 回执已验，更不是生产采纳证据。缺源、异常及 manifest 错误等现有阻断见 `a4_comparison_contract.py:19-20,107-184`；双方 PIT/阶段对齐、PG 回执还需**另行设计并获批的独立闸门**，未实现前一律不能宣称同口径可比，且持续 `BLOCK_CUTOVER`。全部闸门通过后才按逐票记录“仅旧/仅新/共同但方向或贡献不同”，汇总解释覆盖率与未解释票清单；对照仍不自动证明策略效果、可交易性或上线条件。
5. **逐票追因闭环**：以 `(trade_date, market, symbol, stage)` 为键保留双方原始记录引用及 hash/事件 ID；依次核对源文件/池批次、PIT 与 ST 口径、市场/代码转换、策略输入与过滤、同策略同票预聚合的 `superseded`、融合贡献/方向、旧链降级规则与影子标注/最终发布阶段。每票注明责任人、证据指针、原因类别（时点/缺源/规则预期差异/缺陷/待裁决）、处理状态；不以“预期不同”代替证据。未解释票保持 OPEN，修复后基于冻结输入重放，保留原始结果与修订版本，不事后覆盖观察样本。

## 4. fail-closed 与升级

以下任一情况把该比较单元记为 `NOT_COMPARABLE`，且全局继续 `BLOCK_CUTOVER`：源文件缺失/损坏/空或 hash 不一致；归档日期/基础日不符；CN 所选批次缺失、失鲜或未来，其他已拍板必到市场不满足；PIT 可得时间不明或晚于当时截止；非交易日 gate 未决；转换跳过/无效日期、同策略重复票、买卖冲突、源事件对不上、picks 集合不一致；manifest 不一致、PG 回执缺失/不匹配、任务失败/只降级、观察中发现生产写入或外发出口。记录原始异常、隔离研究产物、通知批准的责任人追因；**不能用前一日批次、推断市场归属、补齐缺源或忽略异常换取“可比”**。缺源路径不自动推断是哪个市场，见契约 `a4_comparison_contract.py:172-182`。现有 `xunyou.py` 的 A4 异常降级不等于验收放行；验收层须独立 fail-closed，不改生产运行器。
