## 二、配对规则（以快照为锚，前视污染零容忍）

### 2.1 锚的选择

**锚 = 快照**（快照是**决策时点的事实**：那一刻决定了什么、依据什么）。**不是**以 orders 为锚反向找快照——那样等于让「事后发生了什么」决定「算哪次决策的后验」。

### 2.2 身份键：`ref` 精确配对

```
快照 decision_snapshots.orders_json[i].ref
        │  （engine 落单时写下的幂等键，engine._ref_of 口径）
        │    main 子账本：  {run}#{stock}
        │    非 main 子账本：{run}@{account_id}#{stock}
        ▼
orders.ref  →  SELECT ... WHERE ref IN (...)      ← 无任何日期条件
```

`ref` 是落单当刻写进账的**确定性身份键**，与任何日期无关。

### 2.3 前视防护：三道闸

| 闸 | 规则 | 违反后果 |
|---|---|---|
| ① 配对不含日期 | 配对路径**零日期比较**；`ref` 命中 0 条即 `unlinked`，**不按日期就近回退** | 用「决策后最近的落单」挑结果 = 前视污染 |
| ② 价格必显式 | BUY 腿 `exit` 必须来自调用方 `marks`；SELL 腿 `entry` 必须来自显式 `cost_basis` 或 orders 中**严格早于**本腿成交的成交事实。**永不猜价** | 用事后最优价 / 未来价算后验 |
| ③ asof 时点闸 | `marks` / `cost_basis` 若带 `asof` 且 **早于**该腿 `fill_date` → **抛错** `lookahead_price` | 成交前的价格拿来算这笔成交的收益 |

> 「严格早于」是**因果约束**（不可能用未来的成交价当成本基准），**不是「就近匹配」**：命中多笔 → `ambiguous`，**即便按 FIFO 也不静默择一**。

### 2.4 配对结果四态（`leg.status` / `item.status`）

| 状态 | 触发 | 是否产出收益 |
|---|---|---|
| `linked` | ref 精确命中 1 条、`filled`、价格齐备 | ✅ 进 `posterior` |
| `unlinked` | ref 命中 0 条 / 账户不符 / 策略不符 / 计划无 ref（cancelled）/ 方向未知 | ❌ 显式列候选与原因 |
| `pending_settle` | 命中但 `status != 'filled'`；或已成交但缺 `marks` / 缺成本基准；或快照内部分腿不可算 | ❌ **绝不填 0** |
| `ambiguous` | 同一 ref 命中多行；或 SELL 成本基准有多笔更早 BUY 候选 | ❌ **候选全列出，不写账** |

**串账闸**：`ref` 命中但 `account_id` / `strategy` 与快照不符 → 拒配（子账本隔离，-008 口径）。

### 2.5 歧义处置（禁静默择一）

```python
{"status": "ambiguous",
 "reason_code": "ref_multi_hit",
 "reason": "ref=... 命中 2 条落单 → 配对歧义，**禁静默择一**，需人工裁决后显式指定",
 "candidates": [{"order_id": 11, "filled_price": 10.0, ...},
                {"order_id": 12, "filled_price": 99.0, ...}]}
```

**该快照整体不产出后验、不写回填账。**唯一消歧出口：显式喂 `cost_basis`（SELL 腿）或修数据（BUY 腿）。

## 三、单位与收益口径

### 3.1 unit 是必填入口，**不自动猜**

`link_posteriors(unit=...)` 缺省/空/未知 → **抛错**（`unit_missing` / `unit_unknown`），沿用 -016/-018「不声明单位即不造数」口径。**没有**「按价格量级猜百分比还是金额」的逻辑，也不做单位换算。

| unit | 含义 | 示例 |
|---|---|---|
| `pct` | 收益率小数（`0.05` = +5%） | -016 / -018 |
| `price_diff` | 价格差（元/股） | 逐笔价差审阅 |
| `CNY` | 金额（毛 P&L，未扣 `fee`） | **-013 专用**（与成本同单位方可相减） |

### 3.2 同一算式（side 只决定 entry/exit 取位）

```python
price_diff : exit − entry
pct        : (exit − entry) / entry
CNY        : (exit − entry) × qty          # qty = orders.filled_qty
```

| 方向 | entry | exit | 说明 |
|---|---|---|---|
| **BUY** | 本腿成交价 `orders.filled_price` | 显式估值价 `marks[stock]` | 已成交未平仓者**不猜价**，缺 marks 即 `pending` |
| **SELL** | 成本基准 `cost_basis[stock]` 或**唯一一笔**严格更早的 BUY 成交价 | 本腿成交价 | 卖出价 < 成本 → 负收益，**符号天然正确，无需符号分支** |

> `fee` **不**计入收益（口径：毛 P&L），但照实输出在腿级 `fee` 字段，供成本侧复用。

### 3.3 快照级聚合

- `pct` / `price_diff`：**按成交股数加权均值**（资金加权 = 组合口径；等权会把 100 股与 10000 股当同一切片，失真）。
- `CNY`：**直接求和**（金额可加，等权无意义）。

## 四、不造数与边界

| 场景 | 处置 |
|---|---|
| 无结算（`pending` / `rejected` / `cancelled`） | 显式 `pending_settle`，**绝不填 0**（0 会被读成「打平 / 白干」） |
| 已成交 BUY 无估值价 | `pending`（`mark_price_absent`），**不猜价** |
| SELL 无任何成本基准来源 | `pending`（`cost_basis_absent`），**不猜基准价** |
| **批次内部分可配** | 已配快照**照常回填**，未配快照显式列 `unlinked` / `pending` / `ambiguous`（`summary` 同时给四个计数） |
| **快照内部分腿不可算** | 该快照**整体不出数**（`legs_partial`）——部分腿之和不等于该决策的整体收益，混算即造数；腿级明细照实输出供审阅 |
| 配对歧义 | 候选全列 + **不写账**（见 §2.5） |
| 库缺失 / 无表 / JSON 损坏 | **显式抛错**（closed on failure），不静默返回空 |

## 五、回填账 schema（append-only，幂等）

**独立库 `posterior_ledger`**（本单自己的账，路径由调用方给；默认 `write_ledger=False` = 纯预演，零写入）。

```sql
CREATE TABLE posterior_ledger(
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    idempotency_key TEXT NOT NULL UNIQUE,   -- 幂等键 = snapshot_id || '|' || kind
    snapshot_id     TEXT NOT NULL,
    kind            TEXT NOT NULL,          -- 'return'（默认）/ 后续扩展
    unit            TEXT NOT NULL,
    value           REAL NOT NULL,
    source          TEXT,                   -- 留痕：run_ref@account#腿数/单位
    run_ref         TEXT,
    account_id      TEXT,                   -- = combo@branch（-008/-011 隔离账）
    combo_id        TEXT,
    ts              TEXT,
    legs_json       TEXT,                   -- 腿级明细（entry/exit/来源/候选）
    written_at      TEXT NOT NULL
);
CREATE INDEX ix_posterior_ledger_snapshot ON posterior_ledger(snapshot_id);
```

**幂等纪律**：`INSERT ... ON CONFLICT(idempotency_key) DO NOTHING`

- 重复回填 → **零新增行**，且**既有行一字不改**（既有行是历史事实；也杜绝「同一 snapshot 两种单位两套值」的静默漂移）；
- `kind` 变体（如 `return_v2`）→ 新增行而非覆盖；
- 写 0 行时**照常回报** `{"rows_inserted": 0, "rows_before": N, "rows_total": N}` —— 「跑过回填但零入账」是可审计事实，隐去统计会读成「没跑过」；
- `write_ledger=True` 而未给 `ledger_db` → **抛错** `ledger_db_missing`。

**只读零写入**：快照库、orders 库一律 `sqlite3.connect("file:...?mode=ro")` + 纯 SELECT，**不调** `-004` / `engine` 的 `ensure_table`。

## 六、三处消费接线（**原样喂，不新增第二套口径**）

```python
import posterior_link as pl

r = pl.link_posteriors(snapshot_db="data/paper.db", orders_db="data/paper.db",
                       unit="pct",
                       marks={"000002.SZ": {"price": 11.0, "asof": "2026-10-22"}},
                       write_ledger=True, ledger_db="data/posterior.db")

# ① -018 训练基线（pct 口径；同一 {"snapshots":{sid:{unit,value,source}}} 契约）
import baseline as bl
bl.build_baseline("combo_base_a@follow_research", dimension=bl.DIM_BRANCH,
                  snapshot_db="data/paper.db",
                  posterior=pl.to_topic_posterior(r))

# ② -016 会议议题提炼（同一契约，原样喂）
import topic_miner
topic_miner.mine_topics(snapshot_db="data/paper.db",
                        posterior=pl.to_topic_posterior(r), persist=False)

# ③ -013 组合复盘 ROI（金额口径，按 account_id 归集成 branches）
import combo_review
combo_review.build_review("combo_base_a", posterior=pl.to_revenue_payload(r))
```

**接线纪律**：

- `to_topic_posterior(r)` → `{"snapshots": {sid: {"unit","value","source"}}}`，与 -016 `topic_miner._validate_posterior` / -018 `baseline._validate_posterior` **同一契约、同一必填键**（`unit` 非空、`value` 数值）——**本单不新增第二套口径，只搬运**；
- `to_revenue_payload(r, combo_id=...)` → `{"unit":"CNY", "source":..., "branches": {account_id: 金额}}`，由 -013 自己求和并算 `revenue − compute_cost`；
- **非金额口径喂 -013 → 显式抛错** `unit_mismatch`（pct 与 CNY 成本不可相减），**不静默混算**；
- 本单**不出数成本**，成本账口径唯一定义处仍是 -011 + -013。

**验收实证**（`test_posterior_link.py`）：

| 闭环 | 断言要点 |
|---|---|
