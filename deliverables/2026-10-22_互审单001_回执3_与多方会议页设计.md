## 二、多方会议页设计（老田的新诉求）

### 2.1 今晚态势证明了什么

互审单 #001 三轮交锋（评审→复核→回执#2→回执#3）+ 老田两次批注，全程约 25 分钟，**没有任何两方同时在线**——协同完全靠「文书 + 账本 + 时间戳」异步完成，且质量高于多数同步会议（每条结论带实证、每条批评被独立核实、错了当场撤回）。

**这就是会议页的数据模型**：会议 = 围绕一个议题的多方文书流，不需要任何人同时在场。

### 2.2 设计：`/os-council` 会议页（挂 OS 大屏，纯静态直服零新后端）

```
┌────────────────────────────────────────────────┐
│ 会议厅（/os-council）                            │
├────────────────────────────────────────────────┤
│ ① 议题列表（左栏）                               │
│    每议题 = 一张互审单/一张裁决卡                 │
│    状态灯：🔴分歧中 / 🟡修订中 / 🟢已收敛        │
│    发起人 / 参与方头像（席位制）                  │
├────────────────────────────────────────────────┤
│ ② 发言流（中栏，核心）                           │
│    每条发言 = 一份已落盘文书的投影：              │
│    [席位徽章][时点][文书标题][核心论点折叠摘要]   │
│    [+证据链展开：实测命令/退出码/文件路径]        │
│    [+ 对方回应的 diff 高亮：采纳/部分采纳/驳回]   │
│    —— 就是今晚四轮文书的可视化重放                │
├────────────────────────────────────────────────┤
│ ③ 裁决区（右栏，老田专属）                        │
│    未决分歧自动归集到此（如 S-0 双条件曾是分歧）  │
│    一句话签准 → approval_gate 卡片                │
│    沉默 = 议题保持开放（不默认通过）              │
├────────────────────────────────────────────────┤
│ ④ 会议纪要自动生成                               │
│    议题收敛时自动产出：分歧点/证据/结论/签字       │
│    落 data/meetings/council/（原子写，复用 warroom 模式）│
└────────────────────────────────────────────────┘
```

### 2.3 实现口径（零新协议，全部既有件）

| 层 | 用什么 | 改动量 |
|---|---|---|
| 数据源 | 互审单/裁决文书已全部在 deliverables（git 可溯）；分歧状态从文书头 `STATUS:` 行解析 | 解析器 1 个 |
| 页面 | 复用 v9 生产稿深海军蓝骨架 + 席位徽章（org.json 取 cn_name+emoji） | 1 个静态页 |
| 呈现 | nginx 静态直服（/os-council），照 WO-OS-31 模式零 8091 依赖 | 1 条 location |
| 发言 | 各方继续按今晚方式落盘文书（写 deliverables + git commit）——**会议页只读投影，不改写作习惯** | 零 |
| 裁决 | 老田签准走既有 approval_gate（S-2 审批上 OS 后嵌入右栏） | 复用 |
| 纪要 | 收敛时脚本聚合发言流生成（复用 meeting_backfill 落盘纪律） | 1 个脚本 |

**防混乱三锁（沿用总线纪律）**：①发言必须先落盘 git（会议页只投影不存源，杜绝第二本账）；②席位徽章取 org.json 真源（谁发言谁署席位名，禁止匿名）；③议题状态三态灯由文书 STATUS 行驱动（不手改页面）。

### 2.4 与既有会议线的关系

- 军团晨会/作战会议室（minutes 账本）是**同步例会**——继续原样
- `/os-council` 是**异步交锋厅**——服务互审单/跨席位分歧/裁决类议题
- 两者共用纪要落盘纪律（原子写/data 留对账副本），互不取代

### 2.5 排期建议

挂入 S-1（军团调度视图）一并施工——四角色状态卡 + 互审分歧队列 + 会议发言流，本来就是同一张页的三栏。工单拆分时：S-1a 状态卡、S-1b 会议厅（本节）、S-1c 待签专区；仍受 S-0 双条件门禁前置。
