## 一、问题（为什么必须止血）

`news_collector/daily_report.py::_data_line()` 把 `news_collector/data/` 下两个计划任务产物
（`sentiment_bt_result.json`、`jev_impact.json`）直接当「当日数据实证」拼进飞书统一日报：

- 实测产物 mtime = **2026-10-18 13:59**，相对 2026-11-02 08:2x 的 age = **354.4h（≈14.8 天）**；
- 生成任务已缺失（非显式废弃），短期内不会自愈；
- 后果：读者每天收到「情绪×次日回测 / impact 分层」却误以为是当日实证——**陈旧数据外发**，属对外可信度风险。

`_data_line()` 新判定矩阵：

| 场景 | 判定 | 输出 |
|---|---|---|
| 两产物 age ≤ 48h | 新鲜 | 与旧版**逐字一致**：`📊 **数据实证**（多维数据日报）` + 回测行 + impact 行 |
| bt 陈旧（>48h）、im 新鲜 | 单陈旧 | 回测行**不外发**，改发 `⚠️ 数据实证：sentiment_bt_result.json 数据陈旧 NNNh（阈值 48h），已跳过（S1-05 止血）`；impact 行照常 |
| bt 新鲜、im 陈旧 | 单陈旧 | 回测行照常；impact 行替换为对应告警行（含 `jev_impact.json` 与 `已跳过（S1-05 止血）`） |
| 两产物均陈旧 | 整块陈旧 | **整块跳过**，只返回 1 行：`⚠️ 数据实证：sentiment_bt_result.json / jev_impact.json 数据均陈旧（最长 354h > 48h），整块跳过（S1-05 止血）` |
| bt 缺失/无 `n` | 维持旧行为 | 整块返回 `None`（不出块、不误报） |
| im 缺失 | 维持旧行为 | 只出 header+回测行 |

**边界语义**：`age > 48h` 才判陈旧（恰好 48h 仍算新鲜）；判定纯只读——不写文件、不改产物 mtime、不删产物。

   ```powershell

   # 测试与回执为新增文件，如需一并撤销：删除 news_collector/tests/test_daily_report_freshness.py 与本回执
   ```
   回滚后行为立即恢复旧版（陈旧数据重新外发——仅建议在 L2 生成任务已恢复后回滚）。
2. **热回退（保留代码、放开门槛）**：把 `STALE_GATE_HOURS = 48` 改为极大值（如 `10**9`），等价关闭门槛；
   或将 `age > STALE_GATE_HOURS` 改 `age > 10**9`。**不推荐**（会把旧数据重新当当日实证）。
3. **只降噪**：若希望告警不进入对外卡，可将 `_stale_note` 行改为仅 `print()` 落日志（需改代码，属 L2 决策）。

无数据库/数据文件/计划任务变更，回滚无需重启服务（日报由计划任务按次调起，下次触发即生效）。
