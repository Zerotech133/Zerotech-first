## WO-LEGION-S16-01（工位 DA）：state_path 多进程写合并

**缺陷形态**：`_persist_state` 目前只有 `_STATE_WRITE_THREAD_LOCK`（线程锁）。两个进程注入同一 `state_path` 时，各自「读内存 → 原子替换写盘」，后写者整文件覆盖前写者——前写者落盘的 issues/escalations/escalation_skips 记录**无痕丢失**（账本级丢单）。S14 备注的单写者假设在真实多工位部署（田丰归口席多实例）下不成立。

**要求**：
1. 跨进程串行化 + 合并：写路径加 `file_lock`（复用 `base_agent.file_lock`，锁路径 `<state>.persist.lock` 派生自 state_path）。锁内先重读盘上状态，按顶层「字典套字典」节（issues、escalations、escalation_skips 等）做**键级并集**：冲突键以内存为准（内存是活权威），仅盘上存在的键并入并打 `LOG.warning` 留痕（合并发生次数必须可观测）。合并后原子写盘，并回刷内存视图。
2. 初始化 `_load` 同样进锁。状态契约版本号 `TIANFENG_STATE_CONTRACT_VERSION` 不变；坏 JSON 语义沿现状不动。
3. 零 IO 语义不变：`state_path=None` 全部新分支不生效。
4. 新测试 `tests/test_state_multiproc.py`：至少覆盖——两进程并发各落不同 issue 最终双在（真 subprocess，参考 `tests/test_gate_persistence.py` 的跨进程写法）；进程 A 落盘后进程 B（内存无 A 记录）写入不丢 A；单进程重复写幂等如旧；零 IO 席位零产物。**先写测试（红）再改产品（绿）**。
5. **双向变异检验**（至少两条：去掉合并、去掉跨进程锁），还原后 sha256 一致，结果写入报告。
6. 禁止放松既有断言；`tests/test_tianfeng_persistence.py`、`test_tianfeng_wal.py`、`test_wal_degraded.py`、`test_wal_heartbeat.py` 必须保持全绿。

**验收判据**：
1. 新增用例全绿 + 上述四个既有文件全绿；
2. `py_compile` 通过；
3. 变异检验双向红；

## WO-LEGION-S16-02（工位 DB）：挂起队列跨进程持久化

**缺陷形态**：`message_bus.py` 的 `self._pending`（投递失败挂起 FIFO，上限 `PENDING_DELIVERY_MAX=1000` 占位）是纯进程内存。总线进程重启，未送达的升级/告警报告**全部无声丢失**——这是漏报，按「漏报比重复危险」口径是本波最高优先级。

**要求**：
1. `MessageBus` 增加可选参数 `pending_path: Optional[Path] = None`（默认 `None` = 纯内存，现有零持久化语义与既有测试一个字节不动）。注入时：启动加载盘上快照，`_enqueue_pending` / `_take_pending_locked` / 丢最旧三个变更点同步落快照。
2. 快照用 JSON 文件 + 原子写（tmp + `os.replace`），整队列一个快照（队列有界，写整份最简单且与丢最旧语义一致）；写失败 `LOG.warning` 留痕但**不阻断投递主路径**（队列落盘是兜底，不能反过来打死信道）。
3. 启动加载遇坏 JSON **fail-visible**（抛专用异常类，参照 `LedgerCorrupt` 口径：坏账宁可拒绝启动，不可静默当空队列——把未知当已知是 P0 隐患），异常类放 message_bus 模块内。
4. `entrypoint.py` 增加环境变量接线（如 `LEGION_PENDING_PATH`），缺省不启用。
5. 新测试 `tests/test_pending_queue_persist.py`：至少覆盖——总线 A 挂起 3 条后"重启"（新实例同 path）3 条俱在且顺序保持；超限丢最旧后快照同步；take 后快照移除；坏 JSON 拒绝启动；默认 None 零产物；写盘失败不阻断挂起（monkeypatch 模拟）。**先写测试（红）再改产品（绿）**。
6. **双向变异检验**（至少两条：去掉加载、去掉落盘同步），还原后 sha256 一致。
7. 禁止放松既有断言；`tests/test_contract_versioning.py`、`test_bus_stale.py` 及现有 pending 相关测试必须保持全绿（先 grep 确认涉及文件）。

**验收判据**：
1. 新增用例全绿 + 上述既有文件全绿；
2. `py_compile` 通过；
3. 变异检验双向红；
4. 报告含测试输出尾部与变异矩阵。
