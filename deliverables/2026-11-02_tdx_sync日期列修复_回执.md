# tdx_sync 日期列映射修复 · 回执（2026-11-02 15:12）

> 触发：D 批新增表 `ts_anns_d` 冒烟发现 HTTP200 零行假失败；执行：DSH-Lead

## 一、根因

1. `tdx_sync._date_col_of()` 对未登记表**一律回退 `trade_date`**；新接入表业务日期列不同（ann_date/list_date/end_date/publish_date/month 等）；
2. `_parquet_latest_date()` 因列不存在返回 None → 同步判为「full 全量」；
3. full 模式沿用 manifest 旧 `offset`（如 ts_anns_d offset=5,724,728）→ API 返回 HTTP200 0 行 → `假完成拦截` 报错（可见但不该发生）。

## 二、修复（`quant_backtest/tdx_sync.py`）

1. `_date_col_of()` 补齐 **27 张**新接入表映射（footer 实测列）：anns_d=ann_date、cb_call/cb_issue/cb_share/fund_div/fund_manager/pledge_detail/share_float/stk_holdertrade/top10_floatholders=ann_date、fund_portfolio/pledge_stat=end_date、cb_basic/etf_basic/ths_index/us_basic/fund_basic/fut_basic/opt_basic/bse_mapping/sge_basic=list_date、hs_const=in_date、cn_cpi/m/ppi=month、cn_pmi=MONTH、cn_gdp=quarter 等；
2. 新增 **done 且无可解析日期表跳过**：打印 `[SKIP] done=true 但无可解析日期列（…）；按静态/特殊日期表跳过增量`，不再误走全量旧 offset（如 ts_fx_obasic、ts_hm_list、cn_* 宏表）。

## 四、对今晚 D 批的影响

- D 批保持 33 表；新增表多数将走**增量**（按各表最新日期），静态表自动 SKIP；
- 大表增量 backlog 估算：slb_sec（2024-09 起≈2.1M 行）、share_float/top10_floatholders 等可能数分钟；D 批 PT2H 余量充足；
- 零行假失败将不再出现；无效/静态表不再刷错误（符合 D 批设计）。

## 六、风险

- 增量 `start_date` 由本地最新日期驱动；若某表本地最新与实际不同（历史导入），首次增量可能较大（分钟级）；
- `cn_*` 月/季表因日期非 8 位数字被跳过（本轮不刷；宏表走月度人工/后续月表同步单）。
