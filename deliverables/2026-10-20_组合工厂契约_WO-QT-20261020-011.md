# 组合工厂契约（WO-QT-20261020-011）

- 工单：WO-QT-20261020-011（来源条目 3.2 / 缺口 E-4 + X-5）
- 实现：`k_stock/paper/combo_factory.py`（注册表/订阅账/成本账三账分离，stdlib-only）
- 验收：`k_stock/tests/test_combo_factory.py`（9 例）
- 实施模式说明：本单由主会话凭单实施（子代理通道当日三波基础设施故障：PAC 管道 ENOENT / RPC 超时），独立验收另补位。

## 一、定位

金融游戏里**组合=实验单元**（四元组：选股源×投研 persona×盯盘风格×交易员）。工厂的职责是让新实验单元的诞生**零代码**、且**有成本纪律**。

两条硬语义：
1. **零代码创建**：输入一份组合注册文件（纯 JSON 数据），工厂完成校验→注册→建隔离账本→挂复盘订阅，输出组合凭据；既有代码 diff 为零（沿用 -003 松耦合验收口径）。
2. **成本预算强制（X-5：组合不是免费的，token 成本要进账）**：注册文件**必须**携带 `budget.monthly_llm_cost_budget`（数值 > 0），缺失或非法 → 拒绝创建（closed on failure），**不留半成品**；累计成本超预算 → 组合状态 `over_budget`，`guard_dispatch` 拒绝再派任务。

## 二、创建协议（注册文件 schema v1）

```json
{
  "factory_schema_version": 1,
  "combo_id": "combo_newbie",
  "name": "新实验组合",
  "quad": {
    "pick_source": {"id": "src_xq_news", "version": "v1"},
    "persona": {"id": "persona_momentum", "version": "v1",
                "params": {"risk_appetite": "momentum",
                           "conf_floor": 0.60, "max_pos_pct": 0.25,
                           "max_total_pct": 0.80}},
    "watch_style": {"id": "intraday_v2", "version": "v2"},
    "trader": {"id": "trader_rookie", "version": "v1"}
  },
  "budget": {"monthly_llm_cost_budget": 100.0}
}
```

字段规则：
- `factory_schema_version` 只认 1；
- `quad` 四元组元素各需 `id` + `version`；`persona.params` 走 -003 的 persona v1 必填校验（`conf_floor`∈[0,1]，`max_pos_pct`/`max_total_pct`∈(0,1]）——**复用注册表口径，不复制规则**；
- `budget` 必填且 `monthly_llm_cost_budget` 须为数值 > 0；
- `combo_id` 全局唯一（对既有注册表查重，重复 → `DuplicateComboError`，禁覆盖）。

## 三、创建流程与失败语义

`create_combo(注册文件路径, registry_path=, subscription_log=)`：

1. 注册文件全量校验（schema / 四元组复用 -003 / 预算强校验）→ 失败**不写任何文件**；
2. `combo_id` 查重 → 重复即拒；
3. 注册表**原子写**（同目录临时文件 + `os.replace`），写失败**回滚恢复原文**；
4. 写后复验 `load_registry`（写坏即抛，closed on failure）；
5. 复盘订阅条目 append-only 落账；
6. 返回凭据：`combo_id / name / quad / budget / account_ids / registry_path / subscription_log / status=ready`。

异常族（均带 `reason_code`，禁静默降级）：

| 异常 | reason_code | 触发 |
|---|---|---|
| `ComboFactoryError` | registration_missing / registration_invalid_json / registration_invalid / missing_field / schema_version_unsupported / quad_invalid | 注册文件级违例 |
| `BudgetViolationError` | budget_missing / budget_invalid / cost_invalid | 预算契约违例（X-5） |
| `DuplicateComboError` | duplicate_combo | combo_id 已注册 |
| `BudgetExceededError` | over_budget | 累计成本超预算，派任务被拒 |

> 语义归口：预算缺失归 `BudgetViolationError/budget_missing`（预算维度的违例），不混同普通缺字段（`missing_field`）——便于按 X-5 单独统计预算类问题。

## 四、三账分离

| 账 | 文件 | 语义 |
|---|---|---|
| 注册表 | `k_stock/paper/combos.json`（默认）或 `registry_path` | 组合定义（四元组+预算），原子写、查重 |
| 复盘订阅账 | `k_stock/data/combo_review_subscriptions.jsonl` | append-only；只登记消费口引用，**不复制实现** |
| 成本账 | `k_stock/data/combo_budget_ledger.jsonl` | append-only；`record_combo_cost` 显式喂入（**模拟计费**） |

复盘订阅消费口（对齐既有只读函数）：
- `event_receipts.completeness`（-007：四类回执完整度）
- `strategy_branch.BranchRunner.compare_reviews`（-008：分支复盘并排比较）

隔离账本标识对齐 -008：`account_id = f"{combo_id}@{branch_id}"`（如 `combo_newbie@aggressive_direct`）。

## 五、成本与预算闸门

- `record_combo_cost(combo_id, cost, note, ledger, ts)`：成本须为数值 > 0，按月（`YYYY-MM`）累计；
- `combo_budget_status(combo_id, ...)`：`{month, budget, cost_accumulated, remaining, over_budget, status}`；
- `guard_dispatch(combo_id, ...)`：超预算 → `BudgetExceededError`（closed on failure，拒绝再派任务）；未超 → 返回预算快照。

**当前为模拟计费**：成本由调用方显式喂入，不接真实 token 计量。接真实计量（上游网关/llm_cost）属后续工单。
