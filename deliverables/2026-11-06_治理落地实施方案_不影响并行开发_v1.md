### 3.2 `devtask.py` 具体改法

1. 常量区（`~:1097`）加：`GOV_STATE_ENV="GOV_MODE"`、`GOV_STATE_PATH=<repo>/config/gov_state.json`。
2. 新增 `_gov_state()`：读 JSON，失败/缺失 → `{"mode":"off"}`；环境变量 `GOV_MODE` 优先级最高。
3. `_worktree_cap()`：原逻辑后，若 `mode != off` 且 `cap` 为合法正整数 → 用 `state.cap`。
4. `_enforce_worktree_cap()`：
   - `off`：保持现状（原逻辑一字不改）；
   - `shadow`：`verdict in (warn, block)` 时只写一行 `%TEMP%/gov_observe/gov_shadow.log`，不 print、不 SystemExit；
   - `warn`：`block` 时只 print `[gov-warn] would-block`，不 SystemExit；
   - `enforce`：维持 `count>=cap → SystemExit`（原语义），但 ratchet 保证 `cap ≥ count+1`。
5. `cmd_new()`：解析到 `--explore` 时跳过 `_enforce_worktree_cap()`（explore 不建 worktree，见 3.3）。
6. `_ttl_hours()`：`mode != off` 且 `state.ttl` 合法时用 state.ttl（只影响 prune 标黄，不删）。

## 四、P2 影子（11-09 17:10 → 11-15）

- ratchet 公式（修正版，永不冻结）：
  `cap_new = max(target, min(cap_prev if cap_prev else current, current + 1))`
  - 初始 shadow：cap = current + 1；
  - 只有当 worktree 实际下降时，cap 才跟着降；
  - `count >= cap` 在 enforce 才拦；cap≥current+1 ⇒ 至少 1 个开单位。
- 影子期只产出：`would-block` 次数/原因、merge 等待、窗口吞吐、explore/ship 比例、分支持续时间。
- 出口判据：连续 3 天 would-block=0（或全部来自"应回收未回收"且已回收）才进 P3。
