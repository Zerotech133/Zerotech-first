# 军团 IDE 代码审计与开源对标

- 日期：2026-10-30
- 范围：`agent_platform/legion_ide/`（8103 独立 IDE 服务）+ `portal/ide.html` 前端
- 方法：本地代码审计 + 公开同类项目架构对比 + 回归测试
- 结论：**核心边界设计正确（worktree 隔离、路径白名单、工单锁、命令白名单），但并发锁、资源治理、审批闭环和上下文引擎仍有明显短板。**

## 2. 开源同类项目对标

参考：

- [Open-Source AI Coding Agents in 2026（Cline/Aider/Continue/OpenHands）](https://rightaichoice.com/blog/open-source-ai-coding-agents-2026-self-hosting-guide)
- [Tool-use / computer-agent 设计综述](https://github.com/ombharatiya/ai-system-design-guide/blob/7d614021819a7335e976583e95029cb468654723/17-tool-use-and-computer-agents/01-tool-use-landscape.md)
- [Tauri v2 capabilities 参考](https://github.com/nodnarbnitram/claude-code-extensions/blob/main/plugins/cce-tauri/skills/tauri-v2/references/capabilities-reference.md)

### 值得借鉴的 5 个模式

1. **Human-in-the-loop diff**
   Cline 类工具把每次写文件变成可审 diff，而不是直接落盘。  
   对应优化：`/api/ide/write` 先返回 diff，确认后再提交；军团 IDE 已有锁，补审批即可。

2. **Workspace trust + 命令审批**
   Continue/Cline 首次打开工作区要求信任，危险命令逐条确认。  
   对应优化：目前只有静态白名单；增加“本单允许命令集合”和一次性审批。

3. **Runtime sandbox**
   OpenHands 把 agent 动作放进隔离 runtime（容器/远程沙箱）。  
   对应优化：exec 从宿主 `subprocess` 升级到 Job Object/容器；军团 IDE 现在的风险主要在这里。

4. **Context engine**
   Aider 的 repo map、Continue 的 context providers 都做“按需检索 + 预算”。  
   对应优化：当前只有 18 个 bundle 文件和最近 8 条消息；增加目录索引、文件检索、摘要压缩。

5. **Event-sourced tool trace**
   OpenHands 用事件流记录 tool call/observation，天然支持回放、取消、审计。  
   对应优化：军团 IDE 已有 dev_events，但缺 run 生命周期和取消；补 trace/run_id/取消端点。

## 3. 优化路线

### 短期（1–2 单）

1. 写文件两阶段：preview diff → confirm（P1）
2. exec 增加 `success` 语义 + 前端明确红/绿（P1）
3. chat/exec 增加取消按钮与 SSE（P1）
4. 8103 独立壳资源修复；DEFAULT_PORTAL 改 8734（P2）

### 中期

1. 上下文引擎：repo map + 文件检索 + token 预算
2. 工单锁与会话身份绑定；审计 hash 链
3. Windows Job Object 低权限执行

### 长期

1. Tauri/WebView2 原生壳 + capability 白名单，替代 Edge app 启动器
2. 沙箱 runtime + 可回放事件流
3. 多 Agent 并发写同一工单的冲突检测（分支/文件级）
