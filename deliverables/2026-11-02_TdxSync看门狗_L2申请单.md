## 二、影响面

- **只读**：不写 `quant_backtest/data`、不触发 TdxSync/GlobalFutSync、不删锁、不重启服务、不改 nginx/端口；
- 每小时 1 次 Python 进程（实测单次 <1s CPU），读取 4 个任务状态 + 1 个 manifest + 7 个表目录 mtime；
- 仅写 3 个 `C:\Temp` 文件：`tdx_sync_probe.log`（JSONL，每次约 0.3KB）、`tdx_sync_probe_state.json`（当日基线，约 1KB）、`tdx_sync_probe_task.log`（stdout 重定向）；
- 告警仅在 rc≠0 时发飞书（成功不打扰）；日志无凭据、无业务明细，只有表名/rows/时间。

## 三、不可逆点

- **无**。新增任务可随时删除；基线/日志可删除（下次运行自动重建）；probe 对数据仓零写入，不存在数据不可逆变更。

## 六、附：probe 判定口径（与代码 docstring 一致）

1. **任务级**（四任务）：18:30 后必须今日已跑且 `LastTaskResult ∈ {0, 267009运行中}`；`267011`（未运行）仅 18:30 前允许；其他非 0 一律 fail。
2. **锁**：`C:\Temp\tdx_sync_core.lock`（兼容 `%TEMP%` 同名锁）残留 >2h（= `tdx_sync.py` 自身陈锁阈值）→ fail；<2h 仅 WARN（可能在跑）。
3. **数据级**：7 张 A 批高频表（ts_daily / ts_daily_basic / ts_index_daily / ts_moneyflow / ts_margin_detail / ts_hk_daily / ts_fx_daily）对比**当日 17:30 前基线**：交易日 18:30 后全表零增量 → `zero_row_all_key_tables`；全表 part mtime 早于今日 17:30 → `no_part_updated_since_window`。
4. 非交易日（auto=周一~周五，法定节假日需手工 `--trading-day no` 或后续接交易日历）不判零行；基线缺失/跨日自动重捕，首捕若已过窗口只 WARN 下一轮起判定。
