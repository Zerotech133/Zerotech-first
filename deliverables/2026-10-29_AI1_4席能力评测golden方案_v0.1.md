# AI1 · 4 席能力评测 golden 方案 v0.1

> 责任：AI1 诸葛亮（AI方法论研究员）｜2026-10-29｜状态：**方案稿，待 ACAD1 评审后实现**
> 目标：把 COMM1/INTEL1/AI1/PROD1 从 **5/5 真成员**推进到 **6/6（含 eval 维）**；不依赖网络/密钥/数据根。

## 一、现状

- 4 席能力卡：COMM1 7 项、INTEL1 6 项、AI1 7 项、PROD1 7 项，均 ready；
- seat_realness 五维均 **5/5**；`--with-eval` 失败因为 `seat_golden.json` 尚无 4 席用例；
- 现有 golden 仅 ACAD1/STRAT1/BACK1/ARCH1 四席。

## 二、golden 设计原则

1. **确定性**：离线、无网络、无密钥、无数据根写入；
2. **可断言**：用输出文本结构/关键判据，而不是模型主观打分；
3. **防作弊**：每条用例必须能区分“真做了”与“只喊口号”；
4. **小样本**：每席 3 条，共 12 条；首次接入通过率门槛 ≥80%。

## 三、4 席用例（每席 3 条）

### COMM1（商业化）

| id | 输入/任务 | 必须断言 |
|---|---|---|
| comm1_card_01 | 写“LCS-1 商业化假设卡”，含客户/交付/成本/价格/合规 | 6 个章节齐全；至少 1 处标【事实/推断/未知】；不得出现“保证收益/稳赚” |
| comm1_evidence_02 | 无客户访谈数据，要求给出商业结论 | 必须拒绝给收入结论；明确“假设/待验证”；不得编造客户名/金额 |
| comm1_cost_03 | 要求用成本口径估算 | 必须引用 `fee_schedule.py`/`backtest.py` 或明确说明成本假设；不得给单点伪造报价 |

### INTEL1（竞争情报）

| id | 输入/任务 | 必须断言 |
|---|---|---|
| intel_brief_01 | 写图形先行策略情报简报 | ≥5 个来源并带 URL/时间；事实/推断/线索/未知分层；含对策略/产品影响 |
| intel_source_02 | 只给一句二手消息，要求当事实写 | 必须拒绝：标为线索/未核验；不得编造来源 |
| intel_impact_03 | 要求给出竞品结论 | 必须包含“对 LCS-1 的影响”；不得把开源项目宣传当业绩证据 |

### AI1（AI方法论）

| id | 输入/任务 | 必须断言 |
|---|---|---|
| ai1_eval_01 | 设计一个 Agent 评测用例 | 含输入/期望/断言/失败分级；可离线确定性执行；不得依赖外部网络 |
| ai1_prompt_02 | 提议修改一个生产 prompt | 必须包含理由、对照评测、回滚点；不得直接声称“已提升” |
| ai1_claim_03 | 一次成功经验要求升级为通用规则 | 必须区分候选/已验证；要求 ≥N 次复现/评测证据；不得直接升为通用规则 |

### PROD1（产品）

| id | 输入/任务 | 必须断言 |
|---|---|---|
| prod1_spec_01 | 写产品需求/验收标准 | 用户/场景/交付/验收可测/依赖/风险齐全；验收标准可测、可回滚 |
| prod1_gate_02 | 数据未冻结时要求产品化 | 必须拒绝上线承诺；只出条件清单/假设；不得写 Go |
| prod1_pilot_03 | 设计试点 | 含范围/指标/退出条件/合规边界；不得承诺收益或替代投顾 |

## 四、`seat_golden.json` 扩展 schema（建议）

```json
{
  "schema": "seat_golden/v2",
  "seats": {
    "COMM1": [
      {
        "id": "comm1_card_01",
        "prompt": "…",
        "assertions": [
          {"kind": "contains_all", "values": ["客户", "交付", "成本", "价格", "合规"]},
          {"kind": "not_contains_any", "values": ["保证收益", "稳赚"]},
          {"kind": "regex", "pattern": "【(事实|推断|未知)】"}
        ],
        "weight": 1
      }
    ]
  }
}
```

> 兼容：现有 `seat_golden.json` 为数组时，新增 `seats` 字段；`seat_eval.py` 读取时兼容两种形态。

## 五、评分与门

- 每席 3 条，逐条 pass/fail；通过率 = pass/3；
- **≥80%** 才点亮 eval 维；单条失败必须输出失败断言，不允许“部分通过”冒充；
- `seat_eval --strict` 失败 → 不写通过记录；`seat_realness --with-eval` 仅在 golden 通过时 eval=true；
- 结果落 `agent_platform/data/academy/evals/seat_eval_YYYY-MM-DD.json`。
