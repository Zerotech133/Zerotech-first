# 数仓第一性原则与全域结构化数据盘点 · 报告

- 日期：2026-11-02 ｜ 口径来源：老田（数仓核心本质定义）｜ 数据：`dataset_inventory_20261102.json` + 台账 CSV

## 一、第一性原则（按老田定义落成四条规则）
> **数仓 = 一切可结构化、未来可用、能调取的数据的统一管理者。**
1. **结构化即可入仓**：接口数据、开源情报抽取数据、学习/研究派生结论，只要可结构化，一律纳入统一管理；
2. **未来可用即可调取**：入库不是为了存放，而是为了随时能取——每个数据集必须有明确取数入口（API/MCP/CLI/SQL）；
3. **统一登记/统一口径/统一治理**：唯一登记表、唯一目录、统一新鲜度/质量/权限/保留策略；
4. **派生数据带血缘**：学习结论、报告、KB、因子、策略必须能追溯到源数据与生成过程。

## 四、结论
1. 登记覆盖 265/287（92%）不差，但**取数入口只覆盖 69 个（24%）**——『入仓但调不到』是当前数仓最大问题；
2. **平台运行域登记率仅 25%**（24 个只有 6 个登记），学习派生域缺 shadow/笔记；
3. 开源情报域缺「结构化后数据」的登记（分类后的雪球帖/新闻情绪/情报结论未成独立数据集）；
4. 因此数据仓应升级为「**全域结构化数据统一管理平台**」，而不是行情库 + 治理工具。

## 五、方案（已并入《数据仓研发方案 v2》WP-I）
| 工作项 | 内容 | 排期 |
|---|---|---|
| WP-I1 统一数据集登记模型 | 以「数据集」为登记单位（dataset vs physical tables/shards），字段：id/域/载体/schema/owner/新鲜度/保留/访问方式/敏感级 | Sprint2 |
| WP-I2 四域登记补齐 | 平台运行 18 个、学习派生 2 个、开源情报 1 个、接口 1 个；automation_runs/news.db/quant.db/paper.db/shadow 优先 | Sprint2 |
| WP-I3 统一取数入口 | 按 dataset_id 一码取数：MCP `dw_query` + HTTP `/api/dw/*` + CLI；只读优先，权限分级 | Sprint2-3 |
| WP-I4 派生血缘 | 学习结论/报告/KB/因子/策略 → 源数据集 + 生成脚本的 lineage 边 | Sprint3 |
| WP-I5 治理规则 | 新鲜度/质量/保留/敏感级（运行账本不对公）、审计日志 | Sprint3 |
| WP-I6 验收 | 登记率 100%、取数入口覆盖 ≥80%、任一数据集可从 Hermes/门户取到样本 | Sprint3 末 |

## 六、对既有工作的影响
- 前期审计/方案（v1）侧重「行情仓 + 治理工具」，本报告把范围扩到四域；
