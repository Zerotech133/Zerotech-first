# 开源社区爬虫工具学习报告 —— 雪球链路最优方案

> 日期：2026-10-16 ｜ 背景：雪球风控升级，匿名 warm_session 只能拿到 acw_tc，xq_a_token 获取断供（XueqiuCrawl 18:00 rc=1 / 400016）

---

## 一、社区踩雷判例（最关键发现）

**Agent-Reach**（Gu0Jing/Agent-Reach，2026-03 v1.3.1）修好了与我们一模一样的雷，其 CHANGELOG 原话：

> 修复 400 错误根本原因：`_ensure_cookies()` 仅访问首页只能获取 **acw_tc（防 DDoS token）**，**xq_a_token 由雪球前端 JS 动态生成，无法通过纯 HTTP 请求获取**。

→ 证实我们昨日的实测结论不是偶发，而是雪球全站性策略变更。**匿名通道已死，纯 HTTP 养 token 的老路彻底封死。**

### Agent-Reach 的解法（三级 cookie 加载策略）

| 级 | 来源 | 说明 |
|---|---|---|
| 1 | 配置文件保存的 cookie 串 | `configure --from-browser` 一次性写入 |
| 2 | **本地浏览器自动提取**（rookiepy 优先 / browser_cookie3 回退） | 用户在 Chrome/Edge 登录雪球一次即可，之后每次运行自动取 |
| 3 | 首页 fallback | 只够公开端点，拿不到 xq_a_token |

配套请求面修复：**真实 Chrome UA**（自定义 UA "agent-reach/1.0" 被雪球反爬识别拒绝）+ **所有请求带 `Referer: https://xueqiu.com/`**。

端点迁移情报：`/statuses/hot/listV3.json` 已废弃（返回空 body），改用 `/v4/statuses/public_timeline_by_category.json`（item.data 是 JSON 字符串需二次解析）。⚠️ 我们 L3 用的 `listV2.json` 大概率同样濒危，实现时需实测验证。

## 二、工具生态盘点

| 工具 | 定位 | 本机状态 | 对我们的价值 |
|---|---|---|---|
| **rookiepy 0.5.6** | 浏览器 cookie 提取（Rust，支持 Chrome/Edge/Firefox，支持 DPAPI 解密） | ❌ 未装，清华镜像可装 | ★★★ 自动化 token 供给的核心 |
| **curl_cffi** | TLS/JA3 指纹伪装（impersonate=chrome），requests 同款 API | ✅ 已装 | ★★ 二级保险：风控升级到 TLS 指纹层时启用 |
| DrissionPage / nodriver | 无头浏览器实时养 cookie | ❌ 未装 | ★ 重且慢，只用于取 cookie 不划算，rookiepy 路线更优 |
| browser_cookie3 | cookie 提取（纯 Python 老库） | ❌ 未装 | rookiepy 的回退项，可不强求 |
| pysnowball 0.1.8 | 雪球结构化 API 封装（L1 主力） | ✅ 已装 | 维持不动 |
| AKShare `_xq` 接口 | 雪球补充 | 2026-05 社区实测全线超时不可用 | 维持 L2 占位不投入 |

## 三、数据源格局校验（社区 2026 实测口径）

- 社区验证链：**历史全量 Baostock → 每日增量 tushare → 雪球兜底**，AKShare 路径全部跳过 —— 与我们现有栈（tushare 主力 + tdx + 雪球兜底）完全同构，**架构不用动**。
- 雪球的不可替代价值 = **舆情三表**（讨论帖/热帖/评论，pysnowball/AKShare 均无）+ L1 失效时行情接管。带登录 token 后 kline 2000 条/0.6s、24h 可用（社区实测），token 有效期 20-30 天。
- 雪球防护口径（多源交叉确认）：有 xq_a_token 即通；Referer 校验形同虚设但白送不加白不加；UA 别用 python-requests 默认；未登录 15 次/分，429 指数退避（我们已实现）。

## 四、方案对比与推荐

| 方案 | 内容 | 成本 | 结论 |
|---|---|---|---|
| **A. 三级 cookie 链（推荐）** | xueqiu_common.py 加 rookiepy Edge 自动提取级：`.env.local` 手填 → **rookiepy 从本机 Edge 自动取** → 首页 fallback；补 Referer 头；顺手核验 hot 端点存活 | 改动 ~60 行 + 装 rookiepy 一个包 | ✅ **立即可做**。把"每 20-30 天手取 token"自动化为"Edge 登录一次，之后全自动续命" |
| B. curl_cffi 指纹伪装 | 会话层换 impersonate=chrome | 中（会话对象改造） | ⏸ 储备。当前卡点是 cookie 不是指纹；风控再升级时启用 |
| C. 无头浏览器养 cookie | DrissionPage 实时取 | 高 | ❌ 不采纳，rookiepy 覆盖同一需求且零浏览器开销 |

**方案 A 落地后的用户操作**（对比旧待办）：
- 旧：F12 手取 xq_a_token → 填 .env.local → 每 20-30 天重复一次
- 新：**在 Edge 里登录一次 xueqiu.com**（完事）——之后每次任务运行自动从 Edge 提取新鲜 token，token 过期只需重新登录一次浏览器即可
