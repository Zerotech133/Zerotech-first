## 一、命令全文（批准后照此创建）

```powershell
# 1) 创建每日 09:00 计划任务（LIMITED，仅登录用户）
$script = "C:\项目\老田的AI助手\tools\metadata_daily.py"
$action = New-ScheduledTaskAction -Execute "python" `
  -Argument "`"$script`" --emit --check" `
  -WorkingDirectory "C:\项目\老田的AI助手"
$trigger = New-ScheduledTaskTrigger -Daily -At 09:00
$settings = New-ScheduledTaskSettingsSet -StartWhenAvailable `
  -ExecutionTimeLimit (New-TimeSpan -Minutes 15) -MultipleInstances IgnoreNew
Register-ScheduledTask -TaskName "ZeroBound\MetadataDaily" -TaskPath "\ZeroBound\" `
  -Action $action -Trigger $trigger -Settings $settings -RunLevel Limited `
  -Description "元数据日报：catalog/registry 一致性 + 新鲜度 + 备份覆盖，每日一条事件"

# 2) 手动验证
python tools\metadata_daily.py --json
python tools\metadata_daily.py --emit --check   # 有异常 exit 1（任务结果可见）
```

日志：脚本 stdout 由计划任务记录；报告落 `agent_platform/data/reports/metadata_daily/<日期>.json|.md`，事件层为 `patrol_verdict`。

## 二、影响面

- 只读：三个来源工具均只读（catalog/registry/数据根 stat/备份目录清单），不写数据根、不改 catalog；
- 写入范围：仅 `agent_platform/data/reports/metadata_daily/`（日报/历史 jsonl）+ 事件层一行；
- 运行时长：实测 **< 5 秒**；每日 09:00 一次，CPU/IO 可忽略；
- 依赖：本机 Python 3.11（与现有脚本一致）、数据根可读。

## 三、不可逆点

- **无**（纯读 + 追加式报告文件；事件层为 append-only）；
- 若后续加"自动修复"需另行 L2 审批（本单不含任何修复动作）。

## 四、替代方案与已尝试

| 方案 | 取舍 |
|---|---|
| 人工每天跑 | 已试：需人记，易漏（本单就是要消灭"靠人"）；不采纳 |
| 现有 2h 脏文件巡检任务顺带跑 | 语义混装（脏文件 vs 数据治理），且巡检任务为 L2 已批单一只管脏文件；不采纳 |
| 事件层 + 报告文件（本方案） | 只读、低频、异常可见（--check 退出码），最小改动 |
| 并入备份 0300 链 | 备份链失败会连累日报；且 0300 时点数据未跑批；不采纳 |

## 五、回滚预案

```powershell
schtasks /Delete /TN "ZeroBound\MetadataDaily" /F
```
报告文件保留（只读证据，可手动归档）；事件层历史不可删（append-only，按证据保留）。

## 六、验收标准

1. 创建后 `schtasks /Query /TN "ZeroBound\MetadataDaily" /V /FO LIST` 显示 Last Result 0；
2. 连续 3 天 `agent_platform/data/reports/metadata_daily/` 有当日 json/md；
3. 事件层（`portal/data/dev_events.jsonl` 或 events 存储）每日一条 `patrol_verdict`；
4. 异常日（如新鲜度 FAIL）任务结果非 0 且 detail 含异常摘要。
