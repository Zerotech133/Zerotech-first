## 二、修复详情（≤3 BUG）

### F1 修复：仓外 manifest 校验崩溃

- **根因**：`cmd_validate` 文本分支硬编码 `f.relative_to(ROOT)`；已有 `_display()` 安全助手未使用。
- **修复**（1 行）：`print(f"[{mark}] {_display(f)}  errors=…")`（`tools/composition.py:526`）。
- **影响**：仅输出显示路径；校验逻辑/rc 不变（JSON 分支原本已用 `_display`）。
- **回归测试**：`test_platform_composition.py::test_validate_repo_external_manifest_no_crash`（复制 template-product 到 pytest tmp_path → rc=0、无 Traceback、`[PASS]`）。

### F2 修复：kernel_guard 绝对路径 fail-open 绕过

- **根因**：`_norm()` 只做 `\→/`、去 `./`；绝对路径与内核 artifact（相对）永不相等 → 门禁放行。
- **修复**（`tools/kernel_guard.py:35-48`）：绝对路径（`C:/…` 或 `/…`）尝试 `Path.resolve().relative_to(ROOT.resolve())` 归一为仓内相对；仓外绝对路径保持原样（不命中即放行，因不可能是仓内内核文件）。
- **修复前复现**：`python tools/kernel_guard.py --files C:\…\platform\kernel_v1.yaml` → `OK: 1 个改动，无内核契约命中` rc=0（**应 BLOCK**）。
- **修复后**：同一命令 → `BLOCK` rc=1；`--adr ADR-015` → rc=0。**未放宽门禁**（相对路径行为完全不变）。
- **回归测试**：`test_kernel_guard_absolute_path_blocks_without_adr`（绝对路径无 ADR → rc1 BLOCK；带 ADR → rc0）。

### F3 修复：hermes 构建 CLI 契约（`--json` 纯度 + `--no-verify` 语义）

- **根因 1**：`info()` 固定 `print(..., flush=True)` 到 stdout；`--json` 回执前混入大量 `[acad1]` 行 → `json.loads(stdout)` 失败（task-26 真构建时只能从日志/ VERSION.json 取数）。
- **修复 1**：新增模块级 `_JSON_MODE`，`main()` 解析参数后置位；`info()` 在 `--json` 时写 **stderr**（人类进度仍可见，stdout 纯 JSON）。
- **根因 2**：`--no-verify` 只在构建后 `if not args.no_verify:` 跳过 8787 探针；**构建验证段的 `static_path_check` 无条件执行**，与 argparse help "跳过静态路径/8787 验证" 不符（且 same-origin 分支已跳过，绝对模式未）。
- **修复 2**：验证段改为 `if same_origin: …` / `elif args.no_verify: static_path={ok:null,skipped:true,reason:"--no-verify …"}` / `else: static_path_check(...)`；退出码判定已用 `is False`，跳过不误判失败。
- **影响**：仅 `--json`/`--no-verify` 两显式开关；默认构建/失败语义不变（补丁断言、文件对账仍执行）。
- **回归测试**：`test_hermes_acad1_build_same_origin.py::test_no_verify_skips_static_path_check`（monkeypatch 构建流水线：断言 `static_path_check` 调用次数 0、stdout 可直接 `json.loads`、`static_path.skipped/ok=null/reason`、VERSION.json 落盘、rc=0）。
