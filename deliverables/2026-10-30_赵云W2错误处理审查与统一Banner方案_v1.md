## 二、统一错误 UX 规范（目标）

### 1. 三级反馈

| 级别 | 场景 | 形式 | 行为 |
|---|---|---|---|
| **L1 页面级** | 主数据 `/api/zhaoyun` 失败、写 token 获取失败 | 顶部 banner（`role="alert"`） | 显示「数据不可信/写保护未就绪」+ 重试按钮 + 关闭；写 token 失败时**禁用所有写按钮** |
| **L2 区域级** | loadDrill 四卡、cap2 十五面板 | 面板内 error chip | 「加载失败 · 重试」+ 最后成功时间；同一轮 >3 个失败聚合为 1 条「N 项数据不可用」 |
| **L3 动作级** | 审批/发送/运行/摄取等 12 个动作 | 非阻塞 toast/banner | 动作名 + 原因 + 重试按钮；成功 3s 自动消失；危险操作保留 `confirm()` 说明后果 |

### 2. Banner 组件规格

```html
<div id="banner" class="banner" role="alert" aria-live="polite" hidden>
  <span class="banner-msg"></span>
  <button class="banner-retry">重试</button>
  <button class="banner-close" aria-label="关闭提示">×</button>
</div>
```

- 三类样式：`banner-error`（红）/`banner-warn`（黄）/`banner-info`（蓝灰）；
- 重试回调由调用方传入（`showBanner(msg, {retry, level})`），失败重试仍失败则累计次数；
- 关闭后本轮不再打扰（同一 source 5 分钟内去重）；
- 键盘可达：`Esc` 关闭、焦点在失败动作后移到 banner。

### 3. 数据状态机

```
loading → ok / empty / error
error → retry(loading) → ok/empty/error
```
- 每个数据面板 `data-state` 属性 + CSS 骨架屏；
- 空态文案（如「暂无待签」「暂无评估」）；
- 数据年龄标识：显示 `generated_at` 与「N 分钟前」，超过阈值标黄。

### 4. 从 alert → toast 的替换规则

- 12 处 `alert('X 失败：'+e)` → `toastError('X 失败', {detail, retry})`；
- `approveRequest` / `submitRequest` 保留后果说明 + 二次确认（已有 confirm），失败时 banner 显示可复制的错误码；
- 不再把 `e`（Error 对象）直接拼进用户文案：统一 `errorText(e)` 映射网络/4xx/5xx/超时。
