## 1. 背景与定位（老田原话归义）

老田 2026-10-20 定义两段：

1. **中台定义**：飞书是个人 OS 第一中台，一个 Agent 控 N 个 Agent 的双向桥梁——上行通知（客户/运维/本人），下行把人的判断反向推入 OS。股票预警、新闻预警只是其下的一个能力。
2. **商业化定义（本次新增）**：飞书是未来商业化最好的通道，需要订阅付费能力。核心逻辑：**用户盯某只股票、设预警词，前提是已购买订阅服务；未购买，走不了。飞书是统一管理的能力，核心在订阅闸门。**

即：飞书中台在「通知通道」之上，新增**「权益闸门」**职责——所有面向客户的能力，先验权益，后放行。

## 2. 飞书平台能力核实结论（2026-10-20 官方文档）

| 能力 | 结论 | 来源 |
|---|---|---|
| ISV 商店应用计费 | **平台有完整计费系统**：免费版/按人付费/按企业付费/一次性收费/增值包；试用 7/15 天；购买事件通知服务商；支持「定向销售」（对指定租户定制方案） | open.feishu.cn ISV 指南 |
| ISV 结算 | 需在运营管理后台开户，支持支付宝/微信支付/合众 Pay，**需支付宝企业账户**；有开放平台服务费、保证金 | 同上 |
| ISV 门槛 | 需成为 ISV 认证租户→付费方案与平台沟通确认→接入计费→平台验收→灰度租户测试→上架 | 同上 |
| 自建应用内付费 | **无内置付费能力**。自建应用（机器人/小程序/网页）收费只能跳转外部收银台 | 开放平台自建应用文档 |
| 平台退款 | 平台不支持用户侧退款，退款由服务商自行处理并联系平台取消订单 | 同上 |

**关键判断**：飞书 ISV 计费面向**企业租户采购**（按人付费也是企业管理员买单），老田的场景是 **C 端个人订阅**（个人用户盯某只股票），不是 ISV 商店的标准售卖形态。因此：

- **主路径（B）：自建应用做交互面 + 自有订阅账本 + 外部收银台（微信/支付宝 H5）**——完全自主，支持 C 端个人，与个人 OS 账本一体。
- **远期路径（A）：待产品形态成熟、企业客户出现时，再评估 ISV 上架**（届时「按企业付费+定向销售」正好服务 B 端大客户）。

## 3. 总体架构：双向闸门

```
                      ┌─────────────────────────────────┐
                      │        飞书中台（HERMES 运行体）        │
                      └─────────────────────────────────┘
     下行（发放）                                上行（进化/交互）
┌──────────────┐                          ┌──────────────┐
│ 8097 唯一出口  │                          │ W43 唯一入口   │
│   ★出向闸★    │                          │   ★入向闸★    │
│ 分域校验+额度  │                          │ 身份识别+订阅校验│
└──────┬───────┘                          └──────┬───────┘
       │                                         │
   ┌───┴─────────────┐                    ┌──────┴──────────┐
   │ push_targets 分域 │                    │ 订阅账本（OS 商业化域）│
   │ 本人/运维/客户三域  │◄───── 权益查询 ─────►│ subscriber/plan/ │
   └─────────────────┘                    │ 有效期/额度/状态    │
                                          └──────┬──────────┘
                                                 │
                                          外部收银台（微信/支付宝 H5）
                                          支付回调 → 落账 → 生效
```

**闸门原则（沿用治理红线）**：
- 出向闸挂在 8097 出口内部（不建第二出口）；入向闸挂在 W43 受理器内部（不建第二入口）。
- 未订阅入向请求 → 不执行业务，回引导卡片（订阅介绍+购买链接）。
- 未订阅出向分发 → 不发送，记录 `blocked`（kind=`subscription_required`），进既有 blocked 治理滚窗。
- 订阅账本是个人 OS 的**商业化域**，属新增第一方账本，不与策略账/生产账混同；权益判定只读订阅账本，不反推业务账。

## 4. 三域收件人模型（push_targets 分域）

| 域 | 对象 | 通道特性 | 权益 |
|---|---|---|---|
| 本人 | 老田 | 全量、免额度、critical 豁免静默（现状不变） | OS 所有者 |
| 运维 | 内部运维人员 | 工单/告警类模板，免订阅 | 内部白名单 |
| 客户 | 订阅用户 | 模板白名单（预警/日报/个股盯盘），**频控+额度**，静默窗强制（critical 豁免仅限本人域） | **订阅闸门强制** |

客户域新增约束：
- **模板白名单**：客户能收到什么由方案（plan）决定，不由客户指定任意内容。
- **频控**：每用户/每 kind 日发送上限（防打扰+防成本失控）。
- **外部协作前置**：租户外客户需先加外部协作/关联组织（上轮已核实），这是客户域开通的运营前置条件，写入开通 SOP。
- **合规红线**：股票类内容对客户分发必须带风险提示模板；不承诺收益；留存发送审计。

## 5. 订阅账本设计（最小集）

```
subscriber        订阅者：subscriber_id, feishu_open_id, union_id, 手机号, 状态
plan              方案：plan_id, 名称, 价格, 周期, 额度(盯票数/预警词数/日推送上限), 模板集
subscription      订阅实例：subscriber_id, plan_id, 起止时间, 状态(生效/到期/退订), 支付流水号
entitlement_log   权益判定日志：谁、何时、查了什么、放行/拒绝（审计+争议凭据）
payment_order     支付订单：单号, 金额, 渠道, 回调状态（只存流水号与状态，不存密钥）
```

- 判定口径：`生效 = 状态=生效 AND now∈[起,止] AND 当日额度未耗尽`。额度可做增值包叠加（对齐飞书增值包概念，为远期 ISV 化预留同构）。
- 到期前 N 天（建议 3 天）出向续费提醒（走客户域模板）。
- 所有键、金额、流水不打印明文进日志（沿用 R-1~R-4 凭据纪律）。

## 8. 边界与红线

- 不建第二出口/第二入口：闸门挂 8097/W43 内部。
- 不动现有本人域/运维域任何行为：分域改造对存量域零感知。
- 订阅账本不反推业务账：权益判定单向依赖。
- 商务材料（商户号、ISV 资质、主体信息）由老田提供，AI 不代持、不存储密钥。
- M3 涉及真实资金流，动工前另走五要素审批。
