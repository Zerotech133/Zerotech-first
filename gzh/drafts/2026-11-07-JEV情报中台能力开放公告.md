# 【能力公告】JEV 情报中台开放：六项接口能力可调取，失败可溯源

> 发布：零界 AI 工作站 · 2026-11-07
> 适用：所有需要新闻/公告判读情报的团队（Agent、量化、舆情、运维面板）
> 目录页：**http://127.0.0.1:8080/jev_api.html**（门户导航「🕵️ 情报 → 📡 JEV 能力目录」）

---

## 一、我们开放了什么

JEV 情报中台已完成能力化改造，六项接口即日起对内开放：

| 能力 | 一句话用途 | 调用方式 |
|---|---|---|
| **jev_query** 判定查询 | 按时间窗/方向/个股查已判新闻（含后验命中） | `GET /api/jev/query?hours=24&bias=bull&code=600519` |
| **jev_wordcloud** 加权词云 | 多空词频对比、事件类型矩阵 | `GET /api/jev/wordcloud?days=90&top_n=30` |
| **jev_platform** 中台健康 | 哨兵四查/队列/吞吐一页看 | `GET /api/jev/platform?days=7` |
| **jev_review** 低置信复核 | 人工裁决队列（读公开/写需登录） | `GET/POST /api/jev/review/...` |
| **jev_mcp** MCP 工具 | Agent 生态进程内接入 | `tools/jev_mcp.py`（stdio） |
| **jev_trace** 调用溯源 | 报障自查，见下文第三节 | `GET /api/jev/trace?...` |

完整契约（参数范围、限额、schema 版本）见目录页卡片，或直接调
`GET /api/jev/capabilities` 拿机器可读清单。

## 二、接入约定（两条，都很短）

1. **请求带自报身份**：加请求头 `X-JEV-Ref: 团队名/用途`（如
   `X-JEV-Ref: cowagent/memory`）。非强制，但带上后排查问题时能按团队
   过滤，省双方时间。
2. **报障必带 Req-Id**：每次调用的响应头都有 `X-JEV-Req-Id`。接口异常时
   把这个 id 发给我们（或自查，见下节），可秒级定位到你那次请求。

## 三、失败了怎么溯源（四层分级，先自查再找我们）

所有 `/api/jev/*` 调用自动留痕。自查入口：目录页溯源面板，或直接调

```
GET /api/jev/trace?req_id=<你的Req-Id>          # 精确单查
GET /api/jev/trace?actor=<团队名>&status=fail   # 按团队查失败
```

失败分级口径——**查到哪级就知道找谁**：

| 分级 | 含义 | 找谁 |
|---|---|---|
| **client** | 参数越界/未登录/无权限 | 调用方自己改（占多数） |
| **upstream** | 中台依赖故障（库/模型/总线） | 中台运维，飞书 @值班 |
| **internal** | 中台自身缺陷 | 中台开发，自动立 BUG 卡 |
| **unknown** | 无响应（进程中断） | 中台运维，附时间点 |

## 四、两个诚意细节

- **留痕不影响你**：留痕库独立于业务库，留痕写失败绝不影响接口响应；
- **不记内容只记元数据**：不落你的请求体/响应体，只记 id、团队、端点、
  状态、耗时——排查够用，隐私不越界。
